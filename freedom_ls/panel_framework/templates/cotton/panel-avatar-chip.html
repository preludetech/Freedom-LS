{% load panel_tags %} {% comment %} Avatar chip — an initials circle beside a name, e.g. a learner row's leading element. Attributes: user A user object. The name, the id and the second line come from it through `person_display`: the second line is the email, and only when the user has a first or last name. Given, it replaces `name`, `user_id` and `secondary`. name Display name, and the accessible name, for a caller with no user object (the audit log keeps a name after its user is gone). user_id Picks the colour slot, via the `avatar_slot` filter. initials Overrides the initials derived from `name` (default none: derive from the first and last words, uppercased; one word gives one letter, an empty name gives none). secondary Email or role, second line, text-muted (default none). fallback_icon A semantic icon name. With no user and no id, a neutral circle holding that icon replaces the initials (default none: the initials circle). size "md" (default, table rows), "sm" (a person in a list row beside other text) or "lg" (profile header). name_hidden Off (default). On: the name and second line are not rendered, for a caller that shows the name itself (the attention row's subject link, so the row keeps one visible subject rather than two). Read through the `flag` filter, so "False", "false", "0", "none" and an empty string all count as off. The `badges` slot holds the person's status badges ("You", "Inactive"). They sit on their own line under the name and email, left-aligned with the name, and the avatar stays centred on the name and email. The initials circle is aria-hidden; the name carries the accessible name. Six colour slots, not the course accent slots theme.css reserves for course branding: `success`, `warning` and `error` are left out so no avatar can be mistaken for a status. Each is a `color-mix` of a role token into `--color-surface` at 22% or 42%, chosen so the mix stays light enough for `text-on-surface` (near-black in both shipped themes) to clear 4.5:1 against it.
