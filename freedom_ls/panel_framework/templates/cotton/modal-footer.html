{% comment %} The footer every dialog and bottom sheet ends with. It renders its own secondary button at the left, the one that leaves without changing anything: `cancel` is its label (Cancel, Close, Keep editing). With `cancel_href` it is a link back to that page, for a dialog the server renders open because JavaScript is off; otherwise it is a button calling the Alpine method named by `cancel_click`. That is `cancel` by default, which closes without the dirty-form guard, since pressing Cancel is a deliberate choice to drop the input; `keepEditing` serves the discard prompt. `cancel_click` is always a literal in a template, never filled from context, and `cancel_href` only ever receives a URL the server built. The Cancel button binds `disabled` to the host's `running`, which is true while a confirm that runs in the request is under way. Every host declares `running`, because the CSP Alpine build throws on an undeclared name; a host with no in-request run keeps it false. The link form has no binding. `focus_cancel` makes the button take initial focus and `cancel_describedby` names the element describing it. The default slot holds the actions, right aligned with the primary last, and wraps onto its own row below sm when it does not fit. It stays in view because only the body between it and the header scrolls. With `stepping` the footer steps through a list of dialogs instead of leaving: the left box renders the `previous` slot, the right one the `next` slot, and there is no cancel button and no default slot. A stepping dialog has no Close because the header's close button, Escape and a backdrop click already close it. The shape, spacing and `justify-between` are the same. {% endcomment %}
