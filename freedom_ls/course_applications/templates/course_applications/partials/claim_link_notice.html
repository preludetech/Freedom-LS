{% comment %} The notice an unverified application carries on every form page and on its status page: where the claim link went, whether it still works, and the two ways to get another one. It reads the applicant row, so a reload or a new tab shows the same state the last send left. Send again and Change both post by HTMX and swap the whole notice for the one the server sends back. After a Send again that one carries `resend`, "sent" or "failed", and says so in place of the usual message, so a click always visibly does something. Change opens a form in place. Takes `email_form`, an ApplicantEmailForm, bound after a failed change, and `notice_next_url`, the page the notice sits on when it is rendered as a response to its own forms. The notice and its form carry no id: htmx's settle step gives a swapped-in element the old attributes of the element with its id, which would undo the state Alpine sets as it starts.
