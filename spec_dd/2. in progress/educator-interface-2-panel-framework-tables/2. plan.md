# Plan: panel framework tables

Implementation plan for `1. spec.md`. Every slice runs end to end and leaves `uv run pytest`
green, including the Playwright tests. We follow TDD: each slice names the tests that prove it,
written first, one behaviour per test. Server-side tests live in `panel_framework/tests/` against
the stub models in that directory's `conftest.py`, with no cross-app imports; two short
`educator_interface` tests pin the named success criteria to the real pages.

### `TableQuery` and `parse_query`

`tables.py`:

```python
@dataclass(frozen=True)
class TableQuery:
    key: str
    search: str = ""
    sort: str = ""          # a sort_field, "-" prefix for descending
    page: str = "1"         # raw; Paginator.get_page clamps it
    filters: dict[str, list[str]] = field(default_factory=dict)   # filled in slice 5

    def param(self, name: str) -> str: return f"{self.key}-{name}"
    def to_params(self) -> dict[str, list[str]]: ...   # only non-empty values, prefixed
    def page_changes(self, number: int) -> dict[str, object]:
        return {self.param("page"): number}
```

- `DataTable.parse_query(cls, request: HttpRequest, key: str) -> TableQuery` reads `<key>-page`
  (and, in this slice, still the unprefixed `search`/`sort`/`order` so existing behaviour holds
  until slice 2).
- `DataTable.filter_queryset(cls, request: HttpRequest, queryset: QuerySet, query: TableQuery)
  -> QuerySet`: the search and sort code lifted out of `get_rows`, narrowing only.
- `DataTable.get_rows(cls, request: HttpRequest, queryset: QuerySet, query: TableQuery) -> Page`:
  `Paginator(queryset, cls.page_size).get_page(query.page)`. `CourseDataTable.get_rows` in
  `educator_interface` adopts the new signature.
- `DataTable.page_size = 25`.
- `DataTablePanel.narrow(self, request: HttpRequest) -> tuple[TableQuery, QuerySet]`: the one
  place a table's parameters are parsed and applied: `query = data_table.parse_query(request,
  self.table_key)`, `rows = data_table.filter_queryset(request, self.get_queryset(request),
  query)`. `get_context_data` and, in slice 6, the export call it.
- `DataTable.get_context(cls, request: HttpRequest, query: TableQuery, queryset: QuerySet, *,
  base_url: str, page_url: str, region_id: str) -> dict[str, object]` calls `get_rows` and
  returns the render context: `columns`, `rows`, `page_obj`, `query`, `base_url`, `page_url`,
  `region_id`, `pagination` (below). The template variable is `region_id` throughout; the old
  `table_id` c-var on `data-table.html` goes, and `<c-pagination :table_id="region_id">` feeds
  the generic component's existing input.

### Pagination links

## Slice 2 — `Column`, prefixed sort and search, replace-URL search

Behaviour: sort headers and the search box read and write `<key>-sort` and `<key>-q`; changing
either resets the table's page; search text round-trips encoded; typing replaces the URL
instead of pushing it.

### `Column` dataclass

`tables.py`:

```python
@dataclass
class Column:
    header: str
    template: str
    attr: str = ""
    text_attr: str = ""
    sortable: bool = False
    sort_field: str = ""
    url_name: str = ""
    url_path_template: str = ""
    htmx_nav: bool = False
    header_class: str = ""
    cell_class: str = ""
    card: Literal["primary", "secondary", "md_only"] = "secondary"

    def __post_init__(self) -> None:
        if self.sortable and not self.sort_field:
            self.sort_field = (self.text_attr or self.attr).replace(".", "__")
```

- `DataTable.get_columns() -> list[Column]`; `_prepare_columns` goes.
- `cotton/data-table-cells/link.html` keeps only the `url_path_template` branch, since `Column`
  has no `url_param` and no caller used that branch.

  spec 1) and are dropped.
- `educator_interface/views.py`: a module-level `_interface_link(header: str, text_attr: str,

- `tests/stub_panels.py` `StubDataTable.get_columns` returns `[Column("Name",

### Sort and search in `TableQuery`

- `parse_query` reads `<key>-q` (stripped) and `<key>-sort`; a sort not in the columns'
  `sort_field` set (with or without leading `-`) is ignored. The `order` parameter is gone.
- `TableQuery.sort_changes(self, column: Column) -> dict[str, object]`: `{param("sort"):
  next_sort, param("page"): None}` where `next_sort` is `-<field>` when currently sorted
  ascending by it, else `<field>`.
- `filter_queryset` applies `query.search` over `search_fields` (OR'd `__icontains`), then
  `order_by(query.sort)` when set.
- `get_context` adds `header_columns`: a list of `{"column", "changes", "state"}` (`state` is
  `"asc"`, `"desc"` or `""`), `sorted_by` (the header of the sorted column, or `""`), and
  `hidden_inputs(request: HttpRequest, query: TableQuery, exclude: tuple[str, ...]) ->
  list[tuple[str, str]]`: every pair from `request.GET.lists()` that does not start with
  `<key>-`, plus the table's own `to_params()` minus the excluded names. The search form's
  `hidden_inputs` exclude `("q", "page")`.

## Slice 4 — announcement and focus

Behaviour: a table region swap announces its result and moves focus to the table.

- `tables.py` `get_context` adds `announcement`: `"Showing {start}–{end} of {count}"` from
  `page_obj.start_index()`, `end_index()`, `paginator.count`, plus `", sorted by {sorted_by}"`
  when sorted; `"No results"` when the page is empty.
- New `panel_framework/templates/panel_framework/table_response.html`: `{% include
  region_template_name %}` with the table context, then `{% include
  "panel_framework/partials/announcer.html" with message=announcement oob=True only %}`.
- `_respond`: the `DataTablePanel` region branch renders `table_response.html` with
  `panel.get_context_data()`.
- `cotton/data-table.html`: the first child of the root is `<div tabindex="-1"
  data-table-anchor></div>`, an empty element so focus lands without a layout change.
- `alpine-components.js`: document-level `htmx:afterSettle` listener; when
  `event.detail.target` has `data-table-region`, focus the element matching
  `[data-table-anchor]` inside the element now carrying that id.

### `filters.py` (new)

```python
class TableFilter:
    always_shown: bool = False

    def __init__(self, key: str, label: str, *, lookup: str, always_shown: bool = False) -> None: ...
    def get_choices(self, request: HttpRequest) -> list[tuple[str, str]]: raise NotImplementedError
    def validate(self, values: list[str], request: HttpRequest) -> list[str]:
        allowed = {value for value, _ in self.get_choices(request)}
        return [v for v in values if v in allowed]
    def apply(self, queryset: QuerySet, values: list[str]) -> QuerySet:
        return queryset.filter(**{f"{self.lookup}__in": values})

class ChoiceFilter(TableFilter):        # choices: list[tuple[str, str]] or override get_choices
class RelatedChoiceFilter(TableFilter): # queryset: QuerySet or override get_queryset(request);
                                        # get_choices -> [(str(pk), str(obj))], scoped
class BooleanFilter(TableFilter):       # get_choices -> [("1", label)];
                                        # apply -> filter(**{lookup: True}) when "1" in values
```

## Slice 7 — row selection and bulk actions (desktop)

Behaviour: a table panel with a permitted bulk action renders a checkbox column, a tri-state
header checkbox and a selection bar; submitting selected rows shows a confirmation with the
resolved count, and confirming runs the action and returns to the table with its state, with

### `bulk_actions.py` (new)

```python
class BulkAction:
    label: str = ""
    action_name: str = ""
    max_rows: int = 500
    confirm_template_name: str = "panel_framework/partials/bulk_confirmation.html"

    def has_permission(self, request: HttpRequest) -> bool: return True
    def execute(self, request: HttpRequest, queryset: QuerySet) -> None: raise NotImplementedError
    def get_action_url(self, ctx: PanelContext) -> str:
        return f"{ctx.base_url}/__actions/{self.action_name}"

@dataclass(frozen=True)
class Selection:
    mode: Literal["keys", "all_matching"]
    keys: list[str] = field(default_factory=list)
    query_string: str = ""
    excluded: list[str] = field(default_factory=list)

def parse_selection(request: HttpRequest) -> Selection: ...   # mode, keys, query_string, excluded

def resolve_selection(panel: DataTablePanel, request: HttpRequest, selection: Selection) -> QuerySet:
    """Keys mode only; the view has already answered 422 for any other mode."""
    scoped = panel.get_queryset(request)
    pk_field = scoped.model._meta.pk
    parsed: list[object] = []
    for key in selection.keys:
        try:
            parsed.append(pk_field.to_python(key))
        except ValidationError:
            continue
    return scoped.filter(pk__in=parsed)
```

- `DataTable.get_row_label(row: Model) -> str` staticmethod, default `str(row)`. `get_context`
  renders `rows` as `[{"object": row, "label": get_row_label(row)}]`; cell includes pass
  `object=row.object`.

### `panels.py` / `views.py`

- `DataTablePanel.get_bulk_actions(self) -> list[BulkAction]` default `[]`;
  `ListViewConfig.get_bulk_actions(cls, request: HttpRequest) -> list[BulkAction]` default `[]`;
  `_bind_root` sets `table.bulk_actions = section.get_bulk_actions(request)` and
  `ListViewPanel.get_bulk_actions` returns it. `DataTablePanel.get_context_data` adds
  `bulk_actions` (those passing `has_permission`) and `noun` (`verbose_name_plural`).
- `_resolve_action`: after `current.get_actions()`, when `current` is a `DataTablePanel` search
  `current.get_bulk_actions()` with `_find_action` (it only reads `action_name`).
  `_ResolvedAction.action: PanelAction | BulkAction`.
- `_handle_action(request, resolved) -> HttpResponse | _BulkConfirmation`: when the action is a
  `BulkAction` it runs the flow below instead of `handle_submit`. `panel_framework_view` renders
  a returned `_BulkConfirmation(count, noun, action, action_url, selection, error, status)` as
  the full interface page with `main_template_name =
  "panel_framework/views/bulk_confirmation.html"` (plus `_bulk_confirmation_base.html`) at its
  `status`. Flow:
  1. `not action.has_permission(request)` → 403.
  2. `selection = parse_selection(request)`; mode other than `keys` → 422 "Not supported yet".
  3. `queryset = resolve_selection(panel, request, selection)`; `count = queryset.count()`;
     `count == 0` or `count > action.max_rows` → 422, "Nothing selected" or "{count} selected;
     the limit is {max_rows}".
  4. `request.POST.get("confirmed") != "1"` → confirmation, 200.
  5. Confirmed → `action.execute(request, queryset)`; redirect to `page_url` plus the request's
     query string: `HX-Redirect` on a 204 for htmx, `HttpResponseRedirect(status=303)`
     otherwise.
  Steps 2–4 answer the same way: an htmx request gets `confirm_template_name` rendered with
  `modal_open=True` at the step's status; a plain request gets a `_BulkConfirmation` carrying
  that status, so the JavaScript-off user sees the message with the page chrome.
