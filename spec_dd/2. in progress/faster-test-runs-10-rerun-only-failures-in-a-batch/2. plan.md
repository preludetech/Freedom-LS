# Plan: a batch re-runs only the tests that failed

## Context

Today every caller that fixes a failed `targeted` or `full` run follows
"When a targeted run or full run fails" in `claude_plugins/django-stack/resources/test_tiers.md`:
`uv run pytest --lf --no-cov`, then the whole tier again. This plan splits that section into the
**failed-only re-run** and the **whole-tier re-run**, makes the test runner print the node IDs the
failed-only re-run needs, lets `run_test_tier.md` take and return them, and moves the batch,
fix-batch, integration, final-fix and rebase-`targeted` callers onto the failed-only re-run.

The vocabulary is the spec's: **failed-only re-run**, **whole-tier re-run**, **failed set**.

### What already exists and is reused

- `RunState` in `claude_plugins/django-stack/scripts/run_tests.py` already knows each test's merged
  outcome (`outcomes`), the unfinished set (`unfinished()`), and folds tests that crashed their
  worker in every attempt into `outcomes` as `failed` before `print_closing_lines` runs
  (`run_with_retries`, the `repeat_crashers` block). The new lines read that state; no new tracking.
- `tests/test_run_tests.py` already has the real-pytest fixtures this plan's runner tests need:
  `crash_with_failure_run` (one genuine failure), `crash_every_time_run` (a test that kills its
  worker every attempt), `stop_on_first_failure_run` (`-x`: `test_b_never_runs` is left
  unfinished in a `FAIL` run), `crash_once_run` (a `PASS` run), and `load_runner_module` for calling
  `print_closing_lines` in-process with a built `RunState`.
- `closing_lines()` in `tests/test_run_tests.py` takes the last four stdout lines. Printing the new
  lines **before** `run: pytest attempts` keeps those four lines last, so the existing closing-line
  tests keep holding.
- `tests/plugin_markdown.py` (`code_fragments`) for prompt tests; `tests/test_rebase_prompts.py`
  and `tests/test_checkpoint_prompts.py` show the shape (module docstring, `pytestmark =
  pytest.mark.dev_tooling`, `REPO_ROOT`).
- `tests/test_test_tiers.py`: the `ALLOWED` set already includes `test_tiers.md` and
  `run_test_tier.md`, so the `tier: none` command spelled in `test_tiers.md` keeps the allowlist
  test green. No other file may spell a `uv run pytest` invocation, so every caller names the
  re-run and never restates its command.
- `implement_plan.md` Step 3 point 3 already re-runs failing tests by node ID and then follows
  `run_test_tier.md` with `--range <sha before the fix>..HEAD`: the precedent the integration fix
  copies.

### Slice 1: the runner prints the failed set

Behaviour: a failed run of `.claude/ds/scripts/run_tests.sh` prints one `run: failed <node id>`
line per failed test and, in a `FAIL` run, one `run: unfinished <node id>` line per unfinished
test, so an agent can copy the failed set from the output.

**Builds on:** none

**Touches:** claude_plugins/django-stack/scripts/run_tests.py, tests/test_run_tests.py

Edit `print_closing_lines` in `run_tests.py`. Print the node-ID lines first, before
`run: pytest attempts`, so they come before `run: summary (merged)` and the last four lines stay the
four closing lines.

Put the constant with the module's other constants (next to `EXIT_TESTS_FAILED`), with a one-line
comment:

```python
# Past this many node-ID lines a re-run by node ID is no cheaper than the whole tier.
FAILED_SET_LINE_LIMIT = 200
```

The helper sits next to `print_closing_lines`:

```python
def failed_set_lines(state: RunState, include_unfinished: bool) -> list[str]:
    """The node IDs a failed-only re-run needs, failed tests first, each group sorted.

    Each ID is shell-quoted, so an agent can paste it onto a command line as printed: a
    parametrized ID can hold a quote, `$` or a space.
    A test that crashed its worker in every attempt is already an outcome of `failed` here.
    """
    failed = sorted(node for node, outcome in state.outcomes.items() if outcome == "failed")
    unfinished = sorted(state.unfinished()) if include_unfinished else []
    lines = [f"run: failed {shlex.quote(node)}" for node in failed]
    lines += [f"run: unfinished {shlex.quote(node)}" for node in unfinished]
    if len(lines) > FAILED_SET_LINE_LIMIT:
        hidden = len(lines) - FAILED_SET_LINE_LIMIT
        lines = lines[:FAILED_SET_LINE_LIMIT] + [f"run: failed ... and {hidden} more"]
    return lines
```

`print_closing_lines` calls `failed_set_lines(state, include_unfinished=label == "FAIL")`, prints
each line, then the existing four. An `INCOMPLETE` run lists no unfinished tests: it is blocked on
memory, and a re-run of those tests is not a fix. A `PASS` run has no failed outcome and no
unfinished lines, so it prints none. `shlex.quote` leaves an ordinary node ID
(`tests/test_x.py::test_y[1]`) unchanged, so the common case reads as the bare ID. Add
`import shlex` to the imports.

Tests (TDD, in `tests/test_run_tests.py`; write each RED first):

- `crash_with_failure_run` prints `run: failed test_sample.py::test_genuine_failure` before the
  `run: summary (merged)` line.
- In-process (`load_runner_module`, build a `RunState` with three failed outcomes in unsorted
  order): the `run: failed` lines come out in sorted node-ID order.
- `crash_every_time_run` prints `run: failed test_sample.py::test_kills_its_worker_every_time`.
- `stop_on_first_failure_run` (a `FAIL` run) prints
  `run: unfinished test_sample.py::test_b_never_runs`.
- In-process: 201 failed outcomes print 200 `run:` node-ID lines then
  `run: failed ... and 1 more`.
- `crash_once_run` (`PASS`) prints no line starting `run: failed` or `run: unfinished`.
- In-process: label `INCOMPLETE` with unfinished tests prints no `run: unfinished` line.
- In-process: a failed node ID holding a single quote and a space (`t.py::test_x[it's here]`) is
  printed as `shlex.quote` renders it, and `shlex.split` of the text after `run: failed ` gives
  back the original ID.
- The existing `test_run_without_a_crash_ends_with_the_four_closing_lines` still passes unchanged.

### Slice 2: the tier definition names both re-runs

Behaviour: "When a targeted run or full run fails" defines the failed set, the failed-only re-run
and the whole-tier re-run, and `--lf` is gone from every plugin file.

**Builds on:** none

**Touches:** claude_plugins/django-stack/resources/test_tiers.md, tests/test_test_tiers.py

Rewrite the section under the same heading. It still opens by addressing the agent that owns the
change, never a mechanic briefed only to run a tier. Content, in order:

1. **The failed set.** The node IDs from the failed run's `run: failed <node id>` and
   `run: unfinished <node id>` lines. When the output has no `run: summary (merged)` line (no
   runner, `DS_TEST_MEMORY_GUARD=off`, or the runner's plain fallback), the node ID on each of
   pytest's `FAILED <node id> - <message>` short-summary lines. A run that printed
   `run: failed ... and <n> more` takes the whole-tier re-run, whatever the caller asked for.
2. Fix the failure, then re-run as the caller says. A caller that names neither re-run gets the
   whole-tier re-run.
3. `### Failed-only re-run`:
   - Run the selector with the fix's diff: the files the fix edited as explicit paths when the fix
     is uncommitted (say why: `--working-tree` would select the caller's whole uncommitted change
     again), `--range <sha before the fix>..HEAD` when it is committed.
   - `tier: targeted` → run the printed `command:` line with the failed set appended.
   - `tier: none` → the one spelling of the command in the file:
     `.claude/ds/scripts/run_tests.sh uv run pytest -n auto --no-cov -m '<markers>' <node ids>`,
     where `<markers>` is `markers` from `[tool.test_tiers]` (omit `-m` when unset) and the runner
     prefix is dropped when the runner is not installed.
   - `tier: full` → run the full tier. It is an ordinary full run: its pass finishes the step.
   - The runner's node IDs are already shell-quoted: append them exactly as printed. A node ID
     taken from pytest's `FAILED` line is the text between `FAILED ` and the first ` - `, wrapped
     in single quotes, with each single quote inside it written as `'\''`. Done when that run
     passes. A failure in it is fixed the same
     way, with its own failed set and the new fix's diff.
4. `### Whole-tier re-run`: the failed-only re-run, then, once it passes, the tier again as it
   first ran. The gate is the whole tier.

Remove the `uv run pytest --lf --no-cov` sentence and the closing "not the `--lf` subset" clause.

Add to `## Reporting`: a failed-only re-run reports
`tier: <tier> · summary: failed-only re-run of <n> tests + fix selection: <verdict line>`, after
the failed run's own report line, which stays in the report.
