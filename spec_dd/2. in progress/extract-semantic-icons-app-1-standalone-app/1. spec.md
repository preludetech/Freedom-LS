# Spec: semantic icons app, standalone

Spec 1 of 4 in the Semantic icons extraction effort (`spec_dd/1. next/roadmap.md`). Idea: `idea.md`.
Answers: `answers.md`. Research: `research_*.md` in this directory.

## Purpose

`freedom_ls/icons` imports `freedom_ls.base`, is configured through `FREEDOM_LS_ICON_*` settings
and reads its icon data from `BASE_DIR/node_modules/@iconify-json`. A host project cannot install it
on its own, and a pip or git install has no `node_modules`. After this spec the app imports nothing
from `freedom_ls` outside its own package and reads no `BASE_DIR`. Its settings use the
`SEMANTIC_ICONS_` prefix, and it ships the icon data it needs. Its tests pass under the app's own
minimal settings. It stays at `freedom_ls/icons`, with import name `freedom_ls.icons` and label
`icons`.

## Terminology

| Term | Status | Meaning |
| --- | --- | --- |
| bundled data | coined | The generated Iconify JSON subset under `freedom_ls/icons/data/`, one file per icon set |
| required glyphs | coined | For one icon set, every glyph its mapping in `mappings.py` names, plus each of those glyphs with every non-`None` suffix in the set's variants |

## Scope

In:

- Settings renamed to `SEMANTIC_ICONS_SET`, `SEMANTIC_ICONS_OVERRIDES` and `SEMANTIC_ICONS_BACKEND`,
  plus a new `SEMANTIC_ICONS_ICONIFY_DIR`. The old names stay readable for one tag.
- The app's own copy of the settings reader.
- Bundled data, its licences and manifest, and the maintainer script that generates it.
- Lookup that reads the configured directory first, then bundled data, icon by icon.
- A public loader cache clear that replaces every `loader._cache` reach-in.
- A standalone test run, an import guard, and the move of the Font Awesome invariant into FLS.
- FLS settings, docs, skills, CI and `package.json`. First-Class gets its changes through
  `upgrade_notes.md`.

Out:

- Host-added semantic names, host SVGs, custom icon sets, a registry API
  (`extract-semantic-icons-app-2-host-icons`). The four mappings and the closed set of 63 names stay
  as they are.
- Renaming or moving the app, the package repo, `pyproject` package data, the tag
  (`extract-semantic-icons-app-3-package-and-install`). Removing the old setting names belongs to the
  tag after this one.
- The generic Claude plugin and host docs (`extract-semantic-icons-app-4-claude-plugin`).
- Any change to `<c-icon>`, `{% icon %}`, `render_icon()`, `templates/cotton/icon.html`, or any
  template that uses them.

## Decisions

- **The deprecated names are announced by system checks, not `warnings.warn`.** A check is
  silenceable by id and shows on `check`, `runserver` and `migrate`. Python hides a
  `DeprecationWarning` that library code raises.
- **The configured directory is an overlay, merged icon by icon.** An icon the directory has wins.
  An icon it lacks comes from bundled data. A directory that does not exist is a startup error, so a
  typo cannot pass silently as bundled data.
- **FLS and First-Class keep full data.** `Course.icon`, `Course.icon_fallback` and admonition
  `icon_fallback` let authors name any glyph in any of the four sets (`config/settings_dev.py:14`
  uses `heroicons:scale`). Bundled data holds only required glyphs. So both projects point
  `SEMANTIC_ICONS_ICONIFY_DIR` at `node_modules/@iconify-json`, and bundled data is the zero-config
  default for new hosts.
- **The icons tests run in both the main run and a standalone run**, as the panel framework's do.
  The tier selector and the 92% coverage gate keep covering the app. The standalone run proves the
  app works without FLS.
- **The generator is a Python script outside the app**, because it only reads JSON from
  `node_modules`. It runs as `uv run python scripts/generate_icon_subset.py` after `npm install`.

## Requirements

### Settings (`freedom_ls/icons/app_settings.py`, `config.py`, `checks.py`)

1. `freedom_ls/icons/app_settings.py` holds `Setting` and `AppSettings`, copied byte for byte from
   `freedom_ls/base/app_settings.py` without `required_settings_errors`, the same cut
   `freedom_ls/panel_framework/app_settings.py` makes. Add both pairs to `SAME_SOURCE` in
   `freedom_ls/educator_interface/tests/invariants/test_framework_copies_match_base.py`, and update
   that file's docstring to name both copying apps.
2. `config.py` declares `SEMANTIC_ICONS_SET` (default `"heroicons"`), `SEMANTIC_ICONS_OVERRIDES`
   (default `{}`), `SEMANTIC_ICONS_BACKEND` (default `None`) and `SEMANTIC_ICONS_ICONIFY_DIR`
   (default `None`, `str | Path | None`). It also holds one map, `DEPRECATED_SETTINGS`, from each new
   name to its old name: `FREEDOM_LS_ICON_SET`, `FREEDOM_LS_ICON_OVERRIDES`,
   `FREEDOM_LS_ICON_BACKEND`.
3. Reading a new name returns the new name's value when it is set. Otherwise it returns the old
   name's value when that is set, and otherwise the default. "Set" follows `AppSettings`: present
   with a value other than `None` or `""`. An empty dict counts as set, so
   `SEMANTIC_ICONS_OVERRIDES = {}` beats a non-empty old dict.
4. Every reader in the app (`backend.py`, `render.py`, `checks.py`, including docstrings) uses the
   new names. The old names appear only in `DEPRECATED_SETTINGS` and the deprecation check.
5. New checks, one id per old name: `icons.W002` (`FREEDOM_LS_ICON_SET`), `icons.W003`
   (`FREEDOM_LS_ICON_OVERRIDES`), `icons.W004` (`FREEDOM_LS_ICON_BACKEND`). Each fires when its old
   name is set. The message names the replacement. When the new name is also set, the message says
   the new name is in use and the old one is ignored. The hint gives the rename line, says the old
   name is removed in the next tag, and names the id to add to `SILENCED_SYSTEM_CHECKS`. With
   neither name set, the app produces no check output.

### Icon data (`freedom_ls/icons/data/`, `loader.py`)

6. Bundled data layout, the same shape as `node_modules/@iconify-json`, so one lookup serves both
   roots:

   ```
   freedom_ls/icons/data/
     manifest.json
     heroicons/icons.json   heroicons/LICENSE
     lucide/icons.json      lucide/LICENSE
     tabler/icons.json      tabler/LICENSE
     ph/icons.json          ph/LICENSE
   ```

   Each `icons.json` is Iconify JSON holding the upstream `prefix`, the root `width` and `height`
   when upstream has them, and `icons` entries copied verbatim for exactly the set's required
   glyphs. `aliases`, `info` and the other keys are dropped, since the loader reads none of them.
   `manifest.json` records, per set: npm package name, exact version, SPDX licence id, licence URL
   (from upstream `info.json`) and the sorted list of glyphs kept. It has no timestamps.
7. Each `LICENSE` is the upstream licence text, copied verbatim from the set's repository at the
   URL in its `info.json`. The installed npm packages carry no `LICENSE` file. Lucide's file
   includes its Feather MIT notice. Licences: Heroicons MIT, Lucide ISC, Tabler MIT, Phosphor MIT.
8. `required_glyphs(set_name: str) -> set[str]` lives in the app (in `mappings.py`, beside
   `ICON_SETS`). The generator and the app's data test both call it, and neither keeps a second
   list.
9. `loader.py`:
   - Drops `iconify_json_path` and every `settings.BASE_DIR` read. The path of a set's file is
     `<root>/<PACKAGE_MAP[set]>/icons.json`, where the root is either the bundled data directory
     (found from the module's own location) or `SEMANTIC_ICONS_ICONIFY_DIR`.
   - `load_iconify_data(set_name)` returns bundled data merged with the configured directory's
     file for that set, when the setting is set and the file exists. Directory entries replace
     bundled entries with the same name. Each merged entry keeps the effective `width` and `height`
     of the file it came from, so two files with different root sizes cannot render at the wrong
     size. The result is cached per set.
   - A public `clear_cache() -> None` empties the cache. `_cache` stays private, and nothing outside
     `loader.py` touches it.
10. `SEMANTIC_ICONS_ICONIFY_DIR` must be an absolute path to an existing directory. Otherwise new
    check `icons.E008` fires, naming the value and saying to fix the path or remove the setting to
    use bundled data.
11. `icons.E002` is rewritten, keeping its id. With the directory set, it fires when the directory
    has no `<package>/icons.json` for the active set. The message gives the full path it looked
    for, and the hint names `SEMANTIC_ICONS_ICONIFY_DIR` and the `node_modules/@iconify-json`
    layout. Without the directory set, it fires only when the bundled file is missing, a packaging
    fault. No message tells the host to run `npm install`. `icons.E006` gains a hint: pick a glyph
    in the active set's bundled data, or set `SEMANTIC_ICONS_ICONIFY_DIR` to full data that has it.
    Ids `E001` and `E003` to `E007` keep their meaning.

### Generator (`scripts/generate_icon_subset.py`)

12. A new top-level `scripts/` directory holds `generate_icon_subset.py`, fully typed, since `mypy .`
    runs over it. It reads `node_modules/@iconify-json/<package>/{icons.json,package.json,info.json}`,
    or a directory given by `--source`, and writes `freedom_ls/icons/data/*/icons.json` and
    `manifest.json`. It does not touch `LICENSE` files. A maintainer reruns it whenever a mapping or
    an upstream version changes.
13. A pure function `build_subset(upstream: IconifyData, glyphs: set[str]) -> IconifyData` holds the
    subset logic. `main()` does all the I/O. The module does nothing on import.
14. Output is deterministic: sorted keys, two-space indent, a trailing newline, no trailing spaces.
    Regenerating from unchanged input gives an empty diff and passes the `end-of-file-fixer` and
    `trailing-whitespace` hooks. Each file stays under the 1 MB `check-added-large-files` limit.
15. The script exits non-zero, naming the semantic name, set and glyph, when a required glyph is
    missing upstream. When `node_modules/@iconify-json` is absent, it exits non-zero with
    `Run npm install first.`
16. It prints one line per set: package, version (old to new), glyph count (old to new) and bytes
    written (old to new), measured from the files. It then lists the glyphs added and removed per
    set. `--check` writes nothing and exits 1 when the committed data differs from what it would
    write.

### Tests and test runs

17. `freedom_ls/icons/tests/standalone_settings.py` holds `SECRET_KEY`, `DATABASES = {}`,
    `INSTALLED_APPS = ["django_cotton.apps.SimpleAppConfig", "freedom_ls.icons"]`, and `TEMPLATES`
    with the cotton loader, `app_directories` and the cotton builtins, as
    `freedom_ls/panel_framework/tests/standalone_settings.py` has them. It does not set
    `SEMANTIC_ICONS_ICONIFY_DIR`, so the standalone run exercises bundled data alone.
18. `freedom_ls/icons/tests/standalone_pytest.ini` follows
    `freedom_ls/panel_framework/tests/standalone_pytest.ini`: a file name pytest does not discover,
    `pythonpath = ../../..`, `--ds=freedom_ls.icons.tests.standalone_settings`, `--strict-markers`
    and socket blocking. The run is
    `uv run pytest -c freedom_ls/icons/tests/standalone_pytest.ini freedom_ls/icons/tests`, added
    to `.github/workflows/tests.yml` as a step after the panel framework's standalone step. The
    main run keeps collecting `freedom_ls/icons/tests`.
19. Every icons test passes under both settings modules. No icons test depends on whether
    `SEMANTIC_ICONS_ICONIFY_DIR` is set, except tests that set it themselves. Tests that need a glyph
    outside the required glyphs stub it, as the `phosphor:drone` cases in `test_render.py` do now.
20. Tests in `freedom_ls/icons/tests/invariants/`:
    - an import guard copied from `freedom_ls/panel_framework/tests/test_import_guard.py`, failing
      on any `freedom_ls.*` import outside `freedom_ls.icons` in any `.py` under the app, tests
      included. It also fails on any `BASE_DIR` reference.
    - a check that the active settings module is the standalone one when the run is standalone, as
      `freedom_ls/panel_framework/tests/test_standalone_fixtures.py` does, so a run that silently
      fell back to FLS settings fails.
    - a bundled-data test: for each of the four sets, the glyphs in `data/<package>/icons.json`
      equal `required_glyphs(set)`. `manifest.json` lists the same four sets with versions and
      glyph lists matching the files, and every set has a non-empty `LICENSE`.

    The mirroring exemption for `freedom_ls/icons/tests/invariants/` in
    `test_organisation/mirroring_exemptions.txt` stays, with its comment rewritten for these tests.
21. `tests/test_generate_icon_subset.py` (FLS main run, not standalone) runs `build_subset` over
    `node_modules/@iconify-json` and compares the result with the committed bundled data. It fails,
    rather than skips, when `node_modules` is missing or an installed version differs from
    `manifest.json`, and its message names the regenerate command. It also covers `build_subset`
    on small fixture data: required glyphs kept, everything else dropped, root sizes kept, a missing
    glyph reported. `pyproject.toml` gains a `[[tool.test_tiers.tooling]]` entry mapping
    `scripts/generate_icon_subset.py` and `freedom_ls/icons/data/**` to this test.
22. Loader tests cover: bundled data only; directory set with an icon present in both (directory
    wins) and one only in bundled data (bundled serves it); differing root sizes keep each entry's
    effective size; `clear_cache()` makes a changed directory take effect. Check tests cover:
    `E008` for a missing, relative or non-directory path; `E002` for each of its two cases;
    `W002` to `W004` for old only, new only, both and neither; and no output at all with default
    settings. Settings tests cover the precedence in requirement 3 for all three names.
23. Existing app tests that use `override_settings(FREEDOM_LS_ICON_*=...)` or `_cache` move to the
    new names and `clear_cache()`.

## Open questions

- Q: May `SEMANTIC_ICONS_ICONIFY_DIR` be relative? → A: No, `icons.E008` requires an absolute path
  (assumed default: a relative path resolves against whatever the working directory is at startup,
  which differs between `manage.py`, gunicorn and tests. Overrule by editing requirement 10.)
- Q: How is Lucide's `LICENSE` (with the Feather notice) obtained, given the npm package has none?
  → A: A maintainer copies it by hand from the upstream repository at the URL in `info.json`, once,
  and again only when upstream changes it (assumed default: the generator stays offline and
  deterministic. Overrule by editing requirement 7.)

## Success criteria

- The import guard passes in both runs. It covers `freedom_ls.*` imports and `BASE_DIR`.
- `uv run pytest -c freedom_ls/icons/tests/standalone_pytest.ini freedom_ls/icons/tests` passes,
  and the main `uv run pytest` passes.
- With `node_modules` renamed away and `SEMANTIC_ICONS_ICONIFY_DIR` unset, `manage.py check` is
  clean and all 63 semantic names render in all four sets.
- `uv run python scripts/generate_icon_subset.py --check` exits 0 on the committed data.
- Setting only `FREEDOM_LS_ICON_SET = "phosphor"` renders phosphor icons, and `manage.py check`
  shows `icons.W002`.
- `SEMANTIC_ICONS_ICONIFY_DIR = "/nonexistent"` makes `manage.py check` fail with `icons.E008`.
- With FLS's dev settings, a course whose `icon_fallback` is `heroicons:scale` saves and renders
  that glyph.
- Nothing outside `freedom_ls/icons/loader.py` references `_cache`, and `freedom_ls/conftest.py`
  has no `node_modules`.
