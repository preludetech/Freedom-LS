# Spec: semantic icons app, standalone

Spec 1 of 4 in the Semantic icons extraction effort (`spec_dd/1. next/roadmap.md`). Idea: `idea.md`.
Answers: `answers.md`. Research: `research_*.md` in this directory.

## Purpose

When this spec is done, `freedom_ls/icons` imports nothing from `freedom_ls` outside its own package
and reads no `BASE_DIR`. It is configured through `SEMANTIC_ICONS_*` settings, ships the icon data
it needs, and passes its tests under its own minimal settings. It stays at `freedom_ls/icons`, with
import name `freedom_ls.icons` and label `icons`.

## Terminology

| Term | Status | Meaning |
| --- | --- | --- |
| bundled data | coined | The generated Iconify JSON subset under `freedom_ls/icons/data/`, one file per icon set |
| required glyphs | coined | For one icon set, every glyph its mapping in `mappings.py` names, plus each of those glyphs with every non-`None` suffix in the set's variants |

## Scope

In: the settings rename and its one-tag deprecation, the app's own settings reader, bundled data
with licences, manifest and generator, the configured-directory lookup, a public cache clear, a
standalone test run, and the FLS-side changes these need. First-Class gets its changes through
`upgrade_notes.md`.

Out:

- Host-added semantic names, host SVGs, custom icon sets, a registry API
  (`extract-semantic-icons-app-2-host-icons`). The four mappings and the 63 names stay as they are.
- Renaming or moving the app, the package repo, `pyproject` package data, the tag
  (`extract-semantic-icons-app-3-package-and-install`). Removing the old setting names belongs to the
  tag after this one.
- The generic Claude plugin and host docs (`extract-semantic-icons-app-4-claude-plugin`).
- Any change to `<c-icon>`, `{% icon %}`, `render_icon()` or any template.

## Decisions

- **Deprecated names are announced by system checks, not `warnings.warn`**, because Python hides a
  `DeprecationWarning` raised in library code, and a check can be silenced by id.
- **The configured directory is an overlay, merged icon by icon**, so a host with full data loses
  nothing and a partial directory still renders every semantic name.
- **A bad `SEMANTIC_ICONS_ICONIFY_DIR` is a check error, not a render error.** `manage.py check
  --deploy` catches it on deploy. Gunicorn does not run checks, and at render time the loader falls
  back to bundled data.
- **FLS and First-Class keep full data.** `Course.icon`, `Course.icon_fallback` and admonition
  `icon_fallback` let authors name any glyph in any of the four sets (`config/settings_dev.py:14`
  uses `heroicons:scale`). Bundled data holds only required glyphs, so it is the zero-config default
  for new hosts.
- **The icons tests run in both the main run and a standalone run**, as the panel framework's do,
  so the tier selector and the 92% coverage gate keep covering the app.
- **The generator is a Python script outside the app**, because it only reads JSON from
  `node_modules`.

## Requirements

### Settings (`freedom_ls/icons/app_settings.py`, `config.py`, `checks.py`)

1. `freedom_ls/icons/app_settings.py` holds `Setting` and `AppSettings`, copied byte for byte from
   `freedom_ls/base/app_settings.py` without `required_settings_errors`, the same cut
   `freedom_ls/panel_framework/app_settings.py` makes.
   `freedom_ls/educator_interface/tests/invariants/test_framework_copies_match_base.py` adds both
   pairs to `SAME_SOURCE`. It loads the icons module by path through its existing
   `_load_module_from_path`, finding the file with `importlib.util.find_spec("freedom_ls.icons")`,
   so it adds no import that `lint-imports` forbids. Its parametrize ids include the copy's module,
   so a failure names the app that drifted. The docstring names both copying apps.
2. `config.py` declares `SEMANTIC_ICONS_SET` (default `"heroicons"`), `SEMANTIC_ICONS_OVERRIDES`
   (default `{}`), `SEMANTIC_ICONS_BACKEND` (default `None`) and `SEMANTIC_ICONS_ICONIFY_DIR`
   (default `None`, `str | Path | None`). It holds one map, `DEPRECATED_SETTINGS`, from each new
   name to its old one: `FREEDOM_LS_ICON_SET`, `FREEDOM_LS_ICON_OVERRIDES`,
   `FREEDOM_LS_ICON_BACKEND`.
3. `IconsConfig` overrides `__getattr__` for the three renamed names. It returns the new name's
   value when that is set, otherwise the old name's value read from `django.conf.settings` when
   that is set, otherwise `super().__getattr__` (the default). "Set" follows `AppSettings`: present,
   strings stripped, and a value other than `None` or `""`. One helper in `config.py` applies that
   rule, and both this resolver and the deprecation check call it. A fallback read emits no Python
   warning.
4. New checks, one id per old name: `icons.W002` (`FREEDOM_LS_ICON_SET`), `icons.W003`
   (`FREEDOM_LS_ICON_OVERRIDES`), `icons.W004` (`FREEDOM_LS_ICON_BACKEND`). Each fires when its old
   name is set. The message names the replacement. When the new name is also set, it says the old
   one is ignored. The hint gives the rename line, says the old name goes in the next tag, and names
   the id for `SILENCED_SYSTEM_CHECKS`. With default settings the app produces no check output.

### Icon data (`freedom_ls/icons/data/`, `loader.py`, `checks.py`)

5. Bundled data has the same layout as `node_modules/@iconify-json`, so one lookup serves both
   roots:

   ```
   freedom_ls/icons/data/
     manifest.json
     heroicons/icons.json   heroicons/LICENSE
     lucide/icons.json      lucide/LICENSE
     tabler/icons.json      tabler/LICENSE
     ph/icons.json          ph/LICENSE
   ```

   Each `icons.json` holds the upstream `prefix`, the root `width` and `height` when upstream has
   them, and `icons` entries copied verbatim for exactly the set's required glyphs. Everything else
   (`aliases`, `info`) is dropped, since the loader reads none of it. `manifest.json` records, per
   set: npm package, exact version, SPDX licence id, licence URL from upstream `info.json`, and the
   sorted glyph list. It has no timestamps.
6. Each `LICENSE` is the upstream licence text from the repository at the URL in its `info.json`,
   since the npm packages carry none. It is copied verbatim, except for what the repo's
   `trailing-whitespace` and `end-of-file-fixer` hooks change. Lucide's file includes its Feather
   MIT notice.
7. `required_glyphs(set_name: str) -> set[str]` lives in `mappings.py`, beside `ICON_SETS`. The
   generator and the app's data test both call it.
8. `loader.py` drops `iconify_json_path` and every `BASE_DIR` read. A set's file is
   `<root>/<PACKAGE_MAP[set]>/icons.json`, where the root is the bundled data directory (found from
   the module's location) or `SEMANTIC_ICONS_ICONIFY_DIR`.
   - `load_iconify_data(set_name)` returns bundled data merged with the configured directory's file
     for that set, when the setting is set and the file exists. Directory entries replace bundled
     entries of the same name. The merged root `width` and `height` are the bundled file's. An
     entry whose effective size differs from that root carries explicit `width` and `height`.
   - The cache is keyed on `(set_name, resolved directory or None)`, so `override_settings` of the
     directory never serves data cached under another value.
   - A public `clear_cache() -> None` empties it. `_cache` stays private to `loader.py`.
9. `icons.E008` fires when `SEMANTIC_ICONS_ICONIFY_DIR` is set but is not an absolute path to an
   existing directory. It names the value and says to fix the path or remove the setting to use
   bundled data.
10. `icons.E002` keeps its id and is rewritten. With the directory set and E008 not firing, it
    fires when the directory has no `<package>/icons.json` for the active set. It gives the full
    path it looked for, and its hint names `SEMANTIC_ICONS_ICONIFY_DIR` and the
    `node_modules/@iconify-json` layout. Without the directory set, it fires only when the bundled
    file is missing. No message mentions `npm install`. `icons.E006` gains a hint: pick a glyph in
    the active set's bundled data, or point `SEMANTIC_ICONS_ICONIFY_DIR` at full data that has it.

### Generator (`scripts/generate_icon_subset.py`)

11. A new top-level `scripts/` directory, a namespace package with no `__init__.py`, matching the
    repo's mypy config, holds the fully typed `generate_icon_subset.py`. Run it with
    `uv run python scripts/generate_icon_subset.py`. It reads
    `node_modules/@iconify-json/<package>/{icons.json,package.json,info.json}` (or `--source`) and
    writes the bundled `icons.json` files and `manifest.json`, never `LICENSE`. A maintainer reruns
    it whenever a mapping or an upstream version changes.
12. A pure `build_subset(upstream: IconifyData, glyphs: set[str]) -> IconifyData` holds the subset
    logic. `main()` does all the I/O, and the module does nothing on import.
13. Output is deterministic: sorted keys, two-space indent, a trailing newline and no trailing
    spaces. Unchanged input gives an empty diff, and each file stays under the 1 MB
    `check-added-large-files` limit.
14. It exits non-zero, naming the semantic name, set and glyph, when a required glyph is missing
    upstream, and with `Run npm install first.` when the source directory is absent. It prints a
    per-set summary of versions, glyph counts and bytes written, old to new. `--check` writes
    nothing and exits 1 when the committed data differs.

### Tests

15. `freedom_ls/icons/tests/standalone_settings.py` holds `SECRET_KEY`, `DATABASES = {}`,
    `INSTALLED_APPS = ["django_cotton.apps.SimpleAppConfig", "freedom_ls.icons"]`, and cotton
    `TEMPLATES` as `freedom_ls/panel_framework/tests/standalone_settings.py` has them. It leaves
    `SEMANTIC_ICONS_ICONIFY_DIR` unset.
16. `freedom_ls/icons/tests/standalone_pytest.ini` follows the panel framework's: a file name pytest
    does not discover, `pythonpath = ../../..`, `--ds=freedom_ls.icons.tests.standalone_settings`,
    `--strict-markers` and socket blocking. Its rootdir keeps `freedom_ls/conftest.py` out. CI runs
    `uv run pytest -c freedom_ls/icons/tests/standalone_pytest.ini freedom_ls/icons/tests` after the
    panel framework's standalone step in `.github/workflows/tests.yml`.
17. Every icons test passes under both settings modules. A fixture in
    `freedom_ls/icons/tests/conftest.py` pins the data source, either bundled only or a given
    directory, and tests that depend on it use the fixture. Tests that need a glyph outside the
    required glyphs (`star` overrides, `check-circle`, `phosphor:drone`) stub the loaded data, as
    `test_render.py` does.
18. In `freedom_ls/icons/tests/invariants/`:
    - An AST import guard, modelled on `freedom_ls/panel_framework/tests/test_import_guard.py`, fails
      on any `freedom_ls.*` import outside `freedom_ls.icons` in any `.py` under the app. It also
      fails on any `BASE_DIR` name, attribute or `getattr(settings, "BASE_DIR")`.
    - A standalone-run test, active only when `request.config.inipath` is the standalone ini,
      asserts that `settings.SETTINGS_MODULE` is the standalone module. It also asserts that no
      `freedom_ls.*` module outside `freedom_ls.icons` is in `sys.modules`.
    - A bundled-data test: for each set, the glyphs in its `icons.json` equal
      `required_glyphs(set)`, the manifest's sets, versions and glyph lists match the files, and
      every set has a non-empty `LICENSE`.
19. `tests/test_generate_icon_subset.py` imports `scripts.generate_icon_subset`. It runs
    `build_subset` over `node_modules/@iconify-json` and compares the result with the committed
    data. It fails, rather than skips, when `node_modules` is missing or an installed version
    differs from the manifest, and names the regenerate command. CI's `unit-tests` job provides
    `node_modules` through `npm ci`. It also covers `build_subset` on small fixture data. A
    `[[tool.test_tiers.tooling]]` entry in `pyproject.toml` maps `scripts/generate_icon_subset.py`
    and `freedom_ls/icons/data/**` to it.
20. Each behaviour in requirements 3, 4 and 8 to 10 has a test, and default settings produce no
    check output.

### FLS outside the app

21. `invariants/test_no_font_awesome.py` moves to `freedom_ls/base/tests/invariants/`. It locates
    `icon.html` through `importlib.util.find_spec("freedom_ls.icons")`, with no import statement,
    so `lint-imports` stays clean and the test survives the app's later move.
22. `config/settings_base.py` sets `SEMANTIC_ICONS_SET` and
    `SEMANTIC_ICONS_ICONIFY_DIR = BASE_DIR / "node_modules" / "@iconify-json"`, and sets no old
    name.
23. Outside `config.py`'s deprecation map, the deprecation checks, their tests and
    `upgrade_notes.md`, no code, test, comment or doc names a `FREEDOM_LS_ICON_*` setting (re-grep,
    excluding `spec_dd/` and `.claude/agent-memory/`). Nothing outside `loader.py` touches `_cache`.
    `freedom_ls/conftest.py` no longer mentions `node_modules`, and `settings.BASE_DIR = tmp_path`
    stays for the legal-doc loader.
24. `package.json` moves the four `@iconify-json` packages from `dependencies` to `devDependencies`.

## Open questions

- Q: May `SEMANTIC_ICONS_ICONIFY_DIR` be relative? → A: No, `icons.E008` requires an absolute path
  (assumed default: a relative path resolves against the working directory at startup, which
  differs between `manage.py`, gunicorn and tests. Overrule by editing requirement 9.)
- Q: How is Lucide's `LICENSE` obtained? → A: A maintainer copies it by hand from upstream, again
  only when upstream changes it (assumed default: the generator stays offline and deterministic.
  Overrule by editing requirement 6.)

## Success criteria

- `uv run pytest -c freedom_ls/icons/tests/standalone_pytest.ini freedom_ls/icons/tests` and the
  main `uv run pytest` both pass, and `lint-imports` is clean.
- `uv run python scripts/generate_icon_subset.py --check` exits 0 on the committed data.
- Under FLS dev settings, a course whose `icon_fallback` is `heroicons:scale` saves and renders
  that glyph.
