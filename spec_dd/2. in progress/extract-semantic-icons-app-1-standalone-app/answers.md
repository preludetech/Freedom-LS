# Answers: extract-semantic-icons-app-1-standalone-app

Asked by `/sdd:start` before the spec was written.

- Q: When `SEMANTIC_ICONS_ICONIFY_DIR` is set but the directory does not exist, or a set in it lacks an icon the bundled subset has, what should happen? → A: A configured directory that does not exist is a startup system-check error. An icon missing from the directory's set falls back to the bundled subset, icon by icon. (asked up front)
- Q: How should the deprecated `FREEDOM_LS_ICON_*` settings announce themselves? → A: A system check warning (`icons.W0xx`) for each old name that is set, naming its replacement, shown by `manage.py check` and runserver and silenceable through `SILENCED_SYSTEM_CHECKS`. (asked up front)
- Q: Should the subset generator be a Python or a Node script, given it only reads JSON from `node_modules/@iconify-json`? → A: A Python script outside the app (e.g. `scripts/`), run with `uv run python …` after `npm install`; the drift test imports its pure subset function. (asked up front)
- Q: How should the app's tests, under their own minimal Django settings, run alongside the main FLS suite? → A: A separate pytest run. The main `uv run pytest` excludes `freedom_ls/icons/tests`; a second invocation with the app's own config runs them, wired into the project's test tiers. (asked up front; superseded below)
- Q: Excluding the icons tests from the main run makes the tier selector run nothing for icons changes and drops them from the 92% coverage gate. Run in both, or exclude? → A: Run in both, like the panel framework. The icons tests stay in the main run and also run standalone through `pytest -c freedom_ls/icons/tests/standalone_pytest.ini` as a CI step. They must pass under either settings module. (asked while the research ran; replaces the answer above)
- Q: Authored literal glyphs (`Course.icon`/`icon_fallback`, admonition `icon_fallback`, e.g. `heroicons:scale`) break outside the bundled subset. What should FLS and First-Class do? → A: Hosts keep full data. FLS settings set `SEMANTIC_ICONS_ICONIFY_DIR` to `node_modules/@iconify-json`; the upgrade notes tell First-Class to set it too and to keep its Dockerfile copy of `@iconify-json`. The subset is the zero-config default for new hosts. (asked while the research ran)
