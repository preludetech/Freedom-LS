### 1a. `panel_framework/events.py` and `success_events`

New module `freedom_ls/panel_framework/events.py`:

```python
CLOSE_MODAL_EVENT = "closeModal"
INSTANCE_TITLE_EVENT = "instanceTitleChanged"

def build_hx_trigger(events: dict[str, list[str]], *, close_modal: bool = False, title: str | None = None) -> str:
    payload: dict[str, object] = {name: {"ids": ids} for name, ids in events.items()}
    if close_modal:
        payload[CLOSE_MODAL_EVENT] = {}
    if title is not None:
        payload[INSTANCE_TITLE_EVENT] = {"title": title}
    return json.dumps(payload)
```

`PanelAction` (`actions.py`) gains:

```python
success_events: tuple[str, ...] = ()

def get_success_events(self, instance: Model | None) -> dict[str, list[str]]:
    ids = [str(instance.pk)] if instance is not None else []
    return {name: list(ids) for name in self.success_events}
```

`EditAction.__init__` and `DeleteAction.__init__` take `success_events: tuple[str, ...] = ()`
and store it on the instance.

### 2a. The host and `appModal`

`panel_framework/templates/panel_framework/partials/modal_host.html` (requirement 9):

```html
<dialog id="app-modal" x-data="appModal" aria-labelledby="app-modal-title"
        class="modal-backdrop-host ...">
    <div data-modal-discard-prompt hidden>
        <p>Discard changes?</p>
        <c-button-group variant="right">
            <c-button variant="secondary" x-on:click="keepEditing">Keep editing</c-button>
            <c-button variant="error" x-on:click="discard">Discard</c-button>
        </c-button-group>
    </div>
    <button type="button" x-on:click="requestClose" aria-label="Close"><c-icon name="close" class="size-6" /></button>
    <div id="app-modal-body"></div>
</dialog>
```

Its `<style>` block in `@layer components` sizes the dialog and locks page scroll with
`html:has(#app-modal:modal) { overflow: hidden; scrollbar-gutter: stable; }` (requirement 13's
rule, split so each host locks scroll for its own dialog). `educator_interface/interface.html`
and `panel_framework/tests/templates/panel_framework/test_interface.html` fill
`{% block modal_host %}` with an include of it. Until 2b lands nothing targets the host, so the
old modal keeps working.

`Alpine.data("appModal")` in `panel_framework/static/panel_framework/js/alpine-components.js`.
Two module-level functions in that file serve both this component and `quickView`:
`trackListener(handlers, target, type, handler)` adds a listener and records it so `destroy()`
can remove every entry, and `focusTriggerOrMain(trigger)` focuses the trigger when it is still
in the DOM and `#main-content` otherwise. `_main_base.html` gives `#main-content`
`tabindex="-1"` so it can take focus. Behaviour in this slice:

```
init():
  dialog = $el, body = #app-modal-body
  document htmx:beforeRequest: if detail.target === body and !dialog.open → this._trigger = detail.elt
  document htmx:afterSwap (target === body):
      if !dialog.open → dialog.showModal()          # autofocus in the fragment takes focus
      else if xhr.status === 422 → focus body [data-error-summary] or first [aria-invalid="true"]
      else → focus body [autofocus]
  document htmx:afterSwap (target is #main-content): if this._trigger and document.activeElement === document.body → focus #main-content; this._trigger = null
  document.body closeModal → dialog.close()
  dialog close → body.innerHTML = ""; hide prompt; focusTriggerOrMain(this._trigger)
requestClose(): dialog.requestClose() when the method exists, else dialog.close()
```

The `#main-content` swap listener exists because htmx handles `HX-Trigger` before `HX-Location`:
on a "Save", `closeModal` focuses the trigger, then the navigation swap removes it, so focus
would otherwise drop to `<body>`.

Slice 3 adds the dirty guard, cancel, backdrop and history listeners to the same component. The
modal opens above an open quick view because `showModal()` puts it in the top layer; no code
handles that.

Test (`panel_framework/tests/test_templates.py` or `test_htmx_navigation.py`): a full-page render
through the stub host contains exactly one `id="app-modal"` and it sits outside `#main-content`,
so a navigation response never carries a second one.

## Slice 3: dirty guard, cancel, backdrop and the read-only fragment

Requirements 10 (dirty guard, cancel, `requestClose`, backdrop click), 11, 16 (read-only), 24
(modal half).

`appModal` additions:

```
after every swap into body: form = body.querySelector("form"); this._snapshot = form ? new FormData(form) : null; this.dirty = false
body input / change (delegated): this.dirty = form exists and serialised FormData differs from snapshot
dialog cancel: if this.dirty → event.preventDefault(); show [data-modal-discard-prompt]; focus "Keep editing"
keepEditing(): hide prompt; focus first field
discard(): dialog.close()          # the only caller of close() from a button
dialog click: if event.target === dialog and !body.querySelector("form") → dialog.close()
document htmx:beforeHistorySave: if dialog.open → dialog.close()
```

Comparing snapshots: serialise both `FormData` objects to `[name, value]` pairs in their natural
order (both come from the same form element) and compare the joined strings, so a field edited
then changed back reads clean. Add the requirement 11
comment above the `cancel` listener: a second Esc before any other user activation cannot be
cancelled under CloseWatcher rules, so the dialog closes and typed input is lost.

    refresh_events = (LEARNER_CHANGED,)
