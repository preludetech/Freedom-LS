# Frontend QA: panel framework dialogs, the modal and the quick view

Browser checks for the shared native modal, the quick-view drawer and the declared domain events.
Run them at a desktop viewport unless a test says otherwise.

## 0. Setup

```
npm run tailwind_build
PORT=$(.claude/ds/scripts/find_available_port.sh)
uv run python manage.py runserver $PORT
```

Base URL: `http://127.0.0.1:$PORT`.

Seed data (site name is the one your dev database uses, `DemoDev` in the examples below):

```
uv run python manage.py qa_create_educator_modal_target DemoDev
```

That creates the educator `qa_educator@example.com` (password is the email) with view and delete
rights on the cohort "QA Modal Cohort", one learner member `qa_modal_learner@example.com`, and a
course registration for the cohort. Also log in as the admin from `.claude/fls-dev/config.md`
(`demodev@email.com`), who sees every organisation and holds every permission. If the default
organisation has fewer than three learners or two cohorts, ask the `fls-dev:qa-data-helper` agent
for two more learners, one of them in two cohorts, and one learner with a course progress record
that has a `last_accessed_time`.

Open the educator interface at `/educator/` and note the organisation slug the redirect lands on.
The URLs below use `<org>` for it.

Keep the browser devtools open on the Network tab for the whole run, with "Preserve log" on.

## 1. Create cohort modal

Log in as the admin. Go to `/educator/<org>/cohorts`.

1. Click "Create Cohort". Expect: nothing opens until the request completes; the button is
   disabled while loading; then a centred dialog with the heading "Create Cohort", a Name field
   with the caret already in it, "Save and add another", "Save" and "Cancel" buttons, and a close
   button. The page behind is dimmed and does not scroll (scroll the wheel over the backdrop).
2. Type the name of a cohort that already exists ("QA Modal Cohort") and press Enter. Expect: the
   dialog stays open, an error summary appears above the form and receives focus (a focus ring on
   the summary, screen reader reads it), the Name field shows the "already exists" error, and the
   Network tab shows a 422.
3. Change the name to "QA Alpha" and click "Save and add another". Expect: the dialog stays open
   with a blank form, focus back in the Name field, and the cohort table behind the dialog now
   lists "QA Alpha" without a page reload (one GET of the list region in the Network tab).
4. Type "QA Beta" and click "Save". Expect: the dialog closes, the page navigates to the QA Beta
   cohort page inside `#main-content` (breadcrumbs and title update, no full reload), the URL is
   `/educator/<org>/cohorts/<pk>`, and the response headers of the POST show `HX-Trigger` naming
   `cohortChanged` and `closeModal`, `HX-Location`, and no `HX-Redirect`.
5. Press the browser Back button. Expect: the cohorts list, with no dialog open.
6. Click "Create Cohort" again, then press Tab to leave the Name field and press Esc. Expect: the
   dialog closes and focus is on the "Create Cohort" button (press Space to confirm it reopens).
7. Open it again, type one character, press Esc. Expect: the dialog stays open and shows "Discard
   changes?" above the form with "Keep editing" focused and the typed text still in the field.
   Click "Keep editing". Expect: the prompt hides and focus returns to the field. Press Esc again
   and click "Discard". Expect: the dialog closes and the cohort was not created.
8. Open it again, type one character, delete it, press Esc. Expect: the dialog closes with no
   prompt, because the form matches its original state.
9. Open it again, type something, and click on the dimmed backdrop outside the dialog. Expect:
   nothing happens; the form stays open.
10. Open it again, type something, press Esc (prompt shows), then press Esc a second time
    straight away. Expect: the dialog closes and the typed text is lost. This is the known
    CloseWatcher limit, not a bug.
11. Double-click "Save" quickly with a valid new name. Expect: exactly one POST in the Network
    tab and one new cohort.

## 2. Edit and delete modals

Go to `/educator/<org>/cohorts/<pk of QA Alpha>`.

1. In the Details panel click "Edit". Expect: the dialog opens with the heading "Edit QA Alpha"
   and the Name field prefilled and focused.
2. Rename it to "QA Alpha 2" and click "Save". Expect: the dialog closes, the page heading changes
   to "QA Alpha 2" without a reload, the Details panel refetches itself (one GET of the panel
   region), and the URL is unchanged.
3. Click "Delete". Expect: the dialog opens with a heading naming the cohort, a sentence saying
   what will also be deleted, and focus on "Cancel". Click the backdrop. Expect: the dialog stays
   open. Press Esc. Expect: it closes.
4. Click "Delete" again and confirm. Expect: the dialog closes and the page navigates to the
   cohorts list, which no longer lists the cohort.
5. Go to the "QA Modal Cohort" page and click "Delete". Expect: the dialog explains the cohort
   cannot be deleted because it still has a course progress record (if the seed learner has one),
   with no Delete button. If the seed data has no progress record, ask the data helper for one on
   this cohort and repeat. Click the backdrop. Expect: the dialog closes, because this fragment
   has no form.
6. Adversarial: in a second tab, log in as `qa_educator@example.com`. Go to the QA Modal Cohort
   page. Expect: the educator sees "Delete" but no "Edit" (no change permission), and the page
   loads with no form or cascade work visible in the HTML source. Now paste the delete action URL
   (`/educator/<org>/cohorts/<pk>/__panels/details/__actions/edit`) into the address bar. Expect: a
   403 page, not a form.
7. Adversarial: with the admin, GET `/educator/<org>/cohorts/__actions/create_cohort` directly in
   the address bar. Expect: a bare fragment (heading and form) with no page chrome. This is the
   fragment the modal fetches; it is not a supported page, so just confirm it is not an error.

## 3. Quick view on desktop

Go to `/educator/<org>/learners` at a viewport of at least 1024px wide.

1. Click a learner's first name. Expect: a drawer slides in from the right edge with the learner's
   name as its title, an "Open" link and a close button; a skeleton shows briefly, then the
   learner's name, email, status, cohorts, registered courses with percentages, and "Last active".
   Focus stays on the link you clicked (press Space to confirm it toggles). The page behind is not
   dimmed, and the table still scrolls and is clickable.
2. Click a different learner's name. Expect: the drawer content is replaced, the title changes,
   and the old link's `aria-expanded` returns to `false` (inspect it) while the new one is `true`.
3. Click the same learner's name again. Expect: the drawer closes. Click it once more. Expect: the
   drawer reopens with the same content and the Network tab shows no new request.
4. With the drawer open, press Esc. Expect: it closes and focus is on the link.
5. Hold Ctrl (Cmd on macOS) and click a learner's name. Expect: the learner page opens in a new
   tab and the drawer does not open. Middle-click and right-click "Open in new tab" behave the
   same.
6. Open a drawer and click "Open". Expect: the drawer closes and the browser navigates to the
   learner page.
7. Inside the learner drawer, click a cohort name. Expect: navigation to that cohort page.
8. Go to `/educator/<org>/cohorts`. Click a cohort name. Expect: the cohort drawer with name,
   status, learner count and courses. Click "Open". Expect: the cohort page.
9. On a learner page, in the Cohorts panel, click a cohort name. Expect: the cohort drawer opens
   from inside a panel, not just the section list.
10. On the Learners list, sort a column while a drawer is open. Expect: the table refetches, the
    drawer stays open, and the link for the shown learner still reports `aria-expanded="true"`.
11. Server error: in devtools, block requests whose URL contains `__quick-view` (Network tab,
    "Block request URL"). Click a learner. Expect: the drawer opens and shows an error message
    with a Retry button; the drawer does not close. Unblock the URL and click Retry. Expect: the
    content loads.
12. Staleness through a domain event: open a cohort's drawer from the cohorts list and note its
    pk from the Open link. In the console run
    `document.body.dispatchEvent(new CustomEvent("cohortChanged", {detail: {ids: ["<that pk>"]}}))`.
    Expect: the drawer refetches (one GET in the Network tab). Run it again with a made-up id.
    Expect: no request. Close the drawer, run it with the real pk, then click the same cohort
    again. Expect: a fresh request this time, because the content was marked stale.
13. Modal above the drawer: open a learner drawer on the cohorts page, then click "Create Cohort".
    Expect: the modal opens above the drawer; closing the modal leaves the drawer open.
14. Direct visit: paste a learner's `__quick-view` URL into the address bar. Expect: a redirect to
    the learner page, never a bare fragment.
15. Adversarial: log in as `qa_educator@example.com` in another tab and paste the `__quick-view`
    URL of a learner outside "QA Modal Cohort". Expect: 404. Paste
    `/educator/<org>/learners/not-a-uuid/__quick-view`. Expect: 404.
16. Print: with a drawer open, open print preview. Expect: the drawer is not on the page.
17. Reduced motion: in devtools Rendering, emulate `prefers-reduced-motion: reduce`. Open and
    close a drawer. Expect: it appears and disappears instantly.
18. RTL: in the console run `document.documentElement.dir = "rtl"`. Open a drawer. Expect: it is
    pinned to the left edge. Reset with `document.documentElement.dir = "ltr"`.

## 4. Quick view on mobile

Use device emulation at 375×750 (any phone preset).

1. Go to `/educator/<org>/learners` and tap a learner's name. Expect: a sheet slides up from the
   bottom over a dimmed page, with the same content as on desktop. The page behind does not scroll.
2. Press the browser Back button. Expect: the sheet closes and you are still on the learners page
   at the same URL.
3. Tap a learner again, then tap the close button. Expect: the sheet closes; pressing Back now
   leaves the learners page (the sheet's history entry was unwound).
4. Tap a learner again, then tap the dimmed backdrop. Expect: nothing happens (the drawer never
   dismisses on backdrop). Press Esc or use the close button.
5. Tap a learner, then tap "Open". Expect: the learner page loads. Press Back. Expect: the
   learners list with no sheet open.
6. Open a sheet, then widen the viewport past 768px. Expect: the same content is now the right-hand
   drawer with no new request. Narrow it again. Expect: it becomes the sheet again.
7. Open a sheet, then open the mobile navigation panel. Expect: the two do not fight; whichever
   is on top can be dismissed and the other remains as it was.
8. On iOS Safari (real device or simulator) open the create cohort modal and try to scroll the
   page behind it. Expect: the page behind does not scroll. If it does, the fallback is the
   fixed-body technique named in the spec.

## 5. Screen reader

With VoiceOver (Safari, macOS or iOS) or NVDA (Windows):

1. Open the create cohort modal. Expect: the dialog is announced with its heading as its name,
   and reading order starts at the heading.
2. Submit a duplicate name. Expect: the error summary is announced.
3. Open a learner drawer. Expect: "Showing <learner name>" is announced once the content loads,
   and the drawer is reachable in the reading order with its heading as its name.

## 6. History and navigation side effects

1. Open the create cohort modal, then click "Learners" in the sidebar. Expect: the modal closes
   as the page navigates. Press Back. Expect: the cohorts page with no dialog.
2. Open a learner drawer, then click "Cohorts" in the sidebar. Expect: the drawer closes. Press
   Back. Expect: the learners page with no drawer.
3. Switch organisation from the sidebar switcher with a drawer open. Expect: the drawer closes and
   the switch works as before.
4. The sidebar and the organisation switcher still open and close as before this change, on both
   viewports.
