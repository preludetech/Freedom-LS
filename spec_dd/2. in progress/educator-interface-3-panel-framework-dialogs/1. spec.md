# Spec: panel framework dialogs, the modal and the quick view

Spec 3 of 12 in the educator interface rebuild. Written against `idea.md` and the research files
beside it. The "Educator interface rebuild" section of `spec_dd/1. next/roadmap.md` holds the build
order and the assumptions the effort shares. The mockups are in
`spec_dd/1. next/educator-interface-full-polish/Educator LMS Interface Design/`: `Educator
Learners.dc.html` screens 03 and 04, `Educator Mobile Learners.dc.html` screen M06, and `Educator
Cohorts and Admin.dc.html` screen 07.

## Purpose

The framework's modal (`cotton/modal.html`) is an Alpine `div` that never moves, traps or returns
focus. Every `FormPanelAction` and `DeleteAction` renders its form, or its cascade summary, on every
render of the owning panel. A validation error swaps the whole component and drops focus. The
quick view that the learner table, cohort detail and dashboard all need does not exist yet. Event
names are ad hoc: `panelChanged` fires on every edit and `get_created_event_name()` is chosen per
action.

This spec replaces the modal with one native `<dialog>` that loads its content on open, adds a
quick-view drawer fed by a framework route, and replaces the ad hoc events with declared domain
events. The learner and cohort quick views are the first consumers.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| modal | narrowed | The one shared `<dialog id="app-modal">` in the interface layout, not `cotton/modal.html`, which this spec deletes |
| modal fragment | coined | The HTML an action's GET returns into the modal body: a form, a destructive confirmation or read-only content, with its own heading |
| quick view | coined | The drawer `<dialog id="quick-view">` and the `QuickView` class that feeds it. Not a `Panel` |
| domain event | coined | A camelCase DOM event named in an `HX-Trigger` header after a successful mutation, with detail `{"ids": [...]}`. Distinct from the dotted webhook event types in `base/webhook_event_types.py` |

## Scope

In:

- The shared modal: host markup, the `appModal` Alpine component, the trigger cotton component, and
  fragments for form, destructive-confirmation and read-only content.
- `FormPanelAction`, `CreateInstanceAction`, `EditAction` and `DeleteAction` moved onto the modal,
  with lazy rendering, `HX-Location` and declared events.
- The domain-event mechanism, and the four educator-interface event names as constants.
- The quick view: host markup, the `quickView` Alpine component, the trigger cotton component, the
  `QuickView` class and its `__quick-view` route.
- A learner quick view and a cohort quick view, with triggers in the learner and cohort table
  cells.

Out:

- Deep-linking an open quick view (`?peek=`), pinning two quick views, drag-to-resize.
- A message composer. The drawer only has to be able to host one.
- A read-only modal consumer such as a topic preview. The modal supports read-only fragments and
  tests prove it, but the first real consumer comes in a later spec.
- Emitting `registrationChanged` or `educatorChanged`. This spec defines them. Specs 6 to 9 fire
  them.
- Learner "pending" status (spec 7) and `Cohort.is_active` (spec 6).
- Heavy flows such as CSV import and bulk review. These are pages, never modals, and spec 8 builds
  them.

## Decisions

- **The quick view endpoint is a framework route.** It is served at `<section>/<pk>/__quick-view`
  on a `ListViewConfig` that declares a `QuickView`, so authorisation, the plain-GET redirect and
  `Vary` come from the framework, not from each consumer.
- **Event detail is always `{"ids": [...]}`**, a list of string primary keys of the entity the
  event names. The framework's quick view compares ids without knowing entity types. This
  replaces the typed keys (`cohort_id`, `learner_id`) in `research_domain_events.md`. A mutation
  touching two entity types fires both events.
- **The page-title update moves to a framework event, `instanceTitleChanged`**, with detail
  `{"title": "..."}`, fired by `EditAction`. It is not a domain event and consumers do not declare
  it.
- **The modal closes on a framework event, `closeModal`**, named in the success `HX-Trigger`. A 204
  never swaps, so success cannot hang off `htmx:afterSwap`.
- **History restore: both dialogs close on `htmx:beforeHistorySave`.** `hx-preserve` is rejected
  because it is unverified for a `<dialog>`'s `open` state.
- **Close and cancel buttons call the component's `requestClose` method**, not invoker commands.
  Invoker commands need Safari 26.2 and `requestClose()` needs 18.4.
- **Scroll lock is CSS**: `html:has(#app-modal:modal, #quick-view:modal) { overflow: hidden;
  scrollbar-gutter: stable; }`. If iOS QA finds scroll leaking through, fall back to the
  fixed-body technique. `contentLightbox` keeps its own JS lock.
- **No `django-htmx`.** Headers are set by hand and `Vary` goes through the existing
  `_vary_on_htmx` (`panel_framework/views.py`), following spec 1.
- **A plain click on a quick-view trigger link opens the drawer.** The element stays an `<a href>`
  to the full page, so a modified click, a middle click or "open in new tab" still reaches the
  page.
- **"Last active" is the latest `CourseProgress.last_accessed_time`** across the learner's progress
  records, not `User.last_login`, which is site-wide and records a login rather than course
  activity.

## Requirements

### A. Domain events (`freedom_ls/panel_framework/`)

1. New module `panel_framework/events.py`:
   - Constants `CLOSE_MODAL_EVENT = "closeModal"` and
     `INSTANCE_TITLE_EVENT = "instanceTitleChanged"`.
   - `build_hx_trigger(events: dict[str, list[str]], *, close_modal: bool = False, title: str |
     None = None) -> str` returns the `HX-Trigger` JSON. Each domain event gets `{"ids": [...]}`,
     `closeModal` gets `{}` and `instanceTitleChanged` gets `{"title": title}`. Every action builds
     its header through this function.
2. `PanelAction` gains `success_events: tuple[str, ...] = ()` and
   `get_success_events(self, instance: Model | None) -> dict[str, list[str]]`. By default it maps
   each name in `success_events` to `[str(instance.pk)]`, or `[]` when there is no instance. An
   action whose mutation touches other entities overrides it.
3. `Panel` gains `refresh_events: tuple[str, ...] = ()`. `_panel_base.html` emits
   `hx-get`/`hx-trigger` only when the list is non-empty, with
   `hx-trigger="<e1> from:body, <e2> from:body"`. The literal `panelChanged` disappears from the
   template.
4. `ListViewConfig` gains `refresh_events: tuple[str, ...] = ()`. `_main_for`
   (`panel_framework/views.py`, the `created_events` block) passes it to `list_refresh.html` in
   place of the collected `get_created_event_name()` values. `listRefresh` is unchanged: it
   refetches on the name and ignores the detail.
5. The `panelChanged` listener in `panel_framework/static/panel_framework/js/alpine-components.js`
   listens for `instanceTitleChanged` instead and reads `detail.title`.
6. `get_created_event_name()` and every `panelChanged` reference are removed, including from
   `panel_framework/tests/stub_panels.py`, which declares a generic stub event such as
   `itemChanged`.

### B. Educator-interface event names (`freedom_ls/educator_interface/`)

7. New module `educator_interface/events.py` with `LEARNER_CHANGED = "learnerChanged"`,
   `COHORT_CHANGED = "cohortChanged"`, `REGISTRATION_CHANGED = "registrationChanged"` and
   `EDUCATOR_CHANGED = "educatorChanged"`. Specs 6 to 9 use these and add no others.
8. Existing wiring:
   - `CreateCohortAction.success_events = (COHORT_CHANGED,)`.
   - `CohortDetailsPanel`'s edit and delete fire `COHORT_CHANGED`.
   - `CohortConfig.refresh_events = (COHORT_CHANGED,)` and
     `LearnerConfig.refresh_events = (LEARNER_CHANGED,)`.
   - Every panel on the cohort detail page refreshes on `COHORT_CHANGED` and every panel on the
     learner detail page on `LEARNER_CHANGED`.
   - `InstanceDetailsPanel` passes its own `refresh_events` to the `EditAction` it builds as that
     action's `success_events`.

### C. Modal host and component

9. `panel_framework/templates/panel_framework/partials/modal_host.html` holds:

   ```html
   <dialog id="app-modal" x-data="appModal" aria-labelledby="app-modal-title"
           class="modal-backdrop-host ...">
     <div data-modal-discard-prompt hidden>…</div>
     <button type="button" @click="requestClose" aria-label="Close">…</button>
     <div id="app-modal-body"></div>
   </dialog>
   ```

   `educator_interface/templates/educator_interface/interface.html` fills
   `{% block modal_host %}` with it. The `<dialog>` sits outside `#interface-main`, so a
   `#main-content` swap never touches it.
10. `Alpine.data("appModal")` goes in `panel_framework/static/panel_framework/js/alpine-components.js`.
    It registers every listener in `init()` and cleans them up in `destroy()`. No `hx-on`, no
    trigger filters, no inline expressions. Spec 2 adds components to the same file, and
    whichever spec lands second rebases onto the other.
    - **Open.** On `htmx:afterSwap` whose target is `#app-modal-body`: if the dialog is closed,
      call `showModal()`. The fragment is already in the DOM, so native `autofocus` picks initial
      focus. If it is already open, the swap is a re-render, handled below.
    - **Re-render after a 422.** Move focus to the fragment's `[data-error-summary]` if present,
      otherwise to the first `[aria-invalid="true"]` field.
    - **Re-render after a 200 "save and add another".** Focus the first field.
    - **Success.** On `closeModal` on `document.body`, call `close()`.
    - **Close.** One `close` listener clears `#app-modal-body` and hides the discard prompt.
      Native focus return goes to the trigger.
    - **Dirty guard.** When a fragment containing a `<form>` swaps in, snapshot
      `new FormData(form)`. One delegated `input`/`change` listener recomputes it and sets
      `dirty` when it differs from the snapshot, so a field edited and then reverted reads clean.
      The snapshot is retaken after every re-render.
    - **Cancel.** One `cancel` listener on the dialog serves Esc and `requestClose()`. Clean, it
      lets the dialog close. Dirty, it calls `preventDefault()` and shows the discard prompt
      inline above the form, which stays intact underneath: "Discard changes?", with "Keep
      editing" (focused) and "Discard" (closes). It is not a nested dialog.
    - **`requestClose` method.** Calls `this.$el.requestClose()`. Every close and cancel button
      in the shell and in fragments uses it, never `close()`, so the guard always runs.
    - **Backdrop click.** A click whose `event.target` is the dialog itself closes it only when
      the body contains no `<form>`, which means read-only content. It never closes a form or a
      destructive confirmation. This stays hand-written until Safari ships `closedby`.
11. Known platform limit, documented in a code comment and in QA: a second Esc pressed before any
    other user activation cannot be cancelled (CloseWatcher rules), so the dialog closes and the
    typed input is lost. Nothing in the component can prevent this.
12. No nested modals. A confirmation inside a flow replaces the body. The modal may open above an
    open quick view, including the mobile modal quick view.
13. Page scroll locks through the CSS rule in Decisions, which lives in the host partial or the
    component's styles.

### D. Modal triggers and fragments

14. New cotton component `cotton/modal-trigger.html` renders a `<c-button>` with
    `hx-get="{{ url }}" hx-target="#app-modal-body" hx-swap="innerHTML" hx-disabled-elt="this"`,
    `aria-haspopup="dialog"` and no URL push. Attributes are `url`, `label` and `variant`.
15. `PanelAction` separates the trigger from the fragment:
    - `trigger_template_name`, rendered by `{% render_action %}` from cheap context (label,
      variant, action URL). For modal actions this renders `<c-modal-trigger>`.
    - `template_name`, the modal fragment, rendered only by `_handle_action` on GET, from
      `get_context_data(ctx)`.

    `FormPanelAction.get_context_data` builds the form and `DeleteAction.get_context_data` runs
    `get_cascade_summary`, both only on that GET. Nothing form- or cascade-related runs on a panel
    render.
16. Fragment templates, each opening with `<h2 id="app-modal-title">` and carrying no `modal_open`
    flag:
    - `panel_framework/modal/form.html`: `<form hx-post="{{ form_url }}" hx-target="this"
      hx-swap="outerHTML">`. The form posts to itself and swaps itself. The first field gets
      `autofocus`. On errors the fragment renders `[data-error-summary]` with `tabindex="-1"` and
      invalid fields carry `aria-invalid="true"`. Cancel calls `requestClose`.
    - `panel_framework/modal/delete_confirmation.html`: the cascade summary or the blocked reason,
      Cancel with `autofocus`, and a delete `<form hx-delete ... hx-target="this"
      hx-swap="outerHTML">`.
    - `panel_framework/modal/read_only.html`: a base for read-only content. The heading gets
      `tabindex="-1"` and `autofocus`, and the content sits at reading width.
17. Response contract:

    | Case | Status | Headers | Body |
    | --- | --- | --- | --- |
    | GET action URL | 200 | none | fragment |
    | Validation error | 422 | none | form fragment with errors |
    | `DeleteAction` hits `ProtectedError` at submit | 422 | none | confirmation with blocked reason |
    | Create, "save and add another" | 200 | `HX-Trigger`: domain events | blank form fragment |
    | Create, "Save" | 204 | `HX-Trigger`: `closeModal` plus domain events; `HX-Location: {"path": success_url, "target": "#main-content", "swap": "outerHTML"}` | none |
    | Edit | 204 | `HX-Trigger`: `closeModal`, domain events, `instanceTitleChanged` | none |
    | Delete | 204 | `HX-Trigger`: `closeModal` plus domain events; `HX-Location` to `success_url` as above | none |

    No panel action sets `HX-Redirect`. The 422 swap relies on the existing
    global `htmx:beforeSwap` handler in `base/static/base/js/alpine-components.js`.
18. Deleted: `cotton/modal.html`, `panel_framework/partials/modal_form.html`,
    `panel_framework/partials/delete_confirmation.html`, and `Alpine.data("modal")` in
    `base/static/base/js/alpine-components.js`, which has no other user. The `.modal-backdrop`
    theme class loses its only user and stays defined; see Open questions.

### E. Quick view framework

19. New module `panel_framework/quick_view.py`:

    ```python
    class QuickView:
        template_name: str
        refresh_events: tuple[str, ...] = ()

        def __init__(self, request: HttpRequest, instance: Model) -> None: ...
        def get_title(self) -> str: ...        # default str(instance)
        def get_context_data(self) -> dict[str, object]: ...
    ```

    `ListViewConfig` gains `quick_view: type[QuickView] | None = None`.
20. `_resolve_path` accepts a terminal `__quick-view` segment directly after an instance's pk on a
    `ListViewConfig`:
    - Access runs through `get_instance_view`, and therefore `check_access` and
      `authorise_instance`. An out-of-scope instance, a config with no `quick_view` or a malformed
      pk is a 404. The route adds no permission check of its own.
    - An htmx GET renders `panel_framework/quick_view/frame.html`. The frame wraps the consumer's
      `template_name` in a root carrying `data-quick-view-title`, `data-refresh-events` (space
      separated) and `data-entity-id`.
    - A non-htmx GET redirects (302) to the instance page, `<section>/<pk>`.
    - Every response goes through `_vary_on_htmx`, so it carries `Vary: HX-Request`. No HTTP
      caching headers are set.
21. `panel_framework/templates/panel_framework/partials/quick_view_host.html`, which
    `educator_interface/interface.html` puts in `{% block quick_view_host %}`, holds a
    `<dialog id="quick-view" x-data="quickView" aria-labelledby="quick-view-title">` containing:
    - A sticky header with `#quick-view-title`, an "Open" link (`#quick-view-open`) to the
      trigger's `href`, and a close button calling `requestClose`.
    - `#quick-view-body`, with internal scroll.
    - A `<template>` skeleton and a `<template>` error block with a Retry button.

    Outside the dialog, present from page load, sits a visually hidden
    `<div id="quick-view-status" aria-live="polite" aria-atomic="true">`.

    Styling:
    - Desktop: pinned to `inset-inline-end: 0`, full height, about 480px (`30rem`) inline size,
      no backdrop.
    - Below `md`: a modal sheet.
    - Logical properties throughout, so RTL flips. `@starting-style` entry slide.
      `prefers-reduced-motion` gives an instant change.
    - Exit animation where `allow-discrete` works. Firefox closes instantly.
    - `@media print { #quick-view { display: none } }`.
22. New cotton component `cotton/quick-view-trigger.html` renders:

    ```html
    <a href="{{ href }}" hx-get="{{ url }}" hx-target="#quick-view-body"
       hx-swap="innerHTML" hx-sync="#quick-view-body:replace"
       aria-controls="quick-view" aria-expanded="false"
       data-quick-view-title="{{ title }}" {{ attrs }}>{{ slot }}</a>
    ```

    `hx-push-url` is not set. Extra `data-*` attributes the caller passes, such as cohort and
    status, are shown in the skeleton.
23. `Alpine.data("quickView")` goes in the same JS file and copies `sidePanel`'s modal/non-modal
    skeleton without sharing code with it. It has its own `md` breakpoint (`min-width: 768px`),
    no `localStorage`, and no close-on-`htmx:beforeRequest`. Behaviour:
    - **Before a request** (`htmx:confirm` from a trigger):
      - If the trigger's URL is the one shown and the drawer is open, cancel the request and
        close.
      - If it is the one shown, the drawer is closed and the content is not stale, cancel the
        request and reopen.
      - Otherwise let the request run.
    - **Opening for a request.** Open if closed: `show()` at `md` and up, `showModal()` below.
      Fill the title and Open link from the trigger. Clone the skeleton, including the trigger's
      `data-*` values. Set `aria-busy="true"` on the body. Set `aria-expanded="true"` on this
      trigger and `false` on the previous one.
    - **Desktop focus.** After `show()`, return focus to the trigger. No focus trap, no scroll
      lock, and clicking outside does not dismiss.
    - **After the swap** (`htmx:afterSwap` on `#quick-view-body`), in one handler:
      - Clear `aria-busy`.
      - Take the title from the frame's `data-quick-view-title`.
      - Write "Showing <title>" to `#quick-view-status`.
      - Register the listeners named in the frame's `data-refresh-events`, dropping the previous
        set.
    - **Errors.** On `htmx:responseError` or `htmx:sendError` for the body, render the error
      template inline. Retry re-requests the last URL. The drawer never closes itself on error.
    - **Staleness.** When a registered event's `detail.ids` contains the shown `data-entity-id`,
      refetch if the drawer is open, or mark the content stale if it is closed. Events naming
      other ids do nothing.
    - **Closing.** Close hides the drawer without clearing it. Focus returns to the trigger,
      falling back to `#main-content` if the trigger has left the DOM. Esc closes, handled
      natively in modal mode and by a document `keydown` listener in non-modal mode while no
      modal dialog is open.
    - **Mobile history.** A modal open pushes one history entry and Back closes the drawer. A
      close by any other route calls `history.back()` unless Back caused it, following
      `sidePanel`'s `_closingFromPopstate` guard.
    - **Open link.** Following it closes the drawer first. On mobile the drawer's history entry
      is replaced, not left behind.
    - **Breakpoint change while open.** Close, then reopen in the other mode with the same
      content and no request.
    - **Tables that refetch.** The trigger for the shown URL reports `aria-expanded="true"` again
      after a table refetch.
24. On `htmx:beforeHistorySave`, both `#app-modal` and `#quick-view` close so a restored snapshot
    never reopens a dialog. The mobile quick view's pushed history entry is unwound first.

### F. Learner and cohort quick views

27. Registrations come from a new helper in `freedom_ls/learner_progress/queries.py`,

    `progress_percentage: int | None` and `last_accessed_time: datetime | None`. The helper covers
    only active registrations and costs a fixed three queries whatever the registration count:
    - active `LearnerCourseRegistration` rows,
    - active `CohortCourseRegistration` rows through the learner's memberships,
    - `CourseProgress.objects.filter(learner=learner)`, matched on `learner_registration_id` or
      `cohort_registration_id`.

    It is keyed on the `Learner`, not the `User`, so it never crosses organisations.
    `learner_progress` already depends on `learner_management`, so the helper adds no new app
    dependency.
28. Cohort fields:
    - Name.
    - Status: "Active" as a placeholder until spec 6 adds `Cohort.is_active`, marked the same way
      with `{# TODO spec 6 #}`.
    - Learner count, the same `Count("cohortmembership", distinct=True)` as `CohortDataTable`.
    - Courses, from `course_registrations__course`.
    - The drawer's Open link goes to the cohort page.
29. Triggers:

      renders `<c-quick-view-trigger>` with `href` set to the resolved URL, `url` set to the
      resolved URL plus `/__quick-view`, and the cell text as `title`, in place of the plain or
      `htmx_nav` link.
    - The learner name columns in `LearnerDataTable` and `CourseLearnerRegistrationDataTable`, and
      the name column in `CohortDataTable`, set it.
    - `educator_interface/data-table-cells/cohort_links.html` renders each cohort link through the
      same trigger.
30. The `@claude` comment in `educator_interface/data-table-cells/learner_courses.html` stays.

## Testing

pytest, in `panel_framework/tests/` and `educator_interface/tests/`:

- `build_hx_trigger` produces the exact JSON for one event, two events, `closeModal` and
  `instanceTitleChanged`, and ids are always lists of strings.
- Each row of the response-contract table in requirement 17 is proved by a test that asserts the
  status, the exact headers and the absence of `HX-Redirect`. This rewrites the affected tests in
  `test_panel_actions.py`, `test_configs.py:197`, `test_cohort_delete_action.py` and
  `test_create_cohort_action.py`.
- Lazy rendering: a panel render calls neither `FormPanelAction.get_form` nor
  `DeleteAction.get_cascade_summary`, and the rendered panel contains a trigger with no `<form>`.
- `_panel_base.html` emits `hx-trigger` for the declared `refresh_events` and nothing when there
  are none. This replaces the `panelChanged` assertions in `test_templates.py:101` and
  `test_data_table_panel.py:59`.
- `ListViewConfig.refresh_events` reaches `data-refresh-events`.
- Quick-view route:
  - An in-scope learner and cohort return 200 with the frame's data attributes.
  - An out-of-scope instance, a config without `quick_view` and a malformed pk each return 404.
  - A non-htmx GET returns 302 to the instance page.
  - `Vary` includes `HX-Request`.
- `LearnerQuickView` hides a membership in a cohort the viewing instructor cannot see.
- `registrations_with_progress_for_learner` covers an individual registration, a registration
  through a cohort, a registration without a `CourseProgress` record and an inactive registration.
  It runs in exactly three queries (`django_assert_num_queries`) for one and for many
  registrations, and ignores a second organisation's `Learner` for the same `User`.
- `link.html` with `quick_view` renders the trigger attributes, and without it renders as today.

Playwright, under `tests/playwright/` and marked `@pytest.mark.playwright`:

- Modal, form:
  - Opening puts focus in the first field.
  - A 422 moves focus to the error summary.

  - "Save" closes the modal and navigates `#main-content` with a history entry, and Back works.
  - Esc on a clean form closes it.
  - Esc on a dirty form shows the discard prompt with the form intact. "Keep editing" returns to

## Open questions

Defaults taken; overrule any of them.

- The `.modal-backdrop` theme class (in `tailwind.components.css`, `docs/how tos/theme-fls.md` and
  the frontend-styling skill) has no user after this spec. The default keeps it defined, so theme
  overrides don't break, and leaves retiring it to spec 12.
- The cohort quick view is reachable from the `CohortDataTable` name column and from a learner
  row's cohort links. The idea names no trigger site for it, so these are the default.
- A quick-view trigger shows a skeleton immediately. A modal trigger shows only the disabled
  button (`hx-disabled-elt`) while its fragment loads. Nothing opens until the fragment is back, so
  native `autofocus` keeps working.
