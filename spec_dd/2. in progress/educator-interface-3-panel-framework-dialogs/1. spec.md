# Spec: panel framework dialogs, the modal and the quick view

Spec 3 of 12 in the educator interface rebuild. `idea.md` gives the reasons for this work and the
research files beside it give the evidence. The "Educator interface rebuild" section of
`spec_dd/1. next/roadmap.md` holds the build order and shared assumptions. Mockups are in
`spec_dd/1. next/educator-interface-full-polish/Educator LMS Interface Design/`: `Educator
Learners.dc.html` screens 03 and 04, `Educator Mobile Learners.dc.html` screen M06, and `Educator
Cohorts and Admin.dc.html` screen 07.

This spec replaces `cotton/modal.html` with one native `<dialog>` that loads its content when it
opens. It adds a quick-view drawer fed by a framework route, and replaces `panelChanged` and
`get_created_event_name()` with declared domain events. The first consumers are the learner and
cohort quick views.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| modal | narrowed | The one shared `<dialog id="app-modal">` in the interface layout, not `cotton/modal.html`, which this spec deletes |
| modal fragment | coined | The HTML an action's GET returns into the modal body: a form, a destructive confirmation or read-only content, with its own heading |
| quick view | coined | The drawer `<dialog id="quick-view">` and the `QuickView` class that feeds it. It fills the `quick_view_host` block spec 1 reserved. Not a `Panel` |
| domain event | coined | A camelCase DOM event named in an `HX-Trigger` header after a successful mutation, with detail `{"ids": [...]}`. Distinct from the dotted webhook event types in `base/webhook_event_types.py` |

## Scope

Out:

- Deep-linking an open quick view (`?peek=`), pinning two quick views, drag-to-resize.
- A message composer. The drawer only has to be able to host one.
- A real read-only modal consumer such as a topic preview. Tests prove read-only fragments work.
- Firing `registrationChanged` or `educatorChanged`. Specs 6 to 9 fire them.
- Learner "pending" status (spec 7) and `Cohort.is_active` (spec 6).
- Heavy flows such as CSV import and bulk review. These are pages, never modals (spec 8).
- `django-htmx`. Headers are set by hand, and `Vary` goes through the existing `_vary_on_htmx`
  in `panel_framework/views.py`, as spec 1 does.

## Requirements

### A. Domain events (`freedom_ls/panel_framework/`)

1. New module `panel_framework/events.py`:
   - Constants `CLOSE_MODAL_EVENT = "closeModal"` and
     `INSTANCE_TITLE_EVENT = "instanceTitleChanged"`. Neither is a domain event, and consumers do
     not declare them.
   - `build_hx_trigger(events: dict[str, list[str]], *, close_modal: bool = False, title: str |
     None = None) -> str` returns the `HX-Trigger` JSON. Each domain event gets `{"ids": [...]}`,
     a list of string primary keys of the entity the event names. `closeModal` gets `{}` and
     `instanceTitleChanged` gets `{"title": title}`. Every action builds its header through this
     function.
2. `PanelAction` gains `success_events: tuple[str, ...] = ()` and
   `get_success_events(self, instance: Model | None) -> dict[str, list[str]]`. By default it maps
   each name to `[str(instance.pk)]`, or to `[]` when there is no instance. An action whose
   mutation touches other entities overrides it, and a mutation that touches two entity types
   fires both events. `DeleteAction` records the pk before it calls `instance.delete()`, because
   Django sets it to `None` afterwards.
3. `Panel` gains `refresh_events: tuple[str, ...] = ()`. `_panel_base.html` emits
   `hx-get`/`hx-trigger` only when the tuple is non-empty, as
   `hx-trigger="<e1> from:body, <e2> from:body"`. The literal `panelChanged` is removed from the
   template.
4. `ListViewConfig` gains `refresh_events: tuple[str, ...] = ()`. `_main_for`
   (`panel_framework/views.py`) passes these in place of the collected
   `get_created_event_name()` values. They follow the existing `refresh_events` path through
   `list_view.html` to `list_refresh.html`. `listRefresh` is unchanged: it refetches on the event
   name and ignores the detail.
5. The `panelChanged` listener in `panel_framework/static/panel_framework/js/alpine-components.js`
   now listens for `instanceTitleChanged` and reads `detail.title` into `#instance-title`.
6. `get_created_event_name()` and every `panelChanged` reference are removed. This includes
   `panel_framework/tests/stub_panels.py`, which declares a generic stub event such as
   `itemChanged` instead.

### B. Educator-interface event names (`freedom_ls/educator_interface/`)

7. New module `educator_interface/events.py` with `LEARNER_CHANGED = "learnerChanged"`,
   `COHORT_CHANGED = "cohortChanged"`, `REGISTRATION_CHANGED = "registrationChanged"` and
   `EDUCATOR_CHANGED = "educatorChanged"`. Specs 6 to 9 use these and add no others.
8. Existing wiring:
   - `CreateCohortAction.success_events = (COHORT_CHANGED,)`.
   - `CohortDetailsPanel`'s edit and delete fire `COHORT_CHANGED`.
   - `CohortConfig.refresh_events = (COHORT_CHANGED,)` and
     `LearnerConfig.refresh_events = (LEARNER_CHANGED,)`.
   - Every panel on the cohort detail page refreshes on `COHORT_CHANGED`. Every panel on the
     learner detail page refreshes on `LEARNER_CHANGED`.
   - `InstanceDetailsPanel` gives the `EditAction` it builds its own `refresh_events` as that
     action's `success_events`.

### C. Modal host and component

9. `panel_framework/templates/panel_framework/partials/modal_host.html` holds:

   ```html
   <dialog id="app-modal" x-data="appModal" aria-labelledby="app-modal-title"
           class="modal-backdrop-host ...">
     <div data-modal-discard-prompt hidden>…</div>
     <button type="button" @click="requestClose" aria-label="Close">…</button>
     <div id="app-modal-body"></div>
   </dialog>
   ```

   `educator_interface/templates/educator_interface/interface.html` fills
   `{% block modal_host %}` with it. That block sits outside `#interface-main`, so a
   `#main-content` swap never touches the dialog.
10. `Alpine.data("appModal")` goes in `panel_framework/static/panel_framework/js/alpine-components.js`.
    It registers every listener in `init()` and removes them in `destroy()`. No `hx-on`, no
    trigger filters and no inline expressions, so nothing needs eval under the CSP. Spec 2 adds
    components to the same file, and whichever spec lands second rebases onto the other.
    - **Trigger.** On `htmx:beforeRequest` targeting `#app-modal-body` while the dialog is
      closed, record the requesting element. Native focus return cannot be relied on, because
      `hx-disabled-elt` blurs the trigger before `showModal()` runs.
    - **Open.** On `htmx:afterSwap` whose target is `#app-modal-body`, if the dialog is closed,
      call `showModal()`. The fragment is already in the DOM, so native `autofocus` picks the
      initial focus. If the dialog is already open, the swap is a re-render and the next two
      rules apply.
    - **Re-render after a 422.** Move focus to the fragment's `[data-error-summary]` if there is
      one, otherwise to the first `[aria-invalid="true"]` field.
    - **Re-render after a 200 "save and add another".** Focus the first field.
    - **Success.** On `closeModal` on `document.body`, call `close()`. A 204 never swaps, so
      success cannot be detected with `htmx:afterSwap`.
    - **Close.** One `close` listener clears `#app-modal-body`, hides the discard prompt and
      focuses the recorded trigger, falling back to `#main-content` if the trigger has left the
      DOM. htmx handles `HX-Trigger` before `HX-Location`, so a close followed by navigation
      focuses the trigger and then loses it in the swap; after a `#main-content` swap that leaves
      focus on `<body>`, the component focuses `#main-content`.
    - **Dirty guard.** When a fragment containing a `<form>` swaps in, snapshot
      `new FormData(form)`. One delegated `input`/`change` listener compares the form against
      the snapshot and sets `dirty` when they differ, so a field edited and then changed back
      reads clean. The snapshot is retaken after every re-render.
    - **Cancel.** One `cancel` listener on the dialog handles both Esc and `requestClose()`. A
      clean form lets the dialog close. A dirty form calls `preventDefault()` and shows the
      discard prompt inline above the form, which stays intact underneath: "Discard changes?",
      with "Keep editing" (focused) and "Discard". The prompt is not a nested dialog.
    - **`requestClose` method.** Calls `this.$el.requestClose()`. Every close and cancel button
      in the shell and in fragments uses it, so the guard always runs. Invoker commands are not
      used: they need Safari 26.2, while `requestClose()` needs 18.4. The only button that calls
      `close()` directly is "Discard".
    - **Backdrop click.** A click whose `event.target` is the dialog itself closes it only when
      the body contains no `<form>`, which means read-only content. It never closes a form or a
      destructive confirmation. This stays hand-written until Safari ships `closedby`.
11. Known platform limit, documented in a code comment and in QA: a second Esc pressed before any
    other user activation cannot be cancelled (CloseWatcher rules). The dialog closes and the
    typed input is lost.
12. No nested modals. A confirmation inside a flow replaces the body. The modal may open above an
    open quick view, including the mobile modal quick view.
13. Page scroll is locked in CSS: `html:has(#app-modal:modal, #quick-view:modal) { overflow:
    hidden; scrollbar-gutter: stable; }`. If iOS QA finds scroll leaking through, fall back to the
    fixed-body technique. `contentLightbox` keeps its own JS lock.

### D. Modal triggers and fragments

14. New cotton component `cotton/modal-trigger.html` renders a `<c-button>` with
    `hx-get="{{ url }}" hx-target="#app-modal-body" hx-swap="innerHTML" hx-disabled-elt="this"`,
    `aria-haspopup="dialog"` and no URL push. Its attributes are `url`, `label` and `variant`.
    Nothing opens until the fragment arrives. The disabled button is the only loading state.
15. `PanelAction` separates the trigger from the fragment:
    - `trigger_template_name` is rendered by `{% render_action %}` from
      `get_trigger_context(ctx)`, which is cheap: label, variant and action URL. For modal
      actions it renders `<c-modal-trigger>`.
    - `template_name` is the modal fragment. Only `_handle_action` renders it, on GET, from
      `get_context_data(ctx)`.

    `FormPanelAction.get_context_data` builds the form and `DeleteAction.get_context_data` runs
    `get_cascade_summary`, both only on that GET. Rendering a panel runs nothing form- or
    cascade-related.
16. Fragment templates. Each opens with `<h2 id="app-modal-title">` and none has a `modal_open`
    flag. Every POST or DELETE response that has a body returns a whole fragment, heading
    included, into `#app-modal-body`:
    - `panel_framework/modal/form.html`: `<form hx-post="{{ form_url }}"
      hx-target="#app-modal-body" hx-swap="innerHTML">`. The first field gets `autofocus`. On
      errors the fragment renders `[data-error-summary]` with `tabindex="-1"`, and invalid
      fields carry `aria-invalid="true"`. Cancel calls `requestClose`.
    - `panel_framework/modal/delete_confirmation.html`: the cascade summary or the blocked
      reason, a Cancel button with `autofocus`, and a delete `<form hx-delete ...
      hx-target="#app-modal-body" hx-swap="innerHTML">`.
    - `panel_framework/modal/read_only.html`: a base for read-only content. The heading gets
      `tabindex="-1"` and `autofocus`, and the content sits at reading width.
17. Response contract:

    | Case | Status | Headers | Body |
    | --- | --- | --- | --- |
    | GET action URL | 200 | none | fragment |
    | Validation error | 422 | none | form fragment with errors |
    | `DeleteAction` hits `ProtectedError` at submit | 422 | none | confirmation with blocked reason |
    | Create, "save and add another" | 200 | `HX-Trigger`: domain events | blank form fragment |
    | Create, "Save" | 204 | `HX-Trigger`: `closeModal` plus domain events; `HX-Location: {"path": success_url, "target": "#main-content", "swap": "outerHTML"}` | none |
    | Edit | 204 | `HX-Trigger`: `closeModal`, domain events, `instanceTitleChanged` | none |
    | Delete | 204 | `HX-Trigger`: `closeModal` plus domain events; `HX-Location` to `success_url` as above | none |

    No panel action sets `HX-Redirect`. The 422 swap relies on the existing global
    `htmx:beforeSwap` handler in `base/static/base/js/alpine-components.js`.
18. Deleted: `cotton/modal.html`, `panel_framework/partials/modal_form.html`,
    `panel_framework/partials/delete_confirmation.html`, and `Alpine.data("modal")` in
    `base/static/base/js/alpine-components.js`, which has no other user. The `.modal-backdrop`
    theme class no longer has a user, but it stays defined so theme overrides don't break.
    Spec 12 retires it.

### E. Quick view framework

19. New module `panel_framework/quick_view.py`:

    ```python
    class QuickView:
        template_name: str
        refresh_events: tuple[str, ...] = ()

        def __init__(self, request: HttpRequest, instance: Model) -> None: ...
        def get_title(self) -> str: ...        # default str(instance)
        def get_context_data(self) -> dict[str, object]: ...
    ```

    `ListViewConfig` gains `quick_view: type[QuickView] | None = None`.
20. `_resolve_path` accepts a terminal `__quick-view` segment directly after an instance's pk on a
    `ListViewConfig`. Serving it from the framework means authorisation, the redirect and `Vary`
    are the same for every consumer.
    - Access goes through `get_instance_view`, which means `check_access` and
      `authorise_instance`. An out-of-scope instance, a config with no `quick_view` or a
      malformed pk returns 404. The route adds no permission check of its own.
    - An htmx GET renders `panel_framework/quick_view/frame.html`. The frame wraps the consumer's
      `template_name` in a root element that carries `data-quick-view-title`,
      `data-refresh-events` (space-separated) and `data-entity-id`.
    - A non-htmx GET redirects (302) to the instance page, `<section>/<pk>`.
    - Every response goes through `_vary_on_htmx`, so it carries `Vary: HX-Request`. No HTTP
      caching headers are set.
21. `panel_framework/templates/panel_framework/partials/quick_view_host.html` fills
    `{% block quick_view_host %}` in `educator_interface/interface.html`. It holds a
    `<dialog id="quick-view" x-data="quickView" aria-labelledby="quick-view-title">` containing:
    - A sticky header with `#quick-view-title`, an "Open" link (`#quick-view-open`) to the
      trigger's `href`, and a close button that calls `requestClose`. The Open link is the
      shareable URL. The drawer's state is never in the URL.
    - `#quick-view-body`, which scrolls internally.
    - A `<template>` skeleton, and a `<template>` error block with a Retry button.

    A visually hidden `<div id="quick-view-status" aria-live="polite" aria-atomic="true">` sits
    outside the dialog and is present from page load.

    Styling:
    - Desktop: pinned to `inset-inline-end: 0`, full height, about `30rem` inline size, no
      backdrop.
    - Below `md`: a modal sheet.
    - Logical properties throughout, so RTL flips the layout. An entry slide with
      `@starting-style`. `prefers-reduced-motion` makes the change instant.
    - An exit animation where `allow-discrete` works. Firefox closes instantly.
    - `@media print { #quick-view { display: none } }`.
22. New cotton component `cotton/quick-view-trigger.html` renders:

    ```html
    <a href="{{ href }}" hx-get="{{ url }}" hx-target="#quick-view-body"
       hx-swap="innerHTML" hx-sync="#quick-view-body:replace"
       aria-controls="quick-view" aria-expanded="false"
       data-quick-view-title="{{ title }}" {{ attrs }}>{{ slot }}</a>
    ```

    `hx-push-url` is not set. A plain click opens the drawer. The element stays an `<a href>` to
    the full page, so a modified click, a middle click or "open in new tab" still reaches the
    page. Any extra `data-*` attributes the caller passes, such as cohort and status, appear in
    the skeleton.
23. `Alpine.data("quickView")` goes in the same JS file as `appModal`. It copies the
    modal/non-modal skeleton of `sidePanel` (`base/static/base/js/alpine-components.js`) without
    sharing code with it. It has its own `md` breakpoint (`min-width: 768px`), no `localStorage`,
    and does not close on `htmx:beforeRequest`. Behaviour:
    - **Modified clicks.** htmx only leaves modifier-key clicks alone on boosted anchors, so a
      capture-phase `click` listener on the document stops a Ctrl, Cmd, Shift or Alt click on a
      trigger from reaching htmx. The browser then follows the `href` natively.
    - **Before a request** (`htmx:confirm` from a trigger):
      - If the trigger's URL is the one shown and the drawer is open, cancel the request and
        close.
      - If it is the one shown, the drawer is closed and the content is not stale, cancel the
        request and reopen.
      - Otherwise let the request run.
    - **Opening for a request.** If the drawer is closed, open it: `show()` at `md` and up,
      `showModal()` below. Fill the title and Open link from the trigger. Clone the skeleton,
      including the trigger's `data-*` values. Set `aria-busy="true"` on the body. Set
      `aria-expanded="true"` on this trigger and `false` on the previous one.
    - **Desktop focus.** After `show()`, return focus to the trigger. No focus trap, no scroll
      lock, and clicking outside does not dismiss.
    - **After the swap** (`htmx:afterSwap` on `#quick-view-body`), in one handler:
      - Clear `aria-busy`.
      - Take the title from the frame's `data-quick-view-title`.
      - Write "Showing <title>" to `#quick-view-status`.
      - Register listeners for the events in the frame's `data-refresh-events`, dropping the
        previous set.
    - **Errors.** On `htmx:responseError` or `htmx:sendError` for the body, render the error
      template inline. Retry re-requests the last URL. The drawer never closes itself on error.
    - **Staleness.** When a registered event's `detail.ids` contains the shown `data-entity-id`,
      refetch if the drawer is open, or mark the content stale if it is closed. Events naming
      other ids do nothing.
    - **Closing.** Closing hides the drawer without clearing it. Focus returns to the trigger,
      falling back to `#main-content` if the trigger has left the DOM. Esc closes it: natively in
      modal mode, and through a document `keydown` listener in non-modal mode while no modal
      dialog is open.
    - **Mobile history.** Opening in modal mode pushes one history entry, and Back closes the
      drawer. Closing it any other way calls `history.back()`, unless Back caused the close. This
      follows `sidePanel`'s `_closingFromPopstate` guard.
    - **Open link.** Following it closes the drawer first. On mobile the drawer's history entry
      is replaced, not left behind.
    - **Breakpoint change while open.** Close, then reopen in the other mode with the same
      content and no request.
    - **Tables that refetch.** After a table refetch, the trigger for the shown URL reports
      `aria-expanded="true"` again.
24. On `htmx:beforeHistorySave`, both `#app-modal` and `#quick-view` close, so a restored snapshot
    never reopens a dialog. The mobile quick view's pushed history entry is unwound first.
    `hx-preserve` is not used because it is unverified for a `<dialog>`'s `open` state.

### F. Learner and cohort quick views

25. New module `educator_interface/quick_views.py`:
    - `LearnerQuickView(QuickView)`, with `refresh_events = (LEARNER_CHANGED,)` and template
      `educator_interface/quick_views/learner.html`. `LearnerConfig.quick_view = LearnerQuickView`.
    - `CohortQuickView(QuickView)`, with `refresh_events = (COHORT_CHANGED,)` and template
      `educator_interface/quick_views/cohort.html`. `CohortConfig.quick_view = CohortQuickView`.
26. Learner fields:
    - Name and email, from `User`.
    - Status: "Active" or "Removed", from `Learner.is_active`. This is a placeholder until spec 7
      adds "pending", marked with a TODO template comment and a code comment that name learner
      administration as the work that adds it (no spec numbers in shipped comments).
    - Cohorts: `CohortMembership` filtered to `cohorts_visible_to(request.user, organisation)`,
      the same scoping as `LearnerDataTable.get_queryset`. Each cohort links to the cohort page.
    - Course registrations, both individual and through a cohort. Each shows its
      `progress_percentage` and whether it comes through a cohort.
    - Last active: the latest `CourseProgress.last_accessed_time` across the learner's progress
      records, or "Never". `User.last_login` is not used: it is site-wide and records a login,
      not course activity.
27. Registrations come from a new helper in `freedom_ls/learner_progress/queries.py`,
    `registrations_with_progress_for_learner(learner: Learner) -> list[LearnerRegistrationProgress]`.
    `LearnerRegistrationProgress` is a dataclass with `course`, `cohort: Cohort | None`,
    `progress_percentage: int | None` and `last_accessed_time: datetime | None`. The helper covers
    only active registrations and always runs exactly three queries, however many registrations
    there are:
    - active `LearnerCourseRegistration` rows,
    - active `CohortCourseRegistration` rows through the learner's memberships,
    - `CourseProgress.objects.filter(learner=learner)`, matched on `learner_registration_id` or
      `cohort_registration_id`.

    It is keyed on the `Learner`, not the `User`, so it never crosses organisations.
    `learner_progress` already depends on `learner_management`, so the helper adds no new app
    dependency.
28. Cohort fields:
    - Name.
    - Status: "Active", a placeholder until spec 6 adds `Cohort.is_active`, marked the same way
      with a TODO naming cohort administration.
    - Learner count: the number of `CohortMembership` rows, the same figure `CohortDataTable`
      annotates.
    - Courses, from `course_registrations__course`.
    - The drawer's Open link goes to the cohort page.
29. Triggers:
    - `cotton/data-table-cells/link.html` gains a `column.quick_view` key. When it is set, the
      cell renders `<c-quick-view-trigger>` in place of the plain or `htmx_nav` link. `href` is
      the resolved URL, `url` is the resolved URL plus `/__quick-view`, and `title` is the cell
      text.
    - The learner name columns in `LearnerDataTable` and `CourseLearnerRegistrationDataTable`, and
      the name column in `CohortDataTable`, set it.
    - `educator_interface/data-table-cells/cohort_links.html` renders each cohort link through the
      same trigger.
30. The `@claude` comment in `educator_interface/data-table-cells/learner_courses.html` stays.

## Testing

pytest, in `panel_framework/tests/` and `educator_interface/tests/`:

- `build_hx_trigger` produces the exact JSON for one event, for two events, for `closeModal` and
  for `instanceTitleChanged`, and ids are always lists of strings.
- Each row of the response-contract table in requirement 17 has a test that asserts the status,
  the exact headers and the absence of `HX-Redirect`. A delete's event carries the deleted pk.
  This rewrites the affected tests in `test_panel_actions.py`, `test_configs.py:197`,
  `test_cohort_delete_action.py` and `test_create_cohort_action.py`.
- Lazy rendering: rendering a panel calls neither `FormPanelAction.get_form` nor
  `DeleteAction.get_cascade_summary`, and the rendered panel contains a trigger with no `<form>`.
- `_panel_base.html` emits `hx-trigger` for the declared `refresh_events`, and nothing when none
  are declared. This replaces the `panelChanged` assertions in `test_templates.py:101` and
  `test_data_table_panel.py:59`.
- `ListViewConfig.refresh_events` reaches `list_refresh.html`'s `data-refresh-events`.
- Quick-view route:
  - An in-scope learner and an in-scope cohort return 200 with the frame's data attributes.
  - An out-of-scope instance, a config without `quick_view` and a malformed pk each return 404.
  - A non-htmx GET returns 302 to the instance page.
  - `Vary` includes `HX-Request`.
- `LearnerQuickView` hides a membership in a cohort the viewing instructor cannot see.
- `registrations_with_progress_for_learner` handles an individual registration, a registration
  through a cohort, a registration without a `CourseProgress` record, and an inactive
  registration. It runs in exactly three queries (`django_assert_num_queries`) with one
  registration and with many, and it ignores a second organisation's `Learner` for the same
  `User`.
- `link.html` with `quick_view` renders the trigger attributes. Without it, the cell renders as
  it does today.

Playwright, in the `tests/playwright/` folders of `panel_framework` and `educator_interface`,
marked `@pytest.mark.playwright`:

- Modal, form:
  - Opening puts focus in the first field.
  - A 422 moves focus to the error summary.
  - "Save and add another" leaves a blank form and refreshes the table.
  - "Save" closes the modal and navigates `#main-content` with a history entry. Back works.
  - Esc on a clean form closes it.
  - Esc on a dirty form shows the discard prompt with the form intact. "Keep editing" returns to
    the form and "Discard" closes it.
  - A backdrop click does not close a form.
  - After the modal closes, focus returns to the trigger.
- Modal, delete: Cancel has initial focus, and a delete closes the modal and navigates.
- Modal, read-only: a test-only read-only fragment focuses its heading and closes on a backdrop
  click.
- Edit updates `#instance-title`.
- Quick view, desktop:
  - Clicking a learner opens the drawer with focus still on the link and `aria-expanded="true"`.
  - Clicking a second learner repopulates the drawer, and the table stays clickable.
  - Clicking the same learner closes the drawer. Clicking again reopens it with no network
    request.
  - Esc closes the drawer and returns focus.
  - A Ctrl or Cmd click opens the full page, not the drawer.
  - A server error shows Retry, and Retry loads the content.
  - A domain event naming the shown learner triggers a refetch. One naming another learner does
    not.
- Quick view, mobile viewport: the drawer opens as a modal, and Back closes it without leaving the
  page. Resizing across `md` while it is open keeps the content.
- History: with a dialog open, navigating away and pressing Back restores the page with no
  dialog open.
- `panel_framework/tests/playwright/test_list_view_refresh_htmx.py` is updated for the native
  dialog.
