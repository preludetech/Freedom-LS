# Frontend QA: the bulk-action selection bar, above the table

Checks the selection bar on the educator learners and cohorts tables in a browser. The plan is
`2. plan.md`; its Design section holds the transcriptions the checklists below are copied from.
The checklist, not the screenshot, is what each test judges against.

## Setup

1. Build the stylesheet so the new utilities exist: `npm run tailwind_build`.
2. Start the server on a free port: `uv run python manage.py runserver $PORT`. Base URL:
   `http://127.0.0.1:$PORT`.
3. Log in at `http://127.0.0.1:$PORT/accounts/login/` with the QA login from
   `.claude/sdd/config.md` (`## QA Login`). That user is a site admin and an organisation admin
   of the dev organisation.
4. Open the educator interface and note the organisation slug in the URL
   (`/educator/organisations/<slug>/...`). Every URL below uses that `<slug>`.
   - Learners: `http://127.0.0.1:$PORT/educator/organisations/<slug>/learners/`
   - Cohorts: `http://127.0.0.1:$PORT/educator/organisations/<slug>/cohorts/`
5. Data. The learners table needs more than one page of active learners (the table pages at 25)
   and at least one cohort to add them to. If the dev organisation has fewer, have the QA data
   helper create 30 active learners and one cohort named "QA bulk cohort" in that organisation,
   on the site being browsed. One of the created learners should be a member of "QA bulk cohort"
   so Remove from cohort has something to do.
6. The bar's full learners action set, for a user with every permission: buttons Add to cohort,
   Deactivate, Reactivate, Register for a course; under More: Deactivate a course registration,
   Resend setup email, a rule, Remove from cohort.

Viewports: 1920 (desktop, `lg` and up), 768 (tablet, below `lg`) and 375 (phone, below `md`).
"No sideways scroll" means `document.documentElement.scrollWidth <= window.innerWidth` after
layout settles. "Hidden" means not visible, not merely off-screen.

Keep the browser's console open for every test: a CSP-build Alpine error shows there as a page
error and nothing else reports it.

## Test 1: the bar replaces the toolbar on the desktop

Design state: `educator-learners/02b-bulk-selection`, screenshot
`design_screenshots/educator-learners__02b-bulk-selection.png`.

1. Go to the learners page at 1920. Expect the toolbar (search field, filter chips, Export CSV)
   above the table, no selection bar, and the footer under the table with "Showing 1–25 of N
   learners" at the left and the pager at the right.
2. Note the table's top edge (the header row's position).
3. Tick the first row's checkbox. Expect the toolbar to disappear and the bar to take its row:
   the search field is gone, the bar reads "1 selected", and the table's top edge has not moved.
4. Expect the bar's contents in this order from the left: a checkbox (indeterminate), "1
   selected", "Select all N" (N = the count from the footer), the four action buttons, "More"
   with a chevron; "Clear" with an × alone at the right edge.
5. Expect no outline or fill on the action buttons, More or Clear: text only. Expect "Select all
   N" to look like the framework's link button.
6. Expect the sort headers to still work: click the "Name" header. The table re-sorts, the
   selection clears, the toolbar returns.
7. Tick two rows. Expect "2 selected"; the header checkbox and the bar checkbox are both
   indeterminate. Tick every row on the page through the header checkbox. Expect "25 selected"
   and both checkboxes checked. Untick one row: both are indeterminate again.
8. Click "Clear". Expect the bar to go and the toolbar to return in the same row, with the table's
   top edge where it was. Expect keyboard focus on the header checkbox (press Space: the page's
   rows tick and the bar comes back; press Space again to clear).

Design checklist:
- [ ] The bar sits where the toolbar was, above the table, and the toolbar is hidden.
- [ ] Order: checkbox, count, select-all link, action buttons, More; Clear alone at the right.
- [ ] Action buttons and More are text-only, no outline or fill.
- [ ] More's label is "More" with a chevron; the menu opens below it.
- [ ] In the menu the destructive action sits last, under a rule, in error text.
- [ ] The bar's checkbox and the header checkbox show the same state.
- [ ] The table's top is where it was before the selection.

## Test 2: the More menu

1. At 1920 on the learners page, tick a row and click "More". Expect a menu below the trigger
   holding, in order: "Deactivate a course registration", "Resend setup email", a horizontal
   rule, "Remove from cohort" in red text. No icons on the items, no helper line under any item.
2. Press the down arrow twice, then once more. Expect focus to move through the three items and
   skip the rule. Press Escape: the menu closes and focus returns to More.
3. Click "More" again, then "Remove from cohort". Expect the confirmation dialog in the modal with
   a cohort picker. Cancel it.
4. Repeat step 1 at 768 and at 375 (tick a card's checkbox at 375). Expect the whole menu inside
   the viewport each time, including its last item, whether it opens above or below the trigger.
5. Go to the cohorts page at 1920 and tick a cohort. Expect four text buttons (Register for a
   course, Deactivate a course registration, Deactivate, Reactivate) and no More.

## Test 3: select all, deselect all and clear

1. At 1920 on the learners page with nothing filtered, tick one row, then click "Select all N".
   Expect "N selected" where N is the total in the footer, the link now reading "Deselect all",
   the muted note "Changing page, sort or filters clears the selection.", and both page checkboxes
   checked.
2. Untick one row. Expect "N−1 selected", the link back to "Select all N", both page checkboxes
   indeterminate, and the note still showing. Click "Select all N": the row is ticked again and
   the count is N.
3. Click "Deselect all". Expect the bar to go, the toolbar back, no row ticked and focus on the
   header checkbox.
4. Tick one row, "Select all N", then "Clear". Then tick one row. Expect "1 selected" and the link
   reading "Select all N" (no all-matching state carried over).
5. Filter the table so that every match fits on one page (for example search for a name that
   matches two or three learners). Tick a row and click "Select all N". Expect every visible row
   ticked, "N selected" and the link reading "Deselect all", with no "Changing page..." note
   (the selection stayed in page mode).
6. With "Select all N" active on the unfiltered table, click page 2 in the pager. Expect the
   selection to clear and the toolbar to return.

## Test 4: an action from the bar and the result

Design state: `educator-learners/02d-bulk-result`, screenshot
`design_screenshots/educator-learners__02d-bulk-result.png`.

1. At 1920, tick two learners who are not in "QA bulk cohort" and click "Add to cohort". Expect
   the confirmation in the modal with the cohort picker; choose "QA bulk cohort" and confirm.
2. Expect the result in the modal ("2 learners changed."). Close it.
3. Expect the table refreshed with no row ticked, no bar, the toolbar back in its row, and the
   footer with the entry count and pager.
4. Open one of the two learners and confirm the cohort membership is there.

Design checklist:
- [ ] No bar; the toolbar is back in the same row.
- [ ] No row or header checkbox is checked.
- [ ] The table's top is where it was while the bar showed.

## Test 5: a background run

Only possible if the organisation has more learners than `BULK_BACKGROUND_THRESHOLD` (250 by
default). If the environment sets a lower threshold for QA, or the data helper can create enough
learners, run it; otherwise record the test as not run and why.

1. Tick a row, "Select all N", then "Resend setup email" under More, and confirm.
2. While the run is going, expect the bar to read "Resend setup email is running…" with a
   spinner, no action buttons and no More, and the bar checkbox, "Select all" / "Deselect all" and
   "Clear" disabled along with every row checkbox.
3. When the result modal appears, close it. Expect the bar gone and every checkbox enabled.

## Test 6: tablet and phone

1. At 768 on the learners page, tick a row. Expect the toolbar to stay visible and the bar fixed
   to the bottom of the viewport with the same contents as on the desktop, Clear at the right.
2. Scroll to the end of the page. Expect the last row's checkbox and the pager's "Next" link
   both fully visible above the bar, not under it, and clickable.
3. Click "Clear". Expect the bar gone and no empty band under the footer.
4. At 375, tick the first card's checkbox. Expect the bar fixed at the bottom; its left group
   wraps onto more than one row while Clear stays at the end of the first row; no control is cut
   off; no sideways scroll.
5. Click "More" at 375: the menu stays inside the viewport. Close it.
6. Scroll to the end. Expect the last card's checkbox and the pager's "Next" link reachable above
   the bar.
7. Click "Clear". Expect focus on the "Select all on this page" checkbox above the cards.
8. Tick a card, click "Select all N", then "Deselect all". Expect the same focus target.
9. With a row ticked at 375, check every control in the bar is inside the viewport and
   `document.documentElement.scrollWidth <= window.innerWidth`.

## Test 7: JavaScript off

Open a browser context with JavaScript disabled (Playwright: `browser.new_context(java_script_enabled=False)`)
and log in again in it.

1. Go to the learners page at 1920. Expect the bar visible under the toolbar, holding only the
   action submit buttons (the four promoted ones and the More actions as plain buttons): no
   checkbox, no count, no "Select all", no "Clear" in the bar.
2. Tick two rows and press "Deactivate". Expect the full-page confirmation. Press "Deactivate"
   there. Expect the list again with a flash message naming the two changed learners.
3. At 375 with JavaScript off, expect the fixed bar to possibly cover the end of the list; that
   is accepted, record it without filing a bug.

## Test 8: what else the change touches

1. A table without bulk actions (for example the audit log at
   `/educator/organisations/<slug>/audit-log/`, or any list page without a checkbox column):
   expect the footer with the entry count and pager as before, no bar, no reserved space under
   the footer, and the toolbar unchanged.
2. The learners quick view and row actions still work with a row ticked: open a learner's row
   menu while two rows are selected; the menu opens and the selection is unchanged.
3. Sorting, searching and filtering with rows selected each clear the selection and bring the
   toolbar back (search: type in the field after clearing; the field has to be visible first).
4. Keyboard only, at 1920: Tab from the page heading through the toolbar into the table; tick a
   row with Space; Shift+Tab back up. Expect the bar's controls in the tab order between the
   toolbar's place and the table, in the visual order (checkbox, Select all, actions, More,
   Clear).
5. A screen reader or the accessibility tree (Playwright `browser_snapshot`): with a row ticked,
   expect exactly one status region in the table region, reading "1 selected", and the bar's
   count to be plain text.
6. Dark mode, if the browser offers it: the bar, the menu rule and the red menu item all read
   with theme colours, no hard-coded white or red.
