# Spec: the bulk-action selection bar, above the table

## Purpose

The panel framework's selection bar works but looks bad (`idea.md`). It sits in the table footer
beside the pager, with outlined or filled buttons. This spec moves it above the table, into the
table toolbar's place while rows are selected, and gives it the controls listed under
Requirements.

Resources:

- `design.md`: the registered Claude Design design. Screens 02b (selection bar), 02c (confirm) and
  02d (result) are a visual reference for layout and density only, read as that file says.
- `research_codebase.md`: file and line inventory of the bar, `tableSelection`, the toolbar, the
  modal flow, every bulk action and every test that pins the current bar.
- `research_prior_art.md`: what specs 2, 8 and 12 settled. Its "Do not reopen" list holds for this
  spec.

## Scope

In: the selection bar's position, contents, button styles and More menu at every width; the
`tableSelection` changes they need; the table footer for tables with bulk actions; an error tone
and a separator for dropdown menu items in `freedom_ls/base`.

Out:

- The confirmation and result modal (`bulk_confirmation.html`, `bulk_picker.html`,
  `bulk_result.html`). It already confirms every bulk action and hosts every bulk action's form.
  Spec 12's open item on confirmation body wording stays open.
- What the design draws beyond the idea: Message and Export as bulk actions, per-action icons, a
  helper line under a menu item, the affected-learner list and "Notify learners by email" in the
  confirm, the Undo toast, the selected-row accent edge, and the design's colours, fonts and icons.
- Any change to `BulkAction`'s server contract, selection semantics or permissions.
- A sticky bar, and disabling row menus while rows are selected.

## Decisions

- **From `lg` up, the bar replaces the whole table toolbar** while it shows. Search, filters and
  Export CSV are out of reach until the selection clears; the table's sort headers stay usable.
- **Below `lg` the bar is fixed to the bottom of the viewport**, with the same contents and styles,
  and the toolbar stays visible.
- **Promotion rule.** The first four permitted actions whose `variant` is not `"error"`, in
  registration order, are buttons. Every other action goes under More: the remaining
  non-destructive ones in registration order, then the `"error"` ones below a separator, in error
  text. On the learners table: buttons Add to cohort, Deactivate, Reactivate, Register for a
  course; under More, Deactivate a course registration and Resend setup email, a separator, then
  Remove from cohort. The cohorts table has four non-destructive actions and no More.
- **`BulkAction.variant` now means destructive or not.** `"error"` is destructive; any other value
  is not, and `BulkAction.destructive` is the one property that reads it. The bar no longer passes
  `variant` to `<c-button>`. `confirm_variant` still drives the dialog's confirm button.
- **Text-only buttons are `variant="ghost"` and `size="small"`**, which keeps the small-trigger rule.
  Select all and Deselect all are `variant="link"`, the framework's text-action component.

## Requirements

### Bar layout: `freedom_ls/panel_framework/templates/panel_framework/partials/table_selection_bar.html`, `cotton/data-table.html`

1. In `data-table.html` the bar comes after `table_toolbar.html` and before the table and the
   `md:hidden` card list. It stays inside the bulk `<form>` and keeps `data-total-count` and
   `data-page-count` on its root. `table_toolbar.html` stays outside the form.
2. `x-data="tableSelection"` moves from the form to the `data-table-region` div, still only when
   `bulk_actions` is set, so one Alpine scope covers the toolbar, the bar and the table. The toolbar
   stays in the DOM and takes `lg:hidden` through a method-bound class (`x-bind:class`) while
   `barVisible` is true. The `lg:hidden` literal must appear in a template so Tailwind emits it.
   `x-on:resize.window="measureBar"` moves with `x-data`. `tableSelection` still resolves
   `$refs.modeInput`, `$refs.excluded` and the row checkboxes, and `update`, `toggleAll`,
   `clearSelection` and `activateSelectAll` keep working for the table and card checkboxes
   (`_visibleRowBoxes`). `clearSelection` and `activateSelectAll` find the form through `$root` or
   the event target, never `this.$el`, which is the clicked button once they are called from the
   bar.
3. The bar's root has two children: a left group that wraps (`min-w-0 flex-1 flex-wrap`) and Clear as
   a `shrink-0` sibling. That way Clear stays at the end of the first row at every width, and nothing
   scrolls horizontally. The left group holds, in order:
   - a tri-state checkbox with `aria-label="Select page"`, `data-select-all` and
     `x-on:change="toggleAll"`, kept in sync with the header checkbox;
   - the visible count, "N selected", or "<Label> is running…" with the loading icon during
     a run;
   - the select-all link (requirement 5);
   - the promoted action buttons and More (requirement 6).

   Clear is `variant="ghost"`, `size="small"`, `<c-icon name="close">` then "Clear". It calls
   `clearSelection`, which empties the selection, resets `mode` to page mode, empties `excluded` and
   hides the bar.
4. The bar shows only while `barVisible` (`hasSelection || running`) is true. Before Alpine starts,
   the bar root carries a `data-selection-bar-pending` attribute, hidden by
   `@media (scripting: enabled) { [data-selection-bar-pending] { display: none } }`, and
   `tableSelection.init` removes it. From then on `x-bind:style="barStyle"` alone decides
   (`display: none` while `barVisible` is false; `x-show` would apply a frame after the toolbar's
   class binding and move the table for that frame). With
   JavaScript off the bar shows as it does today. The bar checkbox, the count, the select-all link
   and Clear carry `x-cloak`, so with JavaScript off the bar holds only the action submit buttons.
   The `role="status"` live region sits in the table region outside the bar (`sr-only`), so it is in
   the accessibility tree before any selection. It is the only `role="status"` in the region, and
   the bar's visible count is plain text.
   At `lg` and up the bar has the toolbar's min-height and vertical padding, so swapping one for
   the other does not move the table.
5. The select-all link reads "Select all {{ paginator.count }}" until every matching row is
   selected, then "Deselect all". It calls one method, `activateSelectAll`:
   - when it reads "Deselect all", it calls `clearSelection`;
   - when the page holds every match, it ticks every visible row and stays in page mode;
   - otherwise it ticks every visible row and the page checkboxes, clears `excluded` and calls
     `selectAllMatching`.

   Unticking a row in `all_matching` mode brings back "Select all N". The page prompt and the
   matching prompt go. "Changing page, sort or filters clears the selection." stays, in
   `text-muted`, while `mode === "all_matching"`.
6. Each promoted button is a `<c-button type="submit">` in the Decisions' text-only style, with the existing
   `formaction`, `hx-post`, `hx-target="#app-modal-body"` and `hx-swap`. More is the existing
   `<c-dropdown-menu>` with `trigger_class="btn btn-ghost btn-sm"`. Its visible label is "More"
   followed by `<c-icon name="dropdown">`, and its `aria_label` stays "More actions". The
   `<noscript>` fallback still renders every More action as a plain submit button. The promoted and
   overflow lists, `promoted_bulk_actions` and `overflow_bulk_actions`, are computed in Python by
   `promote_bulk_actions` where `DataTablePanel` builds `context["bulk_actions"]` (`panels.py`),
   not by template slicing. Each entry is a `BulkActionEntry` (`action`, `url`, and
   `separator_before`, true on the first destructive entry under More when a non-destructive one
   sits above it); `PROMOTED_BULK_ACTION_COUNT` is the four. `bulk_actions` stays the full
   permitted list.
7. `<c-button dropdown="true">` in `freedom_ls/base/templates/cotton/button.html` gains a tone option,
   `tone="error"`, that swaps `text-muted` for `text-error`. `<c-dropdown-menu>` gains a separator
   element, `<c-dropdown-menu-separator />` (`role="separator"`, a theme-token border). Both are
   documented in the components' comments.
8. During a run the action buttons and More stay hidden, as today, and every checkbox, the
   select-all link and Clear are disabled.
9. When the bar hides because one of its own controls was used (Clear, Deselect all, or unticking
   the bar checkbox), focus moves to the visible page checkbox. That is the header checkbox from
   `md` up, or "Select all on this page" below `md`, found by visibility (`offsetParent`).
10. Every control stays inside the viewport at 375px.

### Footer: `partials/table_footer.html`, `cotton/data-table.html`

11. A table with bulk actions ends in `table_footer.html` (entry count at the left, pager at the
    right) like every other table. The `{% elif entry_count %}` branch goes, and the pager no longer
    renders inside the bar.

### Phone: below `lg`

12. The bar keeps `fixed inset-x-0 bottom-0` below `lg` and `lg:static` from `lg` up. The region
    reserves the bar's measured height after the footer (a `data-selection-bar-space` element
    whose height `barSpaceStyle` sets), only while the bar shows, so the last rows and the pager
    stay reachable above the bar. With JavaScript off, the fixed bar can cover
    the end of the region on a phone, and that is accepted.

### `tableSelection`: `freedom_ls/panel_framework/static/panel_framework/js/alpine-components.js`

13. `tableSelection` gains `barVisible`, `countSentence` (the count sentence), `allMatchingSelected`,
    `selectAllLabel` (the select-all link's label), `allMatchingMode`, `toolbarClass`,
    `barSpaceStyle` and the `activateSelectAll` method, with the private helpers `_form` (the
    bulk form), `_recount` (the body of `update`, callable without an event) and `_returnFocus`
    (requirement 9). Templates use property and method references only (Alpine's CSP build).

## Testing

Server-rendered (pytest, `freedom_ls/panel_framework/tests/test_bulk_actions.py` and
`components/test_data_table.py`, with stubs in `tests/stub_panels.py`):

- Promotion: with seven permitted stub actions, two of them `variant="error"` (the stubs
  `StubDiscardBulkAction` and `StubPurgeBulkAction`), the bar renders the
  first four non-error actions as buttons in registration order. More holds the rest, with the
  error ones last, after a `role="separator"`, carrying `text-error`. The separator renders only
  between a non-error entry and the error group; a More menu holding error actions alone starts
  with its first item. With four non-error actions and no error ones, there is no More. A
  forbidden action appears in neither list.
- The bar renders before the table in document order, carries `data-total-count` and
  `data-page-count`, and has no pager; the table region holds one `role="status"`, outside the
  bar. A bulk table renders
  `table_footer.html` with the entry count.
- No bar button carries `btn-secondary`, `btn-error` or `btn-primary`.
- `freedom_ls/panel_framework/tests/invariants/test_templates.py` passes.

Browser (`freedom_ls/panel_framework/tests/playwright/test_data_table_flow.py` and
`freedom_ls/educator_interface/tests/playwright/test_learners_list_flow.py`). Tests that pin the old
copy or position are rewritten in the same change, not deleted.

- At `lg` and up: no bar and the toolbar visible before selection. Ticking a row hides the toolbar
  and shows the bar above the table, and the table's top does not move. Clear brings the toolbar
  back and focuses the header checkbox.
- Below `lg`: the bar is fixed to the bottom and covers neither the last card checkbox nor the
  pager's Next link while rows are selected. With nothing selected, no space is reserved under the
  list.
- Clear after "Select all N" returns to page mode: ticking one row afterwards reads "1 selected"
  with no all-matching state carried over. Below `md`, Clear and Deselect all focus "Select all on
  this page".
- "Select all N" selects every match across pages ("N selected") and becomes "Deselect all", which
  empties the selection. Unticking one row after Select all brings back "Select all N", and
  choosing it re-ticks that row. On a single-page table, Select all ticks the page.
- The bar checkbox and the header checkbox stay in sync, including the indeterminate state.
- A promoted action and a More action each open their confirmation in `#app-modal`. The More menu
  stays inside the viewport at the QA viewports.
- During a background run the bar reads "<Label> is running…". Actions and More are hidden, and the
  checkboxes, select-all link and Clear are disabled.
- With JavaScript off, ticking rows and pressing an action reaches the confirmation page, and the
  bar shows no count, select-all link or Clear.
- No horizontal overflow at 375px with the learners table's full action set selected.
- `uv run pytest freedom_ls/panel_framework freedom_ls/educator_interface` passes.

## Open questions

- Q: Where does the selection count's live region sit? → A: an `sr-only` `role="status"` in the
  table region outside the bar, with the bar's count as plain text (assumed default: a live region
  inside the hidden bar is out of the accessibility tree and would miss the first announcement.
  Overrule by editing requirement 4).
- Q: How is "the table does not move" when the bar replaces the toolbar achieved? → A: the bar takes
  the toolbar's min-height and vertical padding from `lg` up (assumed default: it keeps the swap in
  place without restyling the toolbar. Overrule by editing requirement 4 and the `lg` browser
  test).
