# Spec: the bulk-action selection bar, above the table

## Purpose

The panel framework's selection bar works but looks bad (`idea.md`). It sits in the table footer
beside the pager, its actions are outlined or filled buttons, and the only way to empty a selection
of rows on one page is to untick them. This spec moves the bar above the table, where it takes the
table toolbar's place while rows are selected. It also gives the bar a count, Select all and
Deselect all, a Clear control at the right, and text-only action buttons, with the rest of the
actions under a More menu.

Behaviour stays as it is: what a selection is, how it posts, the confirmation and result modal, and
background runs. This is a change to layout and controls in `freedom_ls/panel_framework`.

Resources:

- `design.md`: the registered Claude Design design. Screens 02b (selection bar), 02c (confirm) and
  02d (result) are a visual reference for layout and density only, read as that file says.
- `research_codebase.md`: file and line inventory of the bar, `tableSelection`, the toolbar, the
  modal flow, every bulk action and every test that pins the current bar.
- `research_prior_art.md`: what specs 2, 8 and 12 settled. Its "Do not reopen" list holds for this
  spec.

## Scope

In:

- The selection bar's position, contents, button styles and the More menu, at every width.
- `tableSelection` changes the new controls need.
- The table footer (entry count and pager) for tables that have bulk actions.
- Tests, the panel-framework and alpine-js skills, the product doc and upgrade notes for the above.

Out:

- The confirmation and result modal (`bulk_confirmation.html`, `bulk_picker.html`,
  `bulk_result.html`). It already confirms every bulk action and hosts every bulk action's form, so
  it is unchanged. Spec 12's open item on confirmation body wording stays open.
- What the design draws beyond the idea: Message and Export as bulk actions, per-action icons, a
  helper line under a menu item, the affected-learner list and "Notify learners by email" in the
  confirm, the Undo toast, the selected-row accent edge, and the design's colours, fonts and icons.
- Any change to `BulkAction`'s server contract, selection semantics or permissions.
- A sticky bar, and disabling row menus while rows are selected.

## Decisions

- **The bar replaces the table toolbar from `lg` up.** It sits where the toolbar sits, so the table
  does not move when the first row is ticked. Once the selection is empty the toolbar comes back.
  Filters are out of reach while rows are selected, which matches the existing rule that a filter
  change clears the selection.
- **Below `lg` the bar stays fixed to the bottom of the viewport.** It has the same contents and
  styles as the desktop bar. The toolbar stays visible on phones, because the bar is not in its slot
  there.
- **The bar shows only while rows are selected or a bulk run is in progress.** The entry count and
  pager move to `table_footer.html` for every table, bulk or not.
- **Promotion rule.** The bar shows the first four permitted actions whose `variant` is not
  `"error"`, in registration order, as buttons. Every other action goes under More: first the
  remaining non-destructive ones in registration order, then the `"error"` ones, below a divider and
  in error text. On the learners table that means: buttons Add to cohort, Deactivate, Reactivate,
  Register for a course. Under More: Deactivate a course registration, Resend setup email, a divider,
  then Remove from cohort. The cohorts table has four non-destructive actions, so it shows no More.
  This replaces spec 8's first-two rule.
- **`BulkAction.variant` now means destructive or not.** `"error"` marks an action destructive (it
  goes to the end of More and shows in error text). Any other value means non-destructive. The bar
  no longer passes it to `<c-button>`. `confirm_variant` still drives the dialog's confirm button.
- **Text-only buttons are `variant="ghost"` and `size="small"`**, which keep the small-trigger rule
  and give a hover fill as the affordance. Select all and Deselect all are `variant="link"`, the
  framework's text-action component.
- **More keeps its accessible name.** The visible label is "More" followed by
  `<c-icon name="dropdown">`, and the `aria_label` stays "More actions", which contains the visible
  label.

## Requirements

### Bar layout: `freedom_ls/panel_framework/templates/panel_framework/partials/table_selection_bar.html`, `cotton/data-table.html`

1. The bar renders in the toolbar's slot: in `data-table.html` it comes after
   `table_toolbar.html` and before the table (and before the `md:hidden` card list). It stays inside
   the bulk `<form>`, keeping `data-total-count` and `data-page-count` on its root.
   `table_toolbar.html` stays outside the form, because the search form cannot nest in it.
2. The Alpine scope that owns the selection (`x-data="tableSelection"`) covers the toolbar, the bar
   and the table, so the toolbar can hide from `lg` up while `hasSelection` or `running` is true.
   The toolbar is hidden with `x-show` (it stays in the DOM, so `hx-preserve` on the search input and
   the post-swap focus handlers in `alpine-components.js` keep working). `tableSelection` still
   resolves `$refs.modeInput`, `$refs.excluded` and the row checkboxes after the move.
3. Left to right, the bar holds:
   - a tri-state checkbox carrying `data-select-all` and `x-on:change="toggleAll"`, kept in sync like
     the header checkbox (checked when every visible row on the page is ticked, indeterminate when
     some are);
   - the `role="status"` count, reading "N selected" (or "<Label> is running…" with the loading icon
     during a run);
   - the select-all link (requirement 5);
   - the promoted action buttons and More (requirement 6);
   - at the far right, a Clear button (`variant="ghost"`, `size="small"`, `<c-icon name="close">`
     then "Clear"). It calls `clearSelection` and hides the bar.
4. The bar's root is `hidden` from first paint until `hasSelection || running` (via `x-show` with
   `x-cloak`). With JavaScript off, Alpine does not run and the bar shows, as it does today. In that
   state it shows no count text, and it must not render a bare " selected". The count's whole
   sentence comes from one Alpine getter. The `role="status"` element is in the DOM before any
   selection, and is the only `role="status"` in the table region.
5. The select-all link is one control. It reads "Select all {{ paginator.count }}" (calling
   `selectAllMatching`) while the selection is smaller than everything matching. It reads
   "Deselect all" (calling `clearSelection`) once every matching row is selected: either
   `mode === "all_matching"` with no exclusions, or the page holds every match and all of it is
   ticked. With exclusions in `all_matching` mode it reads "Select all N" again, and choosing it
   clears `excluded`. The page prompt ("All N on this page are selected.") and the matching prompt
   ("All N matching are selected." / "N of M matching are selected." / "Clear selection") are
   removed. The line "Changing page, sort or filters clears the selection." stays, in `text-muted`,
   shown while `mode === "all_matching"`.
6. Actions follow the promotion rule in Decisions. Each promoted button is
   `<c-button type="submit" variant="ghost" size="small">` with the existing `formaction`,
   `hx-post`, `hx-target="#app-modal-body"` and `hx-swap`. More is the existing
   `<c-dropdown-menu>` with `trigger_class="btn btn-ghost btn-sm"`. Each destructive item carries
   `text-error`, and a divider separates them from the items above. The `<noscript>` fallback still
   renders every More action as a plain submit button. The order of actions is computed once in
   Python, as two lists on the context (promoted and overflow), not with template slicing. It is
   built where `DataTablePanel` builds `context["bulk_actions"]` (`panels.py`, near
   `get_bulk_actions`). This keeps it testable without a browser.
7. While a run is in progress, every checkbox, the select-all link, the action buttons, More and
   Clear are disabled, as the existing controls are today.
8. Nothing in the bar scrolls horizontally. At any width the bar wraps onto further rows, with Clear
   staying at the end of the first row, and every control stays inside the viewport at 375px.
9. Focus never lands on `<body>` after the bar hides. Clear, Deselect all and unticking the last row
   all move focus to the visible page checkbox (the header checkbox from `md` up, "Select all on
   this page" below `md`).

### Footer: `partials/table_footer.html`, `cotton/data-table.html`

10. A table with bulk actions ends in `table_footer.html` (entry count at the left, pager at the
    right) like every other table, so the `{% elif entry_count %}` branch goes. The pager no longer
    renders inside the bar.

### Phone: below `lg`

11. The bar keeps `fixed inset-x-0 bottom-0` below `lg` and `lg:static` from `lg` up. The list
    reserves the bar's measured height beneath itself only while the bar is shown. The static
    `md:pb-40` on the table region and `pb-64` on the card list go, so nothing is reserved when
    nothing is selected. This also fixes spec 12's B10, the empty band under tables at tablet width.
    `measureBar`, the `ResizeObserver` and `barHeight` stay.

### `tableSelection`: `freedom_ls/panel_framework/static/panel_framework/js/alpine-components.js`

12. Add the getters the bar binds to: `barVisible` (`hasSelection || running`), the count sentence
    (requirement 4), `allMatchingSelected`, and the select-all link's label and action
    (requirement 5). Remove `showEntryCount`, `showPagePrompt` and `showMatchingPrompt` once nothing
    binds to them. Templates use property and method references only, because the project uses
    Alpine's CSP build.
13. The component finds its form and refs after `x-data` moves to the wrapper (requirement 2).
    `update`, `toggleAll` and `clearSelection` keep working for both the table and card checkboxes
    (`_visibleRowBoxes`).

## Testing

Server-rendered (pytest, `freedom_ls/panel_framework/tests/test_bulk_actions.py` and
`components/test_data_table.py`, with stubs in `tests/stub_panels.py`):

- Promotion: with six permitted stub actions, two of them `variant="error"`, the bar renders the
  first four non-error actions as buttons in registration order. More holds the rest, error ones
  last, below the divider and carrying `text-error`. With four or fewer non-error actions and no
  error ones, there is no More.
- A forbidden action appears in neither list.
- The bar renders before the table in document order, carries `data-total-count` and
  `data-page-count`, holds one `role="status"`, and has no pager. A bulk table renders
  `table_footer.html` with the entry count.
- No bar button carries `btn-secondary`, `btn-error` or `btn-primary`.

Invariants: `freedom_ls/panel_framework/tests/invariants/test_templates.py` passes unchanged,
notably `test_every_framework_action_trigger_is_small`, `test_no_control_link_is_hand_styled` and
`test_no_panel_component_uses_raw_colours`.

Browser (`freedom_ls/panel_framework/tests/playwright/test_data_table_flow.py` and
`freedom_ls/educator_interface/tests/playwright/test_learners_list_flow.py`). Tests that pin the old
copy or position are rewritten in the same change, not deleted. Locators for "Select all on this
page" are scoped (`thead`, the bar or the card list) because the bar adds another checkbox.

- At `lg` and up: no bar and the toolbar visible before selection. Ticking a row hides the toolbar
  and shows the bar above the table, with the table's top not moving. Clear brings the toolbar back
  and focuses the header checkbox.
- Below `lg`: the bar is fixed to the bottom and does not cover the last row or card checkbox. With
  nothing selected, no space is reserved under the list.
- "Select all N" selects every match across pages ("N selected") and becomes "Deselect all", which
  empties the selection. Unticking one row after Select all brings back "Select all N".
- The bar's checkbox and the header checkbox stay in sync, including the indeterminate state.
- A promoted action and a More action each open their confirmation in `#app-modal`. The More menu
  stays inside the viewport at the QA viewports.
- During a background run the bar shows "<Label> is running…" and every control in it is disabled.
- With JavaScript off, ticking rows and pressing an action still reaches the confirmation page, and
  the page shows no bare " selected".
- No horizontal overflow at 375px with the learners table's full action set selected.

  the table not moving. The bar reads "1 selected", "Select all N", four text-only actions, More and
  Clear.

- Clear and Deselect all each empty the selection, hide the bar and return the toolbar.
- At 375px the bar sits at the bottom of the viewport with every control visible. No space is
  reserved under the list when nothing is selected.
- Every confirmation still opens in `#app-modal`, and the JS-off path still confirms on a page.

  included.
