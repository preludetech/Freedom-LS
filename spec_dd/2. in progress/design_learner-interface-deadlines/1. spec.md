# Spec: learner interface deadlines

## Purpose

Learners already see their deadlines: one muted line on each dashboard course card, a line under
each outline row, and a line above the item title in the course player. All of them are plain text,
easy to miss, and give no sign of which deadline is close. This work changes how those deadlines
look, following `idea.md`. It gives each deadline a tier, shown with colour and an icon, adds a
next-deadline card to the outline panel, and keeps the text short. The deadline data, resolution and
policy stay as they are.

Resources:

- `spec_dd/2. in progress/design_learner-interface-deadlines/design.md`: the Claude Design design,
  a visual reference only. Read it as that file says. The treatments this spec builds are
  `cards__card-c`, `p-sb__sb-b`, `p-outline__ol-a`, `p-head__hd-b`, `tablet__tb-player` and
  `mobile__m-toc`. Take layout and hierarchy from them, never colours, fonts, icons or copy.
- `research_*.md` beside this file.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| deadline tier | coined | How urgent an unfinished deadline looks to the learner: `UPCOMING`, `TODAY`, `MISSED` or `CLOSED`. Derived from the existing index keys at render time and never stored. No existing term covers it: `is_overdue` and `is_closed` are two of its inputs. |

## Scope

In:

- A deadline tier for every dated, unfinished outline row and for the course time limit.
- Dashboard course card: a deadline band directly under the accent hero, replacing the card's
  deadline line.
- Course player outline panel: a next-deadline card at the top, and the deadline inline on the
  row's own line, at the right.
- Course player content header: the current item's deadline in a card beside the title.
- The same outline markup at desktop, tablet and in the mobile outline sheet.
- Fix the open deadlines-2 QA bug B1: the card's "Closed" deadline drops the item title.
- A new idea file for the upcoming deadlines page (see Documentation and downstream).

Out:

- The upcoming deadlines page, and any "All deadlines" link to it.
- Everything else in `design.md`: other card, panel, hero, alert, banner, drawer and popover
  options, the dashboard layout at tablet and mobile widths, durations, module counts, tags and
  bookmarks.
- Deadlines on `CoursePart` (module) rows, relative text ("3 days left"), countdowns, penalties,
  extensions, and a distinction between hard and soft deadlines. The system models none of these.
- The course detail page. It still shows no deadline dates. Its outline (`hide_deadlines=True`)
  only takes the new inline position of the existing "Closed" chip.
- The all-courses row (`partials/course_row.html`), which keeps `course_deadline_line.html` as it
  is.
- Any change to deadline resolution, policy or consequences.

## Decisions

1. **Copy stays "Deadline", "Missed deadline", "Closed", "Closes", "Access ends".** The project
   rule in the domain glossary and `docs/product/learner-experience.md` overrides the design's
   "Due", "Overdue" and "was due".
2. **Four tiers, worked out from the existing keys.** No new resolver and no new queries: the
   tier reads `due_at`, `is_overdue` and `is_closed`, which `get_course_index` already
   computes.
3. **`TODAY` uses the site zone.** A deadline is `TODAY` when it is still ahead and falls on the
   current calendar date in the site zone. That is the zone that already fixes an undated
   deadline's end of day. A learner in another zone can see "Today" for a date that their
   browser shows as tomorrow or yesterday. This is accepted.
4. **A past deadline with `mark_overdue` off is `UPCOMING`.** Deadlines-2 makes the switch
   suppress every late mark, so the deadline looks like any other dated item.
5. **Missed beats next everywhere.** The band and the next-deadline card both show the earliest
   missed deadline when there is one, and otherwise the earliest upcoming one. The time limit
   counts as one more deadline, titled "Course". This is the selection the card line uses today,
   so it is shared, not written twice.
6. **Completed items and module rows show no deadline** (user answer; deadlines-1 rule). The
   colour only ever marks work still to do.
7. **Rows use a short date and the header uses the full date.** Rows and the band show the day
   and month only, so they stay short (`idea.md`). The next-deadline card and the header card
   show the date and time, so the full instant is always one look away.
8. **Colour never works alone.** Each tier has its own icon or word as well as its colour, and
   every short form has full screen-reader text.
9. **Project theme only.** The design adds no tokens, icons or components. The existing
   `<c-chip>` variants, theme colour roles and semantic icon names express every tier.

## Requirements

### Deadline tier

In `freedom_ls/learner_interface/utils.py`:

- Add `DeadlineTier(StrEnum)` with `UPCOMING`, `TODAY`, `MISSED` and `CLOSED`.
- Add `deadline_tier(due_at: datetime, *, is_overdue: bool, is_closed: bool, now: datetime, zone: ZoneInfo) -> DeadlineTier`:
  `CLOSED` if `is_closed`; else `MISSED` if `is_overdue`; else `TODAY` if
  `now < due_at` and `due_at.astimezone(zone).date() == now.astimezone(zone).date()`; else
  `UPCOMING`.
- `_deadline_keys` adds a `deadline_tier` key (`DeadlineTier | None`, `None` when `due_at` is
  `None` or the row is complete) to `DeadlineKeys`, so every leaf row in `get_course_index`
  carries it. The zone comes from `site_time_zone(site)` in
  `freedom_ls/site_aware_models/time_zones.py`. That lookup is cached, so no query budget moves.

Each tier looks like this everywhere it appears:

| Tier | Colour | Icon (semantic name) | Visible word |
| --- | --- | --- | --- |
| `UPCOMING` | muted text | `deadline` | none in rows; "Deadline" in the cards and band |
| `TODAY` | `<c-chip variant="warning">` | `deadline` | "Today" |
| `MISSED` | `<c-chip variant="error">` | `warning` | "Missed deadline" in the cards and band; in rows, screen-reader only |
| `CLOSED` | `<c-chip variant="error">` | `locked` | "Closed" |

Chips keep `class="forced-colors:border"`.

### Short date format

In `freedom_ls/deadlines/templatetags/deadline_tags.py`, `local_time` takes an optional
`format="short"`. The tag writes it as `data-format="short"`. The server text is the day and
abbreviated month in the site zone (`site_zone_text` gains a short form). The `localTime`
component in `freedom_ls/base/static/base/js/alpine-components.js` formats it with
`{day: "numeric", month: "short"}`, adds the year when it differs from the viewer's current
year, and shows no time and no zone. The `datetime` attribute is unchanged. Without the
argument, the output is exactly what it is today.

A `TODAY` row shows the word "Today" in a `<time datetime=…>` that `localTime` does not
rewrite.

### Shared deadline selection

Move `CardDeadline`, `CardDeadlineLine` and `_card_deadline_line` from
`freedom_ls/learner_interface/views.py` to `freedom_ls/learner_interface/utils.py` as public
names (`card_deadline_line`), and give `CardDeadline` a `deadline_tier` field. Set the time
limit's tier with `deadline_tier`, the same as a row's. The dashboard (`_annotate_next_up`) and
the player both call it. B1 is fixed here: a closed `CardDeadline` keeps its title wherever it is
drawn.

### Dashboard course card band

- `freedom_ls/learner_interface/templates/cotton/course-card-shell.html` gains a named slot
  `band`. It renders as a full-width strip directly under the accent hero and is omitted when
  empty. The organisation byline still overlaps the bottom of the hero and must not cover the
  band.
- A new partial `learner_interface/partials/course_deadline_band.html` fills the slot from
  `course.missed_deadline` or `course.next_deadline` (Decision 5). On the left: the tier icon,
  the tier word, and the deadline title, with the title truncated. On the right, never
  truncated: the short date ("Today" for `TODAY`), then "Closes <short date>" when `closes_at`
  is set. The band's background uses the tier's tint (muted surface for `UPCOMING`, warning
  tint for `TODAY`, error tint for `MISSED` and `CLOSED`), with text in the matching
  `on-*-light` colour.
- A card with no deadline has no band.
- `partials/course_card.html` stops including `course_deadline_line.html`. The "Access ends
  <date>." line stays in the card body. The status eyebrow is unchanged and stays the only status
  chip in the body.

### Course player: next-deadline card

- Built in the player view (the chrome dict around `freedom_ls/learner_interface/views.py:1627`)
  from `card_deadline_line(...)`, using the `course_index`, `CourseDeadlines`, policy and `now`
  the player already has. Context key `next_deadline_card`, holding the missed-or-next
  `CardDeadline` or `None`.
- Rendered in `partials/course_toc_header.html` directly after the progress bar, inside
  `#course-toc-region`, so the HTMX Previous/Next out-of-band swap refreshes it. It contains:
  the eyebrow "Next deadline" (or "Missed deadline" for `MISSED`, "Closed" for `CLOSED`), the
  deadline title, the tier chip holding the full `local_time`, and "Closes <date>." when
  `closes_at` is set.
- Not rendered when there is no deadline, or when `hide_outline_panel` is set.

### Course player: outline rows

In `partials/course_minimal_toc.html`, the `due-date` partial moves from its own line under the
title onto the row line (`content-row-inner`), at the right. The title keeps `truncate` and the
date is `shrink-0`. The row shows the tier icon and short date, or the tier chip for `TODAY`,
`MISSED` and `CLOSED`, built from `deadline_tier`. `deadline_indent` and the second line go
away. Closed-after-sequential-lock rows (deadlines-2 rule 11) still show "Locked" with no Closed
chip. `hide_deadlines=True` still shows only the Closed chip, now inline.

`partials/deadline_labels.html` stays the single place deadline copy is written. It gains a
compact mode for rows, and the band and cards use its full mode, so no copy is forked.

### Course player: header card

- The `header_extra` block in `learner_interface/_course_base.html` no longer draws the deadline
  line. Instead, `_course_base.html` overrides `page_title` so the title and a deadline card sit
  side by side from `lg`, with the card on the right, and stack below `lg`.
- The card appears under the same condition as today (`current_entry.due_at` and status not
  `COMPLETE`). It shows the tier icon, the tier word ("Deadline", "Deadline today", "Missed
  deadline", "Closed"), the full `local_time`, and "Closes <date>." when that applies.
  `data-testid="player-item-deadline"` moves onto the card.
- It applies to every template that extends `_course_base.html`, `course_item_closed.html`
  included.

### Tablet and mobile

The outline panel is one `<dialog>`: docked from `lg`, a bottom sheet below it. One markup
change covers desktop, tablet and the mobile sheet. No new breakpoint or docked tablet layout is
added.

## Testing

- `deadline_tier`: every branch, plus these boundaries: due later today, due exactly `now`,
  due 00:00 tomorrow in the site zone, a site zone far from UTC, past with `mark_overdue` off,
  closed, and a completed row giving `None`.
- `local_time` with `format="short"`: server text, `data-format`, and the `datetime` attribute.
  Default output unchanged.
- `card_deadline_line`: the existing tests move with it. Add tier on items and on the time
  limit, and a closed deadline keeping its title (B1).
- Dashboard: a band for each tier, with visible word and icon. Missed beats next. Closes shown.
  No band without a deadline, for a completed course, when access is withheld or access has
  ended. The "Access ends" line stays in the body. Existing card-line tests are rewritten to the
  band.
- Player: the next-deadline card for each tier, the time limit as "Course", absence with no deadline, and its presence in the out-of-band `#course-toc-region` of an HTMX
  Previous/Next response.
- Outline rows: the inline date and chip per tier, nothing on completed and module rows,
  `hide_deadlines` keeping only the Closed chip, and the sequential-lock rule.
- Header card: each tier, absence on a completed item, and the moved `data-testid`.
- Query budgets: `test_player_page_query_count_*` (54/51) and the dashboard ceilings
  (`IN_PROGRESS_MAX_QUERIES`, `BYLINE_DASHBOARD_MAX_QUERIES`,
  `test_in_progress_query_count_does_not_grow_with_cards_carrying_deadlines`) stay as they are.
- Playwright (`learner_interface/tests/playwright/test_course_browse_flow.py`): at 375px, a long
  row title truncates and its date stays whole. The band date stays whole on a narrow card. The
  header card stacks under the title below `lg`.

## Success criteria

- A dashboard card with a missed item deadline shows a band under the hero reading "Missed
  deadline", the item title and the short date, with the error tint and warning icon.
- A card whose only deadline is the time limit, due later today in the site zone, shows a
  `TODAY` band titled "Course".
- A card whose deadline is closed names the item in its band.
- A card with no deadline has no band.
- The player's outline panel opens with a next-deadline card that matches the dashboard band's
  deadline for the same learner and course, and it still matches after Previous/Next.
- Every dated, unfinished outline row shows its date on the row's own line, at the right, and a
  long title truncates before the date does at 375px.
- Completed rows and module rows show no deadline.
- The current item's deadline card sits to the right of the title at `lg` and below it on
  mobile.
- No learner-facing string reads "Due" or "Overdue".
- Each tier is identifiable with colour removed (forced colours or greyscale).
- All query-budget tests pass with unchanged ceilings.
