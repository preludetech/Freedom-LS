# Frontend QA: served paper record

Nothing in this change is meant to look different. A quiz is served in authored order, so the
main job here is to show that the learner runner, the results page, the application form and the
educator preview behave as they did, and that a sitting keeps its paper when the form changes
under it.

## Setup

- Start the server: `uv run python manage.py runserver $PORT`
- Base URL: `http://127.0.0.1:$PORT`
- Admin login: `demodev@email.com` / `demodev@email.com`
- The Django admin is at `/admin/`. Form progress records are under Form engine.

### Data needed

Ask the data helper for these. Each learner needs a password you are given.

1. **Quiz course.** A course a learner is registered on, holding one QUIZ form with:
   - 3 pages, each with a title;
   - page 1: a content block, then a multiple-choice question;
   - page 2: a checkboxes question and a dropdown question;
   - page 3: a multiple-choice question;
   - every question with 4 options and one or more marked correct;
   - `quiz_show_incorrect` on, a pass percentage set, `submit_on_exit` off.
   `qa_create_checkbox_scoring_quiz` and `qa_create_multiselect_quiz_scoring` build quizzes close
   to this; extend or follow them.
2. **Two learners** on that course who have not started the quiz: learner A and learner B.
3. **Submit-on-exit quiz.** A second QUIZ form on the same course with `submit_on_exit` on and
   two pages.
4. **Survey.** A non-quiz form (UNSCORED or CATEGORY_VALUE_SUM) on the same course, two pages.
5. **Quiz application form.** A course open for applications whose application form is a QUIZ
   form with two pages. `qa_create_second_application_form_course` builds an application course;
   the form's strategy must be QUIZ.
6. **Old sitting.** One completed quiz sitting for a third learner, learner C, with
   `served_paper` null and scores stored, as a sitting completed before this change would be.

## Test 1: a quiz sitting works as before and records its paper

1. Log in as learner A. Open the quiz course and go to the quiz's start screen.
2. In another browser session, log in as admin and confirm learner A has no form progress record
   for the quiz yet.
3. As learner A, start the quiz.
   - Expect: page 1 opens, the URL ends with page number 1, the header reads "Page 1 of 3".
   - Expect: the content block shows above question 1, and the question is numbered "1.".
   - Expect: the four options show in the order they were authored.
4. As admin, open learner A's form progress record for the quiz.
   - Expect: a "Served paper" field in the Progress section, next to "Asked".
   - Expect: it is read-only, with no input to edit it.
   - Expect: it holds a `seed` number, a `pages` list of 3 entries and an `options` object.
   - Copy the value somewhere for step 9.
5. As learner A, answer question 1 and go to the next page.
   - Expect: page 2, "Page 2 of 3", questions numbered "2." and "3.".
   - Expect: the checkboxes show "Select all that apply." and the dropdown lists its options in
     authored order with a blank first entry.
6. Use Previous.
   - Expect: page 1, with the answer from step 5 still selected.
7. Use the page-jump nav.
   - Expect: pages 1 and 2 can be opened. Page 3 cannot until it has been reached.
8. Reload the page twice.
   - Expect: the same page, questions, options and order each time.
9. As admin, reload the form progress record.
   - Expect: the Served paper value is identical to the copy from step 4, seed included.

## Test 2: resume and save-and-exit

1. Continue as learner A from Test 1, on page 2. Answer both questions and go to page 3.
2. Leave by the exit control and choose to save and exit.
   - Expect: the quiz start screen, offering to continue.
3. Continue the quiz.
   - Expect: page 3 opens, "Page 3 of 3".
4. Open the URL for page 1 directly by changing the page number in the address bar.
   - Expect: page 1 with its saved answer.
5. Open the URL with page number 9.
   - Expect: a 404 page, not a server error.

## Test 3: completing, scoring and the results page

1. As learner A, answer page 3 so that exactly one question in the whole quiz is wrong, and
   submit the last page.
   - Expect: the results page, with a score of 3 out of 4 and the matching percentage.
   - Expect: the passed or failed verdict matches the pass percentage.
   - Expect: the incorrect-answers list names only the one wrong question, with the selected and
     the correct option.
   - Expect: no "score is out of date" notice.
2. As admin, open the form progress record.
   - Expect: Completed time is set, Scores holds `score` 3 and `max_score` 4, Asked is filled,
     and Served paper is still the value from Test 1.

## Test 4: the form changes under a sitting

Use learner B, who has not started.

1. As learner B, start the quiz and answer page 1 only. Stay on page 2.
2. As admin, in the Django admin:
   - change the `order` of the quiz's pages so the authored page 3 comes first;
   - change the `order` of the options on the page 1 question so the last option comes first.
3. As learner B, reload page 2, then use Previous and Next across all pages.
   - Expect: the pages come in the order learner B started with, not the new order.
   - Expect: "Page N of 3" counts along that original order.
   - Expect: the page 1 question shows its options in the original order, with the earlier answer
     still selected.
   - Expect: no error on any page. Note that URLs carry the page's current authored number, so
     the number in the address bar can differ from the "Page N" shown.
4. Log in as learner C's replacement: a fresh learner with no sitting, or reset learner A's
   sittings with `qa_clear_form_sittings` and start again as learner A.
   - Expect: the new sitting is served in the new authored order, pages and options.
5. As learner B, finish the quiz.
   - Expect: the results page shows a score out of 4 and no "score is out of date" notice.
6. As admin, restore the page and option order.

## Test 5: an item is removed after a sitting completes

Admin cannot delete form rows, so ask the data helper to delete by primary key.

1. Note learner B's score and percentage on the results page from Test 4.
2. Have the data helper delete one option that learner B did not select, on a question learner B
   was served.
3. As learner B, reload the results page.
   - Expect: the page renders. The score and percentage shown are the stored ones from step 1.
   - Expect: no "score is out of date" notice.
4. Have the data helper move one served question that learner B left correct to a different form
   (set its `form_page` to a page of the survey).
5. As learner B, reload the results page.
   - Expect: the page renders with the stored score and no "score is out of date" notice.
6. As admin, open learner B's form progress record.
   - Expect: Served paper still lists the removed option's id and the moved question's id.
   - Expect: the answers section of the record renders with no error.

## Test 6: the outdated-score notice still works

1. As admin, open learner C's old sitting (Served paper is empty).
2. As learner C, open the quiz results page.
   - Expect: it renders with the stored score.
3. As admin, change which option is correct on a question so learner C's stored score no longer
   matches a recount.
4. As learner C, reload the results page.
   - Expect: the "score is out of date" notice shows, as it did before this change.
5. As admin, restore the correct option.
6. Repeat steps 3 to 5 for learner A's completed sitting from Test 3, which has a served paper
   and nothing missing.
   - Expect: the notice shows for learner A too, and disappears once the option is restored.

## Test 7: submit-on-exit

1. As a learner with no sitting on the submit-on-exit quiz, start it, answer page 1, then leave by
   the exit control and submit.
   - Expect: the results page with a score.
2. As admin, open that form progress record.
   - Expect: Served paper is filled and Completed time is set.
3. As another learner, start the submit-on-exit quiz, then navigate away without using the exit
   control and come back to the quiz's start screen.
   - Expect: the abandoned sitting is finalised and the start screen shows a completed attempt,
     with no error.

## Test 8: a non-quiz form gets no served paper

1. As learner A, start the survey, answer page 1, go to page 2, go back, then complete it.
   - Expect: navigation, "Page N of 2" and completion all work.
2. As admin, open that form progress record.
   - Expect: Served paper is empty. Asked is filled.

## Test 9: the application form

1. Log out. Open the application course's public page and start an application as an anonymous
   applicant. Fill in the applicant details and continue.
   - Expect: page 1 of the application form. The Back link goes to the applicant-details page.
2. Answer page 1 and continue.
   - Expect: page 2. The Back link goes to page 1 of the form, not to applicant details.
3. Continue to check-your-answers.
   - Expect: one card per page, in page order, each with an Edit link.
4. Use Edit on page 1's card, change the answer and save.
   - Expect: you return to check-your-answers with the new answer shown.
5. As admin, open the application's form progress record.
   - Expect: Served paper is filled.
6. Submit the application.
   - Expect: the status page, with no error.
7. Open the URL of page 1 of the submitted application as its signed-in owner if the applicant
   has an account, otherwise skip this step.
   - Expect: the page renders read-only, with the inputs disabled and options in the same order.
8. Start an application on a course whose application form is not a quiz and walk two pages.
   - Expect: it works as before, and its form progress record has an empty Served paper.

## Test 10: the educator preview

1. As admin, open the educator interface, open the quiz course's outline and preview the quiz.
   - Expect: each page's questions show with options in authored order.
   - Expect: correct answers carry the answer mark, including under the dropdown.
   - Expect: no error, and no sitting is created by previewing: the admin list of form progress
     records has the same count before and after.

## Test 11: the cohort report

1. As admin, generate the cohort report for a cohort holding learners A and B, after Tests 3
   to 5.
   - Expect: the report generates with no error.
   - Expect: learner A's quiz section shows 3 of 4 with the one wrong question listed.
   - Expect: learner B's section lists no question that was removed in Test 5 as wrong or
     unanswered.

## What else to watch for

- Any 500 on a runner page, the results page, check-your-answers or the admin record after form
  content was reordered or removed.
- A sitting's "Page N of M" total changing between reloads.
- A second tab: open the same quiz page in two tabs before the first page has loaded in either,
  then compare. Both tabs must show the same pages and options, and the admin record must hold one
  paper.
- Viewports: check the runner page and the results page at phone, tablet and desktop widths for
  horizontal overflow, since the option lists were re-templated.
