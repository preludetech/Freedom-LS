# Spec: served paper record

Spec 1 of 4 in the SACAA compliance effort. Inputs: `idea.md`, `answers.md` and the
`research_*.md` files beside this spec, plus the effort research named under Resources.

## Purpose

A SACAA audit needs the exact paper a learner sat: which pages, questions and options, in which
order, reproducible years later. Today `FormProgress` stores no order, and quiz scoring walks the
whole live form. This spec stores the served paper on each quiz `FormProgress` and makes
navigation and scoring read it. Nothing shuffles yet, so every quiz looks and scores exactly as it
does today. `sacaa-compliance-2-shuffle`, `-3-question-pools` and `-4-attempt-review` build on it.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| served paper | coined | The pages, children and option order one `FormProgress` was served, stored in `FormProgress.served_paper`. No existing term: `asked` is an unordered set written at completion. |

## Scope

In:

- `FormProgress.served_paper`, written once per quiz sitting and never changed afterwards.
- The path builders, learner navigation (next, previous, resume, page jump, "page N of M") and
  option rendering read the served paper.
- Quiz scoring, the incorrect-answers list, the results page's outdated-score check and the report
  recompute count only served questions.
- Fallback to today's behaviour for any `FormProgress` with no served paper.

Out:

- Shuffling, option locks, keep-together groups and any author-facing flag
  (`sacaa-compliance-2-shuffle`).
- Drawing N questions from a page (`sacaa-compliance-3-question-pools`).
- Displayed order in the educator preview (`full_path`), the admin answer groups and the form
  export, and any per-attempt educator view (`sacaa-compliance-4-attempt-review`).
- Frozen copies of question text (`content_snapshots`, paused). That includes the quoted SACAA
  141.07.1(e) rule that a revised question becomes a new item kept for audit
  (`research_prior_art.md` section 2).
- Non-quiz forms. They get no served paper and their conditional paths are untouched.
- Exam time limits and retake waiting periods.

## Decisions

- **Written lazily, on the first page-serving request.** Two production sites create a
  `FormProgress`, and QA seeders build more by hand (`research_codebase.md` section 3). A write
  at creation misses some of them, and the same lazy write also covers attempts that are in flight
  at deploy (`answers.md`).
- **Write-once by a conditional update.** `filter(pk=..., served_paper__isnull=True).update(...)`,
  then re-read the field, so two tabs racing on the first request both end up reading the first
  writer's paper.
- **The order is stored explicitly; the seed is provenance only.** Nothing reads the seed to
  rebuild an order (idea, "What is settled").
- **References are string uuids**, as `asked` already uses. `content_save` keeps uuids stable
  across re-imports.
- **`asked` stays.** `complete()` keeps writing it. Readers prefer `served_paper` when present.
  Replacing `asked` would touch the admin, `answer_groups` and the export for no gain while
  served equals authored.
- **Missing items are skipped on read; the stored paper never drops an id** (`answers.md`). An
  item is missing when no row with its id belongs to this form any more (deleted, or moved to
  another form). A question moved to another page of the same form is still found and shown
  under its served page.
- **`furthest_page_reached` keeps storing an authored page number** and is translated to a served
  position wherever it is compared. One meaning for the column across quiz and non-quiz forms,
  and record-less attempts are unaffected.
- **Stored scores are never rewritten**, as today. Saved marks are what an audit relies on.

## Requirements

### Model and migration (`freedom_ls/form_engine/models.py`)

- Add `FormProgress.served_paper = models.JSONField(null=True, blank=True)` with help text "The
  pages, children and option order this sitting was served. Written once, before the first page
  is shown." Migration `0010` (renumber on rebase if another form_engine migration lands first).
  No backfill. Old rows stay null. Do not use a callable default, because `AddField` would give
  every existing row the same value.
- Shape:

  ```json
  {
    "seed": 7340032118422265097,
    "pages": [
      {"id": "<page uuid>", "children": ["<content or question uuid>", "..."]}
    ],
    "options": {"<question uuid>": ["<option uuid>", "..."]}
  }
  ```

  `pages` and each `children` list are in served order. `options` holds every served question
  that has options, in served order. `seed` is a random non-negative 63-bit int from `secrets`.
- Show `served_paper` read-only in the `FormProgress` admin beside `asked`
  (`form_engine/admin.py` fieldset).

### Building and writing the served paper (new `freedom_ls/form_engine/served_paper.py`)

- `build_served_paper(form: Form) -> dict[str, object]` builds the paper from the form's current
  tree in authored order: `form.pages.all()`, `page.children()`, `question.options.all()`. This
  is the one place `sacaa-compliance-2-shuffle` will change.
- `ensure_served_paper(form_progress: FormProgress) -> None` writes the paper when all of these
  hold: the form's strategy is QUIZ, `served_paper` is null and `completed_time` is null. It
  uses the conditional update from Decisions. In every other case it does nothing.
- Call `ensure_served_paper` before the path is built in each page-serving request:
  - `form_start` and `form_fill_page` (GET and POST) and `form_submit_and_exit`
    (`learner_interface/views.py`);
  - the application resume, page (GET and POST) and check-your-answers views
    (`course_applications/views.py`);
  - `FormProgress.complete()`, so `finalise_stale_incomplete` and submit-and-exit still complete
    against a served paper.
- These callers do not write; they read with fallback: the course start screen (`view_form`,
  read-only by design), admin `answer_groups`, the export, the file-upload guard
  (`form_engine/views.py`) and the reports app. A record-less in-flight quiz read there is in
  authored order, which is the paper it will be served.

### Path (`freedom_ls/form_engine/conditions.py`)

- Add `served_path(form: Form, served_paper: Mapping[str, object]) -> SittingPath`. It walks the
  paper in order, looks each id up in the prefetched tree of this form, and skips missing items.
  A served page all of whose served children are missing is skipped. Options are looked up the
  same way. Prefetch `pages__questions__options` so building it adds no per-question queries.
- `SittingPath` carries served order:
  - `numbered_pages()`, `pages`, `questions()`, `_page_positions` and `question_positions()`
    follow the path's page order, not `all_pages` order. `all_pages` stays authored, so a page's
    number is still its authored index and URLs, `page_at`, `resolve_page` and
    `off_path_landing` are unchanged.
  - `next_page_number`, `previous_page_number`, `first_page_number_at_or_after`,
    `last_page_number` and `landing_page_number` compare served positions, not authored numbers.
    A number that is not on the path is placed by its authored order relative to the on-path
    pages, as today, so off-path landings behave as they do now.
  - New `options_of(question: FormQuestion) -> list[QuestionOption]`: the served option order,
    or `question.options.all()` for a path with no served paper.
- `current_path(form_progress)` returns `served_path(...)` when `served_paper` is set, else
  `compute_path(...)` as today. `compute_path` and `_condition_holds` are not changed (they
  collide with `form-engine-branch-logic-2-and-conditions`).
- `sitting_path` precedence becomes: `served_paper`, then `asked`, then `full_path` for a
  completed sitting, then `compute_path`.

### Navigation (`freedom_ls/form_engine/paging.py`, `models.py`)

Each of these compares served positions, translating authored numbers through the path:

- `_furthest_answered_page` and `_resume_page_number` (resume), keeping the existing clamp for a
  stored number that no longer resolves.
- `build_page_links`: `is_accessible` is "position at or before the furthest reached position".
- `first_page_number_with_unanswered_required(after=...)`.
- `FormProgress.record_page_reached(page_number)`: forward-only by served position. It still
  stores the authored number.
- `FormProgress.get_current_page_number` already iterates `numbered_pages()` and needs no change
  beyond that.

The learner sees "page N of M" from `page_position` and `total_pages` as today, and these now
come from served order.

### Option rendering (`freedom_ls/form_engine/templates/form_engine/inputs/`)

- `multiple_choice.html`, `checkboxes.html`, `dropdown.html` and the dropdown answer key render
  options in `path.options_of(question)` order, passed through the page context. They no longer
  iterate `question.options.all`.

### Scoring and results (`freedom_ls/form_engine/models.py`, `learner_interface/views.py`)

- `compute_quiz_scores`, `score_quiz` and `get_incorrect_quiz_answers`: for a sitting with a
  served paper, walk `sitting_path(self).questions()`. `max_score` is the total over those
  questions. With no served paper, walk the whole form exactly as today. `score(path)` passes the
  path to the quiz strategy.
- Results page outdated-score check (`learner_interface/views.py`, the `stored_score_outdated`
  block): for a sitting with a served paper, always compare `score`. Compare `max_score` only
  when every served question still exists. A deleted served question is always unanswered,
  because `QuestionAnswer.question` is PROTECT, so a deletion changes only `max_score`, and the
  notice never fires for it (`answers.md`). A sitting with no served paper keeps today's check.
- Results page incorrect-answer labels stay as they are (`question.question_number`). They only
  differ from served positions once `sacaa-compliance-2-shuffle` lands.

### Reports (`freedom_ls/reports/indexes.py`)

- `load_form_progress_rows` carries each sitting's served question ids. `build_sat_questions`
  pairs a sitting that has a served paper only with its served questions that still exist. A
  sitting with no served paper keeps today's pairing with every question of its form.

## Testing

Prove each of these with tests under the mirrored test paths (`ds:testing`, `fls-dev:testing`):

- **Round trip.** Starting a quiz writes `served_paper` once. Reading it back gives exactly the
  pages, children and option order written. A second request does not rewrite it, and a later
  content reorder does not change it.
- **Write-once race.** Two `ensure_served_paper` calls on the same record-less sitting leave the
  first paper in place.
- **Gating.** Non-quiz forms and completed sittings get no served paper. An in-flight quiz
  sitting with none gets one on its next page request. `view_form`, `answer_groups` and the export
  never write one.
- **Injected order, navigation.** With a served paper whose page, child and option order differ
  from authored order, next, previous, resume and page jump follow it. URLs carry authored
  numbers, the screen shows served "page N of M" and served question numbers, and a refresh or
  resume shows the same paper. The application flow does the same.
- **Injected subset, scoring.** With a served paper that omits questions, `score`, `max_score`,
  `quiz_percentage` and `passed` count only served questions. The incorrect-answers list leaves
  out unserved questions, the results page shows no outdated notice, and the report pairs the
  sitting only with served questions.
- **Missing items.** A served page, unanswered question or option deleted after the paper was
  written is skipped in navigation and scoring, `max_score` shrinks, the stored paper keeps the id
  and the outdated notice does not fire. A served question moved to another form is treated as
  missing. One moved to another page of the same form still appears under its served page.
- **Fallback.** A sitting with no served paper navigates, scores and reports exactly as today. The
  existing outdated-score tests in `learner_interface/tests/views/test_form_runner.py` pass
  unchanged.
- **Regression.** The existing conditions, paging, page-flow, scoring, export and runner suites
  pass with every quiz served in authored order.

## Open questions

- Q: Should the served paper also be written when a quiz `FormProgress` is created in
  `get_or_create_incomplete` and `_start_application`, in addition to the lazy write? → A: No,
  the lazy write alone. (assumed default: the first page request runs before any learner sees a
  page, so the paper is the same. Overrule by editing "Building and writing the served paper".)
- Q: Once written, is the served paper read even if the form's strategy later changes away from
  QUIZ? → A: Yes, a written paper is always read. (assumed default: the paper must not change for
  the life of the attempt, and strategy changes after attempts exist are rare. Overrule by
  editing "Path".)
- Q: Is the seed a separate column rather than a key inside `served_paper`? → A: A key inside the
  JSON. (assumed default: nothing reads it in this effort except as provenance, and one field
  keeps the write atomic. Overrule by editing "Model and migration".)

## Success criteria

- Every quiz `FormProgress` that serves a page has a non-null `served_paper`, and the value does
  not change after it is written.
- With every served paper in authored order, the full existing test suite passes unchanged.
- The injected-order and injected-subset tests above pass for both the course runner and the
  application flow.
- A record-less sitting's score, navigation and report rows are identical to today's.
- Deleting a served item never raises an error, never rewrites a stored score and never shows the
  outdated-score notice.
