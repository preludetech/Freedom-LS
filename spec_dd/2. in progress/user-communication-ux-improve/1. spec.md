# Spec: user-communication UX improvements

Source: `idea.md`. Research beside it: `research_codebase.md`, `research_best_practices.md`,
`research_reference_implementations.md`, `research_prior_art.md`, `research_ux_patterns.md`,
`research_known_complaints.md`.

## Purpose

Direct messaging (spec `user-communication-4-direct-messaging`) works, but people reach it through
too many doors and some doors are missing. Messages count twice, once on the header button and once
in the bell. A separate inbox page and an educator-interface Messages section duplicate the two-pane
thread view. Nobody can start a conversation from the thread view, and learners have no one to
message by default. An educator can't see their conversation with a learner from that learner's
page. An organisation admin can't see conversations between learners and educators at all.

## Scope

In:

- Header messages button: icon only, with a dropdown of recent conversations.
- Messages stop raising bell notifications.
- One messages page: the two-pane view at `/messages/`, which replaces the inbox page.
- Starting a conversation from that page, with a recipient list shown before typing.
- Learners may message their educators by default.
- The educator-interface Messages section is removed.
- A Messages tab on the educator interface's learner page.
- Read-only, audited oversight of learner-educator conversations for organisation and site admins.

Out:

- The course-player "ask for help" request, the shared help-desk queue and help tickets. These get
  their own follow-up spec (see Documentation and downstream).
- Learner-to-learner messaging defaults. `learner_to_cohort_peer` and `learner_to_course_peer` stay
  closed until report and block exist (`user-communication-6-moderation`).
- Group conversations, attachments, real-time push. These stay out, as in spec 4.
- Oversight of learner-to-learner and educator-to-educator conversations.

## Decisions

1. **`message.received` is deleted, not hidden.** The header badge already shows unread
   conversations, so a bell row repeats it. The rollup machinery (`NotificationCategory.rollup`,
   `Notification.rollup_key`, the rollup branch in `comms/notify.py`, `mark_notifications_read`)
   stays, now tested against a test-only category, because the next rollup category will need it.
   Existing `message.received` rows are left in place. `NotificationManager` already hides rows of
   unconfigured categories, so no data migration is needed.
2. **The URL name `conversations:inbox` stays and now renders the two-pane page.** Keeping the name
   keeps every `reverse("conversations:inbox")` caller (login redirect, back links) valid. Only the
   template and the view change.
3. **No conversation is auto-selected on `/messages/`.** Auto-selecting would mark a thread read that
   the user never chose to open. On wide screens the thread pane shows a placeholder. On narrow
   screens the list fills the page.
4. **`learner_to_educator` defaults to `open`.** Offered roles stay `["cohort_admin"]`.
5. **Oversight reads go through a separate view, not `thread`.** `participant_conversation()` 404s
   non-participants and `thread_context()` marks the thread read. Oversight uses neither, so a
   participant's unread state can never change because an admin looked.
6. **Oversight is reached through the learner page only.** An admin opens the learner and reads that
   learner's conversations with educators. There is no organisation-wide conversation list. The
   removed Messages section is not rebuilt in another shape.
7. **Disclosure is static copy, not computed per conversation.** `comms` may not import organisation
   or role code (`comms/tests/invariants/test_boundaries.py`). One line beside every composer is
   accurate for every conversation: "Organisation admins can read conversations between learners and
   their educators."
8. **Who counts as an educator of a learner for oversight is decided at read time** by
   `learner_management.queries.educators_of(learner)`. A conversation with someone who no longer holds
   an educator role over the learner drops out of the admin's view.

## Requirements

### Header button and recent-conversations dropdown (`freedom_ls/comms/`)

- `templates/comms/partials/messages_button.html` becomes a `<button>` with only
  `<c-icon name="message">` and the `#messages-badge` badge. The visible "Messages" label goes at
  every width. The accessible name still reads "Messages" plus the unread count, through the existing
  `aria-labelledby="messages-button-label"` span that `unread_badge.html` supplies. The badge's
  `hx-get`/`hx-trigger` and `refreshTimer` polling stay unchanged.
- The button opens a WAI-ARIA disclosure panel built on the bell's markup in
  `partials/notification_bell.html`: `aria-expanded`, Escape and click-away close it, focus returns
  to the button, the panel is a full-screen sheet below `sm` with a close button, and it has separate
  loading and failed blocks with "Try again". It is not `<c-dropdown-menu>`.
- The panel's content loads on first open from a new URL, `conversations:recent` (`recent/`), view
  `partial_recent_conversations` under `@messaging_view`. A page render still runs no conversation
  query, and `test_a_page_render_runs_no_conversation_query` stays green. The panel reloads on
  `conversationChanged from:body` while it is open.
- Rows show the five most recent conversations from `inbox_for(user)`: avatar, the other
  participant's name, a one-line excerpt of the last message, relative time, and unread styling that
  doesn't depend on colour alone. `inbox_for` gains a `last_message_body` subquery annotation for the
  excerpt. Each row links to `conversations:thread`.
- Panel header: a "New message" link to `conversations:start`, shown only when the user has
  recipients. Panel footer: "See all messages", linking to `conversations:inbox`. Empty state: "No
  messages yet.", plus "New message" when the user has recipients.
- Opening the messages panel closes the bell panel, and opening the bell panel closes the messages
  panel. Both live in `freedom_ls/base/templates/partials/header_bar.html`. A shared window event
  works and is the simplest option.

### Messages raise no notification (`freedom_ls/comms/`, `freedom_ls/base/`)

- `comms/messaging.py:send_message` stops calling `raise_notification`.
  `mark_conversation_read` stops calling `mark_notifications_read`.
- Delete the `message.received` entry from `freedom_ls/base/notification_categories.py`, delete
  `comms/notification_urls.py`, and delete its test, `comms/tests/test_notification_urls.py`.
- `comms/tests/test_notify.py` drives its rollup tests through a test-only category with
  `rollup=True` registered by fixture, not `message.received`.
- `qa_helpers/management/commands/qa_create_direct_messaging_scenario.py` stops raising
  `message.received` rows (`_raise_unread_notifications`).

### One messages page (`freedom_ls/comms/`)

- `messaging_views.inbox` renders `comms/thread.html` with no conversation selected. The thread pane
  shows "Select a conversation to read it." and a "New message" button when the user has recipients.
  When the user has no conversations, the pane says so instead, and keeps the button when there are
  recipients. `comms/inbox.html` is deleted. The htmx branch keeps returning the `conversation-list`
  partial for `inbox_poll`.
- `thread.html` below `md`: with no thread selected, the list fills the page and the thread pane is
  hidden. With a thread selected, the thread fills the page and the existing back arrow in
  `partials/thread.html` links to `conversations:inbox`. Thread selection uses real links, so the
  browser's back button and deep links work.
- The list pane gets a header with the title "Messages" and a "New message" button, gated on the
  existing `has_recipients`. The selected row carries `aria-current="true"`.

### Starting a conversation from the messages page (`freedom_ls/comms/`)

- "New message" on the messages page opens the existing recipient picker
  (`partials/recipient_picker.html`) in a modal over the two-pane page. Choosing a recipient loads
  the composer with that recipient. The first send answers with `HX-Location` to the new thread, as
  `_send_response` already does. Choosing someone the user already has a conversation with opens that
  conversation. A send refused by policy returns 422 and keeps the draft, as in spec 4.
- `search_recipients` with an empty term lists recipients straight away, grouped by
  `group_recipients`. `PICKER_MIN_TERM_LENGTH` no longer gates the first list. The list is capped at
  `PICKER_RESULT_LIMIT`, and above the cap the existing truncation note asks the user to type to
  narrow it. `PICKER_LIST_ALL_LIMIT` is removed. Typing filters server-side as it does today.
  Absent and refused names still produce identical output.
- Each recipient row carries a secondary line with its group context (role or course or cohort) when
  `include_email` is off, so two people with the same name can be told apart.
- `conversations:start` keeps working as a full page for direct links. Its back link goes to
  `conversations:inbox`.

### Learners can message their educators (`freedom_ls/messaging_policy/`)

- In `messaging_policy/config.py`, `MESSAGING_DEFAULT_FLAGS["learner_to_educator"]` becomes
  `"open"`. The two peer flags stay `"closed"`. Per-site, organisation, cohort, registration and
  learner rows still override it, as before.
- A learner whose educators include a `cohort_admin` sees "New message" in the list header, the
  dropdown and the placeholder, and sees a "Cohort admin" group in the picker.

### Educator interface: Messages section removed (`freedom_ls/educator_interface/`)

- Remove `ConversationDataTable`, `ConversationThreadPanel`, `NewMessageAction`,
  `ConversationInstanceView` and `MessagesConfig` from `views.py`, and remove `MessagesConfig` from the
  `"Teaching"` `NavGroup`. Remove the `messages_unread_count` view and its URL. Remove the templates
  `panels/conversation_thread.html`, `modal/new_message.html` and
  `data-table-cells/conversation_{with,last_message,state}.html`.
- The panel-framework hooks `SectionConfigBase.get_menu_count_url`, `get_menu_count_poll_seconds`
  and `is_available` stay. They are generic.
- `quick_views.py` `LearnerQuickView`: the message box's "Open conversation" link points to the
  learner page's Messages tab, not `messages/{pk}`.
- `educator_interface/messaging.py` keeps `conversations_in_organisation` only if the Messages tab
  uses it. Otherwise it is removed.

### Educator interface: Messages tab on the learner page (`freedom_ls/educator_interface/`)

- A new panel, `LearnerMessagesPanel` (`model = Learner`), added to `LearnerTabSet.children` as
  `"messages"`. It is shown when `MESSAGING_ENABLED` is on. Its body loads lazily when the tab
  activates.
- For the signed-in user, the tab shows their own conversation with the learner. It reuses
  `comms/partials/thread.html` through `thread_context()` with a fixed pane height, so opening it
  marks the conversation read for that user. A composer sits beneath it. With no conversation yet,
  the tab shows "No messages with <name> yet." and the start composer with the learner as recipient,
  when `get_messaging_policy().can_start` allows it.
- A holder of the oversight capability on the learner (next section) also sees a list of the
  learner's conversations with other educators. Each opens read-only.

### Oversight (`freedom_ls/educator_interface/`, `freedom_ls/comms/`, `freedom_ls/role_based_permissions/`, `freedom_ls/audit_log/`)

- Capability: `freedom_ls_comms.view_conversation`, the model's default view permission, added to
  `organisation_admin` and `site_admin` in `role_based_permissions/roles.py`. A data migration grants
  it, as that file's own comment requires. No other role holds it.
- The overseeable conversations of a learner are those where the learner's user is one participant
  and the other is in `educators_of(learner)`. Learner-to-learner conversations are never overseeable.
  The query lives in `educator_interface/messaging.py`. `comms` gains no new imports.
- The read-only transcript is a new panel or panel action under the learner instance, authorised by
  `LearnerConfig.authorise_instance` plus the capability. A conversation id that isn't overseeable
  for this learner is a 404. It renders the message log with no composer and a banner: "Read only.
  You are viewing this conversation as an organisation admin." It never calls
  `mark_conversation_read`, `participant_conversation` or `thread_context`. A comms helper that
  renders a message page for a given conversation, with no viewer side effects, is added for it.
- Every transcript open writes an audit entry. The new `AuditAction("conversation.viewed",
  "Conversation viewed", ...)` in `audit_log/actions.py` records the learner's organisation, the
  learner as subject, and the educator's name in `details`, through `audit_log/writer.py:record_entry`.
  It shows in the learner's existing History tab.
- Disclosure: `comms/partials/composer.html` and the start composer carry the line from Decision 7, in
  muted text.

## Testing

- Header: the button has no visible "Messages" text, its accessible name includes the count, and
  page renders still run no conversation query. `conversations:recent` returns at most five rows,
  newest first, with the excerpt and unread marker. It shows another user none of the viewer's
  conversations. The empty state shows and hides "New message" according to `has_recipients`.
- Opening one header panel closes the other (Playwright).
- Sending a message creates no `Notification` row. Reading a thread runs no notification query.
  The rollup suite passes on the test-only category.
- `/messages/` renders the two-pane page with the placeholder and no conversation marked read. At a
  narrow viewport, the list shows, then the thread, then back returns to the list (Playwright).
- Picker: an empty term lists recipients grouped and capped, with the truncation note above the cap.
  The output for an absent name and a refused name is identical. Choosing an existing counterpart
  opens the existing thread. A refused first send returns 422 with the draft kept.
- Policy: with no override rows, a learner can start a conversation with a `cohort_admin` of their
  cohort, and can't start one with a cohort peer. An organisation row with `learner_to_educator`
  closed still closes it.
- Educator section removed: the educator URL `.../messages/` is a 404. The sidebar has no Messages
  entry. The quick-view link opens the learner's Messages tab. The interface walk and invariant
  suites (`test_permission_matrix.py`, `test_organisation_isolation.py`,
  `test_config_authorisation.py`) pass with the tab added and the section removed.
- Messages tab: an educator sees only their own conversation with the learner. Sending from the tab
  works. An educator of another organisation gets a 404.
- Oversight: an organisation admin sees the learner's conversations with educators and doesn't see the
  learner's conversations with peers. A `cohort_admin` or `cohort_viewer` sees no other educator's
  conversations. Opening a transcript writes one `conversation.viewed` entry, leaves both
  participants' `last_read_at` unchanged, and renders no composer. Another organisation's learner, or
  a conversation outside the overseeable set, is a 404. The disclosure line renders beside the
  composer.

  learner-educator conversations.

## Open questions

- Should installs be able to switch oversight off, for example with a setting that removes the
  capability? This spec adds no switch.

## Success criteria

- The header messages control has no visible text and opens a panel listing up to five recent
  conversations.
- Sending a message adds nothing to the recipient's bell.
- `GET /messages/` renders the two-pane page, and `comms/inbox.html` no longer exists.
- A learner in a cohort with a `cohort_admin` can start a conversation with them on a fresh install.
- The educator-interface sidebar has no Messages entry, and the learner page has a Messages tab.
- An organisation admin can read, but can't reply in, a learner's conversation with an educator, and
  each read appears in the learner's History tab.
- Opening a conversation as an admin leaves its unread state unchanged for both participants.
