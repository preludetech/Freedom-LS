# Frontend QA: user-communication UX improvements

Direct messaging now lives on one page, `/messages/`, with one unread signal: the header
messages button is icon-only and opens a panel of recent conversations, messages no longer raise
bell notifications, and anyone with a recipient can start a conversation from the page. Learners
can message their cohort admins by default. On the educator interface the Messages section is gone;
a learner's page has a Messages tab showing the signed-in educator's own conversation with the
learner, and, for organisation and site admins, a read-only oversight list of the learner's other
educator conversations. Every oversight open is audited and shows on the learner's History tab.

This run walks the learner side (header, panel, page, picker, first send), the educator side (the
tab, the oversight list and open, the History entry, the removed section), and the ways it could
go wrong: a learner who should not be offered someone, a recipient reached by a guessed URL, a
send refused after the composer opened, a repeat open that must write a second audit entry, an
admin of another organisation who must get a 404, a deactivated learner with nothing under
oversight, a read marker that must not move when an admin looks, and a bell that must stay quiet.

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever
this document writes `<PORT>`. Shell variables do not survive between tool calls. Every URL below
is relative to `http://127.0.0.1:<PORT>`.

## §0 Setup

### 0.1 Server

1. `.claude/ds/scripts/find_available_port.sh`: note the number and use it literally from here on.
2. Start `uv run python manage.py runserver <PORT>` backgrounded, as its own call.
3. Open `/` and confirm `#debug-branch-badge` names the `user-communication-ux-improve` branch.
   If it names another branch, another server holds the port; go back to step 1.

personas, conversations, read markers and role grants below, deletes the personas' stray
conversations and notifications, and resets every messaging configuration row to the shipped
defaults. Anything else that is missing is created through the `fls-dev:qa-data-helper` agent,

## §1 The header button and the messages panel (Lena)

1. Log in as `l1@qa.test`. On the dashboard, find the header's messages button. Expect an icon
   only: no visible "Messages" text at any width. Its accessible name reads "Messages, 1 unread"
   (Vic's message), and the red badge shows **1**.
2. Click the button. Expect a panel below it headed **Messages**, with a **New message** button in
   the header row and a **See all messages** link in its footer. The rows are Lena's two
   conversations, newest first: **Vic Viewer** (bold, "Unread" marker, a one-line excerpt of Vic's
   message, a relative time) and **Eve Educator** (not bold, the excerpt of Lena's newest message).
3. Press Escape. The panel closes and focus is back on the button. Click the button, then click
   anywhere outside the panel. It closes.
4. Click the messages button, then the bell. Expect the messages panel to close as the bell panel
   opens. Click the messages button again: the bell panel closes. Only one header panel is ever
   open.
5. In the messages panel click the **Vic Viewer** row. Expect `/messages/<uuid>` with the thread.
   Return to the dashboard, open the panel again: the Vic row is no longer bold and the badge is
   gone.
6. Open the panel and click **See all messages**. Expect `/messages/`.

## §2 The messages page

   a **New message** button and the two rows; on the right the placeholder "Select a conversation

## §3 Starting a conversation from the messages page (Lara)

1. Log out, log in as `l3@qa.test` (Lara, Cohort A, no conversations yet). Open `/messages/`.
   Expect "No conversations yet." and **New message** in both the list header and the placeholder.
2. At the desktop viewport click **New message** in the list header. Expect the right pane to swap
   to a **New message** picker without a full page load (the list pane stays), the address bar now
   reads `/messages/new/`, and the picker already lists **Eve Educator** under a cohort group
   heading, with no search term typed. Vic Viewer is not listed (cohort viewers are not offered).
3. Type `zz` in the search field. Expect "No one you can message matches 'zz'". Clear it: Eve is
   back.
4. Click **Eve Educator**. Expect the pane to show "To Eve Educator" with a **Change** link and a
   composer whose label reads "Message to Eve Educator", plus the disclosure line under it. The
   address bar reads `/messages/new/?recipient=<pk>`.
5. Type `Hello Eve, question about module 2` and press Ctrl+Enter. Expect the page to navigate to
   `/messages/<uuid>`: the new thread with the message in the log, Lara's new row at the top of the
   list, marked current.
6. Click **New message** again and pick **Eve Educator** again. Expect to land on the same
   `/messages/<uuid>` thread, not a second composer: one conversation per pair.
7. Reload `/messages/new/` directly. Expect the full-page **New message** screen (narrow column,
   heading, the picker) with a **Back to messages** link at the top that goes to `/messages/`.
8. Phone viewport (390 wide), as Lara: open `/messages/`. Expect the list to fill the screen (no
   thread pane). Tap the Eve row: the thread fills the screen with a back arrow labelled "Back to
   messages" in its header. Tap it: the list again. Tap **New message**: the full-page picker at
   `/messages/new/`, with the back link. Check no horizontal scrollbar at 390 and 768 wide.

## §4 A guessed recipient and a send refused after the composer opened (Lara, demodev)

1. As Lara, find Vic Viewer's user id (the `fls-dev:qa-data-helper` agent, or the admin at
   `/admin/` as `demodev@email.com`). Open `/messages/new/?recipient=<vic-pk>`. Expect a 404 page,
   the same as `/messages/new/?recipient=999999` and `/messages/new/?recipient=abc`.
2. As Lara, open `/messages/new/`, choose **Eve Educator**, and type `Are replies closed?` but do
   not send.
3. In a second browser context log in as `demodev@email.com`, open the Django admin, and add an
   **Organisation messaging config** for Northside with `learner_to_educator` = closed (the
   messaging_policy app's model).
4. Back as Lara press Ctrl+Enter. Expect the composer to re-render in place with the status 422 in
   the network log and the alert "Not sent. Eve can't receive messages from you here. Your text is
   still in the box." The typed text is still in the box. Nothing was sent (Lara's thread with Eve
   shows no new message).
5. Open `/messages/<lara-eve uuid>` as Lara. Expect the composer replaced by the closed note
   "Replies are closed" with "Messaging between you and Eve is closed here. You can both still
   read this conversation." and, under it, the disclosure line.
6. As `demodev@email.com` delete that organisation messaging config row. As Lara reload the
   thread: the composer is back.
