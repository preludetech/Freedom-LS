# Plan: panel framework components

Implements `1. spec.md` in this directory. The components are the spec's public API, so a slice is
end to end when its component renders its full contract under test (template, filters, tests); slices
2, 3, 4 and 12 also wire into live view templates and URLs. Every slice leaves
`uv run pytest freedom_ls/panel_framework freedom_ls/icons freedom_ls/base` green when it is committed.
Tests come first in every slice (TDD); the test names here say what each test proves, not how it is
written.

Template mechanics verified against the installed django-cotton before planning:

- A `{% block %}` inside a cotton component's default slot or a `<c-slot>` is overridable from an
  extending template, and `{{ block.super }}` works. Cotton's nodes keep their content in
  `self.nodelist`, which Django's block discovery walks.
- `<c-chip :attrs="attrs">` forwards a component's undeclared attributes to a nested component.
  Writing `{{ attrs }}` inside a `<c-…>` tag does not work.
- `{% if actions.strip %}` is true only when a named slot has non-whitespace content, and false when
  the slot is missing. This is how every "not rendered when the slot is empty" rule is implemented.
- `<h{{ level }}>` interpolates a heading level, and `label="{{ row.label|capfirst }}"` interpolates a
  filtered value into a component attribute.
- `c-icon` has no decorative mode: its `<c-vars>` declares only `name`, `variant`, `class` and
  `aria_label`, it forwards no `attrs`, and an empty `aria_label` falls back to the semantic name. A
  decorative icon is therefore `<span aria-hidden="true"><c-icon name="…" class="…" /></span>`, the
  idiom `cotton/button.html` already uses. Every "decorative icon" below means this wrapper, and the
  tests assert on the wrapper's `aria-hidden="true"` around the `<svg>`.

## Slice 1: status badge and the chip tints

**Behaviour.** `<c-panel-status-badge tone="success" label="Active" />` renders a `c-chip` of the
matching variant; unknown tones, `primary` and `secondary` render `muted`. The default theme's status
chips meet 4.5:1. A source test guards every later component against raw colours.

**Files.**

- `freedom_ls/panel_framework/templatetags/panel_tags.py`: add
  ```python
  TONES = frozenset({"success", "warning", "error", "info", "muted"})

  @register.filter
  def tone(value: str) -> str:
      return value if value in TONES else "muted"
  ```
- New `freedom_ls/panel_framework/templates/cotton/panel-status-badge.html`:
  ```
  <c-vars tone="muted" label="" />
  {% load panel_tags %}
  {% comment %} purpose, attributes, why primary/secondary are not tones, usage {% endcomment %}

  ```
- `tailwind.components.css`: `.chip-success`, `.chip-warning`, `.chip-error`, `.chip-info` become
  `@apply bg-<role>-light text-on-<role>-light`. Nothing else in the file changes.
- New `tests/cotton_helpers.py` (above).

**Tests.**

- `test_component_status_badge.py`: each of the five tones renders `c-chip`'s `chip-<tone>` variant
  hook; `primary`, `secondary` and an unknown tone render `chip-muted` (one `parametrize`). The variant

- `test_panel_tags.py`: `tone` returns its input for the five tones and `muted` otherwise.

## Slice 3: card and the panel frame

**Behaviour.** `panel-card` renders the mockups' card chrome. `_panel_base.html` renders through it,
so every panel gets the same chrome, while `data-panel`, the region `id` and the `hx-*` attributes stay
on the panel's `<section>`. All three block names still work from both override routes.

**Files.**

- New `cotton/panel-card.html`:
  ```
  <c-vars title="" description="" heading_level="2" landmark="" />
  {% load panel_tags %}
  {% partialdef card_body %}
      {% if title %}
          <header class="flex items-start justify-between gap-4 border-b border-border px-4 py-3 sm:px-6">
              <div>
                  <h{{ level }}{% if landmark %} id="{{ title_base }}-title"{% endif %}>{{ title }}</h{{ level }}>
                  {% if description %}<p class="text-sm text-muted">{{ description }}</p>{% endif %}
              </div>
              {% if header_action.strip %}<div class="shrink-0 text-sm">{{ header_action }}</div>{% endif %}
          </header>
      {% endif %}
      <div class="px-4 py-4 sm:px-6">{{ slot }}</div>
      {% if actions.strip %}
          <footer class="border-t border-border px-4 py-3 sm:px-6">
              <c-button-group variant="right">{{ actions }}</c-button-group>
          </footer>
      {% endif %}
  {% endpartialdef %}
  {% with level=heading_level|heading_level:"2" %}
      {% if landmark %}
          {% firstof id title|slugify as title_base %}
          <section aria-labelledby="{{ title_base }}-title" class="bg-surface border border-border rounded-lg" {{ attrs }}>{% partial card_body %}</section>
      {% else %}
          <div class="bg-surface border border-border rounded-lg" {{ attrs }}>{% partial card_body %}</div>
      {% endif %}
  {% endwith %}
  ```
  Two root branches around one `{% partialdef %}` body, the shape `cotton/callout.html` already uses,
  rather than a template tag inside the tag name.
- `panels/_panel_base.html`:
  ```
  <section data-panel="{{ name }}" {% if not region_template_name %}id="{{ region_id }}"{% endif %}
           hx-get="{{ base_url }}" hx-trigger="panelChanged from:body" hx-target="#{{ region_id }}" hx-swap="outerHTML">
      <c-panel-card :title="title" heading_level="2">
          {% block panel_header %}{% endblock panel_header %}
          {% block panel_body %}{% endblock panel_body %}
          <c-slot name="actions">
              {% block panel_actions %}{% for action in actions %}{% render_action action panel.ctx %}{% endfor %}{% endblock panel_actions %}
          </c-slot>
      </c-panel-card>
  </section>
  ```
  Rewrite the template's comment to say why the section, not the card, carries the plumbing, and
  that `panel_header` is a hook for content above the body now that the card owns the heading.

**Tests.**

- `test_component_card.py`: `<div` root by default; `<section aria-labelledby="…-title">` pointing at
  the heading's `id` when `landmark` is set, using the caller's `id` when given; no `<footer>` without

## Slice 5: progress bar

**Behaviour.** `<c-panel-progress-bar percentage="72" label="Course progress" />` renders a native

readable under forced colours.

**Files.**

- `panel_tags.py`:
  ```python
  @register.filter
  def clamp_percentage(value: int | float | str) -> int:
      return min(100, max(0, int(float(value))))
  ```
- New `cotton/panel-progress-bar.html` with `<c-vars percentage="0" label="Progress" show_label="" />`,
  a `<style>@layer components { .panel-progress-bar { … } .panel-progress-bar::-webkit-progress-bar
  { background-color: var(--color-surface-2) } .panel-progress-bar::-webkit-progress-value,
  .panel-progress-bar::-moz-progress-bar { background-color: var(--color-primary) } @media
  (forced-colors: active) { .panel-progress-bar { border: 1px solid CanvasText }
  .panel-progress-bar::-webkit-progress-bar { background-color: Field }
  .panel-progress-bar::-webkit-progress-value, .panel-progress-bar::-moz-progress-bar
  { background-color: Highlight } } }</style>` block, then
  ```
  {% with value=percentage|clamp_percentage %}
  <div class="flex items-center gap-2" {{ attrs }}>
      {% if show_label %}<span class="text-sm text-muted">{{ label }}</span>{% endif %}
      <progress class="panel-progress-bar w-full h-2 rounded-full overflow-hidden" aria-label="{{ label }}" value="{{ value }}" max="100">{{ value }}%</progress>
  ```

## Slice 8: avatar chip

**Behaviour.** `<c-panel-avatar-chip name="Thandi Mokoena" user_id="42" />` renders an
`aria-hidden` initials circle coloured by a stable slot, plus the visible name and optional second line.

**Files.**

- `panel_tags.py`:
  ```python
  @register.filter
  def avatar_slot(value: int | str | uuid.UUID) -> int:
      return zlib.crc32(str(value).encode()) % 6 + 1

  @register.filter
  def initials(name: str) -> str:
      words = str(name).split()
      if not words:
          return ""
      letters = words[0][0] if len(words) == 1 else words[0][0] + words[-1][0]
      return letters.upper()
  ```
- New `cotton/panel-avatar-chip.html`:
  ```

  {% load panel_tags %}
  <style>@layer components {
      .panel-avatar-1 { background-color: color-mix(in oklab, var(--color-primary) 22%, var(--color-surface)); }
      .panel-avatar-2 { background-color: color-mix(in oklab, var(--color-secondary) 22%, var(--color-surface)); }
      .panel-avatar-3 { background-color: color-mix(in oklab, var(--color-accent) 25%, var(--color-surface)); }
      .panel-avatar-4 { background-color: color-mix(in oklab, var(--color-info) 22%, var(--color-surface)); }
      .panel-avatar-5 { background-color: color-mix(in oklab, var(--color-primary) 42%, var(--color-surface)); }
      .panel-avatar-6 { background-color: color-mix(in oklab, var(--color-secondary) 42%, var(--color-surface)); }
  }</style>
  <div class="flex items-center gap-3" {{ attrs }}>
      <span aria-hidden="true" class="panel-avatar-{{ user_id|avatar_slot }} flex shrink-0 items-center justify-center rounded-full font-semibold text-on-surface {% if size == "lg" %}size-13 text-lg{% else %}size-8 text-xs{% endif %}">{% firstof initials name|initials %}</span>
      {% if not name_hidden %}
          <span class="min-w-0">
              <span class="block truncate">{{ name }}</span>
  ```
