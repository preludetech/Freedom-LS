# Frontend QA: audio player widget (`c-audio`)

## Setup

1. Load the demo content so the four demo audio files exist:
   `uv run python manage.py content_save ./demo_content DemoDev`
2. Start the server: `uv run python manage.py runserver $PORT`. Base URL `http://127.0.0.1:$PORT`.
3. Log in at `/accounts/login/` with the QA login from `.claude/sdd/config.md` (`## QA Login`).
4. Open the "Content Widgets - Demo Reference" course and go to the "Media" topic. If the course
   is not open to the learner view (it is `coming_soon`), use the educator interface's course
   content preview for the same topic. Scroll to the `## Audio` section.

Check every test at desktop (1280 px), tablet (768 px) and phone (375 px) widths. Keep the browser
console open: no JavaScript errors at any point.

## Test 1: the widgets render

1. Look at the Audio section.
   - Four items in a grid: Bravo, Charlie, Oscar, Romeo.
   - Each shows the word with a speaker icon button beside it, on one line.
   - The respelling (e.g. "BRAH VOH") sits on a second line under the word, in muted text.
   - No item has a box or border of its own. The button is a square of at least 44×44 px.
   - At phone width the grid is one column and nothing scrolls sideways.
2. Open the network panel and reload. No request goes to `/content/audio/` or to any `.mp3`
   before a button is pressed.

## Test 2: play, switch, stop

1. Press the Bravo button. The icon turns to a spinner briefly, then to a stop icon, and "Bravo"
   plays. The word does not move as the icon changes.
2. While Bravo plays, press Charlie. Bravo stops at once and returns to the speaker icon; Charlie
   plays. Only one sound ever plays.
3. Press Charlie again while it plays. It stops and returns to the speaker icon.
4. Let Oscar play to the end. Its button returns to the speaker icon on its own.
5. Press Romeo rapidly several times. It ends in a consistent state (playing or idle) with no
   error line.
6. In the network panel, a press requests `/content/audio/<uuid>/`, which answers 302 to the media
   file. The 302 response is not cached (`Cache-Control` has `no-store`).

## Test 3: keyboard and screen reader

1. Tab to the Bravo button. The focus ring is visible.
2. Press Enter: it plays. Press Space: it stops. Focus stays on the button throughout.
3. Inspect the button: its accessible name is "Play pronunciation of Bravo" in every state;
   `aria-pressed` is `true` while playing and `false` otherwise; `aria-describedby` points to the
   respelling element.

## Test 4: load failure and retry

1. In devtools, block the request URL pattern `*/media/*` (or `*.mp3`).
2. Press Bravo. The button returns to the speaker icon and "Audio could not be played. Try again."
   appears below it in error colour. The button stays enabled.
3. Unblock the pattern and press Bravo again. It plays and the error line disappears.
4. Nothing retries by itself while blocked.

## Test 5: authoring errors show a red box

Edit `demo_content/functionality_demo_content_widgets/2. media/content.md` temporarily (revert it
afterwards with `git checkout -- "demo_content/functionality_demo_content_widgets/2. media/content.md"`
and re-run the `content_save` command):

1. Add `<c-audio src="audio/missing.mp3" label="Missing"></c-audio>` (with blank lines around it).
   Reload: a red box reads "Audio not found: audio/missing.mp3".
2. Add `<c-audio src="images/diagram.svg" label="Picture"></c-audio>`. A red box reads
   "Audio not found: images/diagram.svg".
3. Add `<c-audio src="audio/bravo.mp3"></c-audio>`. A red box reads
   "Audio needs a label: audio/bravo.mp3".

## Test 6: the redirect URL directly

1. Copy a button's `data-src` (from devtools) and open it in a new tab. The audio file loads.
2. Log out and open the same URL. It still loads (no login needed).
3. Change the last character of the UUID and open it. A 404 page shows.

## Test 7: no regressions on the Media topic

1. The YouTube, pictures, annotated diagrams, image grids and stacked figures sections above the
   Audio section look and behave as before; a picture still opens its lightbox.

## Test 8: real devices and a screen reader (human tester)

These need hardware the automated QA run does not have; record them as open if skipped.

1. On an iPhone (Safari) with the silent switch both on and off, and on an Android phone
   (Chrome), repeat Test 2 steps 1–3. Each press plays on the first try.
2. With VoiceOver (iOS/macOS) or NVDA (Windows), focus the Bravo button. It reads "Play
   pronunciation of Bravo", the pressed state, and the respelling. Trigger a failure as in
   Test 4: the error line is announced.
