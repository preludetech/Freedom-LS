# Research: codebase touch points for the audio player widget

Paths are relative to the worktree root. Builds on `research_content_media.md` and `research_audio_widgets.md` in `spec_dd/1. next/content-widget-sayit-reveal/` without repeating them.

## 1. How c-picture and c-file-download resolve `src` and fail

- Both templates load `content_tags` and run `{% with file_obj=src|get_file_by_path:content_instance %}`:
  `freedom_ls/content_engine/templates/cotton/picture.html:32`, `.../file-download.html:13` (also `pdf-embed.html`, `card.html`).
- `get_file_by_path` (`freedom_ls/content_engine/templatetags/content_tags.py:112-136`): strips the path, returns `None` for empty, calls `content_instance.calculate_path_from_root(file_path)`, then `File.objects.get(file_path=final_path)`. `DoesNotExist` gives `None`; `MultipleObjectsReturned` gives `.first()`. It does not filter on `file_type`, so a `c-audio-player src="x.png"` would resolve to a non-audio `File` unless the template checks `file_obj.file_type`.
- `content_instance` reaches the template through `render_markdown(self.content, None, context={"content_instance": self})` (`freedom_ls/content_base/models.py:96`). Body markdown renders with `request=None`, so the widget gets no request, no user and no site from context. Site filtering therefore comes from `File.objects` (the site-aware manager) and not from a template variable.
- Not-found box, identical shape in both:
  `<div class="my-6 p-4 bg-error/10 border border-error/20 rounded-lg"><p class="text-error">Image not found: {{ src }}</p></div>` (`picture.html:166-172`); `File not found: {{ src }}` in `file-download.html:24-30`. A new `audio-player.html` should copy this block, with text such as "Audio not found: {{ src }}".
- Playable URL: `{{ file_obj.file.url }}` (`picture.html:37`, `file-download.html:17`). This is the only way any template gets a File URL. No other code in `freedom_ls` outside tests calls `.file.url`, except `blog/views.py:13`, `article-card.html:15` and `blog/article_detail.html:44`.
- Cotton wiring: a widget is `freedom_ls/content_engine/templates/cotton/<name>.html` starting with `<c-vars ...>` (`picture.html:1`, `file-download.html:1`). Hyphenated file name gives the `c-` tag (`COTTON_SNAKE_CASED_NAMES = False`, `config/settings_base.py:424`).
- Cotton-dir process doc: `claude_plugins/fls-dev/resources/markdown_content.md` lines 27 and 54 only state the location and step 1 (create the template). It has no audio or media specifics.

## 3. Alpine CSP bundle and component registration

- `@alpinejs/csp@3.15.8` is loaded from jsdelivr in `freedom_ls/base/templates/_base.html:79`. No inline JS expressions; every component is `Alpine.data(...)`.
- Content widgets register in `freedom_ls/content_engine/static/content_engine/js/alpine-components.js`, inside one `document.addEventListener("alpine:init", ...)` block. Current entries: `equation` (line 26), `flashcard` (line 57), `contentLightbox` (line 69). The file header lists them (lines 8-12) and must gain the new one.
- The flashcard pattern to follow: `Alpine.data("flashcard", () => ({ flipped: false, flip() {...}, frontStyle() {...} }))`. The template uses `x-data="flashcard"` (a bare name, no call parens, as the test at `markdown_rendering/tests/test_markdown_utils.py:296` asserts `'x-data="flashcard"'`). Handlers in the template are method names only (`@click="open"` in `picture.html:63`), and `$refs` is used for elements (`this.$refs.dialog`).
- CSP build limits that matter for an audio widget: no `@ended="playing = false"`-style expressions, so each listener is a named method. `<audio>` media events (`error`, `ended`, `pause`, `play`) can be bound as `@error="onError"` etc. in markup or with `addEventListener` in `init()` (as `contentLightbox` does for the dialog `close` event, lines 70-75).
- Script inclusion is per page, not global. `content_engine/js/alpine-components.js` is included by `learner_interface/templates/learner_interface/_course_base.html:18`, `_exam_runner_base.html:29`, `educator_interface/templates/educator_interface/_shell.html:17`, and `blog/templates/blog/article_detail.html:24`. Any new page that renders the widget already has the bundle where those pages render content. No new script tag is needed.
- Tests pinning registration: `learner_interface/tests/views/test_form_runner.py:1070-1079` asserts the content bundle loads on form pages; `educator_interface/tests/test_views.py:8262` asserts KaTeX loads before the bundle. Order requirement: the bundle must load before Alpine (the file header says so).
- A registration invariant test exists for `panel_framework` only (`panel_framework/tests/invariants/test_alpine_registration.py`); `content_engine/tests/invariants/` has only `test_katex_vendor_assets.py`. There is no equivalent check that every `x-data="..."` in content_engine templates is registered. An audio-player invariant of that kind would be new.

## 4. Signed course_media URLs and refetch-on-error

- Storage: `File.file` is a `FileField` on `storage=get_content_media_storage` (`freedom_ls/content_engine/models/files.py:40-42`, alias from `CONTENT_MEDIA_STORAGE_ALIAS = "course_media"`, `config/settings_base.py:296`). Dev and tests use `FileSystemStorage` (`settings_base.py:317-319`), so `file.url` is an unsigned `/media/...` path in dev. Production uses S3 with `querystring_auth` true and `querystring_expire` default 3600 (`freedom_ls/deployment/storage.py:197-202`). `course_media` is in `SIGNED_URL_PURPOSES` (`storage.py:34`), enforced by a deployment check (`deployment/checks.py:309-314`).
- URLs are minted at render time by `file.url`, with the S3 signature done locally and no bucket call (comment at `accounts/models.py:153`). A page left open for more than an hour holds expired URLs. That is the reason for the user's refetch-on-error decision.
- **No existing endpoint returns a fresh URL for a File.** `File.objects` appears only in `content_tags.py:131,136`, `models/articles.py:40,101` and `content_save.py:877`. There is no `content_engine/urls.py` or views module (the glob of `freedom_ls/content_engine/{urls.py,views*.py}` found none). A refetch needs a new view and a new URL, so `content_engine` gains its first URLconf and needs `app_name`, a root include, and possibly `config/urls.py` wiring (check how other apps are included).
- Access checks today: none. `docs/product/security-and-data-handling.md` and `docs/product/roadmap.md` (cited by `learner-interface-features-5-protected-video/idea.md:35-37`) say the presigned course_media URLs are not checked against registration, and routing downloads through the course access check is listed as "not built". `learner-interface-features-5-protected-video/idea.md:78-80` leaves that gap open to its own spec. A refetch view in this spec therefore has to choose: (a) mirror today's behaviour (any request that resolves the File on the current site gets a URL, no registration check), or (b) add an access check. Recommend (a) plus login-required decision to be made in the spec, and state plainly that the view must not widen exposure beyond what the rendered page already gives. The decision should be noted against the protected-video spec.
- Site-awareness: `File` is a `SiteAwareModel` with `UniqueConstraint(site, file_path)` (`files.py:30,54-58`). `get_file_by_path` uses `File.objects` (the site-aware manager), so a refetch view must resolve the File through the same manager (current site from the request, via `site_aware_models`' `get_cached_site`, `site_aware_models/models.py:37`). It must look up by an opaque key. Options: the File pk (an integer; guessable, but the lookup is site filtered), or `file_path` is not safe to accept from the client unscoped. Use `get_object_or_404(File, pk=..., file_type=AUDIO)` and return the new URL as JSON or a tiny HTMX/JSON fragment. Respond 404 for another site's pk (site filtering gives that for free).
- The player must carry the File identity to the browser: render a `data-` attribute (pk or the refetch URL) on the widget, because the widget has no request. Reverse the refetch URL in the template with `{% url %}` (the template tag is available in cotton) or build it from pk in JS.
- Failure case: `<audio>` `error` event fires on 403 from an expired S3 URL. The player should retry once and then show an error state, to avoid a loop. In dev (FileSystemStorage) the URL never expires, so the refetch path is only exercised through a test that forces an error or an S3 storage override.
- Caching: do not cache the refetch response (`Cache-Control: no-store`), because the URL is time-bound.

## 5. File.mime_type and file_type for audio in content_save

- `get_file_type_from_extension` (`freedom_ls/content_engine/management/commands/content_save.py:785-802`): `audio_extensions = {".mp3", ".wav", ".ogg", ".m4a", ".flac", ".aac"}` give `File.FileType.AUDIO`. `.opus` is absent, which matches the user's decision not to add it. Note: `.webm` is classed as VIDEO (line 790), so an audio-only `.webm` clip would be a VIDEO file; not a concern with the supported set.
- `save_file_to_db` (`content_save.py:859-891`): `mime_type, _ = mimetypes.guess_type(str(file_path))`, stored as `mime_type or ""`; the image branch only overrides it for images. For audio the guessed type is the Python standard library's: `.mp3` gives `audio/mpeg`, `.wav` gives `audio/x-wav` (older) or `audio/vnd.wave` (Python 3.13 changed some), `.ogg` gives `audio/ogg`, `.m4a` gives `audio/mp4` on recent Python but can be `None` on a system without registered types, `.flac` gives `audio/flac` (3.13), `.aac` gives `audio/aac` (3.13). Python is 3.13+ per `CLAUDE.md`. The stored value can be `""` when the guess fails, so the widget template should not rely on `mime_type` to build `<source type=...>`; use `<audio src=...>` with the File's URL and fall back to omitting `type`. Audio is stored unoptimised (no transcoding), and re-saving updates `mime_type` on existing rows (`content_save.py:888-891`).
- Supersession: replacing a clip writes a new key and the loader deals with the old one (`content_save.py:904-922`, per `research_content_media.md`). A cached/presigned URL for the old key dies on replace, which is another case for refetch-on-error.
- Test coverage of audio today: `content_engine/tests/management/commands/test_content_save.py` has image `mime_type` assertions (line 709, 851, 889) and no audio case; `get_file_type_from_extension` audio mapping has no explicit test found. Add one for the audio extensions when relevant.

## 6. CSP settings and `media-src`

- `config/settings_base.py:561-615` defines `SECURE_CSP_REPORT_ONLY` (report-only, not enforced) with `default-src`, `script-src`, `style-src`, `img-src`, `connect-src`, `frame-src`. There is no `media-src`, so audio falls back to `default-src 'self'`.
- Because the policy is report-only, nothing breaks today, but production audio from the S3/R2 bucket host would generate reports and would break when enforced.
- Precedent for adding the bucket host: `media_csp_sources(purpose)` in `freedom_ls/deployment/storage.py:140-168`, used at `settings_base.py:589` as `*media_csp_sources(PROFILE_PICTURES_PURPOSE)` in `img-src`. It returns `[]` on local disk and the custom domain, or the bucket host, otherwise. The import at `settings_base.py:27` is `from freedom_ls.deployment.storage import PROFILE_PICTURES_PURPOSE, media_csp_sources`. There is a `COURSE_MEDIA` purpose constant (referenced in `storage.py:34` as part of `SIGNED_URL_PURPOSES`); check its exact name in `storage.py` and import it the same way.
- Where `media-src` would go: a new key `"media-src": [CSP.SELF, *media_csp_sources(COURSE_MEDIA_PURPOSE)]` in the same dict. Setting a `media-src` also stops `default-src` applying to media, so it must include `CSP.SELF`.
- Existing gap worth flagging: course images from the same private bucket (`picture.html` `file.url`) are not in `img-src` either, so enforced CSP would already break c-picture and the PDF embed with a bucket host. Adding `media-src` alone is partial; the spec should decide whether to add course_media to `img-src` and `frame-src` now or note it. `learner-interface-features-5-protected-video/idea.md:40` records the missing `media-src`.
- `connect-src` matters only if the refetch is a same-origin `fetch`, which is covered by `CSP.SELF` (the refetch goes to the FLS origin, not the bucket).
- A project-owned setting: installing projects copy `settings_base`-style dicts, so this is another upgrade-note item (`changed_settings`: `SECURE_CSP_REPORT_ONLY`), as the profile-picture spec did (`spec_dd/3. done/2026-11-15_09:21_learner-public-profile-1-profile-picture/upgrade_notes.md:62`).

## 7. The c-icon component and a speak icon

- `<c-icon name="..." variant="outline" class="size-5" aria_label="">` (`freedom_ls/icons/templates/cotton/icon.html:1-5`), a thin wrapper over `{% icon %}` in `icon_tags`. `name` must be in `SEMANTIC_ICON_NAMES` (`freedom_ls/icons/semantic_names.py:1-73`). Without `aria_label` the icon is `aria-hidden`.
- There is **no** speaker/volume/audio/play semantic name. Nearest: `in_progress` (maps to `play` in every set: `icons/mappings.py:28,92,156,220`), `paused` (maps to `pause-circle` / `circle-pause` / `player-pause` / `pause`, `mappings.py:64,128,192,256`), `download`, `fullscreen`, `info`.
- Mappings are per icon set (four dicts, one per set; the line numbers 21-70, 85-134, 149-198, 213-262 show four blocks that each define every semantic name). Adding a semantic name means: add it to `SEMANTIC_ICON_NAMES` and to all four mapping dicts, and there is an existing test, `content_engine/tests/test_icon_validation.py`, plus presumably icon-mapping completeness tests under `freedom_ls/icons/tests` (not read). Heroicons has `speaker-wave`; Lucide `volume-2`; Tabler `volume`; the fourth set needs a check of the icon set's own name (not verified here).
- Recommended semantic name: `speak` (or `audio`) mapped to those per-set names. `in_progress` must not be reused: its meaning is progress state, and the icons skill requires semantic, not visual, names. The widget-spec question to settle is the name; keep the name semantic (`speak`), not `volume`.
- Accessibility: the icon button needs a text label on the button itself (`aria-label="Play pronunciation of {word}"` or visually hidden text), with the `c-icon` left decorative; the CSP Alpine build allows `:aria-label` bindings only through methods.
