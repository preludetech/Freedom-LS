# Spec: audio player widget (`c-audio`)

Idea: `idea.md`. Up-front answers: `answers.md`. Research: `research_*.md` in this directory, and
`research_content_media.md` and `research_audio_widgets.md` in
`spec_dd/1. next/content-widget-sayit-reveal/`.

## Purpose

Course content has no way to play sound. A concrete project's phonetic-alphabet course needs
learners to hear each word said correctly. This spec adds a `c-audio` content widget: an author
points it at a recorded clip in the content repo, and the learner sees the word with a small speak
button beside it. A page can hold many clips, and only one plays at a time.

## Scope

In:

- The `c-audio` cotton component, its Alpine component and its allow-list entry.
- A redirect view that hands the browser a freshly signed URL for an audio `File` on every play.
- Two semantic icon names for the button.
- A `media-src` CSP directive for the course media host.
- Demo content, authoring docs and upgrade notes.

Out:

- Say-it-then-reveal and audio inside `c-flashcard` faces
  (`content-widget-sayit-reveal-2-say-it-reveal`). Audio on scheduled revision flashcards
  (`content-widget-sayit-reveal-3-audio-on-revision-flashcards`).
- Text-to-speech, speech recognition, recording the learner, speed control, scrubbing, waveforms.
- `.opus` (and `.oga`) in the loader's audio extensions.
- An inline variant for use mid-sentence in prose. `c-audio` is a block-level widget.
- `c-audio` inside `c-table`, `c-accordion`, `c-admonition` or `c-flashcard`. Those emit their
  slot with `{% markdown slot %}`, which strips the widget's interactive markup. `c-grid` emits
  `{{ slot }}` and is the supported layout for a list of clips.
- A registration check on course media. Today's presigned URLs are not checked against course
  registration either. That gap belongs to `learner-interface-features-5-protected-video`.
- Adding course media to `img-src` and `frame-src`. Those directives miss the bucket host today
  too (for `c-picture` and `c-pdf-embed`), and the fix is separate.
- The phonetic-alphabet course itself, which belongs to the concrete project.

## Decisions

- **A redirect view, not a signed URL in the page.** The page never holds an S3 URL. The widget
  points at `content_engine:audio_file`, which 302s to `file.file.url`, re-signed on each request.
  A page left open past the 3600 s expiry still plays, and the JavaScript needs no refetch logic.
- **The view needs no login.** `File.pk` is a UUID and the lookup is site-scoped and limited to
  `AUDIO` files, so the view exposes no more than the presigned URL in a rendered page does today.
  Articles render content to anonymous visitors, so a login check would break them.
- **One shared `HTMLAudioElement` for the whole page**, created on the first press, in module
  scope in the Alpine bundle. Its `src` is set and `play()` is called synchronously inside the
  click handler. Sharing one element guarantees one clip at a time and keeps iOS's per-element
  gesture unlock to a single element. `HTMLAudioElement` is used rather than Web Audio, which the
  iPhone ring/silent switch mutes. Nothing is fetched before the first press, so `preload` is moot.
- **No `<source type>`.** The widget sets `src` only. `File.mime_type` can be empty for audio, and
  a wrong `type` makes a browser refuse a playable file.
- **The button toggles play and stop.** It has a stable accessible name and `aria-pressed`. It
  never changes its name: changing the name as well as `aria-pressed` makes screen readers
  announce a contradiction.
- **`label` is required.** The visible word is the WCAG 2.2 1.2.1 text alternative and part of the
  button's accessible name (2.5.3 Label in Name), so a clip without one renders the red error box.

## Requirements

### Authoring syntax

```html
<c-audio src="audio/alpha.mp3" label="Alpha" respelling="AL FAH"></c-audio>
```

| Attribute | Required | Meaning |
| --- | --- | --- |
| `src` | yes | Path to an audio file, relative to the markdown file, resolved like `c-picture`. |
| `label` | yes | The visible word. Rendered as text and used in the button's accessible name. |
| `respelling` | no | A pronunciation respelling, shown exactly as authored, in muted text below the word. Absent means no element is rendered. |

- `config/settings_base.py` `MARKDOWN_ALLOWED_TAGS` gains
  `"c-audio": {"src", "label", "respelling"}`.
- Like the other block widgets, it needs blank lines around it.

### Component: `freedom_ls/content_engine/templates/cotton/audio.html`

- `<c-vars src="" label="" respelling="" />`. Resolve the file with
  `{% with file_obj=src|get_file_by_path:content_instance %}`, as `file-download.html` does.
- Render the red box, the same markup as `file-download.html`, in these cases:
  - `file_obj` is `None`, or its `file_type` is not `File.FileType.AUDIO`: `Audio not found: {{ src }}`.
  - `label` is empty: `Audio needs a label: {{ src }}`.
- Otherwise render, inside one root element with `my-6` (so `c-grid`'s `[&>*]:my-0!` override
  applies) and `x-data="audioClip"`:
  - A row holding the `label` text followed by the button, with `whitespace-nowrap` so the pair
    never wraps apart.
  - The `respelling`, if given, on a second line below the word in `text-muted`, in the DOM
    before the button. The button is linked to it with `aria-describedby`.
  - The button: a real `<button type="button">`, `aria-label="Play pronunciation of {{ label }}"`,
    `aria-pressed` bound to `playing`, a `data-src` holding
    `{% url "content_engine:audio_file" file_obj.pk %}`, a hit box of at least 44×44 CSS px, a
    `size-5` glyph, a ghost style and the existing `.btn` focus ring. Use `<c-button>` if it
    passes the Alpine and `data-` attributes through to the `<button>` and can render square.
    Otherwise use a bespoke `<button>` with the `.btn` classes.
  - Three pre-rendered icon spans toggled with `x-show` (`x-cloak` on the hidden ones): idle
    `audio_play`, loading `loading` (`animate-spin`), playing `audio_stop`. The icon slot is a
    fixed size, so the word never moves.
  - An error line, `role="status"`, shown only in the failed state, reading "Audio could not be
    played. Try again." in `text-error text-sm`. Wording per the brand voice guide.
- Colours come from role tokens only. There is no per-item box.

### Alpine component `audioClip`: `freedom_ls/content_engine/static/content_engine/js/alpine-components.js`

Registered with `Alpine.data("audioClip", ...)` inside the existing `alpine:init` block and listed
in the file's header comment. Under the CSP build, `x-*` attributes hold method and property
names only.

- State: `playing`, `loading`, `failed`, all false initially.
- Module scope: one shared `HTMLAudioElement` (created lazily) and a reference to the clip that
  currently owns it.
- `toggle()`:
  - If this clip is playing or loading, stop it: `pause()`, `currentTime = 0`, back to idle.
  - Otherwise, stop the current owner (its button returns to idle), clear `failed`, take
    ownership, set the shared element's `src` from `data-src`, call `play()` synchronously, and
    set `loading` until the `playing` event.
- Shared-element events reset only the owning clip: `playing` sets `playing`; `ended` and `pause`
  return to idle; `error` sets `failed` and returns to idle.
- `play()` promise: ignore `AbortError` (another press interrupted the load). Any other rejection
  sets `failed`. The button stays enabled after a failure, and pressing it tries again. Never retry
  automatically.
- `destroy()`: if this clip owns the shared element, stop it, so audio does not outlive a swapped
  or removed widget.
- Nothing plays on page load. Nothing about the learner is stored.

### Redirect view

- New `freedom_ls/content_engine/urls.py` with `app_name = "content_engine"` and
  `path("audio/<uuid:pk>/", views.audio_file, name="audio_file")`. New
  `freedom_ls/content_engine/views.py`.
- `config/urls.py` includes it at `content/`.
- `audio_file`: GET and HEAD only. It runs
  `get_object_or_404(File, pk=pk, file_type=File.FileType.AUDIO)` through the site-aware manager
  and returns a 302 to `file_obj.file.url`. It is decorated `never_cache`. Another site's file,
  a non-audio file and an unknown pk all give 404.

### Icons: `freedom_ls/icons/`

- Add `audio_play` and `audio_stop` to `SEMANTIC_ICON_NAMES` (`semantic_names.py`), and map them
  in all four icon sets in `mappings.py`. Heroicons: `speaker-wave` and `stop`. Lucide:
  `volume-2` and `square`. Tabler and the fourth set: their own speaker and stop glyphs, checked
  against the set.

### CSP: `config/settings_base.py`

- `SECURE_CSP_REPORT_ONLY` gains `"media-src": [CSP.SELF, *media_csp_sources(CONTENT_MEDIA_PURPOSE)]`.
  `CSP.SELF` covers local storage and the redirect hop, and `media_csp_sources` adds the bucket
  host or custom domain. `CONTENT_MEDIA_PURPOSE` is imported beside `PROFILE_PICTURES_PURPOSE`.

### Demo content: `demo_content/functionality_demo_content_widgets/2. media/`

- A new `## Audio` section in `content.md`: one paragraph naming the attributes, then a `c-grid`
  of four `c-audio` clips, each with a respelling: Bravo, Charlie, Oscar, Romeo.
- Clips in `2. media/audio/`, from Wikimedia Commons by K6ka, CC0 1.0 (`En-ca-bravo.oga`,
  `En-ca-Charlie.oga`, `En-ca-Oscar.oga`, `En-ca-Romeo.oga`; URLs in `research_prior_art.md` §3).
  Convert each to mp3 and trim its leading and trailing silence.
- `2. media/audio/LICENCES.txt` records, per file: the source page URL, author, licence, retrieval
  date and the conversion done. It is not a `.md` file, because the loader parses every `.md` as
  content.

## Testing

- **Component rendering** (`render_markdown` with a `content_instance` and `FileFactory` audio
  rows):
  - a resolved clip renders the label, the respelling, `x-data="audioClip"`, the button's
    accessible name, `aria-pressed="false"` and a `data-src` equal to the reversed view URL;
  - no respelling renders no respelling element;
  - a missing file, a non-audio `File`, and an empty `label` each render their red box;
  - `src`, `label` and `respelling` survive nh3, and an unlisted attribute is stripped;
  - inside `c-grid` the interactive markup survives.
- **View**: a 302 to the file's URL; `Cache-Control` no-store; 404 for another site's audio
  file, a non-audio file and an unknown UUID; POST refused; no login needed.
- **Settings**: `media-src` is present and includes `'self'`.
- **Icons**: the existing icon-set completeness tests pass with the two new names.
- **Demo content**: every `c-audio` `src` in the demo resolves to an `AUDIO` `File`.
- **Loader**: `get_file_type_from_extension` returns `AUDIO` for each of the six extensions.
- **Browser (Playwright, content bundle loaded)**:
  - pressing A plays it (`aria-pressed="true"`), and pressing B stops A (A back to idle) and
    plays B;
  - pressing a playing clip stops it;
  - Enter and Space activate the button, and focus stays on it through state changes;
  - a forced load error shows the error line, and the next press tries again;
  - nothing plays or fetches audio on page load.
- **Manual QA**: iOS Safari and Android Chrome on a device, and VoiceOver or NVDA reading the
  button name, the pressed state and the error.

## Open questions

None open. Defaults taken where nobody was asked: the view needs no login; `label` is required;
the respelling sits below the word; the demo uses four CC0 clips and skips Alpha (its only free
recording is CC BY-SA 3.0 in a different voice).

## Success criteria

- An author writes `<c-audio src="..." label="...">` in markdown, and the learner sees the word
  with a speak button.
- Pressing a button plays its clip. Pressing another stops the first. Pressing the playing one
  stops it.
- A clip pressed after the page has been open for more than an hour still plays on S3 storage.
- A missing, non-audio or unlabelled clip shows a red box naming the `src`.
- No audio request is made before the first press.
- `media-src` lists the course media host.
- The demo media topic shows four playable clips, with a licence line for each in `LICENCES.txt`.
- The widget reference, `markdown_content.md`, `file-layout.md`, the content editing workflow doc
  and the upgrade notes name `c-audio`.
