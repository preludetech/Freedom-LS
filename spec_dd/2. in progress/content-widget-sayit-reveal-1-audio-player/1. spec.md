# Spec: audio player widget (`c-audio`)

Idea: `idea.md`. Answers: `answers.md`. Research: `research_*.md` in this directory, and
`research_content_media.md` and `research_audio_widgets.md` in
`spec_dd/1. next/content-widget-sayit-reveal/`.

## Purpose

Course content has no way to play sound. A concrete project's phonetic-alphabet course needs
learners to hear each word said correctly. This spec adds a `c-audio` content widget. An author
points it at a recorded audio file in the content repo, and the learner sees the word with a small
speak button beside it. A page can hold many audio files, and only one plays at a time.

## Scope

In:

- The `c-audio` cotton component, its Alpine component and its allow-list entry.
- A redirect view that hands the browser a freshly signed URL for an audio `File` on every play.
- Two semantic icon names for the button.
- A `media-src` CSP directive for the course media host.
- Demo content, authoring docs and upgrade notes.

Out:

- Say-it-then-reveal and audio inside `c-flashcard` faces
  (`content-widget-sayit-reveal-2-say-it-reveal`). Audio on scheduled revision flashcards
  (`content-widget-sayit-reveal-3-audio-on-revision-flashcards`).
- Text-to-speech, speech recognition, recording the learner, speed control, scrubbing, waveforms.
- `.opus` and `.oga` in the loader's audio extensions.
- An inline variant for use mid-sentence in prose.
- `c-audio` inside `c-table`, `c-accordion`, `c-admonition`, `c-flashcard`, `c-card` or
  `c-pull-quote`, which re-render their slot through `{% markdown %}` and lose the widget. The
  idea's "grid or table" narrows to `c-grid`, which keeps nested widgets intact.
- A course-registration check on course media, which `learner-interface-features-5-protected-video`
  owns.
- Course media in `img-src` and `frame-src`, a gap `c-picture` and `c-pdf-embed` already have.
- The phonetic-alphabet course itself, which belongs to the concrete project.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| audio file | narrowed | `File` (`freedom_ls/content_engine/models/files.py`) with `file_type` `File.FileType.AUDIO`, as one `c-audio` plays it |

## Decisions

- **The page holds a redirect URL, never a signed one** (`answers.md`). `content_engine:audio_file`
  302s to a freshly signed URL on each play, so expiry needs no handling in JavaScript.
- **The view needs no login.** `File.pk` is a UUID and the lookup is site-scoped and limited to
  audio files, so it exposes no more than a rendered page's presigned URL does today. Articles
  render content to anonymous visitors.
- **One shared `HTMLAudioElement` per page**, created on the first press. It plays one audio file
  at a time by construction and needs iOS's gesture unlock once. Web Audio is ruled out because the
  iPhone silent switch mutes it.
- **The widget sets `src` only, never `<source type>`.** `File.mime_type` can be empty for audio.
- **A stable accessible name plus `aria-pressed`.** Changing the name as well makes screen readers
  announce a contradiction ("Stop ..., pressed").
- **`label` is required.** The visible word is the WCAG 2.2 1.2.1 text alternative and sits inside
  the button's accessible name (2.5.3 Label in Name).

## Requirements

### Authoring syntax

```html
<c-audio src="audio/bravo.mp3" label="Bravo" respelling="BRAH VOH"></c-audio>
```

| Attribute | Required | Meaning |
| --- | --- | --- |
| `src` | yes | Path to an audio file, relative to the markdown file, resolved like `c-picture`. |
| `label` | yes | The visible word, used in the button's accessible name. |
| `respelling` | no | A pronunciation respelling, shown exactly as authored. Absent means no element. |

- `config/settings_base.py` `MARKDOWN_ALLOWED_TAGS` gains
  `"c-audio": {"src", "label", "respelling"}`.
- Like the other block widgets, it needs blank lines around it.

### Component: `freedom_ls/content_engine/templates/cotton/audio.html`

- `<c-vars src="" label="" respelling="" />`. Resolve the file with
  `{% with file_obj=src|get_file_by_path:content_instance %}`, as `file-download.html` does.
- The red box, the same markup as `file-download.html`:
  - `file_obj` is `None`, or its `file_type` is not `File.FileType.AUDIO`: `Audio not found: {{ src }}`.
  - `label` is empty: `Audio needs a label: {{ src }}`.
- Otherwise, one root element with `my-6` (so `c-grid`'s `[&>*]:my-0!` applies) and
  `x-data="audioFile"`, holding:
  - a row with the `label` text followed by the button, `whitespace-nowrap`;
  - the `respelling`, if given, on a second line below the word in `text-muted`, placed in the DOM
    before the button, which points at it with `aria-describedby`;
  - the button: `<c-button variant="ghost">` with
    `aria_label="Play pronunciation of {{ label }}"`, `x-bind:aria-pressed="playing"` (never
    `:aria-pressed`, which cotton reads as a component attribute), `x-on:click="toggle"`,
    `data-src="{% url "content_engine:audio_file" file_obj.pk %}"`, and utility classes that make
    it a square hit box of at least 44×44 CSS px. It keeps the `.btn` focus ring;
  - three spans in the button's slot, toggled with `x-show="idle"`, `x-show="loading"` and
    `x-show="playing"` (`x-cloak` on the last two), each holding a `<c-icon>` with an explicit
    `class="size-5"`: `audio_play`, `loading` (`size-5 animate-spin`) and `audio_stop`. Every
    state is the same size, so the word never moves;
  - an error line, `role="status"`, shown with `x-show="failed"`: "Audio could not be played. Try
    again." in `text-error text-sm`, worded per the brand voice guide.
- Colours come from role tokens only. There is no per-item box.

### Alpine component `audioFile`: `freedom_ls/content_engine/static/content_engine/js/alpine-components.js`

Registered with `Alpine.data("audioFile", ...)` inside the existing `alpine:init` block and listed
in the file's header comment. `x-*` attributes hold method and property names only.

- State: `idle` (initially true), `loading`, `playing`, `failed`. Every transition keeps exactly
  one of `idle`, `loading` and `playing` true.
- Module scope: one lazily created `HTMLAudioElement` and the `audioFile` instance that owns it.
- `toggle()`:
  - while this instance is loading or playing: `pause()`, `currentTime = 0`, back to idle;
  - otherwise: return the current owner to idle, clear `failed`, take ownership, set the shared
    element's `src` from `data-src` and call `play()` synchronously in the click handler. Stay
    `loading` until the `playing` event.
- Shared-element events change only the owner: `playing` sets playing; `ended` and `pause` return
  to idle; `error` sets `failed` and returns to idle.
- A rejected `play()` promise sets `failed`, except `AbortError` (another press interrupted the
  load), which is ignored. The button stays enabled after a failure and a press tries again. Never
  retry automatically.
- `destroy()` stops the shared element if this instance owns it.
- Nothing plays on page load. Nothing about the learner is stored.

### Redirect view

- New `freedom_ls/content_engine/urls.py` with `app_name = "content_engine"` and
  `path("audio/<uuid:pk>/", views.audio_file, name="audio_file")`. New
  `freedom_ls/content_engine/views.py`. `config/urls.py` includes it at `content/`.
- `audio_file`: GET and HEAD only, `never_cache`. It runs
  `get_object_or_404(File, pk=pk, file_type=File.FileType.AUDIO)` through the site-aware manager
  and returns a 302 to `file_obj.file.url`.

### Icons: `freedom_ls/icons/`

- `audio_play` and `audio_stop` join `SEMANTIC_ICON_NAMES` in `semantic_names.py` under a new
  "Audio" comment group, and map in all four sets in `mappings.py`:

| Set | `audio_play` | `audio_stop` |
| --- | --- | --- |
| heroicons | `speaker-wave` | `stop` |
| lucide | `volume-2` | `square` |
| tabler | `volume-2` | `player-stop` |
| phosphor | `speaker-high` | `stop` |

### CSP: `config/settings_base.py`

- `SECURE_CSP_REPORT_ONLY` gains `"media-src": [CSP.SELF, *media_csp_sources(CONTENT_MEDIA_PURPOSE)]`,
  with `CONTENT_MEDIA_PURPOSE` imported beside `PROFILE_PICTURES_PURPOSE`. `CSP.SELF` covers local
  storage and the redirect hop. The comment above `SECURE_CSP_REPORT_ONLY` covers course media as
  well as profile pictures.

### Demo content: `demo_content/functionality_demo_content_widgets/2. media/`

- A new `## Audio` section in `content.md`: one paragraph naming the attributes, then a `c-grid`
  of four `c-audio` with respellings: Bravo, Charlie, Oscar, Romeo.
- `2. media/audio/` holds trimmed mp3 versions of the Wikimedia Commons recordings by K6ka, CC0 1.0
  (`En-ca-bravo.oga`, `En-ca-Charlie.oga`, `En-ca-Oscar.oga`, `En-ca-Romeo.oga`; URLs in
  `research_prior_art.md` §3). Alpha is left out: its only free recording is CC BY-SA 3.0 in a
  different voice.
- `2. media/audio/LICENCES.txt` records, per file, the source page URL, author, licence, retrieval
  date and conversion. It is not `.md`, because the loader parses every `.md` as content.

## Testing

- **Component rendering** (`render_markdown` with a `content_instance` and `FileFactory` audio
  rows):
  - a resolved audio file renders the label, the respelling, `x-data="audioFile"`, the button's
    accessible name, `aria-pressed` bound, and a `data-src` equal to the reversed view URL. That
    assertion also catches cotton's silent fallback, which writes a raw `{% url %}` tag into the
    attribute when reversing fails;
  - no respelling renders no respelling element;
  - a missing file, a non-audio `File` and an empty `label` each render their red box;
  - `src`, `label` and `respelling` survive nh3, and an unlisted attribute is stripped;
  - inside `c-grid` the interactive markup survives.
- **Educator course content preview**: a topic with `c-audio` renders `data-src`, and the content
  bundle loads.
- **View** (`freedom_ls/content_engine/tests/test_views.py`, through the test `Client` with
  `mock_site_context`, never by calling the function): a 302 to the file's URL; no-store
  `Cache-Control`; 404 for another site's audio file, a non-audio file and an unknown UUID; POST
  refused; no login needed.
- **Settings**: `media-src` is present and includes `'self'`.
- **Icons**: `test_semantic_names.py`, `test_mappings.py` and check E007 pass with the new names.
- **Demo content** (`freedom_ls/content_engine/tests/demo_content/`, `fls_internal` marker, the
  shared demo fixtures): every `c-audio` `src` resolves to an audio file.
- **Loader**: `get_file_type_from_extension` returns `AUDIO` for each of the six extensions.
- **Browser** (Playwright, `django_db(transaction=True)`, `live_server_site`). Media is not served
  with `DEBUG` off, so `page.route` fulfils the redirect target with a small committed mp3 fixture:
  - pressing A plays it (`aria-pressed="true"`); pressing B returns A to idle and plays B;
  - pressing the playing one stops it;
  - Enter and Space activate the button, and focus stays on it through state changes;
  - a forced load error shows the error line, and the next press tries again;
  - no audio request is made on page load.
- **Manual QA**: iOS Safari and Android Chrome on a device; VoiceOver or NVDA reads the name, the
  pressed state and the error.

## Success criteria

- Pressing a button plays its audio file. Pressing another stops the first. Pressing the playing
  one stops it.
- An audio file pressed after the page has been open for more than an hour still plays on S3
  storage.
- A missing, non-audio or unlabelled audio file shows a red box naming the `src`.
- No audio request is made before the first press.
