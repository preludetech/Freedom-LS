# Course prices: spec

## Purpose

A course can carry a price, and FLS shows it to people browsing courses. FLS takes no payment, and a
price changes nothing about registration, access, CTAs or the access backend's own badge and copy.
In practice prices go on application-gated courses, so a visitor sees the price and still clicks
Apply. The kinds of price and the out-of-scope list are in `idea.md`.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| price kind | coined | Which of the four shapes a course's price takes: `fixed`, `range`, `discounted`, `on_request`. `PriceKind` in code. No existing term; "price" is unclaimed in FLS. |
| current price | coined | The price as shown today: a `CoursePrice` with the currency resolved and an expired sale turned into a fixed price. Returned by `Course.current_price()`. |

## Scope

In:

- Price columns on `Course`, a DB constraint, a migration, and admin editing.
- A `price:` mapping in `course.md` frontmatter, validated by `freedom_ls/content_engine/schema.py`
  and the bundled offline validator, and saved by `content_save`.
- Babel as a new dependency. `DEFAULT_CURRENCY` and `PRICE_LOCALE` settings.
- One `course-price` cotton component on the course card, course row, the course page's stats strip
  and its sign-up panel.
- `offers` in the course page's JSON-LD, and a fix that makes both existing JSON-LD blocks readable
  by crawlers.
- Author docs, product docs and demo content.

Out: everything in `idea.md` § Out of scope. Also out: any change to `CourseAccessDecision`, any
`CourseAccessBackend`, CTA labels, the "Free" / "By application" badge, the acquisition copy and
`isAccessibleForFree`. There is no rule or check about a course that is free to access but carries
a price. That combination is not expected, and FLS neither handles nor forbids it.

## Decisions

- **Nested frontmatter, flat columns.** Authors write one `price:` mapping tagged by `kind`, which
  pydantic validates as a discriminated union, so errors cover only the kind the author chose. The
  model stores typed flat columns so the admin edits real fields and Postgres can enforce the shape.
  A single JSONField was rejected: the admin would edit raw JSON, and there would be no DB types.
- **Babel for formatting and currency data.** `babel.numbers.format_currency`,
  `get_currency_precision` and `list_currencies` supply the formatting, each currency's minor units
  and the set of valid ISO 4217 codes. Babel has no Django dependency, so Django 6 is not a risk.
- **Strict per-currency decimal places.** An amount with more decimal places than its currency uses
  (`"1500.50"` in JPY) is rejected, never rounded.
- **The currency is resolved when the price is saved.** A blank `currency` takes `DEFAULT_CURRENCY`
  at load or admin-save time, and the resolved code is what gets stored. Changing the setting later
  does not change the currency of existing prices.
- **Sale expiry is computed at render time**, never written back. `sale_ends_on` is a date, and the
  sale runs through the whole of that day in the project's `TIME_ZONE` (`timezone.localdate()`).
  From the next day the course shows `amount` as a fixed price. One function decides this, and both
  the visible price and the JSON-LD read from it.
- **An absent `price:` key leaves the stored price alone. `price: null` clears it.** This matches how
  `content_save` already treats `tags`, so a price set in the admin survives a content re-save.

## Requirements

### Model: `freedom_ls/content_engine/models/courses.py`

`PriceKind(models.TextChoices)`: `FIXED = "fixed"`, `RANGE = "range"`, `DISCOUNTED = "discounted"`,
`ON_REQUEST = "on_request"`.

New `Course` fields, all optional:

| Field | Type | Used by kind |
| --- | --- | --- |
| `price_kind` | `CharField(max_length=20, choices=PriceKind.choices, blank=True, default="")` | `""` means no price |
| `price_amount` | `DecimalField(max_digits=12, decimal_places=3, null=True, blank=True)` | fixed; discounted (the original) |
| `price_sale_amount` | same | discounted |
| `price_sale_ends_on` | `DateField(null=True, blank=True)` | discounted, optional |
| `price_low_amount` | `DecimalField` as above | range |
| `price_high_amount` | same | range |
| `price_currency` | `CharField(max_length=3, blank=True, default="")` | every kind except on_request |
| `price_tax_note` | `CharField(max_length=100, blank=True, default="")` | every kind except on_request, optional |

`CheckConstraint` named `course_price_fields_match_kind`: for each kind, its own fields are set,
the others are null or blank, and the orderings hold. That means `price_sale_amount < price_amount`
and `price_low_amount < price_high_amount`. Every amount is `> 0`. With `price_kind = ""` every
price field is empty. The one existing `CheckConstraint`,
`course_progress_has_exactly_one_grant` in `freedom_ls/learner_progress/models.py`, is the pattern
to follow.

`Course.clean()` runs the shared price rules below. When an amount is present and `price_currency`
is blank, it fills in `DEFAULT_CURRENCY`, or raises a field error if that setting is unset.

`Course.current_price() -> CoursePrice | None` returns `None` when `price_kind` is blank. It runs no
queries.

New migration in `freedom_ls/content_engine/migrations/`.

### Price rules and formatting: new `freedom_ls/content_engine/prices.py`

- `price_errors(...) -> dict[str, str]` is one pure function holding every rule, keyed by field. It
  is called by `Course.clean()` and by the pydantic schema, and copied into the bundled validator.
  The rules:
  - The currency is in `babel.numbers.list_currencies()`.
  - Every amount is `> 0` and has no more decimal places than
    `get_currency_precision(currency)`.
  - sale < original, and low < high.
  - `on_request` carries no currency and no tax note.
- `CoursePrice` is a frozen dataclass holding the current price. It has `kind` (with an expired
  discount already turned into `FIXED`), `currency`, the amounts that kind uses, and `tax_note`.
  - It exposes the formatted amount strings the component needs.
  - It has `offers_json_ld() -> dict[str, object] | None`.
- Formatting uses `format_currency(amount, currency, locale=<PRICE_LOCALE>)`, with Babel's default
  currency digits.

### Settings: `freedom_ls/content_engine/config.py`

Add these to `ContentEngineConfig.declared_settings`:

- `DEFAULT_CURRENCY`: `Setting(default=None)`. An ISO 4217 code.
- `PRICE_LOCALE`: `Setting(default=None)`. A Babel locale such as `"en_ZA"`. When `None`, the locale
  is `django.utils.translation.to_locale(settings.LANGUAGE_CODE)`.

In `freedom_ls/content_engine/checks.py`, add a system check that errors when either setting is set
to a value Babel does not recognise.

`babel` is added with `uv add babel`.

### Content schema and loader

`freedom_ls/content_engine/schema.py`:

- Four submodels, `FixedPrice`, `RangePrice`, `DiscountedPrice` and `OnRequestPrice`, each with
  `kind: Literal[...]` and `extra="forbid"`. On `Course`, add
  `price: Annotated[FixedPrice | RangePrice | DiscountedPrice | OnRequestPrice, Field(discriminator="kind")] | None`.
- Author-facing keys:
  - `kind`
  - `amount`
  - `sale_amount`
  - `sale_ends_on` (a YAML date)
  - `low_amount`, `high_amount`
  - `currency` (optional)
  - `tax_note` (optional)
- Amount fields accept a string only and parse it to `Decimal`, because bare YAML numbers go through
  float. A float or int input raises
  "write amounts as quoted strings, e.g. "1499.00"".
- A `model_validator(mode="after")` on each submodel calls `price_errors`. When `currency` is absent,
  the decimal-place check uses `DEFAULT_CURRENCY`, and it is skipped when that is unset. The loader
  catches that case.

`freedom_ls/content_engine/management/commands/content_save.py`, `save_course()`:

- Exclude `price` from the pydantic dump.
- When `"price" in item.model_fields_set`, pass all eight `price_*` columns to `save_with_uuid` as
  extra fields. Columns the kind does not use get `None` or `""`, so switching kind never leaves
  stale columns. An explicit `price: null` clears all eight.
- Resolve a blank currency to `DEFAULT_CURRENCY` here. If the price has an amount and neither is
  set, raise `ValueError` naming the file.

Example frontmatter:

```yaml
price:
  kind: discounted
  amount: "1499.00"
  sale_amount: "999.00"
  sale_ends_on: 2026-12-31
  currency: ZAR
  tax_note: incl. VAT
```

### Offline validator: `claude_plugins/fls-content/validate/`

- `schema.py` gets the same four submodels, the `price` field and a copy of `price_errors`, with
  Babel imported directly.
- It has no `DEFAULT_CURRENCY`. When `currency` is absent, it checks everything except decimal
  places.
- Record the copy as a new patch in the file's header comment.
- Every documented invocation gains `--with babel`: the `validate.py` docstring,
  `commands/validate-content.md` and `skills/conventions/SKILL.md`.

### Admin: `freedom_ls/content_engine/admin.py`

`CourseAdmin.fieldsets` gets a "Price" fieldset with the eight `price_*` fields, all editable.
Errors come from `Course.clean()`.

### Display: `freedom_ls/learner_interface/`

New cotton component `templates/cotton/course-price.html`, with props `price` (a `CoursePrice`) and
`variant` (`"compact"` or `"full"`). It is the only place a price is rendered.

| Kind | compact | full |
| --- | --- | --- |
| fixed | `R1 499,00` | `R1 499,00` + tax note |
| range | `From R1 200,00` | `R1 200,00 – R3 000,00` + tax note |
| discounted (live) | `<s>` original, then sale amount | same + tax note |
| on_request | `Price on request` | `Price on request` |

A discounted price renders
`<span class="sr-only">Original price:</span> <s>…</s> <span class="sr-only">Now:</span> …`. There
is no "% off", no end date and no countdown. The compact variant omits the tax note. The sale end
date is never displayed.

Placement:

- **Course card and course row** (`templates/learner_interface/partials/course_card.html`,
  `course_row.html`): when `course.current_price` exists and `listing_status` is `not_registered` or
  `coming_soon`, the compact price sits on its own line under the title. It shows to anonymous and
  signed-in visitors alike. The eyebrow and access badge are unchanged.
- **Course page stats strip** (`templates/learner_interface/course_detail.html`, the `stat-card`
  partial): a "Price" cell with the compact price, placed before the Enrolment cell. It shows
  whenever the course has a price. The `stat-card` partial currently takes a plain `stat_value`, so
  it needs to accept rendered markup for this cell.
- **Sign-up panel** (same template): the full price sits above the acquisition heading, only when
  the visitor is not registered. The heading, subtext and CTA from the backend are unchanged.

### JSON-LD

- New filter `json_ld_script` in `freedom_ls/base/templatetags/fls_base_filters.py`. It serialises
  with `DjangoJSONEncoder`, escapes `<`, `>` and `&` as `<`, `>` and `&` (as
  `json_script` does, without importing Django's private escape table), and wraps the result in
  `<script id="…" type="application/ld+json">`.
- `course_detail.html:17` and `all_courses.html:10` switch from `json_script` to `json_ld_script`.
- `course_detail()` in `freedom_ls/learner_interface/views.py` sets `json_ld["offers"]` from
  `course.current_price().offers_json_ld()` when that is not `None`, next to the existing
  conditional keys at `views.py:762`:
  - fixed, or an expired discount: `{"@type": "Offer", "price": "1499.00", "priceCurrency": "ZAR"}`
  - live discount: `Offer` with the sale amount, plus `"priceValidUntil": "YYYY-MM-DD"` when
    `sale_ends_on` is set
  - range: `{"@type": "AggregateOffer", "lowPrice": …, "highPrice": …, "priceCurrency": …}`, with no
    `offerCount`
  - on_request: no `offers` key
- Prices are decimal strings, never floats.

## Testing

- **Model and constraint.** Each kind round-trips. The DB rejects mismatched columns for each kind,
  sale ≥ original, low ≥ high, and amounts ≤ 0. `clean()` fills a blank currency from
  `DEFAULT_CURRENCY` and errors when it is unset.
- **`price_errors`.** It rejects an unknown code (`"ZZZ"`), JPY `"1500.50"` and KWD `"1.2345"`, and
  accepts KWD `"1.234"`.
- **`current_price`.** A sale is live on `sale_ends_on` itself and has expired the next day
  (freeze time). With no end date, a sale never expires. The currency default is not applied at
  render.
- **Schema.** Each kind parses. A bare YAML number is rejected with the quoting message. An unknown
  `kind` gives a `union_tag_invalid` error. An extra key in a kind is rejected, and so is a
  `currency` on `on_request`.
- **`content_save`.** Switching a course from range to fixed clears the low and high amounts. An
  absent `price:` keeps an admin-set price, and `price: null` clears it. A missing currency with no
  default raises. Follow the two-stage shape of
  `freedom_ls/content_engine/tests/test_course_difficulty_duration_outcomes.py`.
- **Offline validator** (`claude_plugins/fls-content/validate/tests/test_validator.py`). It accepts
  the example frontmatter and rejects each rule violation above.
- **Settings check.** An invalid `DEFAULT_CURRENCY` or `PRICE_LOCALE` produces an error.
- **Component.** Every kind renders in both variants. A discounted price contains the sr-only
  "Original price:" and "Now:" text. `PRICE_LOCALE="en_ZA"` renders `R1 499,00`.
- **Placement.**
  - The card and row show the price for anonymous and signed-in not-registered visitors, and not for
    registered learners.
  - The stats cell shows for everyone.
  - The sign-up panel price shows only when the visitor is not registered.
  - An application-gated priced course still shows "By application" and its Apply CTA.
- **JSON-LD** (`freedom_ls/learner_interface/tests/test_seo_discoverability.py`).
  - Update `_extract_json_ld` to match `application/ld+json`.
  - Test `offers` for each kind, including an expired discount (shown as fixed with no
    `priceValidUntil`) and on_request (no `offers`).
  - A course title containing `</script>` does not break out of the tag.
  - The catalogue block also emits `application/ld+json`.

## Success criteria

- A `course.md` with each of the four kinds loads and renders. The admin can create and edit each
  kind.
- A priced application-gated course shows "By application", its price and the unchanged Apply CTA
  on the card, row and course page.
- A discount whose `sale_ends_on` has passed shows only the original amount, both on the page and in
  JSON-LD, with no data change.
- Invalid prices fail in the offline validator, `content_save` and the admin with a field-specific
  message.
- Viewing the source of a course page shows `<script type="application/ld+json">` containing
  `offers` for a priced course.
- A screen reader reading a discounted price hears "Original price" before the struck-through
  amount and "Now" before the sale amount.
- `uv run pytest` passes.
