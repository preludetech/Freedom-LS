## Task 2: price rules and `CoursePrice` in `freedom_ls/content_engine/prices.py`

New module. It must not import `freedom_ls.content_engine.models` at module level, because
`models/courses.py` calls into it and `schema.py` imports it. Start the file with
`from __future__ import annotations` and import `PriceKind` under `TYPE_CHECKING` only, the way
`form_engine/typed_answers.py` does. Without the `__future__` import, the `kind: PriceKind`
annotation on the dataclass raises `NameError` when the module loads.

`price_errors` and `KIND_FIELDS` use the standard library, Babel and `decimal_places_used`, which
the bundled validator already has, so the validator can copy them unchanged.

### `KIND_FIELDS` and `price_errors`

```python
# kind -> (fields the kind requires, fields it may also carry)
KIND_FIELDS: dict[str, tuple[frozenset[str], frozenset[str]]] = {
    "fixed": ({"amount"}, {"currency", "tax_note"}),
    "range": ({"low_amount", "high_amount"}, {"currency", "tax_note"}),
    "discounted": ({"amount", "sale_amount"}, {"sale_ends_on", "currency", "tax_note"}),
    "on_request": (set(), set()),
}

def price_errors(
    kind: str, *,
    amount: Decimal | None = None, sale_amount: Decimal | None = None,
    sale_ends_on: date | None = None,
    low_amount: Decimal | None = None, high_amount: Decimal | None = None,
    currency: str = "", tax_note: str = "",
) -> dict[str, str]:
    # Keys are the author-facing field names: "amount", "currency", ...
    # 1. Required fields that are empty: "<field> is required for a <kind> price".
    # 2. Set fields the kind does not use: "<field> is not used by a <kind> price".
    # 3. currency set and not in list_currencies(): error on "currency".
    # 4. Each amount present must be finite (amount.is_finite(), checked first, because comparing
    #    NaN raises InvalidOperation) and > 0. When currency is a valid code,
    #    decimal_places_used(amount) must be <= get_currency_precision(currency).
    # 5. sale_amount >= amount: error on "sale_amount". low_amount >= high_amount: error on "high_amount".
    # A blank currency skips rule 3 and the decimal-place half of rule 4.
```

`decimal_places_used` ignores trailing zeros, and that is what this rule needs. The column keeps
three decimal places, so the admin re-submits a ZAR amount as `1499.000`, and that must pass. JPY
`"1500.50"` still fails, because `.5` is a real half yen. Nothing is ever rounded.

Currency is never required by `price_errors`. Each caller resolves the default first, and each
caller reports a still-missing currency itself (tasks 3 and 7).

The column name for every field is `price_` plus its author-facing name (`amount` and
`price_amount`, `sale_ends_on` and `price_sale_ends_on`). Callers rely on that mapping, so there is
no second lookup table.

### `CoursePrice`

```python
@dataclass(frozen=True)
class CoursePrice:
    kind: PriceKind            # import under TYPE_CHECKING only
    currency: str = ""
    amount: Decimal | None = None
    sale_amount: Decimal | None = None
    sale_ends_on: date | None = None
    low_amount: Decimal | None = None
    high_amount: Decimal | None = None
    tax_note: str = ""

    # formatted_amount, formatted_sale_amount, formatted_low_amount, formatted_high_amount:
    # properties returning format_currency(value, self.currency, locale=price_locale())

    def offers_json_ld(self) -> dict[str, object] | None: ...
```

- `price_locale() -> str` returns `config.PRICE_LOCALE`, or
  `to_locale(settings.LANGUAGE_CODE)` when that is `None`. Import `config` and `settings` inside
  the function.
- `offers_json_ld()` follows the spec's JSON-LD table. Amounts go out as decimal strings quantized
  to the currency's precision, so a stored `1499.000` becomes `"1499.00"` in ZAR and `"1500"` in
  JPY. Use one private helper for that:
  `amount.quantize(Decimal(1).scaleb(-get_currency_precision(currency)))`, then `str()`.
  `priceValidUntil` is `sale_ends_on.isoformat()` and is present only on a discounted price with an
  end date. `on_request` returns `None`. `AggregateOffer` carries no `offerCount`.
- `CoursePrice` never decides expiry. It trusts the `kind` it is given (task 3 decides).

Tests in `freedom_ls/content_engine/tests/test_prices.py`: the `price_errors` cases from the spec
(`"ZZZ"`, JPY `"1500.50"`, KWD `"1.2345"` rejected, KWD `"1.234"` accepted), a missing and a stray
field for each kind, both orderings, amounts `<= 0`, a `NaN` amount, ZAR `"1499.000"` accepted,
`offers_json_ld()` for each kind, and formatting
with `PRICE_LOCALE="en_ZA"` giving `R1 499,00`. Babel separates with non-breaking spaces, so build
the expected string from Babel's output or normalise whitespace. Do not hardcode an ASCII space.

def price_columns(item: CourseSchema) -> dict[str, object]:
    """The eight price_* columns for a course whose frontmatter has a `price:` key."""
    columns = dict(EMPTY_PRICE_COLUMNS)
