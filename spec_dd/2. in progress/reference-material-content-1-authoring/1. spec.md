# Spec: Reference material, authoring

## Purpose

Courses need reference material, such as the regulations in a drone-training course, that learners consult at any time without it counting toward what they must complete. This spec lets an author attach reference parts to a course with a `reference:` key in `course.md`. `content_save` stores them, validates them and keeps the database in step with the files. Learner and educator pages read what this spec stores and are built in the sibling specs (see `idea.md`).

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| learning path | coined | A course's `Course.items`: the placements that count toward completion, gating and deadlines. No existing term; the idea and roadmap use this one. |
| reference part | coined | A `CoursePart` that a `CourseReferencePart` row attaches to a course. It is an ordinary `CoursePart`; "reference" describes how one course attaches it, not the part itself. |
| reference entry | coined | One item of a course's `reference:` list. |

## Scope

In:

- The `CourseReferencePart` model, its migration and an admin inline on the course.
- The `reference:` key on the `Course` schema, in `content_engine` and in the offline validator copy in `claude_plugins/fls-content/validate/`.
- Writing and reconciling `CourseReferencePart` rows in `content_save`, and deleting a course's old part placement for a part that course now lists under `reference:`.
- New cross-file validation rules, run by both check lists.
- Excluding a course directory's `reference/` subdirectory from auto-discovery.
- `danger_content_delete` counting and deleting `CourseReferencePart`.
- A demo course, its test, author docs and product docs.

Out:

- Learner pages and course chrome (`reference-material-content-2-learner-reference`).
- Educator outline and content preview (`reference-material-content-3-educator-reference`).
- Courses with only reference material, and their demo (`reference-material-content-4-library-courses`).
- Nesting deeper than part then topics; PDFs and files; search; forms or activities in reference parts.
- Deleting placements for children dropped from `children:` in general. Only the part placement of a part the same course lists under `reference:` is deleted.
- Recomputing stored `CourseProgress.progress_percentage` or `completed_time` after a placement is deleted. Stored values stay as they are, as for any content change today (`answers.md`).
- `qa_helpers` seeds for reference material.

## Decisions

- **The cleanup deletes and reports.** It runs in the same atomic load as the rest of the save, and the save output names every row it removed (`answers.md`). There is no dry-run or opt-in flag.
- **`DeadlineExtension` rows go with the placement.** `DeadlineExtension.collection_item` is `CASCADE`, like both override models, so an extension on a deleted part placement is deleted too and is counted in the output. A placement cannot be deleted while keeping it.
- **"Not a part" is a cross-file rule.** The schema sees only a path string, so a `reference:` entry naming a topic, form or course fails in `validate.py`, where the target is parsed.
- **Due keys on a reference entry fail at parse time.** The reference entry has its own schema class with no due fields, so they never reach the cross-file rules.
- **The cross-file rules resolve through `_ParsedByPath` in both check lists.** In `validate(path)` a `../` part may sit outside the validated path; in `save_content_to_db` everything under the root is already parsed. One function serves both, as `validate_due_date_placements` does, so the two lists cannot disagree.

## Requirements

### Model (`freedom_ls/content_engine/models/courses.py`)

- `CourseReferencePart(SiteAwareModel)` with:
  - `course`: FK to `Course`, `on_delete=CASCADE`, `related_name="reference_parts"`.
  - `course_part`: FK to `CoursePart`, `on_delete=CASCADE`, `related_name="+"`.
  - `order`: `PositiveIntegerField`.
  - A `UniqueConstraint` on `(course, course_part)`. The site is not in it: both FKs already pin it, as with `CoursePartChildDueDate`.
  - `Meta.ordering = ["order"]`.
- `Course.items` and `ContentCollectionItem` are unchanged.
- A new migration, made with `makemigrations`.

### Schema (`freedom_ls/content_engine/schema.py`)

- A new `ReferenceEntry(BaseModel)` with `model_config = ConfigDict(extra="forbid")` and one field, `path: Path`. When the input carries `due_date`, `due_time`, `due_days_after_registration`, `no_due_date` or `children`, the error names the key and says a reference entry takes only `path` (a `model_validator(mode="before")`, so the author does not get pydantic's bare "Extra inputs are not permitted").
- `Course.reference: list[ReferenceEntry] = Field(default_factory=list, ...)`. An omitted key and `reference: []` mean the same thing: the course has no reference parts.
- `CoursePart` gains no `reference:` key.
- `save_course` in `content_save.py` adds `"reference"` to the `exclude_fields` it passes to `save_with_uuid`.

### Auto-discovery (`freedom_ls/content_engine/validate.py`)

- When a `Course` has no `children:` list, `collection_children` leaves out the `reference` subdirectory beside the course file. Today `reference/` is ignored only when it holds no direct content file. After this spec it is never read as learning path content, whatever it holds.
- A part's auto-discovery is unchanged. A directory named `reference` inside a part is still a child.
- `get_all_files` is unchanged, so every file under `reference/` is still parsed and saved.

### Validation (`freedom_ls/content_engine/validate.py`)

A new `validate_reference_lists(all_parsed) -> list[str]` checks every `Course` with a non-empty `reference:` list. It resolves each entry with `resolve_author_path(course.file_path, entry.path)` and the target with `_ParsedByPath.get`. It reports each problem in the existing `_reference_error` block, under the header `Invalid reference list`, with the field `reference[<index>]`. It rejects:

1. An entry whose path is named twice in the same `reference:` list (`_repeated_indices`, `_NAMED_TWICE`).
2. An entry whose resolved path is also a `children:` entry of the same course. The check compares resolved keys and needs no parse. Fix text: list the part in one of the two lists.
3. An entry whose target is not a `COURSE_PART`. Problem text: `this file is a <TYPE>, not a COURSE_PART`. A target that does not exist or does not parse (`None`) is skipped here; the loader's "was not loaded" error covers it, as for `children:`.
4. A child of the reference part, listed or auto-discovered (`_ParsedByPath.children_of`), that is not a `TOPIC`. The error names the child's path relative to the part and its type.
5. A due key (`holds_due_value()`) on any `children:` entry in the reference part's `part.yaml`.
6. A due key on a reference part's topic file: any of `due_date`, `due_time`, `due_days_after_registration` set, or `no_due_date` true, in the topic's own frontmatter.

`children_of` raises `ValueError` when a file beside the part does not parse. The rule catches it and reports it against the entry, as `_nested_list_errors` does, so one broken file does not abort the run.

Rules 4 to 6 apply to every part any course lists under `reference:`, including a part another course places in its learning path. A part with due keys on its topics cannot also be a reference part.

The same topic may sit in a learning path part and a reference part of one course. Only a whole part is barred from both lists.

`validate_reference_lists` is added to both check lists: the one in `validate(path)` and the one in `save_content_to_db` before any write (beside `validate_children_lists`, `validate_due_date_placements` and `validate_question_sections`).

### Loading (`freedom_ls/content_engine/management/commands/content_save.py`)

In `save_content_to_db`, for each course in the load:

- **Write.** One `CourseReferencePart` per reference entry, `order` set to the entry's index, using `update_or_create` on `(site, course, course_part)`. The part comes from `content_by_path`. An entry whose path was not loaded raises `ValueError` with the same wording as the `children:` loop's "names a child at ... that was not loaded", and the atomic load rolls back. A loaded file that is not a `CoursePart` raises `ValueError` too; the validator normally catches this first.
- **Reconcile.** Delete the course's `CourseReferencePart` rows whose part this load's `reference:` list does not name. This applies only to courses in the load (`loaded_course_ids`). A course with no `reference:` key loses all its rows.
- **Clean up.** For each part the course lists under `reference:`, delete that course's part placement: the `ContentCollectionItem` with `collection_type=Course`, `collection_id=<course>`, `child_type=CoursePart`, `child_id=<part>`. The delete cascades its `CoursePartChildDueDate`, `CohortDeadlineOverride`, `LearnerDeadlineOverride` and `DeadlineExtension` rows. Another course's placement of the same part is untouched. Every write and delete carries `site=site` explicitly, as the existing loader code does.
- **Order.** The cleanup runs before `moved_children` and `carry_placement_due_dates`. Otherwise `_left_behind`, which reads `course.viewable_collection_items()`, still sees the stale part placement.
- **Report.** For each part placement deleted, `click.echo` prints one line naming the course and part by file path relative to the load root, with a count of each cascaded kind. The lines come just before the `✓ Successfully saved all content` line, so a load that rolls back has printed none. Shape:

  ```
  Removed part placement: <course path> no longer places <part path> in its learning path (it is listed under reference:).
    Deleted with it: 2 cohort deadline override(s), 1 learner deadline override(s), 0 deadline extension(s), 3 part child due date(s).
  ```

- A reload with unchanged files writes and deletes nothing, and prints no removal line.
- The part and its topics are saved as for any other part. Its part-to-topic `ContentCollectionItem` rows are written by the existing loop.

### Offline validator (`claude_plugins/fls-content/validate/`)

- `schema.py` mirrors `ReferenceEntry` and `Course.reference`.
- `validate.py` mirrors the `reference/` auto-discovery exclusion and `validate_reference_lists`, and adds it to its check list.
- `tests/test_validator.py` has a test per rule. `test_the_shipped_demo_content_passes` must still pass with the new demo course in `demo_content/`.

### Admin (`freedom_ls/content_engine/admin.py`)

- A `CourseReferencePartInline` on `CourseAdmin`, showing `course_part` and `order` and never `site`. It is read-only, since the loader writes the rows: no add, no delete, `max_num=0`, as `CoursePartChildDueDateInline` (unfold `TabularInline`) is. For the base class, see Open questions.

### Delete command (`freedom_ls/dev_tools/management/commands/danger_content_delete.py`)

- `CourseReferencePart` is added to `models_to_delete` before `Courses` and `Course Parts`, so it is counted in "Total items to delete" and deleted explicitly.

### Demo content (`demo_content/`)

- A new course directory, for example `demo_content/functionality_demo_reference_material/`, with:
  - a learning path of at least one part and one topic, listed under `children:`;
  - one reference part inside the course's own `reference/` directory;
  - one reference part outside the course directory, reached with `../` (for example `demo_content/shared_reference_material/<part dir>/part.yaml`).
- Every course, part and topic file carries a `uuid`, so the demo loads once `sacaa-compliance-content-versions-and-access-1-content-save-safety` makes a missing uuid fail.
- `categories:` names a slug that exists in `demo_content/course_categories.yaml`.
- No course, part, topic or form title repeats one an existing test looks up with `.get(title=...)`: "Core Concepts", "Key Ideas", "Knowledge Check".
- `functionality_demo_course_parts` and `functionality_demo_course_parts_placement` are not changed.

## Testing

Tests mirror source paths (`fls-dev:testing`).

- **Schema** (`freedom_ls/content_engine/tests/test_schema.py`): `reference:` parses; each due key and `children` on a reference entry fails with a message naming the key; `reference:` in a `part.yaml` fails.
- **Auto-discovery** (`test_validate.py`): a course with no `children:` and a `reference/` directory holding a direct `part.yaml` or topic file adopts nothing from it; a part's `reference` subdirectory is still adopted.
- **Validation** (`test_validate.py`): one test per rule 1 to 6, each asserting the header, field and problem text. Rules 4 to 6 also run through `validate(<course dir>)` with the part reached by `../` outside the validated path. A file beside a reference part that does not parse is reported, not raised. A topic in both a learning path part and a reference part of one course passes.
- **Both check lists**: a bad fixture run through `save_content_to_db` raises before any write, with the same rule as `validate`.
- **Loading** (`freedom_ls/content_engine/tests/management/commands/test_content_save.py`):
  - rows written in list order; reorder in the file reorders `order`;
  - an entry removed from `reference:`, and the key removed entirely, delete the rows on reload;
  - a part moved from `children:` to `reference:` loses that course's part placement with its `CoursePartChildDueDate`, `CohortDeadlineOverride`, `LearnerDeadlineOverride` and `DeadlineExtension` rows, and the output names course, part and counts;
  - two courses place one part; one moves it to `reference:`; the other course's placement and its overrides survive;
  - the moved part is no longer in `Course.items` and no longer counts in the course's progress calculation;
  - a second unchanged load writes nothing and prints no removal line;
  - an entry naming an unloaded path, or a non-part file, raises and rolls back.
- **Admin** (`test_admin.py`): the inline renders the course's reference parts and offers no add or delete.
- **Delete command** (`freedom_ls/dev_tools/tests/test_danger_content_delete.py`): `CourseReferencePart` rows are counted and deleted.
- **Demo** (`freedom_ls/content_engine/tests/demo_content/test_reference_parts.py`): after loading `demo_content/`, the new course has its learning path and two `CourseReferencePart` rows in order, and neither reference part is in `Course.items`.
- **Offline validator**: one test per rule in `claude_plugins/fls-content/validate/tests/test_validator.py`, plus the existing whole-demo test.

## Open questions

- Q: Which base class does `CourseReferencePartInline` use? `fls-dev:admin-interface` names `SiteAwareTabularInline`, which does not exist in `freedom_ls/site_aware_models/admin.py`. → A: unfold `TabularInline`, as `CoursePartChildDueDateInline` uses, with `site` not shown (assumed default: matches the read-only loader inline already in `content_engine/admin.py` and adds no new base class. Overrule by editing Requirements → Admin to add `SiteAwareTabularInline` to `site_aware_models/admin.py`.)
- Q: Is the removal reported per course or per part, and in what words? → A: one line per deleted part placement naming course and part, with an indented count line (assumed default: the cleanup is per course and per part, so one line per placement serves both; the shape follows the existing `Wrote N and removed M file(s)` line. Overrule by editing Requirements → Loading → Report.)
- Q: Does an `ACTIVITY` child of a reference part fail? → A: yes (assumed default: the idea settles "topics only"; it names forms and nested parts as examples. Overrule by editing Validation rule 4.)

## Success criteria

- `content_save` on a course with `reference:` writes one `CourseReferencePart` per entry, in list order, and a reload after removing an entry deletes its row.
- After moving a part from `children:` to `reference:` and reloading, that course's `Course.items` holds no placement of the part, and the output names the removed placement and its cascaded rows.
- Each of the six rules fails `content_validate`, `save_content_to_db` and the offline validator with an error naming the file, `reference[<index>]` and the problem.
- A `reference/` directory with a direct content file beside a course with no `children:` adds nothing to that course's learning path.
- `danger_content_delete` lists and deletes `CourseReferencePart`.
- The new demo course loads with the rest of `demo_content/`, and every existing demo test and both whole-tree validator tests pass.
