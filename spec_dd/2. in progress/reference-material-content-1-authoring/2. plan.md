# Plan: Reference material, authoring

Implements `1. spec.md`. An author lists reference parts under `reference:` in `course.md`; `content_save` validates the list, stores one `CourseReferencePart` per reference entry, and removes the course's old part placement of a part that moved there.

## How to work

- TDD throughout: write the failing test, see it fail, make it pass. Each slice is committed alone with its own tests passing.
- Read `claude_plugins/django-stack/resources/test_tiers.md` before running pytest. `dev_tooling` tests are excluded from a bare `uv run pytest`; run them with `-m dev_tooling`.
- Skills to load, by area:
  - every test: `ds:testing` and `fls-dev:testing`. Tests mirror source paths. A test that touches a site-aware model takes the `mock_site_context` fixture and never sets `site` by hand. No `if`/`for`/`try` in a test body; use `pytest.mark.parametrize`. Test data comes from factories or from content files loaded through `save_content_to_db`, never `.objects.create()`.
  - model, loader, delete command: `fls-dev:multi-tenant`. The loader runs with no request, so it follows the existing loader code and passes `site=site` on every write and delete.
  - admin inline: `ds:admin-interface` and `fls-dev:admin-interface`. The inline base is unfold `TabularInline`, as `CoursePartChildDueDateInline` uses; the `SiteAwareTabularInline` the skill names does not exist.
  - naming, error text and the removal output: `fls-dev:domain-glossary`. "Part placement" is the `ContentCollectionItem` whose collection is a `Course` and whose child is a `CoursePart`.
  - demo content: the `content-types` and `conventions` skills under `claude_plugins/fls-content/skills/`.
  - every comment and docstring: `ds:code-comments` and `sdd:planning-references-in-code`.
- No MCP server is needed.
- Existing TODO and `@claude` comments in touched files stay.
- Type hints on every new function, no `Any`, specific exception types, no logging.

## Slices

### Slice 1: a `reference:` list loads as `CourseReferencePart` rows

A `course.md` with `reference:` entries naming parts loads, and the course has one `CourseReferencePart` per reference entry, in list order. A reload after reordering the file reorders `order`. A reload with unchanged files leaves the rows as they were.

**Builds on:** none
**Touches:** freedom_ls/content_engine/models/courses.py, freedom_ls/content_engine/models/__init__.py, freedom_ls/content_engine/migrations/, freedom_ls/content_engine/factories.py, freedom_ls/content_engine/schema.py, freedom_ls/content_engine/management/commands/content_save.py, freedom_ls/content_engine/tests/test_schema.py, freedom_ls/content_engine/tests/management/commands/test_content_save.py

Model, in `models/courses.py`, exported from `models/__init__.py`:

```python
class CourseReferencePart(SiteAwareModel):
    """A part a course offers as reference material. The part is an ordinary CoursePart;
    this row, not a ContentCollectionItem, attaches it, so it never counts toward what a
    learner must complete."""

    course = models.ForeignKey(
        Course, on_delete=models.CASCADE, related_name="reference_parts"
    )
    course_part = models.ForeignKey(
        CoursePart, on_delete=models.CASCADE, related_name="+"
    )
    order = models.PositiveIntegerField()

    class Meta:
        ordering = ["order"]
        constraints = [
            # Both foreign keys already pin the site, so it is not part of the constraint.
            models.UniqueConstraint(
                fields=["course", "course_part"], name="one_reference_part_per_course_part"
            )
        ]

    def __str__(self) -> str:
        return f"{self.course_part} as reference in {self.course}"
```

```python
def sync_reference_parts(
    site: Site,
    collections_data: list[tuple[Course | CoursePart, BaseBaseContentModel]],
    content_by_path: Mapping[Path, models.Model],
) -> list[str]:
    """Write each loaded course's reference parts from its reference: list. Returns the
    lines that report what was removed, for the caller to print once the load is safe."""
    for course, schema_item in collections_data:
        if not isinstance(course, Course) or not isinstance(schema_item, CourseSchema):
            continue
        for order, entry in enumerate(schema_item.reference):
            part = content_by_path[resolve_author_path(schema_item.file_path, entry.path)]
            CourseReferencePart.objects.update_or_create(
                site=site, course=course, course_part=part, defaults={"order": order}
            )
    return []
```

### Slice 2: a malformed reference entry fails at parse time with a message that names the problem

A due key or `children` on a reference entry, or a bare-string entry, fails parsing with a message naming the key or the shape. `reference:` in a `part.yaml` fails.

**Builds on:** slices 1
**Touches:** freedom_ls/content_engine/schema.py, freedom_ls/content_engine/tests/test_schema.py

`ReferenceEntry` gains a before-validator:

```python
# Module level, above ReferenceEntry: pydantic would turn an underscore name in the class
# body into a private attribute.
_REFERENCE_ENTRY_REJECTED_KEYS = (*sorted(DUE_DATE_FIELD_NAMES), "no_due_date", "children")

# On ReferenceEntry:
@model_validator(mode="before")
@classmethod
def _takes_only_a_path(cls, data: object) -> object:
    if not isinstance(data, Mapping):
        raise ValueError(
            f"a reference entry is a mapping with a path key, not {data!r}; "
            "write `- path: <part.yaml>`"
        )
    for key in _REFERENCE_ENTRY_REJECTED_KEYS:
        if key in data:
            raise ValueError(f"{key}: a reference entry takes only path")
    return data
```

`DUE_DATE_FIELD_NAMES` (imported from `freedom_ls.content_base.schema`) holds `due_date`, `due_time` and `due_days_after_registration`; `no_due_date` lives on `PlacementDueDate`, so it is named separately. Add `from collections.abc import Mapping`. `CoursePart` is not changed: its `extra="forbid"` already rejects the key.

Tests: one parametrised test over `due_date`, `due_time`, `due_days_after_registration`, `no_due_date`, `children`, each asserting the message names the key; a bare-string entry gives the mapping message; `reference:` in a `part.yaml` fails.

### Slice 3: the reference rows follow the file on reload, and a bad entry rolls the load back

**Touches:** freedom_ls/content_engine/management/commands/content_save.py, freedom_ls/content_engine/tests/management/commands/test_content_save.py

### Slice 4: moving a part from `children:` to `reference:` removes the course's part placement and reports it

After a part moves from `children:` to `reference:` and the content reloads, that course's part placement is gone with everything that hangs off it, another course's placement of the same part is untouched, and the output names the course, the part and the counts. A second unchanged load prints no removal line.

**Builds on:** slices 1, 3
**Touches:** freedom_ls/content_engine/management/commands/content_save.py, freedom_ls/content_engine/tests/management/commands/test_content_save.py, freedom_ls/deadlines/tests/invariants/, freedom_ls/learner_progress/tests/invariants/, test_organisation/mirroring_exemptions.txt

```python
# What deleting a part placement cascades to, as Django's collector labels it, and how
# the report names it. Labels, not imports: the deadline models live in an app that
# depends on this one.
_PLACEMENT_CASCADES = (
    ("freedom_ls_deadlines.CohortDeadlineOverride", "cohort deadline override(s)"),
    ("freedom_ls_deadlines.LearnerDeadlineOverride", "learner deadline override(s)"),
    ("freedom_ls_deadlines.DeadlineExtension", "deadline extension(s)"),
    ("freedom_ls_content_engine.CoursePartChildDueDate", "part child due date(s)"),
)


def remove_part_placement(site: Site, course: Course, part: CoursePart) -> str | None:
    """Delete this course's placement of a part it now lists as reference material, and
    say what went with it. None when the course did not place the part."""
    total, deleted = ContentCollectionItem.objects.filter(
        site=site,
        collection_type=DjangoContentType.objects.get_for_model(Course),
        collection_id=course.id,
        child_type=DjangoContentType.objects.get_for_model(CoursePart),
        child_id=part.id,
    ).delete()
    if not total:
        return None
    counts = ", ".join(
        f"{deleted.get(label, 0)} {noun}" for label, noun in _PLACEMENT_CASCADES
    )
    return (
        f"Removed part placement: {course.file_path} no longer places {part.file_path} "
        "in its learning path (it is listed under reference:).\n"
        f"  Deleted with it: {counts}."
    )
```

- `course.file_path` and `part.file_path` are already relative to the load root: `save_with_uuid` stores `item.file_path.relative_to(base_path)`.
- Order matters twice, and the call site carries both reasons as a comment. The call sits before the `CoursePartChildDueDate` reconcile, because that reconcile would delete the placement's child due dates first and the report would count none. It sits before `moved_children` and `carry_placement_due_dates`, because `_left_behind` reads `course.viewable_collection_items()` and would still see the stale part placement.
- `save_content_to_db` keeps the returned lines and prints each with `click.echo` immediately before the `✓ Successfully saved all content` line, so a load that rolls back has printed none.

### Slice 6: a reference list that repeats a part, overlaps the learning path, or names a non-part fails validation

`content_validate` and `save_content_to_db` both reject, before any write, a `reference:` list with an entry named twice, an entry that is also a learning path child, or an entry whose target is not a `COURSE_PART`. Each error names the course file, `reference[<index>]` and the problem under the header `Invalid reference list`.

**Builds on:** slices 1, 3, 4, 5
**Touches:** freedom_ls/content_engine/validate.py, freedom_ls/content_engine/management/commands/content_save.py, freedom_ls/content_engine/tests/test_validate.py, freedom_ls/content_engine/tests/management/commands/test_content_save.py

```python
_reference_list_error = functools.partial(_reference_error, header="Invalid reference list")
_PART_NAMED_TWICE = {"problem": "this part is named twice", "fix": "Name each part once."}


def validate_reference_lists(all_parsed: Sequence[BaseBaseContentModel]) -> list[str]:
    """Check every course's reference: list against the files it names.

    A reference part sits outside the learning path, so it may not also be a child of the
    course, and it holds topics with no due dates.
    """
    errors: list[str] = []
    # Reads from disk when a part sits outside the validated path, so validating one
    # course directory gives the same answer as loading the whole tree.
    by_path = _ParsedByPath(all_parsed)
    for course in all_parsed:
        if not isinstance(course, Course) or not course.reference:
            continue
        keys = [resolve_author_path(course.file_path, e.path) for e in course.reference]
        repeated = _repeated_indices(keys)
        learning_path = _learning_path_keys(course)
        for index, (entry, key) in enumerate(zip(course.reference, keys, strict=True)):
            error = functools.partial(
                _reference_list_error,
                course.file_path,
                course.content_type,
                f"reference[{index}]",
                str(entry.path),
            )
            if index in repeated:
                errors.append(error(**_PART_NAMED_TWICE))
            if key in learning_path:
                errors.append(error(
                    problem="this part is also one of the course's children",
                    fix="List the part under children: or under reference:, not both.",
                ))
            target = by_path.get(key)
            if target is None:
                # Nothing at this path, or a file that does not parse: the loader's
                # "was not loaded" error and the file's own validation report those.
                continue
            if not isinstance(target, CoursePart):
                errors.append(error(
                    problem=f"this file is a {target.content_type}, not a COURSE_PART",
                    fix="Point the entry at a part.yaml.",
                ))
    return errors


def _learning_path_keys(course: Course) -> set[Path]:
    try:
        return {path for path, _ in collection_children(course)}
    except ValueError:
        # Auto-discovery met a file that does not parse. That file's own validation
        # reports it, and the loader stops on it, so the overlap check is skipped.
        return set()
```

A `reference:` path may use `../`, so `_ParsedByPath` reads part files outside the validated path, exactly as it already does for `children:` paths. That is accepted: the author and the operator control the checkout.

Add `validate_reference_lists(all_parsed)` to the cross-file loop in `validate(path)` beside `validate_children_lists`, and to `placement_errors` in `save_content_to_db`.

Tests: one test per rule, each asserting header, `reference[<index>]` and problem text. The overlap rule has a case with explicit `children:` and one with an auto-discovered part. A target that does not exist gives no message here. A bad fixture run through `save_content_to_db` raises the same rule before any write. A `reference:` entry naming a topic file, run through `save_content_to_db`, raises the validator's message and writes nothing.

### Slice 7: a reference part that holds anything but topics without due keys fails validation

A reference part with a child that is not a `TOPIC`, a due key on an entry of its own `children:` list, or a due key in a topic's frontmatter fails validation, once per course that lists it, naming that course's file and `reference[<index>]`.

**Builds on:** slices 6
**Touches:** freedom_ls/content_engine/validate.py, freedom_ls/content_base/schema.py, freedom_ls/content_engine/tests/test_validate.py, freedom_ls/content_engine/tests/management/commands/test_content_save.py


```python
def _reference_part_errors(
    error: Callable[..., str], part: CoursePart, by_path: _ParsedByPath
) -> list[str]:
    """A reference part holds topics, and nothing in it carries a due date."""
    # The part may sit outside the validated path, where the per-file pass never saw its
    # siblings, so a file that does not parse is reported here rather than raised.
    try:
        children = by_path.children_of(part)
    except ValueError as e:
        return [error(
            problem=f"a file beside the part does not parse: {e}",
            fix="Fix that file first.",
        )]
    errors: list[str] = []
    for key in children:
        child = by_path.get(key)
        if child is None:
            continue
        shown = _shown_relative_to(key, part.file_path.parent)
        if child.content_type != ContentType.TOPIC:
            errors.append(error(
                problem=f"the part's child {shown} is a {child.content_type}",
                fix="A reference part holds topics only.",
            ))
        elif child.sets_a_due_key():
            errors.append(error(
                problem=f"the part's topic {shown} sets a due date",
                fix="Remove the due keys from the topic file; reference material has no deadline.",
            ))
    errors.extend(
        error(
            problem=f"the part's children: entry {entry.path} sets a due date",
            fix="Remove the due keys from part.yaml; reference material has no deadline.",
        )
        for entry in part.children
        if entry.holds_due_value()
    )
    return errors
```

`sets_a_due_key()` exists today on `PlacementDueDate` in `freedom_ls/content_base/schema.py`. Move it up to `DueDateFields`, unchanged, so a `Topic` and a `children:` entry share the one predicate; `DUE_DATE_FIELD_NAMES` is defined after `DueDateFields` and is only read when the method runs, so the move needs no reordering. A topic file has no `no_due_date` field: `Topic` takes its due keys from `DueDateFields` and forbids extras, so `no_due_date` in a topic's frontmatter already fails when the file is parsed, and this check covers the three due keys.

Tests: one test per rule, asserting header, field and problem text, with `ACTIVITY`, `FORM` and `COURSE_PART` children parametrised for the first. Each of the three also runs through `validate(<course dir>)` with the part reached by `../` outside the validated path. A file beside a reference part that does not parse is reported, not raised. A topic in both a learning path part and a reference part of one course passes. A part referenced by one course and placed with a nested due list by another passes. A part listed by two courses reports once per course. Each of the three rules also runs through `save_content_to_db` on a bad fixture and raises the same message before any write.
