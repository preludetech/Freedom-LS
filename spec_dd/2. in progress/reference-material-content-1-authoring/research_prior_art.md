# Prior art: reference material beside a required path, and collection item cleanup

Facts only. Paths are repo-relative. Vocabulary: collection item = a `ContentCollectionItem` row; child = the object it holds; part placement = a course's collection item whose child is a `CoursePart`.

Limit of this research: the git log could not be searched (no shell tool was available), so no commit hashes are cited. Findings below come from `spec_dd/` files, which record the earlier work. The work is dated in the `spec_dd/3. done/` directory names.

- `spec_dd/3. done/2026-10-25_17:46_deadlines-1-dates-and-overdue/research_known_complaints.md` (item 9, line ~64) raised "optional items" in an earlier spec: "If a placement's course content has optional items, a due date on an optional item still shows overdue; decide whether optional items can carry a due date or are exempt." ## 2. Here: part placement (`../`) and per-placement due dates

- Built in `spec_dd/3. done/2026-11-03_05:13_deadlines-8-per-placement-dates/` (files `idea.md`, `1. spec.md`, `2. plan.md`, `research_*`, `3. frontend_qa.md`, `qa_report.md`, `upgrade_notes.md`). ## 3. Here: moved children and left-behind collection items

- Built in `spec_dd/3. done/2026-10-25_17:46_deadlines-1-dates-and-overdue/` (`2. plan.md` ~line 1300: "Move deadline override rows from a child's stale collection item to the one a load just..."; ~line 1335: the one-new-one-stale case moves both override models' rows; a file with two collection items is a different case). The code is `freedom_ls/content_engine/moved_children.py`, with `deadlines/signals.py` `carry_over_deadline_overrides`.
- Rule as recorded in deadlines-8 `research_prior_art.md` line 13: when a load creates a new collection item for a child that has exactly one stale sibling in the course, deadline overrides move to it. The stale row stays.
- `moved_children.py` docstring: "A sync never removes the row a moved child left behind". `research_content_loader.md` (this spec's research, section 1) confirms the loader never deletes collection items and that move detection is course-rooted (`viewable_collection_items`), so it never sees a reference-only part.
- `spec_dd/1. next/sacaa-compliance-content-versions-and-access-2-retire-removed-content/idea.md` (open item "`ContentCollectionItem` left-behind rows", line 35) restates it: "A sync today never removes the row a moved child left behind, and a dropped child's row stays." Its recommendation: a collection item whose child is retired is skipped when outlines are read, the row itself gets no retired state, and a collection item left behind by a move to another collection "keeps its present behaviour". That spec retires file-sourced content rows rather than deleting ("Never deleted", line 19; "Deleting content ... out of scope", line 45) and lists `ContentCollectionItem` as "derived, not authored" (line 18). The roadmap names it as a collision with `reference-material-content-1-authoring` (`spec_dd/1. next/roadmap.md` line 175).

## 4. Here: decisions about deleting collection items

- `spec_dd/3. done/2026-08-28_14:19_better-course-progress-tracking/decision.md` section 3 (lines ~204-217): `content_save` creates placements with `update_or_create` keyed on `(site, collection_type, collection_id, child_type, child_id)`; "It never sweeps stale items, so a placement disappears only by deliberate act." Consequence recorded: `TopicProgress.collection_item` and related FKs use `SET_NULL`, so a deleted placement keeps the completion record ("an audit answer that must survive a content edit"). Also said: cascade-deleting would be "a genuine data-loss problem" (per `research_shared_content_across_courses.md` in the same directory).
- The same spec's seam QA (`3a. seam_qa/qa_report.md` ~lines 419-424, finding "SET_NULL placement asymmetry"): deleting a collection item that has answered work behind it is permitted and silently nulls the attempt's `collection_item`; the admin's delete confirmation lists only the collection item, not the attempts. Deleting the Form, Topic, registration or Cohort behind the same work is refused (PROTECT). Marked as intentional (`null=True`) but "an author removing a placement quietly detaches real attempts from their position in the course".
- `spec_dd/3. done/2026-08-28_14:19_better-course-progress-tracking/idea.md` line ~203 notes deleting a collection item needs an explicit decision about what it means for progress.
- So the `reference:` cleanup (delete the part placement, its deadline overrides and `CoursePartChildDueDate` rows) is the first automatic collection item deletion by `content_save`. Earlier specs either avoided deleting or deferred it. Whether progress rows (`TopicProgress.collection_item`, `CourseFormAttempt.collection_item`) point at the part's own topic collection items or at the course-to-part item is not checked here; those FKs are `SET_NULL` per `decision.md`.
- Also recorded: `spec_dd/1. next/learner-interface-features/research_question_model.md` line 35 found no code in `content_save` that deletes a question or option dropped from a file (`QuestionAnswer.question` is PROTECT). `spec_dd/3. done/2026-09-13_19:39_cache-optimised-images/research_content_save_integration.md` line ~319 records that `content_save` accepts orphaned objects nothing points at. The loader's whole history is additive; this spec's `CourseReferencePart` replace semantics follow `course.categories.set`, `organisations.set` and the `CoursePartChildDueDate` delete-not-kept pass.

## 5. Elsewhere: optional or supplementary content and what went wrong

Search coverage was thin (two searches). Items below are what the sources say; where no source was found it is stated.

- Moodle: the "My courses" progress percentage tracks activity completion, not course completion criteria; teachers who want a less important activity out of the percentage must turn its completion tracking off. A feature request asks that the percentage follow the course completion criteria. The Completion Progress block and the "Restriction by course progress" plugin use all activities with completion criteria, not the course completion setting. With conditional activities the block shows the percentage of available activities only, which a user called "not the correct percentage at all". The sources do not establish how current Moodle versions treat optional activities in every case. Sources: https://docs.moodle.org/503/en/Course_completion_tracking ; https://docs.moodle.org/503/en/Course_completion_settings ; https://moodle.org/plugins/block_completion_progress ; https://moodle.org/plugins/availability_courseprogress ; https://tracker-old.moodle.org/browse/MDL-67750 ; https://openedx.atlassian.net/wiki/spaces/OEPM/pages/3902931201/Moodle+-+Learner+Progress+Tracking
- Canvas: module requirements are per item with an "all items" or "one item" rule. Reported gaps are completion not honoured for indented items, LTI items never reporting completion, and modules showing completed while a required quiz was locked. No source found states how optional items are excluded from module completion. Sources: https://community.canvaslms.com/t5/Archived-Questions/ARCHIVED-quot-Complete-All-Items-quot-is-not-working/m-p/464806 ; https://community.canvaslms.com/t5/Canvas-Question-Forum/Module-with-a-required-quiz-shows-as-completed-while-the-quiz-is/m-p/545139 ; https://developerdocs.instructure.com/services/canvas/resources/modules
- Canvas overdue marks on work that is done or not required: a paper-submitted assignment stays overdue after scoring (Canvas ideas thread, https://community.canvaslms.com/t5/Canvas-Ideas/Assignments-Student-Submitting-on-Paper-to-an-Online-Assignment/m-p/544984), cited in `spec_dd/3. done/2026-10-25_17:46_deadlines-1-dates-and-overdue/research_known_complaints.md` item 9. Rated Low-Medium there; the not-required case: "none found, design judgement".
- Stale rows after content import in other LMSs: `spec_dd/1. next/sacaa-compliance-content-versions-and-access/research_question_versioning_prior_art.md` (cited by the retire spec) says "all surveyed imports are additive" and Moodle hides while Questionmark retires. That file was not read in full here. No external source was found on stale placement rows after import specifically.
