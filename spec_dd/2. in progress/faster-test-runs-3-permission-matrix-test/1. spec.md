# Spec: the permission matrix test builds its world once

Idea: `idea.md`. Answers: `answers.md`. Research: `research_*.md` beside this file.

## Purpose

`freedom_ls/educator_interface/tests/invariants/test_permission_matrix.py` collects 802 tests. 790
of them call `_build_world`, which creates two sites, three organisations, four cohorts, four
learners, ten password-hashed users and six role grants, so the same world is built 790 times.
`test_can_matches_the_matrix` (696 cases) and
`test_deactivating_the_staff_member_row_withdraws_the_grant` (67 cases) take most of that time.
After this work each world-building test builds one world and checks many cells against it. The
same cells are checked, and a failure names the cell that disagreed.

## Scope

In:

- Every test in `test_permission_matrix.py` that calls `_build_world`.
- A before-and-after measurement of the file, recorded beside this spec.

Out:

- `MATRIX`, `CAPABILITY_SCOPE_KINDS`, `RELATIONS_FOR_KIND`, `ROLES`, `GATED_ROLES` and every
  permission rule. The walk reads these tables unchanged.
- `_build_world` itself: what it builds stays the same.
- Tests in the file that do not build a world: `test_every_capability_a_role_holds_has_a_matrix_entry`,
  `test_every_matrix_entry_names_every_role`,
  `test_a_roles_permissions_equal_the_capabilities_its_matrix_column_allows`, the three
  `walk_interface` tests and `test_assign_cohort_viewer_is_in_the_matrix`.
- Other slow tests, including `scenario_world.build_world` users
  (`faster-test-runs-6-prune-slow-tests`), and the test hasher
  (`faster-test-runs-1-fast-password-hasher`).

## Decisions

- **One world per test, inside pytest-django's per-test transaction.** No module- or
  session-scoped database fixture. `answers.md` chose rollback per test, and the repo's one
  cross-test precedent (`freedom_ls/tests/demo_content_fixtures.py`) needs a manual flush.
- **The matrix walk is parametrized by capability** (30 tests), so `-k <codename>` still re-runs
  one capability. A single test over every capability would build one world but lose that.
- **The deactivation walk is parametrized by gated role** (5 tests), not by capability. Every gated
  cell of a role depends on that role's single `StaffMember` row, so one deactivate and reactivate
  per role checks all of that role's cells.
- **Mismatches are collected, never asserted cell by cell.** The test checks every cell, then fails
  once with the full list. The list is built by hand; no `pytest-check` or subtests.
- **The two tests that change shared data keep a world of their own.**
  `test_cohort_admin_holds_add_cohortmembership_on_another_cohort_only_with_a_grant_there` grants
  cohort_admin on C2, which would flip `(cohort, other_cohort)` cells.
  `test_the_cohort_import_gate_refuses_an_inactive_cohort` deactivates C1, which
  `check_import_gate` reads. Both stay one-case tests, as does the read-only
  `test_cohort_admin_holds_delete_cohortmembership_on_its_own_cohort`.

## Requirements

All changes are in `freedom_ls/educator_interface/tests/invariants/test_permission_matrix.py`.

### The matrix walk

`test_can_matches_the_matrix` is parametrized over the keys of `CAPABILITY_SCOPE_KINDS`, with each
test id the capability's codename (the part after the dot, e.g. `view_cohort`). Each test:

1. Builds one world with `_build_world(mock_site_context)`.
2. Walks every `(role, kind, relation)` that `_cases()` yields for its capability, comparing
   `can(user, capability, scope) is expected`, where `expected` is
   `(kind, relation) in MATRIX[capability][role]`. Identity on `bool` stays, so a truthy non-bool
   return still fails.
3. Asserts the cells it walked equal the cells `_cases()` yields for that capability. This keeps the
   walk tied to `_cases()`, so a future row or role cannot be skipped silently.
4. Fails once if any cell disagreed, with the report described under "The failure report".

### The deactivation walk

`test_deactivating_the_staff_member_row_withdraws_the_grant` is parametrized over `GATED_ROLES`.
Each test builds one world and takes that role's cells from `_gated_true_cases()`. It then:

1. checks that `can()` is `True` for every one of those cells and snapshots the role's
   `ObjectRoleAssignment` rows and, per scope, `get_perms(user, scope)`;
2. deactivates the role's `StaffMember` row and checks that every cell is `False` and both
   snapshots are unchanged;
3. reactivates the row and checks that every cell is `True` again and both snapshots are unchanged.

Reactivation runs in a `finally`, so a failure in step 2 cannot affect step 3's report. Each step
collects its mismatches the same way the matrix walk does. A test that fails reports every
mismatch from every step it reached.

`can()` holds no per-user or per-request cache (`learner_management/capabilities.py`), and
`get_perms` builds a fresh checker per call, so the same user and scope objects are reused across
steps. The plan confirms the `get_perms` behaviour against the installed django-guardian.

### The role walks

These four tests lose their `role` parametrization. Each builds one world and loops over `ROLES`
inside the test, collecting mismatches:

- `test_cohorts_visible_to_agrees_with_can_on_every_cohort`
- `test_learners_visible_to_agrees_with_can_on_every_learner`
- `test_the_organisation_import_gate_needs_bulk_manage_learners_and_add_learner`
- `test_the_cohort_import_gate_needs_add_learner_and_add_cohortmembership`

The expected value for each role is computed from `MATRIX` exactly as now.

### The failure report

One helper builds the report that every walk in the file uses. The report is the assertion
message, so pytest prints it without a traceback into the loop (`pytest.fail(report,
pytrace=False)`):

```
3 of 24 cells disagree for freedom_ls_learner_management.view_cohort
capability=freedom_ls_learner_management.view_cohort role=cohort_admin kind=cohort relation=other_cohort expected=False actual=True
...
```

- The first line gives the disagreeing count, the walked count and what was walked (a capability,
  a role, or the test's subject).
- Each following line holds one cell as `key=value` pairs: every coordinate the cell has
  (capability, role, kind, relation), the expected value and the actual value. A deactivation-walk
  line also names its step.
- Lines are sorted, so two runs of the same failure print the same report.
- An exception raised while checking a cell is not caught for the report. It fails the test, with
  the cell's coordinates added to the exception as a note (`add_note`) before it is re-raised.

## Testing

- **The new walks fail when they should.** Temporarily flip one `MATRIX` entry and one
  `GATED_ROLES` cell locally. The matching walk must fail and name that cell. This is not
  committed.
- **Coverage is unchanged.** Before the change, record the `(capability, role, kind, relation)` of
  every collected `test_can_matches_the_matrix` and `test_deactivating_…` case. After the change,
  record every cell the walks visit. The two sets must be equal: 696 and 67 cells. Both lists'
  counts and the equality go into `measurements.md`.
- **Each walk stays independent.** The file passes under `pytest-randomly`'s random order and under
  `-p no:randomly`.
- The other tests in the file pass unchanged.

## Measurement

Run on this branch before the change and after it, from the worktree root:

```
uv run pytest freedom_ls/educator_interface/tests/invariants/test_permission_matrix.py -n 0 -p no:randomly --durations=0 --durations-min=0 -q
uv run pytest freedom_ls/educator_interface/tests/invariants/test_permission_matrix.py --collect-only -q
```

Record in `measurements.md` beside this spec: the test count, the summed setup and call time
(test-body time, which leaves out test-database creation), the wall time, and the password hasher
in effect. Compare the before figure with `spec_dd/1. next/faster-test-runs/research_test_timings.md`
("Largest parametrized tests"). If `faster-test-runs-1-fast-password-hasher` has landed on main by
the time this branch measures, take the before and after with its hasher.

## Success criteria

- `--collect-only` reports 54 tests in the file: 30 matrix walks, 5 deactivation walks, 4 role
  walks, the 3 one-case world tests and the 12 non-world tests that stay as they are.
- `measurements.md` shows the before and after cell sets are equal (696 matrix cells and 67
  deactivation cells).
- With one `MATRIX` entry flipped locally, the matching walk fails with a report naming that cell's
  capability, role, kind, relation, expected and actual values.
- `measurements.md` records test-body time before and after; after is at most one tenth of before.
- `uv run pytest` on the file passes in random order.
