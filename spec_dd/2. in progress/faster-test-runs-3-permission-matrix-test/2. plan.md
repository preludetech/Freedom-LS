### Why the walks loop

`ds:testing` asks for tests with no `for`, `if` or `try` in their bodies, tests that call the code
under test once and test one behaviour each, and one parametrized test for one generic check over
many inputs. The walks depart from the last three on purpose: every cell pays for building a world,
and the world, not the check, is the cost. A walk still tests one behaviour, the agreement of one
capability (or role, or gate) with `MATRIX`, and names every cell that disagrees. A module- or
session-scoped world fixture, the skill's other route, is ruled out: pytest-django rolls back per
test, and the deactivation walk changes data. The walks keep the first rule: every loop, branch and
`try` sits in a module-level walk helper, and each test body is straight-line (build the world, run
the helper, report). Each helper's docstring says why it walks instead of parametrizing.

The `except Exception` in `_naming_the_cell` departs from the project's "catch specific exceptions"
rule. It re-raises everything it catches, so nothing is swallowed, and its comment says so.

## The shared pieces

These land in Slice 1 and every later walk uses them. Put them after `_cases()` and before the
first test.

```python
class _Walk:
    """Every disagreement a walk finds, kept so one failing cell does not hide the rest.

    A walk checks many cells against one world because building the world costs far more than
    any one check.
    """

    def __init__(self, subject: str) -> None:
        self.subject = subject
        self.checked = 0
        self.mismatches: list[str] = []

    def check(
        self,
        expected: Callable[[], object],
        actual: Callable[[], object],
        *,
        same: Callable[[object, object], bool] = operator.is_,
        **coordinates: str,
    ) -> None:
        """Check one cell and keep any disagreement.

        Both sides are computed under the cell's name, so an error from either one
        names the cell. `same` defaults to identity, which makes a truthy non-bool
        answer fail where True is expected.
        """
        with _naming_the_cell(**coordinates):
            expected_value = expected()
            actual_value = actual()
        self.checked += 1
        if not same(actual_value, expected_value):
            self.mismatches.append(
                _cell_line(
                    **coordinates, expected=str(expected_value), actual=str(actual_value)
                )
            )

    def report(self) -> None:
        """Fail with every mismatch, sorted so the same failure always prints the same report."""
        if not self.mismatches:
            return
        lines = sorted(self.mismatches)
        header = f"{len(lines)} of {self.checked} cells disagree for {self.subject}"
        pytest.fail("\n".join([header, *lines]), pytrace=False)


def _cell_line(**pairs: str) -> str:
    return " ".join(f"{key}={value}" for key, value in pairs.items())


@contextmanager
def _naming_the_cell(**coordinates: str) -> Iterator[None]:
    """An error raised while checking a cell still fails the test, now naming the cell."""
    try:
        yield
    # Broad on purpose: this only adds the cell's coordinates to whatever was raised and
    # re-raises it, so nothing is swallowed. It is the only broad catch in this file.
    except Exception as error:
        error.add_note(_cell_line(**coordinates))
        raise
```

```python
def _always(value: object) -> Callable[[], object]:
    """A side of a check that is already known, such as a step's expected answer."""
    return lambda: value


def _matrix_allows(capability: str, role: str, kind: str, relation: str) -> bool:
    return (kind, relation) in MATRIX[capability][role]
```

Imports to add: `import operator`, `from collections.abc import Callable, Iterator`,
`from contextlib import contextmanager` and `from functools import partial`.

Every walk calls `walk.check(...)` once per cell, so the coordinates are written once. Callers build
both sides with `partial(...)` or `_always(...)`, never a lambda inside the loop: ruff's
flake8-bugbear rules are on, and B023 flags a lambda that closes over a loop variable. `can()` and
the gates use the default identity comparison; snapshots pass `same=operator.eq` and are given as
sorted lists so the report prints in a stable order. `checked` counts every comparison the walk
made, which for the matrix walk is its cell count.

Do not add a separate test for `_Walk`: the success criterion fixes the file at 54 tests. The
deliberate-failure checks in Slices 1 and 2 prove the report.

1. Keep `_gated_true_cases()` unchanged. Add the walk helper:

   ```python
   def _walk_deactivation(world: World, role: str) -> _Walk:
       """The StaffMember gate, one role at a time.

       Every gated cell of a role hangs off that role's single StaffMember row, so one
       deactivate and reactivate checks all of them both ways.

       All three steps share one world on purpose: the row each step reads is the
       one the step before changed.
       """
       walk = _Walk(f"role {role}")
       user = world.users[role]
       cells = [
           (capability, kind, relation)
           for capability, cell_role, kind, relation in _gated_true_cases()
           if cell_role == role
       ]
       scopes = {(kind, relation): world.scopes[(kind, relation)] for _, kind, relation in cells}
       member = StaffMember.objects.get(user=user)

       _check_gated_cells(walk, "active", True, user, role, cells, world)
       before = _Snapshots.take(user, scopes)

       member.is_active = False
       member.save(update_fields=["is_active"])
       try:
           _check_gated_cells(walk, "deactivated", False, user, role, cells, world)
           _check_snapshots(walk, "deactivated", role, before, _Snapshots.take(user, scopes))
       finally:
           member.is_active = True
           member.save(update_fields=["is_active"])
       _check_gated_cells(walk, "reactivated", True, user, role, cells, world)
       _check_snapshots(walk, "reactivated", role, before, _Snapshots.take(user, scopes))
       return walk


   class _Snapshots(NamedTuple):
       """What deactivating a StaffMember row must never touch."""

       assignments: list[tuple[int, int, int, str, str, bool]]
       guardian: dict[tuple[str, str], list[str]]

       @classmethod
       def take(cls, user: AbstractBaseUser, scopes: dict[tuple[str, str], Model]) -> _Snapshots:
           return cls(
               assignments=sorted(
                   (a.user_id, a.site_id, a.content_type_id, a.object_id, a.role, a.is_active)
                   for a in ObjectRoleAssignment.objects.filter(user=user)
               ),
               guardian={key: sorted(get_perms(user, scope)) for key, scope in scopes.items()},
           )


   def _check_gated_cells(
       walk: _Walk,
       step: str,
       expected: bool,
       user: AbstractBaseUser,
       role: str,
       cells: list[tuple[str, str, str]],
       world: World,
   ) -> None:
       for capability, kind, relation in cells:
           walk.check(
               _always(expected),
               partial(can, user, capability, world.scopes[(kind, relation)]),
               step=step, capability=capability, role=role, kind=kind, relation=relation,
           )


   def _check_snapshots(
       walk: _Walk, step: str, role: str, before: _Snapshots, now: _Snapshots
   ) -> None:
       walk.check(
           _always(before.assignments), _always(now.assignments), same=operator.eq,
           step=step, role=role, snapshot="assignments",
       )
       for (kind, relation), perms in before.guardian.items():
           walk.check(
               _always(perms), _always(now.guardian[(kind, relation)]), same=operator.eq,
               step=step, role=role, snapshot="guardian", kind=kind, relation=relation,
           )
   ```

   Every step runs even when an earlier one found mismatches, because `check` only raises when
   the code under test raises. The `step=` coordinate comes first on every line from this walk,
   so the report names its step. The assignment tuple and its type are the ones the current
   `_assignment_snapshot` builds, kept as is. Group the seven arguments of `_check_gated_cells`
   into a small `NamedTuple` if it reads more simply.
