# Plan: staff roles per cohort

Spec: `1. spec.md`. Research: `research_codebase.md` (the survey every slice below starts from).

This plan is implementation only. The glossary rows, the brand-guidelines placement note, the
audit-log README row, the product doc and the upgrade notes are written after implementation by
the documentation hooks and the `todo.md` items beside this plan.

There is no `design.md` for this spec, so there is no Design section.

## Conventions for every slice

- TDD: each slice names its tests; write the failing test, then the change. One behaviour per
  test; parametrise only where the assertion shape is identical (`ds:testing`).
- Tests touching a site-aware model take `mock_site_context` and never set `site` by hand.
  Grant object permissions in tests with `guardian.shortcuts.assign_perm(codename, user, obj)`;
  use `assign_object_role` (or `assign_role` for the checked entry points) only where access
  resolves through role assignments, as `organisations_accessible_to`, the staff-role views and
  the `role_based_permissions` and `role_assignment` tests do (`fls-dev:testing`). Every test in
  this plan is of that second kind. Assert `aria-*`, `role`, `hx-*`, `href`, `data-*` and status
  codes, not CSS classes; assert a refusal by its status and by the message looked up from
  `REFUSAL_MESSAGES`, not by a copy literal, except where the spec makes the text the feature
  (the cohort admin's one 422 message, compared across responses). A new test module mirrors its
  source module and lives beside the module's other tests.
- Skills: `ds:testing` and `fls-dev:testing` for every pytest file; `ds:playwright-tests` and
  `fls-dev:playwright-tests` for every browser test; `ds:template` and `fls-dev:template` for
  every template; `ds:htmx` for every HTMX response (422 for a validation refusal, `hx-target`
  with `hx-swap`, the global CSRF header); `ds:alpine-js` and `fls-dev:alpine-js` for every Alpine
  change (the CSP build is on: components registered with `Alpine.data`, no inline expressions,
  values passed through `data-*`, `x-cloak` and `x-transition` on anything hidden by default,
  listeners declared with `x-on:` so none outlives the component); `fls-dev:icon-usage` for any
  icon; `fls-dev:panel-framework` for every trigger, cell, dialog and Settings-tab change;
  `ds:code-comments` and `sdd:planning-references-in-code` for every comment and test name;
  `fls-dev:domain-glossary` and `brand-guidelines` for every new identifier and every string a
  person reads; `productivity:unslop` on every new string. Slices that need more name them.
- After any model change: `uv run manage.py makemigrations` then `uv run manage.py migrate`.
  Never edit an existing migration. Run `uv run manage.py sync_role_permissions` after slice 1 so
  the dev database has the new permissions.
- After any change to a panel template run
  `uv run pytest freedom_ls/panel_framework/tests/invariants/test_templates.py`.
- Run `npm run tailwind_build` whenever a slice adds a Tailwind class to a template.
- At the end of every slice run the suites the slice touches, Playwright included:

  ```
  uv run pytest freedom_ls/role_based_permissions freedom_ls/learner_management freedom_ls/educator_interface freedom_ls/panel_framework freedom_ls/audit_log freedom_ls/accounts
  ```

- Commit with plain `git commit`.

> **Assumed default:** the Dashboard, Learners, Cohorts and Courses sections, whose
> `view_capability` is `None`, gain a gate in `OrganisationSectionConfig.is_visible`: a section
> with no `view_capability` is visible only when the viewer holds `view_cohort` on the
> organisation or on one of its cohorts (`can_on_any`). Why: today "can enter the organisation"
> is the only gate on those sections, so letting the viewer roles through
> `organisations_accessible_to` would open the Dashboard to them, against the spec's "the Staff
> section is the only section they can open"; every existing staff role holds `view_cohort`
> somewhere in the organisation, so nothing they see changes. To change: slice 2.

> **Assumed default:** the Roles column header stays for a names-only viewer and its cells
> render empty. Why: `DataTable.get_columns` is a request-free static method, so hiding a column
> per viewer would be a panel-framework change the spec does not ask for; the viewer still sees
> names and no roles. To change: slice 2.

> **Assumed default:** slice 1 is large: both viewer roles, four permissions, two migrations,
> the `ORGANISATION_ROLES` sweep and the permission-matrix rows land together. Why: adding a role
> to `STAFF_ROLES` without the sweep makes `staff_role_entries` raise on its first organisation
> assignment, and the matrix's invariant tests fail the moment a role or permission exists
> without its rows, so the pieces cannot be committed apart with the suite green. To change:
> slice 1.

- `queries.py` `staff_of`:

  ```python
  def staff_of(organisation: Organisation) -> QuerySet[User]:
      """Everyone on the organisation's staff: the users with a StaffMember
      row here, active or not, together with everyone holding a staff role
      here. Inactive accounts stay listed; they still hold the row or the
      role. A site admin or superuser is here only through a row or a role,
      never through their site-level access. _base_manager, because the
      organisation handled is not always the Site the current request is for,
      and the site-aware manager would hide its rows."""
      from freedom_ls.accounts.models import User

      members = StaffMember._base_manager.filter(organisation=organisation)
      return User.objects.filter(
          Q(pk__in=members.values("user_id"))
          | Q(pk__in=staff_assignments(organisation).values("user_id"))
      ).order_by("first_name", "last_name", "email", "pk")
  ```

  ```python
          cohort = cast(Cohort, ctx.instance)
          user = _staff_member_param(ctx)  # 404 outside staff_of(organisation)
          role = _action_params(ctx.request).get("role", "")
          if role_target(role) != "cohort" or role not in STAFF_ROLES:
              raise Http404("Not a cohort role")
          return get_object_or_404(
              _active_role_assignments(Cohort, frozenset({role})).select_related("user"),
              user=user,
              object_id=str(cohort.pk),
          )
  ```

  ```python
  MIN_TERM_LENGTH = 2


  def term_condition(term: str, *, include_email: bool) -> Q:
      """Every word of `term` must match a first name, last name or, when
      asked, the email, so "Jane Smith" finds Jane Smith. No words means
      no narrowing."""
      condition = Q()
      for word in term.split():
          word_condition = Q(first_name__icontains=word) | Q(last_name__icontains=word)
          if include_email:
              word_condition |= Q(email__icontains=word)
          condition &= word_condition
      return condition
  ```
