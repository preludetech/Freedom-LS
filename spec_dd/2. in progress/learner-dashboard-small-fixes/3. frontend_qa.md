# Frontend QA: learner dashboard small fixes

Two changes to the learner dashboard. A coming-soon course whose dashboard category is shown on the
dashboard now appears in **both** that category's section and **Coming soon**, interleaved
alphabetically. **Recommended courses** and **Coming soon** now carry the **Browse all courses**
button that every category section and **Available courses** already had.

Both changes widen what renders, so the interesting failures are things rendering too much: a course
appearing three times, a coming-soon course leaking into **Available courses**, the visibility
preview quietly starting to duplicate cards, or the button turning up on **In progress** and
**Learning history**, where it does not belong. This run checks the new behaviour and then goes
looking for each of those.

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever
this document writes `<PORT>`. Shell variables do not survive between tool calls.

---

## §0 Setup

### 0.1 Server

1. `.claude/ds/scripts/find_available_port.sh` — note the number and use it literally from here on.
2. Start `uv run python manage.py runserver <PORT>` backgrounded, as its own call.
3. Open `http://127.0.0.1:<PORT>/` and confirm `#debug-branch-badge` names the
   `learner-dashboard-small-fixes` branch. If it names another branch, another server holds the
   port; go back to step 1.

### 0.2 Seed data

Every item below must exist before §1. Missing data is created through the `fls-dev:qa-data-helper`
agent, never by hand. Every course needs one viewable topic so its card and detail page resolve, and
every one of these courses must have **no** registration and **no** `RecommendedCourse` row for any
persona used below — a registered or recommended course is excluded from the discovery sections
entirely, which would hide exactly what this run is checking.

Every seed below names its slug, and every seed is keyed on that slug plus the site, so a second run
of this plan updates the existing rows rather than minting a second "QA Soon Mix" category or a
second "Mix Bravo". None of these slugs collide with the demo content or with the fixtures
`qa_create_course_visibility` and `qa_create_dashboard_paging_fixtures` already seed.

1. **Demo content loaded.** `uv run python manage.py content_save demo_content DemoDev`. This gives
   the three demo categories: `start-here-demo` ("Start here"), `assessment-demo` ("Assessment") and
   `reference-demo` ("Reference", `show_on_dashboard=False`).
2. **Superuser:** `demodev@email.com` from `.claude/fls-dev/config.md`.
3. **Rich learner:** `uv run python manage.py qa_create_rich_dashboard_learner` — creates
   `demodev_s1@email.com` (password equal to the email) with **In progress**, **Learning history**
   and **Recommended courses** all populated. This is the persona for most of the run.
4. **Seed MIX — a shown category mixing published and coming-soon courses.** A `CourseCategory`
   titled "QA Soon Mix", slug `qa-soon-mix`, `show_on_dashboard=True`, with an `order` high enough
   that it sorts after the demo categories (`order=50`). Four courses, all with `dashboard_category`
   set to it:
   - "Mix Alpha", slug `qa-mix-alpha` — published
   - "Mix Bravo", slug `qa-mix-bravo` — `visibility=coming_soon`
   - "Mix Charlie", slug `qa-mix-charlie` — published
   - "Mix Delta", slug `qa-mix-delta` — published

   The titles matter: the section sorts alphabetically, so the coming-soon course must land second,
   in the middle of page one, not at either end. Four courses also means the section pages at
   `SECTION_PAGE_SIZE` (3), which §5 needs.
5. **Seed UNCAT — "Soon Uncategorised"**, slug `qa-soon-uncategorised`, `visibility=coming_soon`,
   **no** `dashboard_category` and no `categories` rows at all.
6. **Seed HIDDEN — "Soon Hidden"**, slug `qa-soon-hidden`, `visibility=coming_soon`,
   `dashboard_category` set to the `reference-demo` category (the one with
   `show_on_dashboard=False`).
7. **Seed ONLY — a category holding nothing but a coming-soon course.** A `CourseCategory` titled
   "QA Soon Only", slug `qa-soon-only`, `show_on_dashboard=True`, `order=0` so it sorts **first** of
   every shown category. Exactly one course, "Soon Only One", slug `qa-soon-only-one`,
   `visibility=coming_soon`, `dashboard_category` set to it. If a previous run of this plan left
   this category's `order` at `60` (see §4), reset it to `0` before starting.
8. Confirm `config/settings_dev.py` has `OVERRIDE_COURSE_VISIBILITY_TO_VISIBLE = False`. §7 flips it
   and puts it back; if a previous run left it `True`, nothing below §7 will behave as described.

Coming soon will therefore hold four courses — Mix Bravo, Soon Uncategorised, Soon Hidden, Soon Only
One — plus whatever the visibility QA fixtures already contribute. That is enough to page.

## §1 A coming-soon course renders in its category **and** in Coming soon

Sign in as `demodev_s1@email.com` and open `http://127.0.0.1:<PORT>/dashboard/`.

1. Find the **QA Soon Mix** section. Expect three cards on page one, in this order left to right:
   **Mix Alpha**, **Mix Bravo**, **Mix Charlie**. This is the whole first fix — Mix Bravo sits in
   its alphabetical place among the published courses, not bunched at the start or the end.
2. Scroll to the **Coming soon** section. Expect **Mix Bravo** to appear there as well.
3. Count Mix Bravo's cards across the whole page. Expect exactly **two** — one in QA Soon Mix, one in
   Coming soon. Not three, not one.
4. Confirm no other course on the page appears twice. Mix Alpha, Mix Charlie and Mix Delta are
   published, so each renders once.

**Failure to watch for:** Mix Bravo appearing first or last in QA Soon Mix rather than second. That
means the two halves of the pool were concatenated in Python instead of merged into one ordered
queryset, and the alphabetical interleave is broken even though the card is in the right section.

## §2 The repeated card explains itself

Still on the dashboard as `demodev_s1@email.com`.

1. Look at **Mix Bravo's card inside the QA Soon Mix section** — the one sitting between two
   ordinary published cards. Expect:
   - a **Coming soon** label with its icon, exactly as the copy in the Coming soon section carries;
   - **no** enrol, apply, register or "I'm interested" control;
   - **no** "Free" or "By application" access badge (the coming-soon label takes that slot);
   - a **Details** link.
2. Compare it against Mix Bravo's card in the **Coming soon** section. The two cards should be
   identical in content — the section a card sits in changes nothing about the card.
3. Click Mix Bravo's **title** in the QA Soon Mix section. Expect the Mix Bravo course detail page.
   Go back, then click its **Details** link from the Coming soon section. Expect the same page.
4. On that detail page, expect the coming-soon acquisition copy and the **I'm interested** control —
   the express-interest affordance lives here, not on either card.
5. Look at Mix Alpha's card in the same section for contrast. Expect an ordinary published card with
   its access badge and its normal call to action, sitting next to the coming-soon one without
   picking up any coming-soon styling.

## §3 No course renders three times

This is the side-effect check. **Available courses** is the catch-all for courses with no dashboard
category or a hidden one, and a coming-soon course must never fall into it.

1. On the dashboard, find **Available courses**. Expect **Soon Uncategorised** to be **absent** from
   it, and **Soon Hidden** to be **absent** from it.
2. Find **Coming soon**. Expect **Soon Uncategorised** and **Soon Hidden** both present there. Page
   through Coming soon if they are not on page one — it holds four or more courses.
3. Confirm there is **no dashboard section headed "Reference"** anywhere on the page. That category
   is `show_on_dashboard=False`; giving it a section would be a new bug.
4. Count Soon Uncategorised's cards on the page: expect exactly **one**. Same for Soon Hidden.

**Failure to watch for:** either of these two showing up in Available courses. That is the third
rendering the change was specifically shaped to prevent.

## §4 A category of only coming-soon courses now renders, and can lead the page

1. On the dashboard, expect a section headed **QA Soon Only** containing the single card **Soon Only
   One**. Before this change that category rendered no section at all.
2. Check where it sits. Its `order` is `0`, so expect it **above Recommended courses** — it is the
   page's headline group, holding one course nobody can start yet. This is the accepted consequence
   of the change, not a bug: a site controls it through `CourseCategory.order`.
3. Expect **Soon Only One** to also appear in **Coming soon**, for two cards in total.
4. Ask the `fls-dev:qa-data-helper` agent to raise the QA Soon Only category's `order` to `60`,
   reload the dashboard, and confirm the section has moved below **Recommended courses** and that
   some other category now leads. This proves the ordering is the site's to control.
5. Ask the agent to set that `order` back to `0` and reload, confirming the section leads again.
   **Do not leave it at 60** — §8 and any re-run of §1-§4 assume it is back at `0`.

## §5 Two sections holding the same course page independently

**QA Soon Mix** holds four courses and pages at three; **Coming soon** holds four or more and pages
too. Mix Bravo is in both.

1. On the dashboard, note which page of each section Mix Bravo is on.
2. Click **next** on the **QA Soon Mix** section's pagination. Expect only that section's cards to
   change — the page does not reload, Coming soon keeps the page it was on, and the URL gains
   `page_qa-soon-mix` while no other section's page parameter appears.
3. Now click **next** on **Coming soon**. Expect the URL to carry **both** sections' page parameters
   and both sections to hold their own positions. Neither section's paging moves the other.
4. Reload the page with that full query string. Expect both sections to come back on the pages the
   parameters name.
5. Hand-edit the query string to `?page_qa-soon-mix=99&page_coming-soon=0` and reload. Expect no
   error page: the too-high number clamps to the last page and the zero clamps to page one.

## §6 Browse all courses on Recommended courses and Coming soon

Still signed in as `demodev_s1@email.com`, whose dashboard has all six kinds of section.

1. **Recommended courses** — expect a **Browse all courses** button in its header row, beside the
   pagination. This is new.
2. **Coming soon** — expect the same button. Also new.
3. **QA Soon Mix** (a category section) and **Available courses** — expect the button, unchanged
   from before.
4. **In progress** — expect **no** Browse all courses button. It holds the learner's own courses.
5. **Learning history** — expect **no** button either.
6. Click the button under **Coming soon**. Expect the full course catalogue page, showing every
   course, unfiltered — not a catalogue pre-filtered to coming-soon courses. Coming-soon courses
   appear in that list badged "Coming soon", as plain links to their detail pages.
7. Go back, click the button under **Recommended courses**, and confirm it lands on the same
   unfiltered catalogue page.
8. Confirm the wording and styling match the existing buttons: same "Browse all courses" text, same
   link treatment, same arrow icon, sitting in the same place in the header row.

## §7 The visibility preview still shows each course exactly once

This is the regression the change most easily breaks. With the preview on, nothing is coming soon,
so nothing should duplicate.

1. Set `OVERRIDE_COURSE_VISIBILITY_TO_VISIBLE = True` in `config/settings_dev.py` and let the dev
   server reload.
2. Reload the dashboard as `demodev_s1@email.com`. Expect:
   - **no Coming soon section at all** on the page;
   - **Mix Bravo** present in **QA Soon Mix**, exactly **once**, still in its alphabetical place
     between Mix Alpha and Mix Charlie;
   - **Soon Uncategorised** present in **Available courses**, exactly once;
   - **Soon Hidden** present in **Available courses**, exactly once;
   - **Soon Only One** present in the **QA Soon Only** section, exactly once;
   - no "Coming soon" label on any card anywhere.
3. Confirm no course on the page renders twice.
4. Set `OVERRIDE_COURSE_VISIBILITY_TO_VISIBLE` back to `False` and reload. Expect §1's picture back:
   Coming soon returns and Mix Bravo is in two places again. **Do not leave the setting on** — every
   section below assumes it is off.

## §8 Anonymous visitor

Sign out, or use a private window, and open `http://127.0.0.1:<PORT>/dashboard/`.

1. Expect the category sections, **Available courses** and **Coming soon** to render, and **In
   progress** and **Learning history** to be absent.
2. Expect **Mix Bravo** in both QA Soon Mix and Coming soon, as in §1 — the duplication is not
   login-gated.
3. Expect **Browse all courses** under **Coming soon**.
4. Expect Mix Bravo's card to carry the **Coming soon** label rather than a "Free" access badge. An
   anonymous visitor sees access badges on published cards; a coming-soon card must still show the
   coming-soon label instead.

## §9 Adversarial and failure branches

1. **A hidden category's section cannot be fetched directly.** Request the dashboard with the
   htmx headers naming the hidden category's slug — header `HX-Request: true` and header
   `HX-Target: section-page-reference-demo`. Expect **404**, not a rendered section containing Soon
   Hidden. (The `mcp__playwright__browser_network_request` tool can issue this; a `curl` with the
   two headers works too.)
2. **The category section's htmx swap includes the coming-soon course.** Same request but with
   `HX-Target: section-page-qa-soon-mix`. Expect **200** and **Mix Bravo** in the returned
   fragment. This is the single-section render path, which is separate code from the full page — if
   §1 passes and this fails, only the full-page path was fixed.
3. **A nonexistent section slug.** `HX-Target: section-page-no-such-thing`. Expect 404.
4. **Keyboard and screen-reader path through the new button.** Tab through the **Coming soon**
   section. Expect focus to reach the pagination controls and then the **Browse all courses** link,
   each with a visible focus ring, and expect the link to be reachable and activatable with Enter.
   Adding a control to this header row must not strand the pagination arrows.
5. **Paging focus still works with the new button present.** In **Coming soon**, press **next** with
   the keyboard. Expect focus to return to the next arrow if it is still enabled, or to the section
   heading if paging landed on the last page — the Browse all courses link must not steal it.
6. **Narrow viewport.** Resize to about 400px wide and reload. Expect the QA Soon Mix and Coming soon
   headers to wrap rather than overflow, with the pagination and the new Browse all courses button
   both still reachable, and no horizontal page scroll.
7. **Repeat renders are stable.** Reload the dashboard three times. Expect the same course order in
   every section each time — in particular Mix Bravo staying second in QA Soon Mix rather than
   shuffling between the published courses.

## Reporting

For each section above, record pass or fail with what was actually on screen. For any failure,
capture a screenshot into `qa-screenshots/` and note which section and which course was wrong, since
the two fixes fail in quite different ways: a wrong-section or wrong-order card points at the pool
change, a missing or extra button points at the section builders.
