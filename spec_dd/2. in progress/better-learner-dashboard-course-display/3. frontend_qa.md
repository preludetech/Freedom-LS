# Frontend QA: better learner dashboard course display

The learner dashboard now groups discovery courses into category sections declared in the content
repo, pages every course grid three at a time, orders every section, and splits coming-soon courses
into their own section. The course detail page chip, the educator course panel and the Django admin
change with it. Spec: `1. spec.md` in this directory.

Every check below says what to do and what you expect. Record any difference as a failure with a
screenshot. Capture a screenshot of the full dashboard for each of the three visitor states in §1,
§2 and §3; the rest of the sections need a screenshot only where a step says so or where something
fails.

---

## 0. Setup

### 0.1 Build Tailwind

`static/vendor/tailwind.output.css` is not tracked, and this branch adds new grid utilities to the
dashboard. Build it before anything else, or the heading row and the controls render in the wrong
place for the wrong reason.

```bash
npm run tailwind_build
```

### 0.2 Dev server

```bash
PORT=$(.claude/ds/scripts/find_available_port.sh)
uv run python manage.py runserver $PORT
```

Base URL is `http://127.0.0.1:$PORT`. Login page is `http://127.0.0.1:$PORT/accounts/login/`.
Credentials are in `.claude/fls-dev/config.md`; the convention is password equals email address.

### 0.3 Seed

Run in this order, from the project root:

```bash
uv run python manage.py migrate
uv run python manage.py content_save ./demo_content DemoDev
uv run python manage.py qa_create_rich_dashboard_learner
```

After the content load, `git status` must be clean: the demo declaration ships with its uuids
already written, so a load must not rewrite `demo_content/course_categories.yaml`. If it is
modified, that is a failure to record under §9.

The demo content declares three categories:

## 9. Content authoring round trips

These run on a temporary copy of `demo_content/` so the checked-in files stay clean.

```bash
cp -r demo_content /tmp/qa_content
```

1. **Title edit keeps the slug and the section.** In `/tmp/qa_content/course_categories.yaml`
   change the `start-here` title to "Begin here". Run
   `uv run python manage.py content_save /tmp/qa_content DemoDev`. Reload `/`: the first section is
   headed "Begin here", still holds the same courses, and `git status` in the project is clean. The
   yaml file on disk is unchanged apart from your edit.
2. **Reordering the list reorders the sections.** Move the `assessment` entry above `start-here`,
   reload content, reload `/`: Assessment renders first, and Recommended courses (when signed in
   as `demodev_s1@email.com`) sits between Assessment and the next category.
3. **Turning a section off.** Set `show_on_dashboard: false` on `assessment`, reload content,
   reload `/` anonymously: no Assessment section; Functionality Demo - show end with Quiz appears
   under Available courses in alphabetical position; Functionality Demo - show end with Topic
   stays under Start here (it belongs to Assessment too, which must have no effect).
4. **First load writes uuids.** Delete the three `uuid:` lines from the yaml, run `content_save`.
   The file gains one `uuid:` line per entry; the other lines are untouched; a second
   `content_save` leaves the file byte-identical (`md5sum` before and after).
5. **Unknown slug.** In `/tmp/qa_content/functionality_demo_end_with_quiz/course.md` change
   `assessment` to `assesment`. Run
   `uv run python manage.py content_validate /tmp/qa_content`. Expect a non-zero exit and a
   message that names the course file, quotes `assesment`, says it came from `categories[0]`,
   lists `start-here`, `assessment`, `reference` with `course_categories.yaml`, and says adding an
   entry is as valid a fix. Then run `content_save` with the same edit: it fails before writing,
   and the dashboard is unchanged from before.
6. **Retired key.** Put `category: Assessment` into any course.md and run `content_validate`.
   Expect a failure naming `categories` and `dashboard_category`.
7. **Two categories, no dashboard key.** Remove `dashboard_category` from
   `functionality_demo_end_with_topic/course.md`. Expect a failure listing `start-here` and
   `assessment` as the candidates.
8. **Dashboard key outside the course's list.** Set `dashboard_category: reference` on the same
   course. Expect a failure saying the dashboard category has to be one the course belongs to.
9. **Duplicate slug, reserved slug, bad slug, second declaration.** One at a time: duplicate the
   `reference` entry; rename a slug to `available`; rename a slug to `Not A Slug!`; copy the whole
   file to `/tmp/qa_content/second_categories.yaml`. Each produces its own failure naming the slug
   or both files.
10. **Category file inside a course directory.** Move `course_categories.yaml` into
    `/tmp/qa_content/functionality_demo_course_parts/`. `content_validate` fails naming the file
    and telling you to move it to the repo root.
11. **Several errors at once.** Combine 5, 6 and 7 in one run. All three messages appear together.
12. Restore the real content afterwards: `uv run python manage.py content_save ./demo_content DemoDev`.
