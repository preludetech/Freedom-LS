# Frontend QA: per-placement due dates for shared content

A `children:` entry in `course.md` or `part.yaml` can now set a due date for that one placement
of a topic or form, or say there is none with `no_due_date: true`. A `course.md` entry that
places a part can do the same for each of the part's children through a nested `children:`
list. Staff overrides still win. The learner sees the result in the player outline as before
("Deadline <date>"); admins see the placement values in the content admin and as the "Content
default" of an override row.

This run covers:
- the player outline for a part placed in two courses, with different dates in each
- the content admin: `no_due_date` on a placement, the read-only child due dates of a part
  placement, and no `overrides` anywhere
- the deadlines admin: "Content default" from a placement value, "Default has changed" after a
  placement value changes, and an override beating `no_due_date`
- the errors an author gets from `content_save`, `content_validate` and the bundled validator
- the ways it could go wrong: the original course is unaffected, removing the nested list restores
  the file values, the two courses share progress on the same topic, and layout at phone width

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever
this document writes `$PORT`. Shell variables do not survive between tool calls.

Dates are written relative to the learner's registration date. "Reg" is the date part of that
learner's `CourseProgress.created_at` in the site zone. Every learner here registers today, so Reg
is the run date. The site zone is `Africa/Johannesburg` (UTC+2, no DST), so an end-of-day instant
is 21:59:59.999999 UTC. The browser runs in the same zone with the en-US locale, so an end-of-day
instant prints as "Mar 8, 2026, 11:59 PM" and hours are zero-padded ("05:00 PM").

**Wording.** Learner pages say "Deadline" and "Missed deadline" only. If "No due date",
"Placement", "Override" or "no_due_date" shows on a learner page, that is a bug.

## §1 One part, two courses, two sets of dates

### 1.1 The placement course shows the placement values

1. As the fresh learner open the placement course's detail page and press "Start course".
2. In the sidebar outline expand `Core Concepts` and expect:
   - `Key Ideas`: "Deadline <Reg + 3>, 11:59 PM". Not "05:00 PM": the placement sets a day with
     no time, and the file's `17:00` does not leak in.
   - `Going Deeper`: no deadline line.
   - `Knowledge Check`: no deadline line. The file's 21 days is suppressed here.
3. Expect no deadline line and no chip on the `Core Concepts` part row itself.

### 1.2 The parts course is unchanged

1. Still as the fresh learner open the parts course's detail page and press "Start course".
2. Expand `Core Concepts` and expect `Key Ideas`: "Deadline <Reg + 14>, 05:00 PM";
   `Going Deeper`: no line; `Knowledge Check`: "Deadline <Reg + 21>, 11:59 PM".
3. Expand `Getting Started` and expect `Welcome` with its Missed deadline chip and
   "Jan 31, 2024, 11:59 PM" and `What to Expect` with "Deadline <Reg + 7>, 11:59 PM", exactly as
   before this change.

### 1.3 Progress on the shared topic is shared; the deadlines are not

1. In the placement course open `Going Deeper` and complete it (the player's complete control).
2. Open the parts course: `Going Deeper` shows as completed there too. This is the existing
   behaviour for a shared part and is expected.
3. In both courses `Key Ideas` still shows its own course's deadline from 1.1 and 1.2. Completing
   one topic must not change another item's deadline line.

## §3 The deadlines admin

### 3.1 "Content default" shows the placement value

1. Open the cohort course registration change page for `QA Placement Cohort` on the placement
   course (`http://127.0.0.1:$PORT/admin/learner_management/cohortcourseregistration/`, then the
   row).
2. In the deadline override inline add a row: item `Key Ideas`, kind "Days after registration",
   days `10`, reason "QA placement". Save and continue editing.
3. Expect the row's "Content default" column to read "3 days after registration" (the
   placement value, not the file's 14 days at 17:00) and "Effective" to read "10 days after
   registration". No "Default has changed" note.
4. Add a second row: item `Knowledge Check`, kind "Days after registration", days `5`, reason
   "QA no_due_date". Save and continue editing. Expect its "Content default" to read
   "No deadline".

### 3.2 An override beats `no_due_date`

1. As the cohort learner open the placement course in the player.
2. Expect `Knowledge Check`: "Deadline <Reg + 5>, 11:59 PM" (the cohort override from 3.1) and
   `Key Ideas`: "Deadline <Reg + 10>, 11:59 PM".
3. As the fresh learner (no cohort) the placement course still shows 1.1's values.

### 3.3 A changed placement value is reported

1. Edit `demo_content/functionality_demo_course_parts_placement/course.md`: change
   `due_days_after_registration: 3` to `due_days_after_registration: 4` under `Key Ideas`.
2. Re-run `uv run python manage.py content_save demo_content <dev site name>`.
3. Reload the registration change page from 3.1. Expect the `Key Ideas` row to read
   "Default has changed since this override was set (was relative:3, now relative:4)" and its
   "Content default" to read "4 days after registration". The `Knowledge Check` row has no note.
4. Restore the file (`git checkout -- "demo_content/functionality_demo_course_parts_placement/course.md"`)
   and re-run `content_save`. Reload: the note is gone and "Content default" reads "3 days after
   registration" again.

## §4 What an author sees when a file is wrong

These steps run in the terminal, against a scratch copy, so nothing in `demo_content/` changes.
Make the copy once: `cp -r "demo_content/functionality_demo_course_parts" /tmp/qa_placement_bad/`
(a directory outside the repo), then edit the copied `course.md` as each test says, run the
command, and check the output. The copied course keeps its uuids, so never load the copy with
`content_save` into the dev database: use `content_validate` and the bundled validator only.

The two commands, each given the scratch copy's path:

- `uv run python manage.py content_validate /tmp/qa_placement_bad`
- `uv run --no-project --with pydantic --with pyyaml --with python-frontmatter --with babel python claude_plugins/fls-content/validate/validate.py /tmp/qa_placement_bad`

Both must give the same verdict for every case below.

### 4.1 `overrides:` is refused

Add to the copied `course.md` frontmatter:

```yaml
children:
  - path: 01. Getting Started/part.yaml
    overrides: {foo: bar}
```

Expect both commands to fail naming `overrides` as an extra field.

### 4.2 `no_due_date` with a due key

Replace the `children:` block with:

```yaml
children:
  - path: 01. Getting Started/part.yaml
    children:
      - path: 01. welcome/content.md
        no_due_date: true
        due_days_after_registration: 2
```

Expect both to fail with a message containing `01. welcome/content.md` and "no_due_date takes
no due keys".

### 4.3 A nested path that names nothing in the part

Replace the nested entry's path with `99. missing/content.md`. Expect both to fail with a
message naming the copied `course.md`, the field `children[0].children[0]`, the given path and
the part's actual children (`01. welcome/content.md`, `02. what-to-expect/content.md`).

### 4.4 A due key on a part entry

Replace the `children:` block with:

```yaml
children:
  - path: 01. Getting Started/part.yaml
    due_days_after_registration: 2
```

Expect both to fail saying a due date on a `COURSE_PART` placement is not allowed.

### 4.5 A valid file passes both

Replace the `children:` block with:

```yaml
children:
  - path: 01. Getting Started/part.yaml
    children:
      - path: 01. welcome/content.md
        no_due_date: true
  - path: 02. Core Concepts/part.yaml
  - path: 03. Wrapping Up/part.yaml
```

Expect both commands to exit zero. Then delete `/tmp/qa_placement_bad`.

## §5 Removing the nested list restores the file values

1. Edit `demo_content/functionality_demo_course_parts_placement/course.md`: delete the whole
   nested `children:` list under the part entry, leaving just `- path: ../functionality_demo_course_parts/02. Core Concepts/part.yaml`.
2. Re-run `content_save` for `demo_content/`.
3. As the fresh learner open the placement course in the player. Expect `Key Ideas`:
   "Deadline <Reg + 14>, 05:00 PM" and `Knowledge Check`: "Deadline <Reg + 21>, 11:59 PM": the
   part's own values apply again.
4. In the content admin (2.2 step 1) the placement course's `Core Concepts` row now has an empty
   child due dates inline.
5. Restore the file with `git checkout` and re-run `content_save`. Confirm 1.1 holds again.
