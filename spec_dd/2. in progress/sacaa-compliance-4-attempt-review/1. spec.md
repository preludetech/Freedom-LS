# Spec: Educators review one learner's quiz attempt

## Purpose

SACAA's CAR 141.01.17 requires an ATO to keep detailed student records for 5 years and produce them
on request. For a quiz, that means showing the exact paper a learner sat and how it was marked.
`sacaa-compliance-1-served-paper-record` stores the paper (`FormProgress.served_paper`), but there
is no way for an educator to read it. This spec adds a read-only attempt review page, and a quick
view, reached from the quiz attempts table on a learner's Courses tab. See `idea.md`.

## Terminology

- **Attempt review**: the educator instance page for one completed QUIZ form progress record. Its
  URL segment is `quiz-attempts`.

"Attempt" here means one completed sitting: the `FormProgress` row together with the
`CourseFormAttempt` that places it in a course, as the glossary splits them.

## Scope

In:

- A panel-framework instance page and a quick view for one completed QUIZ sitting that has a
  `CourseFormAttempt`.
- A link and quick-view trigger on each row of the learner Courses tab's quiz attempts table.
- A small, generic panel-framework addition: a section that can be routed to without appearing
  in the menu, with a back link it chooses itself.
- Skill and product-doc updates for the new surface.

Out:

- The quiz-attempt export: there is no quiz export to extend (`form_engine/exports.py` only
  serves the course-application export), and it is deferred to a follow-up spec. `exports.py` is
  not changed.
- In-progress attempts, non-quiz forms, course applications, and sittings outside any course.
- An audit entry on open, and gating access to question text:
  `sacaa-compliance-content-versions-and-access-5-answered-version-review` adds both to this page.
- The Django admin's `answer_groups` (`form_engine/queries.py`), which stays in authored order.
  `sacaa-compliance-content-versions-and-access-4-question-access` removes the quiz answers
  document from `FormProgressAdmin`.
- Frozen question text, a stored pass mark, PDF export, retention, time limits, and any change to
  scoring, shuffling or drawing.

## Decisions

- **The single reader is `sitting_path()`** (`form_engine/conditions.py`). Every page, child,
  option order and question number shown comes from the `SittingPath` it returns. The review never
  walks `form.pages` and never re-derives a shuffle or draw. This keeps it correct for
  `sacaa-compliance-3-question-pools` (on a branch) and for the version-backed path that
  `sacaa-compliance-content-versions-and-access-3-question-versions` will bring.
- **Scores are stored, verdicts per question are live.** Score, max score and percentage come from
  `FormProgress.scores`. Pass or fail comes from `quiz_verdict` (`form_engine/queries.py`). The
  per-question mark is computed with `is_quiz_answer_correct` (`form_engine/scoring.py`) against
  the current options, the same way the learner results page computes it.
- **The pass mark shown is the form's current `quiz_pass_percentage`.** Nothing stores the mark
  that applied at sitting time. The summary row is labelled "Pass mark (current setting)", so the
  page does not claim more than it knows.
- **Attempt numbers come from one rule.** The table numbers completed sittings chronologically in
  `reports/gather.py` `_quiz_result_for`. The page uses the same ordering, extracted into one
  function that both call, so the "Attempt 2" row in the table never opens a page that says
  "Attempt 3".
- **The route is a hidden section, not a nested route.** The framework cannot nest an instance
  under another (`learners/<pk>/attempts/<id>`). A `ListViewConfig` with no list view, no menu
  entry and its own back link gives the page and the quick view with the framework's existing
  dispatch, authorisation and invariant walk.
- **No new permission.** Access follows `VIEW_LEARNER` through `learners_visible_to`, and the
  registration must be visible the way the Courses tab filters it. Anything else is a 404, so a
  guessed URL reveals nothing the tab hides.

## Requirements

### Panel framework (`freedom_ls/panel_framework/`)

The framework stays generic: it imports nothing from `freedom_ls` (`test_import_guard.py`).

1. `SectionConfigBase` gains a class attribute, `in_menu: bool = True`. `build_menu_items`
   (`views.py`) leaves out a section with `in_menu = False`. Its paths keep resolving exactly as
   `is_visible` and `is_available` allow.
2. `ListViewConfig` gains an overridable classmethod for the instance page's back link,
   `get_back_link(request, instance) -> tuple[str, str] | None` (label and URL). The default is
   `None`, which keeps today's crumb to the section list. When it returns a pair,
   `build_breadcrumbs` uses it in place of the section crumb.
3. A `ListViewConfig` with `list_view = None`, an `instance_view` and a `quick_view` serves
   `<section>/<pk>` and `<section>/<pk>/__quick-view`. The bare `<section>` path is a 404. Confirm
   this against `_resolve_path` and `_bind_root`, and against `checks.table_key_errors`, which
   needs a `table_key` only when `list_view` is set. Fix whatever does not hold.
4. `claude_plugins/fls-dev/skills/panel-framework/SKILL.md` documents both hooks in one short
   paragraph each.

`extract_panels_framework-5-package-and-install` moves the framework to its own package.
Whichever of the two specs lands second carries these hooks across.

### Report data (`freedom_ls/reports/`)

1. `report_data.py` `QuizAttempt` gains `form_progress_id: UUID`, set in `gather.py`
   `_quiz_result_for`. `screen_cache.py` `SCHEMA_VERSION` goes from 2 to 3. Every other reader of
   `QuizAttempt` (the cohort report and the PDF report) keeps working unchanged.
2. The attempt-numbering rule is extracted from `_quiz_result_for` into one function that the
   attempt review also calls (see Decisions). Its placement belongs to the plan, but course code
   resolves attempts through `learner_progress/attempts.py`, per the glossary.

### Stale-score rule (`freedom_ls/learner_interface/views.py`, `freedom_ls/form_engine/`)

The `stored_score_outdated` check in the learner quiz results view (`learner_interface/views.py`,
around line 2190) is extracted into one function in `form_engine`, taking the form progress record
and its `SittingPath`. The learner view and the attempt review both call it. The rule stays as it
is: compare stored `score` and `max_score` to `compute_quiz_scores(path)`, and skip the comparison
when `path.has_missing_served_items`.

### Attempt review section (`freedom_ls/educator_interface/panels/learner/`)

1. `QuizAttemptConfig(OrganisationSectionConfig, ListViewConfig)`: `url_name = "quiz-attempts"`,
   `model = FormProgress`, `list_view = None`, `in_menu = False`, `instance_view`, `quick_view`,
   and `menu_label = "Quiz attempts"` (used only by the framework's own labels). It is added to
   the same NavGroup as `LearnerConfig` in `educator_interface/views.py` `interface_config`.
2. `authorise_instance` raises `OrganisationScopeDenied` unless all of these hold:
   - the form's strategy is QUIZ and `completed_time` is set;
   - the sitting has a `course_attempt`;
   - the course progress record's learner, in the URL's organisation, is in
     `learners_visible_to(request.user, organisation, include_inactive=True)`;
   - the registration is one that `visible_registrations_with_progress` (`quick_view.py`) would
     show this educator.

   The queryset the framework resolves `<pk>` against is site-filtered by `FormProgress`'s
   manager.
3. `get_back_link` returns ("Back to <learner display name>", the learner's Courses tab URL,
   `learners/<learner_pk>/__tabs/courses`). `get_instance_label` returns "<quiz title>, attempt N".

### Attempt review page

`QuizAttemptInstanceView(InstanceView)`:

- **Header.** Title: the quiz title. Subtitle: "Attempt N · <learner display name> · <course
  title>", with the course shown the way the Courses tab shows a shared course. Status badge:
  Passed or Failed from `passed_badge` (`educator_interface/templatetags/educator_tags.py`). There
  is no badge when the verdict is None (no pass mark). Stats (`HeaderStat`): Score "x/y" and
  Percentage. There are no header actions.
- **Summary panel** (`InstanceDetailsPanel`, `detail_row`): Started, Completed, Pass mark (current
  setting) or "No pass mark". Each fact appears once on the page, so the header's facts are not
  repeated here.
- **Notes**, one `<c-panel-callout>` each, above the paper, each shown only when its condition
  holds:
  - stored score outdated (the extracted rule): "This quiz has changed since the attempt was
    marked. The score is the one recorded at submission; the marks below use the current
    answers.";
  - `path.has_missing_served_items`: "Some items served in this attempt have since been deleted
    from the quiz and are not shown.";
  - no `served_paper`: "This attempt predates the record of the served order. Pages, questions and
    options are shown in the quiz's current order."
- **One muted line** under the paper heading: "Question and option wording is the quiz's current
  wording."
- **Paper panel.** Every served page in `SittingPath` order, each as a section with its position
  and title as a heading (spacing between pages, never a card inside a card). Under each page, the
  page's children from `children_of(page)` in served order:
  - a content block renders its content (`fls-dev:markdown-content`);
  - a question shows its served number (`question_positions()`), its text, and its options in
    `options_of(question)` order. The learner's selection and the correct options are each marked
    in text and with an icon, never by colour alone, as "Learner's answer" and "Correct answer".
    Then a verdict: "Marked correct", "Marked incorrect", or "Not marked" (a question with no
    correct option, such as free text). An unanswered question reads "Did not answer" and is
    marked incorrect when it has a correct option. A free-text answer shows its text.
  - An undrawn question does not appear anywhere.

  Reuse the read-only rendering that the course content preview already uses
  (`panels/course/content_preview.py` `_form_preview_context`, `form_engine/partials/
  page_children.html` with `read_only=True`, `show_answer_key=True`, `existing_answers` from
  `answers_by_question`, `question_positions`, and `sitting_path` in context for
  `{% question_options %}`). Add the per-question verdict as one partial that the page includes
  per question, so that `sacaa-compliance-content-versions-and-access-5-answered-version-review`
  can extend it in one place. Take the verdict wording and icon semantics from the learner
  results page (`learner_interface/templates/learner_interface/course_form_complete.html`), not
  its markup, which uses cards and colours the panel rules forbid.
- **Query count.** The number of queries is bounded and does not grow with the number of questions
  or pages: answers, options and children are prefetched once per page load.

### Attempt quick view

`QuizAttemptQuickView(QuickView)`, with a template under `educator_interface/quick_views/`:

- Title: "<quiz title>, attempt N". Subtitle: the learner's display name.
- `<c-panel-definition-list columns="2">` rows: Result (badge, or nothing with no pass mark),
  Score, Percentage, Pass mark (current setting), Started, Completed.
- One link, "Open full review", to the attempt review page.
- No per-question detail.

### Courses tab attempts table (`educator_interface/templates/educator_interface/panels/learner_courses.html`)

- The Attempt cell becomes `<c-quick-view-trigger>`, with `href` the attempt review page and `url`
  its `__quick-view`. A plain click opens the drawer, and a modified click or a new tab opens the
  page. No other control is added to the row.
- The table keeps working beside an open quick view at 375px wide, using `cards_when_narrow` if
  the panel-framework rules call for it.

## Testing

- **Framework:** a section with `in_menu = False` is absent from `build_menu_items` but its
  instance and quick-view paths resolve; its bare section path is a 404; `get_back_link` replaces
  the crumb, and `None` leaves the default. These are generic tests in `panel_framework`'s own
  suite, using its test host.
- **Authorisation** (page and quick view): a cohort-scoped educator opening an attempt of a
  learner outside their cohorts, or of a registration made through a cohort they cannot see, gets
  a 404. So do another organisation's educator, a non-quiz sitting, an in-progress sitting, a
  sitting with no `CourseFormAttempt`, and an educator without `VIEW_LEARNER`.
  `test_config_authorisation.py` and `tests/interface_walk.py` cover the new config.
- **Served paper:** with a stored `served_paper` whose page, question and option orders differ
  from authored order, and with one question left out of the paper, the page shows the served
  order and numbering, and the left-out question appears nowhere. With no `served_paper` (a legacy
  sitting), the authored order and the "predates" note show. With a served item since deleted,
  the missing-items note shows.
- **Marking:** correct, incorrect, unanswered, and no-correct-option (free text) questions each
  show their verdict text. Score, percentage and verdict match the stored values. The pass-mark
  row reads "No pass mark" and no badge shows when `quiz_pass_percentage` is None. The
  stale-score note shows when a correct option changed after submission, and is suppressed when
  served items are missing. The learner results view's existing tests still pass on the extracted
  rule.
- **Attempt number:** for a learner with three completed attempts and one in progress, each row's
  number in the Courses tab equals the number on the page it opens.
- **Report data:** `QuizAttempt.form_progress_id` is the sitting's pk. The cache schema bump makes
  old cached entries miss.
- **Query count:** the page's queries for a 3-page, 30-question attempt equal those for a 1-page,
  3-question attempt.
- **Playwright flow:** from a learner's Courses tab, clicking an attempt number opens the quick
  view with the right score. "Open full review" reaches the page, which shows the served paper,
  and the back link returns to the Courses tab.

## Open questions

- Q: Should opening the attempt review write an audit entry? → A: No entry in this spec (assumed
  default: the audit log records reads only when worth auditing, and
  `sacaa-compliance-content-versions-and-access-5-answered-version-review` already adds the entry
  together with the question-access gate. Until it ships, a `VIEW_LEARNER` holder sees question
  text and correct answers unlogged, the same exposure as today's content preview. Overrule by
  editing Scope.)
- Q: Should the Django admin's `answer_groups` move onto served order? → A: No (assumed default:
  `sacaa-compliance-content-versions-and-access-4-question-access` removes the quiz answers
  document from the admin, and non-quiz forms have no served paper. Overrule by editing Scope.)
- Q: Should the page show time taken? → A: No (assumed default: the idea asks for start and
  completion times only, and both are shown. Overrule by editing Attempt review page.)
- Q: Should the header badge show both Passed and Failed? → A: Yes (assumed default: both are
  outcomes, not a default state, so neither is suppressed. Overrule by editing Attempt review
  page.)

## Success criteria

- From a learner's Courses tab, clicking an attempt number opens a quick view with Result, Score,
  Percentage, Pass mark, Started and Completed, and a link to the full review.
- The attempt review shows every served page, content block and question in served order, with
  options in the order shown, the learner's answer, the correct answer and a per-question
  verdict. Undrawn questions are absent.
- The attempt number on the page matches the table row it was opened from.
- Every authorisation case in Testing returns 404.
- The "Quiz attempts" section never appears in the educator sidebar.
- The page's query count is the same for a 3-question attempt and a 30-question attempt.
- `uv run pytest` passes, including the interface walk and the framework import guard.
