# Spec: Educators review one learner's quiz attempt

## Purpose

SACAA's CAR 141.01.17 requires an ATO to keep detailed student records for 5 years and produce them
on request. For a quiz, that means showing the exact paper a learner sat and how it was marked.
`sacaa-compliance-1-served-paper-record` stores the paper (`FormProgress.served_paper`), but there
is no way for an educator to read it. This spec adds a read-only attempt review page, and a quick
view, reached from the quiz attempts table on a learner's Courses tab. See `idea.md`.

## Terminology

| term | kind | meaning |
| --- | --- | --- |
| attempt review | coined | The educator instance page for one completed QUIZ sitting that has a course form attempt. URL segment `quiz-attempts`. No existing term names a page that reads one sitting. |
| attempt | narrowed | `claude_plugins/fls-dev/skills/domain-glossary/SKILL.md` (the `FormProgress` / `CourseFormAttempt` split), here only one completed QUIZ sitting, as the Courses tab's "Attempt" column already uses it. |

In requirement prose, "sitting" is the whole event, as the glossary uses it: its form progress
record (`FormProgress`) and its course form attempt (`CourseFormAttempt`).

## Scope

In:

- A panel-framework instance page and quick view for one completed QUIZ sitting that has a course
  form attempt.
- A link and quick-view trigger on the openable rows of the learner Courses tab's quiz attempts
  table.
- Three generic panel-framework additions: a section left out of the menu, an instance page's
  own back link, and a date-time details row.

Out:

- The quiz-attempt export. There is no quiz export to extend (`form_engine/exports.py` only serves
  the course-application export), so it is deferred to a follow-up spec, which also decides the
  served-order and seed columns and their shape. `exports.py` is not changed.
- In-progress sittings, non-quiz forms, course applications, and sittings with no course form
  attempt.
- An audit entry on open, and gating access to question text.
  `sacaa-compliance-content-versions-and-access-5-answered-version-review` adds both to this page.
  Until it ships, a `VIEW_LEARNER` holder sees question text and correct answers unlogged, the
  same exposure as today's content preview.
- The Django admin's `answer_groups` (`form_engine/queries.py`), which stays in authored order.
  `sacaa-compliance-content-versions-and-access-4-question-access` removes the quiz answers
  document from `FormProgressAdmin`.
- A Claude Design pass. The page is built from panel-framework pieces and the brand rules and
  checked in QA.
- Frozen question text, a stored pass mark, time taken, PDF export, retention, time limits, and any
  change to scoring, shuffling or drawing.

## Decisions

- **The single reader is `sitting_path()`** (`form_engine/conditions.py`). Every page, child,
  option order and question number shown comes from its `SittingPath`. The review never walks
  `form.pages` and never re-derives a shuffle or draw, so it stays correct when pools and
  version-backed paths change what `sitting_path()` returns.
- **Scores are stored; per-question marks are live.** Score, max score and percentage come from
  `FormProgress.scores`, and pass or fail from `quiz_verdict` (`form_engine/queries.py`). The
  per-question mark uses `is_quiz_answer_correct` (`form_engine/scoring.py`) against current
  options, as the learner results page does.
- **The pass mark shown is the form's current `quiz_pass_percentage`**, labelled "Pass mark
  (current setting)" everywhere it appears. Nothing stores the mark that applied at sitting time.
- **No new permission.** Access follows `VIEW_LEARNER` through `learners_visible_to`.
- **The route is a section outside the menu**, because the framework has no nested instance route
  (`learners/<pk>/attempts/<id>`).
- **The verdict is a header stat, not a badge.** The panel-framework rule allows a header badge
  only for a non-default state, and Passed and Failed are both outcomes.

## Requirements

### Panel framework (`freedom_ls/panel_framework/`)

The framework stays generic: it imports nothing from `freedom_ls` (`test_import_guard.py`).

1. `SectionConfigBase` gains `in_menu: bool = True`. `build_menu_items` (`views.py`) leaves out a
   section with `in_menu = False`, and `first_visible_section` never lands on one; both ask one
   new classmethod, `is_in_menu(request)`. Its paths
   still resolve as `is_visible` and `is_available` allow. `sections_by_url_name` and the config
   checks accept such a section.
2. `ListViewConfig` gains a classmethod `get_back_link(request, instance) -> tuple[str, str] |
   None` (label, URL). The default `None` keeps today's crumb to the section list. When it returns
   a pair, `build_breadcrumbs` uses it in place of the section crumb. `build_breadcrumbs` gains a
   `request` parameter, and `panel_framework_view` passes it.
3. A `ListViewConfig` with `list_view = None` serves `<section>/<pk>` and
   `<section>/<pk>/__quick-view`. The bare `<section>` path and any `<section>/__…` path raise
   `Http404` in `_bind_root` instead of today's `ValueError`. `checks.table_key_errors` already
   needs a `table_key` only when `list_view` is set.

4. `InstanceDetailsPanel.detail_row` gains a `"datetime"` kind, drawn with `<c-panel-datetime>`,
   for a row that needs the time of day. The `"date"` kind is unchanged.

### Report data (`freedom_ls/reports/`)

1. `report_data.py` `QuizAttempt` gains `form_progress_id: UUID`, set in `gather.py`
   `_quiz_result_for`. `screen_cache.py` `SCHEMA_VERSION` goes from 2 to 3. The cohort report and
   the PDF report keep working unchanged.
2. The attempt-numbering rule in `_quiz_result_for` is extracted into one function that the
   attempt review also calls: completed sittings of one form under one course progress record,
   numbered chronologically, as `FormProgressIndex.completed_attempts_by_learner_form` groups them
   when keyed by course progress record (the Courses tab's keying). The number in the table row and on the page it opens are always equal.

### Stale-score rule (`freedom_ls/learner_interface/views.py`, `freedom_ls/form_engine/`)

The `stored_score_outdated` check in the learner quiz results view (`learner_interface/views.py`,
around line 2190) is extracted into one `form_engine` function taking the sitting and a
`SittingPath | None`, and optionally the sitting's already-loaded answers so the attempt review
marks without a query per question. Both the learner view and the attempt review call it, and both pass `None`
for a sitting with no `served_paper`, which keeps the learner view's behaviour and tests exactly as
they are. The rule: compare stored `score` and `max_score` to `compute_quiz_scores(path)`, and skip
the comparison when `path.has_missing_served_items`.

### Openable sittings (`freedom_ls/educator_interface/panels/learner/`)

One predicate decides whether an educator may open a sitting, and both `authorise_instance` and the
Courses tab call it. A sitting is openable when all of these hold:

- the form's strategy is QUIZ and `completed_time` is set;
- the sitting has a course form attempt, and the sitting's user is the learner of that attempt's
  course progress record (the paper shows the sitting user's answers);
- the course progress record's learner, in the URL's organisation, is in
  `learners_visible_to(request.user, organisation, include_inactive=True)`;
- the registration behind that course progress record (`learner_registration` or
  `cohort_registration`) is one that `visible_registrations_with_progress` (`quick_view.py`) shows
  this educator.

The Courses tab evaluates it for all its rows with a bounded number of queries, not one per row.
Page and quick view requests run it once each, which is acceptable for low-traffic reads.

### Attempt review section (`freedom_ls/educator_interface/panels/learner/`)

1. `QuizAttemptConfig(OrganisationSectionConfig, ListViewConfig)`: `url_name = "quiz-attempts"`,
   `model = FormProgress`, `list_view = None`, `in_menu = False`, `instance_view`, `quick_view`,
   `menu_label = "Quiz attempts"`. It is added to `LearnerConfig`'s NavGroup in
   `educator_interface/views.py` `interface_config`.
2. `authorise_instance` raises `OrganisationScopeDenied` unless the sitting is openable. The pk is
   resolved through `FormProgress`'s site-filtered manager.
3. An organisation switch made from an attempt review lands on the first visible section of the
   other organisation, as a switch from a section that organisation does not show does: a sitting
   belongs to one organisation's learner, and the section has no list to fall back to.
4. `get_back_link` returns ("Back to <learner display name>", the learner's Courses tab URL,
   `learners/<learner_pk>/__tabs/courses`). `get_instance_label` returns "<quiz title>, attempt N".

### Attempt review page

`QuizAttemptInstanceView(InstanceView)`:

- **Header.** Title: the instance label, "<quiz title>, attempt N" (the framework draws
  `get_instance_label` as the header title). Subtitle: "<learner display name> · <course
  title>", with a shared course shown the way the Courses tab shows it. No status badge. Stats
  (`HeaderStat`): Score "x/y", Percentage, and Result (Passed or Failed, or "No pass mark" when
  `quiz_verdict` is None). No header actions.
- **Summary panel** (`InstanceDetailsPanel`, `detail_row`): Started, Completed (both with the
  time of day), Pass mark (current
  setting) or "No pass mark". Each fact appears once on the page.
- **Notes**, one `<c-panel-callout>` each, above the paper, each only when its condition holds:
  - stored score outdated (the extracted rule): "This quiz has changed since the attempt was
    marked. The score is the one recorded at submission; the marks below use the current
    answers."
  - `path.has_missing_served_items`: "Some items served in this attempt have since been deleted
    from the quiz and are not shown."
  - no `served_paper`: "This attempt predates the record of the served order. Pages, questions and
    options are shown in the quiz's current order, limited to the questions recorded as asked
    where that was recorded."
- **One muted line** under the paper heading: "Question and option wording is the quiz's current
  wording."
- **Paper panel.** Every page of the `SittingPath`, in order, each a section headed by its position
  and title (space between pages, never a card inside a card). Under each page, `children_of(page)`
  in order:
  - a content block renders its content (`fls-dev:markdown-content`);
  - a question shows its served number (`question_positions()`), its id muted beside the number,
    its text, and its options in `options_of(question)` order. The learner's selection and the
    correct options are each marked in text and with an icon, never colour alone, as "Learner's
    answer" and "Correct answer". The option inputs gain a `show_learner_answer` flag for the
    first mark, off by default, beside the existing `show_answer_key`, and `question.html` gains
    a `show_question_id` flag, off by default, for the id. Then a verdict: "Marked correct", "Marked incorrect", or "Not
    marked" (a question with no correct option, such as free text). An unanswered question reads
    "Did not answer" and is marked incorrect when it has a correct option. A free-text answer
    shows its text.
  - A question not in the sitting's path appears nowhere.

  The page draws questions with the read-only form partials the course content preview uses
  (`form_engine/partials/page_children.html` with `read_only=True`, `show_answer_key=True`,
  `existing_answers` from `answers_by_question`, `sitting_path` in context for
  `{% question_options %}`), from a new context builder over `sitting_path()` covering every
  page. `page_children.html` gains an optional per-question include (empty by default, so the
  learner player and the preview are unchanged), and the page passes one verdict partial through
  it. `sacaa-compliance-content-versions-and-access-5-answered-version-review` extends that
  partial. Verdict wording and icon semantics match the learner results page
  (`learner_interface/templates/learner_interface/course_form_complete.html`).
- **Query count.** The page's query count does not grow with the number of pages or questions.
  The verdict reads only prefetched answers (`selected_options`) and `options_of`.

### Attempt quick view

`QuizAttemptQuickView(QuickView)`, template under `educator_interface/quick_views/`:

- Title: "<quiz title>, attempt N". Subtitle: the learner's display name.
- `<c-panel-definition-list columns="2">` rows: Result (`passed_badge`, or "No pass mark"), Score,
  Percentage, Pass mark (current setting), Started, Completed.
- One link, "Open full review", to the attempt review page. No per-question detail.

### Courses tab attempts table (`educator_interface/templates/educator_interface/panels/learner_courses.html`)

- On an openable row, the Attempt cell is `<c-quick-view-trigger>`: `href` the attempt review page,
  `url` its `__quick-view`. A plain click opens the drawer, and a modified click or new tab opens
  the page. A row that is not openable shows the number as plain text. No other control is added.
- The learner page hosts `#quick-view`.
- The table takes `cards="true" cards_when_narrow="true"`, with the Attempt cell in its card rows,
  so it stays readable beside an open quick view at 375px.

## Testing

- **Framework** (in `panel_framework`'s own suite, with its test host): a section with
  `in_menu = False` is absent from the menu, and its instance and quick-view paths resolve; with
  `list_view = None`, the bare section path and a `__` path are 404s; `get_back_link` replaces the
  crumb, and `None` leaves the default.
- **Openable predicate and authorisation** (page and quick view): a 404 for a learner outside a
  cohort educator's cohorts, a registration made through a cohort the educator cannot see, another
  organisation's educator, an educator without `VIEW_LEARNER`, a non-quiz sitting, an in-progress
  sitting, and a sitting with no course form attempt, and a sitting whose user is not the record's learner. `tests/interface_walk.py` and
  `test_config_authorisation.py` learn about list-less sections: they walk this section's instance
  and quick-view paths for a seeded sitting, not its list path.
- **Courses tab links:** a learner with one openable sitting and one sitting from another course
  shows a trigger on the first row only. The row's number equals the number on the page it opens,
  for three completed sittings with one in progress.
- **Served paper:** with a `served_paper` whose page, question and option orders differ from
  authored order, and one question left out, the page shows the served order, numbering and ids,
  and the left-out question appears nowhere. A sitting with `asked` and no `served_paper`, and one
  with neither, each show the "predates" note and the path `sitting_path()` returns. A served item
  since deleted shows the missing-items note.
- **Marking:** correct, incorrect, unanswered and free-text questions each show their verdict text.
  Score, percentage and Result match the stored values and `quiz_verdict`. With
  `quiz_pass_percentage` None, Result and the pass-mark row read "No pass mark". The stale-score
  note shows when a correct option changed after submission and is suppressed when served items
  are missing. The learner results view's existing tests pass unchanged on the extracted rule.
- **Report data:** `QuizAttempt.form_progress_id` is the sitting's pk.
- **Query count:** a 3-page, 30-question sitting takes the same number of queries as a 1-page,
  3-question one.
- **Playwright flow:** from a learner's Courses tab, clicking an attempt number opens the quick
  view with the right score; "Open full review" reaches the page showing the paper; the back link
  returns to the Courses tab.

## Open questions

- Q: Should opening the attempt review write an audit entry? → A: No entry in this spec (assumed
  default: `sacaa-compliance-content-versions-and-access-5-answered-version-review` adds it with
  the question-access gate. Overrule by editing Scope.)
- Q: Should the Django admin's `answer_groups` move onto served order? → A: No (assumed default:
  `sacaa-compliance-content-versions-and-access-4-question-access` removes the quiz answers
  document from the admin, and non-quiz forms have no served paper. Overrule by editing Scope.)
- Q: The framework draws `get_instance_label` as the header title; should the header title be the
  quiz title alone? → A: No, the title is "<quiz title>, attempt N" and the subtitle drops the
  attempt number (asked while planning).
- Q: Should the openable check require the sitting's user to be the course progress record's
  learner? → A: Yes (asked while planning).
- Q: `detail_row` has no date-time kind; how are Started and Completed shown? → A: Add a generic
  `"datetime"` kind to the framework (asked while planning).
- Q: Should `QuizAttemptConfig` gate the section on `VIEW_LEARNER`? → A: No, it names no
  `view_capability`, as `LearnerConfig` names none; the openable check enforces `VIEW_LEARNER`
  (asked while planning).
- Q: Should the page show time taken? → A: No (assumed default: the idea asks for start and
  completion times only. Overrule by editing Attempt review page.)
