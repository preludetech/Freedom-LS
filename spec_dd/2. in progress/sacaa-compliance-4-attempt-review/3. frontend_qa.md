# Frontend QA: Educators review one learner's quiz attempt

## Setup

- Start the server on the port the QA command picks: `uv run python manage.py runserver $PORT`.
- Base URL: `http://127.0.0.1:$PORT`.
- Log in at `/accounts/login/` with the admin email and password under `## QA Login` in
  `.claude/sdd/config.md`.
- The educator interface is at `/educator/`. Paths below are relative to
  `/educator/<organisation-slug>/`.
- Run every test at the three QA viewports (phone 375px, tablet, desktop) unless it says otherwise.
- Judge every page against the Visual checklists in
  `claude_plugins/fls-dev/skills/panel-framework/SKILL.md` and
  `claude_plugins/fls-dev/skills/educator-interface/SKILL.md`, and the brand rules in
  `.claude/skills/brand-guidelines/`.

## Data

Ask the QA data helper for the following in one organisation the admin can open. Record each
sitting's pk and the learner's pk.

- **Quiz A**: a QUIZ form, pass mark 60%, two pages. Page 1: a content block, a multiple-choice
  question, a checkboxes question. Page 2: a dropdown question and a long-text question (no
  correct option). Shuffle on, so a served paper differs from authored order where it can.
- **Learner L1**, registered individually on a course that places Quiz A, with four sittings of
  Quiz A: three completed (one failed, one passed, one with a question left unanswered) and one
  still in progress. The completed sittings each have a `served_paper`.
- **Legacy sitting**: one more completed sitting of a second quiz (Quiz B, no pass mark) for L1
  with `served_paper` null and `asked` null.
- **Changed quiz**: a completed sitting of a third quiz (Quiz C) for L1, after which the correct
  option of one question was changed.
- **Deleted item**: a completed sitting of a fourth quiz (Quiz D) for L1, after which one served
  question was deleted from the quiz.
- **Learner L2** in a second organisation the admin can also open, with one completed sitting.
- **Cohort educator E**: a user with a cohort-level educator role on cohort C1 only. **Learner
  L3** in cohort C2 (not C1) with one completed quiz sitting.

## Test 1: The Courses tab links each completed attempt

1. Open `learners/<L1 pk>/__tabs/courses`.
2. Find the "Quiz A attempts" table.

Expect:

- Three rows, numbered 1 to 3. The in-progress sitting has no row.
- Each attempt number is a link. No other new control is in the row.
- Columns and values are otherwise as before: Completed, Score, Percentage, Pass mark, Result,
  with "Latest" on the last row.
- At 375px the table shows as cards, with the attempt number link in each card and every value
  labelled. No sideways scroll on the page.
- The attempt link meets the touch target size at 375px.

## Test 2: A plain click opens the quick view

1. On the Courses tab, click attempt number 2 of Quiz A.

Expect:

- The quick view drawer opens beside the page. The URL does not change.
- Title "Quiz A, attempt 2". Subtitle: L1's display name.
- Six rows: Result (a Passed or Failed badge), Score ("x/y"), Percentage, Pass mark (current
  setting) "60%", Started, Completed. Dates use the project's date-time format.
- One link, "Open full review". No questions or answers are shown.
- A close control closes the drawer and returns focus to the attempt number.
- At 375px the drawer is readable and the Courses tab behind it has no sideways scroll.
- With the drawer open, click attempt number 1: the drawer shows attempt 1's values, not attempt
  2's.

## Test 3: A modified click opens the page

1. On the Courses tab, Ctrl-click (or middle-click) attempt number 1 of Quiz A.

Expect: the attempt review page opens in a new tab at `quiz-attempts/<pk>`. The drawer does not
open in the original tab.

## Test 4: The attempt review page header and summary

1. From the quick view of attempt 2, click "Open full review".

Expect:

- The URL is `quiz-attempts/<pk>`. The browser title names the attempt.
- A back link above the heading reads "Back to <L1 display name>".
- Heading "Quiz A, attempt 2". Subtitle "<L1 display name> · <course title>".
- No status badge beside the heading. No buttons in the header.
- Header stats: Score "x/y", Percentage "n%", Result "Passed" or "Failed". They match the row on
  the Courses tab and the quick view.
- A Summary panel with Started, Completed and "Pass mark (current setting)" 60%. Score,
  percentage and result are not repeated in it.
- The sidebar has no "Quiz attempts" entry.
- No card inside a card, no rules between questions, no sideways scroll at any viewport.

## Test 5: The paper shows the served order and the marking

On the page from Test 4:

Expect:

- A Paper panel with the muted line "Question and option wording is the quiz's current wording."
- Each served page is a section headed "Page n of 2: <title>", in the order the learner was
  served them. Compare with the sitting's `served_paper` (ask the data helper to print it): page
  order, question order and option order all match it.
- The content block renders as formatted content.
- Each question's heading reads "n. question text" on its first line, with the question id under
  the text in small muted monospace, then the learner's answer. The paper has no form fields at all: no text box, select, checkbox or radio
  input, and nothing looks editable.
- The multiple-choice question lists every option as a row with a round indicator. The
  checkboxes question lists every option with a square indicator. The dropdown question also
  lists every option as rows with round indicators, not as a select.
- The long-text answer reads as plain text, line breaks kept, under a "Learner's answer" label
  with an icon, in an outlined box: a thin primary border and a light primary fill, the same box
  as a chosen option row. No answer has a thick bar down its left edge or looks like a callout or
  admonition.
- The option the learner chose is marked "Learner's answer" with an icon. Each correct option is
  marked "Correct answer" with an icon. Where the learner chose the correct option, both marks
  show and both are readable at 375px.
- Each question ends with a verdict in words with an icon: "Marked correct" or "Marked
  incorrect". The long-text question shows the learner's text and "Not marked".
- Meaning is never carried by colour alone: check the page in greyscale (or read it without the
  colours) and confirm every mark is still distinguishable by its words.
- No note callouts show for this sitting.

Then open the attempt with the unanswered question.

Expect: that question reads "Did not answer" and "Marked incorrect", and no option carries
"Learner's answer". An unanswered text question shows no empty answer block.

## Test 6: The back link returns to the Courses tab

1. On an attempt review page, click "Back to <L1 display name>".

Expect: L1's learner page opens on the Courses tab, with the URL
`learners/<L1 pk>/__tabs/courses`. The browser's Back button returns to the attempt review.

## Test 7: A sitting from before the served order was recorded

1. Open the legacy sitting of Quiz B from the Courses tab.

Expect:

- The note "This attempt predates the record of the served order. Pages, questions and options
  are shown in the quiz's current order, limited to the questions recorded as asked where that
  was recorded." shows above the pages as a callout.
- Pages, questions and options are in the quiz's authored order.
- Result reads "No pass mark" in the header, and the Summary panel's pass-mark row reads "No pass
  mark". The quick view for this sitting reads "No pass mark" for Result and for the pass mark,
  with no badge.

## Test 8: A quiz changed after the attempt

1. Open the Quiz C sitting.

Expect:

- The note "This quiz has changed since the attempt was marked. The score is the one recorded at
  submission; the marks below use the current answers." shows.
- The header Score is the score stored at submission (the Courses tab row shows the same).
- The changed question's "Correct answer" mark and verdict follow the current correct option.

## Test 9: A served item deleted since

1. Open the Quiz D sitting.

Expect:

- The note "Some items served in this attempt have since been deleted from the quiz and are not
  shown." shows.
- The stale-score note does not show.
- The deleted question appears nowhere. The remaining questions keep the numbers they were
  served with or renumber consistently with no gap that reads as a broken page; record what is
  shown.

## Test 10: Sittings that must not open

For each URL, load the page and its `/__quick-view` path directly.

1. `quiz-attempts/<pk of L1's in-progress sitting>`.
2. `quiz-attempts/<pk of a non-quiz form sitting>` (ask the data helper for one).
3. `quiz-attempts/not-a-uuid` and `quiz-attempts/<a random uuid>`.
4. `quiz-attempts` (the bare section) and `quiz-attempts/__actions/anything`.
5. L2's sitting pk under the first organisation's slug.

Expect: every one is the standard 404 page. None is a server error. None reveals the quiz title
or learner name.

## Test 11: A cohort educator cannot open another cohort's attempt

1. Log out. Log in as E.
2. Load `quiz-attempts/<L3's sitting pk>` and its `/__quick-view` path.

Expect: 404 for both. E's learners list does not show L3.

3. Still as E, open a learner in C1 who has a completed quiz sitting and open that attempt.

Expect: the quick view and the page both open.

## Test 12: Switching organisation from an attempt review

1. As the admin, open an attempt review page for L1.
2. Use the organisation switcher to switch to the second organisation.

Expect: the interface lands on the second organisation's first section (the dashboard), not on a
404 or an error. No "Quiz attempts" list page is shown.

## Test 13: Pages that share the changed partials still look right

These pages draw the quiz's question partials, which the attempt review no longer uses. Each
must look as it does on `main`. Judge each against the brand rules and the page's own existing
look on this branch's server.

1. As a learner (ask the data helper for a login), sit a page of Quiz A in the course player.
   Expect: no question id under the question text, no "Learner's answer" or "Correct answer" marks, no
   verdict line; options select and submit normally.
2. As the admin, open a course's Course content tab and preview a quiz page.
   Expect: "Correct answer" marks show as before; no question id, no "Learner's answer" marks, no
   verdict line.
3. As the learner, open the results page of a completed quiz.
   Expect: the score banner and the incorrect-answers review render as before, and the stale-score
   note shows only for the changed quiz.
4. As the admin, open the cohort report for a cohort with quiz attempts and download its PDF.
   Expect: both render with attempt numbers and scores, with no error.

## Test 14: Keyboard and screen reader basics

1. On the Courses tab, Tab to an attempt number and press Enter.

Expect: the quick view opens and focus moves into it. Escape closes it and focus returns to the
attempt number. The link's accessible name says which attempt and quiz it opens.

2. On the attempt review page, Tab through the page.

Expect: focus order is back link, then page content. The paper has no focusable form controls.
Each mark's words, and the "Learner's answer" label on a text answer, are in the accessibility
tree (inspect a question's options).
