## Names used across slices

These are the workflow's contract with the remote command. Slices 1 to 4 use them.

- **Test job names.** `unit-<K>` (K = 1..6), `playwright-<K>` (K = 1..2), and
  `standalone-<app>` with `<app>` in `panel_framework`, `icons`. Each test job sets its job `name:`
  to exactly this string. The non-test jobs in a dispatch run are `coverage` and `test-verdict`.
- **The test step.** In every test job, the step that runs pytest is named `Run tests`. Any other
  failing step in a test job means the run has no test verdict.
- **Group report artifacts.** `group-report-<job name>`, one JSONL file each, the run file the
  test runner kept at `DS_TEST_RECORD_PATH`.
- **Coverage data artifacts.** `coverage-unit-<K>`.
- **`coverage-total` artifact.** A file `coverage_total.txt` with two lines, `total=<pct>` and
  `fail_under=<n>`.
- **Steps the remote command reads by name.** In `test-verdict`: `Check every test job
  succeeded` and `Check the partition`. In `coverage`: `Check every group's coverage data is
  present` and `Check combined coverage`.
- **Standalone node IDs.** The two standalone configs set their rootdir to their own `tests/`
  directory, so their node IDs are relative to `freedom_ls/<app>/tests/` (checked:
  `components/test_icon.py::…`). The remote command adds the prefix `freedom_ls/<app>/tests/`
  to node IDs from a `standalone-<app>` report, so a local failed-only re-run accepts them.

Tests, `tests/test_check_test_partition.py` (`dev_tooling`):

- two reports whose collected sets split the collection exactly: exit 0 and the `partition:` count
  line;
- a node ID in two reports: exit 1 and a `duplicate` line naming both reports;
- a node ID in the collection but in no report: exit 1 and a `missing` line;
- a node ID in a report but not in the collection: exit 1 and an `extra` line;
- a report with no `collected` event: exit 1;
- a crash-retried report (a second `attempt` whose `collected` lists a subset) still counts the

- `tests/test_tests_workflow.py`: `test-verdict` needs every job that has a `Run tests` step,

**Touches:** claude_plugins/fls-dev/scripts/remote_full_run.py, tests/test_remote_full_run.py, tests/test_tests_workflow.py, pyproject.toml

The script (stdlib only, `# ruff: noqa: T201` like `run_tests.py`):

```python
"""Run the full test tier on GitHub Actions and print its verdict in the test runner's shape.

Dispatches the `Tests` workflow for the current branch, waits for it, and reads each test
job's group report. Prints `run: RESULT UNAVAILABLE <reason>` and exits 69 whenever GitHub
gives no test verdict, so the caller can run the tier locally instead.
"""

WORKFLOW = "tests.yml"
POLL_INTERVAL_S = 20
QUIET_HEARTBEAT_S = 60
EXIT_PASS, EXIT_FAIL, EXIT_UNAVAILABLE = 0, 1, 69  # 69 is sysexits' EX_UNAVAILABLE
FIND_RUN_ATTEMPTS = 10
FIND_RUN_INTERVAL_S = 3
RUN_LIST_LIMIT = 20
NON_TEST_JOBS = frozenset({"coverage", "test-verdict"})
TEST_STEP = "Run tests"
JOBS_STEP = "Check every test job succeeded"
PARTITION_STEP = "Check the partition"
COVERAGE_PRESENT_STEP = "Check every group's coverage data is present"
COVERAGE_CHECK_STEP = "Check combined coverage"
STANDALONE_PREFIX = "standalone-"

run_tests = ds_runner.load_run_tests()  # the generic runner, imported by path

class Unavailable(Exception):
    """No test verdict: the reason is printed and the tier runs locally."""
```

Flow of `main()`; every `Unavailable` raised anywhere ends in `report_unavailable(reason, url)`,
which cancels the run when one is in progress, prints `run: url <url>` when known, then
`run: RESULT UNAVAILABLE <reason>`, and returns 69:

1. **Settings.** Read `[tool.test_tiers.remote]` from `pyproject.toml` in the current directory:
   `start_timeout_s` (default 900) and `run_timeout_s` (default 1800), integers of at least 1; a
   wrong type is `Unavailable("[tool.test_tiers.remote] '<key>' must be an integer")`. Other keys
   are ignored here: `command` belongs to the tier definition.
2. **Preconditions** (each `Unavailable` with a reason that names the fix):
   - `git status --porcelain --untracked-files=no` prints nothing → else `tracked files have
     uncommitted changes`;
   - `git symbolic-ref --short -q HEAD` names a branch → else `HEAD is detached`;
   - `gh auth status` exits 0 → else `gh is not logged in`; `gh` missing
     (`FileNotFoundError`) → `gh is not installed`. No minimum `gh` version: 2.46.0 works.
3. **Push.** `head = git rev-parse HEAD`; `remote_tip = git ls-remote origin refs/heads/<branch>`
   (first field, empty when the branch is not on `origin`; a non-zero exit is `Unavailable("cannot
   reach origin")`). When `remote_tip == head`, skip the push. Otherwise:
   - branch `main` or `master` → `Unavailable("origin/<branch> lacks HEAD and <branch> is never
     pushed from here")`;
   - `git push origin HEAD:refs/heads/<branch>` (plus `-u` when the branch has no upstream). A plain
     push only: a branch another process rewrote on `origin` is rejected rather than overwritten,
     and that is the command's own choice, stricter than the commit helper's force-with-lease. A
     non-zero exit → `Unavailable("push rejected: <first line of stderr>")`.
4. **Dispatch.** `gh workflow run tests.yml --ref=<branch> -f run_token=<uuid4 hex>`; a
   non-zero exit → `Unavailable("gh workflow run failed: <first line of stderr>")`. Then up to
   `FIND_RUN_ATTEMPTS` times, `scaled(FIND_RUN_INTERVAL_S)` apart: `gh run list
   --workflow=tests.yml --branch=<branch> --event=workflow_dispatch --limit=20
   --json=databaseId,displayTitle,url`, taking the entry whose `displayTitle` is the token (the
   workflow's `run-name` is the token). Never found →
   `Unavailable("the dispatched run did not appear in gh run list")`. Print
   `remote: run <url>` straight away.
5. **Poll.** Every `scaled(POLL_INTERVAL_S)` seconds (reuse `run_tests.scaled`, so tests set
   `DS_TEST_TIME_SCALE=0`): `gh run view <id> --json status,conclusion,headSha,jobs,createdAt,updatedAt`.
   - On the first view, `headSha != head` → `Unavailable("run <id> tests <sha7>, not HEAD <sha7>")`.
   - A `gh run view` that fails three times in a row → `Unavailable("GitHub unreachable")`.
   - Print `remote: <job name> <status or conclusion>` for each job whose status or conclusion
     changed since the last poll, and `remote: waiting, <done> of <total> jobs done, <s> s` after
     `QUIET_HEARTBEAT_S` with no such line.
   - No job `in_progress` or completed after `start_timeout_s` from dispatch → cancel,
     `Unavailable("no job started within <n> s")`. Run not completed after `run_timeout_s` →
     cancel, `Unavailable("run exceeded <n> s")`. Cancelling is `gh run cancel <id>`; its own
     failure is reported in the reason, not raised.
   - Stop when `status == "completed"`.
6. **Download.** `gh run download <id> -D <dir> -p 'group-report-*' -p coverage-total`. A
   non-zero exit is `Unavailable("could not download the group reports")`. `<dir>` is a fresh
   `tempfile.TemporaryDirectory()` that `main()` holds open through steps 6 to 8 and removes on
   every exit, `Unavailable` included; the `.sdd-work/` log is written outside it. A group report
   with a malformed line (`json.JSONDecodeError` from `read_attempt`) is
   `Unavailable("<job> group report is malformed")`, not a traceback.
7. **Classify.** Three functions, so the verdict logic is pure and the file reading sits in
   `main()`:

   ```python
   def require_test_verdicts(jobs: list[Job]) -> None:
       """Raise Unavailable for a test job that was cancelled or skipped, or failed in a step
       other than the test step: such a job left no test verdict."""

   def require_verdict_job(jobs: list[Job]) -> None:
       """`test-verdict` fails its job check whenever a test job or `coverage` failed, which is
       a verdict. Any other failed step (the partition check, a setup step) or a cancelled
       job is not."""
       verdict_job = find_job(jobs, "test-verdict")
       if verdict_job.conclusion not in {"success", "failure"} or not failed_steps(verdict_job) <= {JOBS_STEP}:
           raise Unavailable(f"test-verdict {verdict_job.conclusion} at {first failed step other than JOBS_STEP}")

   def classify(jobs: list[Job], states: dict[str, RunState], coverage_total: CoverageTotal | None) -> Verdict:
       failed = merged failed node ids over states (standalone ones prefixed)
       if any test job failed:
           if not failed:
               raise Unavailable(f"{job.name} failed with no failed test")  # an INCOMPLETE group
           return Verdict("FAIL", failed=failed)
       coverage_job = find_job(jobs, "coverage")
       if coverage_job.conclusion == "success":
           return Verdict("PASS")
       if failed_steps(coverage_job) == {COVERAGE_CHECK_STEP}:
           return Verdict("FAIL", coverage=coverage_total)
       raise Unavailable(f"coverage {coverage_job.conclusion} at {first failed step}")
   ```

   `main()` runs `require_test_verdicts` and `require_verdict_job` on the polled jobs, then loads
   one `RunState` per test job from the download directory (`Unavailable("<job> uploaded no group
   report")` when the file is missing) and the `coverage-total` file when present, then calls
   `classify`.

   A test job that failed with only unfinished tests (the runner's `INCOMPLETE`) has no test
   verdict, so it is `UNAVAILABLE` and the tier runs locally.
8. **Merge and print.** Build one `run_tests.RunState` for printing: `collected` is the union of
   every report's collected IDs (standalone IDs prefixed), `outcomes` takes, per node ID, the
   worst outcome over the reports (`failed` over `skipped` over `passed`): the two standalone
   configs collect tests the unit pool also runs, and a failure in either must show. Then print,
   in this order:

   ```
   run: failed <id>            # run_tests.failed_set_lines(state, include_unfinished=True) on FAIL
   run: tests ... / run: summary (merged): ...   # run_tests.count_lines(state, elapsed)
   run: coverage <pct>% below <fail_under>%     # coverage failure only
   run: log <path>                               # when any test failed
   run: tested <head sha>
   run: url <url>
   run: RESULT PASS|FAIL
   ```

   `elapsed` is `updatedAt - createdAt` of the run. The log file is
   `.sdd-work/remote_full_run_<branch with "/" as "-">.txt` (directory created), holding, per
   failed node ID, the ID and the `longrepr` text from its group report. Exit 0 on PASS, 1 on
   FAIL.

   > **Assumed default:** `longrepr` text is written to the log as the test produced it, with no
   > stripping of terminal escape sequences. Why: it is the same output a local run prints, from
   > this repository's own tests on a commit the command pushed. To change: Slice 4, step 8.

`select_tests.py`:

```python
REMOTE_OFF_ENV = "DS_TEST_REMOTE"

@dataclass(frozen=True)
class TierConfig:
    ...
    # The command that runs the full tier somewhere else, or None to run it here.
    remote_command: str | None = None

def remote_command(table: dict[str, object]) -> str | None:
    """`[tool.test_tiers.remote] command`. The table's other keys belong to that command."""
    remote = table.get("remote", {})
    if not isinstance(remote, dict):
        raise ConfigError("[tool.test_tiers] 'remote' must be a table")
    value = remote.get("command")
    if value is not None and (not isinstance(value, str) or not value.strip()):
        raise ConfigError("[tool.test_tiers.remote] 'command' must be a non-empty string")
    return value
```
