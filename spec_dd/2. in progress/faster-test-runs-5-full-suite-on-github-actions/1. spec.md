# Spec: the full test suite runs on GitHub Actions on demand

Idea: `idea.md`. Answers: `answers.md`. Research: `research_*.md` beside this file.

## Purpose

A local full run of the suite takes about 25 minutes and four workers, so only one worktree can be
verified at a time. The repository is public, so standard GitHub-hosted runners cost nothing, but
the FLS `Tests` workflow has been red since 2026-10-10: the unit job hits its 15-minute cap less
than half way through, and the Playwright job cannot install its browser on `ubuntu-latest`
(Ubuntu 26.04). This spec makes the workflow pass again and split the suite across parallel jobs.
It also lets an SDD run send its full tier there, wait, and read the result in place of a local run.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| remote full run | coined | A full tier run by the project's remote command on GitHub Actions in place of the local `uv run pytest -n auto`; no existing term because every full run is local today |
| group | narrowed | pytest-split's word: one of the N slices `--splits N --group K` selects, here always one matrix job |

## Scope

In:

- `.github/workflows/tests.yml`: a manual trigger, the suite split into duration-balanced groups,
  coverage combined across groups, a completeness check, and the two current failures fixed.
- A committed durations file and the `pytest-split` dev dependency.
- An FLS remote command that pushes the branch, starts the workflow for HEAD, waits, and prints the
  result in the test runner's output shape.
- The generic `ds` tier definition and the generic `sdd` tier helper learn that a full tier may run
  remotely, through per-project configuration.

Out:

- Running targeted tiers, failed-only re-runs or single tests remotely. A failed-only re-run after
  a remote failure runs locally.
- Changing the First Class workflow.
- Claude Code cloud sessions (`faster-test-runs-7-claude-cloud-test-runs`).
- Paid or third-party runners.
- Reusing the test database or skipping migrations in CI
  (`faster-test-runs-2-reuse-test-database`).

## Decisions

- **The split is `pytest-split` by recorded duration, not path groups.** It partitions the
  collected tests, so a new app lands in a group without anyone editing the workflow. Tests absent
  from the durations file get the average duration. A stale file only unbalances groups.
- **Every test job runs on `ubuntu-24.04`.** That image is supported by Playwright 1.58, and
  pinning stops the next image change from breaking the jobs. Playwright is not upgraded. The
  `lint` and `type-check` jobs stay on `ubuntu-latest`.
- **The remote marker set is a superset of the local full tier.** It runs `ci_only`, `weasyprint`
  and `dev_tooling` tests, which the local tier partly deselects. A remote pass still counts as a
  full run.
- **Coverage is combined and enforced once.** Each unit group writes its own coverage data with no
  per-group threshold. A combine job fails below 92%.
- **The remote verdict reads the test jobs and the combine job only.** A `lint` or `type-check`
  failure shows on GitHub and does not fail a remote full run, matching what a local full tier
  checks.
- **FLS runs its full tier remotely by default.** `DS_TEST_REMOTE=off` forces a local run.
- **No usable remote verdict means a local run.** When GitHub is unreachable, the run cannot start,
  no job starts within the start budget, the run exceeds the total budget, or it ends without a
  test verdict (a cancelled job, a failed setup step, a missing report), the remote command cancels
  the run if one exists and the full tier runs locally, saying why. A test failure or a coverage
  failure never falls back.
- **The remote command pushes the branch itself** before it starts the run, following the rules in
  `claude_plugins/sdd/resources/commit_and_push.md`: never force, never `main` or `master`, and a
  rejected push is reported. A dirty tracked tree, a rejected push or HEAD on `main` that
  `origin/main` lacks has no remote verdict, so the full tier falls back to local.
- **The remote command lives in `fls-dev`, not `ds`.** It names this repository's workflow and job
  layout. The generic plugins only learn the contract it fulfils.

## Requirements

### Workflow: `.github/workflows/tests.yml`

1. Triggers: `push` to `main`, `pull_request` to `main`, and `workflow_dispatch` with no required
   inputs. A dispatch runs the workflow file of the ref it is dispatched on.
2. Concurrency: a `pull_request` run still cancels the superseded run for its ref. A
   `workflow_dispatch` run and a push to `main` are never cancelled by another run. The group
   includes `github.event_name`, plus `github.run_id` for dispatches.
3. `unit-tests` becomes a matrix over groups 1 to 6 (`fail-fast: false`, `timeout-minutes: 15`,
   `runs-on: ubuntu-24.04`). Each group:
   - runs `-m "not playwright"` with `--splits 6 --group <K> --splitting-algorithm least_duration
     --durations-path .test_durations`, under `.claude/ds/scripts/run_tests.sh`, `-n auto`, with
     `--cov` and no `--cov-fail-under`;
   - passes the same `--randomly-seed` as every other group in the run (`pytest-randomly` is
     installed; a different seed per group changes the partition);
   - installs the WeasyPrint system libraries (Pango, cairo, gdk-pixbuf, HarfBuzz) before the run;
   - uploads, under `if: always()`, its coverage data file and its group report (requirement 7)
     with a name unique to the group.
4. `playwright-tests` becomes a matrix over groups 1 and 2, with the same split flags, `-m
   playwright`, no coverage, `runs-on: ubuntu-24.04`, `timeout-minutes: 15`, the trace upload on
   failure, and the group report upload under `if: always()`.
5. `dev-tooling-tests` is removed. Its tests run inside the unit groups.
6. A `standalone-tests` job runs the two standalone configs the unit job runs today
   (`freedom_ls/panel_framework/tests/standalone_pytest.ini`, `freedom_ls/icons/tests/standalone_pytest.ini`),
   on `ubuntu-24.04`, and uploads a group report.
7. Group report: each test job uploads the test runner's record for its run. It holds the node IDs
   it collected, the failed and unfinished node IDs, and pytest's short failure text (`-rf
   --tb=short`) for each failed test. The plan picks the file format. The remote command reads
   failures only from these reports, never from scraped logs.
8. A `coverage` job (`needs` every unit group, `if: always()`) downloads every group's coverage
   data, runs `coverage combine`, writes the report to `$GITHUB_STEP_SUMMARY`, and fails under 92.
   It fails when any unit group's data is missing. `[tool.coverage.run]` gains `parallel = true`
   and `relative_files = true` in `pyproject.toml`.
9. A `test-verdict` job (`needs` every test job and `coverage`, `if: always()`) fails unless:
   every needed job succeeded; the node IDs the unit groups collected are a partition (no
   duplicate, none missing) of a single `pytest --collect-only -q -m "not playwright"` over the
   whole suite with the same seed; and the same holds for the Playwright groups. It is the one
   check name the remote command and branch protection read.
10. `setup-uv` gets `enable-cache: true` in every job. Setup is otherwise unchanged (Postgres 17
    service on port 6543, Node 20, `npm ci`, Tailwind build).

### Durations: `.test_durations`

11. A `.test_durations` file at the repository root, generated by a full `--store-durations` run
    and committed. `pytest-split` joins the dev dependencies in `pyproject.toml`.
12. The FLS testing docs name the command that regenerates it. Refreshing it is manual; nothing
    regenerates it automatically.

### FLS remote command: `claude_plugins/fls-dev/scripts/remote_full_run.py`

13. Stdlib only, driving `gh` and `git` through `subprocess`. Run as `uv run python
    claude_plugins/fls-dev/scripts/remote_full_run.py`.
14. Preconditions, each failing to `RESULT UNAVAILABLE <reason>`: the tracked tree is clean; `gh
    --version` is 2.87.0 or later (it prints the dispatched run's URL); `gh auth status` succeeds.
15. Push: when `origin` lacks HEAD, push as the push decision says. Then dispatch with `gh workflow
    run tests.yml --ref <branch>`, take the run ID from the printed URL, and check the run's
    `headSha` equals local HEAD.
16. Wait: poll `gh run view <id> --json status,conclusion,jobs` every 20 seconds. Print the run URL
    first, then one line per job state change and a line every 60 seconds without one. Two
    budgets, from `[tool.test_tiers.remote]` in `pyproject.toml`: `start_timeout_s` (default 900,
    no job started) and `run_timeout_s` (default 1800, whole run). Exceeding either runs `gh run
    cancel <id>` and prints `RESULT UNAVAILABLE <reason>`.
17. Result: download the group reports with `gh run download <id>` and print the test runner's
    reporting lines: `run: tests <n> collected, ...`, `run: summary (merged): <totals>`, one `run:
    failed <node id>` per failed test (capped as the runner caps them, `and <n> more`), `run:
    tested <sha>`, `run: url <url>`, and `run: RESULT PASS|FAIL`. A coverage failure prints `run:
    coverage <pct>% below 92%` and `RESULT FAIL` with no failed node IDs. The full failure text
    goes to `.sdd-work/remote_full_run_<branch>.txt`, printed as `run: log <path>`.
18. Any run that ends without a test verdict per the fallback decision prints `RESULT UNAVAILABLE
    <reason>` with the URL.
19. FLS opts in with `[tool.test_tiers.remote]` in `pyproject.toml`:
    `command = "uv run python claude_plugins/fls-dev/scripts/remote_full_run.py"`, plus the two
    budgets.

### Generic tier definition: `claude_plugins/django-stack/resources/test_tiers.md` and `scripts/select_tests.py`

20. The `full` tier gains a remote branch: when `[tool.test_tiers.remote] command` is set and
    `DS_TEST_REMOTE` is not `off`, run that command (in the background, as any full tier) in
    place of the local command. On `RESULT UNAVAILABLE`, quote its reason and run the local full
    command.
21. The contract a remote command meets, stated generically: it prints the runner's `run:` lines,
    `run: tested <sha>` and `RESULT PASS|FAIL|UNAVAILABLE`; it exits 0 only on `PASS`; its failed
    set is its `run: failed` lines, as for a local run. The other keys in the table belong to the
    command.
22. When `select_tests.py` resolves `tier: full` and the remote command applies, it prints the
    remote command on the `command:` line and the local command on a new `fallback:` line.
    Without a remote table, the output is unchanged.
23. Reporting and failure handling accept the remote output unchanged: `RESULT PASS` is done,
    `RESULT FAIL` with node IDs takes the failed-only re-run locally, and `RESULT FAIL` with no
    node IDs (a coverage failure) takes the whole-tier re-run.

### Generic tier helper: `claude_plugins/sdd/commands/protected/run_test_tier.md`

24. Step 3: a remote full run is recorded only when its `run: tested <sha>` equals the `sha:` that
    `full_run_record.py start` printed. A fallback local run is recorded as any local run.
    `full_run_record.py` is unchanged.
25. Step 4: the summary of a remote full run ends `(remote: <url>)`, and the summary of a fallback
    ends `(local: <reason>)`. The report line keeps its shape.

## Testing

- `tests/test_remote_full_run.py` covers the remote command with `gh` and `git` faked: each
  precondition failure; push skipped when `origin` has HEAD; `headSha` mismatch is unavailable;
  start and run budgets cancel the run; a pass, a test failure with node IDs, a coverage failure,
  a cancelled job and a missing report each print the right lines and exit code; the failed-set
  cap.
- `tests/test_select_tests.py`: `tier: full` prints `command:` and `fallback:` with the remote
  table, the local command alone without it, and the local command alone under
  `DS_TEST_REMOTE=off`.
- `tests/test_test_tiers.py` still passes; the remote command's file names no pytest flags outside
  the allowed files.
- The partition check in `test-verdict` is shown to fail on a deliberately broken split (one group
  given the wrong `--splits`) in a throwaway run, then reverted.
- The workflow passes on this branch's pull request. `workflow_dispatch` is only dispatchable once
  the file is on `main`, so the end-to-end remote full run from an SDD step is proved after merge,
  on the next spec that runs a full tier.
- Report the before and after times against `spec_dd/1. next/faster-test-runs/research_test_timings.md`:
  wall time of the workflow and of a remote full run, queue time included.

## Success criteria

- The `Tests` workflow is green on this branch's pull request, with no test job cancelled at its
  cap.
- `test-verdict` fails when a group's split flags are wrong.
- `coverage` fails when combined coverage is below 92%.
- From a clean worktree with `[tool.test_tiers.remote]` set, a full tier prints the run URL, waits,
  and ends with `RESULT PASS` and a full-run record for HEAD.
- A failing test on GitHub comes back as a `run: failed <node id>` line that the local failed-only
  re-run accepts.
- With `gh` logged out, a full tier prints the reason and runs locally.
- With `DS_TEST_REMOTE=off`, a full tier runs locally and never calls `gh`.
- `grep -ri "freedom\|fls" claude_plugins/sdd claude_plugins/django-stack` finds nothing new.
