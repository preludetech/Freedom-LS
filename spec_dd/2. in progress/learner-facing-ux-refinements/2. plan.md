# Plan: learner-facing UX refinements

Source: `1. spec.md`. Design reference: `design.md` (read as that file says; the Design section below
transcribes the two states this plan builds). Paths are relative to the repo root; `LI` is
`freedom_ls/learner_interface`.

Every slice follows TDD: write the failing test, make it pass, run the targeted tests, run
`uv run pre-commit run --all-files` (it runs `lint-imports`, `test-mirroring` and `app-map-fresh`),
commit. Template class changes need `npm run tailwind_build` before a browser or Playwright run; the
built CSS is not tracked. After the last slice, run `uv run pytest` in full and fix anything it
turns up before the final commit.

   ```python
   from collections.abc import Sequence
   from typing import TYPE_CHECKING

   from django.core.paginator import Page, Paginator

   if TYPE_CHECKING:

       from django.http import HttpRequest


   def clamped_page[T](
       request: HttpRequest,
       param_name: str,
       object_list: Sequence[T] | QuerySet[T],
       per_page: int,
   ) -> Page[T]:
       """The page of ``object_list`` that ``request.GET[param_name]`` names, clamped to a valid page.

       ``get_page`` rather than ``page``: a home page must not 500 on a stale
       bookmark or a hand-edited query string, so a junk page number clamps.

       ``get_page`` on its own clamps a non-integer to page one but clamps
       anything below page one to the *last* page (Django's ``EmptyPage``
       covers both "too high" and "too low", and ``get_page`` maps every
       ``EmptyPage`` to ``num_pages``). A below-range page number is treated
       here the same as a non-integer: it clamps to page one.
       """
       # body of today's page_for, with per_page in place of SECTION_PAGE_SIZE


   def page_href(request: HttpRequest, param_name: str, page_number: int) -> str:
       """The current URL showing ``page_number`` of one pager.

       Copies the incoming query string and touches only this pager's key, so
       every other pager's page survives the link and an unrecognised parameter
       passes through with no allowlist to maintain. Page one drops the key.
       """
       # body of today's section_page_href, unchanged: request.path plus the
       # encoded query, never a scheme or host


   def position_text(page: Page[object]) -> str:
       """The range a page shows, as every dashboard pager words it: "1 to 3 of 7"."""
       return f"{page.start_index()} to {page.end_index()} of {page.paginator.count}"
   ```

3. `alpine-components.js`, inside the existing `alpine:init` listener:

   ```javascript
   // The Back link on the course detail page. Stepping back through history
   // returns the learner to whichever page sent them here; the link's href is
   // the dashboard, used when there is no such page. document.referrer can be
   // stale after an htmx-boosted navigation, which is accepted.
   Alpine.data("historyBackLink", () => ({
       goBack(event) {
           if (!this.cameFromAnotherPageHere()) return;
           event.preventDefault();
           history.back();
       },
       cameFromAnotherPageHere() {
           if (history.length <= 1 || !document.referrer) return false;
           const referrer = new URL(document.referrer, location.href);
           return (
               referrer.origin === location.origin &&
               referrer.pathname !== location.pathname
           );
       },
   }));
   ```

   `document.referrer` is always an absolute URL or empty, so the `URL` constructor cannot throw
   here and needs no guard. The script never navigates to the referrer; it only reads it to decide
   whether to step back, and the fallback is the fixed `href`.

3. `backends.py`:

   ```python
   from django.core.paginator import Page, Paginator

   from freedom_ls.base.pagination import clamped_page, position_text

   APPLICATIONS_PAGE_SIZE = 3
   APPLICATIONS_PAGE_PARAM = "page_applications"
   APPLICATIONS_SWAP_ID = "applications-page"

   def get_dashboard_contributions(self, *, user: RequestUser) -> list[DashboardContribution]:
       """Page one of the learner's applications: with no request there is no page to read."""
       applications = list(get_active_applications(user))
       page = Paginator(applications, APPLICATIONS_PAGE_SIZE).get_page(1)
       return self._applications_panel(page, announce_page=False)

   def get_dashboard_contributions_for_request(self, *, request: HttpRequest) -> list[DashboardContribution]:
       """The signed-in user's applications, or the drafts an anonymous session holds, paged."""
       if request.user.is_authenticated:
           applications = list(get_active_applications(request.user))
       else:
           applications = list(owned_applications(request).filter(...).select_related(...).order_by("-created_at", "pk"))
       page = clamped_page(request, APPLICATIONS_PAGE_PARAM, applications, APPLICATIONS_PAGE_SIZE)
       # Only a swap of the panel's own page is announced: a whole-page load
       # already puts the heading and the position text in front of the reader.
       announce_page = request.headers.get("HX-Target") == APPLICATIONS_SWAP_ID
       return self._applications_panel(page, announce_page=announce_page)

   def _applications_panel(self, page: Page[CourseApplication], *, announce_page: bool) -> list[DashboardContribution]:
       if page.paginator.count == 0:
           return []
       return [
           DashboardContribution(
               template_name="course_applications/partials/dashboard_applications.html",
               context={
                   "applications": list(page.object_list),
                   "applications_page": page,
                   "position_text": position_text(page),
                   "announce_page": announce_page,
                   "swap_id": APPLICATIONS_SWAP_ID,
                   "page_param_name": APPLICATIONS_PAGE_PARAM,
               },
           )
       ]
   ```

   `applications` stays the rows on the current page, so the template loop, the existing
   contribution tests and the `_contributed_applications` helper keep working. The anonymous
   branch keeps its "an empty session map makes this an `IN ()` filter" comment. `swap_id` and
   `page_param_name` reach the template from the constants, so each value has one definition; the
   status region's id is the template's alone.

## Design

Two states are transcribed. `proto__proto` draws the same strip as the first artboard of
`strip__strip-states` inside a whole dashboard, so it needs no transcription of its own. The
elements transcribed are the ones the spec builds; the design's "All applications" links, counts,
action-needed highlight, deadlines and step counts are left out.

### strip__strip-states

- Screenshot: `spec_dd/2. in progress/learner-facing-ux-refinements/design_screenshots/strip__strip-states.png`
- Viewport width: 1280
- Reach: sign in as a learner with applications and open the dashboard (`/`). The first artboard
  needs at least four applications, submitted and draft mixed, so the panel pages; the second
  needs exactly one; the third none, in which case the panel is absent and the first course
  section follows the greeting.
- Elements, in order:
  1. Section heading "Your applications" (left) with, on the same row at the right, the position
     text ("1 to 3 of 7") and the previous/next control.
  2. The list, one column, each row a flat card: accent icon box at the left; title in a
     semibold weight; status chip beside the title (`Pending review` for a submitted application,
     `Incomplete` for a draft); on a draft a muted meta line under the title ("Finish your
     application to have it reviewed."); at the right a small button with a trailing arrow
     ("View my application" / "Continue application").
  3. One application: the same single row, position text "1 to 1 of 1", both arrows disabled.
  4. No applications: no panel.
- Controls in this state: previous/next (disabled at a boundary), one button per row, the title
  link.
- Design checklist:
  - [ ] Heading "Your applications" above the list, position text and arrows on the heading row at the right
  - [ ] Rows in one column, each with icon box, title, chip, optional meta line, button
  - [ ] Submitted row: `Pending review` chip and "View my application"
  - [ ] Draft row: `Incomplete` chip, meta line, "Continue application"
  - [ ] All rows styled the same; no highlighted row
  - [ ] Single application: one row, "1 to 1 of 1", both arrows disabled
  - [ ] No applications: no panel

- Screenshot: `spec_dd/2. in progress/learner-facing-ux-refinements/design_screenshots/phone__p-dash.png`
