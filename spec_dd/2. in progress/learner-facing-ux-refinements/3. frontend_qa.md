# Frontend QA: learner-facing UX refinements

Spec: `1. spec.md`. Plan: `2. plan.md` (its Design section holds the transcriptions the design
checklists below are copied from).

## §0 Setup

Start the server on a free port and use `http://127.0.0.1:$PORT` as the base URL:

```
npm run tailwind_build
uv run python manage.py runserver $PORT
```

Seeds, in this order, from the project root:

1. Demo content (the application-gated demo course and its form, the `start-here-demo` category):

   ```
   uv run python manage.py content_save ./demo_content DemoDev
   ```

2. Dashboard paging personas (`demodev_paging@email.com` has In progress and Start here sections
   that page; `demodev_empty@email.com` has nothing):

   ```
   uv run python manage.py qa_create_dashboard_paging_fixtures
   uv run python manage.py qa_extend_start_here_section DemoDev --category-slug start-here-demo --letters E,F,G,H,I,J
   ```

   The second command adds six unregistered Start here courses. Without it the paging learner is
   registered on every `start-here-demo` course and has no Start here section.

3. Six submitted applications for the paging learner, on six new application-gated courses (the
   seventh application, a draft, is made through the UI in Test 6):

   ```
   uv run python manage.py shell -c "
   from django.contrib.sites.models import Site
   from freedom_ls.accounts.models import User
   from freedom_ls.content_engine.factories import CourseFactory
   from freedom_ls.content_engine.models import Course
   from freedom_ls.course_applications.factories import CourseApplicationFactory
   from freedom_ls.course_applications.models import CourseApplication
   site = Site.objects.get(name='DemoDev')
   user = User._base_manager.get(email='demodev_paging@email.com')
   for n in range(1, 7):
       slug = f'applied-course-{n}'
       course = Course._base_manager.filter(site=site, slug=slug).first() or CourseFactory(
           site=site, title=f'Applied course {n}', slug=slug,
           access_config={'access_type': 'application_gated'})
       if not CourseApplication._base_manager.filter(site=site, user=user, course=course).exists():
           CourseApplicationFactory(site=site, user=user, course=course)
   "
   ```

4. A learner with exactly one submitted application:

   ```
   uv run python manage.py qa_create_clean_applicant --email qa.one.application@email.com
   uv run python manage.py shell -c "
   from django.contrib.sites.models import Site
   from freedom_ls.accounts.models import User
   from freedom_ls.content_engine.models import Course
   from freedom_ls.course_applications.factories import CourseApplicationFactory
   site = Site.objects.get(name='DemoDev')
   user = User._base_manager.get(email='qa.one.application@email.com')
   course = Course._base_manager.get(site=site, slug='applied-course-1')
   CourseApplicationFactory(site=site, user=user, course=course)
   "
   ```

Login: `/accounts/login/`. Every QA account's password is its email address. Sign out between
personas through the avatar menu.

Viewports: phone 375×812, tablet 768×1024, desktop 1280×800. "No horizontal scroll" means
`document.documentElement.scrollWidth <= window.innerWidth`.

## Test 1: Dashboard sections are rows on a phone

Persona: `demodev_paging@email.com`. Viewport 375.

1. Sign in and open `/`.
2. Find the "In progress" section. Expect: the heading, then a controls row with the position
   text "1 to 3 of 6" on the left and the previous/next arrows on the right, then three course
   rows stacked in one column (each row: accent icon box on the left, status eyebrow, title,
   progress bar). No card grid is visible. No "Browse all courses" anywhere in this section.
3. Find the "Start here" section. Expect the same shape with "1 to 3 of 6", and below the three
   rows a centred "Browse all courses" link with a trailing chevron. The link is not in the
   controls row.
4. Check no horizontal scroll.
5. In "In progress", click the next arrow. Expect: the three rows are replaced by the other three
   without a page reload (URL unchanged), the position text reads "4 to 6 of 6", the heading
   "In progress" is still above the controls, the next arrow is now greyed with
   `aria-disabled="true"` and the previous arrow is live, and focus has moved to the heading.
   Click previous. Expect the first three rows back and, because the previous arrow is now
   disabled, focus on the heading.
6. Scroll to the bottom. Expect every other paged section ("Recommended courses" if present,
   "Available courses", "Coming soon") to use the same row layout.

## Test 3: Dashboard sections keep the card grid on a desktop

## Test 4: A row resumes an in-progress course

Persona: `demodev_paging@email.com`. Viewport 375.

1. On `/`, in "In progress", find "Pagination C" (the course this learner has started). Expect a
   "Next up: <item title>" line under its title. Click the title. Expect to land on that item
   inside the course player, not on the course home or detail page.
2. Go back. Find a course this learner has never started (for example "Pagination B"). Expect no
   "Next up" line when it has no actionable item, and clicking the title goes to the course's
   first item or course home, never to the detail page.
3. Open `/courses/`. Expect the registered courses' rows to show the same "Next up" line and to
   link to the same targets as the dashboard rows. Unregistered courses still link to their
   detail page through the title and "Details".

## Test 5: The course detail page has a Back link

Persona: `demodev_paging@email.com`, then signed out. Viewport 1280 and 375.

1. On `/`, click "Details" on any course card. Expect the detail page to open with a "Back" link
   (left-pointing chevron and the word Back) just under the site header, where the breadcrumbs
   used to be. There is no "All courses" link and no breadcrumb trail.
2. Click Back. Expect to return to `/`.
3. Open `/courses/`, click a row's "Details", then Back. Expect to return to `/courses/`.
4. Paste a detail URL straight into a new tab. Click Back. Expect to land on `/`.
5. Sign out. Open the same detail URL directly. Expect the Back link to still render and to take
   you to `/` (the public home page).
6. Repeat step 1 and 2 at 375. Expect the Back link to be at least 44px tall and easy to tap.
7. Open a course item inside the player (any `/courses/<slug>/1/`). Expect the player's own
   breadcrumbs to be unchanged.

## Test 6: The Your applications panel pages three at a time

Persona: `demodev_paging@email.com`. Viewport 1280.

1. Open "All courses" and open the demo course "Functionality Demo - Application gated course"
   (badge "By application"). Click "Apply now", fill in the first page of the form, click Next,
   then leave for `/` without submitting. This creates the seventh application, a draft.
2. On `/`, find the "Your applications" panel above the course sections. Expect: the heading at
   the left and, on the same row at the right, the position text "1 to 3 of 7" with the
   previous/next arrows (previous greyed, `aria-disabled="true"`).
3. Expect three rows in one bordered list. The first is the draft: accent icon box, the course
   title, an "Incomplete" chip, the meta line "Finish your application to have it reviewed." and
   a "Continue application" button with a chevron. The next two are submitted: title, a
   "Pending review" chip, no meta line, a "View my application" button. All rows are styled the
   same; none is highlighted.
4. Click the next arrow. Expect: rows 4 to 6 (all "Pending review"), position "4 to 6 of 7", the
   heading still in place, the URL unchanged, and the hidden status region
   (`#applications-status`, read its text in the DOM) saying "Your applications: showing 4 to 6
   of 7". Click next again: one row, "7 to 7 of 7", next greyed. Click previous twice: back to
   "1 to 3 of 7".
5. Now page the "In progress" section forward. Expect the applications panel to stay on its
   current page (position text unchanged). Page the applications panel forward. Expect "In
   progress" to stay on page two.
6. Click a submitted row's title. Expect the application's status page. Go back. Click "View my
   application". Expect the same page. Click "Continue application" on the draft. Expect the form
   to resume where you left it.
7. Hover a row. Expect the whole row to act as the link target (cursor pointer over the title and
   the empty row space), and the button to be independently focusable with Tab.

Design state `strip__strip-states`: screenshot
`spec_dd/2. in progress/learner-facing-ux-refinements/design_screenshots/strip__strip-states.png`.
Compare the panel at 1280 against the first artboard, in the project's theme:

- [ ] Heading "Your applications" above the list, position text and arrows on the heading row at the right
- [ ] Rows in one column, each with icon box, title, chip, optional meta line, button
- [ ] Submitted row: `Pending review` chip and "View my application"
- [ ] Draft row: `Incomplete` chip, meta line, "Continue application"
- [ ] All rows styled the same; no highlighted row

## Test 9: Bad and mixed page parameters

Persona: `demodev_paging@email.com`. Viewport 1280.

1. Open `/?page_applications=junk`. Expect a 200 page with the applications panel on "1 to 3 of 7".
2. Open `/?page_applications=99`. Expect the last page, "7 to 7 of 7".
3. Open `/?page_applications=-1` and `/?page_applications=0`. Expect "1 to 3 of 7" both times.
4. Open `/?page_in-progress=2&page_applications=2`. Expect "In progress" on "4 to 6 of 6" and
   the applications panel on "4 to 6 of 7". Inspect the applications next arrow's `href`: it
   contains `page_in-progress=2` and `page_applications=3`. Inspect the "In progress" previous
   arrow's `href`: it contains `page_applications=2` and no `page_in-progress`.
5. Open `/?page_no_such_thing=5`. Expect everything on page one and a 200.
