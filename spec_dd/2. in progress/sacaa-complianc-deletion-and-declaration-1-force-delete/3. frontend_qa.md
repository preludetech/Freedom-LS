# Frontend QA: force delete and last active

Pages: the Django admin (Unfold theme) for users and learners, the force delete confirmation page,
and the educator interface's learner pages. Judge each page on this branch's server only.

## Setup

1. Start the server with the `Dev server start` command from `.claude/sdd/config.md`, on `$PORT`.
   Base URL: `http://127.0.0.1:$PORT`.
2. Seed the data. Each command is idempotent:
   - `uv run python manage.py qa_create_deadlines_seed` (superuser `demodev@email.com`, an
     organisation, a cohort, registrations, course progress records with pauses and extensions)
   - `uv run python manage.py qa_create_erase_users` (`qa_erase_blocked@email.com` with one answered
     standalone form sitting; `qa_erase_clean@email.com` with nothing)
   - `uv run python manage.py qa_create_application_review_accounts` (a staff user with view
     permissions but not superuser)
3. Ask the QA data helper for these, on the DemoDev site, each a plain verified user whose password
   is its email:
   - **Two-org learner:** `qa_fd_two_orgs@email.com` with a `Learner` in two organisations, each with
     a cohort membership, a course registration, a `CourseProgress` with a `TopicProgress` and a
     quiz `CourseFormAttempt` (with its `FormProgress` and a `QuestionAnswer` that has an uploaded
     file), plus one standalone `FormProgress` not linked to any course.
   - **Applicant:** `qa_fd_applicant@email.com`, a user, plus an unclaimed `AnonymousApplicant` with
     the same email and a submitted application.
   - **Second superuser:** `qa_fd_super@email.com`, superuser and staff.
   - **Stale learner:** `qa_fd_stale@email.com`, a learner in the educator's organisation whose
     `User.last_active` is 30 days ago and whose latest `CourseProgress.last_accessed_time` is
     yesterday.
   - **Never-active learner:** `qa_fd_never@email.com`, a learner in the same organisation with
     `last_active` null.
4. Log in at `/admin/` as `demodev@email.com` / `demodev@email.com` (superuser) unless a test says
   otherwise. Collapse the debug toolbar before screenshots.

Check each page at the three QA viewports. A page that errors (500, 400, a blank filter, a broken
layout) fails, whatever the step says.

## Test 1: The user admin has no ordinary delete

1. Go to `/admin/freedom_ls_accounts/user/`.
2. Open the action dropdown.
3. Open `qa_erase_clean@email.com`'s change page.
4. Visit `/admin/freedom_ls_accounts/user/<pk>/delete/` for that user by URL.

Checklist:
- [ ] The action dropdown offers "Force delete selected users" and "Export selected", and no
      "Delete selected users".
- [ ] The change page has no Delete link or button at the bottom.
- [ ] The change page shows a red "Force delete" button in the actions at the top.
- [ ] The delete URL answers 403.

## Test 2: Force deleting a bare user

1. On `qa_erase_clean@email.com`'s change page, click "Force delete".
2. Look at the page, then click "Force delete" with the reason empty.
3. Type only spaces in the reason and submit.
4. Type "Erasure request 2026-11" and submit.
5. Go to `/admin/freedom_ls_audit_log/auditlogentry/` and open the newest entry.

Checklist:
- [ ] The confirmation page sits inside the admin shell (sidebar, header, breadcrumb back to Users).
- [ ] It names the user, says SACAA requires records to be kept for five years, and "deactivate
      the user" links to that user's change page.
- [ ] It lists what will be deleted, counted per model (at least the user).
- [ ] It says the reason is recorded against every selected user.
- [ ] Empty and spaces-only reasons re-render the page with an error on the reason field; the user
      still exists (reload the users list).
- [ ] With a reason, the browser lands on the users list with a "Force deleted 1 user." message,
      and the user is gone.
- [ ] The audit entry reads "User force deleted", target the user's name, the reason, actor
      DemoDev's name, and no organisation.

## Test 3: Force deleting a user with records in two organisations

1. Open `qa_fd_two_orgs@email.com`'s change page and click "Force delete".
2. Expand each model's row list.
3. Submit with the reason "Erasure request".
4. In the educator interface, go to each of the two organisations' Audit log.

Checklist:
- [ ] The page lists Learner (2), Cohort memberships, Learner course registrations, Course progress
      (2), Topic progress, Course form attempts, Form progress (3: two linked, one standalone),
      Question answers, Question answer files and Legal consents if any, each with a count that
      matches the seeded data and no model twice.
- [ ] Each model is a collapsed row ending in a down chevron; opening it turns the chevron up and
      shows its rows, which scroll inside their own box when there are many.
- [ ] The rows can be opened and closed with the keyboard (Tab to the row, Enter).
- [ ] No "cannot run" message; the reason field and button show.
- [ ] After submit, the user and every listed row are gone (spot-check the Form progress and Course
      progress lists, searching by the email).
- [ ] The Django audit log list shows one "User force deleted" and two "Learner force deleted"
      entries with the same reason.
- [ ] Each organisation's educator Audit log shows one "Learner force deleted" entry for the user,
      with the reason, and does not show the other organisation's entry.

## Test 5: Several users at once, and a blocked delete

1. In the users list, tick `qa_erase_blocked@email.com` and `qa_fd_super@email.com`, choose "Force
   delete selected users" and run it.
2. Check the page, then cancel.
3. Tick them again, run the action, give a reason and submit.

Checklist:
- [ ] The page names both users and lists the counts for both together.
- [ ] Cancel goes back to the users list and deletes nothing.
- [ ] Submit removes both, the message says "Force deleted 2 users.", and the audit log has one
      "User force deleted" entry per user with the same reason.
- [ ] Force deleting another superuser is allowed.

A blocked page cannot be produced from the dev data alone; the automated tests cover it. Skip it
here.
