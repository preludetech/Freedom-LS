# Spec: organisation courses

Source: `idea.md`. Research: the `research_*.md` files beside it.

## 1. Purpose

Every course on a site is open to every organisation today. Some courses have to belong to
particular organisations: a client gets its own version of a course, independent of every other
version that shares its title. Course content declares which organisations a course belongs to and
whether outsiders may see it. Course cards say which organisation a course belongs to, so a learner
can tell same-titled versions apart.

## 2. Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| organisation course | coined | A `Course` with at least one row in `Course.organisations`. No existing term: until now a course had no organisation. |
| `CourseAudience` | coined | Who may see an organisation course: `organisation_learners` (users with an active `Learner` row in one of its organisations) or `public` (everyone). No existing term. "Members" is avoided because `OrganisationMember` means organisation staff. |
| in the audience | coined | A user may see a course: it is not an organisation course, or its `audience` is `public`, or the user has an active `Learner` row in one of its organisations, or the user is registered for it. |

## 3. Scope

In:

- `Course.organisations` and `Course.audience`, set from course frontmatter by organisation slug.
- The audience gate wherever learners find or open a course, and wherever staff register onto one.
- An organisation byline on learner-dashboard cards.
- Self-registration through the learner's own organisation.

Out:

- Anything in `freedom_ls/course_applications/`, and `Course.access_config`. Which organisation an
  approved application registers through is unchanged.
- The organisation byline on the all-courses list, the markdown embed card, completed cards and
  the course detail page.
- Reports, and per-organisation scoping of `RecommendedCourse` rules (the
  `corporate-job-course-recommendations` effort). Recommendations still pass through
  `filter_visible`, so the audience gate covers them.
- Course slug derivation. Two same-titled courses load as `foo` and `foo-2`, by load order.

## 4. Decisions

- **Content owns the link.** The frontmatter names organisation slugs, resolved per site at
  `content_save`, the way `dashboard_category` is. The Course admin shows both fields read-only.
  `Organisation.slug` is set once and never re-derived on rename, so a reference stays valid.
- **`organisation_learners` is the default audience.** An organisation course hides from outsiders
  unless its frontmatter says `audience: public`. `audience` has no effect on a course with no
  organisations; such a course stays open to everyone.
- **`public` changes the card and nothing else.** A public organisation course is seen, applied for
  and registered onto exactly like an unlinked course, from any organisation.
- **Registered users stay in the audience.** The same exemption `hidden` and `coming_soon` give, so
  a change to a course's organisations never strands a mid-course learner.
- **The M2M lives on `Course`.** This adds the edge `content_engine --> organisations`.
  `organisations` depends only on `base` and `site_aware_models`, so no cycle forms, and the loader
  that resolves the slugs lives in `content_engine`.
- **The default organisation never shows on a byline.** The same rule as
  `course_organisation_chip.html`: the default organisation stands for the site itself.

## 5. Requirements

### 5.1 Model and loader (`freedom_ls/content_engine`)

- `models/courses.py`: add `CourseAudience(models.TextChoices)` with `ORGANISATION_LEARNERS =
  "organisation_learners"` and `PUBLIC = "public"`. On `Course`, add
  `organisations = models.ManyToManyField("freedom_ls_organisations.Organisation", blank=True,
  related_name="courses")` and `audience = models.CharField(choices=CourseAudience.choices,
  default=CourseAudience.ORGANISATION_LEARNERS, max_length=...)`. Add a migration. Existing courses
  get no organisations, so they behave as before.
- `schema.py` `Course`: add `organisations: list[str]` (organisation slugs, default empty) and
  `audience: CourseAudience` (default `organisation_learners`).
- `management/commands/content_save.py` `save_course`: resolve each slug with
  `Organisation._base_manager.filter(site=site, slug__in=...)`. An unknown slug fails the load with
  an error naming the slug and the course file, like the unknown-`dashboard_category` error. Set
  the M2M to exactly the resolved set; an absent `organisations` key clears it.
- `admin.py` `CourseAdmin`: `organisations` and `audience` read-only on the change page;
  `organisations` as a changelist column and a `list_filter`, so same-titled courses can be told
  apart.

### 5.2 The audience gate (`freedom_ls/learner_management/queries.py`, `freedom_ls/course_access`)

- Add a queryset expression for "in the audience" (§2) beside `is_registered_for_course_expression`,
  and a single-course form of it. Anonymous users are in the audience only of courses that are not
  organisation courses or are `public`. Both forms share one definition, so the list rule and the
  single-course rule cannot drift.
- `backends.py` `VisibilityEnforcingBackend.filter_visible`: also exclude courses the user is not in
  the audience of. This covers the dashboard sections, the all-courses list and recommendations.
  `override_visibility_to_visible()` lifts this rule as it lifts `hidden`.
- `visibility.py`: a 404 gate for users outside the audience, applied at every view that calls
  `raise_404_if_hidden_unregistered` (course detail, course home, `initiate_course_access`,
  `_course_access_redirect`, apply, express interest).
- `learner_interface/templatetags/course_card_tags.py` `get_course_by_path`: return `None` for an
  `organisation_learners` organisation course. The tag has no viewer, so the embed card never
  shows one.

### 5.3 Registration (`freedom_ls/learner_management`, `freedom_ls/registration_rules`, `freedom_ls/learner_interface`)

- `LearnerCourseRegistration.clean()` and `CohortCourseRegistration.clean()`: refuse a registration
  onto an `organisation_learners` organisation course when the learner's (or cohort's)
  organisation is not one of the course's organisations.
- `_registerable_courses` / `registerable_courses_for` / `registerable_courses_for_learner` and
  `courses_visible_to`: leave out `organisation_learners` organisation courses not linked to the
  cohort's, learner's or viewed organisation. The educator pickers and Courses list follow.
- `registration_rules`: `RegistrationRule.clean()` refuses a rule whose course is not open to its
  organisation under the same test. `evaluation.py` creates no registration that `clean()` above
  would refuse.
- `learner_interface/views.py` `initiate_course_access`: when the user holds an active `Learner`
  row in one of the course's organisations, register through it, the earliest-created one if
  several. Otherwise register through the default organisation, as today. The audience gate has
  already refused outsiders to an `organisation_learners` course.

### 5.4 Dashboard card byline (`freedom_ls/learner_interface`)

- A new cotton component, `templates/cotton/organisation-byline.html`, takes an organisation and
  renders a muted line: the `logo` in a small fixed-height opaque `bg-surface` box with `alt=""`,
  then the name as text. Name only when there is no logo. Nothing for the default organisation.
- `partials/course_card.html`: render the byline under the title when `course.card_organisation`
  is set. Not in the status eyebrow, which stays the one place status shows.
- The dashboard annotate helpers in `views.py` stamp `card_organisation`:
  - Cards in the In progress section (`registered`, `in_progress`) for an organisation course: the
    organisation of the `Learner` row the winning registration hangs off (the studying-through
    organisation from `course_progress_by_course_for`).
  - `not_registered` and `coming_soon` cards for a course with exactly one organisation: that
    organisation. Zero or several: none.
- No query per card: prefetch `organisations` on the discovery querysets, and add
  `learner__organisation` to the `select_related` in `course_progress_by_course_for`
  (`freedom_ls/learner_progress/queries.py`).

## 6. Testing

- Loader: slugs resolve; an unknown slug fails naming slug and file; removing the key clears the
  M2M; `audience` defaults to `organisation_learners`.
- Audience predicate, both forms, over: an unlinked course; `organisation_learners` with the user
  in, out, inactive (`Learner.is_active=False`), anonymous, and registered while outside; `public`
  with an outsider and anonymous.
- `filter_visible` and each 404 chokepoint agree for every case above.
- Embed card returns nothing for an `organisation_learners` organisation course.
- `clean()` refusals on both registration models and on `RegistrationRule`; rule evaluation creates
  no refused registration; the educator pickers and `courses_visible_to` leave the course out of
  another organisation.
- `initiate_course_access` registers through the linked organisation's `Learner` row, and through
  the default organisation for a public course the user has no row for.
- Cards: byline on a single-organisation discovery card, none for zero or several; byline on an
  in-progress card shows the studying-through organisation; none for the default organisation;
  name-only fallback. A `django_assert_num_queries` test proves the dashboard query count does not
  grow with the number of cards.
- A Playwright flow: two same-titled courses for two organisations; a learner in one sees only
  theirs, with its byline.
- Amend, never delete, the tests and comments that state courses are shared across organisations:
  `educator_interface/tests/invariants/test_organisation_isolation.py:423`,
  `educator_interface/views.py:1360` and `:1518`, `learner_management/queries.py:758`, the
  `qa_register_org_course.py` docstring.

## 8. Open questions

- Should the embed card become viewer-aware, so an organisation's own course can embed another of
  its organisation courses?
- An approved application registers through the default organisation, so the learner's in-progress
  card shows no byline. Settle when course applications next change.

## 9. Success criteria

- A course whose frontmatter names organisation slugs loads with those organisations; an unknown
  slug fails the load.
- A user outside an `organisation_learners` course's audience gets it in no listing and a 404 on its
  URLs; a registered user keeps it.
- A `public` organisation course behaves like an unlinked course except for its byline.
- No admin, educator, rule or self-registration path registers an outsider onto an
  `organisation_learners` organisation course.
- Dashboard cards show the organisation byline in the cases in §5.4 and nowhere else, with no extra
  query per card.
- Every existing course with no `organisations` key behaves exactly as before.
