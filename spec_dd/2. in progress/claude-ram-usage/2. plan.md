## Test conventions for this plan

- `tests/test_run_tests.py` and `tests/test_ds_run_record.py` carry
  `pytestmark = pytest.mark.dev_tooling`, like `tests/test_reap_playwright_mcp.py`: they start
  real processes and read `/proc`. The tiers run them (`[tool.test_tiers] markers` keeps
  `dev_tooling`), and the default run skips them.
- Every test builds its subprocess environment explicitly and removes every `DS_TEST_*` variable
  it does not set, so a value inherited from an outer runner cannot change the result.
- Every test sets `DS_TEST_TIME_SCALE=0` unless it tests timing, and points
  `DS_TEST_MEMINFO_PATH` and `DS_TEST_PSI_PATH` at files in `tmp_path`.
- The runner is run as `[sys.executable, <run_tests.py>, …]` with `cwd=tmp_path`, so
  `pyproject.toml` is the test's own.
- Every test sets `TMPDIR` to `tmp_path`, so a record file the runner keeps is removed with it.
- Every test pins the settings its assertion depends on (`DS_TEST_MAX_WORKERS`,
  `DS_TEST_WAIT_TIMEOUT_S`), so the machine's CPU count and the plugin defaults cannot change
  the result.
- One behaviour per test. Where several assertions need the same expensive run (a real crashing
  pytest run), a module-scoped fixture does the run once and each test asserts one thing.
- Each slice's closing test run is `tier: targeted` over the slice's working tree, as the tier
  definition says. Slice 9 changes `pyproject.toml`, so its tier is `full`.

## Slices

### Slice 1: the test runner runs a pytest command with an xdist worker count sized to free memory

`run_tests.sh uv run pytest -n auto …` reads `MemAvailable`, appends `-n <k>`, runs the command,
prints one `ram:` line and exits with the command's exit code. Plugin defaults only.

**Builds on:** none
**Touches:** claude_plugins/django-stack/scripts/run_tests.py, claude_plugins/django-stack/templates/wrapper_scripts/run_tests.sh, .claude/ds/scripts/run_tests.sh, .claude/settings.json, tests/test_run_tests.py, tests/test_select_tests_wrapper.py, tests/test_select_tests.py

1. `templates/wrapper_scripts/run_tests.sh`: a copy of `select_tests.sh` with the script name and
   the header comment changed. The header says the runner's output and exit code are the test
   run's result. `.claude/ds/scripts/run_tests.sh` is the same file with `PLUGINS_ROOT="."`,
   executable.
2. `.claude/settings.json`: add the three allow entries for `run_tests.sh` (bare, `bash …` and
   `./…` forms), each next to its `select_tests.sh` sibling.
3. `tests/test_select_tests_wrapper.py`: parametrise its four tests over
   `(template, wrapper, plugin script)` for `select_tests` and `run_tests`. The module docstring
   names both wrappers.
4. `tests/test_select_tests.py`: add `run_tests.py` to the shebang parametrisation.
5. `run_tests.py`, with `#!/usr/bin/env python3`, `# ruff: noqa: T201` and a usage docstring:

   ```python
   # None matches any single token: the directory `uv run --directory` is given.
   ACCEPTED_PREFIXES: tuple[tuple[str | None, ...], ...] = (
       ("pytest",),
       ("python", "-m", "pytest"),
       ("python3", "-m", "pytest"),
       ("uv", "run", "pytest"),
       ("uv", "run", "--directory", None, "pytest"),
   )

   def is_pytest_command(argv: list[str]) -> bool:
       """Whether argv starts with one of the accepted forms, compared token for token.

       Bare names only: a path such as `/tmp/x/pytest` is refused, because the wrapper is
       allowed prompt-free and must not run a caller-chosen executable. The flags after the
       prefix are pytest's own and are passed through, as a direct pytest call would take them.
       """

   def run_plain(argv: list[str]) -> int:
       """Run the command as given and return its exit code."""
       return subprocess.run(argv, check=False).returncode

   def mem_available_mb(meminfo: Path) -> int | None:
       """MemAvailable in MB, or None when the file is missing (no /proc on this platform)."""

   def worker_fit(available_mb: int, reserve_mb: int, per_worker_mb: int) -> int:
       return (available_mb - reserve_mb) // per_worker_mb

   def has_worker_option(argv: list[str]) -> bool:
       """True for `-n <x>`, `-n<x>`, `--numprocesses <x>` and `--numprocesses=<x>`."""

   def main() -> int:
       argv = sys.argv[1:]
       if not is_pytest_command(argv):
           print the accepted forms to stderr; return 2
       if os.environ.get("DS_TEST_MEMORY_GUARD") == "off":
           return run_plain(argv)                 # byte-for-byte, no extra lines
       available = mem_available_mb(meminfo_path())
       if available is None:
           print("ram: no /proc/meminfo on this platform; running the command as given")
           return run_plain(argv)
       k = max(1, min(worker_fit(available, RESERVE_MB, PER_WORKER_MB), MAX_WORKERS))
       command = [*argv, "-n", str(k)] if has_worker_option(argv) else argv
       print(f"ram: MemAvailable {available} MB, xdist workers -n {k}")
       return run_plain(command)
   ```

   The snippets in this plan are sketches: `...` and prose lines stand for bodies the implementer
   writes, and every real function carries full type hints.

   `meminfo_path()` returns `DS_TEST_MEMINFO_PATH` or `/proc/meminfo`. The defaults are module
   constants named after the spec's keys (`per_worker_mb` 1024, `reserve_mb` 2048, `max_workers`
   `os.cpu_count() or 1`).

The flags after the accepted prefix are not checked. This is the decision taken at review: the
flag surface equals what the project's existing prompt-free pytest allow entries already give,
and the bare `pytest` and `python -m pytest` forms stay because the runner's own tests run real
pytest in a throwaway package.

**Tests** (`tests/test_run_tests.py`, with a stub `pytest` from `write_stub` that logs its argv):

- parametrised: fake `MemAvailable` gives the expected `-n` as the last two logged tokens (room
  for two workers gives `-n 2`; plenty gives the CPU-count ceiling; too little gives `-n 1`)
- an argv with no `-n` gets no `-n`
- the runner exits with the stub's exit code
- parametrised: each non-pytest argv (`rm -rf x`, `bash -c pytest`, `/tmp/x/pytest`,
  `uv run --with p pytest`) exits 2, logs no invocation, with the guard on and with it off
- `DS_TEST_MEMORY_GUARD=off` passes the argv byte-for-byte and prints no `ram:` line
- a missing meminfo file runs the argv as given and prints the `ram:` note
- the wrapper tests, now covering `run_tests.sh`

### Slice 2: settings come from the environment, then `pyproject.toml`, then the default; `--capacity` prints memory capacity

**Builds on:** slices 1
**Touches:** claude_plugins/django-stack/scripts/run_tests.py, tests/test_run_tests.py

1. A frozen dataclass `MemorySettings` with the seven keys of the spec's table, and a
   `sources: dict[str, str]` of the keys that are not the default (`"env"` or `"pyproject"`).
2. `load_memory_settings(project_root: Path, environ: Mapping[str, str]) -> MemorySettings`:

   ```python
   # key -> (env var, type). The table is the single list of keys; anything else in
   # [tool.test_tiers.memory] is an unknown key.
   SETTINGS: dict[str, tuple[str, type[int] | type[float]]] = {
       "per_worker_mb": ("DS_TEST_PER_WORKER_MB", int),
       ...
   }
   # A missing pyproject.toml, [tool] or [tool.test_tiers] leaves the defaults, as
   # load_tier_config does.
   table = data.get("tool", {}).get("test_tiers", {}).get("memory", {})
   not a table            -> ConfigError("[tool.test_tiers] 'memory' must be a table")
   unknown key            -> ConfigError("[tool.test_tiers.memory] unknown key '<key>'")
   wrong type (bool too)  -> ConfigError("[tool.test_tiers.memory] '<key>' must be an integer")
                             ("must be a number" for psi_some_avg10_limit)
   env var not a number   -> ConfigError("<ENV VAR> must be an integer") (or "a number")
   ```

   `psi_some_avg10_limit` accepts an int or a float; the others are integers. `per_worker_mb` and
   `max_workers` must be at least 1. `main()` turns `ConfigError` and `tomllib.TOMLDecodeError`
   into exit 2 with the message on stderr.
3. The `ram:` line gains each non-default setting and its source, e.g.
   `ram: MemAvailable 9000 MB, xdist workers -n 4 (max_workers=4 from pyproject, reserve_mb=1024 from env)`.
4. `--capacity <unit-mb>` as the first argument: print
   `max(1, (MemAvailable − reserve_mb) // unit-mb)` and exit 0. A missing meminfo file prints
   `999`. A `<unit-mb>` that is not a positive integer exits 2.

**Tests:** env beats pyproject beats default (parametrised over two keys, asserting the `-n`
that results and the source named in the `ram:` line); a wrong type, an unknown key and a
non-numeric env var each exit 2 and name the key; `--capacity` arithmetic for three fake
meminfo values including the floor of 1; `--capacity` without meminfo prints `999`.

### Slice 3: the runner waits a bounded time when memory is short

**Builds on:** slices 2
**Touches:** claude_plugins/django-stack/scripts/run_tests.py, tests/test_run_tests.py

1. `psi_some_avg10(path: Path) -> float | None`: the `avg10` of the `some` line of
   `DS_TEST_PSI_PATH` or `/proc/pressure/memory`; `None` when the file is missing.
2. `scaled(seconds: float) -> float`: `seconds * float(DS_TEST_TIME_SCALE or 1)`. Every sleep,
   poll interval and timeout goes through it.
3. The gate, called before every pytest attempt:

   ```python
   def wait_for_memory(settings: MemorySettings, ceiling: int, first_attempt: bool) -> int:
       """The xdist worker count to run with, after waiting for memory when it is short."""
       if first_attempt:
           # Worktrees started together would otherwise all read the same free figure.
           time.sleep(scaled(random.uniform(0, 5)))
       started = time.monotonic()
       announced = last_line = None
       while True:
           fit = worker_fit(...)
           psi = psi_some_avg10(...)
           if fit >= 1 and (psi is None or psi <= settings.psi_some_avg10_limit):
               if announced: print("ram: wait over after <s> s")
               return min(fit, ceiling)
           waited = time.monotonic() - started
           if waited >= scaled(settings.wait_timeout_s):
               print("ram: still short after <wait_timeout_s> s; running with -n 1")
               return 1
           print one "ram: waiting for memory (MemAvailable <n> MB, PSI <x>)" line when the
               wait starts, then one every scaled(60) s
           time.sleep(scaled(5))
   ```

   `ceiling` is `max_workers` on the first pytest attempt. Slice 5 passes the halved value on a
   retry. `main()` now takes `k` from `wait_for_memory`; the inline sizing line from slice 1 is
   removed, so the fit is computed in one place.
4. The launch `ram:` line gains the PSI figure (`PSI n/a` when the file is missing).

**Tests** (meminfo and PSI files in `tmp_path`; `DS_TEST_WAIT_TIMEOUT_S` and
`DS_TEST_TIME_SCALE` both set, so the whole wait takes well under a second):

- memory too low for one worker for the whole wait: the output has the start line, at least one
  heartbeat line and the timeout line, and the stub pytest was run with `-n 1`
- PSI above the limit with plenty of memory waits; PSI under it does not
- a missing PSI file does not wait
- memory that becomes sufficient during the wait (a background thread in the test rewrites the
  meminfo file) ends the wait with the end line and the sized `-n`

### Slice 4: the record plugin writes what a pytest attempt collected and finished, and can restrict a run to listed node ids

**Builds on:** none
**Touches:** claude_plugins/django-stack/scripts/ds_run_record.py, tests/test_ds_run_record.py

`ds_run_record.py` is a pytest plugin, loaded with `-p ds_run_record` from `PYTHONPATH`. It
imports only the stdlib and `pytest`.

```python
def pytest_addoption(parser: pytest.Parser) -> None:
    group = parser.getgroup("ds_run_record")
    group.addoption("--ds-record", default=None)        # the JSON-lines record file
    group.addoption("--ds-only-nodeids", default=None)  # a file of node ids, one per line

def pytest_collection_modifyitems(config: pytest.Config, items: list[pytest.Item]) -> None:
    """Deselect every item not listed. Runs on xdist workers too: collection happens there,
    and every worker must collect the same set."""
    # config.hook.pytest_deselected(items=dropped); items[:] = kept

class Recorder:
    """Appends one JSON line per event and flushes it, so a killed run loses nothing written."""
    # {"event": "collected", "nodeids": [...]}
    # {"event": "outcome", "nodeid": "...", "outcome": "passed|failed|skipped"}
    # {"event": "crashed", "nodeid": "..."}
    # {"event": "finished", "exitstatus": 1}

    # `node` is an xdist type, which cannot be imported when xdist is absent.
    @pytest.hookimpl(optionalhook=True)
    def pytest_xdist_node_collection_finished(self, node: object, ids: list[str]) -> None: ...
    def pytest_collection_finish(self, session: pytest.Session) -> None: ...
    def pytest_runtest_logreport(self, report: pytest.TestReport) -> None: ...
    def pytest_sessionfinish(self, session: pytest.Session, exitstatus: int) -> None: ...

def pytest_configure(config: pytest.Config) -> None:
    # A process with `workerinput` is an xdist worker: the controller sees every report, so
    # recording there too would write each outcome twice.
    if config.getoption("--ds-record") and not hasattr(config, "workerinput"):
        config.pluginmanager.register(Recorder(...))
```

Outcome rules, in `pytest_runtest_logreport`:

- a report whose `longreprtext` matches `worker '.+' crashed while running` writes a `crashed`
  line and nothing else
- a node id is written once: the recorder keeps the set of node ids already final
- final at the `teardown` report, with the outcome of the worst phase seen (`failed` over
  `skipped` over `passed`)
- final earlier, at a `setup` or `call` report that is not a pass

**Tests** (`tests/test_ds_run_record.py`; each runs real pytest as `python -m pytest` in a
`tmp_path` package with its own `pytest.ini`, `PYTHONPATH` set to the plugin's directory and
`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`, so the repository's `addopts` and plugins do not apply):

- a pass, a failure, a setup-time skip and a teardown error each give one outcome line with the
  expected outcome
- the collected line lists every node id once, without xdist and with `-p xdist -n 2`
- `--ds-only-nodeids` runs only the listed tests, without xdist and with `-p xdist -n 2`
- the plugin loads and records with xdist absent (autoload off, no `-p xdist`)
- an xdist worker writes nothing: with `-n 2` each outcome appears once
- a session that ends on its own writes one `finished` line, also when `-x` stopped it early

### Slice 5: a crashed pytest attempt is retried for its unfinished tests only, and the run ends in one verdict

**Builds on:** slices 3, 4
**Touches:** claude_plugins/django-stack/scripts/run_tests.py, tests/test_run_tests.py

1. **Command building.** Every pytest attempt appends
   `-p ds_run_record --ds-record=<file>`, plus `-n <k> --max-worker-restart=0` when the argv has
   a worker option. The child environment gets the scripts directory prepended to `PYTHONPATH`.
   The record file is one file per run, made with `tempfile.mkstemp(prefix="ds_run_record_",
   suffix=".jsonl")` (close the descriptor it returns); its path is printed once, in a
   `run: record <path>` line after the launch `ram:` line. The runner deletes it after
   `RESULT PASS` and keeps it after any other verdict, for reading. The runner itself appends
   `{"event": "attempt", "n": <n>, "k": <k>}` before each pytest attempt, so one file holds the
   whole run.
2. **Reading the record.**

   ```python
   @dataclass
   class RunState:
       collected: set[str]           # union over pytest attempts
       outcomes: dict[str, str]      # node id -> final outcome; the first one written wins
       crashed_reports: int          # crashed lines in the latest pytest attempt
       session_finished: bool        # the latest pytest attempt wrote its finished line
       crash_retried: bool = False   # any pytest attempt of this run crashed

       def unfinished(self) -> set[str]:
           return self.collected - self.outcomes.keys()

   def read_attempt(record: Path, state: RunState) -> None: ...
   ```

   A truncated last line (the controller died mid-write) is skipped: catch
   `json.JSONDecodeError` for the last line only.
3. **Classification** after each pytest attempt:

   ```python
   # A session that finished on its own with tests unfinished stopped on purpose (-x,
   # --maxfail). Only a crashed worker or a killed controller is a crash.
   crashed = state.crashed_reports > 0 or not state.session_finished
   collection_lost = crashed and not state.collected   # the controller died before collection
   ```

   The exit code is not used to detect a crash: `uv run` turns its child's death by signal into
   an ordinary exit code.
4. **Retry loop.**

   ```python
   BACKOFF_S = (30, 60)
   k = wait_for_memory(settings, settings.max_workers, first_attempt=True)
   only: set[str] | None = None          # None runs the command as given
   for attempt in range(1, settings.max_retries + 2):
       returncode = run_attempt(argv, k, only)
       read_attempt(record, state)
       if not crashed: break
       state.crash_retried = True
       # A worker that died after its test's outcome was final leaves nothing to re-run.
       if not collection_lost and not state.unfinished(): break
       if attempt == settings.max_retries + 1: break
       only = None if collection_lost else state.unfinished()
       backoff = BACKOFF_S[min(attempt - 1, len(BACKOFF_S) - 1)]
       ceiling = max(1, math.ceil(k / 2))
       print(f"run: pytest attempt {attempt}/{settings.max_retries + 1} crashed "
             f"({len(state.unfinished())} tests unfinished); backing off {backoff} s, "
             f"retrying with -n {ceiling}")
       time.sleep(scaled(backoff))
       k = wait_for_memory(settings, ceiling, first_attempt=False)
   ```

   A retry writes the unfinished node ids to a second temporary file, passes
   `--ds-only-nodeids=<file>`, and appends `--no-cov` when
   `importlib.util.find_spec("pytest_cov")` is not `None` (the runner and the pytest it starts
   share one environment when both go through `uv run`; a comment says so). The node-id file is deleted when the
   run ends. With `collection_lost`, the retry runs the whole command again with no
   `--ds-only-nodeids`. The `-n <k>` in the crash line is the ceiling; the gate may choose
   fewer.
5. **Verdict and exit code.**

   | Condition | `run: RESULT` | Exit |
   | --- | --- | --- |
   | No pytest attempt crashed, pytest exit 0 | `PASS` | 0 |
   | No pytest attempt crashed, pytest exit 1 | `FAIL` | 1 |
   | No pytest attempt crashed, pytest exit 2 to 5 | `FAIL` | pytest's code |
   | A crash was retried; any outcome is `failed` | `FAIL` | 1 |
   | A crash was retried; no failure, tests still unfinished | `INCOMPLETE` | 75 |
   | A crash was retried; every collected test finished, none failed | `PASS` | 0 |

   > **Assumed default:** a run with both a genuine failure and tests still unfinished after the
   > last retry ends `FAIL`, exit 1, not `INCOMPLETE`. Why: a known defect is something to fix,
   > and the `unfinished` count on the `run: tests` line still shows the memory problem. To
   > change: the verdict table in slice 5.

6. **The four closing lines**, last in the output, in the spec's wording. `xdist workers` lists
   the `k` of each pytest attempt joined with ` -> `. The merged summary counts come from
   `state.outcomes`, so a test counts once however many pytest attempts ran; its seconds are the
   summed wall time of the pytest attempts, without waits and back-offs.

**Tests** (real pytest, same isolation as slice 4, run as `pytest …` with `-p xdist -n auto` in
the argv, `DS_TEST_TIME_SCALE=0`, `DS_TEST_MAX_WORKERS=4`, fake meminfo with room for four
workers):

- a module-scoped fixture runs a package in which one test SIGKILLs its own xdist worker when a
  marker file is absent, and creates the file first. Separate tests assert: the run ends
  `RESULT PASS` with exit 0; the `xdist workers` line reads `4 -> 2`; the crash line names the
  number of unfinished tests; the merged summary's `passed` is the package's test count, written
  as a literal; the record file is gone
- a second fixture, the same package plus one genuinely failing test. Separate tests assert:
  `RESULT FAIL` with exit 1; the failing test has exactly one outcome line in the kept record
- a test that SIGKILLs its worker every time, `DS_TEST_MAX_RETRIES=1`: `RESULT INCOMPLETE`,
  exit 75, and the crash line reads `pytest attempt 1/2 crashed`
- a `-x` run whose first test fails ends `RESULT FAIL` after one pytest attempt
- a run with no crash prints the four closing lines and one `run: record` line
- a retry carries `--no-cov` (asserted through a stub `pytest` that crashes by signal on its
  first call and logs its argv)

### Slice 6: test processes are the OOM killer's first choice, and nothing outlives a pytest attempt

**Builds on:** slices 5
**Touches:** claude_plugins/django-stack/scripts/run_tests.py, tests/test_run_tests.py

1. `run_attempt` starts pytest with `subprocess.Popen(..., start_new_session=True,
   preexec_fn=functools.partial(set_oom_score, settings.oom_score_adj))`.
   `set_oom_score(value: int) -> None` writes the value to `/proc/self/oom_score_adj` in the
   child, before exec, and catches `OSError`: the score is best effort, and an error raised
   there would stop the run with an opaque message. `oom_score_adj = 0`, or a platform
   without that file, passes no `preexec_fn`. The runner's own score is never written.
2. `become_subreaper() -> None`, called once at start-up on Linux:

   ```python
   PR_SET_CHILD_SUBREAPER = 36
   # A browser a test launched detaches from its worker. As subreaper the runner inherits it
   # when the worker dies, so it can still be found and killed.
   libc = ctypes.CDLL(None, use_errno=True)
   # prctl is variadic and takes unsigned longs; a bare int would be passed as a C int.
   libc.prctl.argtypes = [ctypes.c_int] + [ctypes.c_ulong] * 4
   libc.prctl(PR_SET_CHILD_SUBREAPER, 1, 0, 0, 0)
   ```

   A return of -1 is ignored: the cleanup below then misses detached processes, and the run
   is otherwise unaffected.
3. `descendants(pid: int) -> list[int]`: read `/proc/<n>/stat` for every numeric entry, take the
   parent pid from the field after the last `)` (a command name can contain spaces and
   brackets), and walk the tree. A `/proc/<n>` that vanishes mid-scan (`FileNotFoundError`,
   `ProcessLookupError`) is skipped.
4. `kill_descendants() -> None`, called when each pytest attempt ends, before memory is read
   again:

   ```python
   deadline = time.monotonic() + 5
   while (pids := descendants(os.getpid())) and time.monotonic() < deadline:
       for pid in pids:
           try:
               os.kill(pid, signal.SIGKILL)
           except ProcessLookupError:
               pass                      # it exited between the scan and the kill
       reap_children()                   # waitpid(-1, WNOHANG) until it returns (0, 0)
       time.sleep(0.05)                  # or raises ChildProcessError
   ```

   The scan repeats because a process can fork between one scan and its kill. The deadline is
   real time, not `scaled`, so a test with `DS_TEST_TIME_SCALE=0` still cleans up.
5. SIGINT and SIGTERM handlers: `kill_descendants()`, delete the node-id file when one exists,
   then exit `128 + signum`.

**Tests:**

- with `DS_TEST_OOM_SCORE_ADJ` unset, the pytest child's `/proc/self/oom_score_adj` (written to
  a file by a stub pytest) is 500
- with `DS_TEST_OOM_SCORE_ADJ=700`, the child's score is 700: a value other than the default, so
  a score inherited from an outer runner cannot make the assertion pass by accident
- the runner's own score, read from `/proc/<runner pid>/oom_score_adj` while a stub pytest holds
  the run open, equals the test process's
- `DS_TEST_OOM_SCORE_ADJ=0` leaves the child's score equal to the runner's
- a throwaway test starts a detached grandchild (`start_new_session=True`, `sleep 300`) and
  writes its pid to a file: after the runner exits, that pid is gone
- SIGTERM to the runner while a stub pytest sleeps: the runner exits 143 and the stub's pid is
  gone
- SIGTERM during a retry leaves no node-id file in `TMPDIR`
