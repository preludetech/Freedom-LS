# Spec: memory-aware test runs and SDD fan-out

## Purpose

Parallel SDD batches and parallel pytest runs exhaust RAM on the developer machine. When that
happens an xdist worker or the whole run is killed, and the agent restarts the full tier from
scratch. Sometimes the kernel kills something worse: a Claude session, the browser or the VM.
After this work, a test run sizes its worker count to the memory that is free when it starts. It
waits a bounded time when memory is short. It recovers from a worker crash by re-running only the
tests that never finished. SDD fan-out starts no more units than memory allows.

Inputs: `idea.md`, `answers.md` and the `research_*.md` files in this directory.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| test runner | coined | The generic script `run_tests.py` that wraps one pytest command: memory gate, worker sizing, crash recovery, verdict. No existing term; `select_tests.py` only chooses the command. |
| attempt | coined | One pytest process the test runner starts. The first attempt runs the command; a later one re-runs unfinished tests. |
| unfinished test | coined | A test the attempt collected that has no final report: the test running on a worker when it crashed, and every test queued behind it. |
| memory capacity | coined | The number of units of a given size that fit in free memory now, as printed by `run_tests.py --capacity`. |

## Scope

In:

- A test runner in the `django-stack` plugin that every tier run goes through.
- Memory-aware worker count, bounded wait, crash detection, retry of unfinished tests only, a
  single verdict.
- Memory capacity check before SDD batch waves and before the fan-out recipe's parallel workers.
- FLS values for the thresholds.

Out:

- Splitting the suite into checkpointed sections. The crash retry is the resume (`answers.md`).
- A lock or queue shared across worktrees. Each run checks memory for itself (`answers.md`).
- Dev servers and Playwright MCP browsers started by QA.
- macOS and Windows memory readings. On a platform without `/proc/meminfo` the runner skips the
  gate and sizing and says so.
- The single-test TDD run (`uv run pytest <file>::<test> -x --no-cov`) stays a bare pytest call.
- CI. `.github/workflows/tests.yml` keeps calling pytest directly.

## Decisions

- **Gate on free memory, size workers by it.** This is the root-cause fix. Retry is only the
  safety net.
- **`MemAvailable` sizes, PSI gates.** Swap in use is ignored: this machine has 20 GB swapped at
  idle, so a swap-used threshold would wait forever. `some avg10` from `/proc/pressure/memory`
  catches thrashing that `MemAvailable` misses. When the file is absent, the runner gates on
  `MemAvailable` alone.
- **The runner passes an explicit `-n <k>`.** It replaces `-n auto` in the command it is given.
  The root `conftest.py` hook `pytest_xdist_auto_num_workers` (cap 4) stays for CI and bare
  `-n auto` runs. An explicit `-n` bypasses that hook, so FLS sets `max_workers = 4` in pyproject
  to keep tier runs at the same ceiling.
- **`--max-worker-restart=0`.** xdist's own restart brings a replacement worker up under the same
  pressure. Failing fast hands recovery to the runner.
- **Completion is recorded by a pytest plugin the runner loads, not `--lf`.** `--lf` reruns
  genuine failures and misses tests queued behind a crash.
- **Test processes volunteer as OOM victims.** The runner writes `oom_score_adj` before starting
  pytest, and every child inherits it. The kernel then kills a restartable test worker before a
  Claude session, the browser or the VM.
- **Fan-out capacity is a hook in the SDD config.** The `sdd` plugin cannot call `django-stack`
  scripts directly, so a project points `.claude/sdd/config.md` at a command that prints memory
  capacity. A blank hook means no check.

## Requirements

### Test runner: `claude_plugins/django-stack/scripts/run_tests.py`

Stdlib only, like `select_tests.py`. Wrapper `claude_plugins/django-stack/templates/wrapper_scripts/run_tests.sh`
(installed by `ds:init` as `.claude/ds/scripts/run_tests.sh`, same shape as `select_tests.sh`).
Usage: `run_tests.sh <pytest command…>` or `run_tests.sh --capacity <unit-mb>`.

**Configuration.** Precedence: env var, then `[tool.test_tiers.memory]` in `pyproject.toml`, then
the plugin default. Read and validated the way `load_tier_config` in `select_tests.py` validates
`[tool.test_tiers]`: a wrong type or unknown key exits 2 and names the key.

| Key | Env var | Default | Meaning |
| --- | --- | --- | --- |
| `per_worker_mb` | `DS_TEST_PER_WORKER_MB` | 1024 | Memory one xdist worker needs |
| `reserve_mb` | `DS_TEST_RESERVE_MB` | 2048 | Memory left free for everything else |
| `max_workers` | `DS_TEST_MAX_WORKERS` | `os.cpu_count()` | Ceiling on `-n` |
| `psi_some_avg10_limit` | `DS_TEST_PSI_LIMIT` | 10.0 | Wait while `some avg10` is above this |
| `wait_timeout_s` | `DS_TEST_WAIT_TIMEOUT_S` | 600 | Longest wait before running with 1 worker |
| `max_retries` | `DS_TEST_MAX_RETRIES` | 2 | Crash retries after the first attempt |
| `oom_score_adj` | `DS_TEST_OOM_SCORE_ADJ` | 500 | Written to `/proc/self/oom_score_adj`; 0 skips |

`DS_TEST_MEMORY_GUARD=off` runs the command unchanged: no gate, sizing, retry or extra lines.

**Gate and sizing**, before every attempt:

1. Before the first attempt only, sleep a random 0 to 5 s, so worktrees started together don't
   all read the same free figure.
2. `fit = floor((MemAvailable − reserve_mb) / per_worker_mb)`. When `fit ≥ 1` and PSI is under its
   limit, run with `k = min(fit, max_workers)`, or on a retry `min(fit, max_workers, ⌈previous k / 2⌉)`.
3. Otherwise wait. Poll every 5 s. Print one line when the wait starts, then one every 60 s, then
   one when it ends. When `wait_timeout_s` passes, run with `k = 1` and say so.
4. A command without `-n` is run without a worker count; the gate still applies.

**Each attempt:**

- Starts pytest in its own session (`start_new_session=True`) with `-n <k> --max-worker-restart=0`,
  `-p ds_run_record` (`PYTHONPATH` gains the scripts directory) and the record path.
- When the attempt ends, kills whatever is left of its process group, such as leaked Chromium,
  before memory is read again. SIGINT or SIGTERM to the runner does the same, then exits.

**Record plugin: `claude_plugins/django-stack/scripts/ds_run_record.py`.** On the controller it
appends JSON lines to the record file, flushing each one:

- the collected node ids, from `pytest_xdist_node_collection_finished` (or `pytest_collection_finish`
  without xdist);
- one line per test with its final outcome, written from `pytest_runtest_logreport`;
- a `crashed: true` flag on a report whose longrepr carries xdist's worker-crash text (check the
  exact text against xdist 3.8.0).

With `--ds-only-nodeids=<file>` it deselects every collected item not in the file, in
`pytest_collection_modifyitems`, so a retry keeps the command's markers, paths and options.

**Classification** after each attempt:

- **Crash**: the record has a crashed report, or pytest died from a signal (return code < 0),
  or collected tests are missing a final outcome. The unfinished tests are retried; genuine
  failures already recorded are kept and never retried.
- **No crash**: the attempt's results are final.
- When the controller died before collection was recorded, the next attempt runs the whole
  command again.

**Retry.** Up to `max_retries` times: back off 30 s, then 60 s, then run the gate again, then run
the unfinished tests through `--ds-only-nodeids`. Retries add `-p no:cov`, because a subset run
must not fail a coverage threshold.

**Output.** Every runner line starts with `ram:` or `run:`, has no colour, and gives counts rather
than node-id lists. The full detail goes in the record file, and its path is printed once. The
lines are:

- At launch: one `ram:` line with `MemAvailable`, PSI, the chosen `k` and where each non-default
  setting came from.
- On a crash: `run: attempt <n>/<max_retries + 1> crashed (<unfinished> tests unfinished); backing off <s> s, retrying with -n <k>`.
- At the end, last in the output:

  ```
  run: attempts <n>, workers <k1> -> <kn>
  run: tests <collected> collected, <finished> finished, <failed> failed, <unfinished> unfinished
  run: summary (merged): <n> passed, <n> failed, <n> skipped in <s>s
  run: RESULT PASS|FAIL|INCOMPLETE
  ```

Exit codes: PASS 0. FAIL 1. INCOMPLETE 75, when retries ran out with tests still unfinished. That
is neither a pass nor a code defect. Any other pytest exit code (2 to 5) with no crash passes through.

**`--capacity <unit-mb>`** prints one integer, `max(1, floor((MemAvailable − reserve_mb) / unit-mb))`,
and exits 0. Without `/proc/meminfo` it prints a large number (fail open).

### `select_tests.py` and the tier docs

- `claude_plugins/django-stack/scripts/select_tests.py`: `FULL_COMMAND` and `TARGETED_PREFIX`
  start with the runner wrapper, e.g.
  `command: .claude/ds/scripts/run_tests.sh uv run pytest -n auto --no-cov …`. The printed line
  stays deterministic; memory is read only at run time.
- `claude_plugins/django-stack/resources/test_tiers.md`:
  - The full tier and the `--lf` re-run in "When a targeted run or full run fails" go through the
    runner.
  - "Reporting" quotes the `run: summary (merged)` line and the `RESULT` line, not pytest's own
    last line. `INCOMPLETE` is reported as blocked on memory, not as a failure to fix.
  - The settings table and precedence live here, once.
  - Say that a crash retry happens inside the one background run, so the "no `ps`/`pgrep` loops, no
    `timeout` wrapper" guardrail is unchanged.
- `claude_plugins/sdd/commands/protected/run_test_tier.md`: the blank-hook fallback still runs bare
  `uv run pytest`. The report uses the `RESULT` line when one is present.

### SDD fan-out

- `.claude/sdd/config.md` template in `claude_plugins/sdd/commands/init.md`, under
  `## Worktree Scripts`, gains:
  - `Memory capacity:` a command taking a unit size in MB and printing memory capacity
  - `Batch memory (MB):` the size of one batch: its subagent, Setup script and targeted test run
  - `Subagent memory (MB):` the size of one read-only worker

  Init documents each key next to `Parallel batches`.
- `claude_plugins/sdd/commands/implement_plan.md` **Batch waves**: the batch wave becomes the
  first `min(len(ready), cap, capacity)` of `ready`. `capacity` is the `Memory capacity` command's
  output for `Batch memory (MB)`, read just before each wave forms. A blank hook or a blank size
  means `capacity` is unbounded. A wave of one is unaffected. A batch that dies from memory still
  counts against the existing two-retry budget.
- `claude_plugins/sdd/skills/claude-code-authoring/resources/fanout_recipe.md` point 4 (one worker
  per unit, in parallel): spawn at most `capacity` workers at once, sized by
  `Subagent memory (MB)`, and spawn the next unit as each one returns. Commands that restate the
  recipe follow the same rule: `spec_from_idea.md`, `spec_review.md`, `plan_from_spec.md`,
  `roadmap.md`.

### FLS values

- `pyproject.toml` `[tool.test_tiers.memory]`: `max_workers = 4`, and `per_worker_mb` set from a
  measurement: the peak RSS of one xdist worker plus its Chromium during a full-tier run, rounded
  up to the next 256 MB.
- `.claude/sdd/config.md`: `Memory capacity: .claude/ds/scripts/run_tests.sh --capacity`, plus
  measured `Batch memory (MB)` and `Subagent memory (MB)`.

## Testing

- `tests/test_run_tests.py`, using the stub-tool pattern in `tests/stub_tools.py` with a fake
  meminfo, a fake PSI file and a stub `uv`/pytest:
  - worker count from free memory, capped by `max_workers` and floored at 1
  - wait and its heartbeat lines; after the timeout it runs with 1 worker
  - PSI above the limit waits; a missing PSI file does not
  - env beats pyproject beats default; a bad or unknown key exits 2 naming it
  - `DS_TEST_MEMORY_GUARD=off` runs the command byte-for-byte
  - `--capacity` arithmetic and fail-open
- Crash recovery, against a real pytest run on a throwaway test package in `tmp_path`, where one
  test `os._exit`s or `SIGKILL`s its own worker on the first attempt only:
  - the retry runs only the unfinished tests with half the workers
  - a test that genuinely failed in attempt 1 is not re-run and the verdict is FAIL
  - all tests recovered gives PASS, exit 0
  - retries exhausted gives INCOMPLETE, exit 75
  - the merged summary counts every test exactly once
- `ds_run_record.py`: `--ds-only-nodeids` deselects the rest under xdist and without it.
- Process group: a child the test leaves running is gone when the attempt ends.
- `tests/test_select_tests.py`: the expected `command:` strings gain the runner prefix.
- `tests/test_test_tiers.py`: the allowlist changes only if a newly edited markdown file spells
  out `uv run pytest`.
- New tests are `dev_tooling`, like the existing plugin-script tests.

## Open questions

- The plugin defaults (`per_worker_mb` 1024, `reserve_mb` 2048, PSI limit 10) are assumed. FLS
  replaces the first with a measurement; the other two are reasonable for any project but not
  measured.
- Whether a Claude Code subagent is its own OS process (and so worth sizing) is unverified. If
  measurement shows subagents cost little, `Subagent memory (MB)` stays blank in FLS and the
  recipe change is inert.

## Success criteria

- With `MemAvailable` too low for one worker, a full tier waits, prints a heartbeat each minute,
  and after `wait_timeout_s` runs with `-n 1`.
- With room for two workers, the `ram:` line shows `-n 2` even though `max_workers` is 4.
- A run whose worker is SIGKILLed once ends `RESULT PASS` with every test counted once, and does
  not re-run the tests that finished.
- A run with a genuine failure and a crash ends `RESULT FAIL`, and the failing test ran once.
- `cat /proc/<pytest pid>/oom_score_adj` during a tier run prints 500.
- `implement_plan` with `Parallel batches: 3` and capacity 1 runs a wave of one.
- `grep -rn "freedom\|fls" claude_plugins/django-stack/scripts/run_tests.py claude_plugins/django-stack/scripts/ds_run_record.py` finds nothing.
- `uv run pytest -m dev_tooling tests/test_run_tests.py tests/test_select_tests.py` passes.
