# Frontend QA: FLS on the installed panel framework

The panel framework's templates, scripts and stylesheet now come from the installed
`django-panel-framework` package instead of `freedom_ls/panel_framework/`. Nothing should look or
behave differently. This run checks that every panel-framework page still renders with FLS's look,
that FLS's template overrides still win, and that the stylesheet still carries the framework's
rules.

Substitute the literal port number from `.claude/ds/scripts/find_available_port.sh` wherever this
document writes `$PORT`. Shell variables do not survive between tool calls. Never use the dev
server's default port.

Viewports for every layout check: 375×812, 768×1024, 1920×1080.

QA never checks out, builds, migrates or runs `main` or the `main` worktree. Every page is judged
against the checklists in this file, on this branch's server.

## §0 Setup

### 0.1 Build and server

1. `uv run python manage.py migrate`. It must finish with no `NodeNotFoundError`.
2. `npm run tailwind_build`. It must finish with no error. Afterwards `tailwind.panel_framework.css`
   exists, `git status` does not list it, and both paths inside it point into a `panel_framework`
   directory that exists on disk (under `.venv/lib/python3.13/site-packages/`, or an absolute path
   to a package worktree when one is linked).
3. `ls freedom_ls/panel_framework` must fail: the in-tree app is gone.
4. `.claude/ds/scripts/find_available_port.sh`: note the number and use it literally from here on.
5. Start the dev server with the `Dev server start` command from `.claude/sdd/config.md` on that
   port, backgrounded, as its own call.
6. Open `http://127.0.0.1:$PORT/` and confirm `#debug-branch-badge` names
   `extract_panels_framework-5-package-and-install`. If not, go back to step 4.

### 0.2 Data and login

1. `uv run python manage.py content_save demo_content DemoDev`.
2. Log in as `demodev@email.com` (password = email).
3. Through `sdd:qa-data-helper`, make sure one cohort has at least 25 learners, so its learner
   table paginates and can be bulk-selected.

## §1 Panel pages render from the installed package

### 1.1 Pages

Visit each page at all three viewports. Collapse the Django debug toolbar first

### 1.2 Checklist for each page

- The page is styled: panels sit as cards on the page background, and no element shows as unstyled
  browser-default HTML. An unstyled table, toolbar or dialog means the stylesheet lost the
  framework's rules.
- Buttons have the FLS look. Inspect one inside a panel: its class list holds `btn`, not
  `panel-btn`. This proves FLS's `panel-button` override still wins over the package's template.
- Icons are FLS's icon set, drawn at the same size as the text beside them. Inspect one: it comes
  from FLS's `panel-icon` override, not the package's bundled Heroicons fallback.
- Status chips and applied-filter chips are coloured pills.
- Table footers show "Previous" and "Next" at 375 wide and numbered pages from 768 up.
- Dialogs open centred with a dimmed backdrop from 768 up, and as a bottom sheet at 375 wide.
- The selection bar slides in when rows are selected and its actions menu opens.
- No horizontal scrollbar at any viewport.
- The browser console shows no error, no 404 for a file under `/static/panel_framework/`, and no
  Alpine warning about an undefined component.

### 1.3 Behaviour that crosses the package boundary

1. On a cohort's learners table, select three rows and run a bulk action through to its result.
   The run completes and the table refreshes. This writes a `BulkActionRun` row to the new
   `panel_framework_bulkactionrun` table.
2. Run the same bulk action again right away on the same rows. It must complete or report a clean
   message; no server error.
3. Open a create dialog, submit it empty, and confirm the validation errors render inside the
   dialog (HTTP 422, dialog stays open).
4. Open a quick view, then press Escape and confirm it closes and focus returns to its trigger.
5. Sort and filter a table, then reload the page: the URL keeps the state and the table renders
   the same rows.

## §2 The component reference page

The dev server runs with `DEBUG` on, so `config/urls.py` includes the package's URLs.

1. Visit `http://127.0.0.1:$PORT/panel-framework/components/` as the logged-in staff user, at all
   three viewports.
   - It returns 200 and renders inside FLS's own page chrome (FLS's header and navigation), which
     proves FLS's reference base template still overrides the package's.
   - Scroll to the dialogs and the tables. Each example is styled; the §1.2 checklist applies.
   - The console shows no error and no Alpine warning.
2. Log out and visit the same URL. It redirects to the admin login.
3. Visit `http://127.0.0.1:$PORT/panel-framework/does-not-exist/`. It returns FLS's 404 page.

## §3 The legacy table is gone

1. `uv run python manage.py shell -c "from django.db import connection; t = connection.introspection.table_names(); print('freedom_ls_panel_framework_bulkactionrun' in t, 'panel_framework_bulkactionrun' in t)"`
   prints `False True`.
2. `uv run python manage.py showmigrations panel_framework educator_interface` lists
   `panel_framework 0001_initial` and `educator_interface 0001` to `0004`, all applied.
3. `http://127.0.0.1:$PORT/admin/` loads for the admin user with no server error, and the
   permissions list on a user's admin page holds no entry for an app labelled
   `freedom_ls_panel_framework`.
