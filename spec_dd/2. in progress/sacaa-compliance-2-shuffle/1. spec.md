# Spec: shuffle quiz pages, questions and answer options

Idea: `idea.md`. Up-front answers: `answers.md`. Research: `research_codebase.md`,
`research_best_practices.md`, `research_reference_implementations.md`, `research_prior_art.md`,
`research_ux_patterns.md`, `research_known_complaints.md`, `research_randomization_ux_integrity.md`.

## Purpose

A QUIZ form serves every learner the same order, so learners can pass "question 3 is B" to each
other. Authors get three independent opt-in knobs that shuffle pages, page children and answer
options once per sitting. Two controls keep a shuffled quiz correct: an option lock and a
keep-together group. The shuffled order goes into the served paper that
`sacaa-compliance-1-served-paper-record` built. The learner side already renders from the served
paper, so most of this work is building a shuffled paper and the authoring chain that feeds it.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| keep-together group | coined | The `FormContent` and `FormQuestion` items on one page that share a `group` value. They form one contiguous run and move as one block. |
| shuffle unit | coined | One entry in a page's shuffle. It is either a keep-together group or a single ungrouped child. `sacaa-compliance-3-question-pools` draws the same units. |
| locked option | coined | A `QuestionOption` with `locked: true`. It keeps its authored index while the other options shuffle. |

"Sitting" means `FormProgress` and "served paper" means `FormProgress.served_paper`, as in the
domain glossary.

## Scope

In:

- Form-level knobs `shuffle_pages`, `shuffle_questions` and `shuffle_options`, the option
  `locked` flag and the `group` key on content blocks and questions: schema, models, migration,
  validator, `content_save` and admin.
- Shuffling inside `build_served_paper`.
- The results-page "Question N" label, which shows the served number.
- The `fls-content` authoring documentation and a shuffled demo quiz.

Out (per the idea): the served-paper storage, path, navigation, resume and scoring
(`sacaa-compliance-1-served-paper-record`); question pools (`sacaa-compliance-3-question-pools`);
the educator per-attempt view and the export of the served order
(`sacaa-compliance-4-attempt-review`); shuffling on non-QUIZ forms; per-page or per-question knob
overrides; page locks; shuffling inside a group; a positional-wording lint; any learner-facing
"this quiz is shuffled" notice; any hint on the educator preview.

## Decisions

- **The seed drives the shuffle, and the stored lists stay the record.** The existing 63-bit
  `secrets` seed in the served paper seeds a private `random.Random` for each scope:
  `f"{seed}:pages"`, `f"{seed}:page:{page.id}"` and `f"{seed}:options:{question.id}"`. Separate
  scopes mean editing one page does not reorder another, and each scope can be tested alone.
  `random.shuffle` output is not stable across Python versions, so nothing rebuilds an order from
  the seed. The module-level `random` functions and `random.seed()` are never used.
- **A group is a string, not a model** (`answers.md`). A `group` value may appear in only one
  contiguous run per form. That rule makes "nested" impossible to write, so it needs no separate
  check. Contiguity and staying on one page are validator rules.
- **Groups are allowed when `shuffle_questions` is off** (`answers.md`). There they are a no-op,
  and question pools will draw them as units.
- **The knobs are form-level only** (`answers.md`). `FormPage` forbids extra keys, so a knob in a
  page header already fails the schema.
- **No page lock** (`answers.md`). With `shuffle_pages` on, every page moves.
- **The served paper keeps spec 1's shape** (`seed`, `pages[{id, children}]`, `options`). Group
  membership is read from the model rows and is not copied into the paper.
- **A lock keeps the absolute authored index.** The free options fill the remaining slots in
  shuffled order. They are not shuffled-then-swapped, which would bias the order.

## Requirements

### Schema (`freedom_ls/form_engine/schema.py`)

- `Form`: add `shuffle_pages`, `shuffle_questions` and `shuffle_options`, each `bool = False`. A
  plain `bool` dumps `False`, so removing a key from the file resets the stored value.
  `validate_quiz_fields` raises when any of them is `True` on a non-QUIZ strategy, in that
  method's existing wording: `shuffle_options should only be set when strategy is QUIZ (in <path>)`.
- `QuestionOption`: add `locked: bool = False` beside `correct`.
- `FormContent` and `FormQuestion`: add `group: str | None`. A value that is empty after
  stripping, or that has leading or trailing whitespace, is a schema error. Its maximum length
  matches the model field.

### Models and migration (`freedom_ls/form_engine/models.py`)

- `Form`: three `BooleanField(default=False)` fields, with help text in the style of
  `submit_on_exit`.
- `FormContent` and `FormQuestion`: `group = CharField(max_length=100, blank=True, default="")`.
- `QuestionOption`: `locked = BooleanField(default=False)`.
- One new `form_engine` migration of plain `AddField` operations. Existing rows take the opt-out
  defaults.
- `form_engine/admin.py`: add each field to the explicit `fields`/`fieldsets` lists that hold its
  siblings (`submit_on_exit`, `slug`, `correct`).

### Validator (`freedom_ls/content_engine/validate.py`)

A new pass, `validate_form_shuffle`, is appended to the cross-file passes in `validate()`. It finds
forms and their page files the same way `validate_form_conditions` does. It reports every error in
one run, using the header, field, problem and fix block of `_condition_error`. Generalise that
helper's header. Do not copy it. Rules and wording:

| Rule | Problem / fix |
| --- | --- |
| `group` on an item of a non-QUIZ form | `group is only allowed on QUIZ forms (this form is <strategy>).` / `Remove group, or change the form's strategy to QUIZ.` |
| `locked: true` on an option when the form's `shuffle_options` is off | `option "<text>" is locked, but shuffle_options is off for this form, so it never moves.` / `Set shuffle_options: true in the form front matter, or remove locked.` |
| A group value on two pages | `group "<name>" is used on page "<A>" and page "<B>". A group stays on one page.` / `Rename one of the groups, or move its items onto one page.` |
| A group value in two runs on one page | `group "<name>" is split: <item label> sits between its items.` / `Move the items together, or give <item label> the same group.` |

Item labels come from `_target_label`. A one-member group is valid. So is a group with no content
block, or one that starts with a question. The existing QUIZ ban on `when` stays as it is.

### Shuffle unit and shuffle functions (`freedom_ls/form_engine/served_paper.py`)

- `shuffle_units(children)`: a pure function over items that have a `group` attribute. A maximal
  run of consecutive children with the same non-empty `group` becomes one unit, in authored order.
  Every other child is a one-element unit. The validator uses it on schema items to find split
  groups. `build_served_paper` uses it on model rows. Question pools will import it.
- `shuffle_with_locks(items, is_locked, rng)`: locked items keep their index, and the rest are
  shuffled into the free slots. If every item is locked, or only one is free, the order is
  unchanged.
- Neither function touches the database or global random state. The RNG is passed in.

### Building the served paper (`build_served_paper`)

`ensure_served_paper` still builds the paper once, when the sitting starts:

- The pages come from `form.pages.all()`, and are shuffled with the pages-scope RNG when
  `form.shuffle_pages` is on.
- Each page's children are `shuffle_units(page.children())`. When `form.shuffle_questions` is on,
  the units are shuffled with that page's RNG. Either way they are then flattened, and members keep
  their authored order.
- Each question's options are `shuffle_with_locks(options, lambda o: o.locked, rng)` with that
  question's RNG when `form.shuffle_options` is on, and authored order otherwise.
- When all three knobs are off, no RNG is created and the paper equals today's.
- The "provenance only" comment changes to say that the seed drives the one-time shuffle and that
  nothing rebuilds from it.

### Results page (`learner_interface/templates/learner_interface/course_form_complete.html`)

The incorrect-answer label at line 105 (`Question {{ item.question.question_number }}`) shows the
question's served number, which is the number the learner saw. It comes from
`path.question_positions()`, carried on each item that `FormProgress.get_incorrect_quiz_answers`
returns (that method already receives `path`). The list is in served order. Cohort reports,
`reports/indexes.py` question numbers and the `data-testid` values in `question.html` keep the
authored `question_number`. A report covers many sittings, and those sittings have different
orders.

Nothing else on the learner side changes. `SittingPath`, `page_flow`, `paging` and the
`{% question_options %}` tag already follow the served paper. The three option templates loop
over it with no CSS reordering, so DOM order equals visual order. The educator preview and
answer-key lists use `full_path` and keep authored order.

## Testing

- `shuffle_with_locks`: for every seed in a fixed range, the output is a permutation and every
  locked item is at its authored index. Cover: no locks, all locked, one free, a lock at the first
  index, a lock at the last index, two adjacent locks, a lock in the middle. A stub RNG proves the
  free items fill the free slots in shuffled order. A fixed-range distribution check over three
  free options puts each of the six orders inside a wide band.
- `shuffle_units`: runs become units, singletons stay singletons, members keep authored order.
  Over a seed range, shuffled units leave every group contiguous and in order.
- `build_served_paper`: each knob alone and all three together; the paper is the same when all
  knobs are off, and an RNG that raises when used proves no RNG is touched. Scope isolation:
  turning one knob off, or adding a question to page 1, leaves the other scopes' orders unchanged
  for the same seed. A group on a page with `shuffle_questions` off stays in authored order.
- Validator: one test per rule in the table, plus valid cases: a one-member group, a group with
  `shuffle_questions` off, a lock with `shuffle_options` on. A knob on a non-QUIZ form fails the
  schema. A knob in a page header fails the schema. Removing a knob or `locked` from a file and
  re-saving resets it. Removing `group` resets it to `""`.
- Learner flow on a real shuffled paper with the seed fixed by patching the seed source, never
  `random`: page sequence, child order, numbers and option order in all three input types match the
  paper. They stay the same across reload, back-navigation, an HTMX page post and resume. Page-jump
  links and `record_page_reached` follow served position. A retake gets a new paper. The results
  label shows the served number. Score and `max_score` equal those of the same answers on an
  unshuffled sitting.
- The rendered option order equals the paper's order, and no `order` style is present.

## Documentation and downstream

- `claude_plugins/fls-content/skills/content-types/resources/form-files.md`: add the three knobs to
  the FORM table and the QUIZ example. Add `group` to the FORM_QUESTION and FORM_CONTENT tables
  and `locked` to the options table. Add a "Shuffling a quiz" section modelled on the `when`
  section. It covers the rules from the validator table and the "lock it or reword it" order for
  "All of the above" and "None of these". It also says:
  - a lock fixes a position, not a meaning ("Both A and B" still breaks);
  - shuffled forms have no "see question 3", "the diagram above" or option-letter references;
  - a stimulus is grouped with its questions;
  - instructions go in the form body when `shuffle_pages` is on;
  - authored page numbers show in URLs;
  - shuffling is not proctoring.

  It notes that QTI and Open edX call the lock `fixed`. Check
  `content-types/SKILL.md` and the plugin `README.md` for field summaries that need the new keys.
- Demo content: a new course, `demo_content/functionality_demo_shuffled_quiz/`, with one QUIZ
  form. All three knobs are on. One "All of the above" option is locked. One page holds a group
  made of a content block with a picture and its two questions, next to ungrouped questions, and
  there are at least three pages. The existing demo quizzes are not changed, so their QA keeps the
  authored order.
- Upgrade notes: a migration with defaulted fields, so downstream projects need no action and
  their existing quizzes behave as before.

## Open questions

- Q: Should the served paper record group membership for the audit view? → A: No. Groups are read
  from the model rows (assumed default: this keeps spec 1's paper shape and no consumer needs it
  yet; `sacaa-compliance-4-attempt-review` can add it. Overrule by editing Decisions.)
- Q: Should the results page list the correct and selected options in served order? → A: No, they
  stay in authored order (assumed default: they are lists of answers, not an option group, and the
  learner is not choosing from them. Overrule by editing Results page.)
- Q: Should the demo be a new course or a quiz added to an existing demo course? → A: A new course
  (assumed default: existing demo quizzes and their QA keep the authored order. Overrule by editing
  Documentation and downstream.)

## Success criteria

- With every knob off, `build_served_paper` returns authored order and touches no RNG. Existing
  quiz tests pass unchanged.
- With `shuffle_pages`, `shuffle_questions` and `shuffle_options` on, the learner sees the page
  order, child order and option order stored in the paper, and the same order after a reload,
  back-navigation or resume.
- Locked options keep their authored index on every seed tested. Group members stay contiguous
  and in authored order on every seed tested.
- `content_validate` rejects each case in the validator table with the given wording, and rejects
  a knob on a non-QUIZ form.
- The results page shows "Question N", where N is the number the learner saw.
- The demo course `functionality_demo_shuffled_quiz` loads through `content_save` and shows a
  different order on two sittings with different seeds.
- `form-files.md` documents every new key and the shuffling rules.
