# Frontend QA: Application review states

Start the server with `uv run python manage.py runserver $PORT`. Base URL `http://127.0.0.1:$PORT`.
Log in at `/accounts/login/` with the credentials under `## QA Login` in `.claude/sdd/config.md`, or as the
applicant accounts below. Check every page at phone (375px), tablet and desktop widths: no horizontal scroll, buttons
on one line, chips readable.

## Data

Ask the QA data helper for (state names are `CourseApplication.state` values; approve and reject go through
`freedom_ls.course_applications.transitions.approve_application` / `reject_application` with an `is_staff` actor, never
a raw update, so the audit entries exist):

1. Applicant A (verified account) with **submitted** applications on two application-gated courses that have a form
   (call them Course F1 and Course F2), and nothing else.
2. Applicant B (verified account) with: one **approved** application (Course F3); one **rejected** application
   (Course F4) whose message is `Thanks for applying.\nWe need more detail about your experience.<script>alert(1)</script>`;
   one **draft** on Course F5.
3. One **unclaimed** anonymous application on an application-gated course, rejected with a short message. Note its
   status URL and claim link, and the anonymous session that holds it (apply anonymously in a private window, submit,
   then reject it through the service).
4. An application-gated course with **no** form (Course N), where Applicant A has no application.

## Test 1: Withdraw a submitted application, then apply again

1. As Applicant A, open the dashboard. The "Your applications" panel lists F1 and F2 with a "Waiting for review" chip
   and "View my application".
2. Click "View my application" for F1. Expect: heading "Your application", chip "Waiting for review", "Your
   application for F1 is waiting for review. The decision will show here.", "Submitted <date>" (e.g. "3 Nov 2026"),
   and a "Withdraw application" button. The browser tab title includes "Waiting for review". The old sentence "You
   will be notified once a decision has been made" is gone.
3. Click "Withdraw application". A dialog opens: title "Withdraw your application?", body "Your application for F1 is
   waiting for review. If you withdraw it, nobody will review it. You can apply again later.", buttons "Keep
   application" (left) and "Withdraw application" (right, destructive styling). Focus is inside the dialog.
4. Press Tab repeatedly: focus stays inside the dialog. Press Escape: the dialog closes and focus is back on the
   "Withdraw application" trigger. Nothing changed.
5. Open it again and click "Keep application": closes, nothing changed.
6. Open it again and click "Withdraw application". Expect the page to reload with toast "Application withdrawn.",
   heading "You withdrew your application", chip "Withdrawn", "You withdrew your application for F1 on <date>.
   Nobody will review it.", an "Apply again" button and no "Withdraw application".
7. Go back in the browser to the pre-withdraw page and click "Withdraw application" → confirm again (repeat
   submission). Expect the status page with "This application can no longer be withdrawn." and the withdrawn state.
8. Open the dashboard. F1 is no longer in the panel; F2 still is.
9. Open F1's course detail page. The CTA reads "Apply again" with a link "View your previous application" under it.
   Click the link: it reaches the withdrawn status page. Go back and click "Apply again": you land on the first form
   page of a new application. The dashboard now lists F1 again with "Not submitted" and "Continue application".
10. Visit the old withdrawn application's form page URL (`/…/application/<old pk>/page/1/`) and try to change and save
    an answer. Expect: it renders read-only or redirects to the status page; the answer is not saved.

## Test 2: Withdraw a draft

1. As Applicant B, open the dashboard. F5 shows "Not submitted", the "Finish your application to have it reviewed."
   hint and "Continue application".
2. Click "Continue application". Expect F5's status page (not the form): heading "Your application", chip "Not
   submitted", "You started your application for F5 but have not submitted it.", a "Continue application" button and
   a "Withdraw application" button.
3. Click "Continue application": you land on the form page where you left off. Go back.
4. Click "Withdraw application". The dialog body reads "Your application for F5 is a draft. If you withdraw it, nobody
   will review it. You can apply again later." Confirm. Expect "You withdrew your application" and "Apply again".
5. Open F5's first form page URL and try to save an answer: the page is read-only or redirects to status; nothing is
   saved. Open its check-your-answers URL: no submit button, no Edit links and no "Nothing is sent until…" intro; the
   page ends with "You withdrew this application, so it can no longer be changed." and a "Your application" button.
   Open a rejected application's check-your-answers URL: no Edit links, and the notice reads "A decision has been made
   on this application, so it can no longer be changed." (never "You will hear back once it has been reviewed").
6. In a private window, start an anonymous application on a gated course with a form, leave it as a draft, and open
   its status URL: you are redirected into the form (unclaimed drafts keep the redirect).

## Test 3: Approved and rejected status pages

1. As Applicant B, open the dashboard. Order: draft F5 first, then approved F3 and rejected F4 (newest first between
   those two). F3 shows "Approved" and "View my application". F4 shows "Not approved", the hint "Decision on <date>.
   Read the reviewer's message.", "View my application" and "Apply again". The row does not show the message itself.
2. Open F3's status page. Heading "Your application was approved", chip "Approved", "Your application for F3 was
   approved on <date>.", a "Back to dashboard" button, no withdraw.
3. Open F4's status page. Heading "Your application was not approved", chip "Not approved", "…was not approved on
   <date>.", then a "Message from the reviewer" callout showing the two lines on separate lines and the
   `<script>alert(1)</script>` text shown literally (no alert fires), then "You can apply again." and "Apply again".
4. Click "Apply again" on F4: a new application starts. Back on the dashboard, F4's rejected row is gone, replaced by
   the new "Not submitted" row.
5. Open F3's course detail page: CTA "View my application" (approved counts as active). Visit
   `/…/apply/<F3 slug>/` directly: redirected to the approved status page; no new application.

## Test 4: Ownership and refused withdraws

1. As Applicant A, take F2's status URL. Log in as Applicant B and open it: 404.
2. Signed out, open F2's status URL: redirected to the login page; after logging in as A you land on F2's status page.
3. As B, using browser devtools, submit a POST form to A's `…/status/<F2 pk>/withdraw/` (copy the CSRF token from a
   page): 404, and F2 is still "Waiting for review" for A.
4. Open `…/status/<F2 pk>/withdraw/` with a GET: 405.

## Test 5: Unclaimed rejected application

1. In the anonymous session that holds the unclaimed rejected application, open its status URL. Expect "Check your
   email" and the claim notice first, then the "not approved" state block with the reviewer's message. No "Withdraw
   application" and no "Apply again".
2. In the same session open the course detail page: CTA "View my application". Click it: the status page.
3. Follow the claim link and claim it. On the status page the "Apply again" action now shows.

## Test 6: No-form course

1. As Applicant A, open Course N's detail page and click "Apply now"; confirm on the "Apply to N?" page. Expect the
   status page in the submitted state with "Submitted <date>" and a withdraw button.
2. Withdraw it, then apply again from the course page: the confirmation page appears again and a second submission
   lands as "Waiting for review".

## Test 7: Check your answers after a state change

1. As Applicant A, open the new F1 draft, fill in every required answer and reach "Check your answers". In a second
   tab, open that application's status page and withdraw it.
2. Back in the first tab, click Submit. Expect a redirect to the status page showing "You withdrew your application";
   the application is not submitted.
3. Start another application and submit it normally. Toast: "Your application for F1 has been submitted and is
   waiting for review." Dashboard row: "Waiting for review".

## Test 8: Django admin

1. Log in as the admin and open the course applications changelist. A state column shows each row's state label and
   a state filter replaces the old "submitted" filter. Filter by "Withdrawn": only withdrawn rows remain.
2. Open one application: state is shown read-only; there is no save, add or delete.
