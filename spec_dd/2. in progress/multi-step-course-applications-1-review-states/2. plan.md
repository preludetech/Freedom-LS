## Decisions the plan takes

Status labels render with `<c-panel-status-badge tone=… label=…>`: the brand guide uses it for a record's state on any screen, learner-facing ones included (`.claude/skills/brand-guidelines/visual.md`). It is a cotton component, so `course_applications` takes no Python dependency on `panel_framework`. The dashboard panel's existing `<c-chip>` status labels move to it too.

> **Assumed default:** the panel and API N+1 tests measure the one-row count with `CaptureQueriesContext` and assert the several-row run with `django_assert_max_num_queries(one_row_count)`. Why: the testing skill forbids exact query counts; this still proves "no per-row query". To change: Slices 5 and 7.

> **Assumed default:** `CourseApplication.State` members carry the chip copy as their labels (`"Not submitted"`, `"Waiting for review"`, `"Approved"`, `"Declined"`, `"Withdrawn"`), so the chip, the page title and the admin filter read `get_state_display` and the words live in one place. Values stay `draft`, `submitted`, `approved`, `rejected`, `withdrawn`. Why: one source for the plain-language state names. To change: Slice 1, `State`.

> **Assumed default:** the course CTA's "View your previous application" link needs two new optional fields on the core `CourseAccessDecision`, `secondary_cta_label` and `secondary_cta_url` (both default `None`), rendered by `learner_interface/course_detail.html` as a `variant="link"` button under the main CTA. They name no access type, so core stays ignorant of applications. Why: the decision object has no slot for a second link today. To change: Slice 3.

> **Assumed default:** an unclaimed applicant whose application is closed sees "View my application" as the course CTA, not "Apply again". Why: only a claimed applicant can apply again, and `_anonymous_apply` sends an unclaimed one to the status page anyway. To change: Slice 3, `_gated_decision`.

> **Assumed default:** without JavaScript the withdraw button POSTs straight away, with no confirm step. Why: the spec gives exactly this fallback; the panel-framework rule about no-JS confirm pages governs educator pages, not this learner page. To change: Slice 2.

> **Assumed default:** `course_applications` gains two runtime edges, to `organisations` (the `organisation` FK and
> `get_default_organisation`) and to `audit_log` (`record_entry`). Neither app imports `course_applications`, so there
> is no cycle; the app map is regenerated by the documentation hooks. Why: the spec's organisation field and audited
> decisions need them. To change: Slices 1 and 4.

## Shared shapes

### `transitions.py`

```python
"""The only code that changes a CourseApplication's state.

Each function locks the row, refuses a move the current state does not allow,
writes the new state and its timestamp, and copies what it wrote onto the
instance it was given. A refused call writes nothing.
"""

ALLOWED_FROM: Mapping[CourseApplication.State, frozenset[CourseApplication.State]] = {
    State.SUBMITTED: frozenset({State.DRAFT}),
    State.WITHDRAWN: OPEN_STATES,
    State.APPROVED: frozenset({State.SUBMITTED}),
    State.REJECTED: frozenset({State.SUBMITTED}),
}

# The one timestamp each move writes; approve and reject share decided_at and
# the state says which decision it was.
STAMP_FIELD: Mapping[CourseApplication.State, str] = {
    State.SUBMITTED: "submitted_at",
    State.WITHDRAWN: "withdrawn_at",
    State.APPROVED: "decided_at",
    State.REJECTED: "decided_at",
}


def _move(
    application: CourseApplication,
    to: CourseApplication.State,
    *,
    extra: Mapping[str, str] | None = None,
    actor: User | None = None,
    require_user: bool = False,
) -> CourseApplication:
    with transaction.atomic():
        # _base_manager so the lock works with no request site (reviewer tools,
        # management commands); the pk comes from an instance the caller already
        # fetched through a site-scoped lookup. No select_related: FOR UPDATE
        # refuses the nullable joins.
        locked = CourseApplication._base_manager.select_for_update().get(pk=application.pk)
        if locked.state not in ALLOWED_FROM[to]:
            raise ApplicationStateError(current_state=locked.state)
        if require_user and locked.user_id is None:
            raise UnclaimedApplicationError
        from_state = locked.state
        stamp_field = STAMP_FIELD[to]
        locked.state = to
        setattr(locked, stamp_field, timezone.now())
        for name, value in (extra or {}).items():
            setattr(locked, name, value)
        written = ["state", stamp_field, *(extra or {}), "updated_at"]
        locked.save(update_fields=written)
        for name in written:
            setattr(application, name, getattr(locked, name))
        if actor is not None:
            record_entry(
                action=f"application.{to}",
                actor=actor,
                target=application,
                target_label=f"{application.course.title} application {application.pk}",
                organisation=application.organisation,
                subjects=(application.course,),
                details={"from": from_state, "to": to},
            )
    return application
```

Public functions are one-liners over `_move` (signatures exactly as the spec's table). `reject_application`
validates the message before calling `_move` (strip; empty or `> REJECTION_MESSAGE_MAX_LENGTH` raises
`RejectionMessageError`) and passes `extra={"rejection_message": stripped}`: the stripped text is what is checked
against the cap and what is stored. `approve_application` passes
`require_user=True`. Only approve and reject pass `actor`.

```python
class ApplicationTransitionError(Exception):
    """A state change the application cannot make."""

class ApplicationStateError(ApplicationTransitionError):
    def __init__(self, *, current_state: str) -> None:
        self.current_state = current_state
        super().__init__(f"Application is {current_state}.")

class UnclaimedApplicationError(ApplicationTransitionError): ...
class RejectionMessageError(ApplicationTransitionError): ...
```

```python
def _first(states: frozenset[str]) -> Case:
    """Sorts rows in `states` ahead of every other row."""
    return Case(When(state__in=states, then=Value(0)), default=Value(1))
```

   ```python
   @require_POST
   def withdraw_application(request: HttpRequest, pk: UUID) -> HttpResponse:
       """Close the applicant's own open application.

       Only a claimed application can be withdrawn: an unclaimed one gets a
       404, because its applicant has not yet proven the address.
       """
       status_url = reverse("course_applications:status", kwargs={"pk": pk})
       found = _owned_application(request, _status_applications(request), pk, next_url=status_url)
       if isinstance(found, HttpResponse):

       if not found.is_email_verified:

       try:
           transitions.withdraw_application(found)
       except ApplicationStateError:
           messages.info(request, "This application can no longer be withdrawn.")
       else:
           messages.success(request, "Application withdrawn.")
       return redirect(status_url)
   ```
