## Slices

### Slice 1: `attribution-touches` list and detail with `updated_since`

A `referral_data` key reads its site's touches, oldest `recorded_at` first, and can checkpoint on
`recorded_at`.

**Builds on:** none
**Touches:** freedom_ls/referral_tracking/api.py, freedom_ls/api/scopes.py, freedom_ls/referral_tracking/tests/test_api.py

`freedom_ls/referral_tracking/api.py`:

```python
class RecordedAtFilterSet(django_filters.FilterSet):
    # Touches and conversions are append-only; recorded_at is stamped when the
    # row is written, so it never moves backwards relative to rows already read.
    updated_since = AwareIsoDateTimeFilter(
        field_name="recorded_at",
        lookup_expr="gte",
        help_text="Rows whose recorded_at is at or after this instant.",
    )


class AttributionTouchApiSerializer(serializers.ModelSerializer):
    user_email = serializers.EmailField(source="user.email", read_only=True)

    class Meta:
        model = AttributionTouch
        # key_hash is withheld: it is an internal dedup key, not attribution data.
        fields = (
            "id", "user", "user_email", "advert_code", "referral_code",
            "utm_source", "utm_medium", "utm_campaign", "utm_content", "utm_term",
            "landing_path", "occurred_at", "recorded_at", "recorded_via",
        )
        read_only_fields = fields


class AttributionTouchFilterSet(RecordedAtFilterSet):
    class Meta:
        model = AttributionTouch
        fields: list[str] = []


class AttributionTouchApiViewSet(ReadOnlyApiViewSet):
    queryset = AttributionTouch._base_manager.select_related("user")
    cursor_field = "recorded_at"
    filterset_class = AttributionTouchFilterSet
    required_scope = ApiScope.REFERRAL_DATA
    serializer_class = AttributionTouchApiSerializer


router.register("attribution-touches", AttributionTouchApiViewSet, basename="attribution_touch")
```

`RecordedAtFilterSet` carries no `Meta.model`, like `UpdatedSinceFilterSet` in
`freedom_ls/api/filters.py`.

`freedom_ls/api/scopes.py`: append `AttributionTouch` to `_DESCRIPTIONS[ApiScope.REFERRAL_DATA]`
(`"ReferralCode, ReferralCodeHit, SignupAttribution, FirstTouchCount, AttributionTouch"`).

Tests in `freedom_ls/referral_tracking/tests/test_api.py`:

- Add a `RESOURCES` param `id="attribution_touches"` (`api:attribution_touch_list`,
  `api:attribution_touch_detail`, `AttributionTouchFactory`, `"AttributionTouch"`, the 14-field
  set). The exact-set check proves `key_hash` is absent. The existing shared tests then cover the
  second-site row, 403, 401, 405, HEAD and OPTIONS.
- A new class `TestRecordedAtFeed`, parametrised over a new `FEED_RESOURCES` list holding only the
  touches param for now: `(list_name, model, factory, distinct_rows)`, where `distinct_rows` is a
  dict of factory overrides that keep a batch inside the model's unique constraint. For touches it
  is `{"occurred_at": factory.Sequence(lambda n: BASE + timedelta(seconds=n))}`. Tests:
  - rows come back in ascending `(recorded_at, id)` order across pages (`API_PAGE_SIZE = 2`,
    `recorded_at` set with `_base_manager.filter(pk=...).update(...)`);
  - `query_count(..., page_size=2) == query_count(..., page_size=50)` after a warm-up request,
    as in `freedom_ls/course_interest/tests/test_api.py`;
  - 1,500 rows built with `factory.build_batch(1500, user=user, **distinct_rows)`, saved with
    `model._base_manager.bulk_create`, given one shared `recorded_at` with one `update()`, paged at
    `API_MAX_PAGE_SIZE`: each id appears exactly once;
  - `updated_since` includes a row exactly at the bound and excludes one a second before it;
  - a naive `updated_since` is a 400 keyed `updated_since`;
  - `next` keeps `updated_since` and `page_size`.
- Touch-only: a touch whose `occurred_at` is older than every row on the first page, but whose
  `recorded_at` is later, comes back on the second page.

> **Decision:** slice 1 keeps `updated_since` and `TestRecordedAtFeed`: the cursor and
> `updated_since` make the resource usable, and slice 2 reuses the class.

### Slice 5: referral code filters and their case-insensitive indexes

Code filters on both resources, matching regardless of case, backed by functional indexes the
planner uses.

**Builds on:** slice 4
**Touches:** freedom_ls/referral_tracking/models.py, freedom_ls/referral_tracking/migrations/, freedom_ls/referral_tracking/admin.py, freedom_ls/referral_tracking/api.py, freedom_ls/referral_tracking/tests/test_api.py, freedom_ls/referral_tracking/tests/test_models.py

`freedom_ls/referral_tracking/models.py`:

- Import `Upper` beside `Lower`.
- `AttributionTouch.Meta.indexes` gains
  `models.Index(F("site"), Upper("referral_code"), name="referral_touch_code_upper_idx")`. Keep the
  existing `(site, referral_code)` index.
- `Conversion.Meta.indexes` gains
  `models.Index(F("site"), Upper("first_referral_code"), name="referral_conv_first_upper_idx")` and
  `models.Index(F("site"), Upper("last_referral_code"), name="referral_conv_last_upper_idx")`.
  A comment says why `Upper`: PostgreSQL compiles `iexact` to `UPPER(col::text) = UPPER(%s)`, so
  only an `Upper` expression index serves it.
- A function beside `Conversion`, the single home of "code in play":

```python
def with_code_in_play(
    queryset: QuerySet[Conversion], code: str
) -> QuerySet[Conversion]:
    """Conversions whose first or last referral code is `code`, ignoring case.

    Stored codes keep the case they were typed or printed in, and code text is
    unique ignoring case, so case never distinguishes two codes. An empty code
    leaves the queryset unchanged.
    """
    if not code:
        return queryset
    return queryset.filter(
        Q(first_referral_code__iexact=code) | Q(last_referral_code__iexact=code)
    )
```

Then `uv run manage.py makemigrations freedom_ls_referral_tracking --name referral_code_upper_indexes`
(creates `0008_referral_code_upper_indexes.py`) and `uv run manage.py migrate`.

`freedom_ls/referral_tracking/admin.py`: `CodeInPlayFilter.queryset` returns
`with_code_in_play(queryset, self.value() or "")`. Drop the `Q` import if nothing else uses it. The
existing admin tests prove the behaviour is unchanged.

`freedom_ls/referral_tracking/api.py`:

```python
# On AttributionTouchFilterSet
referral_code = django_filters.CharFilter(
    field_name="referral_code",
    lookup_expr="iexact",
    help_text="Touches whose referral_code is this code, ignoring case.",
)

# On ConversionFilterSet
referral_code = django_filters.CharFilter(
    method="filter_code_in_play",
    help_text=(
        "Conversions whose first_referral_code or last_referral_code is this "
        "code, ignoring case."
    ),
)
first_referral_code = django_filters.CharFilter(
    field_name="first_referral_code",
    lookup_expr="iexact",
    help_text="Conversions whose first_referral_code is this code, ignoring case.",
)
last_referral_code = django_filters.CharFilter(
    field_name="last_referral_code",
    lookup_expr="iexact",
    help_text="Conversions whose last_referral_code is this code, ignoring case.",
)

# A method on ConversionFilterSet: method="filter_code_in_play" resolves it by name there.
def filter_code_in_play(
    self, queryset: QuerySet[Conversion], name: str, value: str
) -> QuerySet[Conversion]:
    return with_code_in_play(queryset, value)
```

`api.py` imports `QuerySet` from `django.db.models` and `with_code_in_play` from `.models`.

The `value: str` hint matters: drf-spectacular reads it to type the method filter, and a missing
hint is a warning that fails `--fail-on-warn`.

Tests in `freedom_ls/referral_tracking/tests/test_api.py`:

- Touches: `referral_code=summer` returns a touch stored as `SUMMER` and not one stored as
  `winter`.
- Conversions, `referral_code`: returns a row whose first code matches, a row whose last code
  matches, and a row where both match exactly once; excludes a row with neither. Query in a
  different case from the stored codes.
- Conversions: `?referral_code=` returns every conversion.
- Conversions: `first_referral_code` returns the first-code row and the both row, not the
  last-code-only row; `last_referral_code` the mirror. Both in a different case.
- `next` keeps every filter: extend the `TestRecordedAtFeed` `next` test with a per-resource dict
  of extra params, `{"referral_code": "abc"}` for touches and
  `{"kind": "account_signup", "referral_code": "abc", "first_referral_code": "abc",
  "last_referral_code": "abc"}` for conversions, with rows that match them all, and assert each
  appears in `next`.

Tests in `freedom_ls/referral_tracking/tests/test_models.py`:

- `with_code_in_play` with `""` returns the queryset unchanged.
- Index use: inside the test's transaction run `SET LOCAL enable_seqscan = off` on
  `connection.cursor()`, so the result does not depend on table size, then:
  - `AttributionTouch._base_manager.filter(site=site, referral_code__iexact="abc").explain()`
    contains `referral_touch_code_upper_idx`;
  - `with_code_in_play(Conversion._base_manager.filter(site=site), "abc").explain()` contains both
    `referral_conv_first_upper_idx` and `referral_conv_last_upper_idx`.

  - `first_referral_code__iexact="abc"` alone uses `referral_conv_first_upper_idx`, and
    `last_referral_code__iexact="abc"` alone uses `referral_conv_last_upper_idx`, so each index is
    proven even if the planner serves the OR some other way.

  These are the spec's `EXPLAIN` success criteria as automated tests. If the planner picks a
  different index with seq scans off, report it rather than changing the index definition.

> **Decision:** keep `SET LOCAL enable_seqscan = off` in the index test. The ORM cannot set a planner
> parameter, the statement is a fixed string with no input, and `SET LOCAL` confines it to the
> test transaction.

> **Decision:** slice 5 stays one slice with one migration: the indexes exist only for these
> filters.
