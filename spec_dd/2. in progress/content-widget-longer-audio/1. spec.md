# Spec: longer audio clip widget (`c-audio-clip`)

## Purpose

The `c-audio` widget plays a word of a few seconds. It cannot pause, seek or show a duration, so course authors cannot put a listening exercise of a few minutes into a topic. This spec adds the `c-audio-clip` widget for longer recordings. It shows a title, an optional kind label, a round play/pause button, a seek bar, elapsed and total time, and an optional transcript. The mockups beside `idea.md` are `image.png` (idle), `image-1.png` (loading), `image-2.png` (playing) and `image-3.png` (error).

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| audio clip | coined | One `c-audio-clip` widget on a page, playing one `File` of `file_type` `AUDIO`. Not a model |
| kind | coined | The `kind` attribute of `c-audio-clip`: free author text shown beside the title ("Listening exercise"). Not an enum like `DeadlineKind` or `PriceKind` |
| active audio handle | coined | The page-level `{id, pause()}` pair naming the one widget, `c-audio` or `c-audio-clip`, whose audio is playing or loading |

## Scope

Out:
- Skip buttons, playback speed, volume, loop and autoplay.
- Lock-screen metadata (Media Session API).
- Remembering the position across page loads.
- Progress tracking or completion for listening.
- Access control on `content_engine:audio_file`, which belongs to the roadmap spec `content-widget-sayit-reveal-4-audio-access-control`.
- Any change to the `c-audio` widget's look or attributes. Its takeover code does change (see Alpine).

## Decisions

- **A new tag, not a `c-audio` variant.** The two widgets share no attribute beyond `src`.
- **`content_save` reads the duration with `mutagen`.** Then the total shows before any byte loads. The alternative, an `ffprobe` subprocess, puts a system binary on every FLS host.
- **Each audio clip owns its own `HTMLAudioElement`, created on first Play.** The `c-audio` widget shares one element across the page and swaps its `src` on every takeover, which would throw away a paused clip's buffer and position.
- **The play button keeps one accessible name and toggles `aria-pressed`**, as `c-audio` does. Changing the name as well makes screen readers say "Pause …, pressed".
- **The seek bar is a native `<input type="range">`.** It gives Home and End, touch drag and the slider role without code in the CSP Alpine build.

## Requirements

### Data: `freedom_ls/content_engine/models/files.py`

- Add `File.duration_seconds = models.FloatField(null=True, blank=True)`. Its help text says it is the audio length read at save time and is null for non-audio or unreadable files.
- Add a new migration after `0013_course_shared_with.py`. Existing rows stay null until their next `content_save`.

### Loader: `freedom_ls/content_engine/management/commands/content_save.py`

- Add `mutagen` to `[project].dependencies` with `uv add mutagen`. It is a runtime dependency, because host projects run `content_save`.
- In `save_file_to_db`, for `File.FileType.AUDIO`, read `mutagen.File(path).info.length` from the local source path before `file_obj.file.save(...)`. Set it in the `get_or_create` `defaults` and in the `not created` branch. For any other file type set `duration_seconds = None`, so a file that stops being audio loses a stale value.
- When `mutagen.File` returns `None` or raises `mutagen.MutagenError` or `OSError`, store `None`, echo one indented warning line naming the file, and carry on, so one bad file does not abort the atomic run. Widen that tuple only by the exception types the truncated and zero-byte mp3 tests actually raise. Never catch `Exception`.
- The existing echo lines stay byte-identical, because tests assert on them.

### Widget template: `freedom_ls/content_engine/templates/cotton/audio-clip.html`

Attributes: `src` (required, resolved with `get_file_by_path`), `title` (required), `kind` (optional, default blank). The default slot is the transcript.

- **Error boxes** use `<c-content-error>`, as `audio.html` does. A missing file or `file_type != "AUDIO"` shows "Audio not found: {{ src }}". An empty `title` shows "Audio needs a title: {{ src }}".
- **Layout**: the round play button sits at the left, in the vertical centre of the card in every state, then a column with the title row above the seek row (or the status text in the error state) and the transcript toggle. The transcript panel opens below that row, indented to the column, so opening it does not move the button.
  - The title is bold and cut to one line with an ellipsis in idle, loading and playing, and wraps in the error state, as the mockups show. Its `title` attribute holds the full text, and the button and seek bar names carry it too.
  - A non-blank `kind` sits at the right of the title row as small, muted mono text that does not shrink. A blank `kind` renders nothing.
  - The seek row holds the seek bar, then `elapsed / total` in `tabular-nums`, with elapsed in `text` and `/ total` in `text-muted`.
  - The border, surface and radius match the `c-audio` widget. The wrapper is `role="group"` with `aria-labelledby` pointing at the title's id. The id comes from `x-id`/`$id`, so two clips on one file never share one.
- **Play button**: a `c-button` of at least 44 px in the primary colour.
  - `aria_label="Play {{ title }}"`, with `aria-pressed` bound to playing. In the error state the accessible name is "Try again: {{ title }}".
  - It shows the `media_play` icon when paused, the `loading` icon spinning while loading (`motion-reduce:animate-none`), `media_pause` while playing, and `retry` in the error state.
  - The icon sits at the button's optical centre: each icon's wrapper is a flex box, not a bare inline span, and the play triangle moves right by one pixel.
  - A mouse click leaves no focus ring on it; keyboard focus does.
  - `data-src` is `{% url 'content_engine:audio_file' file_obj.pk %}`, never a signed URL.
- **Seek bar**: `<input type="range" min="0" step="any">`, with `max` set to `duration_seconds` unrounded.
  - `aria-label="Seek {{ title }}"`. `aria-valuetext` is spoken time ("1 minute 12 seconds of 3 minutes 18 seconds"), updated at most once a second and on change.
  - The hit area is at least 44 px high around a thin track. The visible thumb shows in every state, the played part fills in the primary colour, and focus shows a visible ring.
  - The visible time text is `aria-hidden="true"`.
- **Null duration** (a row not re-saved since the migration, or an unreadable file): the total shows `--:--` and the seek bar is disabled until the element's `duration` is finite after the first Play.
- **Browser duration wins once known**: on `loadedmetadata` the clip takes any finite `duration` the element reports, for the seek `max` and the total, because `mutagen` can misjudge a VBR mp3's length by seconds. The stored `duration_seconds` is the figure shown before the first Play.
- **Time format**: `m:ss` under an hour and `h:mm:ss` from an hour up, chosen from the total so elapsed and total share one format. Seconds are zero-padded and the leading unit is not.
- **Error state** (`image-3.png`): the error border and tint show, and the play button turns red (the `error` fill) and shows the `retry` icon, and pressing it tries again. The seek row is replaced by "This audio couldn't load.". There is no separate Try again button. A `role="status"` element stays in the DOM in every state and only its text changes, so each failure is announced.
- **Transcript**: when the slot holds more than whitespace, a text toggle under the seek row reads "Show transcript" or "Hide transcript", collapsed by default so it doesn't give away a listening exercise's answers.
  - The toggle has `aria-expanded`, `aria-controls` and a `dropdown` chevron that points down while collapsed and turns up (`rotate-180`) while expanded, as brand-guidelines requires of every expand chevron.
  - The panel renders `{% markdown slot %}`, uses `x-collapse` (respecting `motion-reduce`) and is hidden from assistive technology while collapsed.
  - The toggle and panel still work in the error state.
  - The toggle looks the same in both states: a mouse click leaves no focus ring, so "Hide transcript" is as clean as "Show transcript".

### Alpine: `freedom_ls/content_engine/static/content_engine/js/alpine-components.js`

- Register `Alpine.data("audioClip", ...)` and add it to the header list of components. Formatting, percentages and labels live in getters and methods, because the CSP build allows no complex inline expressions.
- **Element**: `new Audio()` on the first Play, with `preload="none"` and no `crossorigin`. Its `src` comes from `data-src`. `play()` is called synchronously in the click handler so iOS counts it as a user gesture.
- **States**: `paused`, `loading`, `playing` and `failed`. They follow the element's own `playing`, `pause` and `waiting` events, so an interruption such as a phone call leaves the button showing Play.
- **Seeking**:
  - A seek before the first Play, or while loading, stores a pending position. `loadedmetadata` applies it, and loading shows until `seeked`.
  - While the learner drags, `input` updates the thumb and time and `timeupdate` is ignored. `change` sets `currentTime`. A seek while paused stays paused.
  - Left and Right arrows move 5 seconds through a `keydown` handler, because `step="any"` leaves the browser's arrow step undefined.
- **Ended**: reset to 0:00 and paused, with any pending seek or drag dropped, so the button always shows Play again. The next press plays from the start, so there is no replay icon.
- **A seek the host can never serve**: a host that ignores Range requests leaves the file unseekable even once it has fully loaded. A pending seek is then dropped and the bar follows the audio again, so it never freezes while sound plays.
- **Failure**: an `error` event, or a `play()` rejection other than `AbortError`, sets `failed` and keeps the position. Pressing the red play button in this state sets `src` again through the redirect, which gets a fresh signed URL, stores the position as a pending seek and plays, all inside the click.
- **Active audio handle**: a module-scope `activeAudio = {id, pause}` or `null`. Each `audioClip` takes an `_id` from a counter, as `audioFile` does, because Alpine hands each method a fresh scope proxy and `this` is no stable identity.
  - `audioClip` Play: if `activeAudio` holds another id, call its `pause()`. Then set `activeAudio` to this clip's id and a `pause` that pauses this clip's element, keeping its position.
  - `audioFile.toggle()` takeover (the `if (owner)` block and `owner = this`): if `activeAudio` holds another id, call its `pause()`, then set `activeAudio` to this widget's id and a `pause` closure. The closure does nothing unless `owner._id` still equals that id. Otherwise it pauses and rewinds `sharedAudio`, clears the owner's `failed` and sets it to idle, which is what the old `owner.failed = false; owner._setState("idle")` did. That keeps the `c-audio` widget's stop-and-rewind.
  - The `audioFile` stop branch and `destroy()` clear `activeAudio` when it holds their id. `audioClip`'s `destroy()` pauses its element, clears its `src` and clears `activeAudio` when it holds its id, so nothing plays after an HTMX swap.
  - `owner` still routes the shared element's `playing`, `ended`, `pause` and `error` listeners to the `audioFile` that owns it. Those four listeners stay as they are.

### Nesting limits

The `c-audio-clip` widget has the same limits as `c-audio`. It does not work inside `c-table`, `c-accordion`, `c-admonition`, `c-flashcard` or `c-card`, and a file-resolving widget inside its transcript fails. Both limits come from `{% markdown slot %}` rendering without `content_instance`. Authors separate transcript paragraphs with blank lines inside the tag.

  - A new audio file stores its duration.
  - A re-save updates it.
  - Replacing the file with a non-audio file clears it.

  - The existing echo-line assertions pass.

  - `m:ss` and `h:mm:ss` totals format correctly.

  - A missing file, a non-audio file and an empty title each give their red box.

- **Sanitising** (`markdown_rendering/tests/test_markdown_utils.py`): a `<script>` and an `onerror` in the transcript are stripped.

The `content_save` tests keep using their own copy of `beep.mp3`. It checks:

- **Frontend QA**: idle, loading, playing and error at the three QA viewports, against the mockups. Home and End seek to the ends, and a touch drag at the mobile viewport moves the thumb. ## Open questions

- Q: On a narrow screen, should a long title wrap instead of being cut to one line? → A: Cut to one line in idle, loading and playing, wrap in the error state (assumed default: it matches the mockups and keeps the widget's height steady while playing. Overrule by editing the Layout bullet under "Widget template").

## Success criteria

- After `content_save`, every audio `File` that `mutagen` can read has a non-null `duration_seconds`, and a damaged audio file leaves the run finished with a warning.
- A topic page with audio clips makes no request to `/content/audio/` before a Play press, and still shows each clip's total time.
- Pause a clip, play another clip or a `c-audio` widget, then press Play on the first clip again: it resumes where it stopped.
- The seek bar reaches the clip's last second by mouse, touch and keyboard (arrows, Home, End).
- With `/content/audio/` blocked, Play shows the error state, and pressing the red retry button plays from the saved position once the request is unblocked.
