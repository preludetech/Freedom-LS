# Spec: educator interface refactor 6, cohort

## Purpose

The rest of the cohort area of `freedom_ls/educator_interface/` moves out of the flat `views.py`, `actions.py`,
`reporting.py` and `quick_views.py` into `panels/cohort/`, and its tests move to `tests/panels/cohort/`. A data
migration repoints the stored `BulkActionRun.action_path` of the four cohort bulk actions. It is a pure move on top
of `panels/common/`, `panels/learner/`, `panels/staff/` and `panels/audit_log/`, as settled in `idea.md`.
`research_codebase.md` holds today's line numbers and test clusters; the idea's ranges are stale.

## Scope

In:
- New modules under `panels/cohort/`, and `CohortCourseRegistrationDataTable` added to the existing
  `panels/cohort/data_tables.py`.
- Repointing every reference to a moved name, the data migration `0003` and its test, and the test moves listed
  under Testing.
- Repointing the learner bulk-action test that spies on `can` in the flat `actions` module, which this move empties.

Out:
- Deleting the emptied flat modules `actions.py`, `reporting.py` and `quick_views.py`, trimming `views.py` beyond
  the imports this move orphans, the `templatetags`, `qa_helpers`, fls-dev skill and test-baseline sweeps
  (`educator-interface-refactor-7-cleanup`).
- Tests of learner, staff or course names that sit in the flat test files; they keep their place and get their
  imports repointed only.
- Any behaviour, UI, URL, URL name, template path or app label change. The flat domain modules `forms.py`,
  `staff.py`, `learner_import.py`, `messaging.py` and `avatars.py`.

## Decisions

- **No re-export shim.** The flat modules lose each moved name. The migration is how stored paths survive.
- **Emptied flat modules stay, docstring only.** `actions.py`, `reporting.py` and `quick_views.py` keep a one-line
  module docstring and nothing else, so the flat test files that still hold other areas' tests mirror a module.
  `educator-interface-refactor-7-cleanup` deletes them.
- **`inactive_cohort_response` stays in `panels/common/actions.py`**, where spec 5 put it. The cohort actions import
  it from there.
- **`_scoped_cohort` moves with `cohort_report_download`.** `cohort_report_download` is its only caller.
- **`DOWNLOAD_COHORT_REPORT`, `REPORT_POLL_SECONDS`, `DOWNLOADS_LISTED`, `DownloadRow`, `_pdf_url`, `REFRESH_PARAM`
  and `_quiz_confusions` move with `reporting.py`**, which holds only cohort code now.
- **Import direction.** A cohort module imports `panels/common/`, `panels/learner/`, `panels/staff/actions.py`,
  `panels/audit_log/` and other cohort modules. Nothing outside `panels/cohort/` imports a cohort module except
  `views.py` (`config`), `urls.py` (`report_download`) and `panels/learner/data_table_panels.py`
  (`data_tables`, as today). `panels/cohort/data_tables.py` imports only `panels/common/`. Inside the area:
  `actions` ← `bulk_actions` ← `config`; `actions`, `data_tables` ← `data_table_panels`; `actions` ← `panels`;
  `panels`, `data_table_panels`, `report_panels` ← `instance_view` ← `config` ← `report_download`; `quick_view` ←
  `config`. Only `report_download.py` imports the shell `views.py`, for `_attach_organisation`, as
  `panels/learner/import_views.py` does; `views.py` never imports `report_download`. Checked by grep, with no new
  import-linter contract.
- **Bulk-action registration stays at startup.** `panels/cohort/config.py` imports the `panels.cohort.bulk_actions`
  module for its side effect, with `# noqa: F401` and the one-line comment `panels/learner/config.py` uses, so the
  cohorts table offers the same bulk actions in the same order.
- **Patch strings name the module that looks the name up.** A stale string on a module that still imports the name
  resolves and patches nothing.
- **Underscore names keep their spelling** and are imported across modules by name.

## Requirements

Paths are under `freedom_ls/educator_interface/`. Each name moves byte-for-byte, comments, `TODO`s and `@claude`
comments included, except for its import lines; quoted casts stay quoted. Each new module starts with a one-line
purpose docstring and `from __future__ import annotations`, and declares a sorted `__all__` of every name it owns,
as the other `panels/` packages do. `panels/cohort/__init__.py` stays empty.

### Migration

`migrations/0003_move_cohort_bulk_runs.py`, modelled on `0002_move_learner_bulk_runs.py`, which is not edited:

- Depends on `("freedom_ls_educator_interface", "0002_move_learner_bulk_runs")`.
- Uses `apps.get_model("freedom_ls_panel_framework", "BulkActionRun")` and literal strings; it imports no action
  class.
- Maps `freedom_ls.educator_interface.actions.<Name>` to
  `freedom_ls.educator_interface.panels.cohort.bulk_actions.<Name>` for exactly the four `@register_bulk_action`
  classes: `RegisterCohortForCourseBulkAction`, `DeactivateCohortRegistrationBulkAction`,
  `DeactivateCohortsBulkAction`, `ReactivateCohortsBulkAction`.
- Matches each row by exact `action_path`, never by prefix, and updates only `action_path`, on every site.
- Its reverse maps the same four back. Forward and reverse share one helper called with the pair swapped.

- A test moves when its subject is a name this spec moves; within the area it goes to the file of the module that
  defines that name. A test of a learner, staff or course name, a test that spans areas, and a table-agnostic test
  (`EDUCATOR_TABLES` and its parametrised tests, bulk run status polling, the all-`BULK_ACTIONS` parametrisations)
  stays and has only its imports repointed. `git mv` of a whole file lands before any slice is appended to it.
- A helper both moving and staying tests use, or two new test files use, goes to `tests/helpers.py` with full type
  hints, in its own first commit. If a moving test uses `_export_csv`, that commit also repoints
  `tests/invariants/test_course_shares.py`, which imports it from `tests.test_views`.
- A moved test keeps the `_site_context` opt-in it had: a module `pytestmark` when every test in the new file needs
  it, otherwise the per-test use or local autouse fixture it came with. `tests/test_quick_views.py` keeps its own.
- `_NEW_REPORTING_FILES` in the moved `test_report_panels.py` replaces `"reporting.py"` with
  `"panels/cohort/report_panels.py"` and gains `"panels/cohort/panels.py"`.
- New `tests/migrations/test_0003_move_cohort_bulk_runs.py`, modelled on the `0002` test, with `BEFORE` at `0002` and
  `AFTER` at `0003`, covers: forward (each of the four rewritten, `action_name` unchanged), reverse (each restored),
  and untouched rows (a learner path under `panels.learner.bulk_actions`, an unknown path, a row already on the new
  path). A parametrised case asserts that `import_string` of each new path returns a `RecordedBulkAction` subclass.
  The `0001` and `0002` tests stay unedited and pass with `0003` as the leaf.
- `test_organisation/mirroring_baseline.txt` loses the `test_cohort_delete_action.py` and
  `test_create_cohort_action.py` lines, each in the commit that moves its file. Whole-file moves are `git mv` with no
  content change in that commit, and their repoints land in the commit before.

## Success criteria

- Over `panels/cohort/`, these find nothing:
  - `grep -rnE "freedom_ls\.educator_interface\.(actions|reporting|filters|quick_views)\b"`
  - `grep -rnE "freedom_ls\.educator_interface\.views\b"` outside `report_download.py`
  - `grep -rnE "panels\.(course|dashboard)"`
  - `grep -rnE "^\s*from \."`
- Outside `panels/cohort/`, only `views.py`, `urls.py`, `panels/learner/data_table_panels.py` and tests import
  `panels.cohort`; `views.py` never imports `panels.cohort.report_download`.
- In `freedom_ls/educator_interface/` outside `tests/` and `migrations/`, each moved name has its `class`, `def` or
  assignment only in its new module, and `actions.py`, `reporting.py` and `quick_views.py` hold only a docstring.
- Each new module imports in a fresh interpreter (`python -I`, after `django.setup()`), and in a fresh interpreter
  that imports `freedom_ls.educator_interface.views`, `bulk_actions_for_table("cohorts")` lists the same actions in
  the same order as on `main`.
- `pytest --collect-only -q` collects the same number of tests as `main`, plus the new `_NEW_REPORTING_FILES` case
  and the `test_0003` cases, and the full suite passes.
- Pointing the `learner_avatars` patch string back at `reporting` makes its test fail, and the repointed `can` spy
  in `test_a_run_reads_who_is_permitted_once_rather_than_per_learner` records at least one call (one-off manual
  checks).
- `manage.py check` and `lint-imports` pass, and `makemigrations --check --dry-run` reports no changes.
- `migrate freedom_ls_educator_interface 0002` followed by `migrate` runs both ways on a database with cohort bulk
  runs.
- The mirroring check passes, and `mirroring_baseline.txt` has lost only the two cohort lines.
- `git diff main --stat` shows no change under `templates/` or `static/`, and the only migration file added is
  `0003`.
