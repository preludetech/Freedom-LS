# Plan: educator interface refactor 6, cohort

Pure move plus one data migration. No behaviour, UI, URL, URL name, template, app label or model
change. Paths are under `freedom_ls/educator_interface/` unless they start with `freedom_ls/`,
`test_organisation/`, `claude_plugins/` or `.sdd-work/`. Line numbers are from the tree at plan
time; re-find each name by grep before cutting it, and move tests by name, never by range.

## Ground rules for every slice

- **TDD for a move.** No test is written and no assertion changes, except: the new `test_0003`
  (slice 3), the reason-mixin walk (slice 4, same count asserted), the `can` spy target (slice 3)
  and the `_NEW_REPORTING_FILES` list and path anchor (slices 6 and 7). The existing tests are the
  safety net: each slice moves code, repoints imports, then runs the targeted tier. "Red" for a
  slice is a failing import or a failing test after the cut. Fix the import, never the assertion.
- **Byte-for-byte.** Each moved name keeps its body, decorators, docstring, comments, `# TODO` and
  `@claude` comments, and spelling (leading underscores included). Only import lines change.
  Quoted casts such as `cast("OrganisationScopedRequest", ...)` stay quoted. Moved tests keep their
  decorators and marks, and their order within each source block.
- **Each new production module** starts with a one-line module docstring stating what the module
  holds (never where it came from), then `from __future__ import annotations`, uses only absolute
  imports (`from freedom_ls....`), and declares a sorted (`RUF022`) `__all__` listing every name
  the module owns, underscore names included. Model: `panels/learner/config.py`,
  `panels/common/request.py`. `panels/cohort/__init__.py` stays empty.
- **Import direction.** A cohort module imports `panels/common/`, `panels/learner/`,
  `panels/staff/actions.py`, `panels/audit_log/`, other cohort modules,
  `freedom_ls.panel_framework`, the flat domain modules (`forms`, `avatars`, `events`, `paths`,
  `exceptions`) and other apps. It never imports `views`, `actions`, `reporting`, `filters` or
  `quick_views`, except that `report_download.py` imports `_attach_organisation` from the shell
  `views.py`. `panels/cohort/data_tables.py` imports only `panels/common/`. Inside the cohort area
  imports run one way:
  `data_tables`, `bulk_actions`, `actions`, `quick_view`, `report_panels` (leaves) ←
  `panels`, `data_table_panels` ← `instance_view` ← `config` ← `report_download`.
  `views.py` imports only `config` from the cohort area once slice 10 lands (until then it imports
  whatever cohort names it still uses), and never imports `report_download`.
- **No pull from a flat module.** Before cutting a block, grep its body for every name it uses.
  If a body uses a name still defined in `views.py`, `actions.py`, `reporting.py` or
  `quick_views.py` (other than `_attach_organisation` for `report_download.py`), stop and report
  it: importing back is forbidden.
- **No re-export shim.** A flat module loses each moved name and never re-imports it for others.
  Imports left unused in a shrunk module go in the same commit (ruff `F401` flags them). While a
  slice is in flight a flat module may import from `panels/cohort/`.
- **Patch strings** name the module that now looks the name up. A stale string on a module that
  still imports the name resolves and patches nothing, so slice 6 checks one by mutation.
- **Commits.** Plain `git commit`. Each slice is at least one commit. The `test-mirroring` hook
  needs each test file's module to exist when the test file is committed, so a production module
  lands in the same or an earlier commit than its test file. A whole-file test move is a `git mv`
  with no content change in its own commit; its import repoints land in the commit before, and the
  matching `test_organisation/mirroring_baseline.txt` line goes in the `git mv` commit. Every commit
  leaves the targeted tier green.
- **Tests per slice:** targeted tier. Before each commit run
  `.claude/ds/scripts/select_tests.sh --working-tree` and run the printed `command:` exactly, in the
  background. See `claude_plugins/django-stack/resources/test_tiers.md`. `--collect-only` and
  partial runs take `--no-cov`.
- **Test placement.** A test moves when its subject is a name this plan moves; within the area it
  goes to the file of the module that defines that name. A test of a learner, staff or course name,
  a test that spans areas, and a table-agnostic test stays and has only its imports repointed. The
  full by-name lists are under "Test placement by name" below and are binding. A moved test keeps
  the `_site_context` opt-in it had: a module `pytestmark` when every test in the new file needs
  it, otherwise the per-test use or local autouse fixture it came with. A helper that a moving and
  a staying test both use, or that two new test files use, goes to `tests/helpers.py` with full type
  hints (no `Any`); a fixture shared the same way goes to `tests/conftest.py`. A helper only one new
  file uses moves into that file with its users. Each new test file starts with a one-line module
  docstring and `from __future__ import annotations`.

## Skills to use

- `fls-dev:testing` with `ds:testing`: test mirroring (`tests/panels/cohort/test_<module>.py`
  mirrors `panels/cohort/<module>.py`), `conftest.py` holds fixtures only and hand-imported helpers
  go in `tests/helpers.py`, marks and `mock_site_context` use stay as they are, never add to
  `test_organisation/mirroring_exemptions.txt`. Verifying hooks: `test-mirroring`, `lint-imports`,
  `app-map-fresh`. `ds:testing` covers the `test_0003` migration test and the "patch where the name
  is looked up" rule.
- `fls-dev:panel-framework`: framework names (`DataTable`, `DataTablePanel`, `QuickView`,
  `register_bulk_action`, `LazyBodyPanel`, ...) stay in `panel_framework` and are imported through
  each framework module's `__all__` (`tests/invariants/test_public_names.py`). `register_bulk_action`
  order is the selection bar's order, so the class order in `bulk_actions.py` is the source order.
  The invariants under `tests/invariants/` and `freedom_ls/panel_framework/tests/invariants/` walk
  `interface_config` and must stay green. `tests/invariants/test_bulk_run_scoping.py` excludes
  `migrations/`; the data migration reaches `BulkActionRun` only through `apps.get_model`.
  `tests/invariants/test_panel_template_rules.py` scans only flat modules; leave it unwidened.
- `fls-dev:educator-interface`: confirms where each cohort panel and action sits (Settings is
  Name, Staff, Status; Learners tab has Add learners, Remove, Move; History keeps its audit-log
  filters). Its file paths go stale after this move; a later spec owns that sweep, so leave the
  skill file alone.
- `ds:code-comments` and `sdd:planning-references-in-code`: module docstrings, the migration
  docstring and the new test's docstrings state purpose; nothing in code narrates the move or cites
  a spec, plan, slice or `spec_dd/` path.
- `fls-dev:domain-glossary`: no new noun is coined; module and test names are the spec's.
- No template, styling, HTMX, Alpine, browser or Playwright skill applies, and no MCP is needed.
