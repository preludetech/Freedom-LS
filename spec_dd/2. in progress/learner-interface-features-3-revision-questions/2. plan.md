## Design notes that hold across slices

- **FSRS API.** The `fsrs` package (`>=6.3`) is not installed yet. After `uv add fsrs`, confirm
  the names this plan uses against the installed package before writing the wrapper
  (`uv run python -c "import fsrs; help(fsrs.Scheduler); help(fsrs.Card)"`): `Scheduler`,
  `Card`, `Rating`, `State`, `Card.to_dict()` / `Card.from_dict()`,
  `Scheduler.review_card(card, rating, review_datetime)`,
  `Scheduler.get_card_retrievability(card, current_datetime)`. Where a name differs, the installed
  package wins.

> **Assumed default:** FSRS fuzzing stays on, as the package ships it. Why: Decision 1 says default
> parameters, and fuzz only applies to cards in the Review state, so every equality the tests
> assert (a new card rated `Hard` against a re-rated one) is on Learning-state cards and stays
> deterministic. To change: the `Scheduler(...)` call in Slice 2.

- **Where code lives.** `revision` owns the models, the scheduler, the bank and the services, and
  takes no `request`. `learner_interface` owns the views, the Django-session storage, the
  templates and every decision about what a learner may open. `content_engine` and `form_engine`
  never import `revision`.
- **New cross-app edges.** The spec names `revision -> form_engine, content_engine,
  learner_progress, accounts, site_aware_models, base` and `learner_interface -> revision`; this
  plan adds no other runtime edge except the one below. `revision`'s tests and factories build
  their records with the factories of those same apps only.

> **Assumed default:** `qa_helpers -> revision` is a new runtime edge, from the seeder the spec
> asks for. Why: `qa_helpers` already depends on every app it seeds, and nothing depends on it. To
> change: Slice 14.

- **Views stay in `learner_interface/views.py`**, beside the private access helpers they call. A
  view that returns only the `#revision-card` partial is named with the `partial_` prefix; the URL
  names are the spec's.
- **The generated app map.** `docs/app_structure.md` and `test_organisation/import_contracts.toml`
  are generated and gate every commit (`app-map-fresh`, `lint-imports`). A slice that adds a
  cross-app import regenerates both with
  `uv run python claude_plugins/django-stack/scripts/generate_app_map.py` and commits the result.
  Never hand-edit either file.
- **Revision session state** lives in the Django session under `f"revision_session:{course.id}"`.
  Whether the current question has been answered is never stored: it is derived from a
  `RevisionReview` for that user and question with `reviewed_at >= state.started_at`.
- **A section** is a `Topic` or a `CoursePart`. Wherever a function takes `section`, it takes the
  model instance.
- **Controls.** A filled `<c-button>` is a forward action. Anything that goes back or sideways
  ("Back to course", a section link after a right answer, the outline panel's "Revision") is
  `<c-button variant="link">`. A card is a `.surface`.

```python
@dataclass(frozen=True)
class _PlacedSections:
    """What one course places, and which of it this record has finished."""
    topic_ids: frozenset[UUID]
    part_ids: frozenset[UUID]
    finished_topic_ids: frozenset[UUID]
    finished_part_ids: frozenset[UUID]
    # Forms placed in the course that the record has not completed.
    uncompleted_form_ids: frozenset[UUID]
    # Every section id in course order, a part ahead of its own topics.
    order: tuple[UUID, ...]


def _placed_sections(record: CourseProgress) -> _PlacedSections:
    # Memoised on the record instance, as Course.collection_items is on the
    # course: one page asks for it many times and nothing in a revision
    # request changes what the record has finished.
    completed = completed_collection_item_ids(record)
    for item in record.course.collection_items_flat():
        # A Topic is finished when any one of its placements here is completed.
        # A CoursePart is finished when it has nested placements and every one is completed.
        # A Form is completed when any one of its placements here is completed.


def _revisable_questions() -> QuerySet[FormQuestion]:
    """Questions that can be asked in revision at all, whoever the learner is."""
    return FormQuestion.objects.filter(type__in=OPTION_QUESTION_TYPES).filter(
        Exists(QuestionOption.objects.filter(question=OuterRef("pk"), correct=True))
    )


def _naming(section: Topic | CoursePart) -> Q:
    """Matches the questions that name this section."""
    # An Exists on FormQuestionTopic or FormQuestionCoursePart, by the section's type.


def bank_questions(record: CourseProgress) -> QuerySet[FormQuestion]:
    """The questions this record's learner may revise in this course.

    Derived on every read, never stored: a section finished by any route,
    including one that sends no completion signal, banks its questions.
    """
    placed = _placed_sections(record)
    unfinished_topics = placed.topic_ids - placed.finished_topic_ids
    unfinished_parts = placed.part_ids - placed.finished_part_ids
    return (
        _revisable_questions()
        .filter(
            Exists(FormQuestionTopic.objects.filter(question=OuterRef("pk"), topic_id__in=placed.topic_ids))
            | Exists(FormQuestionCoursePart.objects.filter(question=OuterRef("pk"), course_part_id__in=placed.part_ids))
        )
        .exclude(Exists(FormQuestionTopic.objects.filter(question=OuterRef("pk"), topic_id__in=unfinished_topics)))
        .exclude(Exists(FormQuestionCoursePart.objects.filter(question=OuterRef("pk"), course_part_id__in=unfinished_parts)))
        # A quiz placed in this course keeps its questions and answers out of
        # revision until the learner has completed it. A bank form is placed
        # in no course, so it is never in this set.
        .exclude(form_page__form_id__in=placed.uncompleted_form_ids)
    )
```

`Exists` subqueries, not joins, so no question is returned twice and no `distinct()` is needed.
`bank_questions` is the only place that decides bank membership; every other function starts from
it.

```python
class RevisionSchedule(SiteAwareModel):
    """One learner's FSRS state for one question.

    Keyed on the user, not the learner or the course: a person in two
    organisations, or a question whose sections sit in two courses, has one
    memory of the question and so one schedule.
    """
    user = FK(settings.AUTH_USER_MODEL, CASCADE, related_name="revision_schedules")
    question = FK("freedom_ls_form_engine.FormQuestion", CASCADE, related_name="revision_schedules")
    state = PositiveSmallIntegerField()
    step = PositiveSmallIntegerField(null=True, blank=True)
    stability = FloatField(null=True, blank=True)
    difficulty = FloatField(null=True, blank=True)
    # FSRS's next-review time, not a deadline: nothing closes when it passes.
    due = DateTimeField()
    last_review = DateTimeField(null=True, blank=True)
    reps = PositiveIntegerField(default=0)
    lapses = PositiveIntegerField(default=0)
    # constraints: UniqueConstraint(user, question, name="unique_revision_schedule_per_user_question")
    # indexes: Index(fields=["user", "due"], name="revision_schedule_user_due_idx")


class RevisionReview(SiteAwareModel):
    """One answer given on the revision page. Append-only, apart from the "I guessed" re-rating."""
    user = FK(settings.AUTH_USER_MODEL, CASCADE, related_name="revision_reviews")
    question = FK("freedom_ls_form_engine.FormQuestion", CASCADE, related_name="revision_reviews")
    # The course whose revision page the answer was given on.
    course = FK("freedom_ls_content_engine.Course", CASCADE, related_name="revision_reviews")
    reviewed_at = DateTimeField()
    # UUID strings, not a relation: an option without a uuid in its file is
    # re-created on every load, and a relation would lose the choice with it.
    selected_option_ids = JSONField(default=list)
    # Stored at answer time so a later edit to an option's `correct` flag never re-marks it.
    was_correct = BooleanField()
    guessed = BooleanField(default=False)
    rating = PositiveSmallIntegerField()
    # The card as it stood before this review, so a re-rating replays from it.
    schedule_before = JSONField()
    # indexes: Index(fields=["user", "question", "-reviewed_at"], name="revision_review_latest_idx")
```

**Views** (`learner_interface/views.py`; each calls `_revision_record` first)

- `_revision_state(request, course) -> RevisionSessionState | None` and
  `_store_revision_state(request, course, state)` read and write the Django session key.
  `_revision_state` catches `pydantic.ValidationError` only and treats a stored value that fails
  validation as no session.
- `_current_revision_question(record, state) -> FormQuestion | None`: the state's current question
  read through `bank_questions(record).filter(pk=state.current_question_id).first()`, never by id
  alone. Every revision view uses it. When the current id is no longer in the bank, the view
  advances the state past it and tries the next, so a session built before the bank changed never
  serves a question the learner may no longer revise.
- `course_revision` (GET): no state renders the start screen; a state with a current question
  renders the card (the question, or its feedback when a review since `started_at` exists for
  it); a state past its last question renders the end screen.
- `course_revision_start` (`@require_POST`): `build_session`, store, redirect (303) to
  `course_revision`. An empty session stores nothing and redirects.
- `partial_course_revision_answer` (`@require_POST`): the question comes from
  `_current_revision_question`, never from the request. Read
  `request.POST.getlist(f"question_{question.id}")`, parse each as a UUID, and keep only ids that
  belong to the question's options. No valid option: 422 with the card and the error "Choose an
  answer." A review since `started_at` already exists for the question: write nothing and return
  its feedback, so an answer can't be changed once submitted. Otherwise `record_answer` and return
  the feedback card. No state or no current question: redirect to `course_revision`.
- `partial_course_revision_next` (`@require_POST`): advances the index only when the current
  question has a review since `started_at`, so a repeated request never skips a question. Returns
  the next card, or the end screen. A request without `HX-Request` redirects to `course_revision`
  after the same rule.

  ```python
  class GuessRefused(Exception):
      """The review can't be re-rated: it was wrong, or a later review has replaced it."""


  @transaction.atomic
  def mark_guessed(review: RevisionReview) -> RevisionReview:
      """Flip "I guessed" on a right answer and re-rate it.

      Replays the review from the card it started from, at the instant it was
      first given, so the schedule ends up where a first-time rating would
      have put it and a second tap undoes the first.
      """
      schedule = RevisionSchedule.objects.select_for_update().get(
          user=review.user, question=review.question
      )
      latest = (
          RevisionReview.objects.filter(user=review.user, question=review.question)
          .order_by("-reviewed_at")
          .first()
      )
      if not review.was_correct or latest is None or latest.pk != review.pk:
          raise GuessRefused
      guessed = not review.guessed
      after, rating = scheduler.review(
          review.schedule_before, scheduler.rating_for(True, guessed), review.reviewed_at
      )
      # Set the schedule's card columns from scheduler.columns_from_card(after) and save;
      # reps and lapses are unchanged. Save review.guessed and review.rating.
  ```

  ```python
  # questions of the forms that load read which their files no longer hold.

  ```

- `content_save.py`, in `save_content_to_db`: collect `seen_question_ids` as the forms loop saves
  each question, and after the loop (after `replace_question_sections`) call

  ```python
  def mark_dropped_questions(
      site: Site, loaded_form_ids: set[UUID], seen_question_ids: set[UUID]
  ) -> None:
      """Mark the loaded forms' questions that their files no longer hold, and unmark the rest.

      Scoped to forms this run loaded, so a partial load never marks another
      form's questions. A question moved to another loaded form was saved onto
      its new page first, so it is seen and stays unmarked.
      """
      # The load runs with no request, so there is no current site to filter
      # by: the base manager with an explicit site, as the loader's other reads do.
      questions = FormQuestion._base_manager.filter(site=site)
      dropped = list(
          questions.filter(form_page__form_id__in=loaded_form_ids)
          .exclude(pk__in=seen_question_ids)
          .values_list("pk", flat=True)
      )
      questions.filter(pk__in=dropped, dropped_from_source_at__isnull=True).update(
          dropped_from_source_at=timezone.now()
      )
      questions.filter(pk__in=seen_question_ids, dropped_from_source_at__isnull=False).update(
          dropped_from_source_at=None
      )
      if dropped:
          form_questions_dropped.send(sender=FormQuestion, question_ids=dropped)
  ```

  `loaded_form_ids` are the forms in `forms_by_dir`.
- `revision/signals.py`: a receiver for `form_questions_dropped` that deletes the
  `RevisionSchedule` and `RevisionReview` rows with `question_id__in=question_ids` through each
  model's `_base_manager`, with a comment: the receiver runs from the content load, where no
  request sets a current site, and a question id belongs to one site, so the id filter is the
  site scope. `RevisionAppConfig.ready()` imports the module. The question rows stay.
- `revision/queries.py`: `_revisable_questions()` adds `dropped_from_source_at__isnull=True`, so
  the bank, `course_has_revision_questions` and `_current_revision_question` all leave a dropped
  question out with no further change.
