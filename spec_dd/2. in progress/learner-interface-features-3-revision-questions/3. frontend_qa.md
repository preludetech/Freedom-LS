# Frontend QA: revision questions

## Setup

Run from the project root. The QA command picks the port; `$PORT` below is that port.

```
uv run python manage.py migrate
uv run python manage.py content_save demo_content DemoDev
uv run python manage.py qa_create_revision_scenario
uv run python manage.py runserver $PORT
```

Base URL: `http://127.0.0.1:$PORT`

Logins (the password is the email address):

| Who | Email | State |
| --- | --- | --- |
| Learner A | `qa-revision@example.com` | Parts "Foundations", "Practice" and "Backlog" finished; "Advanced" not finished; "Practice" is weak; more than 40 questions due |
| Learner B | `qa-revision-new@example.com` | Registered on "QA Revision Course", no section finished |
| Learner C | `qa-revision-back@example.com` | Same bank as Learner A; used for the nothing-due test |
| Admin | `demodev@email.com` | Site admin |

The seeder prints the course slug. Below, `<course>` is the slug of "QA Revision Course" and
`<empty>` the slug of "QA Revision Empty Course".

Run every test at the three QA viewports. Each page must have no horizontal scroll.

Re-run `qa_create_revision_scenario` before Test 8 if earlier tests have used up Learner A's due
questions.

Every revision screen is inside the course player: the course outline panel is on the left at
1024px and wider (behind the outline toggle below that), the breadcrumbs read
"QA Revision Course > Revision", and one revision card sits in the main area. A revision screen
that fills the page without the outline is a failure in any test below.

## Test 1: the course details page is untouched

1. Log in as Learner A. Open `/courses/<course>/detail/`.
2. Expect the page as it renders for any course: hero, "Continue" button, "This course includes",
   course content. Expect no "Revision" card, no "Revise" button, no due or ready count and the
   word "revision" nowhere except in the course's own title and section titles.
3. Log out and open the same page. Expect the same: nothing about revision.

## Test 2: the Revision entry in the course outline

1. As Learner A, open the first item of the course in the player (`/courses/<course>/1/`).
2. In the course outline panel, expect a "Revision" entry **under** the table of contents, below
   the last outline row and separated from it by space alone. Checklist:
   - [ ] "Revision" in the same small uppercase eyebrow as "Reference" and "Course outline";
   - [ ] no divider line above it and no icon;
   - [ ] a pill badge at the right end of the same line reading "40+ due" (not "40+ DUE");
   - [ ] the word is "due", never "ready"; no number above 40 and no word "overdue";
   - [ ] nothing about revision under the progress bar at the top of the panel;
   - [ ] a new section looks like its neighbours: nothing about the entry looks pasted in.
3. Click the entry. Expect `/courses/<course>/revision/`, still inside the player, with the entry
   highlighted the way the Reference link is when current and no outline row highlighted.
4. Below 1024px, open the outline from its toggle. Expect the same entry at the bottom of the
   sheet.

What else could break:

5. As Learner B, open the first item of the course in the player. Expect no "Revision" entry (no
   section is finished, so the bank is empty).
6. As Learner A, use the player's Previous and Next buttons to move between two topics. Expect
   the entry still under the table of contents after each move.

## Test 3: the revision dashboard

1. As Learner A, click the outline's "Revision" entry.
2. Expect one card in the main area. Checklist:
   - [ ] a stacked-cards icon in a tinted circle, centred;
   - [ ] the heading "Revision";
   - [ ] the line "40+ questions due.";
   - [ ] one large "Start revision" button as wide as the card's content;
   - [ ] nothing else: no section list, no "All sections", no "Needs revision" badge, no
         welcome-back line, no back link.
3. Click "Start revision". Expect the first question, "1 of 15".

What else could break:

4. As Learner B, open `/courses/<course>/revision/` from the address bar. Expect the card to read
   "Questions appear here after you finish a section." with a "Back to the course" button and no
   "Start revision" button. Expect status 200.
5. Open `/courses/<course>/revision/start/` in the address bar. Expect the method to be refused
   (405), not a session. Do the same for `/courses/<course>/revision/next/`.

## Test 4: a wrong answer

1. As Learner A, from Test 3 step 3, expect one question, its options, "1 of 15" and a
   "Check answer" button as wide as the card's content.
2. Note the option order. Reload the page. Expect the same question with the options in the same
   order.
3. Click "Check answer" with nothing selected. Expect the error "Choose an answer." on the card
   and the same question still shown. Expect no browser validation bubble.
4. Select a wrong option and click "Check answer".
5. Expect, in this order:
   - [ ] the question;
   - [ ] the options in the order they were asked, each in its own row;
   - [ ] the option you chose with a red border and a light red background, and a cross icon at
         the end of its row;
   - [ ] the correct option with a green border and a light green background, and a check icon at
         the end of its row;
   - [ ] every other option with a plain border, no background and muted text;
   - [ ] one red-toned box under the options. Its bold first line reads "Not quite. The answer is
         {correct option}." Under it, inside the same box: the explanation when the question has
         one, then a "Revisit: {section title}" link with a book icon;
   - [ ] a "Next" button with an arrow, at the right.
6. Expect none of these: the word "Incorrect.", a "Why" heading, a "comes back in" line, a filled
   "Revise:" button, an "I guessed" toggle, a way to change the answer.
7. Expect keyboard focus on the feedback (press Tab once: focus moves to the first link or button
   inside the feedback, not to the top of the page).
8. Reload the page. Expect the same feedback, not the unanswered question.
9. Click "Revisit: {section title}". Expect the course player on that section's first page. For a
   part, that is the part's first child.
10. Click the outline's "Revision" entry. Expect the same feedback again.

## Test 5: a right answer and "I guessed"

1. From Test 4, click "Next". Expect "2 of 15" and a new question.
2. Select the correct option (for checkboxes, every correct option) and click "Check answer".
3. Expect:
   - [ ] the correct option with a green border, a light green background and a check icon;
   - [ ] no option with a red border;
   - [ ] one green-toned box whose bold first line reads "Correct.", holding the explanation when
         one exists and the "Revisit: {section title}" link;
   - [ ] an "I guessed" toggle at the left with the line "We'll ask you this one again sooner.",
         and "Next" at the right of the same row.
4. Expect no rating name ("Good", "Again", "Easy") anywhere on the page.
5. Click "I guessed". Expect it to show as pressed (filled, with a check icon). Click it again.
   Expect it not pressed. Click it a third time and leave it pressed.
6. Reload. Expect the toggle still pressed.
7. As Admin, open the Django admin, "Revision", "Revision reviews". Expect Learner A's latest
   review with "guessed" true. Expect no add, change or delete controls on either revision model.

## Test 6: the "Revision done" card

1. As Learner A, continue the session from Test 5, answering each question (get at least one more
   wrong), to the last question. Keep count of how many you got right without "I guessed", right
   with "I guessed", and wrong. Click "Next" after the last one.
2. Expect one centred card. Checklist:
   - [ ] a check icon in a green-tinted circle;
   - [ ] the heading "Revision done";
   - [ ] the line "You answered 15 questions.";
   - [ ] three counts in one row: "Knew it", "Hard", "Forgot", each with its number above its
         label;
   - [ ] each count is a plain figure, with no border and no tinted fill around it;
   - [ ] "Knew it" equals your right answers without "I guessed", "Hard" your right answers with
         "I guessed", "Forgot" your wrong answers, and the three add up to 15;
   - [ ] one "Back to the course" button as wide as the card's content, with clear space above
         it.
3. Expect none of these: a list of missed questions, a "Revisit:" or "Revise:" link, "Next
   revision" or any date, "Revise more", "Revision overview", a second button.
4. At 375px, expect the three counts still side by side with no label cut off.
5. Click "Back to the course". Expect the course player on the item the course resumes at.
6. Click the outline's "Revision" entry. Expect the dashboard from Test 3, with a due count lower
   than before, not the "Revision done" card.
7. Start a new session. Close the tab after answering two questions. Open
   `/courses/<course>/revision/` again. Expect the session where you left it. As Admin, check
   "Revision reviews": every answer you submitted is there.
8. Expect none of these to appear at any point in Tests 4 to 6: the question the seeder marked
   dropped, the "Foundations" question scheduled 30 days ahead, any "Advanced" question.

## Test 7: nothing due

1. As Admin, in a Django shell set every `RevisionSchedule.due` of `qa-revision-back@example.com`
   10 days ahead and give each of that learner's unscheduled bank questions a schedule due 10 days
   ahead (or ask the QA data helper for "Learner C with nothing due and every schedule due 10 days
   ahead").
2. As Learner C, open the first item of the course in the player. Expect the outline's "Revision"
   entry still shown, with the badge "0 due".
3. Click it. Expect the dashboard with the line "Nothing is due. You can still practise your
   weakest questions." and the "Start revision" button.
4. Click "Start revision". Expect a session to start ("1 of N", N at most 15). Answer it through.
   Expect the "Revision done" card with counts that match your answers.

## Test 8: who is turned away

1. Log out. Open `/courses/<course>/revision/`. Expect the login page.
2. As Learner A, open `/courses/<slug of a course Learner A is not registered on>/revision/`.
   Expect a redirect to that course's detail page.
3. As Admin, in the educator interface pause "QA Revision Course" for Learner A's registration (or
   ask the QA data helper to pause it). As Learner A, open `/courses/<course>/revision/`. Expect
   the course detail page with its paused notice. Resume the course afterwards.
4. As Admin, end Learner A's registration (or ask the QA data helper). As Learner A, open
   `/courses/<course>/revision/`. Expect the course detail page with its access-ended notice.
   Restore the registration afterwards.
5. As Learner A with access restored, open `/courses/does-not-exist/revision/`. Expect a 404.

## Test 9: quiz pages are unchanged

The option-order tag and the correct-answer mark are shared with quizzes.

1. As Learner A, open the "Foundations" quiz in the course player and start a new sitting if the
   course allows one; otherwise open its results page.
2. Checklist for the quiz page: each question shows its number and text; options render as radio
   buttons, checkboxes or a dropdown by type; selecting one highlights it; "Next" and "Submit"
   work; no "Your answer" mark and no explanation appears while answering.
3. Checklist for the results page: the score shows; where the form shows incorrect answers,
   "Correct answer" marks render with a check icon and green text, as text beside the option
   (the words are visible here; only revision feedback shows the icon alone).
4. As Admin, open the educator interface, the course outline, and preview the same quiz.
   Checklist: every question renders with its options in authored order and "Correct answer"
   beside each correct option.
5. As Admin, check the learner's quiz attempt history for the quiz. Expect it unchanged by the
   revision sessions: the same number of attempts as before Tests 4 to 6.

## Test 10: a dropped question and an edited explanation

1. Copy `demo_content` to a scratch directory. Run
   `uv run python manage.py content_save <scratch>/demo_content DemoDev`.
2. Register `qa-revision@example.com` on "Functionality Demo: Course Parts" if needed and
   complete every item of the part "Core Concepts" in the course player.
3. Open that course in the player and click the outline's "Revision" entry. Expect the
   dashboard. Click "Start revision". Expect to meet questions from both the knowledge check and the
   "Core Concepts revision bank" form, and on the bank-form question with a locked option, expect
   that option last on every showing (reload to check).
4. Answer one bank-form question and note its text.
5. Delete that question from the scratch copy of the bank form's `1. page.yaml`. Run `content_save`
   on the scratch copy again.
6. Reload the revision page. Expect the session to carry on without that question, and the
   question never to appear again. As Admin, expect no "Revision reviews" row for it.
7. Remove the `explanation:` from one knowledge-check question in the scratch copy and run
   `content_validate` on the scratch copy. Expect a warning naming that question and the command
   to finish without failing.
8. Run `content_save` again. Meet that question in revision. Expect feedback with the correct
   answer named in the result box, the "Revisit:" link, and no explanation text.
9. Delete the scratch directory.
