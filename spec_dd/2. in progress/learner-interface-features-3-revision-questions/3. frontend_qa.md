# Frontend QA: revision questions

## Setup

Run from the project root. The QA command picks the port; `$PORT` below is that port.

```
uv run python manage.py migrate
uv run python manage.py content_save demo_content DemoDev
uv run python manage.py qa_create_revision_scenario
uv run python manage.py runserver $PORT
```

Base URL: `http://127.0.0.1:$PORT`

Logins (the password is the email address):

| Who | Email | State |
| --- | --- | --- |
| Learner A | `qa-revision@example.com` | Parts "Foundations", "Practice" and "Backlog" finished; "Advanced" not finished; "Practice" is weak; more than 40 questions ready |
| Learner B | `qa-revision-new@example.com` | Registered on "QA Revision Course", no section finished |
| Learner C | `qa-revision-back@example.com` | Same bank as Learner A, last revision 20 days ago |
| Admin | `demodev@email.com` | Site admin |

The seeder prints the course slug. Below, `<course>` is the slug of "QA Revision Course" and
`<empty>` the slug of "QA Revision Empty Course".

Run every test at the three QA viewports. Each page must have no horizontal scroll.

Re-run `qa_create_revision_scenario` before Test 9 if earlier tests have used up Learner A's ready
questions.

## Test 1: the course links to the revision page

1. Log in as Learner A. Open `/courses/<course>/detail/`.
2. Expect a "Revision" card with the text "40+ ready" and a "Revise" button. No number above 40
   and no word "overdue" appears.
3. Click "Revise". Expect `/courses/<course>/revision/`.
4. Open the first item of the course in the player. Open the course outline panel. Expect a
   "Revision" link with "40+ ready" under the progress bar. Click it. Expect the revision page.

What else could break:

5. Log out. Open `/courses/<course>/detail/`. Expect no "Revision" card.
6. Log in as Learner B. Open `/courses/<course>/detail/`. Expect no "Revision" card (the bank is
   empty).
7. As Learner A, open the detail page of any demo course Learner A is not registered on. Expect no
   "Revision" card and the page otherwise as it normally renders: hero, start button, outline.

## Test 2: the start screen

1. As Learner A, open `/courses/<course>/revision/`.
2. Expect the heading "Revision", "40+ ready" and an "All sections" button.
3. Expect a list of sections. "Practice" is first and carries a "Needs revision" badge that reads
   as words, not colour alone. The other sections follow in course order.
4. Expect no section count above "10+ ready". At least one "Backlog" topic reads "10+ ready".
5. Expect no section from the part "Advanced".
6. Expect no welcome-back line.
7. Tab through the page. Each "Revise" button's accessible name includes its section title.

## Test 3: a wrong answer

1. As Learner A, on the revision page click "All sections".
2. Expect one question, its options, a "Check answer" button and "1 of 15".
3. Note the option order. Reload the page. Expect the same question with the options in the same
   order.
4. Click "Check answer" with nothing selected. Expect an error "Choose an answer." on the card and
   the same question still shown.
5. Select a wrong option and click "Check answer".
6. Expect, in this order: a result line "Incorrect." with an icon; the options in the order they
   were asked; "Correct answer" beside the correct option; "Your answer" beside the option you
   chose; the explanation under "Why" when the question has one; a prominent "Revise: {section
   title}" button; a "Next" button.
7. Expect no "I guessed" toggle and no way to change the answer.
8. Expect keyboard focus on the feedback (press Tab once: focus moves to the first link or button
   inside the feedback, not to the top of the page).
9. Reload the page. Expect the same feedback, not the unanswered question.
10. Click "Revise: {section title}". Expect the course player on that section's first page. For a
    part, that is the part's first child.
11. Go back to `/courses/<course>/revision/`. Expect the same feedback again.

## Test 4: a right answer and "I guessed"

1. From Test 3, click "Next". Expect "2 of 15" and a new question.
2. Select the correct option (for checkboxes, every correct option) and click "Check answer".
3. Expect "Correct." with an icon, "Correct answer" beside the correct option, no "Your answer"
   mark, the explanation when one exists, "Revise: {section title}" as a text-style link, not a filled button, an
   "I guessed" toggle with the line "We'll ask you this one again sooner.", and "Next".
4. Expect no rating name ("Hard", "Good", "Again") anywhere on the page.
5. Click "I guessed". Expect it to show as pressed. Click it again. Expect it not pressed. Click it
   a third time and leave it pressed.
6. Reload. Expect the toggle still pressed.
7. As Admin, open the Django admin, "Revision", "Revision reviews". Expect Learner A's latest
   review with "guessed" true. Expect no add, change or delete controls on either revision model.

## Test 5: the end screen

1. As Learner A, continue the session from Test 4, answering each question (get at least one more
   wrong), to the last question. Click "Next" after it.
2. Expect "15 answered, {X} right." where X matches what you answered.
3. Expect each question you got wrong listed with its "Revise: {section title}" link and no
   option marks.
4. Expect "Revise more" as the only filled button (more are ready), "Back to course" as a
   text-style link, and, when any question is scheduled for later, the date the next one becomes
   ready.
5. Reload. Expect the end screen again, not a question.
6. Click "Revise more". Expect a new session at "1 of 15" with none of the questions you just
   answered right.
7. Close the tab mid-session. Open `/courses/<course>/revision/` again. Expect the session where
   you left it. As Admin, check "Revision reviews": every answer you submitted is there.

## Test 6: one section

1. As Learner A, open `/courses/<course>/revision/` (finish or abandon any open session first by
   answering to the end).
2. Click "Revise" on "Foundations".
3. Expect the progress total to be the number of ready "Foundations" questions, not 15.
4. Answer each. On every feedback, expect the "Revise:" link to name "Foundations" or one of its
   topics.
5. Expect none of these to appear at any point in Tests 3 to 6: the question the seeder marked
   dropped, the "Foundations" question scheduled 30 days ahead, any "Advanced" question.

What else could break:

6. Open `/courses/<course>/revision/start/?section=00000000-0000-0000-0000-000000000000` in the
   address bar. Expect the method to be refused (405), not a session. Do the same for
   `/courses/<course>/revision/next/`: expect 405 and, back on the revision page, the same question
   as before.
7. The "Foundations" quiz is completed for Learner A, so its questions appear in revision. As
   Learner B (who has not sat it), confirm on the revision page that no question is offered at
   all.

## Test 7: empty states

1. As Learner B, open `/courses/<course>/revision/`. Expect "Questions appear here after you
   finish a section." and a "Continue course" link that opens the course player. Expect status
   200.
2. As Learner A, open `/courses/<empty>/revision/`. Expect "This course has no revision
   questions." and a link back to the course. Expect status 200, not a 404 page.
3. As Learner A, work through "Foundations" (Test 6) until none are ready, then start "Revise" on
   it from the start screen. Once nothing is ready, expect the "Foundations" row to read "0 ready"
   with its "Revise" button still shown but disabled.
4. Nothing due at all: as Admin, in a Django shell set every `RevisionSchedule.due` of
   `qa-revision-back@example.com` 10 days ahead and give each of that learner's unscheduled bank
   questions a schedule due 10 days ahead (or ask the QA data helper for "Learner C with nothing
   due and a next due date 10 days ahead"). As Learner C, open `/courses/<course>/revision/`.
   Expect "You're all caught up." and the date the next question becomes ready, in the site's date
   format. Expect no "All sections" button.

## Test 8: welcome back

1. Re-run `qa_create_revision_scenario`. Log in as Learner C. Open
   `/courses/<course>/revision/`.
2. Expect the line "Welcome back. We'll start with the ones you're most likely to have forgotten."
   above the start button.
3. Start "All sections". Answer one question. Go back to the start screen after finishing or by
   opening the URL once the session ends. Expect the welcome-back line gone.

## Test 9: who is turned away

1. Log out. Open `/courses/<course>/revision/`. Expect the login page.
2. As Learner A, open `/courses/<slug of a course Learner A is not registered on>/revision/`.
   Expect a redirect to that course's detail page.
3. As Admin, in the educator interface pause "QA Revision Course" for Learner A's registration (or
   ask the QA data helper to pause it). As Learner A, open `/courses/<course>/revision/`. Expect
   the course detail page with its paused notice and no "Revision" card. Resume the course
   afterwards.
4. As Admin, end Learner A's registration (or ask the QA data helper). As Learner A, open
   `/courses/<course>/revision/`. Expect the course detail page with its access-ended notice.
   Restore the registration afterwards.
5. As Learner A with access restored, open `/courses/does-not-exist/revision/`. Expect a 404.

## Test 10: quiz pages are unchanged

The option-order tag and the correct-answer mark are shared with quizzes.

1. As Learner A, open the "Foundations" quiz in the course player and start a new sitting if the
   course allows one; otherwise open its results page.
2. Checklist for the quiz page: each question shows its number and text; options render as radio
   buttons, checkboxes or a dropdown by type; selecting one highlights it; "Next" and "Submit"
   work; no "Your answer" mark and no explanation appears while answering.
3. Checklist for the results page: the score shows; where the form shows incorrect answers,
   "Correct answer" marks render with a check icon and green text, as text beside the option.
4. As Admin, open the educator interface, the course outline, and preview the same quiz.
   Checklist: every question renders with its options in authored order and "Correct answer"
   beside each correct option.
5. As Admin, check the learner's quiz attempt history for the quiz. Expect it unchanged by the
   revision sessions: the same number of attempts as before Tests 3 to 6.

## Test 11: a dropped question and an edited explanation

1. Copy `demo_content` to a scratch directory. Run
   `uv run python manage.py content_save <scratch>/demo_content DemoDev`.
2. Register `qa-revision@example.com` on "Functionality Demo: Course Parts" if needed and
   complete every item of the part "Core Concepts" in the course player.
3. Open that course's revision page. Expect its start screen with the "Core Concepts" section
   listed. Start a session. Expect to meet questions from both the knowledge check and the
   "Core Concepts revision bank" form, and on the bank-form question with a locked option, expect
   that option last on every showing (reload to check).
4. Answer one bank-form question and note its text.
5. Delete that question from the scratch copy of the bank form's `1. page.yaml`. Run `content_save`
   on the scratch copy again.
6. Reload the revision page. Expect the session to carry on without that question, and the
   question never to appear again. As Admin, expect no "Revision reviews" row for it.
7. Remove the `explanation:` from one knowledge-check question in the scratch copy and run
   `content_validate` on the scratch copy. Expect a warning naming that question and the command
   to finish without failing.
8. Run `content_save` again. Meet that question in revision. Expect feedback with the correct
   answer and the section link, and no "Why" block.
9. Delete the scratch directory.
