# Spec: retire content that is removed from the source

## Purpose

A `content_save` run adds and updates content but never takes any away, so a Topic, Form or
FormQuestion deleted from the content repo stays in the database and is still served. SACAA
requires that a withdrawn question is blocked from learners yet kept for audit, and deleting is
not possible because learner rows hold content with PROTECT. This spec makes one `content_save`
run cover a site's whole source. Content missing from the run is **retired**: no learner is served
it, every learner record that points at it is kept, educators see it marked, and it is un-retired
if it comes back. Background and settled decisions: `idea.md`, `answers.md`.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| retired | narrowed | Glossary (`claude_plugins/fls-dev/skills/domain-glossary/SKILL.md`) uses it for `JobTitle`, `Department`, `Location` entries with `is_active=False`. Here it also means a content row whose `retired_at` is set: not served to learners, never deleted. Never "inactive", "deactivated", "removed" or "archived". |
| un-retire | coined | A later `content_save` run that finds a retired row's uuid (or a `File`'s path) clears its `retired_at`. |

## Scope

In:

- A nullable `retired_at` on `Course`, `CoursePart`, `Topic`, `Activity`, `Article`, `Form`,
  `FormPage`, `FormContent`, `FormQuestion`, `QuestionOption`, `CourseCategory` and `File` (the
  "retirable models").
- The retire sweep and un-retire inside the atomic `content_save` write, with its save-time checks
  and its output.
- Excluding retired rows from every learner-facing read, before any shuffle or draw.
- Progress and completion that leave out retired children.
- No new registration on a retired `Course`.
- The Retired mark in the educator interface, the cohort report, the admin answers page and the
  Django admin changelists.
- The glossary entry, product docs and upgrade notes.

Out: question versions (`sacaa-compliance-content-versions-and-access-3-question-versions`); git
checks, several paths and missing-uuid refusal (spec 1, done); the question-viewing role and admin
question page removal (`sacaa-compliance-content-versions-and-access-4-question-access`); deleting
content or changing `danger_content_delete`; `content_snapshots`; changing `Course.visibility` or
`Article.visibility`; building drawing pages (`sacaa-compliance-3-question-pools`); any per-row
audit entry for a retire.

## Decisions

- **The filter is explicit, never in a manager.** `objects`, `_base_manager` and the reverse
  related managers stay unfiltered. Upserts that un-retire, `danger_content_delete`, the admin,
  reports, audit reads, `QuestionAnswer.selected_options` and pinned papers all need retired rows.
  Learner-facing reads opt in to the filter by name.
- **No new abstract class.** `retired_at` goes on the existing abstract `BaseContent`
  (`freedom_ls/content_base/models.py`), which covers ten of the models. `QuestionOption` and
  `File` declare the same field themselves.
- **One timestamp per run.** Every row a run retires gets the same `retired_at`, taken once, so
  "what did this save retire" is one query.
- **Each row retires by its own absence.** Retirement never cascades down to children and is never
  stamped on them. A child whose own uuid is still in the source stays live, and learner reads skip
  it because its parent is skipped.
- **Retired overrides visibility and registration.** A retired `Course` is closed to every learner,
  registered or not. This is unlike `CourseVisibility.HIDDEN`, which lets registered learners in.
- **Learners get a plain 404.** A link to retired content gets the same response as a missing page.
  There is no new learner copy.
- **Pinning is for quiz papers only.** A quiz sitting finishes on its `served_paper`, retired
  questions and options included. A sitting with no served paper (surveys, `CATEGORY_VALUE_SUM`)
  reads the live tree, so a question retired mid-sitting drops out of the pages still to come. Its
  answers already on file are kept.
- **Completion is never taken back.** A `CourseProgress` with `completed_time` set keeps it.

## Requirements

### Models and migrations

- Add `retired_at = models.DateTimeField(null=True, blank=True, db_index=True)` to `BaseContent`,
  `QuestionOption` (`freedom_ls/form_engine/models.py`) and `File`
  (`freedom_ls/content_engine/models/files.py`). Add one `AddField` migration each in
  `content_engine` and `form_engine`, with no backfill.
- Add an `is_retired` property, and a queryset method `not_retired()` for the retirable models that
  learner reads query directly (`Course`, `CourseCategory`, `Article`, `Form`, `File`). Follow
  `ArticleQuerySet.published()` / `ArticleManager` in `content_engine/models/articles.py`, keeping
  `SiteAwareManager` behaviour. `ArticleQuerySet` gains `not_retired()` next to `published()`.
- `ContentCollectionItem` gets no field. A row left behind by a child's move to another collection
  keeps its present behaviour (`content_engine/moved_children.py`).

### `content_save` (`freedom_ls/content_engine/management/commands/content_save.py`)

- **Mark.** `_write_source` collects the pk of every row it saves, per retirable model, and the
  relative path of every `File` it sees. `_write_sources` merges these sets across all paths.
- **Un-retire.** `save_with_uuid` always writes `retired_at=None` in its `defaults`, so the content
  update and the un-retire are one write. `save_file_to_db` clears `retired_at` on an existing
  `File`.
- **Sweep.** After the `for source in sources` loop and before the `ContentSave` row is written,
  inside the same `@transaction.atomic`: for each retirable model,
  `_base_manager.filter(site=site, retired_at__isnull=True)`, excluding the seen pks (seen paths for
  `File`), `.update(retired_at=run_time)`. It covers every row of the site, whether or not it came
  from a file. A run that fails or rolls back retires nothing.
- **Partial loads.** `save_content_to_db` gains `retire_missing: bool = True`. With `False` it skips
  the sweep and the sweep checks; callers that load part of a site (fixtures, tests) pass it. The
  CLI always retires.
- **Course guard.** When the sweep would retire one or more `Course` rows, the run fails and rolls
  back. The error names each course (title and uuid) and the flag that allows it. `content_save`
  gains `--allow-course-retire` (`allow_course_retire: bool = False` on `save_content_to_db`).
- **Checks after the sweep**, each failing the run with a validation error:
  - A live `FormPage`, `FormContent` or `FormQuestion` whose `condition_option` is retired, or
    belongs to a retired question. The error names the gated item and the retired question.
  - A drawing page left with fewer items than its draw count once retired questions (and the whole
    group of any retired grouped question) are taken out of its pool. The error names the page.
    Drawing pages do not exist yet. This spec fixes the rule; `sacaa-compliance-3-question-pools`
    builds the check, and it reuses the same "live children" function as the served paper below.
- **Output.** After the transaction commits, the same way `removal_lines` and the `Images:` summary
  are printed, print one count line per run with per-model counts, zeros included:
  `Retired: 3 (Topic 1, FormQuestion 2). Un-retired: 1 (Topic 1).` A rolled-back run prints neither.
  Un-retired counts come from rows whose `retired_at` was set before the upsert.
- **Progress.** For every course whose tree had a row retired or un-retired, recalculate each
  `CourseProgress` with `recalculate_progress_percentage` (`learner_progress/signals.py`). Reuse the
  `part_placement_removed` / `recalculate_course_progress_on_placement_removal` pattern so the code
  stays in `learner_progress`. A course with nothing left to complete keeps its records as they
  are, as that receiver already does.
- **Slug collisions.** When `_refuse_article_slug_collisions` or `_refuse_category_slug_collisions`
  refuses a slug held by a retired row, the message says the owner is retired.

### Learner reads: courses and categories

- `VisibilityEnforcingBackend._visibility_decision` (`course_access/backends.py`) returns the closed
  decision for a retired course before any visibility or registration check.
  `VisibilityEnforcingBackend.filter_visible` excludes retired courses outside the registration
  exemption.
- `raise_404_if_unavailable` (`course_access/visibility.py`) and `_course_access_decision`
  (`learner_interface/views.py`) raise 404 for a retired course. This covers every player view that
  looks up a course by slug (`view_course_item`, `form_start`, `form_fill_page`,
  `course_form_complete`, `course_reference`, `course_reference_topic`, `course_finish`,
  `form_submit_and_exit`) and the `course_applications` and `course_interest` views.
- `get_all_courses` and `get_course_registrations` (`learner_interface/utils.py`) leave out retired
  courses. That covers the catalogue, discovery, the dashboard and the completed-courses history.
- Retired `CourseCategory` rows leave the dashboard category list (`learner_interface/views.py`
  `CourseCategory.objects.filter(show_on_dashboard=True)`) and the catalogue's category filters. A
  course stays listed when its `dashboard_category` or a `categories` entry is retired.
- The public blog (`blog/views.py`) chains `not_retired()` after `published()` on the index and on
  `article_detail`. The sitemap leaves out retired articles and courses.

### Learner reads: course outline

- `Course.collection_items()` and `CoursePart.collection_items()`
  (`content_engine/models/courses.py`) stay unfiltered, because the educator outline reads them.
- `viewable_collection_items()` and everything built on it (`viewable_items()`, `children_flat()`,
  `collection_items_flat()`, `lesson_count()`, `includes_assessments()`) skip any item whose child
  is retired, and the whole subtree of a retired `CoursePart`. The skip happens in Python on
  `item.child.retired_at`, after the generic `prefetch_related("child")`.
- `course_reference_topics` and the reference views skip retired parts and topics.
- Player navigation (`player-nav.html`, `player-footer.html`), the progress bar and
  `get_resume_index` read the filtered list. Item indexes shift when an earlier item retires, and
  `get_resume_index` already falls back to the first item.
- Markdown links to a retired `Topic` or `Form` (`content_engine/templatetags/content_tags.py`)
  render as unresolved. `get_file_by_path` and the `audio_file` view (`content_engine/views.py`)
  treat a retired `File` as missing.
- `deadlines/resolver.py` and the deadline admin pickers ignore retired items. Deadline rows stored
  on them are kept.

### Learner reads: forms and questions

- Add one function in `form_engine` that returns a page's non-retired children, each with its
  non-retired options. `build_served_paper` (`_served_children`, `_served_options` in
  `form_engine/served_paper.py`) and `compute_path` (`form_engine/conditions.py`) use it before
  `shuffle_units` and any shuffle, so a group is served without its retired member and a group with
  no live member disappears. Retired `FormPage` rows are left out of a new paper and out of
  `compute_path`.
- `served_path`, `frozen_path` and `full_path` stay unfiltered, so a pinned or finished sitting
  keeps its retired questions and options and its `max_score`.
- Scoring works only from the options the sitting was offered. `FormProgress.compute_quiz_scores`
  and every `is_quiz_answer_correct` caller (`form_engine/models.py`, `form_engine/scoring.py`
  `evaluate_quiz_answers`, the report) pass the options on the sitting's served paper when it has
  one, and the non-retired options when it does not. A retired correct option on a paper started
  after the retirement can never make an answer wrong.
- A retired `Form` is not served: the outline skips its placement. `course_applications` refuses a
  retired `Course.application_form` the way it refuses a missing one. An in-progress `FormProgress`
  on a retired form stays as recorded.
- `form_engine/views.py` answer-file upload keeps looking questions up without the filter, so a
  pinned paper can still be answered.
- Learner-facing counts and numbering (`count_form_questions` callers, `FormQuestion.question_number`)
  leave out retired questions when the sitting has no served paper.

### Registrations

- `require_course_open_to` (`learner_management/queries.py`) raises a new
  `CourseRetiredError(ValueError)` for a retired course. It covers `self_register`,
  `register_cohort_for_course`, and reactivating an existing registration.
  `registration_rules/evaluation.py` `apply_rule_changes` skips a retired `rule.course`.
- `registerable_courses`, `registerable_courses_for` and `registerable_courses_for_learner` leave out
  retired courses. That removes them from the educator add-registration forms and the bulk actions.
- No registration's `is_active` changes when content retires.

### Progress and completion

- `completable_items` (`learner_progress/utils.py`), `calculate_course_progress_percentage` and
  `outstanding_items` (`learner_interface/utils.py`) read the filtered outline, so retired children
  are out of totals and completion checks. A learner who has finished every live item completes at
  `course_finish`. `TopicProgress`, `FormProgress`, `QuestionAnswer`, `CourseFormAttempt` and
  `CourseProgress` rows on retired content are not changed.

### Educator interface and reports

- Add `retired_badge(retired_at: datetime | None) -> StatusBadge | None` beside `inactive_badge` in
  `educator_interface/panels/common/badges.py`: `StatusBadge("muted", "Retired")`, or `None` when
  live. Render it with `<c-panel-status-badge>`; add no new component.
- It appears:
  - in `CourseDataTable` (`panels/course/data_tables.py`) as a badge column, and in the course page
    header `badge` slot. The course detail shows "Retired on <date>" in its definition list.
  - on outline, form page, question and option rows of the course content preview
    (`panels/course/content_preview.py`), via a `retired: bool` on `OutlineRow`, in `reference_rows`,
    and in `_form_preview_context`.
  - on course-title cells in learner and cohort registration lists (`panels/learner/`,
    `panels/cohort/`).
  - in course filter choices (`panels/common/filters.py`), with `Course.label_for` gaining a
    "(retired)" suffix there.
- Retired content stays listed and openable in the educator interface. `courses_visible_to` keeps
  retired courses.
- Cohort report (`reports/indexes.py` `build_course_catalogue`, `load_quiz_questions`;
  `reports/gather.py`): a retired Topic or Form stays a column, carrying the Retired badge and the
  recorded progress and answers, and is left out of completion denominators. Quiz questions and
  options answered and later retired are marked. The PDF matches the screen.
- Admin answers page (`answer_groups`, `admin/form_engine/_answers.html`): answers to a retired
  question, and chosen retired options, are shown in full and marked Retired.
- `freedom_ls/educator_interface/tests/invariants/` rules hold for the new column and badges.

### Django admin

- Add `RetiredListFilter(admin.SimpleListFilter)` in `content_base/admin_filters.py`, next to
  `ContentTagListFilter`, with the choices "Live" and "Retired" and no default. Add it, and a
  read-only `retired_at` column, to the changelists of every retirable model's admin in
  `content_engine/admin.py` and `form_engine/admin.py`. `retired_at` is read-only on every change
  form and inline.

## Testing

- Sweep: a row missing from the run is retired with the run's timestamp; a row seen in any one of
  several paths is not; a `File` retires and un-retires by path; a second identical run changes
  nothing; a run that fails after the sweep leaves every `retired_at` as it was;
  `retire_missing=False` retires nothing.
- Un-retire: a returning uuid clears `retired_at` in the same write as its content update, and its
  learner data shows again.
- Course guard: a run that would retire a course fails and names it, and passes with
  `--allow-course-retire`.
- Gate check: a live item gating on an option of a retired question fails the run and names both.
- Output: count lines appear after commit, zeros included, and nothing is printed for a rolled-back
  run.
- Leak tests, one per learner surface, each with a retired row present: catalogue, course list,
  completed history, course detail and player 404, outline, navigation, progress bar, reference
  pages, blog and sitemap, markdown links and file embeds, `audio_file`, categories, registration
  service functions and pickers, application form.
- Served paper: a new paper omits retired questions, options, content and pages; a group loses only
  its retired member; a group with no live member is gone; nothing retired is ever shuffled in.
- Pinning: a quiz sitting started before a question retires still serves, accepts and scores it,
  and keeps its `max_score`. A sitting started after does not get it. A survey sitting drops it
  from the pages still to come.
- Scoring: a retired correct option on a paper that left it out does not make a new sitting's
  answer wrong.
- Completion: retired children leave the percentage and the outstanding list; a learner with every
  live item done completes; a completed `CourseProgress` stays completed; a course with every child
  retired keeps its records.
- Records kept: `FormProgress`, `QuestionAnswer` with its selected options, `TopicProgress`,
  `CourseProgress`, `CourseFormAttempt` and both registration types are unchanged after a retire,
  and `is_active` is unchanged.
- Educator: the Retired badge shows on each surface listed above, and retired content stays
  listed; the cohort report shows a retired column outside the denominator; the admin filter and
  column work.

## Open questions

- Q: Should two `content_save` runs for one site be kept from overlapping (a lock on the site)? → A:
  No lock. (assumed default: saves are rare and run by hand, and the sweep runs in the same
  transaction as the upserts. Overrule by editing "`content_save`".)
- Q: Does a retired row's mark use the muted tone, the same as Inactive? → A: Muted. (assumed
  default: a retired row is not an error, and muted matches the existing exceptional-state badges.
  Overrule by editing "Educator interface and reports".)

## Success criteria

- A content row deleted from the source is never shown to any learner after the next
  `content_save`, and every learner row pointing at it still exists.
- The same row returned to the source with its uuid is served again after the next run.
- A run that would retire a `Course` fails unless `--allow-course-retire` is given.
- A quiz attempt in progress when a question retires finishes with that question and an unchanged
  `max_score`.
- No new paper, shuffle or completion total includes a retired row.
- Every educator surface listed under "Educator interface and reports" shows the Retired badge, and
  the admin changelists filter on it.
- `uv run pytest` passes, including the leak test for each learner surface.
