# Frontend QA: retire content that is removed from the source

A `content_save` run now retires content that is missing from the source. Learners are never
served retired content (a plain 404, or the row is absent). Educators and the Django admin still
see it, marked "Retired". No learner page gains new copy; the educator pages gain a badge.

## Setup

- Start the server with the `Dev server start` command under `## QA Hooks` in
  `.claude/sdd/config.md`, on `$PORT`. The base URL is `http://127.0.0.1:$PORT`.
- Run `uv run python manage.py migrate`.
- **Work on a copy of the demo content, never on `demo_content/` itself.** `content_save` needs a
  clean git repository, and the tests delete content files:

  ```
  QA_SRC="$(mktemp -d)/qa_content"
  cp -r demo_content "$QA_SRC"
  git -C "$QA_SRC" init -q && git -C "$QA_SRC" add -A && git -C "$QA_SRC" commit -qm "baseline"
  uv run python manage.py content_save "$QA_SRC" DemoDev
  ```

  If this first run is refused because the dev database holds courses that are not in the demo
  content (QA fixtures, hand-made rows), that is Test 2's behaviour showing early: note the
  message, then re-run with `--allow-course-retire`.
- Log in at `http://127.0.0.1:$PORT/accounts/login/` as `demodev@email.com`, password
  `demodev@email.com`. This user is a learner, an educator and an admin.
- Courses used: "Functionality Demo - Course Parts" (several parts and topics) and "Functionality
  Demo - Shuffled Quiz" (a scored quiz). Find each slug from `http://127.0.0.1:$PORT/courses/`:
  the detail URL is `/courses/<course-slug>/detail/`. Register `demodev` on both from the detail
  page if it is not registered already.
- The educator interface is reached from the main navigation ("Educator" or similar). The course
  list is its Courses page.
- Ask `sdd:qa-data-helper` for any record a test names that the database lacks.

Check each page at 1920x1080, 375x812 and 768x1024 unless a test names one width. At every width:
no horizontal scroll, no console errors.

## Test 1: a topic removed from the source is retired

1. As the learner, open "Functionality Demo - Course Parts" in the player and complete the first
   topic. Note the outline: the titles in order, the progress bar percentage, and the URL index of
   the third item.
2. In `$QA_SRC`, delete the markdown file of the **second** topic of that course, remove it from
   its parent's `children:` list if it is listed there, and commit:
   `git -C "$QA_SRC" add -A && git -C "$QA_SRC" commit -qm "remove a topic"`.
3. Run `uv run python manage.py content_save "$QA_SRC" DemoDev`.

Expect in the terminal: one line of the form
`Retired: 1 (Topic 1). Un-retired: 0.` (other models may appear if the topic had its own files).

4. Reload the player.

Expect:

- The retired topic is gone from the outline sidebar, at all three widths. The remaining rows keep
  their order and are numbered without a gap.
- The old third item is now at the second index. Previous and Next in the player header and
  footer step over where the retired topic was, with no dead link.
- The progress bar percentage is higher than in step 1 (one of fewer items is done) without the
  learner doing anything.
- The old URL of the last index (`/courses/<course-slug>/<last-index>/`) is a 404 page, the same
  one a made-up index gives.
- The breadcrumb on a topic inside a part still names the right part.

5. Run the same `content_save` command again, unchanged.

Expect: `Retired: 0. Un-retired: 0.` and nothing changes in the player.

## Test 2: a run that would retire a course is refused

1. In `$QA_SRC`, delete the whole `functionality_demo_end_with_topic` directory and commit.
2. Run `uv run python manage.py content_save "$QA_SRC" DemoDev`.

Expect: the command fails. The message names the course by title and uuid and names
`--allow-course-retire`. No `Retired:` line is printed.

3. Reload `http://127.0.0.1:$PORT/courses/`.

Expect: the course is still in the catalogue and its detail page still opens. Nothing was retired.

4. Run the command again with `--allow-course-retire`.

Expect: it succeeds and the `Retired:` line counts 1 Course.

## Test 3: a retired course is closed to learners

Uses the course Test 2 retired. Before Test 2 step 4, register `demodev` on it and note its
detail and player URLs.

1. Open `http://127.0.0.1:$PORT/courses/`.

Expect: the course is not in the catalogue, in any category filter, or in a search for its title.

2. Open the learner dashboard.

Expect: the course is not under in-progress courses, not in recommendations, and not in the
completed-courses history.

3. Open the noted detail URL, the player URL, and `/courses/<course-slug>/reference/`.

Expect: each is the standard 404 page. No page says "retired".

4. Log out and open the detail URL as an anonymous visitor.

Expect: the same 404.

5. If the dev settings have the visibility override on (hidden courses shown to everyone), repeat
   step 3.

Expect: still 404. The override does not reopen a retired course.

## Test 4: content comes back when it returns to the source

1. In `$QA_SRC`, restore the topic deleted in Test 1 and the course deleted in Test 2:
   `git -C "$QA_SRC" revert --no-edit HEAD HEAD~1` (or `git checkout <baseline-commit> -- .` and
   commit).
2. Run `uv run python manage.py content_save "$QA_SRC" DemoDev`.

Expect: `Un-retired:` counts the topic, the course and the course's own children; `Retired: 0`.

3. Reload the catalogue, the dashboard and the player of "Functionality Demo - Course Parts".

Expect: the course is listed again and opens. The topic is back in its old place in the outline.
The first topic is still marked complete, and `demodev`'s registration on the returned course
still works without registering again.

## Test 5: a quiz in progress keeps its paper

1. As the learner, start the quiz in "Functionality Demo - Shuffled Quiz" and answer the first
   question only. Note the question count the quiz shows and the questions on the first page.
2. In `$QA_SRC`, remove one question from that quiz's form file (one the sitting has not answered
   yet, on a later page if there is one) and one option from another question, and commit. Run
   `content_save`.

Expect in the terminal: the `Retired:` line counts 1 FormQuestion and its options, plus 1
QuestionOption.

3. Go back to the open quiz and continue to the end. Submit.

Expect:

- The removed question is still served on its page, with all its options, and accepts an answer.
- The question with the removed option still shows that option.
- The result page's total ("x out of y") uses the same number of questions as step 1.

4. Start a new attempt (retake, or as a second learner the data helper creates and registers).

Expect: the removed question is not on any page; the question that lost an option shows one fewer
option; question numbers run without a gap; the total is one lower than in step 1.

5. Answer the question that lost an option correctly and submit.

Expect: it is marked correct, and the review of wrong answers never shows the removed option as
"the correct answer".

## Test 6: educators see retired content, marked

Retire a course again for this test (repeat Test 2 steps 1 and 4), and keep the retired topic and
question from Tests 1 and 5 retired (re-do those removals in `$QA_SRC` and run `content_save` if
Test 4 brought them back).

1. Open the educator Courses page.

Expect:

- The retired course is still listed. Its row has a muted "Retired" badge in a badge column. Live
  courses have nothing in that column.
- At 375x812 the table shows as cards; the badge stays on one line and nothing overflows.
- The course filter choices on pages that filter by course (the learners list, the cohort pages)
  label it with "(Retired)".

2. Open the retired course's page.

Expect: the page opens. The header shows a "Retired" badge beside the title. The course details
list has a "Retired on" row with the date of the run. A live course's page has neither.

3. Open "Functionality Demo - Course Parts" (live course, retired topic) and look at its outline.

Expect: the retired topic is still in the outline, with a "Retired" badge on its row, on one line
with the title. Its siblings and its part have no badge. Clicking the retired row still opens its
preview.

4. Open the outline of "Functionality Demo - Shuffled Quiz" and preview the quiz form.

Expect: the retired question is shown with a "Retired" badge, and the retired option on the other
question has one too. Live questions and options have none. The answer key still shows.

5. Open a learner page and a cohort page that list a registration on the retired course.

Expect: the registration row is still there, its course title carries the "Retired" badge, and
the registration's active state is unchanged.

6. On a learner's page, open the add-registration form, and try the bulk register action on the
   learners list.

Expect: the retired course is not offered in either picker.

## Test 7: the cohort report

Needs a cohort registered on "Functionality Demo - Course Parts" and on "Functionality Demo -
Shuffled Quiz", with at least two learners who have progress and a completed quiz attempt from
before the retires. Ask `sdd:qa-data-helper` for it if absent.

1. Open the cohort's report on screen.

Expect:

- The retired topic is still a column, its header marked "Retired". Cells show the progress
  learners recorded on it.
- Completion fractions and percentages do not count it: a learner who has done every live item
  shows as complete.
- In the quiz section, the retired question is listed and marked "Retired". A learner's wrong
  answer to it is shown in full. A chosen option that is retired is marked.
- The table scrolls sideways inside its own region at 375x812; the page itself does not.

2. Download the PDF.

Expect: the same columns, the same "Retired" marks and the same fractions as the screen.

## Test 8: the Django admin answers page

1. Open the answers page of the quiz attempt from Test 5 step 3 (Form progress in the admin).

Expect: the answer to the retired question is shown in full with "Retired" beside the question,
and a chosen retired option is marked.

## Test 9: other learner surfaces

1. Blog: in `$QA_SRC`, delete one article from `functionality_demo_articles`, commit and run
   `content_save`. Open the blog index and the article's old URL.

Expect: it is off the index; its URL is a 404; `/sitemap.xml` does not list it.

2. Links and files: pick a topic in "Functionality Demo - Content Widgets" or "Standard Markdown"
   that links to another topic or embeds an image. Delete the linked topic (or the image file) in
   `$QA_SRC`, commit, run `content_save`, and open the topic that referred to it.

Expect: the page still renders. The link shows the way an unresolved content link does and the
image shows the way a missing file does. No traceback and no console error.

3. Category: delete one entry from `$QA_SRC/course_categories.yaml` that a live course uses,
   commit, run `content_save`.

Expect: the category is gone from the catalogue filters and the dashboard category sections. The
courses that used it are still listed.

4. Application form: for "Functionality Demo - Application Form", delete the application form's
   file in `$QA_SRC` (leave the course), commit, run `content_save`, and open the course's apply
   page as a learner who has not applied.

Expect: the same response the apply page gives a course with no application form. No traceback.

## Clean up

Restore the dev database's content: `git -C "$QA_SRC" checkout <baseline-commit> -- .`, commit,
and run `content_save "$QA_SRC" DemoDev` so everything un-retires. Then delete the temporary
directory that holds `$QA_SRC`.
