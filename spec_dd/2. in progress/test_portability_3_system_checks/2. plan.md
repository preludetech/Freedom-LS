## Ground truth (confirmed against the current tree, 2026-08-23)

- **`freedom_ls_course_access.E001` already reports an unset
  `COURSE_ACCESS_BACKEND`.** `freedom_ls/course_access/checks.py:42-46`
  short-circuits on `config.missing_required()` and returns
  `required_settings_errors(config, "freedom_ls_course_access")`.
  `freedom_ls/course_access/tests/test_checks.py::TestCourseAccessSystemCheck::test_unset_backend_reports_required_setting_error`
  passes today. No new check is needed for this.
- **`freedom_ls_course_access.E001` is also used for the `access_config`
  validation error** at `freedom_ls/course_access/checks.py:69` — the overload
  this plan splits.
- **`required_settings_errors(config, app_label)`**
  (`freedom_ls/base/app_settings.py:62`) hardcodes `<app_label>.E001`. It is
  shared with `freedom_ls/reports/checks.py:34` and
  `freedom_ls/content_engine/checks.py:20`, so **do not change the helper** —
  move the *other* course_access error off E001 instead.
- **`freedom_ls/learner_interface/apps.py`** is a bare `AppConfig`
  (`LearnerInterfaceConfig`, `label = "freedom_ls_learner_interface"`) with no
  `ready()`.
- **Sitemap wiring** lives in the project root: `config/urls.py:41-54` names
  `sitemap` and `robots_txt`, with `StaticViewSitemap`/`CourseSitemap` from
  `config/sitemaps.py` and `robots_txt` from `config/views.py`. None of it ships
  in the package.
- **FLS-shipped backends:** `freedom_ls/course_access/backends.py`
  (`CourseAccessBackend`, `FreeOnlyCourseAccessBackend`,
  `VisibilityEnforcingBackend`) and
  `freedom_ls/course_applications/backends.py`
  (`ApplicationCourseAccessBackend`). Only the last lives in an app a downstream
  might legitimately not install — it is the E003 case.
- **Check-test style:** `freedom_ls/course_access/tests/test_checks.py` — call
  the check directly with `app_configs=None`, drive via `@override_settings`,
  assert on `.id`. Note the existing course_access checks do **not** honour the
  `app_configs` contract; new checks here do, but retrofitting the existing ones
  is out of scope.

Add a `TestCourseAccessBackendAppInstalledCheck` class:

- Fires: `@override_settings(COURSE_ACCESS_BACKEND="freedom_ls.course_applications.backends.ApplicationCourseAccessBackend")`
  plus an `INSTALLED_APPS` without `freedom_ls.course_applications` → one Error
  with id `freedom_ls_course_access.E003`.
- Silent for the reference config (the shipped backend with its app installed).
- Silent for a non-FLS path — `@override_settings(COURSE_ACCESS_BACKEND="config.access.MyBackend")`
  → `[]`, even though no app contains it. This is the false-positive guard.
- Silent when the setting is unset (`COURSE_ACCESS_BACKEND=""`) → `[]`, because
  E001 owns that condition.
- `app_configs` early-return: passing an unrelated app config → `[]`.

### T1.2 `freedom_ls/learner_interface/tests/test_checks.py` (new)

- Fires: `INSTALLED_APPS` without `django.contrib.sitemaps`, with the default
  URLconf (which wires `sitemap`) → one Warning, id
  `freedom_ls_learner_interface.W001`.
- Silent under the reference settings (sitemaps installed).
- Silent when no `sitemap` URL is wired — `@override_settings(ROOT_URLCONF=...)`
  pointing at a module with no `sitemap` name, and no `django.contrib.sitemaps`.
- Silent when `freedom_ls.learner_interface` is not in `INSTALLED_APPS`.
- `app_configs` early-return honoured.

Note for whoever writes these: `@override_settings(INSTALLED_APPS=...)` triggers
an app-registry reload, so build the list by filtering
`settings.INSTALLED_APPS` rather than hand-writing a short one.

`freedom_ls/course_access/checks.py`:

- Change the `Error(...)` at line 69 (invalid `access_config`) to

  - `E001` — a required setting is unset (emitted by the shared

  - `W001` — a dev/staging preview override is on while `DEBUG` is `False`.

## T3 — Add `freedom_ls_course_access.E003`

New `@register()` function in `freedom_ls/course_access/checks.py`, alongside the
existing two. Local imports inside the body, matching the module's style.

```python
@register()
def check_course_access_backend_app_installed(
    app_configs: Sequence[AppConfig] | None, **kwargs: object
) -> list[CheckMessage]:
    from django.apps import apps

    from freedom_ls.course_access.config import config

    if app_configs is not None and not any(
        c.label == "freedom_ls_course_access" for c in app_configs
    ):
        return []
    if config.missing_required():
        # An unset backend is E001's business.
        return []
    dotted = config.COURSE_ACCESS_BACKEND
    if not dotted.startswith("freedom_ls."):
        # A downstream's own backend lives outside any FLS app; whether it
        # loads is the conformance suite's question, not this check's.
        return []
    if apps.get_containing_app_config(dotted.rsplit(".", 1)[0]) is None:
        return [
            Error(
                f"COURSE_ACCESS_BACKEND {dotted!r} is not provided by any installed app.",
                hint="Add the backend's app to INSTALLED_APPS, or point COURSE_ACCESS_BACKEND at a backend you have installed.",
                id="freedom_ls_course_access.E003",
            )
        ]
    return []
```

No install-gate on `course_access` itself is needed: the module is only imported
from `CourseAccessConfig.ready()`, so an uninstalled app registers nothing.
`get_containing_app_config` does not import the target and returns `None` rather
than raising, so the check cannot raise.

## T4 — Add `freedom_ls_learner_interface.W001`

### T4.1 New `freedom_ls/learner_interface/checks.py`

```python
@register()
def check_sitemaps_app_installed(
    app_configs: Sequence[AppConfig] | None, **kwargs: object
) -> list[CheckMessage]:
    from django.conf import settings
    from django.core.exceptions import ImproperlyConfigured
    from django.urls import NoReverseMatch, reverse

    if "freedom_ls.learner_interface" not in settings.INSTALLED_APPS:
        return []
    if app_configs is not None and not any(
        c.label == "freedom_ls_learner_interface" for c in app_configs
    ):
        return []
    if "django.contrib.sitemaps" in settings.INSTALLED_APPS:
        return []
    try:
        reverse("sitemap")
    except (NoReverseMatch, ImproperlyConfigured):
        return []
    return [
        Warning(
            "A 'sitemap' URL is wired but 'django.contrib.sitemaps' is not in INSTALLED_APPS.",
            hint="Add 'django.contrib.sitemaps' to INSTALLED_APPS, or remove the sitemap URL.",
            id="freedom_ls_learner_interface.W001",
        )
    ]
```

The `INSTALLED_APPS` test comes before `reverse()` so a correctly-configured
project never loads the URLconf during checks.

## Downstream-visible change

The `E001` → `E002` re-ID must be called out at SDD step 11
(`/update_upgrade_notes`) with `requires_settings_change: true` and
`changed_settings` naming `SILENCED_SYSTEM_CHECKS`: a project silencing
`freedom_ls_course_access.E001` for access-config reasons must switch to
`.E002`, or it will silently keep suppressing the missing-required-setting error.
