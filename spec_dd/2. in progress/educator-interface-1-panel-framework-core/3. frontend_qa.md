# Frontend QA: panel framework core

Browser checks for `1. spec.md`. Run them after `2. plan.md` is implemented and the automated suite is green. Every step says where to go, what to do and what you should see. Steps marked **side effect** or **failure branch** exercise what could break around the golden path.

## 0. Setup

### 0.1 Server

```bash
PORT=$(.claude/ds/scripts/find_available_port.sh)
npm run tailwind_build
uv run python manage.py check
uv run python manage.py runserver $PORT
```

Base URL: `http://127.0.0.1:$PORT`. `manage.py check` must print "System check identified no issues".

### 0.2 Seed data

```bash
uv run python manage.py qa_create_organisation_scenarios
uv run python manage.py qa_create_educator_modal_target
```

The first command seeds three organisations (RPAS Training `rpas-training`, Northside `northside`, Southgate `southgate`), cohorts (Year 9 Maths, Year 10 Science, Southgate Only) and personas. The second seeds one educator with a per-cohort grant plus a cohort that cannot be deleted.

## 1. Entry, dashboard and sidebar

Log in as Admin.

1. Visit `/educator/`. Expect a redirect to `/educator/organisations/<slug>/dashboard` (the remembered or first organisation).
2. Page title in the browser tab reads "Dashboard — <Organisation> — <site name>". The page heading reads "Dashboard".
3. The main content is one surface card titled "Reporting" with a single sentence saying on-screen reporting arrives in a later release. No stat tiles, no lists.
4. Sidebar, top to bottom: the organisation switcher, a "Teaching" heading, then Dashboard, Cohorts, Learners, Courses, each with an icon on the left. Dashboard is highlighted (left border, bold). No counts are shown.
5. Below the nav, a footer shows the logged-in user's full name and email, no role and no settings link.
6. **Failure branch:** log in as `no.access@example.com` and visit `/educator/`. Expect a 404 page. `/educator/organisations/rpas-training/dashboard` also 404s.

## 2. Section navigation over htmx

Still as Admin, on the dashboard. Open DevTools → Network (keep it open for the rest of the run).

1. Click "Cohorts" in the sidebar. Expect: the URL changes to `…/cohorts` without a full reload (one XHR in the network panel), the heading becomes "Cohorts", the breadcrumb shows "Cohorts", the browser tab title updates, and the sidebar highlight moves to Cohorts.
2. Inspect that XHR's response headers: `Vary` contains `HX-Request`, `HX-Target` and `HX-History-Restore-Request`.
3. Press Back. Expect a fresh request (the network panel shows a GET of the dashboard URL, not a cached restore) and the dashboard page again, sidebar highlight on Dashboard.
4. Press Forward. Cohorts again.
5. View page source (`Ctrl+U`) on any educator page: the `<head>` contains `<meta name="htmx-config" content='{"historyCacheSize": 0, "historyRestoreAsHxRequest": false}'>`, and `<div id="scope-announcer" …>` appears once, outside `<div id="main-content">`.

## 3. Cohort list and detail

As Admin in RPAS Training (`/educator/organisations/rpas-training/cohorts`).

1. The list shows Year 9 Maths and Year 10 Science with learner counts and registered courses. A "Create Cohort" button sits above the table.
2. Click "Year 9 Maths". Expect the detail page at `…/cohorts/<pk>`: an `<h1>` with the cohort name, then a tab strip with one tab, "Details", underlined as current, then three surface cards: "Details" (Name row, with Edit and Delete buttons at its foot), "Course Registrations" and "Learners".
3. The Delete button is inside the Details card, not above the tab strip. There are no buttons above the tab strip.
4. The sidebar now shows "Year 9 Maths" expanded under Cohorts, highlighted.
5. The breadcrumb reads "Cohorts › Year 9 Maths"; clicking "Cohorts" returns to the list over htmx.
6. **Side effect:** sort the Learners card by "First Name" and page it if it has more than one page. Only the table inside the card changes; the card's heading stays; the URL does not change; the page does not gain a second "Learners" heading or nested card (inspect: exactly one `section[data-panel="learners"]`, with no `section` inside it).
7. Type in the Learners card's search box. Same expectations as step 6.

## 4. Tabs and history

On the Year 9 Maths detail page.

1. Click the "Details" tab. Expect the URL to change to `…/cohorts/<pk>/__tabs/details`, one XHR, the three cards re-rendered once (no duplicates), the tab still underlined, and keyboard focus still on the tab link (press Tab once: focus moves to the next link after it, not to the top of the page).
2. Inspect the XHR response body: it contains the three cards and an element with `hx-swap-oob="innerHTML:#scope-announcer"` whose text is "Showing Details". It does not contain the sidebar or `<html>`.
3. Press Back. The URL returns to `…/cohorts/<pk>`; the page is fetched fresh; the content is the same three cards.
4. Open `…/cohorts/<pk>/__tabs/details` in a new browser tab. Expect the full page (header, sidebar, breadcrumbs) with the Details tab current, not a bare fragment.
5. **Failure branch:** visit `…/cohorts/<pk>/__tabs/nope`, `…/cohorts/<pk>/__panels/details` (a `__panels` segment on a tab set) and `…/cohorts/<pk>/__tabs/details/__panels/nope`. Each is a 404 page.
6. **Failure branch:** with the network panel, right-click the "Details" tab XHR and copy as cURL; re-run it with `-H "HX-Target: something-else"` added. The response is the navigation bundle (it contains `id="sidebar-nav"`), never a bare fragment.

## 5. Edit a cohort

On Year 9 Maths.

1. Click "Edit" in the Details card. A modal titled "Edit Year 9 Maths" opens with the Name field.
2. **Failure branch:** change the name to "Year 10 Science" (already exists in this organisation) and save. The modal stays open and shows the uniqueness error under the field. Nothing else on the page changes.
3. Change the name to "Year 9 Mathematics" and save. Expect: the modal closes because the Details card re-renders, the Name row shows "Year 9 Mathematics", the `<h1>` shows "Year 9 Mathematics", and no full page reload happened (one POST, then one GET per leaf panel on the page — Details, Course Registrations and Learners — each carrying `HX-Target` equal to its own panel's region id, because every leaf answers `panelChanged`).
4. Reload the page: the new name persists. The sidebar disclosure under Cohorts also shows the new name.
5. Rename it back to "Year 9 Maths".

## 6. Create and delete a cohort

On the cohorts list as Admin.

1. Click "Create Cohort", enter "QA Empty Cohort", click "Save". Expect a redirect to the new cohort's detail page.
2. Click "Delete" in the Details card. The confirmation says "Are you sure you want to delete QA Empty Cohort?" with no "This will also delete" list.
3. Confirm. Expect a redirect to the cohorts list without "QA Empty Cohort".
4. **Side effect:** click "Create Cohort", enter "QA Refresh A", click "Save and add another". The modal stays open with an empty form and the list table behind it now shows "QA Refresh A" without a page reload. Enter "QA Refresh B", "Save". You land on QA Refresh B's page; the list, when you go back, shows both. Delete both afterwards.
5. **Failure branch:** log in as `qa_educator@example.com`, open its cohort ("QA Modal Cohort" or similar, the only one listed). Delete shows the cascade summary (memberships, registrations) or, if a course progress record exists, the sentence "cannot be deleted because it still has …" with a Close button only. There is no "Create Cohort" button on this educator's list page and no "Edit" button (no change permission).
6. **Failure branch:** as that educator, submit the delete anyway with cURL (`curl -X DELETE -b "<session cookie>" -H "X-CSRFToken: <token>" <detail-url>/__actions/delete`). Expect 422 with the blocked reason, or 204 with `HX-Redirect` only if the cohort was genuinely deletable. The response carries the `Vary` header.
