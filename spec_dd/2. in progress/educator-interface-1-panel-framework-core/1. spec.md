# Spec: panel framework core

Spec 1 of 12 in the educator interface rebuild (`../../1. next/educator-interface-full-polish/spec-order.md`). Source: `idea.md` in this directory. The approach and its reasons are settled there and are not restated here.

## Purpose

`freedom_ls/panel_framework` cannot carry the rebuilt educator interface. Panels return HTML strings. Delete actions 500 when returned from a panel. There is no panel permission hook and no instance-free panel. Scoping is split across two methods. Field resolution crashes on properties. Tabs fight htmx over browser history. This spec reworks the framework's API so it can go to a downstream project as a documented, reusable thing. It then re-expresses the educator interface on the new API as the framework's reference consumer and deletes the cohort course-progress matrix.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| `PanelContext` | coined | Frozen, keyword-only dataclass holding everything a panel or action needs at render time. There was no existing term: today these values are positional arguments. |
| bound panel | coined | An instance of a `Panel` subclass, built fresh per request from the declared class and a `PanelContext`. |
| `PanelStack` / `TabSet` | coined | Container panels: one renders its children in order, the other as tabs. |
| region template | coined | The template for the part of a panel that a targeted htmx refresh replaces (`Panel.region_template_name`). |
| base view | coined | A sidebar destination that renders a root panel with no instance and no table (`BaseViewConfig`). |
| `NavGroup` | coined | A headed group of sidebar destinations. It isn't called a "section" because that word already means one destination. |
| section | narrowed | One sidebar destination: a `ListViewConfig`, `ObjectViewConfig` or `BaseViewConfig`. Previously a `ListViewConfig` only (`research_current_structure.md`). |
| child panel | narrowed | A panel inside a container's `children`. It has nothing to do with the course-content "child" in the domain glossary. |

## Scope

In:

- The framework API: bound panels, `PanelContext`, containers, instance-free panels, the panel permission hook, the single scoping seam, the template contract, targeted refresh, vendored field resolution, and `manage.py check` validation.
- URL-state hardening: `Vary`, history restore, the history cache turned off, and tabs as htmx navigation.
- Grouped sidebar navigation with an optional count hook; base views and single-object views.
- Two empty host blocks in `_base_interface.html`.
- Every existing educator-interface panel re-expressed on the new API, a dashboard placeholder, a sidebar user footer, and the progress matrix deleted.
- Tests, the product-doc update and upgrade notes.

Out:

- The table layer's query-state prefixing, filters, selection and export (spec 2). This spec keeps `DataTable` and its dotted column `attr` paths. It must not make spec 2 harder.
- Filling the quick-view and modal blocks (spec 3), the component library (spec 4), and what `has_permission` returns per role (spec 5).
- Any section functionality beyond today's, apart from the dashboard placeholder.
- A mobile bottom tab bar. The sidebar sheet stays.
- Any new dependency or `INSTALLED_APPS` change.

## Decisions

- **A bound panel is an instance of the declared class**, constructed as `PanelClass(ctx)`. No `clone()`/`clone_kwargs()` and no nested `BoundPanel` class. Class attributes are the definition-time binding (`model`, `fields`, `children`, `template_name`); the instance is the render-time binding.
- **`PanelContext` is the one render-time argument** for panels and actions. New fields get defaults, so adding one never breaks a subclass. The name avoids Django's own `django.template.context.RenderContext`.
- **Targeted refresh renders a separate region template, not `template_name#partial`.** In Django 6.0.4 a partial is only reachable through the name of the file that declares it, never through a template that extends it (verified: `leaf.html#region` raises `TemplateDoesNotExist` when the `partialdef` is in `base.html`). A region template can follow the leaf/base pairing like any other. Templates may still use `{% partialdef %}` for reuse within one file.
- **Every tab click fetches.** A tab link does `hx-get` with `hx-push-url` into its tab set's region. There is no client-side cache of loaded tabs, and the Alpine `tabContainer` component is deleted. The click-once-and-show-hide alternative can't push a URL without a request.
- **`aria-current` moves client-side.** The tab nav sits outside the swapped region and a small `htmx:afterSwap` handler moves `aria-current` to the clicked link. Swapping the nav would destroy the focused link, and htmx restores focus only to elements with an id.
- **The framework owns the live region.** `#scope-announcer` moves from the educator interface's template into a framework partial that a host includes once, outside `#main-content`. The id stays, to avoid churn.
- **Check discovery walks `Panel.__subclasses__()` recursively** after importing the root URLconf. The framework has no registry, and every consumer panel is reachable from a module the URLconf imports.
- **Only `InstanceDetailsPanel.fields` moves to `__` paths.** Table column paths and `resolve_url_path_template` stay dotted until spec 2 rebuilds the table layer.
- **The history-cache change is site-wide.** It lives in `_base.html`, so the learner interface gets it too. That is intended: Back always refetches.

## Requirements

### Panel core, `freedom_ls/panel_framework/panels.py`, new `context.py`

1. `PanelContext` in `freedom_ls/panel_framework/context.py`:

   ```python
   @dataclass(frozen=True, kw_only=True)
   class PanelContext:
       request: HttpRequest
       instance: Model | None
       base_url: str   # URL of this panel's own path segment
       name: str       # this panel's key in its parent's children ("" for a root)
   ```

   Children receive `dataclasses.replace(ctx, base_url=..., name=...)`. Nothing mutates a context.

2. `Panel` is constructed as `Panel(ctx: PanelContext)` and exposes `self.ctx`, `self.request` and `self.instance`. Class attributes: `title: str = ""`, `template_name`, `region_template_name: str | None = None`, `model: type[Model] | None = None`. Methods:
   - `has_permission(self, request: HttpRequest) -> bool`. Defaults to `True`. Its docstring is the hook's documentation: what it gates, that it is evaluated per request, and that spec 5 owns the educator interface's rules.
   - `is_shown(self) -> bool`. Returns `has_permission(self.request)` for a leaf. For a container, it also requires at least one child to be shown.
   - `get_actions(self) -> list[PanelAction]`, filtered by each action's `has_permission` before rendering.
   - `get_context_data(self) -> dict[str, object]`. Subclasses call `super()` and add keys. The base provides `panel` (self), `title`, `actions`, `region_id` and `region_template_name`.
   - `region_id` (property). A DOM id derived from `ctx.base_url`, unique on the page. It is the only id a targeted refresh uses, so consumer code never writes one.

   `get_content()` and every `render()` that returns `str` are removed. `PanelGetter` goes.

3. Containers: `PanelStack(Panel)` and `TabSet(Panel)`, each with `children: dict[str, type[Panel]]`. Each child is bound through the same `PanelClass(ctx)` call the leaves use, and only children whose `is_shown()` is true are rendered or reachable by URL. A hidden child's URL is a 404. A `TabSet` child's `title` is its tab label, and a `TabSet` is itself the region a tab switch swaps. `tabs.py` and the `Tab` dataclass are deleted.

4. Instance-free panels. `ctx.instance` may be `None`. `InstanceDetailsPanel` and any panel declaring `model` require an instance. A panel with `model = None` works with an instance or without one.

5. `DataTablePanel` (leaf, instance optional). `data_table: type[DataTable]`, plus `get_queryset(self, request: HttpRequest) -> QuerySet`, which defaults to `self.data_table.get_queryset(request)`. A subclass narrows it with `super().get_queryset(request).filter(...)`. `get_filters()` is removed. `DataTable.get_rows` takes the queryset from the panel instead of a `filters` dict. The table markup is the panel's region template.

6. `InstanceDetailsPanel`. It needs `model` and `fields: list[str]` of `__` paths, and has `empty_value_display: str = "-"`. Context rows are `{"label", "value", "is_boolean"}`. The vendored `label_for_field` resolves the label, and the template applies `capfirst` once. Nothing calls `.title()`. The value comes from `lookup_field` then `display_for_field`, or `display_for_value` when there is no field. `editable` and `form_class` keep adding an `EditAction`. `_resolve_field` is removed.

### Field resolution, new `freedom_ls/panel_framework/field_display.py`

7. Vendor `label_for_field`, `lookup_field`, `display_for_field` and `display_for_value` from Django 6.0.4's `django/contrib/admin/utils.py`, with the private helpers they need (`_get_non_gfk_field`, `get_fields_from_path`, `get_model_from_relation`, `NotRelationField`, `FieldIsAForeignKeyColumnName`). The module header names the origin file, the Django version, and "Copyright (c) Django Software Foundation and individual contributors", with Django's BSD-3-Clause licence text in full. Nothing in the framework imports `django.contrib.admin`. The adaptations:
   - The `model_admin` and `form` parameters are dropped.
   - Booleans return the boolean value, and templates render it with `c-icon`. There is no `_boolean_icon`.
   - The `URLField`/`FileField` link branches and the `avoid_link` parameter are dropped, and those values render as text.
   - The `password` branch is dropped.
   - Choices display their label, empty values honour the field's `empty_values`, and properties, methods and annotations resolve.
   - An unresolvable name raises `AttributeError` naming the model. By then the check (requirement 8) has already caught it.

### System checks, new `freedom_ls/panel_framework/checks.py`

8. Register the checks in `PanelFrameworkConfig.ready()` (`freedom_ls/panel_framework/apps.py`). The check function imports `settings.ROOT_URLCONF`, then walks `Panel.__subclasses__()` recursively and binds each concrete class at definition time, without a request. For every `model`-bound panel it runs `label_for_field` over each entry in `fields`. It also checks that every `children` value is a `Panel` subclass. Each `Error` sets `obj=` to the panel class, and messages follow `freedom_ls/base/app_settings.py:62-75` (sentence, then `hint`):
   - `freedom_ls_panel_framework.E001`: `"{Panel}.fields[{i}] refers to '{name}', which is not a field, property or method on '{app_label.Model}'."`, hint `"Use a field name or a '__' path through relations."`
   - `freedom_ls_panel_framework.E002`: `"{Panel} declares fields but no model."`, hint `"Set {Panel}.model."`
   - `freedom_ls_panel_framework.E003`: `"{Panel}.children['{key}'] is not a Panel subclass."`

### Actions, `freedom_ls/panel_framework/actions.py`

9. Actions render through templates, like panels. `PanelAction` gets a `template_name` and a `get_context_data(self, ctx: PanelContext) -> dict[str, object]`, and a container template includes each action with `only`. `handle_submit(self, ctx: PanelContext)` replaces `(request, instance, base_url)`. Responses that are already `HttpResponse` (422 forms, 204 plus `HX-Trigger`/`HX-Redirect`) keep their behaviour. `has_permission(request, instance)` is unchanged.
10. `DeleteAction` reads the instance from `ctx.instance`. A `DeleteAction` returned from `Panel.get_actions()` renders and submits with no error, and the old `isinstance(context, Model)` `TypeError` path is gone.

### Views, dispatch and responses, `freedom_ls/panel_framework/views.py`

11. `InstanceView` has one root panel, `panel: type[Panel]` (a `PanelStack` or `TabSet`), and keeps `get_actions()` for instance-level actions. The `panels` and `tabs` attributes and `_render_flat`/`_render_tabbed`/`render_tab` are replaced by rendering `panel_framework/views/instance_view.html`. It shows the `<h1 id="instance-title">` from `{{ instance }}` (autoescaped), the instance actions, and the root panel. The two `escape()` calls go.
12. Section configs, all keeping `check_access`, `authorise_instance`, `required_request_attrs` and `check_access_exempt_reason` exactly as they are:
    - `ListViewConfig`, unchanged in shape. Its list view renders through an instance-free `DataTablePanel`, so it refreshes the same way as any table panel. `_render_list_view_content`'s hard-coded `DEFAULT_TABLE_ID` short-circuit and `list_refresh.html`'s target come from `region_id`.
    - `ObjectViewConfig`, new. It links to the instance view of one object from `get_object(cls, request) -> Model`, which runs `check_access`, and has no list.
    - `BaseViewConfig`, new. `panel: type[Panel]` is rendered with `instance=None`, with no list and no instance.
    - Every config gets `menu_label`, `url_name`, `icon: str = ""` and `get_menu_count(cls, request) -> int | None`, which returns `None` by default.
13. `panel_framework_view(config, ...)` takes `config: list[NavGroup]`, where `NavGroup(heading: str, sections: list[type[SectionConfig]])` is a dataclass and `SectionConfig` is the union of the three configs. `url_name` must be unique across groups, and a duplicate raises `ImproperlyConfigured` when the view is called.
14. Path dispatch keeps `__panels/`, `__tabs/` and `__actions/` and the URL shape. `__panels/<name>` and `__tabs/<name>` resolve against the current container's `children` (`__tabs` only on a `TabSet`), recursively.
15. Response branches, in this order, for any path:
    - Plain GET, or any request carrying `HX-History-Restore-Request: true`: the full page, including tab paths, with the addressed tab active.
    - `HX-Target: main-content`: the navigation response (requirement 16).
    - `HX-Target` equal to a `TabSet`'s `region_id`: that tab's panel rendered alone, plus the announcer OOB with the message `"Showing {tab title}"`.
    - `HX-Target` equal to a panel's `region_id`: that panel's region template alone.
    - Any other htmx request: the navigation response. A bare fragment is never returned to an unrecognised target.
    - Every response, including action responses and 403/404/422, carries `Vary: HX-Request, HX-Target, HX-History-Restore-Request` via `django.utils.cache.patch_vary_headers`.
16. The out-of-band navigation response is one `render()` of `panel_framework/navigation_response.html`. It includes main content, breadcrumbs, sidebar, page title, document title, the announcer when `request.panel_announcement` is set, and each template in `request.panel_extra_oob`, every include with `only` and explicit context. The semgrep TODO at `views.py:723-726` is removed, because the finding no longer applies.

### Templates, `freedom_ls/panel_framework/templates/panel_framework/`

17. No `|safe` remains in `panel_framework` templates. The seven current sites (`panel_container.html:8,14`, `main_content.html:2`, `tab_container.html:26`, `tab_panels.html:3`, `instance_actions.html:4`, `list_refresh.html:10`) go with the string API. Every `{% include %}` passes explicit context with `only`.
18. Default templates come in leaf/base pairs. The leaf is the overridable name and contains only `{% extends %}` of its `_base` partner, which carries the markup and named blocks. Pairs under `panels/`: `panel`, `panel_stack`, `tab_set`, `instance_details`, `data_table`, and `data_table_region` (the region template). Under `views/`: `instance_view`, `list_view` and `base_view`. Both extension routes are proved in Testing.
19. `tab_set` markup: `<nav aria-label="{{ title }}">` with a `<ul>` of `<a>` links. Each link has `href` set to the tab's full URL, `hx-get` to the same URL, `hx-target="#{{ region_id }}"`, `hx-push-url="true"` and `hx-swap="innerHTML"`, and the active one has `aria-current="page"`. The region `div` follows the nav, and the nav is never inside the swapped region. There is no `role="tab"`/`tablist`/`tabpanel`. Styling follows `sidebar_nav.html`'s `aria-[current=page]` variant.
20. The `panel` base keeps `data-panel="{{ name }}"` on the root `<section>`, which the Playwright nesting assertion locates.
21. Deleted: `partials/panel_container.html`, `instance_details_panel.html`, `list_view.html`, `main_content.html`, `tab_container.html`, `tab_panels.html` and `instance_actions.html`. They are superseded by the pairs above, and `#main-content` keeps its id. Also deleted are the dead copies `freedom_ls/educator_interface/templates/educator_interface/partials/{panel_container,instance_details_panel,list_view}.html`.
22. New `partials/announcer_host.html`, defining `<div id="scope-announcer" class="sr-only" aria-live="polite" aria-atomic="true">`. A host includes it once, outside `#main-content`. `announcer.html` keeps targeting it.

### JavaScript, `freedom_ls/panel_framework/static/panel_framework/js/alpine-components.js`

## Testing

Framework tests in `freedom_ls/panel_framework/tests/` stay green, and they are rewritten where they exercise the removed API (`test_tabs.py`, `test_tab_panels.py`, `test_panel_actions.py`, `test_data_table_panel.py`, `test_menu_items.py`). `stub_panels.py` grows fixtures for each case below. Every test uses `mock_site_context` per `fls-dev:testing`.

- **API:**
  - A panel whose `has_permission` returns `False` is not rendered, and its `__panels/` URL is 404.
  - A `TabSet` whose children are all hidden is itself hidden.
  - A hidden tab is absent from the nav, and its URL is 404.
  - An instance-free `DataTablePanel` renders in a `BaseViewConfig`.
  - `PanelContext` is frozen.
  - A `DeleteAction` from `Panel.get_actions()` renders its trigger and deletes on submit.
- **Scoping:** a `DataTablePanel.get_queryset` override narrows rows, and each educator registration table excludes another organisation's rows.
- **Checks:**
  - `call_command("check")` passes on the real config.
  - Fixture panels raise E001 (unknown field), E002 (no model) and E003 (bad child), each with `obj` set to the panel class.
  - A property, a method and a `__` path produce no error.
- **Field display** (`test_field_display.py`):
  - Choices show their label, `None` shows `empty_value_display`, and booleans come back as `bool`.
  - Property, method and annotation values resolve.
  - An acronym `verbose_name` ("SAT score") survives.
  - A parity test runs vendored and Django functions over a fixed input set and lists the intended divergences: boolean value versus icon HTML, no URL/file links, no password branch.
- **Templates:**
  - No `panel_framework` template contains `|safe`.
  - A test-only override of a leaf that extends its `_base` renders the base markup plus the override.
  - A panel subclass whose `template_name` extends the framework template renders both.
- **Responses:**
  - `Vary` contains `HX-Request` and `HX-Target` on the plain, region-fragment and navigation branches of one URL, and on an action 422.
  - `HX-Request` plus `HX-History-Restore-Request` with no target, against a tab URL and against a plain instance URL, returns the full page.
  - A plain GET of `…/__tabs/<name>` returns the full page with that tab's link `aria-current="page"`.
  - An htmx request with an unknown `HX-Target` returns the navigation response, never a bare fragment.
  - A tab request's response includes the announcer OOB.
  - The navigation response contains every `panel_extra_oob` fragment.
- **Playwright** (`@pytest.mark.playwright`):
  - A new `tests/playwright/test_tab_navigation_htmx.py` clicks a second tab. It checks that the URL and the visible tab content change together, that `history.length` grows by exactly one, and that focus stays on the clicked link. Then Back restores both the URL and the first tab's content, and Forward restores the second.
  - `_expect_no_nested_panel` moves into a shared helper, used by `test_data_table_panel_htmx.py`, by `test_list_view_refresh_htmx.py` after the create-and-refresh, and by the tab test after a tab's first load.
- **Educator interface:**
  - The existing tests stay green: `test_config_authorisation.py`, `test_organisation_isolation.py`, `test_cohort_delete_action.py`, `test_create_cohort_action.py`, `test_learner_section.py`, `test_course_visibility_and_interest.py`, `test_organisation_switcher.py` and the two organisation-switcher Playwright tests. `test_config_authorisation.py` covers the new config kinds.
  - The dashboard renders.
  - The sidebar shows the "Teaching" heading and the user footer.
- **Shell:** the learner course player's full page renders with the two new blocks empty, and its sidebar still opens on desktop and mobile (smoke test).

## Open questions

- The footer's role label waits on spec 5's role vocabulary.
- Back/Forward with the history cache off swaps the whole body: nothing is announced and focus lands on `<body>`. This is accepted for now. Spec 12's accessibility pass decides whether to handle it.
- Re-clicking the current tab refetches and re-announces the same text, which some screen readers skip. Accepted until spec 12's accessibility pass.
