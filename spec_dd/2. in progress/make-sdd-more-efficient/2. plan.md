# Plan: run the test suite less often in the SDD workflow

The spec is `idea.md` in this directory. Its research files (`research_current_test_runs.md`,
`research_test_selection_tools.md`, `research_tiered_gating.md`) hold the inventory of the twelve
pytest sites, the tool comparison and the practice this follows. Read the spec before any slice,
including its "Named during planning" section, which defines the words the slices use.

The work is one small Python script with tests, one wrapper script, one new resource file, one
allowlist test, and edits to the plugin markdown that runs pytest today. There is no model, view,
template or migration change, and no user-facing page.

## Success criteria

Each row of the spec's "Where each tier runs" table holds once the plan is implemented:

1. The three tiers (`none`, `targeted`, `full`) are defined in exactly one file, the tier
   definition. Every command and agent that runs pytest names a tier and points at that file. No
   command copies pytest flags, and a test enforces it.
2. The `targeted` tier's selection is printed by a script, deterministically, with a reason per
   changed file. Its escalation list is an explicit glob list in that script, and a hit on it
   escalates to `full`.
3. The pre-step rebase runs no tests when main is unchanged, when the branch holds no code yet, or
   when main brought in only `none`-tier files. When the branch has code it runs `targeted` on
   main's diff plus the branch's own tests, and `full` only on escalation.
4. Each implementation batch runs `targeted` on its own diff. The final verification is a
   milestone: it runs `full`.
5. The QA bug fixer's RED and GREEN runs are a single test run with no coverage and exit zero on
   a pass. After the fix it runs `targeted` on its diff. One `full` run, a milestone, follows the
   last fix of a QA pass.
6. `/sdd:address_pr_review` runs `targeted` on the review fixes. CI on the PR is the backstop.
7. `/sdd:finish_worktree` runs one `full` before landing, the third milestone, whether or not main
   moved.
8. `/ds:commit` runs `targeted`; `/sdd:commit_quickly` still runs nothing.
9. Every run smaller than the whole suite passes `--no-cov`, so a partial run (one test, a
   targeted set, `pytest --co`) no longer fails the coverage threshold in `pyproject.toml`. The
   `full` tier keeps the threshold, coverage, Playwright and the project's current meaning of
   "all tests pass".
10. `targeted` and `full` run with `-n auto`, under the existing four-worker cap in the root
    `conftest.py`.

## Vocabulary

The spec's words, used in every identifier below:

- **tier**: `none`, `targeted`, `full`. A **targeted run** or **full run** is one execution of a
  tier. A **single test run** is the TDD RED or GREEN run of one test; it is not a tier.
- **tier definition**: `claude_plugins/django-stack/resources/test_tiers.md`.
- **selection**: the test paths a targeted run executes, and the reasons.
- **escalation list**: the globs that turn `targeted` into `full`.
- **importers**: the apps with a runtime or test-only dep on the changed app in the app dependency
  map.
- **app test directory**: `<app>/tests`, the selection unit.
- **touched app**: an app whose templates, static files, JavaScript or views the diff changed, or
  whose `tests/playwright/` holds a changed test file.
- **the branch's diff** and **main's diff**: the two inputs of a rebase's selection.
- The script is `select_tests.py`; its wrapper is `select_tests.sh`.

### `test_tiers.md`

Follow `writing-for-agents`. The file is read inline by whichever command or agent is about to run
pytest, so it is short and complete. Content, in this order (the `targeted` entry under "The
tiers" is written in slice 4, when its wrapper exists; everything else is written now):

1. **Purpose.** Name a tier and follow this file. A step that runs pytest names `none`, `targeted`
   or `full`; the flags live here and nowhere else.

2. **The tiers.**

   - **none.** No pytest. The step reports `tier: none` and moves on.
   - **targeted.** (slice 4)
   - **full.** The whole suite, parallel, with coverage, the threshold and Playwright:

     ```
     uv run pytest -n auto
     ```

     Everything else comes from `addopts` in `pyproject.toml`.

3. **How to run a tier.** Run `targeted` and `full` with the Bash tool's `run_in_background: true`
   and wait for the completion notification. Run one tier at a time per worktree. Run the bare
   command and let it finish; a full run can take more than ten minutes. The one hard guardrail:
   no `ps` or `pgrep` polling loops and no `timeout` wrapper.

4. **A single test run.** The TDD RED and GREEN runs of one test:

   ```
   uv run pytest <file>::<test> -x --no-cov
   ```

   `--no-cov` is what makes the exit code mean pass or fail: with coverage on, any run smaller
   than the whole suite fails the coverage threshold in `pyproject.toml` whatever the test did.
   The same flag applies to `pytest --co` and to any other partial run.

5. **Reporting.** A step reports the tier that ran as `tier: none|targeted|full`, quoting the
   final pytest summary line. A step is done when that line shows no failures.

6. **When a targeted run or full run fails (the caller fixes).** This section addresses the agent
   that owns the change, never a mechanic briefed only to run a tier. Fix the failure, re-run only
   the failures with `uv run pytest --lf --no-cov` (append `-n auto` for a targeted or full run),
   and once that is green re-run the whole tier as it first ran. The gate is the whole tier, not
   the `--lf` subset.

No site list: each command names its own tier and diff, so the definition stays true when a
command changes.

## Slice 2: `select_tests.py` decides the tier for a set of changed paths

**Behaviour.** Given changed paths, the script prints the tier, one reason line per path, and for
`targeted` or `full` the pytest command. It knows the `none` list, the escalation list, changed
test files and the owning app's test directory. Importers, tooling paths and Playwright come in
slice 3; git ranges come in slice 6.

**Files.**

- New: `claude_plugins/django-stack/scripts/select_tests.py`
- New: `tests/test_select_tests.py`

**Interface.**

```
python select_tests.py [--working-tree] [<path>...]
```

- `<path>` arguments are repo-relative changed paths.
- `--working-tree` adds `git diff --name-only HEAD` plus `git ls-files --others --exclude-standard`.
- Exit 0 after printing a decision. Argument errors go through `parser.error`, so they exit 2 like
  every argparse script; a git failure is reported the same way.

**Output.** Three line kinds, nothing else, so a caller can read it with `grep`:

```
tier: none|targeted|full
why: <changed path> -> <what it selected, or "none", or "full"> (<reason>)
command: <the pytest invocation>        # targeted and full only
```

The caller runs the `command:` line whatever the tier says, so no caller branches on `full`.

**Rules, applied per path in this order.** The first matching rule wins for that path. The tier
for the whole set is `full` if any path says full, else `targeted` if anything was selected, else
`none`.

```python
# Paths whose change cannot alter a test result. "*.md" is root-level only on purpose:
# markdown deeper in the tree can be content that tests read.
NONE_GLOBS = (
    "spec_dd/**",
    "docs/**",
    ".github/**",
    "*.md",
    ".claude/**/*.md",
    ".claude/**/*.json",
    ".claude/agent-memory/**",
    "claude_plugins/**/*.md",
    "claude_plugins/**/*.jsx",
    ".gitignore",
)

# Paths with fan-out the mirror and the app map cannot see. One hit means the whole
# suite. The two named apps are this project's foundations: every model and every
# content type builds on them.
ESCALATION_GLOBS = (
    "**/migrations/**",
    "config/**",
    "**/conftest.py",
    "**/factories.py",
    "**/fixtures/**",
    "**/urls.py",
    "**/middleware.py",
    "**/signals.py",
    "**/apps.py",
    "freedom_ls/site_aware_models/**",
    "freedom_ls/content_base/**",
    "pyproject.toml",
    "uv.lock",
)
```

1. `NONE_GLOBS` match → `why: <path> -> none (matches <glob>)`.
2. A collected test file (`is_collected(p.name) and "tests" in p.parts` with
   `p = PurePosixPath(path)`):
   - the file is absent from the checkout → `why: <path> -> none (deleted test file)`;
   - otherwise select the file itself → `why: <path> -> <path> (changed test file)`.
3. `ESCALATION_GLOBS` match → `why: <path> -> full (matches <glob>)`.
4. `owning_app(apps, project_root, path)` finds an app → select its app test directory →
   `why: <path> -> <app>/tests (owning app <short name>)`. The whole directory runs because its
   tests exercise the same models and views as the mirror of the changed file does. An app with no
   `tests/` directory selects nothing: `why: <path> -> none (owning app <short name> has no tests
   directory)`.
5. Anything else → `why: <path> -> full (unmapped path)`. Slice 3 inserts the tooling and
   importer rules before this one.

Glob matching uses `PurePosixPath(path).full_match(glob)` (Python 3.13), through one helper:

```python
def first_match(path: str, globs: tuple[str, ...]) -> str | None:
    """The first glob that matches `path`, so the reason can name it."""
```

Checked on Python 3.13.5 before this plan was written: `**` spans zero or more directories, so
`**/conftest.py` matches the root `conftest.py` as well as nested ones; a trailing `**` matches
files below the directory; `*.md` matches root-level files only; hidden directories such as
`.claude` match. The tests assert each of these anyway, so the claim is checked, not assumed.

**Command composition.** Every selected app test directory whose `playwright/` subdirectory
exists is ignored; slice 3 lifts the ignore for touched apps. The command is built as a list and
joined once, with `shlex.quote` on every path, because the printed line is run by a shell:

```python
def compose_command(selected: set[str], touched: set[str], project_root: Path) -> str:
    """The pytest line for a targeted run; `touched` keeps those apps' browser tests in."""
    ignores = [
        f"--ignore={shlex.quote(d + '/playwright')}"
        for d in sorted(selected)
        if d.endswith("/tests") and d not in touched and (project_root / d / "playwright").is_dir()
    ]
    return " ".join(["uv run pytest -n auto --no-cov", *ignores, *(shlex.quote(p) for p in sorted(selected))])
```

`full` prints `command: uv run pytest -n auto`. `none` prints no command line. A selected file
whose directory is also selected is dropped from the command.

**Apps.** `find_apps(project_root)` where `project_root = Path.cwd()`, the same as
`check_test_mirroring.py`. Paths are resolved relative to the project root.

**Pseudocode.**

```python
#!/usr/bin/env python3
"""Pick the pytest tier for a set of changed paths and print the paths to run.

Usage:
    python select_tests.py [--working-tree] [<path>...]

Prints `tier:`, one `why:` line per changed path and, for a targeted or full
run, the `command:` to run. Stdlib only, like its siblings.
"""

@dataclass(frozen=True)
class Decision:
    path: str
    kind: Literal["none", "select", "full"]
    selects: tuple[str, ...]
    reason: str

def first_match(path: str, globs: tuple[str, ...]) -> str | None: ...
def decide(path: str, apps: list[App], project_root: Path) -> Decision: ...
def changed_paths(paths: list[str], working_tree: bool) -> list[str]: ...
def compose_command(selected: set[str], touched: set[str], project_root: Path) -> str: ...
def main() -> int: ...
```

`git` calls use `subprocess.run([...], check=True, capture_output=True, text=True)` with a fixed
argv list, never a shell string. `main` catches `subprocess.CalledProcessError` only, and reports
it through `parser.error`.

**Tests to write first** (`tests/test_select_tests.py`, subprocess against a `tmp_path` tree
built with `write_tree`; `run_script` runs the real script; never `import select_tests`, because
the script finds its siblings through `sys.path[0]`). One behaviour per test, for example:

- a `spec_dd/` path alone gives `tier: none` and no `command:` line;
- a migration path gives `tier: full` and `command: uv run pytest -n auto`;
- a changed `pkg/alpha/services.py` selects `pkg/alpha/tests` with reason `owning app alpha`;
- the same when `pkg/alpha` has no `tests/` gives `tier: none` with the no-tests reason;
- a changed test file selects itself; a deleted test file is `none`;
- a selected test directory with a `playwright/` subdirectory gets `--ignore=pkg/alpha/tests/playwright`;
- the targeted command carries `-n auto` and `--no-cov`;
- a path with a space is printed shell-quoted;
- a mix of `none` and selected paths is `targeted`; a mix with one escalation hit is `full`;
- an unmapped path is `full`;
- one parametrized test over the glob facts above (`conftest.py`, `freedom_ls/conftest.py`,
  `spec_dd/x/y.md`, `.claude/settings.json`, `README.md` versus `docs/x.md`);
- two runs over the same tree print identical output;
- `--working-tree` picks up an untracked file (initialise a repo in `tmp_path` with
  `run_command(["git", "init"], project)` the way `tests/test_rebase_lost_change_check.py` builds
  its repo).

The tests need no database and no network, so no `django_db` marker and nothing that opens a
socket.

**Verification.** `uv run pytest tests/test_select_tests.py --no-cov` passes, and
`uv run pre-commit run --all-files` passes (`ruff`, `mypy`, `bandit`, `test-mirroring`). The
script's directory is outside mypy's scope, as its siblings' tests note; the test file is inside.
Nothing calls the script until slice 4.

## Slice 3: importers, tooling paths and the touched app's Playwright tests

**Behaviour.** The selection widens to the importers of the changed app, maps repository tooling
to its tests, and keeps a touched app's `tests/playwright/` in the run.

**Files.** The same two as slice 2.

**Importers.** Read once per run:

```python
edges = parse_existing_edges(project_root / "docs/app_structure.md")
# No app map means the importers are unknown, which is an escalation, not a guess.
if edges is None: every app-owned path decides full with reason "docs/app_structure.md missing"

def importers(app: App, edges: Edges) -> list[tuple[str, str]]:
    """(importer short name, reason) for every app with a dep on `app` in the map."""
    found = []
    for pairs, dep in ((edges.runtime, "runtime dep"), (edges.test, "test-only dep")):
        found += [(src, f"{src} has a {dep} on {app.short_name}") for src, dst in pairs if dst == app.short_name]
    return sorted(found)
```

Rule 4 of slice 2 gains: for each importer, select its app test directory with one `why:` line per
importer; an importer without a `tests/` directory, or one named in the map but absent from
`find_apps`, gets a `why:` line saying so and selects nothing. Direct importers only; the spec
names the apps that import the changed app, not the transitive closure. The declared runtime edge
in `test_organisation/declared_edges.toml` is already in the map, so it needs no special case.

**Tooling and content plugin paths.** Inserted between rule 4 and the final `full` rule:

```python
# Repository tooling has its tests in the top-level tests/ directory; the course

    ("claude_plugins/fls-content/**", ("claude_plugins/fls-content", "freedom_ls/content_engine/tests")),
```

`claude_plugins/fls-content/` is already `none` by rule 1; a helper under `tests/` that is not
itself a collected test file now selects `tests` instead of escalating.

**Touched apps.**


`tests/playwright/` directory marks its owning app the same way. `compose_command` already takes
the touched set: a touched app's test directory gets no `--ignore`, so only its browser tests
run. The `why:` line for the path adds `; playwright: <app>/tests/playwright`.

**Tests to write first**, added to `tests/test_select_tests.py`. The throwaway tree gains a

```
    alpha
    beta
    gamma
    beta --> alpha
    gamma -.-> alpha
```

- a change in `alpha` selects `pkg/beta/tests` with reason `beta has a runtime dep on alpha` and

- a change in `beta` selects only `pkg/beta/tests`;
- an importer with no `tests/` directory selects nothing and says so;
- a missing app map makes an app-owned change `full`;
- one parametrized test over the UI cases (a template, `static/x.js`, `views.py`, `views/x.py`):

- a `services.py` change ignores both apps' `playwright/` directories;
- a changed `pkg/alpha/tests/playwright/test_x.py` selects itself and lifts the ignore for alpha;

### The wrapper

`templates/wrapper_scripts/select_tests.sh` copies the shape of
`rebase_lost_change_check.sh` in the same directory, with the base setup line:

```
exec uv run python "$PLUGIN_DIR/scripts/select_tests.py" "$@"
```

`uv run python` rather than `python3`, because the script needs the project's Python 3.13 for
`full_match`. The generated `.claude/ds/scripts/select_tests.sh` is the same file with
`PLUGINS_ROOT="."`, like the other generated wrappers beside it. `chmod +x` both before the
commit. `ds:init` installs any missing template on its own, so it needs no edit.

`.claude/settings.json` gains the three allow forms the other wrappers have:

```
"Bash(.claude/ds/scripts/select_tests.sh:*)",
"Bash(bash .claude/ds/scripts/select_tests.sh:*)",
"Bash(./.claude/ds/scripts/select_tests.sh:*)",
```

The script validates its arguments, writes nothing, and never runs an argument as shell code,
which is what the trust boundary in `claude_plugins/sdd/commands/README.md` asks of a script
deployed there. Slice 6 adds the git-range validation when ranges arrive.

`tests/test_select_tests_wrapper.py` follows `tests/test_rebuild_after_rebase.py`: with a stubbed
`uv` on `PATH`, running the generated wrapper with two arguments logs one `uv run python
<plugin dir>/scripts/select_tests.py <arg> <arg>` invocation, and the template differs from the
generated wrapper only on the `PLUGINS_ROOT=` line.

### `select_tests.py`: ranges

Two options, each taken once (plain `type=str`, not repeatable; no caller passes either twice):

- `--range <rev>..<rev>` adds `git diff --name-only --end-of-options <range>`.
- `--tests-changed-in <rev>..<rev>` adds only the collected test files changed in that range,
  present in the checkout. They join the selection but never raise the tier: when the other
  inputs give `none`, the tier is `none` and their `why:` lines read
  `(branch test file; runs only with a targeted tier)`.

A range value must match `^[A-Za-z0-9_./~^@{}-]+\.\.[A-Za-z0-9_./~^@{}-]+$`; anything else is a
`parser.error`. `--end-of-options` keeps a value from ever reading as a git option.

Tests to write first:

- `--range` over a repo where one commit changed `pkg/alpha/services.py` selects `pkg/alpha/tests`;
- `--tests-changed-in` with a docs-only `--range` gives `tier: none`;
- `--tests-changed-in` with a `--range` that selects something adds the test file to the command;
- a range of `--output=x` exits 2; a range with a shell metacharacter exits 2.
