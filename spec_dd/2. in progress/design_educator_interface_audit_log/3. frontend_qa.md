# Frontend QA: educator audit log avatars, export and expandable rows

The three audit screens (a learner's History tab, a cohort's History tab, the organisation Audit
log) now show one compact line per entry with an initials avatar beside each person, keep the
description, reason and a bulk run's entries in an expandable row detail, and offer a CSV export
that is itself recorded in the log. This run checks the compact rows and avatars on all three
screens, the row detail by mouse and keyboard, the mobile cards, the export on every screen and
width, the recorded export entry, and the ways it could go wrong: a system entry and a deleted
actor, a target whose row is gone, markup in a label, a formula-looking reason, a cohort admin and
a cohort viewer who must get nothing, another organisation's admin who must see only their own,
and an export that must not contain its own entry.

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever
this document writes `<PORT>`. Shell variables do not survive between tool calls. Never use port
8000.

Everything under `/educator/` below is relative to `http://127.0.0.1:<PORT>`.

### 0.3 Log in

Log in at `/accounts/login/` as `org.admin@qa.test` unless a test says otherwise. Logging in as
another persona means logging out first (`/accounts/logout/`).

### 0.4 Reading a CSV export

An export URL is the screen's URL with the table's export parameter: `?history-export=csv` on a
History tab's URL and `?audit_log-export=csv` on the Audit log. Fetch it with the Playwright
network request tool from the logged-in page so the session cookie is sent, and read the response
body. Expect `Content-Type: text/csv; charset=utf-8`, a `Content-Disposition` attachment
filename as each test states, a body starting with the UTF-8 BOM, then the header line
`When,Who,Actor email,What,Action,Target,Description,Reason,Run ID`. Opening the URL in the tab
instead triggers a download; either is fine as long as the body can be read.

## §1 Learner History: compact rows and the row detail (desktop)

Design state: `design_screenshots/educator-audit-history-v2__09-learner-history.png`.

1. At 1920x1080, open `/educator/organisations/northside/learners`, click **Ada Lovelace**, click
   the **History** tab.
2. Expect a table with the column headers **When**, **Who**, **What** and a fourth, visually
   hidden header "More" (present in the DOM, not drawn). No "Details" column.
3. Expect rows, newest first, for the bulk-run deactivation ("Learner deactivated", Orla Admin)
   and the system reactivation ("Learner reactivated"). Each row is one line: When shows a date
   and a `HH:MM` time together; Who is an initials circle **OA** beside "Orla Admin"; What shows
   the action label and, in muted text on the same line, the description.
4. Hover a row: it gets the surface tint, the same as other educator tables.
5. The bulk-run row ends with a chevron button. Click it. Expect the row below it to appear as a
   tinted full-width panel holding the label **Reason** with "Programme closed". The chevron
   rotates. Click again: the panel hides and the chevron rotates back.
6. Open the row detail again, then click the **Courses** tab and back to **History**: every row
   is closed again.
7. The system reactivation row has no reason and no description: expect no chevron button in its
   last cell, and an empty cell there.
8. Take a screenshot.

Design checklist (from the plan's transcription):

- [ ] Export CSV is at the right end of the toolbar row, on every width.
- [ ] Every row is one line at `md` and up; the description is clipped, not wrapped.
- [ ] When reads as date then time on one line.
- [ ] The row's toggle is the last cell; its header is visually hidden "More".
- [ ] Opening a row reveals a tinted full-width panel under it with uppercase muted labels
      ("Description", "Reason") and the values beside them.
- [ ] The open row's chevron is rotated; rows open and close independently.
- [ ] An entry with no description, reason or run entries has no toggle.
