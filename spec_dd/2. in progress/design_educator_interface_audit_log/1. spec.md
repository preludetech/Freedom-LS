# Spec: Educator audit log — avatars, export, compact expandable rows

Source: `idea.md`. Design reference: `design.md` (read it as that file says; it is never scope).

## Purpose

The audit log built by `spec_dd/3. done/2026-10-29_08:48_educator-interface-11-audit-log/` shows
four or five wrapped text columns per entry, names people as bare text, and cannot leave the
system. Admins need to scan it quickly, tell people apart at a glance, and hand it to an auditor.
This spec makes every row one compact line with an initials avatar beside each person, moves the
detail into an expandable panel, and adds a CSV export to the learner History tab, the cohort
History tab and the organisation Audit log.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| `audit_log.exported` | coined | The audit action written when someone downloads an audit log CSV. Noun `audit_log` (the `AuditLogEntry` rows) and verb `exported` are both new to the glossary's Changes section. |
| row detail | coined | A `DataTable` row's expandable panel: hidden content under the row, opened by a toggle in the row. No existing term; the framework has cards and quick views, neither of which expands in place. |

## Scope

In:

- An initials avatar beside the actor (Who) and beside a target that is a person, on all three
  screens, on the mobile cards, and in a bulk run's list of entries.
- Compact one-line rows on all three screens, with the description truncated, and the full
  description, the reason and a bulk run's entries in a row detail.
- A generic row detail capability in `panel_framework`, used by the audit tables.
- CSV export on all three screens, of every entry matching the current filters.
- Each export writes an `audit_log.exported` entry.

Out:

- Everything the design draws beyond the idea: search, category chips, the Area and Source
  columns, a sortable When column, expand all, learner search, event IDs, the structured
  "Changes (old → new)" block, the affected-members list, the date-range picker.
- Profile pictures. `accounts.User` has no image field; an avatar is an initials circle.
- JSON export, asynchronous or emailed exports, a row cap.
- A separate export capability.
- Keeping rows expanded across pagination, filtering or a refresh swap.

## Decisions

1. **The avatar's initials come from the stored label; its colour comes from the live user's pk.**
   The name beside it stays the snapshot (`actor_label`, `target_label`), as the log records it.
   Keying colour on the user pk gives a person the same colour here as in the learner and member
   tables.
2. **No person, no initials circle.** System (`actor` null, `actor_label` empty) shows the
   `settings` icon in a neutral circle and the text "System". A deleted user (`actor` null,
   `actor_label` set, or a target person whose row is gone) shows the `user` icon in a neutral
   circle beside the stored label, the pattern in
   `freedom_ls/comms/templates/comms/partials/participant_avatar.html`.
3. **Export rides `freedom_ls_audit_log.view_auditlogentry`.** Whoever can see a log can download
   it, as with every other panel export.
4. **The organisation log's export includes a bulk run's per-object entries,** one CSV row each,
   tied to its summary row by the Run ID column. The screen hides them behind the summary row and
   caps that list at `RUN_ROWS_KEPT`; the export has no such cap.
5. **An export's `audit_log.exported` entry has no subjects,** so it appears only on the
   organisation Audit log, never on the History tab of the learner or cohort that was exported.
   The export never contains its own entry.
6. **The CSV carries the description text, not `details` JSON.** Auditors read it in a
   spreadsheet; `details` keys are internal.
7. **Row detail lives in `panel_framework` and stays generic.** `extract_panels_framework` will
   move the table machinery into a package, so no audit or educator name enters it.

## Requirements

### `panel_framework`: row detail

- `DataTable` gains an optional row detail: a template class attribute (default `None`, no
  detail) and a per-row predicate that says whether a row has a detail (default: every row when
  the template is set). Names are the plan's.
- `freedom_ls/panel_framework/templates/cotton/data-table.html`, `md` and up: a table with a row
  detail template gets a trailing toggle column with a visually hidden header ("Details"). A row
  with a detail renders a real `<button>` there with `aria-expanded` and `aria-controls`, an
  accessible name naming the row, and the `dropdown` icon (`aria-hidden`) rotating on open,
  gated by `motion-safe:`. The detail renders in a following `<tr hidden>` with one
  `<td colspan>` spanning every column, the bulk-selection column included. A row without a
  detail has an empty toggle cell. Rows open independently; opening one never closes another.
- Below `md` (`cotton/data-table-card.html` and any `card_template`): a card whose row has a
  detail ends with a native `<details>`/`<summary>` disclosure holding the same detail template.
- The toggle is a small Alpine component in
  `freedom_ls/panel_framework/static/panel_framework/js/alpine-components.js` (reuse the existing
  `aria-expanded` toggle there if it fits). Focus stays on the button after toggling. An HTMX swap
  of the table region renders every row closed.
- Tables without a row detail render exactly as today.

### `panel_framework`: export hooks

`_export_response` in `freedom_ls/panel_framework/views.py` gains two generic hooks, with
defaults that leave every existing export unchanged:

- **Export queryset.** The rows an export narrows from (same `parse_query` and `filter_queryset`
  as the screen), defaulting to the panel's `get_queryset`. Both the `HistoryPanel` subclasses and
  the panel `ListViewConfig` builds for `AuditLogConfig` must be able to override it.
- **Before export.** Called with the request and the narrowed rows after narrowing and before the
  `StreamingHttpResponse` is built (the site thread-local is still set), returning the rows to
  stream. Default: returns them unchanged.

### `educator_interface`: compact rows and avatars

In `freedom_ls/educator_interface/views.py` and
`freedom_ls/educator_interface/templates/educator_interface/data-table-cells/`:

- `AuditLogEntryTable` columns become When, Who, What; `TargetedAuditLogEntryTable` adds Target
  after What. The Details column goes; its content moves to the row detail.
- **When** (`audit_when.html`): one line, date and `HH:MM`, inside
  `<time datetime="<ISO 8601 with offset>">`.
- **Who** (`audit_who.html`): `c-panel-avatar-chip` with the `actor_label` as name and `actor_id`
  as `user_id`, or the System or deleted-user circle of Decision 2. `actor_id` is on the row, so
  this costs no query.
- **What** (`audit_what.html`): the action `label`, then the `description` in muted text, on one
  line, truncated (`truncate`, full text in the row detail).
- **Target**: the `target_label`, with an avatar when the target is a person. Person targets are
  `accounts.User`, `Learner` and `OrganisationMember` rows. `AuditLogEntryTable.get_rows` resolves
  their user pks for the page's entries, and for the bulk run entries attached on the
  organisation log, in at most one query per model type, never one per row. The user pk is
  `target_object_id` for a `User` target and the row's `user_id` for the other two. A target
  whose row no longer exists gets the deleted-user circle. Any other target (cohort, conversation,
  organisation) shows its label with no avatar.
- **Row detail** (a new `audit_detail.html`): the full description; the reason under a "Reason"
  label; and, for a bulk run summary, the run's entries (today's "Show N entries" list in
  `audit_details.html`, each line with the actor and target avatars) and the "and N more" line.
  A row has a detail only when it has a description, a reason or run entries.
- `AuditLogEntryTable.get_queryset` gains `select_related("actor")` only if a cell or export column
  reads the `actor` object; avatars use `actor_id` alone.
- **Mobile card** (`educator_interface/partials/audit_log_card.html`): first line the Who avatar
  chip and the When; second line the label, a visible separator, and the Target (with its
  avatar); then the row detail disclosure. No labelled field renders empty, which removes today's
  empty "Details" label.
- Every value stays escaped user text; nothing is marked safe.

### `educator_interface`: export

- `AuditLogEntryTable.get_export_columns()` returns, in this order:

  | Header | Value |
  | --- | --- |
  | When | `timezone.localtime(created_at).isoformat()` (ISO 8601 with offset) |
  | Who | `actor_label`, or `System` when empty |
  | Who email | `actor.email` while the actor exists, else empty |
  | Action | the action `label` |
  | Action code | `action` |
  | Target | `target_label` |
  | Details | `description` |
  | Reason | `reason` |
  | Run ID | `run_id`, or empty |

  The export queryset uses `select_related("actor")` for Who email. Values go through
  `ExportColumn`, so `escape_csv_formula` applies.
- The table toolbar's existing Export CSV link then appears on all three screens; where a History
  tab renders no toolbar today, it gets one carrying only the link.
- Filenames name the scope through `get_export_scope_slug`: the organisation slug for the
  organisation log, the cohort as the cohort learner export already does, and the learner's name
  for the learner History tab.
- The organisation log's export queryset is `AuditLogEntryTable.get_queryset(request)`, without
  `OrganisationAuditLogTable`'s exclusion of per-object entries. The History tabs export what they
  show.
- The before-export hook on all three screens writes the export's entry with `record_entry`:
  `action="audit_log.exported"`, `actor=request.user`, `target` the organisation, learner or
  cohort exported, `target_label` that object's name, `organisation=request.organisation`, no
  `subjects`, and `details={"scope": "organisation" | "learner" | "cohort", "count": <rows>,
  "filters": "<applied filter labels, empty when none>"}`. It returns the rows excluding that
  entry's pk.

### `audit_log`

- `freedom_ls/audit_log/actions.py`: add `AuditAction("audit_log.exported", "Audit log exported",
  _describe_export)` to `FLS_AUDIT_ACTIONS`. `_describe_export` returns `"<count> entries"`, then
  `", filtered by <filters>"` when filters were applied.
- `freedom_ls/audit_log/tests/invariants/test_vocabulary.py`: add `audit_log` to `NOUNS` and
  `exported` to `VERBS`, after the glossary entry below.
- The `audit_log` app's dependencies do not change.

## Testing

- **Row detail (panel_framework):** a table with a detail template renders the toggle column,
  a button with `aria-expanded="false"` and `aria-controls` matching a hidden detail row whose
  `colspan` covers every column (with and without bulk actions); a row the predicate rejects has
  no button; the card renders a `<details>`; a table without a detail template renders as before.
- **Export hooks (panel_framework):** the default export is unchanged; an overridden export
  queryset is narrowed by the screen's filters; the before-export hook runs once, before
  streaming, and its returned rows are what streams.
- **Avatars:** Who renders a chip keyed on `actor_id`; System renders the `settings` circle;
  a deleted actor renders the `user` circle and the stored label; a `Learner`, `OrganisationMember`
  and `User` target each render a chip keyed on the user pk; a target whose row was deleted
  renders the deleted-user circle; a cohort target renders no avatar; a nameless user's initials
  come from the email label; markup in a label renders as text.
- **Query budget:** `test_the_history_tab_renders_within_a_query_budget` still passes with the
  budget raised by at most the per-model-type target lookups; the organisation log gets the same
  test with bulk run summaries on the page.
- **Rows:** each screen renders When, Who, What (and Target) and no Details column; the
  description and reason appear in the row detail; a row with no description, reason or run
  entries has no toggle; the mobile card has no empty labelled field and separates label and
  Target.
- **Export:** each screen's `?<table_key>-export=csv` returns the nine columns in order; the
  History tabs export only their subject's entries across all pages; the organisation log export
  honours each of the Who, What and When filters and includes a bulk run's per-object entries
  with its Run ID; another organisation's or site's entries never appear; a cohort admin or cohort
  viewer gets a 404; a reason starting with `=` is formula-escaped; a non-ASCII name survives with
  the BOM.
- **Export entry:** each export writes one `audit_log.exported` entry with the right target,
  scope, count and filters, no subjects; it shows on the organisation log and on no History tab;
  it is not in the CSV that wrote it.
- **Playwright:** `test_a_deactivation_reason_shows_on_the_learner_history_and_the_audit_log`
  (`freedom_ls/educator_interface/tests/playwright/test_learner_page_flow.py`) expands the row
  before asserting the reason, by keyboard (Enter on the toggle) on one screen; the table still
  fits its wrapper. A mobile-width check opens a card's disclosure.
- Update the row-reading helpers (`_history_rows`, `_audit_log_rows` in
  `freedom_ls/educator_interface/tests/test_views.py`) for the new columns rather than weakening
  their assertions.

## Success criteria

- On all three screens at `md` and up, every entry is one line: When, Who with avatar, What with
  truncated description, and (cohort and organisation) Target with avatar for a person.
- A row with more to show opens and closes by mouse and by keyboard, independently of other rows,
  and shows the full description, reason and any bulk run entries.
- System and deleted users never show an initials circle.
- Export CSV on each screen downloads every filtered entry, in the nine columns, with the scope in
  the filename; the organisation export includes bulk run entries.
- Every export adds one `audit_log.exported` entry visible only on the organisation Audit log.
- Rendering any of the three screens costs no per-row query.
- Tables elsewhere in the educator interface render unchanged.
