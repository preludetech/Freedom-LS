# QA: SDD review and boy-scout for test organisation

This feature changes the `sdd` plugin, not the web app, so nothing here runs in a browser and no
dev server is needed. QA runs `/sdd:implement_plan` in a Claude Code session on a throwaway spec
with three planted problems, then checks git history, `.sdd-work/` and `boy_scout_record.md`.

It is interactive: the run asks `AskUserQuestion` questions, and the tester answers them as
described below. All work happens on a local throwaway branch that is never pushed and is deleted
at the end.

## Setup

Run this from the feature worktree, with the feature implemented and committed:

```bash
FEATURE=$(git branch --show-current)
git switch -c qa-boy-scout-throwaway
```

The branch has no upstream, so nothing gets pushed. Make sure `.claude/sdd/config.local.md` does
not exist, or has no `## Testing Skills` section.

Create `spec_dd/2. in progress/qa-boy-scout-throwaway/` with three files:

- `1. spec.md`: a two-line spec: "QA spec for the boy-scout. Adds `page_count` to `health` and a
  `percent` filter to `form_engine`." Add a success criterion: "`uv run pytest` passes."
- `todo.md`: copy the todo from this spec's directory, untick every box, and tick everything up to
  and including "Review both plans".
- `2. plan.md`: two slices, with the planted problems written into the steps so the implementer
  follows them exactly:

  **Slice 1: `page_count` in `health`.**
  - Create `freedom_ls/health/pagination.py` with
    `def page_count(total: int, per_page: int) -> int: return total // per_page`.
    (Planted bug: it drops a partial last page. Keep it exactly as written.)
  - Write the tests in `freedom_ls/health/tests/test_misc.py` (planted misplaced test; mirroring
    wants `test_pagination.py`). Test `page_count(10, 5) == 2` only.
  - In the same test file, add a second test that builds a topic with
    `from freedom_ls.content_engine.factories import TopicFactory` and checks
    `page_count(len(TopicFactory.build(title="abcdef").title), 3) == 2`. (Planted cross-app import:
    `health`'s only Runtime dep is `base`.)

  **Slice 2: `percent` filter in `form_engine`.**
  - Add a `percent` filter to `freedom_ls/form_engine/templatetags/form_engine_tags.py` that
    formats a float between 0 and 1 as a whole-number percentage (`0.5` → `"50%"`).
  - Add its test to the existing `freedom_ls/form_engine/tests/test_form_engine_tags.py`. That
    file is already misplaced on `main` (mirroring wants `tests/templatetags/`), so the boy-scout
    has something to tidy.

Commit the three files with `uv run git commit -m "qa: throwaway spec"` and note the SHA as
`QA_BASE`.

## Workflow 1: a full run, interrupted and resumed

1. Start a fresh Claude Code session in this worktree and run
   `/sdd:implement_plan @"spec_dd/2. in progress/qa-boy-scout-throwaway/2. plan.md"`.
2. Watch the batch 1 implementer spawn. It should be `sdd:sdd-implementer`, and its first actions
   should be `Skill` calls for `ds:testing` then `fls-dev:testing`.
3. **Interrupt:** as soon as `git log --oneline -1` shows `[batch 1] …`, press Esc to stop the
   run. If the review worker has already started, that's fine.
4. Re-run the same `/sdd:implement_plan` command. Expected:
   - batch 1 is **not** re-implemented (there is still exactly one `[batch 1]` commit);
   - the run goes straight to batch 1's follow-ons, starting with the test-organisation review;
   - if `.sdd-work/test_org_review_batch_1.md` already ended `status: ok`, no new reviewer spawns.
5. **Review fixes.** Expected: the review finds `freedom_ls/health/tests/test_misc.py` (mirroring)
   and the `content_engine` import (dependency direction). Mechanical findings get fixed in one or
   more `[batch 1 review-fix] …` commits. If a finding comes back as a judgement question, answer
   with the recommended option.
6. **Flagged item.** Expected: an `AskUserQuestion` about `freedom_ls/health/pagination.py`'s
   `page_count` dropping the last partial page, with the boy-scout's recommendation first and the
   three answers "Not a bug", "Fix it now" and "Record a follow-up". Before answering, check that
   the boy-scout did **not** change `pagination.py`:
   `git log --format=%s QA_BASE..HEAD -- freedom_ls/health/pagination.py` shows only `[batch 1] …`.
   Answer **Record a follow-up**.
7. Let the run finish batch 1. Expected:
   - the last batch 1 commit is `[batch 1 record] …`;
   - a follow-up for `page_count` exists either under `## Follow-ups from other specs` in a `next`
     spec's `idea.md` whose Scope covers `health` (`test-organisation-and-hygene-6-small-apps` is
     the likely one), or as a new `spec_dd/1. next/<slug>/idea.md` with `## What`, `## Why` and
     `## Resources`;
   - `git diff QA_BASE HEAD -- "spec_dd/1. next/roadmap.md"` is empty;
   - `.sdd-work/test_org_review_batch_1.md` and `.sdd-work/boy_scout_batch_1.md` are gone.
8. **Batch 2 boy-scout.** Expected: `[batch 2 boy-scout] move freedom_ls/form_engine/tests/test_form_engine_tags.py -> freedom_ls/form_engine/tests/templatetags/test_form_engine_tags.py`,
   followed straight away by a `[batch 2 boy-scout] edit …` commit (for example adding
   `tests/templatetags/__init__.py`). The move commit changes only that one file's path:
   `git show --stat <move-sha>` shows a 100% rename.
9. If batch 2 has any flagged item, answer **Not a bug** for one of them. Expected: a
   `[batch 2 flag-note] <path>` commit whose diff is a single comment saying why the code is
   correct, with no "reviewed by" or "flagged by" wording.
10. Let the run finish. Expected:
    - `[batch 2 record] …` comes before the final commit;
    - `boy_scout_record.md` in the QA spec directory has `## Batch 1`, `## Batch 2` and a final
      `## Summary`, and the summary counts match what happened (review fixes, 1 file moved, the
      deferral, the flagged items by answer);
    - the conversation ends with the same counts;
    - `uv run pytest` passes.

## Workflow 2: budget and scope

On the QA branch after Workflow 1:

1. Count the budget the way `implement_plan` does:
   `git log --format=%s $(git merge-base origin/main HEAD)..HEAD | grep -cE '^\[batch [0-9]+ boy-scout\] (move |edit split )'`
   should print `1`.
2. Find the parent of batch 2's first boy-scout commit, then run
   `claude_plugins/sdd/scripts/batch_scope_check.sh 2 <that-parent>`. Expected: exit 0 and no
   output.
3. Run it with a nonsense ref: `claude_plugins/sdd/scripts/batch_scope_check.sh 2 nope`. Expected:
   exit 64 and a usage line.

## Workflow 3: blank `## Testing Skills` turns the feature off

1. `git reset --hard QA_BASE` on the QA branch. This is the throwaway branch only; check with
   `git branch --show-current` first.
2. Create `.claude/sdd/config.local.md` containing only:

   ```markdown
   ## Testing Skills
   ```

3. Run `/sdd:implement_plan` on the QA plan again. Expected:
   - batches still spawn as `sdd:sdd-implementer`, but make no `Skill` calls;
   - no `.sdd-work/test_org_review_batch_*.md` or `.sdd-work/boy_scout_batch_*.md` is written;
   - no review-fix, boy-scout, flag-note or record commit: `git log --format=%s QA_BASE..HEAD`
     shows only `[batch 1] …`, `[batch 2] …` and the final commit;
   - no `boy_scout_record.md` is created, and there is no final review.
4. Interrupt after `[batch 1]` and re-run. Expected: batch 1 is skipped, since with the review off
   a batch is finished at `[batch N]`.
5. Delete `.claude/sdd/config.local.md`.

## Workflow 4: `/sdd:init` and the unchanged surfaces

1. Switch back to the feature branch: `git switch "$FEATURE"`.
2. Run `/sdd:init`. Expected: `git diff .claude/sdd/config.md` is empty. The existing
   `## Testing Skills` values (`ds:testing`, `fls-dev:testing`) survive the re-run, and the summary
   tells the user to name their Testing Skills.
3. Read the `init.md` Step 2 template. Expected: `## Testing Skills` sits after
   `## Vocabulary Sources` with an empty bullet list.
4. `git diff main -- claude_plugins/sdd/commands/make_pr_quickly.md` is empty, so the PR body
   template is unchanged.

## Cleanup

```bash
git switch "$FEATURE"
git branch -D qa-boy-scout-throwaway
rm -f .claude/sdd/config.local.md
```

Delete any `.sdd-work/test_org_review_*.md` or `.sdd-work/boy_scout_batch_*.md` left behind, by
name. Never delete the `.sdd-work/` directory itself. The follow-up `idea.md` files and
`boy_scout_record.md` lived only on the throwaway branch, so deleting the branch removes them.
