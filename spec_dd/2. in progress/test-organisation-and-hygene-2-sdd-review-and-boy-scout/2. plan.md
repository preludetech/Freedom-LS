## Slice 2: Each batch is reviewed for test organisation, fixed, and recorded

**Behaviour.** After `[batch N]` lands and the suite passes, an `sdd:sdd-worker` reviews the
batch's touched files against mirroring and dependency direction. Mechanical findings are fixed in
`[batch N review-fix]` commits. Judgement findings go to the user. A `## Batch N` section goes into
`boy_scout_record.md` and a `[batch N record]` commit closes the batch. Resume keys on commit
subjects. All of this is skipped when `## Testing Skills` is blank.

### 2b. Touched files

Add a "Touched files" subsection that both the review and (in slice 3) the boy-scout use:

```bash
N=<batch-number>
BASE=$(git merge-base origin/main HEAD)
git log --reverse --format='%H%x09%s' "$BASE..HEAD" \
  | while IFS=$'\t' read -r sha subject; do
```

### 3b. `claude_plugins/sdd/scripts/batch_scope_check.sh` (executable)

```bash
#!/usr/bin/env bash
# Checks that one batch's boy-scout commits touch only that batch's touched files.
#
# Usage: batch_scope_check.sh <batch-number> <from-ref> [<to-ref>]
#
# Exit 0: in scope. Exit 1: a boy-scout commit touched a path outside the batch's touched files;
# prints OUT_OF_SCOPE: then one path per line. Exit 64: bad arguments.
set -euo pipefail
usage() { echo "Usage: $0 <batch-number> <from-ref> [<to-ref>]" >&2; }

[[ $# -eq 2 || $# -eq 3 ]] || { usage; exit 64; }
BATCH=$1; FROM=$2; TO=${3:-HEAD}
[[ $BATCH =~ ^[0-9]+$ ]] || { usage; exit 64; }
for ref in "$FROM" "$TO" origin/main; do
    git rev-parse --verify --quiet "${ref}^{commit}" >/dev/null || { usage; exit 64; }
done
BASE=$(git merge-base origin/main "$FROM")

declare -A allowed=()
violations=()
# 1. allowed set: A/M paths, and the new side of R, from commits in BASE..FROM whose
#    subject starts "[batch $BATCH] " or "[batch $BATCH review-fix] "
# 2. test dirs: for each allowed path with a whole "tests" path segment, the prefix up to
#    and including the first such segment (freedom_ls/app_a/tests/). Match the segment with
#    (^|/)tests/, so a directory like contests/ never counts. under_test_dir <path> succeeds
#    when the path starts with one of them.
# 3. walk commits in FROM..TO oldest first, checking only subjects that start
#    "[batch $BATCH boy-scout] " (see the loop below)
# 4. violations → print "OUT_OF_SCOPE:" then each path; exit 1. Otherwise exit 0.

while IFS=$'\t' read -r sha subject; do
    [[ $subject == "[batch $BATCH boy-scout] "* ]] || continue
    while IFS= read -r -d '' status; do
        case "$status" in
            R*)  # R100, R87, ...: two paths follow
                IFS= read -r -d '' old
                IFS= read -r -d '' new
                [[ -n ${allowed[$old]+x} ]] || violations+=("$old")
                allowed["$new"]=1
                ;;
            M)   IFS= read -r -d '' path; [[ -n ${allowed[$path]+x} ]] || violations+=("$path") ;;
            A)   IFS= read -r -d '' path; under_test_dir "$path" || violations+=("$path") ;;
            *)   IFS= read -r -d '' path; violations+=("$path") ;;  # D, or anything else
        esac
    done < <(git diff-tree -z --no-commit-id -r -M --name-status "$sha")
done < <(git log --reverse --format='%H%x09%s' "$FROM..$TO")
```

Match subjects as bash string prefixes, as above, never with `git log --grep` (which searches the
whole message) or `grep` (which exits 1 on no match under `set -e`). The allowed-set loop in step 1
uses the same `while IFS=$'\t' read -r sha subject` shape. Run `shellcheck` through pre-commit when
committing.

`origin/main` is read inside the script rather than passed in, because the spec fixes the
signature. A missing `origin/main` exits 64 like any bad ref.

```yaml
description: |-
  Tidies test organisation in one batch's touched files, within a budget, and reports what it
  tidied and what it deferred. Spawn one per batch from implement_plan at depth 0.
  Non-interactive; never spawns subagents.
tools: Bash, Read, Edit, Write, Glob, Grep, Skill
model: sonnet
---
```

Body, in `qa-bugfixer.md`'s shape (non-interactive, explicit-path staging, `uv run git commit`,
never `--no-verify`, re-stage after a hook's auto-fix), and no `skills:` key:

- **Brief inputs:** the skill line, the batch number, the touched files, the remaining budget
  (files moved, dependencies removed), whether `docs/app_structure.md` exists, and on a re-run the
  batch's existing `[batch N boy-scout]` commits.
- **What it tidies (test organisation only, touched files only):** move or rename a test file so
  it mirrors the app; remove an existing cross-app test dependency (only when
  `docs/app_structure.md` exists); split a test module that tests more than one source module into
  one module per source module, keeping one part at the original path. It changes no assertion.
- **New files:** only under the `tests/` directory of an app one of its touched test files
  belongs to, such as a local fixture replacing a cross-app import or a split-out module.
- **Commits:** copy the grammar rows from 3e. A move is one file with no content change, always
  followed by its `edit` commit. A split or a dependency removal is one `edit` commit on its own.
  After each move/edit pair or standalone edit, run `uv run pytest <affected app test dirs>`. A
  move-only commit may break a test that relies on its directory's `conftest.py`, and the edit
  commit that follows restores it.
- **Budget:** stop at the remaining budget. Each violation past it goes into `Deferred`, unfixed.
  A split counts as one file.
- **Re-run:** finish a half-done pair from the listed commits rather than repeating it.
- **Report:** write `.sdd-work/boy_scout_batch_<N>.md` in one `Write` with `## Tidied` (one line
  per commit) and `## Deferred` (one entry per item: `file`, `rule`, `detail`, `app`), then the
  `status:` footer.
- **Return contract:** `status=<ok|failed|blocked> report=<path> reason=<short>`.

### 3e. `implement_plan.md`

- Add the boy-scout rows to "Commit-subject grammar":

  | Subject | Made by |
  | --- | --- |
  | `[batch N boy-scout] move <old-path> -> <new-path>` | boy-scout; exactly one file, no content change |
  | `[batch N boy-scout] edit <summary>` | boy-scout; the edit that goes with the move before it |
  | `[batch N boy-scout] edit split <path> into <a>, <b>` | boy-scout; a split |
  | `[batch N boy-scout] edit drop <app> test dependency on <other-app>` | boy-scout; one cross-app dependency removed |

- Under "Commit-subject grammar", below the table, add the budget count. Count fresh each time from `git log`, never carried in memory:

  ```bash
  LOG=$(git log --format=%s "$(git merge-base origin/main HEAD)..HEAD")
  moved=$(grep -cE '^\[batch [0-9]+ boy-scout\] (move |edit split )' <<<"$LOG" || true)   # cap 3
  dropped=$(grep -cE '^\[batch [0-9]+ boy-scout\] edit drop ' <<<"$LOG" || true)          # cap 1
  ```

  Remaining = cap minus count, floored at 0. The boy-scout still runs at zero budget, so it can
  report deferred items.
- Resume: the "follow-ons only" branch also reuses `.sdd-work/boy_scout_batch_<N>.md` when it ends
  `status: ok`, and a re-spawned boy-scout's brief lists the batch's existing `boy-scout` commits.
  The skip branch also deletes a leftover `.sdd-work/boy_scout_batch_<N>.md` by name.
- Follow-ons: insert these headings between Review fixes and Record, in this order:
  - **Boy-scout (follow-on 3).** Skip when no touched file is a test file (under a `tests/` directory, or
     `test_*.py` / `conftest.py`) or production code (any other source file). Markdown, `docs/`
     and `spec_dd/` paths count as neither. Otherwise record `FROM_REF=$(git rev-parse HEAD)` and
     spawn one `sdd:sdd-boy-scout` with the 3d inputs. Before spawning, note
     `git status --porcelain`. `failed` → restore modified tracked files with
     `git restore --staged --worktree <paths>` and delete, by name, any untracked file that was
     not in the earlier listing, then retry up to twice with the prior error in the brief. Its
     commits stay. `blocked` → as for the review.
  - **Scope check (follow-on 4).** Via `sdd:sdd-mechanic`, run `batch_scope_check.sh N <from-ref>`, with the
     script path resolved as in `pre_step_rebase.md` Step 3. `<from-ref>` is `FROM_REF`. On
     resume it is the parent of the batch's oldest `[batch N boy-scout]` commit, or `HEAD` when
     there is none. Exit 1 stops the run and puts the `OUT_OF_SCOPE:` paths to the user. Commits
     are never reverted automatically. Any other non-zero exit is `failed`.
  - **Deferred items (follow-on 6).** For each `Deferred` entry: if a row with status `next` in

     resumed run, skip an item whose bullet or `idea.md` already exists in the working tree.

## Slice 4: The boy-scout flags broken code for the user to decide

**Behaviour.** The boy-scout reports plainly broken code in the touched files, production code
included, and never fixes it. Depth 0 puts each flagged item to the user. "Not a bug" writes a
comment, "Fix it now" runs a test-first fix, and "Record a follow-up" goes the deferred-item route.

### 4a. `sdd-boy-scout.md`

- Update the description to mention flagging.
- New "Flagging" section: flag plainly broken code anywhere in the touched files and never fix it.
  Each flagged item has `file:line`, why it is broken, a recommendation (`fix now` / `record a
  follow-up` / `not a bug`) and a drafted one-line comment explaining why the code is correct, for
  use if the answer is "not a bug". The comment follows `code-comments`: it says why the code is
  correct and never who judged it. Never suppress its own flag. Do not flag a spot that already
  has a comment explaining why the code is correct.
- Report gains `## Flagged` (one entry per item with the fields above) between `## Deferred` and
  the footer.

### 4b. `implement_plan.md`

- Add the rows to "Commit-subject grammar":

  | Subject | Made by |
  | --- | --- |
  | `[batch N bug-fix] <summary>` | implementer, for a flagged item answered "fix it now" |
  | `[batch N flag-note] <path>` | depth 0, the "not a bug" comment |

- Add **Flagged items (follow-on 5)** between Scope check and Deferred items: up to four per `AskUserQuestion`. Each question
  shows `file:line` and why it is broken, puts the boy-scout's recommendation first, and offers
  three answers:
  - "Not a bug": depth 0 writes the drafted comment at the spot, following `code-comments`, and

  - "Fix it now": one `sdd:sdd-implementer` fixes it test-first, with the skill line and the
    subject `[batch N bug-fix] <summary>`, before the next batch starts.
  - "Record a follow-up": handled as a deferred item under Deferred items.

  On a resumed run, skip a flagged item that already has a `[batch N flag-note] <path>` or
  `[batch N bug-fix]` commit for its file.
