## 0. Ground rules

### Working order

Nine phases. Each is a commit. The order is chosen so that the highest-footprint rename lands before
everything that would otherwise have to be written twice, and so the migration reset (§5.8) is last.

| --- | --- | --- |

| 3 | §5.4 deletion semantics + admin lockdown | |

| 8 | §5.7 `course_recommendations` + §5.8 migration reset | §5.8: the reset carries the app move. |
| 9 | Conventions doc, glossary, app map | Reads the finished tree. |

### Every phase

1. **TDD.** Write the failing test(s) named in that phase, confirm RED, implement, confirm GREEN.
   Do not write the whole test suite up front. Only the tests for the phase in hand.
2. `uv run manage.py makemigrations` then `uv run manage.py migrate`. Never edit a migration that has
   already been committed. Only Phases 6 and 8 touch files with commit history behind them, and both
   do it by deleting and regenerating under the §4.5 authorisation, called out where they occur.
   Phase 5's hand-written `tags` swap edits a file `makemigrations` produced moments earlier and that
   has never been committed, which is not what the rule reaches, and needs no exception.
3. `uv run pytest freedom_ls/contrib/conformance/`. `test_migration_state_consistent` must pass at
   **every** commit, not only after Phase 8.
4. `uv run pytest`. Full suite green before committing.
5. Commit with `uv run git commit` (pre-commit hooks).

### Database

Each worktree owns `db_<branch>`. Phases 6 and 8 change app labels and therefore table names, so the
dev database must be rebuilt at those two points:

```
.claude/fls-dev/scripts/db_recreate.sh
```

### Vocabulary

The spec's nouns are the code's nouns. In particular: `course` (never `collection`) for the three
registration-side FKs; `collection` stays reserved for `ContentCollectionItem.collection` alone;
`LearnerCohortDeadlineOverride`; `TimestampedModel`; `course_recommendations`.

### 3b. The GFK pair contract

`SET_NULL` nulls `content_type` and leaves `object_id` populated. Each deadline model's `clean()`
currently recognises a whole-course deadline by `content_type is None and object_id is None`; a
half-nulled row would then skip the check and, worse, fail `full_clean()` semantics on the next admin
edit. Key on `content_type` alone. In the guard **and** in the duplicate lookup it guards, so a
half-nulled row is still found:

```python
def clean(self) -> None:
    super().clean()
    if self.content_type is None:
        existing = CohortDeadline.objects.filter(
            cohort_course_registration=self.cohort_course_registration,
            content_type__isnull=True,
        ).exclude(pk=self.pk)
        if existing.exists():
            raise ValidationError(...)
```

Apply to `CohortDeadline.clean()` (`:186-197`), `LearnerDeadline.clean()` (`:232-243`) and
`LearnerCohortDeadlineOverride.clean()` (the null-content branch at `:295-306`). The membership check
at the top of the override's `clean()` is untouched.

`Meta.constraints` on all three already carry
`condition=Q(content_type__isnull=False, object_id__isnull=False)`. Leave them; a half-nulled row
falls outside the condition, which is correct.

The read path needs nothing: `GenericForeignKey` resolves to `None` once `content_type` is null, and
every `__str__` already renders that as "Whole course".

### 4b. The forms these respellings require (§4.6)

`SiteAwareModelAdmin` excludes `site` from every admin form, and `UniqueConstraint.validate()`
abandons a constraint whose field sits in the exclusion set. `Cohort` gets away with it today only
because it spells the field `"site_id"`, which matches nothing in that set. Respelling it to `"site"`
would silently drop the check and hand back an `IntegrityError` 500 where a field error appears now.

Every one of the five admins therefore needs a `ConstraintValidationFormMixin` form. The mixin's
default `constraint_fields` is already `("site",)`, so these forms declare only a `Meta`:

```python
class CohortAdminForm(ConstraintValidationFormMixin):
    """Admin form for Cohort.

    ``site`` is un-excluded from validation so
    unique_cohort_name_per_organisation is checked while cleaning rather than
    failing at the database. It is still never rendered.
    """

    class Meta:
        model = Cohort
        exclude = ["site"]
```

`exclude = ["site"]`, not `fields = "__all__"`. A `ModelForm` needs one or the other, and `exclude`
is the safer of the two: under `ModelAdmin.get_form` both give the same rendered form, because
`SiteAwareModelAdmin.exclude` governs either way. But a form instantiated directly, outside the
admin, would render `site` as a real required field under `"__all__"`, reopening exactly the hole
`SiteAwareModelAdmin.exclude` exists to close. It is also the spelling
`OrganisationAdminForm` and `WebhookSecretForm` already use (both name an explicit field set that
omits `site`). Un-excluding `site` from *validation* is what `ConstraintValidationFormMixin` does and
is safe, because `SiteAwareModelBase.full_clean()` fills the value from the current request before
validation runs.

def _offending_apps(
    app_configs: Iterable[AppConfig], allowlist: frozenset[str]

## Phase 9. Conventions, glossary and the generated app map

### 9a. New `docs/app_conventions.md`

`docs/` has no developer-conventions tier today. Write it before `referral-link-tracker` is built. Without
it, the next contributor, or a run of `/fls-dev:plan_structure_review`, reads the missing
`SiteAwareModel` edge as an oversight and "fixes" it. It records:

- The `freedom_ls_<app>` label convention.
- The **extractable app** exemption from both that convention and `SiteAwareModel`: an app is
  extractable when a spec has committed it to leaving `freedom_ls/` as its own installable package.
  Today that is `icons` (becoming `django_semantic_iconify`), `markdown_rendering` and the planned
  `referral-link-tracker`. The exemption is permitted, not required. `markdown_rendering` already
  carries `freedom_ls_markdown_rendering` and keeps it, so `icons` is the only app taking it. They
  are exempt from nothing else; dependency direction still points host to app, never the reverse.
  Name `UNPREFIXED_LABEL_ALLOWLIST` in `contrib/conformance/tests/test_app_labels.py` as the place
  that membership is enforced.
- The check-id rule: a system-check id's label segment must equal that app's own registered
  `AppConfig.label`, whatever it is.
- `"site"` as the constraint spelling, and the `ConstraintValidationFormMixin` obligation that comes
  with it on any model with a live admin.
- The `default_auto_field` rule (§5e above) and the GFK `object_id` type rule (§5f above).
