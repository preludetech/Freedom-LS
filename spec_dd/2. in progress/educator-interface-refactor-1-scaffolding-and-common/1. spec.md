# Spec: educator interface refactor 1, scaffolding and common

## Purpose

The helpers every educator interface area shares move out of the flat `views.py`, `actions.py`, `filters.py`
and `reporting.py` into a new `freedom_ls/educator_interface/panels/common/` package. The area specs then
build on it. The approach is settled in `idea.md`. `research_codebase.md` holds the current line numbers.

## Scope

In:
- New packages `freedom_ls/educator_interface/panels/` and `panels/common/`, and eight modules in `common/`.
- Moving the shared names listed under Requirements, and repointing every import and patch string that names
  them.
- Moving the tests of the moved code to `freedom_ls/educator_interface/tests/panels/common/`, and deleting the
  one `mirroring_baseline.txt` line this resolves.

Out:
- Any area subpackage (`dashboard`, `audit_log`, `staff`, `course`, `learner`, `cohort`) and any class that
  belongs to one. Sibling specs 2 to 6 own those.
- Deleting emptied flat modules, trimming `views.py` to the shell, `urls.py`, `qa_helpers`, and the `fls-dev`
  skill docs, which still describe the flat layout. `educator-interface-refactor-7-cleanup` owns those.
- Any behaviour, UI, URL, template path or app label change. The flat domain modules `forms.py`, `staff.py`,
  `learner_import.py` and `messaging.py`.
- Splitting `quick_views.py`. The lazy `interface_config` import in `actions.py`
  (`staff_member_changed_response`).
- The learner code `learner_status_badge`, `_LEARNER_STATUS_TONES`, `LearnerCourseSummary` and
  `learner_course_summaries`, which stay in `views.py`.

## Decisions

- **No re-export shim, no migration.** No `@register_bulk_action` class moves, so no stored
  `BulkActionRun.action_path` changes. `EducatorBulkAction` and `CoursePickerMixin` are bases, not registered
  classes.
- **`panels/common/` is a leaf.** No module under it imports `views`, `actions`, `filters`, `quick_views`,
  `reporting` or anything under `panels/` outside `common/`. It may import the flat `forms.py`, which imports
  none of those. Checked by grep, with no new import-linter contract.
- **Patch strings name the module that looks the name up**, not the module that defines it. A name moved to
  `common` but still called from a flat module is patched on the flat module.
- **Moved names keep their spelling**, leading underscores included.
- **`panels/__init__.py` and `panels/common/__init__.py` are empty**: no package-level imports. Each new
  `common` module declares `__all__`, following the `panel_framework` modules.

the docstring change named below. String casts such as `cast("OrganisationScopedRequest", ...)` stay quoted.

### Flat modules

- `views.py`: imports every moved name it still uses from `panels.common.*`. `_course_title_column` and
  `_cohort_links_column` stay and import `_interface_link`. The `# TODO` block above `_interface_link`
  (`views.py:334-342`) stays in `views.py`. Imports left unused by the move go.
- `actions.py`, `filters.py`, `quick_views.py`, `reporting.py`: the `if TYPE_CHECKING:` import of
  `OrganisationScopedRequest` from `views` becomes a top-level import from `panels.common.request`. The
  `TYPE_CHECKING` guard goes wherever nothing else uses it. `quick_views.py` keeps it for `User`.
- `actions.py` imports the moved action names from `panels.common.actions` and `panels.common.bulk_actions`.
  `filters.py` imports `VisibleCourseFilter` for `LearnerCourseFilter`. `reporting.py` imports
  `report_over_limit_message` and drops imports it no longer uses.
- `quick_views.py`: the lazy `_active_status_badge` wrapper goes. Its callers use `active_status_badge`
  imported at the top from `panels.common.badges`. The lazy `_learner_status_badge` wrapper stays, because
  `learner_status_badge` stays in `views.py`.
- `templatetags/educator_tags.py`: `flag_badge` and `progress_status_badge` come from `panels.common.report`.
  `OrganisationScopedRequest` comes from `panels.common.request`. `LearnerCourseSummary` and
  `learner_course_summaries` still come from `views`.
- `tests/interface_walk.py`: `EducatorBulkAction` comes from `panels.common.bulk_actions`.

### Every reference repointed

After the move, a whole-repo grep finds no import, attribute access or patch string naming a moved name at its
old module, except where that module itself imports the name to use it. `research_codebase.md` section 4 lists
the known sites. One is not a plain import: in `tests/invariants/test_reason_mixin.py` the
`cls is not actions.EducatorReasonMixin` exclusion names `panels.common.actions.EducatorReasonMixin`, while the
walk over `actions` and `len(found) == 9` stay unchanged.

No `mock.patch` or `monkeypatch` string names a moved name today. Re-grep after the move anyway.

## Testing

No new test is written and no assertion changes.

New directories `tests/panels/` and `tests/panels/common/`, each with an empty `__init__.py`.

| New test file | Content | From |
| --- | --- | --- |
| `test_request.py` | the whole file, by `git mv` | `tests/test_denied_experience.py` |
| `test_filters.py` | the four `test_visible_course_filter_*` tests and `test_course_filter_names_the_owner_of_a_course_another_organisation_owns` | `tests/test_filters.py` |
| `test_bulk_actions.py` | the "recorded runs: the organisation scope and the finished notification" section and `test_a_bulk_action_on_rows_that_left_the_scope_answers_the_unavailable_dialog` | `tests/test_actions.py` |
| `test_report.py` | `TestProgressBadges` | `tests/test_reporting.py` |
| `test_badges.py` | `test_active_status_badge_has_one_label_and_tone_per_state` | `tests/test_views.py` |

- `common/actions.py`, `common/tables.py` and `common/ids.py` get no test file: no test exercises them
  directly. The helper, picker and `CoursePickerMixin` tests in `tests/test_actions.py` drive area actions over
  HTTP, so they stay and move with their areas.
- A test helper only the moving slice uses moves with it. A helper both the moving and the staying tests use
  goes to `tests/helpers.py`, not into two copies.
- The autouse `_site_context` fixture in `tests/test_filters.py` becomes a non-autouse fixture in
  `tests/conftest.py`. Both filter test files opt in with `pytestmark = pytest.mark.usefixtures(...)`, so no
  other educator test changes behaviour.
- `test_organisation/mirroring_baseline.txt`: delete the `test_denied_experience.py` line in the commit that
  moves the file. The other nine `# educator_interface` lines stay.
- A test file's module must exist when the file is committed. The mirroring check fails otherwise.
- Each move is its own commit. The whole-file move is a `git mv` with no content change in that commit, so git
  keeps it as a rename through a rebase.

  - `grep -rnE "freedom_ls\.educator_interface(\.(views|actions|filters|quick_views|reporting)\b| import )"`

- No `if TYPE_CHECKING:` import of `OrganisationScopedRequest` remains in `freedom_ls/`.

- Each new `panels.common.*` module and each flat module imports in a fresh interpreter
  (`python -I -c "import ..."`).
- The mirroring check passes, and `mirroring_baseline.txt` has lost only the `test_denied_experience.py` line.
- `git diff main --stat` shows no change under `templates/`, to `urls.py`, or to any migration.
