# Frontend QA: learner administration

This change finishes the learners section of the educator interface: adding learners (new accounts
with a setup email, or existing users), a list with statuses and filters, a tabbed learner page,
deactivate and reactivate, cohort membership add, remove and move from either side, individual
course registration, name editing, and the webhook events behind each action.

What a browser can see:

- **The learners list** shows an avatar chip with name and email, a status badge (Active, Pending,
  Removed), cohorts, courses with progress, and last activity; filters by status (Active and
  Pending by default), cohort and course; every row links to its page and opens a quick view.
- **Add learners** takes one address per line with optional names and an optional cohort, and
  reports each address in plain words. A new address gets a pending account and a setup email.
- **The learner page** has Overview (Details, Cohorts, Registrations), Courses and History tabs, a
  header with the status badge, the email, and Edit name, Deactivate or Reactivate, Resend setup
  email, Add to cohort and Register for course.
- **Membership** can be changed from the learner's Cohorts card and from a cohort's Learners tab;
  Remove and Move confirm with the courses the learner loses, and Move previews the percentage a
  shared course continues at.
- **Registrations** can be added, withdrawn and reinstated individually.
- **An inactive cohort** takes no membership action from either side.

Beyond the golden path, this run hunts for:

- **Stale pages.** A second tab that still offers an action after the learner or cohort changed
  must answer with a reason in the dialog, never silently succeed.
- **Over-granting.** A cohort admin reaching Deactivate, Add learners, Edit name, or a cohort they
  hold no grant on; a cohort viewer seeing any write control.
- **Enumeration.** Another organisation's learner, cohort or registration answers 404 on every
  action URL.
- **Progress lost or duplicated by a move.** A learner at 40% must still read 40% after the move,
  with no new 0% row.
- **Repeat submissions.** Submitting the same add, remove, register or resend twice must be refused
  or be a no-op, and fire no second webhook event.

### 0.3 Logging in

Go to `http://127.0.0.1:$PORT/accounts/login/`, enter the email and password, submit. To switch
persona, log out at `/accounts/logout/` first, or use a second browser context.

Northside's learners list is `http://127.0.0.1:$PORT/educator/organisations/northside/learners`.
A learner's page is `.../learners/<learner pk>`; a cohort's Learners tab is
`.../cohorts/<cohort pk>/__tabs/learners`.
