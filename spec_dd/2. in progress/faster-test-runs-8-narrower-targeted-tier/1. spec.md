# Spec: a batch's targeted run covers only what its change can affect

Idea: `idea.md`. Answers taken before writing: `answers.md`. Research: `research_*.md` beside this
file, chiefly `research_codebase.md` for line references.

## Purpose

Of the last 119 batches, 69 ran most or all of the suite in the targeted tier (`spec_dd/1. next/faster-test-runs/research_batch_test_load.md`).
Two selector rules cause it. Any path matching a built-in escalation glob (`**/conftest.py`,
`**/urls.py`, `**/factories.py` and five more) or no rule at all goes to `full`. And a change to any file in
an app selects the whole tests directory of every app that reaches it through runtime imports, so
one line in `panel_framework` selects 36 of 42 app test directories.

When this ships, a project that opts in gets a targeted tier that selects by module instead of by
app, and scopes the shared files the import graph cannot see instead of escalating them.
`implement_plan`'s final full run stays, and it is where the wide check happens.

## Scope

In:

- An opt-in `narrow` key in `[tool.test_tiers]` that switches branch paths to module-level
  importer selection and scoped handling of the built-in escalation globs.
- A `--wide` flag on the selector that ignores `narrow`, used by `finish_worktree`'s checkpoint.
- A `demo_content/**` rule in FLS's `pyproject.toml`, and `narrow = true` for FLS.
- A replay of the 119 batches, before and after, recorded beside this spec.

Out:

- Coverage-based selection (pytest-testmon).
- How many runs go at once (`faster-test-runs-9-machine-wide-test-run-limit`).
- What happens after a failure (`faster-test-runs-10-rerun-only-failures-in-a-batch`).
- Paths main brought in (`--upstream-range`): `decide_upstream` keeps its outcome, `narrow` or not.
- The dependency-file rule. A dependency file still means `full`.

## Decisions

- **Opt-in per project.** With `narrow` absent or `false` every selection is today's, byte for
  byte. A downstream project without a final full run keeps its wide check.
- **Module-level importers, not a depth cap or a per-app list.** `base` is a direct runtime
  dependency of nearly every app, so a depth-1 cap still selects about 35 apps for it, and a
  hand-kept hub list drifts.
- **The graph is built from source on each run, with `ast`.** The committed app map discards
  module edges, and the selector stays stdlib only like its siblings.
- **The owning app's whole tests directory still runs.** It catches same-app string references
  (templates, URL names, `apps.get_model`) the import graph cannot see.
- **`finish_worktree`'s checkpoint stays wide.** It is the last local run before main.
- **Fix runs select from the fix alone.** Review fix, design fix and criterion fix batches already
  pass `--working-tree` or a range starting at the fix; that stays. The batch's own run covered
  the batch's change, and the final full run covers the combination.

## Requirements

### 1. Configuration: `claude_plugins/django-stack/scripts/select_tests.py`

1.1. `TierConfig` gains `narrow: bool`, default `False`. `load_tier_config` reads
`[tool.test_tiers].narrow`. A non-boolean raises `ConfigError` in the existing style:
`[tool.test_tiers] 'narrow' must be true or false`.

1.2. A new `--wide` argument makes the run behave as though `narrow` were `false`. It is valid
with every other argument.

1.3. When narrowing is in effect, the `tier:` line is followed by `mode: narrow`. Without it,
output is unchanged.

1.4. The `memory` subtable is untouched; `run_tests.py` keeps reading only that.

### 2. Module import graph: new sibling `claude_plugins/django-stack/scripts/module_graph.py`

2.1. Stdlib only. It walks every tracked `.py` file under the project's top-level Python packages
(the roots `generate_app_map.iter_app_trees` already finds) and under the test roots the tooling
rules name, and maps each to a dotted module name (reuse `generate_app_map.module_name`).

2.2. Edges come from `ast.Import` and `ast.ImportFrom`, relative imports resolved. Importing
`a.b.c` is an edge to `a.b.c`, `a.b` and `a`, since Python executes each package's `__init__`.
`from a.b import c` is an edge to `a.b.c` when that module exists, otherwise to `a.b`. Imports
anywhere in the file count, including inside functions and `if TYPE_CHECKING:`.

2.3. Edges are keyed by name, so a test file importing a module the change deleted or renamed
still reaches it (`range_paths` already reports both sides of a rename).

2.4. `module_graph.test_files_reaching(modules) -> set[str]` returns every collected test file
(`check_test_mirroring.is_collected`) from which any of `modules` is reachable through any number
of edges.

2.5. The graph is built at most once per selector run, and only when narrowing is in effect and a
branch path needs it.

### 3. Branch-path rules under `narrow`, in `decide()`

The order of `decide()` stays: `none` globs, test files, dependency files, escalation, owning app,
tooling, unmapped. Under `narrow`:

3.1. **Python module in an app.** Selects the owning app's tests directory (`owner_decision`,
including its Playwright handling) plus `test_files_reaching({module})`. No app-level importer
decisions. The `why:` reason names the count of test files selected through imports.

3.2. **Python module outside any app** (for example a shared `tests/factories.py`). Selects
`test_files_reaching({module})`. If that set is empty it falls through to tooling and then to the
unmapped rule, as today.

3.3. **Non-Python file in an app** (templates, static, JS, data). Selects the owning app's tests
plus the tests directory of each app with a direct runtime or test edge to it in the app map. That
is one app hop, not the chain `importers()` walks today.

3.4. **Built-in escalation globs.** These stop meaning `full`:

| Glob | Under `narrow` |
| --- | --- |
| `**/conftest.py` | Selects the conftest's own directory subtree. Stays `full` when that directory is an ancestor of any app directory (the project root conftest and the package-root conftest). |
| `**/factories.py`, `**/signals.py`, `**/middleware.py` | Rule 3.1 or 3.2. |
| `**/urls.py`, `**/apps.py` | Rule 3.1, plus the tests directory of each app with a direct edge to the owning app, because URL includes and `INSTALLED_APPS` load them by string. |
| `**/fixtures/**` | Rule 3.3. |
| `**/migrations/**` | Stays `full`: a migration changes the schema every test runs against. |

3.5. **Project `escalation` globs** (`[tool.test_tiers].escalation`) still mean `full`. A project
narrows one by removing it from its own list.

3.6. **Unmapped paths.** An unmapped tracked path still means `full`. A project fixes one by
adding a `tooling` rule.

3.7. **Naming the run that covers the rest.** Every `why:` line for a decision narrowed by rule
3.1 to 3.4 ends `(narrow; the rest is left to a full run)`. A decision that is `full` keeps the
` -> full (` substring `full_run_record.run_selector` parses.

3.8. **Paths main brought in** go through `decide_upstream` unchanged, with today's app-level
`importers()`. `narrow` and `--wide` do not change any `--upstream-range` decision.

3.9. `minimal_selection` and `compose_command` handle test-file targets as they already do for
tooling rules.

### 4. The checkpoint: `claude_plugins/sdd/scripts/full_run_record.py`

4.1. Both selector calls in `resolve` pass `--wide`, so the checkpoint's tier is what it is today
whether the project narrows or not.

### 5. FLS configuration: `pyproject.toml`

5.1. `[tool.test_tiers]` gains `narrow = true`, with a comment saying `implement_plan`'s final full
run and CI on the PR cover what it leaves out.

5.2. A `[[tool.test_tiers.tooling]]` entry with `glob = "demo_content/**"` and these targets:
`freedom_ls/content_engine/tests/demo_content`, `freedom_ls/learner_interface/tests/demo_content`,
`freedom_ls/blog/tests/demo_content`, `freedom_ls/content_engine/tests/test_validate.py` and
`claude_plugins/fls-content/validate/tests/test_validator.py`. It applies with or without `narrow`.

5.3. The project escalation list (`config/**`, `freedom_ls/site_aware_models/**`,
`freedom_ls/content_base/**`) stays as it is.

## Testing

In `tests/test_select_tests.py`, with made-up app names in a temp repo, as the existing tests do:

- Every existing test passes unchanged with no `narrow` key.
- `narrow` validation: a non-boolean is rejected naming the key; `narrow = false` matches no key.
- `--wide` with `narrow = true` gives the same output as no `narrow`.
- Module selection: a change to a leaf module of a widely imported app selects only the owning
  app's tests and the test files that reach it; an app that imports another module of the same
  app is not selected.
- Transitive reach: a test file that imports `x`, where `x` imports the changed module, is selected.
- `import a.b.c`, `from a.b import c` (module and attribute), relative imports and a package
  `__init__.py` change each select the right files.
- A deleted module still selects the test files that import it by name.
- Each row of the 3.4 table, including the two `full` cases for conftests above an app and for
  migrations.
- A non-Python app file selects one app hop, not the chain.
- Narrowed `why:` lines end with the 3.7 wording; a `full` line still contains ` -> full (`.
- Every `--upstream-range` test passes unchanged with `narrow = true`.

In `tests/` for `full_run_record.py`: `resolve` passes `--wide` to both calls.

A test that runs the selector against FLS's own `pyproject.toml` for a `demo_content/` path and
asserts the five targets, so the rule cannot silently stop matching.

For the replay, run the selector over the same 119 `[batch …]` commits the research used, with
`narrow` off and on, and write `replay.md` beside this spec. It counts batches per result as the
research table does, and lists for each batch the app test directories `narrow` dropped, so a
later escape can be traced to the rule that dropped it.

## Open questions

- Q: Should a non-Python file in an app (template, static, JS) select one app hop of importers, or
  only the owning app? → A: One app hop (rule 3.3). (assumed default: a shared template or JS
  change, such as the `localTime` rendering change found in `research_known_complaints.md`, breaks
  tests in apps that use it, and one hop catches most of those. Overrule by editing 3.3.)

## Success criteria

- With no `narrow` key, the selector's output for every existing test case is unchanged.
- With `narrow = true`, a one-line change to a leaf module in `panel_framework` no longer selects
  the tests directories of the 36 apps it selects today; the selection is the owning app's tests
  plus the test files that reach that module.
- With `narrow = true`, a change to an app's `tests/conftest.py` gives `targeted` with that
  directory, not `full`.
- A `demo_content/**/*.md` change gives `targeted`, not `full`.
- `replay.md` exists and shows fewer of the 119 batches at `full` or at 28 or more app test
  directories than today's 69.
- The selector, with `narrow = true`, finishes in under 10 seconds on FLS.
- `finish_worktree`'s checkpoint gives the same tier for the same range before and after the change.
- Before and after timings are reported against `spec_dd/1. next/faster-test-runs/research_test_timings.md`.
