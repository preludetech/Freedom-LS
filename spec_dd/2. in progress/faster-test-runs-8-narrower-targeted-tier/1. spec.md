# Spec: a batch's targeted run covers only what its change can affect

Idea: `idea.md`. Answers: `answers.md`. Research: `research_*.md` beside this file, chiefly
`research_codebase.md` for line references.

## Purpose

A project that opts in gets a targeted tier that selects by module instead of by app, and scopes
the shared files the import graph cannot see instead of escalating them to `full`. The idea's
"Why" and `spec_dd/1. next/faster-test-runs/research_batch_test_load.md` give the cause: 69 of the
last 119 batches ran `full` or 28 to 38 of the 42 app test directories.

## Scope

In:

- An opt-in `narrow` key in `[tool.test_tiers]` that switches branch paths to module-level
  importer selection and scoped handling of the built-in escalation globs.
- A `--wide` flag on the selector, used by `finish_worktree`'s checkpoint.
- A `demo_content/**` rule in FLS's `pyproject.toml`, and `narrow = true` for FLS.
- A replay of the 119 batches, before and after, recorded in `replay.md` beside this spec.

Out:

- Coverage-based selection (pytest-testmon).
- How many runs go at once (`faster-test-runs-9-machine-wide-test-run-limit`).
- What happens after a failure (`faster-test-runs-10-rerun-only-failures-in-a-batch`).
- Paths main brought in (`--upstream-range`). `decide_upstream` keeps its outcome, `narrow` or not.
- Dependency files. They still mean `full`.
- Fix batch diffs. Review fix, design fix and criterion fix runs already select from the fix
  alone (`--working-tree`, or a range starting at the fix) and keep doing so.

## Decisions

- **Opt-in per project.** With `narrow` absent or `false` every selection is today's, byte for
  byte, so a downstream project without a final full run keeps its wide check.
- **Module-level importers.** A depth cap still selects about 35 apps for `base`, which nearly
  every app imports directly.
- **What `narrow` cannot see is left to the full run.** `implement_plan`'s final full run and CI
  on the PR cover links the import graph misses: a cross-app model named by string
  (`"app.Model"`, `apps.get_model`), receivers wired in `AppConfig.ready`, dotted paths in
  settings, and a template that includes another app's template. The owning app's whole tests
  directory still runs, which covers these links inside one app.

## Requirements

### 1. Configuration: `claude_plugins/django-stack/scripts/select_tests.py`

1.1. `TierConfig` gains `narrow: bool`, default `False`. `load_tier_config` reads
`[tool.test_tiers].narrow`. A non-boolean raises `ConfigError` in the existing style:
`[tool.test_tiers] 'narrow' must be true or false`.

1.2. `TierConfig` keeps the built-in escalation globs and the project's `escalation` globs in two
fields, so `decide()` can tell which one a path matched.

1.3. `--wide` makes the selector choose as it would with `narrow = false`. It still prints a
`targeted` tier where that applies; it is not the `full` tier. It is valid with every other
argument.

1.4. When narrowing is in effect, the `tier:` line is followed by `mode: narrow`. With no `narrow`
key, with `narrow = false`, or with `--wide`, there is no `mode:` line.

1.5. The `memory` subtable is untouched; `run_tests.py` keeps reading only that.

### 2. Module import graph: new sibling `claude_plugins/django-stack/scripts/module_graph.py`

2.1. Stdlib only. It does its own walk of the tracked `.py` files (`git ls-files`), skipping
`generate_app_map.SKIP_DIRS` through `in_skipped_dir`, and maps each file to a dotted module name
with its own path-to-name function. `iter_app_trees` and `module_name` take an `App` and cannot
walk non-app roots such as `tests/` or `freedom_ls/tests/`.

2.2. Edges come from `ast.Import` and `ast.ImportFrom`, with relative imports resolved. Both
`import a.b.c` and `from a.b import c` add an edge to every parent package (`a`, `a.b`), since
Python runs each `__init__`. `from a.b import c` also adds `a.b.c` when that module exists.
Imports anywhere in the file count, including inside functions and `if TYPE_CHECKING:`.

2.3. Each collected test file has an implicit edge to every `conftest.py` in its directory and
its ancestor directories, because pytest loads them without an import.

2.4. Edges are keyed by name, so a test file importing a module the change deleted or renamed
still reaches it (`range_paths` already reports both sides of a rename).

2.5. `module_graph.test_files_reaching(modules) -> set[str]` returns every collected test file
(`check_test_mirroring.is_collected`) from which any of `modules` is reachable through any number
of edges. When `[tool.pytest.ini_options].testpaths` is set, only files under those paths count
as test files, so a script named like a test (`select_tests.py`) is never selected. A file the
working tree has deleted is not a test file either.

2.6. The graph is built at most once per selector run, and only when narrowing is in effect and a
branch path needs it.

### 3. Branch-path rules under `narrow`, in `decide()`

The order of `decide()` stays: `none` globs, test files, dependency files, escalation, owning app,
tooling, unmapped. Under `narrow`:

3.1. **Python module in an app.** Selects the owning app's tests directory (`owner_decision`,
including its Playwright handling) plus `test_files_reaching({module})`. No app-level importer
decisions. The `why:` reason gives the number of test files selected through imports. A module
under `templatetags/` also gets one app hop (rule 3.3), since templates load it by name.

3.2. **Python module outside any app** (for example `freedom_ls/tests/factories.py`). Selects
`test_files_reaching({module})` plus the targets of any tooling rule the path matches. When both
are empty it falls through to the unmapped rule, as today.

3.3. **Non-Python file in an app** (templates, static, JS, data). Selects the owning app's tests
plus one app hop: the tests directory of each app with a direct runtime or test edge to the
owning app in the app map, without the chain `importers()` walks today.

3.4. **Project escalation globs win.** A path matching a project `escalation` glob is `full`, even
when it also matches a built-in glob (FLS's `config/urls.py`). A project narrows one of its own
globs by removing it from its list.

3.5. **Built-in escalation globs.** For a path that matches no project glob, these stop meaning
`full`:

| Glob | Under `narrow` |
| --- | --- |
| `**/conftest.py` | Selects the conftest's own directory subtree, plus any test file outside it that imports the conftest. Stays `full` when that directory is an ancestor of any app directory (the project root conftest and the package-root conftest). |
| `**/factories.py`, `**/signals.py`, `**/middleware.py` | Rule 3.1 or 3.2. |
| `**/urls.py`, `**/apps.py` | Rule 3.1 plus one app hop, because URL includes and `INSTALLED_APPS` load them by string. One no app owns (a project URLconf) stays `full`: `ROOT_URLCONF` names it by a dotted path. |
| `**/fixtures/**` | Rule 3.3. |
| `**/migrations/**` | Stays `full`: a migration changes the schema every test runs against. |

3.6. **No app map.** When `docs/app_structure.md` is missing, rules 3.1 and 3.2 still narrow; the
rules that need one app hop (3.3, and the `urls.py` and `apps.py` rows of 3.5) are `full`, as
today.

3.7. **Unmapped paths.** An unmapped tracked path still means `full`. A project fixes one by
adding a `tooling` rule.

3.8. **Naming the run that covers the rest.** Every `why:` line for a decision narrowed by rules
3.1 to 3.5 ends `(narrow; the rest is left to a full run)`. A `full` decision keeps the
` -> full (` substring `full_run_record.run_selector` parses.

3.9. **Paths main brought in** go through `decide_upstream` unchanged, with today's app-level
`importers()`. `narrow` and `--wide` do not change any `--upstream-range` decision.

3.10. `minimal_selection` and `compose_command` handle test-file targets as they already do for
tooling rules.

### 4. The checkpoint: `claude_plugins/django-stack/resources/test_tiers.md`

4.1. The tier definition says a checkpoint passes `--wide` to the selector twice: in the
`<selector>` string `run_test_tier` gives `full_run_record.py resolve`, and in the targeted run
that follows when `resolve` returns `targeted`. The `sdd` plugin, including `full_run_record.py`
and `run_test_tier.md`, is unchanged.

### 5. FLS configuration: `pyproject.toml`

5.1. `[tool.test_tiers]` gains `narrow = true`, with a comment saying `implement_plan`'s final
full run and CI on the PR cover what it leaves out.

5.2. A `[[tool.test_tiers.tooling]]` entry with `glob = "demo_content/**"` and these targets:
`freedom_ls/content_engine/tests/demo_content`, `freedom_ls/learner_interface/tests/demo_content`,
`freedom_ls/blog/tests/demo_content`, `freedom_ls/content_engine/tests/test_validate.py` and
`claude_plugins/fls-content/validate/tests/test_validator.py`. It applies with or without `narrow`.

5.3. The project escalation list (`config/**`, `freedom_ls/site_aware_models/**`,
`freedom_ls/content_base/**`) stays as it is.

## Testing

In `tests/test_select_tests.py`, with made-up app names in a temp repo, as the existing tests do:

- Every existing test passes unchanged with no `narrow` key.
- `narrow` validation: a non-boolean is rejected naming the key; `narrow = false` matches no key.
- `--wide` with `narrow = true` gives the same output as no `narrow`, with no `mode:` line.
- The `mode: narrow` line appears only when narrowing is in effect.
- Module selection: a change to a leaf module of a widely imported app selects only the owning
  app's tests and the test files that reach it; an app that imports another module of the same
  app is not selected.
- Transitive reach: a test file that imports `x`, where `x` imports the changed module, is selected.
- `import a.b.c`, `from a.b import c` (module and attribute), relative imports, and a change to a
  parent package's `__init__.py` reached through either form each select the right files.
- A module imported only by an app's `conftest.py` selects the test files below that conftest.
- A deleted module still selects the test files that import it by name.
- Rule 3.2: a non-app module selects graph results plus its tooling targets, and falls through to
  `full` when both are empty.
- Rule 3.4: a path matching both a project glob and a built-in glob is `full`.
- Each row of the 3.5 table, including the two `full` cases for conftests above an app and for
  migrations.
- Rule 3.6: with no app map, a Python module narrows and a template is `full`.
- Rule 3.7: an unmapped tracked path is still `full` under `narrow`.
- A non-Python app file selects one app hop, not the chain.
- Narrowed `why:` lines end with the 3.8 wording; a `full` line still contains ` -> full (`.
- Every `--upstream-range` test passes unchanged with `narrow = true`.

Against FLS's own repository:

- The selector, run on a `demo_content/` path with FLS's `pyproject.toml`, selects the five 5.2
  targets.
- Every test file that names `demo_content` sits under one of the five targets.
- For a sample of checkpoint ranges, the selector with `--wide` and `narrow = true` gives the same
  tier and selection as with no `narrow` key.

For the replay, run the selector over the same 119 `[batch …]` commits the research used, with
`narrow` off and on, and write `replay.md` beside this spec. It builds the module graph from
HEAD's tree, not each batch's, and says so. It records:

- the count of batches per result, as the research table does;
- for each batch, the app test directories `narrow` dropped, so a later escape can be traced to
  the rule that dropped it;
- the selector's run time with `narrow` off and on;
- before and after test-run timings against `spec_dd/1. next/faster-test-runs/research_test_timings.md`.

## Open questions

- Q: Should a non-Python file in an app (template, static, JS) select one app hop of importers, or
  only the owning app? → A: One app hop (rule 3.3). (assumed default: a shared template or JS
  change, such as the `localTime` rendering change in `research_known_complaints.md`, breaks tests
  in apps that use it, and one hop catches most of those. Overrule by editing 3.3.)

## Success criteria

- With `narrow = true`, a one-line change to a leaf module in `panel_framework` no longer selects
  the tests directories of the 36 apps it selects today.
- `replay.md` shows fewer of the 119 batches at `full` or at 28 or more app test directories than
  today's 69, and no fewer batches at `none` than today's 3.
- The selector, with `narrow = true`, finishes in under 10 seconds on FLS, and `replay.md` records
  the current time beside it.
