# Spec: every signed-in user edits their account on panels

Idea: `idea.md`. Answers: `answers.md`. Code facts: `research_codebase.md`, `research_current_account_pages.md`
(its picture and test rows are stale; `research_codebase.md` section 0 corrects them).

## Purpose

The account page (`accounts:account_profile`) is a hand-built page with two plain forms, and the
email and password pages sit under it in a bottom link list. Public-profile editing
(`learner-public-profile-2-profile-and-page` on) adds panels to this area, so the area has to be
on the panel framework first. This spec moves name and profile picture editing onto panels in an
account area with its own shell and sidebar, and puts allauth's email and password pages in the
same shell. It applies to every signed-in user: learners, educators and admins.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| account area | coined | The signed-in user's own settings pages that share the account shell and its sidebar: Personal details, Email, Password, and the sections later specs add. No existing term; "profile" is kept for the coming public profile. |
| account shell | coined | The page template every account-area page renders in, extending `_base_interface.html`. Distinct from the educator `_shell.html`. |

## Scope

In:

- A panel framework host for the account area in `accounts`, with one `ObjectViewConfig` section,
  Personal details, holding a name panel and a profile picture panel.
- The account shell and its sidebar, used by the Personal details page and, through the
  `allauth/layouts/manage.html` override, by every allauth management page.
- Fixing the inline record form's extra space under the field row (bug B1 in the done spec
  `learner-profile-use-panels-framework-1-file-upload-actions`'s `qa_report.md`).
- The header user menu label, tests, upgrade notes, product docs and the parent idea's stale line.

Out:

- Public profile, work experience, completed courses and certificates panels (`learner-public-profile-*`).
- Enabling MFA, sessions or social accounts.
- Rebuilding allauth's views, forms or page bodies (`account/email.html`, `account/password_*.html`).
- `complete_registration`, `legal_doc`, login, signup, password reset, email confirmation and
  reauthentication: they keep the entrance layout.
- The educator interface's own pages. Its sidebar cog keeps its "Account settings" label.

## Decisions

- **Labels.** The area is "Account". The sidebar lists Personal details, Email, Password. The
  page heading and document title of the panel page are "Personal details". The header user menu
  item reads "Account". The page is not called "Profile", so the public profile keeps that word.
- **Sections are sidebar entries, not tabs.** Each entry is its own page; a panel page is one
  `PanelStack`. Later specs add entries to the same sidebar list.
- **The sidebar is an `accounts` partial, not `panel_framework/partials/sidebar_nav.html`.** The
  framework nav only links panel sections with `hx-get` into `#main-content`, and Email and
  Password are allauth pages. Every entry is a plain link (full page load). This also keeps a third
  spec out of the framework templates that `learner-profile-use-panels-framework-2-editable-list-panel`
  and `extract_panels_framework-4-template-contract` edit.
- **Confirmation.** Each account save answers with its panel refreshed plus the out-of-band toast
  from `partials/messages.html`: "Name saved", "Profile picture saved", "Profile picture removed".
  Every account save also swaps the header avatar out of band, since the avatar shows the
  picture or, without one, the initials from the name. A response that carries the toast
  gets no framework error message (`fls-dev:panel-framework`, "Forms with a file field").
- **Removing a picture is a confirmation dialog**, an error-tone `ConfirmAction` in `#app-modal`,
  per `fls-dev:panel-framework`. It replaces the "Remove" checkbox on the upload form.
- **Own-object access only.** The config's `get_object` returns a fresh copy of the signed-in
  user (`User._base_manager.get(pk=request.user.pk)`, as `_own_user` does today), so a refused
  submission never reaches `request.user` and the header. Nothing in a URL names a user.
- **No audit entries.** The audit log is organisation-scoped and a user's own account has no
  organisation.
- **Accounts code copies the educator pattern; it never imports `educator_interface`.**
  `LearnerNamePanel` and `EditLearnerNameAction` are the model to follow, not a dependency. The
  panel framework gets nothing account-specific; its only change is the inline form spacing.
- **The account shell's mobile sidebar is `_base_interface.html`'s own** (the drawer the educator
  shell uses), so the area behaves like the other interface.

## Requirements

### Host, URLs and config (`freedom_ls/accounts/`)

- Code follows the `panels/<area>/` layout (roadmap, "Educator interface code layout" effort):
  `accounts/panels/personal_details/` holds `config.py`, `panels.py`, `instance_view.py`,
  `actions.py`, each only where it has content, with empty `__init__.py` files. Tests mirror at
  `accounts/tests/panels/personal_details/`.
- `urls.py`: `profile/` and `profile/<path:path_string>` both carry the name `account_profile`, so
  `reverse("accounts:account_profile")` with no kwargs still works (header menu, educator cog,
  `EXEMPT_URL_NAMES`, existing tests). The host pattern stays under `profile/` so it never swallows
  `legal/` or `complete-registration/`.
- The host view is `@login_required` (anonymous users go to login; `check_request` alone would
  404 them) and calls `panel_framework_view` with the account area's `list[NavGroup]`, the account
  page template and `url_name="accounts:account_profile"`. An empty `path_string` redirects to the
  first section, as the educator `interface` view does.
- The Personal details section is an `ObjectViewConfig` with `url_name = "personal-details"`:
  - `get_object`: the fresh copy above.
  - `authorise_instance`: 404 unless the instance's pk is `request.user.pk`.
  - `has_capability`: grants the capabilities the account actions ask for, on the signed-in
    user's own row only; denies everything else. (`EditAction.get_capability` falls back to
    `accounts.change_user`, which a learner lacks, so leaving the default denies every action.)
  - `get_instance_label`: "Personal details".
- `edit_profile`, `edit_profile_picture`, the `account_profile_picture` URL and
  `accounts/profile.html` are removed.
- `EXEMPT_URL_NAMES` in `accounts/middleware.py` is unchanged. Panel and action URLs resolve to
  `account_profile`, so a user with incomplete registration forms is still sent to
  `complete_registration`.

### Name panel

- Edits `first_name` and `last_name` with one inline Save, posted to an `EditAction` subclass with
  `renders_in_footer = False`, through `panel_framework/partials/inline_record_form.html`.
- Validation is today's `UserForm`: both fields optional, at most 200 characters. An invalid
  submit answers 422 and shows each error as one line under its field (`role="alert"`,
  `aria-describedby`, `aria-invalid`).
- Success: the panel shows the saved names, the "Name saved" toast appears, and the header
  avatar's initials and accessible name show the new name.

### Profile picture panel

- Shows the stored picture (or the initials fallback) from a copy of the user that the upload
  form does not bind to, so a refused file never shows as the current picture.
- Uploads with `ProfilePictureForm`'s validation, WebP re-encoding and storage unchanged
  (`validate_profile_picture`, `encode_profile_picture`, the `profile_pictures` storage alias,
  `profile_picture_upload_to`). Replacing deletes the superseded file after commit, as
  `ProfilePictureForm.save` does today. The form's own Save is inline in the panel and posts
  multipart.
- Renders the field's help text ("JPEG, PNG or WebP, up to 10 MB…"), and the input names it with
  `aria-describedby`. The `accept` list stays `image/jpeg,image/png,image/webp`.
- A refused file answers 422 with its field error (for example `WRONG_TYPE`), and the panel still
  shows the stored picture.
- "Remove picture" shows only when a picture is stored. It opens an error-tone confirmation that
  says the current picture will be deleted and the initials shown instead. Confirming clears
  `profile_picture` and deletes the file after commit.
- Upload and removal each refresh the panel and show their toast.
- The header avatar markup in `header_bar_user_menu.html` moves into a partial with a stable id,
  so the full page and the out-of-band swap render the same markup.

### Account shell and sidebar (`freedom_ls/accounts/templates/accounts/`)

- The account shell extends `_base_interface.html` and supplies the panel framework host
  contract, from `extract_panels_framework-4-template-contract` once it has landed, until then
  from `spec_dd/1. next/extract_panels_framework/research_coupling_audit.md` T11 and J3:
  `modal_host.html`, `quick_view_host.html`, `announcer_host.html`,
  `panel_framework/js/alpine-components.js` in `extra_alpine_components`, the
  `document_title.html` fragment in `head_title`, and every DOM id J3 lists, `#interface-main`
  included. It uses framework partials and `panel-*` components only, no educator templates.
- The sidebar partial renders `<nav id="sidebar-nav" aria-label="Account">` from one Python list
  of entries (label, URL name) in `accounts`. The active entry carries `aria-current="page"`, found
  from `request.resolver_match`. `account_set_password` marks Password as active.
- After Email and Password, the sidebar keeps today's guarded entries for allauth's social
  connections, MFA and sessions pages (`{% url … as x %}`), so they appear only if a project
  enables those apps.
- The sidebar has no Log out entry. The header user menu keeps log out.

### allauth pages

- `freedom_ls/base/templates/allauth/layouts/manage.html` extends the account shell. allauth's
  `content` block lands in the shell's main area under the page header, and allauth's `head_title`
  feeds the document title. Django messages from allauth views show as toasts, as they do today.
- `entrance.html`, `base.html` and `elements/button.html` are unchanged. Reauthentication keeps
  the entrance layout (allauth's `account/base_reauthenticate.html` extends `base_entrance.html`).
- allauth's views, forms, URLs, rate limits, reauthentication and emails are unchanged.

### Header user menu (`freedom_ls/base/templates/partials/header_bar_user_menu.html`)

- The menu item to `accounts:account_profile` reads "Account".

### Inline record form spacing (`freedom_ls/panel_framework/templates/panel_framework/partials/inline_record_form.html`)

- The hidden `[data-request-error]` element adds no space under the field row, and neither does
  the base `form { @apply space-y-2 }` rule in `tailwind.components.css`. The revert in
  `494c1202f` shows why setting the margin alone fails. The fix applies to every inline record
  form, educator and account.

## Testing

Write the name-flow tests against today's `edit_profile` first, then move them to the panel:
GET shows the stored names; a valid POST saves; blank names are accepted; a 201-character name is
refused. The picture-era tests in `accounts/tests/test_views.py:937-1090` are the regression list
for the picture panel and are rewritten against it.

- **Access.** Anonymous GET of `/accounts/profile/`, the section, a panel URL and an action URL
  redirects to login. `authorise_instance` 404s for another user's row. `has_capability` denies a
  capability the account actions do not use. A learner, an educator and an admin each see and save
  their own Personal details. `/accounts/profile/` redirects to `personal-details`, and
  `reverse("accounts:account_profile")` with no kwargs resolves.
- **Name panel.** Valid save: names stored, HX-Trigger refreshes the panel, the "Name saved" toast
  is in the response, the header avatar swap is in the response, and no audit entry is written.
  Invalid: 422 with one-line errors and `aria-invalid`.
- **Picture panel.** Valid upload: stored as WebP, superseded file deleted, toast, header avatar
  swap. Refused file: 422, field error, stored picture still shown. Help text rendered and named by
  `aria-describedby`. Remove trigger absent with no picture. The remove confirmation is error-tone
  and names the picture. Confirmed removal: file deleted, initials shown, toast.
- **Shell and sidebar.** The Personal details page, `account_email`, `account_change_password` and
  `account_set_password` each render the sidebar with the right entry marked `aria-current="page"`
  and the host ids. `account_reauthenticate` renders the entrance layout.
- **Header menu.** `base/tests/components/test_header_bar_user_menu.py` asserts "Account".
- **Unchanged.** `accounts/tests/test_middleware.py`, `educator_interface/tests/test_sidebar.py:170-185`,
  `contrib/conformance/test_urls.py:79`, `base/tests/invariants/test_error_pages.py:55-63` and
  `manage.py check` (`check_panels`) pass.
- **Browser.** `accounts/tests/playwright/test_profile_picture_flow.py` is rewritten for the panel:
  upload, refused file with its error lined up under the field, confirmed removal, and the header
  avatar changing without a reload. A Playwright test measures the rendered inline record form on
  both the account name panel and the educator learner name panel and asserts no space below the
  field row beyond the form's own padding.

## Open questions

- Q: Keep the `accounts:account_profile_picture` URL answering for downstream callers? → A: Removed and listed as a breaking change. (assumed default: only `profile.html` and tests reverse it in FLS, and keeping a dead endpoint is unrequested work. Overrule by editing Host, URLs and config.)
- Q: Should reauthentication render in the account shell? → A: No, it keeps the entrance layout. (assumed default: allauth builds it on `base_entrance.html`, and the idea keeps the entrance flows as they are. Overrule by editing allauth pages.)
- Q: Keep the guarded social, MFA and sessions sidebar entries? → A: Kept, rendering only when the app is enabled. (assumed default: today's `manage.html` has them, and dropping them would hide those pages from a project that enables one. Overrule by editing Account shell and sidebar.)

## Success criteria

- A learner, an educator and an admin each change their name and picture at `/accounts/profile/`
  without a full page reload, and see a toast and the new header avatar.
- Every request for someone else's account data 404s, and anonymous requests redirect to login.
- Name and picture validation errors answer 422.
- Personal details, Email and Password render the same sidebar, with the current entry marked.
- Removing a picture asks for confirmation first.
- The inline record form shows no extra space under its field row, measured in a browser.
- `reverse("accounts:account_profile")` resolves with no kwargs, and the existing middleware,
  sidebar and conformance tests pass unchanged.
- The upgrade notes name every changed template and the removed picture URL.
