# Frontend QA: account area on panels

## Setup

- Start the server: `uv run python manage.py runserver $PORT`. The base URL is
  `http://127.0.0.1:$PORT`.
- Log in at `/accounts/login/` with the QA login from `.claude/sdd/config.md` (`## QA Login`).
  That account is an admin.
- Some tests need a learner and an educator who have finished registration. Create or reuse one
  of each in the dev database, and log in as them in a separate browser context.
- Have three files ready: a JPEG (under 10 MB), a second PNG, and a refused file such as a `.txt`
  renamed to `.jpg`.
- Run every test at desktop 1920×1080. Re-run the tests marked **(viewports)** at mobile 375×812
  and tablet 768×1024.

## Test 1: the account area loads (viewports)

1. Open the header user menu (avatar, top right). The item reads **Account**, not "Profile".
2. Click Account. The URL becomes `/accounts/profile/personal-details` (from
   `/accounts/profile/`).
3. Expect:
   - Heading "Personal details". The browser tab title is "Personal details — <site title>".
   - A sidebar labelled Account with Personal details (marked current), Email and Password, in
     that order. There is no Log out entry, and no Account connections, Two-factor or Sessions
     entry unless those apps are enabled.
   - Two panels, in order: Name (First name, Last name, one Save on the same row) and Profile
     picture (current picture or initials, a file input with the help text "JPEG, PNG or WebP, up
     to 10 MB…", and Save picture).
   - The Name card has no extra space under its field row: its bottom padding matches the
     other card's.
4. Mobile: the sidebar is behind one navigation toggle (exactly one toggle on the page). Opening
   it shows the same three entries. There's no sideways scroll.
5. Visit `/accounts/profile/` directly. It redirects to `personal-details`.

## Test 2: change the name inline

1. Change First name to "Ada" and Last name to "Lovelace", then click Save.
2. Expect: Save shows "Saving…" and is disabled while the request runs. Then a "Name saved" toast
   appears, the fields keep the new values, and the page doesn't reload (the scroll position and
   the URL stay the same). With no picture stored, the header avatar's initials become "AL".
   Open the user menu: its accessible name (screen reader, or the trigger's text in the
   accessibility tree) is "Open user menu for Ada Lovelace".
3. Clear both names and Save. Accepted, with the toast. The header falls back to the email-based
   name or the user icon.
4. Type 201 characters into First name and Save. Expect one red line under the field row
   ("Ensure this value has at most 200 characters…"), the input marked invalid, no toast, and the
   header unchanged. Reload: the stored name is still the previous one.
5. Restore the original name.

## Test 3: upload, replace and refuse a picture (viewports)

1. Choose the JPEG and click Save picture. Expect "Uploading…", then the "Profile picture saved"
   toast. The panel preview and the header avatar show the new picture without a reload. The
   file input is empty again.
2. Choose the PNG and Save picture. The picture is replaced in both places.
3. Choose the refused file and Save picture. Expect the type error one line under the input,
   lined up with the label, with no toast. The preview and the header still show the PNG.
4. Pick a valid file again and save. The error clears.
5. Mobile: the file input, help text and Save picture fit the width with no sideways scroll.

## Test 4: remove the picture through the confirmation

1. With a picture stored, the Profile picture panel shows **Remove picture**. There is no
   "Remove profile picture" checkbox anywhere.
2. Click Remove picture. A dialog opens (a centred modal on desktop, a sheet on mobile). It asks
   to remove the picture, says the current picture will be deleted and the initials shown, and
   its confirm button is red (error tone). Cancel closes it and nothing changes.
3. Open it again and press Escape. It closes, and nothing changes.
4. Open it and confirm. The button shows "Removing…". The dialog closes, the "Profile picture
   removed" toast shows, and the preview and header show the initials. Remove picture is gone.
5. Side effect: in another tab, open the dialog, then remove the picture from the first tab, then
   confirm in the second. Expect no error page. The picture stays removed.

## Test 5: email and password pages share the shell (viewports)

1. Click Email in the sidebar. A full page load to `/accounts/email/`. The sidebar shows Email
   as current, allauth's own heading and email list render in the main column, and the tab
   title is allauth's. Exactly one mobile navigation toggle.
2. Add a secondary email, or resend a verification. allauth's success message shows as a toast.
3. Click Password. `/accounts/password/change/` with Password current. Submit a wrong current
   password: allauth's form error shows. Don't change the QA password.
4. If the dev database has a user with no usable password, visit `/accounts/password/set/` as
   them. Password is marked current.
5. Click Personal details. Back on the panel page.
6. Mobile: open the sidebar from each of these pages. The three entries are there and no page
   scrolls sideways.

## Test 6: pages that keep the entrance layout

1. Log out. Visit `/accounts/login/`, `/accounts/signup/` and `/accounts/password/reset/`. They
   have no account sidebar and look as before.
2. Logged out, visit `/accounts/profile/`, `/accounts/profile/personal-details` and
   `/accounts/profile/personal-details/__panels/name`. Each redirects to login.
3. Log in, then trigger reauthentication if available (`/accounts/reauthenticate/`). It renders
   in the entrance layout, not the shell.

## Test 7: every role sees only their own account

1. As the learner: open Account from the header menu, change the name and upload a picture.
   Both work, and there's no 403 or "not allowed" message.
2. Repeat as the educator. Then check the educator interface's sidebar cog: still labelled
   "Account settings", and it leads to Personal details.
3. No URL in the area names a user. Try `/accounts/profile/personal-details/<another user's pk>`
   and `/accounts/profile/someone-else`. Both are 404, and no other user's data shows.
4. A learner whose registration forms are incomplete (if the site has extra registration forms)
   is sent to `complete-registration` when opening Account, as before.

## Test 8: the educator inline name form spacing is fixed

1. As the admin, open the educator interface. Go to a learner, then the Settings tab, then the
   Name panel. Then do the same for a cohort.
2. Expect the Name card's space under the field row to equal its top padding, with no extra
   12px gap. Compare it with the other cards on the tab.
3. Save a valid name there. It still saves, and the panel refreshes. Then submit an empty or
   too-long name. The error line shows under the row and the card grows only by that line.
