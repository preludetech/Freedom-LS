# Implementation plan — better form start page

## Goal

Restyle the **form start page** — the screen a learner sees before beginning a `Form` in the course
player — to match the "Quiz Start — First Time" design, using theme role tokens so it holds up under
any theme rather than only `first_class`.

This is a presentation change. No model changes, no migrations, no new view context, no new URLs, no
new functionality.

| Thing | Path |
| --- | --- |
| View | `view_form`, `freedom_ls/learner_interface/views.py:912` |
| Template | `freedom_ls/learner_interface/templates/learner_interface/course_form.html` |
| Meta grid partial | `.../partials/exam_meta_grid.html` |

Checked, not assumed: **no theme shadows any of these templates.** `freedom_ls/themes/*/templates/`
holds no files, so there is exactly one copy of each file to edit.

## The design being copied

The canvas offers two start screens. **The simple variant (`CheckinIntroFirstSimple`) is the one to
build** — one centred card, everything centre-aligned:

```
                   ┌────────┐
                   │  icon  │      60px rounded square, solid secondary fill
                   └────────┘
              SUBTITLE · EYEBROW     mono, uppercase, wide tracking, muted
           Form title goes here      display face, bold, large
        One paragraph of the form's
        authored markdown intro.

     ( icon 8 questions )  ( icon 3 pages )    pill chips, secondary-coloured icons

              [ Start Form ▸ ]                 primary button
```

### What is deliberately not built

The design shows several things FLS has no data for. The idea is explicit that no new functionality
comes out of this design, so each of these is **dropped**, not faked:

| Design element | Why it is dropped |
| --- | --- |
| "~10 min · Relaxed pace" | `Form` has no duration field. |
| "Unlimited tries" | There is no attempt-limit field to read. |
| "Or review the section first" ghost link | The form start page context carries no previous-item URL. |
| Third fact pill | Only two of the three are backed — question count and page count. |
| The teal glow shadow under the badge | `brand-guidelines` forbids drop shadows and decorative gradients, and FLS has no brand-coloured shadow token. |
| The filled (`ph-fill`) hand-wave glyph | `brand-guidelines` forbids filled icons; the badge uses the default outline `c-icon`. |
| The pill-shaped CTA button | `.btn` is `rounded-md` in both shipped themes and the theme owns button shape. Forcing `rounded-pill` here would make this one button ignore the theme — the opposite of what the idea asks for. The button stays whatever shape the active theme gives it. |

The design's simple variant also has nowhere to put previous attempts — but the FLS start page serves
returning learners as well as first-timers, and dropping that section would be removing working
functionality rather than restyling it. **Previous attempts stay**, restyled to sit below the card as
its own centred section.

One more thing the design keeps that `brand-guidelines` would rather it did not: the solid-fill badge
and the bordered attempt rows are "colour blocks and borders for structure", which its third UI
principle asks you to prefer whitespace over. That is pre-existing FLS practice — chips, bordered
rows and the whole course-card system already work this way — so it is kept, but it is a deliberate
choice rather than an oversight.

## Token and component mapping

Everything below already exists. Nothing new is added to `tailwind.components.css` or to any theme.

| Design | Use |
| --- | --- |
| `--color-secondary` badge fill | `bg-secondary text-on-secondary` |
| `--color-secondary-600` icon colour | `text-secondary` (FLS has no numeric colour ramp) |
| `--grey-100` pill background | `<c-chip variant="muted">` → `bg-surface-2` |
| `--bg-elev` panel | `bg-surface` |
| `--border` | `border-border` |
| `--fg-1` / `--fg-2` / `--fg-3` | `text-on-surface` / `text-muted` / `text-muted` |
| `--font-heading` / `--font-mono` | `font-display` / `font-mono` |
| 38px `h1` | the `@layer base` `h1` rule already gives `lg:text-4xl font-bold font-display` — do not re-declare a size |
| pill radius | leave chip and button shape to the theme (`.chip` / `.btn` own it); do not force `rounded-pill` |
| 560px card | `max-w-xl mx-auto` |

Icons come from `c-icon` semantic names only. Badge: `form`. Questions pill: `notes`. Pages pill:
`course_part`. No new semantic name is added — that would mean editing `semantic_names.py` plus all
four maps in `mappings.py` for decoration.

The research doc maps the design's question-count glyph to `form`, which is what the partial being
deleted used. The badge takes `form` instead — it stands for the whole form — so the questions pill
moves to `notes` rather than putting the same glyph on the page twice.

Two judgement calls worth stating rather than burying:

- **Icon sizing.** `fls-dev:icon-usage`'s table sizes the *icon*, not a container: `size-16` is its
  "hero" size and the only precedent (`course_finish.html:17`) is a bare `size-16` glyph with no box
  behind it. Putting `size-8` inside a `size-16` filled box is new. Check it by eye at all three
  viewport widths before treating it as settled; if it reads wrong, a bare `size-16` icon with no box
  is the safe fallback and is closer to house style anyway.
- **No CSS is added, deliberately — but the debt is real.** `ds:frontend-styling`'s reuse ladder says
  a repeating utility pattern should be promoted to a component class, and the
  `rounded-lg border border-border` panel-row shape is already hand-rolled in six templates. This
  change touches two of them. Promoting it is the right fix and it is **not** done here: it would
  reach into `course_form_complete.html`, `course_form_page.html` and `dashboard_applications.html`,
  which is a different change from restyling one page. Left as noted debt, not silently ignored.

## Tasks

Follow TDD: write the failing test, watch it fail, then make it pass.

### Task 1 — Failing tests for the restyled start page

Add to `freedom_ls/learner_interface/tests/test_form_runner_views.py`, in the existing
`# view_form context (start screen)` section. Follow the shape of
`test_view_form_context_includes_question_count_and_page_count` (`:460`) — `mock_site_context`,
`FormFactory` / `FormPageFactory` / `FormQuestionFactory`, `course_with_form`,
`register_user_for_course`, `client.force_login`, then GET
`learner_interface:view_course_item`.

**Four separate tests, one behaviour each** — `ds:testing` forbids multi-act tests and conditionals in
test bodies, so the subtitle-present and subtitle-absent cases cannot share a function:

| Test | Asserts |
| --- | --- |
| `test_form_start_page_shows_question_and_page_counts` | the rendered HTML carries "3 questions" and "2 pages" |
| `test_form_start_page_counts_are_singular_for_one` | a one-question, one-page form renders "1 question" and "1 page", not "1 questions" |
| `test_form_subtitle_renders_as_eyebrow` | a form with a `subtitle` renders that text inside a `<p>` |
| `test_form_without_subtitle_renders_no_eyebrow` | a form with a blank `subtitle` renders no empty eyebrow element |

`data-testid="start-form-button"` is already covered by `playwright/form_ui_tests.py:293`; do not add
a duplicate assertion for it.

These are template-level assertions on `response.content`, so no new pytest marker is needed —
`django_db` alone, matching the neighbouring tests. Unmarked is the portable default set.

**Assert on text and testids, never on Tailwind classes.** `ds:testing` forbids asserting on CSS
classes, colours or sizes, and a test that pins `bg-secondary` would have to be rewritten the next
time the theme moves. The styling is verified by eye, not by pytest.

### Task 2 — Rebuild `course_form.html`

Replace the body of the `content` block. Keep: the `x-data="coursePlayer"` root, the `buttons` loop
with every existing `data-testid`, and the `c-player-nav` wrapper (it carries the `hx-boost` config
that makes player navigation swap only the content column — see the component's own docs).

Sketch:

```
<c-page flush="true">
  {% comment %}c-page already owns py-8 lg:py-12; do not stack more here{% endcomment %}
  <div class="mx-auto max-w-xl text-center space-y-6" x-data="coursePlayer">

    {% comment %}badge{% endcomment %}
    <div class="mx-auto flex size-16 items-center justify-center rounded-lg bg-secondary text-on-secondary">
        <c-icon name="form" class="size-8" />
    </div>

    {% comment %}eyebrow + title{% endcomment %}
    <div class="space-y-2">
        {% if form.subtitle %}
            <p class="font-mono text-xs uppercase tracking-widest text-muted">{{ form.subtitle }}</p>
        {% endif %}
        <h1>{{ form.title }}</h1>
    </div>

    {% comment %}authored intro: only paragraphs centre, every other block stays left{% endcomment %}
    {% if form.rendered_content %}
        <c-markdown-container class="text-left [&_p]:text-center">
            {{ form.rendered_content }}
        </c-markdown-container>
    {% endif %}

    {% comment %}fact pills{% endcomment %}
    <div class="flex flex-wrap justify-center gap-2">
        <c-chip variant="muted" class="text-on-surface">
            <c-icon name="notes" class="size-4 text-secondary" />
            {{ question_count }} question{{ question_count|pluralize }}

            <c-icon name="course_part" class="size-4 text-secondary" />
            {{ page_count }} page{{ page_count|pluralize }}
        </c-chip>
    </div>

    {% comment %}CTA: every button action keeps its data-testid{% endcomment %}
    <c-player-nav>
        <c-button-group variant="centered">
            ... existing {% for button in buttons %} branches, unchanged ...
        </c-button-group>
    </c-player-nav>

    {% include "learner_interface/partials/exam_previous_attempts.html" %}
  </div>
</c-page>
```

There is no `<c-badge>` cotton component in the repo, and this does not warrant inventing one for a
single use. The nearest precedent for a large centred hero glyph is
`freedom_ls/learner_interface/templates/learner_interface/course_finish.html:14-18` — a bare `c-icon`
at `size-16` inside a centred wrapper. The only thing this adds is the filled square behind it.

Details that matter:

- Drop the `<p>` wrapper around each `c-button` — a paragraph around a button adds nothing and the
  centred group handles spacing.
- `c-button-group variant="space-between"` becomes `variant="centered"`; there is only ever one
  button in the list, and the design centres it.
- Drop `pt-4 border-t border-border` from `c-player-nav` — the simple variant has no CTA rule.
- Do not re-declare `font-display text-on-surface` on the `h1`; the base layer already applies both.
- `c-chip` composes its class as `{{ class }} chip chip-{{ variant }}`, and Tailwind's utilities layer
  beats the components layer, so `class="text-on-surface"` correctly overrides `chip-muted`'s
  `text-muted`.

## Skills to follow

- `ds:frontend-styling` + `fls-dev:frontend-styling` — read the stylesheets before styling, use only
  tokens that exist, run `npm run tailwind_build` after adding classes, never write unlayered CSS.
  This change should add no CSS at all.
- `ds:template` + `fls-dev:template` — cotton component conventions and the
  `freedom_ls/<app>/templates/` path convention.
- `fls-dev:icon-usage` — `c-icon` with semantic names only; no raw SVG, no icon-set names.
- `brand-guidelines` — no gradients, drop shadows or filled icons; "learners" not "students"; let
  whitespace do the work. **Take its tone and copy guidance, not its class names.** It names colours
  (`bg-ocean`, `text-midnight`, `bg-chalk`, `text-slate`) that do not exist as Tailwind classes in
  this repo; the live token set is the one in `themes/default/.../theme.css`, and
  `fls-dev:frontend-styling` is the authority there.
- `domain-glossary` — the noun is **`Form`**. Never introduce a `student_*` name.
- `code-comments` — template comments explain intent, never restate the markup, and never cite this
  plan or a section number.
- `unslop` — applies to the small amount of user-facing copy on the page.
- `ds:testing` + `fls-dev:testing` — pytest conventions and the `mock_site_context` fixture rule for
  site-aware tests.

Not relevant here: `fls-dev:multi-tenant` (no model changes), `ds:admin-interface`,
`ds:app-settings`, `fls-dev:file-storage`, `ds:htmx` (the existing `c-player-nav` boost is unchanged),
`ds:alpine-js` (no new client-side state — the root keeps its existing `x-data="coursePlayer"`, which
scrolls the outline to the current item and must stay).

Two tooling facts worth knowing:

- Template formatting is **not** gated. The `djlint` pre-commit hook is commented out
  (`.pre-commit-config.yaml:45-49`) and no CI job runs it, but `[tool.djlint]` in
  `pyproject.toml:110-118` still states the house conventions — a blank line after
  `{% load %}` / `{% extends %}` / `{% include %}`. Conform voluntarily.
- The Alpine CSP build is enabled (`.claude/ds/config.md`), so no inline `x-data` / `x-on`
  expressions. This change adds none.

## Naming

The two surviving partials are called `exam_previous_attempts.html` and `exam_score_ring.html`, but
the glossary's noun for the thing they describe is **`Form`**, not "exam". That mismatch predates this
work and renaming them would mean touching `course_form_complete.html` too, so it stays out of scope
here — noted so the next person knows it was seen rather than missed. Deleting `exam_meta_grid.html`
removes one of the three by itself.

"Fact pill" is the design canvas's own word for the small labelled chips (`research_design_source.md`),
not a coined FLS term; in the codebase they are just `c-chip`s.
