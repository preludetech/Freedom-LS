# Frontend QA — split into two plans

**This plan has been split. Do not run this file.** It is kept only as a signpost, because tooling
and earlier documents look for `3. frontend_qa.md` at this path.

The QA for this spec is now two independent runs, each in its own directory so that neither can
overwrite the other's screenshots or report:

| Plan | Covers | Run with |
|---|---|---|
| `3a. report_generation_qa/frontend_qa_report_generation.md` | QA 0–10 — admin generate flow, the rendered PDF, page breaks, at-risk flags, cohort confusions, greyscale print, the landscape column budget, permissions, failure branches, deletion and system checks | `/fls-dev:do_qa` on that file |
| `3b. quiz_marking_qa/frontend_qa_quiz_marking.md` | QA 11–13 — multi-select quiz scoring and everything it touches in the student interface (quiz runner, results page, course player, dashboard), plus the educator live panel and demo content | `/fls-dev:do_qa` on that file |

The QA section numbering is unchanged from the original document, so existing references to "QA 5.6"
or "QA 12.2" still resolve — the first ten sections are in the report plan and the last three in the
quiz-marking plan.

Each plan writes its `screenshots/` and `qa_report.md` into its own directory, and only the report
plan produces PDF artifacts (`3a. report_generation_qa/qa-artifacts/`). Neither run touches this
directory's `qa_report.md`, `screenshots/` or `qa-artifacts/` — those are the record of the earlier
combined run.

The two plans can be run in either order and by different people. The only place they meet is the
legacy-checkbox-score discrepancy, which is deliberately split so neither waits on the other: the
report plan's QA 2.11 owns the `legacy-score-discrepancy.pdf` artifact, and the quiz-marking plan's
QA 12.6 checks the same rule on the student's results page.
