# Implementation plan: error pages

Source: `idea.md` in this directory, plus `research_django_error_wiring.md`,
`research_error_states_design.md`, `research_error_page_ux.md` and
`research_rate_limit_surfaces.md`.

## What this comes down to

Seven templates, one shared cotton component, two new semantic icon names, and a restyle of one
existing template. No new views, no new URLs, no models, no migrations, no settings.

Django already routes every one of these surfaces at a template name we do not currently supply:

| Status | Who renders it | Template it looks for | Context it renders with |
| --- | --- | --- | --- |
| 404 | `django.views.defaults.page_not_found` | `404.html` | full `RequestContext` |
| 403 | `django.views.defaults.permission_denied` | `403.html` | full `RequestContext` |
| 400 | `django.views.defaults.bad_request` | `400.html` | full `RequestContext` |
| 403 CSRF | `django.views.csrf.csrf_failure` (the default `CSRF_FAILURE_VIEW`) | `403_csrf.html` | full `RequestContext` |
| 429 | allauth's `_impl.handler429`, reached from `respond_429` | `429.html` | full `RequestContext` |
| 500 | `django.views.defaults.server_error` | `500.html` | **none — no request, no context processors** |
| 503 | nothing in FLS; a downstream proxy or maintenance middleware | `503.html` | whatever renders it |

So **do not** add `handler400`/`handler403`/`handler404`/`handler500`/`handler429` to
`config/urls.py`, and **do not** set `CSRF_FAILURE_VIEW`. Every one of those defaults already
resolves through this project's only configured template backend, which is the cotton-aware,
`{% extends %}`-capable engine (`config/settings_base.py:169-200`). Shipping the templates is the
whole wiring job. Adding handlers would put custom code on the one path that has no safety net
underneath it.

These seven filenames are the one place in this repo where a page template is not namespaced under
its app. Django and allauth call `loader.get_template()` with the bare literal name, so the
app-directories loader can only find them at the root of `freedom_ls/base/templates/`.

The one existing precedent is `freedom_ls/accounts/templates/accounts/lockout.html`, served by
django-axes at status 429. It gets restyled onto the same shared component.

## The pages

Copy follows GOV.UK's rules: plain language, no blame, no jokes, no exclamation marks, no HTTP
jargon in the heading, one primary action. The status code is a small secondary label above the
heading. Retry is offered only on 429, 500 and 503, where retrying can actually work.

| Template | Shell | `status` | `level` | `icon` | `<h1>` and `<title>` | Actions |
| --- | --- | --- | --- | --- | --- | --- |
| `404.html` | `_base.html` | `404` | `neutral` | `unknown` | We cannot find that page | Go to your dashboard (primary); Browse courses (secondary) |
| `403.html` | `_base.html` | `403` | `warning` | `locked` | You do not have access to this page | Browse courses (primary); Sign in as a different account (secondary) |
| `400.html` | `_base.html` | `400` | `warning` | `warning` | We could not handle that request | Go to your dashboard (primary) |
| `403_csrf.html` | `_base.html` | `403` | `warning` | `deadline` | The form was not sent | Sign in again (primary) |
| `429.html` | `_base.html` | `429` | `warning` | `rate_limit` | You have made too many attempts | Try again (primary) |
| `500.html` | standalone | `500` | `error` | `warning` | Sorry, there is a problem with this page | Try again (primary); Go to your dashboard (secondary) |
| `503.html` | standalone | `503` | `info` | `maintenance` | Sorry, the service is unavailable | Try again (primary) |
| `accounts/lockout.html` | `_base.html` | `429` | `warning` | `rate_limit` | Too many sign-in attempts | Back to sign in (primary); reset-password link |

Body copy per page:

- **404** — "The web address may be wrong, or the page may have moved or been taken down. Check the
  address for mistakes."
- **403** — "Your account does not have permission to open it. If you think that is wrong, ask an
  administrator to check your account." Say "an administrator", never a named route: FLS cannot
  resolve which administrator owns a given learner's access, and the page must not confirm what the
  visitor was reaching for.
- **400** — "Part of the request was malformed, so it was stopped before it reached the page. Check
  the web address for mistakes."
- **403 CSRF** — "Your session expired while the form was open, so nothing was sent and nothing was
  saved. Sign in again, then fill the form in once more." Never render Django's `reason`, and never
  echo the failure detail; the default view does not pass it into the template anyway
  (`django/views/csrf.py:69-70` renders with `request` only, no context dict).
- **429** — "Access is paused for a short while. Wait a few minutes, then try again." No countdown,
  no requests-per-minute figure. FLS cannot read a remaining cooldown out of allauth's cache keys or
  axes' rows, and a number that does not match when access returns is worse than none.
- **500** — two paragraphs. "The problem is on our side. It is not your account, your device or your
  connection." then "Anything you were part-way through may not have been saved." The second
  paragraph is the only claim about saved work the page can honestly make, and GOV.UK's pattern
  requires the page make one.
- **503** — "Maintenance is in progress. You will be able to use the service again later." No window,
  no expected-back time, no status-page link.
- **lockout** — keeps its current meaning and both its links. Reword the body to match the 429's
  register: "Sign-in for this account is paused after too many failed attempts. Wait a few minutes,
  then try again."

Nothing on any page carries a support contact, a reference code, a status link or a "report a broken
link" affordance. FLS has no `SUPPORT_EMAIL` setting, surfaces no Sentry event id, and this work adds
neither.

**Two labels deliberately differ from the idea's table.** `learner_interface:courses` renders
`all_courses.html`, which titles itself "All Courses" and is the public catalogue every visitor sees
— not a registration-filtered view, which FLS does not have. So the link reads "Browse courses", not
"My courses". And 403's "sign in as another account" cannot be a bare link to `account_login`:
allauth's `LoginView` carries `RedirectAuthenticatedUserMixin` and `AUTHENTICATED_LOGIN_REDIRECTS`
defaults to `True` (never overridden here), so an authenticated visitor — which is who a 403 is
mostly for — would be bounced straight back to their own dashboard without ever seeing a form. Point
it at `{% url 'account_logout' %}?next={% url 'account_login' %}` instead. `LogoutView` carries
`NextRedirectMixin`, and `ACCOUNT_LOGOUT_ON_GET` is off, so an authenticated visitor gets the
sign-out confirmation and then the login form, and a signed-out visitor is redirected straight to the
login form. `idea.md`'s table has been corrected to match.

## Shared decisions that apply to every task

**The 500 and 503 extend nothing.** `django.views.defaults.server_error` calls `template.render()`
with no arguments at all, so no `RequestContext` is built and not one context processor runs — no
`site_config`, no `user`, no `messages`, no working `csrf_token`. Rendering `_base.html` under those
conditions does not raise, but it produces a header with a blank site title, no logo, and an
`hx-headers` attribute carrying an empty CSRF token. So `500.html` and `503.html` are complete
`<!DOCTYPE html>` documents that link the compiled stylesheet and nothing else. The 503 is built the
same way because whatever serves it may be running with the app down.

**`{% static %}` is safe on those two pages.** It resolves through `staticfiles_storage` and never
touches `request` or any context processor, so it works identically with a bare `Context`.

**URL reversal on the standalone pages uses the `as` form.** `{% url 'x' %}` raises `NoReverseMatch`
if the app is not mounted, and an exception raised inside `500.html` has nothing left to catch it —
Django's exception handler calls `handler500` exactly once. Use
`{% url 'learner_interface:dashboard' as dashboard_url %}` and guard the link with
`{% if dashboard_url %}`. This is the idiom `freedom_ls/base/templates/partials/login_prompt.html`
already uses. Apply it on all seven pages so the templates read the same way. `lockout.html` keeps
its existing direct `{% url %}` calls to allauth's own always-present URLs.

**"Try again" is a plain anchor with an empty `href`.** An empty `href` resolves against the document
URL, so it reloads the current page with no JavaScript and no request object — which is what the 500
needs. `<c-button>` cannot express it: `cotton/button.html` renders a `<button>` rather than an `<a>`
when `href` is falsy, and an empty string is falsy. So write
`<a href="" class="btn btn-primary">Try again</a>` on 429, 500 and 503. `.btn` carries
`no-underline` in `@layer components` (`tailwind.components.css:163-168`), which wins over the
base-layer `a` rule, so it renders as a button, not an underlined link. Bare `<a class="btn …">` is
already an established pattern here — see `cotton/pagination.html` and `cotton/data-table.html`.

**Icons are hidden from assistive technology by wrapping.** `<c-icon>` always emits `role="img"` with
a non-empty `aria-label` (`freedom_ls/icons/backend.py:56-60` builds the SVG,
and `DefaultIconBackend.render` at `:101` falls the label back to the semantic name), so there is no
decorative mode on the component. The codebase's existing answer is an `aria-hidden="true"` wrapper,
which removes the whole subtree from the accessibility tree; a dozen templates already do this, e.g.
`freedom_ls/learner_interface/templates/learner_interface/partials/course_status_eyebrow.html:21`.
Use that. Buttons carry no icons at all — their labels already say what they do.

**Colour is never the only signal.** The status label and the heading carry the severity in text. The
status mark's colour is decoration on top.

**Status marks use the `*-light` pairing only.** A `*-light` background with its own `on-*-light`
foreground. Never `text-warning`: under the `default` theme `--color-warning` is `#F6E05E`, a pale
yellow chosen to be a background, and it is illegible on a light tint. Record that reason in the
component's comment block — it is the kind of thing that gets "tidied" back into `text-warning` by
someone who has only seen the `first_class` theme, where the same token is a saturated amber.

**Every page carries `noindex` and its own `<title>`.** Shell pages set the meta tag through
`{% block extra_head %}` and the title through `{% block head_title %}`; the standalone pages write
both literally. All eight titles are distinct.

**Headings.** The error content owns the page's `<h1>`. Shell pages will carry two `<h1>` elements —
the site title from `partials/header_bar.html:12` and the error heading — exactly as every other FLS
page does today, `accounts/lockout.html` included. That is intentional and unchanged; do not suppress
the header's heading. The standalone 500 and 503 have one `<h1>` each because they have no header.

**Source order is the reading order.** These pages have to make sense with no stylesheet, which on a
page that exists because something broke is a live possibility. Status label, heading, body, actions,
in that order in the markup, with no content revealed by CSS or JavaScript.

## Task 1 — add the `rate_limit` and `maintenance` semantic icon names

Two of the marks these pages need have no FLS semantic name. Everything else they need
(`unknown`, `locked`, `warning`, `deadline`) already exists.

**Files:** `freedom_ls/icons/semantic_names.py`, `freedom_ls/icons/mappings.py`.

**Red first.** Adding a name to `SEMANTIC_ICON_NAMES` without adding it to all four mapping dicts
turns `freedom_ls/icons/tests/test_mappings.py::TestMappingKeysMatchSemanticNames` red for all four
sets. Make that the failing step, then fill in the mappings.

**The mappings.** These glyph names were checked against the Iconify JSON in `node_modules/`, base
name plus every variant suffix each set declares in `mappings.py` (`-solid`/`-20-solid`/`-16-solid`
for heroicons, none for lucide, `-filled` for tabler, `-fill`/`-bold`/`-light`/`-thin` for phosphor).
All eight entries below resolve for every declared variant:

| Semantic name | heroicons | lucide | tabler | phosphor |
| --- | --- | --- | --- | --- |
| `rate_limit` | `hand-raised` | `gauge` | `gauge` | `gauge` |
| `maintenance` | `wrench` | `wrench` | `barrier-block` | `wrench` |

heroicons has no gauge glyph and tabler has no `wrench`, hence the two substitutions. tabler's `tool`
and `tools` were rejected: neither ships a `-filled` variant, so both would trip `icons.E004`.

Both names go in the existing `# Status` group in `SEMANTIC_ICON_NAMES`, alongside `locked`,
`warning` and `info` — every group comment in that file names a category of icon concept, never the
feature that consumes it. Add them in the same relative position in each of `HEROICONS_MAPPING`,
`LUCIDE_MAPPING`, `TABLER_MAPPING` and `PHOSPHOR_MAPPING`, so the four dicts stay readable side by
side.

**Done when:** `uv run pytest freedom_ls/icons` is green (its existing tests already assert that every
mapping value exists in every set's Iconify JSON) and `uv run python manage.py check` reports no
`icons.E003`/`icons.E004`.

## Task 2 — build the shared `<c-error-page>` component

Every one of the eight pages renders the same panel: a status mark, a small status label, an `<h1>`,
then body copy and actions. That lives in one component; the pages supply only what differs.

**File:** `freedom_ls/base/templates/cotton/error-page.html`.

**Red first.** Render the component in memory with `CottonCompiler`, the way
`freedom_ls/base/tests/test_button_component.py` already tests `<c-button>` — no host template on
disk, no fixture file, and no dependency on Task 3 having landed:

```python
from django_cotton.compiler_regex import CottonCompiler
from django.template import Context, Template

processed = CottonCompiler().process('<c-error-page status="404" heading="…">…</c-error-page>')
Template(processed).render(Context())
```

Assert the status label text, the heading, exactly one `<h1>` in the fragment, that the mark is
wrapped in `aria-hidden="true"`, and that slot content comes through. Do **not** assert on class
names — `ds:testing` forbids asserting styling, and the `text-on-warning-light` choice is guarded by
the comment block instead.

**Shape.** Follow `freedom_ls/base/templates/cotton/callout.html`, which solves the same
variant-to-classes problem with `{% partialdef %}` plus `{% with %}`. Name the variant attribute
`level` and give it the same values `callout.html` uses, plus `neutral`:

```
<c-vars status="" heading="" icon="warning" level="neutral" class="" />

{% partialdef error-panel %}
<div class="mx-auto max-w-2xl px-4 py-12 space-y-6 {{ class }}" {{ attrs }}>
    <span aria-hidden="true"
          class="inline-flex size-16 items-center justify-center rounded-full {{ mark }}">
        <c-icon :name="icon" class="size-8" />
    </span>
    <div class="space-y-2">
        <p class="text-sm font-medium text-muted">Error {{ status }}</p>
        <h1>{{ heading }}</h1>
    </div>
    <div class="space-y-6">{{ slot }}</div>
</div>
{% endpartialdef %}

{% if level == "error" %}
    {% with mark="bg-error-light text-on-error-light" %}{% partial error-panel %}{% endwith %}
{% elif level == "warning" %}
    {% with mark="bg-warning-light text-on-warning-light" %}{% partial error-panel %}{% endwith %}
{% elif level == "info" %}
    {% with mark="bg-info-light text-on-info-light" %}{% partial error-panel %}{% endwith %}
{% else %}
    {% with mark="bg-surface-2 text-muted" %}{% partial error-panel %}{% endwith %}
{% endif %}
```

Notes for the implementer:

- The `{% if %}` chain is not stylistic. Tailwind v4's scanner only sees literal class strings in the
  source, so `bg-{{ level }}-light` would never make it into the built stylesheet.
- Partial names are kebab-case per the template skill. `callout.html`'s `callout_box` predates that
  rule; do not copy it.
- `{{ heading }}` covers both call styles. `heading="…"` as an attribute works for the plain-English
  pages; `<c-slot name="heading">{% trans "…" %}</c-slot>` works for `lockout.html`, which is one of
  the four templates in this repo that use i18n and should keep doing so. `cotton/media-card.html`'s
  `footer` var is the existing precedent for one name serving both.
- `size-16` is the documented hero tier for an error result page; the glyph inside sits at `size-8`,
  matching the existing treatment in `accounts/lockout.html`.
- The `<h1>` needs no classes. The base layer already gives `h1` its type scale, `font-display` and
  `text-on-surface` (`tailwind.components.css:23-25`).
- Close the file with a `{% comment %}…{% endcomment %}` usage block, per the repo's template
  convention — never `{# … #}`. Record two things there: the empty-`href` retry idiom, and why the
  mark pairs `*-light` with `on-*-light` and never `text-warning`.

**Done when:** the component renders for all four levels and the new test is green.

## Task 3 — the five shell templates

**Files:** `freedom_ls/base/templates/404.html`, `403.html`, `400.html`, `403_csrf.html`,
`429.html`. Root of the `base` app's template dir, so the app-directories loader resolves them at the
bare names Django and allauth look for.

**Red first, per page.** Drive these from the real machinery rather than from `render_to_string`
where you can:

- **404** — `client.get("/no-such-page/")` returns 404, renders `404.html`, shows the heading, and
  does **not** contain the requested path anywhere in the body. Django hands `request_path` to this
  template; we never render it, and a test should pin that.
- **403 and 400** — add `freedom_ls/base/tests/error_pages_urls.py`, a small urlconf module holding
  two views that raise `PermissionDenied` and `BadRequest`, splatted in front of
  `config.urls.urlpatterns` so `{% url %}` still reverses inside the templates under test. Drive it
  with `@override_settings(ROOT_URLCONF="freedom_ls.base.tests.error_pages_urls")`. This matches the
  codebase's existing idiom — `freedom_ls/health/tests/root_urls.py`,
  `freedom_ls/panel_framework/tests/root_urls.py`, `freedom_ls/learner_interface/tests/no_sitemap_urls.py`
  — rather than the `ROOT_URLCONF=__name__` trick, which works but has no precedent here.
- **403 CSRF** — `Client(enforce_csrf_checks=True).post(reverse("account_login"), {…})` returns 403
  and renders `403_csrf.html`. Assert Django's built-in fallback wording ("CSRF verification failed")
  is absent.
- **429, signed out** — `@override_settings(ACCOUNT_RATE_LIMITS={"signup": "1/m/ip"})` (dev settings
  set `ACCOUNT_RATE_LIMITS = False`, which zeroes every scope), POST the signup URL twice, assert
  429, `429.html` rendered, and that allauth's bare fallback string "429 Too Many Requests" is
  absent. Clear the cache in the test so the counter does not leak between tests. This test matters
  more than it looks: allauth wraps its render in `except TemplateDoesNotExist` and silently falls
  back to the bare string, so a template that fails to load would look like nothing changed.
- **429, signed in** — the same again through a `login_required` scope, because the idea's QA section
  calls for it explicitly and because the signed-in account pages use
  `allauth/layouts/manage.html` rather than the entrance layout. Log a user in, override
  `ACCOUNT_RATE_LIMITS={"change_password": "1/m/user"}`, POST `account_change_password` twice, and  # pragma: allowlist secret
  make the same three assertions.
- **403's route forward actually works** — as an authenticated client, follow the secondary action's
  href and assert it does not land back on the dashboard. As an anonymous client, follow it and
  assert the login form renders. This is the regression that a bare `{% url 'account_login' %}` would
  have shipped silently.

**Shape.** Each is the same five lines around a `<c-error-page>` call. `404.html` in full; the other
four differ only in the table values above and their body copy:

```
{% extends "_base.html" %}

{% block head_title %}We cannot find that page{% endblock head_title %}

{% block extra_head %}<meta name="robots" content="noindex" />{% endblock extra_head %}

{% block content %}
    {% url 'learner_interface:dashboard' as dashboard_url %}
    {% url 'learner_interface:courses' as courses_url %}
    <c-error-page status="404" level="neutral" icon="unknown"
                  heading="We cannot find that page">
        <p>The web address may be wrong, or the page may have moved or been taken down.
           Check the address for mistakes.</p>
        <div class="flex flex-wrap gap-3">
            {% if dashboard_url %}
                <c-button href="{{ dashboard_url }}" variant="primary">Go to your dashboard</c-button>
            {% endif %}
            {% if courses_url %}
                <c-button href="{{ courses_url }}" variant="secondary">Browse courses</c-button>
            {% endif %}
        </div>
    </c-error-page>
{% endblock content %}
```

`403.html`'s secondary action is the one that needs care:

```
{% url 'account_logout' as logout_url %}
{% url 'account_login' as login_url %}
...
{% if logout_url and login_url %}
    <c-button href="{{ logout_url }}?next={{ login_url }}" variant="secondary">
        Sign in as a different account
    </c-button>
{% endif %}
```

The URL names each page needs: `learner_interface:dashboard`, `learner_interface:courses`,
`account_login`, `account_logout`. `429.html` has no `{% url %}` at all — its only action is the
empty-`href` retry anchor.

**Done when:** all seven tests are green and no page is a dead end.

## Task 4 — the two standalone templates

**Files:** `freedom_ls/base/templates/500.html`, `503.html`.

**Red first.** The contract test is the one that matters here, and it must call the template exactly
the way Django does — `get_template("500.html").render()`, no arguments:

- renders without raising, with a bare `Context`;
- contains the heading and the compiled-stylesheet link;
- does **not** contain the header bar's markup, an empty `hx-headers` CSRF attribute, or an empty
  site title — i.e. it did not go anywhere near `_base.html`;
- carries `noindex`;
- needs neither `django_db` nor `mock_site_context`, unlike every shell-page test. That asymmetry is
  the whole point of these two templates, so pin it.

Repeat for `503.html`. Then add an end-to-end 500 test: a view in `error_pages_urls.py` that raises,
driven by `Client(raise_request_exception=False)` so the client returns the error response instead of
re-raising, asserting status 500 and that `500.html` rendered.

**Shape.**

```
{% load static %}
<!DOCTYPE html>
<html lang="en">
    <head>
        <meta charset="UTF-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover" />
        <meta name="robots" content="noindex" />
        <title>Sorry, there is a problem with this page</title>
        <link rel="stylesheet" type="text/css" href="{% static 'vendor/tailwind.output.css' %}" />
    </head>
    <body>
        <main>
            {% url 'learner_interface:dashboard' as dashboard_url %}
            <c-error-page status="500" level="error" icon="warning"
                          heading="Sorry, there is a problem with this page">
                <p>The problem is on our side. It is not your account, your device or your connection.</p>
                <p>Anything you were part-way through may not have been saved.</p>
                <div class="flex flex-wrap gap-3">
                    <a href="" class="btn btn-primary">Try again</a>
                    {% if dashboard_url %}
                        <c-button href="{{ dashboard_url }}" variant="secondary">Go to your dashboard</c-button>
                    {% endif %}
                </div>
            </c-error-page>
        </main>
    </body>
</html>
```

`503.html` is the same skeleton with `status="503"`, `level="info"`, `icon="maintenance"`, the
heading "Sorry, the service is unavailable", the one-line body, and the retry anchor as its only
action. It gets **no** dashboard link and no navigation: a maintenance page must not carry anything
that implies the service is up.

**Done when:** both render from a bare `Context` and the end-to-end 500 test is green.

## Test file

New tests live in `freedom_ls/base/tests/test_error_pages.py`, with the urlconf they need in
`freedom_ls/base/tests/error_pages_urls.py`, and the one lockout assertion added to the existing
`freedom_ls/accounts/tests/test_lockout_page.py`.

Leave them unmarked. They are portable contract tests — status codes, template names, rendered text —
and every unmarked test is real integration signal for a downstream project. Reach for
`fls_internal` only if an assertion turns out to depend on FLS's own branding, and de-brand it first.

Any test that renders a page through `_base.html` runs the `site_config` context processor, so it
needs `pytest.mark.django_db` and the `mock_site_context` fixture. The two standalone templates need
neither.

Behaviours worth pinning, beyond the per-task red steps above:

- every page offers at least one working route forward — parametrize over the eight;
- every page carries `noindex`;
- every page has a `<title>`, and all eight titles are distinct from one another. Several pages use
  the same wording for `<title>` and `<h1>`, so a body-text assertion alone would not notice a
  deleted or duplicated title block;
- no page renders the requested path, an exception message, a stack trace, a framework version, or a
  reference code;
- no page shows a countdown, a remaining time, or a rate figure.

## Explicitly out of scope

- **HTMX error handling.** htmx does not swap non-2xx responses and FLS has no global
  `htmx:responseError` listener, so an htmx request that 404s or 500s outside the course player still
  changes nothing on screen. `interface-swap-fallback.js` already forces a full reload onto the real
  error page for `#interface-main`. Everywhere else, the visitor never reaches any page this work
  builds. That gap is real and should become its own spec. Do not close it here.
- **Maintenance mode.** FLS ships `503.html` and never serves it. No middleware, no switch, no
  schedule, no deadline shifting.
- **A support or status surface.** No contact link, no reference code, no Sentry event id, no
  status-page link, no `SUPPORT_EMAIL` setting.
- **401, 410, 402, offline, 504.** The designs draw them; FLS cannot honestly build them. 504 is left
  to whatever proxy generates it.
- **In-context failures and toast variants.** FLS's toast system already has the same four
  severities and nothing there needs changing.
- **`partials/header_bar.html`.** Its site-title `<h1>` stays as it is.
- **A registration-filtered "my courses" view.** It does not exist, and this work does not add one.
