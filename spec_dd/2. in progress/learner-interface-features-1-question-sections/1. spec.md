# Spec: Question sections

## Purpose

A quiz question cannot say which part of a course it tests. `learner-interface-features-2-test-out`
scores a pretest per section and `learner-interface-features-3-revision-questions` points a wrong
answer back to its section; both need that link. This spec adds it: the author names, in the form
file, the sections a question tests, and the loader stores them as real database links that are
rewritten on every `content_save`. Nothing reads the link yet. Why it is built first, and on its
own, is in `idea.md`.

Inputs: `idea.md`, `answers.md`, and the `research_*.md` files in this directory, chiefly
`research_codebase.md`.

## Terminology

| Term | Status | Meaning |
| --- | --- | --- |
| section | coined | A `CoursePart` or a `Topic` that a `FormQuestion` tests. The content row, never its placement (`ContentCollectionItem`). No existing term: `CoursePart`'s docstring says "chapter or section", but a section here may also be a `Topic`. |

## Scope

In:
- A `sections:` key on a form (`form.md`) as a default for its questions, and on a question as its
  own list.
- Storing each question's effective sections as foreign-key links to `Topic` and `CoursePart`.
- Load-time and validator checks on every section path.
- Forms placed in no course (bank forms) carrying sections.
- `fls-content` validator copy, `form-files.md` and demo content.

Out:
- Anything that reads the link: per-section scoring, test-out, the revision bank, pointing a wrong
  answer back. Owned by the later specs named in `idea.md`.
- Showing a section to the learner or educator anywhere.
- Explanations on questions or options; question pools, draw and shuffling; flashcards.
- Pruning questions dropped from a file. Today's behaviour (the row stays) is kept.
- A per-page (`FormPage`) default.

## Decisions

1. **A section is a `CoursePart` or a `Topic`.** Flat courses have no parts, so topics have to
   count. `Course`, `Activity`, `Form` and `Article` targets are errors.
2. **A question may name several sections.** Order carries no meaning.
3. **Authored by path, stored as a foreign key.** The path is resolved with `resolve_author_path`
   against the declaring file, as `children:` and `application_form` are. The path string is not
   stored. A part is named by its `part.yaml`, a topic by its markdown file.
4. **Storage is two plain many-to-many fields on `FormQuestion`**, one to `Topic` and one to
   `CoursePart`. Both have real foreign keys, they follow the `Course.categories` precedent, and
   the loader rewrites them with `.set()`. A generic-FK link table, like `ContentCollectionItem`,
   was rejected because it has no database integrity.
5. **Deleting a `Topic` or `CoursePart` row removes its links (auto-through CASCADE).** Only the
   admin or a shell deletes content rows. If the file is still there, the next load re-creates the
   row under its `uuid` and re-links it. If the file is gone, the forms that name it fail to load
   (decision 8).
6. **Form default, question override, replace semantics.** A question with no `sections:` key
   inherits the form's `sections:`. A question with the key uses its own list and ignores the form's.
   `sections: []` on a question means it tests no section, which is different from leaving the key
   out. The effective list is written onto each question at load. `Form` stores no default.
7. **Every load rewrites the links.** Each question's links become exactly its effective list.
   Removing a path, or the key, removes the link. A hand edit in the admin is overwritten, so the
   admin shows the links read-only.
8. **A path that doesn't resolve fails the whole load.** It is checked before anything is written,
   and every bad path in the run is reported at once. A renamed or moved target is never followed
   or re-linked: the author fixes the path. The validator applies the same rule.
9. **Unplaced forms need no loader change.** Forms are saved and pages attached by directory, never
   through placement (the demo application form already loads this way). A bank form has to sit in
   a sibling directory of the courses: in a course directory with no `children:` list it gets
   auto-discovered and placed, and under a `_` prefix it isn't loaded at all.
10. **Questions dropped from a file keep their links.** `content_save` never deletes a question,
    and `QuestionAnswer.question` is PROTECT. A stale question still carries the sections it had
    when it was last loaded. Whatever reads the link later has to deal with that.

## Requirements

### Schema (`freedom_ls/form_engine/schema.py`)

- `Form` gains `sections: list[Path] | None = None`.
- `FormQuestion` gains `sections: list[Path] | None = None`. Absent (`None`) and `[]` must stay
  distinct after parsing. The loader reads `model_fields_set`, as it already does for `tags`.
- Adding the key must not change `FormPage.derive_content_type`'s choice of `FORM_QUESTION`.
- The key is allowed on every form `strategy`.

### Models and migration (`freedom_ls/form_engine/models.py`)

- `FormQuestion.topics = ManyToManyField("freedom_ls_content_engine.Topic", blank=True,
  related_name="testing_questions")`.
- `FormQuestion.course_parts = ManyToManyField("freedom_ls_content_engine.CoursePart", blank=True,
  related_name="testing_questions")`.
- One new migration. The field names differ from the pydantic key `sections`, so `save_with_uuid`
  never hands a list of paths to a model field.

### Validation (`freedom_ls/content_engine/validate.py`)

- A new cross-file check, modelled on `validate_form_conditions` and using `_ParsedByPath`, so that
  a target outside the validated directory is read from disk. It is called from `validate()` and
  from the pre-write validation list in `save_content_to_db` (beside `validate_children_lists`).
- The form default resolves against the `form.md`. A question's list resolves against its page
  file. Both sit in the form's directory, so a path means the same thing at either level.
- Each path must resolve to an existing file of content type `COURSE_PART` or `TOPIC`. A path
  listed twice in one list is an error, as in `validate_children_lists`.
- Errors are collected across the run and raised once, in the `_reference_error` block layout:
  - the declaring file;
  - the field (`sections[<i>]`, plus the question label from `_target_label` for a question);
  - the problem: no file at the path, wrong content type (naming the type found), or duplicate;
  - the path as written and as resolved;
  - the fix.

### Loader (`freedom_ls/content_engine/management/commands/content_save.py`)

- `sections` goes into `exclude_fields` for `save_form` and `save_form_question`.
- After the form's questions are saved, each question's effective list (decision 6) is resolved
  through `content_by_path`, never by a slug or database lookup, so the link stays on the loading
  site. It is written with `question.topics.set(...)` and `question.course_parts.set(...)`. Both
  are always called, with empty lists when there's nothing to link, so stale links are cleared.
- A resolved object that is not a `Topic` or `CoursePart` raises `ValueError`, as the
  `application_form` binding does. The pre-write check should already have caught it.

### Admin (`freedom_ls/form_engine/admin.py`)

- `FormQuestionAdmin` shows `topics` and `course_parts` read-only. `FormQuestionInline` is unchanged.

### `fls-content` plugin

- Mirror the schema and validator changes into `claude_plugins/fls-content/validate/schema.py` and
  `validate.py`, keeping the patch headers, by the re-sync that
  `claude_plugins/fls-dev/commands/update_claude_plugin_fls_content.md` describes.
- `claude_plugins/fls-content/skills/content-types/resources/form-files.md`:
  - add `sections` to the FORM frontmatter table and the FORM_QUESTION fields table;
  - add a section, laid out like the `when` section, covering: what a section is, paths relative to
    the form's directory, default and override, `[]`, the load error, and where a bank form has to
    sit;
  - give an example. For path syntax, link to `course-files.md` rather than repeat it.

### Demo content

- `demo_content/functionality_demo_course_parts/02. Core Concepts/03. knowledge-check/`: a form
  default naming the enclosing part, and one question overriding it with a topic.
- `demo_content/functionality_demo_end_with_quiz/`: quiz questions naming the topics they test, so
  a flat course shows topic sections.

## Testing

Loader (`freedom_ls/content_engine/tests/test_content_save.py`, temp content directories):
- A question naming a part and a topic gets both links.
- A form default is inherited by a question without the key. A question's own list replaces the
  default, and `[]` gives no links.
- Reloading twice is stable. Reloading after removing one path, or the key, removes the link.
  Reloading after changing the form default changes every inheriting question.
- A question first loaded without a `uuid` gets its links, and they are unchanged on the second load.
- A path to a missing file, to a `Course`, `Form` or `Activity`, or listed twice fails the load,
  writes nothing, and names the file, the question and the path. Two bad paths in one run are both
  reported.
- A renamed target file fails the load. The old link is not re-pointed.
- An unplaced `QUIZ` form in a sibling directory loads, and its question links resolve.
- Deleting a linked `Topic` row removes the link. Reloading with the file still present re-links it.
- Links are stored on the loading site only.

Validator: the same error cases in `freedom_ls/content_engine/tests/test_validate.py` and, through
the bundled script, in `claude_plugins/fls-content/validate/tests/test_validator.py`, including a
target outside the validated directory.

Schema (`test_schema.py`): `sections` is accepted on `Form` and `FormQuestion`, and absent is
distinguished from `[]`.

Demo content: the demo tests load the two updated demo courses with their links.

- `form-files.md`, as above.
- Downstream projects get one migration and a new optional key. No existing content changes

## Open questions

- Q: Is `sections:` allowed on forms that aren't quizzes (`UNSCORED`, `CATEGORY_VALUE_SUM`)? → A:
  Yes, on every strategy (assumed default: a bank form may not be a `QUIZ`, and storing an unread
  link is harmless. Overrule by editing Requirements › Schema.)
- Q: Delete behaviour when a linked `Topic` or `CoursePart` row is deleted? → A: CASCADE removes
  the link (assumed default: a reload with the file present re-creates and re-links it, and
  PROTECT would block an admin deletion for the first time ever on these models. Overrule by
  editing Decisions 5.)

## Success criteria

- `uv run manage.py content_save` on the demo content stores the sections the demo files name, and
  a second run changes nothing.
- A form naming a missing or wrongly typed section fails `content_save` and
  `/fls-content:validate-content` with an error that names the file, the question and the path, and
  the database is unchanged.
- `FormQuestion.topics` / `course_parts`, and `Topic.testing_questions` /
  `CoursePart.testing_questions`, return the authored links.
- A question in an unplaced quiz form carries the sections it names.
- The bundled validator and the core validator give the same verdict on the new test fixtures.
