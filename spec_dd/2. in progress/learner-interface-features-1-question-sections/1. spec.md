# Spec: Question sections

## Purpose

A quiz question cannot say which part of a course it tests. `learner-interface-features-2-test-out`
scores a pretest per section and `learner-interface-features-3-revision-questions` points a wrong
answer back to its section; both need that link. This spec adds it: the author names, in the form
file, the sections a question tests, and every `content_save` rewrites them as database foreign
keys. Nothing reads the link yet. Why it is built first, and on its own, is in `idea.md`.

Inputs: `idea.md`, `answers.md`, and the `research_*.md` files in this directory, chiefly
`research_codebase.md`.

## Terminology

| Term | Status | Meaning |
| --- | --- | --- |
| section | coined | A `CoursePart` or a `Topic` that a `FormQuestion` tests. The content row, never its placement (`ContentCollectionItem`). No existing term: `CoursePart`'s docstring says "chapter or section", but a section here may also be a `Topic`. |

## Scope

In: the `sections:` authoring key, its storage, its checks in the loader and validator, the
`fls-content` copy and docs, and demo content.

Out:
- Anything that reads the link: per-section scoring, test-out, the revision bank, pointing a wrong
  answer back. Owned by the later specs named in `idea.md`.
- Showing a section to the learner or educator.
- Explanations on questions or options; question pools, draw and shuffling; flashcards.
- Pruning questions dropped from a file. `content_save` never deletes a question and
  `QuestionAnswer.question` is PROTECT, so a dropped question keeps the sections it had at its last
  load.
- A per-page (`FormPage`) default.

## Decisions

1. A section is a `CoursePart` or a `Topic`. Flat courses have no parts, so topics have to count.
2. A question may name several sections. Order carries no meaning.
3. The author writes a path. The database stores a foreign key, never the path string.
4. Storage is two many-to-many fields on `FormQuestion` with explicit through models, so that the
   target side can be PROTECT. A generic-FK table, like `ContentCollectionItem`, was rejected
   because it has no database integrity.
5. A `Topic` or `CoursePart` that any question names cannot be deleted. That includes questions
   dropped from their file. To delete it, change or remove the questions that name it first.
6. A question with no `sections:` key inherits the form's. A question with the key uses its own list
   in place of the form's, and `sections: []` means it tests no section. `Form` stores no default:
   each question stores its effective list.
7. Every load rewrites each question's sections to exactly its effective list. The admin shows them
   read-only, because a hand edit would be lost on the next load.
8. A path that does not resolve to a section loaded in the same run fails the whole load before
   anything is written, and every bad path is reported at once. A renamed or moved target is never
   followed: the author fixes the path. A section target must sit inside the directory passed to
   `content_save`.
9. `sections:` is allowed on every form `strategy`, so a bank form need not be a `QUIZ`.
10. A form placed in no course needs no loader change. Forms are saved, and pages attached, by
    directory, as the demo application form already is.

## Requirements

### Schema (`freedom_ls/form_engine/schema.py`)

- `Form` and `FormQuestion` each gain `sections: list[Path] | None = None`. The loader reads
  `model_fields_set`, as it does for `tags`, so absent and `[]` stay distinct.
- The new key must not change `FormPage.derive_content_type`'s choice of `FORM_QUESTION`.

### Models and migration (`freedom_ls/form_engine/models.py`)

- `FormQuestion.topics = ManyToManyField("freedom_ls_content_engine.Topic", through="FormQuestionTopic", blank=True, related_name="testing_questions")`.
- `FormQuestion.course_parts = ManyToManyField("freedom_ls_content_engine.CoursePart", through="FormQuestionCoursePart", blank=True, related_name="testing_questions")`.
- `FormQuestionTopic`: `question` FK to `FormQuestion` (CASCADE), `topic` FK to `Topic`
  (PROTECT), unique on the pair. `FormQuestionCoursePart` is the same shape with `course_part`.
  Like `Course.categories`' through table, neither carries `site`: both ends are site-aware rows of
  one site.
- One new migration. The field names differ from the pydantic key `sections`, so `save_with_uuid`
  never hands a list of paths to a model field.

### Validation (`freedom_ls/content_engine/validate.py`)

- A new cross-file check, modelled on `validate_form_conditions`, called from `validate()` and from
  the pre-write validation list in `save_content_to_db` beside `validate_children_lists`. In
  `validate()` it reads targets outside the validated directory through `_ParsedByPath`.
- Paths resolve with `resolve_author_path` against the declaring file: the `form.md` for the form
  default, the page file for a question. Both sit in the form's directory, so a path means the same
  at either level. A part is named by its `part.yaml`, a topic by its markdown file.
- Errors: no file at the path; a target whose content type is not `COURSE_PART` or `TOPIC` (naming
  the type found); a path listed twice in one list, as in `validate_children_lists`.
- Errors are collected across the run and raised once, in the `_reference_error` block layout:
  declaring file, field (`sections[<i>]`, with the `_target_label` question label for a question),
  problem, path as written and as resolved, fix.

### Loader (`freedom_ls/content_engine/management/commands/content_save.py`)

- `sections` goes into `exclude_fields` for `save_form` and `save_form_question`.
- Keep each form directory's parsed `Form` schema item next to `forms_by_dir`. In the page loop,
  right after `save_form_question`, compute the question's effective list and resolve each path
  through `content_by_path`, never by slug or database lookup, so the targets are this site's rows.
  Write with `question.topics.set(...)` and `question.course_parts.set(...)`. Call both every time,
  with empty lists when there is nothing to link, so stale rows go.
- A path missing from `content_by_path`, which means a target outside the loaded directory, or a
  resolved object that is not a `Topic` or `CoursePart`, raises `ValueError` with the same error
  block as the validator. Nothing has been written at that point, because the pre-write check runs
  first.

### Admin (`freedom_ls/form_engine/admin.py`)

- `FormQuestionAdmin` adds `topics` and `course_parts` to `readonly_fields` and to a new "Sections"
  fieldset. `FormQuestionInline` is unchanged.

### `fls-content` plugin

- Re-sync `claude_plugins/fls-content/validate/schema.py` and `validate.py` with
  `/fls-dev:update_claude_plugin_fls_content`.
- `claude_plugins/fls-content/skills/content-types/resources/form-files.md`:
  - add `sections` to the FORM frontmatter table and the FORM_QUESTION fields table;
  - add a section, laid out like the `when` section, covering the default and override, `[]`,

    auto-discovered and placed, and one under a `_` prefix is not loaded;
  - give an example. For path syntax, link to `course-files.md` rather than repeat it.

### Demo content

- `demo_content/functionality_demo_course_parts/02. Core Concepts/03. knowledge-check/`: a form

- `demo_content/functionality_demo_end_with_quiz/`: quiz questions naming the topics they test.

## Testing

Loader, validator, schema and bundled-validator tests use temp directories and stay portable. The
demo-content tests carry `pytest.mark.fls_internal`. The cases that guard behaviour easily got
wrong:

- Absent `sections:` inherits the form default; `[]` gives none; a question's own list replaces
  the default rather than merging.
- Reloading after removing a path, the key, or changing the form default rewrites the sections.
- A question first loaded without a `uuid` keeps the same sections on its second load.
- A bad path fails the load, writes nothing, and names the file, question and path. Two bad paths
  are both reported.
- A target outside the directory passed to `content_save` fails the load.
- An unplaced `QUIZ` form in a sibling directory loads with its sections.
- Deleting a named `Topic` or `CoursePart` raises `ProtectedError`.
- The sections are stored only on the loading site.
- The bundled validator reports the same errors as the core one, including for a target outside
  the validated directory.

## Documentation and downstream

Downstream projects get one migration and a new optional key. No existing content changes meaning.
The new PROTECT means a downstream that deletes topics or parts by hand can now be refused. The
upgrade note says both.

## Success criteria

- `uv run manage.py content_save` on the demo content stores the sections the demo files name, and
  a second run changes nothing.
- A form naming a missing or wrongly typed section fails `content_save` and
  `/fls-content:validate-content` with an error that names the file, question and path, and leaves
  the database unchanged.
- Deleting a `Topic` that a question names is refused in the admin.
