# Frontend QA: question sections

The branch lets a quiz question name, in its form files, the topics and course parts it tests.
`content_save` stores them as links; nothing learner-facing reads them yet. What a browser can
see:

- **Admin.** A `FormQuestion` change page gains a read-only "Sections" fieldset listing its topics
  and parts.
- **Side effects.** The demo quizzes now carry `sections:` keys. They must load, render and score
  exactly as before. A topic or part a question names can no longer be deleted, so the dev content
  reset (`danger_content_delete`) must still work.

**Viewports.** Admin pages and existing learner pages only: desktop (1920x1080) is enough, plus
one 375x812 check of a quiz page in §3.

Substitute the literal port number from `.claude/ds/scripts/find_available_port.sh` wherever this
document writes `$PORT`. Shell variables do not survive between tool calls.

---

## §0 Setup

### 0.1 Server

1. `uv run python manage.py migrate`.
2. `.claude/ds/scripts/find_available_port.sh`: note the number and use it literally from here on.
3. Start `uv run python manage.py runserver $PORT` backgrounded, as its own call.
4. Open `http://127.0.0.1:$PORT/` and confirm `#debug-branch-badge` names
   `learner-interface-features-1-question-sections`. If it names another branch, another server
   holds the port; go back to step 2.

### 0.2 Data

1. `uv run python manage.py danger_content_delete --yes`. **Expect:** it finishes with no
   `ProtectedError`, even when an earlier run already stored section links.
2. `uv run python manage.py content_save demo_content DemoDev`. **Expect:** no error.
3. Run the same `content_save` a second time. **Expect:** no error, and `git status` shows no
   change under `demo_content/` (no uuid write-back on the second run).

### 0.3 Login

Log in at `http://127.0.0.1:$PORT/accounts/login/` as `demodev@email.com` / `demodev@email.com`.
This account is staff and can open the admin.

## §1 The admin shows a question's sections

1. Open `http://127.0.0.1:$PORT/admin/freedom_ls_form_engine/formquestion/` and search for
   `What is a course part?`. Open it.
   **Expect:** a "Sections" fieldset after "Answer format". Topics shows "Key Ideas" (the title of
   `02. Core Concepts/01. key-ideas/content.md`); Course parts is empty. Both are plain text, not
   inputs.
2. Go back and open `Which file identifies a directory as a course part?`.
   **Expect:** Topics empty; Course parts shows the "Core Concepts" part. This question has no key
   of its own and inherits the form default.
3. Open `Some question blah blah` (the end-with-quiz mid course quiz).
   **Expect:** Topics shows "Content title 2 - Before Quiz".
4. Open any question from the demo application form or survey form.
   **Expect:** the "Sections" fieldset shows both fields empty, with no error.
5. On any question above, change "Order" by one and click Save, then reopen it.
   **Expect:** the save succeeds and the Sections values are unchanged (the read-only fieldset
   is not submitted and not cleared by a save).

## §2 A named topic or part cannot be deleted

1. Open `http://127.0.0.1:$PORT/admin/freedom_ls_content_engine/topic/` and open "Key Ideas".
   **Expect:** no Delete button on the change page, and no "Delete selected" action in the list
   view's action menu.
2. Same for `http://127.0.0.1:$PORT/admin/freedom_ls_content_engine/coursepart/` and "Core
   Concepts".

## §3 The demo quizzes still work

1. Open the learner course list at `http://127.0.0.1:$PORT/`, open the course "Functionality
   Demo - show end with Quiz", register if asked, and open "Mid course Quiz".
   **Expect:** the quiz renders its pages and questions as on `main`; no section, topic or path
   text appears anywhere on the learner page.
2. Answer every question with the option marked CORRECT and submit.
   **Expect:** the quiz scores and passes as before.
3. Open the course "Functionality Demo" with course parts, go to the "Core Concepts" part and take
   "Knowledge Check" at 375x812.
   **Expect:** the page renders with no overflow and no console error; submitting scores as before.

## §4 A broken section path is refused (terminal)

1. In a scratch copy, outside the repo: `cp -r demo_content/functionality_demo_end_with_quiz <scratch>/q`.
   In `<scratch>/q/3. quiz/1. page.yaml`, set the first question's `sections:` to
   `[../2. topic/missing.md, ../course.md]`.
2. `uv run python manage.py content_save <scratch>/q DemoDev`.
   **Expect:** the command fails. The output has an "Invalid section reference" block for each
   path: the page file, the question text, `sections[0]` / `sections[1]`, the path as written and
   as resolved, "no file at this path" for the first and "this file is a COURSE" for the second.
3. Reload `http://127.0.0.1:$PORT/admin/freedom_ls_form_engine/formquestion/`.
   **Expect:** no new or changed questions from the failed load (the admin list matches §1).
4. Delete the scratch copy.
