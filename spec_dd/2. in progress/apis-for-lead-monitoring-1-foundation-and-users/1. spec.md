# Spec: Lead monitoring API, foundation and users

Spec 1 of 6 in the Lead monitoring API effort (`spec_dd/1. next/roadmap.md`, "Lead monitoring
API"). Source: `idea.md` in this directory. Research beside it: `research_api_foundation.md`,
`research_codebase.md`, `research_best_practices.md`, `research_reference_implementations.md`,
`research_prior_art.md`, `research_ux_patterns.md`, `research_known_complaints.md`.

## Purpose

Lead monitoring scripts need to pull learner and lead data out of a site without a person
exporting CSVs from the admin. FLS has no machine authentication today. This spec adds a
read-only REST API under `/api/v1/` authenticated by a hashed, site-bound, scoped API key that a
site's admin issues in the Django admin, and ships the first resource, `/api/v1/users/`. It also
builds the conventions specs 2 to 6 reuse, and removes the dead `django-ninja` code.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| `ApiKey` | coined | A credential for one `Site`, holding read scopes. No existing machine credential in FLS (`WebhookSecret` is outbound signing). |
| API scope | coined | One of four fixed read permissions a key holds (`ApiScope`). Unrelated to role-based permissions. |
| API resource | coined | One read-only endpoint family under `/api/v1/` (a viewset registered with the API router). |

## Scope

In:

- Two new apps: `freedom_ls.api` (key model, authentication, scopes, shared read conventions,
  router, schema) and `freedom_ls.api_admin` (issuing and revoking keys in the Django admin, with
  audit entries).
- The `users` resource, in `accounts`.
- Bumping `User.updated_at` when the user's email verification changes.
- Removing `django-ninja` and the code that imports it.
- `docs/api.md` and the product-doc updates listed under "Documentation and downstream".

Out:

- Every other resource (specs 2 to 6). Write endpoints, webhooks, push, any UI, the browsable API,
  Swagger UI, OAuth, cross-site keys, keys tied to users or to role-based permissions.
- A deletion feed.
- Moving `User.updated_at` on login.
- A throttle on failed authentication attempts per IP. DRF throttles run after authentication, so
  bad-key floods are not rate-limited by this spec.
- Rejecting plain-http requests in code. The docs carry the HTTPS rule.
- Changing the admin exports. Deleting the `xapi_learning_record_store` stub.

## Decisions

| Decision | Reason |
| --- | --- |
| Each API resource lives in the app that owns its model, in `<app>/api.py`, and registers with the router in `freedom_ls.api`. Specs 2 to 6 follow this. | Chosen by the user: model knowledge stays in its app. |
| `freedom_ls.api` imports only `base` and `site_aware_models`. The key admin, which imports `audit_log`, lives in `freedom_ls.api_admin`. | `accounts` imports `api`; an `api → audit_log → accounts` edge would close a cycle. |
| `ApiKey` has no foreign key to the user model. The audit entry records who issued and who revoked it. | Keys are not tied to users (idea), and a user FK would add `api → accounts`. |
| Installing both apps and including `freedom_ls.api.urls` turns the API on. There is no enabled flag. | Matches the `blog` pattern in `config/urls.py`. |
| The router discovers resources with `django.utils.module_loading.autodiscover_modules("api")`, called from `freedom_ls/api/urls.py`. | `api` must not import resource apps; discovery is not a static import, so it adds no app-map edge. |
| The key is SHA-256 hashed, not run through a password hasher. | The secret has 256 bits of entropy; Argon2 on every request is CPU cost with no gain. |
| The site is the admin request's host site, set the way every `SiteAwareModel` sets it. The add form has no site field. | `SiteAwareModelAdmin` excludes `site`; the idea's "carries a site" holds without a picker. |
| The issued key is shown on a page rendered directly by the admin's add response, not through `messages`. | `MESSAGE_STORAGE` is unset, so a message would store the key in the messages cookie or the session. |
| Everything about a key except its `name` is fixed at issue. Revocation is one-way. | Changing a live key's scopes surprises a running script; rotate by issuing a new key and revoking the old one. |
| API views carry their DRF configuration on a base viewset class, not in a project `REST_FRAMEWORK` setting. | Concrete projects keep their own settings files; the API must work with no `REST_FRAMEWORK` entry. |
| Throttle: 600 requests per minute per key, as an app setting. A system check warns when the default cache is per-process. | Chosen by the user. Throttle counters only hold across processes in a shared cache. |
| `last_used_at` is written at most once every 5 minutes per key. | A script paging a table would otherwise write the key row on every request. |
| Users: list and detail routes. | Chosen by the user. Specs 2 to 6 follow the same shape. |
| `User.updated_at` moves when email verification changes, not on login. | Chosen by the user. Verification matters for leads; login churn would flood incremental syncs. |

### `freedom_ls.api`: the key model

`ApiKey(SiteAwareModel, TimestampedModel)` in `freedom_ls/api/models.py`:

| Field | Type | Notes |
| --- | --- | --- |
| `name` | `CharField(max_length=200)` | Required. What the key is for, e.g. "Nightly CRM sync". Not unique. |
| `key_prefix` | `CharField(max_length=16, unique=True)` | Non-secret public id, random. Shown in admin and audit. |
| `key_hash` | `CharField(max_length=64, unique=True)` | SHA-256 hex of the full key. Never displayed. |
| `scopes` | `ArrayField(CharField(choices=ApiScope.choices))` | At least one, no duplicates. |
| `expires_at` | `DateTimeField(null=True, blank=True)` | No expiry when null. |
| `revoked_at` | `DateTimeField(null=True, blank=True)` | Set once; never cleared. |
| `last_used_at` | `DateTimeField(null=True, blank=True)` | Approximate to 5 minutes. |

- Key text: `flsk_<key_prefix>.<secret>`, `secret = secrets.token_urlsafe(32)`. Site, scopes and
  expiry are never encoded in the key.
- `ApiKey.issue(*, name, scopes, expires_at, site) -> tuple[ApiKey, str]` creates the row and
  returns the full key once. Nothing else ever holds the full key.
- `is_active(now)`: `revoked_at is None and (expires_at is None or expires_at > now)`.
- `revoke(now)` sets `revoked_at` if unset; it does not clear or move an existing value.
- `__str__` returns the name and prefix, never the hash.
- Clean rejects an `expires_at` in the past and an empty scope list.
- Add `"freedom_ls_api.ApiKey"` to `TIMESTAMPED_MODELS`
  (`freedom_ls/contrib/conformance/tests/test_timestamped_models.py`).

### `freedom_ls.api`: authentication

`ApiKeyAuthentication(BaseAuthentication)` in `freedom_ls/api/authentication.py`:

- Reads only the `Authorization` header: exactly two parts, scheme `Bearer` (case-insensitive),
  token `flsk_<prefix>.<secret>`. A key in the query string or anywhere else is ignored.
- No header → returns `None` (DRF then answers 401 through `authenticate_header`).
- Resolves the site with `get_cached_site(request._request)`. `UnknownSite`, `Site.DoesNotExist`
  and `SiteResolutionError` all fail authentication.
- Looks the key up by `key_prefix` with an explicit `site` filter on the base manager (not the
  host-filtered default manager), and compares `sha256(token)` to `key_hash` with
  `hmac.compare_digest`. An unknown prefix still runs one hash and compare.
- Malformed header, unknown prefix, wrong secret, revoked, expired, key site ≠ host site,
  unresolvable site: every case raises the same `AuthenticationFailed`, with one message.
- `authenticate_header()` returns `'Bearer realm="api"'`, so failures are 401 with
  `WWW-Authenticate`, never 403.
- On success returns `(None, api_key)`; views read `request.auth`. It then runs
  `ApiKey.objects.filter(pk=..., last_used_at is null or < now - 5 min).update(last_used_at=now)`,
  which neither calls `save()` nor moves `updated_at`. Failed attempts never touch `last_used_at`.
- No code logs the header, echoes it in a response, or puts it in an exception message.

`freedom_ls/api/schema.py`: an `OpenApiAuthenticationExtension` for `ApiKeyAuthentication`
declaring an HTTP bearer scheme.

### `freedom_ls.api`: permission and throttle

- `HasApiScope` (`freedom_ls/api/permissions.py`): passes when `request.auth` is an `ApiKey` and
  `view.required_scope` is in its `scopes`. Otherwise 403 with a body that names the missing scope.
- `ApiKeyRateThrottle(SimpleRateThrottle)` (`freedom_ls/api/throttling.py`): rate from
  `API_THROTTLE_RATE`, cache key from the key's `pk` (never the key text or hash). 429 carries
  `Retry-After`.

### `freedom_ls.api`: shared read conventions

- `ApiCursorPagination` (`freedom_ls/api/pagination.py`): ordering `("updated_at", "id")`
  ascending, `page_size = API_PAGE_SIZE`, `page_size_query_param = "page_size"`,
  `max_page_size = API_MAX_PAGE_SIZE`. Envelope `{"next", "previous", "results"}`, no count. A run
  of more rows sharing one `updated_at` than `offset_cutoff` allows must still page without
  duplicates or skips; if DRF's cursor cannot do that, the class encodes the `(updated_at, id)` pair
  itself. A malformed cursor is a 400 with `{"cursor": [...]}`, not DRF's 404.
- `UpdatedSinceFilterSet(django_filters.FilterSet)` (`freedom_ls/api/filters.py`): `updated_since`
  → `updated_at__gte`. ISO 8601 with a timezone or `Z`; a naive or unparseable value is a 400 that
  names the parameter.
- `ReadOnlyApiViewSet(ReadOnlyModelViewSet)` (`freedom_ls/api/viewsets.py`), the base every API
  resource uses:
  - `authentication_classes = [ApiKeyAuthentication]`, `permission_classes = [HasApiScope]`,
    `throttle_classes = [ApiKeyRateThrottle]`, `renderer_classes = [JSONRenderer]`,
    `pagination_class = ApiCursorPagination`, `filter_backends = [DjangoFilterBackend]`,
    `http_method_names = ["get", "head", "options"]`, drf-spectacular's `AutoSchema`.
  - `required_scope: ApiScope` must be set; a subclass without one fails at class definition or
    at the system check, not at request time.
  - No ordering filter: the order is fixed.
  - `get_exception_handler()` returns a handler whose error bodies are
    `{"detail": str, "code": str}` (DRF's error code), and JSON for every error under `/api/`.
    Field validation errors (400) keep DRF's field-keyed dict.
  - OPTIONS returns 200 with an `Allow` header and no serializer field metadata.
  - Responses carry `Cache-Control: private, no-store`.
  - `site_queryset(self, queryset)` filters on `site=self.request.auth.site` explicitly; resource
    querysets go through it rather than relying on the host-filtered manager.
- `ApiRouter` (`freedom_ls/api/routers.py`): a `SimpleRouter` (no root view) with trailing slashes,
  whose route names are snake_case (`<basename>_list`, `<basename>_detail`). A module-level
  `router` instance is what `<app>/api.py` modules register with.
- `freedom_ls/api/urls.py`: `app_name = "api"`; `autodiscover_modules("api")`; `router.urls`;
  `schema/` → `SpectacularAPIView` (name `schema`) with `ApiKeyAuthentication`, a permission that
  needs any active key and no scope, the JSON OpenAPI renderer only, and title/version through
  `custom_settings`.

### `freedom_ls.api_admin`: issuing and revoking keys

- `apps.py`: `label = "freedom_ls_api_admin"`. A system check errors when `freedom_ls.api` is not
  installed (precedent: `registration_rules/apps.py`). No models.
- `ApiKeyAdmin(SiteAwareModelAdmin)` in `freedom_ls/api_admin/admin.py`, registered for `ApiKey`:
  - Add form: `name`, `scopes` (checkboxes over `ApiScope`, with each scope's description),
    `expires_at`. `save_model` on add calls `ApiKey.issue(...)` with the request host's site.
  - `response_add` renders a one-off admin-shell page (`admin_page_context`) with the full key in
    a monospace box, the warning that it will not be shown again, and `Cache-Control: no-store`.
    No redirect, no message.
  - Change form: `name` editable while the key is active. `key_prefix`, `scopes`, `expires_at`,
    `created_at`, `last_used_at`, `revoked_at` read-only. Revoked or expired keys are read-only
    throughout. `key_hash` is never shown.
  - Changelist: name, `key_prefix`, scopes, status label (Active / Expired / Revoked),
    `expires_at`, `last_used_at`, `created_at`. Filter by status.
  - Revoke: a "Revoke selected keys" action and a change-page button, both through one
    confirmation page that lists the keys and says scripts using them stop at once. Already
    revoked keys are skipped.
  - Delete is disabled (`has_delete_permission` false).
- Audit (`audit_log.writer.record_entry`, inside the save's transaction): new actions
  `api_key.issued` ("API key issued") and `api_key.revoked` ("API key revoked") in
  `FLS_AUDIT_ACTIONS` (`freedom_ls/audit_log/actions.py`). One entry per key: actor the admin
  user, target the key, `organisation=None`, `details` holding `name`, `key_prefix`, `scopes` and
  `expires_at`. The full key and hash never go into the audit log.

### `accounts`: the users resource

- `freedom_ls/accounts/resources.py`: extract the `email_verified` `Exists` annotation from

  call.
- `freedom_ls/accounts/api.py`:
  - `UserApiSerializer`: fields `USER_EXPORT_FIELDS + ("updated_at",)`, i.e. `id`, `email`,
    `first_name`, `last_name`, `is_active`, `is_staff`, `email_verified`, `created_at`,
    `last_login`, `updated_at`. ISO 8601 timestamps. `id` is the integer pk.
  - `UserFilterSet(UpdatedSinceFilterSet)`.
  - `UserApiViewSet(ReadOnlyApiViewSet)`: `required_scope = ApiScope.USERS`; queryset is
    `site_queryset(User.objects...)` with the `email_verified` annotation; detail lookup by `id`.
  - `router.register("users", UserApiViewSet, basename="user")`.
- New migration: index on `User` over `(site, updated_at, id)`.
- `email_verified` change moves `updated_at`: a receiver in `accounts` on allauth `EmailAddress`
  `post_save` and `post_delete` sets the owning user's `updated_at` with a queryset `update()`.

## Testing

Wrong-host and unresolvable-site tests use real `Site` rows, `ALLOWED_HOSTS` and `HTTP_HOST`, not
`mock_site_context`, which hides the host. Throttle tests clear the cache before and after
(precedent: `referral_tracking/tests/conftest.py`). Tests mirror source modules.

- Key model: issued key's hash matches and the full key appears nowhere on the row; prefix unique;
  `is_active` at the expiry instant; `revoke` is one-way; clean rejects past expiry and no scopes.
- Authentication, each a 401 with `WWW-Authenticate: Bearer realm="api"` and an identical body:
  no header, wrong scheme, malformed token, unknown prefix, wrong secret, revoked, expired, key of
  site A on host B, allowed host with no `Site` row. Also: a key in the query string alone is 401;
  a signed-in session alone is 401; header scheme is case-insensitive.
- `last_used_at`: set on success, not on failure, not rewritten within 5 minutes
  (`time_machine`), and `updated_at` unchanged by it.
- Scope: a valid key without `users` gets 403 naming the scope.
- Throttle: the request past the rate is 429 with `Retry-After`; two keys from one client have
  separate buckets. System check W001 fires for `LocMemCache` with `DEBUG` false and not for
  `DatabaseCache`.
- Every route under `/api/` (iterate the resolver) rejects a request with no key, and every
  registered viewset declares a `required_scope`.
- Pagination: follow `next` over more rows than one page and get each row once; a run of identical
  `updated_at` larger than DRF's `offset_cutoff` pages with no duplicates or skips; `page_size`
  above the cap is clamped; `next` keeps `updated_since`; a malformed cursor is 400.
- `updated_since`: inclusive at the boundary; naive and invalid values are 400.
- Users: fields equal `USER_EXPORT_FIELDS + ("updated_at",)` exactly; no `password`,
  `is_superuser`, `groups` or `user_permissions`; another site's users absent from list and 404 on
  detail; `email_verified` matches the export; query count fixed regardless of page size; HEAD
  returns GET's status and headers with no body; OPTIONS returns no field metadata.
- `updated_at`: verifying, unverifying or deleting a user's `EmailAddress` moves it.
- Admin: issuing shows the key once, sets no message and redirects nowhere; the add form has no
  site field and binds the key to the host's site; one `api_key.issued` entry
  (`freedom_ls/tests/audit_assertions.py` `assert_entry`) without the key; revoke action and button
  each write one `api_key.revoked` entry per key and skip revoked keys; revoked keys are read-only;
  delete is unavailable.
- Schema: `/api/v1/schema/` is 401 without a key and 200 with any active key; it declares the
  bearer scheme, `updated_since`, `cursor` and `page_size`; `manage.py spectacular --validate
  --fail-on-warn` passes.
- Logging: a Sentry event built from an API request carries no `Authorization` value. If the
  current `sentry_sdk.init` config does not strip it, `deployment/sentry.py` gains a scrub.
- `api_admin` system check errors without `freedom_ls.api` installed.
- `docs/api.md`: the Python example compiles (a test extracts the code block).
- Ninja removal: content loading still validates with pydantic (existing tests pass).

## Success criteria

- A script with a key holding `users` reads every user of the key's site by following `next` from
  `/api/v1/users/`, and a second run with `updated_since` returns only rows changed since.
- The same key on another site's host, revoked, expired, or with a wrong secret gets an identical
  401; a key without `users` gets 403.
- `django-ninja` is absent from `pyproject.toml` and `uv.lock`, and `grep -r ninja freedom_ls config`
  finds nothing.
- `freedom_ls.api` imports no app other than `base` and `site_aware_models` (app map).
- Issuing a key in the admin shows it once, stores only its hash, and writes one audit entry;
  revoking writes one more and the key stops working on the next request.
- The full test suite, `manage.py spectacular --validate --fail-on-warn`, `makemigrations --check`
  and pre-commit pass.
