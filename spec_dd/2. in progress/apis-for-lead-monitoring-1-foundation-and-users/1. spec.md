# Spec: Lead monitoring API, foundation and users

Spec 1 of 6 in the Lead monitoring API effort (`spec_dd/1. next/roadmap.md`, "Lead monitoring
API"). Source: `idea.md`. The research files sit beside this spec.

## Purpose

Scripts need to read a site's user data without a person exporting CSVs from the admin. This spec
adds a read-only API under `/api/v1/`, authenticated by a hashed, site-bound API key that a site's
admin issues in the Django admin, and ships `/api/v1/users/` as the first API endpoint. Specs 2 to
6 build on its conventions.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| lead | coined | The effort's name for a person who has applied or signed up but is not yet registered for a course. Not a model. |
| `ApiKey` | coined | A credential for one `Site`, holding API scopes. FLS has no machine credential today (`WebhookSecret` signs outbound requests). |
| API scope | coined | One of four fixed read permissions an `ApiKey` holds (`ApiScope`). Always written "API scope" in prose: role grants already use "scoped". |
| API endpoint | coined | One read-only route family under `/api/v1/`: a viewset registered with the API router. "Resource" is taken by the import-export `Resource` classes. |
| revoked | coined | An `ApiKey` ended for good (`revoked_at` set). Not an `is_active` flag, so not "deactivated", and never reversed. |

## Scope

In: the apps `freedom_ls.api` and `freedom_ls.api_admin`; the users API endpoint in `accounts`;
moving `User.updated_at` when email verification changes; removing `django-ninja`; `docs/api.md`
and the product-doc updates below.

Out:

- Every other API endpoint (specs 2 to 6). Write endpoints, webhooks, push, any UI, the browsable
  API, Swagger UI, OAuth, cross-site keys, keys tied to users or to role-based permissions.
- A deletion feed.
- Moving `User.updated_at` on login.
- A per-IP throttle on failed authentication. DRF throttles run after authentication, so bad-key
  floods are not rate-limited by this spec.
- Rejecting plain-http requests in code. The docs carry the HTTPS rule.
- Changing the admin exports. Deleting or changing the rest of the `xapi_learning_record_store`
  stub (apps, models, admin, README and its TODOs).

## Decisions

| Decision | Reason |
| --- | --- |
| Each API endpoint lives in the app that owns its model, in `<app>/api.py`, and registers with the router in `freedom_ls.api`. Specs 2 to 6 follow this. | Chosen by the user: model knowledge stays in its app. |
| `freedom_ls.api` imports only `base` and `site_aware_models`. The key admin, which imports `audit_log`, lives in `freedom_ls.api_admin`. | `accounts` imports `api`, so `api` stays out of `audit_log` and its fan-out into `organisations` and `learner_management`. |
| Installing both apps and including `freedom_ls.api.urls` turns the API on. There is no enabled flag. | Matches the `blog` pattern in `config/urls.py`. |
| `ApiKey` has no foreign key to the user model; the audit entry records who issued and who revoked it. | Keys are not tied to users, and a user FK would add `api → accounts`. |
| Everything about a key except its `name` is fixed at issue. | Changing a live key's API scopes surprises a running script; rotation is issue new, then revoke old. |
| `User.updated_at` moves when email verification changes, not on login. | Chosen by the user. Verification matters for leads; login churn would flood incremental syncs. |

### `freedom_ls.api`: API scopes

`freedom_ls/api/scopes.py`:

class ApiScope(models.TextChoices):

    COURSE_APPLICATIONS = "course_applications"
    REFERRAL_DATA = "referral_data"

Each choice has a label and a one-line description naming the model classes it covers, used as

### `freedom_ls.api`: the key model

`ApiKey(SiteAwareModel, TimestampedModel)` in `freedom_ls/api/models.py`:

| Field | Type | Notes |
| --- | --- | --- |
| `name` | `CharField(max_length=200)` | Required, not unique. What the key is for, e.g. "Nightly CRM sync". |
| `key_prefix` | `CharField(max_length=16, unique=True)` | Random, non-secret public id. Shown in admin and audit. |
| `key_hash` | `CharField(max_length=64, unique=True)` | SHA-256 hex of the full key. The secret has 256 bits of entropy, so a password hasher would add per-request cost for nothing. Never displayed. |
| `scopes` | `ArrayField(CharField(choices=ApiScope.choices))` | At least one, no duplicates. |
| `expires_at` | `DateTimeField(null=True, blank=True)` | Null means no expiry. Clean rejects a past value. |
| `revoked_at` | `DateTimeField(null=True, blank=True)` | Set once, never cleared. |
| `last_used_at` | `DateTimeField(null=True, blank=True)` | Accurate to 5 minutes. |

- Key text: `flsk_<key_prefix>.<secret>`, `secret = secrets.token_urlsafe(32)`. Site, API scopes and
  expiry are never encoded in it.
- `ApiKey.issue(instance, *, site)` fills an unsaved instance (prefix, hash, site), saves it, and
  returns the full key. Nothing else ever holds the full key.
- `is_active(now)`: `revoked_at is None and (expires_at is None or expires_at > now)`.
- `revoke(now)` sets `revoked_at` only when it is unset.
- `__str__` is the name and prefix.
- Add `"freedom_ls_api.ApiKey"` to `TIMESTAMPED_MODELS`
  (`freedom_ls/contrib/conformance/tests/test_timestamped_models.py`).

### `freedom_ls.api`: authentication

`ApiKeyAuthentication(BaseAuthentication)` in `freedom_ls/api/authentication.py`:

- Reads only the `Authorization` header: two parts, scheme `Bearer` (case-insensitive), token
  `flsk_<prefix>.<secret>`. A key anywhere else, including the query string, is ignored.
- Resolves the site with `get_cached_site(request._request)`, so the DRF wrapper does not get its
  own site cache. `UnknownSite`, `Site.DoesNotExist` and `SiteResolutionError` fail authentication.
- Looks the key up by `key_prefix` and the resolved site through the base manager, not the
  host-filtered default manager, and compares `sha256(token)` to `key_hash` with
  `hmac.compare_digest`. An unknown prefix still runs one hash and compare.
- Malformed header, unknown prefix, wrong secret, revoked, expired, key site not the host site,
  unresolvable site: each raises the same `AuthenticationFailed` with one message. A missing header
  returns `None`. `authenticate_header()` returns `'Bearer realm="api"'`, so both are 401 with
  `WWW-Authenticate`, never 403.
- On success returns `(None, api_key)`; views read `request.auth`. It then runs a conditional
  queryset `update(last_used_at=now)` where `last_used_at` is null or older than 5 minutes, so the
  key row is written at most once per 5 minutes and `updated_at` does not move. Failures never
  touch `last_used_at`.
- Nothing logs the header, echoes it in a response or puts it in an exception message.

`freedom_ls/api/schema.py`: an `OpenApiAuthenticationExtension` for `ApiKeyAuthentication`
declaring an HTTP bearer scheme.

### `freedom_ls.api`: permission and throttle

- `HasApiScope` (`freedom_ls/api/permissions.py`): passes when `request.auth` is an `ApiKey` and
  `view.required_scope` is in its `scopes`; otherwise 403 with a body naming the missing API scope.
- `ApiKeyRateThrottle(SimpleRateThrottle)` (`freedom_ls/api/throttling.py`): overrides `get_rate()`
  to return `config.API_THROTTLE_RATE` (DRF's default reads the absent `REST_FRAMEWORK` setting).
  The cache key is built from the key's `pk`, never the key text or hash. 429 carries `Retry-After`.

### `freedom_ls.api`: shared read conventions

- `ApiKeysetPagination` (`freedom_ls/api/pagination.py`), a custom `BasePagination`, not DRF's
  `CursorPagination` (which stores only the first ordering field plus an offset, and rejects
  offsets past 1000):
  - Orders by `("updated_at", "id")` ascending. The opaque `cursor` query parameter encodes the
    last row's `(updated_at, id)`, and the next page is the rows after that pair. Any run of equal
    `updated_at` pages with no duplicates or skips.
  - `page_size` query parameter, default `API_PAGE_SIZE`, clamped to `API_MAX_PAGE_SIZE`.
  - Envelope `{"next": url | null, "results": [...]}`. No `previous`, no count. `next` keeps the
    request's other query parameters.
  - A malformed cursor is 400 with `{"cursor": [...]}`.
  - Describes `cursor` and `page_size` to drf-spectacular.
- `UpdatedSinceFilterSet(django_filters.FilterSet)` (`freedom_ls/api/filters.py`): `updated_since`
  → `updated_at__gte`. ISO 8601 with a timezone or `Z`; a naive or unparseable value is 400 naming
  the parameter.
- `ReadOnlyApiViewSet(ReadOnlyModelViewSet)` (`freedom_ls/api/viewsets.py`), the base every API
  endpoint uses:
  - `authentication_classes = [ApiKeyAuthentication]`, `permission_classes = [HasApiScope]`,
    `throttle_classes = [ApiKeyRateThrottle]`, `renderer_classes = [JSONRenderer]`,
    `pagination_class = ApiKeysetPagination`, `filter_backends = [DjangoFilterBackend]`,
    `http_method_names = ["get", "head", "options"]`, drf-spectacular's `AutoSchema`.
  - `required_scope: ApiScope` is required. A registered viewset without one fails a system check
    in `freedom_ls/api/checks.py`.
  - `get_exception_handler()` returns a handler that renders every error a DRF view raises as JSON
    `{"detail": str, "code": str}` (DRF's error code). 400 field errors keep DRF's field-keyed dict.
    Unmatched URLs, the missing-slash redirect and unhandled 500s are Django's own responses.
  - OPTIONS returns 200 with an `Allow` header and no serializer field metadata.
  - Responses carry `Cache-Control: private, no-store`.
  - `site_queryset(queryset)` filters on `site=self.request.auth.site`. During schema generation
    (`swagger_fake_view`, or `request.auth` not an `ApiKey`) it returns `queryset.none()`.
    Endpoint querysets go through it rather than the host-filtered manager.
- `ApiRouter` (`freedom_ls/api/routers.py`): a `SimpleRouter` (no root view) with trailing slashes
  and snake_case route names (`<basename>_list`, `<basename>_detail`). A module-level `router` is
  what `<app>/api.py` modules register with.
- `freedom_ls/api/urls.py`: `app_name = "api"`. It calls
  `django.utils.module_loading.autodiscover_modules("api")`, which imports each installed app's
  `api.py` without a static import, so `api` gains no edge to endpoint apps. Then `router.urls`,
  plus `schema/` → `SpectacularAPIView` (name `schema`) with `ApiKeyAuthentication`, a permission
  that accepts any active key with no API scope, the JSON OpenAPI renderer only, and title and
  version through `custom_settings`.

### `freedom_ls.api_admin`: issuing and revoking keys

- `apps.py`: `label = "freedom_ls_api_admin"`. A system check errors when `freedom_ls.api` is not
  installed (precedent: `registration_rules/apps.py`). No models.
- `ApiKeyAdmin(SiteAwareModelAdmin)` in `freedom_ls/api_admin/admin.py`, registered for `ApiKey`:
  - Add form: `name`, `scopes` (checkboxes over `ApiScope` with their descriptions), `expires_at`.
    No site field: the key gets the admin request host's site.
  - `save_model` on add calls `ApiKey.issue(obj, site=...)` on the form's own `obj`, so Django's
    add view logs and links the saved row, and keeps the returned full key on `obj` for
    `response_add`.
  - `response_add` renders a one-off admin-shell page (`admin_page_context`) with the full key in a
    monospace box, the warning that it will not be shown again, and `Cache-Control: no-store`. No
    redirect and no `messages` call: `MESSAGE_STORAGE` is unset, so a message would store the key in
    the messages cookie or the session.
  - Change form: `name` editable while the key is active; all other fields read-only; revoked or
    expired keys read-only throughout. `key_hash` is never shown.
  - Changelist: name, `key_prefix`, API scopes, status label (Active / Expired / Revoked),
    `expires_at`, `last_used_at`, `created_at`. Filter by status.
  - Revoke: a "Revoke selected keys" action and a change-page button, both through one
    confirmation page that lists the keys and says scripts using them stop at once. Already-revoked
    keys are skipped.
  - `has_delete_permission` is false.
- Audit, through `audit_log.writer.record_entry` inside the save's transaction: actions
  `api_key.issued` ("API key issued") and `api_key.revoked` ("API key revoked") in
  `FLS_AUDIT_ACTIONS` (`freedom_ls/audit_log/actions.py`). One entry per key: actor the admin user,
  target the key, `organisation=None`, `details` holding `name`, `key_prefix`, `scopes` and
  `expires_at`. The full key and hash never enter the audit log.
- Change vocabulary: in `.claude/skills/domain-glossary/SKILL.md` "Changes", add the noun `api_key`
  and the verbs `issued` and `revoked` (a one-way end, distinct from `deactivated`). In
  `freedom_ls/audit_log/tests/invariants/test_vocabulary.py`, add them to `NOUNS` and `VERBS`, and
  let the retired-word check allow `api_key.revoked` while still rejecting "revoke" elsewhere. The
  glossary's `is_active` row keeps "revoke" ruled out for `is_active` flips.

### `accounts`: the users API endpoint

- `freedom_ls/accounts/resources.py`: move the `email_verified` `Exists` annotation out of
  `UserResource.filter_export` into one `accounts` function that both the export and the API call.
- `freedom_ls/accounts/api.py`:
  - `UserApiSerializer`, fields `USER_EXPORT_FIELDS + ("updated_at",)`: `id` (integer pk),
    `email`, `first_name`, `last_name`, `is_active`, `is_staff`, `email_verified`, `created_at`,
    `last_login`, `updated_at`. Timestamps ISO 8601 with timezone.
  - `UserFilterSet(UpdatedSinceFilterSet)`.
  - `UserApiViewSet(ReadOnlyApiViewSet)`: `required_scope = ApiScope.USERS`; list and detail;
    queryset `site_queryset(...)` over `User` with the `email_verified` annotation. No related rows
    are serialised, so it needs no `select_related` or `prefetch_related`.
  - `router.register("users", UserApiViewSet, basename="user")`.
- New migration: an index on `User` over `(site, updated_at, id)`.
- A receiver in `accounts` on allauth `EmailAddress` `post_save` and `post_delete` runs
  `User._base_manager.filter(pk=instance.user_id).update(updated_at=timezone.now())`. The base
  manager works with no request or a request for another host. Queryset `update()` and bulk
  operations on `EmailAddress` send no signals and are not covered.

## Testing

Wrong-host and unresolvable-site tests use real `Site` rows, `ALLOWED_HOSTS` and `HTTP_HOST`, not
`mock_site_context`, which hides the host. Throttle tests clear the cache before and after
(precedent: `referral_tracking/tests/conftest.py`).

- Key model: the row never holds the full key and its hash matches; `is_active` at the expiry
  instant; `revoke` does not move an existing `revoked_at`; clean rejects past expiry and empty
  API scopes.
- Authentication, each a 401 with `WWW-Authenticate: Bearer realm="api"` and an identical body: no
  header, wrong scheme, malformed token, unknown prefix, wrong secret, revoked, expired, a site-A
  key on host B, an allowed host with no `Site` row, a key only in the query string, a signed-in
  session with no key. A lowercase `bearer` scheme authenticates.
- `last_used_at`: set on success, not on failure, not rewritten within 5 minutes (`time_machine`);
  `updated_at` unchanged by it.
- A valid key without `users` gets 403 naming the API scope.
- Throttle: the request past the rate is 429 with `Retry-After`; two keys have separate counters;
  the API works with no `REST_FRAMEWORK` setting. W001 fires for `LocMemCache` with `DEBUG` false
  and not for `DatabaseCache`. The `required_scope` check fires for a viewset without one.
- Every route under `/api/` (iterate the resolver) rejects a request with no key.
- Pagination: following `next` returns each row once; 1,500 users with one identical `updated_at`
  page with no duplicates or skips; `page_size` above the cap is clamped; `next` keeps
  `updated_since`; a malformed cursor is 400.
- `updated_since` is inclusive at the boundary; naive and invalid values are 400.
- Errors: detail 404 for an unknown or other-site id, and 405 on POST, PUT, PATCH and DELETE, are
  JSON `{"detail", "code"}`. Every API response has `Cache-Control: private, no-store`.
- Users: the field set is exactly the serializer's; no `password`, `is_superuser`, `groups` or
  `user_permissions`; timestamps ISO 8601 with timezone and `id` an integer; another site's users
  absent from the list; `email_verified` agrees with the export; query count fixed regardless of
  page size; HEAD returns GET's status and headers with no body; OPTIONS has no field metadata.
- `updated_at` moves when a user's `EmailAddress` is verified, unverified or deleted, including
  from a context with no request.
- Admin: issuing shows the key once on the response page with no message and no redirect; the add
  form has no site field and the key gets the host's site; the admin LogEntry points at the saved
  key; one `api_key.issued` entry (`freedom_ls/tests/audit_assertions.py` `assert_entry`) without
  the key; the revoke action and button each write one `api_key.revoked` entry per key and skip
  revoked keys; revoked keys are read-only; delete is unavailable.
- Schema: `/api/v1/schema/` is 401 without a key and 200 with any active key; it declares the
  bearer scheme, `updated_since`, `cursor` and `page_size`; `manage.py spectacular --validate
  --fail-on-warn` passes.
- A Sentry event built from an API request carries no `Authorization` value. If the current
  `sentry_sdk.init` config does not strip it, `freedom_ls/deployment/sentry.py` gains a scrub.
- The `api_admin` system check errors when `freedom_ls.api` is not installed.
- The Python example in `docs/api.md` compiles (a test extracts the code block).

## Documentation and downstream

- `docs/api.md`, outside `docs/product/` (that folder is not API reference, and its docx build
  lists its files). Beyond describing the behaviour above, it says: HTTPS only, and a key sent over
  plain http is compromised and must be revoked; follow `next` verbatim; rows updated mid-run come
  back later in the same run; upsert by `id`; checkpoint at the max `updated_at` seen minus 5
  minutes, advanced only after a full run; deleted users never appear, deactivation shows as
  `is_active`, and a periodic full pull finds deletions; `last_login` changes do not move
  `updated_at`; additions stay in v1 and removals or renames need v2; rotate by issuing a new key
  before revoking the old one; the throttle needs a shared cache. It has a short `httpx` example
  that reads the key from an environment variable, follows pages and honours `Retry-After`, and a
  users section (API scope, filters, field table) that specs 2 to 6 copy.
- `docs/product/security-and-data-handling.md`: the API key, the data the users API endpoint
  exposes, `last_used_at` and its retention, API key issue and revoke in the audit-log list, and
  Authorization-header scrubbing. Bump "Last updated".
- `docs/product/multi-tenancy-and-isolation.md`: keys bind to one site.
  `docs/product/admin-interface.md`: the API keys admin.
- Regenerate `docs/app_structure.md` and `test_organisation/import_contracts.toml` with
  `/ds:app_map`. New edges, for approval: `api → base, site_aware_models`; `api_admin → api,
  audit_log, site_aware_models`; `accounts → api`. `accounts → api → base` closes a transitive loop
  like the existing `accounts → base → learner_management → accounts`.
- Upgrade notes for concrete projects: the `INSTALLED_APPS` and URL changes from "Dependencies and
  settings"; use a shared cache; `pydantic` is now a direct dependency; `django-ninja` is gone.
