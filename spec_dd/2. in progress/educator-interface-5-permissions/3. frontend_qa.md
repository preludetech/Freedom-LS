# Frontend QA: educator permissions

This change gives the four educator roles new names and makes every permission question in the
educator interface go through one capability check, `can`. An `OrganisationMember` row switches a
person's grants in an organisation on and off. A denied action now answers with a visible
explanation instead of an empty 403.

What a browser can see:

- **Organisation admins can create, edit and delete cohorts** in their own organisation. Before
  this change, only superusers could.
- **Cohort admins and cohort viewers see only their own cohorts** and those cohorts' learners,
  including on a course's detail page, which used to leak other cohorts' rows.
- **An inactive `OrganisationMember` locks the person out** of that organisation. Their role rows
  stay as they are.
- **A stale action returns a denial modal.** This is an action the page offered, but the role no
  longer allows. The modal says what happened, why, and who to ask, and offers only Close. If the
  object has left the user's scope altogether, the action answers 404 with a "This is no longer
  available" modal instead, which does not reveal whether the object still exists.
- **Report generate and download** check `download_cohort_report`.

Beyond the golden path, this run hunts for:

- **Over-granting.** A cohort-scoped role reaching another cohort, another organisation's data, or
  an organisation-level control.
- **Under-granting.** An organisation admin or site admin losing something they had, or a
  superuser losing anything.
- **The 403 swap landing on the wrong responses.** `alpine-components.js` now swaps every 403 into
  its target, as it already does for 422. Check that 422 validation still behaves, that a plain
  (non-htmx) 403 still renders the full 403 page, and what a CSRF failure on an htmx form looks
  like now.
- **Hidden-not-disabled.** A control the role can't use must be absent, not greyed out.
- **Enumeration.** An out-of-scope cohort, learner or organisation returns 404, never 403.

## §0 Setup

1. `PORT=$(.claude/ds/scripts/find_available_port.sh)`. Use that number literally from here on.
2. `uv run python manage.py runserver $PORT`, backgrounded.
3. Base URL: `http://127.0.0.1:$PORT`. Check that `#debug-branch-badge`, bottom left, names
   `educator-interface-5-permissions`.

## §1 The organisation admin (golden path)

Persona: `org.admin@qa.test`.

1. Go to `/educator/`. **Expect** a redirect to `/educator/organisations/northside/dashboard`.
   The organisation switcher lists Northside only.
2. Go to `/educator/organisations/northside/cohorts`. **Expect** Cohort A, Cohort B and Cohort
   Empty, and a **Create Cohort** button.
3. Click **Create Cohort** and enter the name `QA Cohort 1`. Click **Save**. **Expect** a redirect to
   the new cohort's detail page and the cohort on the list.
4. Open Create Cohort again and enter `Cohort A`, a name already used in this organisation. Click
   **Save**. **Expect** the modal to stay open with a field error (a 422 swap), not the denial modal.
5. Open **Cohort A**. **Expect** Edit and Delete controls on its details panel. Edit the name to
   `Cohort A (renamed)`, save, and check that the title updates. Rename it back.
6. Open **Cohort Empty** and choose Delete. **Expect** the confirmation to name nothing that
   cascades. Confirm, and **expect** a redirect to the cohorts list with Cohort Empty gone.
7. Open Delete on **Cohort A**. **Expect** the blocked reason (it still has memberships and
   registrations) and no live delete button.
8. Go to `/educator/organisations/southside/dashboard`. **Expect** a 404.
9. Open *the course* from Courses. **Expect** both Cohort A and Cohort B in "Cohort
   Registrations", and both `learner.a1` and `learner.b1` in "Direct Registrations".

## §2 The cohort admin

Persona: `cohort.admin@qa.test`.

1. `/educator/` redirects to Northside. The switcher lists Northside only.
2. Cohorts list: **expect** Cohort A only and **no Create Cohort button**. The button must be
   absent, not disabled.
3. Open Cohort A. **Expect** no Edit and no Delete control. Name, courses and learners panels
   show, and the learners panel lists `learner.a1` and `learner.a2` only.
4. Learners list: **expect** `learner.a1` and `learner.a2` only. The Cohorts cell names Cohort A
   only.
5. Type Cohort B's detail URL (`/educator/organisations/northside/cohorts/<Cohort B pk>`).
   **Expect** a 404, not a 403.
6. Type `learner.b1`'s and `learner.none`'s learner detail URLs. **Expect** a 404 for each.
7. Open *the course*. **Expect** "Cohort Registrations" to show Cohort A only, and "Direct
   Registrations" to show `learner.a1` only. Before this change, Cohort B and `learner.b1` leaked
   here.
8. Hand-made request. From the cohorts list page's console, run
   `fetch(location.pathname + '/__actions/create_cohort', {method: 'POST', headers: JSON.parse(document.body.getAttribute('hx-headers')), body: new URLSearchParams({name: 'Sneaky'})}).then(r => r.status)`.
   **Expect** `403`, and no "Sneaky" cohort after a reload. The request carries no HX-Request, so
   this is the plain 403 path.
9. Go to `/educator/organisations/southside/cohorts`. **Expect** a 404.

## §7 The denied experience

Persona: `stale.admin@qa.test`. This persona holds `cohort_viewer` on Cohort B as well, so
Northside stays reachable after the admin grant goes.

1. Open the Northside cohorts list. **Expect** the Create Cohort button.
2. Click **Create Cohort** so that the modal is open. Type `Too Late`. **Leave the modal open.**
3. In the shell, run `remove_object_role(stale_admin, northside, "organisation_admin")`.
4. Click **Save**. **Expect**, in place of the create form:
   - a modal headed **You can't use “Create Cohort” here any more**;
   - the text **Your role doesn't allow it.**;
   - **Ask an organisation admin of Northside.** with no names listed, because this persona now
     lacks `view_organisationmember`;
   - one **Close** button, and no retry or save button.
5. **Expect** that the network response was a 403 whose body is the fragment, that the console has
   no uncaught htmx error, and that no toast says something failed.
6. Click **Close**. **Expect** the modal to close. The Create Cohort button that was inside the
   replaced modal is gone.
7. Reload. **Expect** no Create Cohort button, Cohort B only on the list, and no `Too Late`
   cohort.
8. Stale delete on a cohort that leaves scope. Reassign `organisation_admin` on Northside to
   `stale.admin` in the shell. Open **QA Cohort 1** (from §1) and open its Delete confirmation.
   Remove the grant in the shell again, then confirm the delete. QA Cohort 1 is now outside this
   persona's scope. **Expect**, in place of the confirmation:
   - a modal headed **This is no longer available**, saying it may have been removed or you may no
     longer have access to it, and naming no cohort;
   - one **Close** button, and no retry or delete button;
   - a 404 network response whose body is the fragment, and no uncaught htmx error in the console.

   Click **Close**, then open the Northside cohorts list and **expect** QA Cohort 1 absent from
   it. In the shell, **expect** QA Cohort 1 to still exist.
8a. Stale delete on a cohort still in scope. In the shell, reassign `organisation_admin` and also
   give `stale.admin` `cohort_viewer` on QA Cohort 1. Repeat step 8. The cohort stays visible, so
   **expect** the 403 denial modal headed **You can't use “Delete” here any more**, and QA Cohort 1
   still existing. Remove the extra `cohort_viewer` grant afterwards.
9. Repeat steps 2 to 4 at 375×812, after giving the grant back. **Expect** the denial modal to fit the viewport, with the heading
    readable and Close reachable without horizontal scrolling.

## §9 Side effects of the 403 and 404 swaps

1. **A plain 403 still renders the full page.** §2 step 8 and §8 step 4 already prove this. Note
   in the report that both showed the standard 403 page, not a fragment.
2. **The 422 swap is unchanged.** §1 step 4.
3. **CSRF failure on an htmx form.** As `org.admin@qa.test`, open Create Cohort. In the console,
   run `document.body.setAttribute('hx-headers', '{"X-CSRFToken": "broken"}')`, then submit a
   name. Record exactly what appears: before this change, htmx dropped the 403 and nothing
   visible happened. Now the response swaps into the modal. Report what the user sees and whether
   the page is still usable after a reload. This is an observation for the report, not a pass/fail
   check, unless the page breaks beyond a reload.
4. **The notification bell and other polling** keep working on educator pages. Nothing in the
   console after a minute on the dashboard.
5. **Only marked 404s swap.** As `stale.admin@qa.test`, open a cohort the persona can see. In the
   console, run `htmx.ajax('GET', location.pathname + '/__panels/no-such-panel', '#main-content')`.
   **Expect** the network response to be a 404, nothing to swap into the page, and no Django 404
   page nested inside it. Only §7 step 8's "no longer available" fragment should ever swap in.
