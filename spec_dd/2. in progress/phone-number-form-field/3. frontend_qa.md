# Frontend QA: phone number form field

Checks the `phone` question in a browser: the country picker, the browser-country preselection,
validation messages, the stored form shown back to readers, and what must not have changed.

## Setup

1. Build the stylesheet: `npm run tailwind_build`.
2. Start the server on a free port: `uv run python manage.py runserver $PORT`. Base URL:
   `http://127.0.0.1:$PORT`.
3. Log in at `http://127.0.0.1:$PORT/accounts/login/` with the QA login from
   `.claude/sdd/config.md` (`## QA Login`).
4. The phone question lives in the demo application form: page 1 ("About you") of the course
   "Functionality Demo - Application gated course", question "What is your phone number?"
   (optional). Find the course in the course list, open it and press "Apply now". If the QA user
   already has a submitted application for it, ask the data helper for a fresh learner with no
   application for that course.
5. Data the demo content lacks, to request from the data helper:
   - **Course form with a phone question**: a course the QA user is registered on, holding one
     form with a single page and two questions: a required `phone` question "Contact number" and
     an optional `short_text` question "Anything else". Needed for Tests 7 and 8.
   - **Legacy phone answer**: on a second, unsubmitted application sitting (any learner), a
     `QuestionAnswer` for the phone question with `text_answer="082 123 4567"`, written directly,
     not through the form. Needed for Test 6.

Setting the browser's language: the country is preselected from the `Accept-Language` request
header. Before a test that names a language, set it on the browser context, for example with
`page.context().setExtraHTTPHeaders({"Accept-Language": "en-ZA"})`, then reload the page. Each
test below says which value to use.

Viewports: 375, 768 and 1920 wide. "No sideways scroll" means
`document.documentElement.scrollWidth <= window.innerWidth` after layout settles.

## Test 1: layout and labels

`Accept-Language: en`.

1. Open page 1 of the application form.
2. Under "What is your phone number?" expect two controls, each with a visible label: a select
   labelled "Country" and a text input labelled "Phone number".
3. The select shows "Choose a country". Open it: the first option is "Choose a country", then
   countries in alphabetical order, each ending with its calling code, e.g. "South Africa (+27)".
   "Åland Islands" sits among the A names, not at the end.
4. At 1920 and 768 the two controls sit side by side. At 375 they stack, Country first. No
   sideways scroll at any width.
5. The controls look like the other inputs on the page: same border, radius, padding and focus
   ring. Tab moves from Country to Phone number.
6. With "Choose a country" selected, no hint shows under "Phone number". Choose South Africa:
   a hint `For example: 71 123 4567` (a South African mobile number with no `+27` and no leading
   `0`) appears under the number input in the muted hint style. Choose United Kingdom: the hint
   changes to a UK number with no `+44` and no leading `0`. Back to "Choose a country": the hint
   goes.
7. The other questions on the page look as they did before.

## Test 2: browser country preselected

1. `Accept-Language: en-ZA`. Reload page 1. The select shows "South Africa (+27)", and the
   hint under the number shows a South African example.
2. `Accept-Language: en-GB,en;q=0.9`. Reload. "United Kingdom (+44)".
3. `Accept-Language: fr-FR;q=0.5, de-DE;q=0.9`. Reload. "Germany (+49)".
4. `Accept-Language: es-419`. Reload. "Choose a country".
5. `Accept-Language: *`. Reload. "Choose a country", and the page renders without an error.
6. Country names stay in English in every step: the header changes the selection only, not the
   language of the page.

## Test 3: a valid number is stored and shown in international format

`Accept-Language: en-ZA`.

1. On page 1, answer the required questions. Leave South Africa selected and type
   `82 123 4567` in "Phone number". Press Next.
2. The next page opens with no error.
3. Go Previous. South Africa is selected and the input shows `82 123 4567`.
4. Continue to the check-your-answers page. The phone answer reads `+27 82 123 4567`.
5. Follow Edit back to page 1: still South Africa and `82 123 4567`. Press Next without
   changing it: accepted.
6. Open the sitting in the admin (form progress record → answers). The phone answer reads
   `+27 82 123 4567`.

## Test 4: invalid input is refused with a useful message

`Accept-Language: en`. After each step, expect: the page re-renders with the "Invalid answers"
callout naming the question, the message below the two controls in the error colour, the typed
number still in the input, the chosen country still selected, and the other answers on the page
kept.

1. No country, `082 123 4567` → `You entered "082 123 4567". Choose a country, or start the number with + and its country code.` The select still shows "Choose a country".
2. South Africa, `hello` → `You entered "hello". Enter a valid phone number for South Africa, like 71 123 4567.` (the example may differ; it must be a South African number with no `+27` and no leading `0`, matching the hint).
3. South Africa, `0800 FLOWERS` → the same South Africa message.
4. South Africa, `82 123` → the same South Africa message.
5. South Africa, `82 123 4567 ext. 12` → `You entered "82 123 4567 ext. 12". Enter the number without an extension.`
6. No country, `+27 82 123` → `You entered "+27 82 123". Enter a valid phone number, starting with + and its country code.`
7. South Africa, `082 123 4567` → `You entered "082 123 4567". Leave out the 0 at the start, like 71 123 4567.`
   South Africa, `27821234567` → the same message naming `27`. South Africa, `0027 82 123 4567`
   → naming `0027`.
8. With a screen reader or the accessibility tree: the number input is marked invalid and
   described by the hint and the error message.
9. Then fix it: South Africa, `(82) 123-4567` → accepted; check-your-answers shows
   `+27 82 123 4567`.
10. After a valid answer is stored (step 9), go back and submit `hello`. It is refused. Leave the
   page without fixing it and open check-your-answers: the earlier valid number is still there.

## Test 5: a leading + wins over the picker

`Accept-Language: en-GB`.

1. United Kingdom is preselected. Type `+27 82 123 4567`. Press Next. Accepted.
2. Check-your-answers shows `+27 82 123 4567`.
3. Edit: the select now shows South Africa and the input `82 123 4567`.

## Test 6: an answer stored before validation existed

Use the legacy-answer sitting from Setup.

1. Check-your-answers (or the admin answers view) shows `082 123 4567` exactly as stored.
2. Open the form page: the input holds `082 123 4567`, and the select shows "Choose a country"
   whatever `Accept-Language` is (try `en-ZA`).
3. Press Next without changing anything: the "Choose a country" message appears. Pick South
   Africa and press Next: the "Leave out the 0 at the start" message appears. Change the number
   to `82 123 4567` and press Next: accepted, and it now reads `+27 82 123 4567`.

## Test 7: required, optional and the preselected country

1. Application form, `Accept-Language: en-ZA`, phone question optional: leave the number empty
   with South Africa preselected, answer the required questions, press Next. The page is
   accepted, and check-your-answers shows no phone answer.
2. Give a number, continue, come back, clear the number (leave the country) and press Next:
   accepted, and the phone answer is gone from check-your-answers.
3. Course form from Setup, required "Contact number", `Accept-Language: en-ZA`: press Next or
   Submit with the number empty. The browser's own "fill in this field" prompt lands on the
   number input, and nothing is submitted.

## Test 8: the exam runner's answered tally

Course form from Setup, `Accept-Language: en-ZA`.

1. Open the form page. South Africa is preselected. The tally reads `0 of 2 answered`.
2. Change the country to another one. Still `0 of 2 answered`.
3. Type a number. `1 of 2 answered`. Clear it. `0 of 2 answered`.
4. Type a valid number and submit the form. The submit dialog's answered count is 1.
5. Open the completed form's read-only view, if the course offers one: both controls are
   disabled and show the stored country and the number without its calling code.

## Test 9: export

1. In the admin, export the applications for the demo course to CSV (the applications
   changelist's export action).
2. The phone column holds `'+27821234567` for the sitting from Test 3: the stored E.164 text with
   the leading apostrophe every `+` cell gets. The legacy sitting's cell is `082 123 4567`.

## Test 10: JavaScript off

1. Disable JavaScript for the browser context and reload page 1 of the application form
   (`Accept-Language: en-ZA`).
2. Both controls render, South Africa is preselected with its example hint, and the select
   opens and changes (the hint stays on the South African example; that is expected).
3. Type `hello` and submit the page with its Next button. The page comes back with the error
   message, the number kept and the country kept.
4. Type `82 123 4567` and submit. The next page opens.

If the surrounding page cannot be driven with JavaScript off for reasons unrelated to the phone
question (login, page navigation), record that and judge only steps 2 and 3's markup: the two
controls and the server-rendered hint must not depend on any script.

## Test 11: what else could break

1. A form page with no phone question (any other demo form) renders and submits as before.
2. On the application form, the other typed questions still refuse bad input with their own
   messages (an invalid date, a malformed email), alongside a phone error on the same
   submission. Both messages show, each under its own question.
3. Submit the same valid phone answer twice in a row (Next, Previous, Next). One answer, one
   value, no duplicate row in the admin.
4. Hand-edit the select's value in dev tools to `ZZ` and submit `082 123 4567`. The response is
   the "Choose a country" message, not a server error, and the select comes back on "Choose a
   country".
5. Type `<script>alert(1)</script>` as the number. The message quotes it as text; nothing runs.
6. `Accept-Language` set to 2,000 characters of junk: the page still renders, with "Choose a
   country".
