# Spec: phone number form field

Idea: `idea.md`. Up-front answers: `answers.md`. Research: `research_*.md` in this directory.

## Purpose

The form engine's `phone` question type is an unvalidated `<input type="tel">`. It stores whatever
was typed in `QuestionAnswer.text_answer`, so "hello" is accepted and shown back to reviewers (bug
APP-1 in `spec_dd/2. in progress/downstream_bugs_oct_29/learner-ux-polish-from-mega-qa/idea.md`).
This work gives the `phone` type a country picker, real validation and one normalised stored form.
The country is preselected from the browser's language header when that header names a country.
`multi-step-course-applications` is blocked on this spec; its "ask for help" form needs the field
for anonymous applicants.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| country | narrowed | Here, an ISO 3166-1 alpha-2 code that `phonenumbers.SUPPORTED_REGIONS` contains (`ZA`). `phonenumbers` calls it a "region"; FLS already uses "region" for UI refresh regions (`educator_interface/reporting.py`), so the spec says "country" throughout. |
| browser country | coined | The country taken from the `Accept-Language` request header (`en-ZA` → `ZA`), used only to preselect the picker. No existing term: FLS runs no `LocaleMiddleware` and reads that header nowhere today. |

## Scope

In:

- The existing `phone` question type (`QuestionType.PHONE`) wherever a form-engine question
  renders: course form pages and course application form pages, HTMX re-renders included.
- Validating, normalising, storing and displaying phone answers.
- Preselecting the browser country.

Out:

- Any site, organisation or per-question default-country setting (`answers.md`).
- IP geolocation.
- A phone number on `User`, or on the course-applications applicant-details step (a plain Django
  form, not form-engine questions).
- Restricting a question to some countries, or to mobile numbers.
- SMS or call verification, and `tel:` links.
- Rewriting phone answers stored before this change.
- JavaScript: no Alpine component, no intl-tel-input, no formatting as you type.

## Decisions

- **Reuse `phone`.** Bare `type: phone` YAML stays valid. No schema field, model column or
  migration, so the fls-content bundled schema needs no re-sync.
- **Store E.164** (`+27821234567`) in `QuestionAnswer.text_answer`, so a stored answer carries its
  own country.
- **Validate strictly** with `phonenumbers.is_valid_number` (user decision). A newly allocated
  number range is rejected until the library is upgraded.
- **Use `phonenumberslite`**: this feature reads no carrier or geocoder data.
- **Native `<select>` beside `type="tel"`**: works with no JavaScript. A searchable combobox needs
  ARIA work the idea did not ask for.
- **A leading `+` wins over the selected country**, so a pasted or autofilled international
  number is read as typed.
- **Validate at submission only.** Stored rows are never re-validated, so a library upgrade cannot
  break an old answer and legacy free-text answers stay readable.

## Requirements

### Phone logic: new module `freedom_ls/form_engine/phone_numbers.py`

Every `phonenumbers` and `Accept-Language` call lives here. The module imports no `models`.
Nothing the fls-content plugin bundles imports it.

- `browser_country(accept_language: str) -> str | None`: split the header on commas, read each
  tag's `q` (default 1), drop `q=0`, and walk the tags in descending `q` order. Return the country
  of the first tag whose region subtag is in `SUPPORTED_REGIONS`. Parse each tag with
  `babel.core.parse_locale(tag, sep="-")`, catching `ValueError`. Skip `*`, bare languages (`en`),
  malformed tags, numeric regions (`419`) and non-geographic codes (`001`, `EU`). A script subtag
  is handled (`zh-Hant-TW` → `TW`). An empty header returns `None`. Do not add
  `LocaleMiddleware`: it would change the active language for the whole site.
- `country_choices() -> list[tuple[str, str]]`: one `(country, label)` pair per supported country,
  labelled `"<country name> (+<calling code>)"`, e.g. `"South Africa (+27)"`. Names come from
  Babel in the active Django language (converted from Django's `en-us` form to Babel's). A country
  Babel cannot name (`AC`, `TA`, `XK`) falls back to its code. Sort on an accent-folded name
  (`unicodedata` NFKD), so `Åland Islands` sorts under A. Cache per active language.
- `phone_answer_error(text: str, country: str) -> str | None`: why `text`, with the selected
  `country` (`""` for none), is not an acceptable phone answer. A number starting with `+` is
  parsed with no country; any other number is parsed with `country`, and libphonenumber strips
  the national trunk `0` (`082…` with ZA → `+2782…`). Never strip or add a `0` or a calling code by
  hand. Spaces, hyphens, dots and brackets are tolerated. Messages, each naming the value as
  `answer_error` does:
  - No `+` and no country: `You entered "<text>". Choose a country, or start the number with + and its country code.`
  - An extension was parsed: `You entered "<text>". Enter the number without an extension.`
  - Letters remain once a recognised extension is removed, the number does not parse, or
    `is_valid_number` is false, with a country: `You entered "<text>". Enter a valid phone number for <country name>, like <example>.`
    `<example>` is `format_number(example_number(country), PhoneNumberFormat.NATIONAL)`. When
    `example_number` returns `None`, the `, like <example>` clause is left out.
  - The same failure for a `+` number: `You entered "<text>". Enter a valid phone number, starting with + and its country code.`
- `e164_phone_answer(text: str, country: str) -> str`: the E.164 form of an answer that
  `phone_answer_error` accepted.
- `stored_phone_country(text: str) -> str | None`: the country of a stored E.164 answer, or `None`
  for a legacy row that does not parse.
- `display_phone(text: str) -> str`: a stored answer in international format
  (`+27 82 123 4567`), or the raw text when it does not parse.
- `national_phone(text: str) -> str`: a stored answer in national format for refilling the number
  input, or the raw text when it does not parse.

### Submission: `submissions.py`, `typed_answers.py`, `models.py` in `freedom_ls/form_engine/`

- The phone question POSTs `question_<id>` (the number, as today) and `phone_country_<id>` (the
  selected country, `""` for none). The country key stays outside the `question_` prefix because
  the exam runner's `_countAnsweredOnPage`
  (`learner_interface/static/learner_interface/js/alpine-components.js`) counts every
  `question_*` field as a question.
- New `submitted_phone_country(question, post_data) -> str`: returns `""` for a value outside
  `SUPPORTED_REGIONS`.
- `has_submitted_answer` is unchanged: a selected country with no number is no answer, so a
  preselected country never satisfies `required`.
- `RejectedAnswer` gains `country: str = ""`, handing back the selected country with the text.
- `answer_error(question, text, country: str = "")`: a `PHONE` branch returns
  `phone_answer_error(text, country)`, replacing the "nothing to check" comment for phone. Update
  the `typed_answers.py` module docstring, which says it imports only `enums` and `django.utils`.
- `FormProgress.save_answers`: for a `PHONE` question, pass `submitted_phone_country` to
  `answer_error`. On error, record `RejectedAnswer(text, message, country)` and keep the old row,
  as other types do. Otherwise store `e164_phone_answer(text, country)`.
- `format_answer`: a `PHONE` answer returns `display_phone(text)`. This reaches the
  `answer_display` filter, the admin `_answers.html`, `QuestionAnswerAdmin` and the applications
  `check_your_answers.html`.
- Exports need no code change. `exports.answer_value` already writes `text_answer`, now E.164,
  through the existing formula escaping.

### Rendering: `freedom_ls/form_engine/templates/form_engine/` and `templatetags/form_engine_tags.py`

- `question.html` sends `phone` to a new `inputs/phone_input.html` instead of `text_input.html`.
- A new simple tag `phone_field_state` (takes context) returns the selected country, the number
  input's value and `country_choices()`:
  - Selected country, first match wins: the rejected answer's `country` (an empty choice stays
    empty), the stored answer's `stored_phone_country`, the browser country from
    `request.headers["Accept-Language"]`, then none. Without a `request` in the context, there is
    no browser country.
  - Number value: the rejected text, else `national_phone` of the stored answer, else empty.
- `phone_input.html` renders inside the question's existing `<fieldset>`/`<legend>`:
  - `<select name="phone_country_<id>" id="phone_country_<id>">` with the visible label
    "Country", a first option "Choose a country" valued `""`, then the choices;
  - `<input type="tel" name="question_<id>" id="question_<id>" autocomplete="tel">` with the
    visible label "Phone number";
  - the input classes `dropdown.html` and `text_input.html` use, side by side when wide and
    stacked when narrow;
  - on the number input, `required`, `aria-invalid` and `aria-describedby="question_<id>_error"`
    as `text_input.html` has them. One error message serves the group. `read_only` disables both
    controls.

### Dependency

`uv add phonenumberslite`.

## Testing

Take every valid-number fixture from `phonenumbers.example_number(country)` under the pinned
version, or confirm it valid there, rather than hand-picking digits.

- `browser_country`: `en-ZA` → `ZA`; `en-GB,en;q=0.9` → `GB`; `en, fr-FR;q=0.8` → `FR`;
  `fr-FR;q=0.5, de-DE;q=0.9` → `DE`; `en-ZA;q=0, fr-FR;q=0.5` → `FR`; `zh-Hant-TW` → `TW`; `es-419`,
  `en`, `*`, `""` and garbage → `None`.
- `phone_answer_error` / `e164_phone_answer`: a ZA national number with a trunk `0` → E.164; a `+27`
  number with GB selected → stored as `+27…`; a national number with no country → the "Choose a
  country" message; `hello` and `0800 FLOWERS` with ZA → the ZA message; a ZA-invalid number →
  rejected; an Italian number keeps its leading `0`; `ext. 12` → the extension message; brackets
  and hyphens accepted; a country with no example number → message without `, like`.
- `country_choices`: labels carry the calling code; accented names sort by their base letter.
- `save_answers`: a valid answer is stored as E.164. An invalid one gives a `RejectedAnswer` with
  `text`, `message` and `country`, and the earlier row is untouched. A country with no number
  stores nothing and fails `required`.
- `format_answer` / `answer_display`: E.164 → international format; a legacy `082 123 4567` →
  unchanged.
- `phone_field_state`: the selection precedence; a rejected empty country stays empty; a legacy
  stored value refills the number raw; no `request` in the context → no browser country.
- Rendering: both controls labelled, the error linked by `aria-describedby`, `read_only` disables
  both, and the country select's name does not start with `question_`.
- Export: a phone answer exports as its E.164 string through the existing escaping.
- Playwright (`form_engine/tests/playwright/`): Playwright's default locale is `en-US`, so each test
  sets its locale. With `en-ZA`, South Africa is preselected; submitting a national number shows
  it in international format on the review page. With `en`, nothing is preselected, and a
  national number gives the "Choose a country" error with the number kept. Check the existing
  form_engine and course_applications Playwright tests that render a phone question; they will now
  see United States preselected.
- `demo_content/functionality_demo_application_form/1. about-you.yaml` still loads unchanged.

## Documentation and downstream

- `claude_plugins/fls-content/skills/content-types/resources/form-files.md`, "Phone question
  example": replace "The number itself is not format-validated" with what happens now (a country
  picker preselected from the browser's language, a validated number, stored in international
  form). No new YAML keys.
- `docs/product/learner-experience.md`: the form-question bullet says a phone number is checked
  against the chosen country.
- Upgrade notes: phone answers stored earlier are not converted. They display and export as typed
  and are validated only when resubmitted. `phonenumberslite` is a new dependency, and keeping it
  current keeps validation current.
- Bug APP-1's "reject fewer than 7 digits" stopgap is superseded.

## Open questions

- Q: Should an exported phone cell show the formula-escaping apostrophe (`'+27821234567`)? → A: Yes, keep `escape_csv_formula` unchanged for every column (assumed default: weakening a security rule for one column needs its own review. Overrule by editing Requirements → Submission.)
- Q: Should a typed extension be rejected rather than silently dropped? → A: Rejected (assumed default: E.164 cannot hold an extension, and silent loss surprises the person. Overrule by editing Requirements → Phone logic.)

## Success criteria

- The phone question works with JavaScript disabled.
- A legacy stored `082 123 4567` still shows as typed to educators and reviewers.
- On a course form page with a browser country preselected and no number typed, the exam runner's
  answered count does not go up.
- `grep -rn phonenumbers claude_plugins/fls-content` finds nothing.
