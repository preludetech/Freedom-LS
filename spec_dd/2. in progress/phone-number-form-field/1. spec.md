# Spec: phone number form field

Idea: `idea.md`. Up-front answers: `answers.md`. Research: `research_*.md` in this directory.

## Purpose

The form engine's `phone` question type is an unvalidated `<input type="tel">`. It stores whatever
was typed in `QuestionAnswer.text_answer`, so "hello" is accepted and shown back to reviewers (bug
APP-1 in `spec_dd/2. in progress/downstream_bugs_oct_29/learner-ux-polish-from-mega-qa/idea.md`).
This work gives the `phone` type a country picker, real validation, and a single normalised stored
form. The country is preselected from the browser's language header when it names a region.
`multi-step-course-applications` is blocked on this spec; its "ask for help" form needs the field
for anonymous applicants.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| browser region | coined | The two-letter region taken from the `Accept-Language` request header (`en-ZA` → `ZA`), used only to preselect a country. No existing term: FLS runs no `LocaleMiddleware` and reads that header nowhere today. |

## Scope

In:

- The existing `phone` question type (`QuestionType.PHONE`) in every place a form-engine question
  renders: course form pages and course application form pages, including HTMX re-renders.
- Validating, normalising, storing, displaying and exporting phone answers.
- Preselecting the country from the browser region.

Out:

- Any site, organisation or per-question default-country setting (`answers.md`).
- IP geolocation.
- A phone number on `User` or on the course-applications applicant-details step. That step is a
  plain Django form, not form-engine questions.
- Restricting a question to some countries, or to mobile numbers only.
- Phone extensions, SMS or call verification, and `tel:` links.
- Rewriting existing stored phone answers.
- JavaScript: no Alpine component, no intl-tel-input, no formatting as you type.

## Decisions

- **Reuse `phone`, add no new type.** Existing YAML with a bare `type: phone` stays valid. No
  schema field, model column or migration is added, so the bundled schema in
  `claude_plugins/fls-content/validate/schema.py` needs no re-sync.
- **Store E.164** (`+27821234567`) in `QuestionAnswer.text_answer`. The stored value carries its
  own country, so it can be read back without a region.
- **Validate strictly** with `phonenumbers.is_valid_number`, not `is_possible_number` (user
  decision, matching the idea's "proper validation"). The cost is that a newly allocated number
  range is rejected until the library is upgraded. Keeping `phonenumbers` current is routine
  dependency upkeep.
- **Use `phonenumberslite`**, the `phonenumbers` build without carrier and geocoder data, which
  this feature never reads. Add it with `uv add phonenumberslite`.
- **Use a native `<select>` beside a `type="tel"` input.** It works with no JavaScript, is
  accessible by default, and finds a country when the person types its first letters. A searchable
  combobox was rejected because it would need ARIA and live-region work the idea did not ask for
  ("don't overcomplicate things").
- **A number typed with a leading `+` wins over the selected country.** It is parsed with no
  region, and its own country code decides the country. A number without `+` is parsed with the
  selected country, so libphonenumber strips the national trunk `0` (`082…` with ZA →
  `+2782…`). Never strip or add a `0` or a country code by hand.
- **Validate at submission only.** Stored rows are never re-validated on read, edit or export. A
  `phonenumbers` upgrade must not break old answers, and legacy free-text answers stay readable.
- **Keep the CSV formula-escaping rule as it is.** An exported E.164 cell starts with `+`, which
  `freedom_ls/base/csv_safety.py` escapes. See Open questions.

## Requirements

### Phone logic: new module `freedom_ls/form_engine/phone_numbers.py`

Every `phonenumbers` and `Accept-Language` call lives here. `typed_answers.py` imports from this
module, and nothing that the fls-content plugin bundles imports `phonenumbers`. Functions, with
type hints and specific exception types (`phonenumbers.NumberParseException`, Babel's
`UnknownLocaleError` / `ValueError`):

- `browser_region(accept_language: str) -> str | None`: walk the header's language tags in
  descending `q` order and return the region of the first tag that carries one that
  `phonenumbers.SUPPORTED_REGIONS` contains. Skip `*`, bare languages (`en`), malformed tags,
  numeric regions (`419`) and non-geographic codes (`001`, `EU`). Handle script subtags
  (`zh-Hant-TW` → `TW`). Return `None` for an empty or missing header. Babel (already a
  dependency) may do the tag parsing. Do not add `LocaleMiddleware`: it would change the active
  language for the whole site.
- `country_choices() -> list[tuple[str, str]]`: one `(region, label)` pair per supported region,
  labelled `"<country name> (+<calling code>)"`, e.g. `"South Africa (+27)"`, and sorted by
  country name. Names come from Babel in the active Django language; a region Babel cannot name
  falls back to its code. Compute the list once per process.
- `phone_answer_error(text: str, region: str) -> str | None`: why `text`, with the selected
  `region` (`""` when none is selected), is not an acceptable phone answer. Each message follows
  the `answer_error` pattern of naming the value:
  - No `+` and no region: `You entered "<text>". Choose a country, or start the number with + and its country code.`
  - Fails to parse, or `is_valid_number` is false, with a region: `You entered "<text>". Enter a valid phone number for <country name>, like <example>.`
    `<example>` is `phonenumbers.example_number(region)` in national format.
  - Same failure for a `+` number: `You entered "<text>". Enter a valid phone number, starting with + and its country code.`
  - The parse found an extension: `You entered "<text>". Enter the number without an extension.`
  - Spaces, hyphens, dots and brackets are tolerated, never an error.
- `e164_phone_answer(text: str, region: str) -> str`: the E.164 form of an answer that
  `phone_answer_error` accepted.
- `stored_phone_region(text: str) -> str | None`: the region of a stored E.164 answer, or `None`
  when the stored text does not parse (a legacy row).
- `display_phone(text: str) -> str`: a stored answer in international format
  (`+27 82 123 4567`), or the raw text unchanged when it does not parse.
- `national_phone(text: str) -> str`: a stored answer in national format for refilling the
  number input, or the raw text when it does not parse.

### Submission: `freedom_ls/form_engine/submissions.py`, `typed_answers.py`, `models.py`

- The phone question POSTs two keys: `question_<id>` (the number, as today) and
  `question_<id>_country` (the selected region, `""` for none). Add
  `submitted_phone_region(question, post_data) -> str`, which returns `""` for a value outside
  `SUPPORTED_REGIONS`.
- `has_submitted_answer` is unchanged: a selected country with an empty number is no answer, so a
  preselected country never makes an optional phone question answered or a required one satisfied.
- `RejectedAnswer` gains `region: str = ""`, so a rejected phone answer hands back the country
  that was selected as well as the typed text.
- `answer_error(question, text, region: str = "")`: a `PHONE` branch returns
  `phone_answer_error(text, region)`, replacing the "nothing to check" comment for phone.
- `FormProgress.save_answers`: for a `PHONE` question, pass `submitted_phone_region` to
  `answer_error`. On error, record `RejectedAnswer(text, message, region)` and keep the old row,
  as other types do. Otherwise store `e164_phone_answer(text, region)`.
- `format_answer`: a `PHONE` answer returns `display_phone(text)`. This covers the
  `answer_display` filter, the admin `_answers.html`, `QuestionAnswerAdmin`, and the applications
  `check_your_answers.html`.

### Rendering: `freedom_ls/form_engine/templates/form_engine/`

- `question.html` sends `phone` to a new `inputs/phone_input.html` instead of `text_input.html`.
- `phone_input.html` renders, inside the question's existing `<fieldset>`/`<legend>`:
  - a `<select name="question_<id>_country" id="question_<id>_country">` with a visible label
    "Country", a first option "Choose a country" with value `""`, then `country_choices()`;
  - an `<input type="tel" name="question_<id>" id="question_<id>" autocomplete="tel">` with a
    visible label "Phone number";
  - the classes `dropdown.html` and `text_input.html` already use, laid out side by side when wide
    and stacked when narrow;
  - `required`, `disabled` (when `read_only`), `aria-invalid` and
    `aria-describedby="question_<id>_error"` on the number input, as `text_input.html` does. One
    error message serves the group.
- Selected country, first match wins: `rejected.region` when the answer was rejected (an empty
  choice stays empty), the stored answer's `stored_phone_region`, the browser region, then none.
- Number input value: `rejected.text`, else `national_phone(stored answer)`, else empty.
- Changing the country never clears the typed number. With a native select and no script this
  holds without extra work.
- The browser region reaches the template through a simple tag in `form_engine_tags.py`
  (`phone_default_region`), which reads `request.headers` from the context. The `request` context
  processor is enabled in `config/settings_base.py`. Every page that renders `question.html`
  needs no view change.

### Dependency

`phonenumberslite` in `pyproject.toml` and `uv.lock`.

## Testing

- `browser_region`: `en-ZA` → `ZA`; `en-GB,en;q=0.9` → `GB`; `en, fr-FR;q=0.8` → `FR`;
  `fr-FR;q=0.5, de-DE;q=0.9` → `DE`; `zh-Hant-TW` → `TW`; `es-419`, `en`, `*`, `""` and garbage
  → `None`.
- `phone_answer_error` / `e164_phone_answer`: ZA `082 123 4567` → `+27821234567`; `+27 82 123
  4567` with region GB → `+27821234567`; national number with no region → the "Choose a country"
  message; `hello` with ZA → the ZA message with its example; a ZA-invalid number → rejected; an
  Italian number keeps its leading `0` (`IT`, `06 1234 5678` → `+390612345678`); a number with
  `ext. 12` → the extension message; brackets and hyphens accepted.
- `save_answers`: a valid phone answer is stored as E.164; an invalid one is a `RejectedAnswer`
  carrying `text`, `message` and `region`, and the earlier row is untouched; a country with no
  number stores nothing and fails `required`.
- `format_answer` / `answer_display`: E.164 → international format; a legacy `082 123 4567` →
  unchanged.
- Rendering: preselection precedence (rejected region, then stored, then browser region, then
  none); a rejected empty country stays empty; the legacy stored value refills the number input
  raw; `read_only` disables both controls; both controls have labels, and the error is linked by
  `aria-describedby`.
- Export: a phone answer exports as its stored E.164 string through the existing formula-escaping
  path.
- Playwright (`form_engine/tests/playwright/`): a browser with locale `en-ZA` sees South Africa
  preselected, submits `082 123 4567`, and the review page shows `+27 82 123 4567`. With locale
  `en`, nothing is preselected, and submitting a national number shows the "Choose a country"
  error with the typed number kept.
- The demo form `demo_content/functionality_demo_application_form/1. about-you.yaml` still loads
  unchanged.

## Documentation and downstream

- `claude_plugins/fls-content/skills/content-types/resources/form-files.md`, "Phone question
  example": replace "The number itself is not format-validated" with what now happens (a country
  picker preselected from the browser's language, validated, stored in international form). No
  new YAML keys.
- `docs/product/learner-experience.md`: the form-question bullet says a phone number is checked
  against the chosen country.
- Upgrade notes: phone answers stored before this change are not converted. They display and
  export as typed, and they are validated only when resubmitted. `phonenumberslite` is a new
  dependency, and keeping it current keeps validation current.
- Bug APP-1's "reject fewer than 7 digits" stopgap is superseded; its owner drops it.

## Open questions

- Q: Should an exported phone cell show the formula-escaping apostrophe (`'+27821234567`)? → A: Yes, keep `escape_csv_formula` unchanged for every column (assumed default: weakening a security rule for one column needs its own review. Overrule by editing Decisions.)
- Q: Should a typed extension be rejected rather than silently dropped? → A: Rejected, with the message in `phone_answer_error` (assumed default: E.164 cannot hold an extension and silent loss surprises the person. Overrule by editing Requirements → Phone logic.)

## Success criteria

- Submitting `hello` to a phone question is refused with a message naming the value.
- With `Accept-Language: en-ZA`, the country select shows South Africa (+27) before any input; with
  `Accept-Language: en`, it shows "Choose a country".
- `082 123 4567` with South Africa selected is stored as `+27821234567`.
- A `+44…` number typed while South Africa is selected is stored with `+44`.
- Educator and reviewer views show `+27 82 123 4567`; a legacy stored `082 123 4567` still shows
  as typed.
- The phone question works with JavaScript disabled.
- `grep -rn phonenumbers claude_plugins/fls-content` finds nothing.
