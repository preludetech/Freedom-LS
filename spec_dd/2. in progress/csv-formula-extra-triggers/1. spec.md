# Spec: wider spreadsheet-formula escaping for CSV exports

Idea: `idea.md`. Research: `research_*.md` beside it.

## Purpose

`escape_csv_formula` in `freedom_ls/base/csv_safety.py` prefixes `'` only when a cell's first
character is one of `=`, `+`, `-`, `@`, tab or carriage return. A spreadsheet also runs a formula
when the cell starts with a line feed or one of the full-width `＝＋－＠`, or when the trigger
follows leading spaces. Every FLS CSV export goes through this helper and carries text that
learners and visitors typed, so each gap is open in every export at once. When this work is done,
the helper closes all three and no caller changes.

## Scope

In:

- Line feed and the full-width `＝` (U+FF1D), `＋` (U+FF0B), `－` (U+FF0D), `＠` (U+FF20) as
  triggers. They count even if a given spreadsheet does not run them: the cost is one visible `'`.
- A trigger after leading whitespace.

Out:

- A trigger at the start of a later line of a multi-line cell. Spreadsheets read only the cell's
  first character, and a `'` inside a cell is visible and survives re-import, so marking later
  lines would spoil every exported bullet list for no protection.
- Other Unicode lookalikes: the small forms U+FE62, U+FE63, U+FE66, U+FE6B, the minus sign U+2212,
  `｜`, and NFKC normalisation. No authority in `research_best_practices.md` lists them.
- Zero-width, bidi-control, BOM and other characters that `str.isspace()` rejects, in front of a
  trigger. The cell is not escaped.
- Exempting numeric-looking text such as `-5` or `+27…` from escaping. The helper escapes it today
  and still will.
- Escaping that strips the trigger or uses a tab prefix instead of `'`.
- Any change to the callers: `FormulaSafeCSV` in `freedom_ls/site_aware_models/admin_exports.py`,
  the export column cell in `freedom_ls/panel_framework/tables.py`, and `write_error_csv` in
  `freedom_ls/base/csv_import.py`. Panel-export headers are set by developers and stay unescaped
  in `freedom_ls/panel_framework/views.py`.

## Decisions

- **Explicit trigger list, not normalisation.** The four full-width characters go into
  `FORMULA_TRIGGERS` by name, as in `idea.md`.
- **`FORMULA_TRIGGERS` keeps its name and its tuple-of-single-character `str` shape.**
  `freedom_ls/base/tests/test_csv_safety.py` and
  `freedom_ls/site_aware_models/tests/test_admin_exports.py` import it, parametrise over it and
  `sorted()` it.
- **"Whitespace" means what `str.isspace()` means.** That covers space, NBSP (U+00A0), the
  ideographic space U+3000, and also `\v`, `\f` and U+2028, which it accepts as escaping more.
  Tab, CR and LF are triggers in their own right.

## Requirements

### `freedom_ls/base/csv_safety.py`

- `FORMULA_TRIGGERS` becomes
  `("=", "+", "-", "@", "\t", "\r", "\n", "＝", "＋", "－", "＠")`. Write the full-width entries as
  `\uff1d`, `\uff0b`, `\uff0d`, `\uff20` escapes, so the source does not depend on glyph rendering.
- `escape_csv_formula(value: str) -> str` keeps its signature. The cell needs escaping when its
  first character is in `FORMULA_TRIGGERS`, or when its first character that is not whitespace is.
  An empty `value` comes back unchanged. A cell that needs escaping gets `'` prefixed; its leading
  whitespace and the rest of the cell stay as they were, so a clean cell comes back identical. Only
  the start of the cell is checked: a trigger at the start of a later line is left alone.
- The module docstring and the function docstring describe the widened rule in a sentence each,
  without listing the characters.

Expected results, which the tests use as cases:

| input | output |
| --- | --- |
| `"=1+1"` | `"'=1+1"` |
| `"\n=1+1"` | `"'\n=1+1"` |
| `"\nplain"` | `"'\nplain"` |
| `"＝1+1"` | `"'＝1+1"` |
| `"－テスト"` | `"'－テスト"` |
| `" =1+1"` | `"' =1+1"` |
| `"\u00a0@SUM(A1)"` | `"'\u00a0@SUM(A1)"` |
| `"\u3000=1+1"` | `"'\u3000=1+1"` |
| `"plain"`, `""`, `"1+1"`, `"a=b"`, `"   "`, `"one\ntwo"` | unchanged |
| `"note\n=HYPERLINK(\"x\")"`, `"one\r\n  -5\rtwo"`, `"one\r\n\ttab"`, `"Notes:\n- one\n- two"` | unchanged |

### Learner-import error CSV

`write_error_csv` output is meant to be fixed and re-uploaded through `parse_csv`, which strips
whitespace from each cell but not a leading `'`. The new rule adds marks only to cells with leading
whitespace before a trigger, never inside a cell. `csv_import.py` does not change.

## Testing

In `freedom_ls/base/tests/test_csv_safety.py`:

- `test_escape_csv_formula_prefixes_every_trigger` keeps parametrising over `FORMULA_TRIGGERS`, so
  it covers the five new characters with no edit. A separate test pins the tuple's exact contents,
  so a trigger cannot drop out unnoticed.
- One parametrised test covers the escaped rows of the table above. It proves leading-whitespace
  escaping (space, NBSP, U+3000) and that leading whitespace is kept.
- `test_escape_csv_formula_leaves_other_values_alone` covers the unchanged rows, including the
  later-line triggers, so a change that starts marking inside a cell fails a test.

One integration case each proves the widened rule reaches the export:

- `freedom_ls/site_aware_models/tests/test_admin_exports.py`: a body cell with a trigger after
  leading whitespace comes out escaped from `FormulaSafeCSV`.
- `freedom_ls/panel_framework/tests/test_tables.py`: a cell starting with `＝` comes out escaped.

The existing header test in `test_admin_exports.py` parametrises over `sorted(FORMULA_TRIGGERS)`
and reads the CSV back with `csv.reader`. It has to pass for `"\n"` and the full-width entries
unchanged.

## Documentation and downstream

- **Upgrade notes** (`fls-dev:update_upgrade_notes`). Exports now add `'` to more cells, so a
  downstream consumer that re-imports FLS CSVs sees the extra marks.
  First-Class-LMS can delete its `EXTRA_FORMULA_TRIGGERS` / `escape_visitor_text` wrapper in
  `apps/admin_dashboard/lead_csv.py` and call `escape_csv_formula` directly.
- **Panel-framework extraction.** `spec_dd/1. next/extract_panels_framework-3-standalone-backend`
  copies `escape_csv_formula` into the standalone package (`idea.md:14`). That copy has to take this
  version, so that idea gets a line saying so.

## Success criteria

- No file outside `freedom_ls/base/csv_safety.py` and test modules changes under `freedom_ls/`.
- Every row of the expected-results table is a test case in `test_csv_safety.py`, and the suite
  passes.
- A test fails if any entry is removed from `FORMULA_TRIGGERS`.
