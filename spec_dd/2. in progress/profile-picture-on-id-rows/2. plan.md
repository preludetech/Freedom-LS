## Template pattern for an id-only row

Every attention and report row resolves its avatar the same way. Cotton's bound attributes take a
plain variable, not a filter chain, so the lookup and both fallbacks happen in template tags first.
`avatar_user_id` and `avatar_picture_url` are template-local names:

```django
{% with avatar=avatars|lookup:row.learner_id %}
    {% firstof avatar.user_pk row.learner_id as avatar_user_id %}
    {% firstof avatar.picture_url "" as avatar_picture_url %}
    <c-panel-attention-row :subject="row.full_name" :href="learner_url"
        :user_id="avatar_user_id" :picture_url="avatar_picture_url" ...>
{% endwith %}
```

`avatar` is `None` for a learner whose `Learner` row is gone. Never bind `avatar.picture_url`
directly: django-cotton treats an attribute of `None` as unprocessable and silently drops the
attribute, so the c-vars default is not applied either. `firstof` resolves the missing attribute
to the next value, so the chip keys its colour on the `Learner` id and shows initials. Region
templates that do not yet `{% load educator_tags %}` gain it.

## Slices

### Slice 1: Cohort needs-attention rows show the learner's picture

Behaviour: on a cohort's Overview tab, a flagged learner with a profile picture shows it in the
Needs attention card; one without shows initials; the chip colour matches the learners table.

**Builds on:** none
**Touches:** freedom_ls/educator_interface/avatars.py, freedom_ls/educator_interface/tests/test_avatars.py, freedom_ls/educator_interface/templatetags/educator_tags.py, freedom_ls/educator_interface/tests/templatetags/, freedom_ls/panel_framework/templates/cotton/panel-attention-row.html, freedom_ls/panel_framework/tests/components/test_attention_list.py, freedom_ls/educator_interface/reporting.py, freedom_ls/educator_interface/templates/educator_interface/panels/cohort_needs_attention_region.html, freedom_ls/educator_interface/tests/test_reporting.py

1. **Resolver, learner half.** New `freedom_ls/educator_interface/avatars.py`. Imports models only
   (`accounts.models.User`, `learner_management.models.Learner`), never `educator_interface.views`
   or `educator_interface.reporting`, because both of those (and the template tags) import it.

   ```python
   @dataclasses.dataclass(frozen=True)
   class PersonAvatar:
       """A person's avatar as an id-only row needs it: the colour key and the picture."""

       user_pk: int
       picture_url: str | None


   def learner_avatars(learner_ids: Iterable[UUID]) -> dict[UUID, PersonAvatar]:
       """Each learner's user pk and picture URL, in one query.

       Report and attention rows carry a Learner pk, so the user is reached
       through Learner, never by treating the id as a User pk. A Learner that
       no longer exists is absent. No is_active filter: an inactive user
       keeps their picture.
       """
       ids = set(learner_ids)
       if not ids:
           return {}
       learners = (
           Learner.objects.filter(pk__in=ids)
           .select_related("user")
           .only("pk", "user", "user__profile_picture")
       )
       return {
           learner.pk: PersonAvatar(learner.user.pk, learner.user.profile_picture_url)
           for learner in learners
       }
   ```

   Tests in `freedom_ls/educator_interface/tests/test_avatars.py`, from the spec's resolver list:
   an empty iterable makes no query; a generator is read once (pass a generator, assert the result
   still holds its ids); a learner id maps to its user's pk and URL, and reading `picture_url` makes
   no further query; an unknown id is absent; a user without a picture gives `picture_url` `None`.

2. **The `lookup` filter.** In `freedom_ls/educator_interface/templatetags/educator_tags.py`:

   ```python
   @register.filter
   def lookup[K, V](mapping: Mapping[K, V], key: K) -> V | None:
       """`mapping[key]`, or None when absent, for a key held in a template variable."""
       return mapping.get(key)
   ```

   Test in `freedom_ls/educator_interface/tests/templatetags/test_educator_tags.py` (new directory
   with an empty `__init__.py`): a present key gives its value, a missing key gives `None`. Run the
   `test-mirroring` pre-commit hook after adding the directory.

3. **`panel-attention-row` takes `picture_url`.** In
   `freedom_ls/panel_framework/templates/cotton/panel-attention-row.html`: add `picture_url=""` to

   comment block, under `user_id`:

   ```

   ```

4. **The cohort needs-attention panel.** `CohortNeedsAttentionPanel.get_loaded_context` in
   `freedom_ls/educator_interface/reporting.py`:

   ```python

   return {
       "attention": attention,
       "avatars": learner_avatars(learner.learner_id for learner in attention.learners),

   ```

   `cohort_needs_attention_region.html` loads `educator_tags` and renders each row by the template
   pattern above.

   Tests in `freedom_ls/educator_interface/tests/test_reporting.py`, through `_attention_region`:
   - a flagged learner with a picture renders `img[data-profile-picture]` with their URL;
     one without renders none and no `src="None"`;
   - a row whose `Learner` was deleted after the progress was cached renders a chip with initials,
     without error;
   - 25 flagged learners with pictures cost no more queries than one
     (`CaptureQueriesContext` on one, `django_assert_max_num_queries` on 25). Region pages are

### Slice 4: The audit log shows the who and target pictures

1. **Resolver, user half**, in `avatars.py`:

   ```python
   def user_picture_urls(user_pks: Iterable[int]) -> dict[int, str]:
       """Picture URLs by user pk, in one query; only users with a picture are present.

       Audit log callers already hold the user pk, so only the URL is returned.
       """
       pks = set(user_pks)
       if not pks:
           return {}
       users = User.objects.filter(pk__in=pks).only("pk", "profile_picture")
       return {
           user.pk: url for user in users if (url := user.profile_picture_url) is not None
       }
   ```
