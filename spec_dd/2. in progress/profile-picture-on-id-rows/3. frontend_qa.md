# Frontend QA: Profile picture on id-only rows

Checks, in a browser, that a person with a profile picture shows it on the dashboard attention
list, the cohort Needs attention card, the on-screen cohort report and the audit log, that a person
without one shows initials, and that nothing else changed (the PDF report, deleted users, system
entries, avatar colours).

## Setup

1. Build the stylesheet: `npm run tailwind_build`.
2. Migrate: `uv run python manage.py migrate`.
3. Start the server on a free port: `uv run python manage.py runserver $PORT`. Base URL:
   `http://127.0.0.1:$PORT`.
4. Log in at `http://127.0.0.1:$PORT/accounts/login/` with the QA login from
   `.claude/sdd/config.md` (`## QA Login`). This user is the **admin**, an organisation admin.
   Note the organisation slug the educator interface opens on (`/educator/<org>/`).
5. Data, from the QA data helper, on the site being browsed, in the admin's organisation:
   - A cohort, **Cohort P**, registered for a course with at least one topic.
   - Three learners in Cohort P who have not started, so each is flagged as needing attention:
     - **Pia Picture**, with a profile picture (any small square WebP or PNG in a distinctive
       colour, stored through `User.profile_picture`, e.g. `profile_picture.save(...)`).
     - **Nadia Noface**, with no picture.
     - **Gone Learner**, with no picture (used in Test 6).
   - A user **Tariq Target** with a profile picture who is a learner in the organisation.
   - A user **Ava Actor** with a profile picture who is staff in the organisation.
   - Audit log entries in the organisation, written through the audit-log writer the app already
     uses (or `AuditLogEntryFactory`), so they look real:
     - actor Ava Actor, target Tariq Target (a person target);
     - actor Nadia Noface's user (no picture), target Pia Picture;
     - a bulk run: a run summary whose run entries have actor Ava Actor and targets Pia Picture and
       Nadia Noface;
     - a **deleted actor** entry: actor label "Deleted Person", actor `None`;
     - a **system** entry: no actor label, no actor.
   Report each user's name and the cohort pk and learner pks.
6. Before any page is opened, warm nothing: the first load of each panel gathers the figures.

Viewports: 1920, 768 and 375. "No sideways scroll" means
`document.documentElement.scrollWidth <= window.innerWidth`. Keep the console open throughout: a
JavaScript error or a failed image request shows there.

"Shows the picture" means an `<img data-profile-picture>` inside the round avatar, with `alt=""`,
showing the person's stored image. "Initials alone" means the round avatar holds the initials and
no `<img>`. In every test, inspect the DOM: no element anywhere has `src="None"`.

## Test 1: Dashboard attention list

1. As the admin, open `http://127.0.0.1:$PORT/educator/<org>/` (the dashboard). Click "Load the
   figures" if the card shows it.
2. In the attention list, expect a row for Pia Picture that shows the picture beside the name, and
   rows for Nadia Noface and Gone Learner with initials alone.
3. The avatar is small, centred on the name's first line, and sits beside the name exactly as
   before; the per-cohort detail ("Cohort P", Courses …) and the quick-view trigger are unchanged.
4. Click Pia Picture's name: it goes to her learner page. Go back. Click the quick-view trigger:
   the quick view opens.
5. At 375: the whole row is the tap target, the trailing "next" icon shows, no sideways scroll, and
   the picture is not clipped or stretched.
6. Reload the dashboard: the pictures still show (the cached figures carry no URL; the page looks
   them up each time).

## Test 2: Avatar colour matches the learners table

1. On the dashboard, inspect Nadia Noface's avatar and note its `panel-avatar-N` class.
2. Open `http://127.0.0.1:$PORT/educator/<org>/learners` and inspect Nadia Noface's avatar in the
   table.
3. Expect the same `panel-avatar-N` class (and so the same colour) in both places.
4. Repeat for Gone Learner on the cohort's Needs attention card (Test 3) against the learners
   table.

## Test 3: Cohort Needs attention card

1. Open Cohort P (`http://127.0.0.1:$PORT/educator/<org>/cohorts/<cohort pk>`), Overview tab. Load
   the Needs attention card if it asks.
2. Expect Pia Picture's row to show the picture, the other two initials alone. The learner badges
   (completion, flags) sit under the name as before.
3. Check at 1920, 768 and 375: no sideways scroll, the avatar sits on the name's first line.

## Test 4: On-screen cohort report

1. Open Cohort P's Report tab (`…/cohorts/<cohort pk>/__tabs/report`). Load the figures.
2. In "Learners needing attention", Pia Picture shows the picture; the others show initials alone.
3. In "Summary of learner progress", the Learner column shows Pia Picture's picture beside her
   name, and initials for the others. If the course has more quiz columns than fit one table and
   the summary continues in a second table, the pictures show there too.
4. The sticky Learner column still sticks when the table scrolls sideways at 375 and 768, and the
   picture does not overlap the next column.
5. Click "Refresh" (or the refresh control the report shows): after the reload the pictures still
   show.
6. Download the PDF report from the report's downloads card. Open it: every learner shows initials
   or names exactly as before, with no profile pictures anywhere.

## Test 5: Audit log

1. Open the organisation audit log, `http://127.0.0.1:$PORT/educator/<org>/audit-log`.
2. Ava Actor → Tariq Target entry: the Who cell shows Ava's picture, the Target cell shows Tariq's.
3. Nadia Noface → Pia Picture entry: Who is initials alone, Target shows Pia's picture.
4. The deleted-actor entry: Who shows "Deleted Person" beside the neutral circle with a person icon,
   no picture.
5. The system entry: Who shows the "System" chip with the settings icon, no picture.
6. Expand the bulk run summary's detail: under Entries, each run entry's actor reads "Ava Actor"
   with no avatar (the summary row above already shows Ava's picture), and the targets show Pia's
   picture and Nadia's initials.
7. Sort by Who and by Target, and filter by Who (Ava Actor): the table behaves as before and the
   pictures stay with the right people.
8. At 375 the log renders as cards: the Who and Target lines show the same pictures and chips as
   the table did. No sideways scroll.
9. Open Tariq Target's learner page, History tab (`…/learners/<pk>/__tabs/history`): the entry
   naming him shows Ava's picture as Who and Tariq's as Target. Open Cohort P's History tab: any
   entry shown keeps the same rules.

## Test 6: Pictures follow the live user

1. Ask the QA data helper to remove Tariq Target's profile picture (clear `profile_picture`).
2. Reload the audit log: the Ava → Tariq entry now shows Tariq with initials alone. No broken image.
3. Ask the QA data helper to delete Gone Learner's `Learner` row (leave the cohort's cached figures
   in place; do not clear the cache).
4. Reload the dashboard and Cohort P's Needs attention card and Report tab without refreshing the
   figures. Gone Learner's row (if still listed from the cached figures) shows a chip with
   initials and no error; the page renders fully. Refreshing the report drops the row.

## Test 7: A picture that fails to load

1. On the dashboard, set Pia Picture's `<img data-profile-picture>` `src` to a URL that 404s
   (for example with `browser_evaluate`), without reloading.
2. Expect the initials to show in the circle instead of a broken image, as on the learners table.
