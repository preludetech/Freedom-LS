## Elsewhere: public write-ups (search summaries, unverified)

- Keep verbose output out of the main context: run test runs and log processing in a subagent that returns a summary; filter test output to the failing test, trace and expected-versus-received; cap command output (`BASH_MAX_OUTPUT_LENGTH`); `/clear` between features; compaction instructions in CLAUDE.md. Caveat noted by sources: each subagent adds its own prompt overhead, so it only pays when the main thread would be flooded. FLS already does all of these via `sdd-mechanic` and `run_tests.sh` verdict lines.

- Test frequency for agents: "always run the full suite" instructions burn budget parsing irrelevant results; recommended is dependency-graph impact analysis (reverse import graph from changed files), an explicit path-to-test mapping, the full suite reserved for shared modules, and a scheduled or milestone full run as a safety net, with recall measured on skipped tests. This is what FLS's tiers already implement. A cited 2026 paper, TDAD (arXiv:2603.17973), reports regression drops with an impact map (figures unverified by us). Static analysis misses dynamic dispatch.

- Bounded repair is the pattern for flaky/failing tests: cap the number of fix attempts, record the cause, then escalate (the TDAD-adjacent "phase gates, bounded repair" write-up above). FLS already caps at three attempts in `rebase_main.md` Step 9 and two retries in `implement_plan.md`.

## Takeaways for the spec

1. The tier machinery exists and works. The efficiency gain is now in call-site policy, not new selection tech. Count the full runs a typical spec cycle still triggers: implement_plan final, implement_plan fix-loop repeats, QA's after-last-fix full, qa_fix full, finish_worktree Step 1 full, plus finish_worktree rebase and exit-7 retry as full. The agreed "milestones" in `make-sdd-more-efficient` were three; the current code has more.
2. A likely cheap win: let a full run's green result be reused when nothing test-visible changed since (record the tested tree/commit and the tier in `todo.md` or `.sdd-work/`, skip when `select_tests.sh --range <tested>..HEAD` is `none`). Not tried before; no prior spec records it.
3. finish_worktree: on exit 7 or a moved main, loop rebase (targeted unless escalation says full) and land, instead of stopping after one retry. Handle a failing test by checking whether it also fails on `origin/main`, or re-running it alone, before declaring failure. Answers.md already fixes the fix location as the current branch.
4. Reconcile with prior "Stops that stay" decisions (dirty main worktree, upstream `direction: changed`) rather than overriding them quietly.
5. For docs: no diagram precedent beyond the roadmap SVGs. The prose workflow lives in `claude_plugins/sdd/README.md` and `claude_plugins/sdd/commands/README.md`; both mention address_pr_review and the old checklist.
6. For token work: no baseline exists. Measure first (which command files are largest, read counts per run), and remember the tidy-up spec already applied "writing for agents" once.
