# Spec: SDD efficiency and docs

Idea: `idea.md`. Up-front answers: `answers.md`. Research: `research_*.md` in this directory.

## Purpose

An SDD cycle is slow, mostly because of repeated full test runs. Measured from the current
commands (`research_codebase.md` §1.2–1.4), a normal cycle runs the full suite 2–4 times, a
long-lived one 4–7 times, and many of those runs are on code that has not changed since the last
green run. `finish_worktree` stops on states it could fix itself, the command files cost more tokens
than they need to, and nothing shows the process as a picture. This spec covers six things: full
runs only at named checkpoints, a rebase that does not test a branch with no code changes, a
`finish_worktree` that recovers on its own, a measured token trim, removal of unused steps, and
draw.io diagrams of the process.

## Terminology

- **Full-run record**: the commit SHA of the last full tier that passed in this worktree, kept in
  `.sdd-work/full_green_<branch>.txt` (gitignored, per worktree). It is written only by a passing
  full run and is never written from a failure or a skip.
- **Checkpoint tier**: a new `<tier>` value, `checkpoint`, for `run_test_tier.md`. It runs the full
  tier when there is no full-run record. When there is one, it runs whatever the selector picks for
  `git diff --name-only <record> HEAD`: `none` skips, `targeted` runs targeted tests over that
  range, and `full` runs the full tier.
- **Spec-only change**: a set of paths that all fall under the project's spec root, the directory
  the sdd config names for specs (`spec_dd/` in FLS).

## Scope

In:

- Full-run checkpoints, the full-run record and the checkpoint tier.
- Rebase test selection and pre-commit scope for a branch that holds no code changes.
- `finish_worktree` self-recovery: the main-moved loop, pushing main, spec-only dirty or changed
  state, force-push, and flaky tests.
- The token audit and trim of every file an SDD run loads: sdd commands, resources and agents, plus
  the ds and fls-dev skills, commands and resources that SDD runs read.
- Removing `address_pr_review` and everything that exists only for it, plus a list of other
  candidates for the user to confirm.
- `.drawio.svg` diagrams of the SDD process, and a check that keeps them in sync with the commands.

Out:

- Finishing several worktrees at once (`spec_dd/0. maybe/better-finish-worktree-command`).
- CI changes (`.github/workflows/tests.yml` keeps its full run on the PR).
- Making individual tests faster, and changing the rebase's rebuild step.
- Editing the `address_pr_review` line in other specs' `todo.md` files. Those files belong to other
  worktrees, and the dead line does no harm.
- Deleting any candidate from the unused-steps audit other than `address_pr_review`. The candidates
  are only listed (see Open questions).

## Decisions

- **Two full-run checkpoints:** the end of `implement_plan`, and landing in `finish_worktree`. Every
  other step runs targeted tests or the checkpoint tier. CI covers the PR, so a third local full run
  adds no proof.
- **The full-run record is keyed by commit, and selection uses a tree diff** (`git diff <record>
  HEAD`, not `<record>..HEAD`). This keeps working after a rebase, when the recorded commit is no
  longer an ancestor of HEAD.
- **The selector stays authoritative.** The checkpoint tier never skips on its own judgement. It
  skips only when `select_tests.sh` returns `none` over the range since the record, so the existing
  escalation globs (migrations, `pyproject.toml`, `uv.lock`, `config/**` and so on) still force a
  full run.
- **pytest-testmon is not adopted.** It does not track templates, and the earlier tier spec
  (`spec_dd/3. done/2026-10-09_09:03_make-sdd-more-efficient/`) rejected it.
- **A flaky-test fix lands on the branch being finished**, as its own commit (answers.md).
- **Diagrams are hand-authored in uncompressed draw.io XML**, with a script check rather than a
  generator. A generator gives plainer layouts, and the check catches the drift that matters
  (answers.md).
- **Generic plugins stay generic.** The spec root, the flaky-test guide and the diagram `none` glob
  reach `sdd` and `ds` only through `.claude/sdd/config.md`, `.claude/ds/config.md` or
  `pyproject.toml [tool.test_tiers]`.

## Requirements

### Test checkpoints (`claude_plugins/sdd`)

1. **`commands/protected/run_test_tier.md`** accepts `<tier>: checkpoint`, as defined under
   Terminology. Every pass of `<tier>: full` (asked for directly, or reached through `checkpoint`)
   writes the full-run record with HEAD's SHA. The report line names the tier that actually ran and
   why, for example `tests: none (no test-visible change since full green at abc1234)` or
   `tests: targeted (range abc1234..HEAD)`. A skip is always reported as a skip, never as a pass.
   The full-run record lives in sdd; the selector is called through the tier definition, so `ds`
   needs no change for this.
2. **`commands/implement_plan.md` Step 3** keeps `<tier>: full`. When that run fails, the fix
   sub-agent re-runs the failing tests with `--lf` until they pass, then runs `targeted` over the
   fix's range. The command does not repeat the full run (it currently does, at
   `implement_plan.md:124`). The finish checkpoint covers the fixes.
3. **`commands/do_qa.md`**, "Full run after the last fix" (around `:737`): becomes `<tier>:
   checkpoint`.
4. **`commands/qa_fix.md` Step 7**: becomes `<tier>: checkpoint`.
5. **`commands/finish_worktree.md` Step 1**: becomes `<tier>: checkpoint`. The `Pre-test rebuild`
   runs only when the checkpoint resolves to `targeted` or `full`. The "Step 0's rebase reported
   `tier: full`" shortcut goes, because the full-run record replaces it.
6. **`commands/plan_from_spec.md:66`**: the rule that every slice is committable "with the full test
   suite passing" becomes "with its targeted tests passing".

### Rebase (`claude_plugins/django-stack/commands/rebase_main.md`, `claude_plugins/sdd/commands/protected/pre_step_rebase.md`)

7. **Step 9 (tests):** when the branch diff `origin/main..HEAD` selects `none`, run no tests and
   return `tier: none`, whatever main's own diff selects. The branch's code is then main's code, and
   main has already been tested. When the branch diff selects something, Step 9 works as it does
   today.
8. **Step 10 (pre-commit):** run on the files the branch changed (`pre-commit run --from-ref
   origin/main --to-ref HEAD`), not `--all-files`.
9. **`finish_worktree.md` Step 0 and the exit-7 path** stop hard-coding `<tier>: full` for the
   rebase. They use the default tier, and the full-run record decides what Step 1 runs.

### `finish_worktree` self-recovery (`claude_plugins/sdd/commands/finish_worktree.md`, `claude_plugins/sdd/scripts/land_on_main.sh`)

The rule: fix what can be fixed, continue, and log each auto-fix in the final report. Stop only on
the states listed under Requirement 15.

10. **Main moved (exit 7):** loop. Each pass runs the rebase command (default tier), the checkpoint
    tier, then `land` again. The loop ends when `land` succeeds. It stops only when the same blocker
    repeats five passes in a row (`status: blocked · reason: origin/main moved 5 times in a row`).
11. **Local main ahead of origin with no worktree on main** (`land_on_main.sh:137-142`, currently
    exit 3, "push main yourself"): the script pushes `main` itself with `git push origin
    main:main`, which needs no checkout. A rejected push re-fetches and goes through the
    main-moved loop.
12. **Dirty main worktree** (`land_on_main.sh:92-96`, uncommitted change overlapping the incoming
    files): when every overlapping path is a spec-only change, commit those paths in the main
    worktree as their own commit, push `main`, and continue through the main-moved loop. When any
    overlapping path is outside the spec root, stop as today. The spec root comes from a new key
    under `## Worktree Scripts` in `.claude/sdd/config.md`, `Spec root: spec_dd/`, which
    `land_on_main.sh` takes as an argument.
13. **Upstream change review `direction: changed`** (`pre_step_rebase.md` Steps 3–5): when every
    path main brought in is a spec-only change, continue without pausing. Otherwise pause as today.
14. **Force-push:** the rebase's `git push --force-with-lease --force-if-includes` runs as it does
    now. When the push is denied (a permission refusal or a protected branch), return `status:
    paused · reason: force-push needed: <exact command>`. Re-running `/sdd:finish_worktree` after
    the user runs that command continues from where it stopped.
15. **Conflicts during the rebase:** a conflict whose paths are all spec-only changes is resolved
    without asking: the branch's version for its own spec directory, main's version for any other.
    A conflict in any other path stops (`blocked`), as today. `rebase_main.md` Step 6 takes the
    spec-only paths through a new ds config key, `Auto-resolve paths`, and `pre_step_rebase.md`
    passes the branch's own spec directory as the "keep ours" path.
16. **Flaky tests at the checkpoint:** when the checkpoint run fails:
    1. Re-run each failing test on its own, three times (`--lf`, `--no-cov`, in the targeted
       runner). A test that fails all three times is a real failure, and the command stops with
       `status: failed`, as today.
    2. A test that passes at least once is flaky. Spawn one `general-purpose` sub-agent (not
       `sdd-mechanic`) per flaky test. Its brief names the test, the failure output, and the file
       named by a new `Flaky test guide` key under `## Test Hooks` in `.claude/sdd/config.md`. The
       sub-agent finds and fixes the root cause on the current branch. It never skips, deletes or
       marks the test to get a pass. It proves the fix by running the test 10 times in a row with
       no failure, then commits it as `fix flaky test <test id>`.
    3. Each test gets at most two fix attempts. When both fail, stop with `status: failed · reason:
       flaky test <id> not fixed: <diagnosis>`.
    4. After the fixes, re-run the checkpoint tier and continue.
17. **FLS flaky-test guide:** a new section in `claude_plugins/fls-dev/skills/testing/SKILL.md`, or
    a resource it links, covers the FLS causes: shared DB state and transaction leakage,
    `transaction=True` browser tests, Playwright timing, factory randomness, bare sleeps and
    ordering. `.claude/sdd/config.md` points `Flaky test guide` at it.
18. **The final report** lists every auto-fix (main pushed, main-worktree spec commit, rebase
    passes, flaky fixes with their commits) and every test decision line from Requirement 1.

### Token efficiency

19. **Baseline:** a script, `claude_plugins/sdd/scripts/measure_prompt_size.py`, prints lines,
    words and approximate tokens (characters / 4) for each file an SDD command loads. That is every
    file under `claude_plugins/sdd/{commands,resources,agents,skills}`, plus the ds and fls-dev
    files named by `.claude/sdd/config.md` or referenced from sdd commands. It takes the file list
    from config and globs, never from FLS paths written into the script. Its output before the trim
    is saved as `token_baseline.md` in this spec directory, and its output after as
    `token_after.md`.
20. **Trim rules.** No rule or instruction is lost. Each one is moved, merged with its duplicate,
    or kept.
    - Rationale written for humans moves out of agent-loaded files and into
      `claude_plugins/sdd/commands/README.md` or the diagrams.
    - Any command over 500 lines is split, with rarely used branches moved to one-level-deep
      reference files that the command names and reads only on that branch. Today that is
      `do_qa.md` (852 lines).
    - `pre_step_rebase.md` is split so the up-to-date path reads only Steps 0–2 and the return
      contract. Steps 3–5 (the upstream-change scan and review) move to
      `protected/upstream_change_review.md`, which is read only when the scan exits 2.
    - Dense paragraphs in `implement_plan.md` (`:36-81`) become numbered steps or tables.
    - A repeated shell sequence becomes a script.
21. **Quality guard:** the existing tests that read prompt files (`tests/test_test_tiers.py`,
    `tests/test_update_concrete_projects.py`) still pass, and every file keeps a heading structure a
    human can scan.

### Diagrams (`claude_plugins/sdd/docs/diagrams/`)

24. One `.drawio.svg` per flow, saved with **uncompressed** XML:
    - `overview` (start to finish, with each command as one box linking to its diagram)
    - `start`, `spec_from_idea`, `plan_from_spec`, `implement_plan`, `do_qa`, `qa_fix`,
      `document`, `finish_worktree`
    - `rebase` (`pre_step_rebase.md` together with `rebase_main.md`)
25. Each diagram uses swimlanes for Human, Orchestrator (depth 0), Sub-agents, Hooks (config
    keys) and Git/Tests. Decisions are diamonds. A hook box is labelled with its config key, never
    an FLS value. Test runs are coloured by tier (none, targeted, checkpoint, full), with a legend
    on each diagram. A call to the rebase flow appears as one box, labelled "Pre-step rebase", that
    points to `rebase.drawio.svg`. `implement_plan` shows the orchestrator reading the plan, the
    batches and waves, the sub-agents and their targeted runs, the Design check and Batch review
    hooks, and the Step 3 full run. Every diagram shows where the checkpoint and full runs sit.
26. `claude_plugins/sdd/commands/README.md` embeds each diagram (`![<alt>](../docs/diagrams/<name>.drawio.svg)`),
    each with alt text and a two-to-four-line summary. The README becomes the human-facing guide,
    holding the rationale that moves out of command files under Requirement 20.
27. **Sync check:** `claude_plugins/sdd/scripts/check_diagrams.py` reads each diagram's embedded
    XML and its command file. It fails when a `Step N` heading in the command (`#`/`##`, title
    included, for example `Step 1: Full tier`) has no diagram label starting with the same text,
    or when a diagram's `Step N` label names a step the command lacks. A test in `tests/` runs it.
28. `pyproject.toml [tool.test_tiers] none` gains `claude_plugins/**/*.drawio.svg`, so adding or
    editing a diagram selects no tests.

## Testing

- `run_test_tier` checkpoint: with no record it runs full and writes the record. With a record and
  only `spec_dd/**` changed, it reports `none` with the skip reason. With a record and an app file
  changed, it runs targeted over the range. With a record and `uv.lock` changed, it runs full. A
  failed full run writes no record. A record from before a rebase still selects correctly. The
  record logic lives in a script under `claude_plugins/sdd/scripts/` so these run as pytest tests
  in `tests/`.
- `land_on_main.sh`: new tests next to its existing ones (in `tests/`), against a temporary git
  repo with an origin:
  - local main ahead with no main worktree is pushed (exit 0, not 3)
  - a dirty main worktree whose overlapping paths are all under the spec root is committed and
    landed
  - one with an overlapping code path still exits 3
- `rebase_main.md` Step 9: the selector call with a spec-only branch diff and a main diff touching
  `pyproject.toml` gives `tier: none`. Covered through `select_tests` tests if the branch-first rule
  lives in the script.
- `check_diagrams.py`: passes on the committed set, fails when a step heading is renamed, and fails
  when a diagram names a step that does not exist.
- `measure_prompt_size.py`: lists every sdd command and resolves config-named files.
- Removals: no file in the repo (outside `spec_dd/`) mentions `address_pr_review` or
  `fetch_pr_comments`.
- Flaky-test path: one manual run of `finish_worktree` against a branch carrying a deliberately
  order-dependent test, recorded in the QA plan.

## Documentation and downstream

- `claude_plugins/sdd/commands/README.md`: rewritten around the diagrams. It names the two
  checkpoints, the full-run record, the self-recovery rules, and when a `finish_worktree` run
  stops.
- `claude_plugins/sdd/commands/init.md`: documents the new config keys (`Spec root`, `Flaky test
  guide`, ds `Auto-resolve paths`), with their defaults: blank `Spec root` means no spec-only
  shortcuts, and blank `Flaky test guide` means the sub-agent works without a guide.
- `claude_plugins/django-stack/README.md` and `resources/test_tiers.md`: the branch-first rebase
  rule and the scoped pre-commit.
- Downstream projects using the plugins get the new optional config keys, and lose
  `## PR Hooks` and `fetch_pr_comments.sh`. `/sdd:document`'s upgrade-notes hook records both.

## Open questions

Assumed defaults (the spec proceeds on these unless the user says otherwise):

- The main-moved loop gives up after 5 consecutive passes with the same blocker.
- A local `main` that has diverged from `origin/main` (both have unique commits) still stops
  `finish_worktree`. Answers.md does not cover it, and resolving it would rewrite unpushed commits.
- Flaky fixes get two attempts per test, and are proved by 10 consecutive passes.

Unused-steps candidates for the user to keep or remove (`research_codebase.md` §8). This spec
removes none of them:

- `/sdd:spec_review` as a standalone command. `spec_from_idea` runs the same review wave, and the
  last tick of the standalone command was on 2026-10-22.
- `/sdd:make_pr_quickly` as a standalone command. `/sdd:document` Step 3b opens the PR.
- `/sdd:commit_quickly`, used ad hoc and not on the checklist.
- `/sdd:capture_feedback`, a 17-line wrapper over the `capture-feedback` skill.
- `finish_worktree` Step 5 (tidy Claude project settings).
- The upstream-change scan and review (`pre_step_rebase.md` Steps 3–5). No done spec records a
  `direction: changed` verdict.

## Success criteria

- In a cycle where main does not move and QA fixes nothing, the full tier runs once
  (`implement_plan` Step 3), and `finish_worktree` reports `tests: none` with the record SHA.
- A branch whose diff from main is only under `spec_dd/` runs no pytest during any pre-step rebase,
  even when main brought in `pyproject.toml` or migration changes.
- `pre-commit` in a rebase checks only the branch's changed files.
- `finish_worktree` lands without stopping when main moved, when local main was unpushed, or when
  the main worktree held uncommitted spec-only changes, and its report lists each auto-fix.
- `finish_worktree` stops on a code conflict, on a test that fails three isolated re-runs, and
  pauses with the exact command when a force-push is denied.
- A flaky test at finish ends with a `fix flaky test <id>` commit on the branch and a landed
  branch.
- `token_after.md` shows a lower total than `token_baseline.md`, and no instruction from the
  baseline files is missing (each moved, merged or kept).
- `grep -r address_pr_review` and `grep -r fetch_pr_comments` outside `spec_dd/` return nothing.
- Every diagram opens in draw.io, renders as an image in GitHub's markdown preview of
  `claude_plugins/sdd/commands/README.md`, and passes `check_diagrams.py`.
- No FLS name or path appears in `claude_plugins/sdd`, `claude_plugins/django-stack` or
  `claude_plugins/productivity` as a result of this work.
