# Spec: SDD efficiency and docs

Idea: `idea.md`. Up-front answers: `answers.md`. Research: `research_*.md` in this directory.

## Purpose

An SDD cycle runs the full test suite 2–7 times, often on code no test can tell apart from the last
green run (`research_codebase.md` §1.3). `finish_worktree` stops on states it could fix, the
command files cost more tokens than they need, and no picture shows the process. This spec makes
full runs happen only where they prove something, makes `finish_worktree` recover on its own, trims
the prompts against a measured baseline, removes `address_pr_review`, and adds draw.io diagrams.

## Terminology

- **Spec root**: `spec_dd/`, the directory layout sdd already builds in (`spec_dd/1. next/`,
  `2. in progress/`, `3. done/`). It is the sdd plugin's own convention, not a project value.
- **Spec-only change**: a change whose paths all fall under the spec root.
- **Full-run record**: the commit SHA of the last full tier that passed in this worktree, kept in
  `.sdd-work/full_run_record_<branch>.txt` (gitignored, per worktree). Only a passing full run on a
  clean working tree writes it. A failed run, a `RESULT INCOMPLETE` run, a skip, or a run on a dirty
  tree writes nothing.
- **Checkpoint tier**: a new `<tier>` value, `checkpoint`, for `run_test_tier.md`. It resolves to a
  real tier, using the selector of the `Test tiers` definition (blank `Test tiers` → `full`):
  1. the branch diff `origin/main..HEAD` selects `none` (a spec-only branch) → `none`
  2. no full-run record, or the recorded SHA no longer resolves → `full`
  3. otherwise, whatever `select_tests.sh --range <record>..HEAD` selects (`git diff` treats that
     range as a tree diff, so it works after a rebase moved the record off the branch). The
     selector's escalation globs (migrations, `pyproject.toml`, `uv.lock` and the rest) still force
     `full`, including ones main brought in.
- **Full-run point**: a step that asks for `<tier>: full` outright. There are two (Decisions).

## Scope

In:

- The checkpoint tier, the full-run record and the two full-run points.
- Rebase test scope and pre-commit scope.
- `finish_worktree` self-recovery: main moving, an unpushed main, a dirty main worktree, spec-only
  upstream changes and conflicts, force-push, flaky tests.
- A token audit and trim of every file an SDD run loads: sdd commands, resources and agents, and the
  ds and fls-dev files that SDD runs read.
- Removing `address_pr_review` and what exists only for it.
- `.drawio.svg` diagrams of the process, with a sync check.

Out:

- Finishing several worktrees at once (`spec_dd/0. maybe/better-finish-worktree-command`).
- CI changes. `.github/workflows/tests.yml` keeps its full run on the PR.
- Faster individual tests, and the rebase's rebuild step.
- The `address_pr_review` line in other specs' `todo.md` files, which belong to other worktrees.
- Removing anything in `unused_step_candidates.md`.
- A local `main` that has diverged from `origin/main` still stops `finish_worktree`: resolving it
  would rewrite another process's unpushed commits.

## Decisions

- **Two full-run points:** `implement_plan` Step 3 and nothing else asks for `full`. QA, `qa_fix`
  and `finish_worktree` use the checkpoint tier, which runs `full` only when there is no record or
  the selector escalates. CI runs the full suite on the PR, so a habitual third local run adds no
  proof.
- **Generic plugins stay generic.** New project values reach `sdd` and `ds` only through
  `.claude/sdd/config.md`, `.claude/ds/config.md` or `pyproject.toml [tool.test_tiers]`. FLS
  content goes in `fls-dev`.
- **Diagrams** are authored as uncompressed draw.io XML, exported by the draw.io CLI, and checked by
  a script (answers.md).

## Requirements

### Test runs (`claude_plugins/sdd`)

1. **`commands/protected/run_test_tier.md`** accepts `<tier>: checkpoint` as defined under
   Terminology, and every passing full run writes the full-run record. The record logic lives in a
   script, `claude_plugins/sdd/scripts/full_run_record.py` (`read`, `resolve`, `write`), so it is
   testable. The report line keeps the existing contract and names the tier that ran and why:
   `tier: none · summary: no test-visible change since full green at abc1234`, or
   `tier: targeted · summary: range abc1234..HEAD`. A skip never reads as a pass.
2. **`commands/implement_plan.md` Step 3** keeps `<tier>: full`. When it fails, the fix sub-agent
   re-runs the failing tests by node ID until they pass, then runs `targeted` over the fix's range.
   It does not repeat the full run (it does today, at `:124`). The checkpoint tier in
   `finish_worktree` Step 1 covers the fixes.
3. **`commands/do_qa.md`** "Full run after the last fix" (`:737`) and **`commands/qa_fix.md`**
   "Step 7: Full run" become `<tier>: checkpoint`, and their headings say so.
4. **`commands/finish_worktree.md` "Step 1: Full tier"** becomes "Step 1: Checkpoint tier" and runs
   `<tier>: checkpoint`. The `Pre-test rebuild` runs only when the checkpoint resolves to `targeted`
   or `full`. The "Step 0's rebase reported `tier: full`" shortcut goes: the record replaces it.
5. **`commands/plan_from_spec.md:66`**: "with the full test suite passing" becomes "with its
   targeted tests passing".

### Rebase (`claude_plugins/django-stack/commands/rebase_main.md`, `claude_plugins/sdd/commands/protected/pre_step_rebase.md`)

6. **`finish_worktree.md` Step 0 and the main-moved loop** pass `<tier>: none` to the rebase
   instead of `<tier>: full`. The checkpoint tier that follows decides what runs, so each pass tests
   once.
7. **Step 10:** pre-commit runs on the branch's changes (`pre-commit run --from-ref origin/main
   --to-ref HEAD`), not `--all-files`.
8. **The main-moved loop** calls the `Rebase command` directly, as Step 7 does today, because the
   pre-step rebase skips a spec already under `3. done/`. `finish_worktree` therefore passes the
   auto-resolve list (Requirement 14) to the rebase itself. The upstream-change review does not run
   for a finished spec.

### `finish_worktree` self-recovery (`commands/finish_worktree.md`, `scripts/land_on_main.sh`, `scripts/upstream_change_scan.sh`)

`finish_worktree` fixes what it can and continues, and lists each auto-fix in its report. It stops
only on the states Requirements 9, 11, 12, 13, 14 and 15 name, and on a diverged main (Scope).

9. **Main moved (exit 7):** loop. Each pass runs the rebase (Requirements 6 and 8), the checkpoint
   tier and `land`. A pass whose rebase replays without a code conflict continues; only a code
   conflict (Requirement 14) stops it. After five passes in a row end with the same blocker, return
   `status: blocked · reason: origin/main moved 5 times in a row`.
10. **Local main ahead with no worktree on main** (`land_on_main.sh:137-142`, exit 3 today): the
    script pushes it with `git push origin main:main`. A rejected push re-fetches and enters the
    main-moved loop.
11. **Dirty main worktree** (`land_on_main.sh:92-96`, an uncommitted change overlapping the
    incoming files): never stash, reset or edit those files; another process may be working on
    them. Ask the user, naming the paths: "Commit them for me" or "I'll commit main, then continue".
    On "commit": commit exactly those paths in the main worktree as their own commit. Local main is
    behind `origin/main` at this point, so rebase that one new commit onto `origin/main` in the main
    worktree (`git pull --rebase`, which moves only the commit just made). A conflict aborts the
    rebase, leaves the commit on local main and returns `paused` with the paths. Otherwise push
    `main` and enter the main-moved loop. On "wait": return
    `status: paused · reason: main worktree has uncommitted changes: <paths>`. Re-running
    `/sdd:finish_worktree` continues from there. The rule at `finish_worktree.md:16-20` that the
    command never acts in the main worktree gains this one exception, with the user's consent.
12. **Upstream change review with `direction: changed`** (`pre_step_rebase.md` Steps 3–5): when
    every path main brought in is a spec-only change, continue without pausing. Otherwise pause as
    today. This applies to every command that runs the pre-step rebase, not only
    `finish_worktree`. `upstream_change_scan.sh` makes the spec-only check, from the changed-path list it
    already computes, so the rule is testable.
13. **Force-push:** the rebase pushes with `--force-with-lease --force-if-includes` as now. A
    stale-lease rejection re-fetches and loops. Any other refusal (the permission system declines
    the command, or the remote rejects it as protected) returns `status: paused · reason:
    force-push needed: <exact command>`. Re-running `/sdd:finish_worktree` after the user runs it
    continues.
14. **Rebase conflicts:** `pre_step_rebase.md` passes `rebase_main.md` an auto-resolve list as an
    argument, so ds gets no sdd layout and no new config key. A conflict whose paths all fall under
    the spec root is resolved without asking: the branch's side (`--theirs` in Step 6's terms) for
    the branch's own spec directory, wherever it is at that point (`2. in progress/` or, in the
    exit-7 loop, `3. done/`), and main's side (`--ours`) for any other spec path. The existing
    `roadmap.md` rule (`finish_worktree.md:35-38`: keep both sides' removals, regenerate with
    `roadmap.py`) takes precedence. Step 6's rule against `--ours`/`--theirs` on other non-generated
    files stays. A conflict in any other path stops with `blocked`, as today.
15. **Flaky tests at the checkpoint:** when the checkpoint run fails:
    1. Re-run each failing test by its node ID, on its own, three times (`--no-cov`, through the
       targeted runner). A test that fails all three times is a real failure, and the command stops
       with `status: failed` as today.
    2. A test that passes at least once is flaky. Spawn one `general-purpose` sub-agent (not
       `sdd-mechanic`) per flaky test, briefed with the test, its failure output and the file the new
       `Flaky test guide` key under `## Test Hooks` names. The sub-agent fixes the root cause on the
       current branch. It never skips, deletes or marks the test to get a pass. It proves the fix
       with 10 consecutive passing runs of the test, then commits it as `fix flaky test <test id>`.
    3. Each test gets two fix attempts. When both fail, stop with `status: failed · reason: flaky
       test <id> not fixed: <diagnosis>`.
    4. After the fixes, re-run the checkpoint tier and continue.
16. **FLS flaky-test guide:** a section in `claude_plugins/fls-dev/skills/testing/SKILL.md`, or a
    resource it links, lists the FLS causes: shared DB state and transaction leakage,
    `transaction=True` browser tests, Playwright timing, factory randomness, bare sleeps and test
    order. `.claude/sdd/config.md` sets `Flaky test guide` to it.
17. **Report:** the final report lists every auto-fix (main pushed, main-worktree commit, rebase
    passes, flaky fixes with their commits) and every test report line from Requirement 1.

### Token efficiency

18. **Baseline:** `claude_plugins/sdd/scripts/measure_prompt_size.py` prints lines, words and
    approximate tokens (characters / 4) per file for the files an SDD run loads: everything under
    `claude_plugins/sdd/{commands,resources,agents,skills}`, plus the files `.claude/sdd/config.md`
    names and the paths sdd commands reference through `${CLAUDE_PLUGIN_ROOT}` or config. It names
    no plugin directory other than `claude_plugins/sdd`, and lists a referenced file it cannot
    resolve as unmeasured. Its output before the trim is saved as `token_baseline.md` here, and
    after as `token_after.md`.
19. **Trim rules:** no instruction is lost; each is kept, moved or merged with its duplicate.
    Rationale written for humans moves into `claude_plugins/sdd/commands/README.md` or the
    diagrams. A command over 500 lines (today only `do_qa.md`) moves its rarely used branches into
    one-level-deep files it reads only on that branch. An up-to-date branch reads none of
    `pre_step_rebase.md`'s upstream-change scan and review text. A shell sequence repeated across
    files becomes a script.
20. **Quality guard:** the tests that read prompt files (`tests/test_test_tiers.py`,
    `tests/test_update_concrete_projects.py`) still pass.

### Removals

    and the `fetch_pr_comments.sh` scripts (`claude_plugins/django-stack/scripts/`,
    `claude_plugins/django-stack/templates/wrapper_scripts/`, `.claude/ds/scripts/`), which only it

    `sdd:protected:update_todo`. Re-grep when planning: the research's line list is incomplete.
22. Remove the duplicate Panel-framework entry under `## Rule Files` in `.claude/sdd/config.md`

### Diagrams (`claude_plugins/sdd/docs/diagrams/`)

23. One `.drawio.svg` per flow: `overview`, `start`, `spec_from_idea`, `plan_from_spec`,
    `implement_plan`, `do_qa`, `qa_fix`, `document`, `finish_worktree`, and `rebase`
    (`pre_step_rebase.md` with `rebase_main.md`). In `overview`, a command with a diagram links to
    it, and a command without one (`spec_review`, `make_pr_quickly` and the others) is a plain box.
24. **Production:** each diagram is written as uncompressed draw.io XML, then exported with the
    draw.io CLI (`drawio -x -f svg --embed-diagram -u`, under `xvfb-run` when there is no display)
    so the SVG holds both the drawn
    shapes GitHub renders and the XML draw.io edits. Only the `.drawio.svg` is committed.
25. **Content:** swimlanes for Human, Orchestrator (depth 0), Sub-agents, Hooks (labelled with
    their config keys) and Git/Tests. Decisions are diamonds. Test runs are coloured by tier (none,
    targeted, checkpoint, full), with a legend on each diagram. A call to the rebase flow is one box,
    "Pre-step rebase", pointing at `rebase.drawio.svg`. `implement_plan` shows the orchestrator
    reading the plan, the batches and waves, the sub-agents and their targeted runs, the Design check
    hook, the Batch review step (its `Comment standard` and `Test standard` hooks), and the Step 3
    full run.
26. **README:** `claude_plugins/sdd/commands/README.md` becomes the human guide. It embeds each
    diagram (`![<alt>](../docs/diagrams/<name>.drawio.svg)`) with alt text and a two-to-four-line
    summary, and explains the two full-run points, the full-run record, the self-recovery rules and
    the states that stop `finish_worktree`.
27. **Sync check:** `claude_plugins/sdd/scripts/check_diagrams.py` holds a table mapping each
    diagram to its command files (`rebase` to `pre_step_rebase.md`, `rebase_main.md` and any file
    split out of them; a split command to all its files; `overview` exempt). It reads labels from
    the embedded XML and fails when a `Step N` heading (`#` to `###`, decimals like `Step 0.5`
    included, title included) has no label starting with the same text, or when a `Step N` label
    names a step the files lack. Its test runs on fixture pairs and on the committed set.
28. **`pyproject.toml [tool.test_tiers]`:** map `claude_plugins/**/*.drawio.svg` to the
    `check_diagrams` test file as a tooling entry, and add that test file to the existing
    `claude_plugins/*/**/*.md` tooling entry, so a diagram edit or a step rename runs the check and
    nothing else.

## Testing

- `full_run_record.py`: no record resolves `full`; a record plus only `spec_dd/**` changed resolves
  `none`; a record plus an app file changed resolves `targeted` over the range; a record plus
  `uv.lock` changed resolves `full`; an unreachable SHA resolves `full`; a record from before a
  rebase resolves correctly; a failed, incomplete or dirty-tree run writes nothing.
- `land_on_main.sh` (in `tests/test_land_on_main.py`, against a temporary repo with an origin):
  local main ahead with no main worktree gets pushed (exit 0, not 3); a dirty overlapping main
  worktree still exits with its own code so the command can ask.
- `upstream_change_scan.sh`: a spec-only incoming change reports no pause; one with a code path
  does.
- `check_diagrams.py`: passes on the committed set; fails on a fixture with a renamed heading, and
  on one whose diagram names a missing step.
- `measure_prompt_size.py`: lists every sdd command and resolves config-named files.
- Removals: no file outside `spec_dd/` mentions `address_pr_review` or `fetch_pr_comments`.
- Manual runs, recorded in the QA plan: `finish_worktree` with main moved twice during the run; with
  a dirty spec file in the main worktree (both answers); with a spec-only rebase conflict; with a
  denied force-push; with a deliberately order-dependent test. One pre-step rebase of a spec-only
  branch, checking that pre-commit checked only the branch's files.

## Open questions

- Q: Which other unused steps should go? → A: none in this spec; the user decides each line of
  `unused_step_candidates.md`.
- Q: How many main-moved passes before giving up? → A: five in a row with the same blocker
  (assumed default: main settles within minutes in practice. Overrule by editing Requirement 9.)
- Q: How hard should flaky fixes try? → A: two attempts per test, proved by 10 consecutive passes
  (assumed default: bounded so a real defect cannot loop. Overrule by editing Requirement 15.)
- Q: Should main's escalating changes (a migration, `uv.lock`) make the checkpoint tier resolve
  to `full` on a branch with code changes? → A: yes (assumed default: the branch's code has not run against them.
  Overrule by editing the Checkpoint tier definition.)
- Q: Can taking main's side for another spec's conflicting file drop an edit the close-out made
  outside its own spec directory? → A: only `roadmap.md` is edited there today, and its own rule
  wins (assumed default: no other close-out edit exists. Overrule by editing Requirement 14.)
- Q: How are diagrams rendered for GitHub? → A: exported with the installed draw.io CLI (assumed
  default: hand-written SVG shapes would drift from the XML. Overrule by editing Requirement 24.)

## Success criteria

- In a cycle where main does not move and QA fixes nothing, the full tier runs once, and
  `finish_worktree` reports `tier: none` with the record SHA.
- A spec-only branch runs no pytest in any pre-step rebase, even when main brought in
  `pyproject.toml` or migration changes.
- `finish_worktree` lands without stopping when main moved twice and when local main was unpushed,
  and its report lists each auto-fix.
- `token_after.md` totals less than `token_baseline.md`, and every baseline instruction is kept,
  moved or merged.
- Every diagram opens in draw.io, renders in GitHub's markdown preview of
  `claude_plugins/sdd/commands/README.md`, and passes `check_diagrams.py`.
