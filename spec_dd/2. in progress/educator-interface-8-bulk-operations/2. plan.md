# Plan: Bulk operations

Implementation plan for `1. spec.md` beside this file. Paths are relative to the project root.
Requirement numbers (R1 to R9) refer to the spec's sections.

## How to read this plan

- The work is ordered as vertical slices. Each slice runs end to end through the layers it needs
  and leaves the suite green when it is committed alone. Later slices widen earlier ones.
- We follow TDD. Each slice names the behaviours its tests must prove; the tests themselves are
  written during implementation, red first.
- Pseudocode shows the shape, not the final code. Comments in it state the reasoning and may be
  copied into the code as they stand.
- The skills to load at each step are named in the slice. "Skills and conventions" at the end
  collects the rules that cut across slices.
- A `> **Assumed default:**` callout records a review judgement call and the choice made.

### `freedom_ls/panel_framework/bulk_actions.py`

```python
@dataclass(frozen=True)
class BulkOutcome:
    status: Literal["changed", "skipped", "failed"]
    reason: str = ""  # empty for "changed"


@dataclass(frozen=True)
class BulkCount:
    status: Literal["changed", "skipped", "failed"]
    reason: str
    count: int


@dataclass(frozen=True)
class BulkResultEntry:
    key: str
    row_label: str
    status: Literal["skipped", "failed"]
    reason: str


@dataclass(frozen=True)
class BulkResult:
    counts: list[BulkCount]            # one per distinct (status, reason), queryset order
    entries: list[BulkResultEntry]     # at most RESULT_ENTRY_LIMIT skipped or failed objects
    left_out: int                      # skipped or failed objects beyond the entry limit

    @property
    def changed(self) -> int: ...
    def to_json(self) -> dict[str, object]: ...        # dataclasses.asdict
    @classmethod
    def from_json(cls, data) -> BulkResult: ...


@dataclass(frozen=True)
class BackgroundRun:
    result_url: str


RESULT_ENTRY_LIMIT = 500
FAILED_REASON = "could not be changed"


class BulkAction:
    label = ""
    action_name = ""
    variant = "secondary"
    max_rows = 500  # applies to keys mode only; an all_matching selection has no cap
    confirm_template_name = "panel_framework/partials/bulk_confirmation.html"
    result_template_name = "panel_framework/partials/bulk_result.html"
    # Exception types `apply` may turn into a failed outcome. Any other
    # exception propagates: a failure the action did not name is a bug.
    failure_exceptions: tuple[type[Exception], ...] = ()

    def has_permission(self, request) -> bool: return True
    def apply(self, user, obj, cleaned_data) -> BulkOutcome: raise NotImplementedError
    def row_label(self, obj) -> str: return str(obj)
    def execute(self, request, queryset, cleaned_data) -> BulkResult | BackgroundRun:
        return run_apply(self, request.user, queryset, cleaned_data)
```

`run_apply(action, user, queryset, cleaned_data, on_progress=None) -> BulkResult` is a module
function so a task can call it too:

```python
for processed, obj in enumerate(queryset.iterator(chunk_size=200), start=1):
    try:
        with transaction.atomic():
            outcome = action.apply(user, obj, cleaned_data)
    except action.failure_exceptions:
        # A fixed reason: exception text is for developers and never reaches the page.
        outcome = BulkOutcome("failed", FAILED_REASON)
    tally(outcome, key=str(obj.pk), row_label=action.row_label(obj))
    if on_progress and processed % 50 == 0:
        on_progress(processed)
```

```python
@contextmanager
def record_run(record: BulkActionRun | LearnerImport) -> Iterator[None]:
    """Mark the record running, then done or failed, stamping the timestamps.

    A try/finally rather than a broad except: the body's own exception still
    propagates to the worker, and a record the body did not mark done is
    marked failed with a generic message so it never stays running forever.
    """
    record.status, record.started_at = RunStatus.RUNNING, timezone.now()
    record.save(update_fields=["status", "started_at"])
    try:
        yield
    finally:
        if record.status == RunStatus.RUNNING:
            record.status, record.error_message = RunStatus.FAILED, "Unexpected error."
        record.finished_at = timezone.now()
        record.save(update_fields=["status", "error_message", "finished_at"])
```

The body sets `record.status = RunStatus.DONE` (or `FAILED` with its own message) before it
returns.

### `freedom_ls/educator_interface/actions.py`

The whole contract is declared on the base class, with defaults, so `run_bulk_action` needs no
`hasattr`:

```python
class EducatorBulkAction(BulkAction):
    table_key: str
    capability: str
    noun_model: type[Model]
    unchanged_reason: str = ""   # the skip reason when the service reports no change

    def has_permission(self, request) -> bool:
        scoped = cast(OrganisationScopedRequest, request)
        return can_on_any(scoped.user, scoped.organisation, self.capability)

    def permitted(self, user, organisation, queryset, cleaned_data) -> QuerySet: ...
    def with_related(self, queryset) -> QuerySet: return queryset
    def skip_reason(self, obj, cleaned_data) -> str | None:
        """The reason this permitted object would be skipped, from its current state."""
    def scope_object(self, obj, cleaned_data) -> Model:
        """What the single action asks `can` about before acting."""
    def perform(self, obj, cleaned_data) -> bool: ...
    def target_json(self, cleaned_data) -> dict[str, str]: return {}
    def resolve_target(self, organisation, target) -> dict[str, object]: return {}
    def objects_for_keys(self, organisation, keys) -> QuerySet:
        return self.noun_model._base_manager.filter(organisation=organisation, pk__in=keys)

    def not_permitted_reason(self) -> str:
        return f"{self.noun_model._meta.verbose_name_plural} you don't have permission to change"

    def classify_all(self, user, queryset, cleaned_data):
        organisation = queryset.model ... (from the request's organisation)
        permitted_ids = set(self.permitted(user, organisation, queryset, cleaned_data).values_list("pk", flat=True))
        outcomes = {}
        for obj in self.with_related(queryset):
            if obj.pk not in permitted_ids:
                outcomes[str(obj.pk)] = BulkOutcome("skipped", self.not_permitted_reason())
            elif (reason := self.skip_reason(obj, cleaned_data)) is not None:
                outcomes[str(obj.pk)] = BulkOutcome("skipped", reason)
            else:
                outcomes[str(obj.pk)] = BulkOutcome("changed")
        return outcomes

    def apply(self, user, obj, cleaned_data) -> BulkOutcome:
        if not can(user, self.capability, self.scope_object(obj, cleaned_data)):
            return BulkOutcome("skipped", self.not_permitted_reason())
        if self.perform(obj, cleaned_data):
            return BulkOutcome("changed")
        # The service said nothing changed, so the same reason the preview gave applies.
        return BulkOutcome("skipped", self.unchanged_reason)

    def execute(self, request, queryset, cleaned_data) -> BulkResult | BackgroundRun:
        run = BulkActionRun.objects.create(
            organisation=..., requested_by=request.user, table_key=self.table_key,
            action_name=self.action_name, target=self.target_json(cleaned_data),
            keys=[str(pk) for pk in queryset.values_list("pk", flat=True)],
            status=RunStatus.QUEUED,
        )
        return run_bulk_action(str(run.pk), request.site.pk)
```

`run_bulk_action(run_id, site_id) -> BulkResult` lives in
`freedom_ls/educator_interface/bulk_runs.py` and returns the live result, so the inline path never
parses its own JSON:

```python
def run_bulk_action(run_id: str, site_id: int) -> BulkResult:
    run = get_object_or_404(BulkActionRun._base_manager.filter(site_id=site_id).select_related(...), pk=run_id)
    action = bulk_action_for(run.table_key, run.action_name)
    with record_run(run):
        cleaned_data = action.resolve_target(run.organisation, run.target)
        queryset = action.with_related(action.objects_for_keys(run.organisation, run.keys))
        result = run_apply(action, run.requested_by, queryset, cleaned_data, on_progress=save_processed(run))
        # A key that no longer resolves is reported, not silently dropped.
        result = with_missing_keys(result, run.keys, queryset, reason="no longer exists")
        run.result, run.status = result.to_json(), RunStatus.DONE
    return result
```

`save_processed(run)` returns a callback that writes `processed_count` with `update_fields`.

it, and `bulk_actions_for_table(table_key) -> list[EducatorBulkAction]` instantiates the table's
actions in that order. `LearnerConfig.get_bulk_actions` and `CohortConfig.get_bulk_actions` return
`bulk_actions_for_table(cls.table_key)`, so the bar order and the lookup have one source.

    # _base_manager with a row lock, as _set_learner_active does: this also runs
    # from a task with no ambient site for the site-aware manager to read.

## Skills and conventions

- `ds:htmx`: 422 for the `expected_count` mismatch, an invalid picker and a file-level import
  failure; `hx-target` and `hx-swap` together; HTMX partial views carry the `partial_` prefix;
  CSRF is global on `<body>`, never per request. The background hand-off uses `HX-Redirect`
  (303 with JS off) as the spec fixes it, a deliberate departure from the skill's `HX-Location`
  preference, because the destination is a standalone page outside `#main-content`.
- `ds:alpine-js` and `fls-dev:alpine-js`: CSP build, so no inline expressions; `tableSelection`
  is extended in `panel_framework/static/panel_framework/js/alpine-components.js`, server values
  arrive through `data-*` read in `init()`; hidden-by-default prompts carry `x-cloak` and
  `x-transition`.
- `fls-dev:multi-tenant`: `LearnerImport`, `LearnerImportRow` and `BulkActionRun` extend
  `SiteAwareModel`; tasks and housekeeping read through `_base_manager` filtered on `site_id` and
  write `site` explicitly, the one deliberate exception R4 makes to "never set `site` by hand".
- `ds:app-settings` and `fls-dev:app-settings`: the three settings live in
  `learner_management/config.py` and are read through `config.NAME`.
- `ds:template`, `fls-dev:template`, `fls-dev:icon-usage`, `ds:frontend-styling`,
  `fls-dev:frontend-styling`: pages under `educator_interface/templates/educator_interface/`,
  partials under `.../partials/`; `<c-icon name=...>` only; theme tokens only; run
  `npm run tailwind_build` after adding classes.
- `ds:testing` and `fls-dev:testing`: test mirroring (`base/tests/test_csv_import.py`,
  `educator_interface/tests/test_learner_import.py`, `test_tasks.py`, `test_bulk_runs.py`,
  `learner_management/tests/test_run_records.py` and `test_models.py` extensions);
  `mock_site_context` in every site-aware test; factories, `reverse()`, `force_login`; markers only
  `playwright` for browser tests; `transaction=True` with the shared `database_task_backend`;
  `time_machine` for windows; `django_assert_max_num_queries` as an upper bound; "no writes"
  proved by captured statements and row counts, never by an exact query count.
- `ds:playwright-tests` and `fls-dev:playwright-tests`: one flow per test ending with the
  `QA_VIEWPORTS` layout loop, `educator_logged_in_page`, JS-off cases as separate functions in the
  same file.
- `code-comments`: comments state reasons, never spec or plan references.
- `domain-glossary`, `brand-guidelines`: the spec's copy is used verbatim; "not added" for import
  rows, "skipped" for bulk runs.
- `fls-dev:file-storage`: no `FileField`; nothing to store.
