## Conventions for every slice

- TDD: each slice names its tests; write the failing test, then the change. One behaviour per
  test; a parametrised test only where the assertion shape is identical.
- Tests assert contract attributes and text, not CSS classes. Two small hooks make that possible
  where a variant or tone is the behaviour under test: `cotton/button.html` renders
  `data-variant="{{ variant }}"` and `cotton/panel-status-badge.html` renders
  `data-tone="{{ tone|tone }}"` (both added in the first slice that needs them).
- Skills: `ds:testing` and `fls-dev:testing` for every pytest file (test layout mirrors the module,
  `mock_site_context` for site-aware factories, markers from the taxonomy); `ds:playwright-tests`
  and `fls-dev:playwright-tests` for every browser test; `ds:template` and `fls-dev:template` for
  every template; `ds:htmx` for every HTMX response; `ds:alpine-js` and `fls-dev:alpine-js` for
  every Alpine change (the CSP build is on: no inline expressions, every binding names a property

  name (no spec, slice or defect references in code); `fls-dev:domain-glossary` for every new

- Every new CSS rule goes in a layer in `tailwind.components.css` (`@layer base` for element
  rules), never in an inline `<style>` block. Commit with `uv run git commit`. Run
  `npm run tailwind_build` whenever a slice adds a Tailwind class to a template or
  `tailwind.components.css`.
- Keep `removed` where it describes a deleted `CohortMembership` or role row (the glossary's
  `removed` row); the sweep in slice 3 renames only the `is_active` uses.
- Run the educator interface and panel framework suites, Playwright included, at the end of every

## Slice 1: Smoke test per section and the console-error helper

The thinnest end-to-end piece: a test that loads every section as it is today, so each later slice
has a net under it.

**Behaviour:** seven sections load for an `organisation_admin` with no console errors.

- `tests/playwright/helpers.py`: add the console-error helper.

  ```python
  from collections.abc import Iterator
  from contextlib import contextmanager

  from playwright.sync_api import ConsoleMessage, Error, Page


  @contextmanager
  def no_console_errors(page: Page) -> Iterator[None]:
      """Fails the test if the page logged a console error or an uncaught
      exception while the block ran."""
      errors: list[str] = []

      def record(message: ConsoleMessage) -> None:
          if message.type == "error":
              errors.append(message.text)

      def record_exception(error: Error) -> None:
          errors.append(str(error))

      page.on("console", record)
      page.on("pageerror", record_exception)
      try:
          yield
      finally:
          page.remove_listener("console", record)
          page.remove_listener("pageerror", record_exception)
      assert errors == [], errors
  ```

- New `tests/playwright/test_section_smoke.py`, `pytestmark = [playwright, django_db(transaction=True)]`.
  One parametrised test over `(path_string, heading, row_text)` for dashboard (`""`), `learners`,
  `cohorts`, `courses`, `members`, `audit-log` and `cohorts/<pk>/__tabs/report`. A module-level
  helper `seed_sections(user)` (a plain function, since the transactional database fixture is
  function-scoped) creates one organisation with one cohort, one learner, one course
  registration and one audit log entry (the deactivation of a second learner), and grants
  `organisation_admin` to `educator_user` with `assign_role`. The test opens the page inside
  `no_console_errors` and asserts `get_by_role("heading", name=heading)` and one row or card by
  role locator. Seven logins in one parametrised file is a deliberate exception to the
  one-flow-per-journey rule in `ds:playwright-tests`: a per-section smoke test must fail on its
  own section, which one long flow cannot do, and the spec names this file and its
  parametrisation.

### Cohort page

1. **Header Reactivate stays on its tab.** `CohortStateAction.handle_submit` (`actions.py:395`)
   navigates to `ctx.page_url`, the instance root. Add to `panel_framework/actions.py`:

   ```python
   def current_page_within(request: HttpRequest, root: str) -> str:
       """The path of the page the request was made from, when it lies
       under `root`; otherwise `root`. The header is client-supplied, so
       only its path is used and only within the page the action belongs to."""
       current = request.headers.get("HX-Current-URL", "")
       if not url_has_allowed_host_and_scheme(
           current, {request.get_host()}, request.is_secure()
       ):
           return root
       path = urlsplit(current).path
       if path == root or path.startswith(root.rstrip("/") + "/"):
           return path
       return root
   ```
