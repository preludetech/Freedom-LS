# Frontend QA: Educator interface docs and polish

Spec: `1. spec.md`. Plan: `2. plan.md`.

## Setup

- Start the server: `uv run python manage.py runserver $PORT`. Base URL: `http://127.0.0.1:$PORT`.
  Run the whole pass twice, once with `FLS_THEME=default` and once with `FLS_THEME=first_class`
  (set the variable before starting the server; run `uv run python manage.py write_active_theme_css`
  and `npm run tailwind_build` after switching).
- Log in at `/accounts/login/` as `demodev@email.com` / `demodev@email.com`.
- Data: run `uv run python manage.py qa_create_educator_interface_seed` and the
  `qa_create_cohort_administration_scenario`, `qa_create_learner_administration_scenario`,
  `qa_create_bulk_operations_scenario` and `qa_create_member_administration_scenario` commands.
  Where a test below needs something those do not give, ask the data helper for it by shape:
  - an organisation the login is `organisation_admin` of, with at least 12 learners, two cohorts
    (one inactive), two courses, and a course registration per cohort;
  - one learner whose user has no first or last name (shown by email);
  - one inactive learner and one pending learner (no password set);
  - a cohort with more learners than `REPORTS_MAX_LEARNERS` (500 by default; the helper can lower
    the setting in `settings_local` for the run instead);
  - two courses each holding a quiz titled "Checkpoint", both registered to the same cohort with
    at least one wrong answer recorded;
  - a second organisation the login can also reach, so the organisation switcher shows;
  - a `cohort_viewer` user on one cohort (email and password in the data report).
- Viewports: 390×844 (phone), 768×1024 (tablet, learners and cohorts tables only), 1440×900
  (desktop). "Org" below means the organisation's slug in URLs: `/educator/<org>/…`.

Record every finding with a screenshot in `qa-screenshots/`.

## Test 1: Every section loads without console errors

For each of `/educator/<org>/`, `…/learners`, `…/cohorts`, `…/courses`, `…/members`,
`…/audit-log` and `…/cohorts/<pk>/__tabs/report`, at desktop and phone, in both themes:

- The page heading names the section, one data row or card shows, the browser console shows no
  errors, and nothing scrolls sideways at 390 (`document.documentElement.scrollWidth <= window.innerWidth`).
- Compare the dashboard, learners and cohorts screens with the mockups in
  `spec_dd/1. next/educator-interface-full-polish/Educator LMS Interface Design/` (desktop and
  "Mobile" files) for layout and density. Note any visible difference; the mockups are not pixel
  references.

## Test 2: Renamed bulk actions

1. On `/educator/<org>/learners`, tick two learners. The selection bar's actions include
   "Deactivate a course registration" (possibly under "More actions"). Open it, choose a course:
   the dialog title is "Deactivate the {course} registration for 2 learners?" (or the number
   that will change), the confirm button is the primary style, Cancel is focused. Confirm: the
   button reads "Deactivating…" while in flight, the result dialog shows, the table refreshes.
2. Same on `/educator/<org>/cohorts` for "Deactivate a course registration": the sentence reads
   "… for N cohorts."
3. Adversarial: visit `/educator/<org>/learners/__actions/unregister_from_course` and
   `/educator/<org>/cohorts/__actions/unregister` directly: a 404 page. Repeat with the
   `HX-Request: true` header (Playwright `page.request.post` with the CSRF cookie): still 404.
4. On a cohort's page, the Courses tab's header action reads "Register for a course"; the learners
   list's row menu and the bulk menu read the same.

## Test 3: Confirmation dialogs share one shape

Open each of these and check: the title is a question naming the object ("Deactivate Thandi
Nkosi?", "Remove … from Cohort A?", "Delete Cohort A?", "Resend the setup email to …?"); the body
says what stops, what is kept and how to undo it; the footer is Cancel then the verb; Cancel has
focus on open; the confirm button is primary for deactivate, reactivate, register, move and resend
and the error (red) style for delete and remove from cohort; while submitting the button reads
"Deactivating…" / "Removing…" / "Deleting…" / "Moving…" / "Sending…".

- Learner row menu: Deactivate, Reactivate (on the inactive learner), Resend setup email (on the
  pending learner), Remove from cohort (on a cohort's Learners tab), Move to another cohort (the
  destination select has focus, not Cancel; the Move button enables once a destination is chosen).
- Learner page Courses tab: Deactivate and Reactivate on a registration.
- Cohort header: Deactivate; Reactivate on the inactive cohort; Settings tab: Delete (on an
  empty cohort).
- Members: Deactivate role, Deactivate member, Reactivate member.
- Bulk, from the selection bar: Deactivate (trigger is the secondary style, confirm primary),
  Remove from cohort (trigger and confirm both red), Reactivate, Register for a course, Add to
  cohort, Resend setup email.
- Side effects: after each confirm, the row or table behind the dialog refreshes, focus returns to
  the row's trigger (or the table heading when the row was replaced), and the History tab of the
  object shows the entry with the Reason you typed.
- Repeat submission: open Deactivate on an already-deactivated learner (use a second tab to
  deactivate it first): the dialog says the learner is already inactive rather than erroring.

## Test 4: Empty states

1. As the `cohort_viewer`, open `/educator/<org>/members` on an organisation with no members
   visible to them, and `/educator/<org>/audit-log` on an organisation with no entries: a centred
   message ending in a full stop, and no "Add member" button for the viewer. As the admin the
   members first-use state offers "Add member".
2. On every table (learners, cohorts, courses, members, audit log, a cohort's Learners and Courses
   tabs, a learner's Courses tab and History tab), apply a filter or search that matches nothing:
   the message says nothing matched and a "Clear filters" link returns the full list. On the
   learners table, "Clear filters" and "Clear all" both land on Active + Pending (the inactive
   learner is not shown).
3. Dashboard and cohort Overview cards with nothing to show (a new organisation, a cohort with no
   educators, no needs-attention learners) render the same centred style, each message ending in
   a full stop.

## Test 5: Badges

Across the learners list, a learner's page, quick view and Courses tab, the cohorts list, a
cohort's Courses tab, the members list and the report: Active and Registered are the green
(success) tone, Inactive is grey (muted), Pending is blue (info). A member whose account is
`is_active=False` (ask the data helper) shows "Account inactive" in grey; the "Inactive"
membership marker is grey too. No state is shown by colour alone: each badge has text.

## Test 6: Nameless learner

With the learner whose user has no name: in the learners list the link text and the quick-view
trigger's label are the email; the quick view's title is the email; the learner page's heading
and breadcrumb are the email; the row checkbox's accessible name is "Select <email>" (read it from
the accessibility snapshot); the cohort History tab and the cohort report rows show the email.
Open the learner page from the list by clicking the name: it opens.

## Test 7: Status filter

On `/educator/<org>/learners`: the Status chip shows Active + Pending and has no remove control.
Add Inactive, confirm the inactive learner appears, then clear by each route and confirm the
inactive learner disappears each time: the chip's own control (if one shows), "Clear all" on
desktop, and the phone sheet's Reset (open Filter at 390, press Reset). The URL after each has no
`learners-status` value or the default pair.

## Test 8: A 404 shows the action-unavailable dialog

Open `/educator/<org>/learners` in tab A. In tab B (or the admin), deactivate the login's access
to a cohort-scoped learner, or delete a cohort the list shows. Back in tab A without reloading:

1. Open that row's menu and choose Deactivate: a dialog "This is no longer available" with body
   "It may have been removed, or you may no longer have access to it." and a Close button.
2. Click that row's quick-view trigger: the same dialog, not the quick view's retry state.
3. Tick that row and run a bulk action: the same dialog.
4. Sort or filter the table so it refetches a region whose scope is gone (delete the cohort whose
   Learners tab is open): the same dialog, not a page reload.
5. Enumeration: with Playwright `page.request.get`, fetch
   `/educator/<org>/learners/<uuid-of-a-learner-in-another-org>/__quick-view` and
   `/educator/<org>/learners/00000000-0000-0000-0000-000000000000/__quick-view`, both with
   `HX-Request: true`: both 404 and the two response bodies are identical.

## Test 9: Known defects

1. Header Reactivate on an inactive cohort's Courses tab: after confirming, the page stays on the
   Courses tab (URL ends `/__tabs/courses`), the badge reads Active.
2. Open a second tab, deactivate a cohort, then in the first tab (stale) use Register for a course,
   Add learners and Edit name on it: each notice names its own action ("… to register it for a
   course", "… to add learners to it", "… to change its name").
3. Cohort Overview, Educators card: a nameless educator's email shows in lower case as stored.
4. Tablet 768: the cohorts and learners tables show every column; a wide one scrolls inside the
   table region (Tab to it: it takes focus and arrow keys scroll it) with no column cut off.
5. Phone 375 (set the viewport to 375×812 for this one): select more than
   `BULK_BACKGROUND_THRESHOLD` learners (choose "Select all N matching" on an organisation with
   enough rows, or ask the helper to lower the threshold) and run Deactivate: while it runs the bar
   at the bottom shows "Deactivate is running…" with a spinner and stays under about 120px tall;
   the action buttons are hidden until it finishes.
6. Learner import: upload a CSV where every row is an existing member: the preview has no
   "0 new accounts…" line; the result has no "0 rows were not added." line and no "0 setup
   emails…" line.
7. `/educator/<org>/learners/import`: the file input looks like the other inputs (bordered, with a
   styled Choose file button) in both themes.
8. Bulk "Add to cohort": open it, then from another tab delete the cohort you are about to pick,
   then confirm: the error reads "Choose a cohort from the list." and no UUID appears. Same for
   Move to another cohort.
9. Phone 375: open Add member, look up an address, reach the role step: the Cancel and Add member
   buttons are visible without scrolling the sheet; the same for Move and Change cohorts dialogs.
10. Dashboard and the over-limit cohort's Report tab: one identical sentence
    ("<cohort> has N learners, over the report's learner limit of 500, so it is not included."), in a tinted
    box whose text passes 4.5:1 (sample the colours), and the string `REPORTS_MAX_LEARNERS`
    appears nowhere.
11. Cohort Report tab, "Quiz confusions": the two "Checkpoint" cards are headed
    "Checkpoint (<course A>)" and "Checkpoint (<course B>)"; a quiz with a unique title is headed by
    its title alone.
12. Phone: on the audit log, the sheet opened by Filter is titled "Filter" (no sort controls);
    on learners it is "Filter and sort"; the status chips and sort options have no box border
    around their group.
13. Desktop: the organisation switcher's popover opens directly under its trigger (not offset
    down); choosing the other organisation switches the page and the sidebar label. Rename a cohort
    with Edit name: the browser tab title starts with the new name immediately.

## Test 10: Keyboard

Desktop, mouse untouched:

1. Tab through the learners list to a row's quick-view trigger, press Enter: the quick view opens
   and focus is inside it (the heading or the Close button). Press Escape: it closes and the
   trigger has focus again. Repeat at 390: the quick view is modal (the page behind it is inert,
   Tab stays inside it, a scrim shows).
2. Tab to a row's menu, open it, choose Deactivate with Enter: Cancel has focus. Tab cycles
   through the dialog only. Escape closes it and the trigger has focus.
3. Confirm a deactivation by keyboard: afterwards focus is on the table heading or the row's
   trigger, never lost to `<body>`.
4. Sort a column with Enter, open the Add filter menu, pick a choice, use the phone sheet (Filter,
   choose, Show results), the selection checkbox and "Select all N matching", the pagination
   links, the organisation switcher, the sidebar, the dashboard tiles' links, and the report's
   Generate and Download buttons: every one works by keyboard, and the focus ring is visible on
   each (not hidden under the sticky header, the selection bar or the quick view: scroll back and
   check).

## Test 11: Accessibility tree

Use the Playwright accessibility snapshot on each screen (this is the automated half of the
screen-reader pass; record the result in the QA report):

- The quick view's name is the learner's name; every dialog's name is its heading.
- Every table has a caption or `aria-labelledby`; column headers have `scope="col"`; the sorted
  column has `aria-sort` and the sort link's name is the column label (no "sort_neutral",
  "sort_asc" in any name); the table region is focusable and named.
- Row checkboxes are named "Select <learner name>".
- After a bulk result or a toast, the polite live region contains the message.
- Badge text appears as text in the tree.

## Test 12: Contrast and layout sweep

In both themes, at 390 and 1440 (plus 768 for the two tables): sample text against its background
on the dashboard tiles, badges, the over-limit notice, muted text, links, focus rings and
borders. Text must reach 4.5:1 and non-text 3:1. Touch targets below 768 are at least 44px
tall; at 1440 they are compact. Note each failure with the screen and the WCAG criterion so it
can be fixed or recorded in `deliberately_left.md`.
