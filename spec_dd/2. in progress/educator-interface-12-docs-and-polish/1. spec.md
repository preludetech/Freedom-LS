# Spec: Educator interface docs and polish

Spec 12 of 12 in the educator interface rebuild (`spec_dd/1. next/roadmap.md`, "Educator interface
rebuild"). Idea: `idea.md`. Research: the `research_*.md` files beside this one.

## Purpose

Specs 1 to 11 each documented and tested their own change, but nobody has read or walked the result
end to end. This spec closes the effort. It rewrites the educator product doc as one piece, walks
every screen for layout, keyboard and screen-reader use, makes the wording consistent, fixes the
defects earlier QA left open, consolidates the upgrade notes for downstream projects, and deletes
what the old interface left behind.

## Scope

In:

- The educator interface (`freedom_ls/educator_interface/`) and the panel framework templates and
  Alpine components it renders through (`freedom_ls/panel_framework/`).
- `docs/product/educator-interface.md`, `docs/product/roadmap.md`, `docs/product/README.md`,
  `docs/product/admin-interface.md`, the project `README.md`'s educator section, and
  `docs/how tos/theme-fls.md` where it names deleted hooks.
- `claude_plugins/fls-dev/skills/alpine-js/SKILL.md`, `claude_plugins/fls-dev/skills/domain-glossary/SKILL.md`
  and `claude_plugins/fls-dev/resources/testing.md` where they describe deleted code.
- Stale notes under `.claude/agent-memory/`.
- A smoke test per educator section.

Out:

- New features. A missing capability found during the pass becomes its own idea in
  `spec_dd/1. next/`.
- Dark mode. Neither theme has one (no `prefers-color-scheme`, no `dark:` classes). The pass covers
  the `default` and `first_class` themes, and a dark-mode idea is filed in `spec_dd/1. next/`.
- The panel framework's developer doc and skill: `extract_panels_framework-6-claude-plugin` writes
  them.
- Automated accessibility scanning (axe-core): no new dependency.
- Screenshot-diff testing. Mockup fidelity is checked by eye; the mockups are not pixel references.

## Decisions

- **Spec 12 lands before any `extract_panels_framework-*` spec starts.** The polish pass edits
  framework templates and `alpine-components.js`, which the extraction moves.
- **Touch targets follow spec 9's rule:** 44px below the `md` breakpoint only. 40px buttons and 38px
  row actions at 768 and wider stay as they are.
- **Confirm-button weight:** in a confirmation dialog, a reversible action (deactivate, reactivate,
  register, move, resend) confirms with `primary`, and an action that deletes a row (delete,
  remove from cohort) confirms with `error`. Trigger buttons in row menus and the bulk bar use
  `secondary` for reversible actions and `error` for deleting ones. This follows `brand-guidelines`:
  `error` is reserved for irreversible actions.
- **A learner with no name** shows `user.email` wherever a learner name is the link text or the
  quick-view title, so the row can be opened and the link has an accessible name.
- **Clearing the learner status filter** (removing its chip, "Clear all", or Reset) returns to the
  default Active + Pending view. Inactive learners show only when the filter asks for them.
- **A 404 from a panel action request** (the object left the educator's scope after the page
  loaded) shows the existing action-unavailable dialog, the same way a 403 shows the
  action-denied dialog. The status stays 404 and the body names no object, so it reads the same
  for "never existed" and "out of scope" and cannot be used to enumerate.
- **Consolidated upgrade notes live in `effort_upgrade_notes.md`** in this spec directory, not in
  this spec's own `upgrade_notes.md`. `update_fls` reads `upgrade_notes.md` one spec at a time, so a
  downstream that already advanced through specs 1 to 11 would apply their steps twice.
- **The screen-reader pass is two parts:** QA inspects the accessibility tree through Playwright,
  and a person runs a short checklist with a real screen reader.

## Requirements

### 1. Consistency pass

The reference is `fls-dev:domain-glossary`, section "Changes" and the `is_active` row of "Words that
are already taken".

1. **Bulk "Unregister" actions are renamed.** In `freedom_ls/educator_interface/actions.py`:
   - `UnregisterFromCourseBulkAction` becomes `DeactivateRegistrationBulkAction`, with `label =
     "Deactivate a course registration"` and `action_name = "deactivate_registration"`.
   - `UnregisterCohortFromCourseBulkAction` becomes `DeactivateCohortRegistrationBulkAction`, with
     the same label and `action_name = "deactivate_cohort_registration"`.
   - The `sentence()` copy on both reads "Deactivate the {course} registration for N learners" (or
     "N cohorts").

   The slugs match spec 11's single-row slugs. If the bulk and single-row actions share a URL
   namespace on the same table, the plan picks non-colliding slugs in the same verb family.
2. **One label per action.** `RegisterCohortForCourseAction.label` becomes "Register for a course",
   matching the learner and bulk actions.
3. **Identifiers follow the glossary too.** Test names, helpers and variables that say
   `unregister`, `suspend`, `removed` (for an `is_active` flip) or `revoke` are renamed. Known
   ones: `_unregister_triggers` and its neighbours in `freedom_ls/educator_interface/tests/test_views.py`,
   `test_a_cohort_viewers_pasted_unregister_url_answers_403`, `test_unregister_naming_another…` in
   `invariants/test_organisation_isolation.py`, the docstring of
   `tests/playwright/test_register_deactivate.py`, and
   `test_the_history_tab_shows_the_code_of_an_unregistered_action`. A grep for those words across
   `freedom_ls/educator_interface/`, `freedom_ls/panel_framework/` and `docs/product/` finds only
   rows that were actually deleted, or the old names quoted in upgrade notes.
4. **Member badge.** `data-table-cells/member.html` says "Account inactive", not "Account turned
   off", for `User.is_active` False. The glossary's `is_active` row gains `User` (an account that
   cannot sign in).
5. **Confirmation dialogs share one shape**, in every template under
   `educator_interface/templates/educator_interface/modal/` and the bulk confirmation partials:
   - the title is a question naming the object and, for bulk, the count ("Deactivate Thandi
     Nkosi?", "Remove 12 learners from Cohort A?");
   - the body says what stops, what is kept, and how to undo it, in glossary words;
   - the footer is `<c-button-group variant="right" …>` with Cancel (`autofocus`) and a confirm
     button labelled with the verb, never "Yes" or "OK", weighted per the confirm-button decision;
   - `loading_text` is the verb's "-ing" form followed by "…".

   `move_confirmation.html` gains `autofocus` on Cancel. `reactivate_registration_confirmation.html`
   and the bulk Deactivate (`DeactivateLearnersBulkAction.variant`) are brought into line.
6. **Empty states.** Every empty list and card renders through `<c-panel-empty-state>`, including
   `partials/members_empty.html` and `partials/audit_log_empty.html`. Each list has two messages:
   first use (nothing exists yet: what will appear, and the action to add one, shown only to someone
   who can take it) and no results (filters matched nothing, with a clear-filters link). Every
   message is a sentence ending in a full stop.
7. **Badges.** The state of a record renders through `<c-panel-status-badge>` (directly or through
   `<c-active-status-badge>`, `learner_status_badge`, `progress_status_badge`, `flag_badge`). One
   state has one label and one tone everywhere: Active and Registered are `success`, Inactive is
   `muted`, Pending is `info`. `<c-chip>` is kept for tags and categories (quiz options, import file
   info, applied filters).

### 3. Polish pass

Walk every educator screen and dialog: dashboard, learners (list, learner page and its tabs, quick
view, add, import, bulk), cohorts (list, detail and every tab, quick view), courses (list and
detail), members (list, add, role changes), history (learner and cohort History tabs, the audit-log
section) and reports (cohort Report tab, download), plus the organisation switcher.

- **Layout:** at 390×844 and 1440×900, in the `default` and `first_class` themes (rebuild the CSS
  with `FLS_THEME=first_class npm run tailwind_build` before the second theme). No page-level
  horizontal scroll at 390. Wide tables scroll inside a labelled, focusable region. Dashboard,
  learners and cohorts match the mockups in
  `spec_dd/1. next/educator-interface-full-polish/Educator LMS Interface Design/` for layout and
  density, by eye. Courses, members, history and reports have no mockups and are checked against
  those three screens for density and component shape.
- **Keyboard:** every action is reachable and operable by keyboard alone. Focus is visible and never
  hidden by a sticky header, the selection bar or the quick view (WCAG 2.4.11). A dialog moves
  focus in on open, traps Tab, closes on Escape, and returns focus to the trigger (or to the table
  heading when a refresh replaced the trigger). The quick view is non-modal on desktop and modal
  below `md`, as spec 3 built it.
- **Accessibility tree:** the quick view and every dialog have an accessible name from their
  heading. Tables have a caption or `aria-labelledby`, `th scope`, and `aria-sort` on the sorted
  column. Row checkboxes are labelled with the row's name ("Select Thandi Nkosi"). Toasts and HTMX
  result messages sit in a polite live region. Badge text is read, not conveyed by colour alone.
- **Contrast:** text 4.5:1 and non-text (borders, focus rings, badge edges) 3:1, in both themes.

Each finding is fixed or recorded in `deliberately_left.md` beside this spec: one row per item with
screen, issue, WCAG criterion where one applies, why it is left, and the follow-up idea's path in
`spec_dd/1. next/` when there is one. The dark-mode idea is its first row.

### 4. Product doc

`docs/product/educator-interface.md` is rewritten whole, following
`claude_plugins/fls-dev/commands/update_product_docs.md`'s altitude rules, in the order an educator
meets the interface:

1. Dashboard
2. Learners: the list, the learner page, the quick view, messaging from it, adding and importing,
   bulk actions
3. Cohorts
4. Courses
5. Members and roles
6. History: the History tabs and the audit log
7. Reports

Organisation scope, access control and limits follow as reference sections. The doc:

- uses only glossary words (no "removed" for an inactive learner, no "unregister");
- has no per-spec history;
- states each fact once, which removes the duplicate "recalculated every few minutes" and the
  overlap between Limits and Bulk actions;
- uses one desktop screenshot per section, plus the quick view, one confirmation dialog with the
  Reason field, and one 390-wide view. Every image is taken after the fixes land, from QA
  screenshots or captured fresh per `update_product_docs.md` Step 4. Stale images
  (`educator_panel.png`, `educator_learners_list.png` if they lack the panel-card chrome) are
  replaced, and every image has alt text saying what it shows.

`docs/product/roadmap.md`:

- **Educator Interface Gaps** reduces to the deadline point: the "needs attention" placeholder line
  and the duplicated text go.
- **Deadlines** no longer implies the "needs attention" card is missing.
- **Cohort Report Deferrals** no longer says a report is produced only from the admin.
- "removed" for a deactivated learner becomes "deactivated".

`docs/product/README.md`: the Educator Interface row lists the dashboard, reporting, History and
the audit log, and the Roadmap row no longer says "remaining educator interface management
actions". `docs/product/admin-interface.md:53` says "deactivating a learner".

Project `README.md`, "The educator experience": rewritten to match the product doc's summary. The
`educator_cohort_progress_matrix.png` embed goes.

### 7. Upgrade notes

`effort_upgrade_notes.md` in this spec directory follows the schema in
`claude_plugins/fls-dev/commands/update_upgrade_notes.md`. Its frontmatter is the union of the flags
and lists from specs 1 to 12 and `educator-interface-looks-good`. Its body opens with a "Do you need to act?" checklist, then:

- URL changes, old to new;
- templates a downstream may have overridden, each marked changed, renamed (to what) or deleted,
  generated from `git diff --name-status` over the effort's range and annotated;
- new and renamed settings, with defaults, marked hard or optional;
- system checks added;
- event types, by final name only;
- migrations by app, with the data steps;
- `requires_tailwind_rebuild` and `npm run tailwind_build`.

Each entry names an exact path, URL name, setting or event. The file links each spec's own
`upgrade_notes.md` under `spec_dd/3. done/`, and every name resolves against the tree.

This spec's own `upgrade_notes.md` (written by the `fls-dev:update_upgrade_notes` hook) covers only
spec 12's changes: the renamed bulk slugs, the deleted `.modal-backdrop`, and the changed templates.

## Testing

- **Smoke test per section**, in `freedom_ls/educator_interface/tests/playwright/test_section_smoke.py`
  (markers `playwright`, `django_db(transaction=True)`), parametrised over dashboard, learners,
  cohorts, courses, members, audit log and the cohort Report tab. Each loads the section as an
  `organisation_admin`, asserts the heading and one data row by role locator, and asserts no console
  errors. Courses and the audit log have no smoke test today.
- **Keyboard flow:** one Playwright test opens a learner's quick view with Enter, asserts focus moves
  into it, closes it with Escape, and asserts focus returns to the row trigger. A second opens a
  deactivate dialog by keyboard and asserts Cancel has focus.
- **Decisions, proved by unit tests:**
  - a nameless learner's row links with their email;
  - clearing the status filter yields Active + Pending;
  - a panel action on an out-of-scope object answers 404 and renders the action-unavailable dialog,
    with a body identical to the one for a non-existent id;
  - the renamed bulk actions answer at their new slugs and the old slugs 404.
- **Each known defect** that changes behaviour or copy has a test that fails before the fix.
- **The educator interface and panel framework suites run green**, Playwright included.
  `test_modal_form_htmx` has flaked under load before; a failure that passes alone is recorded, not
  ignored.
