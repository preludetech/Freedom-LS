# Spec: educator interface refactor 4, course

## Purpose

The course area of the educator interface moves out of `freedom_ls/educator_interface/views.py` into a new
`freedom_ls/educator_interface/panels/course/` package, and its tests move to `tests/panels/course/`. A reader
who wants the course screens opens one small package. The approach is settled in `idea.md`
settles the approach. `research_codebase.md` holds the current line numbers.

## Scope

In:
- The package `panels/course/` and its six modules, holding every name in the table under Requirements.
- Moving `_course_title_column` and `_cohort_links_column` from `views.py` into `panels/common/tables.py`.
- Repointing every import, attribute access and patch string that names a moved name.
- Moving the course tests to `tests/panels/course/`, and the baseline and invariant lines that name the old
  paths.

Out:
- Any behaviour, UI, URL, URL name, template path or app label change.
- The dashboard, audit log, staff, learner and cohort areas, including the cross-area tables
  `CohortCourseRegistrationDataTable` and `LearnerDataTable`, which only change an import.
- Trimming `views.py` to the shell, `urls.py`, `templatetags`, and the `fls-dev` skill docs and
  `docs/app_structure.md`. `educator-interface-refactor-7-cleanup` owns those.
- The flat domain modules `forms.py`, `staff.py`, `learner_import.py` and `messaging.py`.
- A data migration. The course area registers no bulk action, so no stored `BulkActionRun.action_path` changes.

## Decisions

- **No re-export shim.** No moved name stays importable from `views.py` except where `views.py` imports it to use
  it (`CourseConfig` in `interface_config`).
- **`panels/course/` imports only `panels/common/`**, `panel_framework`, the flat `exceptions.py`, domain apps
  and the standard library. It never imports `views`, `actions`, `filters`, `quick_views`, `reporting` or another
  area package. `views.py` imports `course`, never the reverse.
- **The two shared column helpers go to `common/tables.py`.** `_course_title_column` serves the course and cohort
  tables, `_cohort_links_column` the course and learner tables. Leaving them in `views.py` would make
  `course/data_tables.py` import `views`, which imports `CourseConfig`, and that is a cycle.
- **`CourseOutlineTable` lives in `content_preview.py`** with `CourseContentPanel` and `OutlineRow`. In
  `data_tables.py` it would import `OutlineRow` from `content_preview`, which imports the table back.
- **No `data_table_panels` or `instance_view` test file.** No course test exercises either module alone, and the
  mirroring check forbids a test file without its module, not a module without a test file.
- **Moved names keep their spelling**, leading underscores included. Each new module declares a sorted
  `__all__` listing every name it holds, underscore names included, as `panels/common/` does. `__init__.py` is
  empty.
- **Patch strings name the module that looks the name up**, not the one that defines it.

## Requirements

Paths are under `freedom_ls/educator_interface/`. Each name moves byte-for-byte: only import lines change.
String casts such as `cast("OrganisationScopedRequest", ...)` keep their quoting. `TODO` and `@claude` comments
move with their code. Each new module opens with a one-line docstring that says what it holds, not where it came
from, then `from __future__ import annotations`.

### `views.py`

- `interface_config` imports `CourseConfig` from `panels.course.config`.
- `CohortCourseRegistrationDataTable` and `LearnerDataTable` import the two column helpers from
  `panels.common.tables`.
- Imports left unused by the cut go. `uv run ruff check` decides, not a hand list.
- The move leaves everything outside the course block and the two helpers where and as it is. Sibling specs cut
  neighbouring ranges and edit the same import block, so a minimal diff keeps their rebases mechanical.
