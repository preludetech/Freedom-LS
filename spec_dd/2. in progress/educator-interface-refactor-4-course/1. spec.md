# Spec: educator interface refactor 4, course

## Purpose

The course area of the educator interface moves out of `freedom_ls/educator_interface/views.py` into a new
`freedom_ls/educator_interface/panels/course/` package, and its tests move to `tests/panels/course/`. A reader
who wants the course screens opens one small package. `idea.md` settles the approach. `research_codebase.md`
holds the current line numbers and lists each test with its lines.

## Scope

In:
- The package `panels/course/` and its six modules, and two shared helpers added to `panels/common/tables.py`,
  holding every name in the table under Requirements.
- Repointing every import, attribute access and patch string that names a moved name.
- Moving the course tests to `tests/panels/course/`, and the baseline and invariant lines that name the old
  paths.

Out:
- Any behaviour, UI, URL, URL name, template path or app label change.
- The dashboard, audit log, staff, learner and cohort areas, including the cross-area tables
  `CohortCourseRegistrationDataTable` and `LearnerDataTable`, which only change an import.
- Trimming `views.py` to the shell, `urls.py`, `templatetags`, and the `fls-dev` skill docs and
  `docs/app_structure.md`. `educator-interface-refactor-7-cleanup` owns those.
- The flat domain modules `forms.py`, `staff.py`, `learner_import.py` and `messaging.py`.
- A data migration. The course area registers no bulk action, so no stored `BulkActionRun.action_path` changes.

## Decisions

- **No re-export shim.** No moved name stays importable from `views.py` except where `views.py` imports it to use
  it (`CourseConfig` in `interface_config`, and the two column helpers in `CohortCourseRegistrationDataTable` and
  `LearnerDataTable`).
- **`panels/course/` imports only its own modules, `panels/common/`**, `panel_framework`, the flat
  `exceptions.py`, domain apps and the standard library, all by absolute import. It never imports `views`,
  `actions`, `filters`, `quick_views`, `reporting` or another area package.
- **The two shared column helpers go to `common/tables.py`.** They serve the course table and a cohort or learner
  table. Left in `views.py`, they would make `course/data_tables.py` import `views`, which imports `CourseConfig`.
- **`CourseOutlineTable` lives in `content_preview.py`**, above `CourseContentPanel`, which names it at class-body
  time. In `data_tables.py` it would import `OutlineRow` from `content_preview`, which imports the table back.
- **No `data_table_panels` or `instance_view` test file.** No course test exercises either module alone.
- **Moved names keep their spelling**, leading underscores included. Each new module declares an `__all__`
  listing every name it holds, underscore names included, in the order ruff's `RUF022` gives. `__init__.py` is
  empty.

## Requirements

Paths are under `freedom_ls/educator_interface/`. Each name moves byte-for-byte: only import lines change.
String casts such as `cast("OrganisationScopedRequest", ...)` keep their quoting. `TODO` and `@claude` comments
move with their code. Each new module opens with a one-line docstring that says what it holds, not where it came
from, then `from __future__ import annotations`.

  `CourseCohortRegistrationDataTable` from `panels.course.data_tables`. Its docstring names the new module.

block. `test_views.py` has an unrelated helper `_outline_rows` and `test_course_preview_flow.py` a local

- `tests/test_course_visibility_and_interest.py` reaches `tests/panels/course/test_data_tables.py` by `git mv`,
  in a commit with no content change, so git keeps the rename through a rebase. The code commit that removes
  `CourseDataTable` and `CourseDetailsPanel` from `views.py` repoints both of that file's imports, the lazy one
  at its line 260 included, so no commit leaves the suite red. That code commit lands before the `git mv`.
- A test file's module exists in or before the commit that adds the file, or the mirroring check fails.
- A helper only the moving tests use moves with them. A helper defined in a moving range and used outside it, or
  defined in a staying range and used by a moving test, goes to `tests/helpers.py` under its existing name, and
  every user imports it from there. A grep of each underscore helper finds them. The known two are
  `_content_action_url` (also used by `tests/invariants/test_course_shares.py`) and `_get_document`. The moved
  tests take `_interface_url` from `tests/helpers.py`, which already defines the same function.
- These stay in `tests/test_views.py`, since they cover several areas: `EDUCATOR_TABLES` and its parametrised
  tests, `PICTURE_SURFACES` and `_registrations_table`, and the shared-course owner-note tests for learners,
  cohorts and cohort completion.
- `test_organisation/mirroring_baseline.txt`: delete the `test_course_visibility_and_interest.py` line, found by
  content.
- `test_organisation/import_baseline.txt` and `test_organisation/import_contracts.toml`: the
  `freedom_ls.educator_interface.tests.test_course_visibility_and_interest -> freedom_ls.course_interest.factories`
  line becomes `freedom_ls.educator_interface.tests.panels.course.test_data_tables -> ...`. That file is the only
  new importer of `course_interest.factories`.

  tip.

  `DJANGO_SETTINGS_MODULE=config.settings_dev uv run python -c "import django; django.setup(); import <module>"`.- `pre-commit run --all-files` passes, including `test-mirroring` and `lint-imports`.

- `git diff main --stat` shows no change under `templates/`, to `urls.py`, or to any migration.
