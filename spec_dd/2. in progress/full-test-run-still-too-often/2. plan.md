### Slice 2: `--upstream-range` drops main's changes that do not meet the branch

With `--upstream-range <old>..<new>`, a path main changed in an app outside the related apps

dependency file from main still forces `full`. It delivers the argument, the classification, the
related apps, the owning-app rules and the `why:` wording together.

```python
def upstream_range_type(value: str) -> str:
    # The range is split in two to build the branch's own diff, so it must hold exactly one
    # `..`: `a...b` and `a..b..c` pass the character check and would split into a different range.
    range_type(value)
    if "..." in value or value.count("..") != 1:
        raise argparse.ArgumentTypeError(f"not a single <rev>..<rev> range: {value!r}")
    return value

parser.add_argument("--upstream-range", type=upstream_range_type, action="append", default=[], ...)
...
if len(args.upstream_range) > 1:
    parser.error("--upstream-range may be given once")
```

**Classification.** `changed_paths()` keeps its signature and result. Its working-tree lookup
moves into a helper it calls, which `main()` also calls for the branch's own diff:

```python
def working_tree_paths() -> tuple[set[str], set[str]]:
    """(uncommitted and untracked paths, the untracked subset)."""

@dataclass(frozen=True)
class UpstreamSplit:
    upstream: frozenset[str]   # changed by the upstream range, absent from the branch's own diff
    own_paths: frozenset[str]  # the branch's own diff

def split_upstream(upstream_range: str, working_tree: set[str]) -> tuple[set[str], UpstreamSplit]:
    """(every path the upstream range changed, how they split).

    The branch's own diff runs from the range's new end to HEAD, plus `working_tree`.
    """
    _old, new = upstream_range.split("..", 1)
    changed = set(range_paths(upstream_range))
    own_paths = set(range_paths(f"{new}..HEAD")) | working_tree
    return changed, UpstreamSplit(frozenset(changed - own_paths), frozenset(own_paths))
```

- `main()` passes the working-tree paths to `split_upstream()` only when `--working-tree` is
  given, else an empty set.
- The branch's own diff reaches git only through `range_paths()`, which already passes
  `--end-of-options`. No second git call is built.
- The changed paths become `paths ∪ changed`. A changed path in `split.upstream` is an upstream
  path; every other changed path is a branch path. The paths of the branch's own diff do not join
  the changed paths.
- A git failure goes through the existing `parser.error("git failed: …")` branch.
- With `edges is None` the related apps cannot be computed: `main()` treats `split.upstream` as
  empty, so every path follows `decide()` and an app-owned path is `full` with
  `docs/app_structure.md missing`.

**Related apps.** Two new functions beside `importers()`:

```python
def runtime_closure(apps: set[str], edges: Edges) -> set[str]:
    """`apps` plus every app their code imports, through any number of runtime deps."""

def app_dependencies(app: str, edges: Edges) -> set[str]:
    """Every app whose code `app`'s code or tests run.

    Runtime deps chain. A test-only dep is one hop from `app` itself, then that app's own
    runtime deps chain: `app`'s tests import it, and it imports them.
    """
    test_only = {dst for src, dst in edges.test if src == app}
    return (runtime_closure({app}, edges) | runtime_closure(test_only, edges)) - {app}
```

`app_dependencies()` takes a short name, where `importers()` takes an `App`, because the branch
apps are held as short names. `branch_apps` is `owning_app(...).short_name` over
`split.own_paths ∪ branch paths`; `related_apps` is `branch_apps` plus `app_dependencies(a, edges)`
for each.

### Slice 4: The checkpoint passes main's range to the selector

After a rebase, `full_run_record.py resolve` tells the selector which part of `<record>..HEAD` main
brought in, and a `full` result says which path forced it.

**Builds on:** slices 2, 3
**Touches:** claude_plugins/sdd/scripts/full_run_record.py, tests/test_full_run_record.py

```python
def merge_base(project_root: Path, revision: str) -> str | None:
    """The merge base of `revision` and `origin/main`, or None when git cannot name one.

    The value goes on to the selector inside a range, so only a full SHA is let through.
    """
    result = git(project_root, "merge-base", "--end-of-options", revision, "origin/main")
    sha = result.stdout.strip()
    return sha if result.returncode == 0 and FULL_SHA.fullmatch(sha) else None

def record_diff(project_root: Path, sha: str) -> tuple[str, ...]:
    """The selector's diff arguments for everything since the recorded commit.

    When main moved under the branch since the record, the part main brought in is passed as
    the upstream range, so the selector can tell it from the branch's own change.
    """
    plain = ("--range", f"{sha}..HEAD", "--working-tree")
    old, new = merge_base(project_root, sha), merge_base(project_root, "HEAD")
    # Equal bases: main has not moved under the branch, so there is no upstream side.
    if old is None or new is None or old == new:
        return plain
    return ("--upstream-range", f"{old}..{new}", *plain)
```

- `resolve()` keeps its first two checks (branch diff `none`, record present and resolvable)
  exactly as they are, then uses `record_diff()`. The targeted `Resolution.diff` is
  `" ".join(diff)`, so it carries the upstream range when one was used. The targeted `why` stays
  `range <sha7>..HEAD`.
- `selected_tier()` becomes `run_selector()` and returns a frozen dataclass

- A `full` resolution's `why` is `selection.full_reason` when present, else the current

- Update the module docstring where it describes how a checkpoint compares HEAD with the record.
