### Slice 1: a table's page size falls back to `DEFAULT_PAGE_SIZE`

      @classmethod
      def get_page_size(cls) -> int:

### Slice 2: a table over a sequence of rows

A `DataTablePanel` whose `get_queryset` returns a list renders, pages and shows its empty state
like a queryset-backed table, and a sequence combined with a query-only feature fails loudly.

**Builds on:** slice 1
**Touches:** freedom_ls/panel_framework/tables.py, freedom_ls/panel_framework/panels.py, freedom_ls/panel_framework/bulk_actions.py, freedom_ls/panel_framework/views.py, freedom_ls/panel_framework/tests/stub_panels.py, freedom_ls/panel_framework/tests/test_tables.py, freedom_ls/panel_framework/tests/test_panels.py, freedom_ls/educator_interface/views.py

- Signatures widen to `QuerySet | Sequence[object]` for the rows and `object` for one row:
  `DataTable.get_queryset` (return), `get_rows`, `get_context`, `get_row_label`, `has_row_detail`,
  and `DataTablePanel.get_queryset` (return) and `narrow` (parameter and return).
- mypy rejects an override whose parameter is narrower than its base. Every override therefore
  takes the widened type and narrows inside with `cast`, as the stubs already do for attributes:
  - `get_row_label(row: Model)` at `educator_interface/views.py:486, 653, 919, 2554`;
  - `has_row_detail(row: Model)` at `educator_interface/views.py:924` and
    `tests/stub_panels.py:407`;
  - `get_rows(cls, request, queryset: QuerySet, query)` at `educator_interface/views.py:936, 1996,
    2509, 2628` (those that override `DataTable.get_rows`).

  Run `uv run mypy freedom_ls` (or the pre-commit hook) to find any other. No `Any`, no
  `# type: ignore`.

  > **Assumed default:** each override narrows its row with `cast`; `DataTable` is not made generic
  > over its row type. Why: the stubs already cast, and a generic `DataTable` is a wider public API
  > change than the spec asks for. To change: Slice 2.
- One private helper in `tables.py` for the callers that can only work on a queryset:

  ```python
  def _require_queryset(rows: QuerySet | Sequence[object], what: str) -> QuerySet:
      """`rows` as a queryset, for a feature a sequence cannot serve."""
      if not isinstance(rows, QuerySet):
          raise ImproperlyConfigured(f"{what} needs a queryset, not a sequence of rows.")
      return rows
  ```

  Used by `bulk_actions.py:659-675` (selection), `views.py:1365` (export), and in `panels.py` by
  `noun`, `noun_singular` and `hidden_by_defaults` where they read `.model` or call `.exists()`.
  That is the branch the spec asks for: none of them reads `.model` off a sequence.
- `DataTablePanel.narrow` detects the sequence once:

  ```python
  rows = self.get_queryset(request) if queryset is None else queryset
  query = self.data_table.parse_query(request, self.table_key)
  if isinstance(rows, QuerySet):
      return query, self.data_table.filter_queryset(request, rows, query)
  self._check_sequence_table()
  return query, rows
  ```

  `_check_sequence_table` raises `ImproperlyConfigured`, naming the table and the offending
  option, when the table declares `search_fields`, any filter, a sortable column or an export
  column, or leaves `noun` or `noun_singular` empty.
- `get_context_data` must call `get_queryset` once for a sequence table: the rows may cost a
  gather. `noun` and `noun_singular` already short-circuit on the table's own values, and
  `hidden_by_defaults` short-circuits before `get_queryset` when the table has no defaulted
  filter; keep both orders.
- `DataTable.get_context` needs no branch: `Paginator` takes a list, and an empty list gives
  `paginator.count == 0`, which already renders the empty state.
- Stubs (`tests/stub_panels.py`): a frozen dataclass row (`StubSequenceRow`: `name`, `kind`,
  `children`), `StubSequenceDataTable` (one text column, `noun = "stub items"`,
  `noun_singular = "stub item"`) and `StubSequenceTablePanel` (`table_key = "sequence"`) whose
  `get_queryset` returns a module-level list. `children` is unused until slice 3.

Tests: a sequence table renders its rows and the footer count from `noun`; it pages (page 2 holds
the rows after the page size); an empty sequence renders the empty state; one parametrised test
over the five `ImproperlyConfigured` cases (search fields, a filter, a sortable column, an export
column, a missing noun); the render stays within `django_assert_max_num_queries(0)`; bulk selection and export over a sequence
panel raise `ImproperlyConfigured`.

### Slice 3: child rows

A table with `has_child_rows` shows each row's children under it, in the table and in cards, with
a chevron on each group row that hides and shows its descendants.

**Builds on:** slice 2
**Touches:** freedom_ls/panel_framework/tables.py, freedom_ls/panel_framework/panels.py, freedom_ls/panel_framework/templates/cotton/data-table.html, freedom_ls/panel_framework/templates/cotton/data-table-card.html, freedom_ls/panel_framework/templates/panel_framework/panels/_data_table_region_base.html, freedom_ls/panel_framework/templates/panel_framework/partials/row_indent.html, freedom_ls/panel_framework/static/panel_framework/js/alpine-components.js, freedom_ls/panel_framework/tests/stub_panels.py, freedom_ls/panel_framework/tests/test_tables.py, freedom_ls/panel_framework/tests/test_panels.py, freedom_ls/panel_framework/tests/components/test_data_table.py, freedom_ls/panel_framework/tests/components/test_data_table_card.py, freedom_ls/panel_framework/tests/playwright/test_data_table_flow.py

Python (`tables.py`):

```python
class DataTable:
    #: Rows may have child rows: full table rows nested under a group row,
    #: which carries a chevron that hides and shows them. Not for a table
    #: with a row detail or bulk actions.
    has_child_rows: bool = False

    @staticmethod
    def get_child_rows(row: object) -> Sequence[object]:
        """This row's child rows, in display order. Only consulted when
        `has_child_rows` is set; no row has any by default."""
        return ()
```

`get_context` replaces the `rows = [...]` comprehension with a depth-first flatten of the page's
rows, done by a module-level helper so it has no closure state:

```python
def _flatten_rows(
    table: type[DataTable],
    rows: Iterable[object],
    region_id: str,
    numbers: Iterator[int],          # itertools.count(1), shared down the recursion
    parent_ids: tuple[str, ...] = (),
) -> Iterator[dict[str, object]]:
    """Each row's dict, followed by its descendants' in display order."""
    for row in rows:
        row_id = f"{region_id}-row-{next(numbers)}"
        children = (
            list(_flatten_rows(table, table.get_child_rows(row), region_id, numbers, (*parent_ids, row_id)))
            if table.has_child_rows else []
        )
        yield {
            "object": row,
            "label": SimpleLazyObject(lambda row=row: table.get_row_label(row)),
            "has_row_detail": table.row_detail_template_name is not None and table.has_row_detail(row),
            "row_id": row_id,
            "depth": len(parent_ids),
            "parent_ids": parent_ids,
            # Direct children only: a grandchild names this row among its parents.
            "child_row_ids": [c["row_id"] for c in children if c["depth"] == len(parent_ids) + 1],
        }
        yield from children
```

The comment on the lazy label in `get_context` (why it is lazy) moves with it.

- The paginator still sees only top-level rows, so a page holds whole groups and `entry_count`
  counts top-level rows. Nothing else in paging changes.
- Every row dict carries the four new keys, with or without `has_child_rows`.
- `has_child_rows` goes into the context dict, the `<c-vars>` of both cotton templates and the
  attribute list in `_data_table_region_base.html`. A key missing from any of the three is dropped
  silently, so add all three together.
- `has_child_rows` with `row_detail_template_name` raises `ImproperlyConfigured` in
  `DataTable.get_context`. `has_child_rows` with bulk actions raises it in
  `DataTablePanel.get_context_data`, where the bulk actions are known.

The depth indent is written once, in a new partial
`panel_framework/partials/row_indent.html`: it prints `ps-8`, `ps-12` or `ps-16` for depth 1, 2 and
3 or more, as literal class names in an `{% if %}` chain so Tailwind finds them, and nothing for
depth 0. The table cell, the card and (slice 4) the spanning cell include it inside their `class`
attribute.

Table markup (`cotton/data-table.html`), only when `has_child_rows`:

- `<table x-data="childRows">`.
- Each `<tr>`: `id="{{ row.row_id }}"`, and, when it has parents,
  `x-show="shown" data-parents="{{ row.parent_ids|join:' ' }}"`.
- The primary column's cell gets the depth indent and wraps its content in `<div class="flex items-center gap-2">`:
  - a group row (`row.child_row_ids`): the chevron button, with the row-detail button's classes
    plus `-my-1 shrink-0`, `aria-expanded="true"`, `x-bind:aria-expanded="expandedAttr"`,
    `aria-controls="{{ row.child_row_ids|join:' ' }}"`, `aria-label="{{ row.label }}"`,
    `data-row="{{ row.row_id }}"`, `x-on:click="toggle"`;
  - any other row: an empty `<span class="size-8 shrink-0">`, so content lines up;
  - then the column's own template.
- A table without `has_child_rows` renders exactly the markup it renders today: every addition

Card markup (`cotton/data-table-card.html`, plus `has_child_rows` passed from `data-table.html`):

- Each `<li>`: `id="{{ row.row_id }}-card"`, the depth indent, and, with parents, `x-show="shown"`

```js
// Child rows (cotton/data-table.html). x-data sits on the <table> and on the
// card list, and the two share nothing. A group row's chevron names its own
// row in data-row; a child row names every group above it in data-parents,
// so closing a group hides all of its descendants and reopening it shows
// each one as its own group left it. Every group starts open, and an htmx
// swap of the region starts a fresh instance, open again. The CSP build
// passes no arguments, which is why the ids travel in data attributes.
// No x-transition: a table row's display cannot animate, and the cards
// behave as the rows do.
Alpine.data("childRows", () => ({
    collapsed: {},
    toggle(event) { const id = event.currentTarget.dataset.row; this.collapsed[id] = !this.collapsed[id]; },
    expandedAttr() { return this.collapsed[this.$el.dataset.row] ? "false" : "true"; },
    shown() { return (this.$el.dataset.parents || "").split(" ").every((id) => !this.collapsed[id]); },
}));
```

def get_reason_form(self, ctx: PanelContext, data: Mapping[str, str] | None = None) -> ReasonForm:
