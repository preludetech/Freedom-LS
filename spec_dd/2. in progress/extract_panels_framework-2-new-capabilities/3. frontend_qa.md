# Frontend QA: panel framework new capabilities

Checks in a browser that the course outline works as a data table with child rows, that the new
reference page examples behave, and that the screens that did not adopt anything look as they did.

Only two places show the new capabilities: the educator course page (child rows, per-row template
rows, compact density, a sequence-backed table, the default page size) and the component reference
page (all of those, plus the reason dialog variants and the `as_of` stamp). No other screen
adopts them.

## Setup

1. Build the stylesheet: `npm run tailwind_build`.
2. Start the server on a free port: `uv run python manage.py runserver $PORT`. Base URL:
   `http://127.0.0.1:$PORT`.
3. Log in at `http://127.0.0.1:$PORT/accounts/login/` with the QA login from
   `.claude/sdd/config.md` (`## QA Login`). That user is staff and an organisation admin of the
   dev organisation.
4. Open `http://127.0.0.1:$PORT/educator/` and note the organisation slug in the URL
   (`/educator/organisations/<slug>/...`).
5. Data, through the QA data helper:
   - `uv run python manage.py qa_create_course_content_preview` gives "QA Preview Course"
     (Welcome, Reading, part "Module one" with two items, part "Empty module", "Feedback survey"),
     "QA Empty Course" and "QA Draft Outline" (in development).
   - A course with a multi-page form (three pages), if the preview course's survey has one page.
   - A course with at least 12 top-level items, one of them a part with three items, placed so
     the part is the 10th item ("QA Long Course"). This is what makes the outline page.
   - A part nested inside a part, holding one topic, in any course ("nested part").
   - An active cohort and a learner, for the regression checks in Test 9.
6. Course pages are at `/educator/organisations/<slug>/courses/<course pk>`; reach them from
   "Courses" in the sidebar. The reference page is `http://127.0.0.1:$PORT/panel-framework/components/`
   (it exists only with `DEBUG` on).

Viewports: 1920 (desktop), 768 (tablet) and 375 (phone). "No sideways scroll" means
`document.documentElement.scrollWidth <= window.innerWidth` after layout settles.

Keep the browser console open for every test. A missing Alpine component (`childRows`) or a
CSP-build Alpine error shows there and nowhere else. Any console error fails the test it appears
in.

## Test 1: the outline as a table (1920)

1. Open "QA Preview Course" at 1920 and find the "Course content" panel.
2. Expect a table with the columns "#", "Title", "Type" and a last column with no visible header.
   Expect the header labels in the same bold uppercase mono style as the Learners table's.
3. Expect the first row to be "Course details", with no number, type "Course" and a small
   "Preview" button.
4. Expect the rows numbered "1.", "2.", "3.", then "3.1", "3.2" under "Module one", then "4." and
   "5.", in the course's order.
5. Expect "Module one" and "Empty module" each to have a chevron before the title, pointing up
   (open), and no "Preview" button. Expect every other row to have "Preview" and no chevron.
6. Expect the titles of rows without a chevron to line up with the titles of rows with one.
7. Expect "Module one"'s two items indented under it, further right than "Module one" itself.
8. Expect "No items in this part." under "Empty module", indented, muted, spanning the Title, Type
   and action columns, with no number, no button, and no hover tint when the pointer is over it.
9. Expect each row with one line of text to be one line high and visibly shorter than a row of the
   Learners table (`/educator/organisations/<slug>/learners/`). Expect all one-line rows the same
   height.
10. Expect a footer under the table reading "7 course outline items" (top-level rows only: the
    part's children are not counted) and no page controls.
11. Expect no search box, no filter button, no sort control and no Export button above the table.
12. Expect no sideways scroll.

## Test 2: opening and closing a part

1. On "QA Preview Course" at 1920, click "Module one"'s chevron. Expect its two items to
   disappear, the chevron to point down, and "Empty module" and the rows after it to move up.
   Expect focus to stay on the chevron.
2. Press Enter. Expect the items back and the chevron up. Press Space. Expect them hidden again.
3. With "Module one" closed, press Tab repeatedly from the chevron. Expect focus to go to the next
   visible row's control, never to a "Preview" button of a hidden row.
4. With a screen reader or the accessibility tree: expect the chevron to be a button named
   "Module one" with expanded true or false matching what is on screen, and the hidden rows absent
   from the tree while closed.
5. Reload the page. Expect every part open again.
6. On the course with the nested part: close the inner part, then close the outer part. Expect
   every descendant hidden. Reopen the outer part. Expect the inner part's row back, still closed,
   with its topic still hidden. Open the inner part. Expect the topic back.
7. Expect the nested part's topic indented further than the inner part, and the inner part further
   than the outer.

## Test 3: a multi-page form

1. Open the course with the three-page form at 1920.
2. Expect the form's row to have a chevron and a "Preview" button, and three page rows under it
   numbered "<n>.1" to "<n>.3", each of type "Page" with its own "Preview".
3. Close the form's row. Expect the three page rows hidden. Open it again.
4. Click a page row's "Preview". Expect the preview dialog for that page ("Page 2 of 3" in it).
   Close it. Expect the outline unchanged, the form still open.
5. Click "Course details"'s "Preview". Expect the course details preview dialog.
6. A form with one page elsewhere in the outline: expect one row, no chevron.

## Test 4: empty and in-development courses

1. Open "QA Empty Course". Expect the "Course details" row, then "No content in this course yet."
   as the empty-state message in the table, with no number and no button. Expect no chevron
   anywhere.
2. Open "QA Draft Outline". Expect the callout "Learners can't see this outline yet. The course is
   marked as still in development." above the table, inside the panel, with the same left and
   right padding as before. Expect the table under it as in Test 1.
3. Open "QA Preview Course". Expect no callout.

## Test 5: a long outline pages

1. Open "QA Long Course" at 1920.
2. Expect the footer to read "Showing 1–10 of <n> course outline items" (the wording the Learners
   table uses), where `<n>` counts "Course details" and the top-level items only, and page
   controls beside it.
3. Expect the part that falls last on page 1 to show all three of its items on page 1: a page
   never cuts a part off from its items.
4. Close a part on page 1, then go to page 2. Expect page 2 to start with the next top-level item,
   numbered in sequence. Expect the address bar to carry the page.
5. Go back to page 1. Expect every part open again (a page change resets them).
6. Reload on page 2. Expect page 2.
7. Edit the URL's page parameter to 999 and to "abc". Expect the last page and the first page, not
   an error.
8. Click "Preview" on a page-2 row. Expect the right item's preview.

## Test 6: the outline on a phone (375) and a tablet (768)

1. Open "QA Preview Course" at 375.
2. Expect cards instead of the table: one card per row, each with its number, kind icon, title and
   "Preview".
3. Expect "Module one"'s two items as their own cards, indented under its card. Expect the nested
   part's topic indented further.
4. Expect a chevron on "Module one"'s and "Empty module"'s cards, at least 44px tall and wide to
   the touch, and card first lines aligned whether or not the card has a chevron.
5. Tap "Module one"'s chevron. Expect its two cards to go, the chevron to turn down. Tap again.
   Expect them back.
6. Expect "No items in this part." as an indented card under "Empty module", with no button.
7. Tap "Preview" on a card. Expect the preview, as a sheet or dialog that fits the screen.
8. Expect every "Preview" at least 44px tall, and no sideways scroll.
9. On "QA Long Course" at 375: expect the footer count and page controls under the cards, and
   page 2 reachable.
10. At 768: expect the table, not cards, with the Type column showing, compact rows one line high,
    and no sideways scroll.
11. Resize from 1920 to 375 with "Module one" closed in the table. Expect the cards to show it
    open: the table and the cards keep separate state. This is expected, not a defect.

## Test 7: reference page, data tables

1. Open the reference page at 1920 and find the "Data table" section. Expect a "Use …" line above
   each example.
2. Row detail example: expect a leading chevron pointing down on each row that has a detail. Click
   one. Expect the detail to open under the row and the chevron to turn up. Click again to close.
3. Child rows example: expect group rows with chevrons pointing up, child rows indented, and one
   note row spanning the columns with no hover tint. Close a group by mouse, then by Enter and by
   Space with focus on the chevron. Expect its children hidden and focus kept.
4. Close an inner group, close and reopen its outer group. Expect the inner group still closed.
5. Compact example: expect rows visibly shorter than the row detail example's rows, each one line.
6. At 375: expect each example as cards, the child rows example's cards indented with working
   chevrons, and no sideways scroll in any of the three.
7. At 768: expect no sideways scroll and one-line compact rows.

## Test 8: reference page, reason dialogs and the lazy panel

1. In the "Reason dialog" section at 1920, expect three examples, each with a "Use …" line.
2. Required: expect a text field labelled "Reason" (no "(optional)").
3. Choice list: expect a select labelled "Reason" whose first option reads "Choose a reason",
   then a text field labelled "Details (optional)".
4. Choice list with required text: expect the same select and a text field labelled "Details".
5. Expect each dialog laid out as the app's confirm dialogs are: a title, the body, a footer with
   "Cancel" at the left and one confirm button at the right, body text at the base size.
6. Click into each field and tab through. Expect a visible focus ring on the select, the text
   field and both buttons.
7. Click a confirm button with the fields empty. Expect the browser not to block the submit with
   its own "Please fill out this field" bubble. (The examples post nowhere, so no server error is
   expected here; the 422 is covered by the automated tests.)
8. In the "Lazy panel" section, expect a line "As of <day month year>, <hh:mm> <zone>" in small
   muted text above the example's body, for example "As of 17 Nov 2026, 14:32 SAST".
9. At 375 and 768: expect no sideways scroll in either section, and the select and text fields no
   wider than their dialog.

## Test 9: what must not have changed

1. Open an active cohort and click "Deactivate". Expect the dialog as before: a "Reason
   (optional)" text field with its help text, no select. Submit with the reason empty. Expect the
   cohort deactivated. Reactivate it.
2. In the same dialog, paste a reason longer than the field allows (over 500 characters, or the
   audit limit shown). Expect the dialog to stay open with the error under the field and the text
   kept.
3. Open the educator dashboard and a cohort's report tab. Expect the lazy panels to load from
   their skeletons as before, with no "As of" line added. The cohort report keeps its own
   "Figures as of" line.
4. Open the Learners table at 1920. Expect the default row height (taller than the outline's),
   10 rows per page, search, filters, sort and the selection checkboxes as before.
5. Open the audit log (History). Expect 25 rows per page and the row-detail chevron opening and
   closing a detail, closed by default.
6. At 375, open the Learners table and the audit log. Expect cards as before, with no indent and
   no stray empty slot before each card's first line (the audit log keeps its chevron slot).
7. Tick two learners and run a bulk action through to its result. Expect it to work as before.
8. Export the Learners table as CSV. Expect the file.

## Test 10: with JavaScript off

1. Disable JavaScript and open "QA Preview Course" at 1920.
2. Expect every row of the outline visible, parts open, since nothing can hide them. The chevrons
   do nothing; that is accepted.
3. On "QA Long Course", click page 2 in the footer. Expect a full page load showing page 2.
