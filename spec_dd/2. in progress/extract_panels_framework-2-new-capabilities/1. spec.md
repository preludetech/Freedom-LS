# Spec: Panel framework new capabilities

Spec 2 of 6 in the Panel framework extraction effort (`spec_dd/1. next/roadmap.md`, "Panel framework
extraction"). Idea: `idea.md`. Answers: `answers.md`. Research: `research_*.md` beside this file.

## Purpose

FLS's upcoming specs need four capabilities from the panel framework, and they have to be in the
package's first tag so the second project never meets an API that changes after it installs. They
are listed under Scope.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| group row | narrowed | `claude_plugins/fls-dev/skills/panel-framework/SKILL.md`: a `DataTable` row with child rows, carrying the chevron that shows and hides them |
| child row | narrowed | same source: a full table row nested under a group row, with its own cells, as opposed to the single detail block `row_detail_template_name` renders |

## Scope

In:

- `ReasonMixin` and `ReasonForm`: a required reason and a reason-choice list.
- `LazyBodyPanel`: an opt-in `as_of` stamp.
- `DataTable`: child rows (table and card layouts), per-row templates, a sequence of rows in place
  of a queryset, a global default page size, and a `compact` density.
- The course outline (`CourseContentPanel`) moves onto `<c-data-table>`, and its
  `HAND_WRITTEN_TABLE_EXEMPTIONS` entry goes.
- Component reference page entries for all of the above, and for the row detail that exists today.

Out:

- Adopting any capability in another FLS screen.
- Changes to the existing row detail (`row_detail_template_name`, `rowDetail`), and a
  fetched-on-open detail.
- An "Other" choice that forces text, a minimum reason length, expand-all and collapse-all
  controls, keeping open state across a swap, a relative ("5 min ago") stamp and a refresh
  control.
- Everything the idea lists as out of scope.

## Decisions

- Child rows are a plain table with a disclosure button per group row, not an ARIA treegrid
  (`research_best_practices.md` §1).
- Group rows start open, and a swap resets them to open. This keeps the outline's QA-passed
  behaviour and the skill's rule. Row detail keeps starting closed.
- A table has child rows or row detail, not both, and child rows never go with bulk actions. No
  consumer needs either combination.

## Requirements

### 1. Required reason and reason choices (`freedom_ls/panel_framework/actions.py`, `forms.py`, `context.py`)

- `ReasonMixin` gains:
  - `reason_required: bool = False` (the idea's name).
  - `reason_choices: Sequence[tuple[str, str]] = ()`, as `(value, label)` pairs.
  - `get_reason_choices(self, ctx: PanelContext) -> Sequence[tuple[str, str]]`, returning
    `reason_choices`. Override it for a list computed per request.
  - `get_reason_form(self, ctx, data=None) -> ReasonForm`. It builds `reason_form_class`, passing
    `required=True` only when `reason_required` is set and `choices=` only when the list is
    non-empty, so a host form with the old `__init__(self, data=None)` keeps working for an
    action that uses neither. `get_context_data` and `handle_submit` both use it, so the list
    rendered is the list validated.
- `ReasonForm.__init__(self, data=None, *, required=False, choices=())`:
  - With choices, a required `reason_choice` `ChoiceField` comes before `reason`, its first
    option an empty placeholder (`reason_choice_placeholder`, "Choose a reason"). A declared list
    makes choosing required. A posted value not in the list is a field error.
  - `reason` is required when `required` is true. `strip=True` already makes whitespace-only
    empty.
  - `use_required_attribute = False`. A required field renders `aria-required="true"` instead, so
    the browser never blocks the submit and the 422 field error is the one path.
  - Labels are class attributes a host subclass rewords, following `reason_label`:

    | Attribute | Default | Used for |
    | --- | --- | --- |
    | `reason_label` | "Reason (optional)" | the text field, optional, no list (unchanged) |
    | `reason_required_label` | "Reason" | the text field, required, no list |
    | `reason_choice_label` | "Reason" | the select |
    | `reason_detail_label` | "Details (optional)" | the text field beside a list, optional |
    | `reason_detail_required_label` | "Details" | the text field beside a list, required |

- `PanelContext` gains `reason_choice: str = ""`, the chosen value (not its label). A valid
  submit sets `reason` and `reason_choice` on `ctx`. `ReasonMixin.handle_submit` stays the only
  validation point (`tests/invariants/test_reason_mixin.py`).
- An invalid submit is a 422 that re-renders the dialog fragment with the bound form, keeping the
  chosen value and the typed text, with the error under its field as the over-long reason has
  today.
- With the defaults, `ReasonForm` and `EducatorReasonForm` render exactly as today, and no action
  using `EducatorReasonMixin` changes. `reason_field.html` keeps rendering through
  `partials/form.html`.

### 2. `as_of` stamp (`freedom_ls/panel_framework/lazy_panels.py`, `templates/panel_framework/panels/_lazy_region.html`)

- `LazyBodyPanel.show_as_of: bool = False` (opt-in, `answers.md`).
- When `show_as_of` is true and the body loaded, the context's `as_of` is the value
  `get_loaded_context` returned under `"as_of"`, else `django.utils.timezone.now()`. A naive
  datetime raises `ValueError`. The `show_as_of` docstring says a panel whose data is gathered or
  cached must return its compute time.
- A new partial `panel_framework/partials/as_of.html` renders a `text-sm text-muted` line: "As of
  <c-datetime :value="as_of" /> {{ as_of|date:"T" }}", e.g. "As of 17 Nov 2026, 14:32 SAST", in
  the current time zone. A zone with no letter abbreviation shows its offset ("-03"), which is
  accepted. `<c-datetime>` gives the `<time datetime>` with the offset.
- `_lazy_region.html` includes the partial in a `{% block as_of %}` inside the `is_loaded`
  branch, above `loaded_body`, when `show_as_of` is set. A region template that overrides
  `region_content` (as `DashboardPanel`'s does) includes the partial itself if it opts in.
- No stamp in the skeleton, in the too-large notice, or when `show_as_of` is false. The three FLS
  lazy panels render as today.

### 3. Data tables (`freedom_ls/panel_framework/tables.py`, `panels.py`, `config.py`, `cotton/data-table.html`, `cotton/data-table-card.html`, `static/panel_framework/js/alpine-components.js`, `tailwind.components.css`)

#### Child rows

- `DataTable` gains `has_child_rows: bool = False` and `get_child_rows(row) -> Sequence[object]`,
  a static hook like `has_row_detail` that returns `()` and is consulted only when
  `has_child_rows` is true.
- `get_context` flattens rows depth-first, each row followed by its children in the hook's order.
  Paging, sorting and search act on top-level rows, so a page holds whole groups and the footer
  counts top-level rows. Each row dict gains:
  - `row_id`: `{region_id}-row-{n}`, unique in the region.
  - `depth`: 0 for top level.
  - `parent_ids`: every ancestor's `row_id`.
  - `child_row_ids`: direct children only.
- Table layout:
  - A group row's primary column cell holds the chevron button before its content: `size-8`,
    `aria-expanded="true"`, `aria-controls` set to the child rows' ids, `aria-label` set to
    `get_row_label(row)`.
  - The primary cell's content is indented by depth with `ps-8`, `ps-12` and `ps-16` for depths 1
    to 3. Deeper rows use the depth-3 indent.
  - A row without children has an empty chevron-width slot, so its content lines up.
- Card layout (below `md`, or narrow with `cards_when_narrow`):
  - Each row is its own card, indented by depth with the same steps on the `<li>`.
  - A group card's chevron sits on its first line at the 44px phone target the row-detail card
    toggle uses, and a leaf card keeps the empty `w-6` slot.
  - Cards use their own ids (`{row_id}-card`) in `aria-controls` and `data-parents`, so no id
    appears twice in the DOM.
- A new framework Alpine component (e.g. `childRows`) replaces `courseOutline`:
  - Registered in the framework's `alpine-components.js`.
  - One instance on the `<table>` and another on the card `<ul>`. The two do not share state.
  - CSP-safe through method references and data attributes, as `courseOutline` is.
  - Closing a group hides every descendant. Reopening restores each descendant group's own
    state.
  - Hidden rows leave the tab order and the accessibility tree (`x-show`).
  - The chevron turns with `group-aria-expanded:rotate-180`.
- `has_child_rows` with `row_detail_template_name`, or with bulk actions, raises
  `ImproperlyConfigured` when the table renders.

#### Per-row templates

- `DataTable.get_row_template_name(row) -> str | None` returns `None` by default. When it returns
  a template, that row:
  - leaves the cells before the primary column empty;
  - renders the template in one cell spanning from the primary column to the last column, with
    the row's depth indent and no hover style;
  - in card layout, renders the template as the card body.
- The row keeps its `<tr>`, `row_id`, `depth` and `parent_ids`, so it hides with its ancestors.
  The template gets `object` and `row`.
- This is the custom child row `answers.md` allows.

#### Sequence-backed tables

- `DataTablePanel.get_queryset`, `DataTable.get_context`, `get_rows`, `get_row_label`,
  `has_row_detail` and the other row hooks take `QuerySet | Sequence[object]` and `object` rows.
  No `Any` and no `# type: ignore`.
- `DataTablePanel` detects a sequence once (in `narrow`). `noun`, `noun_singular` and
  `hidden_by_defaults` branch on it rather than reading `.model`.
- A sequence is allowed only when the table declares no `search_fields`, filters, sortable
  columns or export columns, and sets `noun` and `noun_singular`. Anything else raises
  `ImproperlyConfigured`.
- Paging works on the sequence. An empty sequence renders the table's empty state, as an empty
  queryset does.

#### Page size

- `PanelFrameworkConfig` gains `DEFAULT_PAGE_SIZE` (default 10, today's value).
- `DataTable.page_size: int | None = None`, and a `get_page_size()` classmethod returns
  `page_size` or `config.DEFAULT_PAGE_SIZE`. Every reader uses `get_page_size()`, including the
  two `qa_helpers` commands that read `page_size`.
- The footer count and the page controls follow the page size as they do today.

#### Compact density

- `DataTable.compact: bool = False`. Like every option, it goes through `get_context`, the
  `<c-vars>` of `data-table.html` and `data-table-card.html`, and the attribute list in
  `_data_table_region_base.html`.
- When true, the table root gets `panel-data-table-compact`. From `md` up, an `@layer components`
  rule in `tailwind.components.css` sets `th` and `td` vertical padding to `py-2`, the padding the
  outline hand-sets today.
- Left alone: the toggle cells, the empty-state cell (`py-8`), the open-detail row rules
  (`tailwind.components.css:118-138`), cards below `md`, text size, and button and chevron hit
  areas.
- A compact row with one-line content stays one line at 768px and 1920px.

### 4. The course outline moves onto `<c-data-table>` (`freedom_ls/educator_interface/views.py`, `templates/educator_interface/panels/course_content.html`, `static/educator_interface/js/alpine-components.js`)

- `CourseContentPanel` becomes a sequence-backed `DataTablePanel` with a `table_key`, over a new
  outline `DataTable` with:
  - `has_child_rows = True` and `compact = True`;
  - `noun = "course outline items"` and `noun_singular = "course outline item"`;
  - the default page size, so a long outline pages with the footer count and page controls.

  The region's accessible name follows `noun`, and the tests' selectors change to match.
- Columns:
  - `#`: `tabular-nums`, muted, `w-0`.
  - Title (primary): kind icon, sr-only kind label, title.
  - Type: `md_only`.
  - Actions: the Preview `c-modal-trigger` per row, with an sr-only header through
    `header_class`.

  A `card_template_name` gives the phone card its number, icon, kind label, title and Preview.
  `get_row_label` returns the row's title.
- `OutlineRow` gains `children`, and `outline_rows(course)` returns the top-level rows as a tree.
  The hand-built `row_id`, `parent_ids` and `child_row_ids` go. "No items in this part." and "No
  content in this course yet." become per-row template rows.
- `course_content.html` extends the data-table panel base and keeps the in-development callout in
  the panel's header block.
- The outline keeps the behaviour the tests in `educator_interface/tests/test_views.py:7991-8180`
  check. A selector changes only where framework markup forces it.
- On a phone the outline shows indented cards (`answers.md`).
- `courseOutline` is removed from the educator JS. The `HAND_WRITTEN_TABLE_EXEMPTIONS` entry in
  `freedom_ls/panel_framework/tests/invariants/test_templates.py:474-480` is removed, along with
  the dict and its use if it is left empty.

### 5. Component reference page (`freedom_ls/panel_framework/reference.py`, `templates/panel_framework/reference/`)

- New sections, each example a `<component>-<variant>` id with a one-line "Use …" note:
  - `reason-dialog-`: required, choice list with optional text, and choice list with required
    text.
  - `lazy-panel-`: loaded with the stamp.
  - `data-table-`: row detail, child rows with a per-row template row, and compact.
- The view builds the examples by running real generic example classes (a sequence-backed
  `DataTable`, a `_lazy_region.html` extender, a `confirm.html` extender) with the request. Their
  templates sit under `templates/panel_framework/reference/`, and `tests/test_reference.py`
  renders with a request.
- No FLS nouns. Zero queries, which sequence-backed examples keep. Each new name goes in
  `COMPONENT_NAMES`.

## Testing

Framework tests live under `freedom_ls/panel_framework/tests/`, using stubs in `stub_panels.py`,
`helpers.py` and `tests/templates/`. `tests/conftest.py` gets no edits, because spec 3 edits it in
parallel. Stub tables need no model.

Cases that are easy to miss:

- Reason:
  - The default form renders unchanged.
  - A host `ReasonForm` subclass with the old `__init__` still works.
  - Whitespace-only text counts as empty.
  - The 422 keeps both values.
  - A per-request list is used both to render and to validate.
- `as_of`:
  - Time is frozen.
  - The active zone is not UTC, and the abbreviation and the `<time datetime>` offset are
    asserted.
  - A naive value raises.
  - No stamp in the skeleton or the too-large notice.
- Data tables:
  - Paging counts top-level rows, and a page never splits a group.
  - Table and card ids are distinct.
  - The `ImproperlyConfigured` combinations raise.
  - `DEFAULT_PAGE_SIZE` is overridable through settings.
  - A default table's markup is unchanged.
- Playwright, added as steps of the existing flows (`tests/playwright/test_data_table_flow.py`,
  `test_component_reference_flow.py`, `educator_interface/tests/playwright/test_course_preview_flow.py`):
  - Child rows open and close by mouse, Enter and Space, with focus kept on the chevron.
  - Closing an outer group hides grandchildren, and reopening restores an inner group's closed
    state.
  - Hidden rows are not tabbable.
  - The same works in cards at 375.
  - Compact one-line rows hold at 768 and 1920 (`QA_VIEWPORTS`).
  - The reference sections show no horizontal overflow.
  - Collapsing a part in the outline works on desktop and at 375.
- Invariants pass: Alpine registration, chevron rotation, no hand-written table (without the
  exemption), no raw colours, and public names in each module's `__all__`.

## Open questions

- Q: Is a choice required whenever a list is declared? → A: Yes. (assumed default: the list
  exists to be chosen from, and text stays independent through `reason_required`. Overrule by
  editing Requirements §1.)
- Q: May a table have child rows and row detail at once? → A: No. (assumed default: no consumer
  needs both, and refusing it keeps one toggle per row. Overrule by editing Decisions.)
- Q: Does the `as_of` line sit above or below the loaded body? → A: Above. (assumed default:
  matches the one existing "Figures as of" line in `cohort_report_body_region.html`, and a panel
  can override the block. Overrule by editing Requirements §2.)

## Success criteria

- Every existing reason action, lazy panel and data table renders and submits as before: their
  existing tests pass unchanged.
- An action with `reason_required = True` or `reason_choices` returns 422 with the field error on
  an empty, whitespace-only, missing or unknown value, and its submit reads `ctx.reason` and
  `ctx.reason_choice`.
- The course outline renders through `<c-data-table>`, `HAND_WRITTEN_TABLE_EXEMPTIONS` has no
  entry for it, and `courseOutline` is gone from the educator JS.
- `uv run pytest` passes.
