# Spec: Panel framework new capabilities

Spec 2 of 6 in the Panel framework extraction effort (`spec_dd/1. next/roadmap.md`, "Panel framework
extraction"). Idea: `idea.md`. Answers: `answers.md`. Research: `research_*.md` beside this file.

## Purpose

The panel framework gets the capabilities FLS's upcoming specs need, so they are in the package's
first tag. These are:

- a required reason and a reason-choice list on confirm dialogs,
- an "as of" stamp on lazy panels,
- child rows in a data table, with the course outline moved onto them,
- a compact table density.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| group row | narrowed | `claude_plugins/fls-dev/skills/panel-framework/SKILL.md`: a `DataTable` row with child rows, carrying the chevron that shows and hides them |
| child row | narrowed | same source: a full table row nested under a group row, with its own cells, as opposed to the single detail block `row_detail_template_name` renders |

## Scope

In:

- `ReasonMixin` and `ReasonForm`: a required reason and a reason-choice list.
- `LazyBodyPanel`: an opt-in `as_of` stamp.
- `DataTable`: child rows (table and card layouts), per-row templates, a sequence of rows in place
  of a queryset, and a `compact` density.
- The course outline (`CourseContentPanel`) moves onto `<c-data-table>`. Its
  `HAND_WRITTEN_TABLE_EXEMPTIONS` entry is removed.
- Component reference page entries for all of the above, and for the row detail that exists
  today.

Out:

- Adopting any capability in another FLS screen.
- The existing row detail (`row_detail_template_name`, `rowDetail`) keeps its behaviour and look.
  `design_educator_interface_audit_log` built it in the framework and the audit log already uses
  it, so nothing moves out of `educator_interface`. A fetched-on-open detail is not built, because
  the tables are paged.
- An "Other" choice that forces text, a minimum reason length, expand-all and collapse-all
  controls, keeping open state across a swap, a relative ("5 min ago") stamp and a refresh
  control.
- Everything the idea lists as out of scope: the sticky action rail, preview-then-confirm,
  import, bulk-bar and filter changes, cutting FLS imports (specs 3 and 4), and packaging.

## Decisions

- **Required and choices are set on the action, not the form.** `reason_required` and
  `reason_choices` are action attributes, as the idea names them, so one form class serves both
  required and optional actions. `ReasonMixin` passes them into the form. Labels and length stay on
  the form subclass, as spec 1 settled.
- **A declared choice list makes choosing required.** A list exists to be chosen from. Whether the
  text is required is still `reason_required`, independent of the list.
- **Child rows use plain table semantics with a disclosure button per group row, not an ARIA
  treegrid.** The outline is read-only, with buttons in its cells. A treegrid's grid navigation
  would replace the table's reading model for no gain (`research_best_practices.md` §1).
- **Group rows start open, and a swap resets them to open.** This keeps the outline's QA-passed
  behaviour and the skill rule. Row detail keeps starting closed.
- **A table has child rows or row detail, not both.** No consumer needs both. Setting both raises
  `ImproperlyConfigured` when the table renders.
- **Compact changes cell padding from `md` up, and nothing else.** Cards below `md`, text size,
  and button and chevron hit areas stay as they are (WCAG 2.5.8, and the skill's 44px phone
  buttons). Compact padding is `py-2`, which the outline hand-sets today, so the outline looks the
  same on desktop after the move.
- **The `as_of` stamp is a block in `_lazy_region.html`, not a cotton component.** That is where
  the loaded state is drawn, so every lazy panel gets it with no template change. A panel that
  wants it elsewhere overrides the block.

## Requirements

### 1. Required reason and reason choices (`freedom_ls/panel_framework/actions.py`, `forms.py`, `context.py`)

- `ReasonMixin` gains:
  - `reason_required: bool = False`.
  - `reason_choices: Sequence[tuple[str, str]] = ()`, as `(value, label)` pairs.
  - `get_reason_choices(self, ctx: PanelContext) -> Sequence[tuple[str, str]]`, returning
    `reason_choices`. Override it for a list computed per request.
  - `get_reason_form(self, ctx, data=None) -> ReasonForm`, which builds `reason_form_class` with
    `required=self.reason_required` and `choices=self.get_reason_choices(ctx)`. Both
    `get_context_data` and `handle_submit` use it, so the list rendered and the list validated are
    the same.
- `ReasonForm.__init__(self, data=None, *, required=False, choices=())`:
  - With choices, a `reason_choice` `ChoiceField` comes before `reason`. It is required, and its
    first option is an empty placeholder (`reason_choice_placeholder`, "Choose a reason"). A posted
    value not in the list is a field error.
  - `reason` is required when `required` is true. `strip=True` already makes whitespace-only
    empty.
  - Labels are class attributes a host subclass rewords. They follow `reason_label`:

    | Attribute | Default | Used for |
    | --- | --- | --- |
    | `reason_label` | "Reason (optional)" | the text field, optional, no list (unchanged) |
    | `reason_required_label` | "Reason" | the text field, required, no list |
    | `reason_choice_label` | "Reason" | the select |
    | `reason_detail_label` | "Details (optional)" | the text field beside a list, optional |
    | `reason_detail_required_label` | "Details" | the text field beside a list, required |

- `PanelContext` gains `reason_choice: str = ""`, the chosen value (not its label). On a valid
  submit, `ReasonMixin.handle_submit` sets both `reason` and `reason_choice` on `ctx`.
  `handle_submit` stays the only validation point (`tests/invariants/test_reason_mixin.py`).
- An invalid submit is a 422 that re-renders the dialog fragment with the bound form. The 422
  keeps the chosen value and the typed text. The error sits under its field, as the over-long
  reason does today.
- A required field is marked required in its markup (`required` or `aria-required`), and its
  label does not say "(optional)".
- With the defaults, a `ReasonForm` and `EducatorReasonForm` render exactly as today: one optional
  `reason` field, the same label, the same length. None of the actions using `EducatorReasonMixin`
  change. `remove_staff_from_cohort_confirmation.html` keeps working.
- `reason_field.html` keeps rendering through `partials/form.html`. The select needs no markup of
  its own beyond what that partial gives a `ChoiceField`.

### 2. `as_of` stamp (`freedom_ls/panel_framework/lazy_panels.py`, `templates/panel_framework/panels/_lazy_region.html`)

- `LazyBodyPanel.show_as_of: bool = False`.
- When `show_as_of` is true and the body loaded, the context's `as_of` is the value
  `get_loaded_context` returned under `"as_of"`, else `django.utils.timezone.now()`. A naive
  datetime raises `ValueError`. A panel whose data is gathered or cached must return its compute
  time, and the `show_as_of` docstring says so.
- `_lazy_region.html` gains `{% block as_of %}` inside the `is_loaded` branch, above
  `loaded_body`. When `show_as_of` is set it renders a `text-sm text-muted` line: "As of
  <c-datetime :value="as_of" /> <zone>". `<zone>` is `{{ as_of|date:"T" }}` in the current time
  zone, e.g. "As of 17 Nov 2026, 14:32 SAST". `<c-datetime>` already gives a `<time datetime>`
  with the offset.
- No stamp in the skeleton, in the too-large notice, or when `show_as_of` is false.
  `CohortNeedsAttentionPanel`, `CohortReportBodyPanel` and `DashboardPanel` render as today.

### 3. Child rows (`freedom_ls/panel_framework/tables.py`, `panels.py`, `cotton/data-table.html`, `cotton/data-table-card.html`, `static/panel_framework/js/alpine-components.js`, `tailwind.components.css`)

- `DataTable` gains `has_child_rows: bool = False` and `get_child_rows(row) -> Sequence[object]`,
  a static hook like `has_row_detail` that returns `()` by default and is only consulted when
  `has_child_rows` is true.
- `get_context` flattens rows depth-first: each row is followed by its children, in the hook's
  order. Paging, sorting and search act on top-level rows only, and children always follow their
  parent. Each row dict gains:
  - `row_id`: `{region_id}-row-{n}`, unique in the region.
  - `depth`: 0 for top level.
  - `parent_ids`: every ancestor's `row_id`.
  - `child_row_ids`: direct children only.
- Table layout:
  - A group row's primary column cell holds the chevron button before its content. The button is
    `size-8`, with `aria-expanded="true"`, `aria-controls` set to the child rows' ids, and
    `aria-label` set to `get_row_label(row)`.
  - The primary cell's content is indented by depth: `ps-8`, `ps-12` and `ps-16` for depths 1 to
    3. Deeper rows use the depth-3 indent.
  - A row without children gets no chevron. Its content lines up with siblings that have one.
- Card layout (below `md`, or narrow with `cards_when_narrow`):
  - Each row is its own card, indented by depth.
  - A group card has the same chevron on its first line, at the 44px phone touch target the
    row-detail card toggle uses.
- A new framework Alpine component (e.g. `childRows`) replaces `courseOutline`. It is used on the
  `<table>` and the card `<ul>`, and registered in the framework's `alpine-components.js`.
  - It works with the CSP build: no inline expressions or arguments, and rows are named through
    data attributes.
  - Closing a group hides every descendant row or card. Reopening restores each descendant group
    to its own state.
  - Hidden rows leave the tab order and the accessibility tree (`x-show`, i.e. `display: none`).
  - The chevron turns with `group-aria-expanded:rotate-180` (invariant
    `test_every_expand_chevron_turns_when_its_control_opens`).
- `DataTable` gains `get_row_template_name(row) -> str | None`, which returns `None` by default.
  When it returns a template, that row renders the template in one cell spanning the data columns,
  with no hover style, in place of the column cells. In card layout, the template is the card's
  body.
  - The row keeps its `<tr>`, `row_id`, `depth` and `parent_ids`, so it hides with its ancestors.
  - The template gets `object` and `row`.
  - This is the "fully custom child row" `answers.md` asks for. The outline uses it for "No items
    in this part." and "No content in this course yet.".
- A `DataTablePanel` may return a sequence of row objects from `get_queryset` instead of a
  queryset when its table declares no `search_fields`, filters, sortable columns or export
  columns.
  - Paging works on the sequence.
  - `noun` and `noun_singular` must be set, because there is no model to name the rows. Leaving
    them unset raises `ImproperlyConfigured`.
  - Any other combination with a sequence raises `ImproperlyConfigured`.
- With `has_child_rows` false (the default), every existing table renders unchanged.

### 4. Compact density (`tables.py`, `cotton/data-table.html`, `templates/panel_framework/panels/_data_table_region_base.html`, `tailwind.components.css`)

- `DataTable.compact: bool = False`. Like every option, it is passed through `get_context`, the
  `<c-vars>` of `data-table.html` and `data-table-card.html`, and the attribute list in
  `_data_table_region_base.html`.
- When true, the table root gets a modifier class (`panel-data-table-compact`). From `md` up, that
  class sets `th` and `td` vertical padding to `py-2`. The row-detail and child-row toggle cells
  keep their own padding, and the open-detail row rules (`tailwind.components.css:118-138`) still
  join a detail to its row.
- A compact row with one-line content is one line at 768px and 1920px.
- `npm run tailwind_build` after the CSS change.

### 5. The course outline moves onto `<c-data-table>` (`freedom_ls/educator_interface/views.py`, `templates/educator_interface/panels/course_content.html`, `static/educator_interface/js/alpine-components.js`)

- `CourseContentPanel` becomes a `DataTablePanel` over a new `DataTable` for the outline. It sets
  `has_child_rows = True`, `compact = True` and `noun = "course outline"`, which keeps the region's
  `aria-label="Course outline"`.
- Its columns are `#` (`tabular-nums`, muted, `w-0`), Title (primary: kind icon, sr-only kind
  label, title), Type (`md_only`) and Actions (the Preview `c-modal-trigger` per row, as today).
  `OutlineRow` and `outline_rows(course)` supply the top-level rows and `get_child_rows`. The
  hand-built `row_id`, `parent_ids` and `child_row_ids` give way to the framework's.
- Kept, as the outline's tests in `educator_interface/tests/test_views.py:7991-8180` check:
  - the numbering;
  - "Course details" first;
  - part rows as group rows whose `aria-label` is the part title;
  - a multi-page form expanding into one row per page, and a one-page form as a single row;
  - "No items in this part." and "No content in this course yet.";
  - the in-development callout;
  - the Preview triggers and their query strings;
  - the bounded query count.

  Selectors the tests use change only where framework markup forces it, and each such change is
  made in the test.
- On a phone the outline shows indented cards (`answers.md`), not today's table.
- `courseOutline` is removed from the educator JS. Removing the `HAND_WRITTEN_TABLE_EXEMPTIONS`
  entry in `freedom_ls/panel_framework/tests/invariants/test_templates.py:474-480` makes
  `test_no_template_hand_writes_a_table_outside_the_table_components` cover the outline. Remove
  the dict and its use if it is left empty.

### 6. Component reference page (`freedom_ls/panel_framework/reference.py`, `templates/panel_framework/reference/_examples.html`)

New sections, each example a `<component>-<variant>` id with a one-line "Use …" note:

- `reason-dialog-`: required, choice list with optional text, and choice list with required text.
- `lazy-panel-`: loaded with the stamp.
- `data-table-`: row detail, child rows (with a per-row template row) and compact.

Example names and data are generic (no FLS nouns). The page still renders with zero queries, so
examples use static data in `EXAMPLE_CONTEXT`. Each new name goes in `COMPONENT_NAMES` in
`tests/test_reference.py`.

## Testing

Framework tests under `freedom_ls/panel_framework/tests/`, using stubs in `stub_panels.py`,
`helpers.py` and `tests/templates/`. `tests/conftest.py` gets no edits (spec 3 edits it in
parallel). Stub tables need no model, and a sequence-backed stub needs no table.

- Reason (`test_actions.py`, `test_forms.py`):
  - The default form is unchanged.
  - A required reason submitted empty or whitespace-only is a 422 with the field error.
  - A missing choice and a value not in the list are each a 422.
  - The 422 keeps the chosen value and the text.
  - A valid submit puts `reason` and `reason_choice` on `ctx`.
  - A per-request list from `get_reason_choices` is used both to render and to validate.
  - The invariant `test_reason_mixin.py` still passes.
- `as_of` (`test_lazy_panels.py`):
  - Off by default: no stamp.
  - On with no value: render time, with time frozen.
  - On with a supplied value: that value.
  - Rendered in a non-UTC active zone, with the zone abbreviation and `<time datetime>` offset.
  - No stamp in the skeleton or the too-large notice.
  - A naive value raises.
- Child rows (`test_tables.py`, `components/test_data_table*.py`):
  - Depth-first order, ids, depth, `parent_ids` and `child_row_ids`.
  - Paging counts top-level rows only.
  - The chevron's `aria-expanded`, `aria-controls` and label.
  - The indent classes, and the per-row template row.
  - Cards carry the same contract.
  - `has_child_rows` with `row_detail_template_name` raises.
  - A sequence with search or sort, or without a `noun`, raises.
- Compact: the modifier class is present only when set. A default table's markup is unchanged.
- Playwright (`tests/playwright/test_data_table_flow.py`, `test_component_reference_flow.py`):
  - Child rows close and open by mouse and by keyboard (Enter, Space). Focus stays on the
    chevron.
  - Closing an outer group hides grandchildren, and reopening restores an inner group's closed
    state.
  - Hidden rows are not tabbable.
  - The same at 375px in cards.
  - A compact table's one-line rows are one line at 768 and 1920.
  - Reference page sections show at `QA_VIEWPORTS` with no horizontal overflow.
- Educator: the outline tests in `test_views.py` pass. A Playwright test covers collapsing a part
  in the outline on desktop and at 375px.
- Invariants pass: Alpine registration, chevron rotation, no hand-written table (now without the
  exemption), no raw colours, public names (new public names go in each module's `__all__`).

## Open questions

- Q: Is a choice required whenever a list is declared? → A: Yes. (assumed default: the list
  exists to be chosen from, and text stays independent through `reason_required`. Overrule by
  editing Decisions and Requirements §1.)
- Q: Does the `as_of` line sit above or below the loaded body? → A: Above. (assumed default:
  matches the one existing "Figures as of" line in `cohort_report_body_region.html`, and a panel
  can override the block. Overrule by editing Requirements §2.)
- Q: May a table have child rows and row detail at once? → A: No. (assumed default: no consumer
  needs both, and refusing it keeps one toggle per row. Overrule by editing Decisions.)

## Success criteria

- An action with `reason_required = True` returns 422 on an empty or whitespace-only reason, and
  the dialog re-renders with the error under the field.
- An action with `reason_choices` (fixed or from `get_reason_choices`) renders a select before the
  text, rejects a missing or unknown value with 422, and its submit reads `ctx.reason_choice` and
  `ctx.reason`.
- Every existing reason action renders and submits as before (existing tests pass unchanged).
- A `LazyBodyPanel` with `show_as_of = True` shows "As of <date>, <time> <zone>" in a `<time
  datetime>` once loaded. Without it, no stamp renders.
- A `DataTable` with `has_child_rows` renders group rows whose chevrons hide and show all
  descendants, in the table and in cards, by mouse and keyboard.
- `HAND_WRITTEN_TABLE_EXEMPTIONS` no longer lists `course_content.html`. The outline renders
  through `<c-data-table>`, and its existing tests pass.
- `courseOutline` no longer exists in the educator JS.
- A `DataTable` with `compact = True` has `py-2` cells from `md` up, and its cards are unchanged.
- The reference page shows `reason-dialog-*`, `lazy-panel-*` and `data-table-*` examples, renders
  with zero queries, and has no FLS nouns in those sections.
- `uv run pytest` passes.
