# Spec: educator reference panel and reference topic preview

Spec 3 of 4 in the Reference material effort (`spec_dd/1. next/roadmap.md`, "Reference material").
Inputs: `idea.md`, `answers.md` and the `research_*.md` files beside this spec.

## Purpose

`reference-material-content-1-authoring` lets a course list `CourseReferencePart` rows
(`Course.reference_parts`), but the educator course page shows only the learning path
(`Course.items`), and `PreviewContentAction` finds only learning-path items, so a reference topic's
preview is a 404. Educators who review a course cannot see its reference material. After this spec
the course page has a "Reference" panel listing the course's reference parts and their topics, each
topic previewable the way a learning-path topic is.

## Scope

In:

- A "Reference" panel on the educator course page, directly after "Course content", always shown.
- Reference topic previews through `PreviewContentAction`.
- The educator-interface skill and the product docs.

Out (each owned elsewhere):

- Library-course wording ("Lessons 0", "No content in this course yet.", progress figures):
  `reference-material-content-4-library-courses`. `outline_rows` is not changed here, so that spec
  can change its empty note without conflict.
- The admin inline: `reference-material-content-1-authoring`. Learner-side reading:
  `reference-material-content-2-learner-reference`.
- Editing, reordering or attaching reference parts from the educator interface; forms, PDFs and files
  in reference; nesting deeper than part then topics.

## Decisions

- **The Reference panel is a concrete subclass of `CourseContentPanel`.** The availability gate is
  applied in three places today (`outline`, the template's withheld note, `get_actions()`). Inheriting
  all three is the only way they cannot drift apart. `CourseContentPanel` gains two small hook methods
  so that the subclass overrides only which rows are built and which actions are offered, never the
  gate. This is a concrete class, not an ABC.
- **Each panel's preview action finds only its own section.** `PreviewContentAction` is constructed
  with the section it looks in: the learning path (the default, today's behaviour) or the reference
  parts. A reference item id sent to the "Course content" panel's action URL is a 404, as is a
  learning-path id sent to the Reference panel's URL. A preview URL answers only for a row its panel
  lists.
- **The lookup starts from the authorised course.** The action finds reference items by walking
  `course.reference_parts` → `course_part.collection_items()`, never by querying
  `ContentCollectionItem` by pk, so an item from another course, another site or a part the course
  does not list is a 404 by construction. A part shared by several courses is reachable only through
  a course that lists it.
- **The same action class, not a new one.** Reusing `PreviewContentAction` keeps the preview modal,
  its 404 family and any gate added to the action later
  (`sacaa-compliance-content-versions-and-access-4-question-access`) on both panels.
- **The panel always shows** (`answers.md`). A course with no reference parts shows one note row
  "No reference material in this course yet.", the same mechanism as the "Course content" empty note.
  The note row is not counted, so the footer count is empty.
- **No "in development" callout on Reference.** That callout is about the learning-path outline.

## Requirements

### Rows (`freedom_ls/educator_interface/panels/course/content_preview.py`)

- Lift the `CoursePart` branch of `_outline_item_rows` into a function that takes a `CoursePart` and
  its number, and returns the group row with its child rows or the "No items in this part." note.
  `_outline_item_rows` calls it for its part case. The learning-path output is unchanged.
- New `reference_rows(course: Course) -> list[OutlineRow]`: one group row per
  `course.reference_parts` row in `order`, numbered `1.`, `2.`, …, with child rows `1.1`, `1.2`, …, built
  by the lifted function. There is no "Course details" row. A course with no reference parts returns
  the single note row "No reference material in this course yet.".
- `reference_rows` reads `course.reference_parts` with `select_related("course_part")`. Its query
  count grows with the number of reference parts, never with the number of topics.
- A reference part holding a `Form` or a nested `CoursePart` is impossible after validation but
  allowed by the database. Such a part renders through the existing row code without error and
  without special handling.

### Panel

- `CourseContentPanel` gets a hook that builds its rows (`outline_rows(course)` by default) and a hook
  that lists its actions when preview is available (`[PreviewContentAction(), PreviewCourseDetailsAction()]`
  by default). `outline` and `get_actions()` keep the `preview_available` check and call the hooks
  only when it passes.
- New `CourseReferencePanel(CourseContentPanel)`: `title = "Reference"`, `table_key = "reference"`,
  `data_table = ReferenceOutlineTable`, rows from `reference_rows`, actions
  `[PreviewContentAction(<reference section>)]` only, and its own template.
- New `ReferenceOutlineTable(CourseOutlineTable)` with `noun = "reference items"` and
  `noun_singular = "reference item"`. The footer counts parts and topics at every depth, excluding note
  rows (`_outline_content_count`), so it reads e.g. "5 reference items". The "Course content" footer
  ("course outline items") never counts reference rows.
- `freedom_ls/educator_interface/panels/course/instance_view.py`: add `"reference": CourseReferencePanel`
  to `CoursePanelStack.children` between `"content"` and `"cohorts"`.
- Columns, cell partials, group rows open by default, and the "Preview" button on each topic row
  (`aria-label="Preview <title>"`) are the outline table's, unchanged. There are no deadline or
  progress columns. A topic listed both on the learning path and in a reference part gets the same
  accessible name in both panels, which is acceptable because each panel has its own heading.

### Template

- New `educator_interface/templates/educator_interface/panels/course_reference.html` extends
  `course_content.html` and empties `panel_header`, so the withheld note ("Content preview isn't
  shared with your organisation.", `data-testid="preview-withheld"`) comes from one template.
  Tests select that note scoped to `section[data-panel='<key>']`.

### Preview (`PreviewContentAction`)

- Constructor argument for the section, defaulting to the learning path. One module-level function
  returns the candidate items for a course and a section; the learning-path branch is today's
  `_all_collection_items(course.collection_items())`, and the reference branch is
  `_all_collection_items` over each reference part's `collection_items()`.
- Everything else is unchanged: the `HX-Request` check, `uuid_or_404`, a `CoursePart` target being a
  404, `page` only on a form, and `modal/content_preview.html` titled "<title> (Preview)" with the
  "Topic" chip and content in the reading column. `_form_preview_context` and the string
  `show_answer_key` stay in `content_preview.py` (`test_answer_key_flag.py`).

### Permission and withholding

- For an organisation that holds the course only through a registration (`_preview_available` false),
  the Reference panel shows the withheld note, no rows and no actions, so its preview URL is a 404.
- An unseen course is a 404 for the panel and its action through `CourseConfig.authorise_instance`, as
  today.

## Testing

In `freedom_ls/educator_interface/tests/panels/course/test_content_preview.py` unless noted. Build
data with `CourseReferencePartFactory`.

- Reference rows: parts in `order`, numbered `1.` / `1.1` independently of the learning path, an
  empty part's note, the empty-course note row, no "Course details" row, and a Form or nested part in a
  reference part rendering without error.
- The learning-path outline is unchanged, including its count, for a course with reference parts.
- Footer: "N reference items" counts parts and topics. The empty case has no count.
- The panel stack order is details, content, reference, cohorts, learners.
- Reference preview: 200 with "<title> (Preview)" and the Topic chip for an own reference topic. A 404
  for a reference id on the content panel URL, a learning-path id on the reference URL, an item of a
  reference part listed only by another course, an item on another site, a part row, and a missing or
  malformed id.
- A part shared by two courses previews through each course that lists it, and 404s through a course
  that does not.
- Withholding: extend the `PREVIEW_AVAILABLE` parametrised tests (over `course_per_reach_row`) to the
  Reference panel's rows, note and actions. Add `preview_content` on the reference panel to
  `tests/invariants/test_course_shares.py::test_revoking_a_share_makes_the_content_previews_answer_404`.
- Query count: building the Reference panel stays bounded as the number of topics per part grows, in
  the style of `test_course_content_query_count_stays_bounded_as_children_grow`.
- `_content_action_url` in `tests/helpers.py` takes the panel key.
- Playwright (`tests/playwright/test_course_preview_flow.py`): open a reference topic's preview from
  the Reference panel. Re-run `test_touch_targets.py`.
- The automatic invariants (`walk_interface`, organisation isolation, permission matrix, system checks
  on unique `table_key` and sequence tables, template rules) pass with the new panel.

## Success criteria

- On the demo course "Functionality Demo - Reference Material", the course page shows a "Reference"
  panel after "Course content" listing its two reference parts and their topics as `1.`, `1.1`, ….
- Every reference topic row's "Preview" opens "<title> (Preview)" with the Topic chip.
- A course with no reference parts shows the panel with "No reference material in this course yet."
  and no footer count.
- For a registration-only organisation, both panels show "Content preview isn't shared with your
  organisation." and every reference preview URL is a 404.
- A reference item id on the "Course content" action URL, and any item of another course, is a 404.
- "Course content"'s rows and footer count are identical with and without reference parts.
- `uv run pytest` passes, including the invariants and `manage.py check`.
