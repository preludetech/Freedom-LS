# Spec: educator reference panel and reference topic preview

Spec 3 of 4 in the Reference material effort (`spec_dd/1. next/roadmap.md`, "Reference material").
Inputs: `idea.md`, `answers.md` and the `research_*.md` files beside this spec.

## Purpose

After this spec the educator course page has a "Reference" panel listing the course's reference
parts (`Course.reference_parts`) and their topics, and each topic previews the way a topic on the
learning path does. Why: `idea.md`.

## Scope

In:

- A "Reference" panel on the educator course page, directly after "Course content", always shown.
- Reference topic previews through `PreviewContentAction`.
- The educator-interface skill and the product docs.

Out (each owned elsewhere):

- Library-course wording ("Lessons 0", "No content in this course yet.", progress figures):
  `reference-material-content-4-library-courses`. `outline_rows` is not changed here, so that spec
  can change its empty note without conflict.
- The admin inline: `reference-material-content-1-authoring`. Learner-side reading:
  `reference-material-content-2-learner-reference`.
- Editing, reordering or attaching reference parts from the educator interface; forms, PDFs and files
  in reference; nesting deeper than part then topics.

## Decisions

- **The Reference panel is a concrete subclass of `CourseContentPanel`.** The availability gate is
  applied in three places (`outline`, the template's withheld note, `get_actions()`), and inheriting
  all three is the only way they cannot drift apart.
- **Each panel's preview action looks in one list of the course.** The id of a collection item in a
  reference part sent to the "Course content" panel's action URL is a 404, as is the id of a
  collection item on the learning path sent to the Reference panel's URL. A preview URL answers only
  for a row its panel lists.
- **The lookup starts from the authorised course.** The action finds a reference part's collection
  items by walking `course.reference_parts` → `course_part.collection_items()`, never by querying
  `ContentCollectionItem` by pk, so a collection item from another course, another site or a part the
  course does not list is a 404 by construction. A part shared by several courses is reachable only
  through a course that lists it.
- **The same action class, not a new one.** Reusing `PreviewContentAction` keeps the preview modal,
  its 404 family and any gate added to the action later
  (`sacaa-compliance-content-versions-and-access-4-question-access`) on both panels.
- **The panel always shows** (`answers.md`), with an empty note row when the course has no reference
  parts. It is a note row, not the framework's empty table row, because "Course content" shows its
  empty note the same way.
- **No `Course` helper for reference parts.** `reference_rows` and the preview lookup read
  `course.reference_parts.select_related("course_part")` directly. If
  `reference-material-content-2-learner-reference` lands a helper first, use it.
- **No "in development" callout on Reference.** That callout is about the learning-path outline.

## Requirements

### Rows (`freedom_ls/educator_interface/panels/course/content_preview.py`)

- Reference parts and learning-path parts build their group row, child rows and "No items in this
  part." note through the same function, taking `(part: CoursePart, number: str, *, nested: bool)`.
  The learning-path output is unchanged.
- New `reference_rows(course: Course) -> list[OutlineRow]`: one group row per
  `course.reference_parts` row in `order`, numbered `1.`, `2.`, … (`nested=False`), with child rows
  `1.1`, `1.2`, …. There is no "Course details" row. A course with no reference parts returns the
  single row `OutlineRow(number="", title="", kind="course", note="No reference material in this
  course yet.")`, which `course_outline_note.html` renders as `<c-panel-empty-state>`.
- Building the rows costs a number of queries that grows with the number of reference parts, never
  with the number of topics.
- A reference part holding a `Form` or a nested `CoursePart` is impossible after validation but
  allowed by the database. Such a part renders through the existing row code without error and
  without special handling; a `Form` there may cost one query of its own.

### Panel

- `CourseContentPanel` gets `build_rows(self, course: Course) -> list[OutlineRow]` (returns
  `outline_rows(course)`) and `preview_actions(self) -> list[PanelAction]` (returns
  `[PreviewContentAction(), PreviewCourseDetailsAction()]`). `outline` and `get_actions()` keep the
  `preview_available` check and call these only when it passes.
- New `CourseReferencePanel(CourseContentPanel)`: `title = "Reference"`, `table_key = "reference"`,
  `data_table = ReferenceOutlineTable`, `template_name` the new template, `build_rows` returning
  `reference_rows(course)`, and `preview_actions` returning
  `[PreviewContentAction(course_list="reference")]`.
- New `ReferenceOutlineTable(CourseOutlineTable)` with `noun = "reference outline items"` and
  `noun_singular = "reference outline item"`. The footer counts parts and topics at every depth,
  excluding note rows (`_outline_content_count`), so it reads e.g. "5 reference outline items". The
  "Course content" footer ("course outline items") never counts reference rows.
- `freedom_ls/educator_interface/panels/course/instance_view.py`: add `"reference": CourseReferencePanel`
  to `CoursePanelStack.children` between `"content"` and `"cohorts"`.
- Columns, cell partials, group rows open by default, and the "Preview" button on each topic row are
  the outline table's. There are no deadline or progress columns.
- The outline table (`CourseOutlineTable`, so both outline panels) gives its `#`, Type and Actions
  columns fixed widths, so "Course content" and "Reference" line those columns up at every table
  width. It declares `cards_when_narrow = True`, so both outlines show as cards at 768, on a phone
  and beside an open quick view.

### Template

- New `educator_interface/templates/educator_interface/panels/course_reference.html` extends
  `course_content.html` and empties `panel_header`, so the withheld note ("Content preview isn't
  shared with your organisation.", `data-testid="preview-withheld"`) comes from one template.
  Tests select that note scoped to `section[data-panel='<key>']`.

### Preview (`PreviewContentAction`)

- `PreviewContentAction.__init__(self, course_list: Literal["learning_path", "reference"] =
  "learning_path")`. A module-level `_course_list_items(course, course_list)` returns the collection
  items the action searches: `_all_collection_items(course.collection_items())` for the learning
  path, and `_all_collection_items` over each reference part's `collection_items()` for reference.
- Everything else is unchanged: the `HX-Request` check, `uuid_or_404`, a collection item whose child
  is a `CoursePart` being a 404, `page` only on a form, and `modal/content_preview.html` titled
  "<title> (Preview)" with the "Topic" chip and content in the reading column.
  `_form_preview_context` and the string `show_answer_key` stay in `content_preview.py`
  (`test_answer_key_flag.py`).

### Permission and withholding

- For an organisation that holds the course only through a registration (`_preview_available` false),
  the Reference panel shows the withheld note, no rows and no actions, so its preview URL is a 404.
- An unseen course is a 404 for the panel and its action through `CourseConfig.authorise_instance`, as
  today.

## Testing

In `freedom_ls/educator_interface/tests/panels/course/test_content_preview.py` unless noted. Build
data with `CourseReferencePartFactory`.

- Reference rows: parts in `order`, numbered `1.` / `1.1` independently of the learning path, an
  empty part's note, the empty-course note row, no "Course details" row, and a Form or nested part in a
  reference part rendering without error.
- The learning-path outline is unchanged, including its count, for a course with reference parts.
- Footer: "N reference outline items" counts parts and topics. The empty case has no count.
- The panel stack order is details, content, reference, cohorts, learners, in a new
  `tests/panels/course/test_instance_view.py`.
- Reference preview: 200 with "<title> (Preview)" and the Topic chip for a topic in one of the
  course's own reference parts. A 404 for the id of a collection item in a reference part on the
  content panel URL, of a collection item on the learning path on the reference URL, of a collection
  item in a reference part listed only by another course, of a collection item on another site, of the
  collection item placing a `CoursePart` nested inside a reference part, for a `CourseReferencePart`
  pk, and for a missing or malformed id.
- A part shared by two courses previews through each course that lists it, and 404s through a course
  that does not.
- Withholding: extend the `PREVIEW_AVAILABLE` parametrised tests (over `course_per_reach_row`) to the
  Reference panel's rows, note and actions. Add `preview_content` on the reference panel to
  `tests/invariants/test_course_shares.py::test_revoking_a_share_makes_the_content_previews_answer_404`.
- Query count: building the Reference panel stays bounded as the number of topics per part grows, in
  the style of `test_course_content_query_count_stays_bounded_as_children_grow`. Seed topics only.
- Playwright (`tests/playwright/test_course_preview_flow.py`): open a reference topic's preview from
  the Reference panel. Re-run `test_touch_targets.py`.
- The automatic invariants (`walk_interface`, organisation isolation, permission matrix, system checks
  on unique `table_key` and sequence tables, template rules) pass with the new panel.

## Success criteria

- On the demo course "Functionality Demo - Reference Material", the course page shows a "Reference"
  panel after "Course content" listing its two reference parts and their topics as `1.`, `1.1`, ….
- Every reference topic row's "Preview" opens "<title> (Preview)" with the Topic chip.
- A course with no reference parts shows the panel with "No reference material in this course yet."
  and no footer count.
- For a registration-only organisation, both panels show "Content preview isn't shared with your
  organisation." and every reference preview URL is a 404.
- The id of a collection item in a reference part on the "Course content" action URL, and of any
  collection item of another course, is a 404.
- "Course content"'s rows and footer count are identical with and without reference parts.
- `uv run pytest` passes, including the invariants and `manage.py check`.
