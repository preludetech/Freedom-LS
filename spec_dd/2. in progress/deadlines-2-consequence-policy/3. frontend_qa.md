# Frontend QA: deadline consequence policy

Staff set a deadline policy per site, organisation, course, cohort or registration in the Django
admin. Learner pages enforce it when read: a "Missed deadline" chip that a policy can switch off, an
item that closes a grace window after its deadline ("Closes <date>." before, a "Closed <date>" chip
after, a closed notice in the player), course access that ends a grace window after the time limit
("Access ends <date>." before, "Access ended <date>" after), and what an ended learner may still
open. Staff restore ended access with a fixed-date time-limit override on the existing override
inlines. `CourseProgress` in the admin shows the effective policy and which layer set each value.

This run covers:
- the six config admins and the "Inherit" round-trip
- the effective policy panel on a `CourseProgress`
- the `mark_overdue` switch
- closing: inside the grace window, closed topic, closed form with and without an open attempt,
  "Submit your answers", sequential unlock past a closed item
- access ending: dashboard card and row, course detail, course home, every player route, under both
  `after_access_ended` values
- restore by a fixed-date override
- the ways it could go wrong: a guessed URL for a closed or ended item, a learner whose policy is
  inherited and untouched, a deactivated registration, a second config row for one owner, a
  negative grace window, a fixed time-limit override with a time, a hidden course, a completed
  course.

**Wording.** Learner pages say "Deadline", "Missed deadline", "Closes", "Closed", "Access ends",
"Access ended" and "Next deadline:". A closed item never reads "Locked". If "Due", "Overdue",
"Expired", "Locked" (for a closed item) or "Enrol for free" (for an ended learner) shows on a
learner page, that is a bug. Every "Closed" and "Missed deadline" chip carries text, never colour
alone, and the "Closed" chip carries an icon.

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever
this document writes `$PORT`. Shell variables do not survive between tool calls.

The site zone for this run is `Africa/Johannesburg` (UTC+2, no DST). An end-of-day deadline is
21:59:59 UTC; the browser is set to the same zone, so it prints as "11:59 PM" on the local date.
"Today" is the date of the run. The seed registers the *late learner* and the *restored learner*
100 days before today, so the parts course's 90-day time limit ended 10 days ago for both.

## §1 Admin: config rows

### 1.1 The six config admins exist and round-trip "Inherit"

1. As the superuser, open `/admin/`. Under "Deadlines" expect six new entries: Site deadline
   configs, Organisation deadline configs, Course deadline configs, Cohort deadline configs, Cohort
   course registration deadline configs, Learner course registration deadline configs.
2. Open "Course deadline configs" > Add. Every switch select offers exactly "Inherit", "On", "Off";
   "After access ended" offers "Inherit", "Outline and results", "Nothing"; "Grace window" is empty
   and its help text names the `DD HH:MM:SS` format; each help text says what "Inherit" passes to.
3. Pick the parts course, leave everything at Inherit and the grace window empty, save. The list
   row shows `inherit` in every switch column and an empty grace window. Open the row: every select
   still reads "Inherit" (not "Off"), grace window still empty (not `0`).
4. Set grace window to `0 00:00:00`, save, reopen: it reads zero, not empty.
5. Delete the row at the end of §1.

### 1.2 One row per owner, and bad values refused

1. Add a second "Course deadline config" for the parts course: expect a form error naming the
   duplicate, no 500, and the list still shows one row.
2. Add a "Site deadline config" (no owner field shown), save; add a second one: a form error, no
   500. Delete both.
3. Add a "Cohort deadline config" for `QA Deadlines Cohort` (one exists from the seed): form error.
4. On any add form, set grace window to `-1 00:00:00`: the form rejects it (a field error, not an
   `IntegrityError` page).

### 1.3 Effective policy panel

1. Open "Course progress" in the admin, filter by learner `qa_deadline_solo@email.com`, open the
   parts-course record. A "Deadlines" section shows "Effective deadlines" (from before) and a new
   "Effective deadline policy" list: `mark_overdue: True (settings)`, `close_items: True
   (registration)`, `end_course_access: False (registration)`, `notify_educators: False
   (settings)`, `grace_window: 3 days (registration)`, `after_access_ended: outline_and_results
   (settings)`, and no "Access ends" line.
2. Open the cohort learner's parts-course record: `end_course_access: True (cohort)`,
   `after_access_ended: outline_and_results (cohort)`, and "Access ends: 30 May 2026 11:59 PM
   SAST" (the time limit end; grace is zero).
3. Open the fresh learner's record: every source reads `settings`.
4. Add an `OrganisationDeadlineConfig` for `QA Deadlines Org` with `close_items=off`. Reopen the
   late learner's record: `close_items` still `True (registration)`, since the registration layer
   is more specific. Reopen the cohort learner's record: `close_items: False (organisation)`. Delete

## §3 Closing

Log in as the late learner for every test in §3 unless told otherwise. The parts course is the
subject.

### 3.1 Inside the grace window

1. Open the player. In the outline `Course Feedback` reads "Missed deadline <yesterday 11:59 PM>
   Closes <tomorrow + 1 day 11:59 PM>." with the chip but no "Closed" chip, and keeps its link.
2. Open `Course Feedback` (item 5 of the parts course: `/courses/functionality-demo-course-parts/5/`
   or by the outline link). The form start page renders with its "Start Form" button, and the
   header repeats the "Missed deadline" and "Closes" line.

### 3.2 Closed topic

1. In the outline `Welcome`, `What to Expect` and `Key Ideas` each show a "Closed <date>" chip with
   an icon and keep their links. The screen-reader status text of the row reads "Closed" (inspect
   the `sr-only` span), not "Locked".
2. Click `What to Expect`. The player shows the item title and, instead of the topic body, a notice
   "Closed on <date>. Ask your educator if you need more time." The footer has Previous and Next
   only, no "Next" form button that marks the topic complete and no "Submit your answers".
3. Open the admin's Course progress record for this learner: `last_accessed_item` did not change
   to `What to Expect` and `started_at` is still empty (the closed visit records nothing).
4. Guess the URL of a closed topic directly: the same notice, `200`, never a 404 or 500.

### 3.3 Closed form, no open attempt, and the gates

1. `Course Feedback` is inside its grace window; find a closed *form* without an attempt: set the
   late learner's `Course Feedback` override to 10 days ago (through `qa-data-helper`), reload. Its
   row now reads "Closed". Clicking it shows the closed notice with no "Submit your answers" button
   and no "Start Form".
2. Visit `/courses/functionality-demo-course-parts/5/start_form` (the `form_start` URL):
   redirected to the course detail page (`/courses/functionality-demo-course-parts/detail/`), no
   attempt created (check the admin's Form progress list for this learner: nothing new).
3. Visit the fill page URL `/courses/functionality-demo-course-parts/5/fill_form/1`: redirected to
   the course detail page.
4. Restore the override to yesterday.

### 3.4 Closed form with an open attempt: "Submit your answers"

1. `Knowledge Check` (item 4) is closed and has an open attempt from the seed. Its outline row reads
   "Closed". Open it: the closed notice plus a "Submit your answers" button.
2. Open the fill page URL for item 4 directly: redirected to the course detail page, nothing saved.
3. Back on the notice, click "Submit your answers": the results page for `Knowledge Check` renders,
   with the score of the answers that were already saved (none, so 0 or no score). The outline row
   for `Knowledge Check` now reads as complete or "Needs retry", no longer "Closed".
4. Press Back and resubmit the same form (a double submit): the results page again, no 500, still
   one completed attempt in the admin.

### 3.5 Sequential unlock and parts

1. The items after a closed, incomplete item stay withheld: in the outline, the item after
   `What to Expect` that sequential unlock has not offered is drawn unlinked with "Locked" sr text,
   not "Closed", and has no "Closed" chip.
2. A part whose open children are all closed shows the part row with no link; its children stay
   individually reachable (closed notice).

### 3.6 Nothing closes by default

1. Log in as the fresh learner (no config rows). `Welcome` shows "Missed deadline" and opens
   normally; no "Closes" and no "Closed" anywhere in the outline, the header or the dashboard card.

### 3.7 Completed item past its close instant

1. As the late learner, complete `Course Feedback` is not possible once closed, so use the cohort
   learner instead: `Welcome` is complete for them and far past any deadline. In their outline it
   shows no deadline line and no chip, and it opens (completed items stay open under
   `outline_and_results`).

## §4 Access ended

1. Log in as the cohort learner. Dashboard: the parts course stays in the current-courses list; its
   card eyebrow reads "Access ended May 30, 2026, 11:59 PM" with an icon, the progress bar shows,
   there is no "Next up:" line, no deadline line and no "Continue". The card title links to the
   course detail page, not the player. At 375x812 the compact row shows the same eyebrow.
2. Course detail (`/courses/functionality-demo-course-parts/detail/`): the sign-up panel shows "Your access
   to this course ended on May 30, 2026, 11:59 PM. Your progress is saved. Ask your educator to
   restore it." and no button at all (no "Continue", "Start course", "Review course" or "Enrol for
   free"). The "Course content" outline shows `Welcome` linked (complete) and every other row
   unlinked.
3. `/courses/functionality-demo-course-parts/` as the resume URL (`course_home`): lands on the
   course detail page, no loop.
4. Admin: the cohort registration is still active and the cohort learner's membership unchanged;
   nothing was written by any of the above.

### 4.2 Player routes under `outline_and_results`

1. As the cohort learner, open `Welcome` from the detail outline (item 1): it opens, with the
   player outline showing `Welcome` linked and every other row unlinked. The header shows no
   deadline line.
2. Click Next: redirected to the course detail page (item 2 is not complete).
3. Visit items 2, 3, 5 by URL: each redirects to the course detail page.
4. `Knowledge Check` (item 4) has no completed attempt: `/courses/functionality-demo-course-parts/4/`
   redirects; its results URL `/courses/functionality-demo-course-parts/4/complete` redirects.

6. Through `qa-data-helper`, give the cohort learner a completed attempt on `Knowledge Check`, then
   open its results URL: the results page renders. Its "Try again" button leads to `form_start`,

### 4.3 `nothing`

3. Through `qa-data-helper`, give the late learner an open attempt on a form in the plain course

   plain course has no form, record "not applicable".

### 4.4 Access ends ahead, and nothing ends by default

1. As the restored learner (restored to 30 days ahead), the dashboard card reads "Access ends <today
   + 30 days 11:59 PM>." and the course opens.
2. As the fresh learner (no config), the dashboard shows "Next deadline:" lines only, no "Access
   ends", and the course opens. The time limit (reg + 90 days) does not end access when the policy
   is off: confirm with the late learner's parts course (time limit 10 days ago,
   `end_course_access=off`): it opens, and the card shows "Missed deadline Course <date>".

### 4.5 Side effects that must not happen

1. As the cohort learner, visit `/courses/functionality-demo-course-parts/access/` (the
   `initiate_course_access` URL): redirected to the course detail page; the admin shows no new
   `LearnerCourseRegistration` for this learner.
2. Deactivate the late learner's plain-course registration (`is_active=False`) through
   `qa-data-helper`. The dashboard no longer lists the plain course; its detail page shows the
   normal not-registered "Enrol for free" state, not the ended message. Reactivate it.
3. Hidden course: set the parts course's visibility to `hidden` through `qa-data-helper`. The
   cohort learner still reaches its detail page (ended message). An anonymous visitor gets 404.
   Set it back to `published`.
4. Completed course: through `qa-data-helper` set `completed_time` on the cohort learner's record.
   The card moves to the completed section and reads "Completed", not "Access ended"; the course
   opens for review. Clear `completed_time` again.

## §5 Restore

### 5.1 Fixed-date time-limit override on a learner

1. As the superuser, open the cohort learner's parts-course Course progress record. In the
   "Deadline overrides" inline add a row: collection item "Course time limit", kind "Fixed date",
   due date today + 14 days, no time. The inline's help says a fixed date or a day count restores
   ended access. Save: no error, the "Effective" column shows the fixed date at 11:59 PM SAST, the
   "Effective deadline policy" panel's "Access ends" line moves to that date.
2. As the cohort learner: dashboard card reads "Access ends <today + 14 days 11:59 PM>." and the
   title links into the player; course detail shows the "Continue" button; item 2 opens. Progress
   percentage and `Welcome`'s completion are unchanged in the admin.
3. Edit the override to add a due time: the inline rejects it ("The course time limit ends at the
   end of its day."). Set the date to yesterday: access ends again (card "Access ended").
4. Delete the override row.

### 5.2 Cohort override

1. On the `QA Deadlines Cohort` > parts course cohort registration change page, add a time-limit
   override: fixed date, today + 14 days. Save.
2. As the cohort learner, the course is open again. Delete the override.
