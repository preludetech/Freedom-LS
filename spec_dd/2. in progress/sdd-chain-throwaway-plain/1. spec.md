# Spec: two small display helpers

## Purpose

Two pure functions that turn numbers into display strings: a duration in seconds as hours and
minutes, and a form score as earned over possible. Each lives in its own app with its own tests.
See `idea.md`.

## Scope

In:

- `format_duration(seconds)` in `freedom_ls/health/durations.py`.
- `format_score(earned, possible)` in `freedom_ls/form_engine/score_display.py`.
- A test module for each.

Out:

- Any model, migration, view, template or template filter. No caller is changed to use the helpers.
- Localisation of the unit letters and separator.
- Percentages.
- Screen-reader wording such as "1 hour 2 minutes" or "7 out of 10". That belongs to whichever
  template renders the string later.

## Decisions

- **Floor, never round.** Leftover seconds are dropped, so `3599` is `0h 59m`, never `1h 00m`. This
  differs on purpose from `CourseContent.display_estimated_duration`
  (`freedom_ls/content_engine/models/courses.py`), which rounds, and from the `duration` filter in
  `freedom_ls/base/templatetags/fls_base_filters.py`, which takes a `timedelta`. Neither is reused
  or changed.
- **Under a minute keeps the shape.** `45` is `0h 00m`.
- **`possible == 0` renders the numbers as given.** `format_score(0, 0)` is `0 / 0`. The helper does
  no division, so there is nothing to guard.
- **Negative input raises `ValueError`** in both helpers, rather than rendering `-1h -1m` or
  `-1 / 10`.

## Requirements

### `freedom_ls/health/durations.py`

```python
def format_duration(seconds: int) -> str: ...
```

- Returns `f"{hours}h {minutes:02d}m"`. Hours are whole hours, unpadded and unbounded, so `360000`
  is `100h 00m`. Minutes are the remaining whole minutes, zero-padded to two digits.
- `3720` → `1h 02m`; `0` → `0h 00m`; `45` → `0h 00m`; `3600` → `1h 00m`.
- `seconds < 0` raises `ValueError`.
- No Django import and no I/O.

### `freedom_ls/form_engine/score_display.py`

```python
def format_score(earned: int, possible: int) -> str: ...
```

- Returns `f"{earned} / {possible}"`, with a space either side of the slash.
- `(7, 10)` → `7 / 10`; `(0, 0)` → `0 / 0`; `(12, 10)` → `12 / 10` (earned above possible is
  rendered as given).
- `earned < 0` or `possible < 0` raises `ValueError`.
- No Django import and no I/O.

## Testing

Plain pytest functions, unmarked (portable), with no database. Each module's cases are
parametrised.

- `freedom_ls/health/tests/test_durations.py`: `0`, `45`, `59`, `60`, `3599`, `3600`, `3720`,
  `360000` give the strings above; `-1` raises `ValueError`.
- `freedom_ls/form_engine/tests/test_score_display.py`: `(7, 10)`, `(0, 10)`, `(10, 10)`, `(0, 0)`,
  `(12, 10)` give the strings above; `(-1, 10)` and `(1, -10)` raise `ValueError`.

## Open questions

- Q: Should the helpers reject non-`int` input such as `45.5`, `None` or `True` at runtime? → A: No
  runtime type check; the `int` hints are the contract and the tests cover `int` only (assumed
  default: nothing in the idea passes anything else, and the project says not to build unrequested
  functionality. Overrule by editing Requirements.)

## Success criteria

- `uv run pytest freedom_ls/health/tests/test_durations.py freedom_ls/form_engine/tests/test_score_display.py` passes.
- `format_duration(3720)` returns `"1h 02m"` and `format_score(7, 10)` returns `"7 / 10"`.
- The branch's own commits add or change only the two new modules, their two test modules and files
  under `spec_dd/`.
