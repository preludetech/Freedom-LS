# Plan: Lead monitoring API, course applications

Implementation plan for `1. spec.md` beside this file. Paths are relative to the project root.
The spec's documentation and upgrade-note deliverables are not part of this plan; they follow
implementation separately.

## What exists and is reused

- **The API framework** in `freedom_ls/api/`: `ReadOnlyApiViewSet` (`viewsets.py`) authenticates
  the API key, checks the API scope, throttles, paginates with `ApiKeysetPagination` and narrows
  every list and detail lookup to the API key's site in `filter_queryset`. `UpdatedSinceFilterSet`
  (`filters.py`) gives `updated_since` on `updated_at`. `router` (`routers.py`) names routes
  `<basename>_list` and `<basename>_detail` under `app_name = "api"`. `autodiscover_modules("api")`
  in `urls.py` imports every installed app's `api.py`. Nothing in `freedom_ls/api/` changes.
- **The users API endpoint** `freedom_ls/accounts/api.py` is the shape to copy for serializer,
  filterset, viewset and `router.register`. Its tests `freedom_ls/accounts/tests/test_api.py` are the
  shape to copy for access, shape, paging, `updated_since` and query-bound tests, with
  `collect_pages` from `freedom_ls/api/tests/helpers.py` and `ApiKeyFactory` from
  `freedom_ls/api/factories.py`.
- **`touch_user_updated_at`** in `freedom_ls/accounts/signals.py` is the bump pattern:
  `Model._base_manager.filter(...).update(updated_at=timezone.now())`.
- **`accounts_user_site_updated_idx`** on `User` (`freedom_ls/accounts/models.py`) is the index
  pattern.
- **`ApiScope.COURSE_APPLICATIONS`** already exists in `freedom_ls/api/scopes.py`, and
  `HasApiScope` already produces the 403 body naming it.
- **`answer_cell`** in `freedom_ls/form_engine/exports.py` already holds the per-type answer
  logic; it is rebuilt on the new `answer_value` rather than duplicated.
- **The export's query recipe** `filter_export` in `freedom_ls/course_applications/resources.py`
  shows the `select_related` and `prefetch_related` paths the API needs.
- **Model properties** `is_submitted`, `submitted_time`, `is_email_verified`, `applicant_email`
  and `applicant_name` on `CourseApplication` are read as they are.
- **Test builders** `gated_course_with_form` and `unverified_application_with_file` in
  `freedom_ls/course_applications/tests/helpers.py`, the factories in
  `freedom_ls/course_applications/factories.py` (`anonymous` and `anonymous_draft` traits) and
  `freedom_ls/form_engine/factories.py` (`QuestionAnswerFactory`, `QuestionAnswerFileFactory`,
  `QuestionOptionFactory`), `site_context` in `freedom_ls/tests/site_context.py` and `SiteFactory`
  in `freedom_ls/tests/factories.py`.
- **Existing write paths the receivers observe, unchanged:** `FormProgress.complete()`,
  `FormProgress.save_answers()` and `record_page_reached()` (`freedom_ls/form_engine/models.py`),
  `partial_question_file_upload` and `partial_question_file_remove`
  (`freedom_ls/form_engine/views.py`), `update_applicant_email` and `attach_to_user`
  (`freedom_ls/course_applications/claims.py`). allauth's email-change flow ends in
  `user.save(update_fields=["email"])`, a save the receiver sees. No write path found changes an
  API-visible value through `QuerySet.update()`, `bulk_create` or `bulk_update`, so no explicit
  bump is needed; the implementer re-checks this with `grep` before closing slice 4.

## Facts that shape the plan

- `CourseApplication.objects` is the host-filtered `SiteAwareManager`. The viewset starts from
  `CourseApplication._base_manager`; the base viewset filters on the API key's `site_id`.
- A prefetch named by string goes through the related manager. For a reverse foreign key
  (`form_progress__answers`) and a many-to-many (`selected_options`) that manager is built on the
  site-filtered default manager, so a request on another host would drop rows. Both get an explicit
  `Prefetch` on `_base_manager`. A reverse one-to-one (`answer_file`) and `select_related` joins
  are not filtered.
- `test_organisation/import_contracts.toml` forbids `course_applications` tests from importing
  `freedom_ls.api` because the app has no runtime import of it yet. Adding
  `course_applications/api.py` adds that runtime edge; the generator refreshes the contract and
  `docs/app_structure.md` together, and the `app-map-fresh` and `lint-imports` pre-commit hooks
  check both. Slice 1 runs the generator.
- `settings.API_PAGE_SIZE` is the page size the users tests override.
- No `design.md` applies. No template, frontend, admin or setting changes.

```python
from django.db.models import QuerySet
from rest_framework import serializers

from freedom_ls.api.filters import UpdatedSinceFilterSet
from freedom_ls.api.routers import router
from freedom_ls.api.scopes import ApiScope
from freedom_ls.api.viewsets import ReadOnlyApiViewSet

from .models import CourseApplication


class CourseApplicationApiSerializer(serializers.ModelSerializer):
    # Properties, not columns: read through the model so they follow when
    # application review adds a state.
    applicant_email = serializers.CharField(read_only=True)
    applicant_name = serializers.CharField(read_only=True)
    is_email_verified = serializers.BooleanField(read_only=True)
    course_id = serializers.UUIDField(read_only=True)
    course_title = serializers.CharField(source="course.title", read_only=True)
    is_submitted = serializers.BooleanField(read_only=True)
    # allow_null marks the OpenAPI schema nullable; a draft has no submitted_time.
    submitted_time = serializers.DateTimeField(read_only=True, allow_null=True)
    answers = serializers.SerializerMethodField()

    class Meta:
        model = CourseApplication
        fields = (
            "id", "applicant_email", "applicant_name", "is_email_verified",
            "course_id", "course_title", "is_submitted", "submitted_time",
            "created_at", "updated_at", "answers",
        )
        read_only_fields = fields

    def get_answers(self, application: CourseApplication) -> list[dict[str, object]]:
        return []


class CourseApplicationFilterSet(UpdatedSinceFilterSet):
    class Meta:
        model = CourseApplication
        fields: list[str] = []


class CourseApplicationApiViewSet(ReadOnlyApiViewSet):
    filterset_class = CourseApplicationFilterSet
    required_scope = ApiScope.COURSE_APPLICATIONS
    serializer_class = CourseApplicationApiSerializer

    def get_queryset(self) -> QuerySet[CourseApplication]:
        # The base manager crosses sites; the base viewset's filter_queryset
        # narrows every lookup to the API key's site.
        return CourseApplication._base_manager.select_related(
            "user", "anonymous_applicant", "course", "form_progress"
        )


router.register(
    "course-applications", CourseApplicationApiViewSet, basename="course_application"
)
```

The explicit field tuple is the whole contract: no `AnonymousApplicant` consent or claim field
can leak because nothing reads the applicant model directly. Every field is declared by hand,
although `ModelSerializer` would map the properties on its own, so the OpenAPI schema gets real
types.

## Slice 2: one answer-value function

**Behaviour:** `answer_value` in `freedom_ls/form_engine/exports.py` returns an answer's value by
question type; `answer_cell` is rebuilt on it and its output is unchanged.

```python
def answer_value(answer: QuestionAnswer) -> str | list[str] | None:
    """An answer's value by question type; None when the row holds nothing.

    Checkboxes give a list, because several options can be selected; a single
    choice gives one string. Dates and times stay as their stored ISO text.
    """
    question_type = answer.question.type
    if question_type in OPTION_QUESTION_TYPES:
        options = sorted(answer.selected_options.all(), key=lambda option: option.order)
        texts = [option.text for option in options]
        if not texts:
            return None
        if question_type == QuestionType.CHECKBOXES:
            return texts
        # Multiple choice and dropdown hold one option by design, but a row
        # that somehow holds several must not lose any.
        return "; ".join(texts)
    if question_type == QuestionType.FILE_UPLOAD:
        # The name the applicant gave the file, never its storage key or a URL.
        # hasattr, because a missing reverse one-to-one raises rather than returning None.
        if not hasattr(answer, "answer_file"):
            return None
        return answer.answer_file.original_filename or None
    return answer.text_answer or None


def answer_cell(answer: QuestionAnswer | None) -> str:
    """One answer as spreadsheet text; an empty cell for a question never answered."""
    if answer is None:
        return ""
    value = answer_value(answer)
    if value is None:
        return ""
    if isinstance(value, list):
        return "; ".join(value)
    return value
```

`answer_cell`'s existing docstring and reasoning comments move onto `answer_value` where the
logic now lives.

## Slice 3: nested answers

**Behaviour:** each application carries its `answers`, keyed by question id, ordered by page,
question, then id, loaded in a fixed number of queries whatever the page size, and complete
whatever host the request arrives on.

### `freedom_ls/course_applications/api.py`

```python
from django.db.models import Prefetch
from drf_spectacular.utils import extend_schema_field

from freedom_ls.form_engine.enums import QuestionType
from freedom_ls.form_engine.exports import answer_value
from freedom_ls.form_engine.models import QuestionAnswer, QuestionOption

# OpenAPI 3.0 reads nullable only beside a type, so each branch carries it.
ANSWER_VALUE_SCHEMA: dict[str, object] = {
    "oneOf": [
        {"type": "string", "nullable": True},
        {"type": "array", "items": {"type": "string"}, "nullable": True},
    ],
}


class QuestionAnswerApiSerializer(serializers.Serializer):
    question_id = serializers.UUIDField(read_only=True)
    question_text = serializers.CharField(source="question.question", read_only=True)
    question_type = serializers.ChoiceField(
        source="question.type", choices=QuestionType.choices, read_only=True
    )
    value = serializers.SerializerMethodField()

    @extend_schema_field(ANSWER_VALUE_SCHEMA)
    def get_value(self, answer: QuestionAnswer) -> str | list[str] | None:
        return answer_value(answer)


class CourseApplicationApiSerializer(serializers.ModelSerializer):
    ...
    @extend_schema_field(QuestionAnswerApiSerializer(many=True))
    def get_answers(self, application: CourseApplication) -> list[dict[str, object]]:
        if application.form_progress is None:
            return []
        # .all() reads the prefetched rows in their prefetched order.
        answers = application.form_progress.answers.all()
        return list(QuestionAnswerApiSerializer(answers, many=True).data)


def answers_prefetch() -> Prefetch:
    """The answers of a page of applications, complete whatever host the request is on.

    A related manager is built on the site-filtered default manager, so a
    string prefetch would drop another host's rows; the base managers do not.
    """
    options = Prefetch("selected_options", queryset=QuestionOption._base_manager.all())
    answers = (
        QuestionAnswer._base_manager.select_related("question__form_page")
        .prefetch_related(options, "answer_file")
        .order_by("question__form_page__order", "question__order", "question_id")
    )
    return Prefetch("form_progress__answers", queryset=answers)


class CourseApplicationApiViewSet(ReadOnlyApiViewSet):
    ...
    def get_queryset(self) -> QuerySet[CourseApplication]:
        return (
            CourseApplication._base_manager.select_related(
                "user", "anonymous_applicant", "course", "form_progress"
            ).prefetch_related(answers_prefetch())
        )
```

If `ChoiceField` with `source="question.type"` does not render the enum in the schema the way
`test_schema` expects, a `CharField` with `@extend_schema_field` listing `QuestionType.values` is
the fallback. `nullable` is the OpenAPI 3.0 spelling drf-spectacular emits by default; if
`/api/v1/schema/` reports 3.1, a `{"type": "null"}` branch replaces it. `answers_prefetch()` stays
a function because a `Prefetch` holding a queryset is built per request, not at import.

## Slice 4: what moves `updated_at`

**Behaviour:** an `updated_since` poll sees every application whose sitting, answers, files,
anonymous applicant or user changed since the given time.

### `freedom_ls/course_applications/receivers.py` (extend)

```python
# pre_delete is already imported for the existing user-erasure receiver.
from django.db.models.signals import post_delete, post_save, pre_delete
from django.utils import timezone

from freedom_ls.form_engine.models import FormProgress, QuestionAnswer, QuestionAnswerFile

# Saves of only these fields change nothing the API shows, so they move nothing.
# Every sign-in saves last_login alone; counting those would send most
# applications on every run.
SIGN_IN_FIELDS = frozenset({"last_login"})
CLAIM_EMAIL_FIELDS = frozenset({"claim_email_sent_at", "updated_at"})


def touch_application_updated_at(**match: object) -> None:
    """Move updated_at on the applications `match` names.

    A changed-since sync reads updated_at alone, so a change to anything the
    API shows for an application has to land there. The base manager works
    with no request and with a request for another host; update() moves only
    updated_at.
    """
    CourseApplication._base_manager.filter(**match).update(updated_at=timezone.now())


@receiver(post_save, sender=FormProgress)
def touch_application_on_sitting_save(
    sender: type[FormProgress], instance: FormProgress, **kwargs: object
) -> None:
    touch_application_updated_at(form_progress_id=instance.pk)


@receiver(post_save, sender=QuestionAnswer)
@receiver(post_delete, sender=QuestionAnswer)
def touch_application_on_answer_change(
    sender: type[QuestionAnswer], instance: QuestionAnswer, **kwargs: object
) -> None:
    # Selected options change through selected_options.set(), which sends no
    # signal; save_answers saves the answer afterwards, and that save lands here.
    touch_application_updated_at(form_progress_id=instance.form_progress_id)


@receiver(post_save, sender=QuestionAnswerFile)
@receiver(post_delete, sender=QuestionAnswerFile)
def touch_application_on_answer_file_change(
    sender: type[QuestionAnswerFile], instance: QuestionAnswerFile, **kwargs: object
) -> None:
    # The join, not instance.answer: on a cascade from the answer's deletion the
    # file's post_delete runs while the answer row still exists, and the answer's
    # own post_delete bumps the application too, so no extra SELECT is needed.
    touch_application_updated_at(form_progress__answers__id=instance.answer_id)


@receiver(post_save, sender=AnonymousApplicant)
def touch_application_on_applicant_save(
    sender: type[AnonymousApplicant],
    instance: AnonymousApplicant,
    update_fields: frozenset[str] | None = None,
    **kwargs: object,
) -> None:
    if update_fields is not None and update_fields <= CLAIM_EMAIL_FIELDS:
        return
    touch_application_updated_at(anonymous_applicant_id=instance.pk)


@receiver(post_save, sender=User)
def touch_applications_on_user_save(
    sender: type[User],
    instance: User,
    update_fields: frozenset[str] | None = None,
    **kwargs: object,
) -> None:
    # Any other save may change the email or name the API shows.
    if update_fields is not None and update_fields <= SIGN_IN_FIELDS:
        return
    touch_application_updated_at(user_id=instance.pk)
```

`User` and `AnonymousApplicant` are already imported in this module. A `post_save` for a sitting
or applicant no application names yet matches nothing; that is harmless. `update_fields` arrives
as a `frozenset` or `None`. The helper takes lookup kwargs, as `touch_user_updated_at` does; every
call site is covered by an event test, which is what catches a mistyped lookup.

> **Assumed default:** slice 4 is one slice, landed and committed in three steps by sender
> (sitting, answers and files; anonymous applicant and claims; user), each step with its event
> tests and its query-count fix-ups, and the full suite run after each. Why: the shared helper and
> the final write-path audit are common to all three, and a per-sender commit keeps a failure in
> one sender from blocking the others. To change: make the three steps three slices, or land all
