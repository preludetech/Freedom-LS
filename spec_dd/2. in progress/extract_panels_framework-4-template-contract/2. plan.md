# Plan: panel framework templates, JS and CSS stop assuming FLS

Spec: `1. spec.md` beside this file. Paths are relative to the repository root. `PF` stands for
`freedom_ls/panel_framework`.

## How to work this plan

- TDD throughout: write the failing test, see it fail, make it pass, refactor.
- Read `claude_plugins/django-stack/resources/test_tiers.md` before running pytest. After any
  change to a panel template, run `freedom_ls/educator_interface/tests/playwright/test_touch_targets.py`.
- After any CSS or template class change, run `npm run tailwind_build` and grep
  `static/vendor/tailwind.output.css` for the classes you added. A clean exit code proves nothing.
- A comment copied from an FLS original is rewritten to state the fact it stands for. It names no
  spec, QA fix or FLS template. `@claude` and TODO comments are copied as they are.
- Template comments use `{% comment %}`, never `{# #}`.
- Non-browser tests hold no `if`, `for` or `try`: parametrise, or assert a set difference equals
  `set()`.
- Every new test directory gets an empty `__init__.py`. A new test directory or module that mirrors
  no Python module gets a line with its reason in `test_organisation/mirroring_exemptions.txt`.

### Deliberate departures from skill rules

- **One framework stylesheet, not per-component `<style>` blocks.** The rules are cross-component
  descendant selectors (`[data-modal-footer] .panel-btn`), classes a theme reopens
  (`.panel-surface`) or use `@apply`, and all must pass through the host's Tailwind build.
- **The minimal shell does not extend `_base.html`.** The framework is not a host.
- **Invariants read stylesheets.** They check a contract between two files (templates and
  `reference_theme.css`, the stylesheet and the hit-area rule), which the project's existing
  invariants already do. They live in `tests/invariants/`.

### Decisions taken in review

- **`freedom_ls.base` depends on the panel framework.** The wrappers, the one-line partial
  includes, `panel_reference_base.html` and the `base`-owned tests that render framework templates
  or call the framework's rule functions add a `base` → `panel_framework` edge. It is accepted.
- **Of the unguarded copies, only the dropdown's JavaScript gets a drift test.** `.panel-btn*`,
  `.panel-chip*` and `minimal_shell.css` are the framework's own defaults and may diverge from
  FLS's look.

### Slice 1: the framework stylesheet reaches FLS's Tailwind build

**Behaviour:** `manage.py write_panel_framework_css` writes `tailwind.panel_framework.css`, FLS's
build imports it, and the rules framework templates depend on (other than buttons and chips) live
in the framework stylesheet. FLS's compiled CSS is unchanged in effect.

**Builds on:** none
**Touches:** `PF/management/`, `PF/css/panel_framework.css`, `PF/tests/management/`, `PF/tests/invariants/test_templates.py`, `tailwind.components.css`, `tailwind.input.css`, `package.json`, `.gitignore`, `test_organisation/mirroring_exemptions.txt`, `freedom_ls/base/tests/invariants/test_stylesheet_boundary.py`, `freedom_ls/base/tests/invariants/test_panel_framework_tailwind.py`

1. `PF/management/__init__.py`, `PF/management/commands/__init__.py`,
   `PF/management/commands/write_panel_framework_css.py`:

   ```python
   GENERATED_FILE_NAME = "tailwind.panel_framework.css"

   def _css_path(target: Path, base_dir: Path) -> str:
       """`./relative` inside base_dir, absolute outside it. Both POSIX."""

   class Command(BaseCommand):
       def handle(self, *args: object, **options: object) -> None:
           base_dir = Path(settings.BASE_DIR)
           app_dir = Path(apps.get_app_config("freedom_ls_panel_framework").path)
           content = HEADER + (
               f'@source "{_css_path(app_dir / "templates", base_dir)}";\n'
               f'@import "{_css_path(app_dir / "css" / "panel_framework.css", base_dir)}";\n'
           )
           target = base_dir / GENERATED_FILE_NAME
           # Tailwind's watcher rebuilds on any write, so an unchanged file is left alone.
           if not target.exists() or target.read_text() != content:
               target.write_text(content)
           self.stdout.write(str(target))
   ```

   `@source not-ignored`. `_css_path` repeats four lines of `write_active_theme_css.py` on

### Slice 8: `REQUIRED_ICON_NAMES` and the icon check

**Behaviour:** `manage.py check` reports a host whose `c-icon` cannot draw a name the framework
uses.

**Builds on:** slice 7
**Touches:** `PF/checks.py`, `PF/apps.py`, `PF/tests/test_checks.py`, `PF/tests/invariants/test_icon_names.py`, `freedom_ls/educator_interface/tests/invariants/test_system_checks.py`

1. `PF/checks.py`:

   ```python
   REQUIRED_ICON_NAMES: frozenset[str] = frozenset({...})

   def _render_icon(name: str) -> str:
       """The host's c-icon for `name`, rendered. A string template is never
       compiled by cotton's loader, so the tag is compiled here."""
       source = CottonCompiler().process(f'<c-icon name="{name}" />')
       return Template(source).render(Context())

   def check_icon_names(
       *,
       app_configs: Sequence[AppConfig] | None,
       databases: Sequence[str] | None = None,
       **kwargs: object,
   ) -> list[CheckMessage]:
       """Report each icon name the framework draws that the host's c-icon cannot."""
       messages: list[CheckMessage] = []
       for name in sorted(REQUIRED_ICON_NAMES):
           try:
               rendered = _render_icon(name)
           except (TemplateDoesNotExist, TemplateSyntaxError, LookupError):
               messages.append(Error(..., id="freedom_ls_panel_framework.E010"))
               continue
           if not rendered.strip():
               messages.append(Warning(..., id="freedom_ls_panel_framework.W003"))
       return messages
   ```

   Each message names the icon; each hint names the icon and `HOST_CONTRACT.md#icons`. No
   `deploy=True`, no database access.
2. The set: every static `c-icon name="…"` in `PF/templates/`, every literal
   `icon_left`/`icon_right` on a `c-panel-button`, and the names the primitives draw (`loading`,
   `previous`, `next`, `more_options`, `info`, `warning`, `error`, `success`). Reference-page names
   count. Names bound at runtime (`:name="item.icon"`) do not.
3. `PF/apps.py`: `register(check_icon_names)` beside the other three.
4. Tests:
