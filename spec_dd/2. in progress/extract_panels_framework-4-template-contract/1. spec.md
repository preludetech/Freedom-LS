# Spec: panel framework templates, JS and CSS stop assuming FLS

Spec 4 of 6 in the Panel framework extraction effort. Inputs: `idea.md`, `answers.md` and the
`research_*.md` files beside this spec, the parent's `research_coupling_audit.md`, and the "Panel
framework extraction" section of `spec_dd/1. next/roadmap.md`.

## Purpose

`freedom_ls/panel_framework/` templates call FLS cotton components (`c-button`, `c-chip`,
`c-pagination` and others), include two FLS partials, rely on CSS classes defined only in FLS's
`tailwind.components.css`, and reach Tailwind only because they sit inside the FLS source tree. The
framework's tests render inside FLS's `_base.html`. After this spec a bare Django project with
django-cotton, htmx 2, the Alpine CSP build, Tailwind 4.1.16 or later, an icon component and the
documented tokens can render every framework template. The framework's own test tiers prove it with a
shell the framework ships. FLS looks and behaves exactly as before.

## Terminology

| Term | Status | Meaning |
| --- | --- | --- |
| host contract | coined | What a host project must provide for framework templates to work: the shell ids, `site_name`, scripts and load order, Tailwind wiring, the `c-icon` names, the role tokens. Written down in `freedom_ls/panel_framework/HOST_CONTRACT.md`. |
| framework primitive | coined | A `panel-` cotton component that replaces a control the framework used to borrow from the host, shipped as a default the host may override: button, button group, chip, callout, back link, pagination, dropdown menu, dropdown menu separator, page, date, datetime. The framework's other `panel-*` components (`panel-card`, `panel-list`, `panel-notice` and the rest) are not primitives. |
| minimal shell | coined | `panel_framework/minimal_shell.html`, the one page shell the framework ships, for the reference page's default and the framework's test tiers. A host's own page shell is what the host contract describes. |

## Scope

In:

- Framework primitives replacing every host cotton call except `c-icon`, with FLS overrides that keep
  FLS's output unchanged.
- The page title and form partials moving into the framework.
- A framework stylesheet holding every CSS rule framework templates depend on, with prefixed button
  and chip classes.
- A reference theme block and the closed lists of tokens and icon names.
- Two system checks (base template, icon names).
- A management command that writes the Tailwind source-and-import file, wired into FLS's build.
- The minimal shell, a compiled reference stylesheet, and the framework's component, invariant and
  Playwright tiers running on them.
- `HOST_CONTRACT.md`.

Out:

- Python imports of FLS (`AppSettings`, CSV helpers, `SiteAwareModel`, the site hook,
  `field_display.py`'s use of `freedom_ls.base.date_display`) and the standalone settings module:
  spec 3, which is on main. This spec builds on what it left: the framework's own `AppSettings`,
  `tests/standalone_settings.py`, `tests/standalone_templates/`, the `needs_fls_host` marker, the
  import guard and the copy drift guard.
- Where `sidePanel`, `refreshTimer` and the menu item's `count_events` live: spec 1 put them in
  `static/panel_framework/js/shell-components.js` and on the menu item, so `sidebar_nav.html` and
  `table_toolbar.html` already name no FLS app or event. This spec consumes that and its invariant
  keeps it true.
- The package repo, app label, `v0.1.0`, install mechanics, and whether the compiled reference
  stylesheet is committed to the package: spec 5.
- The generic `panel-framework` skill and plugin: spec 6.
- A production page shell, other frontend stacks, a visual redesign, an open-ended icon registry or
  token set.

## Decisions

- **Primitives are `panel-` prefixed** (`answers.md`). A host's `c-button` is never shadowed by app
  order; a host restyles by shipping `cotton/panel-button.html` earlier in template precedence.
- **Framework button and chip classes are prefixed too**: `.panel-btn`, `.panel-btn-<variant>`,
  `.panel-btn-sm`, `.panel-chip`, `.panel-chip-<variant>`, `.panel-chip-xs` (`answers.md`). The
  framework never claims `.btn` or `.chip`, which hosts commonly use.
- **FLS overrides all eleven primitives** with thin wrappers, not only the ones whose output differs.
  One rule avoids a per-primitive judgement and keeps FLS's markup, `.btn`/`.chip` classes and
  first_class theme overrides exactly as today. `freedom_ls.base` precedes
  `freedom_ls.panel_framework` in `INSTALLED_APPS`, so the wrappers win.
- **No framework template writes a button or chip class string.** Styling reaches a control only
  through a primitive's props, so an FLS wrapper can map the same props to `.btn` classes.
- **The framework's dropdown Alpine component is `panelDropdownMenu`**, because `Alpine.data` is one
  flat registry where a later registration silently wins, and FLS keeps `dropdownMenu` for its own
  menus.
- **One minimal shell** serves the reference page default, the docs and the test tiers (`answers.md`).
  It lives in the framework's real templates directory because the reference page extends it outside
  tests.
- **The generated Tailwind file uses a plain `@source "<path>"`**: `@source not-ignored` is a build
  error in Tailwind 4.1.16, and an explicit `@source` into a gitignored `.venv` is scanned
  (`research_tailwind_source_probe.md`).
- **The framework stylesheet is not a static file.** It uses `@layer` and `@apply` and must pass
  through the host's Tailwind build, so it lives in `freedom_ls/panel_framework/css/`, outside
  `static/`.
- **Shell layout CSS never reaches a host.** The minimal shell's side-panel layout lives in a file only
  the reference build imports.

## Requirements

### Host contract document

`freedom_ls/panel_framework/HOST_CONTRACT.md` is where a host reads what it must provide. Every check
hint below points at a section of it. It holds:

1. **Shell ids**: the host renders `#interface-main` around the page content, with `quick_view_host`
   and `modal_host` included outside it (the framework JS and `quick_view_host.html` address it). Every
   other id comes from a framework fragment and is listed as reserved: `#main-content`,
   `#instance-header`, `#sidebar-nav`, `#breadcrumbs`, `#page-title`, `#app-modal`, `#app-modal-body`,
   `#quick-view*`, `#scope-announcer`.
2. **Fragments the host includes**: `modal_host`, `quick_view_host`, `announcer_host`, `sidebar_nav`,
   `breadcrumbs`, `document_title` (`#document-title` partial), `page_title`, with a copyable block
   taken from the minimal shell.
3. **Context**: `site_name` (optional), and the optional request attributes `panel_scope_name`,
   `panel_url_kwargs`.
4. **Scripts and order**: htmx 2.x global; the global
   `<body hx-headers='{"X-CSRFToken": "{{ csrf_token }}"}'>`; `panel_framework/js/shell-components.js`
   and `panel_framework/js/alpine-components.js`, both after the host's own Alpine component scripts
   and before the Alpine CSP build starts. Each step names the failure it prevents (unregistered
   `x-data` names, 403 on htmx POSTs).
5. **Tailwind** (4.1.16 or later): run `manage.py write_panel_framework_css` before the Tailwind
   build; add `@import "./tailwind.panel_framework.css";` to the input CSS after
   `@import "tailwindcss"` and before the host's theme overrides; commit neither the generated file nor
   the compiled output.
6. **Tokens**: the closed token list, kept equal to `reference_theme.css` by the token test, and that
   file's path.
7. **Icons**: `REQUIRED_ICON_NAMES` and how the check reports a missing one.
8. **Primitives**: one row per primitive with its file, props (`c-vars`), slots, the Alpine and class
   hooks an override must keep, and a one-line thin-wrapper example. `panel-dropdown-menu`'s row says
   `trigger_variant` and `trigger_size` are the trigger button's `variant` and `size`.
   `panel-callout`'s row says it is for pages, and that inside a panel or dialog the framework's
   `panel-notice` is used. The section states that an override wins by template precedence (`DIRS`
   before apps, then `INSTALLED_APPS` order).
9. **Reference page**: `PANEL_REFERENCE_BASE_TEMPLATE`, and the two blocks a base named by it must
   define, `head_title` and `content`. The reference-page tests render under both the minimal shell
   and FLS's `panel_reference_base.html` and assert each fills both blocks.

### Framework stylesheet

New `freedom_ls/panel_framework/css/panel_framework.css`, all rules inside `@layer components` (and
`@layer base` only where scoped to framework classes). It takes from `tailwind.components.css`:

- `.panel-surface`, `.panel-canvas`, their form-control min-height rule, `.panel-heading`,
  `.panel-table-selection-bar` with `@keyframes selection-bar-in`, `.panel-data-table-compact`, the
  bottom-sheet block, `.modal-backdrop-host::backdrop`. These move: FLS's file no longer defines them.
- The `.btn*` and `.chip*` rules re-expressed as `.panel-btn*` and `.panel-chip*`, including
  `.panel-data-table td .panel-btn`, `.panel-data-table-card .panel-btn`,
  `[data-modal-footer] .panel-btn` and the below-`md` `.panel-btn::after` 44px hit area. FLS's `.btn*`
  and `.chip*` rules, with their `.panel-data-table … .btn` and `[data-modal-footer] .btn` forms, stay
  in `tailwind.components.css` because the FLS wrappers render `.btn` inside framework markup.
- A copy of the select-chevron base rule scoped to `:is(.panel-surface, .panel-canvas) select`. FLS's
  global `select` rule stays, so FLS selects render identically.

FLS themes keep overriding `.panel-surface` and `.panel-canvas` (first_class `theme.css:157,161`);
their override still wins because the framework stylesheet is imported before the active theme.

### Reference theme and closed lists

- `freedom_ls/panel_framework/css/reference_theme.css` is the source of truth for the closed token
  list: one `@theme` block of neutral working values, one comment per group, including `sidepanel` for
  the minimal shell. The starting set is the colour roles framework templates and the framework
  stylesheet use as utilities (`primary`, `on-primary`, `surface`, `surface-2`, `on-surface`, `muted`,
  `border`, the status roles and their `-hover`, `on-*`, `*-light` and `on-*-light` forms,
  `secondary`, `accent`, `focus-ring`) and the raw CSS variables read directly (`--color-primary`,
  `--color-secondary`, `--color-accent`, `--color-info`, `--color-surface`, the `--color-surface-*`
  used by the avatar and progress bar). `--panel-table-head`, `--sidebar-top` and the `--modal-*`
  variables are framework-internal.
- `REQUIRED_ICON_NAMES` in `freedom_ls/panel_framework/checks.py` is a `frozenset` of every static
  `c-icon name=` in framework templates, every literal `icon_left`/`icon_right` on a `c-panel-button`,
  and the names the primitives render themselves (`loading`, `previous`, `next`, `more_options`,
  `info`, `warning`, `error`, `success`). Names host data supplies at runtime (`item.icon`, the empty
  state's `icon`) are the host's. Names used only on the reference page are included, because the
  reference page is the framework's.

### System checks

In `freedom_ls/panel_framework/checks.py`, registered from `apps.py` beside `check_panels`,
`check_task_backend` and `check_site_resolver`, never `deploy=True`, no database access. Ids continue
the existing sequences (errors end at E008, warnings at W002); spec 5 renames them all if the label
changes.

- `check_reference_base_template`: `freedom_ls_panel_framework.E009` when
  `get_template(config.PANEL_REFERENCE_BASE_TEMPLATE)` raises `TemplateDoesNotExist`. The hint names the
  setting and `HOST_CONTRACT.md#reference-page`.
- `check_icon_names`: for each name in `REQUIRED_ICON_NAMES`, compiles `<c-icon name="<name>" />` with
  `django_cotton.compiler_regex.CottonCompiler` (a string template is otherwise never compiled) and
  renders it, one message per failing name. `E010` when rendering raises `TemplateDoesNotExist`,
  `TemplateSyntaxError` or `LookupError` (FLS's `{% icon %}` raises `KeyError` for an unknown name).
  `W003` when the output is empty after stripping. The hint names the icon and
  `HOST_CONTRACT.md#icons`.

### Tailwind source command

New `freedom_ls/panel_framework/management/commands/write_panel_framework_css.py`, modelled on
`freedom_ls/base/management/commands/write_active_theme_css.py` (typed without `Any`):

- Writes `BASE_DIR/tailwind.panel_framework.css`:

  ```css
  /* Generated by manage.py write_panel_framework_css. Do not edit by hand.
     Re-run after installing or upgrading the panel framework: the paths are machine-specific. */
  @source "<path to the installed panel_framework/templates>";
  @import "<path to the installed panel_framework/css/panel_framework.css>";
  ```

- The framework JS builds no class strings, so only the templates directory is scanned.
- Paths come from the installed app's path at run time, written relative to `BASE_DIR` (`./…`) when
  inside it, absolute otherwise.
- Rewrites the file only when its content changes, and prints the path written.
- `.gitignore` gains `tailwind.panel_framework.css`.

FLS wiring:

- `tailwind.input.css` adds `@import "./tailwind.panel_framework.css";` after
  `@import "./tailwind.components.css"` and before `@import "./tailwind.active_theme.css"`. FLS's `./freedom_ls/**/templates/**/*.html` glob still
  covers the framework in-tree. It cannot exclude it: a negated `@source` also cancels the generated
  file's positive one (`research_tailwind_source_probe.md`).
- `package.json`: `_write_active_theme` also runs `manage.py write_panel_framework_css`, so
  `tailwind_build`, `tailwind_watch`, CI and the rebase script pick it up.

## Testing

- **No framework template names an FLS component, app or event.** An invariant: every `<c-…>` tag in
  framework templates is a framework cotton file or `c-icon`, no template includes a path outside
  `panel_framework/`, and no FLS app name or FLS-only htmx event appears.
- **Primitive contract, both ways.** For each primitive: the default renders from the framework's
  templates directory with its documented props, and a test override inserted at `DIRS[0]` wins.
  Under FLS settings, `c-panel-<name>` renders HTML equal (parsed and normalised) to the old
  `c-<name>` call for a table of props per primitive (button variants, sizes, `href`, `loading`,
  `dropdown`, `icon_left`, `disabled`, attribute passthrough; chip variants and `size="xs"`; callout
  with a caller margin class; date with `short`; dropdown with each trigger variant; pagination in both
  modes).
- **Cotton names are unique** across every installed app's `templates/cotton/`, except the FLS
  `panel-*` wrappers, which are the intended overrides.
- **Alpine registration**: `test_alpine_registration.py` sees `panelDropdownMenu` registered once, and
  `HOST_SUPPLIED_COMPONENTS` stays empty.
- **Tokens**: every colour utility and `var(--…)` in framework templates, the framework stylesheet and
  `minimal_shell.css` is defined in `reference_theme.css`, and every token there is used. The no-raw-hex
  and no-palette rule covers the new `panel-*.html` primitives.
- **Icons**: `REQUIRED_ICON_NAMES` equals the set derived from the templates as defined above.
- **Checks**: E009 with a missing base template; E010 for an unknown icon name; W003 for an icon
  component rendering empty; no `freedom_ls_panel_framework` messages from `manage.py check` on FLS
  with the default and first_class themes.
- **Command**: writes the expected two lines for an app inside `BASE_DIR` and for one outside it
  (absolute path); no rewrite when unchanged.
- **Tailwind coverage**: a Tailwind build of an input holding only
  `@import "tailwindcss" source(none);`, `@import` of `reference_theme.css` (the framework stylesheet
  `@apply`s role tokens) and `@import` of the generated file emits a class used only in
  a framework template and `.panel-surface` from the framework stylesheet. FLS's own
  `static/vendor/tailwind.output.css` still contains both.
- **Cascade**: under the first_class theme, a framework panel's computed background is the theme's
  `.panel-surface` override (`bg-white`), in a Playwright check.
- **FLS unchanged**: the full FLS suite passes, including the `educator_interface` Playwright flows and
  `test_touch_targets.py`. A one-off before/after screenshot pass of the educator interface at the
  three QA viewports in the QA plan shows no difference.
- **Framework tiers on framework defaults**: the component, invariant and Playwright tiers pass with
  the minimal shell and `reference.css`.
- **Standalone run**: `uv run pytest -c freedom_ls/panel_framework/tests/standalone_pytest.ini
  freedom_ls/panel_framework` passes with the component and invariant tiers included, and covers
  the primitive defaults, both checks, the command and the token and icon lists.
- **Import guard**: `test_import_guard.py` passes with no exempt directory.
- **Date formats**: the format strings in `panel-date.html` and `panel-datetime.html` equal
  `field_display.DATE_DISPLAY_FORMAT` and `DATETIME_DISPLAY_FORMAT`.
- **No stand-in shadows the framework**: no file under `tests/standalone_templates/` has the path of
  a template the framework ships.
