# Spec: panel framework templates, JS and CSS stop assuming FLS

Spec 4 of 6 in the Panel framework extraction effort. Inputs: `idea.md`, `answers.md` and the
`research_*.md` files beside this spec, the parent's `research_coupling_audit.md`, and the "Panel
framework extraction" section of `spec_dd/1. next/roadmap.md`.

## Purpose

`freedom_ls/panel_framework/` templates call FLS cotton components (`c-button`, `c-chip`,
`c-pagination` and others), include an FLS partial, rely on CSS classes defined only in FLS's
`tailwind.components.css`, and reach Tailwind only because they sit inside the FLS source tree. The
framework's tests render inside FLS's `_base.html`. After this spec a bare Django project with
django-cotton, htmx 2, the Alpine CSP build, Tailwind v4, an icon component and the documented
tokens can render every framework template, and the framework's own test tiers prove it with a
shell the framework ships. FLS looks and behaves exactly as before.

## Terminology

| Term | Status | Meaning |
| --- | --- | --- |
| host contract | coined | What a host project must provide for framework templates to work: the shell ids, `site_name`, scripts and load order, the `c-icon` names, the role tokens. Written down in `freedom_ls/panel_framework/HOST_CONTRACT.md`. |
| framework primitive | coined | A `templates/cotton/panel-<name>.html` component the framework ships as an overridable default for a generic control it used to borrow from the host: button, button group, chip, callout, back link, pagination, dropdown menu, dropdown menu separator, page, date, datetime. |
| minimal shell | coined | `panel_framework/minimal_shell.html`, the one page shell the framework ships, used by the reference page by default and by the framework's test tiers. Not a production shell. |

## Scope

In:

- Framework primitives replacing every host cotton call except `c-icon`, with FLS overrides that keep
  FLS's output unchanged.
- The page title partial moving into the framework.
- A framework stylesheet holding every CSS rule framework templates depend on, with prefixed button
  and chip classes.
- A reference theme block and the closed lists of tokens and icon names.
- Two system checks (base template, icon names).
- A management command that writes the Tailwind source-and-import file, wired into FLS's build.
- The minimal shell, a compiled reference stylesheet, and the framework's component, invariant and
  Playwright tiers running on them.
- `HOST_CONTRACT.md`.

Out:

- Python imports of FLS (`AppSettings`, CSV helpers, `SiteAwareModel`, the site hook) and the
  standalone settings module: spec 3. This spec adds one setting to whatever `config.py` holds when it
  lands and must not duplicate spec 3's settings work.
- Where `sidePanel`, `refreshTimer` and `count_events` live: spec 1 put them in
  `static/panel_framework/js/shell-components.js` and on the menu item. This spec consumes that.
- The package repo, app label, `v0.1.0`, install mechanics, and whether the compiled reference
  stylesheet is committed to the package: spec 5.
- The generic `panel-framework` skill and plugin: spec 6.
- A production page shell, other frontend stacks, a visual redesign, an open-ended icon registry or
  token set.

## Decisions

- **Primitives are `panel-` prefixed** (`answers.md`). A host's `c-button` is never shadowed by app
  order; a host restyles by shipping `cotton/panel-button.html` earlier in template precedence.
- **Framework button and chip classes are prefixed too**: `.panel-btn`, `.panel-btn-<variant>`,
  `.panel-btn-sm`, `.panel-chip`, `.panel-chip-<variant>`, `.panel-chip-xs` (`answers.md`). The
  framework never claims `.btn` or `.chip`, which hosts commonly use.
- **FLS overrides every framework primitive** with a thin wrapper in `freedom_ls/base/templates/cotton/`
  that delegates to its own component (`panel-button.html` → `<c-button>`, and so on). `freedom_ls.base`
  precedes `freedom_ls.panel_framework` in `INSTALLED_APPS`, so the wrappers win. One rule for all
  eleven primitives avoids a per-primitive judgement and keeps FLS's markup, `.btn`/`.chip` classes and
  first_class theme overrides exactly as today.
- **No framework template writes a button or chip class string.** The two `trigger_class="btn …"`
  call sites (`partials/table_selection_bar.html:55`, `partials/table_toolbar.html:203`) pass
  variant and size props to `c-panel-dropdown-menu` instead, so an FLS wrapper can map them to `.btn`
  classes and the default to `.panel-btn` classes.
- **The framework's dropdown Alpine component is `panelDropdownMenu`**, registered in
  `static/panel_framework/js/alpine-components.js`. FLS's `dropdownMenu` stays in
  `base/static/base/js/alpine-components.js` for FLS's other menus. `Alpine.data` is one flat
  registry where the later registration wins silently, and `test_alpine_registration.py` already fails
  on a name registered twice.
- **One minimal shell** serves the reference page default, the docs and the test tiers (`answers.md`).
  It lives in the framework's real templates directory, not under `tests/`, because the reference page
  extends it outside tests.
- **The generated Tailwind file uses a plain `@source "<path>"`.** Tailwind 4.1.16 has no
  `not-ignored` keyword: it is a build error. An explicit `@source` into a gitignored directory,
  uv's `.venv` with its nested `.gitignore` included, is scanned
  (`research_tailwind_source_probe.md`). This replaces the idea's `@source not-ignored:`.
- **One generated file holds the `@source` and the stylesheet `@import`** (`answers.md`), so a host's
  input CSS gains exactly one line.
- **The framework stylesheet is not a static file.** It uses `@layer` and `@apply` and must pass
  through the host's Tailwind build, so it lives at `freedom_ls/panel_framework/css/`, outside
  `static/`, where `collectstatic` never serves it raw.
- **The compiled reference stylesheet is built by an in-tree npm script** (`answers.md`) and is
  gitignored. It is what the minimal shell links, so the reference page under the default shell and
  the Playwright tier look the same.
- **Framework test tiers render the framework defaults, not FLS's wrappers.** A test fixture puts the
  framework's own `templates/` directory first in `DIRS` for those tiers. Otherwise, under FLS
  settings, the Playwright tier would render `.btn` markup that the reference stylesheet does not
  define.
- **Check ids continue the existing sequence**: `freedom_ls_panel_framework.E009` onward and
  `freedom_ls_panel_framework.W001`. Spec 5 renames every id at once if the label changes.

## Requirements

### Host contract document

`freedom_ls/panel_framework/HOST_CONTRACT.md` is the single place a host reads what it must provide.
Every check hint below points at a section of it. It holds:

1. **Shell ids**: the host renders `#interface-main` around the page content, with `quick_view_host`
   and `modal_host` included outside it (the framework JS and `quick_view_host.html` address it). Every
   other id comes from a framework fragment and is listed as reserved: `#main-content`,
   `#instance-header`, `#sidebar-nav`, `#breadcrumbs`, `#page-title`, `#app-modal`, `#app-modal-body`,
   `#quick-view*`, `#announcer`.
2. **Fragments the host includes**: `modal_host`, `quick_view_host`, `announcer_host`, `sidebar_nav`,
   `breadcrumbs`, `document_title` (`#document-title` partial), `page_title`, with a copyable block
   taken from the minimal shell.
3. **Context**: `site_name` (optional; framework templates fall back to `{{ site_name|default:"" }}`),
   and the optional request attributes `panel_scope_name`, `panel_url_kwargs`.
4. **Scripts and order**: htmx 2.x global; the global
   `<body hx-headers='{"X-CSRFToken": "{{ csrf_token }}"}'>`; `panel_framework/js/shell-components.js`
   and `panel_framework/js/alpine-components.js`, both after the host's own Alpine component scripts
   and before the Alpine CSP build starts. The failure each step prevents is named (unregistered
   `x-data` names, 403 on htmx POSTs).
5. **Tailwind**: run `manage.py write_panel_framework_css` before the Tailwind build; add
   `@import "./tailwind.panel_framework.css";` to the input CSS after `@import "tailwindcss"` and
   before the host's theme overrides; commit neither the generated file nor the compiled output.
6. **Tokens**: the closed list of colour role tokens and raw CSS variables (below), and the path of the
   reference theme block.
7. **Icons**: the closed list of `c-icon` names (below) and how the check reports a missing one.
8. **Primitives**: one row per framework primitive with its file, props (`c-vars`), slots, the Alpine
   and class hooks an override must keep, and a one-line thin-wrapper example. It states that an
   override wins by template precedence (`DIRS` before apps, then `INSTALLED_APPS` order).
9. **Reference page**: `PANEL_REFERENCE_BASE_TEMPLATE` and the blocks the reference page fills.

### Framework stylesheet

New `freedom_ls/panel_framework/css/panel_framework.css`, all rules inside `@layer components` (and
`@layer base` only where scoped to framework classes). It takes from `tailwind.components.css`:

- `.panel-surface`, `.panel-canvas`, their form-control min-height rule, `.panel-heading`,
  `.panel-table-selection-bar` with `@keyframes selection-bar-in`, `.panel-data-table-compact`, the
  bottom-sheet block, `.modal-backdrop-host::backdrop`. These move: FLS's file no longer defines them.
- The `.btn*` and `.chip*` rules re-expressed as `.panel-btn*` and `.panel-chip*`, including
  `.panel-data-table td .panel-btn`, `.panel-data-table-card .panel-btn`,
  `[data-modal-footer] .panel-btn` and the below-`md` `.panel-btn::after` 44px hit area. FLS's `.btn*`
  and `.chip*` rules, including their `.panel-data-table … .btn` and `[data-modal-footer] .btn` forms,
  stay in `tailwind.components.css` because the FLS wrappers render `.btn` inside framework markup.
- A copy of the select-chevron base rule scoped to framework surfaces
  (`:is(.panel-surface, .panel-canvas) select`). FLS's global `select` rule stays, so FLS selects render
  identically.

FLS themes keep overriding `.panel-surface` and `.panel-canvas` (first_class `theme.css:157,161`).
Their override still wins because the framework stylesheet is imported before the active theme.

### Reference theme and closed lists

- `freedom_ls/panel_framework/css/reference_theme.css`: one `@theme` block defining every token in the
  closed token list with neutral working values, one comment per group. The test input CSS imports it,
  and `HOST_CONTRACT.md` points at it, so docs and tests cannot drift.
- Closed token list: the colour roles framework templates and the framework stylesheet use as
  utilities (`primary`, `primary-hover`, `on-primary`, `surface`, `surface-2`, `on-surface`, `muted`,
  `border`, `error`, `warning`, `success`, `info`, their `-hover`, `on-*` and `on-*-light`/`*-light`
  forms used by `.panel-btn*`/`.panel-chip*`, `secondary`, `accent`, `focus-ring`) and the raw CSS
  variables read directly (`--color-primary`, `--color-secondary`, `--color-accent`, `--color-info`,
  `--color-surface`, the `--color-surface-*` used by the avatar and progress bar). The exact list is
  whatever the token test below finds, written into `HOST_CONTRACT.md`. `--panel-table-head`,
  `--sidebar-top` and the `--modal-*` variables are framework-internal and listed as such.
- Closed icon list: `REQUIRED_ICON_NAMES` in `freedom_ls/panel_framework/checks.py`, a `frozenset` of
  every static `c-icon name=` in framework templates (16 today), every literal `icon_left`/`icon_right`
  value on a `c-panel-button` (`add`, `download`, `filter`, `retry`, `close`), and the names the
  framework primitives render themselves (`loading`, `previous`, `next`, `more_options`, `info`,
  `warning`, `error`, `success`). Names that host data supplies at runtime (`item.icon`, the empty
  state's `icon`) are the host's, not in the list. `settings` and `warning` used only on the reference
  page are in the list because the reference page is the framework's.

### Tailwind source command

New `freedom_ls/panel_framework/management/commands/write_panel_framework_css.py`, modelled on
`freedom_ls/base/management/commands/write_active_theme_css.py` (but typed without `Any`):

- Writes `BASE_DIR/tailwind.panel_framework.css`:

  ```css
  /* Generated by manage.py write_panel_framework_css. Do not edit by hand.
     Re-run after installing or upgrading the panel framework: the paths are machine-specific. */
  @source "<path to the installed panel_framework/templates>";
  @import "<path to the installed panel_framework/css/panel_framework.css>";
  ```

- The framework JS builds no class strings, so only the templates directory is scanned.
- Paths are resolved from the installed app (`apps.get_app_config(...).path`) at run time, written
  relative to `BASE_DIR` (`./…`) when inside it, absolute otherwise.
- Rewrites the file only when its content changes, and prints the path written.
- `.gitignore` gains `tailwind.panel_framework.css`.

FLS wiring:

- `tailwind.input.css`: adds `@import "./tailwind.panel_framework.css";` before
  `@import "./tailwind.active_theme.css"`, and `@source not "./freedom_ls/panel_framework";` so that
  FLS's `./freedom_ls/**/templates/**/*.html` glob no longer covers the framework. The generated file
  becomes the framework's only Tailwind coverage, which proves the mechanism in-tree.
- `package.json`: `_write_active_theme` also runs `manage.py write_panel_framework_css`, so
  `tailwind_build`, `tailwind_watch`, the three CI jobs and
  `claude_plugins/fls-dev/scripts/rebuild_after_rebase.sh` all pick it up.

## Testing

What must be proved:

- **No framework template names an FLS component.** An invariant test: every `<c-…>` tag in framework
  templates is a framework cotton file or `c-icon`, and no template includes a path outside
  `panel_framework/`.
- **Primitive contract, both ways.** For each primitive: the default renders from the framework's
  templates directory with its documented props; a test override in an earlier `DIRS` entry wins.
  Under FLS settings, `c-panel-<name>` renders HTML equal (parsed and normalised) to the old `c-<name>`
  call for a table of props per primitive (button variants, sizes, `href`, `loading`, `dropdown`,
  `icon_left`, `disabled`, attribute passthrough; chip variants and `size="xs"`; callout with a caller
  margin class; dropdown with each trigger variant; pagination in both modes).
- **Cotton names are unique** across every installed app's `templates/cotton/`, except the FLS
  `panel-*` wrappers, which are the intended overrides.
- **Alpine registration**: `test_alpine_registration.py` sees `panelDropdownMenu` registered once, and
  `HOST_SUPPLIED_COMPONENTS` stays empty.
- **Tokens**: every colour utility and `var(--…)` in framework templates and the framework stylesheet
  is defined in `reference_theme.css`, and every token there is used. The existing no-raw-hex /
  no-palette rule now covers the new `panel-*.html` primitives too.
- **Icons**: `REQUIRED_ICON_NAMES` equals the set derived from the templates as defined above, so a new
  icon in a template fails until the list grows.
- **Checks**: E009 with a missing base template; E010 for an unknown icon name; W001 for an icon
  component rendering empty; no messages on FLS.
- **Command**: writes the expected two lines for an app inside `BASE_DIR` and for one outside it
  (absolute path); is idempotent (no rewrite when unchanged).
- **Tailwind coverage**: after `npm run tailwind_build`, FLS's `static/vendor/tailwind.output.css`
  contains a class used only in a framework template (proof the generated `@source` reaches the
  framework now that the glob excludes it), and `.panel-surface` from the framework stylesheet.
- **Cascade**: under the first_class theme, a framework panel's computed background is the theme's
  `.panel-surface` override (`bg-white`), in a Playwright check.
- **FLS unchanged**: the full FLS suite passes, including `educator_interface` Playwright flows and
  `test_touch_targets.py`. A one-off before/after screenshot pass of the educator interface at the
  three QA viewports in the QA plan shows no difference (spec 1's open QA B1, the sticky header over a
  tinted notice, is pre-existing and not a regression).
- **Framework tiers standalone of FLS markup**: the component, invariant and Playwright tiers pass
  with the minimal shell and `reference.css`, rendering framework defaults.

  `panel_framework/partials/page_title.html` to affect htmx navigation responses. A project that
  restyled framework buttons through `.btn` keeps that only via FLS's wrappers.
