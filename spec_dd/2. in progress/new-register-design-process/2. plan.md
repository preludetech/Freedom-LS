# Plan: register a design from a Claude Design Artifact

Spec: `1. spec.md`. Platform facts: `platform_facts.md`. The plan changes the `sdd` plugin only:
two commands, one fallback line and one frontmatter line in a third, the screenshot script and its
tests, and the two READMEs. Nothing in the Django app changes, so there is no migration and no
Design section.

## What the Artifact tool does, checked against a Design Artifact

The spec's `support.js` spike ran against one of the user's own Design Artifacts (five artboards,
one `ds/` folder, ten `_blob` assets). The plan is written to these results:

- **The spike passes.** `artifact-type/dc-runtime.js`, saved as `project/support.js` and served
  from a copy of `design_source/`, mounts every artboard kind with non-blank text and no page
  errors: a fixed `$preview` artboard (400 × 500), an `expand: "fill"` artboard (1440 wide) and an
  artboard that is only a `<dc-import>` of another. It bundles React itself and fetches nothing
  but Google Fonts. So `register_design.md` Step 2 point 4 reads `artifact-type/dc-runtime.js`
  and saves it as `design_source/project/support.js`, and the script supplies no runtime of its
  own.
- **A file read lands at `<out_dir>/<published path>`**, so `artifact-type/dc-runtime.js` read
  with `out_dir` `design_source` lands at `design_source/artifact-type/dc-runtime.js` and has to
  be moved.
- **An asset read lands as `<id>.<ext>`.** `read` with an asset id and `out_dir` saves
  `<out_dir>/<id>.svg` (or `.png`, …), never a bare `<id>`. The command saves assets under
  `design_source/_blob/`, and the script serves `/_blob/<id>` from the file there whose stem is
  the id, typed by its extension (an SVG served as `application/octet-stream` does not draw).
- **A missing asset only leaves a gap.** The artboard still renders; the request is a 404.
- **`list` with `scope: "files"`** prints `(version <string>)` in its header, lists the type's
  files (`SKILL.md`, `index.html`, `artifact-type/**`) and the design's own `project/**`. A Design
  Artifact nobody has drawn on lists no `project/` file at all, which is the "not a Design
  Artifact" stop in Step 2.
- **`read` with `paths`** returns the text of small files inline with the save. The command treats
  that text as the designer's data and does nothing with it.

## Slices

### Slice 1: artboards from `canvas.json`

**Behaviour:** when `design_source/project/canvas.json` exists, the script renders one PNG per
artboard in `order`, fixed artboards at their `w` × `h` and `expand: "fill"` artboards full-page at
width `w`, named `<stem>.png`; an artboard whose file is missing exits 1 naming the path before the
browser starts; `design.md` is not read. Without `canvas.json` nothing changes.

**Builds on:** none
**Touches:** claude_plugins/sdd/scripts/design_screenshots.py, claude_plugins/sdd/scripts/design_screenshots.sh, tests/test_design_screenshots.py, tests/playwright/test_design_screenshots.py

Changes to `design_screenshots.py`:

- Module docstring: a Design Artifact's `design_source/project/canvas.json` names the artboards
  and their sizes, each rendered from `design_source/project/<path>`; the three older shapes
  remain for a source without it.
- Reading the canvas. Three small functions, so each failure names `canvas.json` and the board
  instead of leaving a traceback, and so a path from the canvas can never point outside
  `design_source/project/`:

  ```python
  CANVAS_JSON = Path("project") / "canvas.json"

  # Chromium's viewport limit; also stops a corrupt size from exhausting memory.
  MAX_ARTBOARD_SIDE = 10_000


  class Artboard(TypedDict):
      path: str
      width: int
      height: int
      fill: bool


  def load_canvas(source: Path) -> dict[str, object]:
      canvas_json = source / CANVAS_JSON
      try:
          canvas = json.loads(canvas_json.read_text())
      except (OSError, json.JSONDecodeError) as error:
          raise DesignScreenshotError(f"could not read {canvas_json}: {error}") from error
      if not isinstance(canvas, dict):
          raise DesignScreenshotError(f"{canvas_json}: not a JSON object")
      return canvas


  def parse_artboard(path: str, board: object, canvas_json: Path) -> Artboard:
      if not isinstance(board, dict):
          raise DesignScreenshotError(f"{canvas_json}: board {path!r} is not an object")
      try:
          width, height = int(board["w"]), int(board["h"])
      except (KeyError, TypeError, ValueError) as error:
          raise DesignScreenshotError(f"{canvas_json}: board {path!r} has no usable w and h") from error
      for side in (width, height):
          if not 0 < side <= MAX_ARTBOARD_SIDE:
              raise DesignScreenshotError(f"{canvas_json}: board {path!r} is {width}x{height}")
      return {"path": path, "width": width, "height": height, "fill": board.get("expand") == "fill"}


  def read_canvas(source: Path) -> list[Artboard]:
      canvas_json = source / CANVAS_JSON
      canvas = load_canvas(source)
      boards = canvas.get("boards")
      if not isinstance(boards, dict):
          raise DesignScreenshotError(f"{canvas_json}: no boards")
      order = canvas.get("order")
      if not isinstance(order, list):
          order = list(boards)
      project = (source / "project").resolve()
      artboards: list[Artboard] = []
      for path in order:
          if not isinstance(path, str) or path not in boards:
              raise DesignScreenshotError(f"{canvas_json}: order names {path!r}, not a board")
          file = (project / path).resolve()
          if not file.is_relative_to(project):
              raise DesignScreenshotError(f"{canvas_json}: board {path!r} points outside project/")
          if not file.is_file():
              raise DesignScreenshotError(f"artboard file not found: {source / 'project' / path}")
          artboards.append(parse_artboard(path, boards[path], canvas_json))
      return artboards


  def artboard_stem(path: str) -> str:
      return path.removesuffix(".dc.html").replace("/", "__")
  ```

  def served_page(source: Path, out: Path, needs_stand_in: bool) -> Iterator[tuple[Page, str]]:
      out.mkdir(exist_ok=True)

### Slice 2: `_blob` assets and blank artboards

**Behaviour:** `/_blob/<id>` is served from `design_source/_blob/<id>.<ext>` with the type its
extension gives; a missing blob is exit 0 with one stderr line per missing id per artboard; an
artboard that renders neither text nor an image exits 1 naming it.

**Builds on:** slice 1
**Touches:** claude_plugins/sdd/scripts/design_screenshots.py, tests/playwright/test_design_screenshots.py

- One definition of a blob URL, used by the server and the browser side:

  ```python
  BLOB_URL = re.compile(r"^/_blob/([0-9a-f]{32})$")
  ```

- A handler that maps blob URLs onto the saved files (`from urllib.parse import quote, urlsplit`):

  ```python
  class SourceHandler(QuietHandler):
      def translate_path(self, path: str) -> str:
          match = BLOB_URL.match(urlsplit(path).path)
          if match:
              saved = next(iter(sorted((Path(self.directory) / "_blob").glob(f"{match.group(1)}.*"))), None)
              if saved is not None:
                  return str(saved)
          return super().translate_path(path)
  ```

  `serve` uses it; `guess_type` then reads the saved file's extension. The id is 32 hex
  characters by construction, so the glob pattern carries no path or wildcard character. An
  unmatched blob URL falls through to the default translation and 404s like any other missing
  file.

- Blank detection, a JS constant beside `SETTLED_JS` and `FRAMES_JS`, with a one-line comment
  that an unmounted `<x-dc>` template or a `<dc-import>`-only artboard draws nothing:

  ```python
  BLANK_JS = """
  () => !document.body.innerText.trim()
     && !document.body.querySelector('img, svg, canvas, video, picture')
  """


  def assert_not_blank(page: Page, artboard: Artboard) -> None:
      if page.evaluate(BLANK_JS):
          raise DesignScreenshotError(f"{artboard['path']}: rendered blank")
  ```

  The script supplies no runtime of its own; the served copy holds whatever `design_source/`
  holds, so a canvas synced without `support.js` fails here.

- Missing blobs are collected per artboard on the browser side, with a listener that lives only
  as long as the artboard's load, so the report names the page that asked and no list outlives
  an artboard. `missing_blob_id(response: Response) -> str | None` returns the id when the status
  is 404 and `BLOB_URL` matches the response URL's path. `screenshot_canvas_artboard` becomes:

  ```python
  missing: list[str] = []

  def note_missing(response: Response) -> None:
      blob_id = missing_blob_id(response)
      if blob_id is not None:
          missing.append(blob_id)

  page.set_viewport_size(...)
  page.on("response", note_missing)
  try:
      load(page, url)
  finally:
      page.remove_listener("response", note_missing)
  assert_not_blank(page, artboard)
  page.add_style_tag(content=PREVIEW_CSS)
  path = unique_path(...)
  screenshot_page(page, path, full_page=artboard["fill"])
  for blob_id in missing:
      sys.stderr.write(f"{artboard['path']}: missing blob {blob_id}\n")
  return path
  ```

Tests, in `tests/playwright/test_design_screenshots.py`, extending `make_canvas_spec_dir` with an
`<img src="/_blob/<32 hex>">` in the fill artboard and a one-pixel PNG at
`design_source/_blob/<id>.png` (the bytes of a 1 × 1 PNG, written from a constant):

- the blob loads: exit 0 and no `missing blob` line in stderr;
- the blob file deleted from the fixture: exit 0, stderr has one line naming the id, both PNGs
  still written;
- a canvas whose only artboard is `<x-dc><dc-import name="Other"></dc-import></x-dc>` with no
  `support.js`: exit 1, stderr names the artboard path and `rendered blank`.

> **Assumed default:** the headless Chromium keeps open network access while it renders a design,
> as it does today for the older design shapes. Why: the old `.dc.html` runtime and the designs'
> stylesheets load React, icon fonts and web fonts from public CDNs, so blocking non-local
> requests would blank every registered design; and the register flow only syncs a Design
> Artifact the user owns or was given edit access to, so its scripts come from collaborators the
> user chose. To change: add a `page.route` allowlist in `served_page` (slice 1) and list the
> CDN hosts it admits.
