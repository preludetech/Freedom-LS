# Spec: register a design from a Claude Design Artifact

Idea: `idea.md`. Research: `research_codebase.md`, `research_best_practices.md`,
`research_reference_implementations.md`, `research_prior_art.md`, `research_ux_patterns.md`,
`research_known_complaints.md`. Platform facts: `platform_facts.md`.

## Purpose

`/sdd:register_design` reads a design through `DesignSync` from a `claude.ai/design/p/<project-id>`
link, and that route no longer works (see `idea.md`). A design now lives in Claude as an Artifact
made from the **Design** Artifact type, at a `claude.ai/artifact/<id>` (or
`claude.ai/code/artifact/<uuid>`) link, which Claude Code reads with the `Artifact` tool. The
command moves to that route, and the plugin documents the steps a person takes to register a
design.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| Design Artifact | coined | An Artifact made from the Design Artifact type: a canvas whose own files are `project/canvas.json`, one `project/<path>.dc.html` per artboard, and `project/ds/<folder>/**` for an installed design system. No existing term, because the old word "project" named the standalone Claude Design project; the plugin's lowercase "artifact" (`writing_standard.md`) means a document the workflow writes, and is not this. |
| artboard | narrowed | `register_design.md` ("a canvas artboard"), `design_screenshots.py` (`[data-artboard]`). In a Design Artifact, one entry of `canvas.json` `boards` and its `.dc.html` file. `design.md`'s coverage table still calls it a "screen". |

## Scope

In:

- `claude_plugins/sdd/commands/register_design.md` takes a Design Artifact link and reads the whole
  canvas with the `Artifact` tool.
- `claude_plugins/sdd/scripts/design_screenshots.py` renders a Design Artifact's synced source, one
  PNG per artboard.
- `/sdd:start`'s design pre-check and hook call, and `plan_from_spec`'s fallback, use the
  `Artifact` tool instead of `DesignSync`.
- A "Registering a design" section in `claude_plugins/sdd/commands/README.md`: the steps a person
  follows.

Out:

- The old route: no `claude.ai/design/p/` project link, no `DesignSync`, no `/design-login`
  anywhere in the register flow.
- Registered `design.md` files that point at old projects. Their `design_source/` and
  `design_screenshots/` stay, and nothing migrates them.
- Other intake routes: the "Project archive" zip export, "Send to Claude Code Web", the `/design`
  skill.
- Picking artboards: the whole canvas is synced every time.
- `claude_plugins/sdd/commands/spec_from_idea.md`: it defers to `design.md`, so it does not change.
- `.claude/settings.json`: no `Artifact` permission entry; the first read asks for permission.

## Decisions

- **`design_source/` is the record; the link is only for re-registering.** Every later step reads
  the files on disk.
- **`design_prompt.md` keeps its name** and holds whatever the person pasted; `/sdd:start` triggers
  on that name.
- **Files keep their `project/` prefix.** `read` with `out_dir` saves a file at
  `<out_dir>/<published path>`, so artboards land at `design_source/project/<path>.dc.html` and
  their relative links keep working.
- **The type's own files are not committed** (`SKILL.md`, `index.html`, `artifact-type/**`, about
  6 MB), except the one runtime file a render needs, if the spike below finds one.
- **Only a person with edit access can register.** For an Artifact owned by someone else, `read`
  returns an isolated summary, not files. The command never asks anyone to publish or widen sharing
  to make a design readable.

## Requirements

### `claude_plugins/sdd/commands/register_design.md`

- Frontmatter: add `Artifact` to `allowed-tools`. Set `argument-hint` to
  `[spec-dir] <design artifact link, or a file holding one> [notes on how to treat the design] (see commands/README.md "Registering a design")`.
- Intro: the design lives in Claude as a Design Artifact. The outputs stay `design_prompt.md`,
  `design_source/`, `design_screenshots/` and `design.md`.
- Inputs paragraph: the caller passes "the design-access answer" (see `start.md` below).
- **Step 1, the design input.** Accept a pasted link, a pasted handoff prompt, or the path to a file
  holding either, and take the first `https://claude.ai/artifact/<id>` or
  `https://claude.ai/code/artifact/<uuid>` link from it. Standalone, write what was pasted verbatim
  to `<spec-dir>/design_prompt.md`. Input with no such link (including one with only a
  `claude.ai/design/p/` link) stops the command with a message pointing at the README section.
- **Step 2, the sync.** Replace the whole step:
  1. Load `Artifact` (`ToolSearch` `select:Artifact`) if it is deferred. Call `list` with `url` and
     `scope: "files"`, and record the version string from the listing's header. If the listing has
     no `project/canvas.json`, or the read returns a summary instead of files, stop: say whether the
     user lacks edit access or the link is not a Design Artifact, and point at the README section.
     In hook mode the design-access answer decides instead: "Done" retries the listing once;
     "without reading it", or a retry that still fails, registers the design with the coverage
     table marked "not yet read".
  2. On re-registration, empty `design_source/` first. `read` every `project/` file with `paths`
     (at most 256 a call) and `out_dir` set to `<spec-dir>/design_source`.
  3. Call `list` with `scope: "assets"`. Scan every synced text file for `/_blob/<id>` references
     and `read` each referenced asset by its id with `out_dir` set to
     `<spec-dir>/design_source/_blob`. The tool saves it as `_blob/<id>.<ext>`, the extension of
     its type, which is how the script serves `/_blob/<id>` with the right content type when it
     serves `design_source/` as its root.
  4. If the spike (Screenshots) found a runtime file that stands in for `support.js`, `read` it too
     and save it at `design_source/project/support.js`.
  5. Never read the link with `WebFetch`, a browser, Playwright or `curl`.
  6. Done when every artboard in `canvas.json` `boards` has its file in `design_source/project/`,
     and every `/_blob/` reference is either saved or listed in the report as missing. From
     `canvas.json` (`boards`, `order`, `pages`, `title`) and the artboard files, list the screens
     the design draws.
- **Step 3, `design.md`.** The header becomes:

  ```markdown
  This is a **Claude Design** design: a Design Artifact in Claude.

  - Link: <the artifact link>
  - Version: `<version string from the listing>`
  - Entry file: `project/<the first artboard in canvas.json order>`
  - Made of: `<the artboards, the ds/ folders, and the count of _blob assets>`
  - Registered: <YYYY-MM-DD>
  ```

  "How to read it" names the screenshot files as the script writes them (below), and its
  re-register sentence says: use the `Artifact` tool as in Step 2, and register again after the
  design changes in Claude. Every artboard gets a row in "What it covers"; one no spec owns gets
  `none (out of scope)`.
- **Step 4** names the artboard screenshots the script now writes.
- **Report.** The title from `canvas.json`, the version, the artboard count and names, the files
  and assets synced, any missing assets, the screenshots written, and each consumer edited.

### Screenshots: `claude_plugins/sdd/scripts/design_screenshots.py`

- **The `support.js` spike comes first.** Every artboard loads `./support.js`, which the live
  canvas runtime supplies; a Design Artifact's file list has none. Before the script changes, the
  plan checks whether `artifact-type/dc-runtime.js` stands in for it: it passes when an artboard
  rendered locally shows non-blank text. Register Step 2 point 4 depends on the answer.
- When `design_source/project/canvas.json` exists, the artboards come from it and the script does
  not read `design.md`. A `canvas.json` artboard whose file is missing is a `DesignScreenshotError`
  naming the path, raised before the browser starts. Render each artboard in `order` from
  `design_source/project/<path>`:
  - one without `expand` at a `w` × `h` viewport with `PREVIEW_CSS`, as `screenshot_whole_page`
    does for a `$preview`;
  - one with `expand: "fill"` at a `w` × `h` viewport, captured full-page.

  Write `<stem>.png`, where the stem is the path without `.dc.html` and with `/` replaced by `__`.
- When `design_source/support.js` and `design_source/project/support.js` are both absent, the
  served copy gets none, and each artboard falls back to the whole-page render. A blank capture, an
  artboard whose page shows no text and no image element once it has settled, is a
  `DesignScreenshotError` `<path>: rendered blank` and an exit 1, so Step 4's summary reports it.
- Without `canvas.json`, the current behaviour (`read_entry_file`, `list_pages`,
  `[data-artboard]`, `FRAMES_JS`, the whole-page fallback, the `design_canvas_flat.jsx` stand-in)
  is unchanged.
- `/_blob/<id>` requests are served from the file in `design_source/_blob/` whose stem is `<id>`,
  with the content type its extension gives. A missing blob is not an error: exit 0, with one
  stderr line per missing id per artboard.

### `claude_plugins/sdd/commands/start.md`

- Add `Artifact` to the frontmatter `allowed-tools`.
- Step 3's design pre-check, when `design_prompt.md` exists and `design.md` does not: load
  `Artifact`, take the link the way `register_design.md` Step 1 does, and call `list` with
  `scope: "files"`. If the listing has no `project/canvas.json`, returns a summary, or the file
  holds only a `claude.ai/design/p/` link, ask one question: "Get edit access to the design (or
  move it into Claude), then choose Done (Recommended)" or "Register the design without reading
  it". Pass the answer to Step 6 under the new name "the design-access answer" (it was "the
  design-login answer"), in `start.md` Steps 3, 5 and 6, `register_design.md`'s Inputs paragraph
  and Step 2, and the `answers.md` entry.

### `claude_plugins/sdd/commands/plan_from_spec.md`

Step 1's fallback, "Load `DesignSync` … only when those files are missing", becomes: read the design
through the `Artifact` tool as its `design.md` says, only when those files are missing.

### Human procedure: `claude_plugins/sdd/commands/README.md`

Add a "Registering a design" section, linked from Step 1 point 2 of the workflow, with no project
names in it:

1. The design is a Design Artifact in Claude. Its owner moves a design still in standalone Claude
   Design into Claude before 14 December 2026; a project that cannot move is redrawn in Claude.
2. The person running the command can edit the design: they own it, or the owner shared it with
   edit access.
3. Copy the design's link (`claude.ai/artifact/<id>`). A handoff prompt Claude generates for the
   design also works if it contains that link.
4. Either paste it into `<spec-dir>/design_prompt.md` before `/sdd:start`, or run
   `/sdd:register_design <link> [notes]` on the feature branch.
5. Check the report.
6. After the design changes in Claude, register it again.

Step 1 point 2 takes `<design artifact link>` instead of `<handoff prompt or claude-design-url>`.
`claude_plugins/sdd/README.md`'s `register_design` paragraph says the design is read through the
`Artifact` tool and takes a Design Artifact link.

## Testing

- `tests/test_design_screenshots.py`, no browser:
  - a `canvas.json` naming an artboard whose file is missing exits 1 naming the path, with no
    `design.md` in the fixture;
  - artboard paths map to PNG names (`Main.dc.html` → `Main.png`, `flows/Signup.dc.html` →
    `flows__Signup.png`);
  - the existing four tests pass unchanged.
- `tests/playwright/test_design_screenshots.py`, a fixture with `project/canvas.json`, a fixed
  artboard and an `expand: "fill"` artboard, a few-line `project/support.js` that mounts the
  artboard's markup, and one `_blob/<id>.png` image:
  - one PNG per artboard, the fixed one at `w` × `h`, the fill one at width `w`;
  - the blob image loads with no 404;
  - a missing blob gives exit 0, a stderr line naming its id, and the PNG still written;
  - the existing three tests pass unchanged.

## Documentation and downstream

- The upgrade notes say that `register_design` takes a Design Artifact link, that it no longer uses
  `DesignSync` or `/design-login`, and that old `design.md` files stay valid.
- Two in-progress specs hold old-format handoff prompts that still need registering. For
  `spec_dd/2. in progress/design_educator-interface-bulk-action/`, the owner replaces
  `design_prompt.md`'s contents with the Artifact link. For
  `spec_dd/2. in progress/educator-interface-design-learner-csv-upload-design-fix/`, whose prompt is
  in `prompt.md`, the owner pastes the link into a new `design_prompt.md`. This spec edits neither.

## Success criteria

- `grep -rn "DesignSync\|design-login" claude_plugins/sdd/commands` returns nothing.
- `design_screenshots.sh` on an old `design_source/` (no `canvas.json`) produces the same PNG names
  as before.
- Manual, by the user: registering one of their own Design Artifacts on a scratch spec directory
  writes `design_source/project/canvas.json`, every artboard's `.dc.html`, the `_blob/` assets, one
  PNG per artboard, and a `design.md` with `Link`, `Version` and `Entry file` lines.
- Manual: given a `claude.ai/design/p/` link, or a link to an Artifact the user cannot edit, the
  command stops with a message pointing at the README section.
