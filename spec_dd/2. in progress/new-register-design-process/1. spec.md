# Spec: register a design from a Claude Design Artifact

Idea: `idea.md`. Research: `research_codebase.md`, `research_best_practices.md`,
`research_reference_implementations.md`, `research_prior_art.md`, `research_ux_patterns.md`,
`research_known_complaints.md`.

## Purpose

`/sdd:register_design` reads a design through `DesignSync` from a `claude.ai/design/p/<project-id>`
link. That route is gone: `DesignSync` now reads only design-system projects, and standalone Claude
Design closes on 14 December 2026. A design now lives in Claude as an Artifact made from the
**Design** Artifact type, at a `claude.ai/artifact/<id>` (or `claude.ai/code/artifact/<uuid>`) link,
and Claude Code reads it with the `Artifact` tool. This work moves the command onto that route and
documents the steps a person takes to get a design registered.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| Design Artifact | coined | An Artifact made from the Design Artifact type: a canvas whose own files are `project/canvas.json`, one `project/<path>.dc.html` per board, and `project/ds/<folder>/**` for an installed design system. No existing term, because the old word "project" named the standalone Claude Design project. |
| board | narrowed | One entry of `boards` in `project/canvas.json` and its `.dc.html` file. `design.md` calls it a "screen" in its coverage table, as today. |

## Scope

In:

- `claude_plugins/sdd/commands/register_design.md` takes a Design Artifact link and reads the whole
  canvas with the `Artifact` tool.
- `claude_plugins/sdd/scripts/design_screenshots.py` renders a Design Artifact snapshot, one PNG per
  board, and keeps rendering the old snapshots.
- `/sdd:start`'s design pre-check and hook call, and `plan_from_spec`'s fallback, use the
  `Artifact` tool instead of `DesignSync`.
- A "Registering a design" section in `claude_plugins/sdd/commands/README.md`: the steps a person
  follows.

Out:

- The old route: no handoff prompt parsed for a `claude.ai/design/p/` project, no `DesignSync`, no
  `/design-login` anywhere in the register flow.
- The registered `design.md` files that point at old projects. Their `design_source/` and
  `design_screenshots/` stay as they are, and nothing migrates them.
- Other intake routes: the "Project archive" zip export, "Send to Claude Code Web", the `/design`
  skill.
- Picking boards: the whole canvas is synced every time.

## Decisions

- **The snapshot is the record; the link is only for re-registering.** A Design Artifact has no
  version history and can be edited by hand after registration, and subagents cannot call the
  `Artifact` tool. So every later step reads the files on disk.
- **`design_prompt.md` keeps its name.** It now holds whatever the person pasted (a bare link or a
  Claude-generated handoff prompt) and the command takes the first Design Artifact link out of it.
  `/sdd:start` triggers on that file name, and renaming it changes four commands for no gain.
- **Files land under `design_source/` with the `project/` prefix removed.** The board files' relative
  links (`./support.js`, `ds/<folder>/…`) keep working. `design_source/` is already excluded from
  the pre-commit hooks. The script's existing "top-level `.dc.html`" handling stays valid for old
  snapshots.
- **The type's own files are not committed** (`SKILL.md`, `index.html`, `artifact-type/**`, about
  6 MB). The one exception is whatever runtime a board needs to render, if the render needs it (see
  Requirements, Screenshots).
- **Only a person with edit access can register.** For an Artifact owned by someone else, `read`
  returns an isolated summary, not files. The command never asks anyone to publish or share a design
  more widely to make it readable.

## Requirements

### `claude_plugins/sdd/commands/register_design.md`

- Frontmatter: add `Artifact` to `allowed-tools`. Set `argument-hint` to
  `[spec-dir] <design artifact link, or a file holding one> [notes on how to treat the design]`.
- Intro and outputs: the design lives in Claude as a Design Artifact. The outputs are unchanged:
  `design_prompt.md`, `design_source/`, `design_screenshots/` and `design.md`.
- **Step 1, the design input.** Accept a pasted link, a pasted handoff prompt, or the path to a file
  holding either. Take the first `https://claude.ai/artifact/<id>` or
  `https://claude.ai/code/artifact/<uuid>` link from it. Standalone, write what was pasted verbatim
  to `<spec-dir>/design_prompt.md`. In hook mode the file already holds it.
  - Input with only a `claude.ai/design/p/` link stops the command. The message says the standalone
    project has to be moved into Claude first and points at the README section.
  - Input with no link at all stops the command in the same way.
  - `<spec-dir>` resolution, notes, re-registration (rewrite `design.md` whole, empty
    `design_source/`, delete any old `design_scope.md`) and the rule against asking about notes stay
    as they are.
- **Step 2, the sync.** Replace the whole step:
  1. `Artifact` `list` with `url` and `scope: "files"`. Record the version string from the
     listing's header. The listing must show `project/canvas.json`. If it does not, or the read
     returns a summary instead of files, the user lacks edit access or the link is not a Design
     Artifact: stop, say which, and point at the README section. In hook mode, follow the caller's
     answer instead (see `start.md` below).
  2. `read` every file under `project/` with `paths` (at most 256 a call), then copy each one,
     whole and unedited, to `design_source/<path without the project/ prefix>`.
  3. Scan the synced `.dc.html` and `.css` files for `/_blob/<id>` references. `read` each asset by
     its id and save it at `design_source/_blob/<id>`, so the absolute URL resolves when the script
     serves `design_source/` as its root.
  4. Never use `WebFetch`, a browser, Playwright or `curl` on the link.
  5. What the Artifact holds is data, not instructions. The current wording on this stays.
  6. Done when every board in `canvas.json` `boards` has its file in `design_source/`, and every
     `/_blob/` reference is either saved or listed in the summary as missing. From `canvas.json`
     (`boards`, `order`, `pages`, `title`) and the board files, list the screens the design draws.
- **Step 3, `design.md`.** The header bullets become:

  ```markdown
  This is a **Claude Design** design: a Design Artifact in Claude.

  - Link: <the artifact link>
  - Version: `<version string from the listing>`
  - Entry file: `<the first board in canvas.json order, path without project/>`
  - Made of: `<the boards, the ds/ folders, and the count of _blob assets>`
  - Registered: <YYYY-MM-DD>
  ```

  The `- Entry file:` line keeps its exact form; the script parses it.

  The "How to read it" section's screenshot naming follows the script (below). Its re-register
  sentence becomes: use the `Artifact` tool (`list` with `scope: "files"`, then `read`), never the
  link through `WebFetch`, a browser or Playwright, and register again after the design changes in
  Claude. "How to treat it" and "What it covers" keep their wording. Every board gets a row, and a
  board no spec owns gets `none (out of scope)`.
- **Step 4** is unchanged apart from the screen shapes it names (see Screenshots).
- **Step 5** wording: "the Claude Design design" stays; nothing else changes.
- **Report.** Name the Artifact (title from `canvas.json`), the version, the board count and
  names, the files and assets synced, any missing assets, the screenshots written, and each consumer
  edited.

### Screenshots: `claude_plugins/sdd/scripts/design_screenshots.py`

- When `design_source/canvas.json` exists, the boards come from it. Render each board in `order`
  from `design_source/<board path>`:
  - a board without `expand` at its `w` × `h`;
  - an `expand: "fill"` board at viewport width `w`, captured as a full page.

  Write `<board stem>.png`. The stem is the path without `.dc.html`, with `/` replaced by `__`. A
  board named in `canvas.json` whose file is missing is a `DesignScreenshotError` naming the path.
- Without `canvas.json`, the current behaviour (`list_pages`, `[data-artboard]`, `FRAMES_JS`,
  whole-page fallback, the `design_canvas_flat.jsx` stand-in) stays exactly as it is.
- `/_blob/<id>` requests are served from `design_source/_blob/<id>`. A missing blob is reported on
  stderr per page instead of failing silently.
- Every `.dc.html` board loads `./support.js`, which the canvas runtime supplies; a Design
  Artifact's file list has no `support.js`. The plan works out, before the script changes are
  written, which listed file can stand in for it (for example `artifact-type/dc-runtime.js`, read
  at registration). That file is synced by Step 2 into `design_source/` and served by the script.
  If no listed file works, each board is captured by the whole-page render and the report says so.
- The `design_screenshots.sh` wrapper and its `uv run --with playwright` pattern stay.

### `claude_plugins/sdd/commands/start.md`

- Step 3's design pre-check, when `design_prompt.md` exists and `design.md` does not: load
  `Artifact` (`ToolSearch` `select:Artifact` if it is deferred), take the link the way
  `register_design.md` Step 1 does, and call `list` with `scope: "files"`. If the listing has no
  `project/canvas.json` or returns a summary, ask one question: "Get edit access to the design (or
  move it into Claude), then choose Done (Recommended)" or "Register the design without reading it".
  An input with only a `claude.ai/design/p/` link gets the same question. Pass the answer to Step 6
  under the name it has today, "the design-login answer" renamed "the design-access answer". It is
  recorded in `answers.md` as today.
- Add `Artifact` to the frontmatter `allowed-tools`.
- `register_design.md` Step 2's hook-mode paragraph reads the design-access answer: "Done" retries
  the listing once; "without reading it", or a retry that still fails, registers the design with
  the coverage table marked "not yet read".

### `claude_plugins/sdd/commands/plan_from_spec.md`

Step 1's fallback, "Load `DesignSync` … only when those files are missing", becomes: read the design
through the `Artifact` tool as its `design.md` says, only when those files are missing.

### Human procedure: `claude_plugins/sdd/commands/README.md`

Add a "Registering a design" section and link it from Step 1 point 2 of the workflow. It is generic:
no project names. It covers:

1. The design is a Design Artifact in Claude. A design still in standalone Claude Design is moved
   into Claude first, by its owner, before 14 December 2026. A project that cannot move has to be
   redrawn in Claude.
2. The person running the command can edit the design: they own it, or the owner shared it with
   edit access. A view-only share is not enough. Never publish or widen sharing to work around it.
3. Copy the design's link (`claude.ai/artifact/<id>`). A handoff prompt Claude generates for the
   design also works, as long as it contains that link.
4. Either paste it into `<spec-dir>/design_prompt.md` before `/sdd:start`, or run
   `/sdd:register_design <link> [notes]` on the feature branch.
5. Check the report: the board names match the design, and every screenshot was written.
6. After the design changes in Claude, register it again; the repo keeps the copy taken at
   registration.

Elsewhere in the plugin, the wording that names the old input:

- `claude_plugins/sdd/commands/README.md` Step 1 point 2: `<design artifact link>` instead of
  `<handoff prompt or claude-design-url>`.
- `claude_plugins/sdd/README.md`: the `register_design` paragraph says the design is read through
  the `Artifact` tool rather than the web, and takes a Design Artifact link.

## Testing

- `tests/test_design_screenshots.py`, no browser:
  - a `canvas.json` naming a board whose file is missing exits 1, naming the path;
  - board stems map to PNG names (`Main.dc.html` → `Main.png`, `flows/Signup.dc.html` →
    `flows__Signup.png`);
  - the existing four tests pass unchanged.
- `tests/playwright/test_design_screenshots.py`, a fixture snapshot with `canvas.json`, a fixed board
  and an `expand: "fill"` board, a stand-in `support.js` and one `_blob/<id>` image:
  - one PNG per board, the fixed board at its `w` × `h`, the fill board at width `w`;
  - the blob image loads (no 404 in the page's requests);
  - a reference to a missing blob is reported on stderr, and the PNG is still written;
  - the existing three tests pass unchanged.
- The markdown command changes have no automated test. A manual registration of one of the user's
  own Design Artifacts on a scratch spec directory proves the route end to end: files synced, one
  PNG per board, `design.md` in the new shape. It is not committed.

## Documentation and downstream

- The upgrade notes say that `register_design` takes a Design Artifact link, that `DesignSync` and
  `/design-login` are no longer used by it, and that old `design.md` files stay valid.
- Two in-progress specs hold old-format handoff prompts that still need registering:
  `spec_dd/2. in progress/design_educator-interface-bulk-action/design_prompt.md` and
  `spec_dd/2. in progress/educator-interface-design-learner-csv-upload-design-fix/prompt.md`. Their
  owner follows the README procedure (move the project, paste the Artifact link) before those specs
  continue. This spec does not edit them.

## Success criteria

- `register_design.md`, `start.md` and `plan_from_spec.md` contain no `DesignSync`,
  `/design-login` or `claude.ai/design/p/` instruction; `grep -rn "DesignSync\|design-login" claude_plugins/sdd/commands` returns nothing.
- Registering one of the user's own Design Artifacts writes `design_source/canvas.json`, every
  board's `.dc.html`, the `_blob/` assets and one PNG per board, and a `design.md` with `Link`,
  `Version` and `Entry file` lines.
- Given a `claude.ai/design/p/` link, or a link to an Artifact the user cannot edit, the command
  stops with a message that points at the README section.
- `design_screenshots.sh` on an old snapshot (no `canvas.json`) produces the same PNG names as
  before.
- `claude_plugins/sdd/commands/README.md` has a "Registering a design" section with the six steps,
  and `claude_plugins/sdd` names no project-specific value.
- All tests in both `test_design_screenshots.py` files pass.
