## Anthropic: Claude Design to Claude Code

- **Export menu handoff (standalone era).** Per secondary sources, the Export menu at the top right of
  an open project offers folder, PDF, PPTX, Canva, standalone HTML, an organisation share URL and
  "Hand off to Claude Code" (local, or Claude Code Web). The bundle is described as design files, the
  chat and a README, or as a machine-readable spec of component structure, tokens, layout hierarchy and
  assets, "not a PNG". The user pastes a generated prompt that carries the bundle URL into Claude Code.
  A Japanese walkthrough says the pasted command sometimes fails to start, with a ZIP download as the
  fallback. This is the flow `register_design` encodes today (prompt with a project link).
  - https://claude-code-playbook.pages.dev/en/docs/level-4/claude-design-handoff
  - https://claudefa.st/blog/guide/mechanics/claude-design-handoff
  - https://horadecodar.com.br/claude-design-claude-code/
  - https://www.issoh.co.jp/tech/details/12682/
- **`/design-sync`.** Secondary source: runs inside Claude Code and brings a design system into context
  from a GitHub repo, design files, uploads or the local codebase; needs the Claude Design MCP server
  (`claude mcp add --scope user --transport http claude-design https://api.anthropic.com/v1/design/mcp`).
  Nothing found on what it writes to the repo or how it detects change. This matches the platform
  facts: DesignSync is for design-system projects only.
  - https://horadecodar.com.br/claude-design-claude-code/
- **`/design` from Claude Code.** One Japanese source claims a 17 June 2026 update added starting design
  work from Claude Code via `/design`; unconfirmed elsewhere (https://www.issoh.co.jp/tech/details/12682/).
- **Move into Claude (official).** Claude Design moved into Claude on 16 September 2026; standalone
  claude.ai/design goes read-only and closes 14 December 2026. Projects become artifacts, each owner moving
  their own (rolling out to paid plans); design systems migrate via the Artifacts page. Chats and comments
  do not move; **public links to standalone projects stop working** when it closes. Export before closure:
  Share > Project HTML > "Project archive" > Export gives a .zip of every project file (free); bulk download
  of all projects also rolling out. The article says nothing about Claude Code.
  - https://support.claude.com/en/articles/17440474-migrate-from-standalone-claude-design-to-claude.md
- **Public Claude Code plugins/skills that pull artifacts into a repo:** searched; none found. No public
  source documents reading `claude.ai/artifact/...` links programmatically; the `Artifact` tool in the
  platform facts is the only mechanism seen. Treat it as the reference path.

Implications for the procedure: two registration inputs exist for a human: (a) an Artifact link (new
designs and migrated projects), (b) a ZIP "Project archive" export for a not-yet-migrated or closed
standalone project (the only durable path once standalone closes). The old `?file=` project link and
`DesignSync get_file` path covers neither.

## Figma (the closest mature analogue)

- **Identification:** user copies a link to a frame/layer; the MCP client cannot open the link but extracts
  the `node-id`. URL form uses `123-456`, tools expect `123:456` (convert). Invalid-id errors are fixed by
  re-copying the id.
- **Fetching:** `get_design_context` (structured React+Tailwind representation), `get_variable_defs`,
  `get_metadata` (node map, for large selections), `get_screenshot` (visual reference), assets endpoint
  for images/SVGs (use localhost sources directly). Recommended order: context, then screenshot, then assets.
  Write-to-canvas tools are remote-only.
- **Auth:** remote server `https://mcp.figma.com/mcp` (Streamable HTTP, OAuth, e.g. `/mcp auth figma`); a
  local Dev Mode server runs inside the desktop app at `http://127.0.0.1:3845/mcp`. Rate limits per seat type.
- **Repo contents:** nothing is snapshotted; code is generated on demand. Durable artefacts are a rules file
  (Claude Code: an "MCP Servers" markdown section; Cursor: `.mdc`) and Code Connect mappings so output reuses
  real components ("without it, the model is guessing").
- **Re-sync:** re-run the tools on the node id; the link itself is the stable reference.
- Sources: https://github.com/figma/mcp-server-guide ;
  https://forum.figma.com/report-a-problem-6/figma-mcp-get-design-context-and-get-screenshot-fail-with-invalid-node-id-for-valid-nodes-52736 (via search summary).
- Lesson: Figma keeps the design remote and links by id; this repo's approach (snapshot source plus PNGs
  committed under the spec) is stronger for review and offline reproducibility, and no reference found does
  that snapshot automatically.

## Prompt-to-app builders

- **Lovable:** git sync, automatic two-way, creating a new repo when linked; edits in Lovable push to GitHub,
  commits to the default branch pull back. The repo is the whole app, not a design reference.
  https://docs.lovable.dev/integrations/git-sync-overview
- **Bolt:** two-way git integration for all users; import repos or connect to a new private repo; imports
  Lovable projects via GitHub. https://bolt.new/blog/github-hackathon ;
  https://support.bolt.new/integrations/lovable-import
- **v0:** no official docs on GitHub export found; not verified.
- Lesson: these hand over implemented code with git as the transport, so identification is "the repo" and
  re-sync is git. Not applicable to a visual reference whose output must be re-themed.

## Penpot and Storybook

- **Penpot:** official agentic dev environment docs describe an MCP server working against a live Penpot
  instance incl. exporting elements as images (https://help.penpot.app/technical-guide/developer/agentic-devenv/).
  Community servers: `export_object` (montevive), `export_shape` PNG/JPG/SVG/PDF (zcube), token export to
  CSS/JSON/SCSS/Tailwind (devstroop); credentials are Penpot API keys. Overview:
  https://shop.smashingmagazine.com/2026/01/penpot-experimenting-mcp-servers-ai-powered-design-workflows/ ;
  https://lobehub.com/mcp/montevive-penpot-mcp . A mid-2026 blog reports Claude writes Penpot JS less
  reliably than Figma calls.
- **Storybook:** `npx storybook add @storybook/addon-mcp` serves MCP at the dev server `/mcp`; the docs
  toolset reads a components manifest (off by default; `!manifest` tag excludes stories); Chromatic notes the
  manifest costs tokens. No snapshot lands in the repo: it is live. https://storybook.js.org/docs/ai/mcp/overview ;
  https://www.chromatic.com/docs/mcp . Chromatic snapshot review itself: not found.

## Cross-cutting patterns

1. Every reference identifies the design by a stable link or id that a tool (not a web fetch) resolves with
   the user's auth. Matches the `Artifact` tool rule "not WebFetch or curl".
2. Few snapshot into the repo. Those that persist anything persist rules and mappings, not the design.
   A committed copy (source plus screenshots) is this project's own choice and is justified by the
   closure of standalone links and by the reviewable-history need.
3. Re-sync is "re-read the link". Only git-based builders have diffable sync.
4. Screenshots are always a first-class fetch (Figma `get_screenshot`, Penpot export): an agent-readable
   image beside the structure. The existing `design_screenshots.sh` rendering plays that role for `.dc.html`
   artboards.
5. Exports as ZIP are the universal fallback (Claude Project archive, Lovable download), useful when a link
   dies.
