# Plan: better-looking notifications, phase 1 (carry a design through SDD)

This plan builds phase 1 of `1. spec.md`: the SDD process changes. Phase 2, the notifications UI,
is planned later in `2b. plan.md` (spec, Decision 1), so nothing here touches `freedom_ls/`.

Inputs to keep open while implementing: `1. spec.md`, `research_design_render_spike.md` (the
stand-in canvas and the render friction), `research_design_scope_and_sync_flow.md` §3 (how scope
candidates are found) and `spec_dd/3. done/2026-09-08_17:31_better-form-start-page/research_design_source.md`
(the shape of a token mapping).

## Skills and tools

- **`sdd:claude-code-authoring`**: every command edit in slices 3-10. Fan-out, `AskUserQuestion`
  and the design check's judgement stay at depth 0. Batch and fix-batch workers never ask the user.
  A helper followed inline (`design_check.md`) runs on the caller's model and grants.
- **`domain-glossary`**: use the spec's Terminology nouns exactly: drawn element, design state,
  design checklist, design check, design miss, token mapping, artboard, handoff prompt.
- **`ds:testing`, `fls-dev:testing`, `fls-dev:playwright-tests`**: `tests/test_design_screenshots.py`
  in slices 1-2. Browser tests carry `@pytest.mark.playwright`.
- **`code-comments`**: `design_screenshots.py`, `.sh` and the stand-in. No spec or plan citations
  in comments.
- **`unslop`**: all command and README prose.
- **`sdd:update-claude-project-settings`**: do not run its audit. Slice 1 adds one allow entry by
  hand and touches nothing else in `.claude/settings.json`.
- **MCP**: `design_check.md` drives the browser through `mcp__plugin_ds_playwright__*`, which is
  already allow-listed. `design_screenshots.py` uses the `playwright` Python package, not MCP
  (Decision 3). `DesignSync` is loaded with `ToolSearch` (`select:DesignSync`) at depth 0 in
  `register_design.md`, as today.

Slices 3-10 change command prose, which has no automated tests. Later runs exercise them, mostly
phase 2's (re-registering `user-communication`, then `/sdd:plan_from_spec 2b`,
`/sdd:implement_plan 2b` and `/fls-dev:do_qa`). Each slice names the run that does.

## Slice 1: screenshot a design's artboards with a script

**Behaviour.** `claude_plugins/sdd/scripts/design_screenshots.sh <spec-dir>` renders the entry file
from `<spec-dir>/design_source/` and writes one PNG per `[data-artboard]` element into
`<spec-dir>/design_screenshots/`. It fails with a named error when the entry file can't be found.

**Files.**

- New `claude_plugins/sdd/scripts/design_screenshots.sh`, modelled on
  `claude_plugins/fls-dev/scripts/compress_screenshots.sh` (header comment, `set -euo pipefail`,
  `SCRIPT_DIR` via `readlink -f`). Unlike that script it needs no `CLAUDE_PROJECT_DIR`: the spec
  dir comes in as an argument, relative to the caller's working directory.

  ```bash
  uv run --with playwright playwright install chromium   # a no-op when Chromium is present
  exec uv run --with playwright python "${SCRIPT_DIR}/design_screenshots.py" "$@"
  ```

- New `claude_plugins/sdd/scripts/design_screenshots.py`. Type hints throughout: mypy crawls it.

  ```python
  class DesignScreenshotError(Exception): ...

  def read_entry_file(spec_dir: Path) -> str:
      # design.md's "- Entry file: `User Communication.html`, a canvas of ..." line:
      # take the first backtick-quoted value. Raise when design.md or the line is missing.

  def prepare_copy(source: Path, dest: Path, entry: str) -> None:
      # shutil.copytree(source, dest). design_source/ itself is never written to.

  def serve(directory: Path) -> ThreadingHTTPServer:
      # ThreadingHTTPServer(("127.0.0.1", 0), partial(SimpleHTTPRequestHandler, directory=...))
      # on a daemon thread. Port 0 picks a free port. Silence the request log.

  def wait_for_artboards(page: Page) -> int:
      # one page.wait_for_function(js, timeout=30_000) whose JS resolves once
      # document.querySelectorAll('[data-artboard]').length has stopped changing
      # across a few ticks; return the count

  def capture(spec_dir: Path) -> list[Path]:
      entry = read_entry_file(spec_dir)
      if not (spec_dir / "design_source" / entry).is_file(): raise DesignScreenshotError(...)
      with TemporaryDirectory() as tmp:
          prepare_copy(...); server = serve(tmp)
          try:
            chromium; browser.new_context(viewport={"width": 1440, "height": 900},
                                          device_scale_factor=1)
            response = page.goto(url_for(entry), wait_until="networkidle")   # quote() the path
            if response is None or not response.ok: raise DesignScreenshotError(...)
            if wait_for_artboards(page) == 0: raise DesignScreenshotError("no artboards rendered")
            out = spec_dir / "design_screenshots"; out.mkdir(exist_ok=True)
            delete out/*.png
            for each [data-artboard] locator:
                name = attribute.replace("/", "__") + ".png"
                locator.screenshot(path=out / name, animations="disabled", scale="css")
          finally:
            server.shutdown()

  def main(argv: list[str]) -> int:
      # one positional <spec-dir>; DesignScreenshotError → "design_screenshots: <message>"
      # on stderr, exit 1. Success prints the written paths, one per line.
  ```

- `.claude/settings.json`: add `"Bash(claude_plugins/sdd/scripts/design_screenshots.sh:*)"` after
  the `land_on_main.sh` entry.
- New `tests/test_design_screenshots.py` (no browser) and `tests/playwright/test_design_screenshots.py`
  (browser, `@pytest.mark.playwright`, the location the playwright-tests skill requires), in the
  style of `tests/test_upstream_change_scan.py`. Each test builds a spec dir under `tmp_path` (use
  a name with a space, as real spec dirs have), writes a `design.md` and a `design_source/`, and
  runs the Python script as a subprocess with `sys.executable`. The project venv already has
  `playwright` and Chromium for the Playwright suite, so the tests don't go through
  `uv run --with`. No test runs the `.sh` wrapper, because its first line can download Chromium;
  shellcheck covers it. Add `tests/playwright/__init__.py` so the two same-named test modules
  don't collide. Shared builders go in `tests/conftest.py` fixtures only if both files need
  them. The browser tests don't take the `page` or `live_server` fixtures: they test a script
  that drives its own browser against its own static server, not a Django view.

**Tests.**

- No `design.md`, or no "Entry file" line: exit 1, and stderr names the problem.
- The entry file named in `design.md` is missing from `design_source/`: exit 1, and stderr names
  the missing path. No browser starts.
- `@pytest.mark.playwright`: a static `index.html` holding two
  `<div data-artboard="s-1/a">`/`"s-1/b"` elements writes exactly `s-1__a.png` and `s-1__b.png`.
  A stale `old__x.png` placed there beforehand is gone. Every file in `design_source/` is
  byte-identical afterwards.

## Slice 2: render a Claude Design canvas flat, and fall back for plain pages

**Behaviour.** An entry file that loads `design-canvas.jsx` renders through the flat stand-in, so
every artboard sits at 1:1 and can be screenshotted. A canvas page that renders no artboards is an
error. A page with no canvas gets two whole-page screenshots instead.

**Files.**

- New `claude_plugins/sdd/resources/design_canvas_flat.jsx`: the stand-in from
  `research_design_render_spike.md` ("The flat canvas stand-in"), unchanged in behaviour.
- `design_screenshots.py`:

  ```python
  STAND_IN = Path(__file__).resolve().parents[1] / "resources" / "design_canvas_flat.jsx"

  def uses_design_canvas(entry_html: str) -> bool:
      return "design-canvas.jsx" in entry_html

  capture computes is_canvas = uses_design_canvas(entry text) once and passes it on.

  prepare_copy(source, dest, is_canvas): after copytree, when is_canvas, copy STAND_IN over
      dest / "design-canvas.jsx" (the copy only)

  capture, after wait_for_artboards:
      count > 0                         → artboard screenshots (slice 1)
      count == 0 and canvas             → DesignScreenshotError("no artboards rendered")
      count == 0 and not canvas         → for width in (1280, 375): set viewport width,
                                          page.screenshot(full_page=True, animations="disabled",
                                          scale="css") to "<entry stem>__<width>.png"
  ```

**Tests.**

- `prepare_copy(..., is_canvas=True)` on a `design_source/` holding `design-canvas.jsx` leaves
  the copy's `design-canvas.jsx` equal to `design_canvas_flat.jsx`, and the source file unchanged.
  Load the module with `importlib.util.spec_from_file_location`, since `claude_plugins/sdd/scripts/`
  is not a package.
- `@pytest.mark.playwright`: an entry holding `<script type="text/babel" src="design-canvas.jsx">`,
  with no Babel loaded, renders nothing. Exit 1, and stderr says no artboards rendered.
- `@pytest.mark.playwright`: a plain `index.html` with no artboards writes `index__1280.png` and
  `index__375.png`. Read each width from the PNG's IHDR bytes (offset 16, big-endian `uint32`) and
  assert 1280 and 375.

## Slice 4: registration settles scope in `design_scope.md`

**Behaviour.** Registration asks about every drawn element nobody has accounted for and records
each answer as one row in `<spec-dir>/design_scope.md`. Re-registration reconciles the file
instead of rewriting it.

**Files.** `claude_plugins/sdd/commands/register_design.md`.

- **New Step 5: scope**, after slice 3's Step 4. "Point the consumers at it" and the commit move
  to Steps 6 and 7; fix every in-file reference to them.
- The step finds candidates by comparing each drawn element in the synced source and screenshots with the design brief, the owning spec's `idea.md` or
  `1. spec.md`, and FLS's existing code (a matching URL name, view or model). An element that
  fails at least one check is a candidate (`research_design_scope_and_sync_flow.md` §3). Skip any
  element that already has a row. Ask about each candidate through `AskUserQuestion`, up to four
  per call, with the options `build`, `leave out` and `later: <spec>`. Offer `later` only when the
  coverage table names a spec for that screen.
- The file's shape, written in the command:

  ```markdown
  # Design scope: <effort or spec name>

  | Drawn element | Design section | Question asked | Answer | Decided at | Date | Why |
  |---|---|---|---|---|---|---|
  | Preferences gear (panel header) | 1 Bell and badge | Build the Preferences gear? | later: user-communication-2-notification-email | user-communication-1-notifications-core | 2026-09-27 | No preferences page exists yet |
  ```

- **Cut effort parent.** Settle only what applies to the whole effort. A question that belongs to
  one child gets the answer `open: ask when <child> starts`.
- **Rules stated once in the command:** one row per drawn element. A later spec that reverses a
  decision edits the row and never adds a second one.
- **Re-registration.** Existing rows stay as they are. New drawn elements are asked about and
  appended. A row whose element the design no longer draws gets the answer `removed from design`
  and stays. An unchanged design leaves the file byte-identical.
- **`design.md` template, "How to treat it"**: add that `design_scope.md` is the one home for scope
  decisions, that specs and plans cite it rather than restating it, and that a drawn element whose
  row says `leave out` or `later` is not built even though the source shows it.
- **Commit step** also stages `design_scope.md`.

**Tests.** None automated (command prose). The phase-2 re-registration exercises it. The suite
must stay green.

## Slice 7: the plan transcribes the design

**Behaviour.** When a `design.md` applies, `/sdd:plan_from_spec` writes a Design section: a
per-state transcription with a design checklist per design state, and a token mapping. Each slice
that builds a designed screen names its design states, and each QA test for a design state names
its design screenshot and checklist.

**Files.** `claude_plugins/sdd/commands/plan_from_spec.md`.

- Replace Step 1's design paragraph (L38): when the spec or its directory names a `design.md`,
  read `design_source/`, `design_screenshots/` and `design_scope.md` from the directory that holds
  it. Use `DesignSync` only if those files are missing, and then say so in the summary.
- Step 3 gains **"The Design section"**, required when a `design.md` applies:
  - **Per-state transcription**, one block per design state the plan builds, headed by its id
    (`<section-id>/<artboard-id>`). Each block gives: the design screenshot path; the viewport width
    (the artboard's width); how to reach the state in the running app (URL and the data it
    needs); the elements in order with their hierarchy and copy; which controls show in this state.
    It ends with a **design checklist**: one checkable line per element, order or state rule.
    Drawn elements that `design_scope.md` answers `leave out` or `later` are omitted, citing the
    row. Where the screenshot and the CSS disagree, transcribe the screenshot.
  - **Token mapping**: a table `Design treatment | FLS token / component / icon | Lost`, covering
    every tint, tile, weight, text treatment and icon the transcriptions use, in the shape of
    `spec_dd/3. done/2026-09-08_17:31_better-form-start-page/research_design_source.md` ("Token

  `**Design states:** <id>, <id>` naming the states it builds. `implement_plan` reads this line.
- Step 1 also gains: a drawn element found while planning that has no `design_scope.md` row is
  asked about in the Step 1 `AskUserQuestion` batch, and the answer is appended as a row.
- Step 5 gains: a QA test that maps to a design state names the state's design screenshot path and
  copies that state's design checklist from the transcription.
- Step 9 also stages `design_scope.md` when this run changed it. Add this to the staging list
  slice 6 wrote; don't replace it.

    do not build a drawn element whose `design_scope.md` row says `leave out` or `later`, even when

    `pre_step_rebase.md` reads `## Rebase Hooks`. After a batch whose slice has a

    ```
    blank or absent → skip; record "design check skipped: no Design check hook" for the summary
    otherwise:
      fixes = 0
      loop:
        follow the hook file with <spec-dir>, <plan path> and the slice's design states
          → one screenshot path per state and width
        for each state: Read the app screenshot and the design screenshot. List each one's
          elements region by region, then diff both lists against the state's design checklist.
          Judge layout, order, hierarchy, relative density, states and copy.
          Never colour, font or exact pixels.
        drawn element with no design_scope.md row → AskUserQuestion (build / leave out /
          later: <spec>), append the row, carry on
        no design misses → delete the hook's screenshots by name; log "design check passed"; break

          → stop the run: status: blocked, naming the miss, the plan line it contradicts and
            the hook's screenshot paths. The screenshots stay as evidence; the next check of
            that slice overwrites them (the names are fixed) and deletes them when it passes
        otherwise → spawn one fix batch (general-purpose, model "sonnet") with the list of
          misses plus the same design paths as the batch brief; it commits
          "[batch <id>] design fix <n>"; fixes += 1
    ```

  - Resume scan: when the last completed batch has design states and no later batch is committed,
    run its design check before spawning the next batch.
  - Step 3 summary lists each design check (passed, fix batches used) or that the check was
    skipped.
- `README.md` workflow step 4: after a designed slice, implementation runs the design check
  through the `Design check` hook. Add this after the suffix sentence slice 6 wrote; don't replace
  it.
