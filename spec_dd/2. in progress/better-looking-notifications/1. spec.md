# Spec: better-looking notifications

## Purpose

`user-communication-1-notifications-core` built the bell, panel and notification centre from a
registered Claude Design design, and the result looks nothing like it. The design never reached the
implementation batches or QA, no step mapped its styling onto FLS tokens, and no step ever rendered
it (`idea.md`, "What went wrong"). This spec fixes how SDD carries a design from registration to QA
(phase 1), then rebuilds the notifications UI to match the design through the fixed process
(phase 2). Phase 2 is the test of phase 1.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| drawn element | coined | A control, region or state that a design's artboard draws. Each one gets one row in `design_scope.md`. "Item" is taken. |
| artboard | borrowed | Claude Design's `DCArtboard` in `design-canvas.jsx`: one framed screen-state on a design canvas. |
| handoff prompt | borrowed | The prompt Claude Design copies for a selection (`design sync prompt.md` is one). |
| token mapping | coined | The plan's table saying which FLS token, cotton component or semantic icon expresses each visual treatment the design draws, and what is lost. |

## Scope

**In, phase 1 (SDD process).** `/sdd:register_design` takes a handoff prompt, syncs the design's
source, screenshots every artboard and records scope answers in `design_scope.md`.
`/sdd:spec_from_idea`, `/sdd:plan_from_spec`, `/sdd:implement_plan` and `/fls-dev:do_qa` build and
check against those files. Pre-commit leaves synced design source byte-for-byte intact.

**In, phase 2 (notifications UI).** Re-register `spec_dd/1. next/user-communication/`, then
restyle every surface `user-communication-1-notifications-core` built. That covers the bell and
badge, and the panel as a desktop popover and as the full-width sheet at 375px. It covers the
notification centre populated, all read, empty, with the Unread filter empty, as a long list, and
at 375px. The behaviour of those surfaces does not change.

**Out:**
- The drawn elements seeded as `leave out` in phase 2 (see "design_scope.md seed").
- `header_bar.html`'s site title hiding instead of truncating at 375px. It belongs to `base`, not
  `comms`.
- The bell's 40px hit target against the design's 44px.
- Re-registering any design other than `user-communication`. It is the only `design.md` in the
  repo.
- Pixel diffing. FLS's theme deliberately differs from the design's.

## Decisions

1. **Two phases on one branch.** `/sdd:plan_from_spec` runs twice: once for phase 1
   (`2. plan.md`), and again after phase 1 is implemented, for phase 2 (`2b. plan.md`,
   `3b. frontend_qa.md`). Planning phase 2 with today's commands would skip the transcription and
   the conformance checks it exists to test.
2. **The design source is committed whole, including `kit.css`.** A worktree only has what git
   has. `design-system/kit.css` styles every artboard. It is not "the other theme" that the current
   `design.md` says to ignore.
3. **The screenshots come from a script, not from Playwright MCP.** A Python script run by
   `sdd:sdd-mechanic` produces the same PNGs on every run and costs no model context. The spike's
   one-MCP-call-per-artboard approach does neither.
4. **Hooks skip `design_source/`, and the secrets baseline is not used for it.** Synced files must
   stay byte-identical, and re-syncs are routine, so baselining every SRI `integrity` hash again on
   each re-sync is churn.
5. **Implementation fixes its own conformance misses.** A miss is work the plan asked for and the
   batch did not do. It goes back to a fix batch, not to the user. QA never auto-fixes a
   conformance miss, as the idea asks.
6. **The category tile colour is optional.** A category with no colour gets a neutral tile. That is
   also what the design draws for registration, the one category FLS ships, so no downstream
   project breaks.
7. **`mark_all_read` maps to Heroicons `check-circle`.** Heroicons has no double tick. Lucide,
   Tabler and Phosphor get their real double tick.

## Requirements

### Registration: `claude_plugins/sdd/commands/register_design.md`

- **Input.** The second argument is a handoff prompt, pasted or given as a file path. A bare
  `https://claude.ai/design/p/…` link is still accepted. From the prompt, take the project id and
  entry file from the link, the focus files from "Focus on these files" and the imports from "Also
  read these files". Given a bare link, work out the file list as today, and say so in the summary.
- **`design_prompt.md`.** Copy the prompt verbatim into `<spec-dir>/design_prompt.md`.
- **`design_source/`.** Sync through `DesignSync` `get_file`, at depth 0: the focus files, the
  listed imports, and every local file they reference through `@import`, `<link href>` or
  `<script src>`, repeated until nothing new turns up. Write each file whole and unedited to
  `<spec-dir>/design_source/<project path>`. Skip external URLs and binaries (fonts, images). On
  re-registration, replace the directory's contents.
- **`design_screenshots/`.** Delegate to `sdd:sdd-mechanic`, which runs
  `claude_plugins/sdd/scripts/design_screenshots.sh <spec-dir>`. `design_screenshots/` must never be
  `screenshots/`, which `do_qa` wipes on every run.
- **`design_scope.md`.** Find candidates: drawn elements that the design brief, the owning spec's
  idea or spec, and FLS's existing code don't all account for
  (`research_design_scope_and_sync_flow.md` §3). Ask about each through `AskUserQuestion`, with the
  answers `build`, `leave out`, or `later: <spec>`. Write one row per drawn element:

  ```markdown
  | Drawn element | Design section | Question asked | Answer | Decided at | Date | Why |
  |---|---|---|---|---|---|---|
  | Preferences gear (panel header) | 1 Bell and badge | Build the Preferences gear? | later: user-communication-2-notification-email | user-communication-1-notifications-core | 2026-09-27 | No preferences page exists yet |
  ```

  For a cut effort, settle only what applies to the whole effort. Any question that belongs to one
  child is written `open: ask when <child> starts`.
- **Re-registration.** `design.md` is still rewritten whole. `design_scope.md` is reconciled:
  existing rows stay, new drawn elements are asked about, and rows for elements the design dropped
  are marked `removed from design` and kept.
- **The `design.md` template (L66-110).** "Made of" comes from the prompt, and the old "ignore the
  other files" line goes. "How to read it" now says to read `design_source/` and
  `design_screenshots/` from the repo first, and to use `DesignSync` only to re-register. "How to
  treat it" adds that `design_scope.md` is the one home for scope decisions and that specs and plans
  cite it rather than restating it.
- **Step 5's commit** stages `design_prompt.md`, `design_source/`, `design_screenshots/` and
  `design_scope.md`.

### Screenshot script: `claude_plugins/sdd/scripts/design_screenshots.{sh,py}` and `claude_plugins/sdd/resources/design_canvas_flat.jsx`

- `design_canvas_flat.jsx` is the stand-in from `research_design_render_spike.md`, unchanged in
  behaviour. Every artboard renders 1:1 inside `data-artboard="<section-id>/<artboard-id>"`.
- `design_screenshots.sh` is a thin wrapper in the `compress_screenshots.sh` style that runs
  `uv run --with playwright python design_screenshots.py "$@"`. It installs Chromium through
  `playwright install chromium` when it is missing.
- `design_screenshots.py <spec-dir>` works like this:
  1. Copy `design_source/` to a temporary directory. When the entry file loads
     `design-canvas.jsx`, replace that file with the stand-in. `design_source/` itself is never
     modified.
  2. Serve the copy on `127.0.0.1` on a free port.
  3. Open it in Chromium at viewport 1440x900 with `deviceScaleFactor: 1`. Wait for `networkidle`,
     then for the `[data-artboard]` count to stop changing.
  4. Take one element screenshot per artboard (`animations: "disabled"`, `scale: "css"`) and write
     it to `<spec-dir>/design_screenshots/<section-id>__<artboard-id>.png`, clearing the old PNGs
     first.
  5. If the design has no canvas, screenshot the whole page at widths 1280 and 375 instead.
  6. Exit non-zero, naming the problem, when the page fails to render or finds no artboards.
- `.claude/settings.json` gets an allow entry for the `.sh`, next to the existing
  `claude_plugins/sdd/scripts/*` entries (L106-107).

### Spec step: `claude_plugins/sdd/commands/spec_from_idea.md`

The design passage (L65-68) gains these rules. When a `design.md` applies, read `design_scope.md`
and ask about any `open` row or unrecorded drawn element on this spec's screens in the Step 2
batch, then write the answers into `design_scope.md`. Scope → Out cites `design_scope.md` by path
and does not restate the exclusions. Resources names `design.md`.

### Plan step: `claude_plugins/sdd/commands/plan_from_spec.md`

- Step 1 (L38): when a `design.md` applies, the plan reads `design_source/`, `design_screenshots/`
  and `design_scope.md` and gains a **Design** section with two parts.
  - A per-state transcription for each designed screen and state the plan builds: its design
    screenshot file; the elements in order with their hierarchy and copy; which controls show in
    which state; and how to reach the state in the running app (URL and data). Drawn elements that
    `design_scope.md` leaves out are omitted, citing the row. The screenshot wins over the CSS when
    they disagree.
  - A token mapping: `Design treatment | FLS token / component / icon | Lost`. It covers every tint,
    tile, weight, text treatment and icon the transcription uses, in the shape of
    `better-form-start-page/research_design_source.md`. No new theme tokens.
- Each slice that builds a designed screen is marked with the states it builds, so the
  implementation knows where to check.
- Step 5: each `frontend_qa.md` test that maps to a design state names that state's design
  screenshot and carries its conformance checklist, taken from the transcription.
- If planning turns up a drawn element with no `design_scope.md` row, ask about it and add the row.

### Implementation step: `claude_plugins/sdd/commands/implement_plan.md`

- Every batch brief (Step 2) passes paths, not contents: the plan's Design section, the design
  screenshots for the batch's states, and `design_scope.md`. It also says not to build a drawn
  element whose row says `leave out` or `later`, even when the source shows it.
- After a slice marked with design states returns `ok`, the depth-0 orchestrator does a
  conformance check:
  1. Start the dev server and reach each state the way the transcription says.
  2. Screenshot each state through Playwright MCP at the design's widths, into `.sdd-work/`.
  3. Read that screenshot and the design screenshot. List each one's elements region by region,
     then diff the lists against the plan's checklist. Judge layout, order, hierarchy, relative
     density, states and copy. Do not judge colour, font or exact pixels.
  4. For each miss, spawn a fix batch with the list of misses, then check again.
  5. A miss that survives two fix batches unchanged stops the run with `status: blocked`, naming
     the miss. It points to a contradiction between the plan and the tokens, and a human has to
     settle it.
  6. A drawn element with no scope row goes to `AskUserQuestion`. The answer is written to
     `design_scope.md`, and the run carries on.
- `allowed-tools` gains `ToolSearch`, `AskUserQuestion` and `mcp__playwright__*`.

### QA: `claude_plugins/fls-dev/commands/do_qa.md`

- Steps 7-9: for every test that names a design screenshot, put this run's screenshot beside it,
  check the test's conformance checklist, and record a `<section>.<n>-design` row in the report.
  Compare the same way as the implementation check.
- A drawn element the build lacks passes if `design_scope.md` says `leave out` or `later`.
- Step 13: every conformance miss goes to the red lane, with the reason "design conformance: needs
  a human to confirm".
- Step 15: a miss becomes an item under category 1. A drawn element with no scope row becomes an
  item under category 4: `Decide whether to build <element>, then record it in design_scope.md`.

### Pre-commit: `.pre-commit-config.yaml`

Add `exclude: '(^|/)design_source/'` to `trailing-whitespace`, `end-of-file-fixer` and
`detect-secrets`. `check-added-large-files` keeps scanning `design_screenshots/`.

### Phase 2 setup

- Run the new `/sdd:register_design spec_dd/1. next/user-communication/` with
  `design sync prompt.md`. It writes `design_prompt.md`, `design_source/`, `design_screenshots/`
  and `design_scope.md` there, and rewrites `design.md`.
- **design_scope.md seed.** Every row below is `leave out` unless its "Why" says otherwise, decided
  at `user-communication-1-notifications-core` on 2026-09-27. "Question asked" reads
  `not recorded (settled before design_scope.md existed)`.

  | Drawn element | Section | Why |
  |---|---|---|
  | Preferences gear (panel header) | 1 | No preferences page yet. Answer is `later: user-communication-2-notification-email` |
  | Preferences button (centre header) | 2 | Same as the gear |
  | "about" line on centre rows | 2 | Left out by the done spec's plan |
  | "Show older notifications" | 2 | The centre keeps its pagination |
  | `role="dialog"` / `aria-haspopup="dialog"` on the panel | 1 | The panel is a disclosure and does not trap focus |
  | Message item (panel and centre) | 1, 2 | No message category until `user-communication-4-direct-messaging` |

- Once re-registration is committed, delete the stand-ins beside this spec: `design_source/`,
  `design_screenshots/`, `design_snapshot_notifications.md` and `design sync prompt.md`. The parent
  directory holds the real ones.

### Phase 2 UI: `freedom_ls/comms/`, `freedom_ls/base/`, `freedom_ls/icons/`

The per-state transcription in `2b. plan.md` is the source of truth for the details. The spec fixes
these outcomes:

- **Category colour.** In `freedom_ls/base/notification_categories.py`, add
  `NotificationColour(StrEnum)` with `PRIMARY`, `SUCCESS`, `WARNING`, `INFO` and `ERROR`, and add
  `colour: NotificationColour | None = None` as the last field of `NotificationCategory`.
  `course.registered` stays `None`. `Notification.colour` in `freedom_ls/comms/models.py` reads it
  the way `Notification.icon` does.
- **Icon tile** (`notification_row.html`). The icon sits in a small rounded tile. Each colour maps
  to literal classes in the template, so Tailwind sees them: `-light`/`on-*-light` pairs for the
  statuses, `bg-primary/10 text-primary` for primary, and `bg-surface-2 text-muted` for `None`. The
  glyph must reach 3:1 against its tile under every shipped theme.
- **Rows are inbox items.** The message link uses the row's text colour with no underline. A
  stretched `::after` covers the row, so the whole row is the click target, with a pointer cursor.
  The Mark read/unread `c-button` stays a sibling of the link, never inside it, and sits above the
  stretched area. The row stays one real `<a>` to `comms:notification_open`.
- **Unread rows** get a primary opacity-modifier tint, on top of the bold weight, the dot and the
  label. The visible "Unread" label becomes `aria-hidden="true"`, because the `sr-only` "Unread."
  prefix already announces it.
- **Messages** clamp to two lines wherever the design screenshot clamps them.
- **Day headings** (`notification_list.html`) follow the design screenshots' treatment: uppercase,
  tracked and muted. The screenshots decide their size.
- **Badge** (`notification_badge.html`) gets a ring in the header colour, so it separates from the
  bell.
- **Filter** (`notification_list.html`) keeps its two `<a>` elements with `aria-current`. They lose
  the underline and read as the design's segmented control.
- **Mark all as read**, in the panel (`notification_panel.html`) and on the centre, becomes a ghost
  `c-button` with `icon_left="mark_all_read"`. Add `mark_all_read` to `SEMANTIC_ICON_NAMES`
  (`freedom_ls/icons/semantic_names.py`) and to all four dicts in `freedom_ls/icons/mappings.py`:
  Heroicons `check-circle`, Lucide `check-check`, Tabler `checks`, Phosphor `checks`.
- **All-read banner** uses `c-icon name="success"` in place of `complete`.
- **No new theme tokens.** No changes to views, URLs, the Alpine component or polling.

## Testing

- Registration run against `spec_dd/1. next/user-communication/`:
  - `design_source/` holds every prompt-listed file plus `design-system/colors_and_type.css`, found
    by following `kit.css`'s `@import`.
  - Each synced file matches `DesignSync`'s content byte for byte.
  - `design_screenshots/` holds one PNG for every artboard in `User Communication.html`, including
    the ten spike names (`uc-1-bell__hd.png` … `uc-2-centre__emptym.png`).
  - `git commit` of the result passes pre-commit without changing any synced file.
- `design_screenshots.py` fails with a named error when `design_source/` has no entry file, or
  when the page renders no artboards.
- Registering again unchanged leaves `design_scope.md` identical. Deleting an artboard from the
  copy marks its rows `removed from design`.
- `NotificationCategory` built without `colour` gets `None`. `Notification.colour` passes the
  category's colour through.
- Row rendering (`freedom_ls/comms/tests/test_rendering.py`):
  - an unread row carries the tint class and `aria-hidden` on its visible label;
  - `Mark read` is not a descendant of the row's `<a>`;
  - each `NotificationColour` and `None` renders its tile classes.
- `mark_all_read` resolves in all four icon sets, and the icon system checks
  (`freedom_ls/icons/checks.py`) pass.
- Playwright (`freedom_ls/comms/tests/playwright/test_notification_bell.py`,
  `test_notification_centre.py`): the existing tests still pass. Clicking a row outside the message
  text opens its target. Clicking Mark read in a row marks it read without navigating.
- `3b. frontend_qa.md`: each of the ten design states is compared, with a conformance row in the
  report.

## Open questions

- QA sends conformance misses to a human as todo items, as the idea says, while the implementation
  step fixes its own. Should QA fix them too, through `fls-dev:qa-bugfixer` with a Playwright test
  that proves the fix? Default: no.
- `uv run --with playwright` may pull a different Playwright version than the Chromium already
  installed, which costs a one-off browser download. Default: accept it.
- Seed rows record no question, because the decisions were made before `design_scope.md` existed.
  Default: `not recorded`.
