# Implementation plan: Google Analytics 4

Source: `idea.md` in this directory, and the four research files beside it. There is no spec, the
idea is the source of truth.

GA4 goes in the way PostHog did: a setting in `DeploymentSettings`, a context processor, a snippet in
`_base.html`. On top of that come four GA4 events carried by one-shot flags in the session, a
`user_id` for logged-in users, one boolean that decides whether any analytics snippet loads, the CSP
domains for both services, and a privacy policy that admits analytics exists.

Follow TDD throughout: a failing test first, then the code that passes it.

---

## What already exists, and must be reused

- **`DeploymentSettings`** (`freedom_ls/deployment/config.py`) declares `POSTHOG_API_KEY` with
  `Setting(default=None)`. The measurement ID is declared the same way, beside it.
- **`posthog_config`** (`freedom_ls/deployment/context_processors.py`) is the shape to copy for the
  GA4 context processor. It is registered in `config/settings_base.py:196`, and the raw environment
  reads sit at `config/settings_base.py:539-547`.
- **The PostHog block in `_base.html:84-93`** is gated by `{% if posthog_api_key %}` and nothing else.
  The GA4 block sits next to it.
- **`freedom_ls/deployment/tests/test_context_processors.py`** has the two test shapes this work
  needs: call the context processor with a `RequestFactory` request, and fetch `/` with the test
  client to assert the snippet is present or absent. Use `mock_site_context` for the client tests.
- **The webhook call sites** mark three of the four moments already: `fire_webhook_event` in
  `AccountAdapter.save_user()` (`freedom_ls/accounts/allauth_account_adapter.py:126`) and in
  `course_finish` (`freedom_ls/learner_interface/views.py:1618`). Their tests
  (`accounts/tests/test_account_webhook_events.py`,
  `learner_interface/tests/test_course_completion_webhook_events.py`) show how to reach each branch.
- **`#interface-main`** (`freedom_ls/base/templates/_base_interface.html:207`) is the only region a
  boosted course-player navigation keeps. `c-player-nav` sets `hx-select="#interface-main"`.
- **`SECURE_CSP_REPORT_ONLY`** (`config/settings_base.py:479`) and its test
  `freedom_ls/base/tests/test_csp.py`.

Two decisions the idea leaves to the plan:

- **The one-shot flag code lives in `freedom_ls/base`, not `freedom_ls/deployment`.** Three apps
  record flags (`accounts`, `course_applications`, `learner_interface`) and no app imports
  `deployment` today. `base` has no outgoing app dependencies and the flag code needs only the
  session, so it fits there. The one new edge is `course_applications --> base`.
  `deployment --> base` already exists, so the context processor can import the pop function.
- **The no-form `generate_lead` is recorded in `apply`, not inside `_start_application`.**
  `_start_application(user, course)` has no request. `apply` returns early when an application
  already exists, so reaching its no-form branch means the application was just created.

## Task 2: `analytics_enabled`, the one place that decides whether analytics loads

**`freedom_ls/deployment/context_processors.py`**

```python
TOKEN_BEARING_URL_NAMES = frozenset(
    {"account_confirm_email", "account_reset_password_from_key"}
)


def analytics_enabled(request: HttpRequest) -> dict[str, bool]:
    """The one place that decides whether any analytics snippet loads."""
    match = request.resolver_match
    url_name = match.url_name if match is not None else None
    return {"analytics_enabled": url_name not in TOKEN_BEARING_URL_NAMES}
```

`resolver_match` is `None` on a 404, which is why the guard is there. The docstring should say that a
downstream deployment adds consent by listing its own context processor in place of this one. The
two names are allauth's own (`allauth/account/urls.py`).

**`config/settings_base.py`**

Register `freedom_ls.deployment.context_processors.analytics_enabled` directly above `posthog_config`.

**`freedom_ls/base/templates/_base.html`**

Change the PostHog gate to `{% if analytics_enabled and posthog_api_key %}`. Nothing else in the
PostHog block changes.

A page rendered without context processors (the 500 page) has no `analytics_enabled`, so it loads
nothing. That is the behaviour we want from an error page.

Tests, in `freedom_ls/deployment/tests/test_context_processors.py`:

- `analytics_enabled` is true for an ordinary URL name, false for each of the two token-bearing URL
  names, and true when `resolver_match` is `None`.
- With `POSTHOG_API_KEY` set, `posthog.init(` is present on `/` and absent on
  `reverse("account_confirm_email", args=["some-key"])`. allauth renders that page for an invalid
  key too, so no real confirmation is needed.

## Task 3: the gtag.js snippet and `user_id`

**`freedom_ls/deployment/context_processors.py`**

Add `google_analytics_config(_request)` returning
`{"google_analytics_measurement_id": deployment_config.GOOGLE_ANALYTICS_MEASUREMENT_ID}`. Task 4 adds
a second key to it. Register it in `config/settings_base.py` directly under `posthog_config`.

**`freedom_ls/base/templates/_base.html`**

Directly after the PostHog block, inside `<head>`:

```django
{% if analytics_enabled and google_analytics_measurement_id %}
    <script async
            src="https://www.googletagmanager.com/gtag/js?id={{ google_analytics_measurement_id|urlencode }}"></script>
    <script>
    window.dataLayer = window.dataLayer || [];
    function gtag(){dataLayer.push(arguments);}
    gtag('js', new Date());
    gtag('config', '{{ google_analytics_measurement_id|escapejs }}'{% if user.is_authenticated %}, {user_id: '{{ user.pk }}'}{% endif %});
    </script>
{% endif %}
```

No `send_page_view`, no `debug_mode`, no other config option. GA4's enhanced measurement records the
page views, including the ones htmx makes through the History API. Nothing in FLS fires a
`page_view` by hand.

`user_id` is `user.pk` and nothing else. No email, name or phone number goes into the snippet.

Tests, in `test_context_processors.py`, mirroring `TestPosthogSnippetRendering`:

- ID set: the `googletagmanager.com/gtag/js?id=G-TEST` loader and `gtag('config', 'G-TEST'` are in
  the response for `/`.
- ID unset: `googletagmanager.com` appears nowhere in the response.
- ID set, anonymous request: no `user_id` in the response.
- ID set, logged-in user: `user_id: '<pk>'` is in the response, and the user's email is not inside
  the GA4 script block.
- ID set, token-bearing page: `googletagmanager.com` appears nowhere in the response.

## Task 4: one-shot flags and the events partial

**`freedom_ls/base/google_analytics.py`** (new)

```python
class GoogleAnalyticsEvent(StrEnum):
    SIGN_UP = "sign_up"
    GENERATE_LEAD = "generate_lead"
    TUTORIAL_BEGIN = "tutorial_begin"
    TUTORIAL_COMPLETE = "tutorial_complete"


GOOGLE_ANALYTICS_FLAGS_SESSION_KEY = "google_analytics_flags"


def record_google_analytics_flag(
    request: HttpRequest, event: GoogleAnalyticsEvent
) -> None:
    """Record a one-shot flag; the next page render emits the GA4 event."""
    flags = request.session.get(GOOGLE_ANALYTICS_FLAGS_SESSION_KEY, [])
    if event.value not in flags:
        request.session[GOOGLE_ANALYTICS_FLAGS_SESSION_KEY] = [*flags, event.value]


def pop_google_analytics_flags(request: HttpRequest) -> list[str]:
    return request.session.pop(GOOGLE_ANALYTICS_FLAGS_SESSION_KEY, [])
```

The enum is the allow-list. Only its four values can reach the inline script, so nothing a user
typed ever does. Add a module docstring saying these are GA4's event names and that `tutorial_*` is
GA4's word for the begin and complete pair, not FLS's.

Assigning a new list, not appending in place, is what marks the session modified.

**`freedom_ls/deployment/context_processors.py`**

`google_analytics_config` now takes `request` and returns a second key. This is its final shape:

```python
def google_analytics_config(
    request: HttpRequest,
) -> dict[str, str | None | Callable[[], list[str]]]:
    measurement_id = deployment_config.GOOGLE_ANALYTICS_MEASUREMENT_ID
    if measurement_id is None:
        # Nothing will emit these, so drop them instead of letting them wait for
        # a measurement ID that may arrive weeks later.
        pop_google_analytics_flags(request)
    return {
        "google_analytics_measurement_id": measurement_id,
        "google_analytics_flags": partial(
            pop_google_analytics_flags, request
        ),
    }
```

The value is a callable on purpose. Django calls it when a template first resolves the variable, so
the flags are popped only by a template that emits them. A render that never reaches the events
partial (an HTMX partial, an email, a token-bearing page) leaves the flags in the session for the
next page. With no measurement ID the flags are discarded up front, and the callable then finds
nothing.

**`freedom_ls/base/templates/partials/google_analytics_events.html`** (new)

```django
{% if analytics_enabled and google_analytics_measurement_id %}
    {% for flag in google_analytics_flags %}
        <script>gtag('event', '{{ flag|escapejs }}'); document.currentScript.remove();</script>
    {% endfor %}
{% endif %}
```

The script removes itself so htmx's history snapshot of the page does not carry it, and a Back
navigation cannot fire the event again. Say so in a template comment, along with why the partial is
included twice.

**Two include points.** `{% include "partials/google_analytics_events.html" %}` goes:

1. In `freedom_ls/base/templates/_base_interface.html`, as the first thing inside
   `<div id="interface-main">`. A boosted course-player navigation keeps only this region, and htmx
   runs inline scripts in swapped content, so the event travels with the swap.
2. In `freedom_ls/base/templates/_base.html`, directly before `</body>`. This covers every page that
   has no `#interface-main`, such as the allauth pages after sign-up.

The first include to render pops the flags. The second finds none and renders nothing, so an event is
never emitted twice from one response.

Tests:

- `freedom_ls/base/tests/test_google_analytics.py`: recording stores the flag, recording the same
  event twice stores it once, popping returns the flags and empties the session, popping with
  nothing recorded returns `[]`. Use a request with a real session (the test client's, or
  `SessionMiddleware` applied to a `RequestFactory` request).
- `test_context_processors.py`, with `mock_site_context` as in Task 2: with an ID set, a flag put
  in the client session appears as `gtag('event', 'sign_up')` on the next full page and is gone
  from the session afterwards. It
  appears once on a page that extends `_base_interface.html`. With the ID unset, no `gtag('event'`
  renders and the flag is gone from the session. On a token-bearing page nothing renders and the
  flag is still in the session.
- A boosted request (send the `HX-Request` header to a course-player page) still has the event
  script inside the `#interface-main` element of the response.

## Task 5: record the four flags

Each call is one line beside code that already marks the moment. Import
`GoogleAnalyticsEvent` and `record_google_analytics_flag` from
`freedom_ls.base.google_analytics` at module level.

| GA4 event | File | Where |
| --- | --- | --- |
| `SIGN_UP` | `freedom_ls/accounts/allauth_account_adapter.py` | `save_user()`, inside `if commit:`, after `fire_webhook_event("user.registered", …)` |
| `GENERATE_LEAD` | `freedom_ls/course_applications/views.py` | `application_check_answers`, directly after `form_progress.complete()` |
| `GENERATE_LEAD` | `freedom_ls/course_applications/views.py` | `apply`, on the branch where `app.form_progress is None`, before `redirect("course_applications:status", …)` |
| `TUTORIAL_BEGIN` | `freedom_ls/learner_interface/views.py` | `view_course_item`, inside `if course_progress.started_at is None:`, beside the stamp |
| `TUTORIAL_COMPLETE` | `freedom_ls/learner_interface/views.py` | `course_finish`, inside the branch that stamps `completed_time`, after `fire_webhook_event("course.completed", …)` |

For `apply`, split the existing two-line return so the no-form branch reads:

```python
app = _start_application(user, course)
if app.form_progress is not None:
    return redirect(_resume_url(app, app.form_progress))
record_google_analytics_flag(request, GoogleAnalyticsEvent.GENERATE_LEAD)
return redirect("course_applications:status", pk=app.pk)
```

A draft application with a form records nothing until `application_check_answers` completes it.

`accounts/tests/test_account_webhook_events.py` calls `save_user` with `mocker.Mock()` as the
request. A bare `Mock` session does not support `in`, so those two tests need a request with a real
session once `save_user` records a flag. Update them as part of this task.

Tests, one pair per call site, placed beside the existing tests for that view:

- The flag is in the session after the moment happens.
- It is not recorded when the moment does not happen: `save_user(commit=False)`, a second visit to a
  course that already has `started_at`, `course_finish` with outstanding items or with
  `completed_time` already set, `application_check_answers` with unanswered required questions,
  `apply` for a learner who already has an application, and `apply` for a course with an
  application form.

One end-to-end test for `sign_up`, because the flag has to survive allauth's own signup chain: with
a measurement ID set, post the real signup form through the test client, follow the redirect, and
assert `gtag('event', 'sign_up')` is on the page the new user lands on. `save_user()` runs before
allauth touches the session, and mandatory email verification defers login, so this passes today.
The test is there so a later allauth upgrade cannot break it quietly.

## Task 6: CSP

**`config/settings_base.py`**, `SECURE_CSP_REPORT_ONLY`:

- `script-src`: add `https://www.googletagmanager.com` and `https://*.i.posthog.com`.
- `img-src`: add `https://*.google-analytics.com` and `https://www.googletagmanager.com`.
- `connect-src`: add `https://*.google-analytics.com`, `https://*.analytics.google.com`,
  `https://www.googletagmanager.com` and `https://*.i.posthog.com`.

`*.i.posthog.com` covers both the region ingestion host (`us.i.posthog.com`, `eu.i.posthog.com`) and
the assets host the PostHog snippet derives from it (`us-assets.i.posthog.com`). A deployment that
reverse-proxies PostHog through its own host adds that host itself. Leave a short comment above the
dict saying which entries belong to which service.

The policy stays report-only. Moving it to enforcing mode is a separate piece of work.

Test in `freedom_ls/base/tests/test_csp.py`: the report-only header names the GA4 and PostHog hosts
in the directives above.

## Task 8: Google Ads

Added 2026-09-23, after QA of tasks 1 to 7 passed. `idea.md` § Google Ads has the design. Nothing
about the events, their parameters or their call sites changes.

**`freedom_ls/deployment/config.py`**: `GOOGLE_ADS_CONVERSION_ID: str | None` (`default=None`) and
`GOOGLE_ADS_CONVERSION_LABELS: dict[str, str]` (`default={}`) under the GA4 entry.

**`freedom_ls/deployment/google_ads.py`** (new, no model imports, because `settings_base.py`
imports it while settings are still being built):

- `parse_conversion_labels(raw)`: `"sign_up=AbCdEf,course_registered=GhIjKl"` to a dict.
  Whitespace and a trailing comma are tolerated. A pair without `=` or with an empty side raises
  `ImproperlyConfigured`, so a typo fails at boot.
- `conversion_send_to(conversion_id, labels, event_name)`: `"AW-ID/LABEL"` or `None`.

**`config/settings_base.py`**: read both from the environment beside the GA4 ID. `.env.example`
gets both, with the label format shown.

**`freedom_ls/deployment/checks.py`**: `W002`, Ads ID without a GA4 ID (the tag never loads);
`W003`, labels without an Ads ID (no conversion is ever sent). One registered function.

**`freedom_ls/deployment/context_processors.py`**: `google_analytics_config` also returns
`google_ads_conversion_id`, and `google_analytics_events` now pops events with a `send_to` key
attached (`PendingGoogleAnalyticsEvent`). Attached at render time, not stored in the session, so a
label change applies to events already waiting.

**`_base.html`**: after the GA4 config call,
`{% if google_ads_conversion_id %}gtag('config', '…');{% endif %}`. Same block, same gates.

**`partials/google_analytics_events.html`**: each event's script gains
`{% if event.send_to %} gtag('event', 'conversion', {send_to: '…'});{% endif %}` before the
self-removal, so the conversion shares the GA4 event's lifetime.

**CSP** (`SECURE_CSP_REPORT_ONLY`), from Google's tag-platform CSP guide: `script-src` gains
`www.googleadservices.com` and `www.google.com`; `img-src` and `connect-src` gain those plus
`googleads.g.doubleclick.net`, `pagead2.googlesyndication.com` and `www.google.co.za`;
`connect-src` also `ad.doubleclick.net`; `frame-src` gains `www.googletagmanager.com`.

**Privacy policy**: version 1.2. An "Advertising measurement" subsection naming Google Ads, a
purpose line, Google's ads settings as the opt-out, and Google Ads in the sharing list.

**Docs**: `docs/product/deployment.md` gets a Google Ads subsection with both routes and the Ads
account steps.

Tests: `deployment/tests/test_google_ads.py` (new), and additions to `test_config.py`,
`test_checks.py`, `test_context_processors.py` and `base/tests/test_csp.py`. The rendering tests
cover: Ads config after the GA4 one; absent when unset; absent with no GA4 ID; absent on a
token-bearing page; a mapped event's conversion in the same script, once on a `_base_interface`
page and inside `#interface-main` on a boosted request; no conversion for an unmapped event or
without an Ads ID; a label that would close the script element is escaped.
