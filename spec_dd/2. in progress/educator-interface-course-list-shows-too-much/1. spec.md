# Spec: course shares between organisations

Idea: `idea.md`. Decisions taken with the user: `answers.md`. Research: `research_*.md` in this
directory.

## Purpose

An organisation course with `audience: public` is open to every organisation, so every
organisation's educators see it on their Courses page, open its content previews, and register
their own learners and cohorts onto it. Educator registration never consults the course-access
backend, so a paid or application-gated course can be handed out for free by any organisation.

After this work an educator reaches another organisation's course only when that course's owning
organisation has shared it with their organisation in `course.md`, and only as far as the share
allows. A course the organisation already holds a registration for stays visible, without content.
Learner self-join of public courses is unchanged.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| owning organisation | coined | An `Organisation` listed in `Course.organisations` for that course. The code says "organisation course" and "its organisations"; no noun exists for the organisation side. |
| course share | coined | One `CourseShare` row: a course's owning organisation lets one other named organisation `see`, `register` or `preview` that course. Not "grant", which the glossary reserves for role assignments, and not "audience", which `Course.audience` holds. |
| `see` / `register` / `preview` | coined | The three things a course share allows. `register` and `preview` each imply `see`. |

## Scope

In:

- A `shared_with:` front-matter key on `course.md`, loaded into a new `CourseShare` model.
- The educator interface for organisation courses: the Courses list, the course detail page and its
  panels, the content preview actions, the course filters on the cohort and learner lists, and every
  course picker that registers a learner or cohort (single and bulk).
- The registration write gate, so a `register` share lets that organisation hold registrations on
  a course that is not public.
- Author tooling, demo content, product docs and the glossary.

Out:

- Learner-facing behaviour: browsing, the audience rule (`in_audience_expression`), self-join of
  public courses through the course-access backend, and the embed card. All unchanged.
- Courses with no `organisations:`. They keep today's behaviour for educators and learners.
- Seat caps or counts on a `register` share.
- Wildcard shares. Every share names one organisation.
- Badges or columns marking shared courses in the Courses list.

## Decisions

- **No share means hidden.** Every multi-tenant LMS surveyed isolates by default
  (`research_cross_org_course_sharing.md`).
- **Three independent flags, not a ladder.** An owner can allow `register` without `preview`.
- **A `register` share is the licence.** Educator registration through it skips the course's price
  and application gate, which educator registration already does for courses it can reach.
- **The loader writes shares to a table.** `course.md` stays the source of truth. The table lets
  lists and counts apply the rule as a subquery.
- **The learner write gate is widened, never narrowed.** `is_course_open_to_organisation` also
  decides learner self-join (`research_codebase.md` §1); narrowing it would break self-join of
  public courses. The educator rules are new expressions beside it.
- **Superusers follow the same rule** as today (`test_a_superuser_does_not_see_another_organisations_course`).
- **Every denial is a 404**, as `CourseConfig.authorise_instance` already does.

## Requirements

### What each organisation reaches

For an educator acting in organisation O, a course C is:

| C is… | listed and detail page | content preview | in register pickers |
| --- | --- | --- | --- |
| unowned (no `organisations:`) | yes | yes | yes |
| owned by O | yes | yes | yes |
| owned by others, shared with O allowing `preview` | yes | yes | only with `register` |
| owned by others, shared with O allowing `register` | yes | only with `preview` | yes |
| owned by others, shared with O allowing `see` only | yes | no | no |
| owned by others, not shared with O, but O holds a registration on it | yes | no | no |
| owned by others, not shared with O, no registration held by O | no (404) | no (404) | no |

`audience` plays no part in this table. Course visibility (`published`, `hidden`, `coming_soon`)
narrows each column exactly as it does today: listing as in `courses_visible_to`, pickers as in
`registerable_courses`. "O holds a registration" keeps today's meaning: a registration, active or
not, of a cohort or learner visible to the educator in O.

### `CourseShare` model and loader

- New `CourseShare(SiteAwareModel)` in `freedom_ls/content_engine/models/courses.py`: `course` (FK
  `Course`, `related_name="shares"`, cascade), `organisation` (FK `Organisation`,
  `related_name="course_shares"`, cascade), booleans `see`, `register`, `preview`. Constraint
  `unique_course_share_per_organisation` on `(course, organisation)`. Migration via
  `makemigrations`.
- `content_engine/schema.py` `Course`: new optional field `shared_with`, a list of
  `{organisation: str, allow: list[Literal["see", "register", "preview"]]}`. Front matter:

  ```yaml
  organisations:
    - northwind-logistics
  audience: public
  shared_with:
    - organisation: harbour-college
      allow: [register]
  ```

- Load-time errors, each failing the load the way an unknown `organisations:` slug does today:
  `shared_with` on a course with no `organisations:`; an organisation slug unknown on the site
  (reuse `_resolve_course_organisations` in `content_save.py`); an owning organisation listed in
  `shared_with`; the same organisation twice; an empty `allow`.
- `content_save.save_course` adds `shared_with` to `exclude_fields` and replaces the course's
  `CourseShare` rows on every load: rows are written with `see=True` whenever `register` or
  `preview` is set, and a removed entry or key deletes its row.
- `CourseAdmin` (`content_engine/admin.py`) shows the course's shares read-only beside
  `organisation_names`.

### Rules in `freedom_ls/learner_management/queries.py`

- One expression per flag, built on an `Exists` over `CourseShare` for the organisation:
  `visible_to_organisation_expression(organisation)`,
  `registerable_by_organisation_expression(organisation)` and
  `previewable_by_organisation_expression(organisation)`. Each is "unowned, or owned by this
  organisation, or shared with it allowing the flag". Single-course forms go through
  `_course_matches`, as `is_course_open_to_organisation` does.
- `courses_visible_to` replaces `open_to_organisation_expression` with
  `visible_to_organisation_expression`; `held`, the superuser branch and the subquery structure stay.
- `registerable_courses` (and so `registerable_courses_for`, `registerable_courses_for_learner` and
  `CoursePickerMixin`) uses `registerable_by_organisation_expression`. A course reached only through
  a held registration is not registerable.
- `is_course_open_to_organisation` becomes `open_to_organisation_expression | registerable by a
  register share`. `require_course_open_to`, `validate_course_open_to`, the registration models'
  `clean()` and registration rules follow it unchanged.
- `open_to_everyone_expression`, `in_audience_expression` and `is_in_audience` do not change.

### Educator interface (`freedom_ls/educator_interface/views.py`)

- `CourseDataTable` and `CourseConfig.authorise_instance` need no change of their own; they read
  `courses_visible_to`. Reword `CourseDataTable.empty_message` to "Courses your organisation owns or
  that are shared with it will appear here." It must not distinguish "none exist" from "none shared".
- `CourseContentPanel`: when the course is not previewable by the organisation, the outline is not
  rendered and `get_actions` returns no preview actions. The panel body reads: "Content preview isn't
  shared with your organisation."
- `PreviewContentAction` and `PreviewCourseDetailsAction` raise `Http404` when the course is not
  previewable by the organisation, whatever the URL's `item` or `page`.
- `CourseDetailsPanel` and the cohort and learner registration panels are unchanged; their queries
  are already scoped to the organisation.
- `VisibleCourseFilter` and `LearnerCourseFilter` inherit the change through `courses_visible_to`.

## Testing

- **The matrix.** Parametrised over every row of the table above × each surface: the Courses list,
  the detail URL, the content panel, both preview action URLs, the course filter choices, the single
  and bulk register pickers, and a tampered POST naming a course outside the picker. Expected result
  for each cell, 404 included.
- **Write gate.** A `register` share on an `organisation_learners` course lets an educator register
  a cohort and a learner of the shared-with organisation, and model `clean()` accepts the result.
  Without the share it is refused with `COURSE_NOT_OPEN_MESSAGE` as today.
- **Learner side unchanged.** A learner of another organisation still self-joins a public
  organisation course through the course-access backend, gates applied; the course is still in
  their browse list. A learner registered by an educator through a `register` share reaches the
  content (cover both the free backend and `ApplicationCourseAccessBackend`).
- **Revoking a share.** Removing a `shared_with` entry and reloading deletes the `CourseShare` row,
  keeps every registration and progress record, keeps the course listed for the organisation through
  its held registrations, and removes it from the pickers.
- **Loader.** Each load-time error above; `see` implied by `register` and `preview`; replacement on
  reload; demo content loads.
- **Query count.** The Courses list issues the same number of queries for 1 and 10 shared courses.
- **Existing tests.** Tests asserting that another organisation's public course is visible to or
  registerable by educators are amended to the new rule, not deleted.
  `test_a_public_course_of_another_organisation_is_open` stays true: it tests the write gate.

## Open questions

- Q: Should unowned courses (no `organisations:`) that are paid or application-gated also be hidden
  from educators or withheld from registration? → A: No; unowned courses keep today's behaviour.
  (assumed default: the user scoped the change to organisation courses, and an unowned course has no
  owner to share it. Overrule by editing Scope.)
- Q: Once a `register` share is revoked, should the bulk deactivate picker still offer the course so
  educators can deactivate the registrations they hold? → A: No; it keeps sharing
  `registerable_courses`, as it does today for a course that closes. (assumed default: matches
  current behaviour for closed courses. Overrule by editing "Rules in queries.py".)

## Success criteria

- An educator in Harbour College does not see Northwind's public course without a share: list, filter
  and pickers omit it, and its detail and preview URLs return 404.
- With `allow: [register]` they see it, register a cohort onto it, and its preview URLs return 404.
- With `allow: [preview]` they open its content previews and it is absent from the pickers.
- A Harbour College learner still self-joins Northwind's public course from the learner interface.
- A load with an unknown, duplicate or owning organisation in `shared_with` fails with a message
  naming the course file.
- `uv run pytest` passes.
