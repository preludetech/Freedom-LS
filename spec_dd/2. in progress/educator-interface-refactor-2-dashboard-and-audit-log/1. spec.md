# Spec: educator interface refactor 2, dashboard and audit log

## Purpose

The dashboard and audit log areas of `freedom_ls/educator_interface/` move out of the flat `views.py`,
`reporting.py` and `filters.py` into `panels/dashboard/` and `panels/audit_log/`, and their tests move to
`tests/panels/dashboard/` and `tests/panels/audit_log/`. It is a pure move on top of `panels/common/`, as settled
in `idea.md`. `research_codebase.md` holds the current line numbers.

## Scope

In:
- New packages `panels/dashboard/` and `panels/audit_log/` with the modules listed under Requirements, and the
  repointing of every reference to the moved names.
- The test moves, shared test helpers and baseline change listed under Testing.

Out:
- `LearnerHistoryPanel`, `CohortHistoryPanel`, `LearnerCoursesPanel`, the cohort report classes and the learner
  and cohort History tests. Specs 5 and 6 own them. This spec only repoints the subclasses' base-class imports.
- Deleting emptied flat modules, trimming `views.py`, `urls.py`, `templatetags`, `qa_helpers` and the `fls-dev`
  docs, including `claude_plugins/fls-dev/skills/educator-interface/SKILL.md`'s audit filter paths.
  `educator-interface-refactor-7-cleanup` owns those.
- Any behaviour, UI, URL, template path, stored value or app label change. The flat domain modules.
- `tests/playwright/test_audit_log_flow.py` and `tests/playwright/test_dashboard_attention_layout.py`, which stay.

## Decisions

- **No re-export shim, no migration.** None of the moved classes carries `@register_bulk_action`, so no stored
  `BulkActionRun.action_path` changes.
- **An area imports only `panels/common/`, `panel_framework`, the leaf module `educator_interface.avatars` and
  other apps.** It never imports `views`, `reporting`, `filters`, `actions`, `quick_views` or a sibling area.
  Inside `audit_log`, imports run one way: `filters` ← `data_tables` ← `data_table_panels` and `config`, private
  names included. Checked by grep, with no new import-linter contract.
- **Patch strings name the module that looks the name up.** `views.py` keeps importing `HistoryPanel` and
  `TargetedAuditLogEntryTable` for its subclasses, and `reporting.py` keeps importing `learner_avatars`, so a
  stale string on the old module still resolves and patches nothing.
- **Underscore names are not public API.** They keep their spelling, and the upgrade notes say so.

## Requirements

Paths are under `freedom_ls/educator_interface/`. Each name moves byte-for-byte except for its import lines.
String casts such as `cast("OrganisationScopedRequest", ...)` stay quoted. Each new module starts with
`from __future__ import annotations` and declares a sorted `__all__`, following `panels/common/`.

- `test_organisation/mirroring_baseline.txt` loses the `test_dashboard.py` line in the commit that moves the file.
  A test file's module must exist when the file is committed. The `test_dashboard.py` move is a `git mv` with no
  content change in that commit, so git keeps it as a rename; its two repoints follow in the next commit.

## Success criteria

- Over `panels/dashboard/` and `panels/audit_log/`, these greps find nothing:
  - `grep -rnE "freedom_ls\.educator_interface(\.(views|actions|filters|quick_views|reporting)\b| import )"`
  - `grep -rnE "panels\.audit_log"` under `dashboard/`, and `grep -rnE "panels\.dashboard"` under `audit_log/`
  - `grep -rnE "^\s*from \."`
- In `freedom_ls/educator_interface/` outside `tests/`, each moved name has its `class`, `def` or assignment only
  in its new module. The `_cohort_rows` methods in `actions.py` are a different name in a different scope.
- No string or attribute access in the repo outside `spec_dd/` names a moved name on `views`, `reporting` or
  `filters`, apart from the two `views.py` imports.
- `pytest --collect-only -q` collects the same number of tests before and after, and the full suite passes.
- Pointing the `learner_avatars` patch string back at `reporting` makes its dashboard test fail (a one-off manual
  check).
- `manage.py check` passes and `makemigrations --check --dry-run` reports no changes.
- Each new module imports in a fresh interpreter (`python -I -c "import ..."`).
- The mirroring check passes, and `mirroring_baseline.txt` has lost only the `test_dashboard.py` line.
- `git diff main --stat` shows no change under `templates/`, to `urls.py`, or to any migration.
