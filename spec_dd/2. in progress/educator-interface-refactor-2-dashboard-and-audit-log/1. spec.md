# Spec: educator interface refactor 2, dashboard and audit log

## Purpose

The dashboard and audit log areas of `freedom_ls/educator_interface/` move out of the flat `views.py`,
`reporting.py` and `filters.py` into `panels/dashboard/` and `panels/audit_log/`, and their tests move to
`tests/panels/dashboard/` and `tests/panels/audit_log/`. It is a pure move on top of `panels/common/`. The approach
is settled in `idea.md`. `research_codebase.md` holds the current line numbers.

## Scope

In:
- New packages `panels/dashboard/` and `panels/audit_log/` with the modules listed under Requirements.
- Moving the names listed there, and repointing every import, attribute access and patch string that names them.
- Moving their tests, moving the test helpers they share with staying tests into `tests/helpers.py`, and
  deleting the `test_dashboard.py` line from `test_organisation/mirroring_baseline.txt`.

Out:
- `LearnerHistoryPanel`, `CohortHistoryPanel`, `LearnerCoursesPanel`, the cohort report classes and the learner
  and cohort History tests. Specs 5 and 6 own them. This spec only repoints the subclasses' base-class imports.
- Deleting emptied flat modules, trimming `views.py`, `urls.py`, `templatetags`, `qa_helpers` and the `fls-dev`
  docs. `educator-interface-refactor-7-cleanup` owns those, including
  `claude_plugins/fls-dev/skills/educator-interface/SKILL.md:40-41`, which will name the audit filters at their
  old path.
- Any behaviour, UI, URL, template path, stored value or app label change. The flat domain modules.
- `tests/playwright/test_audit_log_flow.py` and `tests/playwright/test_dashboard_attention_layout.py`, which stay.

## Decisions

- **No re-export shim, no migration.** None of the moved classes carries `@register_bulk_action`, so no stored
  `BulkActionRun.action_path` changes.
- **An area imports only `panels/common/`, `panel_framework` and other apps**, never `views`, `reporting`,
  `filters`, `actions`, `quick_views` or a sibling area. Modules inside one area may import each other, private
  names included. Checked by grep, with no new import-linter contract.
- **Patch strings name the module that looks the name up.** `views.py` keeps importing `HistoryPanel` and
  `TargetedAuditLogEntryTable` for its subclasses and `reporting.py` keeps importing `learner_avatars`, so a stale
  string on the old module still resolves and patches nothing. Each one is read and repointed by hand.
- **Moved names keep their spelling**, leading underscores included. Underscore names are not public API, and
  the upgrade notes say so.
- **Both `__init__.py` files are empty.** Each new module declares a sorted `__all__` and starts with
  `from __future__ import annotations`, following `panels/common/`.

## Success criteria

- These greps over `freedom_ls/educator_interface/panels/dashboard/` and `panels/audit_log/` find nothing:
  - `grep -rnE "freedom_ls\.educator_interface(\.(views|actions|filters|quick_views|reporting)\b| import )"`
  - `grep -rnE "panels\.audit_log"` under `dashboard/`, and `grep -rnE "panels\.dashboard"` under `audit_log/`
  - `grep -rnE "^\s*from \."`
- Grepping every moved name finds it defined only in its new module.
- No string or attribute access in the repo names a moved name on `views`, `reporting` or `filters`, outside
  `spec_dd/` and the two `views.py` imports.
- The full suite passes, and `pytest --collect-only -q` collects the same number of tests before and after.
- Making the `learner_avatars` patch string wrong on purpose makes its dashboard test fail.
- `manage.py check` passes and `makemigrations --check --dry-run` reports no changes.
- Each new module, `views`, `reporting` and `filters` imports in a fresh interpreter (`python -I -c "import ..."`).
- The mirroring check passes, and `mirroring_baseline.txt` has lost only the `test_dashboard.py` line.
- `git diff main --stat` shows no change under `templates/`, to `urls.py`, or to any migration.
