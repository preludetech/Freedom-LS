## Slice 3: the courses section is read-only and organisation-scoped

Closes the declared disclosure gap before any new surface is built on it, and supplies
`courses_visible_to` for the cohort list's course filter in Slice 4.

**Behaviour:** an educator sees every published course, plus hidden or coming-soon courses only
through a registration they can see in this organisation. A course outside that set is a 404. The
course page shows registrations with cohort and registration status, and offers no action.

1. `freedom_ls/learner_management/queries.py`:

   ```python
   def courses_visible_to(user: RequestUser, organisation: Organisation) -> QuerySet[Course]:
       """Courses this user may see in this organisation: every published
       course, plus any course a visible cohort or learner holds a
       registration for, active or not. A hidden or coming-soon course
       shows only through such a registration."""
       everything = Course.objects.all()
       resolved = _resolved_or_none(user, everything)
       if resolved is not None:
           return resolved
       # Subqueries, not joins: CourseDataTable annotates Count() over the same
       # relations, and a filter join would narrow those counts.
       through_cohorts = CohortCourseRegistration.objects.filter(
           cohort__in=cohorts_visible_to(user, organisation)
       ).values("course_id")
       through_learners = LearnerCourseRegistration.objects.filter(
           learner__in=learners_visible_to(user, organisation)
       ).values("course_id")
       return everything.filter(
           Q(visibility=CourseVisibility.PUBLISHED)
           | Q(pk__in=through_cohorts)
           | Q(pk__in=through_learners)
       )
   ```

   A superuser sees everything, as `_resolved_or_none` already decides. `Course`,
   `CourseVisibility` and `LearnerCourseRegistration` become runtime imports; `content_engine` is
   already a runtime dependency of `learner_management`.

       """Register, or re-register, the cohort for the course.

## Slice 10: Unregister with confirmation

**Behaviour:** each active registration row offers Unregister. The confirmation says how many
members lose access, who keeps it and why, that progress stays, and that the cohort can be
registered again. Confirming deactivates the registration.

1. `freedom_ls/learner_management/queries.py`:

   ```python
   def members_keeping_access(registration: CohortCourseRegistration) -> QuerySet[Learner]:
       """Active members of the registration's cohort who still reach its
       course once the registration is withdrawn: through an active
       individual registration, or through another cohort whose
       registration grants access."""
       course = registration.course
       other_cohorts = access_granting_cohort_registrations().filter(course=course).exclude(
           pk=registration.pk
       ).values("cohort_id")
       return (
           Learner.objects.filter(
               is_active=True, cohortmembership__cohort_id=registration.cohort_id
           )
           .filter(
               Q(learnercourseregistration__course=course, learnercourseregistration__is_active=True)
               | Q(cohortmembership__cohort_id__in=other_cohorts)
           )
           .select_related("user")
           .distinct()
           .order_by("user__first_name", "user__last_name")
       )
   ```

   Both `learnercourseregistration__` conditions sit in one `Q`, as the access reads require.
2. `freedom_ls/educator_interface/actions.py` `UnregisterCohortFromCourseAction(
   RequiresActiveCohortMixin, PanelAction)`: `label = "Unregister"`, `action_name =
   "unregister"`, `variant = "secondary"`, `capability =
   "freedom_ls_learner_management.change_cohortcourseregistration"`, `trigger_template_name =
   "panel_framework/partials/modal_trigger.html"`, `template_name =
   "educator_interface/modal/unregister_confirmation.html"`.
   - `_registration(ctx)`: read `registration` from `ctx.request.POST` on a submit and
     `ctx.request.GET` otherwise, parse it with `UUID(raw)` and raise `Http404` on `ValueError`
