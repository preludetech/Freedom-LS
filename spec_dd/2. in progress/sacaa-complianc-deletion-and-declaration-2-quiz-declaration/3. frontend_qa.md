# Frontend QA: learners sign a declaration before each quiz attempt

A quiz with `requires_declaration: true` asks the learner to sign a declaration before the first
page of every attempt. They tick a box and type their full name. The system stores the text shown, the
typed name, the time and the IP address, and staff see the record on the form progress record in
the Django admin. Other quizzes and surveys start as they did before.

## Setup

- Start the server with the `Dev server start` command from `.claude/sdd/config.md` on `$PORT`.
- Base URL: `http://127.0.0.1:$PORT`
- Admin login: `demodev@email.com` / `demodev@email.com`
- Django admin: `/admin/`. Form progress records are under Form engine.
- Check each page at 1920x1080, 375x812 and 768x1024 unless a test says otherwise.

### Data needed

Ask the data helper for:

1. **Demo content loaded** through `content_save` on `demo_content`, including the new course
   "Functionality Demo - quiz declaration" (`demo_content/functionality_demo_quiz_declaration/`).
2. **Learner A**, registered on "Functionality Demo - quiz declaration" and on "Functionality Demo
   - shuffled quiz", with no attempts at either. Get learner A's password.
3. **Learner B**, registered on the declaration course, holding an open, unsigned sitting at the
   quiz with its own declaration, created directly (as a sitting from before the author turned the
   declaration on would be), with no answers.
4. **Learner C**, registered on the declaration course, holding a completed, failed, signed
   attempt at the quiz with the default declaration, so its start screen offers "Try Again".

Before starting, open both quiz `form.md` files in the demo course and note the own declaration
text of the first quiz. The second quiz uses the default text from `form_engine/config.py`
`FORM_DECLARATION_DEFAULT_TEXT`.

## Test 1: starting a declaration quiz opens the declaration page

1. Log in as learner A. Open the declaration course and go to "quiz with its own declaration".
2. On the start screen, click "Start Form".

Expect, at each viewport:

- The URL ends in `/declaration`.
- A back link at the top returns to the start screen.
- The page shows, in this order: the quiz title, the lead line "Before you start, read this
  declaration and sign it.", the quiz's own declaration text with its paragraph breaks, a tick box
  labelled "I make this declaration.", a "Full name" field (empty), the helper text "Your name
  is stored with this declaration, the time and your IP address.", and a "Sign and start" button.
- The declaration text is part of the page flow. It has no scroll box of its own, and the page has
  no horizontal scroll at 375 wide.
- "Sign and start" is enabled before anything is filled in.
- The admin shows no form progress record for learner A at this quiz yet.
- No console errors.

## Test 2: an empty or partial signature is refused

On the declaration page from Test 1:

1. Click "Sign and start" with nothing filled in.
2. Tick the box, type only spaces in "Full name", and submit.
3. Untick the box, type a name, and submit.

Expect:

- After step 1: "Tick the box to make the declaration." beside the tick box and "Type your full
  name to sign." beside the name field. Keyboard focus is on the tick box. With keyboard only
  (Tab, Space, typing), the learner can fix both and submit.
- After step 2: only the name error shows, and focus is on the name field.
- After step 3: only the tick-box error shows, and the typed name is still in the field.
- Each response is HTTP 422 (network tab), and the URL is still `/declaration`.
- In the admin there is still no form progress record and no declaration for learner A.

## Test 3: signing starts the attempt on page 1

1. Tick the box, type " Ada Lovelace " (with a leading and a trailing space) and click "Sign and
   start".
2. In another tab, log in as the admin and open learner A's form progress record for this quiz.

Expect:

- The learner lands on page 1 of the quiz (`/fill_form/1`) and sees its questions.
- The admin change page shows one declaration row with the quiz's own text, the typed name with
  both spaces kept, a time, and an IP address (`127.0.0.1`). It has no add row and no delete box,
  and none of the fields can be edited.

## Test 4: the signature is asked once per attempt and again on every new attempt

1. As learner A, answer page 1, leave the quiz by its exit, and come back to the start screen.
   Click "Continue Form".
2. Finish the attempt. On the start screen, click "Try Again" if offered, or log in as learner C
   and click "Try Again" on "quiz with the default declaration".

Expect:

- Step 1: "Continue Form" goes straight back to the quiz page. No declaration page shows.
- Step 2: "Try Again" opens the declaration page again. For learner C it shows the default text.
  Signing opens page 1, and the admin shows a second declaration, on the new form progress record.

## Test 5: an unsigned sitting cannot be continued

1. Log in as learner B. Open "quiz with its own declaration". The start screen offers "Continue
   Form". Click it.
2. Type the quiz's `.../fill_form/1` URL directly.
3. Sign the declaration.

Expect:

- Steps 1 and 2 both land on the declaration page, not on a quiz page.
- After signing, the learner is on page 1, and the admin shows the same form progress record as
  before (same start time), now with a declaration.

## Test 6: other quizzes are unchanged

1. As learner A, open "Functionality Demo - shuffled quiz" and click "Start Form".
2. Open any survey in the demo content and start it.

Expect: both go straight to the first page. No declaration page shows.

## Test 7: the back link and repeat submits

1. As learner C (after Test 4), or a fresh learner, open a declaration page. Click the back link.
2. Open the declaration page again. Fill it in correctly and double-click "Sign and start".

Expect:

- Step 1 returns to the start screen, and the admin shows no new form progress record.
- Step 2 lands on page 1 once, and the admin shows one new form progress record with exactly one
  declaration.
