# Spec: conditional pages and questions

## Purpose

Every sitting of a `Form` sees every `FormPage`, `FormQuestion` and `FormContent`, and a required
question anywhere blocks submission whether or not it applied to that learner. A form author needs to
gate a page, a question or a content block on an answer given earlier, so that, for example, an
applicant whose employer is not paying never sees, or is held up by, the page of employer questions.
The approach is settled in `idea.md`; this spec fixes what has to be true when it ships.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| condition | coined | The rule on a `FormPage`, `FormQuestion` or `FormContent` that decides whether it is on a sitting's path. Authored as the `when` key; stored as `condition_option`. |
| path | coined | The `FormPage`s, `FormQuestion`s and `FormContent` blocks whose conditions hold for a sitting, in authored order. Never a field or module name (`BaseContent.file_path` owns the word). |
| on-path / off-path | coined | Whether an item is on the sitting's path. |
| not asked | coined | An off-path `FormQuestion` in a sitting, as shown to an admin or in an export. Distinct from "Not answered" (on-path, no answer). |

## Scope

In:

- A `when` key on page, question and content YAML sections, and an author-chosen `slug` on
  `FormQuestion`, validated at import.
- One server-side evaluator that decides the path from the sitting's stored answers, used by both
  runners (`form_fill_page` and `application_form_page`), required validation, answer storage,
  navigation, resume, progress counts, check-your-answers, scoring, the admin answers view and
  exports.
- Off-path answers kept during a sitting and deleted at `FormProgress.complete()`.
- The path frozen on the `FormProgress` at completion.
- Per-sitting `max_score` for `CATEGORY_VALUE_SUM`.

Out:

- `QUIZ` forms: a condition on one is an import error.
- Same-page reveal of any kind, client-side rule evaluation, HTMX or Alpine reveal.
- Visible-but-disabled questions.
- Boolean combinators (`all`/`any`), negation, numeric or text comparisons.
- Conditions on anything outside the sitting's own answers.
- `compliance-form-randomization`: this spec designs nothing for it.
- A path changed after submission (the reviewer re-routing case in
  `spec_dd/1. next/multi-step-course-applications/idea.md`).
- An author tool for previewing or enumerating paths.
- `freedom_ls/reports/`: it reads `scores["max_score"]` only for `QUIZ` forms
  (`reports/gather.py` `_score_attempt`), so nothing there changes.

## Decisions

- **The source of a condition is a `multiple_choice`, `dropdown` or `checkboxes` question**, so every
  literal can be checked against `QuestionOption.value` at import.
- **The condition is stored as a FK to the `QuestionOption` it tests**, not as a slug and a string.
  Options keep their uuid across re-imports (`save_form_question`), so the FK survives a slug rename,
  and one test ("is this option among the source answer's `selected_options`") serves single-select
  and checkbox sources alike.
- **No separate cycle check.** The earlier-page rule makes a cycle impossible.
- **An unanswered source, or an off-path source, makes the condition false.**
- **A page whose condition holds but whose items are all off-path is off-path.** A page with no items
  at all is treated as today.
- **The URL page number stays the authored page index; what the learner reads is the position on the
  path.** "Page 2 of 3" counts on-path pages; `/page/4/` still means the fourth authored page.
- **`question_number()` is unchanged**, a stable ordinal in the full authored form, so `data-testid`s
  and "Question N needs an answer" keep their identity.
- **In-progress sittings are evaluated against the current form**, so an author's edit changes their
  path. Completed sittings read their frozen path.
- **The course start screen keeps whole-form counts** (`learner_interface/views.py`, the
  `question_count`/`page_count` context). It describes the form before any answer exists.
- **Completed sittings from before this feature have `asked = None` and are read as "every item
  asked"**, which is what they were.

## Requirements

### Authoring schema (`freedom_ls/form_engine/schema.py`)

- `FormQuestion` gains `slug: str | None`, matching `^[a-z0-9_]+$`.
- A new `Condition` model, `extra="forbid"`:

  ```yaml
  when:
    question: employer_pays   # a FormQuestion slug in the same form
    equals: "yes"             # multiple_choice / dropdown source
  # or
  when:
    question: dietary_needs
    includes: vegetarian      # checkboxes source
  ```

  Exactly one of `equals` / `includes`. An `int` literal is coerced to `str` (the same normalisation
  `save_form_question` applies to `QuestionOption.value`). A `bool` literal is rejected with a message
  telling the author to quote it, since unquoted `yes`/`no`/`on` parse as booleans.
- `FormPage`, `FormQuestion` and `FormContent` gain `when: Condition | None = None`. A file without
  `when` or `slug` validates exactly as today.

### Import validation (`freedom_ls/content_engine/validate.py`)

A new cross-file pass beside `validate_category_references`, run over each form's parsed pages in the
order `content_save` assigns `FormPage.order` (sorted file paths, so `10. x.yaml` before
`2. y.yaml`). It reports every error in one run, each naming the file, the target and the `when` key,
and rejects:

1. a duplicate `slug` within a form, naming both files;
2. a `when.question` that matches no slug in the form, listing the form's slugs;
3. a source on the same page as the target or a later one;
4. a source whose type is not `multiple_choice`, `dropdown` or `checkboxes`;
5. `equals` on a `checkboxes` source, or `includes` on any other;
6. a literal matching no `QuestionOption.value` on the source, listing the valid values;
7. any `when` in a form whose `strategy` is `QUIZ`.

The same checks go into the offline validator in `claude_plugins/fls-content/validate/`
(`schema.py`, `validate.py`), whose `extra="forbid"` mirror otherwise rejects the new keys.

### Models (`freedom_ls/form_engine/models.py`, migration `0009`+)

- `FormQuestion.slug`: `CharField(blank=True, default="")`. Uniqueness within a form is an import
  check (a constraint cannot span `form_page__form`).
- `FormPage`, `FormQuestion`, `FormContent` each gain
  `condition_option = ForeignKey(QuestionOption, null=True, blank=True, on_delete=PROTECT)`, with
  `related_name` `gated_pages`, `gated_questions`, `gated_content`.
- `FormProgress.asked`: `JSONField(null=True, blank=True)`, written once by `complete()`:

  ```json
  {"pages": ["<FormPage uuid>", ...], "questions": ["<FormQuestion uuid>", ...]}
  ```

  `null` while the sitting is in progress and for sittings completed before this feature.

### Saving (`freedom_ls/content_engine/management/commands/content_save.py`)

- `save_form_question` writes `slug`. A section's `when` resolves to the `QuestionOption` of the
  slugged question in the same form whose `value` equals the literal. The earlier-page rule
  guarantees the source is already saved.
- A section without `when` writes `condition_option=None` explicitly. `save_with_uuid` dumps with
  `exclude_none=True`, so without that a removed `when` would stay in force (the same trap
  `content_save.py` handles for `Course.application_form`).
- A test proves a hand-written `when` mapping survives `update_file_with_uuid`'s re-dump.

### The evaluator (new `freedom_ls/form_engine/conditions.py`)

- `compute_path(form: Form, answers: Mapping[UUID, QuestionAnswer]) -> SittingPath`, answers keyed
  by question id, walks pages in order. An item is on-path
  when its page is on-path (for questions and content) and it has no `condition_option`, or its
  `condition_option.question` is on-path and that question's `QuestionAnswer.selected_options`
  contains `condition_option`. A page is on-path when its own condition holds and, if it has items,
  at least one is on-path.
- `sitting_path(form_progress: FormProgress) -> SittingPath` returns the frozen path when `asked` is
  set, every item when the sitting is complete with `asked` null, and `compute_path` otherwise.
- `SittingPath` is a frozen dataclass holding the ordered on-path pages and the on-path question and
  content ids, with what callers need: whether a page or question is on it, a page's on-path
  questions and children, a page's position and the count of on-path pages, and the next and previous
  on-path page after a given one.
- A whole sitting's path is computed in a bounded number of queries (prefetch pages, children,
  `condition_option`, and answers with `selected_options`), not one per item.

### Paging and page flow (`freedom_ls/form_engine/paging.py`, `page_flow.py`, `queries.py`)

- `page_flow.submit_page` passes only the page's on-path questions to `unanswered_required_on_page`
  and `FormProgress.save_answers`. A value in the POST for an off-path question is never stored, and
  its existing row is left alone (`save_answers` deletes the row of any question it is handed blank).
- `unanswered_required_in_form` checks on-path questions only, recomputing the path server-side.
- `CurrentPage`/`page_context`: `next_page_url`, `previous_page_url`, `has_next_page` and `is_last`
  come from the path. Requesting an off-path page number redirects to the next on-path page after it,
  or, when none remains, to where the last page's submit would go (completion in the course player,
  check-your-answers in the application shell).
- `resume_page_number` (and `FormProgress.get_current_page_number`, which feeds it): the candidate
  it computes today, moved to the first on-path page at or after it, else the last on-path page.
  `page_accessibility_limit` uses the same rule, so the resume page and the page-jump ceiling agree.
- `build_page_links` emits on-path pages only, labelled by position on the path; `is_accessible`
  keeps its current meaning for pages ahead of the learner.
- `answered_counts`: `answered_count` counts answers to on-path questions; `total_question_count`
  counts on-path questions.
- `FormPage.children()` callers that render a page show on-path children only.

### File-upload endpoints (`freedom_ls/form_engine/views.py`)

`partial_question_file_upload` and `partial_question_file_remove` 404 for an off-path question
(`_owned_file_question` checks the path as well as the form).

### Completion (`FormProgress.complete()`)

In one transaction: compute the path from the answers, delete `QuestionAnswer` rows for off-path
questions, write `asked`, then score. Stored files of deleted `QuestionAnswerFile` rows are removed
only after the transaction commits. `form_attempt_completed` is sent after commit, as today. A
`submit_on_exit` sitting completed through `form_submit_and_exit` records its path the same way: an
on-path question it never reached is asked and unanswered.

### Scoring (`FormProgress.score_category_value_sum`)

Walks on-path questions only, so each category's `max_score` is this sitting's. A category or
sub-category with no on-path question is absent from `scores`. The templates that render the tree
(`course_form_complete.html`, `partials/form_progress_scores.html`) already skip absent keys.
`compute_quiz_scores` and the other `QUIZ` paths are untouched.

### Course player (`freedom_ls/learner_interface/`)

- `form_fill_page` advances to the next on-path page and completes on the last on-path page.
- `course_form_page.html`: "Page N of M", the progress bar, the sr-only `<h1>`, the `aria-live`
  announcement and the page dots use path position and on-path page count. The answered tally and the
  submit dialog's totals use the path-aware `answered_counts`.

### Application shell (`freedom_ls/course_applications/views.py` and templates)

- `application_form_page` follows the path for next, previous and the off-path redirect, including
  the read-only render of a submitted sitting (which reads the frozen path).
- `application_check_answers` shows on-path pages and questions only. A page with no on-path rows has
  no card. The untitled-page fallback "Page N" uses path position.
- Edit with `?return=check`: after an accepted POST, redirect to the first on-path page after the
  edited one on which no on-path question has an answer, carrying `return=check`; when there is none,
  to check-your-answers. Saving on that page applies the same rule, so the learner is walked through
  every newly applicable page before returning.
- `_resume_url` uses the path-aware resume. A sitting with no on-path pages goes to
  check-your-answers, as a zero-page form does today.
- Submit from check-your-answers runs `unanswered_required_in_form` (path-aware) then `complete()`.

### Admin answers view and exports

- `queries.answer_groups` (admin `_answers.html`) shows an off-path question as a muted "Not asked",
  keeping "Not answered" for an on-path question without an answer. In-progress sittings use the live
  path; completed ones use `sitting_path`. An in-progress off-path answer row shows as "Not asked", not
  as its value.
- `exports.answer_cell` / `answer_columns` (and `course_applications/resources.py` through them) write
  `Not asked` for an off-path question; an on-path unanswered question stays an empty cell.

### Dev tools and QA helpers

- `dev_tools/management/commands/danger_content_delete.py` and
  `danger_clear_all_course_progress.py` still run against forms with conditions (`condition_option`
  is `PROTECT`, so gated items or their FKs go before the options they reference).
- `qa_helpers` commands that complete a sitting without `complete()` either go through it or set
  `asked`, so QA data matches real data.

### Demo content

`demo_content/functionality_demo_application_form` gains the employer case: a `multiple_choice`
question with a `slug` on page 1 ("Is your employer paying for this course?") and a page of employer
questions gated on it with `when`, including at least one required question. Tests and `qa_helpers`
that count its questions or pages are updated with it.

## Testing

Unit tests, by area:

- **Schema:** `when` with `equals` and with `includes`; both or neither rejected; unknown key
  rejected; int literal coerced; bool literal rejected with the quote hint; `slug` format.
- **Import validation:** one test per rejection 1–7, each asserting the message names the file,
  target and key (and lists slugs or option values where stated); several errors in one form reported
  together; `10.` vs `2.` file ordering decides "earlier"; existing demo forms import unchanged.
- **Saving:** `when` resolves to the right `QuestionOption`; removing `when` clears
  `condition_option`; re-import keeps the FK; a `when` block round-trips through the uuid write-back.
- **Evaluator:** page, question and content gated true and false; checkbox membership with one and
  several selections; unanswered source is false; chained condition whose source is itself off-path is
  false; page with all items off-path is off-path; frozen `asked` wins over current answers and over a
  later condition edit; complete legacy sitting with `asked` null returns every item; query count is
  bounded.
- **Storage and validation:** a POST carrying a value for an off-path question stores nothing and
  leaves the existing row; an off-path required question blocks neither the page nor the form;
  flipping a trigger and back keeps the earlier answers.
- **Completion:** off-path rows deleted, on-path kept; `asked` written; off-path file answer's stored
  object removed after commit and kept on rollback; `submit_on_exit` partial sitting records its path.
- **Scoring:** `max_score` counts on-path questions only; a wholly off-path category is absent; two
  sittings of one form with different paths score against different denominators.
- **Navigation:** next/previous/last skip off-path pages; off-path page URL redirects; resume never
  lands on an off-path page; page links omit off-path pages and are labelled by position;
  `answered_counts` uses the path; `question_number()` is unchanged by the path.
- **File endpoints:** upload and remove 404 for an off-path question.
- **Check-your-answers:** off-path cards absent; an edit that makes a page applicable routes through
  it with `return=check` then back; an edit that removes a page returns straight to review.
- **Admin and export:** "Not asked" vs "Not answered" for completed and in-progress sittings;
  export cells `Not asked` vs empty.
- **Offline validator:** `claude_plugins/fls-content/validate/tests/test_validator.py` covers the
  new keys and the seven rejections.

Playwright, on the demo application form: answer "no" and never see the employer page, submit with
its required question unanswered; answer "yes", fill the page, go back and answer "no", reach review
without the employer card, switch to "yes" from review and be walked through the employer page with
the earlier answers still filled in. In the course player, "Page N of M" reflects the path.

## Success criteria

- A form directory with no `when` or `slug` imports and behaves exactly as before.
- Each of the seven invalid conditions fails import with a message naming file, target and key.
- On the demo application form, an applicant who answers "no" submits without seeing the employer
  page, and the completed sitting has no `QuestionAnswer` for any employer question.
- No POST, including a crafted one, stores an answer to an off-path question.
- An off-path required question never blocks a page or submission.
- A completed sitting's `asked` is set, and editing a condition afterwards changes neither its
  check-your-answers page nor its admin view.
- A `CATEGORY_VALUE_SUM` sitting's `max_score` excludes off-path questions.
- Resume, page links, "Page N of M" and answered counts never refer to an off-path page.
- The admin answers view and the export distinguish "Not asked" from "Not answered".
- A `when` on a `QUIZ` form fails import.
