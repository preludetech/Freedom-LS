# Implementation plan: the About you page

Source: `1b. spec.md` in this directory, which builds on `1. spec.md` (implemented on this branch
through `2. plan.md`).

Code snippets below are shapes, not finished files: they omit imports and the implementer adds
them, with full type hints on every function and no `Any`. Comments and docstrings in the snippets
are written to be copied as they are. Nothing else in this document is: never copy a sentence that
names a slice, or says "as today" or "unchanged", into code.

Vocabulary is the spec's: the **About you page** is the fixed first page of an application, owned
by `course_applications`, asking for the applicant's name and email. It is not a `FormPage`.
**Unclaimed**, **claim**, **handoff** and **sitting** (`FormProgress`) keep their meanings. The
check page is **check-your-answers**; the About you block on it is the **About you card**; the
blocks for form pages are the **page sections**. "A form with no pages" is the spec's phrase.

## Slice 1: the application records the applicant's name

**Behaviour:** `CourseApplication` has `first_name` and `last_name`; existing claimed rows take the
owner's names; a signed-in applicant's new application copies the account's names; the admin shows
and searches them.

@property

Rewrite the model docstring's paragraph on unclaimed applications so it describes the present:
an anonymous applicant types their name and email before any other row exists, so every

`uv run manage.py makemigrations course_applications` for the schema migration (0006), then a data
migration `0007_backfill_application_names.py` copying `0005`'s shape:

```python
def backfill_names(apps: Apps, schema_editor: BaseDatabaseSchemaEditor) -> None:
    """Claimed rows take their owner's names, so the admin can show a name
    without reading the user for every application."""
    application = apps.get_model("freedom_ls_course_applications", "CourseApplication")
    user = apps.get_model(settings.AUTH_USER_MODEL)
    owner = user.objects.filter(pk=OuterRef("user_id"))
    application.objects.filter(user__isnull=False).update(
        first_name=Subquery(owner.values("first_name")[:1]),
        last_name=Subquery(owner.values("last_name")[:1]),
    )
```

Reverse is `RunPython.noop`. Then `uv run manage.py migrate`.

## Slice 2: the claim decides by submission, and a claimed draft takes the account's details

**Behaviour:** an unsubmitted draft is claimed on session possession whatever email it carries, and
takes the account's email and names. A submitted application still needs the verified-address
match and keeps the typed details. Nothing writes to `User`. This lands before any view stores a
typed email on a draft, so the claim never treats such a draft as a mismatch.

### `claims.py`

```python
# in _claim_one, after the collision check:
if not application.is_submitted:
    # A draft is still being written in this browser, so possession of the
    # session is the whole credential, and the account's details replace
    # whatever was typed: the decision goes to the account's address.
    _take_account_details(application, user)
elif not _has_verified_address(user, application.email):
    return "mismatched", pk, sitting_pk
return (*_attach(application, user), sitting_pk)
```

```python
def _take_account_details(application: CourseApplication, user: User) -> None:
    application.email = user.email
    application.first_name = user.first_name
    application.last_name = user.last_name


def _attach(application: CourseApplication, user: User) -> tuple[ClaimOutcome, str]:
    """Set the owner, inside a savepoint so a lost race is a collision, not an error.

    A submitted application keeps the details it was sent with: they are the
    record of what was submitted, and the address already matched a verified one.
    """
    application.user = user
    ... save(update_fields=["user", "email", "first_name", "last_name", "updated_at"]) and
        the sitting's user, as the function does now ...
```

`is_submitted` reads `form_progress`, which `_claim_one` already `select_related`s. Rewrite the
`claim_unclaimed_applications` docstring's middle sentence: "An unsubmitted draft is still being
written in this browser, so possession of the session that created it is the whole credential."

## Slice 3: a form question renders through a shared field shell and text input

**Behaviour:** `question.html` and `inputs/text_input.html` draw their markup through two new
cotton components that take plain values, so the About you page can draw its fields through the
same components. Nothing user-visible changes. This groundwork sits here because the next slice
needs it and no single slice can own it.

### `freedom_ls/form_engine/templates/cotton/field-shell.html` (new, `<c-field-shell>`)

```html
<c-vars legend="" number="" testid_key="" :required="False" error="" error_id="" class="" />
{% comment %}
The fieldset every form field sits in: legend with an optional number, the
required marker, the input, and the error line. A field with no number is one
that is not a form question, so it never claims a question number. The `hint`
slot sits between the legend and the input; `after_error` sits after the error
line, for a message a script reveals.
{% endcomment %}
<fieldset class="space-y-3 border-0 p-0 {{ class }}" {{ attrs }}>
    {% comment %}
    (keep question.html's legend comment about the inline last paragraph here)
    {% endcomment %}
    <legend class="font-semibold text-on-surface w-full float-left px-0 [&>p:last-of-type]:inline">
        {% if number %}
            <span class="float-left mr-1" data-testid="question-number-{{ testid_key }}">{{ number }}.</span>
        {% endif %}
        {{ legend }}{% if required %}&nbsp;<span class="text-error" data-testid="required-indicator-{{ testid_key }}" aria-hidden="true">*</span><span class="sr-only">(required)</span>{% endif %}
    </legend>
    {% if hint %}{{ hint }}{% endif %}
    <div class="space-y-2 clear-both">
        {{ slot }}
    </div>
    {% if error %}
        <p class="text-sm text-error" id="{{ error_id }}">
            <span class="sr-only">Error: </span>{{ error }}

    {% endif %}

</fieldset>
```

`legend` is passed with the `:` prefix so `question.rendered_question` arrives as the safe HTML it

### `form_engine/inputs/text_input.html`

```html
{% with answer=existing_answers|get_dict_item:question.id %}
<c-text-input type="{{ input_type }}"
              inputmode="{{ input_mode }}"
              id="question_{{ question.id }}"
              name="question_{{ question.id }}"
              :label="question.rendered_question"
              value="{% if rejected %}{{ rejected.text }}{% else %}{{ answer.text_answer }}{% endif %}"
              :required="question.required"
              :disabled="read_only"
              :invalid="rejected"
              :min="question.min" :max="question.max" :step="question.number_step"
              error_id="question_{{ question.id }}_error" />
{% endwith %}
```

`value` is a quoted attribute because it needs template logic; `:invalid="rejected"` is truthy
exactly when a rejected answer exists. `read_only` is absent from a context that never set it (the
`_render` helper in the template tests passes none), and an unresolvable `:` attribute falls back
to the component's default, which is the bool `False`. The one difference from the current markup
is that a rejected answer with empty text no longer emits `value=""`; an empty answer is never
rejected (it is unanswered), so no rendered page changes.

## Slice 4: an anonymous applicant to a form course starts on About you

**Behaviour:** the apply URL renders About you for an anonymous visitor on a form course; nothing
exists until a valid POST, which creates the sitting and the application and lands on page 1 (or
check-your-answers for a form with no pages). About you can be revisited at its own URL, edited,
read once submitted; a claimed application is sent away from it. The form pages' nav lists About
you first and page 1's Previous links to it. Check-your-answers opens with the About you card and
has no email field; the anonymous submit completes the sitting and hands off without reading the
POST. The browser journey proves it end to end.

### `ApplicantDetailsForm` (`forms.py`, beside `ApplicantEmailForm`, which Slice 6 deletes)

```python
DETAIL_FIELDS = ("first_name", "last_name", "email")


class ApplicantDetailsForm(HoneypotFormMixin, forms.Form):
    """The details the About you page asks for.

    `ask_for` limits the form to the details still needed: a signed-in
    applicant is only asked for what the account lacks. Whether a first name
    is required follows the site's signup rule, so an application never
    demands more than signup does.
    """

    honeypot_context_label = "Application"
    honeypot_error_message = _(... the wording ApplicantEmailForm carries ...)

    first_name = forms.CharField(
        max_length=200, required=False, label="First name",
        widget=forms.TextInput(attrs={"autocomplete": "given-name"}),
    )
    last_name = forms.CharField(
        max_length=200, required=False, label="Last name (optional)",
        widget=forms.TextInput(attrs={"autocomplete": "family-name"}),
    )
    email = forms.EmailField(
        label="Email address", widget=forms.EmailInput(attrs={"autocomplete": "email"})
    )

    def __init__(self, *args: object, ask_for: tuple[str, ...] = DETAIL_FIELDS, **kwargs: object) -> None:
        super().__init__(*args, **kwargs)
        for name in DETAIL_FIELDS:
            if name not in ask_for:
                del self.fields[name]
        if "first_name" in self.fields and not self._first_name_required():
            self.fields["first_name"].label = "First name (optional)"
        elif "first_name" in self.fields:
            self.fields["first_name"].required = True

    def _first_name_required(self) -> bool:
        return get_effective_require_name(get_signup_policy_for_request(_get_request_or_none()))

    def clean_email(self) -> str:
        """Addresses are matched case-insensitively at claim, so the stored form is lowercase."""
        ...

    @property
    def details(self) -> dict[str, str]:
        """The cleaned values of the details asked for, ready to set on an application."""
        return {name: self.cleaned_data[name] for name in DETAIL_FIELDS if name in self.fields}
```

`CharField` strips by default. `_get_request_or_none` is the accounts helper the honeypot mixin
already uses; outside a request the policy is `None` and the rule falls back to `REQUIRE_NAME`,
the same as signup.

### Nav entries (`form_engine/paging.py`, then `views.py`)

In `paging.py`, give the nav entry a type and split the entry-building out of `build_page_links`
so the About you view can build entries for a form no sitting exists for yet:

```python
@dataclass(frozen=True, slots=True)
class PageLink:
    """One entry of the page-jump nav."""

    number: int
    title: str
    url: str
    is_current: bool
    is_accessible: bool


def page_link_entries(
    pages: list[FormPage], current_page_number: int, limit: int, url_for_page: Callable[[int], str]
) -> list[PageLink]:
    """One entry per page, in page order; pages past `limit` are not accessible."""
    return [PageLink(number, page.title, url_for_page(number), number == current_page_number, number <= limit)
            for number, page in enumerate(pages, start=1)]


def build_page_links(form, form_progress, current_page_number, url_for_page) -> list[PageLink]:
    pages = list(form.pages.all())
    limit = max(_resume_page_number(form_progress, pages), current_page_number)
    return page_link_entries(pages, current_page_number, limit, url_for_page)
```

The template reads `page.number` and friends the same way for a dataclass as for a dict. The
three `build_page_links` tests in `test_paging.py` switch from `link["is_accessible"]` to
`link.is_accessible`. `build_page_links` still accepts `FormProgress | None` until Slice 5.

ABOUT_YOU_TITLE = "About you"

def _with_about_you_entry(page_links: list[PageLink], *, url: str, is_current: bool) -> list[PageLink]:

### Rendering helper and the apply flow (`views.py`)

```python
def _render_about_you(
    request: HttpRequest,
    course: Course,
    details_form: ApplicantDetailsForm,
    *,
    application: CourseApplication | None,
    form_progress: FormProgress | None,
    read_only: bool = False,
    return_to_check: bool = False,
    is_unclaimed: bool = True,
) -> HttpResponse:
    """Draw About you at the status its submission earned.

    With no application yet, the form pages are listed but none is reachable.
    """
    form = course.application_form
    if application is None or form_progress is None:
        entries = page_link_entries(list(form.pages.all()) if form else [], 0, 0, lambda number: "")
        about_you_url = ""
        check_answers_url = ""
    else:
        entries = build_page_links(form, form_progress, 0, lambda number: _page_url(application, number))
        about_you_url = _about_you_url(application)
        check_answers_url = reverse("course_applications:check_answers", kwargs={"pk": application.pk})
    if return_to_check:
        submit_label = "Save and return to your answers"
    else:
        submit_label = "Next" if form is not None else "Submit application"
    refused = details_form.is_bound and not details_form.is_valid()
    submission = PageSubmission(
        required_answers_error=(
            " ".join(details_form.non_field_errors()) or "Check the details below."
        ) if refused else ""
    )
    context = {
        "application": application,
        "course": course,
        "details_form": details_form,
        "page_heading": ABOUT_YOU_TITLE,
        "page_links": _with_about_you_entry(entries, url=about_you_url, is_current=True),
        "read_only": read_only,
        "return_to_check": return_to_check,
        "check_answers_url": check_answers_url,
        "previous_page_url": None,
        # About you is always followed by a page or by check-your-answers, so
        # the read-only page never offers the last page's "Your answers" link.
        "has_next_page": True,
        "submit_label": submit_label,
        "privacy_url": _privacy_url(request),
        "is_unclaimed": is_unclaimed,
        "session_lifetime": _session_lifetime(),
        **{key: getattr(submission, key) for key in ("required_answers_error", "rejected_answers_error")},
    }
    return render_form_page(request, "course_applications/about_you.html", context, submission)

@never_cache_same_origin
def application_about_you(request: HttpRequest, pk: UUID) -> HttpResponse:
    """The About you page of an application that already exists.

    Only an unclaimed application shows it: a claimed application's details
    are the account's, so there is nothing here for its owner to edit.
    """
    app, form, form_progress = _application_for_request(request, pk)
    if app.is_claimed:
        return _landing_for(app)
    read_only = app.is_submitted
    if read_only and request.method == "POST":
        return _redirect_after_submission(request, app)
    return_to_check = request.GET.get("return") == RETURN_TO_CHECK
    details_form = ApplicantDetailsForm(
        request.POST if request.method == "POST" else None,
        initial={"first_name": app.first_name, "last_name": app.last_name, "email": app.email},
    )
    if request.method == "POST" and details_form.is_valid():
        for name, value in details_form.details.items():
            setattr(app, name, value)
        app.save(update_fields=[*details_form.details, "updated_at"])
        if return_to_check:
            return redirect("course_applications:check_answers", pk=app.pk)
        return redirect(_resume_url(app, form_progress, page_number=1))
    return _render_about_you(
        request, app.course, details_form,
        application=app, form_progress=form_progress,
        read_only=read_only, return_to_check=return_to_check,
    )
```

## Slice 8: a signed-in applicant is asked only for what the account lacks

**Behaviour:** a signed-in applicant whose account has everything required never sees About you.
One missing a required first name sees About you with only that field; a valid POST saves it to the
account and continues as the signed-in apply does.

### `views.py`

```python
def _account_lacks_required_name(request: HttpRequest, user: User) -> bool:
    """Whether About you has to ask a signed-in applicant for a first name.

    Only a required field is asked for: a blank optional name never is, and
    the account always has an email.
    """
    return get_effective_require_name(get_signup_policy_for_request(request)) and not user.first_name
```

In `apply`, the coming-soon redirect stays where it is; the block after it becomes:

```python
if _account_lacks_required_name(request, user):
    return _signed_in_about_you(request, user, course)
return _apply_signed_in(request, user, course)
```

`_apply_signed_in(request, user, course)` is the current tail of `apply` from
`if course.application_form is not None or request.method == "POST":` to the `apply.html` render.

```python
def _signed_in_about_you(request: HttpRequest, user: User, course: Course) -> HttpResponse:
    details_form = ApplicantDetailsForm(
        request.POST if request.method == "POST" else None, ask_for=("first_name",)
    )
    if request.method == "POST" and details_form.is_valid():
        user.first_name = details_form.details["first_name"]
        user.save(update_fields=["first_name"])
        return _apply_signed_in(request, user, course)
    return _render_about_you(
        request, course, details_form, application=None, form_progress=None, is_unclaimed=False
    )
```

`_apply_signed_in` on a no-form course with `request.method == "POST"` creates and submits the
application, so the About you POST on a no-form course is the submission, as the button says.
