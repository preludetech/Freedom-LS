# Frontend QA: the About you page

An anonymous applicant now starts on a fixed **About you** page asking for first name, last name
and email. Submitting it creates the unclaimed application and its sitting, so every form page
after it (including a page with a file question) has a sitting behind it. Check-your-answers shows
an About you card instead of an email field, and the handoff prefills signup's names as well as the
email. A signed-in applicant sees About you only when the account lacks a required first name. A
claimed unsubmitted draft takes the account's details; a claimed submitted application keeps what
was typed. This run walks the anonymous journey on a form course, a no-form course and a page-less
form, the revisit and read-only states, the claim rules, the signed-in branch, the admin, and the
form-engine pages that share the extracted field markup.

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever
this document writes `<PORT>`. Shell variables do not survive between tool calls.

"A fresh browser" means a new Playwright browser context with no cookies. "The same browser" means
the context that holds the application's session cookie.

The three QA viewports are 1280 px, 768 px and 390 px wide. Everything is run at 1280 unless a
step says otherwise.

## §0 Setup

### 0.1 Server

1. `.claude/ds/scripts/find_available_port.sh`: note the number and use it literally from here on.
2. Start `uv run python manage.py runserver <PORT>` backgrounded, as its own call.
3. Open `http://127.0.0.1:<PORT>/` and confirm `#debug-branch-badge` names the
   `allow-course-apply-anon` branch. If it names another branch, another server holds the port; go
   back to step 1.
4. Signup confirmation mail lands in Mailpit at `http://localhost:8025`. Open it once to check it
   is up.

### 0.2 Seed data

Missing data is created through the `fls-dev:qa-data-helper` agent, never by hand.

1. **Demo content loaded.** `uv run python manage.py content_save demo_content DemoDev`. This
   loads "Functionality Demo - Application gated course" (*the form course*) and its three-page
   application form. After this work, page 1 of that form is titled "Your background" and asks no
   name or email question.
2. **Superuser:** `demodev@email.com`, password `demodev@email.com` (from
   `.claude/fls-dev/config.md`).
3. **The no-form course.** `uv run python manage.py qa_create_application_docs_scenario` creates
   an application-gated course naming no form, slug `advanced-product-analytics-masterclass`
   (*the no-form course*).
4. **Edge courses.** `uv run python manage.py qa_create_anon_apply_edge_courses` creates "QA
   page-one file course" (*the page-one-file course*: one page with a required "Your name" and a
   required "Upload your ID"), "QA page-less course" (*the page-less course*: a form with no
   pages) and "QA hidden gated course".
5. **Two verified learners with no applications:**
   `uv run python manage.py qa_create_clean_applicant --email qa.anon.a@email.com` and the same
   for `qa.anon.b@email.com`. Password equals the email. Through the data helper, give
   `qa.anon.a@email.com` the first name "Alex" and last name "Anon", and leave
   `qa.anon.b@email.com` with an empty first name and last name.
6. **The DemoDev `SiteSignupPolicy`** has `allow_signups=True` and `require_name=True`. §3 and §6
   flip `require_name` and flip it back through the data helper.
7. **A PNG to upload.** Any PNG under 1 MB with real pixel content, saved as `id-scan.png` in the
   scratch directory.
8. **Fresh addresses.** Each test that signs up needs an address no account holds. Use
   `qa-about-<n>@example.com` with a new `<n>` per test, and note which were used.

Between sections, unclaimed applications are removed through the admin (open the row, "Delete"),
never by database command.

## §1 The anonymous form journey

### 1.1 "Apply now" opens About you without creating anything

1. In a fresh browser, open `http://127.0.0.1:<PORT>/courses/`, click the form course, then
   "Apply now".
2. **Verify:** the URL is `/applications/apply/<slug>/`. Above the heading: "Application for
   Functionality Demo - Application gated course". The heading is "About you".
3. **Verify:** the info callout "This application is saved in this browser only, for up to 14
   days. Submit it to keep it." is shown (14 is `SESSION_COOKIE_AGE` in days in dev).
4. **Verify:** the page nav shows four entries: "1" highlighted as current, then "2", "3", "4"
   greyed and not clickable. Hovering "2" shows the title "Your background".
5. **Verify:** three fields, in order: "First name" with a red asterisk, "Last name (optional)"
   with no asterisk, "Email address" with an asterisk. Each is a fieldset with a bold legend and a
   full-width bordered input, visually the same as a short-text question on a form page. No field
   carries a number.
6. **Verify:** below the email field, the statement "We use this address to link your application
   to your account and to send your decision..." with the "Read our privacy policy." link.
7. **Verify:** one button, "Next", on the right; no "Previous".
8. In another browser, sign in as `demodev@email.com`, open
   `http://127.0.0.1:<PORT>/admin/freedom_ls_course_applications/courseapplication/`.
   **Verify:** no new row for the form course.

### 1.2 A refused About you creates nothing and keeps what was typed

1. In the fresh browser, type "Lovelace" into "Last name (optional)", leave the other two blank,
   press "Next".
2. **Verify:** the response is 422 (network log), still at the apply URL. A "Missing answers"
   callout at the top reads "Check the details below." Under "First name" and "Email address" an
   error line in red starting with the (screen-reader) "Error:" prefix; the two inputs carry
   `aria-invalid="true"`. "Lovelace" is still in the last-name field.
3. Type `not-an-email` into "Email address" and press "Next". **Verify:** 422 again, the email
   error reads "Enter a valid email address."
4. **Verify** in the admin: still no row.

### 1.3 A valid About you creates the draft and lands on page 1

1. Fill "First name" `Ada`, "Last name (optional)" `Lovelace`, "Email address"
   `QA-About-1@Example.com` (mixed case on purpose). Press "Next".
2. **Verify:** the URL is `/applications/application/<uuid>/page/1/`, heading "Your background".
   The browser-only callout is still shown.
3. **Verify:** the nav now shows "1" (About you) clickable, "2" current, "3" and "4" not
   reachable. The questions on this page are numbered from 1 (the first question is "1.", not
   "4."), and the page has no name or email question.
4. **Verify:** the button row has "Previous" on the left and "Next" on the right. Click
   "Previous". **Verify:** the URL is `/applications/application/<uuid>/about-you/`, the fields
   show "Ada", "Lovelace" and `qa-about-1@example.com` (lowercased), the nav shows "1" current.
5. **Verify** in the admin: one row for the form course with Applicant `qa-about-1@example.com`,
   "Applicant name" `Ada Lovelace`, "Claimed" unticked, "Submitted" unticked.

### 1.4 Editing About you returns to page 1, and a refused edit keeps the page

1. On About you (same browser), change "First name" to `Augusta` and press "Next".
   **Verify:** you land on page 1 (`/page/1/`).
2. Click "1" in the nav to return. Clear "Email address" and press "Next". **Verify:** 422, the
   error line under the email field, "Augusta" still in the first-name field. Put the address back
   and press "Next".

### 1.5 A file question works straight after About you

1. In a fresh browser, open the page-one-file course and click "Apply now". Fill About you (`Grace`,
   `Hopper`, `qa-about-2@example.com`), press "Next".
2. **Verify:** page 1 shows "Your name" and a live file picker for "Upload your ID", with no
   "Save this page to attach a file." sentence and no "Your answers are saved" callout.
3. Choose `id-scan.png`. **Verify:** the widget swaps to show the file name and size with a
   "Remove" button, without a page reload.
4. Fill "Your name" and press "Next". **Verify:** check-your-answers opens with the file listed.
   Leave this browser open for §2.3.

### 1.6 Check your answers shows the About you card and no email field

1. Back in the first browser (Ada), fill page 1 (every required question), "Next" through pages 2
   and 3 (attach `id-scan.png` on "Supporting documents"), and reach "Check your answers".
2. **Verify:** the first card is titled "About you" with an "Edit" button; it lists "Name:
   Augusta Lovelace" and "Email address: qa-about-1@example.com". The page cards follow, titled
   "Your background", "Supporting documents", "Availability", each with its own "Edit".
3. **Verify:** the page has no email input and no "Where should we send your decision?" label;
   the only control in the form is "Submit application".
4. Click the About you card's "Edit". **Verify:** the About you URL carries `?return=check`; the
   button row shows "Back to your answers" on the left and "Save and return to your answers" on
   the right. Change "First name" back to `Ada`, press the save button. **Verify:** you are back
   on check-your-answers and the card reads "Ada Lovelace".
5. Click "Edit" again, clear the email, press save. **Verify:** 422, the URL still carries
   `?return=check`, and "Back to your answers" is still offered. Restore the address and save.

### 1.7 Submit hands off to signup with the names prefilled

1. Press "Submit application".
2. **Verify:** the browser lands on the signup page. The URL carries
   `email=qa-about-1%40example.com`, `first_name=Ada`, `last_name=Lovelace` and `next=`.
3. **Verify:** the "Email" field reads `qa-about-1@example.com`, "First name" reads `Ada`, "Last
   name" reads `Lovelace`. The toast says the application for the course has been sent.
4. **Verify** in the admin: the row is now "Submitted" ticked, still unclaimed, name
   `Ada Lovelace`.

### 1.8 A posted signup value wins over the query string

1. On that signup page, change "First name" to `Grace`, leave the password blank, press "Create
   account". **Verify:** the page re-renders with the password error and "First name" still reads
   `Grace`, not `Ada`.
2. Now sign up for real with `qa-about-1@example.com`, first name `Grace`, a password. Confirm the
   address through the Mailpit link in the same browser.
3. **Verify:** the claim landing says "Your application for ... is now on your dashboard".
   Open the application's "Check your answers" from the dashboard. **Verify:** the About you card
   still reads "Ada Lovelace" and `qa-about-1@example.com` (a submitted application keeps what was
   typed), and the card has no "Edit" button. Open `/accounts/profile/`. **Verify:** the account's
   first name is `Grace` (the claim never changed the account).

### 1.9 About you is read-only once submitted, and redirects once claimed

1. Before §1.8 step 2 (do this between 1.7 and 1.8, in the same browser): open the About you URL
   noted in §1.3 directly. **Verify:** the three fields are disabled, the page says "This
   application has been submitted and can no longer be changed.", and there is no "Next" or
   "Submit" button.
2. After §1.8 step 3 (claimed): open the same About you URL. **Verify:** it redirects to the
   application's status page.
3. In a fresh browser, open that About you URL. **Verify:** 404.

### 1.10 Apply again while holding an unsubmitted draft resumes it

1. In a fresh browser, start the form course, submit About you (`qa-about-3@example.com`), reach
   page 1. Then open the course page and click "Apply now" again.
2. **Verify:** you land on page 1 of the same application (same uuid), not on a new About you,
   and the admin shows one row for that address.
3. Press the browser Back button until the About you page shows, and press "Next" again.
   **Verify:** no second row is created (the admin still shows one row for `qa-about-3`).

## §3 Claim rules

### 3.1 An unsubmitted draft claimed on login takes the account's details

1. In a fresh browser, start the form course and submit About you as `Typed Name`,
   `qa-about-6@example.com`. Reach page 1 and stop.
2. In the same browser, log in as `qa.anon.a@email.com` (first name Alex Anon).
3. **Verify:** the claim landing resumes the draft (page 1 of the same uuid). Open
   check-your-answers. **Verify:** the About you card reads "Alex Anon" and `qa.anon.a@email.com`,
   with no "Edit" button. The admin row shows name `Alex Anon` and the account's address.
4. Open `/accounts/profile/` as this user. **Verify:** the name is still Alex Anon.

### 3.2 A submitted application needs the verified address and keeps the typed details

1. In a fresh browser, apply to the no-form course as `Other Person`, `qa-about-7@example.com`
   and submit. On the signup page, switch to "Log in" and log in as `qa.anon.b@email.com`.
2. **Verify:** the mismatch page says the application was made with another address. The admin
   row is still unclaimed with name `Other Person`.
3. Through the data helper, add `qa-about-7@example.com` as a verified address on
   `qa.anon.b@email.com`, then open `/applications/claim/` in the same browser. **Verify:** the
   application is claimed; its status page opens; the admin row shows name `Other Person` and
   `qa-about-7@example.com` (typed details kept). The account's first name stays empty.

## §4 The signed-in applicant

### 4.1 A complete account never sees About you

1. In a fresh browser, log in as `qa.anon.a@email.com` (Alex Anon; `require_name` is on).
   Open the form course, "Apply now".
2. **Verify:** page 1 ("Your background") opens directly, with no About you entry in the nav
   (entries "1", "2", "3" only) and no browser-only callout. Page 1 has no "Previous".
3. Open check-your-answers via the nav's last page. **Verify:** the About you card reads
   "Alex Anon" and `qa.anon.a@email.com` with no "Edit" button; the page has no email input.

### 4.2 An account missing a required first name is asked for it only

1. In a fresh browser, log in as `qa.anon.b@email.com` (empty name). Open the form course,
   "Apply now".
2. **Verify:** About you with a single field, "First name" with an asterisk. No last-name field,
   no email field, no browser-only callout, nav "1" current with "2", "3", "4" unreachable.
3. Press "Next" blank. **Verify:** 422 with the error under "First name". No application in the
   admin for this user.
4. Fill `Bea`, press "Next". **Verify:** page 1 opens with the nav showing only the form pages
   ("1" current, no About you entry). The admin row shows name `Bea`, claimed. Open
   `/accounts/profile/`. **Verify:** first name `Bea`.
5. Repeat step 1 with `qa.anon.b@email.com` for the no-form course after the data helper clears
   the name again. **Verify:** About you shows the single first-name field and a "Submit
   application" button; a valid submit lands on the application's status page.

### 4.3 An optional blank name is never asked for

1. Through the data helper set the DemoDev `SiteSignupPolicy` `require_name=False` and clear
   `qa.anon.b@email.com`'s first name again; remove their applications through the admin.
2. Logged in as `qa.anon.b@email.com`, "Apply now" on the form course. **Verify:** page 1
   directly.
3. In a fresh browser, anonymous, "Apply now" on the form course. **Verify:** the first field is
   labelled "First name (optional)" with no asterisk; pressing "Next" with only an email filled
   is accepted. Afterwards set `require_name=True` back.
