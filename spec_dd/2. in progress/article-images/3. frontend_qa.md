# Frontend QA: Article images

Browser checks for an article's image: on the blog index, on the article page, in the social
meta tags and in article cards inside content. Run them after the implementation plan is complete.

## 0. Setup

1. Pick a port and start the dev server:
   ```bash
   PORT=$(.claude/ds/scripts/find_available_port.sh)
   uv run python manage.py runserver $PORT
   ```
   The base URL is `http://127.0.0.1:$PORT`.
2. Load the demo content into the dev site (the site is named `DemoDev`):
   ```bash
   uv run manage.py content_save ./demo_content DemoDev
   ```
   Then run `git status --short demo_content/` and confirm it prints nothing. A rewritten file
   means a uuid was written back, which is a bug: the committed demo articles already carry theirs.
3. Admin login (from `.claude/fls-dev/config.md`): email `demodev@email.com`, password
   `demodev@email.com`. Only test 6 needs it. Every other test runs logged out: open a private
   window or log out first.
4. Demo articles (file stems under `demo_content/functionality_demo_articles/`):

   | Slug | Image |
   | --- | --- |
   | `getting-started-with-articles` | `backyard-drone-flight.jpg` (a photograph) |
   | `unsigned-update` | `landscape.svg` |
   | `undated-notes` | none |
   | `hidden-draft` | none, and hidden |

   To fill a three-column row on the index, create two more published articles with images using
   the `fls-dev:qa-data-helper` agent, or load a scratch content directory with `content_save`.
5. Viewports: phone 375 × 812, tablet 768 × 1024, desktop 1280 × 800.
6. **Design reference.** Compare the blog index against `design_screenshots/Blog__1280.png`
   (desktop) and `design_screenshots/Blog__375.png` (phone). The article page has no screenshot.
   Compare layout, density and hierarchy only: colours, fonts, the site header and the card
   border come from the active theme. The design draws things this feature does not build, and
   they must be absent: tag filters, tag labels on cards, reading time, the featured article above
   the grid, the intro sentence under the heading, author avatars, "Copy link", "Filed under" and
   "More articles".

## 1. The blog index grid

Design screenshots: `design_screenshots/Blog__1280.png`, `design_screenshots/Blog__375.png`.

1. Go to `/articles/` logged out at desktop.
2. Expect the H1 "Articles" and a grid of cards, three per row, newest `published_on` first. The
   hidden draft is absent.
3. "Getting started with articles" and "Unsigned update" show a thumbnail above the title, 16:10,
   cropped (the drone photograph is not squashed). "Undated notes" has no thumbnail and starts with
   its title.
4. All cards in a row are the same height. The card without an image is as tall as its neighbours,
   with its text at the top.
5. Under each thumbnail: title, description, byline, in that order. Bylines are unchanged from
   before: author · date, author only for "Undated notes", date only for "Unsigned update".
6. Hover a card: the title link does not change the layout. Click the thumbnail: the article page
   opens (the whole card is one link). Click the description: same.
7. Reload, Tab to a card: a focus ring surrounds the whole card, including the thumbnail, and is
   not clipped.
8. Tablet: two cards per row, same checks. Phone: one card per row, no horizontal scroll, each
   thumbnail spans the card width.
9. Empty state: in a scratch site with no articles, or after
   `uv run python manage.py danger_content_delete --yes`, `/articles/` still shows the "No articles
   yet" paragraph with no grid. Reload the demo content afterwards.

Design checklist (desktop, `Blog__1280.png`):

- [ ] The index H1 is the blog name.
- [ ] Published articles render as cards in a three-column grid at 1280.
- [ ] Each card with an image shows a 16:10 thumbnail above the title.
- [ ] The title, description and byline appear in that order under the thumbnail.
- [ ] Every card in a row is the same height, including a card with no image.
- [ ] No tag, reading time, filter row or featured article is rendered.

Design checklist (phone, `Blog__375.png`):

- [ ] The grid is one column at 375 with no horizontal scroll.
- [ ] Each thumbnail spans the card's width at 16:10.
- [ ] The title, description and byline wrap and do not overflow the card.

## 3. Social meta tags

1. Fetch the page source of `/articles/getting-started-with-articles/`:
   ```bash
   curl -s http://127.0.0.1:$PORT/articles/getting-started-with-articles/ | grep -E 'og:image|twitter:card'
   ```
2. Expect `<meta property="og:image" content="http://127.0.0.1:<port>/media/...">`: an absolute
   URL starting with the scheme and host, not a bare `/media/` path. Expect
   `<meta property="og:image:alt" ...>` with the alt text, and
   `<meta name="twitter:card" content="summary_large_image" />`.
3. Open the `og:image` URL in the browser: the image loads.
4. Run the same `curl` for `/articles/undated-notes/`: no `og:image` line, no `og:image:alt`,
   and `twitter:card` is `summary`.
5. Run it for `/courses/` and the site root: nothing about `og:image` changed there; the Twitter
   card is still `summary`.

## 5. The validator and the loader

1. Copy `demo_content/functionality_demo_articles/` to a scratch directory outside the repo and
   change `getting-started-with-articles.md`'s `image` to `images/missing.jpg`. Run:
   ```bash
   uv run manage.py content_validate <scratch dir>
   ```
   Expect a failure that names the article file, the path `images/missing.jpg` and the `image`
   field, in the same block shape as a broken widget path.
2. In the scratch copy, remove the `image_alt` line but keep `image`. Validate: expect a failure
   that says the image has no alt text and that `image_alt: ""` marks it decorative.
3. Set `image_alt: ""` instead. Validate: passes.
4. Add `category: something` to an article. Validate: still rejected as not an article field.
5. Remove both `image` and `image_alt` from `unsigned-update.md` in the real demo directory, load
   with `content_save`, and open `/articles/unsigned-update/`: no header image, and the index card
   has no thumbnail. Restore the file with `git checkout demo_content/` and load again: the image is
   back.

## 6. Admin and side effects

1. Log in as the admin and open the Articles admin list. Opening "Getting started with articles"
   shows the stored `image` path and `image_alt`. Nothing else in the form changed.
2. Open a course topic that uses `c-picture` and `c-card` with images (the
   `functionality_demo_content_widgets` course): they render as before.
3. Open the sitemap at `/sitemap.xml`: the article entries are unchanged.
