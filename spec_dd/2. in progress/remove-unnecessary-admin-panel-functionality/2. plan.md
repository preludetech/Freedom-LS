# Plan: remove unnecessary admin panel functionality

Spec: `1. spec.md` in this directory. No model, migration, URL or settings change.

## Skills to use

- `fls-dev:admin-interface` with `ds:admin-interface` (read `admin_unfold.md` and `admin_guardian.md`,
  never `admin_standard.md`): every admin edit. Admins extend `SiteAwareModelAdmin`; inlines extend
  unfold's `TabularInline`/`StackedInline` and keep `site` out through `fields` or `exclude`.
  `ds:admin-interface` says to prefer `autocomplete_fields`. Here they go because their target admin
  is gone (system checks `admin.E039`/`admin.E040`). `raw_id_fields` serves the same purpose of not
  loading every option, so do not restore autocomplete.
- `fls-dev:testing` with `ds:testing`: test layout (tests mirror modules; deleting a module deletes
  its mirror test), `mock_site_context` on every test that touches a site-aware model, factories,
  `assign_perm` for permissions, no markers (portable tests). `ds:testing` forbids render-only admin
  tests, so every changelist-opens-with-200 check also asserts something about the page (the filter
  is there, or the rows it filters to).
  The project prunes slow tests, so parametrise over admins rather than writing one test per
  combination.
- `fls-dev:multi-tenant`: site-aware factories and `mock_site_context` in the new tests.
- `sdd:planning-references-in-code`: every comment, docstring and test name states the fact. None
  cites the spec, the plan, a slice or a removed class "per spec".
- `fls-dev:domain-glossary`: names in test names and comments.

`CLAUDE.md`: never drop a `TODO` or `@claude` comment. The only open one in a deleted file is the
`@claude:` comment on `CohortAdmin`, which Slice 8 moves.

## Groundwork shared by every slice

### `test_organisation/` baselines

Deleting a test file or a module can leave a stale line in `test_organisation/mirroring_baseline.txt`
or `test_organisation/import_baseline.txt`. The `test-mirroring`, `lint-imports` and `app-map-fresh`
pre-commit hooks fail on a stale line. In each slice that deletes a file:

1. Delete the lines naming the deleted file from `mirroring_baseline.txt` and `import_baseline.txt`.
2. Run `uv run python claude_plugins/django-stack/scripts/generate_app_map.py` (no `--check`). It
   rewrites `docs/app_structure.md` and `test_organisation/import_contracts.toml` when an app edge
   disappears, such as `content_engine → form_engine` once `content_engine/admin.py` is gone.
3. Run `uv run pre-commit run --all-files` with only those three hooks in mind; fix what they name.

Because of this, every slice lists `test_organisation/` and `docs/app_structure.md` under
`Touches:`, and so every slice builds on the one before it.

Every slice ends with `uv run manage.py check` passing. Django runs the system checks when the test
run starts, so an `admin.E039`/`admin.E040` left by a slice fails the whole suite.

### Test shape

`ds:testing` asks for one request per test and no `if`, `for` or `try` in a test body. The
view-only checks in Slices 1 and 3 are therefore one test per behaviour, each parametrised over the
admins (or inline classes) it covers. The behaviours: changelist 200; change page 200 with no
`name="_save"` button; add GET 403; change POST 403 with the row unchanged; delete POST 403 with the
row still there; `delete_selected` not in `get_actions`; a changelist POST with
`action=delete_selected` returns the changelist and leaves the row.

### The admin registry invariant test

`freedom_ls/base/tests/invariants/test_admin_registry.py` (new; `base/tests/invariants/` is an
existing mirroring exemption for repo-wide checks). It looks models up by label with
`django.apps.apps.get_model`, so `base`'s tests import no other app, as `import_contracts.toml`
requires:

```python
import pytest

from django.apps import apps
from django.contrib import admin
from django.core.checks import run_checks

# Content comes from content_save only, so no content model has an admin page.
# Every model in the app is listed, so a content model added later is covered too.
CONTENT_MODELS = [
    ("freedom_ls_content_engine", model.__name__)
    for model in apps.get_app_config("freedom_ls_content_engine").get_models()
]

REMOVED_ADMIN_MODELS = [*CONTENT_MODELS]


@pytest.mark.parametrize(("app_label", "model_name"), REMOVED_ADMIN_MODELS)
def test_the_model_has_no_admin(app_label: str, model_name: str) -> None:
    assert not admin.site.is_registered(apps.get_model(app_label, model_name))


def test_the_system_checks_raise_no_admin_error() -> None:
    errors = [message for message in run_checks() if message.id.startswith("admin.")]
    assert errors == []
```

Slice 5 creates it. Slice 6 adds a `FORM_DEFINITION_MODELS` list of explicit
`("freedom_ls_form_engine", "<Model>")` tuples, and Slice 8 adds a `LEARNER_MANAGEMENT_MODELS`
list of `("freedom_ls_learner_management", "<Model>")` tuples. Each is spread into
`REMOVED_ADMIN_MODELS`. Those two are explicit, not looped: the answer admins in `form_engine`
stay registered, and a future `learner_management` model may well get an admin.
