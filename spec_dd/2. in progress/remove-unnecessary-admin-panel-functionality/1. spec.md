# Spec: remove unnecessary admin panel functionality

Source: `idea.md`, `answers.md`. Research: `research_*.md` in this directory.

## Purpose

The unfold admin exposes content and learner management that belong elsewhere. Content comes from
`content_save` only and must not be edited or viewed in the admin. Learners, cohorts and course
registrations are managed in the educator interface, where only authorised organisation users can
act. This work removes those admins and makes the progress and form-answer admins that stay
view-only.

## Scope

In:

- Remove every admin in `freedom_ls/content_engine/admin.py`.
- Remove the form-definition admins in `freedom_ls/form_engine/admin.py`.
- Remove every admin in `freedom_ls/learner_management/admin.py`, and every seam other apps use to
  put things on the Learner, Cohort, registration or Organisation pages from it.
- Make the learner progress admins (`TopicProgress`, `CourseProgress`, `CourseFormAttempt`) and the
  form answer admins (`FormProgress`, `QuestionAnswer`, `QuestionAnswerFile`) view-only.
- Repair every surviving admin that depends on a removed one.

Out:

- No model, migration, URL or settings change.
- No setting to turn the removed admins back on. A downstream project that wants one registers its
  own.
- No replacement screen for anything that was admin-only (see Decisions).
- `UserAdmin`, `OrganisationAdmin`, the deadline config admins, `CoursePauseAdmin`,
  `DeadlineExtensionAdmin`, and every other admin not named here keep their current behaviour,
  apart from the picker repairs below.

## Decisions

- **Delete the registrations, never `admin.site.unregister`.** Unregister is for third-party models;
  FLS owns these.
- **Deadline overrides, pause, resume and extend leave the admin with no replacement.**
  `deadlines-6-educator-management` adds the educator screens. Until it lands, nobody can edit
  these.
- **Learner HR attributes lose their only edit screen.** A follow-up spec gives them an
  educator-interface screen.
- **Learner creation needs no replacement.** Authorised organisation users already add learners in
  the educator interface.
- **Course price and Article deletion leave the admin.** Both come from `content_save`.
- **`ORGANISATION_SUMMARIES` and `OrganisationAdmin.inlines` stay as extension points.** They are
  `OrganisationAdmin`'s own seams, and `hr_attributes` still adds `OrganisationHRSettingsInline`.
  Only `learner_management`'s contributions go.

## Requirements

### View-only admin mixin (`freedom_ls/site_aware_models/admin.py`)

- Move `ReadOnlyAdminMixin` from `freedom_ls/referral_tracking/admin.py` to
  `site_aware_models/admin.py` and import it from there in `referral_tracking`.
- It returns False from `has_add_permission`, `has_change_permission` and `has_delete_permission`
  for every user, superusers included. With delete denied, Django drops the `delete_selected` bulk
  action.

### content_engine

- Delete `freedom_ls/content_engine/admin.py`, including `FormQuestionWithSectionsAdmin` and its
  `unregister`/`register` of `FormQuestion`.
- Delete `FileAdminForm` from `freedom_ls/content_engine/forms.py`, and the file if nothing else
  lives in it.
- Delete `ContentTagListFilter` from `freedom_ls/content_base/admin_filters.py`. It has no user left.

### form_engine (`freedom_ls/form_engine/admin.py`)

- Delete `QuestionOptionAdmin`, `FormContentAdmin`, `FormQuestionAdmin`, `FormPageAdmin`,
  `FormAdmin`, their inlines (`QuestionOptionInline`, `FormContentInline`, `FormQuestionInline`,
  `FormPageInline`) and `_condition_label`.
- `FormProgressAdmin`, `QuestionAnswerAdmin` and `QuestionAnswerFileAdmin` take
  `ReadOnlyAdminMixin`.
  - Drop their `autocomplete_fields` and the add-only branch of `FormProgressAdmin.get_readonly_fields`.
  - Replace `("form", AutocompleteSelectFilter)` with `("form", RelatedDropdownFilter)`.
  - The answers change view (`answers_change_form.html`, `answers_context`) and the
    `QuestionAnswerFileAdmin` download URL keep working.
- `answers_context`, `applicant_label` and `FormProgressCompletionFilter` stay;
  `course_applications/admin.py` imports `answers_context`.

### learner_management

- Delete `freedom_ls/learner_management/admin.py`. With it go `LEARNER_SUMMARIES`,
  `LEARNER_SUMMARIES_FIELD`, `ScopedLearnerAutocompleteSelect`, `narrow_learners`, every inline,
  `OrganisationCohortInline`, `OrganisationLearnerInline`, `organisation_learner_search_link` and
  the lines that add them to `OrganisationAdmin.inlines` and `ORGANISATION_SUMMARIES`.
- Delete the admin forms in `freedom_ls/learner_management/forms.py` (`CohortAdminForm`,
  `LearnerAdminForm`, `LearnerCourseRegistrationAdminForm`, `CohortCourseRegistrationAdminForm`),
  and the file if nothing else lives in it.
- Move the `@claude:` comment on `CohortAdmin` (the unfold and guardian pairing check) to
  `OrganisationAdmin` in `freedom_ls/organisations/admin.py`. It also uses
  `GuardedSiteAwareModelAdmin`, so the check is still open.
- Delete `freedom_ls/qa_helpers/management/commands/qa_create_org_cohort_pagination.py`. It exists
  to QA `OrganisationCohortInline`.

### Seam contributors

- `freedom_ls/hr_attributes/admin.py`: delete the `LearnerAdmin` import, `LearnerHRAttributesInline`,
  `_picker_querysets`, `_PICKER_MODELS` and the `LearnerAdmin.inlines` line. `ListEntryAdmin` and
  `OrganisationHRSettingsInline` stay.
- `freedom_ls/learner_progress/admin.py`: delete the `learner_management.admin` import,
  `LearnerCourseProgressInline`, `_LEARNER_RECORD_LINKS`, `learner_progress_links` and the lines
  that wire them into `LearnerAdmin` and `LEARNER_SUMMARIES`.
- `freedom_ls/registration_rules/admin.py`: delete the `LearnerCourseRegistrationAdmin` import, the
  `registration_rule` helper and the fieldset it adds.
- `freedom_ls/deadlines/admin.py`: delete the `CohortCourseRegistrationAdmin` import and the
  `CohortDeadlineOverrideInline` wiring (see deadlines below).

### learner_progress (`freedom_ls/learner_progress/admin.py`)

- `TopicProgressAdmin`, `CourseProgressAdmin` and `CourseFormAttemptAdmin` take
  `ReadOnlyAdminMixin`. Their inlines deny add, change and delete too.
- Drop their `autocomplete_fields`.
- Replace each `AutocompleteSelectFilter` whose target admin is removed (learner, topic, course,
  form) with `RelatedDropdownFilter`.

### deadlines (`freedom_ls/deadlines/admin.py`, `freedom_ls/deadlines/admin_views.py`)

- Delete `DeadlineOverrideInline`, `CohortDeadlineOverrideInline`, `LearnerDeadlineOverrideInline`
  and their wiring.
- Delete `pause_course_action`, `resume_course_action`, `extend_deadline_action`, `_get_urls`,
  `_get_actions_detail` and the `setattr(CourseProgressAdmin, ...)` lines for them.
- Delete `pause_view`, `resume_view` and `extend_view`, with `admin_views.py` if it is left empty.
- Keep the read-only `CoursePauseInline`, `DeadlineExtensionInline`, `effective_deadlines`,
  `effective_deadline_policy` and the "Deadlines" fieldset on `CourseProgressAdmin`.

### Pickers that point at removed admins

- Admin system checks `admin.E039` and `admin.E040` fail at startup for every `autocomplete_fields`
  entry whose target admin is gone. Drop each entry and let the field render as a plain select,
  which `SiteAwareModelAdmin` already narrows to the site:
  - `deadlines/admin.py`: `CourseDeadlineConfigAdmin`, `CohortDeadlineConfigAdmin`,
    `CohortCourseRegistrationDeadlineConfigAdmin`, `LearnerCourseRegistrationDeadlineConfigAdmin`
  - `messaging_policy/admin.py`: `CohortMessagingConfigAdmin`, `LearnerMessagingConfigAdmin`,
    `LearnerCourseRegistrationMessagingConfigAdmin`, `CohortCourseRegistrationMessagingConfigAdmin`
  - `course_interest/admin.py`: `course`
  - `registration_rules/admin.py`: `course`
- `AutocompleteSelectFilter` only breaks at runtime, when the changelist opens. Replace each one
  whose target admin is gone with `RelatedDropdownFilter`:
  - `deadlines/admin.py`: `CoursePauseAdmin`, `DeadlineExtensionAdmin` (`course_progress__course`)
  - `course_applications/admin.py`: both `("course", AutocompleteSelectFilter)` entries

### User erasure (`USER_ERASURE_CASCADE_MODELS`, `freedom_ls/accounts/admin.py`)

`UserAdmin.get_deleted_objects` refuses to erase a user when a registered admin denies delete on a
cascaded row, unless that row's model is in `USER_ERASURE_CASCADE_MODELS`.

- Add `TopicProgress`, `CourseProgress` and `CourseFormAttempt` to the set from
  `learner_progress/admin.py`.
- Add `FormProgress`, `QuestionAnswer` and `QuestionAnswerFile` from `form_engine/admin.py`.
- `Learner`'s entry goes with `learner_management/admin.py`. An unregistered model never blocks
  erasure.

## Testing

- Every removed model is unregistered: a test parametrised over the content_engine models, the five
  form-definition models, `Learner`, `Cohort`, `LearnerCourseRegistration` and
  `CohortCourseRegistration` asserts `admin.site.is_registered(Model)` is False.
- `django.core.checks.run_checks()` returns no `admin.*` error.
- For each of the six view-only admins, as a superuser:
  - the changelist and change page return 200 and show no save button;
  - add, change POST and delete return 403 or redirect without writing;
  - `delete_selected` is not in `get_actions`, and a bulk-delete POST deletes nothing;
  - every inline denies add, change and delete.
- Every changelist that had an `AutocompleteSelectFilter` replaced opens with 200.
- A superuser can still erase a user who has course progress and form answers, from `UserAdmin`.
- The `QuestionAnswerFileAdmin` download URL still serves the file.
- The answers change view still renders each question's text.
- Tests that cover removed code are deleted. Tests that reverse a removed admin URL are rewritten
  against a surviving page or deleted. `research_codebase.md` section 5 lists them; the
  `site_aware_models/tests/test_admin.py` guardian tests move from `Cohort` to `Organisation`.

## Open questions

- Q: How should pickers whose target admin is gone be repaired? → A: Drop the `autocomplete_fields`
  entry so it renders as a plain select, and swap `AutocompleteSelectFilter` for
  `RelatedDropdownFilter` (assumed default: both already appear in this codebase and need no
  registered target. Overrule by editing "Pickers that point at removed admins".)
- Q: Should the six view-only models join `USER_ERASURE_CASCADE_MODELS`? → A: Yes (assumed
  default: without it, denying delete blocks erasing any user with progress. Overrule by editing
  "User erasure".)
- Q: Should `ContentTagListFilter` be kept as shared infrastructure? → A: Deleted (assumed default:
  nothing uses it after the removal. Overrule by editing "content_engine".)
- Q: Should `ORGANISATION_SUMMARIES` go now that nothing in FLS contributes to it? → A: Kept
  (assumed default: it is `OrganisationAdmin`'s extension point for downstream projects. Overrule by
  editing Decisions.)

## Success criteria

- `uv run manage.py check` passes.
- The admin index lists no content_engine model, form-definition model, `Learner`, `Cohort` or
  course-registration model.
- No view-only admin offers add, save, delete or bulk delete, for any user.
- A superuser can erase a user who has progress.
- The full test suite passes.
