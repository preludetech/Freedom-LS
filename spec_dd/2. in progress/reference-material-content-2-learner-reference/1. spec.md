# Spec: learner reference

## Purpose

`reference-material-content-1-authoring` stores a course's reference parts as `CourseReferencePart`
rows, but the player only knows the learning path, so a learner cannot read them. This spec lets a
registered learner open a course's reference listing and read reference topics from any player
page, with nothing tracked, and tells visitors to the public course page that the course has
reference material. The idea is `idea.md`.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| reference listing | coined | The page at `courses/<slug>/reference/` that lists a course's reference parts and their topics. No existing term. |
| reference topic | coined | A `Topic` that is a child of a `CoursePart` attached to the course through `CourseReferencePart`. No existing term. |
| reference part topics | coined | A reference part's `CoursePart` with its `Topic` children in order, as requirement 1's query returns it (`ReferencePartTopics`, from `course_reference_topics()`). Not `course.reference_parts`, which names the `CourseReferencePart` rows. |
| Reference link | coined | The link to the reference listing in the player sidebar. Not "Reference entry", which `ReferenceEntry` in the content schema already names. |

## Scope

In:
- The reference listing and reference topic pages, their URLs, access checks and chrome.
- The Reference link in the player sidebar, which serves the docked panel and the mobile
  bottom-sheet.
- A reference section on the public `course_detail` page.

Out: everything the idea lists under "Out of scope". `course_home` for a course with an empty
learning path still 404s until `reference-material-content-4-library-courses` lands (its idea now
has `course_home` render the course description there), so the Course crumb on such a course's
reference pages 404s until then.

## Requirements

### Reference query (`freedom_ls/learner_interface/utils.py`)

1. A function returns a course's reference parts in `CourseReferencePart.order`, each with its
   `Topic` children in `ContentCollectionItem.order`. Non-topic children are dropped, and so are
   parts left with no topics. The query is
   `course.reference_parts.select_related("course_part")` with
   `Prefetch("course_part__items", queryset=ContentCollectionItem.objects.prefetch_related("child"))`.
   It does not call `CoursePart.children()` or `collection_items()`, which query once per part. The
   query count grows with the number of distinct child content types, never with parts or topics.
   The function lives in `learner_interface`, not as a `Course` method, so it cannot collide with
   `reference-material-content-3-educator-reference`'s changes to `content_engine/models/courses.py`.

### URLs (`freedom_ls/learner_interface/urls.py`)

2. `courses/<slug:course_slug>/reference/` → `course_reference`, the reference listing.
3. `courses/<slug:course_slug>/reference/<slug:part_slug>/<slug:topic_slug>/` →
   `course_reference_topic`, a reference topic page.

### Views (`freedom_ls/learner_interface/views.py`)

4. Both views are `@login_required` and fetch the course with `get_object_or_404(Course, slug=...)`.
5. Access: call `_course_access_decision(request.user, course)`, which 404s for a hidden or
   out-of-audience course, and redirect to `course_detail` when `decision.can_access_content` is
   false. No `PlayerRoute` member is added.
6. `course_reference_topic` finds the part through `CourseReferencePart` rows for this course
   (`course_part__slug=part_slug`). The topic must be a `Topic` child of that part with
   `slug=topic_slug`. Anything else is a 404, including a part slug that is valid only for another
   course and a topic slug that exists only outside the part.
7. Neither view calls `view_course_item`, `view_topic` or `_ensure_player_course_progress`. Neither
   writes `TopicProgress`, `CourseProgress` (`last_accessed_item`, `last_accessed_time`,
   `started_at`) or an analytics event (`record_course_started` or any other).
8. Sidebar context: build the outline the way `course_finish` builds it, with `get_course_index` and
   no current row. Read progress with `course_progress_for(request.user, course)`. Pass the
   `course_progress` that returns (it may be `None`) and the course's deadlines and deadline
   policy.
9. The topic view passes `current_part` (the reference part), so `_course_base.html`'s
   `head_title` appends the part title to the topic title. It also passes the URLs of the previous
   and next topic within the part, or `None` at either end. Previous and Next never cross into
   another part.
10. The topic body is `topic.rendered_content()`, unchanged. Media resolve from the topic's own
    `file_path`, so the demo's shared `../shared_reference_material/` part renders under any
    course.

### Templates (`freedom_ls/learner_interface/templates/learner_interface/`)

11. **Reference link** (`_course_base.html`, `sidebar_content`). A new inclusion tag in
    `freedom_ls/learner_interface/templatetags/` takes `course` from the template context, runs one
    `exists()` query on `course.reference_parts`, and renders the link only when a row exists, so
    no player view changes. Place it inside `#course-toc-region`, right under the course table of
    contents: after the `course_minimal_toc.html#course-children` include and outside the
    `{% if course_index %}` guard, so a course with an empty learning path still shows it. The
    region is the HTMX out-of-band swap target, so the link stays current across Previous and Next.
    The link shows on every page whose outline panel is shown. That includes the pages a paused or
    ended learner can still reach (a finished item, form results, submit-and-exit), where following
    the link redirects to `course_detail` like a closed lesson. The one page without it is the
    exam-results page for an ended learner whose policy keeps no outline, which sets
    `hide_outline_panel`. On the listing and topic pages the link carries `aria-current="page"` and
    the outline's current-row highlight. It is not a `<nav>` and not an `<li>` inside the outline
    list, so the existing `#course-toc-region nav` selectors in
    `tests/views/test_course_player.py` still match only the outline.
12. **Reference icon.** Add the semantic name `reference` to `SEMANTIC_ICON_NAMES` in
    `freedom_ls/icons/semantic_names.py` and to all four icon sets in
    `freedom_ls/icons/mappings.py`, each mapped to a glyph that set has. Then regenerate the bundled
    glyph data with `scripts/generate_icon_subset.py`, as the `icon-usage` skill's
    `configuring-icons.md` describes.
13. **Reference breadcrumb**: a new partial beside `partials/player_breadcrumbs.html`, with the same
    markup conventions (`<nav aria-label="Breadcrumb">`, `<ol>`, `aria-hidden` separators,
    truncation). The Course crumb links `learner_interface:course_home`, the Reference crumb links
    the listing, and the Part crumb links the listing at `#<part slug>`. On the listing: Course ›
    Reference, with Reference as `aria-current="page"`. On a topic page: Course › Reference › Part,
    all three links; the topic title is the page heading, not a crumb.
14. **Reference listing** (new, extends `_course_base.html`): page title "Reference"; one
    `<section id="<part slug>">` per part with an `<h2>` part title and a `<ul>` of topic-title
    links, in order. The section needs a scroll margin so the anchor target is not hidden. The
    page shows no progress, status or "viewed" marks. When no part has a topic, the page shows the
    single message "No reference material yet" as a large centred `<c-icon>` (`size-12`) with the
    text under it, never a callout.
15. **Reference topic page** (new, extends `_course_base.html`): `<c-back-link>` to the listing
    above the heading; the topic title and subtitle as the page title; the body in
    `<c-markdown-container>` at reading width, as in `course_topic.html`. The footer goes inside
    `<c-player-nav>`/`<c-player-footer>`, so Previous and Next boost and swap the sidebar like the
    learning path. The footer is a `<nav>` named "Reference topics", and each control's accessible
    name includes the neighbouring topic's title. No mark-complete form, Finish Course or Home
    control.
16. **`course_detail.html`**: a `<section>` titled "Reference material" after the "Course content"
    section in the main column. It lists the titles of parts that have topics, in order, as plain
    text with no links. Above them sits one muted line saying the material is available to
    registered learners. The section is hidden when `course.table_of_contents_in_development` is
    set. It does not copy "Course content"'s `children or not access_ended_at` condition, so an
    ended learner still sees the titles. With no part that has a topic, the section is absent. The
    `course_detail` view adds the part titles to its context from requirement 1's query.

Visual treatment follows the `brand-guidelines` skill. Copy follows its voice rules.

## Testing

Use `CourseReferencePartFactory` and `mock_site_context`. The demo course
`demo_content/functionality_demo_reference_material/` covers manual QA, including the shared
`../` part.

- Access, for both views: anonymous → login redirect; unregistered → redirect to `course_detail`;
  hidden course and out-of-audience → 404; paused → redirect; ended → redirect; registered →
  200.
- Scoping: a part attached only to another course → 404; a topic not in the part → 404; a
  non-topic child is never listed or served.
- Nothing tracked: after viewing the listing and a topic, the counts of `TopicProgress` rows and
  `CourseProgress.last_accessed_item`, `last_accessed_time` and `started_at` are unchanged, and no
  analytics event fires. This includes a learner with no `CourseProgress` yet, for whom none is
  created.
- Listing: parts and topics in order; an empty part is hidden; all parts empty → empty-state
  message.
- Topic page: Previous and Next within the part, absent at the first and last topic, never
  crossing into another part; breadcrumb links; no progress controls; shared-part image renders.
- Reference link: present on topic, form, closed-item and finish pages and on a paused learner's
  read-only page; present when the learning path is empty; absent for a course with no reference
  parts and on the exam-results page with `hide_outline_panel`; current on reference pages; still
  present after an HTMX Previous/Next swap.
- Icon: the `icons` system checks pass with the new `reference` name.
- `course_detail`: the section lists part titles with topics, without links, for an anonymous
  visitor and for an ended learner; absent with no parts, only empty parts, or
  `table_of_contents_in_development`.
- Query count: the listing and topic views run a fixed number of queries as parts and topics grow.
- Playwright: from a topic page, open the Reference link in the mobile bottom-sheet, read a
  reference topic, step Next, return to the learning path by the breadcrumb.
