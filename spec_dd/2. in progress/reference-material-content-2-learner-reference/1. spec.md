# Spec: learner reference

## Purpose

`reference-material-content-1-authoring` stores a course's reference parts as `CourseReferencePart`
rows, but the player only knows the learning path, so a learner cannot read them. This spec lets a
registered learner open a course's reference listing and read reference topics from any player
page, with nothing tracked, and tells visitors to the public course page that the course has
reference material. The idea is `idea.md`; the decisions it settles are not repeated here.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| reference listing | coined | The page at `courses/<slug>/reference/` that lists a course's reference parts and their topics. No existing term. |
| reference topic | coined | A `Topic` that is a child of a `CoursePart` attached to the course through `CourseReferencePart`. No existing term. |
| Reference entry | coined | The link to the reference listing in the player sidebar. |

## Scope

In:
- The reference listing and reference topic pages, their URLs, access checks and chrome.
- The Reference entry in the player sidebar, which serves the docked panel and the mobile
  bottom-sheet.
- A reference section on the public `course_detail` page.

Out: everything the idea lists under "Out of scope". The empty-learning-path behaviour of
`course_home` (a 404 today) belongs to `reference-material-content-4-library-courses`.

## Decisions

- **Previous and Next stay inside one reference part.** They never wrap into the next part, and
  the first and last topic show only the one control that applies. (answers.md)
- **Breadcrumb on both pages: Course › Reference, plus Part on a topic page.** The course crumb
  links `learner_interface:course_home`, the Reference crumb links the reference listing, and the
  part crumb links the listing at `#<part slug>`. The topic title is the page heading, not a crumb.
  (answers.md)
- **The Reference entry sits right under the course table of contents**, inside
  `#course-toc-region` after the outline rows. One placement serves the docked sidebar and the
  mobile bottom-sheet, which share the `sidebar_content` block. Inside the region, the HTMX
  out-of-band swap keeps it current. (answers.md)
- **Parts with no topics are hidden** on the listing and on `course_detail`. When no part has a
  topic, the listing shows one empty-state message, and the Reference entry still links to it.
  (answers.md)
- **The reference query lives in `learner_interface`**, not as a `Course` method in
  `content_engine`. `reference-material-content-3-educator-reference` needs a similar query, and
  keeping this one local avoids a rebase collision on `content_engine/models/courses.py`.

## Requirements

### Reference query (`freedom_ls/learner_interface/utils.py`)

1. A function returns a course's reference parts in `CourseReferencePart.order`, each with its
   `Topic` children in `ContentCollectionItem.order`. Non-topic children are dropped, and so are
   parts left with no topics. It uses `course.reference_parts.select_related("course_part")` and
   prefetches the children, so the query count does not grow with the number of parts or topics.
2. A second check answers "does this course have any `CourseReferencePart` row" with one
   `exists()` query, for the Reference entry.

### URLs (`freedom_ls/learner_interface/urls.py`)

3. `courses/<slug:course_slug>/reference/` → `course_reference`, the reference listing.
4. `courses/<slug:course_slug>/reference/<slug:part_slug>/<slug:topic_slug>/` →
   `course_reference_topic`, a reference topic page.

### Views (`freedom_ls/learner_interface/views.py`)

5. Both views are `@login_required` and fetch the course with `get_object_or_404(Course, slug=...)`.
6. Access: call `_course_access_decision(request.user, course)`, which 404s for a hidden or
   out-of-audience course. When `decision.can_access_content` is false, redirect to
   `course_detail`. This covers paused and ended learners too. No `PlayerRoute` member is added and
   `_read_only_route_redirect` is not consulted, so no read-only exception opens a reference page.
7. `course_reference_topic` finds the part through `CourseReferencePart` rows for this course
   (`course_part__slug=part_slug`). The topic must be a `Topic` child of that part with
   `slug=topic_slug`. Anything else is a 404, including a part slug that is valid only for another
   course and a topic slug that exists only outside the part.
8. Neither view calls `view_course_item`, `view_topic` or `_ensure_player_course_progress`. Neither
   writes `TopicProgress`, `CourseProgress` (`last_accessed_item`, `last_accessed_time`,
   `started_at`) or an analytics event (`record_course_started` or any other).
9. Sidebar context: build the outline the way `course_finish` builds it, with `get_course_index` and
   no current row. Read progress with `course_progress_for(request.user, course)`. Pass the
   `course_progress` that returns (it may be `None`) and the course's deadlines and deadline
   policy. No learning-path row is marked current.
10. The topic view passes `current_part` (the reference part), so `_course_base.html`'s
    `head_title` appends the part title to the topic title. It also passes the URLs of the previous and next topic
    within the part, or `None` at either end.
11. The topic body is `topic.rendered_content()`, unchanged. Media resolve from the topic's own
    `file_path`, so the demo's shared `../shared_reference_material/` part renders under any
    course.

### Templates (`freedom_ls/learner_interface/templates/learner_interface/`)

12. **Reference entry** (`_course_base.html`, `sidebar_content`). Place it inside
    `#course-toc-region`, after the `course_minimal_toc.html#course-children` include and outside
    the `{% if course_index %}` guard, so a course with an empty learning path still shows it.
    Render it only when the course has a `CourseReferencePart` row (requirement 2) and the outline
    panel is shown (`not hide_outline_panel`). On the listing and topic pages it carries
    `aria-current="page"` and the outline's current-row highlight. Its icon is a new semantic name
    `reference`, added to every icon set in `freedom_ls/icons/mappings.py`. It is not a `<nav>` and
    not an `<li>` inside the outline list, so the existing `#course-toc-region nav` selectors still
    match only the outline.
13. **Reference breadcrumb**: a new partial beside `partials/player_breadcrumbs.html`, with the same
    markup conventions (`<nav aria-label="Breadcrumb">`, `<ol>`, `aria-hidden` separators,
    truncation). On the listing: Course › Reference, with Reference as `aria-current="page"`. On a
    topic page: Course › Reference › Part, all three links.
14. **Reference listing** (new, extends `_course_base.html`): page title "Reference"; one
    `<section id="<part slug>">` per part with an `<h2>` part title and a `<ul>` of topic-title
    links, in order. The section needs a scroll margin so the anchor target is not hidden. The
    page shows no progress, status or "viewed" marks. The empty state follows the brand rule for
    an empty but usable page: icon plus muted text, not a callout.
15. **Reference topic page** (new, extends `_course_base.html`): `<c-back-link>` to the listing
    above the heading; the topic title and subtitle as the page title; the body in
    `<c-markdown-container>` at reading width, as in `course_topic.html`. The footer goes inside
    `<c-player-nav>`/`<c-player-footer>`, so Previous and Next boost and swap the sidebar like the
    learning path. The footer is a `<nav>` named "Reference topics", and each control's accessible
    name includes the neighbouring topic's title. No mark-complete form, Finish Course or Home
    control.
16. **`course_detail.html`**: a `<section>` titled "Reference material" after the "Course content"
    section in the main column. It lists the titles of parts that have topics, in order, as plain
    text with no links. Above them sits one muted line saying the material is available to
    registered learners. It sits under the same `table_of_contents_in_development` gate as
    "Course content". With no part that has a topic, the section is absent. The `course_detail`
    view adds the part titles to its context from requirement 1's query.

Visual treatment follows the `brand-guidelines` skill. Copy follows its voice rules.

## Testing

Use `CourseReferencePartFactory` and `mock_site_context`. The demo course
`demo_content/functionality_demo_reference_material/` covers manual QA, including the shared
`../` part.

- Access, for both views: anonymous → login redirect; unregistered → redirect to `course_detail`;
  hidden course and out-of-audience → 404; paused → redirect; ended → redirect; registered →
  200.
- Scoping: a part attached only to another course → 404; a topic not in the part → 404; a
  non-topic child is never listed or served.
- Nothing tracked: after viewing the listing and a topic, the counts of `TopicProgress` rows and
  `CourseProgress.last_accessed_item`, `last_accessed_time` and `started_at` are unchanged, and no
  analytics event fires. This includes a learner with no `CourseProgress` yet, for whom none is
  created.
- Listing: parts and topics in order; an empty part is hidden; all parts empty → empty-state
  message.
- Topic page: Previous and Next within the part, absent at the first and last topic, never
  crossing into another part; breadcrumb links; no progress controls; shared-part image renders.
- Reference entry: present on topic, form, closed-item and finish pages of a course with reference
  parts; present when the learning path is empty; absent for a course with none; current on
  reference pages; still present after an HTMX Previous/Next swap; existing
  `#course-toc-region nav` assertions in `tests/views/test_course_player.py` still pass.
- `course_detail`: section lists part titles with topics, without links, for an anonymous visitor;
  absent with no parts or only empty parts.
- Query count: the listing and topic views run a fixed number of queries as parts and topics grow.
- Playwright: from a topic page, open the Reference entry in the mobile bottom-sheet, read a
  reference topic, step Next, return to the learning path by the breadcrumb.

## Open questions

- Q: Is the Reference entry shown to a paused or ended learner, whose reference pages redirect to
  `course_detail`? → A: Yes, it follows the outline panel and the route decides (assumed default:
  the entry's condition stays one `exists()` query, and the redirect is the same one a lesson gives
  them. Overrule by editing requirement 12.)
- Q: Does the topic page repeat a "Back to reference" link in its footer? → A: No, the back link
  sits above the heading only (assumed default: answers.md asks for one way back, and the
  breadcrumb is a second. Overrule by editing requirement 15.)
- Q: Does the `course_detail` reference section ignore `table_of_contents_in_development`? → A: No,
  it follows the same gate as "Course content" (assumed default: a course whose contents are still
  in development hides its structure consistently. Overrule by editing requirement 16.)

## Success criteria

- A registered learner reaches the reference listing from the sidebar entry on any player page,
  desktop and mobile.
- Every reference topic of the demo course renders, including the shared part's images.
- Viewing reference pages leaves every progress, resume and analytics record unchanged.
- Paused, ended, unregistered and anonymous users cannot open a reference page; a foreign part or
  topic slug 404s.
- Previous and Next on a reference topic page never leave its part.
- `course_detail` lists reference part titles without links, and shows nothing for a course with
  none.
