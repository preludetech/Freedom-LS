# Frontend QA: Profile picture

Checks, in a browser, that a user can upload, replace and remove a profile picture on the account
page, and that the picture shows wherever the spec (`1. spec.md`) says it should, with initials as
the fallback.

## Setup

1. Build the stylesheet: `npm run tailwind_build`.
2. Migrate: `uv run python manage.py migrate`.
3. Start the server on a free port: `uv run python manage.py runserver $PORT`. Base URL:
   `http://127.0.0.1:$PORT`.
4. Log in at `http://127.0.0.1:$PORT/accounts/login/` with the QA login from
   `.claude/sdd/config.md` (`## QA Login`). This user is the **admin**. Note its name and initials.
5. Data, from the QA data helper, on the site being browsed:
   - A second user, the **learner**: a named user with a password, who is an active learner in the
     admin's organisation and in a cohort the admin is assigned to as staff, so the two can message
     each other. The learner starts with no picture.
   - At least one message from the learner to the admin, so the admin's inbox has a conversation.
6. Test images, made by the tester in a scratch directory (not in the repo):
   - `landscape.jpg`: a 1600×900 JPEG whose left third is red, middle third green, right third
     blue. After a centre crop the picture is mostly green.
   - `portrait.png`: a 600×1200 PNG in a single different colour (yellow).
   - `square.webp`: a 500×500 WebP (purple).
   - `rotated.jpg`: a JPEG with EXIF orientation 6 and GPS EXIF tags, with a visible mark in what
     should be the top-left once upright.
   - `tiny.png`: 100×100.
   - `fake.png`: an SVG file (`<svg xmlns="http://www.w3.org/2000/svg"/>`) renamed to `.png`.
   - `notes.txt`: plain text.
   - `huge.jpg`: any file over 10 MB with a `.jpg` name (a 10.5 MB file of random bytes is
     enough).
   - `truncated.jpg`: the first half of the bytes of `landscape.jpg`.
7. In dev, stored pictures live on local disk under `media/profile_pictures/<user pk>/`. Some tests
   look there.

Viewports: 1920, 768 and 375. "No sideways scroll" means
`document.documentElement.scrollWidth <= window.innerWidth`. Keep the console open throughout: a
JavaScript error or a failed image request shows there.

"Header avatar" is the round menu trigger at the top right. "A broken image" is the browser's
broken-image icon or an empty box where a picture should be.

## Test 1: the account page before any picture

1. As the admin, open `http://127.0.0.1:$PORT/accounts/profile/`.
2. Expect, above the fields: a circle with the admin's initials and the admin's name beside it as
   text.
3. Expect a file input labelled "Profile picture" and the help text "JPEG, PNG or WebP, up to
   10 MB. Square pictures work best; others are cropped to the centre."
4. Inspect the input: `accept="image/jpeg,image/png,image/webp"`, and its `aria-describedby`
   names the help text's element.
5. Expect no "Remove profile picture" checkbox.
6. Inspect the form: `enctype="multipart/form-data"`.
7. The header avatar shows initials and contains no `<img>`.

## Test 2: upload a picture

1. On the account page, choose `landscape.jpg`. Expect no preview to appear before saving.
2. Click Save. Expect the page to reload at `/accounts/profile/` with "Profile saved".
3. Expect the picture above the form, round, mostly green (the centre of the image), not
   stretched, with the name beside it.
4. Expect the same picture in the header avatar.
5. Inspect the header image: `alt=""`, `width` and `height` set, and its `src` under
   `/media/profile_pictures/<admin pk>/` ending `.webp`. The name `landscape` appears nowhere in
   the `src`.
6. Open the image URL in a new tab and check its natural size: 400×400.
7. Look in `media/profile_pictures/<admin pk>/`: exactly one file.
8. Reload the page (F5). Expect no browser prompt about resubmitting a form.
9. Expect a "Remove profile picture" checkbox now.

## Test 3: the picture shows across the app

Do this with the admin's picture set (Test 2). Then log in as the learner in a second browser
profile or private window, upload `portrait.png` on the learner's account page, and come back.

1. **Educator sidebar.** As the admin, open the educator interface
   (`http://127.0.0.1:$PORT/educator/`). Expect the admin's picture in the user block at the bottom
   of the sidebar, with the name and email beside it unchanged.
2. **Learners table.** Open the learners table. Expect the learner's yellow picture in the
   learner's row, beside the name. Other learners show initials on a coloured circle, as before.
3. **Staff table.** Open the organisation's staff page. Expect the admin's picture in the admin's
   row.
4. **Cohort settings.** Open the cohort the admin is staff on and open its settings panel. Expect
   the admin's picture in the Staff list.
5. **Messaging inbox.** Open `http://127.0.0.1:$PORT/conversations/` (or the Messages link).
   Expect the learner's picture on the conversation row.
6. **Thread.** Open that conversation. Expect the learner's picture at the head of the thread.
7. **Recipient picker.** Start a new message (`/conversations/new/`) and search for the learner.
   Expect the learner's picture in the result row.
8. **Learner's messages panel.** On the learner's page in the educator interface, open the
   messages panel. Expect the admin's picture where the educator is shown.
9. **The learner's side.** As the learner, open the inbox and the thread. Expect the admin's
   picture.
10. On every page above: no broken image, no console error, and each picture is a circle the same
    size as the initials circles beside it.
11. At 375 and 768, repeat steps 1, 2 and 5. Expect no sideways scroll and no picture overflowing
    its circle.

## Test 4: surfaces that keep initials

These are out of scope and must not change.

1. As the admin, open the educator dashboard. Any attention rows naming the learner show initials,
   not the picture.
2. Open the audit log. Rows whose actor or target is the admin or the learner show initials.
3. Open a cohort report on screen, if one exists. Learners show initials.
4. Expect no broken image on any of these.

## Test 5: replace the picture

1. As the admin, on the account page, choose `square.webp` and save.
2. Expect the purple picture above the form and in the header.
3. Inspect the header image: its `src` is a different file name from the one in Test 2.
4. Look in `media/profile_pictures/<admin pk>/`: exactly one file, the new one. The old file is
   gone.
5. Open the educator sidebar and the staff table: both show the purple picture.

## Test 6: rotation and metadata

1. Choose `rotated.jpg` and save.
2. Expect the picture upright: the mark is at the top-left.
3. Download the stored file from its URL and inspect its metadata (for example
   `uv run python -c "from PIL import Image; im = Image.open('<file>'); print(im.format, im.size, dict(im.getexif()))"`).
   Expect `WEBP (400, 400) {}`: no EXIF, so no GPS.

## Test 7: rejected files change nothing

Start each step with a picture set, and note the header image's `src` first.

For each file below: choose it, also change First name to "Zzz", click Save, and check:

- the named error shows on the Profile picture field;
- "Profile saved" does not show;
- the First name input still holds "Zzz";
- the header avatar and the picture above the form still show the previous picture, and the name
  beside the picture and in the header menu's label is the saved name, not "Zzz";
- after a plain reload of `/accounts/profile/`, First name is the saved name and the header image's
  `src` is the same file as before;
- `media/profile_pictures/<admin pk>/` still holds exactly one file.

| File | Expected error |
| --- | --- |
| `notes.txt` | Use a JPEG, PNG or WebP image. |
| `fake.png` | Use a JPEG, PNG or WebP image. |
| `tiny.png` | That image is 100×100 pixels. Use one at least 128×128. |
| `huge.jpg` | That file is 10.5 MB. The limit is 10 MB. (the figure matches the file's size) |
| `truncated.jpg` | That image could not be read. Save it again or choose another file. |

Also check that no error text contains the uploaded file's name or a Python or Pillow exception
message.

## Test 8: saving names keeps the picture

1. With a picture set, change Last name, choose no file, leave Remove unticked, save.
2. Expect "Profile saved", the new name beside the picture and in the header menu label, and the
   same picture (same `src` file name as before).

## Test 9: remove the picture

1. Tick "Remove profile picture" and save.
2. Expect "Profile saved", initials above the form and in the header, and no `<img>` in either.
3. Expect no "Remove profile picture" checkbox.
4. `media/profile_pictures/<admin pk>/` holds no file.
5. Open the educator sidebar and the staff table: the admin shows initials.
6. Upload `landscape.jpg` again, then in one submission tick "Remove profile picture" **and**
   choose `square.webp`. Save. Expect the purple picture (the new file wins), and one file in the
   directory.

## Test 10: a picture whose file is missing shows initials

1. With a picture set for the admin, delete the file from `media/profile_pictures/<admin pk>/` by
   hand. Do not change the database.
2. Reload `/accounts/profile/`. Expect initials above the form and in the header avatar, in the
   same circles, with no broken image. The console may show a 404 for the image; it shows no
   JavaScript error.
3. Open the educator interface. Expect initials in the sidebar user block, no broken image.
4. As the learner, open the thread with the admin. Expect the admin's initials, no broken image.
5. In the educator interface, navigate between two pages using the sidebar links (HTMX
   navigation, no full reload) and open the staff table. The admin's row shows initials, no broken
   image.
6. Back on the account page, upload `landscape.jpg`. Expect the picture to show again everywhere.

## Test 11: a deactivated user keeps their picture

1. With the learner's picture set, have the admin deactivate the learner's user account (Django
   admin, untick Active).
2. Open the conversation with the learner and the learners table (with inactive learners shown, if
   the filter hides them). Expect the learner's picture still showing.
3. Reactivate the learner afterwards.

## Test 12: the Django admin

1. As the admin, open the Django admin (the "Admin Panel" link in the header menu) and open the
   learner's user.
2. Expect "Profile picture" under Personal info, shown read-only: no file input and no clear
   checkbox.
3. Change the learner's first name there and save. Expect the learner's picture unchanged
   afterwards.
4. On the user list, run the export. Expect no profile picture column and no storage path in the
   file.

## Test 13: deleting a user deletes the file

1. Have the QA data helper create a throwaway user with no learner row, give it a picture through
   the account page, and note the file in `media/profile_pictures/<pk>/`.
2. Delete that user in the Django admin.
3. Expect the file gone from disk.

## Test 14: other users cannot be changed from the account page

1. As the learner, open `/accounts/profile/`. The form shows the learner's own names and picture.
2. Save an upload. Expect the learner's picture to change and the admin's to stay as it was (check
   the admin's row in a table as the admin).
3. Log out and request `/accounts/profile/`. Expect a redirect to the login page.

## Test 15: layout

At 1920, 768 and 375, on `/accounts/profile/` with a picture set and again with an error showing
(use `tiny.png`):

1. No sideways scroll.
2. The picture and the name sit on one row and the name is not clipped where it has room.
3. The file input, its help text, the Remove checkbox and the Save button are all visible and none
   overlaps another.
4. The header avatar is a full circle and the picture fills it.
