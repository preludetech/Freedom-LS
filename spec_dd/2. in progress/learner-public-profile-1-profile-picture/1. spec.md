# Spec: Profile picture

Source: `idea.md` in this directory. Recorded answers: `answers.md`. Research: the `research_*.md`
files beside this spec and `spec_dd/1. next/learner-public-profile/research_existing_profile_code.md`.

## Purpose

A `User` has a name and an initials avatar and nothing else. Every user gets one profile picture,
uploaded, replaced and removed on the account profile page. It shows wherever the initials avatar
shows today, and initials remain the fallback. The later public profile
(`learner-public-profile-2-profile-and-page`) shows the same picture to anonymous viewers.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| profile picture | coined | The one image a `User` uploads to stand for themselves. Stored as `User.profile_picture`. Named after the `fls-dev:file-storage` skill's "profile pictures" and kept apart from `Organisation.profile_logo`. |

## Scope

In:

- A `User.profile_picture` field, its storage alias, upload validation and re-encoding.
- Upload, replace and remove on `accounts:account_profile`.
- The picture in place of the initials on every user avatar listed under "Avatars" below.
- Deleting superseded and orphaned stored files.

Out:

- The public profile page and its fields (`learner-public-profile-2-profile-and-page`).
- A crop or zoom UI, moderation, per-viewer visibility rules, HEIC support.
- `Organisation` logos: their validator keeps its current behaviour and messages exactly.
- The cohort report (`educator_interface/panels/cohort_report_body_region.html` and the PDF built
  from the same `reports` data). Its rows are a report snapshot keyed on learner ids, and a signed
  URL inside a stored report or PDF would expire. It keeps initials.
- The neutral circle for a deleted user (`comms/partials/participant_avatar.html`,
  `educator_interface/partials/audit_person.html`). No user, so no picture.

## Decisions

- **Private bucket, signed URLs** (`answers.md`). Every rendered URL is signed and expires after the
  purpose's `querystring_expire` (default 3600 s). The browser cannot cache an avatar across page
  loads because each render mints a new signature. The 400 px WebP rendition keeps that cost to tens
  of kilobytes per avatar. The URL is not cached server-side: in production `CACHES` is the database
  cache, so a lookup per avatar would add a query per row.
- **One stored rendition**: a 400×400 WebP, centre-cropped (`answers.md`). It covers every current
  surface (largest is the 52 px `lg` chip) and a 200 px picture on the public page at 2× density.
  The original upload is not kept.
- **JPEG, PNG and WebP only** (`answers.md`). HEIC is refused with the accepted-types error.
- **A new storage alias and purpose**, never `user_uploads` or `public`, so the picture gets its own
  key prefix, bucket setting and signing rule without changing another purpose's behaviour.
- **A deactivated user keeps their picture** (`answers.md`). No code path checks `is_active` for
  avatars.
- **Only the account page writes the field.** The Django admin shows the picture read-only, so every
  stored picture has been through validation and re-encoding.
- **The panel framework stays FLS-free.** `panel-avatar-chip` takes a plain `picture_url` string.
  FLS templates resolve the URL. The framework is being extracted
  (`extract_panels_framework-1-gather-generic-code`) and must not import FLS models.

## Requirements

### Model and storage

- `freedom_ls/accounts/models.py`: add `User.profile_picture`, a `FileField(blank=True)` with
  `storage=get_profile_picture_storage` and `upload_to=profile_picture_upload_to`, plus a migration
  in `freedom_ls/accounts/migrations/`.
  - `get_profile_picture_storage()` returns `storage_for_alias("profile_pictures",
    "STORAGES['profile_pictures']")`, as `form_engine.models.get_user_uploads_storage` does.
  - `profile_picture_upload_to(instance, filename)` ignores the uploader's filename and returns
    `profile_pictures/{user.pk}/{uuid4 hex}.webp`. A new key per upload means a replaced picture
    never shares a URL with the old one.
  - `User.profile_picture_url` (property) returns the storage URL, or `None` when the field is
    empty. It reads no request state, so it works for anonymous viewers and outside a request. It
    never calls the storage backend over the network: no `exists()` check per render.
- `freedom_ls/deployment/storage.py`: add purpose `PROFILE_PICTURES_PURPOSE = "PROFILE_PICTURES"`,
  map alias `profile_pictures` to it in `FIXED_ALIAS_PURPOSES`, add it to `SIGNED_URL_PURPOSES`.
  Leave it out of `_OVERWRITE_PURPOSES` and `_OBJECT_PARAMETERS`. Env vars follow the existing
  `AWS_S3_PROFILE_PICTURES_*` pattern.
- `config/settings_base.py` `STORAGES`: add a `profile_pictures` `FileSystemStorage` entry without
  `allow_overwrite`.
- `freedom_ls/tests/storages.py`: a pathless binding for `User.profile_picture`, generalised from
  `bind_pathless_logo_storage`, so tests prove no code calls `.path()` on the picture.

### Validation and re-encoding

- One image-safety routine serves both the logo and the picture. Factor the decode-and-check core
  out of `organisations/validators.py` `check_logo_safety` into `freedom_ls/base/images.py`,
  parameterised by byte cap, allowed formats and dimension cap. Logo limits, messages and the logo's
  EXIF-keeping behaviour must stay unchanged; the existing logo tests are the proof.
- Picture rules, in a new `freedom_ls/accounts/validators.py`:
  - Size at most 10 MB, checked from `file.size` before reading, then a bounded read.
  - Format decided by decoding (`JPEG`, `PNG`, `WEBP`), never the extension or `Content-Type`.
  - At least 128 px on each side and at most 40 megapixels in total. A 12 MP or 48 MP phone photo
    must pass the dimension check.
  - Decoded inside `bomb_warnings_as_errors()` and `truncated_images_rejected()`.
- Re-encoding (`freedom_ls/accounts/images.py` or beside the validator), bytes in, bytes out:
  `ImageOps.exif_transpose`, first frame only for animated input, `ImageOps.fit` to 400×400
  centred with `LANCZOS`, convert to `RGB` or `RGBA`, save as WebP at quality 80. EXIF and XMP are
  not carried into the output. Use JPEG draft mode so a large JPEG does not decode at full size.
  Never return the source bytes; content_engine's `optimise_image` is not reused for that reason.
- Errors, one per failure, shown on the field and naming the limit:
  - wrong or unreadable type: "Use a JPEG, PNG or WebP image."
  - too large: "That file is {size} MB. The limit is 10 MB."
  - too small: "That image is {w}×{h} pixels. Use one at least 128×128."
  - too many pixels or a decompression bomb: "That image is too large to process. Use one under
    40 megapixels."
  - truncated: "That image could not be read. Save it again or choose another file."
  The uploader's filename and Pillow's exception text never reach the page.

### Account page

- `freedom_ls/accounts/forms.py` `UserForm`: add the picture as an upload field plus a
  "Remove profile picture" checkbox shown only when a picture exists. A new file wins over a ticked
  remove. Remove the `# TODO: allow the user to upload a profile picture` comment.
- `UserForm.save()` handles all three paths: upload, replace, remove. It reads the previous stored
  name through `User._base_manager` before saving, as `QuestionAnswerFile.save()` does. It deletes
  the superseded file in `transaction.on_commit` so a rolled-back save keeps the old file. Delete
  failures behave as `Organisation.save()`'s do: no catch.
- A failed picture leaves the name fields, the stored picture and every other value unchanged. The
  form re-renders with the error and the typed names.
- `freedom_ls/accounts/views.py` `edit_profile`: pass `request.FILES` to the form.
- `freedom_ls/accounts/templates/accounts/profile.html`: `enctype="multipart/form-data"`; the
  current picture (or initials) at the top of the form; the file input labelled "Profile picture"
  with `accept="image/jpeg,image/png,image/webp"` and help text "JPEG, PNG or WebP, up to 10 MB.
  Square pictures work best; others are cropped to the centre.", linked by `aria-describedby`. No
  client-side preview is required.
- `freedom_ls/accounts/admin.py` `UserAdmin`: `profile_picture` read-only. `UserResource` does not
  export it.

### Avatars

The picture replaces the initials in each surface below. Where a caller passes only a pk, the view
loads the `User`s with `select_related`/`prefetch_related` so no row costs a query.

| Surface | File |
| --- | --- |
| Header menu trigger | `freedom_ls/base/templates/partials/header_bar_user_menu.html` |
| Educator sidebar user block | `freedom_ls/educator_interface/templates/educator_interface/_shell.html` |
| Messaging participant | `freedom_ls/comms/templates/comms/partials/participant_avatar.html` (all four includers) |
| Recipient picker | `freedom_ls/comms/templates/comms/partials/recipient_picker.html` |
| Cohort settings panel | `freedom_ls/educator_interface/templates/educator_interface/panels/cohort_settings.html` |
| Learner and staff member table cells | `educator_interface/data-table-cells/learner.html`, `staff_member.html` |
| Audit log who and target | `educator_interface/partials/audit_person.html` (live-user branch) |
| Attention rows | `freedom_ls/panel_framework/templates/cotton/panel-attention-row.html` callers |

- `panel-avatar-chip.html` gains an optional `picture_url` attribute, also passed through
  `panel-person-link.html` and `panel-attention-row.html`. With a URL, the circle holds an `<img>`
  with `alt=""`, explicit `width`/`height`, `object-fit: cover`, and `loading="lazy"` in lists. The
  circle keeps its `panel-avatar-N` colour class and `aria-hidden`, and the accessible name still
  comes from the name text or the caller's label. Update the chip's comment block, the
  `panel-framework` skill and `panel_framework/reference/_examples.html`.
- The header trigger keeps its own markup and its `aria_label`, and shows the picture the same way.
- The initials stay in the markup under the picture. When the image fails to load (missing file,
  expired signature on a long-open page), the initials show, never a broken-image icon. One shared
  mechanism serves the chip and the header.

### Deleting files

- A `post_delete` receiver on `User` deletes the stored picture. Queryset and cascade deletes fire
  it too. Register it in `AccountsConfig.ready()`.
- Replace and remove delete the old file after commit (above). Deactivation deletes nothing.

## Testing

- Validator: each rejection with its message (oversize bytes, under 128 px, over 40 MP,
  decompression bomb, truncated file, SVG renamed `.png`, HEIC, text file named `.jpg`); a 4032×3024
  JPEG is accepted.
- Re-encoding: output is 400×400 WebP; a JPEG with GPS EXIF comes out with no EXIF; an EXIF-rotated
  photo comes out upright; a polyglot (image plus trailing payload) loses the payload; animated input
  keeps one frame.
- Logo regression: the existing `organisations` validator tests pass unchanged.
- Form and view: upload stores the file under `profile_pictures/{pk}/`; replace deletes the old key
  after commit; remove deletes the file and empties the field; new file plus remove keeps the new
  file; a rolled-back save keeps the old file (`django_capture_on_commit_callbacks`); an invalid file
  leaves names and picture unchanged; the TODO is gone.
- Storage: `profile_pictures` in `FIXED_ALIAS_PURPOSES` and `SIGNED_URL_PURPOSES`, not in
  `_OVERWRITE_PURPOSES`; `build_storages()` emits a signed entry; the pathless binding passes.
- `User.profile_picture_url`: `None` when empty; a URL with no request in scope.
- Receiver: deleting a user deletes the stored picture, including by queryset delete.
- Avatars: each surface in the table renders the `<img>` for a user with a picture and initials
  for one without, with no extra query per row (`django_assert_num_queries`); the chip keeps
  `aria-hidden` and `alt=""`; the cohort report still shows initials.
- Browser (Playwright): a picture whose file is missing shows initials, not a broken image; the
  upload, replace and remove flow on the account page.

## Documentation and downstream

- Downstream projects get the migration and must set `AWS_S3_PROFILE_PICTURES_BUCKET_NAME` (or rely
  on the shared bucket fallback) before deploying; `check --deploy` reports it otherwise. The upgrade
  notes say so.
- Any reverse proxy in front of the app must allow a 10 MB request body on the account page.

## Success criteria

- A user uploads a JPEG, PNG or WebP on the account page and sees it in the header, messaging and
  educator views. The stored object is a 400×400 WebP with no EXIF.
- Replacing or removing the picture leaves no superseded object in storage; removing it brings back
  the initials everywhere.
- Each rejected file shows its named error and changes nothing else on the account.
- Every picture URL in production is signed, and the `profile_pictures` purpose is in
  `SIGNED_URL_PURPOSES`.
- Deleting a user deletes their stored picture.
- A missing or expired picture shows initials, never a broken image.
- Organisation logo validation behaves exactly as before.
- The panel framework imports nothing from FLS.
