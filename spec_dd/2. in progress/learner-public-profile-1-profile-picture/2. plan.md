### Slice 2: The Content Security Policy allows the profile-picture bucket's host

With a custom domain or endpoint configured for `PROFILE_PICTURES`, the report-only policy's
`img-src` lists that host; on local disk it is unchanged.

**Builds on:** slices 1
**Touches:** `freedom_ls/deployment/storage.py`, `freedom_ls/deployment/tests/test_storage.py`, `config/settings_base.py`

1. `freedom_ls/deployment/storage.py`: lift `_alias_entry`'s inner `name_for` to a module-level
   `_property_name(purpose, prop, shared)`, update `_alias_entry` to call it, then add

   ```python
   def media_csp_sources(purpose: str) -> list[str]:
       """The origins a browser loads `purpose`'s objects from; empty on local disk.

       Reads the same custom domain or endpoint `_alias_entry` hands the storage,
       so the policy and the URLs the storage mints cannot name different hosts.
       """
       bucket, _from_shared = bucket_name_for(purpose)
       if not bucket:
           return []
       custom_domain = env_str(_property_name(purpose, "CUSTOM_DOMAIN", "AWS_S3_CUSTOM_DOMAIN"))
       if custom_domain:
           return [f"https://{custom_domain}"]
       endpoint = env_str(_property_name(purpose, "ENDPOINT_URL", "AWS_S3_ENDPOINT_URL"))
       if not endpoint:
           return []
       host = urlsplit(endpoint).netloc
       # A signed URL puts the bucket in the path or in a subdomain of the
       # endpoint, depending on the addressing style the client picks. The
       # subdomain is named, never wildcarded: a wildcard would allow every
       # other bucket on a shared endpoint host.
       return [f"https://{host}", f"https://{bucket}.{host}"]
   ```

   `*media_csp_sources(PROFILE_PICTURES_PURPOSE)` to `SECURE_CSP_REPORT_ONLY["img-src"]`. Add a
   sentence to the comment block above the policy saying what the host is for.

### Slice 3: An uploaded picture is validated and re-encoded to a 400×400 WebP

Bytes in, either a named `ValidationError` or the stored rendition out. No form or view yet: the
two functions are pure, so they are proved on their own and built alongside slice 1, and slice 5
is the first slice that calls them.

**Builds on:** none
**Touches:** `freedom_ls/accounts/validators.py`, `freedom_ls/accounts/images.py`, `freedom_ls/accounts/tests/test_validators.py`, `freedom_ls/accounts/tests/test_images.py`, `freedom_ls/accounts/tests/profile_picture_samples.py`

1. `freedom_ls/accounts/validators.py` (new):

   ```python
   # MPO is a JPEG with extra frames appended (a phone's depth or portrait
   # data). Pillow reports it as its own format; the first frame is the photo.
   ALLOWED_FORMATS = frozenset({"JPEG", "MPO", "PNG", "WEBP"})
   MAX_BYTES = 10 * 1024 * 1024
   MIN_SIDE = 128
   MAX_PIXELS = 50_000_000

   WRONG_TYPE = "Use a JPEG, PNG or WebP image."
   TOO_MANY_PIXELS = (
       "That image is too large to process. "
       f"Use one under {MAX_PIXELS // 1_000_000} megapixels."
   )
   UNREADABLE = "That image could not be read. Save it again or choose another file."


   def validate_profile_picture(file: UploadedFile) -> bytes:
       """Return the upload's bytes once every check has passed.

       The checks run cheapest first, so nothing large is read or decoded
       before it is refused: declared size, a bounded read, the header, then
       the full decode. No message carries the uploader's filename or
       Pillow's own text.
       """
       if (file.size or 0) > MAX_BYTES:
           raise _too_large(file.size or 0)
       file.seek(0)
       # One byte over the cap is all it takes to refuse a handle that
       # under-reported its size.
       raw = file.read(MAX_BYTES + 1)
       if len(raw) > MAX_BYTES:
           raise _too_large(len(raw))

       with bomb_warnings_as_errors(), truncated_images_rejected():
           try:
               img = Image.open(io.BytesIO(raw))
               # The decoder's verdict, never the extension or Content-Type.
               if img.format not in ALLOWED_FORMATS:
                   raise ValidationError(WRONG_TYPE)
               width, height = img.size
               if width * height > MAX_PIXELS:
                   raise ValidationError(TOO_MANY_PIXELS)
               if width < MIN_SIDE or height < MIN_SIDE:
                   raise ValidationError(
                       f"That image is {width}×{height} pixels. "
                       f"Use one at least {MIN_SIDE}×{MIN_SIDE}."
                   )
               # A header can parse cleanly over a truncated body; only a
               # full decode finds that. The draft keeps a large JPEG from
               # decoding at full size just to be checked.
               img.draft("RGB", (PROFILE_PICTURE_SIDE, PROFILE_PICTURE_SIDE))
               img.load()
           except BOMB_FAILURES as err:
               raise ValidationError(TOO_MANY_PIXELS) from err
           except Image.UnidentifiedImageError as err:
               # Pillow has no decoder for it: HEIC and SVG land here.
               raise ValidationError(WRONG_TYPE) from err
           except DECODE_FAILURES as err:
               raise ValidationError(UNREADABLE) from err
       return raw
   ```

   `_too_large(size)` builds "That file is {size in MB, one decimal} MB. The limit is 10 MB.",
   taking the limit from `MAX_BYTES`, so no message can disagree with its constant.
   `UnidentifiedImageError` subclasses `OSError`, so its `except` must sit above
   `DECODE_FAILURES`. `ValidationError` is in neither family, so the three raised inside the `try`
   pass straight through.
2. `freedom_ls/accounts/images.py` (new):

   ```python
   PROFILE_PICTURE_SIDE = 400
   WEBP_QUALITY = 80


   def encode_profile_picture(raw: bytes) -> bytes:
       """The one stored rendition: a centre-cropped square WebP.

       Always re-encodes, so nothing of the upload but its pixels survives:
       no EXIF or XMP (a phone photo carries GPS), and no bytes appended
       after the image data.
       """
       with Image.open(io.BytesIO(raw)) as img:
           # JPEG only: decode at a reduced scale that still covers the target.
           img.draft("RGB", (PROFILE_PICTURE_SIDE, PROFILE_PICTURE_SIDE))
           # An animated upload contributes its first frame, which is the
           # frame an opened image sits on.
           upright = ImageOps.exif_transpose(img)
           has_alpha = "A" in upright.getbands() or "transparency" in upright.info
           fitted = ImageOps.fit(
               upright.convert("RGBA" if has_alpha else "RGB"),
               (PROFILE_PICTURE_SIDE, PROFILE_PICTURE_SIDE),
               Image.Resampling.LANCZOS,
               centering=(0.5, 0.5),
           )
           out = io.BytesIO()
           fitted.save(out, "WEBP", quality=WEBP_QUALITY, exif=b"", xmp=b"")
       return out.getvalue()
   ```

   `validators.py` imports `PROFILE_PICTURE_SIDE` from `images.py`. `encode_profile_picture` is
   called only on bytes `validate_profile_picture` returned, which already decoded them under both
   guards, and its docstring says so: that is why it carries no guard or `except` of its own.
3. `freedom_ls/accounts/tests/profile_picture_samples.py`: small builders that return image bytes

### Slice 6: Replacing a profile picture deletes the one before it

A second upload stores a new file under a new key, and the superseded file is deleted when the save
commits. A save that rolls back keeps the old file.

**Builds on:** slices 5
**Touches:** `freedom_ls/accounts/forms.py`, `freedom_ls/accounts/tests/test_forms.py`, `freedom_ls/accounts/tests/playwright/`

1. `freedom_ls/accounts/forms.py` `UserForm` gains:

   ```python
       def save(self, commit: bool = True) -> User:
           if not commit:
               # The superseded file is deleted when this save commits, so an
               # unsaved form has nothing to hang that on.
               raise ValueError("UserForm.save() does not support commit=False.")
           superseded = self._stored_profile_picture_name()
           user = super().save()
           if superseded and superseded != user.profile_picture.name:
               storage = user.profile_picture.storage
               # Deferred to commit: a save that rolls back keeps the row
               # pointing at the old file, so the old file has to survive.
               transaction.on_commit(lambda: storage.delete(superseded))
           return user

       def _stored_profile_picture_name(self) -> str:
           """The picture name the database holds now.

           Read from the database, not the instance: validation has already
           written the new file onto the instance by the time save() runs.
           Through the base manager, because `objects` filters to the
           request's site.
           """
           stored = (
               User._base_manager.filter(pk=self.instance.pk)
               .values_list("profile_picture", flat=True)
               .first()
           )
           return stored or ""
   ```

   A delete failure is not caught.

### Slice 11: Deleting a user deletes their picture

1. `freedom_ls/accounts/signals.py` (already imported by `AccountsConfig.ready()`):

   ```python
   @receiver(post_delete, sender=User)
   def delete_profile_picture(
       sender: type[User], instance: User, **kwargs: object
   ) -> None:
       """Storage does not follow the row, and a person's picture must not
       outlive their account. A signal, because queryset and cascade deletes
       never call the model's delete()."""
       if not instance.profile_picture:

       stored = instance.profile_picture
       # Deferred to commit: a delete that rolls back must leave the picture.
       transaction.on_commit(lambda: stored.delete(save=False))
   ```
