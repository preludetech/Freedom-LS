# Frontend QA: reporting and dashboards (educator interface spec 10)

## 0. Setup

```bash
npm run tailwind_build                                   # the PDF render and the new classes both need the bundle
uv run python manage.py qa_create_report_course --course-key medium --num-items 12 --num-quizzes 3
uv run python manage.py qa_create_report_course --course-key short --num-items 6 --num-quizzes 1
uv run python manage.py qa_create_report_cohort --cohort-name "QA Report Alpha" --num-learners 9 --num-flagged 3 \
    --course-slug qa-report-medium-course --course-slug qa-report-short-course \
    --educator-email qa.report.viewer@email.com
uv run python manage.py qa_create_report_cohort --cohort-name "QA Report Beta" --num-learners 5 --num-flagged 1 \
    --course-slug qa-report-medium-course --email-prefix qa-report-beta
uv run python manage.py qa_create_report_cohort --cohort-name "QA Report Empty" --num-learners 0
uv run python manage.py qa_create_single_org_educator --email qa.org.admin@email.com
PORT=$(.claude/ds/scripts/find_available_port.sh)
uv run python manage.py runserver $PORT
```

- Base URL: `http://127.0.0.1:$PORT`. The educator interface is under `/educator/`; the
  DemoDev organisation's dashboard is `/educator/organisations/demodev/dashboard`, its cohorts
  list `/educator/organisations/demodev/cohorts`, and a cohort page
  `/educator/organisations/demodev/cohorts/<cohort-id>` (called `<cohort-url>` below; copy the
  id from the cohorts list).
- Logins (password equals the email in every case):
  - Site admin: `demodev@email.com` (sees everything).
  - Organisation admin of DemoDev: `qa.org.admin@email.com` (sees every DemoDev cohort).
  - Cohort viewer on "QA Report Alpha" only: `qa.report.viewer@email.com`.
- Learners are `qa-report-learner-01@email.com` upwards (Alpha) and
  `qa-report-beta-01@email.com` upwards (Beta). The seeder flags three Alpha learners, one each
  for "No recorded activity", "Failed most recent quiz attempt" and "No activity recently", and
  one Beta learner.
- The Django admin is at `/admin/`. The reports admin is
  `/admin/freedom_ls_reports/generatedreport/`.
- Use a fresh private window per login. django-axes locks an email after five failed logins;
  run `uv run python manage.py axes_reset` if you trip it.
- The on-screen cache lives five minutes. When a scenario changes data and needs the figures to
  move, use the Report tab's **Refresh** control, or wait out the cache, or restart the server
  after `uv run python manage.py shell -c "from django.core.cache import cache; cache.clear()"`.

## Scenario 1: dashboard for an organisation admin

1. Log in as `qa.org.admin@email.com`. Open `/educator/`.
2. **Expect:** you land on the dashboard. Four stat tiles across the top: **Learners** with
   "Across N cohorts" under it, **Cohorts**, **Average progress**, **Learners needing
   attention**. Learners and Cohorts show their numbers immediately. The other two show a pulsing
   placeholder for a moment, then fill in without a page reload.
3. **Expect:** the Learners figure counts the 14 seeded learners (9 + 5; the Empty cohort adds
   none) plus any other DemoDev learners already in the database. Cohorts counts active DemoDev
   cohorts, Empty included. Clicking the Cohorts tile goes to the cohorts list.
4. **Expect:** Average progress shows a percentage with a bar. Learners needing attention shows
   4 (three Alpha, one Beta) plus any other flagged learners in pre-existing cohorts.
5. **Expect:** a "Figures as of <date, time>" line.
6. **Expect:** a **Needs attention** card listing one row per flagged learner, lowest completion
   first. Each row: the learner's name as a link, a warning icon, and under the name each cohort
   they are flagged in with the cohort name linked, a badge per flag ("No recorded activity",
   "Failed most recent quiz attempt" or "No activity recently") and the reason sentence visible
   beside it (not only on hover).
7. Click a learner's name. **Expect:** their learner page. Go back.
8. Click the small quick-view icon at the end of a row. **Expect:** the quick view drawer opens
   with that learner's name, status, cohorts and course registrations. Close it. The page
   underneath did not navigate.
9. **Expect:** a **Cohort progress** card with one row per cohort: name linked to the cohort
   page, a mean completion percentage with a bar (an em dash for "QA Report Empty"), the learner
   count and the flagged count. Lowest mean first; the Empty cohort last.
10. Click a cohort name. **Expect:** that cohort's page.

3. Deactivate every cohort of a second organisation that has a cohort viewer, or simpler: in the

## Scenario 4: the over-limit notice

1. In the admin, open DemoDev's site settings or the environment and set
   `REPORTS_MAX_LEARNERS` to 6 (an `.env` value or `settings_dev.py` override), then restart the
   server with the same `$PORT`.
2. As `qa.org.admin@email.com` open the dashboard. **Expect:** Alpha (9 learners) is named in a
   notice: "QA Report Alpha has 9 learners, over the report limit of 6, and is not included".
   Learners still counts Alpha's 9; Cohorts still counts Alpha. The attention list and the cohort
   progress rows no longer include Alpha. Beta is unaffected.
3. Open Alpha's page, Overview tab. **Expect:** the Needs attention card shows the limit message
   instead of a list. Open the Report tab. **Expect:** the report body shows the same message;
   the Downloads panel still works.
4. Restore the setting and restart the server.

## Scenario 6: Report tab, Downloads panel, generate and download the PDF

1. As `qa.org.admin@email.com` open Alpha's page. **Expect:** tabs in the order Overview,
   Learners, Courses, **Report**, Settings.
2. Open **Report**. **Expect:** a **Downloads** panel first with "Download cohort members
   (CSV)" and the line "Lists the learners and the educators assigned to this cohort.", then a
   **Generate PDF report** button. Below it the **Cohort report** panel (scenario 8).
3. Click **Generate PDF report**. **Expect:** the panel swaps to "A report is being generated,
   requested by <your name> at <time>". In dev the task runs immediately, so within about three
   seconds the panel swaps again, with no click, to **Download PDF (generated <time> by <your
   name>)** and a **Generate a new report** button.
4. Click **Download PDF**. **Expect:** a PDF downloads named
   `<organisation-slug>-qa-report-alpha-progress-report.pdf`. Open it: the at-a-glance page
   shows "Learners in cohort 9".
5. Click **Generate a new report**, and while it says "being generated" click it again if you
   can (or open the same Report tab in a second window and click there). **Expect:** no error:
   both windows show the same "being generated" state, and one report results.
6. In the admin at `/admin/freedom_ls_reports/generatedreport/` confirm the reports for Alpha,
   each with a Download link. The admin path still works (open one Download link).

## Scenario 7: failed, stalled, and permission-gated downloads

1. In the admin, open one of Alpha's ready reports and note its id. Create a failure state:
   `uv run python manage.py shell -c "from freedom_ls.reports.models import GeneratedReport as R; r=R.objects.filter(cohort__name='QA Report Alpha').first(); r.pk=None; r.status='failed'; r.error_message='Render failed in QA'; r.file=''; r.save()"`
   (this clones the newest row as a failed one, newer than the ready one).
2. Reload Alpha's Report tab. **Expect:** the Download PDF link for the ready report is still
   there, the text "Render failed in QA" shows, and the button reads **Try again**. Click it.
   **Expect:** a new report generates and the panel ends on Download PDF with a fresh time.
3. Stalled state: `uv run python manage.py shell -c "from freedom_ls.reports.models import GeneratedReport as R; from django.utils import timezone; from datetime import timedelta; r=R.objects.filter(cohort__name='QA Report Alpha').first(); r.pk=None; r.status='pending'; r.file=''; r.save(); R.objects.filter(pk=r.pk).update(requested_at=timezone.now()-timedelta(minutes=11))`.
   Reload the Report tab. **Expect:** "A report is being generated …", then "This is taking
   longer than expected" and a **Check again** link, and the panel no longer polls (watch the
   network tab: no request every three seconds). Click Check again. **Expect:** the same state
   re-renders. Delete that pending row in the admin afterwards.
4. Log in as `qa.report.viewer@email.com` (cohort viewer; the built-in role holds
   `download_cohort_report`). Open Alpha's Report tab. **Expect:** the Downloads panel shows the
   CSV link and the PDF controls, and generating works for this role too.
5. Copy the Download PDF link's URL. Log in as a learner (`qa-report-learner-01@email.com`) in a
   new window and open that URL. **Expect:** a 404, not the file.
6. As `qa.org.admin@email.com`, edit the Download PDF URL: swap the report id for a report id
   belonging to Beta (from the admin list). **Expect:** 404. Swap the cohort id in the URL for
   Beta's cohort id while keeping Alpha's report id. **Expect:** 404. Use the id of the failed
   report from step 1. **Expect:** 404.

## Scenario 8: Report tab body

1. As `qa.org.admin@email.com` open Alpha's Report tab and scroll to **Cohort report**.
2. **Expect:** a text placeholder, then the body fills: "Figures as of <time>" with a
   **Refresh** button; **Cohort at a glance** with four figures (Learners in cohort 9, Median
   completion N%, Not started, Completed everything); **Learners needing attention** with the
   three flagged learners, badges and reasons; **Summary of learner progress** with one card per
   course (medium and short) holding a table: Learner (linked), a status badge ("Not started",
   "In progress" or "Complete"), a completion bar with "N of M items", Last item completed,
   When, then one column per quiz (abbreviations in the header, a legend under the table). Quiz
   cells show a percentage, "Passed" or "Failed" text, and "×N" attempts, or an em dash. Then
   **Quiz confusions across the cohort** with a table per quiz that has at least one wrong answer: question
   number, question text with the correct options as success chips, the wrong options chosen as
   error chips with "×count", and "Got it wrong" as "N of M learners" (fewer than ten respondents
   here, so counts rather than percentages).
3. **Expect:** no learner's wrong answers or per-learner answer detail anywhere on the page.
4. Compare the at-a-glance figures with the PDF downloaded in scenario 6 (generated after the
   same seed): the four numbers match.
5. As `qa-report-learner-02@email.com` in another window, open the medium course and complete
   the next topic. Back as the admin, click **Refresh** on the Report tab. **Expect:** the
   "Figures as of" time moves to now and that learner's completion increases. Without Refresh,
   a plain reload within five minutes keeps the earlier time.
6. In the admin, remove a flagged Alpha learner from the organisation (Learners, untick active)
   and reload the Report tab without Refresh. **Expect:** that learner is gone from every
   list and table and the Learners in cohort figure drops by one, even though the time line is
   unchanged. Reactivate the learner afterwards.
