# Spec: reporting and dashboards (educator interface spec 10)

Idea: `idea.md`. Effort context: the "Educator interface rebuild" section of
`spec_dd/1. next/roadmap.md`. Measurement behind the data decisions:
`research_gather_measurement.md`. Other research: the `research_*.md` files beside this spec.

## Purpose

An educator's only view of learner progress is the cohort report PDF, which they request from the
Django admin. The educator interface's dashboard is a placeholder. The cohort Overview's "Needs
attention" card always reads "Nothing needs attention yet". The learner page shows a progress bar per
course and nothing more. This spec puts the report's gathered data on screen at three levels
(organisation, cohort, learner). It moves PDF generation and download into the interface and adds a
cohort roster CSV.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| progress gather | coined | `gather_cohort_progress`: the cohort report gather without the answer loaders and branding. Produces `LearnerDetail` rows, flags and completion figures, but no quiz confusion and no wrong answers. No existing term, because the gather has only ever run whole. |
| progress status | coined | Not started, in progress or complete, derived from a completion percentage. `docs/product/educator-interface.md` uses "status" for `LearnerStatus` (active, pending, removed), a different thing. |
| attention flag | narrowed | `AtRiskFlag` in `freedom_ls/reports/report_data.py`, produced by `AT_RISK_RULES` in `freedom_ls/reports/at_risk.py`. |

## Scope

In:

- The organisation dashboard, replacing `DashboardPanel`'s placeholder: four stat tiles, a
  needs-attention list across visible cohorts, and a cohort progress list.
- A Report tab on the cohort detail page that renders the gathered report data.
- The cohort Overview's "Needs attention" card, filled from the progress gather.
- A learner drill-down on the learner page's Courses tab.
- Generating and downloading the cohort report PDF from the cohort page.
- A cohort roster CSV: learners plus organisation members holding a role on the cohort.
- One shared definition of progress status and attention flags in `reports`.
- Removed learners leave the report roster, in the PDF too.

Out:

- Redesigning the PDF or its pipeline, beyond the roster filter above. Deadlines. Retakes.
  Messaging. Anything learner-facing.
- Report types beyond the cohort report and the roster.
- Charts of any kind. Progress bars that carry a number are not charts.
- A quick view version of the learner drill-down. The learner quick view stays as spec 7 left it.
- Mockup elements outside the idea: "Awaiting review", "Pass rate" and its trend, "This week",
  "Message", "Review", retake language, the Instructors and Compliance cards.
- Report retention, scheduled or emailed reports, shareable links (`docs/product/reports.md` Limits
  stay true).

## Decisions

1. **Which data each level reads.** The measurement showed a constant 17 queries. Time was 163 ms at
   30 learners, 555 ms at 100, and 1.7 to 13.9 s at 300, 75% of it in
   `load_selected_options_by_pair`. So: tile counts come from ORM aggregates; attention lists,
   progress figures and the drill-down come from the progress gather; only the Report tab runs the
   full gather.
2. **A short per-cohort cache, not invalidation.** Both cohort gathers are cached in Django's cache
   for `REPORTS_SCREEN_CACHE_SECONDS` (default 300). Every screen that shows cached figures says
   "as of <time>". The Report tab has a refresh control. Event-driven invalidation would couple the
   cache to every progress write path.
3. **Progress figures use the gather's recomputed completion, not
   `CourseProgress.progress_percentage`.** That keeps the dashboard, the Report tab and the PDF on one
   number. The stored percentage has drifted before (the deleted matrix's QA). The learner quick
   view keeps showing the stored percentage; see Open questions.
4. **Removed learners leave the roster.** `load_roster` keeps only memberships whose
   `Learner.is_active` is true, the same predicate `cohort_counts` uses. The PDF changes with it, so
   the report's learner count matches the cohort header and the Learners tab.
5. **`REPORTS_MAX_LEARNERS` still refuses rather than truncates.** A cohort over the limit gets no
   report, on screen or as a PDF. The screen says so in the `ReportTooLargeError` message's terms.
6. **The roster is one CSV with a Role column**, built by a small view rather than the table export
   hook. The hook takes one queryset of one model, and the roster mixes `Learner` rows with
   `cohort_educators(cohort)` pairs.
7. **The drill-down uses a per-learner loader with the gather's shape.** The cohort gather cannot
   cover individually registered courses, and it needs a cohort. It runs live, uncached, since it
   reads one learner.
8. **Presentation stays in `educator_interface`, data in `reports`.** This adds an
   `educator_interface → reports` edge to `docs/app_structure.md`. It is acyclic, since `reports`
   imports neither `educator_interface` nor `panel_framework`.

## Requirements

### `reports`: gathers and cache (`freedom_ls/reports/gather.py`, `indexes.py`, `config.py`)

- `load_roster(cohort, site_id)` filters memberships on `learner__is_active=True` before the
  `REPORTS_MAX_LEARNERS` check, so a removed learner neither appears nor counts toward the limit.
- New `gather_cohort_progress(cohort_id: str, site_id: int) -> CohortProgressData`. It runs the same
  loaders as `gather_cohort_report_data` except `load_first_attempt_ids`,
  `load_selected_options_by_pair`, `load_distractor_rows`, `load_organisation_logo_data_uri` and
  `resolve_site_name`. `CohortProgressData` (in `report_data.py`) holds `cohort_id`, `cohort_name`,
  `generated_at`, `learners: list[LearnerDetail]` (with `wrong_answers` empty),
  `attention_list: AttentionList`, `cohort_size`, `mean_completion: int | None`,
  `median_completion`, `not_started_count` and `complete_count`. `mean_completion` is `None` for an
  empty cohort.
- `gather_cohort_report_data` and `gather_cohort_progress` share their loader sequence, and neither
  copies the other's. For the same cohort and instant, every `LearnerDetail` field except
  `wrong_answers` is equal across the two.
- New `freedom_ls/reports/screen_cache.py` with `cached_cohort_progress(cohort, *, refresh=False)`
  and `cached_cohort_report(cohort, *, refresh=False)`. Each keys on site id, cohort id, gather
  kind and a module-level schema version constant, stores the returned dataclass, and expires after
  `REPORTS_SCREEN_CACHE_SECONDS`. `refresh=True` re-gathers and overwrites. `ReportTooLargeError` is
  not cached; it propagates. The cache holds permission-neutral cohort data; callers authorise
  before reading.
- `ReportsConfig` in `config.py` gains `REPORTS_SCREEN_CACHE_SECONDS: int`, default 300.

### `reports`: per-learner drill-down data (`gather.py`, `indexes.py`)

- New `gather_learner_course_details(learner: Learner, registrations: list[LearnerCourseRegistration | CohortCourseRegistration], site_id: int) -> list[LearnerCourseDetail]`.
  It returns one entry per registration, in the order given. Each `LearnerCourseDetail` holds the
  course title, the registration (cohort name or individual), `completion_percentage`,
  `completed_item_count`, `total_item_count`, `completed_items`,
  `quiz_results: list[QuizResult]` (every attempt with score, percentage and pass state),
  `last_completed_title`, `last_completed_at`, `flags: list[AtRiskFlag]` evaluated over that course
  alone, and `progress_status`.
- It reuses the gather's catalogue, folding, scoring (`_quiz_result_for`, `_score_attempt`) and
  `AT_RISK_RULES`. The loaders it shares learn to take individual registrations as well as cohort
  ones. Its query count is fixed by the courses' structure, never by the attempt count.
- It reads course progress records through `reports/indexes.py`, the read path the domain glossary
  already allows. It adds no new hand-written filter on `CourseProgress`.

### `reports`: one status definition (`freedom_ls/reports/statuses.py`, new)

- `ProgressStatus(TextChoices)`: `NOT_STARTED` "Not started", `IN_PROGRESS` "In progress",
  `COMPLETE` "Complete". `progress_status(completion_percentage: int) -> ProgressStatus` returns 0 →
  not started, 100 → complete, otherwise in progress. `_completion_statistics` uses it for
  `not_started_count` and `complete_count`.
- Attention flags stay as `AT_RISK_RULES` defines them. No other module re-implements a rule or its
  7-day threshold.
- `reports` returns no tones or markup. `educator_interface` maps `ProgressStatus` to badge tones
  (not started → `muted`, in progress → `info`, complete → `success`) and a flag's `severity`
  (`error`, `warning`) straight to the tone of the same name.
- Wherever a learner shows, the progress status badge always shows. Each attention flag adds its
  own badge, labelled with the rule's `label`, and its `reason` is visible on the row, not only in a
  tooltip.

### `reports`: generation and download outside the admin (`freedom_ls/reports/views.py`, new `services.py`)

- Extract from `generate_report_view` a
  `request_cohort_report(cohort: Cohort, user: User) -> GeneratedReport | None` that holds the
  in-flight pre-check, the `transaction.atomic()` create, the `on_commit` enqueue and the
  `IntegrityError` race path. It returns `None` when a report is already in flight. Extract from
  `download_report_view` a `report_file_response(report: GeneratedReport) -> FileResponse`. It keeps
  the slugified `{organisation}-{cohort}-progress-report.pdf` filename and the `Cache-Control:
  private, no-store, must-revalidate` header, and raises `Http404` unless `status == ready` with a
  readable file. The admin views call both, and their tests stay green unchanged.
- `latest_cohort_reports(cohort) -> CohortReportState` returns the in-flight report (if any), the
  newest ready report and the newest failed report newer than that ready one, in one query.

### `educator_interface`: organisation dashboard (`views.py` `DashboardPanel`, `templates/educator_interface/panels/dashboard.html`)

New panels and queries go in a new `freedom_ls/educator_interface/reporting.py` that `views.py`
imports, to keep the shared `views.py` diff small.

- **Visible cohorts** for every figure below: `cohorts_visible_to(request.user, organisation)`
  filtered to `is_active=True`. One queryset feeds the tiles, the list and the cohort rows.
- **Stat tiles** (`c-panel-stat-row` with four `c-panel-stat-tile`):
  - Active learners: `learners_visible_to(user, organisation)` filtered by
    `learner_status_q(LearnerStatus.ACTIVE)`, counted. Sub-line "Across N cohorts".
  - Cohorts: the visible cohort count. Links to the cohorts section.
  - Average progress: the mean of `LearnerDetail.completion_percentage` over every learner row of
    every visible cohort's progress gather, with a `c-panel-progress-bar`. A dash, not 0%, when there are no rows.
  - Learners needing attention: the number of distinct learners with at least one attention flag
    in any visible cohort's progress gather. It is the same set the list below is drawn from.
- **Needs attention list** (`c-panel-attention-list`): one row per flagged learner. Each row names
  the learner, links to their learner page, carries a quick view trigger for `LearnerQuickView`,
  and lists each visible cohort they are flagged in with that cohort's flag badges and reasons.
  Rows are ordered least complete first, as `_build_attention_list` orders. The list shows at most
  `ATTENTION_LIST_MAX` rows and says "N flagged, M shown" in `cap_disclosure.html`'s wording when it
  cuts. When nobody is flagged it says so as a result ("Nobody needs attention right now"), not as
  an error. `panel-attention-row` gains an optional quick view trigger, a `<button>` whose accessible
  name includes the learner's name, that sits beside the row link, not inside it.
- **Cohort progress list**: one row per visible cohort. Each row has the cohort name linked to the
  cohort page, `mean_completion` as a number and a progress bar, the learner count and the flagged
  count. Rows are ordered by lowest mean first, then by name.
- **Freshness and limits**: the panel shows "Figures as of <oldest generated_at among the gathers
  used>". A cohort whose gather raises `ReportTooLargeError` is left out of every figure, and the
  panel names it in a notice ("<cohort> has N learners, over the report limit of M, and is not
  included").
- **Empty states**: no visible cohorts shows "You have no cohorts yet" for an organisation admin
  and "No cohorts are assigned to you" otherwise. No division by zero anywhere.
- The placeholder copy "On-screen reporting for … arrives in a later release" is gone.

### `educator_interface`: cohort page (`CohortTabSet`, `CohortOverviewStack` in `views.py`)

- **Report tab**: a `report` child of `CohortTabSet`, after `learners` and before `settings`. Its
  body loads lazily: the tab's first response is a `c-panel-skeleton` that fetches the body with
  `hx-trigger="load"`. The body renders `cached_cohort_report(cohort)` as panels in the PDF's
  order:
  - At a glance: cohort size, median completion, not started and complete counts.
  - Attention list: flags and reasons, with the cap disclosure.
  - Per course: a summary table of learner rows with the completion and quiz cells, split as
    `summary_tables` split them.
  - Quiz confusion per quiz, with the PDF's below-10-respondents rule (counts, not percentages).

  Section headings match the PDF's. A "Figures as of <generated_at>" line sits at the top with a
  "Refresh" control that re-requests the body with `refresh=1`. A cohort over the limit shows the
  `ReportTooLargeError` message in place of the panels. Per-learner detail with wrong answers is
  not rendered on screen. Each learner name links to the learner page.
- **Downloads** (a panel at the top of the Report tab, visible only when
  `can(user, "freedom_ls_learner_management.download_cohort_report", cohort)`):
  - Idle: a "Generate PDF report" button that POSTs to `request_cohort_report`.
  - In flight: the button is replaced by the text "A report is being generated", requested by
    <name> at <time>. The region polls every 3 s and its response drops the trigger once the report
    is ready or failed. The region is `role="status"` / `aria-live="polite"`.
  - Ready: "Download PDF (generated <time> by <name>)" linking to a new download route that
    authorises the cohort and calls `report_file_response`. "Generate a new report" stays offered.
  - Failed: the report's `error_message` and a retry button.
  - A POST that loses the in-flight race returns the in-flight state, not an error.
  - "Download roster (CSV)" with one line saying what it includes.
- **Overview "Needs attention" card** (`CohortNeedsAttentionPanel`): rendered from
  `cached_cohort_progress(cohort).attention_list`, with flag badges, reasons, learner links and the
  cap disclosure. The `{% comment %}TODO …{% endcomment %}` in `cohort_needs_attention.html` is
  removed, since this completes it.
- **Roster CSV route** under the cohort instance: `text/csv; charset=utf-8`, prefixed with
  `UTF8_BOM`, written with `csv.writer`, every text cell through `escape_csv_formula`
  (`freedom_ls/base/csv_safety.py`). Columns: Name, Email, Role, Status. Learner rows carry Role
  "Learner" and Status from `learner_status`. Removed learners are excluded. Organisation member
  rows come from `cohort_educators(cohort)`, with the role display name and Status left blank.
  Learners come first in report order, then members in `cohort_educators` order. The filename is
  `{organisation-slug}-{cohort-slug}-roster-{YYYY-MM-DD}.csv`. The route requires `view_cohort` on
  the cohort, through the same authorisation as the cohort instance.

### `educator_interface`: learner drill-down (`LearnerCoursesPanel`, `templates/educator_interface/panels/learner_courses.html`)

- Built from `gather_learner_course_details(learner, registrations, site_id)`, where
  `registrations` are the ones `visible_registrations_with_progress` already shows. Registrations
  through a cohort the viewer cannot see stay hidden.
- One card per registration, with:
  - the course title, "via <cohort>" or "Individual", and the progress status badge plus any flag
    badges with reasons;
  - a progress bar with "N of M items";
  - the last completed item and when;
  - the completed items, collapsed by default;
  - an attempts table per quiz: attempt number, completed date, score, percentage, pass mark and
    a "Passed" / "Failed" badge with the word, the latest attempt marked.
- "Not registered on any courses yet" when there are none.

### Permissions

- Every new route and panel goes through the existing organisation authorisation and the cohort or
  learner `authorise_instance`. A cohort or learner outside the viewer's scope is a 404.
- Generate and download check `download_cohort_report` with `can()` once per request, never per
  row. The download route also checks that the report belongs to the cohort in the URL.
- Cohort admins and cohort viewers see dashboard figures computed only over their assigned cohorts.

### Mobile

At phone width the tiles go two-up and the attention and cohort rows become two-line rows with
the whole row tappable. Each summary table scrolls horizontally inside its card with the learner
column sticky, and the download buttons go full width.

## Testing

- `load_roster` excludes a removed learner, and the limit counts active learners only.
- `gather_cohort_progress` runs no answer, distractor or logo loader (query count below the full
  gather's), and its `LearnerDetail` values match the full gather's apart from `wrong_answers`.
- The query count of `gather_learner_course_details` stays constant across 1 and 3 attempts per
  quiz and across a cohort and an individual registration. Its flags and percentages for a
  cohort-registered course equal the cohort gather's for that learner.
- `screen_cache`: a second read within the TTL runs no queries, `refresh=True` re-gathers, keys
  differ by site and kind, and `ReportTooLargeError` is not cached.
- `progress_status` at 0, 1, 99 and 100.
- Dashboard, per role (`organisation_admin`, `cohort_admin`, `cohort_viewer`) with a second
  out-of-scope cohort and a second site seeded: every tile, the list and the cohort rows count only
  the visible cohorts. The attention tile equals the distinct learners in the list. Empty states
  and the over-limit notice render.
- Report tab: the skeleton loads the body, figures equal the gather's, the refresh parameter
  bypasses the cache, and the over-limit message replaces the panels.
- Downloads: generate creates one `GeneratedReport` and enqueues once. A second POST returns the
  in-flight state, and polling stops on ready and on failed. Download returns the PDF for a ready
  report and 404s for pending, failed, another cohort's report, or a viewer without the capability.
- Roster CSV: columns and order, BOM present, a name of `=HYPERLINK("x","y")` neutralised, a
  non-ASCII name and a comma-quote-newline name round-trip through `csv.reader`, removed learners
  absent, and a cohort viewer of another cohort gets a 404.
- Learner drill-down: hidden-cohort registrations stay hidden, attempts render with pass state, and
  the empty state renders.
- `educator_interface/tests/invariants/test_permission_matrix.py` exercises `download_cohort_report`
  (its docstring names this as a gap). `test_dashboard.py`'s placeholder assertion is replaced.
- Playwright: generate a report on the cohort page and see it move from "being generated" to a
  download link (ImmediateBackend), and the dashboard at phone width.

## Open questions

- The learner quick view and the learner list's Courses cell show
  `CourseProgress.progress_percentage`, while the drill-down and dashboard show the recomputed
  completion. They can disagree for the same course. Is moving the quick view onto the recomputed
  figure a spec 12 item?
- `ATTENTION_LIST_MAX` (12) caps the dashboard list, and nothing lists every flagged learner across
  cohorts. Is a "view all" page wanted later?
- A `pending` `GeneratedReport` whose task is never picked up keeps the cohort "being generated"
  until the task layer's late-task handling acts. Is that acceptable, or should the housekeeping
  sweep also close old pending rows?

## Success criteria

- `/educator/<org>/dashboard` shows the four tiles, the needs-attention list and the cohort progress
  list. A cohort viewer's figures cover only their cohorts.
- The cohort page has a Report tab whose figures equal the PDF's for the same cohort and instant.
- An educator with `download_cohort_report` can generate and download the PDF from the cohort page
  without the Django admin.
- The cohort Overview's "Needs attention" card lists flagged learners.
- The roster CSV downloads with learners and role holders, opens correctly in Excel, and
  neutralises formula cells.
- The learner Courses tab shows per-course attempts with score and pass state.
- A removed learner appears in neither the on-screen report nor the PDF.
- No figure on screen reads `CourseProgress.progress_percentage` except where an earlier spec
  already did.
- `uv run pytest` passes, including the new permission-matrix case.
