# Spec: Articles

## Purpose

A site needs a public blog: pages anyone can read without logging in, written as markdown in the
content repo alongside course content. They are loaded by `content_save`, checked by the validator
and use the same widgets. The settled approach is in `idea.md`. This spec adds the `Article` content
type, a new leaf app `freedom_ls/blog` that serves the public index and article pages, and four
widgets: an inline article link, an article card, a course card and a general grid.

Inputs: `idea.md`, `research_content_pipeline_fit.md`, `research_course_card_widgets.md`,
`research_blog_features_and_ux.md`, `research_content_editing_plugin.md`.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| `Article` | coined | A standalone markdown content item (`ContentType.ARTICLE`) that belongs to no course and can be read publicly. Not in the glossary, and no model uses the word. |
| blog | coined | The public index that lists a site's published articles, served by the `freedom_ls/blog` app. |
| byline | coined | The line under an article's title that shows its `published_on` date and its `author`, each only when shown. |
| `ArticleVisibility` | narrowed | Same idea as `CourseVisibility` (`content_engine/models/courses.py:42`), with only `published` and `hidden`. |

Say "article" in identifiers, never "post" or "page" (`Topic` is "a page of markdown" and `FormPage`
and `<c-page>` already exist). Always qualify "card": article card, course card. `c-card` is a
different, existing widget.

## Scope

In:

- The `Article` model, pydantic schema, loader pass and admin, all in `content_engine`.
- The `freedom_ls/blog` leaf app: the blog index, the article page, sitemaps and a URL-prefix
  setting.
- SEO for article pages: title, meta description, canonical, Open Graph, Twitter card, sitemap
  entries and a `robots.txt` allow line.
- Widgets: `c-article-link` and `c-article-card` (`content_engine`), `c-course-card`
  (`learner_interface`), and `c-grid` (`content_engine`), with `c-image-grid` delegating to
  `c-grid`.
- A body-scanning validator pass, in the host validator and in the bundled offline copy.
- Updates to the `fls-content` plugin, the docs and the demo content.

Out (later specs, listed in `idea.md`): article images (`spec_dd/1. next/article-images/`),
tags and tag pages, RSS/Atom, JSON-LD, slug redirects, related articles, a staff preview of hidden
articles, author pages, scheduled publishing, pagination, a nav link to the blog, caching of the
public pages, and repairing `c-content-link`.

## Decisions

- **Article widgets live in `content_engine`. The course card lives in `learner_interface`.** A
  course card needs the access badge from `course_access`. `content_engine` cannot import
  `course_access` because that would create a cycle. `learner_interface` already owns
  `course-card-shell`, `course-row-shell`, `c-course-price`, `card_title_link.html` and
  `course_detail`, and already depends on `course_access`, so the course card adds no new app edge.
  Cotton component names are global, so the widget works in any markdown.
- **The only new app edge is `blog -> content_engine`.** Content_engine widgets reach the article
  page through `reverse("blog:article_detail")`, which is a string and needs no import. When the
  blog app is not installed they degrade (see Widgets).
- **The admin can delete an article**, unlike every other content admin
  (`has_delete_permission -> False`). That is the only way to take down an article whose file was
  removed. `content_save` never deletes an article. Deleting an article whose file is still in the
  repo is undone by the next `content_save`, because the uuid in the file recreates it.
- **An article whose file is removed stays live** until it is deleted in the admin. `content_save`
  does not hide it.
- **`published_on` is required** and is a `DateField`, so `USE_TZ` never shifts the day. The `_on`
  suffix follows `Course.price_sale_ends_on`, so it does not read as a visibility gate.
- **The link text of `c-article-link` is required.** A link to a hidden article renders that text
  as plain text and never shows the target's title, so a hidden title never reaches a public page.
- **The URL prefix is read in exactly one place**, the root URLconf include. Everything else
  (sitemap, robots, widgets, templates) uses `reverse()`. An installing project can skip the setting
  and mount `freedom_ls.blog.urls` itself.
- **Hidden and unknown slugs return the same 404**, never a 410, which would confirm the slug once
  existed.
- **No `lastmod`, `changefreq` or `priority` in the article sitemaps.** `updated_at` changes on
  every `content_save`, even a no-op, so it is not a trustworthy `lastmod`.

## Requirements

### Content model (`freedom_ls/content_engine`)

- `freedom_ls/content_base/schema.py` `ContentType`: add `ARTICLE = "ARTICLE"`.
- New `freedom_ls/content_engine/models/articles.py`:
  - `ArticleVisibility(models.TextChoices)`: `PUBLISHED = "published"`, `HIDDEN = "hidden"`.
  - `Article(TitledContent, MarkdownContent)` with `CONTENT_TYPE = SchemaContentTypes.ARTICLE`.
    Its fields come from the bases (`title`, `subtitle`, `description`, `slug`, `content`,
    `file_path`, `meta`, `tags`) plus:
    - `published_on = DateField()`
    - `author = CharField(max_length=200, blank=True)`
    - `visibility = CharField(max_length=20, choices=ArticleVisibility, default=PUBLISHED, db_index=True)`
    - `show_date = BooleanField(null=True)` and `show_author = BooleanField(null=True)`: `None`
      means use the site-wide default.
  - `UniqueConstraint(fields=["site", "slug"], name="unique_article_slug_per_site")`.
  - `Meta.ordering = ["-published_on", "slug"]`. The slug breaks ties, so equal dates sort the
    same way on every request.
  - A queryset method `published()` (visibility `published`), exposed on the site-aware manager.
    The index, the article view, the sitemap and both article widgets all use it, so no public
    query can forget the visibility filter.
  - Properties `shows_date` (`show_date`, else `config.ARTICLE_SHOW_DATE`) and `shows_author`
    (false when `author` is empty, otherwise `show_author`, else `config.ARTICLE_SHOW_AUTHOR`).
  - `get_absolute_url()` reverses `blog:article_detail` with the slug.
- Re-export `Article` and `ArticleVisibility` from `models/__init__.py` and add them to `__all__`.
- Migration `0006_...` in `freedom_ls_content_engine`.
- `freedom_ls/content_engine/config.py` `ContentEngineConfig`: add `ARTICLE_SHOW_DATE: bool`
  (default `True`) and `ARTICLE_SHOW_AUTHOR: bool` (default `True`). They live here rather than in
  the blog app because the content_engine article card reads them.
- `freedom_ls/content_engine/factories.py`: `ArticleFactory`, the same shape as `TopicFactory`, with
  `published_on` and `visibility` set.

### Schema (`freedom_ls/content_engine/schema.py`)

`ArticleVisibility(StrEnum)`, which mirrors the model enum, and
`class Article(BaseContentModel, MarkdownContentModel, content_type=ContentType.ARTICLE)` with:

| Frontmatter key | Type | Rule |
| --- | --- | --- |
| `title`, `subtitle`, `description`, `tags`, `meta`, `uuid` | inherited | `description` doubles as the index blurb and the meta description |
| `slug` | `str \| None` | Must match `SLUG_PATTERN.fullmatch` (`schema.py:45`). When absent, a `model_validator` fills it from `file_path`: `slugify` of the file stem, or of the parent directory name when the file is `content.md` |
| `published_on` | `date` | required |
| `author` | `str \| None` | plain name |
| `visibility` | `ArticleVisibility` | default `published`. `coming_soon` is rejected |
| `show_date`, `show_author` | `bool \| None` | override the site-wide default |

`category` and `image` are rejected with a clear message, following `_category_is_retired`
(`schema.py:343-353`). Without that, `image` would fail later in `save_with_uuid` with a generic
"field doesn't exist" error. Unknown keys are already rejected by `extra="forbid"`.

### Loader (`freedom_ls/content_engine/management/commands/content_save.py`)

- `save_article(item, site, base_path)` beside `save_topic`. It calls
  `save_with_uuid(Article, item, site, base_path, derive_slug=False, ...)`, and its pass runs after
  the `ACTIVITY` pass.
- `_refuse_article_slug_collisions` runs before saving, modelled on
  `_refuse_category_slug_collisions` (`:365-394`). When a different uuid already holds the same
  `(site, slug)`, it raises a `ValueError` that names the owner. A slug is never silently suffixed,
  because that would change a public URL.
- Removing `author`, `show_date` or `show_author` from the file clears the stored value. The
  default `exclude_none` dump would otherwise keep the stale value. `save_article` passes these
  explicitly.
- The course-directory scan (`:985-999`) skips `ARTICLE` files the same way it skips
  `COURSE_CATEGORIES`. An article can sit anywhere in the repo, including inside a course
  directory, and is never adopted as a collection child. No validator rule governs placement.
- Articles are never deleted by the loader. That needs no new code, and a test pins it.

### Admin (`freedom_ls/content_engine/admin.py`)

`ArticleAdmin(SiteAwareModelAdmin)`, modelled on `TopicAdmin`:

- `list_display`: title, slug, `published_on`, visibility.
- `list_filter` includes visibility and `ContentTagListFilter`.
- `slug` and `visibility` are read-only, because the repo owns them.
- **`has_delete_permission` is allowed.** The fieldset or `help_text` warns that an article whose
  file is still in the repo comes back on the next `content_save`.

### Blog app (`freedom_ls/blog`, new)

- `apps.py`: `name = "freedom_ls.blog"`, `label = "freedom_ls_blog"`. The label prefix is enforced
  by `contrib/conformance/tests/test_app_labels.py`. `ready()` imports `checks`. `meta_pixel` is the
  layout to copy.
- `config.py`: `BlogConfig(AppSettings)` with `BLOG_URL_PREFIX: str`, default `"articles"`.
- `checks.py`: `freedom_ls_blog.E001` when `BLOG_URL_PREFIX` doesn't match
  `[a-z0-9-]+(/[a-z0-9-]+)*`. An empty prefix, a leading or trailing slash and anything else fail.
- `urls.py`: `app_name = "blog"`. `""` maps to `article_list` (name `index`), and `"<slug:slug>/"`
  maps to `article_detail` (name `article_detail`).
- `views.py`:
  - `article_list`: `Article.objects.published()` (site-scoped through the manager), newest first.
    No pagination. One query.
  - `article_detail`: `get_object_or_404(Article.objects.published(), slug=slug)`. Neither view
    requires a login.
- `templates/blog/article_list.html`: extends `_base.html` and uses `<c-page>`, following
  `all_courses.html`. It has an H1 and, for each article, its title (linked), byline date when
  `shows_date`, and `description`. When there are no articles it shows an empty state.
- `templates/blog/article_detail.html`: extends `_base.html`.
  - It renders `<h1>{{ article.title }}</h1>`, the subtitle when present, the byline, and then
    `{{ article.rendered_content }}`. Body `#` already renders as H2 through `mdx_headdown`.
  - The byline renders the date as `<time datetime="YYYY-MM-DD">` through Django's `date` filter,
    only when `shows_date`. It renders `author` only when `shows_author`.
  - The page has no learner UI, progress or registration state.
- SEO on `article_detail.html`. Only block names that exist in `_base.html` are used; there is no
  `canonical_link` block.
  - `head_title` is the title, following `course_detail.html`.
  - `meta_description` is `description`, else `subtitle`, else `title`, passed from the view as
    plain text the way `course_detail` does it (`views.py:757-762`).
  - `og_type` is `article`. `og_title` is the title and `og_description` is the same value as
    `meta_description`.
  - `extra_head` adds `<meta property="article:published_time">` (the ISO date) when `shows_date`,
    and `<meta name="author">` when `shows_author`. There is no `article:author`, because Open Graph
    expects a profile URL there.
  - `og_image` is left untouched, so it gets the site default. `twitter_card` stays at the base
    default, `summary`.
  - The default canonical link and `og:url` from `{% canonical_url %}` are already correct and are
    not overridden.
- `sitemaps.py`: `BlogIndexSitemap` (one item, `blog:index`) and `ArticleSitemap` (`items()` is
  `Article.objects.published()`, and `location()` is `get_absolute_url()`).

### Widgets

All four widgets identify their target by a `path` relative to the file that uses them. The path
resolves through `content_instance.calculate_path_from_root`. Lookups are site-scoped with
`Model._base_manager.filter(site_id=content_instance.site_id, file_path=...)`. The thread-local
manager is not relied on, because widgets render with `request=None`. Card titles are H3 links with
one stretched overlay (`card_title_link.html`) and no second link. Cards are responsive at the
375 px QA phone viewport: no horizontal scroll, and the title and description wrap. The row variant
follows `course-row-shell` (narrow accent strip, `min-w-0` text column). If the row variant doesn't
hold up at 375 px, it collapses to the compact layout below `sm`.

- **Lookup filters** in `freedom_ls/content_engine/templatetags/content_tags.py`, beside
  `get_content_by_path`, which stays unchanged:
  - `get_published_article_by_path(path, content_instance)` returns a published `Article` or
    `None`.
  - `article_url(article)` returns `get_absolute_url()`, or `""` on `NoReverseMatch` (the blog app
    is not installed).
- **`c-article-link`** (`content_engine/templates/cotton/article-link.html`, precedent
  `content-link.html`):
  - `<c-article-link path="../other.md">link text</c-article-link>`.
  - A published target with a URL renders `<a href>` around the slot.
  - Otherwise it renders the slot as plain text. That covers a hidden target, a missing target and a
    project without the blog app.
  - It never renders the target's title and never renders an error span on a public page.
- **`c-article-card`** (`content_engine/templates/cotton/article-card.html`, precedents `card.html`
  and the two course shells):
  - Attributes: `path` and `variant`. `variant` takes `row` (the default; a long horizontal card) or
    `compact` (for grids). Any other value falls back to `row`.
  - It shows the target's title as the stretched H3 link, its `description`, and the byline date
    and author when the target's `shows_date` / `shows_author` allow them.
  - It renders nothing when the target is hidden or missing, or when the blog app is absent.
- **`c-course-card`** (`learner_interface/templates/cotton/course-card.html`, with a new tag module
  `learner_interface/templatetags/course_card_tags.py`):
  - Attributes: `path` (to a `course.md`) and `variant` (`row` → `course-row-shell`, `compact` →
    `course-card-shell`; anything else → `row`).
  - It shows the title, `subtitle` or else `description`, the price through `<c-course-price>` using
    `course.current_price()` (no tax note; a course with no price shows the badge and no price
    line, never "$0"), difficulty (`get_difficulty_display`), estimated
    duration (`display_estimated_duration`), and the access badge from
    `get_course_access_backend().get_access_badge(course=course)`, rendered as `<c-chip>` the way
    `course_row.html:49-51` does. It never reads `access_config`.
  - Its one link is the stretched title link to `learner_interface:course_detail`, with neutral
    wording.
  - It renders nothing for a missing course or a `hidden` course. `coming_soon` courses show.
  - `course_card.html` and `course_row.html` are not reused, because they carry status and
    progress.
- **`c-grid`** (`content_engine/templates/cotton/grid.html`, precedent `image-grid.html`):
  - `columns` keeps the whitelist behaviour of `image-grid.html:21-27`: `2` and `4` get their own
    layouts, and anything else gets 3. Each value maps to literal Tailwind class strings, and the
    grid is one column on phones.
  - Children render with `{{ slot }}`. Pictures keep the figure-neutralising rule, and cards fill
    the cell (`h-full`).
  - `image-grid.html` becomes a wrapper that passes `columns` to `<c-grid>`. Existing
    `c-image-grid` content renders the same as before.

### Validator

The new cross-file pass `validate_widget_references(all_parsed) -> list[str]` goes in
`freedom_ls/content_engine/validate.py`. It is called from `validate()` beside
`validate_category_references` and modelled on it: it collects every error and reports each with
`_category_reference_error`'s block shape.

- It scans the `content` of every parsed item that has a body, for `c-article-link`,
  `c-article-card` and `c-course-card` tags.
- It resolves each `path` against the item's `file_path.parent`. The error cases are:
  - the target isn't in `all_parsed`;
  - an article widget's target isn't an `ARTICLE`;
  - a course card's target isn't a `COURSE`;
  - a `c-article-link` has empty or whitespace-only link text, or is self-closing.
- A target outside the validated path counts as missing, the same limitation the category pass
  has.
- Duplicate article slugs among the parsed articles are an error that names both files.
- The same pass and the `ARTICLE` schema are ported to `claude_plugins/fls-content/validate/`
  (`schema.py`, `validate.py`), following the patch headers there. The bundled copy has to pass
  mypy and ruff.
- `claude_plugins/fls-dev/commands/update_claude_plugin_fls_content.md` Step 1 regex: add
  `freedom_ls/learner_interface/templates/cotton/course-card\.html`, so a change to the course card
  triggers a sync.

## Testing

- **Schema:** `ContentType`/`SCHEMAS` parity (`test_schema_registry.py`) passes. The `slug`
  default comes from the stem, or from the directory for `content.md`. A bad slug is rejected.
  `published_on` is required. `coming_soon`, `category` and `image` are rejected.
- **Loader** (modelled on `test_content_save_course_categories.py`):
  - an article loads and its uuid is written back;
  - a second load is byte-identical;
  - a slug collision with another uuid is refused, naming the owner;
  - a missing `slug` gives the stem;
  - removing `author`/`show_date`/`show_author` clears them;
  - an `ARTICLE` file inside a course directory loads as an article and is not a collection child;
  - a removed file leaves the row in place.
- **Model:** `published()` excludes hidden articles. `shows_date` and `shows_author` honour the
  overrides, the settings, and an empty author. Ordering ties break by slug.
- **Admin:** `ArticleAdmin` allows delete. `slug` and `visibility` are read-only.
- **Views:**
  - the index lists published articles only, newest first, for the current site only, logged out,
    with an empty state;
  - the article page returns 200 logged out;
  - a hidden slug and an unknown slug both return 404 with identical responses;
  - an article on another site returns 404;
  - the byline obeys `shows_date`/`shows_author`;
  - the `<title>`, meta description, `og:type=article`, `og:title`, `og:description`,
    `article:published_time` (absent when the date is hidden) and canonical are correct;
  - no `og:image` is emitted by default.
- **Sitemap and robots** (extend `learner_interface/tests/test_seo_discoverability.py` or add
  blog tests): the sitemap contains the index and published articles and excludes hidden articles
  and other sites' articles. `robots.txt` contains `Allow: /articles/`. Under a changed
  `BLOG_URL_PREFIX` with the URLconf reloaded, the robots line and the sitemap URLs follow it.
- **Checks:** `freedom_ls_blog.E001` fires for an empty prefix, a slash-wrapped prefix and a prefix
  with unsafe characters, and not for `articles` or `news/blog`.
- **Widgets** (`test_content_tags.py`, `test_markdown_utils.py`):
  - `c-article-link`: a published target gives a link. Hidden, missing and blog-not-installed
    targets give plain slot text and never the target title.
  - `c-article-card`: each variant renders; an unknown variant falls back to `row`; byline fields
    follow the target; hidden or missing targets render nothing.
  - `c-course-card`: each variant renders; the price and the badge come from the backend (Free, By
    application); there is no tax note; a hidden course renders nothing; a coming-soon course
    renders; the link goes to `course_detail`.
  - `c-grid`: `2`, `3`, `4` and an invalid value produce the expected classes.
  - `c-image-grid`: renders the same as before.
  - All four new tags survive `render_markdown` with the FLS allowlist.
  - Lookups are scoped to `content_instance.site_id`. The same `file_path` on another site is not
    returned.
- **Validator, host and bundled:**
  - a broken path in each of the three widgets is reported;
  - a wrong target type is reported;
  - empty link text is reported;
  - duplicate article slugs are reported;
  - a valid tree passes.
- **Demo content:** `loaded_demo_content` loads with the new articles, and the existing

- **Playwright / QA:** at 375 px, 768 px and desktop, the article page, the index and the demo grid

## Open questions

Defaults taken, which the user can overrule:

- The frontmatter key is `published_on`, not `date`.
- The index H1 is "Articles", whatever the prefix.
- The default slug for `content.md` is the directory name passed through `slugify`, so a numbering
  prefix such as `1. ` stays in the slug.
- There is no nav link to the blog. Installing projects add their own.
