# Spec: Slow and redundant tests are cut from a measured ranking

## Purpose

One command records every test's cost in a full run and writes a committed ranking. The tests at
the top of that ranking that cost the most for the least are merged, rewritten or removed until the
full run meets a CPU-time target set from the first ranking. The case is in `idea.md`.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| test cost | coined | A test's setup + call + teardown seconds from pytest's `TestReport.duration`, less any `django_db_setup` time. No existing term: the code has no per-test timing. |
| ranking | coined | `test_organisation/test_cost_ranking.md`, the generated file this spec adds. |
| ranking run | coined | One run of `scripts/rank_test_costs.py`. |

## Scope

In:

- A pytest plugin that records test cost per node id, and a script that runs the suite with it and
  writes the ranking.
- Merging, rewriting or removing tests found through the ranking. Rewriting includes cheaper
  setup: `build()` in place of `create()`, shared class- or module-scoped data, dropping
  `django_db(transaction=True)` where no test needs real commits, and fewer parametrized cases.
- `timings.md` in this spec directory: baseline, target and result.
- The refresh command in `claude_plugins/fls-dev/skills/testing/SKILL.md`.

Out:

- Playwright tests (`faster-test-runs-4-playwright-tests`) and
  `educator_interface/tests/invariants/test_permission_matrix.py`
  (`faster-test-runs-3-permission-matrix-test`). The ranking run leaves both out.
- Per-session cost: database creation and migrations (`faster-test-runs-2-reuse-test-database`),
  collection.
- `.github/workflows/tests.yml`, `claude_plugins/django-stack/scripts/run_tests.py`,
  `select_tests.py`, `claude_plugins/django-stack/resources/test_tiers.md` and
  `[tool.test_tiers]`. Sibling specs own them.
- The standalone `panel_framework` and `icons` runs.
- Any per-test time limit. The existing `timeout = 300` in `pyproject.toml` stays the only one.

## Decisions

- **The ranking is refreshed by hand, by one command.** CI can call the same command later.
- **Report only.** Nothing fails because a test is slow; timings on a machine shared with other
  worktrees are too noisy for a limit.
- **The plugin is loaded with `-p`, not from a conftest.** `freedom_ls/conftest.py` is star-imported
  by concrete projects, and the ranking is an FLS development tool.
- **Per-test cost is wall time; the target is CPU time.** pytest reports per-phase wall durations.
  The run's total CPU time (user + sys of pytest and its xdist workers) is the steadier number to
  hold a target against. Postgres CPU is in neither.
- **Fixed conditions.** `-n 4`, no coverage, `-p no:randomly`, the tier markers
  `not ci_only and not weasyprint` plus `not playwright`. The ranking compares runs only when the
  conditions match.
- **A removal needs a named covering test that asserts the same behaviour.** Executing the same
  lines is not enough. The name goes into `pruned_tests.md`; no per-test sign-off beyond that.
- **The target is fixed from the first ranking, before any test changes.** It is written into
  `timings.md` and into this spec's Success criteria.

## Requirements

### Recording: `scripts/test_cost_recorder.py`

- A pytest plugin module, loaded as `-p scripts.test_cost_recorder`.
- `pytest_runtest_logreport` collects `report.duration` per `report.nodeid` and `report.when`
  (`setup`, `call`, `teardown`).
- A `pytest_fixture_setup` hookwrapper times the `django_db_setup` fixture and subtracts that time
  from the setup phase of the test that triggered it. The plugin records database creation once
  per worker as its own figure, so the first test on each worker does not top the ranking.
- Under xdist only the controller writes: it skips the write when `config` has `workerinput`. The
  controller receives every worker's reports.
- At `pytest_sessionfinish` it writes `.sdd-work/test_costs.json`: per node id, the three phase
  seconds; plus the run's database-setup seconds, test count, and outcome counts. `.sdd-work/` is
  already gitignored.

### Ranking: `scripts/rank_test_costs.py`

- `uv run python scripts/rank_test_costs.py` with no arguments runs:

  ```bash
  uv run pytest -p scripts.test_cost_recorder -p no:randomly -n 4 --no-cov \
    -m "not ci_only and not weasyprint and not playwright" \
    --ignore=freedom_ls/educator_interface/tests/invariants/test_permission_matrix.py
  ```

  and records the CPU time of that subprocess tree with `resource.getrusage(RUSAGE_CHILDREN)`
  (user + sys). It exits non-zero, writing no ranking, when pytest exits with failures.
- It reads `.sdd-work/test_costs.json` and writes `test_organisation/test_cost_ranking.md`:
  - A first line: `Generated by uv run python scripts/rank_test_costs.py. Do not edit by hand.`
  - A header: date, commit SHA, test count, total CPU seconds, wall seconds, summed test cost,
    database-setup seconds, and the run conditions.
  - A per-app rollup (`freedom_ls/<app>`, `tests`, `claude_plugins/fls-content`): test count,
    seconds, share of summed cost.
  - The top 50 files by cost: file, test count, seconds, share.
  - The top 200 test functions by cost, parametrized cases grouped under the function: node id
    with its `[...]` suffix stripped, case count, total seconds, mean per case, setup share, share
    and cumulative share of the summed cost.
- A function's grouping key splits the node id on `::` first, then strips from the first `[` in the
  last segment, so a parameter id holding `::` or `[` groups correctly.
- Seconds are rounded to one decimal, shares to whole percent. Rows are sorted by seconds, then by
  node id, so the file diffs line by line.
- The full per-test data stays in `.sdd-work/test_costs.json` and is not committed.

### Pruning

- Work goes down the ranking's top functions by total seconds. Each candidate is merged (one test,
  or parametrized cases with distinct ids, sharing one setup), rewritten cheaper, removed, or left
  with a one-line reason.
- A removal, or a merge that drops an assertion, names in `pruned_tests.md` the test that still
  asserts the same behaviour, and the difference between the two if any.
- A merge keeps a failure message that names the behaviour that broke: parametrize or label each
  assertion rather than chaining unrelated asserts.
- When a whole test file is removed or renamed, `test_organisation/mirroring_baseline.txt` and
  `test_organisation/import_baseline.txt` are updated as the `check_test_mirroring.py` and
  `lint-imports` checks require. No entry is removed except for that file.
- Coverage: CI's unit-job selection, `uv run pytest -m "not playwright and not dev_tooling" -n auto
  --cov --cov-fail-under=92`, passes before and after. No file under `freedom_ls/` loses a covered
  line or branch; `pruned_tests.md` lists the per-file comparison.
- Test files touched by an in-progress spec (`form_engine/tests/` by
  `sacaa-compliance-3-question-pools`, `educator_interface/tests/` by `educator-interface-refactor-*`)
  are pruned only when the gain covers a likely rebase conflict; `pruned_tests.md` says which were
  skipped for that reason.

### Records in this spec directory

- `timings.md`: the baseline ranking run's totals, the target with the rule that set it, the final
  ranking run's totals, and the result against the target. It also gives the
  `freedom_ls/accounts` and `freedom_ls/course_access` test-body times measured as
  `spec_dd/1. next/faster-test-runs/research_test_timings.md` measured them, before and after.
- `pruned_tests.md`: one row per changed test function: node id, action, seconds before and after,
  covering test (for a removal), reason. Then the per-file coverage comparison.

## Testing

`tests/test_rank_test_costs.py`, marked `dev_tooling`, as the other script tests in `tests/` are.

- The plugin, run through `pytester` on a small suite with and without `-n 2`, writes one entry per
  node id with three phase seconds, and only the controller writes.
- A test that triggers `django_db_setup` is ranked without the database-setup time, and the
  file reports that time separately.
- Grouping: `a.py::test_x[1]` and `a.py::test_x[2]` group under `a.py::test_x`;
  `a.py::TestC::test_y[p::q]` groups under `a.py::TestC::test_y`.
- The written ranking from a fixed `test_costs.json` matches an expected file exactly: header,
  rollups, ordering, rounding, the top-200 cut.
- A pytest run with failures leaves the existing ranking unchanged and exits non-zero.

## Documentation and downstream

- `claude_plugins/fls-dev/skills/testing/SKILL.md`: a section "The slow-test ranking" with the
  command, when to run it (after pruning, or when the suite feels slower), its run time, what the
  file holds, and that nothing fails on slowness.
- No upgrade notes beyond the changed test list: concrete projects do not load the plugin, and FLS
  ships no changed fixture or setting.

## Open questions

- Q: Where does the committed ranking live? → A: `test_organisation/test_cost_ranking.md`
  (assumed default: that directory already holds the suite's committed metadata. Overrule by
  editing Requirements, "Ranking".)
- Q: When does pruning stop if the target is met early or cannot be met? → A: at the target, or
  when the next function's total cost is under 0.5% of the baseline summed test cost, whichever
  comes first; `timings.md` says which (assumed default: below that the review costs more than it
  saves. Overrule by editing Requirements, "Pruning".)
- Q: How many rows does the ranking keep? → A: 200 functions and 50 files (assumed default: enough
  to show the curve flattening without thousands of churning lines. Overrule by editing
  Requirements, "Ranking".)

## Success criteria

- `uv run python scripts/rank_test_costs.py` writes `test_organisation/test_cost_ranking.md`, and
  the file is committed from the final ranking run.
- `timings.md` records baseline, target and result, and the result's total CPU seconds are at or
  under the target.
- Every removal in `pruned_tests.md` names a covering test.
- CI's unit-job coverage command passes at 92%, and no `freedom_ls/` file loses a covered line or
  branch.
- `uv run pytest` passes.
- No diff in `.github/workflows/tests.yml`, `run_tests.py`, `select_tests.py`, `test_tiers.md` or
  `[tool.test_tiers]`.
