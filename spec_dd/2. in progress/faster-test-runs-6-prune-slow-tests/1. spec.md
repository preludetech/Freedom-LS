# Spec: Slow and redundant tests are cut from a measured ranking

## Purpose

One command records every test's cost and writes a committed ranking. The tests at the top of that
ranking that cost the most for the least are merged, rewritten or removed until the ranking run
meets a CPU-time target set from the first ranking run. The case is in `idea.md`.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| test cost | coined | A test's setup + call + teardown seconds from pytest's `TestReport.duration`, less any `django_db_setup` time. |
| ranking | coined | `test_organisation/test_cost_ranking.md`, the generated file this spec adds. |
| ranking run | coined | One run of `scripts/rank_test_costs.py`. Not the `full` tier in `claude_plugins/django-stack/resources/test_tiers.md`: it uses other markers, `-n 4` and no Playwright. |
| test-body time | narrowed | The `call` phase only, as `spec_dd/1. next/faster-test-runs/research_test_timings.md` uses it. |

## Scope

In:

- A pytest plugin that records test cost per node ID, and a script that runs the suite with it and
  writes the ranking.
- Merging, rewriting or removing tests found through the ranking. Rewriting includes cheaper
  setup: `build()` in place of `create()`, shared class- or module-scoped data, dropping
  `django_db(transaction=True)` where no test needs real commits, and fewer parametrized cases.
- `timings.md` and `pruned_tests.md` in this spec directory.
- The refresh command in `claude_plugins/fls-dev/skills/testing/SKILL.md`.

Out:

- Playwright tests (`faster-test-runs-4-playwright-tests`) and
  `educator_interface/tests/invariants/test_permission_matrix.py`
  (`faster-test-runs-3-permission-matrix-test`). The ranking run leaves both out.
- `ci_only` and `weasyprint` tests. The ranking run leaves them out, so the CPU target does not
  cover them.
- Per-session cost: database creation and migrations (`faster-test-runs-2-reuse-test-database`),
  collection.
- `.github/workflows/tests.yml`, `claude_plugins/django-stack/scripts/run_tests.py`,
  `select_tests.py` and `test_tiers.md`. Sibling specs own them.
- The standalone `panel_framework` and `icons` runs.

## Decisions

- **The ranking is refreshed by hand, by one command.** CI can call the same command later.
- **Report only.** Nothing fails because a test is slow; timings on a machine shared with other
  worktrees are too noisy for a limit. `timeout = 300` in `pyproject.toml` stays the only limit.
- **The plugin is loaded with `-p`, not from a conftest.** `freedom_ls/conftest.py` is star-imported
  by concrete projects, and the ranking is an FLS development tool.
- **Test cost is wall time; the target is CPU time.** pytest reports per-phase wall durations.
  The run's total CPU time (user + sys of pytest and its xdist workers) is the steadier number to
  hold a target against. Postgres CPU is in neither.
- **Fixed run conditions.** Two ranking runs are compared only when their conditions match, so the
  ranking's header records them.
- **`dev_tooling` tests are ranked.** They cost CPU on every tier run. CI's coverage job does not
  run them, so a change to one rests on the named test alone.
- **A removal needs a test that still asserts the same behaviour.** Executing the same lines is not
  enough. Naming that test in `pruned_tests.md` is the only sign-off.
- **The target is fixed from the first ranking run, before any test changes,** and recorded in
  `timings.md`.

## Requirements

### Recording: `scripts/record_test_costs.py`

- A pytest plugin module, loaded as `-p scripts.record_test_costs`.
- A `pytest_fixture_setup` hookwrapper times the fixture named `django_db_setup` in the worker. A
  `pytest_runtest_makereport` hookwrapper subtracts that time from the triggering test's setup
  report and adds it to the report's `user_properties`, which xdist sends to the controller.
  Database creation is then reported once per worker as its own figure, and the first test on each
  worker does not top the ranking.
- `pytest_runtest_logreport` collects `report.duration` per `report.nodeid` and `report.when`
  (`setup`, `call`, `teardown`). A phase with no report counts as 0.0.
- Under xdist only the controller writes: it skips the write when `config` has `workerinput`.
- At `pytest_sessionfinish` it writes `.sdd-work/test_costs.json`: per node ID, the three phase
  seconds; plus the run's database-setup seconds, test count and outcome counts. `.sdd-work/` is
  already gitignored.

### Ranking run: `scripts/rank_test_costs.py`

- `uv run python scripts/rank_test_costs.py` with no arguments runs, from the repo root with
  `PYTHONPATH` set to it so `-p` can import the plugin:

  ```bash
  python -m pytest -p scripts.record_test_costs -p no:randomly -n 4 --no-cov \
    -m "not ci_only and not weasyprint and not playwright" \
    --ignore=freedom_ls/educator_interface/tests/invariants/test_permission_matrix.py \
    --ignore=tests/test_rank_test_costs.py
  ```

  It records that subprocess tree's CPU time with `resource.getrusage(RUSAGE_CHILDREN)`
  (user + sys). It exits non-zero, writing no ranking, when pytest exits with failures.
- `main()` takes an optional pytest command and output path, which only its tests pass.
- It reads `.sdd-work/test_costs.json` and writes `test_organisation/test_cost_ranking.md`:
  - A first line: `Generated by uv run python scripts/rank_test_costs.py. Do not edit by hand.`
  - A header: date, commit SHA, test count, total CPU seconds, wall seconds, summed test cost,
    database-setup seconds, and the run conditions.
  - A per-area rollup (`freedom_ls/<app>`, `tests`, `claude_plugins/fls-content`): test count,
    seconds, share of summed test cost.
  - The top 50 files by test cost: file, test count, seconds, share.
  - The top 200 test functions by test cost, parametrized cases grouped under the function: node
    ID with its `[...]` suffix stripped, case count, total seconds, mean per case, setup share,
    share and cumulative share of the summed test cost.
- A function's grouping key splits the node ID on `::` first, then strips from the first `[` in the
  last segment, so a parameter ID holding `::` or `[` groups correctly.
- Seconds are rounded to one decimal, shares to whole percent. Rows are sorted by seconds, then by
  node ID, so the file diffs line by line.
- The full per-test data stays in `.sdd-work/test_costs.json` and is not committed.

### `pyproject.toml`

- One `[[tool.test_tiers.tooling]]` entry, `glob = "scripts/*_test_costs.py"`, mapping
  `scripts/record_test_costs.py` and `scripts/rank_test_costs.py` to
  `tests/test_rank_test_costs.py`, as `scripts/generate_icon_subset.py` has. No other
  `[tool.test_tiers]` key changes.

### Pruning

- Work goes down the ranking's top functions. A candidate not changed gets a one-line reason in
  `pruned_tests.md`.
- Pruning stops at the target, or when the next function's test cost is under 0.5% of the first
  ranking run's summed test cost, whichever comes first.
- A merge keeps a failure message that names the behaviour that broke: parametrize or label each
  assertion rather than chaining unrelated asserts.
- When a whole test file is removed or renamed, `test_organisation/mirroring_baseline.txt` and
  `test_organisation/import_baseline.txt` are updated as `check_test_mirroring.py` and
  `lint-imports` require. No entry is removed except for that file.
- Coverage: before the first change and after the last, run CI's unit-job selection with a JSON
  report:

  ```bash
  uv run pytest -m "not playwright and not dev_tooling" -n auto --cov --cov-fail-under=92 \
    --cov-report=json
  ```

  Both runs pass, and no file under `freedom_ls/` loses a covered line or branch.

### Records in this spec directory

- `timings.md`: the first ranking run's totals and commit SHA, the target and the rule that set it,
  the last ranking run's totals, and the result against the target. A one-off cross-check of the
  `RUSAGE_CHILDREN` total against `/usr/bin/time -v` on the same command. The
  `freedom_ls/course_access` test-body time and the `freedom_ls/accounts` run and database-setup
  times, measured as `research_test_timings.md` measured them, before and after.
- `pruned_tests.md` ("pruned" covers merged, rewritten and removed): one row per changed test
  function with node ID, action, seconds before and after, the test that still asserts the same
  behaviour (for a removal, or a merge that drops an assertion) and any difference between the two,
  and the reason. Then candidates left unchanged, and the per-file coverage comparison.

## Testing

`tests/test_rank_test_costs.py`, marked `dev_tooling`, as the other script tests in `tests/` are.
It runs inner suites with `pytester.runpytest_subprocess`, `PYTHONPATH` at the repo root and
`-p scripts.record_test_costs`. The inner suite's `conftest.py` defines a fixture named
`django_db_setup` that sleeps, so no database is needed.

- The plugin, with and without `-n 2`, writes one entry per node ID with three phase seconds, and
  only the controller writes.
- A test that triggers `django_db_setup` is ranked without its time, and the file reports that
  time separately.
- Grouping: `a.py::test_x[1]` and `a.py::test_x[2]` group under `a.py::test_x`;
  `a.py::TestC::test_y[p::q]` groups under `a.py::TestC::test_y`.
- The ranking written from a fixed `test_costs.json` matches an expected file exactly: header,
  rollups, ordering, rounding, the top-200 cut.
- A pytest run with failures leaves the existing ranking unchanged and exits non-zero.

## Documentation and downstream

- `claude_plugins/fls-dev/skills/testing/SKILL.md`: a section "The test-cost ranking" with the
  command, when to run it (after pruning, or when the suite feels slower), its run time, what the
  file holds, and that nothing fails on slowness.
- No upgrade notes beyond the changed test list: concrete projects do not load the plugin, and FLS
  ships no changed fixture or setting.

## Open questions

- Q: Where does the committed ranking live? → A: `test_organisation/test_cost_ranking.md`
  (assumed default: that directory already holds the suite's committed metadata. Overrule by
  editing Requirements, "Ranking run".)
- Q: How many rows does the ranking keep? → A: 200 functions and 50 files (assumed default: enough
  to show the curve flattening without thousands of churning lines. Overrule by editing
  Requirements, "Ranking run".)
- Q: Must each test named in `pruned_tests.md` exist in the last ranking run? → A: no separate
  check; the reviewer of the change confirms it (assumed default: the name is copied from a run
  that collected it. Overrule by editing Requirements, "Pruning".)

## Success criteria

- `test_organisation/test_cost_ranking.md` is committed, and its header SHA is the last ranking
  run's commit.
- The last ranking run's total CPU seconds in `timings.md` are at or under the target, or
  `timings.md` shows the 0.5% rule ended pruning.
- Both coverage runs pass at 92%, and the per-file comparison in `pruned_tests.md` shows no
  `freedom_ls/` file losing a covered line or branch.
- `uv run pytest` passes.
- No diff in `.github/workflows/tests.yml`, `run_tests.py`, `select_tests.py` or `test_tiers.md`,
  and only the one new entry in `[tool.test_tiers]`.
