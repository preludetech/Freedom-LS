# Pruned tests

Seconds saved so far (before minus after, summed over both changed-tests tables): 242.36 in the first pass + 49.35 in the second pass. The two passes were measured under different load, so the sum is not one figure: the rerun of the last ranking put the first pass at about 127 s of test cost at the first run's load (about 120 CPU seconds; see `timings.md`), not 242.36. The second pass's 49.35 s was measured serially on a quieter machine (load average 6 to 11); the tests it changed cost 1.76 times as much in the rerun's `-n 4` ranking (181.5 s) as in that serial before-run (103.3 s), and the rerun ran 1.393 times slower than the first run, so the pass is roughly 49.35 x 1.76 / 1.393 = 62 s of test cost at the first run's load (about 59 CPU seconds). Both passes together are then about 179 CPU seconds against the 192.9 the target needs; every figure in that sum rests on a load ratio. The ranking run after this pass is the measurement.

## Why pruning stopped

The summed savings reached the target estimate: 242.36 s of test cost x 0.9465 = 229.4 CPU seconds, against the 192.9 CPU seconds the target needs. The five costliest functions, all in `freedom_ls/messaging_policy/tests/test_policy.py`, accounted for all of it. The first ranking's next function (14.8 s) was still above the 7.28 s threshold, so the target was the stopping rule. The before figures were taken under heavier load than the after figures (the file took 555 s before and 354 s after), so the true saving is smaller than 242 s; the last ranking run is the measurement.

After the rerun of the last ranking showed the first pass short of the target, a second pass changed the three costliest functions left in `test_policy.py` and the image divisor test (the second table above). It stopped where the remaining candidates above the 7.28 s threshold had no cheaper form that keeps their assertions: the two pair tests and the migration tests under "Candidates left unchanged".
