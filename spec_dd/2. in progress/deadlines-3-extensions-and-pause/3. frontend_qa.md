# Frontend QA: extensions and pause

Checks the staff actions in the Django admin and what a paused or extended learner sees.

## 0. Setup

### 0.1 Server

- Start: `uv run python manage.py runserver $PORT`
- Base URL: `http://127.0.0.1:$PORT`

### 0.2 Data

Run, in order:

```
uv run python manage.py migrate
uv run python manage.py create_demo_data --yes
uv run python manage.py content_save ./demo_content DemoDev
uv run python manage.py qa_create_deadlines_seed --site-name DemoDev
```

Re-run the last command to reset the `qa_deadline_*` accounts before a repeat of any test that
changes them (tests 2 to 7, 12 and 13 change data).

### 0.3 Accounts

Every password equals the email address.

| Account | Role and state |
| --- | --- |
| `demodev@email.com` | superuser; the "staff" in every admin test |
| `qa_deadline_fresh@email.com` | learner, parts course, not paused, no deadlines moved |
| `qa_deadline_paused@email.com` | learner, parts course paused 2 days ago, planned resume 5 days from today; "Welcome" and "What to Expect" complete; "Knowledge Check" has an open attempt |
| `qa_deadline_paused_open@email.com` | learner, parts course paused 2 days ago, no planned resume; "Welcome" complete |
| `qa_deadline_resumed@email.com` | learner, parts course paused 6 days ago and resumed 3 days ago |
| `qa_deadline_extended@email.com` | learner, parts course; "Key Ideas" extended by 7 and 5 days; whole course extended by 2 days |
| `qa_deadline_restored@email.com` | learner, parts course, existing spec-2 state (access restored by an override) |

The parts course is "Functionality demo: course parts", slug
`functionality-demo-course-parts`. Its items, in order: Welcome, What to Expect, Key Ideas,
Knowledge Check, Course Feedback.

### 0.4 Finding a course progress record in the admin

Log in as `demodev@email.com`, open `/admin/`, go to Learner progress > Course progress, search
for the learner's email, and open the row for the parts course. This page is "the record
page" below.

## Staff: pause and resume

### Test 1: The record page offers the right action

1. Open the record page for `qa_deadline_fresh@email.com`.
2. Expect buttons "Pause course" and "Extend deadline" at the top. Expect no "Resume course".
3. Open the record page for `qa_deadline_paused@email.com`.
4. Expect "Resume course" and "Extend deadline". Expect no "Pause course".
5. In the Deadlines section, "Effective deadlines" opens with "Paused since <date>, until
   <date>" and every unfinished item's line ends "(+N days)".
6. A "Course pauses" table lists one row: state "Paused", the reason, who started it.

### Test 2: Pause with a planned resume

1. Record page for `qa_deadline_fresh@email.com` > "Pause course".
2. Expect the page title "Pause <learner> on <course>", the line "<learner> can open this
   course now. After pausing, nothing in it can be opened; past results stay visible.", a
   Reason field, a planned resume date field with the help "Leave empty to pause until you
   resume it. Deadlines move by the whole days paused, rounded up.", a "Pause course" button
   and a Cancel link.
3. Submit with the reason empty. Expect the form again with an error on Reason. Go back to
   the record page: no pause was created.
4. Open the form again. Enter a reason and today's date as planned resume. Submit. Expect a
   form error saying the date must be after today; nothing created.
5. Enter a reason and a date 3 days from today. Submit.
6. Expect the record page with the message "Paused <learner> on <course>.", "Resume course"
   in place of "Pause course", and a new row in the pauses table.
7. Open `/admin/` > Audit log (or the educator audit log at
   `/educator/organisations/<org>/audit-log` for the learner's organisation). Expect one entry
   "Course paused" for this learner reading "Until <date>", with the reason.

### Test 3: Pause with no planned resume

1. Reset data (0.2). Record page for `qa_deadline_fresh@email.com` > "Pause course".
2. Enter a reason only. Submit.
3. Expect the success message. "Effective deadlines" opens with "Paused since <date>" with no
   "until".

### Test 4: Resume

1. Record page for `qa_deadline_paused_open@email.com` > "Resume course".
2. Expect "Paused since <date>. Resuming moves the time limit and every unmet deadline forward
   by 2 days." (the seed paused it 2 days ago; 3 if the run crosses the hour of the seed), a
   Reason field and a "Resume course" button.
3. Submit with no reason: error on Reason, still paused.
4. Enter a reason. Submit. Expect "Resumed <learner> on <course>. Deadlines moved by N days."
   with the same N as step 2.
5. On the record page: "Pause course" is back; the pause row reads "Ended" with its paused
   days; "Effective deadlines" shows "(+N days)" on "What to Expect" and later items and on
   "Course time limit end", and no "(+N days)" on "Welcome", which was completed before the
   pause (it either has no line or an unshifted one).
6. Press the browser Back button to the resume form and submit it again. Expect a warning
   that the course is not paused, and no second "Course resumed" audit entry.

### Test 5: Pausing an already-paused record

1. Open the pause form for `qa_deadline_fresh@email.com` in two tabs.
2. Submit a reason in the first tab: success.
3. Submit a reason in the second tab. Expect the form again with the error "This course is
   already paused." and one pause row on the record page.

## Staff: extend a deadline

### Test 6: Extend one item by days

1. Reset data. Record page for `qa_deadline_fresh@email.com` > "Extend deadline".
2. Expect a target choice ("One item", "Course time limit", "Whole course"), an item picker
   listing the course's items, a days field, a date field, a Reason field, and a list of the
   current effective date of each item with a deadline and of the time limit.
3. Choose "One item", pick "Key Ideas", enter 7 days and a reason. Submit.
4. Expect "Extended Key Ideas for <learner> by 7 days. Its deadline is now <date>." The date
   is 7 days after the date step 2 listed, at the same time of day (17:00).
5. "Effective deadlines": the "Key Ideas" line ends "(+7 days)"; no other line changed.
6. A "Deadline extensions" table lists the row.
7. Repeat steps 1 to 3 with 5 days. "Key Ideas" now ends "(+12 days)" and the table has two
   rows.

### Test 7: Extend by date, the time limit, and the whole course

1. Record page for `qa_deadline_fresh@email.com` > "Extend deadline". Choose "Course time
   limit", enter a date 10 days after the listed time limit end and a reason. Submit. Expect
   "Extended Course time limit for <learner> by 10 days. Its deadline is now <date>."
2. Again: choose "Whole course", enter 2 days and a reason. Submit. Expect "Moved <learner>'s
   deadlines in <course> by 2 days." Every unfinished item's line and the time limit gained 2
   more days.

### Test 8: Extend form refuses bad input

For each row, open the extend form for `qa_deadline_fresh@email.com`, enter a reason plus the
input, submit, and expect the form again with an error and no new row in the extensions table.

| Input | Expected error is about |
| --- | --- |
| "One item", "Key Ideas", days and date both filled | giving exactly one of days and date |
| "One item", "Key Ideas", neither days nor date | giving exactly one of days and date |
| "Whole course" with a date | whole course takes days only |
| "One item" with no item picked | picking an item |
| "One item", "Key Ideas", a date before its current deadline | a date after the current deadline |
| "Course time limit", 7 days, no reason | the reason |
| "Course time limit", 3651 days | giving between 1 and 3650 days |

Then, with "One item" chosen on a course whose item has no deadline (use
`functionality-demo-show-end-with-topic` for `qa_deadline_solo@email.com`'s plain-course
record): expect "This item has no deadline".

### Test 9: A time-limit extension restores ended access

1. Log in as `qa_deadline_cohort@email.com`. The parts course card reads "Access ended".
2. As staff, extend that record's "Course time limit" by enough days to pass today (the form
   lists the current end; pick a date 30 days from today).
3. As the learner, reload the dashboard. The card no longer reads "Access ended" and the
   course opens.

## Staff: lists, permissions, policy

### Test 10: Read-only lists

1. `/admin/` > Deadlines > Course pauses. Expect a list with filters (course, state, started
   by, date) and a search box. Search a seeded learner's email: their pauses show.
2. Open a row or look for an Add button: the list offers no add, no edit and no delete.
3. Same for Deadlines > Deadline extensions.
4. On a record page, the pauses and extensions tables have no editable cells, no "Add
   another" and no delete boxes.

### Test 11: Policy settings

1. `/admin/` > Deadlines > Site deadline configs > add or open the DemoDev row. Expect three
   new fields: learners may pause (Inherit / On / Off), max pauses, max pause days, the two
   numbers with help text saying empty inherits and 0 means no limit.
2. Set max pauses to 2 and save. On any record page, "Effective deadline policy" lists
   `max_pauses: 2 (site)`, `max_pause_days: No limit (settings)` and
   `learners_may_pause: Off (settings)`.
3. Enter -1 for max pauses: the form refuses it.
4. With max pauses at 2, pause and resume `qa_deadline_fresh@email.com` three times as staff.
   All three succeed: the limits bind nobody yet. Clear the field and save.

### Test 12: A staff user without change permission

1. In the admin, create a staff user with view-only permission on Course progress.
2. As that user, open a record page: no "Pause course", "Resume course" or "Extend deadline"
   button.
3. Type the pause URL by hand (`.../courseprogress/<id>/pause/`). Expect 403. Same for
   `/resume/` and `/extend/`.

## Learner: a paused course

Check tests 13 to 17 at desktop, mobile and tablet widths.

### Test 13: Dashboard and all-courses page

1. Log in as `qa_deadline_paused@email.com`. Open `/`.
2. The parts course card's eyebrow reads "Paused until <date>" (the planned resume date) with
   an icon. The title links to `/courses/functionality-demo-course-parts/detail/`. The card
   has no Continue button, no "Next up" line and no deadline line.
3. Open `/courses/`. The parts course row shows a "Paused until <date>" chip, links to course
   detail, and has no Continue.
4. Log in as `qa_deadline_paused_open@email.com`. Card and row read "Paused" with no date.
5. No text on either page shows the staff reason.

### Test 14: Course detail

1. As `qa_deadline_paused@email.com`, open
   `/courses/functionality-demo-course-parts/detail/`.
2. Where the Start/Continue button normally sits, an info callout reads "Your educator paused
   this course. It resumes on <date>. Your progress is saved." then "Your deadlines move by
   the time paused." There is no Start or Continue button.
3. The "Course content" outline shows: "Welcome" and "What to Expect" as links (completed);
   "Key Ideas", "Knowledge Check" and "Course Feedback" not linked, each with a "Paused" chip.
   The part row reads paused and links to "Welcome".
4. As `qa_deadline_paused_open@email.com`, the callout reads "Your educator paused this
   course. Your progress is saved. You can continue when they resume it." then "Your deadlines
   move by the time paused."
5. The callout never shows the staff reason.

### Test 15: What still opens, and what does not

As `qa_deadline_paused@email.com`:

1. Click "Welcome" in the outline. The topic opens. The outline panel shows, with "Paused"
   chips on unfinished rows. There is no mark-complete control, no Next and no Previous, and
   no next-deadline card.
2. Open `/courses/functionality-demo-course-parts/` (the bare course URL). Expect a redirect
   to the course detail page, not to an item.
3. Type the URL of "Key Ideas" (item 3:
   `/courses/functionality-demo-course-parts/3/`, or follow the pattern of the "Welcome"
   URL). Expect a redirect to course detail.
4. Type the URL of "Knowledge Check" (item 4), then its start URL and a fill-in page URL
   (follow the pattern the player uses for a quiz in an unpaused account). Each redirects to
   course detail.
5. Type the course finish URL (`/courses/functionality-demo-course-parts/finish/`, or the
   pattern the player uses). Expect a redirect to course detail.

### Test 16: An open attempt is frozen, then continues

1. As staff, open the record page for `qa_deadline_paused@email.com`. In the form attempts
   table, the "Knowledge Check" attempt is not complete.
2. As the learner, try the URLs in test 15 step 4 again. As staff, reload: the attempt is
   still not complete and has the same answers.
3. As staff, resume the course.
4. As the learner, open the course: "Knowledge Check" opens and continues the same attempt on
   the page it was left on, with its answers.

### Test 17: Results stay visible

1. Reset data. As `qa_deadline_fresh@email.com`, complete "Welcome", "What to Expect" and
   "Key Ideas", then sit "Knowledge Check" and submit it.
2. As staff, pause the record.
3. As the learner, open the results page of "Knowledge Check" from its URL (the page you
   landed on after submitting). The results show. There is no Retry, Next or Previous. The
   outline panel shows.
4. If the attempt failed, the text reads "You needed N% to pass." with no invitation to try
   again.

### Test 18: A planned resume takes effect on its own

1. As staff, pause `qa_deadline_fresh@email.com` with a planned resume of tomorrow. As the
   learner, the card reads "Paused until <tomorrow>".
2. In a shell, move the pause into the past so its planned resume is today:

   ```
   uv run python manage.py shell -c "
   from datetime import timedelta
   from django.utils import timezone
   from freedom_ls.deadlines.models import CoursePause
   p = CoursePause._base_manager.filter(course_progress__learner__user__email='qa_deadline_fresh@email.com', ended_at__isnull=True).get()
   p.started_at -= timedelta(days=3); p.planned_resume_on = timezone.localdate(); p.save()
   "
   ```

3. As the learner, reload the dashboard. The card reads its normal status with a Continue
   button, the course opens, and its deadlines are 3 days later than before the pause.
4. As staff, the record page offers "Pause course" again and "Effective deadlines" shows no
   "Paused since" line.

## Learner: moved deadlines and notifications

### Test 19: A resumed learner's dates

1. Log in as `qa_deadline_resumed@email.com`. Open the parts course in the player.
2. Deadlines on unfinished items read 3 days later than the same items for
   `qa_deadline_fresh@email.com` would with the same registration date (compare with the
   admin "Effective deadlines" of both records: the resumed one shows "(+3 days)").
   "Welcome", completed before the pause, shows no moved date.
3. Nothing reads "Paused" anywhere.

### Test 20: An extended learner's dates

1. Log in as `qa_deadline_extended@email.com`. Open the parts course.
2. "Key Ideas" shows a deadline 14 days later than its content default (7 + 5 + 2), still at
   17:00. Other unfinished items are 2 days later.
3. If "Key Ideas" would have read "Missed deadline" or "Closed" without the extensions, it
   reads neither.

### Test 21: Notifications

1. Reset data. As staff, pause `qa_deadline_fresh@email.com` with a planned resume.
2. As the learner, open the notification bell. Expect "Your educator paused <course>. It
   resumes on <date>. Your progress is saved." Clicking it opens the course detail page.
3. As staff, resume. The learner gets "Your educator resumed <course>. Your deadlines moved
   by 1 day." ("1 day", not "1 days").
4. As staff, extend "Key Ideas" by 7 days. The learner gets "Your educator extended the
   deadline for Key Ideas in <course> to <date>."
5. As staff, extend the whole course by 2 days. The learner gets "Your educator moved your
   deadlines in <course> by 2 days."
6. No notification shows the staff reason. The three arrive as separate rows.
