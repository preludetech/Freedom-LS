# Spec: Educator interface refactor, cleanup of the flat modules

## Purpose

Specs 1 to 6 of the Educator interface code layout effort moved each area into
`freedom_ls/educator_interface/panels/<area>/` and left the flat files behind. This spec removes
those leftovers, puts every remaining test beside the module it tests, and writes the effort's
upgrade note. The idea is `idea.md`. The effort's decisions are in the "Educator interface code
layout" section of `spec_dd/1. next/roadmap.md`.

## Scope

In:

- Delete `freedom_ls/educator_interface/actions.py`, `quick_views.py` and `reporting.py`.
- Move the tests in `tests/test_actions.py`, `tests/test_quick_views.py` and the non-shell part of
  `tests/test_views.py` to mirrored homes. Fold the four baselined shell test files into
  `tests/test_views.py`.
- Clear the `educator_interface` lines in `test_organisation/mirroring_baseline.txt`.
- Widen `EDUCATOR_PYTHON_FILES` in `tests/invariants/test_panel_template_rules.py` to the `panels/`
  tree.
- Fix two stale docstrings.
- Write `upgrade_notes.md`.

Out:

- Any behaviour, UI, URL name, URL path, template path or app label change. No migration and no
  re-export shim.
- `views.py` and `urls.py`: both are already at the end state. The `# TODO` block at
  `views.py:41-49` stays.
- The other flat domain modules and their tests.
- The imports from `views` in `panels/staff/actions.py` (lazy `interface_config`),
  `panels/cohort/report_download.py` and `panels/learner/import_views.py`. Both directions are
  deliberate.
- Migrations `0001` to `0003` and their tests: the old dotted paths there are history.
- Everything under `spec_dd/3. done/`, the generated `test_organisation/test_cost_ranking.md` and
  `.test_durations`, and the stale pointer in `freedom_ls/panel_framework/tests/test_views.py`.
- Layering rules and baseline lines other than `educator_interface` mirroring:
  `test-organisation-and-hygene-15-educator-interface` owns them.

## Decisions

- **A test's home is the test file mirroring the module that defines the behaviour it checks**, under
  `tests/panels/<area>/` or `tests/panels/common/`. A test that only reaches `views.py` code stays in
  `tests/test_views.py`. A new test file is created only beside an existing module.
- **A parametrised test whose cases span areas moves whole** to the `tests/panels/common/` file
  mirroring the shared module it exercises. It is never split per area, so its name and its
  cases survive.
- **The upgrade note indexes the six sibling notes** instead of restating their name lists. Those
  notes already list every moved name per area.

## Requirements

### Flat modules

- `freedom_ls/educator_interface/actions.py`, `quick_views.py` and `reporting.py` are gone. If one
  holds a live definition when the work starts, that definition moves to its `panels/` home first
  and the PR says so.
- `tests/test_actions.py` and `tests/test_quick_views.py` are deleted in the same commit as their
  modules, or `check_test_mirroring.py` flags them as orphans.

Where the table names a directory, the Decisions rule picks the file.

- Every moved test keeps its name and assertions. Its fixtures, helpers, `mock.patch` strings and
  marks move with it. A helper used by tests in more than one destination goes to `tests/helpers.py`.
- Folding into `tests/test_views.py` brings no silent redefinition. `test_interface_urls.py`'s local
  `_interface_url` gives way to the one in `tests/helpers.py`. Its autouse `_site_context`
  override of `tests/conftest.py`'s fixture applies only to the tests that had it.
  `test_sidebar.py`'s local fixtures and `_messaging_off` keep names that collide with nothing.
- Every new test directory has an empty `__init__.py`.

### Baselines and invariants

- `test_organisation/mirroring_baseline.txt` has no line naming `freedom_ls/educator_interface/`.
- A moved test that adds a cross-app test import gets a line in `import_baseline.txt` and
  `import_contracts.toml`, the same way the existing `tests.panels.course.test_data_tables` line
  does.
- `tests/invariants/test_panel_template_rules.py:21`: `EDUCATOR_PYTHON_FILES` covers every `.py`
  file under `freedom_ls/educator_interface/` except `tests/` and `migrations/`.

### Stale references

- `freedom_ls/qa_helpers/management/commands/qa_create_learner_registrations_panel.py:4`: the
  docstring names `freedom_ls/educator_interface/views.py` as the home of
  `LearnerRegistrationsPanel`. It names `freedom_ls/educator_interface/panels/learner/data_table_panels.py`
  instead.
- `freedom_ls/reports/gather.py:371`: the docstring names `educator_interface/views.py`. Drop that
  path pointer, because the guard it cites no longer exists in `educator_interface`. Keep the guard
  statement: `quiz_percentage()` raises on unreadable input, `passed()` raises when
  `quiz_pass_percentage` is unset, and that field is nullable.
- A grep of `freedom_ls/`, `config/`, `claude_plugins/fls-dev/`, `test_organisation/` and `docs/` for
  `educator_interface.(actions|filters|quick_views|reporting)` and
  `educator_interface(.|/)views` finds only the out-of-scope items above and true references to
  the shell `views`. The same holds for strings passed to `mock.patch`, `monkeypatch.setattr` and
  `import_string`.

## Testing

- The full suite passes.
- `uv run pytest --collect-only -q freedom_ls/educator_interface` reports the same count at the
  branch's first commit and at its last.
- `claude_plugins/django-stack/scripts/check_test_mirroring.py` passes with no stale baseline line
  and no `educator_interface` violation.
- One moved `mock.patch` target is checked by mutation: point it at a wrong module and confirm the
  test fails.
- A test asserts that `EDUCATOR_PYTHON_FILES` contains a file under `panels/` (for example
  `panels/learner/actions.py`). `test_no_educator_module_sets_the_modal_trigger_template_by_hand`
  passes over the wider set.
- The flat modules and the six flat or shell test files listed above no longer exist.

## Documentation and downstream

`spec_dd/2. in progress/educator-interface-refactor-7-cleanup/upgrade_notes.md`, in the format of
`claude_plugins/fls-dev/commands/update_upgrade_notes.md`:

- Frontmatter: `requires_migrations: true`, because the effort's `0002_move_learner_bulk_runs` and
  `0003_move_cohort_bulk_runs` rewrite stored `BulkActionRun.action_path` values. Every other flag is
  `false` and every list `[]`.
- **Breaking changes**:
  - `freedom_ls.educator_interface.actions`, `.quick_views` and `.reporting` no longer exist.
    `.filters` was removed by `educator-interface-refactor-5-learner`. No re-export shim.
  - `freedom_ls.educator_interface.views` now exposes only the shell names. The pass-through imports
    that the sibling notes said "still resolve for now" no longer resolve.
  - `OrganisationScopedRequest` is at `freedom_ls.educator_interface.panels.common.request`.
    `interface_config` stays at `freedom_ls.educator_interface.views`.
  - An index by area naming each sibling's `upgrade_notes.md` (the six
    `spec_dd/3. done/*_educator-interface-refactor-<n>-*/` directories) for the name-by-name moves.
  - URL names, URL paths and template paths are unchanged.
- **Manual steps**: run `uv run manage.py migrate`. Grep the project for
  `freedom_ls.educator_interface.(views|actions|filters|quick_views|reporting)` in imports,
  `mock.patch` strings and settings. A project that uses only
  `include("freedom_ls.educator_interface.urls")` and `INSTALLED_APPS` needs no action. That
  covers First-Class-LMS.
- Every dotted path and file path in the note is checked against the tree.
