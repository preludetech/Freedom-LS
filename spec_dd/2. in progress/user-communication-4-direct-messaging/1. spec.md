# Spec: direct messaging

Spec 4 of the User communication effort (`spec_dd/1. next/roadmap.md`, "User communication"). It
absorbs spec 5, `user-communication-5-educator-messaging`. The approach and its reasons are in
`idea.md`; the research files beside it hold the evidence. The design is registered in `design.md`.
It is a visual reference only, read the way that file says.

## Purpose

Two people on a site can hold a private, one-to-one conversation inside FLS. Learners and educators
get an inbox, a thread and a composer. Educators also get an inbox section in the educator interface
and a message box in the learner quick view, so they never leave the interface to answer. Every send
goes through spec 3's `MessagingPolicy`. Delivery is by polling, and each unread conversation raises
one notification.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| `Conversation` | coined | A private exchange between exactly two users on one site. |
| `Message` | coined | One entry in a `Conversation`. Not Django's `django.contrib.messages` flash. Never name a module, variable or context key `messages` for these. |
| inbox | coined | The list of a user's conversations, newest activity first. |
| thread | coined | One conversation's messages as displayed, with its composer. |
| rollup | coined | A notification category whose new events update the recipient's one unread notification for the same target instead of adding a row. |

## Scope

In:

- `Conversation`, `ConversationParticipant` and `Message` models in `comms`.
- The shared inbox page, thread page and new-conversation picker, on a neutral page base.
- The header Messages button with a polled unread-conversation count.
- Thread and inbox polling, keyset loading of older messages, retry-safe sending.
- Rollup notifications for messages.
- The educator interface inbox section, with a polled count on its sidebar link.
- The message box in the learner quick view.
- `MESSAGING_ENABLED`, off by default.

Out (as `idea.md` lists): group conversations, broadcasts and cohort-wide messaging; attachments,
editing, deleting, typing indicators and presence; reporting and blocking (spec 6); the
notification email, preferences and unsubscribe (spec 2); digests (spec 7); configuring who may
message whom (spec 3, Django admin); WebSockets (spec 8). Also out: a message-specific row in the bell
panel, since the generic notification row serves.

## Decisions

1. **One conversation per pair of users per site, no organisation stored.** The policy is per pair
   and colleague pairs have no `Learner` row; the educator section derives the organisation from the
   other participant's `Learner` row.
2. **Colleague conversations appear only in the shared inbox.** The educator interface section lists
   conversations with learners in the selected organisation.
3. **The header Messages button always opens the shared inbox**, for educators as well as learners.
4. **A policy refusal on send returns 422**, like a validation error. The repo's `htmx:beforeSwap`
   listener (`freedom_ls/base/static/base/js/alpine-components.js`) swaps 422 bodies already, and the
   draft has to stay in the box. A conversation the user does not take part in returns 404.
5. **The new models are not registered in the Django admin.** Private message bodies stay out of
   staff view; spec 6 builds the report queue.
6. **Read state is a timestamp per participant.** `ConversationParticipant.last_read_at` is set to the
   `created_at` of the newest message the user was shown, never to `now()`. Sending a message moves the
   sender's `last_read_at` to that message's `created_at`. A conversation is unread for a participant
   when `Conversation.last_message_at > last_read_at`, or `last_read_at` is null and a message exists.
   That makes the unread count one join with no `Message` scan.
7. **Cursors are keysets on `(created_at, id)`.** `Message.id` is a random UUID, so `id` alone neither
   orders nor bounds.
8. **Polling reuses the bell's Alpine timer idiom.** It is a visibility-aware `setInterval` that
   dispatches a custom `refresh` event on an `hx-trigger="refresh"` element. The CSP Alpine build rules
   out inline `hx-trigger` filters. Generalise the timer in
   `freedom_ls/comms/static/comms/js/alpine-components.js` rather than copying it.
9. **Recipient grouping is the policy's job.** `comms` may import only `accounts`, `base` and
   `site_aware_models`, and this spec never re-derives cohort, registration or role relationships.
   `MessagingPolicy` gains a grouping method (see "Policy").
10. **Enter inserts a newline; Ctrl+Enter or Cmd+Enter sends.** A visible hint names the shortcut, and
    the Send button is always present.
11. **The quick-view message box keeps the existing bottom sheet** below `md` and asks before
    discarding a draft when the educator opens another learner.
12. **Deleting a user cascades** to their `ConversationParticipant` rows and their `Message` rows, as
    `Notification.user` does. A conversation left with one participant is read-only for that user,
    worded as `INACTIVE_USER`.

## Requirements

### Models (`freedom_ls/comms/models.py`, new migration `0002_...`)

All three subclass `SiteAwareModel`.

- `Conversation`: `pair_key` (`CharField`, `"<low user pk>:<high user pk>"`), `created_at`
  (`auto_now_add`), `last_message_at` (`DateTimeField`, null). `UniqueConstraint(fields=["site",
  "pair_key"])`. Only the create function below writes `pair_key`.
- `ConversationParticipant`: `conversation` (FK, CASCADE, `related_name="participants"`), `user` (FK
  `AUTH_USER_MODEL`, CASCADE, `related_name="conversation_participants"`), `last_read_at` (null).
  `UniqueConstraint(conversation, user)`. `Index(user, site)`.
- `Message`: `conversation` (FK, CASCADE, `related_name="messages"`), `sender` (FK `AUTH_USER_MODEL`,
  CASCADE, `related_name="sent_messages"`), `body` (`TextField`), `created_at` (`auto_now_add`),
  `client_key` (`UUIDField`, null). `UniqueConstraint(fields=["conversation", "sender", "client_key"],
  condition=Q(client_key__isnull=False))`. `Index(conversation, created_at, id)`.
- `Notification` gains `rollup_key` (`CharField`, null, set only for rollup categories, value
  `"<content_type_id>:<object_id>"`), with `UniqueConstraint(fields=["user", "site", "rollup_key"],
  condition=Q(read_at__isnull=True, rollup_key__isnull=False))`. A model comment says that `created_at`
  on a rollup row means "last changed".

### Messaging service (`freedom_ls/comms/messaging.py`, new)

Views in `comms` and `educator_interface` call these. None of them re-derives a relationship.

- `get_or_create_conversation(*, user_a, user_b, site) -> Conversation`: transactional. It catches the
  specific `IntegrityError` on `pair_key` and re-reads.
- `send_message(*, sender, conversation | recipient, body, client_key, site) -> SendResult`. Order:
  1. Validate the body. Normalise `\r\n` to `\n`. It must not be blank or whitespace-only, and it is
     at most `MESSAGE_MAX_LENGTH` characters.
  2. If a `Message` with this `(conversation, sender, client_key)` exists, return it as a success with
     no side effects, even if the policy has changed since.
  3. Ask `can_start` for a new conversation, or `can_reply` for an existing one. If refused, store
     nothing and return the `MessagingRefusal`.
  4. Insert the message. Set `Conversation.last_message_at` and the sender's `last_read_at` in the same
     transaction. On an `IntegrityError` on `client_key`, return the existing row.
  5. Call `raise_notification(user=<other participant>, category="message.received",
     target=conversation, site_id=conversation.site_id, data={"sender_name": sender.display_name})`
     after the save, inside the transaction. The sender is never notified. Any work later moved out of
     the request carries `site_id` and the participant ids as arguments, and reads with
     `_base_manager` filtered by `site_id`, as `comms/tasks.py` does.
- `mark_conversation_read(*, user, conversation, up_to: datetime)`: sets `last_read_at` to
  `Greatest(last_read_at, up_to)`, then calls `mark_notifications_read` for that conversation.
- `reply_decision(*, viewer, conversation) -> MessagingDecision`: `can_reply` with the other
  participant. A missing participant gives `MessagingDecision.refuse(INACTIVE_USER)`.
- `unread_conversation_count(user) -> int`, and the inbox queryset for a user: conversations they take
  part in, ordered by `-last_message_at`, annotated with unread state and the other participant
  (`select_related` / `prefetch_related`, so the query count is flat).
- Thread page queries: the latest page (`MESSAGE_PAGE_SIZE`), the page before a cursor (fetch
  `PAGE_SIZE + 1` to know whether more exist), and messages after a cursor. The after-cursor query
  re-reads a two-second overlap, because concurrent inserts can commit out of `created_at` order; the
  client drops duplicates by `id`.

### Message body

Store the raw text. Render with `{{ message.body|urlize|linebreaksbr }}` under autoescape, inside an
element with `overflow-wrap: anywhere`. `urlize` links http, https and email addresses (as mailto), and
adds `rel="nofollow"`. Message text never goes through `render_markdown`. The limit is 2,000
characters, in the `MESSAGE_MAX_LENGTH` setting. The textarea carries `maxlength`, and a counter
appears from 1,800. An over-long or blank body returns 422 with the text kept.

### Policy (`freedom_ls/comms/messaging_policy.py`, `freedom_ls/messaging_policy/policy.py`)

- Add `RecipientGroup(label: str, users: list[User])`, a frozen dataclass, and
  `MessagingPolicy.group_recipients(*, sender, site, recipients: Sequence[User], scope: Model | None
  = None) -> list[RecipientGroup]`. The base class returns one group with an empty label, so existing
  custom policies keep working.
- `LayeredMessagingPolicy.group_recipients`: for a learner sender, offered educators first (labelled
  with the role display name from the role config, never "instructors"), then peers grouped by shared
  course. For an educator sender, learners grouped by cohort, restricted to cohorts the educator can
  see (inside `scope` when it is an `Organisation`), then a "Colleagues" group. A person appears once,
  under their first group by label. The cost is a fixed number of queries, run only on the capped page.
  It never names a cohort or course the sender cannot see.
- Narrow `can_reply`'s `conversation` type to `Conversation` under `TYPE_CHECKING`.

### Settings (`freedom_ls/comms/config.py`)

Add to `CommsConfig`: `MESSAGING_ENABLED` (default `False`), `MESSAGE_MAX_LENGTH` (2000),
`MESSAGE_PAGE_SIZE` (30), `MESSAGE_THREAD_POLL_SECONDS` (8), `MESSAGE_INBOX_POLL_SECONDS` (45). Set
`MESSAGING_ENABLED = False` in `config/settings_base.py` beside `NOTIFICATIONS_ENABLED`, and `True` in
`config/settings_dev.py`. While it is off, every messaging entry point renders nothing: the header
button, the inbox section's nav item, and the quick-view box. Every messaging URL returns 404.

### Notifications (`freedom_ls/base/notification_categories.py`, `freedom_ls/comms/notify.py`, `freedom_ls/comms/views.py`)

- `NotificationCategory` gains `rollup: bool = False`. Add to `FLS_NOTIFICATION_CATEGORIES`:
  `key="message.received"`, label "Direct message", icon `message`, message "New message from
  %(sender_name)s", `url_builder="freedom_ls.comms.notification_urls.conversation_url"`, `rollup=True`.
  The message carries no excerpt.
- `raise_notification`'s `write()`: for a rollup category, update the user's unread row with the same
  `rollup_key` if one exists. The update sets `data`, `created_at=now` and `seen_at=None`, and enqueues
  no delivery. Otherwise it creates a row as today, setting `rollup_key`. On an `IntegrityError` on the
  rollup constraint, it retries as an update. Non-rollup categories are unchanged.
- Public `mark_notifications_read(*, user, target, site_id)` in `comms`, sharing the read-implies-seen
  body of `_stamp_read`.
- `notification_mark_unread` is a no-op on a rollup row when another unread row with the same
  `rollup_key` exists.
- Marking a notification read or unread never changes the conversation's unread state.

### Shared pages and endpoints (`freedom_ls/comms/messaging_urls.py`, `app_name = "conversations"`, mounted at `messages/` in `config/urls.py`)

Every view is `login_required_htmx` and 404s when messaging is off. `send` and `start` respond with
the fragment for the surface that posted: the thread, or the quick-view box. A `start` from the
picker page redirects to the new thread. The decorator needs a `next`
parameter, since today it hard-codes the notification list. A conversation id the user does not take
part in returns 404.

| Name | Path | Does |
| --- | --- | --- |
| `inbox` | `""` | Inbox page. The fragment for htmx is a `{% partialdef %}`, and a history restore gets the full page. |
| `inbox_poll` | `"poll/"` | `?since=<latest last_message_at>`. Returns 204 when nothing changed, else the re-rendered list. |
| `unread_badge` | `"badge/"` | The header count fragment. |
| `thread` | `"<uuid:pk>/"` | Thread page. It marks read before the header renders. |
| `thread_poll` | `"<uuid:pk>/poll/"` | `?after=<cursor>`. Returns 204 when nothing is new; otherwise only the new messages, appended to the log. Re-asks `reply_decision` every time, and swaps the composer out-of-band only when the decision flipped. Marks read when the response holds incoming messages. Sends an `HX-Trigger` so the header count and inbox row refresh. |
| `thread_older` | `"<uuid:pk>/older/"` | `?before=<cursor>`. Returns the older page plus a fresh "Load earlier messages" control when more exist. |
| `send` | `"<uuid:pk>/send/"` | POST reply. |
| `start` | `"new/"` | GET picker. POST first message to `recipient` (a user pk), which creates or reuses the conversation. |
| `recipient_search` | `"new/search/"` | Debounced search, filtered inside `recipients_for`. |

Behaviour:

- **Pages** extend a neutral base (`_base.html` with `<c-page>`), not the course layouts. On desktop
  the inbox and the open thread sit side by side. At 375px the inbox and the thread are separate views,
  with a back control (icon `previous`). Inbox rows show the other participant, their last message
  time, an unread marker ("Unread" text plus an icon, never colour alone) and a "Read only" tag with
  the `locked` icon when `reply_decision` refuses. A refused thread keeps its place in the inbox and
  still counts as unread.
- **Thread** header names the other participant. There is no "who can read this" line. Messages carry
  `id="msg-<uuid>"` and a `data-` cursor. Day separators and sender grouping are derived server-side
  from the neighbouring message, including across appended and prepended fragments. The log is
  `role="log"` with an accessible name, and is changed only by appending or prepending. A separate
  polite `role="status"` region announces incoming messages from polls as "N new messages from
  <name>", never the text. A user who has scrolled up sees a "New messages" button rather than being
  pulled down. Prepending keeps the scroll position.
- **Accessibility**: every surface meets WCAG 2.2 AA at 375px. Targets are at least 24px. The
  sticky composer never covers the focused element (`scroll-padding`). The textarea has a visible
  label, not a placeholder alone.
- **Composer**: a labelled textarea, the counter, a hidden per-draft `client_key` UUID, and a Send
  button (icon `send`) with `hx-disabled-elt`. Polls never swap the composer's subtree. On success, the
  response appends the message, moves the newer cursor, and swaps in a fresh composer (new key, empty
  box). Focus stays in the textarea. On a 422 refusal, the composer is re-rendered with the draft and
  the same key, and an inline `role="alert"` shows the refusal copy below. There is no Retry. On a
  network failure (`htmx:sendError` / `htmx:timeout`), the draft stays in the box with the same key,
  and "Not sent. Check your connection and try again." offers Retry. The two failures look different.
- **Closed thread**: when `reply_decision` refuses, the composer is replaced (not disabled) by a
  `role="status"` note with the `locked` icon. The next load or poll that is allowed brings the
  composer back. The copy is keyed on `MessagingRefusal`, uses the other person's first name, and never
  says why the other person can't be reached (no status, course or date):

  | Reason | Heading | Body |
  | --- | --- | --- |
  | `CLOSED_BY_CONFIGURATION` | Replies are closed | Messaging between you and {first name} is closed here. You can both still read this conversation. |
  | `NO_RELATIONSHIP` | Replies are closed | You can no longer message {first name} from here. You can both still read this conversation. |
  | `INACTIVE_USER`, `SAME_USER` | Replies are closed | This conversation can't take new messages. You can still read it. |

  Refused on send, for every reason: "Not sent. {first name} can't receive messages from you here. Your
  text is still in the box."
- **Picker** (`start`): the search runs on the server inside `recipients_for`. It matches first name,
  last name and, for an educator sender, email, is debounced at 300ms, ordered by name, and capped at
  20 with a "Keep typing to narrow the list" line when the cap truncates. Results are grouped by
  `group_recipients`. If the sender has at most 15 recipients, all of them are listed grouped, with no
  typing needed. Above that, an empty field lists nobody, and a term of at least 2 characters is
  required. "No one you can message matches '…'" is the same whether the name is absent or refused.
  Educators see email as a disambiguator; peers see name and group only. The picker is a search field
  plus a list of buttons, built on `<c-panel-search-field>` and the `table_toolbar.html` trigger and
  `hx-sync` idiom. It is not an ARIA combobox. The server re-asks `can_start` on send. With an empty
  recipient set, the empty inbox for a learner reads "Your educators can message you, and you can
  reply." and shows no New message button.

### Header (`freedom_ls/base/templates/partials/header_bar.html`, `freedom_ls/comms/templatetags/comms_tags.py`)

A `messages_button` inclusion tag, a sibling of `notification_bell`. It renders nothing when
`MESSAGING_ENABLED` is off. The button links to `conversations:inbox`, with an icon (`message`) and an
`aria-label` that includes the count. The count badge is its own fragment (`conversations:unread_badge`),
polled every `MESSAGE_INBOX_POLL_SECONDS` with the shared timer and refreshed by the thread poll's

refresh"`), so the page render runs no count query.

### Icons (`freedom_ls/icons/semantic_names.py`, `freedom_ls/icons/mappings.py`)

Add `message` and `send` to `SEMANTIC_ICON_NAMES`, mapped in every set in `ICON_SETS`. The unread

### Educator interface inbox section (`freedom_ls/educator_interface/views.py`)

- `MessagesConfig(OrganisationSectionConfig, ListViewConfig)`, `url_name = "messages"`, `menu_label =
  "Messages"`, icon `message`, added to `interface_config`. It is hidden when messaging is off.
- The list is the educator's own conversations whose other participant has an active `Learner` row in
  `learners_visible_to(request.user, request.organisation)`. Rows are ordered by `-last_message_at`,
  with the same unread and Read only markers as the shared inbox.
- `authorise_instance` raises `OrganisationScopeDenied` (404) when the conversation is not the
  educator's or its learner is outside the organisation. A cohort viewer cannot open a cohort admin's
  conversation with the same learner, and a `site_admin` sees only their own.
- The instance view renders the thread partials from `comms`, posting and polling to the
  `conversations:*` endpoints.
- A New message action opens the picker, with `group_recipients(..., scope=request.organisation)`, and
  the candidates are limited to learners visible in that organisation.
- `educator_interface` importing `comms` is a new dependency edge. Declare it and regenerate
  `docs/app_structure.md`.

### Sidebar count (`freedom_ls/panel_framework/views.py`, `panel_framework/partials/sidebar_nav.html`)

`SectionConfigBase` gains `get_menu_count_url(request) -> str | None` (default `None`). When it
returns a URL, the sidebar renders a lazily loaded count fragment polled by the shared timer, instead
of calling `get_menu_count`. Navigating within the educator interface keeps the rendered count (stable
`id`, `hx-preserve`) and does not re-query it. Switching organisation refreshes it. `MessagesConfig`
points it at an educator-interface view that counts unread conversations in the selected
organisation's scope.

### Learner quick-view message box (`freedom_ls/educator_interface/quick_views.py`, `educator_interface/quick_views/learner.html`)

- `LearnerQuickView.get_context_data()` adds `reply_decision` or `can_start` for (educator, learner).
  When it is refused, the template shows no message box.
- The box shows the latest 3 messages of the pair's conversation if one exists, the composer, and an
  "Open conversation" link to the inbox section's instance. The link appears once a conversation
  exists. The box does not poll.
- The form posts to `conversations:send` or `conversations:start`, targeting a region inside the box,
  never `#quick-view-body`, so the drawer stays open. Errors render inline: a 422 refusal, or a network
  failure with Retry. A successful send shows the message among the 3 and a fresh composer.
- `LearnerQuickView.refresh_events` must not cause a refetch that wipes a draft. No messaging event is
  added to it.
- With a non-empty draft, opening another learner or closing the drawer asks before discarding. Reuse
  `appModal`'s dirty check (`_checkDirty`, `_serialiseForm`) in
  `panel_framework/static/panel_framework/js/alpine-components.js` rather than writing a second one.

## Testing

Use `mock_site_context`, `comms/factories.py` (add `ConversationFactory`, `MessageFactory`), and
`messaging_world.py` for policy pairs. Add a `MESSAGING_ENABLED = True` autouse fixture in
`comms/tests/conftest.py`.

- **Models and service**: one conversation per pair per site, both orders, with a concurrent create
  ending with one row. The pair key is unique per site, so the same pair on another site gets its own.
  A repeat `client_key` returns the original with no second row and no second notification. A repeat
  after the policy closed still returns the original. A refused send stores nothing. A blank or
  2,001-character body is refused, and exactly 2,000 is accepted.
- **Read state**: opening a thread sets `last_read_at` to the newest shown message, not `now()`. A
  message created between render and mark stays unread. Sending marks the sender read. The unread count
  counts conversations, not messages, with a flat query count.
- **Body rendering**: `<script>` and `<img onerror>` are escaped. `javascript:alert(1)` is not linked.
  `https://example.com/a?b=1&c=2` is linked with `rel="nofollow"`. An email address becomes a mailto
  link. Newlines become `<br>`. `{{ 7*7 }}` and `{% load %}` render literally.
- **Policy**: every send path asks the policy. `group_recipients` never names a cohort or course
  outside the sender's visibility, puts each person in one group, and runs a fixed number of queries.
  The base class's default returns one group.
- **Rollup**: the first message creates a row and enqueues delivery. A second message updates the same
  row (`seen_at` cleared, `created_at` bumped, no enqueue). After a read, the next message creates a
  new row and enqueues. Concurrent raises end with one unread row. Mark unread with an existing unread
  row is a safe no-op. The sender gets nothing. Opening the thread, or a poll that returns incoming
  messages, marks the notification read. `course.registered` behaviour is unchanged.
- **Views**: a non-participant gets 404 on every `conversations:*` URL. Another site's ids return 404.
  Messaging off returns 404 and hides the header button, nav item and quick-view box. Polls return 204
  when nothing is new and write nothing on that path. A refusal returns 422 with the draft and the same
  key. A refused thread swaps its composer for the note, and an allowed poll brings it back. Older
  pages return `PAGE_SIZE` with a control only when more exist. A message landing during a page load
  appears once. The picker shows the same output for an absent name and a refused one.
- **Educator interface**: `MessagesConfig` joins `interface_walk.py`, `test_permission_matrix.py`,
  `test_organisation_isolation.py` (foreign-organisation conversation or learner id returns 404) and
  `test_config_authorisation.py`. Colleague conversations are absent from the section. A cohort viewer
  cannot open a cohort admin's conversation. Navigation does not run the sidebar count query. The
  quick view shows no box when refused.
- **Playwright** (`comms/tests/playwright/`, `educator_interface/tests/playwright/`): an educator
  messages a learner from the quick view, moves to the next learner with the drawer open (the discard
  prompt appears with a draft), and the learner sees the header count and replies. The thread receives
  a message by polling without losing a draft. A double click on Send posts once. A send refused
  mid-thread keeps the draft. A network failure offers Retry. The 375px inbox-to-thread-and-back flow
  works for learner and educator.

## Open questions

Defaults taken; overrule any of them:

- Poll intervals: thread 8s, inbox and header count 45s.
- Picker thresholds: list everyone at 15 recipients or fewer, cap search results at 20, require 2
  characters above 15.
- The quick-view box shows the last 3 messages and does not poll.
- `urlize` links open in the same tab, with no `target="_blank"`.
- Educator copy for `CLOSED_BY_CONFIGURATION` carries no "a site admin can change this" hint.

## Success criteria

- With `MESSAGING_ENABLED = False`, no messaging control renders and every messaging URL returns 404.
- An educator sends a learner a message from the quick view without the drawer closing or a draft
  being lost to a refetch.
- A second message in an unread conversation leaves the recipient with exactly one unread
  notification, and only one delivery enqueued.
- Submitting the same draft twice stores one `Message`.
