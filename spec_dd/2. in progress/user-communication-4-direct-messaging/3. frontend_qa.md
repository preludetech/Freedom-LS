# Frontend QA: direct messaging

Two people on a site hold a private one-to-one conversation. Learners and educators get an inbox,
a thread and a composer on a neutral page; educators also get a Messages section in the educator
interface and a message box in the learner quick view. Delivery is by polling. Each unread
conversation raises one notification.

What a browser can see:

- **The header Messages button** with a polled unread-conversation count, beside the bell.
- **The inbox** at `/messages/`: rows newest-activity first, an "Unread" marker, a "Read only" tag,
  a New message button when the user has recipients.
- **The thread** at `/messages/<pk>/`: day separators, sender groups, Load earlier messages, a
  "New messages" button when a poll appends while scrolled up, a composer with Ctrl+Enter, a
  counter from 1,800 characters, and alerts for a refusal and a network failure.
- **The closed note** replacing the composer when replies are closed, and "Deleted user" when the
  other participant is gone.
- **The picker** at `/messages/new/`: search, grouped results, "Keep typing to narrow the list",
  "No one you can message matches '…'".
- **The educator Messages section** with a polled sidebar count, a New message action in the app
  modal, and the thread on the instance page.
- **The quick-view message box** with the last 3 messages, a composer, an Open conversation link
  and a discard prompt for an unsent draft.
- **The bell** showing one "New message from <name>" row per unread conversation.

Beyond the golden path, this run hunts for:

- **Duplicate sends** from a double click, a retry after a network failure, or a poll landing
  during a send.
- **Lost drafts**: a poll, a flip to the closed note, a quick-view refresh or moving to the next
  learner must never wipe text the user typed.
- **Leaks**: another site's or organisation's conversation id, a colleague conversation in the
  educator section, a cohort viewer opening a cohort admin's conversation, a refused name looking
  different from an absent one, message text in a notification or an announcement.
- **Counts that disagree** between the header badge, the sidebar count, the bell and the inbox.
- **Stale composers**: a thread whose policy changed under it must refuse on send and keep the
  text.

## §8 Failure modes and enumeration

1. **Double click.** As `l1` in the Vic thread, type "once" and double-click Send fast. Exactly one
   "once" bubble appears; the Send button was disabled during the request.
2. **Network failure.** With the thread open, set the browser offline (devtools), type "offline
   text", Send. The alert reads "Not sent. Check your connection and try again." with a Retry
   button; the text is still in the box. Go online, click Retry: the message appears once. Repeat
   with Retry clicked twice quickly: still once.
3. **Over-long body.** Remove the `maxlength` attribute through devtools, paste 2,001 characters,
   Send: 422, the alert says the message is too long, the text stays. Paste exactly 2,000: accepted.
4. **Non-participant.** As `l1` open `/messages/<pk of edu↔l2>/`: 404. Also 404 for
   `/messages/<pk>/send/` (POST), `/messages/<pk>/poll/`, `/messages/<pk>/older/`.
5. **Other site.** Any conversation pk from a different site (create one on another site if the
   dev database has one): 404.
6. **Foreign organisation.** As `edu` open
   `/educator/organisations/northside/messages/<pk of south.admin↔s1>`: 404. As `south.admin`
   open `/educator/organisations/southside/messages/<pk of edu↔l1>`: 404.
7. **Cohort viewer.** As `viewer@qa.test` open `/educator/organisations/northside/messages`: the
   list holds only Vic's own conversation with Lena. Open
   `/educator/organisations/northside/messages/<pk of edu↔l1>`: 404.
8. **Colleague conversation.** As `edu` the `edu↔edu2` pk under `/educator/organisations/northside/messages/<pk>`:
   404 (not a learner conversation), while `/messages/<pk>/` works.
9. **Deleted learner.** The deleted-user conversation's pk under the educator section: 404 (its
   learner row is gone); under `/messages/<pk>/` it renders read-only.
10. **Messaging off** (optional, needs a restart): set `MESSAGING_ENABLED = False` in
    `config/settings_dev.py`, restart the server. The header button is gone, `/messages/` is 404,
    the sidebar has no Messages item, `/educator/organisations/northside/messages` is 404, and the
    learner quick view shows no message box. **Revert the setting and restart** before continuing.
11. **Malformed cursor.** `/messages/<pk>/older/?before=garbage`: 400, no traceback.
12. **Stale picker.** As `edu` open New message, then in another context remove Bea from Cohort B
    and deactivate her Learner row. Back in the modal choose Bea (still listed), send: 422 with
    the refusal alert; nothing was created (no Bea row in the list after closing).
