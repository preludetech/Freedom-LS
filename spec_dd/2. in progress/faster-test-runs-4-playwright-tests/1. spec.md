# Spec: Fewer, faster Playwright tests

## Purpose

There are 218 Playwright test nodes (the idea's 220 was an estimate; `audit.md` counts them). Each
holds a browser and a live server for about 7s, and 147 of them fill in the allauth login form
before checking anything. Many load the same page with the same data to check one thing each, or
repeat a page once per viewport. This spec gets a signed-in session into the browser without the
form and merges same-page tests into flows. Every check the suite makes today is kept. Idea:
`idea.md`.

## Scope

In:

- A sign-in helper that gives the browser a session without the form, and every signed-in
  Playwright fixture and test switched to it.
- One Playwright test whose subject is signing in through the form.
- The merges `audit.md` lists, file by file.
- The `ds:playwright-tests` and `fls-dev:playwright-tests` skills, their resource files and the
  `playwright_fixtures.py` docstring, rewritten to the new rules.
- A before-and-after timing of the Playwright run.

Out:

- Non-browser tests.
- QA runs through the Playwright MCP.
- `DJANGO_ALLOW_ASYNC_UNSAFE` (already `True` for pytest in `pyproject.toml`), test-order hooks
  and xdist settings.

## Decisions

- **Session per test, by `Client.force_login`.** `transaction=True` flushes `django_session` after
  every test, so a session saved once (`storage_state`) is dead by the second test. A session made
  inside the test, after its user exists, lives until that test's flush. `force_login` builds the
  session through Django's own session engine and fires `user_logged_in` as a real login does; the
  receivers in `course_applications/receivers.py` and `referral_tracking/signals.py` are safe with a
  request that has an empty session and no cookies.
- **`backend="django.contrib.auth.backends.ModelBackend"` is passed explicitly.** The first entry in
  `AUTHENTICATION_BACKENDS` is Axes's backend, and `qa_login_session.py` already stores
  `ModelBackend`.
- **`audit.md` lists every node: 218 become 104, none dropped or moved to Client.**
- **Markup and text sub-checks in panel framework flows stay in their flows.** They cost
  milliseconds there, and moving them adds tests without removing a browser.
- **The 7 `test_section_smoke` cases stay separate**, so a failure names its section.
- **A merged flow stops at its first failure.** Plain sequential `expect` calls, no soft assertions
  or subtests.
- **One page at several viewports is one test.** It builds the data and signs in once, then calls
  `page.set_viewport_size` for each entry of `QA_VIEWPORTS` and checks in turn. A check that depends
  on JS that reads the size only at load reloads after resizing.
- **Fixture names stay.** `freedom_ls/conftest.py` re-exports `logged_in_page` and `logged_in_user`
  to downstream projects, so they keep their names and gain the faster sign-in with no change on
  their side. `_login_via_ui` stays importable for the sign-in test.

## Requirements

### Sign-in helper and fixtures

- `freedom_ls/tests/playwright_fixtures.py` gains a public function
  `sign_in(page: Page, live_server: LiveServer, user: User) -> None`. It calls
  `Client().force_login(user, backend="django.contrib.auth.backends.ModelBackend")` and adds one
  cookie to `page.context`: name `settings.SESSION_COOKIE_NAME` (it differs per worktree, see
  `config/settings_dev.py`), value from the client's cookie, `url=live_server.url`. It does not
  navigate.
- `logged_in_page` calls `sign_in` in place of `_login_via_ui`. `logged_in_user` is unchanged. Sign-in
  no longer needs its verified `EmailAddress`, but it stays, because a page may read it.
- `educator_logged_in_page` and `cohort_admin_logged_in_page`
  (`freedom_ls/educator_interface/tests/playwright/conftest.py`) call `sign_in`.
- Every other caller of `_login_via_ui` calls `sign_in`, including any second sign-in inside a
  test, which becomes a cookie swap on a fresh context or `page.context.clear_cookies()` followed by
  `sign_in`. The callers: `api_admin/.../test_add_form_layout.py`,
  `educator_interface/.../test_cohort_detail_mobile.py`,
  `form_engine/.../test_admin_answers_layout.py`, `mail/.../test_admin_changelist_mobile.py`,
  `messaging_policy/.../test_admin_changelist_mobile.py`,
  `referral_tracking/.../test_referral_admin_flow.py`,
  `registration_rules/.../test_rule_preview_flow.py`.
- `panel_framework/tests/playwright/test_component_reference_flow.py` keeps its own
  `force_login` helper, because panel framework tests never import `freedom_ls.tests`.
- After the change, `_login_via_ui` is called only by the sign-in test.

### Sign-in test

- New `freedom_ls/accounts/tests/playwright/test_sign_in_flow.py`, marked `playwright` and
  `django_db(transaction=True)`. On the bare `page` fixture, an email-verified user fills in the
  login form through `_login_via_ui` and leaves `account_login`.

### Merges

- Each file in `audit.md` ends with the tests its "Result" line names. Each merged flow carries
  every check of the rows marked `merges` into it, in an order where no earlier step changes the
  data a later check reads. `audit.md` notes where the order matters (for example
  `test_thread_composer_flow` and `test_learner_settings_flow`).
- A merged flow's assertion messages name the check, and inside a viewport loop the viewport, so a
  failure in pytest output says which check failed without opening the trace.
- Rows marked `stays` are untouched apart from the sign-in change.

### Skills and docs

- `claude_plugins/django-stack/skills/playwright-tests/SKILL.md` (lines 22 and 33) and
  `claude_plugins/django-stack/resources/playwright-testing.md`: a signed-in fixture makes a session
  on the server per test and adds its cookie to the browser context; only the test whose subject is
  signing in drives the form; one page at several viewports is one test that resizes; a merged
  flow's messages name the check and viewport. The resource's form-driving login fixture (lines
  118-136) is replaced by a `force_login` and `add_cookies` example with generic placeholders. No
  FLS names, paths or values: the plugin is generic.
- `claude_plugins/fls-dev/skills/playwright-tests/SKILL.md`: the fixture lines (13-14) name
  `sign_in` and say no form is used; "Why transaction=True and a login per test" says why the
  session is made per test.
- `claude_plugins/fls-dev/resources/playwright-testing.md` line 14 describes `sign_in`, not the form
  login.
- The `playwright_fixtures.py` module docstring describes `sign_in` and says why it is per test, and
  drops the "Role variants" advice.

### Timing

- `timings.md` beside this spec records two runs of `uv run pytest -m playwright --durations=20`
  on the same machine, back to back: "before" in a second worktree at the commit the branch started
  from, with its own test database; "after" on the finished branch. For each: node count,
  wall-clock time, and the slowest 20 tests. It compares them with the "Playwright" section of
  `spec_dd/1. next/faster-test-runs/research_test_timings.md` and says whether
  `faster-test-runs-1-fast-password-hasher` or `faster-test-runs-2-reuse-test-database` had landed
  in either run.

## Testing

- The full Playwright run passes on the finished branch.
- The sign-in test fails when the login form is broken. Check this once by pointing its submit at a
  wrong password; that edit is not committed.
- A test that takes `logged_in_page` and opens a page that needs sign-in lands on that page, not on
  `account_login`.
- `uv run pytest --collect-only -m playwright -q` shows about 104 nodes, and each "after" test name
  in `audit.md` is among them.

## Documentation and downstream

- `upgrade_notes.md` for downstream projects: `logged_in_page` no longer drives the login form, and
  a project test that used it to test its own login form must call `_login_via_ui` on `page`.
  `sign_in` is available for project fixtures.

## Success criteria

- `grep -rn "_login_via_ui(" freedom_ls` finds only the definition and the sign-in test.
- `pytest --collect-only -m playwright` collects about 104 nodes, down from 218.
- `timings.md` exists with both runs.
