## Rules every merge slice follows

These come from the spec's Decisions and Merges sections. Each merge slice applies them to its
files.

1. **Every check survives.** Before deleting an absorbed test, list its `expect`/`assert` lines.
   After the merge, each of those lines exists in the flow, with its data. A check whose data
   changed because the seed was unified (row counts, learner counts) is updated to the new
   number, and `audit.md` names each such case.
2. **Order.** No earlier step changes the data a later check reads. `audit.md`'s "Into" column
   gives the order wherever it matters. A step that navigates away, mutates rows, installs a
   route, overrides `navigator.clipboard.writeText` or changes a setting runs after every check
   that needs the untouched state, or the flow does a fresh `page.goto` after it. Remove every
   route with `page.unroute(...)` before the next step.
3. **Assertion messages name the check.** Plain `assert` lines carry a message
   (`assert box["width"] >= 160, "Who cell narrower than 160px at 768px"`). `expect(...)` calls
   that sit in a viewport loop or that are not self-describing pass `message=`. Inside a viewport
   loop the message includes the width:

   ```python
   for viewport in QA_VIEWPORTS:
       width = viewport["width"]
       page.set_viewport_size(viewport)
       # The tab strip reads its width only at load, so a resize needs a reload.
       page.reload()
       expect(name_cell, f"learner name truncated at {width}px").not_to_have_css(
           "text-overflow", "ellipsis"
       )
       assert_no_horizontal_overflow(page)
   ```

   `assert_no_horizontal_overflow` takes no message today. Leave the helper alone. When a loop
   calls it, the `width` is already visible in the test's preceding step, and Playwright's
   failure names the call site line. Do not edit `freedom_ls/tests/playwright_helpers.py` or the
   panel framework copy in `freedom_ls/panel_framework/tests/playwright/helpers.py`
   (`test_framework_copies_match_base.py` fails when they drift).
4. **Viewport loops.** One page at several viewports is one test. Build the data and sign in
   once, then `page.set_viewport_size(viewport)` for each entry of `QA_VIEWPORTS` (or the widths
   the original tests used). A check that depends on JS that reads the size only at load
   reloads after resizing. A former `parametrize` over widths becomes this loop.
5. **No soft assertions, no subtests.** Plain sequential `expect` and `assert`. The flow stops
   at the first failure.
6. **Separate contexts stay separate steps in one test only where the audit says merge.** A step
   that needs a JS-off or locale context opens it with `browser.new_context(...)` and signs it in
   with `sign_in` on a page from that context (see "Second sign-in" below), and closes it at the
   end of the step.
7. **Shared builders.** Where two absorbed tests built the same objects with different names,
   keep one builder (a private `_seed_...` function in the test file) and delete the duplicate.
   Do not add helpers to shared modules. A long flow may move each group of steps into a
   private `_check_<what>(page, ...)` function in the same file, called in order from the one
   test; the test's docstring still lists what the flow proves.
8. **`TODO` and `@claude` comments** in an absorbed test move into the flow beside the check they
   concern. A grep on the starting commit found none under `tests/playwright/`; re-grep each file
   before deleting a test.
9. **Count check per file.** After the slice, `uv run pytest --collect-only -q --no-cov <file>`
   lists exactly the tests the file's `audit.md` "Result" line names, under the names the audit
   gives.
10. **Run each file as its merge finishes**, then the slice's files together at the end
    ("Run the N files." below).

### Second sign-in

A test that needs a second user, or a fresh context, signs in with the helper on that context:

```python
# A learner session in its own context, so the admin's cookie never reaches it.
learner_context = browser.new_context(base_url=live_server.url)
learner_page = learner_context.new_page()
sign_in(learner_page, live_server, learner_user)
```

or, staying on one page, swaps the cookie:

```python
page.context.clear_cookies()
sign_in(page, live_server, learner_user)
```

Pick the cookie swap where the old test already called `clear_cookies()`. Pick a new context
where the old test opened one (JS-off, locale, `storage_state`). A test that copied cookies from
`logged_in_page.context.cookies()` into a new context calls `sign_in` on the new context's page
instead, with the same user.

   ```python
   from django.conf import settings
   from django.test import Client
   from pytest_django.live_server_helper import LiveServer


   def sign_in(page: Page, live_server: LiveServer, user: User) -> None:
       """Give ``page``'s browser context a session for ``user``, without the login form.

       The session is made in this test, after ``user`` exists, because ``transaction=True``
       flushes ``django_session`` after every test: a session saved once would be gone by the
       next test. ``force_login`` builds it through the session engine and fires
       ``user_logged_in`` as a real login does. Does not navigate.
       """

       # session, so the session records the model backend.
       client.force_login(user, backend="django.contrib.auth.backends.ModelBackend")
       # The cookie name differs per worktree (settings_dev), so read it from settings.
       cookie_name = settings.SESSION_COOKIE_NAME
       page.context.add_cookies(
           [
               {
                   "name": cookie_name,
                   "value": client.cookies[cookie_name].value,
                   "url": live_server.url,
               }
           ]
       )
   ```
