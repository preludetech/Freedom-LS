# Frontend QA: referral codes and the redirects behind them

The change adds a `ReferralCode` a builder creates in the admin, two public redirect routes
(`/go/{code}` and `/d/{CODE}`) that log every access as a `ReferralCodeHit`, a `ref` query parameter
that now mints the attribution cookie and lands in `referral_code` on the two existing tracking
models, a writable `ReferralCode` admin with copy buttons and a deactivate action, a read-only
`ReferralCodeHit` admin, a setting with a system check, and a prune command. Learners never see a
new screen. The risk is in the redirect (a public, unauthenticated route anyone can hammer), in what
the capture middleware now does and does not do, and in whether the admin refuses what it says it
refuses.

## §0 Setup

### Start the server

```bash
PORT=$(.claude/ds/scripts/find_available_port.sh)
uv run python manage.py runserver $PORT
```

Base URL is `http://127.0.0.1:$PORT`. Substitute it everywhere below.

### Login

Admin is `demodev@email.com` / `demodev@email.com` (password equals email). Admin lives at
`http://127.0.0.1:$PORT/admin/`. The four changelists are:

- `http://127.0.0.1:$PORT/admin/freedom_ls_referral_tracking/referralcode/`
- `http://127.0.0.1:$PORT/admin/freedom_ls_referral_tracking/referralcodehit/`
- `http://127.0.0.1:$PORT/admin/freedom_ls_referral_tracking/signupattribution/`
- `http://127.0.0.1:$PORT/admin/freedom_ls_referral_tracking/firsttouchcount/`

### The dev site's domain

The `go_url` and `d_url` fields build their host from the code's `Site` row, not from the address
you are browsing. Dev pins the site by name (`FORCE_SITE_NAME = "DemoDev"`), so read the domain once:

```bash
uv run python manage.py shell -c "
from django.contrib.sites.models import Site
print(Site.objects.get(name='DemoDev').domain)
"
```

Call that value `$SITE_DOMAIN` below. It will usually not carry the port you are running on; that
is expected.

### Cookie inspection

Several tests check the `fls_attribution` cookie. Use devtools (Application → Cookies) or read the
response headers of the landing request. The cookie is `HttpOnly`, so `document.cookie` never shows
it.

### Fresh visitors

Each landing test needs a browser with no `fls_attribution` cookie. Delete the cookie for
`127.0.0.1` between tests, or use a new incognito / Playwright context. A signup test also needs
Mailpit at `http://localhost:8025` and an email address never used on this database.

### Watching hits from the shell

The hit admin is the main way to see hits, but this prints the counters directly when a test asks
for exact numbers:

```bash
uv run python manage.py shell -c "
from freedom_ls.referral_tracking.models import ReferralCode, ReferralCodeHit
for c in ReferralCode._base_manager.all():
    print(c.code, c.is_active, c.hit_count, c.last_hit_at, c.hits.count())
"
```

## §1 Create a referral code

1. Log in as admin. Open the `ReferralCode` changelist and click Add.

**Expect:**

- The form offers `code`, `label`, `notes`, `destination`, `inactive_destination` and `is_active`
  (ticked). `code`'s help text says a blank code generates an 8-character print code and that the
  code cannot be changed after saving. No `site` field.
- `go_url`, `d_url`, `destination_preview`, `inactive_destination_preview`, `hit_count`,
  `last_hit_at` and `created_at` are shown as read-only text saying they appear once the code is
  saved.

2. Fill `code` `MrBeast`, `label` `MrBeast sponsorship`, `destination` `/courses/?utm_source=mrbeast`,
   leave `inactive_destination` blank, and save.

**Expect:**

- The changelist shows one row: `MrBeast`, the label, the destination, `is_active` ticked,
  `hit_count` 0, empty `last_hit_at`.
- Open the row. `code` is read-only text, not an input. `go_url` reads
  `https://$SITE_DOMAIN/go/MrBeast` and `d_url` reads `HTTPS://$SITE_DOMAIN/D/MRBEAST`, the second
  fully uppercase. The scheme is `https` because dev does not set
  `ACCOUNT_DEFAULT_HTTP_PROTOCOL`, so these URLs are for copying, not for opening against the dev
  server. Each has a Copy button beside it.
- `destination_preview` reads `/courses/?utm_source=mrbeast&ref=MrBeast`.
- `inactive_destination_preview` reads `/?ref=MrBeast` and says it is the default.

3. Add a second code leaving `code` blank, `label` `Van door`, `destination` `/courses/`,
   `inactive_destination` `/courses/?retired=1`.

**Expect:**

- The row saves with an 8-character uppercase code made of digits and letters, with no `I`, `L`,
  `O` or `U` in it. Its inactive preview reads `/courses/?retired=1&ref=<CODE>` with no "default"
  note.

4. Click the Copy button beside `go_url` on the `MrBeast` row, then paste into the browser's address
   bar or a text field.

**Expect:**

- The pasted text is exactly the `go_url`. A screen reader, or the accessibility tree in devtools,
  shows a polite live region reading "Copied" after the click. The button has an accessible name
  naming the URL it copies. The URL text stays selectable by mouse.
- Check the page source: no `onclick` attribute anywhere on the form. The script is loaded from
  `/static/referral_tracking/js/copy_button.js`.

5. Break the clipboard, then click Copy again. In the devtools console on the `MrBeast` change form:

```js
Object.defineProperty(navigator.clipboard, "writeText",
  {value: () => Promise.reject(new Error("denied"))});
```

**Expect:**

- The live region reads "Could not copy. Select the URL and copy it." — the button never looks like
  it worked when it did not. Nothing is written to the console as an unhandled rejection. Reload to
  restore the real clipboard.

## §2 Codes the admin refuses

Try each of these on the Add form.

1. `code` `mrbeast` (case-only duplicate of `MrBeast`).

**Expect:** the form re-renders with an error about a duplicate code, not a 500.

2. `code` `admin`, then `Admin`, then `login`, then `ACCOUNTS`.

**Expect:** each is refused as reserved.

3. `code` `demodev` and `demo-dev` (the site's own name, slugified, with and without the hyphen; adjust
   to the site's actual name if it differs).

**Expect:** each is refused.

4. `code` `my_code`, `my code`, `code!`, and a 65-character string.

**Expect:** each is refused with a message about letters, digits and hyphens. `my-code` is accepted
and can stay.

5. `destination` `//evil.com`, then `/\evil.com`, then `https://evil.com`, then `courses`, then
   `/a b`, then `/go/MrBeast`, then `/d/other`.

**Expect:** each is refused on the `destination` field with a message about a path on this site.
`/courses/x?a=1#top` is accepted. The same holds for `inactive_destination`.

6. Open the `MrBeast` change form and, in devtools, turn the read-only `code` text into an input
   named `code` with value `Other`, then save.

**Expect:** the code is still `MrBeast`. The form ignores a field it did not render.

## §3 The redirect

Use a fresh browser (no `fls_attribution` cookie) unless a step says otherwise. Watch the network
panel with "preserve log" on.

1. Open `http://127.0.0.1:$PORT/go/MrBeast`.

**Expect:**

- One 302 straight to `/courses/?utm_source=mrbeast&ref=MrBeast`, then the course listing renders.
  No intermediate 301, no trailing-slash hop.
- The 302 carries `Cache-Control: private, no-store` and `X-Robots-Tag: noindex`, and sets **no**
  `fls_attribution` cookie. The landing on `/courses/` **does** set it.
- `FirstTouchCount` gains one row for today with `utm_source` `mrbeast` and `referral_code`
  `MrBeast`, `count` 1. `ReferralCodeHit` gains one row: the code, the label, door `/go/`,
  `is_machine_fetch` unticked. The `MrBeast` row's `hit_count` is 1 and `last_hit_at` is now.

2. Still holding the cookie, open `http://127.0.0.1:$PORT/GO/MRBEAST`, then
   `http://127.0.0.1:$PORT/d/mrbeast`, then `http://127.0.0.1:$PORT/D/MRBEAST`.

**Expect:**

- All three 302 to the same target with `ref=MrBeast` (stored case, not what you typed).
- Three more hits, with doors `/go/`, `/d/`, `/d/`. `hit_count` is 4.
- The tally is unchanged at `count` 1 and no new cookie is set: a visitor already holding the
  cookie keeps the first touch.

3. Open `http://127.0.0.1:$PORT/go/MrBeast?utm_source=van&utm_campaign=spring&ref=hijack&x=`.

**Expect:**

- 302 to `/courses/?utm_source=van&utm_campaign=spring&x=&ref=MrBeast`: the visitor's `utm_source`
  wins over the destination's, the destination's other pairs would survive if it had any, the
  blank `x` survives, `ref=hijack` is dropped and the stored code appended last.

4. Open `http://127.0.0.1:$PORT/go/nobody` and `http://127.0.0.1:$PORT/go/my_code`.

**Expect:** both 404. No hit row, no cookie, no tally row.

5. From the shell:

```bash
curl -si -I "http://127.0.0.1:$PORT/go/MrBeast" | head -5
curl -si -X POST "http://127.0.0.1:$PORT/go/MrBeast" | head -3
curl -si -A "" "http://127.0.0.1:$PORT/go/MrBeast" | head -3
curl -si -A "Slackbot-LinkExpanding 1.0" "http://127.0.0.1:$PORT/go/MrBeast" | head -3
curl -si -A "Mozilla/5.0 (Linux; Android 12; CUBOT KINGKONG 5) Chrome/120.0" "http://127.0.0.1:$PORT/go/MrBeast" | head -3
curl -si -H "Sec-Purpose: prefetch" -A "Mozilla/5.0" "http://127.0.0.1:$PORT/go/MrBeast" | head -3
```

**Expect:**

- `HEAD` is a 302 and writes no hit.
- `POST` is 405.
- The empty UA, the Slackbot UA and the prefetch request each 302 and each write a hit with
  `is_machine_fetch` ticked, and none of them moves `hit_count` or `last_hit_at`.
- The CUBOT UA writes an unflagged hit and moves both.
- Check the numbers from §0's shell snippet: `hit_count` counts only the unflagged hits, while
  `hits.count()` counts every row.

## §4 Deactivation

1. In the changelist, tick `MrBeast`, choose "Deactivate selected referral codes", Go.

**Expect:** a message reporting 1 deactivated. `is_active` is unticked. Run the action again on the
same row: it reports 0.

2. In a fresh browser open `http://127.0.0.1:$PORT/go/MrBeast?utm_source=poster`.

**Expect:**

- 302 to `/?utm_source=poster&ref=MrBeast` (the setting's default `/`), then whatever `/` does for an
  anonymous visitor. A hit is still written and `hit_count` still rises. The changelist's
  `inactive_destination_preview` for this row matches the redirect's path and `ref`.

3. Set `inactive_destination` on `MrBeast` to `/courses/?retired=1` and repeat step 2.

**Expect:** 302 to `/courses/?retired=1&utm_source=poster&ref=MrBeast`, and the preview no longer
says "default".

4. Re-tick `is_active` on the change form and save.

**Expect:** the code is live again and `hit_count` was never reset.

## §5 What the admin refuses

1. On the `ReferralCode` changelist, open the action select.

**Expect:** "Delete selected referral codes" is absent. On a row's change form there is no Delete
button. Visiting `.../referralcode/<id>/delete/` directly returns 403.

2. Open the `ReferralCodeHit` changelist.

**Expect:**

- No Add button; `.../referralcodehit/add/` returns 403. Rows show `hit_at`, the code, its label,
  door and `is_machine_fetch`. Filters for `door` and `is_machine_fetch`; a date drilldown by
  `hit_at`; search by code or label finds the `MrBeast` rows.
- Opening a row shows every field read-only. The delete URL returns 403.

3. Create a staff user with no permissions (`User` admin, `is_staff` ticked) and log in as them in
   another context.

**Expect:** neither new model is on the admin index and both changelists return 403. Grant only
"Can view referral code" and reload: the `ReferralCode` changelist renders, its add URL returns
403, the change form is read-only, and the Export button is present. `ReferralCodeHit` still returns
403.

4. Make a code whose text the admin would refuse, then open its change form:

```bash
uv run python manage.py shell -c "
from django.contrib.sites.models import Site
from freedom_ls.referral_tracking.models import ReferralCode
ReferralCode._base_manager.create(site=Site.objects.get(domain__startswith='127.0.0.1'),
    code='has_underscore', label='Written past validation', destination='/courses/')
"
```

**Expect:**

- The change form opens. Edit its label and save: the row saves and the changelist shows the new
  label. It must not raise a server error — `code` is read-only here, so a complaint about the code
  text has no field to attach itself to. The Add form still refuses `has_underscore` if you type it.

## §6 Attribution carries the code

1. In a fresh browser, open `http://127.0.0.1:$PORT/go/MrBeast?advert_code=A1&utm_source=x`, then go
   to `http://127.0.0.1:$PORT/accounts/signup/` and sign up with a never-used email.

**Expect:**

- `FirstTouchCount` has a row with `referral_code` `MrBeast`, `advert_code` `A1`, `utm_source` `x`,
  `count` 1. The two compose; neither displaces the other.
- `SignupAttribution` has a row for the new email with `referral_code` `MrBeast`, `advert_code`
  `A1`, `utm_source` `x`, `landing_path` `/courses/` and a `raw_query` beginning
  `utm_source=x&advert_code=A1&ref=MrBeast` or the equivalent order.
- Both changelists show a `referral_code` column and search by it finds the rows. Neither offers
  `referral_code` as a sidebar filter.

2. In a fresh browser, open `http://127.0.0.1:$PORT/courses/?ref=anything-at-all`.

**Expect:** the page renders, a cookie is minted, and the tally gains a row with `referral_code`
`anything-at-all`. No `ReferralCode` is looked up and no hit is written: `ref` alone is a tracked
parameter and is stored as free text.

3. Export both existing changelists (tick a row, "Export selected …").

**Expect:** the CSV has a `referral_code` column with the values above. Export the two new
changelists the same way: `ReferralCode` exports every field except `site`; `ReferralCodeHit`'s
`referral_code` column holds the code text, not a UUID.

## §7 The setting and the check

1. Stop the server. In `config/settings_dev.py` add `REFERRAL_TRACKING_INACTIVE_DESTINATION = "//x"`
   and run:

```bash
uv run python manage.py check
```

**Expect:** the command fails with `freedom_ls_referral_tracking.E001` naming the setting. Change the
value to `https://x`: still fails. Change it to `/courses/`: passes. Remove the line: passes.

2. With `/courses/` set, start the server, deactivate a code with a blank `inactive_destination`,
   and follow it.

**Expect:** 302 to `/courses/?ref=<CODE>`, and its inactive preview says it comes from the default.
Remove the setting afterwards.

3. Stop the server, set `REFERRAL_TRACKING_HIT_LOG_LIMIT = 2` in `config/settings_dev.py`, start it
   again, and follow `/go/MrBeast` five times in a fresh browser window.

**Expect:**

- Every one of the five redirects lands on the destination: the cap never refuses the redirect.
- The hit admin gains 2 rows, not 5, and `hit_count` moves by at most 2 (§0's shell snippet).
- Set the value to `0` and repeat: all five are logged again. Remove the line afterwards.

## §8 Pruning

1. Age some hits from the shell, then prune:

```bash
uv run python manage.py shell -c "
from datetime import timedelta
from django.utils import timezone
from freedom_ls.referral_tracking.models import ReferralCodeHit
qs = ReferralCodeHit._base_manager.all()
first = qs.order_by('hit_at').first()
ReferralCodeHit._base_manager.filter(pk=first.pk).update(hit_at=timezone.now() - timedelta(days=40))
print(qs.count())
"
uv run python manage.py prune_referral_code_hits --older-than-days 30
uv run python manage.py prune_referral_code_hits --older-than-days 0
uv run python manage.py prune_referral_code_hits
```

**Expect:**

- The first run prints that it deleted 1 hit. The hit admin has one row fewer; every code's
  `hit_count` and `last_hit_at` are unchanged (§0's shell snippet).
- `--older-than-days 0` is refused with a usage error. Omitting the option is refused as missing.

2. Open one row in the referral code hit admin.

**Expect:** the page heading and the browser tab name the code text — `MrBeast via go at …` — not a
UUID. The changelist and the CSV export name it too.

## §9 What else could break

The middleware and the URLconf run on every request, so check these once:

- Existing routes still resolve: `/courses/`, `/accounts/login/`, `/educator/`, `/admin/`, `/robots.txt`,
  `/sitemap.xml`, `/health/`. `/go` and `/d/` with no code 404 through the normal handler.
- A learner course page such as `http://127.0.0.1:$PORT/courses/<slug>/` reached via a code still
  renders and its HTMX interactions still work; the cookie was minted on that landing, not on the
  redirect.
- A tracked landing on a page that redirects to login (`http://127.0.0.1:$PORT/?ref=MrBeast` as an
  anonymous visitor) still mints: the 302 to login sets the cookie and the tally gains a row.
- Open the `MrBeast` change form at a 375px-wide viewport: the long `go_url` and previews wrap inside
  their fields and the page does not scroll sideways. The Copy buttons still work.
- Log in and out of the admin with `?utm_source=x` on the URL: the admin renders, the visit is
  tallied like any other GET, and nothing on the redirect routes ever does.
- Deleting a user who signed up in §6: the delete summary lists their `SignupAttribution` row and
  the deletion succeeds. `ReferralCode` and `ReferralCodeHit` rows are untouched, since they never
  point at a user.
- A code created on another site (create a second `Site` from the shell and a code on it with
  `ReferralCode._base_manager.create(site=..., code="Other", label="x", destination="/")`):
  `http://127.0.0.1:$PORT/go/Other` returns 404 on the DemoDev site, and the code does not appear on
  the DemoDev admin changelist.
