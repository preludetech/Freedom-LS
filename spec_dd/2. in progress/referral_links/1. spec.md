# Spec: referral codes and the redirects behind them

Written against `idea.md` and the `research_*.md` files beside it. Where the older research files
disagree with `research_shipped_referral_tracking.md`, the latter describes the code as it is.

## Purpose

Marketing hands out URLs, on an affiliate's website, a trade-stand board or the side of a van, and
cannot later tell whether anyone used them. `referral_tracking` records who signed up and what they
arrived carrying, so a code that brought a thousand visitors and no signups looks the same as a code
nobody used. This work adds a `ReferralCode` a builder creates in the admin. Two routes redirect it
to a path on the same site and log every access. The code then joins the existing attribution
records as a seventh key value.

## Terminology

| Term | Status | Meaning |
| --- | --- | --- |
| `ReferralCode` | coined | A per-site code with a destination, an optional inactive destination, a label, notes and a hit counter. Replaces the "partner referral code" `referral_tracking` deferred to `Organisation`. |
| `ReferralCodeHit` | coined | One logged access of a `ReferralCode`. Holds no personal data. |
| `referral_code` | coined | Which `ReferralCode` a row concerns. On `SignupAttribution` and `FirstTouchCount` it is the code text a first touch carried. On `ReferralCodeHit` it is the foreign key. |
| door | coined | The prefix a hit arrived through: `go` (probably a click) or `d` (probably a scan). |
| inactive destination | coined | Where a deactivated `ReferralCode` redirects. Blank means `REFERRAL_TRACKING_INACTIVE_DESTINATION`. |
| machine fetch | coined | A hit whose request identified itself as automated or as a prefetch. Decided when the hit is written, and only the verdict is kept. |

## Scope

**In**

- `ReferralCode` and `ReferralCodeHit` models, inside `freedom_ls/referral_tracking/`.
- The `/go/{code}` and `/d/{CODE}` redirect routes and their view, the app's first.
- `ref` as a tracked parameter and `referral_code` as the seventh attribution key field on
  `SignupAttribution` and `FirstTouchCount`, on their changelists and in their exports.
- Capture suppressed on the two redirect routes.
- A writable `ReferralCode` admin with a bulk deactivate action, and a read-only `ReferralCodeHit`
  admin with CSV export.
- `REFERRAL_TRACKING_INACTIVE_DESTINATION`, validated by a system check.
- A `prune_referral_code_hits` management command.

**Out**

- QR image generation. FLS hands over the URL, and the designer renders the symbol.
- Any link to `Organisation`. The label says who a code is for.
- A bulk-create management command, a dashboard, and a partner-facing view.
- De-duplicating visitors, conversion rates per hit, and anything describing the visitor.
- Bot filtering on `FirstTouchCount`. The tally stays unfiltered.
- Retention tooling for `SignupAttribution` or `FirstTouchCount`.

## Decisions

- **Built inside `referral_tracking`, not as an extractable app.** Codes are unique per `Site`, and
  the cookie, the tally and the attribution rows all live in that app.
- **302, never 301.** A cached 301 skips the server, so repeat visits are never logged.
- **An inactive code still redirects and still logs.** A dead end on printed material is the worst
  outcome, and retired material that still pulls traffic is worth seeing. 404 is only for a code
  that never existed.
- **Codes are never recycled.** The admin refuses deletion outright, including for typos, and the
  code text is read-only once saved. A mistaken code is deactivated and keeps its text reserved.
- **The code's `ref` always wins, and otherwise the visitor's query wins.** Letting a visitor-typed
  `ref` survive would let anyone re-attribute a landing. For other keys, an advert wrapping a code
  is more specific than the builder's destination.
- **The counter and the most recent hit exclude machine fetches.** The log keeps every hit. The
  number on the changelist is the upper bound on human use, so a link preview does not make a dead
  code look alive.
- **Hits hold the verdict, never the user agent.** The raw string is a fingerprinting field on an
  anonymous visitor. The cost is that old hits cannot be reclassified.
- **Machine-fetch detection is a short list in the app, not a dependency.** The fetchers that
  matter here, link unfurlers and mail scanners, are not what crawler lists target.
- **`HEAD` resolves but writes no hit.** It is what monitors and "does this still work" checks send.
- **A referral code reaches attribution only as a first touch.** The shipped cookie is frozen on the
  first tracked landing and this work does not change that.
- **Capture suppression is keyed to the view, not to the status code or a path prefix.** A tracked
  landing on a page that redirects to login is a real landing, and the path check would break if the
  routes were ever mounted elsewhere.
- **Attribution rows hold the code text, not a foreign key.** They are written once from the cookie,
  and codes are never reused.
- **Case-insensitive uniqueness is a `Lower("code")` functional constraint, not `citext`.**
  `citext` needs a Postgres extension that a downstream database may not have.
- **Accept the one-day `FirstTouchCount` split on upgrade.** A seventh value changes every
  `key_hash`, so a key tallied on upgrade day lands on two rows. The tally is comparative, and a
  rehash migration is not worth writing for one day.
- **The change form shows both URL forms for every code.** Either door resolves any code, and the
  builder hands the right form to the right person.

### Code text and paths (`freedom_ls/referral_tracking/codes.py`, new)

**Code text**

- `CODE_PATTERN`: `[A-Za-z0-9_-]{1,64}`. The URL patterns use the same pattern, so anything else
  404s at the resolver.
- `GENERATED_CODE_ALPHABET = "0123456789ABCDEFGHJKMNPQRSTVWXYZ"`, which leaves out `I`, `L`, `O`  # pragma: allowlist secret
  and `U`, and `GENERATED_CODE_LENGTH = 8`. `generate_code(site)` draws with `secrets.choice` and retries a
  bounded number of times when a candidate collides or is reserved.
- The admin generates a code when the add form leaves it blank. Validation, including the uniqueness
  constraint, must see the generated value, so a collision surfaces as a form error or a retry and
  never as an `IntegrityError` 500.
- `RESERVED_REFERRAL_CODES`: a module-level `frozenset`, following `RESERVED_SECTION_SLUGS` in
  `freedom_ls/content_engine/schema.py:27`. At minimum: `admin`, `api`, `account`, `accounts`,
  `login`, `logout`, `signup`, `register`, `support`, `help`, `contact`, `security`, `billing`,
  `official`, `staff`, `static`, `media`, `www`, `mail`.
- A code is also reserved when it equals the code's own site brand: `slugify(site.name)`, or the
  same with hyphens removed. Skipped when `site.name` is blank.
- `validate_code_text(code, site)` enforces the pattern and both reserved checks, case-insensitively.
  It runs from `ReferralCode.clean()`.

**Paths**

- `validate_site_path(value)` accepts a destination, inactive destination or the setting when all
  of these hold:
  - It starts with exactly one `/`.
  - The second character is neither `/` nor `\`.
  - It has no whitespace or control characters.
  - Its path part does not resolve to either redirect view, which would make a loop.

  A query string and a fragment are allowed.
- `build_redirect_url(referral_code, query_string) -> str` is the single place a redirect target is
  assembled. The view and the admin previews both call it.
  1. Take `destination` when `is_active`. Otherwise take `inactive_destination`, or
     `config.REFERRAL_TRACKING_INACTIVE_DESTINATION` when that is blank.
  2. Split it with `urlsplit`. Parse its query and the visitor's with `parse_qsl(...,
     keep_blank_values=True)`.
  3. Keep the destination's pairs whose key the visitor does not also send, then all the visitor's
     pairs, in their original order. Drop every `ref` pair from both sides.
  4. Append `ref=<referral_code.code>`, the stored text rather than what was typed.
  5. Reassemble with `urlunsplit`, so the fragment stays last.
- `absolute_code_url(referral_code, door) -> str` joins the scheme,
  `getattr(settings, "ACCOUNT_DEFAULT_HTTP_PROTOCOL", "https")` as in
  `freedom_ls/accounts/allauth_account_adapter.py:123`, with `referral_code.site.domain` and the path
  from `reverse()`. The host comes from the code's site, never from the admin request. For
  `Door.D` the whole string is uppercased, so a QR symbol stays in alphanumeric mode.

### Hits (`freedom_ls/referral_tracking/hits.py`, new)

- `is_machine_fetch(request) -> bool` is true when any of these hold:
  - The `User-Agent` is empty or missing.
  - The lower-cased `User-Agent` contains a named fetcher. At least Slackbot, facebookexternalhit,
    Twitterbot, WhatsApp, TelegramBot, Discordbot, LinkedInBot, Googlebot, bingbot, Applebot and
    SkypeUriPreview.
  - The lower-cased `User-Agent` contains a generic token: `crawler`, `spider`, `preview`,
    `headless` or `bot`. `bot` is matched so that a device name such as "CUBOT" does not trip it.
  - `Sec-Purpose`, `Purpose` or `X-Moz` contains `prefetch`.
- `record_hit(referral_code, door, request)` writes the `ReferralCodeHit`. When the hit is not a
  machine fetch, it also runs one
  `.update(hit_count=F("hit_count") + 1, last_hit_at=<now>)`, in the same `transaction.atomic()`
  savepoint as the insert. A `DatabaseError` goes to `sentry_sdk.capture_exception` and is
  swallowed, so the visitor is still redirected. The precedent is
  `signals.record_attribution_on_signup`.

### Routes and view

- New `freedom_ls/referral_tracking/urls.py`, with `app_name = "referral_tracking"`, with two patterns
  and no trailing slash: `go/<code>` named `follow_go` and `d/<code>` named `follow_d`. Both
  prefixes match in either case, so `/D/P5H2B3C8` and `/Go/mrbeast` resolve. Both patterns must
  still reverse.
- `config/urls.py`: `path("", include("freedom_ls.referral_tracking.urls"))`, placed with the
  single-purpose mounts before the `""`-mounted apps.
- New `freedom_ls/referral_tracking/views.py`, holding one view, `follow_referral_code(request, code,
  door)`, restricted with `require_safe`. In order:
  1. Call `suppress_capture(request)` before anything else, so a 404 on this route does not mint
     either.
  2. If `get_cached_site(request)` is not a `Site`, return 404. The lookup must filter on that site
     explicitly, because `SiteAwareManager` falls through unfiltered for an `UnknownSite`.
  3. Look up the code on that site through the same `Lower("code")` expression the constraint
     indexes. If there is none, return 404. Inactive codes are found like active ones.
  4. On `GET`, call `record_hit`. `HEAD` skips it.
  5. Build the target with `build_redirect_url(code, request.META["QUERY_STRING"])`. Re-check it
     with `url_has_allowed_host_and_scheme(target, allowed_hosts={request.get_host()})`. If the
     check fails, use `/` as the base path and keep the same query rules.
  6. Return a 302 `HttpResponseRedirect` with `Cache-Control: private, no-store` and
     `X-Robots-Tag: noindex`. Set no `Referrer-Policy`.

### Capture (`capture.py`, `middleware.py`, `factories.py`)

- `ref` joins `TRACKED_PARAMS`, so a landing carrying only `ref` mints.
- The payload is keyed by field name, and `ref` is the one tracked parameter whose field name
  differs. `first_touch_from_request` reads `request.GET["ref"]` into `referral_code`, sanitised to
  `CAPS["referral_code"]`. Today the payload, `CAPS`, `COOKIE_KEYS` and the `**frozen` handed to
  `SignupAttribution.objects.create` all assume the parameter name is the field name. That
  assumption has to hold for every other parameter and be broken deliberately for this one.
- `ref` is not in `LOWERCASED_PARAMS`, since the redirect already appends the stored text.
- Capture never looks `ref` up against `ReferralCode`. A hand-typed `?ref=anything` is stored as
  free text, the way `advert_code` is, and the mint path gains no query.
- `COOKIE_KEYS["referral_code"] = "rc"`. `referral_code` is never in `COOKIE_DROP_ORDER`. A cookie
  minted before the upgrade has no `rc` and reads as a blank `referral_code`.
- `capture.py` gains `suppress_capture(request)` and `is_capture_suppressed(request)`. The redirect
  view calls the first. `AttributionCaptureMiddleware.__call__` (`middleware.py:45`) checks the
  second after `self.get_response(request)` returns and, when it is set, returns the response
  without setting the cookie or incrementing the tally.
- `FirstTouchCountFactory` declares `referral_code = ""` explicitly, beside the other key fields, so
  its `key_hash` `LazyAttribute` sees it.
- New `ReferralCodeFactory` and `ReferralCodeHitFactory`, both on `SiteAwareFactory`.

### Admin (`admin.py`, `resources.py`, `forms.py`)

`ReferralCodeAdmin(SiteAwareExportModelAdmin)`:

- The form uses `ConstraintValidationFormMixin` (`freedom_ls/site_aware_models/forms.py:20`) with
  `constraint_fields = ["site"]`, so a case-only duplicate is a form error.
- Editable: `label`, `notes`, `destination`, `inactive_destination`, `is_active`, and `code` on the
  add form only. The `code` help text says a blank code generates an 8-character print code, and
  that the code cannot be changed after saving.
- Read-only on the change form:
  - `go_url` and `d_url`, from `absolute_code_url`, each with a copy button.
  - `destination_preview` and `inactive_destination_preview`, from `build_redirect_url` with an
    empty query string, so they show the `ref` a partner's analytics will record. The inactive
    preview says when it comes from the default.
  - `hit_count`, `last_hit_at` and `created_at`.

  On the add form these fields say they appear once the code is saved.
- The copy button is a static script loaded through the admin's `Media`, beside
  `site_aware_models/css/admin.css`. It uses no inline handler, since `SECURE_CSP_REPORT_ONLY` is
  one step from enforcement, and adds no dependency. It calls `navigator.clipboard.writeText`, has
  an accessible name, and announces "Copied" through a polite live region. The URL stays selectable
  text for when the clipboard API is unavailable, as it is over plain HTTP.
- `list_display`: `code`, `label`, `destination`, `is_active`, `hit_count`, `last_hit_at`.
  `list_filter`: `is_active`. `search_fields`: `code`, `label`, `notes`.
- `has_delete_permission` returns `False`, which also removes Django's "Delete selected" action.
- `actions`: `deactivate_referral_codes`, which sets `is_active=False` across the selection and
  reports how many changed.
- `resource_classes = [ReferralCodeResource]`, exporting every field except `site`.

`ReferralCodeHitAdmin(SiteAwareExportModelAdmin)`, read-only like the two existing admins:

- `list_display`: `hit_at`, the code, its label, `door`, `is_machine_fetch`.
  `list_select_related = ["referral_code"]`.
- `list_filter`: `door`, `is_machine_fetch`. `date_hierarchy = "hit_at"`.
  `search_fields`: `referral_code__code`, `referral_code__label`.
- Add, change and delete are refused. Pruning is the command's job.
- `ReferralCodeHitResource` exports the code text through `ForeignKeyWidget(ReferralCode, "code")`,
  mirroring `SignupAttributionResource.user`.

`SignupAttributionAdmin` and `FirstTouchCountAdmin` gain `referral_code` in `list_display` and
`search_fields`, not in `list_filter`. It has one value per code, the high-cardinality trap those
admins already avoid. Their exports pick the column up with no change.

### Setting and check (`config.py`, `checks.py` new, `apps.py`)

- `REFERRAL_TRACKING_INACTIVE_DESTINATION: str`, `Setting(default="/")`.

### Management command

`freedom_ls/referral_tracking/management/commands/prune_referral_code_hits.py`, in `djclick`:

- `--older-than-days N` is required, and `N` must be at least 1.
- It deletes `ReferralCodeHit` rows with `hit_at` older than now minus `N` days, across every site,
  in primary-key batches, and prints how many it deleted.
- It never touches `hit_count` or `last_hit_at`.

## Testing

Tests go one file per module, beside the existing ones in `freedom_ls/referral_tracking/tests/`,
using `mock_site_context`.

- **Models.** `mrbeast` and `MrBeast` on one site violate the constraint, and the same code on two
  sites does not. Deleting a `ReferralCode` that has hits is refused.
- **Code text.** Each reserved word in any case is rejected, as is the site's slugified name with
  and without hyphens. Anything outside `CODE_PATTERN` is rejected. A generated code has 8
  characters from the alphabet, and generation retries past a collision and past a reserved
  candidate.
- **Paths.** Rejected: `//evil.com`, `/\evil.com`, `https://x`, `x`, `/a b`, a control
  character, and `/go/other`. Accepted: `/`, `/courses/x`, `/courses/x?a=1#top`.
- **`build_redirect_url`.** For an active code, an inactive code with its own inactive destination,
  and an inactive code on the default, checking that:
  - destination query pairs survive;
  - the visitor's query survives;
  - the visitor wins on a shared key;
  - `ref` from either side is replaced by the stored code;
  - a stored `MrBeast` reached as `mrbeast` appends `ref=MrBeast`;
  - the fragment stays last.
- **View.**
  - `/go/mrbeast`, `/GO/MRBEAST`, `/d/mrbeast` and `/D/MRBEAST` all 302 to the same target, and
    each hit records its door.
  - The response has no trailing-slash hop and carries `Cache-Control: private, no-store` and
    `X-Robots-Tag: noindex`.
  - An inactive code 302s and logs. An unknown code 404s. A code on another site 404s.
  - `HEAD` 302s and writes no hit. `POST` is 405.
  - A `DatabaseError` in `record_hit` still redirects.
- **Machine fetch.** Each named fetcher, an empty UA, and each prefetch header are flagged. A fixed
  set of real browser UAs, including a CUBOT Android device, is not. A flagged hit writes a row but
  moves neither `hit_count` nor `last_hit_at`; an unflagged hit moves both.
- **Capture.**
  - `/go/mrbeast?utm_source=x` sets no cookie and tallies nothing.
  - The destination landing with `ref=mrbeast&utm_source=x` mints one cookie and one tally row
    whose `referral_code` and `utm_source` are both set.
  - A visitor already holding the cookie is logged as a hit and keeps the original first touch.
  - A signup after a `ref` landing writes `SignupAttribution.referral_code`.
  - A pre-upgrade cookie without `rc` still reads.
  - A tracked landing on a page that redirects to login still mints.
- **Admin.**
  - Add with a blank code generates one. A case-only duplicate is a form error, not a 500.
  - `code` is read-only on change.
  - No delete permission and no "Delete selected" action.
  - The deactivate action flips the selection.
  - `go_url` uses the code's site domain, and `d_url` is fully uppercase.
  - The previews match what the view redirects to.
  - The hit admin refuses add, change and delete.
  - Both new exports work, and the two existing exports carry `referral_code`.
- **Command.** Rows older than the cutoff are deleted on every site, newer rows stay, and
  `hit_count` is unchanged.
- **Check.** `E001` fires for `//x` and for `https://x`, and is silent for the default.
- **Playwright.** the copy button puts `go_url` on the clipboard.

## Success criteria

- `/go/{code}` and `/d/{CODE}`, in any case, 302 an existing code to its destination with `ref` set
  to the stored code, and 404 an unknown one.
- A deactivated code 302s to its inactive destination, or to the setting when that is blank, and
  still logs.
- `ReferralCodeHit` has no column that describes the visitor.
- A machine fetch writes a hit row and leaves `hit_count` and `last_hit_at` unchanged.
- No request to either redirect route sets the attribution cookie or increments `FirstTouchCount`.
- A signup whose first tracked touch came through a code has that code in
  `SignupAttribution.referral_code`, and `FirstTouchCount` rows split by it.
- The admin cannot delete a `ReferralCode` or change its code text.
- A duplicate code differing only in case is refused with a form error.
- The change form shows copyable `go_url` and `d_url` and both redirect previews.
- `prune_referral_code_hits --older-than-days 30` removes older hits and leaves counters intact.
- `manage.py check` fails when `REFERRAL_TRACKING_INACTIVE_DESTINATION` is not a site path.
- `uv run pytest` passes.
