Source: `1. spec.md` in this directory. Research that backs the plan: `research_codebase.md`
(touch points, `update_fields` writers, receivers) and the shipped foundation spec at
`spec_dd/3. done/2026-11-03_09:54_apis-for-lead-monitoring-1-foundation-and-users/`, whose
`freedom_ls/accounts/api.py` and `freedom_ls/accounts/tests/test_api.py` are the templates every

slice can own (the abstract base and the widened bound); slice 2 is the thinnest behaviour that
runs end to end (a key lists one site's course interest with `updated_at`); slices 3 to 5 widen it
to the two registration models; slice 6 is the final verification.

> invariant, the product-doc edit, the upgrade notes and the roadmap edit are not slices. Why: the

## Skills and conventions for every slice

- `fls-dev:testing` and `ds:testing`: tests live at `freedom_ls/<app>/tests/test_<module>.py`
  (`api.py` → `test_api.py`; `models.py` → `test_models.py`; the migration tests sit beside the
  existing `test_migrations.py`). Every test that touches a site-aware model takes
  `mock_site_context` and never sets `site`. Factories, never `.objects.create()`. `reverse()`,
  never a literal path. One behaviour per test (a name that needs "and" is two tests), no
  `if`/`for`/`try` in a test body, AAA. A query-count guard never asserts an exact count; the
  spec's same-count-at-page-size-2-and-50 test is the one deliberate exception, and it compares
  two measured runs rather than asserting a number. Framework behaviour (`auto_now` on create
  and full save) is not tested; only the partial-save override and its callers are. No markers:
  every test here is portable. Run tiers with the commands in
  `claude_plugins/django-stack/resources/test_tiers.md`.
- `fls-dev:multi-tenant`: every `get_queryset` starts from `Model._base_manager` and lets
  `ReadOnlyApiViewSet.filter_queryset` apply the key's site. This departs from the manager's
  automatic filtering on purpose: an API request has no ambient site, so the key's site is the
  only site there is. The backfill runs on the historical model's `_base_manager` so every
  site's rows are stamped. Tests that read rows outside the ambient site use `_base_manager`.
- Fixtures: `api_key`, `auth`, `client` and `_clear_cache` are copied per app rather than shared,
  because the spec allows no change in `freedom_ls/api/` beyond the two bounds and each is a few
  lines; `freedom_ls/accounts/tests/test_api.py` is the precedent.
- `ds:code-comments` and `sdd:planning-references-in-code`: a comment states a reason, never a
  restatement, and never names the spec, the plan, a slice, another spec or a QA bug. The
  snippets below are written to be copied as they are.
- `fls-dev:domain-glossary`: "registration" is the word; an `is_active=False` row is
  "deactivated", never "removed"; removing course interest deletes the row, so "removed" is right
  there and only there.
- `ds:testing`'s dependency rule: an app's tests import only apps it depends on at runtime.
  `learner_management` tests may not import `registration_rules`, so the rule-retraction
  call-site test lives in `registration_rules/tests/test_evaluation.py`.
- No MCP is needed for implementation.

## Slice 1: `UpdatedAtModel` and the widened pagination bound

> **Reverted in code review.** Field order is read: `pre_save` stamps `auto_now` and
> `auto_now_add` fields in declaration order, so putting `updated_at` in a parent of
> `TimestampedModel` stamped it before `created_at` on every `TimestampedModel` row. The three
> models now declare `updated_at` directly after their creation timestamp, `TimestampedModel`
> is as it was, and `freedom_ls/api/` was already bound to `Model`. The text below is the
> original slice, kept as the record of what was built and undone.

**Behaviour.** `ApiKeysetPagination` and `paginate_all` accept any model that takes
`UpdatedAtModel`. Nothing user-visible changes; the existing suite proves nothing regressed.

> **Assumed default:** this groundwork stays its own slice rather than folding into slice 2.
> Why: it edits a base class forty models take, and a commit that runs mypy, the pagination
> tests and `makemigrations --check` on that change alone isolates any regression from the
> endpoint work. To change: merge this section into slice 2 as its first step.

**Files.**

`freedom_ls/site_aware_models/models.py`, above `TimestampedModel`:

```python
class UpdatedAtModel(models.Model):
    """Adds a modification timestamp on its own.

    The base the API's keyset paging reads updated_at through, for models that
    record their creation under a domain name such as registered_at and must
    not gain a second creation column.
    """

    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        abstract = True


class TimestampedModel(UpdatedAtModel):
    """Adds creation and modification timestamps. ..."""  # existing docstring stays

    created_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        abstract = True
```

`TimestampedModel` drops its own `updated_at` line and keeps its docstring. The field
definitions every concrete model ends up with are unchanged, so `makemigrations --check` stays
clean; `updated_at` now precedes `created_at` in their field order, which nothing reads.
`TIMESTAMPED_MODELS` in `freedom_ls/contrib/conformance/tests/test_timestamped_models.py` tests
`issubclass(model, TimestampedModel)`, which the three models of later slices will not be, so the
registry is untouched.

`freedom_ls/api/pagination.py`: import `UpdatedAtModel` instead of `TimestampedModel`;
`M = TypeVar("M", bound=UpdatedAtModel)`. Nothing else in the file moves.

`freedom_ls/api/tests/helpers.py`: `def paginate_all[M: UpdatedAtModel](...)`, same import swap.

**Tests.** None new: `freedom_ls/api/tests/test_pagination.py`, `freedom_ls/accounts/tests/test_api.py`
and `freedom_ls/contrib/conformance/tests/test_timestamped_models.py` (run it with
`-m fls_internal`) pass unchanged. `uv run mypy freedom_ls/api freedom_ls/site_aware_models` and
`uv run manage.py makemigrations --check` pass.

```python
from django.apps.registry import Apps
from django.db import migrations, models
from django.db.backends.base.schema import BaseDatabaseSchemaEditor
from django.db.models import F


def backfill_updated_at(apps: Apps, schema_editor: BaseDatabaseSchemaEditor | None) -> None:
    # Rows that predate the column are stamped with the interest date, so
    # incremental sync sees them in age order rather than all at deploy time.
    CourseInterest = apps.get_model("freedom_ls_course_interest", "CourseInterest")
    CourseInterest._base_manager.update(updated_at=F("created_at"))


class Migration(migrations.Migration):
    dependencies = [("freedom_ls_course_interest", "0001_initial")]

    operations = [
        # Nullable first: the column has to exist and be filled before it can
        # refuse NULL.
        migrations.AddField(
            model_name="courseinterest",
            name="updated_at",
            field=models.DateTimeField(null=True),
        ),
        migrations.RunPython(backfill_updated_at, migrations.RunPython.noop),
        migrations.AlterField(
            model_name="courseinterest",
            name="updated_at",
            field=models.DateTimeField(auto_now=True),
        ),
        migrations.AddIndex(
            model_name="courseinterest",
            index=models.Index(
                fields=["site", "updated_at", "id"], name="course_interest_site_upd_idx"
            ),
        ),
    ]
```

The final `AlterField` must spell the field exactly as the model does, or `makemigrations
--check` reports a change. One migration, one transaction: the `UPDATE` touches no foreign-key
column, so no deferred trigger event blocks the `ALTER TABLE`; the executor test below proves it.

**Shared user flattening.** `freedom_ls/accounts/api.py` gains, above `UserApiSerializer`:

```python
def user_fields(
    source: str,
) -> tuple[
    serializers.IntegerField,
    serializers.EmailField,
    serializers.CharField,
    serializers.CharField,
]:
    """The read-only user_id, user_email, user_first_name and user_last_name
    fields, in that order, read from the user at `source` ("user",
    "learner.user"). Unpacked under those names in a serializer body, so every
    endpoint that flattens a user names the columns the same way and user_id
    joins to id on the users endpoint.
    """
    return (
        serializers.IntegerField(source=f"{source}.id", read_only=True),
        serializers.EmailField(source=f"{source}.email", read_only=True),
        serializers.CharField(source=f"{source}.first_name", read_only=True),
        serializers.CharField(source=f"{source}.last_name", read_only=True),
    )
```

A tuple rather than a mixin: DRF's `SerializerMetaclass` only collects `Field` attributes from
the class body and from bases that are serializers, and the four fields' `source` differs per
endpoint, so a mixin would need a fixed path. Unpacking four names in the class body is what the
metaclass sees as four declared fields. `read_only=True` is set on each declared field because
`Meta.read_only_fields` does not reach declared fields.

## Slice 3: `updated_at` on both registration models

**Behaviour.** `LearnerCourseRegistration` and `CohortCourseRegistration` carry `updated_at`,
which moves on every save including `save(update_fields=["is_active"])`, so every deactivation
and reactivation the application makes is visible to incremental sync. Existing rows carry
`updated_at` equal to `registered_at`. Receivers that read `update_fields` behave as before.

> **Assumed default:** both registration models change in this one slice, with no endpoint,
> and the model and call-site tests stay here rather than moving to slices 4 and 5. Why: the
> spec allows one `learner_management` migration, so the two models cannot be split across
> slices without a second migration, and the mixin is tested once where it is written. To
> change: edit the spec's "Models and migrations" to allow two migrations, then fold the learner
> half into slice 4 and the cohort half into slice 5.

**Model.** `freedom_ls/learner_management/models.py`: both classes gain `UpdatedAtModel` as
their last base and the mixin below as their first; each `Meta` gains `indexes = [models.Index(fields=["site", "updated_at", "id"],
name="lm_learner_reg_site_upd_idx")]` (cohort: `lm_cohort_reg_site_upd_idx`). Both need the same
`save` override, so it lives once in `UpdatedAtInUpdateFieldsMixin`, placed next to
`LoadedIsActiveMixin` in the same module and typed the same way (`_MixinBase` under
`TYPE_CHECKING`):

```python
class UpdatedAtInUpdateFieldsMixin(_MixinBase):
    """Keep updated_at moving on partial saves."""

    def save(
        self,
        *,
        force_insert: bool | tuple[ModelBase, ...] = False,
        force_update: bool = False,
        using: str | None = None,
        update_fields: Iterable[str] | None = None,
    ) -> None:
        # Every is_active writer saves with update_fields=["is_active"], which
        # skips auto_now; the stamp rides along so a deactivation is visible
        # to anyone syncing on updated_at. An empty update_fields means "write
        # nothing" and is left alone.
        fields = None if update_fields is None else frozenset(update_fields)
        if fields:
            fields = fields | {"updated_at"}
        super().save(
            force_insert=force_insert,
            force_update=force_update,
            using=using,
            update_fields=fields,
        )
```

The `frozenset` first, as `LoadedIsActiveMixin.save` does, so an exhausted generator cannot
read as non-empty.

The resulting bases:
`class LearnerCourseRegistration(UpdatedAtInUpdateFieldsMixin, LoadedIsActiveMixin, SiteAwareModel, UpdatedAtModel)`
and the same for `CohortCourseRegistration`. The MRO runs this `save` first, then `LoadedIsActiveMixin.save`, which freezes the set; the
receivers then see `frozenset({"is_active", "updated_at"})`. `detach_rule_on_foreign_is_active_change`
tests `"is_active" not in update_fields`, `evaluate_learner_on_save` tests
`update_fields.isdisjoint({...})` on `Learner` (not these models), and the `flipped_on`/
`flipped_off` methods of `LoadedIsActiveMixin`, which the `registration_rules` and
`course_recommendations` receivers call, test `"is_active" in update_fields`: the extra member
changes none of them.

**Migration.** `freedom_ls/learner_management/migrations/0010_registration_updated_at.py`,
depending on `("freedom_ls_learner_management", "0009_learnerimport_learnerimportrow")`, the
shape of slice 2's migration with the operations doubled: `AddField` (nullable) for both models,
one `RunPython(backfill_updated_at, migrations.RunPython.noop)` whose function updates both
historical models with `F("registered_at")`, `AlterField` to `models.DateTimeField(auto_now=True)`

```python
def organisation_fields(
```
