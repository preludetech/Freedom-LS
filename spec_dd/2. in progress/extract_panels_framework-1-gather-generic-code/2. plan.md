# Plan: gather the generic panel code into the framework

Spec: `1. spec.md` in this directory. Evidence: `research_codebase.md` (what moves, with line
numbers) and `research_consistency_audit.md` (every hand-built copy a slice replaces).

## How to read this plan

- `PF` is `freedom_ls/panel_framework`, `EI` is `freedom_ls/educator_interface`. `PF/templates/pf/`
  is short for `PF/templates/panel_framework/`, and `EI/templates/ei/` for
  `EI/templates/educator_interface/`. `Touches:` lines spell paths in full.
- Line numbers are from the start of the work and drift as slices land. Find code by name.
- The work is TDD. Each slice lists the tests that prove it; write each test first and watch it
  fail. A moved test keeps its assertions and changes only its imports, stubs and location.
- No model changes anywhere. `uv run manage.py makemigrations --check` must report no changes
  after every slice.
- Every slice ends with the full suite passing (`uv run pytest`), `npm run tailwind_build` when a
  template changed, and one commit.

### Rules every slice follows

- **No aliases and no copies.** A moved name is deleted from its old module, and every importer is
  updated in the same slice. A moved cotton component is deleted from its old app in the same slice:
  two apps holding the same `cotton/<name>.html` shadow each other by `INSTALLED_APPS` order.
- **The framework imports no FLS app in Python beyond what it imports today** (`base`,
  `site_aware_models`). Nothing moved in may import `audit_log`, `comms`, `reports`, `deployment`,
  `learner_management` or `sentry_sdk`.
- **Educator wording stays in `EI`.** A moved template or form takes its visible text from an
  attribute or context key with a neutral default, and `EI` sets today's text.
- **Framework tests use stubs.** Client-level tests build their stub action, panel or section in
  the test module and call it through `PF/tests/view_helpers.py`. Only a stub a browser must reach
  by URL goes in `PF/tests/stub_panels.py`. Component tests use
  `PF/tests/cotton_helpers.py::render_cotton`. Framework tests never import `EI`.
- **Render tests assert the contract, not the styling:** `role`, `aria-*`, `href`, `hx-*`,
  `data-*`, `autofocus`, `disabled`, text. Template-source scans in
  `PF/tests/invariants/test_templates.py` are the one place class names are checked.
- **Browser tests extend an existing flow** in `PF/tests/playwright/` with a step and an
  assertion; a new file is for a new journey only. Each is `@pytest.mark.playwright` and
  `@pytest.mark.django_db(transaction=True)`, and its last step loops `QA_VIEWPORTS` with
  `assert_no_horizontal_overflow`.
- **Alpine is the CSP build:** no inline expressions, every component registered with
  `Alpine.data()`, values passed through `data-*`, listeners and timers removed in `destroy`.
- **Comments and docstrings give the reason itself.** None names this plan, the spec, a slice or
  a section. Existing `TODO` and `@claude` comments move with their code and stay.
- **Snippets are abbreviated.** Every real signature carries full type hints, with no `Any` and
  no `# type: ignore`.
- **A new framework module gets its `__all__` when it is created** (`forms`, `errors`,
  `housekeeping`, `lazy_panels`), and a name added to a module that already has one is added to it.
- **A slice that deletes or renames something greps for it before committing** and leaves no
  reference behind, tests and comments included.
- **Loading text** uses the ellipsis character "…", and `hx-disabled-elt` is
  `find button[type='submit']`.

### Cross-app edges this work adds

The spec's Decisions accept each of these, so they are not open questions:

- `reports` imports `panel_framework` (`ReportTooLargeError` subclasses `PanelBodyTooLargeError`).

  and JS use framework cotton components and the `visibilityPoller` global. These are template and
  static-file references from a host to the framework. No Python import is added, and none may be.

### Slice 13: row-scoped actions read their row through the framework

An action on one row of a panel names the request parameter that carries the row and the rows it
may reach, and the framework does the lookup and the 404.

**Builds on:** slice 12
**Touches:** freedom_ls/panel_framework/actions.py, freedom_ls/panel_framework/tests/test_actions.py, freedom_ls/educator_interface/actions.py, freedom_ls/educator_interface/tests/

  ```python
  #: The request parameter naming the row a row-scoped action acts on.
  row_param: str | None = None

  def get_row_queryset(self, ctx) -> QuerySet:
      """The rows this action may act on, already narrowed to what the request may reach."""
      raise NotImplementedError

  def get_row_object(self, ctx) -> Model:
      if self.row_param is None:
          raise ImproperlyConfigured(f"{type(self).__name__} sets no row_param.")
      params = ctx.request.POST if ctx.request.method == "POST" else ctx.request.GET
      # A value the pk field cannot parse is the same miss as an unknown one.
      try:
          return get_object_or_404(self.get_row_queryset(ctx), pk=params.get(self.row_param, ""))
      except (ValueError, ValidationError):
          raise Http404 from None
  ```

  never runs against an unscoped manager.
