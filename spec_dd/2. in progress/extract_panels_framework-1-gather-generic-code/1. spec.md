# Spec: gather the generic panel code into the framework

Spec 1 of 6 in the panel framework extraction. Source: `idea.md` in this directory. The effort's
order, decisions and assumptions are in the "Panel framework extraction" section of
`spec_dd/1. next/roadmap.md`.

## Purpose

Generic panel code lives in five apps today, and the framework's tests lean on the educator
interface to prove it works. A host that installed `freedom_ls/panel_framework` on its own would get
bulk-run rows stuck in `running` forever, no reason dialog, no skeleton-first panels, no bulk-action
registry, and a sidebar whose Alpine controllers are defined in `base` and `comms`. This spec moves
every one of those pieces into the framework and closes the framework's test gaps, so specs 2 and 3
start from one self-contained unit. Behaviour for educators and learners does not change.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| public API | coined | The names listed in a framework module's `__all__`. Hosts import only these; no existing term. |
| shell components | coined | The Alpine components every interface page needs (`sidePanel`, `refreshTimer`), kept in their own framework file so a page can load them without the panel components. |

## Scope

In:

- Move `ReasonMixin`, `ReasonForm` and `reason_field.html` from `educator_interface`.
- Move `LazyBodyPanel`, `LOADED_PARAM`, `render_region`, `lazy_panel.html` and `_lazy_region.html`
  from `educator_interface`, with a framework error type in place of `ReportTooLargeError`.
- Split `EducatorBulkAction` into a generic framework class plus the educator subclass, and move the
  bulk-action registry.
- Move `ShowInactiveFilter` and `AuditPeriodFilter`, renamed and generalised.
- Move the `modal-trigger` and `quick-view-trigger` cotton components from `base`.
- Move the generic run-record sweeps from `deployment/housekeeping.py`.
- Move `sidePanel`, `refreshTimer` and `visibilityPoller` into the framework, and have nav items
  name the events their count refreshes on.
- Declare the public API with `__all__` in every public module.
- The tests listed under Testing.

Out (each belongs to a later spec, per `idea.md`): expandable rows, compact density, `as_of`,
required-reason and reason-choice dialogs (spec 2); cutting the framework's Python imports of FLS
and standalone test settings (spec 3); the host page shell, theme tokens, `c-icon` names, the framework's own
base components and the template-resolution test (spec 4); the app label, repo move and install
(spec 5); dark-mode and mobile Playwright checks of the reference page; preview-then-confirm
lists, the import scaffold, a sticky action rail, date/text/range filters;
`RequiresActiveCohortMixin`, `RelationLinkColumn`, the educator quick views, `memberRoleChooser`
and `cohortChecklist`, which stay in `educator_interface`.

## Decisions

- **Shell components live in the framework, and FLS loads them on every page.** FLS is the
  framework's host, so `_base.html` loading a framework static file is the allowed direction. The
  framework's 55 KB `alpine-components.js` stays off learner pages.
- **`ReportTooLargeError` subclasses the framework's `PanelBodyTooLargeError`.** One edit in
  `reports`, which keeps catching its own type in `screen_cache.py` and `tasks.py`. Translating in
  three `get_loaded_context` methods instead would repeat the same `try` three times.
- **The sweeps report closed rows through a callback, not Sentry.** The framework gains no
  `sentry_sdk` import, and the operator wording that names `fls_run_housekeeping` stays in FLS.
- **`delete_stale_previews` stays in `deployment`.** It sweeps `LearnerImport` rows in `PREVIEWED`
  and nothing else; a `BulkActionRun` has no preview stage.
- **The three sweeps stay separately callable.** FLS's orchestrator runs one `try` per sweep and
  model so one table's failure leaves the others run, and keeps that.
- **`ReasonForm` takes its length from a framework constant.** Importing `REASON_LENGTH` from
  `audit_log` would add an FLS import the framework tests' import contract forbids.
- **Filters take the general constructor.** Each of the two classes has one FLS call site, and both
  are updated to the new form.
- **No aliases at old import paths.** FLS is the only importer.
- **No migrations.** No model moves; `makemigrations --check` stays clean.

## Requirements

Paths are under `freedom_ls/`. Every moved file is deleted from its old location in the same
change; a cotton component left in two apps is shadowed silently by `INSTALLED_APPS` order.

### Reason dialog

- `panel_framework/forms.py` (new): `REASON_LENGTH = 500` and `ReasonForm`, moved unchanged from
  `educator_interface/forms.py:274-282` except that it uses the framework constant.
- `ReasonMixin` moves from `educator_interface/actions.py:297-323` to `panel_framework/actions.py`,
  unchanged. Its template reference becomes `panel_framework/partials/reason_field.html`.
- `educator_interface/templates/educator_interface/partials/reason_field.html` moves to
  `panel_framework/templates/panel_framework/partials/reason_field.html`. The eight educator modal
  templates that include it point at the new path.
- `audit_log/writer.py` and `audit_log/README.md` keep saying the length is shared with `ReasonForm`,
  now naming its framework location.

### Lazy panels

- `panel_framework/lazy_panels.py` (new) holds `LOADED_PARAM`, `render_region`, `LazyBodyPanel` and
  `PanelBodyTooLargeError`.
- `PanelBodyTooLargeError(Exception)`: its `str()` is the message the region shows. `LazyBodyPanel`
  catches it in `get_context_data` and sets `too_large_message = str(error)`.
- `reports/report_data.py`: `ReportTooLargeError` subclasses `PanelBodyTooLargeError`. Its
  `__init__`, attributes and message are unchanged, so every educator screen shows the same text.
- `educator_interface/reporting.py` keeps `CohortNeedsAttentionPanel`, `CohortReportBodyPanel` and
  `DashboardPanel` and imports the moved names. It no longer imports `ReportTooLargeError` for
  `LazyBodyPanel`.
- `lazy_panel.html` and `_lazy_region.html` move to `panel_framework/templates/panel_framework/panels/`.
  `LazyBodyPanel.template_name` and the three educator region templates that extend `_lazy_region.html`
  point at the new paths.

### Bulk actions

- `panel_framework/bulk_actions.py` gains `PermittedBulkAction(RecordedBulkAction)`: the members of
  `EducatorBulkAction` (`actions.py:2461-2618`) marked generic in `research_codebase.md` section 1a.
  `permitted` takes `scope: Model | None` where it now takes `organisation: Organisation`.
  `classify_all` reaches the scope through a hook the subclass overrides, not a cast to
  `OrganisationScopedRequest`. The class names no FLS model.
- The registry moves to `bulk_actions.py`: `BULK_ACTIONS`, `register_bulk_action`,
  `bulk_actions_for_table`, typed on `PermittedBulkAction`, with registration order still the action
  bar's order.
- `EducatorBulkAction` stays in `educator_interface/actions.py`, subclasses `PermittedBulkAction`, and
  keeps `has_permission` (`can_on_any`), `objects_for_keys` (organisation filter),
  `on_finished`/`on_result_shown` (`comms.notify`), the organisation scope hook and the `Organisation`
  narrowing of `permitted`. `LearnerBulkAction`, `CohortBulkAction` and every registered action keep
  their wording, capabilities and scoping.

### Filters

- `panel_framework/filters.py` gains:
  - `ToggleFilter(key, label)`: today's `ShowInactiveFilter`, a filter whose `apply` returns the
    queryset unchanged because the table widens its own queryset when the toggle is set. Its
    docstring says how it differs from `BooleanFilter`, which narrows.
  - `PeriodFilter(key, label, field, presets)`: today's `AuditPeriodFilter` with the field name and
    the presets as arguments. `presets` maps a URL value to `(label, days)`. The window is calendar
    days ending today in the project time zone, as now. `apply` filters on `field`, not a hard-coded
    `created_at`.
- `educator_interface/filters.py` loses both classes. `CohortDataTable.get_filters` uses
  `ToggleFilter("inactive", "Show inactive")` and its `isinstance` check tests `ToggleFilter`. The
  audit log table uses `PeriodFilter("when", "When", "created_at", <today's five presets>)`, so its
  URL values, labels and windows are unchanged.

### Cotton components

- `base/templates/cotton/modal-trigger.html` and `quick-view-trigger.html` move to
  `panel_framework/templates/cotton/`. Call sites need no change, since cotton resolves by name.

### Run-record sweeps

- `panel_framework/housekeeping.py` (new) holds `UNPICKED_MESSAGE`, `ORPHANED_MESSAGE`,
  `mark_unpicked_runs_failed`, `mark_orphaned_runs_failed` and `delete_finished_records`, moved from
  `deployment/housekeeping.py:246-340`, plus `sweep_run_records`, which runs all three for one model
  and returns the three counts.
- Each sweep takes the model class (`type[Model]` whose rows satisfy `RunRecord`), its threshold as
  an argument, and a keyword `on_closed: Callable[[type[Model], str, int], None] | None` that is
  called with `(model, pk, site_id)` for each closed row. A closed `BulkActionRun` still calls
  `report_finished`. The framework imports no setting for these windows.
- `RunRecord` (`panel_framework/run_records.py`) gains `created_at` and `site_id`.
- `deployment/housekeeping.py` keeps `delete_stale_previews`, `BULK_RECORD_MODELS`, the settings
  lookups, the per-(sweep, model) `try`, its notes, and a Sentry reporter passed as `on_closed` that
  sends today's operator messages with today's scope extras.

### Shell components and nav events

- `panel_framework/static/panel_framework/js/shell-components.js` (new) holds `visibilityPoller`,
  `sidePanel` (moved from `base/static/base/js/alpine-components.js:439`, with its instance-local
  `dialog`/`grid` fields, `data-mobile-only` and popstate handling unchanged) and `refreshTimer`
  (from `comms/static/comms/js/alpine-components.js:167-180`).
- `base/templates/_base.html` loads `shell-components.js` with `defer` before the base and comms
  component scripts. `comms` drops its `visibilityPoller` and `refreshTimer` and uses the
  framework's for `notificationBell`, `messagesPanel` and its templates.
- `SectionConfigBase` (`panel_framework/views.py:122`) gains `get_menu_count_events() -> tuple[str, ...]`,
  default empty. `build_menu_items` puts the tuple on each item and `sidebar_nav.html` builds
  `hx-trigger` from `load, refresh` plus `<event> from:body` per name. `conversationChanged` no
  longer appears in the framework. No FLS section sets a count URL today, so no host section
  changes.

### Public API

- Every framework module a host imports from defines `__all__`: `actions`, `bulk_actions`,
  `bulk_runs`, `config`, `context`, `events`, `filters`, `forms`, `housekeeping`, `lazy_panels`,
  `models` (including `RunStatus`, `BulkActionRun`, `scope_lookup`), `panels`, `quick_view`,
  `run_records`, `tables`, `views`, `reference`. Seed lists are in `research_codebase.md` section 7.
- A name outside `__all__` is private. `views.py` helpers keep their leading underscore. A private
  name a test outside the framework imports is either listed or the import is replaced.

### New FLS dependencies, for spec 3

The moved code adds no new Python import of `freedom_ls` to the framework. It adds these
template-level dependencies on FLS components: `partials/form.html` (from `reason_field.html`) and
`c-button` (from `_lazy_region.html` and `modal-trigger.html`). Spec 3 and spec 4 read this list.

## Testing

Moved tests move with their code and keep their assertions; `educator_interface` keeps tests only
for what it still owns.

- **Reason dialog:** `educator_interface/tests/invariants/test_reason_mixin.py` and the
  `ReasonMixin` render tests move to the framework, driven by a stub action. A blank reason
  succeeds; an over-length reason is a 422. One FLS test asserts
  `panel_framework.forms.REASON_LENGTH == audit_log.models.REASON_LENGTH`.
- **Lazy panels, on a stub panel:** the first render is the skeleton with `aria-busy`; `?loaded=1`
  renders the body; JS-off renders the "load" link; a stub `PanelBodyTooLargeError` shows its message
  in the region. A `reports` test asserts `ReportTooLargeError` is a `PanelBodyTooLargeError` with
  the same message. `test_reporting.py:1314-1326` drops the two moved template paths.
- **Bulk actions:** a framework-only stub subclass of `PermittedBulkAction` proves permitted and
  skipped rows, skip reasons, sentence and consequences, and that `bulk_actions_for_table` returns
  one table's actions in registration order and an empty list for an unknown table. The
  `BULK_ACTIONS` tests at `test_actions.py:7782-7809` move. Organisation scoping and notification
  tests stay in `educator_interface`.
- **Filters:** `ToggleFilter` and `PeriodFilter` tests move from `educator_interface/tests/test_filters.py`.
  New framework tests cover, for all six filters, the widget's checked or selected state read from the
  URL, toggling a value on and off, other tables' parameters left alone, and an unknown period value
  ignored without an error. Period windows run under a frozen clock, and `PeriodFilter` filters on a
  field other than `created_at`.
- **Cotton components:** a direct render test for each of `panel-search-field` (including with a
  sort active), `panel-filter-toggle`, `panel-applied-filter`, `panel-attention-row`,
  `panel-stat-row`, `panel-definition-row`, `data-table`, `data-table-card`,
  `data-table-cells/{datetime,link,text}`, `modal-header`, `modal-trigger` (the two
  `TestModalTriggerSize` tests move from `base/tests/components/test_button_component.py:65-81`) and
  `quick-view-trigger`.
- **Alpine, in Playwright on stub panels:** `listRefresh` (re-requests with the address bar's query),
  `headerRefresh`, the instance-title update, and `sidePanel` opening and closing the sidebar at
  phone width with the filter sheet staying closed on desktop. `tableSelection` already has
  framework coverage; extend it only where a behaviour in `idea.md` is unpinned. The educator
  Playwright tests stay as the cross-check.
- **Alpine registry check:** every `x-data` name in a framework template is registered by
  `Alpine.data` in `alpine-components.js` or `shell-components.js`, and no name is registered twice
  across the framework and FLS component files. Names that `base` registers and framework templates
  use are an explicit allow-list for spec 4, and the failure message names the template and the
  missing component.
- **Nav events:** a stub section with a count URL and a made-up event name renders that name in
  `hx-trigger`. A section with no events renders `load, refresh` only.
- **Sweeps:** `TestMarkUnpickedRunsFailed`, `TestMarkOrphanedRunsFailed`, `TestDeleteFinishedRecords`
  and the `report_finished` test move to the framework against `BulkActionRun`, and cover the threshold
  boundary, `on_closed` called once per closed row, a second run closing nothing, and
  `sweep_run_records` returning the three counts. `deployment` keeps the `LearnerImport`
  parametrisation, `TestDeleteStalePreviews` and `TestRunHousekeepingSweepsBulkRecords`, and asserts
  the Sentry reporter sends today's message and extras.
- **Public API:** a test parses every Python file outside `freedom_ls/panel_framework/` and
  fails on any `from freedom_ls.panel_framework.<module> import <name>` whose name is not in that
  module's `__all__`. A second test imports each module and checks every `__all__` entry exists.
- `test_organisation/import_contracts.toml` gains the new framework test modules under the
  framework's contract; the moved `deployment` tests leave its contract.

## Open questions

Assumed defaults, each changeable without touching another requirement:

- Assumed: the names `PermittedBulkAction`, `ToggleFilter`, `PeriodFilter`, `PanelBodyTooLargeError`,
  `lazy_panels.py`, `housekeeping.py` and `shell-components.js`.
- Assumed: `ReportTooLargeError` subclasses the framework error rather than being translated in
  `educator_interface`.
- Assumed: the sweeps report closed rows through an `on_closed` callback, with the Sentry reporting
  kept in `deployment`.
- Assumed: duplicate bulk-action registration keeps overwriting silently, as today.

## Success criteria

- `grep -rn "ReasonMixin\|ReasonForm\|LazyBodyPanel\|render_region\|register_bulk_action\|bulk_actions_for_table\|ShowInactiveFilter\|AuditPeriodFilter" freedom_ls` finds definitions only under `panel_framework/` (`AuditPeriodFilter` and `ShowInactiveFilter` nowhere).
- `modal-trigger.html` and `quick-view-trigger.html` exist only under `panel_framework/templates/cotton/`.
- `grep -rn "conversationChanged" freedom_ls/panel_framework` finds nothing outside tests.
- `grep -rn "sentry_sdk\|freedom_ls.audit_log\|freedom_ls.comms\|freedom_ls.reports\|freedom_ls.deployment" freedom_ls/panel_framework --include=*.py` finds nothing outside tests.
- `Alpine.data("sidePanel"` and `Alpine.data("refreshTimer"` appear once each in the repo, in `shell-components.js`.
- Every framework module a host imports defines `__all__`, and the public API test passes.
- `uv run manage.py makemigrations --check` reports no changes.
- The full test suite passes, educator and learner Playwright tests included, with no educator test
  assertion about wording, capability or scoping changed.
