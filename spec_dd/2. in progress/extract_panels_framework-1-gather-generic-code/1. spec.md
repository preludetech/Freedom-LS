# Spec: gather the generic panel code into the framework

Spec 1 of 6 in the panel framework extraction. Source: `idea.md` in this directory. The effort's
order, decisions and assumptions are in the "Panel framework extraction" section of
`spec_dd/1. next/roadmap.md`.

## Purpose

Generic panel code lives in five apps, and a host that installed `freedom_ls/panel_framework` alone
would get `BulkActionRun` rows stuck in `running` forever and a sidebar with no Alpine controller.
This spec moves that code into the framework and closes its test gaps, so specs 2 and 3 start from
one self-contained unit. Educators and learners see no change.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| public names | coined | The names listed in a framework module's `__all__`. Hosts import only these. "API" already means the REST API in `freedom_ls/api`. |
| shell components | coined | The Alpine components every interface page needs (`sidePanel`, `refreshTimer`), kept in their own framework file so a page can load them without the panel components. |

## Scope

In: the moves and tests under Requirements and Testing.

Out: expandable rows, compact density, `as_of`, the required-reason and reason-choice dialogs
(spec 2); cutting the framework's Python imports of FLS (spec 3); the host shell contract for the
sidebar and the page shell (spec 4); the app label and repo move (spec 5). `RequiresActiveCohortMixin`,
`RelationLinkColumn`, the educator quick views, `memberRoleChooser` and `cohortChecklist` stay in
`educator_interface`. No polish of the educator interface.

## Decisions

- **FLS loads the shell components from the framework on every page.** FLS is the framework's
  host, so `_base.html` loading a framework static file is the allowed direction.
- **`ReportTooLargeError` subclasses `PanelBodyTooLargeError`**, so `reports` keeps catching its own
  type in `screen_cache.py` and `tasks.py`.
- **`delete_stale_previews` stays in `deployment`**, a departure from `idea.md`'s list: it sweeps
  only `LearnerImport` rows in `PREVIEWED`, and a `BulkActionRun` has no preview stage.
- **Educator wording stays in FLS.** Moved templates and forms take their visible text from
  attributes with neutral defaults, and `educator_interface` sets today's text.
- **No aliases at old import paths, and no copies left behind.** FLS is the only importer, and a
  cotton component in two apps is shadowed silently by `INSTALLED_APPS` order.

## Requirements

Paths are under `freedom_ls/`. No model moves, so no migration.

### Reason dialog

- `panel_framework/forms.py` (new): `REASON_LENGTH = 500` and `ReasonForm`, from
  `educator_interface/forms.py:274-282`. It uses the framework constant, not `audit_log`'s, whose
  contract forbids the import. Label and help text are class attributes defaulting to
  "Reason (optional)" and no help text.
- `ReasonMixin` moves from `educator_interface/actions.py:297-323` to `panel_framework/actions.py` and
  gains `reason_form_class = ReasonForm`. `educator_interface` defines a `ReasonForm` subclass with
  today's help text ("Only staff can see this. It is shown in the history.") and its eight reason
  actions use it.
- `reason_field.html` moves to `panel_framework/templates/panel_framework/partials/`. The eight
  educator modal templates include the new path.
- `audit_log/writer.py` and `audit_log/README.md` name `ReasonForm`'s new location.

### Lazy panels

- `panel_framework/errors.py` (new, imports nothing from the framework): `PanelBodyTooLargeError(Exception)`,
  whose `str()` is the message the region shows.
- `panel_framework/lazy_panels.py` (new): `LOADED_PARAM`, `render_region` and `LazyBodyPanel` from
  `educator_interface/reporting.py`. `LazyBodyPanel` catches `PanelBodyTooLargeError` and sets
  `too_large_message = str(error)`. It gains `load_label = "Load"`, the JS-off link text.
- `reports/report_data.py`: `ReportTooLargeError` subclasses `PanelBodyTooLargeError`, with
  `__init__`, attributes and message unchanged.
- `lazy_panel.html` and `_lazy_region.html` move to `panel_framework/templates/panel_framework/panels/`;
  `_lazy_region.html` renders `load_label`. `CohortNeedsAttentionPanel`, `CohortReportBodyPanel` and
  `DashboardPanel` stay in `educator_interface/reporting.py`, set `load_label = "Load the figures"`,
  and their region templates extend the new path.

### Bulk actions

- `panel_framework/bulk_actions.py` gains `PermittedBulkAction[ActorT: AbstractBaseUser](RecordedBulkAction)`,
  holding the members of `EducatorBulkAction` (`actions.py:2461-2618`) marked generic in
  `research_codebase.md` section 1a.
  - `perform` and `apply` take `actor: ActorT`, so the educator `perform` overrides type-check unchanged.
  - `permitted` takes `scope: Model | None`.
  - `classify_all` gets the scope from `scope_for_request(request) -> Model | None`, which
    subclasses override.
  - The class names no FLS model.
- The registry moves to `bulk_actions.py`: `BULK_ACTIONS`, `register_bulk_action` and
  `bulk_actions_for_table`, typed on `PermittedBulkAction`, with registration order still the action
  bar's order and duplicate registration still overwriting.
- `EducatorBulkAction(PermittedBulkAction[User])` stays in `educator_interface/actions.py`. It keeps
  `has_permission` (`can_on_any`), `objects_for_keys` (organisation filter),
  `on_finished`/`on_result_shown` (`comms.notify`), and `scope_for_request` returning the request's
  organisation. Every registered action keeps its wording, capabilities and scoping.

### Filters

`panel_framework/filters.py` gains two filters, and `educator_interface/filters.py` loses the
classes they replace:

- `ToggleFilter(key, label)` replaces `ShowInactiveFilter`. Its `apply` returns the queryset
  unchanged, and the table widens its own queryset when the toggle is set. Its docstring says how
  it differs from `BooleanFilter`, which narrows. `CohortDataTable.get_filters` uses
  `ToggleFilter("inactive", "Show inactive")`, and its `isinstance` check tests `ToggleFilter`.
- `PeriodFilter(key, label, field, presets)` replaces `AuditPeriodFilter`. `presets` maps a URL value
  to `(label, days)`. The window is calendar days ending today in the project time zone, and `apply`
  filters on `field`. The audit log table uses
  `PeriodFilter("when", "When", "created_at", <today's five presets>)`, so URL values, labels and
  windows are unchanged.

### Cotton components

`base/templates/cotton/modal-trigger.html` and `quick-view-trigger.html` move to
`panel_framework/templates/cotton/`.

### Run-record sweeps

- `panel_framework/housekeeping.py` (new) holds `UNPICKED_MESSAGE`, `ORPHANED_MESSAGE`,
  `mark_unpicked_runs_failed`, `mark_orphaned_runs_failed` and `delete_finished_records` from
  `deployment/housekeeping.py:246-340`, and `sweep_run_records(model, *, unpicked_max_age,
  orphaned_max_age, retention_days, report_closed=None)`, which runs all three for one model and
  returns the three counts.
- Each sweep takes a model class whose rows satisfy `RunRecord`, its threshold as an argument, and a
  keyword `report_closed: Callable[[type[Model], str, int], None] | None`, called with
  `(model, pk, site_id)` per closed row. For a closed `BulkActionRun` the framework sweep calls
  `report_finished` itself, before `report_closed`. The
  framework reads no setting and imports no `sentry_sdk`.
- `RunRecord` (`panel_framework/run_records.py`) gains `created_at` and `site_id`. The
  `BulkRecordModel` alias in `deployment` goes; `BULK_RECORD_MODELS` stays as FLS's list of
  `RunRecord` models.
- `deployment/housekeeping.py` keeps `delete_stale_previews`, the settings lookups and its
  per-(sweep, model) `try` and notes. It calls the three sweeps separately, each with a
  `report_closed` closure holding that sweep's operator message and threshold, so Sentry receives
  today's messages and scope extras.
- The `housekeeping.py` docstring separates these run-record sweeps from `deployment`'s
  `mark_orphaned_running_tasks_failed` and `mark_orphaned_running_reports_failed`.

### Shell components and menu count events

- `panel_framework/static/panel_framework/js/shell-components.js` (new) holds `visibilityPoller`,
  `sidePanel` (from `base/static/base/js/alpine-components.js:439`, its instance-local
  `dialog`/`grid` fields, `data-mobile-only` and popstate handling unchanged) and `refreshTimer`
  (from `comms/static/comms/js/alpine-components.js:167-180`). `visibilityPoller` stays a top-level
  function declaration in a classic script, since `comms` calls it as a global.
- `base/templates/_base.html` loads `shell-components.js` with `defer`. `base` drops `sidePanel`;
  `comms` drops `visibilityPoller` and `refreshTimer` and uses the framework's. `_base_interface.html`
  (every interface's sidebar, the learner course shell included) is the one `sidePanel` user outside
  the framework, and it reaches the controller through `_base.html`.
- `SectionConfigBase` (`panel_framework/views.py:122`) gains `get_menu_count_events() -> tuple[str, ...]`,
  default empty. `build_menu_items` puts the tuple on each menu item, and `sidebar_nav.html` builds
  `hx-trigger` from `load, refresh` plus `<event> from:body` per name. The framework names no
  `comms` event. No FLS section sets a count URL today.

### Public names

- These framework modules define `__all__`: `actions`, `bulk_actions`, `bulk_runs`, `config`,
  `context`, `errors`, `events`, `filters`, `forms`, `housekeeping`, `lazy_panels`, `models`
  (including `RunStatus`, `BulkActionRun`, `scope_lookup`), `panels`, `quick_view`, `run_records`,
  `tables`, `views`, `reference`. Seed lists are in `research_codebase.md` section 7.
- Other modules (`tasks`, `checks`, `field_display`, `templatetags`) are private, as is any name
  outside `__all__`. `educator_interface/tests/test_actions.py:99` stops importing
  `_run_bulk_action_task`.

### Template dependencies on FLS

The moved code adds no Python import of `freedom_ls` to the framework. Spec 4 takes over these
template dependencies: `partials/form.html` (from `reason_field.html`) and `c-button` (from
`_lazy_region.html` and `modal-trigger.html`).

## Testing

Moved tests keep their assertions. `educator_interface` keeps tests only for what it still owns.

- **Reason dialog:** `invariants/test_reason_mixin.py` and the `ReasonMixin` render tests move to
  the framework on a stub action. A blank reason succeeds, and an over-length reason is a 422. An
  `educator_interface` test asserts `panel_framework.forms.REASON_LENGTH == audit_log.models.REASON_LENGTH`
  and that the educator reason form shows today's help text.
- **Lazy panels, on a stub panel:** the first render is the skeleton with `aria-busy`, `?loaded=1`
  renders the body, JS-off renders a link with `load_label`, and a raised `PanelBodyTooLargeError`
  shows its message in the region. A `reports` test asserts `ReportTooLargeError` is a
  `PanelBodyTooLargeError` with the same message. `test_reporting.py:1314-1326` drops the two moved
  template paths.
- **Bulk actions:** a stub subclass of `PermittedBulkAction` proves permitted and skipped rows, skip
  reasons, sentence and consequences, `scope_for_request`, and that `bulk_actions_for_table` returns
  one table's actions in registration order and nothing for an unknown table. The wording tests at
  `test_actions.py:7782-7809` stay in `educator_interface` with the new import path, alongside the
  organisation-scoping and notification tests.
- **Filters:** the `ToggleFilter` and `PeriodFilter` tests move from
  `educator_interface/tests/test_filters.py`. New framework tests cover `ChoiceFilter`,
  `RelatedChoiceFilter`, `BooleanFilter`, `ToggleFilter` and `PeriodFilter` across the chips, select
  and grouped-checklist widgets. They check the state read from the URL, toggling a value on and off,
  other tables' parameters left alone, and an unknown period value ignored without an error. Period
  windows use `time-machine`, and one case filters on a field other than `created_at`.
- **Cotton components:** a direct render test for every framework cotton component without one:
  `panel-search-field` (with a sort active), `panel-filter-toggle`, `panel-applied-filter`,
  `panel-attention-row`, `panel-stat-row`, `panel-definition-row`, `data-table`, `data-table-card`,
  `data-table-cells/*`, `modal-header`, `modal-trigger` (the two `TestModalTriggerSize` tests move from
  `base/tests/components/test_button_component.py:65-81`) and `quick-view-trigger`.
- **Alpine, in Playwright on stub panels:** `tableSelection` keeps its existing framework flows,
  `listRefresh` re-requests with the address bar's query,
  `headerRefresh` refreshes the header, the instance title updates, and `sidePanel` opens and closes
  the sidebar at phone width with the filter sheet staying closed on desktop. The educator Playwright
  tests stay as the cross-check.
- **Alpine registration:** a framework test fails, naming the template and the component, when an
  `x-data` name in a framework template is not registered by `Alpine.data` in `alpine-components.js`
  or `shell-components.js`. Names `base` registers that framework templates use form an explicit
  allow-list for spec 4. A `base/tests` test fails when a name is registered in two FLS or framework
  component files.
- **Menu count events:** a stub section with a count URL and a made-up event name renders that name in
  `hx-trigger`, and a section with no events renders `load, refresh` only.
- **Sweeps:** the unpicked, orphaned, retention and `report_finished` tests in
  `deployment/tests/test_housekeeping.py` move to the framework against `BulkActionRun`. They cover the
  threshold boundary, `report_closed` called once per closed row, a second run closing nothing, and
  `sweep_run_records` returning three counts. `deployment` keeps the `LearnerImport` cases,
  `TestDeleteStalePreviews` and `TestRunHousekeepingSweepsBulkRecords`, and asserts Sentry gets
  today's messages and extras.
- **Public names:** a test parses every Python file outside `freedom_ls/panel_framework/` and fails on
  an import from a framework module whose name is not in that module's `__all__`, or from a private
  module. A second test checks every `__all__` entry exists.

  Run-record sweeps.)
