# Spec: gather the generic panel code into the framework

Spec 1 of 6 in the panel framework extraction. Source: `idea.md` in this directory. The effort's
order, decisions and assumptions are in the "Panel framework extraction" section of
`spec_dd/1. next/roadmap.md`. The evidence for Dialogs, Components and Action API is in
`research_consistency_audit.md`.

## Purpose

Generic panel code lives in five apps, and a host that installed `freedom_ls/panel_framework` alone
would get `BulkActionRun` rows stuck in `running` forever and a sidebar with no Alpine controller.
Where the framework lacked a shape, the educator interface built its own, page by page. It wrote
13 confirm dialogs by hand, with the form in two places and Cancel wired three ways. It left five
refusal dialogs with no Close button and drew six tables outside `data-table`, with five header styles.

This spec moves the generic code into the framework. It gives the framework one shape for each job
the educator interface had to hand-build, moves the educator interface onto those shapes, and closes
the test gaps. Specs 2 and 3 then start from one self-contained, consistent unit.

Educators see the same pages and wording. Dialogs, notices, tables and lists now share one look, and
the changes are listed under each requirement. Learners see no change.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| public names | coined | The names listed in a framework module's `__all__`. Hosts import only these. "API" already means the REST API in `freedom_ls/api`. |
| shell components | coined | The Alpine components every interface page needs (`sidePanel`, `refreshTimer`), kept in their own framework file so a page can load them without the panel components. |
| confirm dialog | coined | A dialog that states what is true now and what the action changes, then asks for one decision: Cancel or the confirm button. It may hold a reason field, but no other fields. `ConfirmAction` and `modal/confirm.html`. |
| message dialog | coined | A dialog that only tells: a title, a body and Close. Refusals, "already changed", denied and unavailable. `modal/message.html`. |
| notice | coined | A compact boxed sentence inside a panel or dialog, toned info, warning, error or success. `<c-panel-notice>`. Not `<c-callout>`, which stays the course-content component. |

## Scope

In: the moves, shapes and tests under Requirements and Testing, and moving every educator template
and action named there onto the new shapes.

Out, each with the spec that takes it:

- **Spec 2:** expandable rows, compact density, `as_of`, and the required-reason and reason-choice dialogs.
- **Spec 3:** cutting the framework's Python imports of FLS; making `has_permission`, `get_actions` and
  the context methods take one signature across `Panel`, `PanelAction` and `BulkAction`; a per-run
  state object for bulk actions in place of `permitted_ids` and its siblings on `self`; one binding
  style for tables, quick views and instance views; one `noun` hook.
- **Spec 4:** the host shell contract for the sidebar and the page shell. This includes replacing the
  `request.panel_*` attributes the educator interface sets. Spec 4 also makes cotton attribute names
  one convention (`variant`/`tone`/`level`, `size` values, `href` for a page and one name for a
  fragment URL).
- **Spec 5:** the app label and the repo move.

Also out:

- `run_status.html` and `import_stepper.html` stay in `educator_interface` until a second user exists.
- `RequiresActiveCohortMixin`, `RelationLinkColumn`, the educator quick views, `memberRoleChooser` and
  `cohortChecklist` stay in `educator_interface`.
- No educator copy changes beyond what is listed here.

## Decisions

- **FLS loads the shell components from the framework on every page.** FLS is the framework's
  host, so `_base.html` loading a framework static file is the allowed direction.
- **`ReportTooLargeError` subclasses `PanelBodyTooLargeError`**, so `reports` keeps catching its own
  type in `screen_cache.py` and `tasks.py`.
- **`delete_stale_previews` stays in `deployment`**, a departure from `idea.md`'s list: it sweeps
  only `LearnerImport` rows in `PREVIEWED`, and a `BulkActionRun` has no preview stage.
- **Educator wording stays in FLS.** Moved templates and forms take their visible text from
  attributes with neutral defaults, and `educator_interface` sets today's text.
- **No aliases at old import paths, and no copies left behind.** FLS is the only importer, and a
  cotton component in two apps is shadowed silently by `INSTALLED_APPS` order.
- **One shape per job, and FLS uses it.** Where the framework gains a shape for a job the educator
  interface did by hand, every hand-built copy named in `research_consistency_audit.md` moves onto
  it in this spec. Correcting the framework now costs less than after `v0.1.0`, when the package
  promises its API to a second host.
- **Cancel in a footer never asks to discard.** A footer's Cancel or Close calls `cancel()`, a
  deliberate choice to drop the input. The header close control and Esc call `requestClose()`, which
  goes through the dirty-form guard.
- **Tone follows the effect.** A confirm button that deletes a row (Delete, Remove) is `error`; one that
  flips `is_active` (Deactivate, Reactivate) is `primary`, as the bulk actions already are.

### Dialogs

`panel_framework/templates/cotton/` gains three components:

- `<c-modal-body>`: the dialog body's padding, gap and base text size. Every dialog's body is one,
  so no dialog template writes `px-6 py-4` or `text-sm` itself.
- `<c-panel-notice tone title>`: the notice, `tone` one of `info`, `warning`, `error`, `success`
  (default `info`). `error` carries `role="alert"`, `success` `role="status"`. No outer margin.
- `<c-panel-close-button href>`: the one close control (44px, `aria-label="Close"`,
  `<c-icon name="close">`). It is a link when `href` is set and calls `requestClose` otherwise.
  `<c-modal-header>`, `quick_view_host.html` and `table_sheet.html` render it, so the quick view's
  close grows from 36px to 44px.

`<c-modal-footer>` renders its own Cancel. It takes these attributes:

- `cancel` (label, default "Cancel"; "Close" in a message dialog)
- `cancel_href` (a link back to the page, for a dialog the server renders open with JavaScript off)
- `cancel_click` (default `cancel`; the discard prompt passes `keepEditing`)
- `focus_cancel` (autofocus on the Cancel)

The `cancel` slot goes, so no template writes a Cancel button. The default slot still holds the
actions, the primary last.

Four framework templates define the dialogs:

- **`modal/confirm.html`** (new): the confirm dialog, rendered from these blocks and keys:
  - blocks `title`, `body` and `hidden_fields`
  - context `action_url`, `confirm_label`, `confirm_variant`, `loading_text`, optional `refusal` (an
    error notice above the body), optional `reason_form`, optional `confirm_disabled_reason`, and
    optional `page_url`

  It renders, in order: `<c-modal-header>` (with `close_href` when `page_url` is set), one `<form>`
  posting to `action_url` that wraps body and footer, `<c-modal-body>`, the reason field, and
  `<c-modal-footer focus_cancel>` with one confirm button. A disabled confirm renders
  `confirm_disabled_reason` beside the footer and names it with `aria-describedby`.
- **`modal/message.html`** replaces `modal/read_only.html`: blocks `title` and `body`, and a footer
  whose Close takes focus. `action_denied.html` and `action_unavailable.html` extend it and keep
  their copy and status codes. `bulk_result.html` uses the footer's `cancel="Close"`.
- **`modal/form.html`**: its error summary moves to `partials/error_summary.html`, its status message
  becomes `<c-panel-notice tone="success">`, and `empty_message` renders through `message.html`.
- **`modal/delete_confirmation.html`** extends `confirm.html`. `DeleteAction` accepts POST as well as
  DELETE, renders its 422 with the error summary, and works with `ReasonMixin`.

`panel_framework/actions.py` gains:

- **`ConfirmAction(PanelAction)`.** Its trigger is the modal trigger, its `template_name` is
  `modal/confirm.html` and its trigger `variant` is `"secondary"`. Attributes: `confirm_label` (default
  `label`), `confirm_variant = "primary"` and `loading_text = "Saving…"`. Hooks:
  `get_title(ctx) -> str`, `get_hidden_fields(ctx) -> dict[str, str]` and
  `get_confirm_context(ctx) -> dict[str, object]`. A subclass that mixes in `ReasonMixin` gets the
  reason field.
- **`refusal_response(ctx, *, title, message, status=422) -> HttpResponse`.** It renders
  `message.html`, and `ConfirmAction.refuse(ctx, message, title=...)` calls it.

The bulk confirmation (`bulk_confirmation.html`, `_form.html`, `_message.html`) uses
`<c-modal-body>`, `<c-panel-notice>` for `error` and `notice`, and the footer's `cancel_href` in place
of its own `page_url` branch. `confirm_disabled` gains a reason, and the notice tone becomes
`warning`.

The discard prompt is one partial, `partials/discard_prompt.html`, ending in `<c-modal-footer>`. Both
`modal_host.html` and `quick_view_host.html` use it. Its title and body default to "Discard
changes?" and "The changes you made haven't been saved." When the dirty form carries

today's "Discard your message?" wording that way. `quickView`'s `keepDraft` and `discardDraft` become
`keepEditing` and `discard`.

Every dialog writes its loading text with the ellipsis character "…", and `hx-disabled-elt` is
`find button[type='submit']`.

In `educator_interface`:

- **The 13 confirm actions subclass `ConfirmAction`.** These are the actions that set

## Testing

Moved tests keep their assertions. `educator_interface` keeps tests only for what it still owns.
Educator tests that assert a dialog's markup (padding, `text-sm`, Cancel's click handler) change with
it; tests that assert wording, capability or scoping do not.

- **Reason dialog:** `invariants/test_reason_mixin.py` and the `ReasonMixin` render tests move to
  the framework, on a stub action. A blank reason succeeds, and an over-length reason is a 422. An
  `educator_interface` test asserts `panel_framework.forms.REASON_LENGTH == audit_log.models.REASON_LENGTH`
  and that the educator reason form shows today's help text.
- **Dialogs, on stub actions:**
  - A `ConfirmAction` GET renders the title, body, hidden fields and one confirm button with its
    label, variant and loading text, the form wrapping body and footer.
  - With `ReasonMixin` it renders the reason field inside the body.
  - With `refusal` it renders an error notice.
  - With `confirm_disabled_reason` the button is disabled and named by `aria-describedby`.
  - With `page_url` both the close control and Cancel link back to the page.
  - `refusal_response` returns 422 with a message dialog whose Close takes focus.
