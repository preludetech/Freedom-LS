Rules from those skills that bite here:

- Factories for all test data; one behaviour and one call per test, no loops or `if` in a test body
  (parametrize the worst-case cookie test). An idempotency test ("called twice writes one row")
  arranges the first write with a factory (`AttributionTouchFactory`, `ConversionFactory` with the same
  target) and makes the single act the repeat call. "A, B, A" seeds A and B and acts with the third
  landing.
- A `DatabaseError` test patches the manager method that writes the row (for example
  `Conversion._base_manager.get_or_create`) to raise `DatabaseError`: the database is the system
  boundary, and this is the one deliberate patch of ORM code in the plan. Each test says which
  method it patches.
- A test that needs another site's rows builds that site with `SiteFactory` and creates the rows
  inside a second `mock_site_context`/`site_context(...)` block; a test that needs no ambient site
  calls `drop_ambient_request()` from `freedom_ls/tests/site_context.py`. No test sets `site=` by hand.
- `test_config.py` cases assert that a setting is declared in `declared_settings`, never its default.
- `time_machine.travel(...)` for every window, expiry and `occurred_at` case. Settings under test go
  through `override_settings`, never by asserting a default.
- Exact `django_assert_num_queries` is used where the spec pins a cost contract (anonymous append:
  zero; signed-in live touch: the pinned count). N+1 guards elsewhere use
  `django_assert_max_num_queries`.
- `fls-dev:multi-tenant` says never set or filter `site` by hand. The exceptions here are deliberate
  and stay inside `referral_tracking/conversions.py` and `referral_tracking/resolution.py`, reads and
  writes alike, all through `_base_manager`: the flush writes and reads on `user.site` because
  `user_logged_in` can fire outside a site context; `record_conversion` writes on `user.site` and
  `touches_in_play` filters on an explicit `site` so a shell script or background job can call them
  with no request; `record_live_touch` writes and reads on the request's resolved `Site`. Each carries
  a comment saying why.
- Comments never name the spec, a slice or an idea slug. An index comment says "cursor for a
  changed-since conversions feed", not the idea's directory name.
- Mirroring: a new `referral_tracking/<module>.py` gets `referral_tracking/tests/test_<module>.py`.

### Slice 1: a signed-in tracked landing writes an `AttributionTouch`

**Behaviour:** a signed-in user who opens any tracked URL gets one `AttributionTouch` row
(`recorded_via=live`) and no cookie change. A `?gclid=`-only landing and an exact repeat of the latest
touch write nothing. A write failure is reported and the response still succeeds.

**Builds on:** none
**Touches:** freedom_ls/referral_tracking/models.py, freedom_ls/referral_tracking/migrations/, freedom_ls/referral_tracking/factories.py, freedom_ls/referral_tracking/counters.py, freedom_ls/referral_tracking/tests/test_counters.py, freedom_ls/referral_tracking/best_effort.py, freedom_ls/referral_tracking/hits.py, freedom_ls/referral_tracking/signals.py, freedom_ls/referral_tracking/conversions.py, freedom_ls/referral_tracking/middleware.py, freedom_ls/referral_tracking/tests/test_models.py, freedom_ls/referral_tracking/tests/test_best_effort.py, freedom_ls/referral_tracking/tests/test_conversions.py, freedom_ls/referral_tracking/tests/test_middleware.py

3. **Shared best-effort helper** in new `best_effort.py`:

   ```python
   @contextmanager
   def best_effort_write() -> Iterator[None]:
       """Run a write that must never fail the request it rides on.

       The savepoint keeps a failed INSERT from poisoning the caller's transaction;
       the failure is reported rather than retried, so a lost write stays lost.
       """
       try:
           with transaction.atomic():
               yield
       except DatabaseError as exc:
           sentry_sdk.capture_exception(exc)
   ```

   Refactor `hits.record_hit` and `signals.record_attribution_on_signup` onto it; their existing tests
   must pass unchanged, so the refactor is behaviour-preserving and lands here rather than as a later
   third copy. In `record_hit`, `is_hit_log_throttled` and its early `return` stay outside the `with`:
   the throttle touches the cache, not the database. Callers that use a value written inside the
   block set it to `None` before the `with`.
4. **`conversions.py`** (new) with `record_live_touch(*, request, user, site, occurred_at) ->
   AttributionTouch | None` per spec §5:

   ```python
   landing = first_touch_from_request(request)
   if not any(attribution_key_values(landing)):
       return None
   key_hash = attribution_key_hash_of(landing)
   touch = None
   with best_effort_write():
       latest = (AttributionTouch._base_manager.filter(site=site, user=user)
                 .order_by("-occurred_at", "-recorded_at")
                 .values_list("key_hash", flat=True).first())
       if latest == key_hash:
           return None
       touch = AttributionTouch._base_manager.create(
           site=site, user=user, recorded_via=TouchSource.LIVE, occurred_at=occurred_at,
           key_hash=key_hash, landing_path=landing["landing_path"],
           **{name: landing[name] for name in ATTRIBUTION_KEY_FIELDS})
   return touch
   ```
5. **Middleware.** Restructure `AttributionCaptureMiddleware.__call__` so the landing (and its time,
   `datetime.fromisoformat(landing["first_seen"])`) is read **before** `get_response`; also before it,
   if `request.user.is_authenticated` and the site resolves to a `Site`, call `record_live_touch`, and

   the site only on the paths that need it (mint and live), so the anonymous-with-cookie path stays at

### Slice 3: the cookie carries a bounded touch list

**Behaviour:** an anonymous visitor who already holds the cookie and lands on another tracked URL has
that landing appended to the cookie's touch list. Nothing reads the list into the database until the
next slice's flush, so this slice's end-to-end check is the `Set-Cookie` the browser receives. A repeat of the latest key, or a click-id-only
landing, leaves the cookie byte-identical. The first-touch keys and `read_attribution_cookie`'s return
do not change. Expiry never rolls past 90 days after the first touch.

**Builds on:** slices 1, 2
**Touches:** freedom_ls/referral_tracking/capture.py, freedom_ls/referral_tracking/config.py, freedom_ls/referral_tracking/middleware.py, freedom_ls/referral_tracking/tests/test_capture.py, freedom_ls/referral_tracking/tests/test_middleware.py, freedom_ls/referral_tracking/tests/test_config.py

1. **Setting.** `REFERRAL_TRACKING_MAX_COOKIE_TOUCHES: int`, `Setting(default=10)`.
2. **`capture.py`:**
   - `COOKIE_TOUCHES_KEY = "tl"`, kept out of `COOKIE_KEYS` (comment: `t` is taken, and downstream
     projects build fields from `COOKIE_KEYS`).
   - `CookieTouch`: a frozen dataclass with the seven key fields as `str`, `occurred_at: datetime` and
     `landing_path: str = ""` (set only for the frozen first touch, used by the flush in slice 4). Its
     key values and hash come from `attribution_key_values` / `attribution_key_hash_of`.
   - One timestamp parser, `_parse_cookie_time(text) -> datetime | None`, used for `ts` in both the
     first touch and every list entry: `None` when `fromisoformat` fails **or the result is naive**,
     so every later comparison with `timezone.now()` is between aware values and cannot raise
     `TypeError` inside a signal receiver.
   - Validation: `_is_first_touch_payload` keeps its rule for every key except `tl`, which must be a
     list of dicts whose keys are the seven short keys or `ts`, values all `str`, `ts` accepted by
     `_parse_cookie_time`. A decoded payload whose `first_seen` is more than
     `REFERRAL_TRACKING_COOKIE_MAX_AGE_DAYS` old is rejected too (exactly at the limit is accepted).
   - One decode per request: a private `_decode_cookie(request)` memoises the **raw** validated payload
     on a request attribute; each reader builds a fresh dict or list from it, so a caller that mutates
     what it gets (`record_signup_attribution` pops `first_seen`) cannot change what the next reader
     sees. Used by `read_attribution_cookie` (unchanged return: exactly the `COOKIE_KEYS` names) and
     new `read_cookie_touches(request) -> list[CookieTouch]` (empty for a cookie without `tl`).
   - `append_touch(touches, first_touch, request) -> list[CookieTouch] | None`: builds an entry from
     `first_touch_from_request`; returns `None` when all seven are blank or equal the last entry's (the
     frozen first touch's when the list is empty); otherwise a **new** list (never the one passed in),
     oldest evicted beyond `REFERRAL_TRACKING_MAX_COOKIE_TOUCHES`. `first_touch` is the cookie's
     frozen first touch, as `read_attribution_cookie` returns it, not the current landing.
   - `set_attribution_cookie(response, first_touch, *, touches=())`: build payload with `tl` (short
     keys, blanks omitted, `ts` ISO); shed `COOKIE_DROP_ORDER` first; then drop list entries oldest
     first, never the newest; still too big → `False`, set nothing. `max_age =
     max(0, _cookie_max_age() - seconds since first_seen)`. A cookie at exactly the limit is re-set
     with `max_age` 0, which the browser treats as expiry: the visitor's touches end there, as the
     non-rolling expiry intends.
3. **Middleware.** Anonymous tracked GET with a valid cookie: `append_touch`; when it returns a list,
   `set_attribution_cookie(response, first_touch, touches=...)` and `patch_cache_control(private=True,
   no_store=True)`. No tally, no query. When the set returns `False`, the browser keeps its old cookie.

**Tests:**

- `test_capture.py`: a cookie with a list still makes `read_attribution_cookie` return exactly the
  `COOKIE_KEYS` names; `read_cookie_touches` is empty for a pre-list cookie; each malformed `tl` shape
  (not a list, unknown key, non-str value, bad `ts`, naive `ts`) reads as absent; a mint response
  carries the full `_cookie_max_age()`; `append_touch` skips blank,
  click-id-only and repeat landings, appends A after B after A, evicts the oldest at the cap
  (`override_settings`); a re-signed cookie whose `first_seen` is over 90 days old reads as absent;
  one at exactly 90 days is re-set with `max_age` 0; `max_age` shrinks with the first touch's age;
  `test_a_multibyte_worst_case_cookie_fits_the_browser_limit` parametrized over entry counts (1, 5,
  cap) never exceeds the limit and keeps the newest entry; a worst-case entry that cannot fit beside
  the first touch returns `False`.
- `test_middleware.py`, changed per spec "Tests that change":
  `test_second_tracked_get_in_the_same_client_leaves_the_cookie_byte_identical` becomes two tests
  (different key appends one entry; same key byte-identical); `..._costs_no_query` still zero for an
  anonymous append; `test_a_visitor_holding_the_cookie_is_logged_as_a_hit_and_keeps_the_first_touch`

  `..._carries_vary_cookie` also asserts `private, no-store` on an append. New: a `?gclid=`-only landing

### Slice 4: signup and login flush the cookie, and signup converts

**Behaviour:** an account that signs up after three tracked landings has three `signup_flush` touches at
the landing times and an `account_signup` conversion; the signup response deletes the cookie. A login
flushes the same way with `login_flush`. Flushing twice writes each touch once.

**Builds on:** slices 1, 2, 3
**Touches:** freedom_ls/referral_tracking/capture.py, freedom_ls/referral_tracking/conversions.py, freedom_ls/referral_tracking/signals.py, freedom_ls/referral_tracking/middleware.py, freedom_ls/referral_tracking/tests/test_capture.py, freedom_ls/referral_tracking/tests/test_conversions.py, freedom_ls/referral_tracking/tests/test_signals.py, freedom_ls/referral_tracking/tests/test_middleware.py

1. **Clear flag** in `capture.py`: `request_cookie_clear(request)` / `is_cookie_clear_requested(request)`,
   shaped like `suppress_capture` / `is_capture_suppressed`.
2. **Middleware:** after `get_response` on **every** path (early return included), when the flag is
   set, `response.delete_cookie(config.REFERRAL_TRACKING_COOKIE_NAME, path="/", samesite="Lax")`.
3. **`flush_cookie_touches(*, request, user, source) -> list[AttributionTouch]`** in `conversions.py`:

   ```python
   if request is None:
       return []
   cookie_touches = flushable_cookie_touches(request)   # capture.py, below
   written: list[AttributionTouch] = []
   with best_effort_write():
       for cookie_touch in cookie_touches:
           # user.site, not the ambient site: user_logged_in can fire outside a request's site context
           touch, _ = AttributionTouch._base_manager.get_or_create(
               site=user.site, user=user, occurred_at=cookie_touch.occurred_at,
               key_hash=attribution_key_hash_of(cookie_touch.key_fields()),
               defaults={**cookie_touch.key_fields(), "landing_path": cookie_touch.landing_path,
                         "recorded_via": source})
           written.append(touch)
       flushed = written
   request_cookie_clear(request)
   return flushed   # set to [] before the `with`, so a failed flush returns nothing half-written
   ```

   `flushable_cookie_touches(request) -> list[CookieTouch]` in `capture.py`: the frozen first touch as
   a `CookieTouch` (with its `landing_path`, at `first_seen`) followed by the list entries whose
   `occurred_at` lies between `first_seen` and now, dropping any whose seven values are all blank.
   Empty when there is no valid cookie. The window check lives here, not in the flush.

   The clear flag is set whether or not the write succeeded: a lost write stays lost, and nothing
   retries it.
4. **Signals.** `record_attribution_on_signup` writes `SignupAttribution` as today (inside
   `best_effort_write`), then `flush_cookie_touches(source=SIGNUP_FLUSH)`, then
   `record_conversion(kind=ACCOUNT_SIGNUP, target=user, occurred_at=attribution.signed_up_at,
   target_label="Account signup")`. Set `attribution = None` before the `with`; when the attribution
   write failed, `occurred_at` is `timezone.now()`. Put the label in a module constant. New `@receiver(user_logged_in) flush_cookie_touches_on_login` calling
   `flush_cookie_touches(source=LOGIN_FLUSH)` only; `ready()` already imports `signals`.

**Tests:**

- `test_conversions.py`: three landings flush three rows at their times with `signup_flush`; the
  frozen first touch keeps its `landing_path`, list entries have none; an entry with `ts` in the future
  or before `first_seen` is skipped; with the cookie's touches already seeded by
