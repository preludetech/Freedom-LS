# Spec: panel framework form actions accept file uploads

Spec 1 of 3 in the "Account area on panels" effort (`spec_dd/1. next/roadmap.md`).

## Purpose

A `FormPanelAction` builds its form from `request.POST` only, and neither the dialog form nor the
inline form posts multipart. So a panel form cannot carry a file. The account area's picture panel
(`learner-profile-use-panels-framework-3-account-page`) and certificate uploads
(`learner-public-profile-4-certificates`) both need one. This spec adds file upload to the
framework once, for `FormPanelAction` and its subclasses, in the dialog shape and the inline shape.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| current file | coined | The file a file field already holds on the form's instance (its initial value). Never a `content_engine` `File` row. |
| choose-again message | coined | The field error the framework adds to a file field after a 422, telling the user to choose the file again (requirement 6). |
| request error message | coined | The `role="alert"` message a panel form shows when its request fails without a swappable response (requirements 9 and 10). Distinct from the dialog's error summary (`partials/error_summary.html`), which lists field errors. |

## Scope

In:

- Files reach the form of `FormPanelAction`, `EditAction` and `CreateInstanceAction`, from
  multipart dialog and inline forms, with a framework inline form partial and file widget.
- The choose-again message, and the request error message on every panel form.
- "Uploading…" while a chosen file is in flight, and a chosen file counts for the discard prompt.
- A static example on the component reference page, and framework tests.

Out:

- Any host panel, including the picture panel, and any change to `accounts/`.
- Storage, size limits and file-type checks. These stay in the host's form and model.
- Keeping a chosen file across a 422. A server stash needs temp storage, tokens and cleanup, and
  `hx-preserve` would also keep a file that was itself invalid.
- Progress bars, drag-and-drop, multiple files per field, previews, cropping, resizing.
- A link to the current file. A host that wants one adds it in its own panel.
- A request timeout. htmx has none configured, so a slow upload is never cut off, and a network
  failure still shows the request error message.
- Enter-to-submit from a text field and closing the dialog while an upload is in flight. These
  get no handling beyond today's `hx-disabled-elt`.
- File fields in a form that also uses `refresh_on_change`. The refresh is a GET and carries no
  file. Not supported, and not guarded.
- A live-region announcement of the busy state.

## Requirements

All new framework code, templates and tests stay generic, so they survive
`extract_panels_framework-3-standalone-backend` and `-4-template-contract` with the same
behaviour. They contain no FLS name. The only `freedom_ls.*` they import is `panel_framework` and
the shared test helpers in `freedom_ls/tests/` the framework's tests already use (such as
`playwright_helpers`). They import no FLS app or model.

### Files reach the form (`freedom_ls/panel_framework/actions.py`)

1. `FormPanelAction.get_form_kwargs` adds `"files": ctx.request.FILES` on POST and
   `"files": None` otherwise. `CreateInstanceAction.get_form_kwargs`, `EditAction.get_form_kwargs`
   and every override in `educator_interface/actions.py` inherit it through `super()`.
2. `FormPanelAction.get_unbound_form` sets `files` to `None` as well as `data`, so a "save and add
   another" form comes back empty. The `refresh_on_change` GET rebuild in `get_form` passes no
   files.
3. A private helper beside `_mark_refresh_fields`, called from both `get_form` and
   `get_unbound_form`, swaps the framework widget (requirement 8) into every field whose widget is
   exactly Django's `ClearableFileInput`. It copies the old widget's `attrs` (a copy, not the
   same dict, so `accept` survives) and sets `is_required` from `field.required`. `ModelForm` file
   fields get `ClearableFileInput` by default, so hosts get the framework widget without
   declaring it. A form that declares another widget is left alone.

### Multipart encoding and the in-flight label

4. `panel_framework/modal/form.html` and the inline partial (requirement 7) carry
   `hx-encoding="multipart/form-data"` and `enctype="multipart/form-data"` on the `<form>` when
   `form.is_multipart` is true. Multipart is decided by Django's own `is_multipart()`. The
   attributes sit inline in the tag, so a form without a file field renders the same `<form>`
   tag as today.
5. When a panel form is submitted with at least one file input holding a file, its submit buttons'
   loading text reads `Uploading…`. Otherwise it reads the button's own loading text: `Saving…`,
   or whatever a `submit_buttons` entry sets. The framework's JS sets the text on every
   `htmx:beforeRequest` from the form, to `Uploading…` or back to the original, so a failed
   request never leaves a stale label. It finds the text through a `data-loading-label`
   attribute added to the loading span in `cotton/button.html` (markup only, no new `c-button`
   attribute). Every loading text uses the single "…" character, so the inline partial's
   `Saving...` becomes `Saving…`.

### The choose-again message (`actions.py`)

6. In `FormPanelAction.handle_submit`, when the form is invalid, the framework adds this error
   before calling `form_invalid`:
   "Choose the file again. It is not kept when the form has errors."
   It goes on each file field that received an upload (`form.add_prefix(name)` is in
   `ctx.request.FILES`) and has no error of its own. It is added in `handle_submit` rather than
   `form_invalid` because `educator_interface/actions.py:1286` overrides `form_invalid`. Adding
   the error drops the field from `cleaned_data`, which no current override reads. A file field
   with its own error keeps that error only. The message counts towards `field_error_count`, so
   the dialog's error summary lists it. The wording is a module-level constant in `actions.py`.

### The inline form partial

7. The markup of `educator_interface/partials/inline_record_form.html` moves to
   `freedom_ls/panel_framework/templates/panel_framework/partials/inline_record_form.html`. It
   keeps its context contract (`form`, `action_url`, `form_id`), its comment and its markup, plus
   requirements 4, 5 and 9. The educator file stays as a one-line include of the framework
   partial, so `learner_name_form.html`, `cohort_name_form.html` and any host shadowing the old
   path keep working. The partial's `x-data="refocusAfterRequest"` is already registered in
   `panel_framework`'s JS.

### The file widget (`freedom_ls/panel_framework/widgets.py`, new)

8. `PanelClearableFileInput`, a `ClearableFileInput` subclass, public in the module's `__all__`, with `use_fieldset = False`
   and its own template at `panel_framework/widgets/clearable_file_input.html`. The template
   replaces Django's stock one rather than extending it.
   - `is_initial(value)` is true when the value has a non-empty `name`. Nothing in the widget
     reads `.url`: on private storage that signs a URL, and the stock template also prints the
     storage key.
   - With a current file, the template shows `Current file:` followed by the basename
     (`os.path.basename(value.name)`), autoescaped. Long names wrap with `break-all`, and the full
     basename is in a `title` attribute. No storage directory and no URL appear.
   - When the field is not required and there is a current file, it shows a checkbox labelled
     `Remove` (it clears the field's file, not a row). Its accessible name also includes the
     basename, as visually hidden text. The checkbox uses the context's `widget.checkbox_name`
     and `widget.checkbox_id`, so Django's `<name>-clear` handling works unchanged. A bound form
     re-renders the checkbox ticked when it was ticked on submit. A new upload with Remove ticked
     gets Django's own contradiction error.
   - Then the native file input, keeping the field's `id`, `aria-describedby` and
     `aria-invalid`. The label and error wiring stay on the file input, not on the checkbox. No
     custom button and no hidden input.
   - It uses only framework components and role tokens, and no `text-sm` (a dialog body is base
     size).

### Request error message (`freedom_ls/panel_framework/static/panel_framework/js/alpine-components.js` and both form templates)

9. The dialog form and the inline partial each hold an empty element marked
   `data-request-error`, with `tabindex="-1"`, inside the `<form>`. This is the only markup either
   template gains for a form without a file field. A document-level framework handler for
   `htmx:responseError` and `htmx:sendError` acts only when `requestConfig.elt` is a marked form
   itself, so a failed `refresh_on_change` GET or a quick-view request is left to its existing
   handling. It fills the element with a `role="alert"` message and, in a dialog, moves focus to
   it:
   - 413: "The file may be too large to upload. Choose a smaller file."
   - Anything else: "Your changes could not be saved. Try again."
   The response body is never swapped into the form. The dialog stays open, the entered values
   stay, and Save is usable again. The element clears on the next submit.
10. The handler skips a 403 or 404 (the framework already reloads the page for those). It also
    skips a response a host has already shown, which the host marks by setting
    `requestConfig.panelErrorShown = true` in its `htmx:beforeSwap`. `base/js/alpine-components.js`
    sets it where it swaps an OOB toast on a 4xx or 5xx.

### Discard prompt (`alpine-components.js`)

11. `dirtyTracker` serialises a `File` value as its name, size and last-modified time, not
    `[object File]`. `appModal` and the quick view run the dirty check on `change` as well as
    `input`. Picking a file then marks the dialog dirty, and Esc shows the discard prompt. A
    nameless, empty `File` (an input with nothing chosen) serialises as an empty string, because
    browsers stamp its `lastModified` with the current time.

### Component reference page (`panel_framework/reference.py`, `reference/_examples.html`)

12. A "File field" section with ids prefixed `file-field-`, built from plain `forms.Form` classes
    in `reference.py` with static `initial` and static data, so it runs no queries:
    - a dialog form with an optional file field and a current file (Current file, Remove, picker);
    - the same form bound with an error, showing the choose-again message;
    - an inline form with a required file field.
    The current file is a stand-in object with a `name` and no `url`. `file-field` is added to
    `COMPONENT_NAMES` in `tests/test_reference.py`.

## Testing

Framework suite (`freedom_ls/panel_framework/tests/`). `FormPanelAction` is tested with a plain
`forms.Form` holding a `FileField`. `EditAction` and `CreateInstanceAction` use a stub model with
a `FileField` and a per-test temp-dir storage from a helper under `panel_framework/tests/`.

- `get_form_kwargs` passes `request.FILES` on POST and nothing on GET. `get_unbound_form` is
  unbound for files and uses the framework widget.
- A multipart POST to a dialog `FormPanelAction`, an `EditAction` and a `CreateInstanceAction`
  reaches `form_valid` with the file. The `EditAction` saves it on the instance.
- The same for an inline-shape action rendering `panel_framework/partials/inline_record_form.html`.
- 422 with a file chosen and another field invalid: the input renders empty, the choose-again
  message is on the file field, the dialog's error summary lists it, and the current file is still
  shown. A prefixed form gets the message too.
- 422 where the file field has its own error: only that error shows. 422 with no file chosen: no
  choose-again message.
- Remove ticked on an optional field clears the instance's file. Remove ticked with another field
  invalid comes back ticked. Remove ticked with a new upload gives Django's contradiction error.
- The widget shows the basename only, never calls `.url` (a value whose `url` raises still
  renders), escapes a hostile name (`<script>"x.png`) and shows no Remove on a required field.
- The swap replaces a `ModelForm` field's `ClearableFileInput`, keeping its `attrs` and
  `is_required`. A declared plain `FileInput` is not replaced.
- `modal/form.html` and the inline partial: `hx-encoding` and `enctype` present with a file
  field. Without one, the render equals a golden render captured before the change, apart from
  the `data-request-error` element, the `data-loading-label` attribute on the button's loading
  span and the inline ellipsis.
- The existing learner name and cohort name panel tests pass through the delegating include.
- The invariants in `tests/invariants/test_templates.py` pass, and the inline partial is added to
  the loading-text ellipsis check.
- Reference page: the `file-field-` ids exist, no duplicate ids, still zero queries.
- Playwright, dialog and inline. These hold the upload route open with `page.route` until the
  button has been checked:
  - Save is disabled and reads "Uploading…" with a file chosen, and "Saving…" with none. After a
    failed upload, clearing the file and resubmitting reads "Saving…".
  - Picking a file then pressing Esc shows the discard prompt.
  - A routed 413 and a routed 500 each show their message, keep the dialog open with focus on the
    message, keep the typed values and re-enable Save.
  - A failed request on a form without a file field shows the generic message.

## Documentation and downstream

- `claude_plugins/fls-dev/skills/panel-framework/SKILL.md` gets a "Forms with a file field"
  section. It covers what the host owns: the storage alias (per `fls-dev:file-storage`), size and
  type validators in the form, and a reverse-proxy body limit at or above the largest allowed
  file. It points to requirement 10's `requestConfig.panelErrorShown` contract for a host's own error
  handling.
- Upgrade notes: the inline form's markup now lives at
  `panel_framework/partials/inline_record_form.html`. The educator path still works as an include,
  and a host that shadows it should move its override to the framework path.

## Success criteria

- A host `ModelForm` with a `FileField` on an `EditAction` uploads from a dialog and an inline form
  with no host code beyond the form.
- A failed panel form request shows a message in the form, and Save works again.
