# Spec: learner CSV upload design fix

## Purpose

The educator interface's learner CSV import (upload, preview, result) works but looks unfinished: a
bare "Choose File" input, a comma-joined header string, a bullet list of counts, and a plain-text
result. This spec brings the three pages into line with the registered design while keeping every
behaviour the import already has.

Resources:

- `idea.md`: the idea.
- `design.md`: the Claude Design design for the import (screens 05 to 08). It is a visual reference only; read it as that file says.
- `research_*.md`: the research beside this spec.

## Scope

In:

- Restyle `learner_import_upload.html`, `learner_import_preview.html`, `learner_import_result.html`,
  `partials/learner_import_result_body.html` and `partials/import_stepper.html` under
  `freedom_ls/educator_interface/templates/educator_interface/`.
- A drag-and-drop zone on the upload page, built on the native file input.
- A file format table on the upload page, built from the existing column constants.
- On the preview page: summary tiles that are the label filters, a separate block for error rows,
  and a rows table that leaves error rows out unless the error filter is chosen.
- Two copy fixes QA logged against the shipped import: no "0 new accounts will get a setup email."
  line, and no "0 rows were not added." clause.
- The view-context additions these need (listed under Requirements). No model, URL or migration
  changes.

Out:

- Everything the design draws that the product does not do: the sample file, the cohort codes list,
  by-cohort counts, the update-or-skip choice for existing learners, the invitation checkbox, a
  Cancel button, the extra columns (`cohort_code`, `location`, `licence_held`), and the design's
  limits (1,000 rows, 5 MB).
- The design's sidebar, top bar and breadcrumb: the educator shell and `standalone_page.html` already draw them.
- `partials/run_status.html`. Other background runs share it; it stays as it is.
- `learner_import_denied.html`.
- The design's theme, colours, fonts and icons. The pages use the project theme, existing cotton
  components and semantic icon names only. No theme token, icon name or font is added.

## Decisions

1. **Step labels stay "1. Upload", "2. Preview", "3. Result"**, and "Step N of 3" stays. Only the
   stepper's look changes.
2. **Drag-and-drop fills the native input.** The `<input type="file">` stays in the form and still
   works by click and keyboard (WCAG 2.2 SC 2.5.7 needs a non-drag path). The drop zone is its
   `<label>`; dropping a file sets `input.files`. Nothing uploads until "Upload and preview" is pressed.
3. **The preview's rows table leaves error rows out by default.** Error rows have their own block
   above it, so listing them twice adds nothing. Choosing the Error tile filters the table to error
   rows, as `?label=error` does today.
4. **The importing state is styled inside the import's own result card**, not by changing
   `run_status.html`. The queued and running copy ("Waiting to start.", "N of M rows processed.")
   is unchanged.
5. **Limits shown on the upload page come from the code**: `LEARNER_IMPORT_MAX_ROWS` and
   `MAX_UPLOAD_BYTES`. The design's numbers are never copied.

## Requirements

### Stepper: `partials/import_stepper.html`

- Keep the `nav[aria-label="Import steps"]`, the ordered list, `aria-current="step"` on the
  current step, and the "Step {{ step }} of 3" text.
- Each step renders as a numbered marker and its label in one row. A completed step's marker shows
  the `check` icon in place of the number. The current step is emphasised with weight and colour,
  never colour alone.
- Below `sm` the labels may hide visually (screen readers still read them) as long as "Step N of 3"
  plus the current label stays visible. The list has no bullet markers at any width.

### Upload page: `learner_import_upload.html`

Layout: from `lg`, two columns: the upload card on the left and a "File format" card on the right.
Below `lg` they stack, upload first.

**Upload card** (`c-panel-card`, title "Upload a CSV file"):

- A one-line lede stating the limits: up to `max_rows` learners and `max_file_size` per file, and
  that nothing is created until the preview is confirmed.
- File-level errors: keep the existing alert element's `role="alert"`, `tabindex="-1"`,
  `autofocus`, its heading "The file could not be uploaded." and the error list, styled with the
  error tone and the `error` icon (match the look of `c-callout level="error"`; wrap it or keep the
  div, but the attributes stay on the alerting element). It sits above the drop zone, which stays
  usable for the re-upload.
- The drop zone: a dashed-border `<label for="{{ form.file.id_for_label }}">` containing the
  visually hidden (not `display:none`) native input, a prompt "Drop your CSV here, or browse" with
  "browse" styled as a link, and a muted line giving `.csv` and the limits. The input gets
  `accept=".csv,text/csv"` as a hint (set on `LearnerImportForm.file`'s widget in `forms.py`) and
  `aria-describedby` pointing at the limits line. The label text the Playwright test finds with
  `get_by_label("File")` must still match.
- Drop zone states, each shown with text or border style as well as colour:
  - idle: the prompt above.
  - drag-over: the border turns solid and the prompt reads "Drop to choose this file".
  - file chosen: the file's name and size replace the prompt, with a "Choose a different file" hint.
  - focus: a visible focus ring on the zone while the hidden input has focus (`focus-within`).
- The submit button "Upload and preview" stays, full width below `sm`.
- A cohort import keeps its sentence that every learner goes into the named cohort and the
  `cohort` column is ignored.

**Drop-zone behaviour**: a new Alpine component, registered with `Alpine.data("fileDropZone", …)`
in `freedom_ls/base/static/base/js/alpine-components.js` following the `fls-dev:alpine-js` skill.
It handles `dragenter`/`dragover`/`dragleave`/`drop` on the label, assigns the dropped file to the
input through a `DataTransfer`, and listens to the input's `change` event so a picked file shows its
name the same way. It does not filter files by type; the server's existing validation decides. With
JavaScript off the zone is still a working label for the native input.

**File format card** (`c-panel-card`, title "File format", description "One learner per row. The
first row must contain these column headers."):

- The "Download template" `c-button` (`icon_left="download"`) in the card's `header_action` slot,
  still an `<a href="{{ template_url }}" download>`, so cohort imports keep their `?cohort=` link.
- A table with columns Column, Required, Format, one row per name in `HEADERS`, in `HEADERS`
  order. The column name renders in `<code>`. Required reads "Required" for `email` and "Optional"
  for the others, as text. Format is a short description plus an example in muted monospace, taken
  from `TEMPLATE_EXAMPLE_ROWS` where it has a value. The descriptions are new copy:
  - `email`: "Used to sign in, and to match learners who already have an account."
  - `first_name`: "Given name. Existing accounts keep their names."
  - `last_name`: "Family name."
  - `cohort`: "The cohort's name, matched exactly." On a cohort import this row reads "Ignored:
    everyone goes into {{ cohort.name }}."
- The table below `sm` must not push the page sideways: stack each row as a card, or scroll inside
  its own focusable region.

The descriptions belong with the constants: `learner_import.py` gains a `HEADER_DESCRIPTIONS`
mapping keyed by header name, and `learner_import` (view) passes a `format_rows` list (name,
required, description, example) built from `HEADERS`, `HEADER_DESCRIPTIONS` and
`TEMPLATE_EXAMPLE_ROWS`, plus `max_rows` and `max_file_size` (`filesizeformat` of
`MAX_UPLOAD_BYTES`). The comma-joined `headers` context value goes.

### Preview page: `learner_import_preview.html`

Top to bottom:

1. **File header card.** The file chip (`c-chip`, text unchanged: "{{ file_name }} · N rows") and
   "Upload a different file" as a secondary `c-button` linking to `upload_url`, using the `retry`
   icon.
2. **Summary tiles.** `c-panel-stat-row` with one `c-panel-stat-tile` per entry in `label_counts`:
   value is the count, label is the label name. Each tile is the filter link for its label: the link
   keeps `data-label-filter`, its `?label=` href and `aria-current="true"` on the active one, and
   its accessible name stays "{{ name }}: {{ count }}". The Error tile, when its count is above 0,
   uses the error tone and the `error` icon. When a filter is active, a "Clear filter" link returns
   to `preview_url`.
3. **Error block**, only when `error_count` is above 0. A bordered card in the error tone with the
   `warning` icon, heading "{{ error_count }} row(s) with errors will not be added.", the line "Fix
   them in your file and upload it again, or add the other rows now.", and two actions: the existing
   "Download the N error row(s)" button (`data-error-download`, text unchanged) and "Upload a
   corrected file" linking to `upload_url`. Below them, a table of up to `IMPORT_RESULT_ERROR_ROWS`
   error rows with columns Line, Email, Reason, and the same row-as-card layout below `md` that the
   rows table uses. When there are more error rows than shown, a line says "Showing the first 50 of
   N. Download the error rows to see them all." The view adds `error_rows` (built as the result
   page builds it: `error_rows(learner_import)` sliced, with `error_reason`) to the preview
   context.
4. **Rows card** (title "Rows", `flush`). The existing desktop table and `ul[data-row-cards]`
   mobile cards, column order unchanged (Line, Email, First name, Last name, Cohort, Label,
   Reason), with the Label cell as a `c-panel-status-badge`. The tone comes from a
   `PREVIEW_LABEL_TONES` mapping in `learner_import.py`: new account `success`; joined,
   reactivated and added to cohort `info`; already a member `muted`; error `error`. With no filter
   the view excludes `preview_label=error` rows from `shown`; with a filter it shows that label's rows
   as today. Pagination: replace the hand-rolled `nav` with `c-pagination` if it keeps the
   `rel="prev"`/`rel="next"` links and the `label` query parameter; otherwise restyle the existing
   nav. When the unfiltered table would be empty (every row is an error), the card is omitted.
5. **Confirm card**, last. The existing notes as a short muted list:
   - "{{ new_account_count }} new account(s) will get a setup email." only when the count is above 0.
   - "Existing accounts keep their names."
   - "Counts can change if someone else adds these learners before you confirm."
   - The background note when `add_count and in_background`.

   Then the POST form with the primary "Add N learners" button, right-aligned from `sm`, full
   width below. When `add_count` is 0, the card instead says "Nothing can be added: every row has
   an error or is already a member." and "Upload a different file" is its primary action. The
   page has no other `type="submit"` button.

### Result page: `learner_import_result.html` and `partials/learner_import_result_body.html`

- The result card is centred and narrower than the canvas from `md` (one column of content), with
  no card title; the stepper stays above it.
- **Queued and running**: the card's heading is "Importing learners", above the unchanged
  `run_status.html` output. The heading sits outside `#run-status`, so the poll cannot replace it:
  when `partial_learner_import_status` answers with a finished run (done or failed), it adds an
  `HX-Refresh: true` header, and the full page re-renders with the finished layout. The fragment
  body stays as it is today.
- A finished run, on any render, has no "Importing learners" heading; the done or failed body
  below supplies the heading.
- **Done**: the `success` icon, the headline "Added N learner(s)." followed by " M row(s) were not
  added." only when M is above 0, then a muted line with the file name and `finished_at` in the
  viewer's local time. The per-label counts and "N setup email(s) were sent." become a list of
  rows, each a label and a right-aligned count, with the `error` icon on the error row; the setup
  email row shows only when the count is above 0.
- **Failed**: the `error` icon and the existing "Stopped after X of Y rows" and `error_message`.
- The error rows table (`table[data-error-rows]`, columns unchanged) and the download button stay,
  styled as on the preview page's error block, with the same card layout below `md`.
- "Uploading the whole file again is safe: rows already added show as 'already a member'." stays, as
  muted text.
- Actions: "Import another file" as a secondary `c-button` and the back link ("Back to learners" or
  "Back to the cohort's learners", same href) as the primary `c-button` with `icon_right="next"`.
  Side by side from `sm`, stacked full width below.

### All pages

- No horizontal page scroll at any QA viewport (375, 768, 1920).
- Touch targets for buttons, tiles and the drop zone are at least 44px tall below `md`.
- Status is never colour alone: every error or success treatment has an icon or text with it.
- Styling uses Tailwind utilities on the markup and existing theme tokens (`fls-dev:frontend-styling`).

## Testing

Update the existing assertions in `freedom_ls/educator_interface/tests/test_views.py` and
`tests/playwright/test_learner_import_flow.py` that the restyle changes on purpose (the first-`code`
header string, "0 rows were not added.", the `tbody tr` count that included error rows, "Show all
rows"). Keep every other import assertion passing unchanged; they pin the behaviour this spec
keeps.

New view tests:

- The upload page's format table has one row per name in `HEADERS`, in order, with `email` marked
  Required and the others Optional, and shows the row and size limits from the config.
- On a cohort import the `cohort` row says it is ignored and names the cohort.
- The file input has `accept=".csv,text/csv"` and an `aria-describedby` that resolves to the limits line.
- A bad file still gives 422 and a focused `role="alert"`, and the drop zone label is still present.
- Preview with no filter: the rows table has no error rows; with `?label=error` it has only error rows.
- Preview with errors: the error block lists the error rows with line, email and reason, has the
  download link and an "Upload a corrected file" link to `upload_url`; with more than 50 error rows
  it shows 50 and the "Showing the first 50 of N" line.
- Preview with no errors: no error block.
- Preview with no new accounts: no "new accounts will get a setup email" line.
- Every summary tile link keeps `data-label-filter`, its href and its "{{ name }}: {{ count }}"
  accessible name; the active one has `aria-current="true"`.
- Each label renders as a status badge with the tone from `PREVIEW_LABEL_TONES`.
- Result with no rows lost: "Added N learners." with no "were not added" clause and no setup-email
  row when none were sent.
- Result while running: heading "Importing learners", `#run-status` unchanged (poll attributes,
  "Waiting to start.", the progress element).

Playwright (`tests/playwright/test_learner_import_flow.py`):

- Dropping a CSV onto the drop zone (dispatching `dragenter`, `dragover` and `drop` with a
  `DataTransfer`) fills the input, shows the file name, and "Upload and preview" reaches step 2.
- The drag-over state shows "Drop to choose this file".
- Choosing a file through the input by keyboard (focus the input, set files) shows its name the same way.
- The stepper and the summary tiles have `list-style-type: none`, and no page in the flow scrolls
  sideways at any of `QA_VIEWPORTS`.

## Documentation and downstream

- `docs/product/` pages that describe the learner import: update any wording or screenshot
  reference to the upload, preview or result page that this spec changes (the
  `fls-dev:update_product_docs` hook does this).
- Downstream projects that shadow any of the five templates by path lose the new look until they
  merge it; the upgrade notes say which templates changed and that `headers` left the upload
  page's context in favour of `format_rows`.

## Success criteria

- The upload page shows the drop zone and the file format table side by side from `lg`, stacked below.
- Dropping a `.csv` on the drop zone and pressing "Upload and preview" reaches the preview.
- A file-level error renders above a still-usable drop zone with a focused `role="alert"`, and the
  response is 422.
- The preview shows summary tiles that filter the rows, a separate error block when errors exist,
  and a rows table without error rows unless the Error filter is on.
- No "0 new accounts" line on the preview and no "0 rows were not added" clause on the result.
- The result page shows "Importing learners" with progress for a background import and the
  restyled summary with two actions when done.
- `run_status.html` and `learner_import_denied.html` are unchanged.
- No new theme token, font or icon name in the diff.
- No horizontal page scroll at 375, 768 or 1920 on any import page.
- `uv run pytest freedom_ls/educator_interface` passes.
