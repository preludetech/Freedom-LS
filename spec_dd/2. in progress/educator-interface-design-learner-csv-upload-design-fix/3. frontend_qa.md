# Frontend QA: learner CSV upload design fix

Checks the restyled import flow (upload, preview, result) in a browser. The plan is
`2. plan.md`; its Design section holds the transcriptions the checklists below are copied from.

## Setup

1. Build the stylesheet so the new utilities exist: `npm run tailwind_build`.
2. Start the server on a free port: `uv run python manage.py runserver $PORT`. Base URL:
   `http://127.0.0.1:$PORT`.
3. Log in at `http://127.0.0.1:$PORT/accounts/login/` with the QA login from
   `.claude/sdd/config.md` (`## QA Login`). That user is a site admin and an organisation admin
   of the dev organisation.
4. Open the educator interface and note the organisation slug in the URL
   (`/educator/organisations/<slug>/...`). Every URL below uses that `<slug>`.
5. The upload page is `http://127.0.0.1:$PORT/educator/organisations/<slug>/learners/import/`.
   The learners list links to it as "Import learners".

Files to prepare in a scratch directory:

- `good.csv`: header `email,first_name,last_name,cohort`, then three rows: two new emails
  (`qa-one@example.com,One,Person,` and `qa-two@example.com,Two,Person,`) and one row for a
  learner who is already a member of the organisation (take an email from the learners list).
- `mixed.csv`: `good.csv` plus two error rows: `not-an-email,,,` and a row whose email repeats
  `qa-one@example.com`.
- `all-errors.csv`: the header and two rows: `nonsense,,,` and `,Blank,Email,`.
- `bad-header.csv`: `name\nAda\n`.
- `big.csv`: the header and 60 rows, 55 of them `badN,,,` style errors (N = 1 to 55) and 5 new
  emails, so the Error filter paginates.
- `notes.txt`: any text file.

Viewports: 375, 768 and 1920 wide. "No sideways scroll" means
`document.documentElement.scrollWidth <= window.innerWidth` after layout settles.

## Test 1: upload page layout and format table

Design state: `educator-learner-import/05-upload`, screenshot
`design_screenshots/educator-learner-import__1280.png` (frame "05 Upload").

1. Go to the upload page at 1920.
2. Expect the stepper above the cards: "Step 1 of 3" and three steps in a row, step 1's marker
   filled and its label bold, steps 2 and 3 muted. No bullet markers.
3. Expect two columns: "Upload a CSV file" on the left and "File format" on the right.
4. In the upload card, expect a muted lede naming the limits: "Add up to 2,000 learners at
   once, 1.0 MB per file. Nothing is created until you review the preview and confirm."
5. Expect the dashed drop zone reading "Drop your CSV here, or browse" with "browse" styled as a
   link, and a muted monospace line under it: ".csv · up to 2,000 rows · 1.0 MB".
6. Expect the "Upload and preview" button under the zone.
7. In the "File format" card: the description "One learner per row. The first row must contain
   these column headers.", a "Download template" button with a download icon in the header, and
   a table with columns Column, Required, Format holding four rows in this order: `email`
   (Required), `first_name` (Optional), `last_name` (Optional), `cohort` (Optional). Each Format
   cell has a sentence and an example in muted monospace under it (`grace@example.com`,
   `Grace`, `Hopper`, `Cohort name`).
8. Click "Download template". Expect a download named `learner-import-template.csv`.
9. Resize to 768: the cards stack, upload first. The format table is still a table.
10. Resize to 375: the format table becomes a list of cards, one per column, each showing the
    name, Required/Optional, the sentence and the example. The "Upload and preview" button is
    full width and at least 44px tall. The stepper shows "Step 1 of 3: Upload" with the step
    labels visually hidden.
11. At every viewport: no sideways scroll.

Design checklist:
- [ ] Three steps in one row, marker then label; current step filled and bold; no bullets.
- [ ] Two columns from `lg`, upload left and format right; stacked below.
- [ ] Lede states the row and size limits.
- [ ] Dashed drop zone with the prompt and "browse" styled as a link.
- [ ] Limits line under the zone, muted.
- [ ] Format table: one row per header in `HEADERS` order; `email` Required, others Optional.
- [ ] Each row: name in `<code>`, description, example in muted monospace.
- [ ] "Download template" with the download icon in the card header.

## Test 2: drop zone states

1. On the upload page at 1920, press Tab until the hidden file input has focus. Expect a visible
   focus ring around the whole drop zone.
2. Click anywhere in the drop zone. Expect the native file picker to open (choose `good.csv`
   through it, or close it and set the file on the input directly).
3. With `good.csv` chosen: the prompt is replaced by `good.csv`, its size (e.g. "0.1 KB"), and
   the hint "Choose a different file".
4. Choose `mixed.csv` through the zone again. Expect the name to change to `mixed.csv`.
5. Drag-over state. In the page's console (or an evaluate call), build a `DataTransfer` holding
   a `File`, then dispatch `dragenter` and `dragover` on the `label[for="id_file"]` element with
   that `dataTransfer`. Expect the border to turn solid and the prompt to read "Drop to choose
   this file". Dispatch `dragleave` once: the state must stay (the counter handles nested
   enters); dispatch it again until the zone returns to the previous state. Dispatch `drop` with
   the transfer: the dropped file's name shows and the drag-over styling is gone.
6. Move the pointer over the prompt text and the limits line while dragging (a real drag from the
   OS file manager, if available): the zone must not flicker between states.
7. Nothing is uploaded until "Upload and preview" is pressed: the URL does not change during any
   of the above.
8. Reload the page with JavaScript disabled (DevTools: Disable JavaScript). The zone is still a
   label: clicking it opens the picker, and submitting a chosen file reaches the preview.
   Re-enable JavaScript afterwards.
9. At 375: the zone is at least 44px tall and the states above look the same.

## Test 3: upload with a file-level error

Design state: `educator-learner-import/05-upload-error`, screenshot
`design_screenshots/educator-learner-import__1280.png` (frame "05 Upload").

1. Choose `bad-header.csv` and press "Upload and preview".
2. Expect the page to re-render (status 422 in the network log) with an alert above the drop
   zone: an error icon, "The file could not be uploaded." and a list holding "Unknown column(s):
   name". The alert has an error-coloured left border and tint, and it has focus on load.
3. The drop zone is still usable under it: choose `mixed.csv` and upload. Expect step 2.
4. Repeat with `notes.txt`: expect an alert explaining the file is not a CSV (the exact text is
   the server's existing message), not a client-side rejection.
5. Repeat on the cohort upload page (Test 9) with `bad-header.csv`: the alert shows and the
   cohort name is still on the page.
6. At 375 and 768: the alert fits the card with no sideways scroll.

Design checklist:
- [ ] Alert above the drop zone with the error icon, heading and list.
- [ ] Alert is focused on load.
- [ ] Drop zone still works beneath it.

## Test 4: preview with errors

Design state: `educator-learner-import/06-review`, screenshot
`design_screenshots/educator-learner-import__1280.png` (frame "06 Review").

1. Upload `mixed.csv`. Expect "Step 2 of 3", step 1's marker now a check.
2. Block 1: a chip "mixed.csv · 5 rows" and a secondary "Upload a different file" button with a
   retry icon at the right. The button links back to the upload page.
3. Block 2: summary tiles, one per label present: "New account" 2, "Already a member" 1,
   "Error" 2. Each tile is a link (hover shows the pointer) whose accessible name is
   "<name>: <count>". The Error tile has an error-coloured border, red count and an error icon.
   No "Clear filter" link yet.
4. Block 3: an error-tinted block with a warning icon, heading "2 rows with errors will not be
   added.", the line "Fix them in your file and upload it again, or add the other rows now.",
   the buttons "Download the 2 error rows" and "Upload a corrected file", and a table with
   Line, Email, Reason listing both error rows (`not-an-email` with "This isn't a valid email
   address." and the duplicate with "Same email as line 2.").
5. Click "Download the 2 error rows": a CSV downloads whose header is
   `email,first_name,last_name,cohort,reason` and holds only the two error rows.
6. Block 4: the "Rows" card lists 3 rows (the two new accounts and the member), none of the error
   rows. The Label column shows status badges: "New account" in the success tone, "Already a
   member" in the muted tone.
7. Block 5, last: a muted list "2 new accounts will get a setup email.", "Existing accounts keep
   their names.", "Counts can change if someone else adds these learners before you confirm.",
   then the primary "Add 2 learners" button right-aligned. It is the only submit button on the
   page.
8. Click the "Error" tile. The URL gains `?label=error`, the tile shows as active (ring and
   `aria-current="true"`), the Rows card now lists only the 2 error rows with "Error" badges in
   the error tone and their reasons, and a "Clear filter" link appears under the tiles. The
   error block is still above.
9. Click "Clear filter": back to the unfiltered preview with no `label` in the URL.
10. Click the "New account" tile: only the 2 new-account rows show.
11. At 768: tiles in two columns, the rows table still a table. At 375: tiles in two columns,
    each at least 44px tall; the error rows and the rows become cards (`data-row-cards`), the
    "Add 2 learners" button is full width. No sideways scroll at any viewport.

Design checklist:
- [ ] File chip and the secondary "Upload a different file" on one row.
- [ ] Tiles: two columns, four from `lg`; Error tile outlined in error colour with an icon.
- [ ] Active tile marked (`aria-current` and a ring).
- [ ] Error block: tinted, warning icon, heading, line, two buttons, error table.
- [ ] Rows table has no error rows unless filtered to them.
- [ ] Label column rendered as status badges.
- [ ] Confirm card last, primary button right-aligned from `sm`, full width below.

## Test 5: preview pagination under a filter and the capped error list

1. Upload `big.csv`. The error block's table shows the first 50 error rows and the line "Showing
   the first 50 of 55. Download the error rows to see them all."
2. Click the "Error" tile. The Rows card shows 50 rows and "Page 1 of 2" with a "Next" button.
   Click "Next": the URL is `?label=error&page=2` and 5 rows show. "Previous" returns to page 1
   with the filter kept.
3. Clear the filter: the Rows card shows the 5 good rows with no pagination.

## Test 6: preview edge cases

1. Upload `all-errors.csv`. Expect the error block listing both rows, no "Rows" card at all, and
   the confirm card reading "Nothing can be added: every row has an error or is already a
   member." with a primary "Upload a different file" button. There is no submit button.
2. Upload `good.csv`. Expect no error block, three tiles, three rows, and "2 new accounts will
   get a setup email." in the confirm card.
3. Make a CSV with only existing members of the organisation (two emails from the learners list).
   Upload it. Expect a single "Already a member" tile, no error block, a "Rows" card listing both
   rows with muted "Already a member" badges (they are not error rows, so they stay in the table),
   and the confirm card saying "Nothing can be added" with the primary "Upload a different file".
4. Make a CSV with one email of a user who exists on the site but is not in this organisation
   (ask the data helper to create one). Upload it. Expect a "Joined the organisation" tile with
   an info-tone badge, "Add 1 learner", and no "new accounts will get a setup email." line.
5. Press the browser Back button from the preview to the upload page, then Forward. The preview
   still renders (it is a GET).
6. Open the preview URL in a private window logged in as a different staff user: expect a 404
   page, as before this change.

## Test 7: result done

Design state: `educator-learner-import/08-done`, screenshot
`design_screenshots/educator-learner-import__1280.png` (frame "08 Import complete").

1. From the `mixed.csv` preview, press "Add 2 learners". Expect "Step 3 of 3" with steps 1 and 2
   showing checks, and a centred card narrower than the canvas (at 1920 it is clearly narrower;
   at 768 it fills the canvas).
2. The card: a success icon, the headline "Added 2 learners. 3 rows were not added.", focused on
   load (the headline is the active element), then a muted line "mixed.csv · completed <local
   time>".
3. A list of rows, label left and count right: "New account" 2, "Already a member" 1, "Error" 2
   with an error icon, then "2 setup emails were sent." with its count.
4. The error block: Line, Email, Reason for the two error rows and "Download the 2 error rows".
5. The muted line "Uploading the whole file again is safe: rows already added show as 'already a
   member'."
6. Two buttons side by side at the right: "Import another file" (secondary) and "Back to
   learners" (primary, arrow icon). "Back to learners" opens the learners list and the two new
   learners are in it.
7. Upload `good.csv` again and confirm: the preview counts 3 "Already a member" and nothing to
   add. Upload a file with two fresh emails and confirm: the result headline is "Added 2
   learners." with no "0 rows were not added." clause, no error block, and the setup-email row
   present. Import a file whose only addable row is an existing site user joining the

Design checklist:
- [ ] Success icon above the headline.
- [ ] Headline without "0 rows were not added."
- [ ] File name and completion time in a muted line.
- [ ] Count rows: label left, count right; error row with icon.
- [ ] Two actions side by side from `sm`, stacked below; the back link is primary.

## Test 8: result while importing and after a failure

Design state: `educator-learner-import/07-importing`, screenshot
`design_screenshots/educator-learner-import__1280.png` (frame "07 Importing").

Reaching the importing state needs an import whose add count is above
`BULK_BACKGROUND_THRESHOLD` (default 250). Ask the data helper for a CSV of 300 fresh emails, or
run the server with `BULK_BACKGROUND_THRESHOLD=2` in the environment if the settings read it.
If the dev task backend runs tasks immediately, the state may only flash; note that and move on.

1. Confirm the large import. The preview's confirm card first shows "This import runs in the
   background. The result page will show progress."
2. On the result page: the narrow centred card headed "Importing learners", then "Waiting to
   start." or "N of M rows processed." and a progress bar. The element polls every 2 seconds
   (network log shows `/status/` requests).
3. When the run finishes, the whole page reloads by itself (the `HX-Refresh` header on the last
   poll) and shows the done state with its headline focused. No "Importing learners" heading
   remains.
4. Failure: ask the data helper to mark a confirmed import as failed with an error message (status
   `failed`, `error_message` "Something broke."). Open its result page: an error icon, the
   headline "Stopped after 0 of N rows", the message, the re-upload note and both action
   buttons.

Design checklist:
- [ ] Card centred and narrower than the canvas from `md`.
- [ ] "Importing learners" heading above the status text and progress bar.

   cohort's learners tab, where the new learners are listed.

## Test 10: accessibility pass

1. On each of the three pages, Tab through every control: the drop zone input, buttons, tile
   links, pagination, error-block buttons. Every focused element shows a visible focus ring, and
   the tab order follows the visual order.
2. With a screen reader or the accessibility tree: the stepper is `nav "Import steps"` with the
   current step marked; each tile link's name is "<label>: <count>"; the file input's name is
   "CSV file" and its description is the limits line; the result headline is announced on load.
3. Status is never colour alone: the Error tile and error rows have an icon or wording, the
   success result has an icon, the drag-over state changes the prompt text.
