# Frontend QA: Reports rendered with the organisation's brand

The rendered surface here is a **PDF**, not a web page. The browser work is the admin flow that
generates and downloads it; the assertions are made by opening the downloaded file. Both halves
matter — a report that generates fine but downloads under the wrong name still fails.

## Setup

### Server

```bash
PORT=$(.claude/ds/scripts/find_available_port.sh)
uv run python manage.py runserver $PORT
```

Base URL: `http://127.0.0.1:$PORT`

### Login

Admin: `demodev@email.com` / `demodev@email.com`
Log in at `http://127.0.0.1:$PORT/admin/`.

### Test data

Five organisations are needed. Build them, then build a report cohort in each.

```bash
# The two seeded organisations: one with a logo, one without.
uv run python manage.py qa_create_organisations --site-name DemoDev

# A report cohort per organisation. Repeat --organisation-slug per org.
uv run python manage.py qa_create_report_fixtures --only standard-cohort-medium-course \
    --organisation-slug <slug>
```

The organisations QA needs, and what each proves:

| Organisation | How to get it | Proves |
|---|---|---|
| **With a logo** (`RPAS Training`) | `qa_create_organisations` seeds it | logo on the cover, contained |
| **Without a logo** (`Northside`) | `qa_create_organisations` seeds it | wordmark fallback |
| **The site's default ("house") org** | already exists on every Site; omit `--organisation-slug` and the fixtures land in it | no "Powered by" mark anywhere |
| **A ~150-character name** | the extended `qa_create_organisations`, or create it in the admin | `condensed` wordmark, footer truncation |
| **A non-Latin name** (Cyrillic or Greek) | the extended `qa_create_organisations`, or create it in the admin | download filename preserves the script |

To create one by hand instead: `/admin/organisations/organisation/add/`, fill **Name**, upload a
**Logo** if the case needs one, save. Then build a cohort in it with the `--organisation-slug`
command above. Note the slug is read-only in the admin — it is derived from the name on save.

### Generating a report

1. Go to `/admin/freedom_ls/reports/generatedreport/`.
2. Click **Generate cohort report** (the object-list action).
3. Pick the cohort from the dropdown — cohorts are grouped by organisation name — and submit.
4. You land back on the changelist with *"Generating a progress report for &lt;cohort&gt;."*
5. The row's status goes `Pending` → `Running` → `Ready`. **Reload the changelist** to see it
   change; there is no auto-refresh. Generation takes a few seconds.
6. Click the row's **Download** link to get the PDF.

If the status sticks at `Pending`, the background task runner is not processing. Check the
runserver console for the task backend; a report that never leaves `Pending` is an environment
problem, not a bug in this feature.

## Test 1 — An organisation with a logo (the golden path)

Generate and download a report for the cohort in **RPAS Training**.

**On the cover (page 1):**
- The organisation's logo sits at the **top left**. Not top right — the block moved.
- The logo is **whole**: nothing clipped, no squashing or stretching. A wide banner logo should be
  bound by its width; a square crest by its height. Both are correct; a cropped one is not.
- The logo is no taller than about 16mm (roughly a fifth of the top margin area) and no wider than
  about 70mm (about 40% of the page width).
- The organisation's **name is not repeated as text beside the logo**. It appears only once more
  on the cover, in the metadata list.
- A short accent rule sits under the brand block, aligned to the **left** edge — not floating on
  the right where the old design put it.
- The **Organisation** row of the metadata list shows the full name.
- The solid coloured band at the bottom of the page reads **"Powered by DemoDev"** (or whatever
  `HEADER_TITLE` is set to), with "Powered by" visibly **smaller and lighter** than the site name
  next to it. If both read at the same size and weight, the two-tier treatment is broken.
- The site's name appears **nowhere else** on the cover — not top-left, not in the metadata list.

**On page 2 and every page after:**
- The bottom-left footer reads **`<Organisation> · <Cohort> · Cohort progress report`**, in that
  order. The site name must **not** be in this line any more.
- The bottom-**centre** reads **`Powered by <site>`**.
- The bottom-right still reads `Page N of M`.
- The three do not overlap or collide.

**Back on page 1 — the trap this feature is most likely to fall into:**
- **"Powered by" must appear exactly ONCE on the cover** — on the band only.
  If it *also* appears in the cover's bottom margin, above or below the band, `@page :first`
  is not clearing the new `@bottom-center` box. This is the single most likely defect; check it
  deliberately rather than glancing.

**Landscape pages** (the summary tables rotate to landscape):
- The full footer row — identity, "Powered by", page number — appears on landscape pages too.
  A landscape page is an interior page and carries the whole row.

**Document properties** (in your PDF reader: File → Properties, or `Cmd/Ctrl+D`):
- **Author** = the organisation name (`RPAS Training`).
- **Creator** = the site name.
- Author holds **one** name only. If it reads `"RPAS Training, DemoDev"` there are two author
  meta tags and one must go.
- Title is unchanged: `<cohort> — Cohort progress report`.

**Download filename:**
- The saved file is named `rpas-training-<cohort-slug>-progress-report.pdf`. The organisation
  comes first.

## Test 2 — An organisation with no logo (wordmark fallback)

Generate and download a report for the cohort in **Northside**.

- The top-left slot holds the **organisation's name set large, in the deployment's primary
  colour**. The cover must read as finished, not as though an image failed to load.
- **No monogram / initials badge anywhere on the report.** A two-letter circle in the brand slot is
  a defect, not a fallback — the on-screen organisation chip uses one, the report must not.
- No broken-image icon, no empty box, no alt text showing.
- Everything from Test 1's footer, band, metadata, document-properties and filename checks still
  holds — the fallback changes the brand slot only.

## Test 3 — The house organisation (attribution suppressed)

Generate a report for a cohort in the site's **default** organisation. (Run
`qa_create_report_fixtures` with **no** `--organisation-slug` — it falls back to the default org.
The default organisation is the one auto-created with the Site; it usually shares the site's name.)

- **"Powered by" appears NOWHERE in the document.** Not on the band, not in any page footer.
  Search the PDF for "Powered" — zero hits.
- **The coloured band at the bottom of the cover is still there**, still solid, just empty.
  A missing or collapsed band is a defect: the block is part of the page's composition.
- The bottom-centre footer box on interior pages is empty, and the bottom-left identity line and
  bottom-right page number are **unaffected** — they must not shift, re-centre or re-space because
  the middle box has nothing in it.
- The identity line still reads `<Organisation> · <Cohort> · Cohort progress report`.

## Test 4 — A very long organisation name

Create an organisation with a name of roughly **150 characters** (the field maximum) and no logo,
then generate a report for a cohort in it.

- The wordmark on the cover is set **smaller** than in Test 2 — the condensed size class.
- It **wraps within its slot**, at most three lines, and **stays inside the left ~70mm** of the
  page. It must not run to the full page width, spill under the accent rule, or push the cover
  body down the page.
- It does **not** overlap the accent rule, the "Cohort progress report" overline, or the cover
  title.
- If the name was too long even for three lines, it ends with a single **`…`** character — one
  ellipsis glyph, not three periods. Zoom in to check; `...` and `…` look alike at 100%.
- **In the footer**, the organisation name is **truncated** with the same single `…`, and the
  footer row stays **one or two lines**. It must not grow tall enough to reach the page content
  above it, and must not collide with the centre "Powered by" box.
- Check the footer on both a **portrait** and a **landscape** page — the landscape page is wider,
  and the truncation is a fixed character budget, so the two look different and both must be sane.
- Also try a **medium** name (~45 characters): it should get the condensed size, not the full one.
  A ~40-character name should still be at full size. The exact boundary is pinned in code; what QA
  is checking is that a name in the middle of the range does not overflow at either size.

## Test 5 — A non-Latin organisation name

Create an organisation named in **Cyrillic or Greek** (e.g. `Северный Колледж`) — scripts the
report's bundled fallback face covers — and generate a report for a cohort in it.

- The name renders as **real text** on the cover and in the footer, not as empty boxes (`□□□`).
  It may render in a visibly different, plainer face than the rest of the cover; that is the
  bundled fallback and is expected, not a bug.
- **The download filename preserves the script** — the saved file should carry the organisation's
  own characters, not be stripped to `-cohort-progress-report.pdf` with the organisation missing.
  Check the actual saved filename in your downloads folder.
- If you want to see the harder case: a **Chinese, Japanese, Korean, Devanagari or Thai** name is
  a known accepted limitation — it may render as missing-glyph boxes on the cover depending on the
  host's fonts, **but its download filename must still carry the name correctly.** Those two
  behaviours differing is intended; report it only if the *filename* loses the name.

## Test 6 — Things that could break sideways

Work through these deliberately; several are the failure branches this change opens.

**6.1 A logo that vanished from storage.**
Upload a logo to an organisation, generate one report (confirm the logo is on the cover), then
delete the file from disk under `media/organisations/` — leaving the database row pointing at it.
Generate a **second** report for the same cohort.
- The report **generates successfully** and its status reaches `Ready`. It must **not** go to
  `Failed`.
- Its cover falls back to the **wordmark**.
- No traceback in the runserver console.

**6.2 A file that is not really an image.**
Rename a text file to `logo.png` and get it onto an organisation. The admin form will reject it
(that is correct and worth confirming), so to exercise the render path use the shell:
```bash
uv run python manage.py shell
```
and attach the file to an organisation's `logo` field via `.save()` directly, bypassing
`full_clean()`. Then generate a report.
- The report **generates successfully** and falls back to the wordmark.
- It must not fail, and must not embed garbage that shows as a broken image on the cover.

**6.3 Admin upload validation still works.**
At `/admin/organisations/organisation/<id>/change/`, try uploading:
- an **SVG** renamed to `.png` → rejected with a validation message
- a file over **2 MB** → rejected
- a **48×24px** image (under the 64×32 minimum) → rejected
None of these should reach a report. This is existing behaviour; confirm this change did not
disturb it.

**6.4 A previously-generated report is not retroactively rebranded.**
Take an organisation that already has a `Ready` report. Change its **name**, or upload a
**different logo**. Re-download the **old** report.
- The old PDF is **unchanged** — old name, old logo. Generated PDFs are immutable snapshots.
- Generate a **new** report for the same cohort: the new one carries the new name and logo.
Both behaviours are correct; the point is that the first does not silently change.

**6.5 An organisation name with markup or quotes in it.**
Create an organisation named something like `Acme & Sons <b>Ltd</b> "Trading"` and generate a
report.
- The cover and the footer show the name **literally**, including the `<b>` as visible text.
- No bold text, no missing characters, no broken layout, and no styling anywhere else in the
  document going wrong. A quotation mark in the name breaking rules further down the page would
  mean a name reached the stylesheet instead of the markup.

**6.6 An organisation name of only punctuation.**
Create one named `---` (or `!!!`) and download its report.
- The filename comes out as something like `-<cohort>-progress-report.pdf` — ugly but valid.
- It downloads; it does not 500 or produce a file with no name.

**6.7 Download permissions are unchanged.**
Log in as `qa-report-restricted@email.com` (password == email; seeded by
`qa_create_report_fixtures`). This user may view **QA Report Standard Cohort** only.
- Downloading that cohort's report works, with the organisation-named filename.
- Downloading a **different** cohort's report is refused (403 / permission denied).
The filename change must not have widened who can download what.

**6.8 A report in a non-Ready state.**
While a report is still `Pending` or `Running`, hit its download URL directly
(`/admin/freedom_ls/reports/generatedreport/<pk>/download/`).
- You get a **404**, not a broken file and not a traceback.

**6.9 Repeat generation.**
Click **Generate cohort report** twice in a row for the same cohort without waiting.
- The second attempt says *"A report for this cohort is already being generated."*
- Exactly one new report row appears, not two.

**6.10 A cohort with no learners.**
Generate a report for the **QA Report Empty Cohort** fixture.
- The cover still carries the organisation's brand and the band correctly. An empty cohort must
  not lose its branding along with its content.

## What to report

For each failure, capture: which test, which organisation, what you expected, what you saw, and
**attach or screenshot the PDF page** — cover-page defects in particular are much easier to judge
from the page than from a description. Note the page number for footer issues, and say whether the
page was portrait or landscape.
