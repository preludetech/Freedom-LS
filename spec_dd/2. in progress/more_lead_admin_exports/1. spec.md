# Spec: admin CSV exports for users and course applications

Idea: `idea.md`. Research: the `research_*.md` files beside this spec.

## Purpose

Site staff need to take users and course applications out of the admin into a spreadsheet. An
application export carries the applicant's full application form, one column per question.
Applications from anonymous applicants are included. The admin already has a tested CSV export
base. Only the `referral_tracking` admins use it so far.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| answer column | coined | One column of an application export, holding the answers to one `FormQuestion`. No existing term: nothing in the code lays answers out as columns yet. |

## Scope

In:

- A CSV export on the `User` changelist (`freedom_ls/accounts/admin.py: UserAdmin`).
- A CSV export on the `CourseApplication` changelist (`freedom_ls/course_applications/admin.py:
  CourseApplicationAdmin`). It covers user-held and anonymous applications, drafts and submitted
  ones, with an answer column for every question of each form in the export.
- Formula-escaping of header cells in `FormulaSafeCSV`.

Out:

- An export on `AnonymousApplicantAdmin`. Every anonymous applicant already appears in the
  application export through `CourseApplication.anonymous_applicant`, and a claimed one would be
  counted twice.
- Registration-form answers (`SiteSignupPolicy.additional_registration_forms`), `LegalConsent`
  records, HR attributes and signup attribution in the Users export.
- File contents. A file-upload answer exports its filename only.
- XLSX or any format besides CSV, a column picker, a long (row-per-answer) format, background or
  emailed exports, and an export audit trail.
- A new "lead admin" role or export permission.

## Decisions

- **Reuse `SiteAwareExportModelAdmin`.** It gives both entry points. The "Export" changelist button
  honours the active filters and search, and the "Export selected" action takes the ticked rows. It also supplies
  the formula-safe CSV and the view-permission gate.
- **Export is gated on the model's view permission, not a new permission.** Anyone who can view an
  application can already read its answers on the change page. The export shows them nothing new,
  and file contents stay behind `can_download_answer_files`. A site's "lead admins" are whoever the
  operator grants `accounts.view_user` and `course_applications.view_courseapplication` to.
- **One row per application, with the union of answer columns across every form in the export.**
  The user chose this. A cell is blank when the question belongs to another course's form, or when
  the applicant did not answer it.
- **Answer columns are keyed by `FormQuestion.id`, not by question text.** A question reworded since
  an applicant answered it keeps one column, and two forms that ask the same text get two.
- **Questions follow the form's current layout, the way `form_engine.queries.answer_groups` lays
  them out.** Current pages in order and, within each page, `page_questions` order. Then any
  answered question that is on no page, so no answer is dropped.
- **Drafts are exported with an `is_submitted` column.** The user chose this. The existing
  submitted/draft filter narrows the export when wanted.
- **Users export account fields only.** The user chose this. It is an explicit `fields` whitelist,
  so `password`, `groups`, `user_permissions` and `is_superuser` never reach the file.
- **Synchronous, in-memory export through django-import-export.** Nothing asks for background
  export. Query count must not grow with row count.

## Requirements

### Shared export base (`freedom_ls/site_aware_models/admin_exports.py`)

- `FormulaSafeCSV.export_data` escapes the header row with `escape_csv_formula`, as it does every
  string cell. Question text becomes header text, so headers are no longer only model field names.
  Update the class docstring to match.

### Users export (`freedom_ls/accounts/`)

- New `freedom_ls/accounts/resources.py: UserResource(SiteAwareModelResource)`. Resolve the model
  with `get_user_model()`, per the CSV-export rules in
  `claude_plugins/fls-dev/resources/admin_interface.md`.
- Columns, in this order: `id`, `email`, `first_name`, `last_name`, `is_active`, `is_staff`,
  `email_verified`, `created_at`, `last_login`.
- `email_verified` is true when the user has an allauth `EmailAddress` row for their own `email`
  with `verified=True`. It comes from an annotation on the export queryset, not a per-row query.
- `UserAdmin` extends `SiteAwareExportModelAdmin` instead of `SiteAwareModelAdmin`, with
  `resource_classes = [UserResource]`. Its forms, fieldsets and inline are unchanged.

### Application export (`freedom_ls/form_engine/`, `freedom_ls/course_applications/`)

- The answer-column logic lives in `form_engine`, which must not import `course_applications`. A new
  module, `freedom_ls/form_engine/exports.py`, exposes:
  - a function that takes a collection of `FormProgress` and returns the ordered answer columns
    for them (`FormQuestion` plus header text), and
  - a function that renders one `QuestionAnswer` (or `None`) as cell text.

  Both share the page-and-question ordering with `answer_groups` rather than restating it.
- Column order across forms: forms ordered by `title`, then `id`. Within a form, the ordering in
  Decisions. Each form contributes every question currently on its pages, plus each off-page
  question that some exported sitting answered.
- Header text is the question's `question` field. When two answer columns in one export would
  share a header, append ` (<form title>)` to each of them. If any are still equal, append
  ` (<n>)` by column position.
- Cell text by question type:
  - `MULTIPLE_CHOICE`, `DROPDOWN`, `CHECKBOXES`: the selected options' `text`, in option `order`,
    joined with `"; "`.
  - `FILE_UPLOAD`: the answer file's `original_filename`. Never the storage path or a URL.
  - `DATE` and `TIME`: the stored ISO `text_answer` unchanged, not `format_answer`'s
    locale-formatted text.
  - Every other type: `text_answer` in full, newlines kept.
  - No answer row: an empty cell.
- New `freedom_ls/course_applications/resources.py: CourseApplicationResource(SiteAwareModelResource)`.
  Fixed columns first, in this order:
  - `id`
  - `applicant_email`
  - `applicant_name`
  - `is_email_verified`
  - `course` (the course `title`)
  - `is_submitted`
  - `submitted_time` (ISO, the same value as the `CourseApplicationAdmin.submitted_time` column)
  - `created_at`

  The answer columns follow, built from the `form_progress` sittings of the rows being exported.
  An application with no sitting has blank answer cells.
- `CourseApplicationAdmin` extends `SiteAwareExportModelAdmin`, with
  `resource_classes = [CourseApplicationResource]`. It stays read-only. Move `submitted_time` to a
  `CourseApplication` property, or a function both the admin and the resource call, so the two
  cannot drift apart.
- The export queryset keeps the changelist's `select_related` and prefetches
  `form_progress__form`, `form_progress__answers__question`,
  `form_progress__answers__selected_options` and `form_progress__answers__answer_file`. The forms'
  pages and questions load once per form, not once per application. Query count is constant in the
  number of applications exported.

### Site isolation

Both exports read only through the admin's own queryset, so `SiteAwareManager` scopes them to the
request's site. No code filters on `site_id` by hand. Prefetched forms, questions, options and answers
come from the same site.

## Testing

Follow `claude_plugins/fls-dev/skills/testing/SKILL.md`. The templates are
`freedom_ls/referral_tracking/tests/test_resources.py` and `tests/test_admin.py`.

- `FormulaSafeCSV`: a header cell starting with `=`, `+`, `-`, `@`, tab or carriage return comes
  out escaped.
- `UserResource`: exports exactly the nine columns in order. `password` appears in no form, neither
  header nor hash. `email_verified` is true only for a verified `EmailAddress` matching the user's
  `email`.
- Users admin: the export button downloads the filtered changelist. A staff user without
  `accounts.view_user` gets 403 on the export URL.
- Answer columns:
  - two forms are ordered by title, with blanks for the other form's questions;
  - a skipped question gives a blank cell;
  - a question moved off every page but answered still has its column, after the page questions;
  - a reworded question keeps one column under its current text;
  - duplicate headers get the form-title suffix, then the positional suffix.
- Cell rendering: multiple choice, dropdown and checkboxes (option text joined `"; "`, in option
  order); file upload (filename only); date and time (stored ISO text); long text with newlines;
  an answer starting with `=` comes out escaped.
- `CourseApplicationResource`:
  - a user-held application and an unclaimed anonymous one: the anonymous row takes its email and
    name from `AnonymousApplicant`, with `is_email_verified` false;
  - a draft row has `is_submitted` false;
  - an application with no sitting has blank answer cells;
  - the query count is the same for 2 and for 10 applications.
- Applications admin: the export honours the course filter and the submitted filter. A staff user
  without `course_applications.view_courseapplication` gets 403.
- Multi-site: users and applications, anonymous included, on a second site never appear in an
  export taken on the first.

## Documentation and downstream

- `docs/product/admin-interface.md`: the users and applications lists export to CSV, what each
  export contains (answer columns, drafts, anonymous rows, file names only), and that the
  view permission is what grants the export.
- `docs/product/security-and-data-handling.md`: the applicant and user exports are a new way
  personal data leaves the system. Note who can run them and that files are never included.
- Upgrade notes: `FormulaSafeCSV` now escapes headers, which affects a downstream subclass or a
  custom resource with a header starting with a trigger character. No settings or migrations.

## Success criteria

- On the users changelist, Export downloads a CSV of the filtered users with the nine whitelisted
  columns and no password data.
- On the applications changelist, Export downloads one row per filtered application, anonymous and
  draft ones included, followed by an answer column for every question of every form involved.
- Header and cell values starting with a formula trigger are escaped in both exports.
- Staff without the model's view permission cannot export either list.
- No export contains a row from another site.
- Exporting more applications does not add queries.
