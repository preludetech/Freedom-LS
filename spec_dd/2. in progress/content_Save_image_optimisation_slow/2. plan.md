# Implementation plan: cache optimised images in the content repository

Source of truth: `idea.md` in this directory, plus its four `research_*.md` files. Where this plan
and a research file disagree, the idea wins. That happens once, on keying:
`research_manifest_format.md` argues for the stored WebP name, and the idea, backed by
`research_cache_invalidation.md` §5, settles on the source filename.

## What changes

`content_save` stops re-encoding an image whose source bytes, encode constants and version number
have not moved since the last run. The optimised WebP and one `manifest.yaml` describing it live in
an `_optimised/` subdirectory beside the source images, committed to the content repository.

Nothing about `File`, `course_media` storage, the storage-key bookkeeping, or `optimise_image`'s own
behaviour changes. No models, no migrations, no templates, no views, no settings.

## What already exists and must be reused, not rebuilt

- `optimise_image` (`freedom_ls/content_engine/images.py:137`) stays a pure function that knows
  nothing about caching. The cache calls it on a miss. It is never taught to look anything up.
- `ImageEncodeDecision` (`images.py:29`) is the whole interface between the cache and
  `save_file_to_db`. A hit reconstructs one, and everything downstream already treats `decision` as
  an opaque value: the `File` upsert, the superseded-key dance, `file_obj.file.save(...)`, and both
  author-facing lines all keep working with no new branch.
- `_store_source` (`images.py:90`) is the only place the five encode fields get blanked as a group.
  The cache must not hand-roll a second copy of that discipline. It calls the same helper, which is
  why Task 1d makes it public.
- `_format_image_decision_line` and `_format_bytes` (`content_save.py:613`, `:596`) already render
  everything an author sees about an image from the decision alone. That is why an entry records the
  decision's fields rather than rendered strings.
- The three copies of the scanner skip rule, `get_all_files`/`should_skip`
  (`freedom_ls/content_engine/validate.py:22`), `is_skipped_path` (`content_save.py:566`) and the
  bundled `claude_plugins/fls-content/validate/validate.py:83`, already skip any path component
  starting with `_`. **None of them changes.** `_optimised/` is invisible to all three the day it
  appears. Do not add a fourth rule or a named exclusion for it.
- `freedom_ls/tests/images.py` already generates every image shape the tests need:
  `photographic_jpeg_bytes`, `png_bytes`, `animated_gif_bytes`, `screenshot_png_bytes`,
  `break_png_chunk_crc`, `already_minimal_png_bytes`. Write no new byte-generating helpers.
- `hashlib.sha256(...).hexdigest()` is the house digest, per
  `freedom_ls/referral_tracking/counters.py` and `freedom_ls/webhooks/signing.py`. Use it. Do not
  introduce a second hashing convention.

## Vocabulary

The idea's words, carried into the identifiers.

| Concept | Identifier |
| --- | --- |
| the cache directory beside the images | `CACHE_DIR_NAME = "_optimised"` |
| the manifest describing it | `MANIFEST_NAME = "manifest.yaml"` |
| one entry, keyed by the source filename | a mapping under the source filename in `manifest.yaml` |
| SHA-256 digest of the source bytes | entry field `digest` |
| the `images.py` constants that shaped the encode | entry field `encode_constants`, from `images.ENCODE_CONSTANTS` |
| the hand-bumped version number | `images.ENCODE_VERSION`, carried inside `encode_constants` |
| an entry whose source is gone | an orphan. The run deletes it, and deletes its file with it |
| a manifest that cannot be trusted | cold. Nothing in that directory is read from the cache |

The constant is `ENCODE_VERSION`, not `CACHE_VERSION`, because it describes what `images.py` does
and `images.py` is the module that must not know about the cache. It is also not the installed
Pillow or libwebp version, which deliberately invalidates nothing.

"Manifest" is also the word `accounts` uses for its legal-docs build artefact
(`build_legal_docs_manifest.py`). Different app, different format, no shared code, no import between
them.

## Task 1, images.py: the recorded constants and the version number

No change to `optimise_image`'s behaviour. Three additions and one rename.

**1a. `ENCODE_VERSION`**, placed with the other module constants, after `LOSSY_WINS_DIVISOR`. It
lives here rather than in the cache module because a developer changing the decision logic is
reading this file, and the comment has to be where that diff is.

```python
# Bump when a change to this module changes the bytes optimise_image returns
# for some input without changing any constant above. That covers branch
# order, the never-grow comparison, which formats get a second encode, and
# where the camera EXIF gate sits. It is also the one deliberate lever for
# re-encoding after a Pillow or libwebp upgrade. Nothing else invalidates a
# cached encode when the encoder changes, because a stale WebP is still a
# correct WebP, and a silent re-encode would rewrite every binary file in
# every content repository for a change no learner can see.
ENCODE_VERSION = 1
```

**1b. `ENCODE_CONSTANTS`**, immediately below the constants, so a newly added constant is one screen
away from the list it has to join.

```python
# The constants above, as an entry records them. An entry written under a
# different set of values reads as a miss, so nobody has to remember
# anything for a retuned knob to take effect. SVG_SUFFIXES is deliberately
# absent. Changing it changes which branch an image takes, not what that
# branch produces, which is ENCODE_VERSION's half of the problem.
ENCODE_CONSTANTS: dict[str, int | list[int]] = {
    "encode_version": ENCODE_VERSION,
    "max_dimension_px": MAX_DIMENSION_PX,
    "lossy_quality": LOSSY_QUALITY,
    "lossless_effort": LOSSLESS_EFFORT,
    "encode_method": ENCODE_METHOD,
    "second_encode_bytes": SECOND_ENCODE_BYTES,
    "lossy_wins_divisor": LOSSY_WINS_DIVISOR,
    "transposed_orientations": sorted(TRANSPOSED_ORIENTATIONS),
}
```

`sorted(...)` rather than the `frozenset`, so a round trip through YAML compares equal with one `==`
against the whole mapping. That single comparison is the point. A constant added to the mapping
invalidates every older entry automatically, with no per-key loop for anyone to forget to extend.

**1c. `WEBP_SUFFIX = ".webp"` and `WEBP_MIME_TYPE = "image/webp"`**, used by `optimise_image`'s final
return in place of the current literals, and by the cache when it reconstructs an `OPTIMISED`
decision. Two call sites each, one definition.

**1d. Rename `_store_source` to `store_source`** and update its five call sites inside the module
(`images.py:151`, `:172`, `:181`, `:256`, `:266`). Its docstring already explains why every
non-`OPTIMISED` outcome must go through it. The cache is now a second caller with exactly that need,
so the helper stops being private rather than being duplicated.

No test changes for this task on its own. `test_optimise_image.py` exercises `optimise_image`'s
behaviour, which does not move.

## Task 2, image_cache.py: the cache

New module at `freedom_ls/content_engine/image_cache.py`. No Django and no ORM imports, matching
`images.py`'s own constraint, so it is testable on a `tmp_path` tree with no database. It imports
`hashlib`, `pathlib`, `yaml`, and from `images.py`: `ENCODE_CONSTANTS`, `ImageEncodeDecision`,
`ImageEncodeStatus`, `SVG_SUFFIXES`, `WEBP_MIME_TYPE`, `WEBP_SUFFIX`, `optimise_image`,
`store_source`.

It must not import `content_save`, which imports it. That is why the collision check in 2h works off
the names the cache is asked about rather than off `get_file_type_from_extension`.

### 2a. Module constants and the digest

```python
CACHE_DIR_NAME = "_optimised"
MANIFEST_NAME = "manifest.yaml"


def source_digest(raw: bytes) -> str:
    """The source bytes' identity, as an entry records it.

    Never mtime. Every clone, checkout and branch switch rewrites mtimes
    without touching a byte, so an mtime-keyed entry would miss on a fresh
    checkout and in CI, the two cases with the most to gain.
    """
    return f"sha256:{hashlib.sha256(raw).hexdigest()}"
```

The `sha256:` prefix keeps the manifest self-describing, so a later change of algorithm reads as a
miss rather than as a digest that happens not to match.

### 2b. Entry shape

An entry carries the digest, the encode constants, and the fields
`_format_image_decision_line` and `save_file_to_db` print. It carries nothing its status does not
call for, so a stray `lossless` on a `kept source` entry can never be read as meaningful.

```yaml
backyard-drone-flight.jpg:
  digest: sha256:3b1c…e04a
  encode_constants:
    encode_method: 6
    encode_version: 1
    lossless_effort: 100
    lossy_quality: 80
    lossy_wins_divisor: 3
    max_dimension_px: 1600
    second_encode_bytes: 256000
    transposed_orientations: [5, 6, 7, 8]
  lossless: false
  source_format: JPEG
  source_size: [4032, 3024]
  status: optimised
  stored_size: [1600, 1200]
diagram.png:
  digest: sha256:9af2…11c0
  encode_constants: {…}
  source_format: PNG
  source_size: [800, 600]
  status: kept source
corrupt-scan.jpg:
  digest: sha256:71e0…abcd
  encode_constants: {…}
  error: 'UnidentifiedImageError: cannot identify image file'
  status: could not decode
```

What is deliberately absent:

- `suffix` and `mime_type`, which are constants of `optimised` and come from `WEBP_SUFFIX` and
  `WEBP_MIME_TYPE` on reconstruction.
- Any stored byte count. `_format_bytes`'s "before" already comes from the live source read, and its
  "after" is `len(decision.data)`, which the cached file itself supplies.
- **Any file-level field at all.** No count, no total, no timestamp, no version hoisted to a header.
  Every aggregate is a line two unrelated single-image edits would both touch.

### 2c. Building an entry from a decision

The one function where the per-status field discipline and the YAML-shaped types both live.

```python
def entry_for(decision: ImageEncodeDecision, digest: str) -> dict[str, object]:
    """One entry, carrying only the fields its status calls for."""
    entry: dict[str, object] = {
        "digest": digest,
        "encode_constants": ENCODE_CONSTANTS,
        # PyYAML's SafeDumper has no representer for a StrEnum and raises on
        # one, so the value is taken here and the word turned back into a
        # member on the way in.
        "status": decision.status.value,
    }
    if decision.source_format is not None:
        entry["source_format"] = decision.source_format
    if decision.source_size is not None:
        # A list, not the decision's tuple. SafeDumper writes either as a
        # plain sequence, and a plain sequence is what reads back, so the
        # conversion happens once here rather than leaving the written entry
        # and the read entry different Python types.
        entry["source_size"] = list(decision.source_size)
    if decision.status is ImageEncodeStatus.OPTIMISED:
        entry["lossless"] = decision.lossless
        entry["stored_size"] = list(decision.stored_size)
    if decision.status is ImageEncodeStatus.UNDECODABLE:
        entry["error"] = decision.error
    return entry
```

### 2d. Reading a manifest

```python
def read_manifest(manifest_path: Path) -> tuple[dict[str, object], str | None]:
    """Every entry in one manifest, plus the reason it could not be read.

    A manifest half-merged with conflict markers, truncated or hand-edited
    into nonsense cold-caches its own directory and nothing else. The cache
    is a speed optimisation over behaviour that is already correct without
    it, and a content_save that a typo in a cache file can wedge would be a
    worse failure than the slowness it was built to fix.
    """
    if not manifest_path.exists():
        return {}, None
    try:
        loaded = yaml.safe_load(manifest_path.read_text(encoding="utf-8"))
    except (yaml.YAMLError, UnicodeDecodeError) as err:
        return {}, str(err)
    if loaded is None:
        return {}, None
    if not isinstance(loaded, dict):
        return {}, f"expected a mapping of entries, found {type(loaded).__name__}"
    return loaded, None
```

Named exception types only, no bare `except Exception`. Conflict markers are not valid YAML, so they
arrive here as a `yaml.YAMLError`. A document that parses but is missing entries needs no special
case, because a missing entry is already a miss.

### 2e. Turning an entry into a decision

```python
def entry_to_decision(
    entry: object, digest: str, cache_dir: Path, stored_name: str
) -> ImageEncodeDecision | None:
    """The decision this entry recorded, or None if it cannot be trusted.

    None is always a miss: re-encode from the pristine source and overwrite.
    """
    if not isinstance(entry, dict):
        return None
    if entry.get("digest") != digest:
        return None
    if entry.get("encode_constants") != ENCODE_CONSTANTS:
        return None
    try:
        status = ImageEncodeStatus(entry["status"])
    except (KeyError, ValueError):
        return None

    source_format = entry.get("source_format")
    if status is ImageEncodeStatus.UNDECODABLE:
        # The only status whose source_format is legitimately absent: a PNG
        # with a too-short IHDR fails before there is a format to name.
        if source_format is not None and not isinstance(source_format, str):
            return None
        if not isinstance(entry.get("error"), str):
            return None
    elif not isinstance(source_format, str):
        return None

    source_size = _pair(entry.get("source_size"))
    if entry.get("source_size") is not None and source_size is None:
        return None

    if status is not ImageEncodeStatus.OPTIMISED:
        return store_source(
            status,
            source_format=source_format,
            source_size=source_size,
            # Only UNDECODABLE carries one. Forwarding a stray error key on a
            # passthrough entry would break the dataclass's own contract.
            error=entry["error"] if status is ImageEncodeStatus.UNDECODABLE else None,
        )

    stored_size = _pair(entry.get("stored_size"))
    lossless = entry.get("lossless")
    if stored_size is None or source_size is None or not isinstance(lossless, bool):
        return None

    stored_path = cache_dir / stored_name
    if not stored_path.exists():
        return None
    data = stored_path.read_bytes()
    if not _webp_is_complete(data):
        return None

    return ImageEncodeDecision(
        status=status,
        source_format=source_format,
        source_size=source_size,
        data=data,
        suffix=WEBP_SUFFIX,
        mime_type=WEBP_MIME_TYPE,
        lossless=lossless,
        stored_size=stored_size,
        error=None,
    )


def _pair(value: object) -> tuple[int, int] | None:
    """A recorded width and height, back as the dataclass declares them."""
    if (
        isinstance(value, list)
        and len(value) == 2
        and all(isinstance(item, int) and not isinstance(item, bool) for item in value)
    ):
        return (value[0], value[1])
    return None
```

Routing every non-`OPTIMISED` status through `store_source` is what keeps the five encode fields
blanked as a group in one place rather than two.

The truncation check reads the container header, not the image.

```python
# RIFF: b"RIFF", a little-endian byte count that excludes those four bytes
# and its own four, then b"WEBP".
RIFF_HEADER_BYTES = 12


def _webp_is_complete(data: bytes) -> bool:
    """Whether a cached WebP is all there, from its own header.

    An interrupted checkout or a bad merge leaves a file shorter than the
    length it declares. Decoding it to find that out would cost the encode a
    hit exists to avoid.
    """
    if len(data) < RIFF_HEADER_BYTES or data[:4] != b"RIFF" or data[8:12] != b"WEBP":
        return False
    return len(data) >= int.from_bytes(data[4:8], "little") + 8
```

### 2f. Writing only what changed

```python
def _write_if_changed(target: Path, data: bytes) -> bool:
    """Write data unless the file already holds exactly it, and say whether it wrote.

    The encode is deterministic, so a run over an unchanged tree has to leave
    the working tree alone: no new bytes, no new mtimes, nothing for git
    status to show. That is what keeps the noise proportional to real image
    changes rather than to how often the command is run.
    """
    if target.exists() and target.read_bytes() == data:
        return False
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_bytes(data)
    return True
```

### 2g. `ImageCache` state

One instance per run, constructed with the content repository root so notices can name paths the way
the per-file lines already do.

```python
class ImageCache:
    """The _optimised/ cache for one run: consulted per image, written per directory.

    Holds entries, never encoded bytes. An optimised file is written the
    moment it is produced, so a run over hundreds of images does not carry
    every encode in memory to produce a manifest.
    """

    def __init__(self, base_path: Path) -> None:
        self._base_path = base_path
        self._read: dict[Path, dict[str, object]] = {}      # cache dir -> entries found on disk
        self._entries: dict[Path, dict[str, object]] = {}   # cache dir -> entries this run produced
        self._claims: dict[Path, dict[str, str]] = {}       # cache dir -> stored name -> source name
        self._current: Path | None = None
        self.notices: list[str] = []
        self.written: set[Path] = set()
        self.removed: set[Path] = set()
```

`_claims` is a direct index for one question, "has another source in this directory already claimed
this stored name this run". The alternative is scanning `_entries` for a key whose stem matches,
which trades a dict for a loop and reads less like the rule it enforces.

### 2h. `decide`

```python
def decide(self, file_path: Path, raw: bytes) -> ImageEncodeDecision:
    if file_path.suffix.lower() in SVG_SUFFIXES:
        # Returns on the suffix before Pillow is ever called, so there is no
        # decode to skip and nothing to record.
        return optimise_image(raw, file_path.suffix)

    cache_dir = file_path.parent / CACHE_DIR_NAME
    if self._current is not None and self._current != cache_dir:
        # Written on the way out of a directory rather than at the end of the
        # run, so a run that fails on a later directory leaves every earlier
        # directory's cache usable and its retry fast.
        self._write_manifest(self._current)
    self._current = cache_dir

    stored_name = file_path.with_suffix(WEBP_SUFFIX).name
    self._check_claim(cache_dir, stored_name, file_path)
    entries = self._load(cache_dir)

    digest = source_digest(raw)
    decision = entry_to_decision(entries.get(file_path.name), digest, cache_dir, stored_name)
    if decision is None:
        decision = optimise_image(raw, file_path.suffix)
        if decision.status is ImageEncodeStatus.OPTIMISED:
            stored_path = cache_dir / stored_name
            if _write_if_changed(stored_path, decision.data):
                self.written.add(stored_path)

    self._entries.setdefault(cache_dir, {})[file_path.name] = entry_for(decision, digest)
    return decision
```

A hit re-records the entry it read. That is deliberate. The entry is rebuilt from the decision on
every run, so the written manifest is a pure function of the current tree and cannot drift toward
whatever shape an older run or a hand edit left behind.

`_load` reads a manifest once per directory, memoised in `self._read`, and turns a failure into a
notice naming the manifest and its error, so an author who committed a bad merge hears about it on
the next run instead of wondering why things got slow again.

```python
entries, error = read_manifest(cache_dir / MANIFEST_NAME)
if error is not None:
    self.notices.append(
        f"Could not read {self._relative(cache_dir / MANIFEST_NAME)}: {error}\n"
        f"  Ignoring it. Nothing in this directory is read from the cache."
    )
```

`_check_claim` is the one failure that is not self-healing.

```python
claimed = self._claims.setdefault(cache_dir, {})
owner = claimed.setdefault(stored_name, file_path.name)
if owner != file_path.name:
    raise ValueError(
        f"{self._relative(file_path.parent)} holds both {owner} and "
        f"{file_path.name}, which both optimise to {stored_name}. Rename one: "
        f"an optimised file and its entry cannot belong to two source images."
    )
```

Two sources differing only by extension both target one WebP name, and quietly picking a winner
would serve one image's bytes against the other's content on every run afterwards. This fails the
run, which is how `save_content_to_db` already treats a collection child it cannot resolve
(`content_save.py:1004`). Deriving the collision from the names the cache is asked about needs no
directory listing and no file-type table, and fires for exactly the files that would collide.

The comparison is case-sensitive on purpose. `Photo.JPG` beside `photo.png` collides only on a
case-insensitive filesystem, where the git checkout collides before the cache does, and folding the
key here would fail runs on the Linux repositories where those two files genuinely are distinct.

### 2i. `write_manifests`

```python
def write_manifests(self) -> None:
    """Write every manifest this run touched, and every one it inherited.

    Seeding from the manifests already on disk is what lets a directory
    whose last image is gone lose its manifest. Nothing in such a directory
    is scanned, because the scanner skips _optimised/ and there is no source
    image left, so nothing else would ever bring it up.
    """
    for manifest_path in self._base_path.rglob(f"{CACHE_DIR_NAME}/{MANIFEST_NAME}"):
        self._entries.setdefault(manifest_path.parent, {})
    for cache_dir in sorted(self._entries):
        self._write_manifest(cache_dir)


def _write_manifest(self, cache_dir: Path) -> None:
    source_dir = cache_dir.parent
    carried = dict(self._entries.get(cache_dir, {}))
    # Read even for a directory nothing was scanned from, so a run against one
    # file cannot delete the rest of that directory's cache. An entry survives
    # on its source still existing, not on this run having seen it.
    for name, entry in self._load(cache_dir).items():
        if name not in carried and (source_dir / name).exists():
            carried[name] = entry

    manifest_path = cache_dir / MANIFEST_NAME
    if carried:
        body = yaml.safe_dump(
            carried, sort_keys=True, default_flow_style=None, allow_unicode=True
        ).encode("utf-8")
        if _write_if_changed(manifest_path, body):
            self.written.add(manifest_path)
    elif manifest_path.exists():
        # The last image in this directory is gone, so the manifest goes too.
        manifest_path.unlink()
        self.removed.add(manifest_path)

    keep = {
        Path(name).with_suffix(WEBP_SUFFIX).name
        for name, entry in carried.items()
        if isinstance(entry, dict)
        and entry.get("status") == ImageEncodeStatus.OPTIMISED.value
    }
    for stale in sorted(cache_dir.glob(f"*{WEBP_SUFFIX}")):
        if stale.name not in keep:
            # An orphan's file is deleted when its entry is, and so is a file
            # a run that failed before its manifest was written left behind.
            stale.unlink()
            self.removed.add(stale)
    if cache_dir.exists() and not any(cache_dir.iterdir()):
        cache_dir.rmdir()
```

`_write_manifest` is idempotent, which is what makes the per-directory flush safe. `get_all_files`
sorts its result, so one directory's files are almost always contiguous, but a nested directory can
sort between two of them. A directory revisited after its flush is simply written again from the
fuller entry set, and `_write_if_changed` keeps the superseded write off the disk.

Only `*.webp` is ever deleted, so anything else a human left in `_optimised/` is left alone. A
directory whose images are all SVG never gets an `_optimised/` directory in the first place, because
`decide` returns before touching one and no manifest is written for a directory with no entries.

`safe_dump` with `sort_keys=True` and no custom representer: entries sorted by source filename, one
self-contained block each, ordinary `SafeDumper` quoting for anything that would otherwise read as a
number or a boolean, no anchors, and no `PreservingDumper`, whose literal-block styling for long
strings is exactly the kind of "preserve what a human typed" behaviour that would let two identical
runs disagree on their bytes. `default_flow_style=None` keeps `[1600, 1200]` and
`transposed_orientations` on one line each while every entry stays a block. Both settings are
deterministic, and the inline pairs keep an entry readable at around a dozen lines.

```python
    click.echo(
        f"Wrote {len(cache.written)} and removed {len(cache.removed)} file(s) under "
        f"{CACHE_DIR_NAME}/. Commit them alongside the content change, or every "
        f"other clone pays the full encode again."
    )
```

Counting both sets is what makes the sentence true. A deleted orphan is as much a working-tree change
the author has to commit as a new encode is, and `cache.written` already covers the `.webp` files
`decide` wrote inline as well as the manifests.

A cache write destroys nothing and its validity was never contingent on a database row, so
`transaction.on_commit`, which exists for the destructive asymmetric case the superseded-key delete
has, buys nothing here. Every entry is computed from its own pristine source and is valid on its own.

The closing summary (`content_save.py:1012`) is left alone. A hit reproduces the decision the encode
recorded, including its status, so the counts keep meaning exactly what they mean today.

### 5a. freedom_ls/content_engine/tests/test_image_cache.py, new, no database

Pure `tmp_path` work. No `@pytest.mark.django_db`, no `mock_site_context`, no factories, no markers.
Source bytes come from `freedom_ls/tests/images.py`.

A hit is asserted on output, never on call counts. The shape that does it: plant an entry that
validates, by hand. Write a manifest whose `digest` matches the source and whose `encode_constants`
equal `images.ENCODE_CONSTANTS`, put a small valid WebP that no encode of that source could produce
under `_optimised/`, then assert `decide` returns those bytes. A fresh encode of a photographic JPEG
could never produce them, so the assertion proves the encode was skipped without touching an
internal. The same trick inverted proves a miss: when the planted bytes do not come back, the
encoder ran.

Cases, one behaviour each:

- A cold directory. `decide` on a photographic JPEG returns `optimised`, writes
  `_optimised/photo.webp`, and `write_manifests` writes `_optimised/manifest.yaml` with one entry
  keyed `photo.jpg`.
- A planted entry that validates returns the planted bytes.
- A second `ImageCache` over the tree the first one wrote returns an equal decision, writes nothing,
  and leaves the manifest bytes byte-identical.
- Source bytes changed, entry otherwise intact: the planted bytes do not come back.
- `encode_constants` stale by one value, from a hand-written manifest carrying `lossy_quality: 75`:
  the planted bytes do not come back. Hand-written rather than monkeypatched, so the test exercises
  the on-disk contract.
- `encode_version` stale: the same.
- The entry's `.webp` missing: a fresh `optimised` decision, and the file is written again.
- The entry's `.webp` truncated, cut short of the length its RIFF header declares: the same.
- An `optimised` entry with no `source_format`: a miss, not a decision that would print `None` in
  the author-facing line.
- `kept source` from `already_minimal_png_bytes`, `could not decode` from
  `break_png_chunk_crc(png_bytes())` whose `error` text survives the round trip, and `passthrough`
  from `animated_gif_bytes` each get an entry, and each hits on the next run.
- An SVG gets no entry, and a directory holding only SVGs gets no `_optimised/` directory.
- An orphan. A manifest naming a source that is not in the directory loses its entry, and its
  `.webp` is deleted.
- An entry whose source is still on disk but which this run never saw survives, which is the
  single-file-run case.
- A directory whose last image is gone loses its `manifest.yaml` and its `_optimised/` directory,
  even though nothing in that directory is scanned.
- A `.webp` no entry claims, the trace a run that failed before its manifest was written leaves, is
  deleted by the next `write_manifests`.
- A manifest with conflict markers. Every image in the directory is encoded again, a notice names
  the manifest path and the YAML error, and the manifest is rewritten clean and parseable.
- A manifest that parses to a list: the same.
- `photo.jpg` and `photo.png` in one directory. `decide` raises `ValueError` naming both filenames
  and the WebP name they collide on.
- Two directories, and a `ValueError` raised while deciding in the second. The first directory's
  manifest is already on disk and valid, which is what the per-directory write buys.

## Acceptance

Straight from the idea.

1. A second run over an unchanged tree performs no encode, writes no bytes anywhere in the working
   tree, and produces the same per-image lines as the first.
2. `_optimised/` holds the optimised WebP files and one `manifest.yaml`, and all three copies of the
   scanner skip rule ignore it with no code change.
3. Entries are keyed by the source filename and carry a SHA-256 digest of the source bytes, the
   `images.py` constants by value, and the hand-bumped version number.
4. A changed source, a changed constant or a bumped version is a miss. A change to the installed
   Pillow or libwebp is not.
5. `optimised`, `kept source`, `could not decode` and non-SVG `passthrough` are all cached. SVG gets
   no entry.
6. An orphan entry and its file are deleted. A manifest that cannot be parsed cold-caches its own
   directory, is named with its error in the run output, and is rewritten clean. A missing or
   truncated cached WebP is a miss.
7. Two source images in one directory that target the same WebP name fail the run.
8. The run states that files were written under `_optimised/` and need committing.
9. `optimise_image` still knows nothing about caching, `File`, `course_media` and the storage-key
   bookkeeping are untouched, and `demo_content/` stays cold.

## Out of scope

Skipping the storage write for a file whose bytes did not change. `File` carries no digest to compare
against, and once encoding is cached that becomes the remaining cost of a run, particularly against a
real bucket. The idea names it as its own idea and deliberately does not fold it in. Documents, video
and audio stay written through verbatim, because there is no per-file work to cache for them.
