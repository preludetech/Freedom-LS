# Spec: question access

Spec 4 of 5 in the SACAA content versions and access effort. Source: `idea.md`. Answers taken before
writing: `answers.md`. Research: `research_codebase.md` (current paths and symbols; read it first),
`research_question_access_surfaces.md`, `research_ux_patterns.md`, `research_best_practices.md`,
`research_prior_art.md`, `research_known_complaints.md`, `research_reference_implementations.md`.

## Purpose

An aviation-authority audit expects a quiz question bank to be confidential and every look at it to
be traceable. Today anyone who can see a course or cohort in the educator interface can read quiz
questions and their correct answers in four places: the course content preview, the cohort report
on screen, the cohort report PDF and the quiz attempt review. None of them is logged. The Django
admin shows QUIZ answers to staff, with no log. When this spec is done, only holders of a new
permission see quiz questions and correct answers, each view writes one audit entry, and the admin
shows no QUIZ answers.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| question detail | coined | Quiz question text, option text, which options are correct, wrong-option counts, and a learner's chosen options on a quiz question. No existing term covers the set. |
| quiz | narrowed | A `Form` whose `strategy` is `FormStrategy.QUIZ` (`form_engine/models.py`). Surveys and application forms are the other strategies. |

## Scope

In:

- A permission `freedom_ls_content_engine.view_course_questions` and an organisation role
  `question_bank_viewer` that holds it.
- Gating and auditing question detail on four educator surfaces: the course content preview (quiz
  rows only), the cohort report quiz confusions on screen, the cohort report PDF (at generation and
  download), and the quiz attempt review's Paper panel.
- Removing QUIZ answers from the Django admin.
- The audit action `question.viewed`, glossary, docs.

Out:

- The learner-facing incorrect-answers review (`Form.quiz_show_incorrect`).
- Showing the answered version in the attempt review (spec 5) and question versioning (spec 3).
- The course applications API, exports of application answers, shell commands (`content_save`,
  `qa_*`).
- Dedupe or throttling of view entries, logging refused requests, a notice telling holders they are
  logged.
- A course-scoped role or a `Course` scope in `can()`, and a course History tab.

The Django admin's question, option, form and content pages are already gone
(`base/tests/invariants/test_admin_registry.py`). Only the QUIZ answer views remain to change.

## Decisions

- **One check, organisation-scoped.** Every gate calls one helper,
  `can_view_course_questions(user, organisation) -> bool`, which is
  `can(user, VIEW_COURSE_QUESTIONS, organisation)`. A cohort grant never passes an organisation
  check, so a site's permissions module cannot hand the permission to a cohort role by accident.
  The organisation is `request.organisation` on educator pages, `cohort.organisation` for a PDF, and
  the learner's organisation for an attempt.
- **Superusers pass and are logged** like everyone else, through the same code path.
- **One entry per request that renders question detail, and only on an HTMX request.** Same rule as
  `conversation.viewed`: a prefetch or plain GET writes nothing, and a request that renders no
  question detail writes nothing. The one exception is the PDF download, which is a plain GET by
  nature (below).
- **A non-HTMX request never renders question detail.** Without this, the lazy panels' `<noscript>`
  `?loaded=1` link would show the detail and write no entry. Such a request renders the panel without
  the detail and with the note "Question detail loads only with JavaScript turned on."
- **Every re-render is a view.** A `cohortChanged` re-fetch or `?refresh=1` of the report body
  writes another entry. No dedupe.
- **Disabled Preview on quiz rows** (user's choice in `answers.md`). This is a deliberate exception
  to the panel-framework rule that a row the viewer cannot act on leaves its buttons cell empty.
  Topic, activity and survey rows are unchanged.
- **The PDF's content is fixed when it is generated.** Whether it carries question detail depends
  on the generator's permission at that moment, and is stored on the `GeneratedReport`. Each
  download checks the downloader's current permission.
- **The screen cache stays permission-neutral.** `cached_cohort_report` keeps one entry per cohort.
  The panel removes question detail for a non-holder at read time, so cached data is never rendered
  unredacted for them. No cache-key change.
- **Admin hides QUIZ answers from everyone, superusers included.** The admin writes no log, so it
  cannot be a gated path.

## Requirements

### Permission and role

- `content_engine/models/courses.py` `Course.Meta.permissions = [("view_course_questions", "Can view a course's quiz questions, options and correct answers")]`.
  The new `content_engine` migration is an `AlterModelOptions` that restates
  `ordering = ["title", "pk"]`.
- `role_based_permissions/registry.py` `PERMISSIONS`: add `freedom_ls_content_engine.view_course_questions`
  and `freedom_ls_role_based_permissions.assign_question_bank_viewer`.
- `role_based_permissions/models.py` `ObjectRoleAssignment.Meta.permissions`: add
  `("assign_question_bank_viewer", "Can grant or remove the question_bank_viewer role")`, with a
  migration.
- `role_based_permissions/roles.py` `BASE_ROLES`: new role
  ```python
  "question_bank_viewer": Role(
      display_name="Question bank viewer",
      assignment_scope=SCOPE_OBJECT,
      lti_role=None,
      description="May view a course's quiz questions, options and correct answers, in course previews, cohort reports and quiz attempts. Each view is logged.",
      permissions=frozenset({"freedom_ls_content_engine.view_course_questions"}),
  )
  ```
  `site_admin` and `organisation_admin` gain `assign_question_bank_viewer`. No role gains
  `view_course_questions`.
- `learner_management/queries.py`: `VIEW_COURSE_QUESTIONS` beside `VIEW_CONVERSATION`;
  `question_bank_viewer` added to `STAFF_ROLES` and `ORGANISATION_ROLES`, so `role_target`
  returns `"organisation"` and the Staff section can list, filter, grant and deactivate it.
- `can_view_course_questions` lives beside `can()` in `learner_management/capabilities.py`.
- `educator_interface/tests/invariants/test_permission_matrix.py`: `ROLES`, a `MATRIX` row for
  `VIEW_COURSE_QUESTIONS` (allowed: `question_bank_viewer` only; superuser passes),
  `CAPABILITY_SCOPE_KINDS` kind `organisation`, a cell for the new assign capability, and
  `_build_world` assignments.

### Audit action

  `question` (a `FormQuestion`, as an audit noun) to the Changes noun list, extends the `viewed` row

- `audit_log/tests/invariants/test_vocabulary.py` `NOUNS` gains `question`. The group is `Other`,

### Course content preview

File `educator_interface/panels/course/content_preview.py`.

- `OutlineRow` gains `preview_withheld: bool`. The row builders (`outline_rows`, `reference_rows`,
  `_outline_item_rows`, `_form_page_rows`) take `may_view_questions: bool`. For a `Form` whose
  `strategy` is `QUIZ` and a viewer without the permission, the form row and every page row get an
  empty `preview_query` and `preview_withheld=True`. `preview_sequence` and `_stepping_urls` then
  skip those rows, unchanged. All four callers (`CourseContentPanel.build_rows`,
  `CourseReferencePanel.build_rows`, `PreviewContentAction.get_context_data`,
  `PreviewCourseDetailsAction.get_context_data`) compute the boolean once per request with
  `can_view_course_questions(request.user, request.organisation)`.
- `partials/course_outline_actions.html` (and the card partial, if it has its own trigger): a
  withheld row shows the Preview button disabled, with the reason beside it, linked by
  `aria-describedby`: "Previewing a quiz needs the question bank viewer role."
- `PreviewContentAction` keeps `capability = None`. `render_fragment` resolves the target. For a
  quiz and a viewer without the permission it returns `denied_response`, a 403 whose text names the
  organisation's admins (`OrganisationSectionConfig.get_denied_context`). This refusal does not
  depend on the row list.
- For a holder, `get_context_data` calls `record_question_view` with surface `preview` when the
  rendered page shows at least one question. That is a page row, or a single-page quiz's form row.
  The intro row of a multi-page quiz shows only `quiz_facts` and writes nothing. The existing
  non-HTMX 404 guard stays.

### Cohort report on screen

File `educator_interface/panels/cohort/report_panels.py`, template
`panels/cohort_report_body_region.html`.

- `CohortReportBodyPanel.get_loaded_context` passes `question_detail: bool`. It is true only for a
  holder on an HTMX request. When false, `confusions` is empty and the "Quiz confusions across the
  cohort" section shows one `<c-panel-callout tone="info">` in its place:
  - non-holder: "Question detail is hidden: you do not have permission to view questions."
  - non-HTMX: the JavaScript note from Decisions.

  The section's "No quiz in this report has any incorrect answers to analyse." empty state appears
  only when `question_detail` is true. Everything else in the report is unchanged.
- When `question_detail` is true and at least one confusion card renders, write one entry with
  surface `cohort_report_screen` and `forms` set to the quizzes shown.

### Cohort report PDF

- `reports/models.py` `GeneratedReport.includes_question_detail = BooleanField(default=True)`. The
  migration's default marks every existing report as carrying detail, which is `answers.md`'s rule
  for old PDFs. Add it to `GeneratedReportAdmin.readonly_fields`.
- `reports/services.py` `request_cohort_report(cohort, user)` sets the field to
  `can_view_course_questions(user, cohort.organisation)` when it creates the row. This covers both
  the educator `GenerateReportAction` and the admin `generate_report_view`. Generation writes no
  audit entry.
- `reports/tasks.py` `generate_cohort_report` passes the stored value into
  `reports/gather.py` `gather_cohort_report_data(..., question_detail=...)`, a new keyword separate
  from `pdf_detail`. With `question_detail=False`, `confusions_by_quiz` blocks are empty,
  `wrong_answers` are empty, and `reports/report_data.py` `CohortReportData.question_detail` is
  false. Bump `reports/screen_cache.py` `SCHEMA_VERSION`.
- Templates (`reports/templates/reports/report.html`, `partials/learner_detail.html`,
  `confusions.html`, `contents.html`, `methodology.html`): without question detail, the confusions
  section and each learner's Incorrect answers block print one line in their place: "Question detail
  is not included: the person who generated this report did not have permission to view questions."
  The contents and methodology pages do not describe content that is absent.
- Downloads: one shared check-and-log step used by
  `educator_interface/panels/cohort/report_download.py` `cohort_report_download` and
  `reports/views.py` `download_report_view` before `report_file_response`. For a report with
  `includes_question_detail`:
  - downloader without the permission: refused (educator: 403 with "You do not have permission to
    download this report. It includes question detail."; admin: `PermissionDenied`), with no entry;
  - holder: one entry with surface `cohort_report_pdf`, on a GET that returns the file.

  A report without detail downloads as today, with no entry.
- `CohortReportDownloadsPanel` (`cohort_report_downloads_region.html`): for a non-holder, a row
  whose report carries detail shows its Download control disabled, with the reason beside it: "This
  report includes question detail, which needs the question bank viewer role."

- The Summary panel, page header stats and `QuizAttemptQuickView` show no question detail and stay

- `educator_interface/tests/invariants/test_answer_key_flag.py` stays green: `show_answer_key`

### Django admin

File `form_engine/admin.py`.

- `answers_context(request, form_progress)`: for a QUIZ form, returns no `answer_groups` and
  sets `quiz_answers_hidden=True`. `admin/form_engine/answers_change_form.html` then shows "Answers
  to quizzes are not shown in the admin." instead of the document. This covers `FormProgressAdmin`
  and `CourseApplicationAdmin`. Survey and application answers are unchanged.
- `QuestionAnswerAdmin` and `QuestionAnswerFileAdmin`: `get_queryset` excludes answers whose

  direct change URL all exclude them. The `question__form_page__form` list filter must still load.
- No admin link or filter is left pointing at a removed page. `admin_change_link` already degrades
  an unregistered model to plain text.

## Testing

- Role and permission: `test_roles.py` (the role exists, its display name and description verbatim,
  only `question_bank_viewer` holds the permission, `site_admin` and `organisation_admin` hold the
  assign permission); the permission matrix invariants; `validate_role_permissions` passes; Staff
  section grant, list, filter and deactivate of the new role by an organisation admin; a cohort
  admin cannot grant it.
- Helper: a holder passes; a holder in another organisation fails; a cohort-scoped grant of the
  permission (via a test role config) fails; a superuser passes; an inactive staff member fails.
- Preview: a non-holder sees Preview disabled with its reason on every quiz row (form and page rows),
  enabled on topic, activity and survey rows; stepping skips quiz rows; a direct HTMX request for a
  quiz item or page is a 403 and writes nothing; a holder's page view writes exactly one entry with
  the target, organisation and `details` above; a second open writes a second; the multi-page intro
  writes none; a non-HTMX request writes none; a superuser's view is logged.
- Cohort report screen: holder HTMX load writes one entry and shows confusions; a re-fetch writes
  another; a non-holder sees the note, no question or option text, unchanged scores, and no entry;
  the non-HTMX `?loaded=1` shows the JavaScript note and writes nothing; a holder's load followed by
  a non-holder's load from the same cache shows no detail to the non-holder.
- PDF: generation by a holder stores `includes_question_detail=True`, by a non-holder `False`, from
  both entry points; a no-detail PDF contains no question text, option text or wrong answers and
  does contain the note; a pre-existing report (migration default) is treated as carrying detail;
  each holder download writes one entry; a non-holder download of a detail-carrying report is
  refused in both views and writes nothing; a no-detail report downloads for anyone with
  `download_cohort_report` and writes nothing; the Downloads panel disables the control for a
  non-holder on a detail-carrying row.
- Attempt review: holder HTMX load shows the paper and writes one entry with the learner as subject
  (it appears on the learner's History tab); non-holder sees the note and no question text; the
  non-HTMX load writes nothing.
- Admin: a QUIZ form progress shows the hidden note and no question text, for a superuser too; a
  survey form progress and a course application still show their answers;
  `QuestionAnswerAdmin` and `QuestionAnswerFileAdmin` changelists and change URLs exclude QUIZ
  answers; the changelist filters and search still load.
- Vocabulary invariants pass with `question.viewed`.
- Browser (Playwright): a non-holder's course outline with a quiz; a holder previewing a quiz page,
  then the organisation Audit log listing the entry.

## Open questions

- Q: Does `question_bank_viewer` open any educator section by itself? → A: No. It only adds the
  permission; a holder also needs a role that opens the course, cohort or learner pages. (assumed
  default: the idea calls it a dedicated role holding the permission, and roles add up. Overrule by
  editing "Permission and role".)
- Q: Should the Downloads panel disable or hide the Download control for a non-holder on a
  detail-carrying PDF? → A: Disable it, with the reason beside it. (assumed default: it matches the
  disabled Preview the user chose for the same situation. Overrule by editing "Cohort report PDF".)
- Q: Should the attempt review's Paper panel load lazily so its entry follows the HTMX-only rule?
  → A: Yes. (assumed default: it is the only way to keep one rule for every on-screen surface.
  Overrule by editing "Quiz attempt review".)

## Success criteria

- A user with no `question_bank_viewer` role, who is not a superuser, can reach no quiz question
  text, option text or correct answer in the educator interface, a PDF they generate, a PDF they try
  to download, or the Django admin.
- Each view of question detail by a holder or superuser writes exactly one `question.viewed` entry,
  with the target and details above. Refused requests, non-HTMX renders and the multi-page quiz intro write none.
- An organisation admin can grant and deactivate `question_bank_viewer` from the Staff section; a
  cohort admin cannot.
- Topic, activity and survey previews, report scores and survey and application answers in the
  admin behave as before.
- The vocabulary, permission matrix, answer-key flag and admin registry invariants pass.
