# Spec: question access

Spec 4 of 5 in the SACAA content versions and access effort. Source: `idea.md`. User answers:
`answers.md` (where the later answers supersede earlier ones, the later ones apply). Research:
`research_codebase.md` (current paths and symbols; read it first), `research_question_access_surfaces.md`,
`research_ux_patterns.md`, `research_best_practices.md`, `research_prior_art.md`,
`research_known_complaints.md`, `research_reference_implementations.md`.

## Purpose

Quiz question detail must be confidential, and every view of it traceable (`idea.md`, Why). When
this spec is done, only holders of a new permission see question detail in the educator interface,
each view writes one audit log entry, PDF reports carry no question detail for anyone, and the
Django admin shows no QUIZ answers.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| question detail | coined | Quiz question text, option text, which options are correct, wrong-option counts, and a learner's chosen options on a quiz question. No existing term covers the set. |
| quiz | narrowed | A `Form` whose `strategy` is `FormStrategy.QUIZ` (`form_engine/enums.py`). `CATEGORY_VALUE_SUM` and `UNSCORED` are the other strategies; surveys and application forms use them. |
| question bank viewer | coined | The organisation role `question_bank_viewer`, the only base role holding `view_course_questions`. |

## Scope

In:

- A permission `freedom_ls_content_engine.view_course_questions` and an organisation role
  `question_bank_viewer` that holds it.
- Gating and auditing question detail on three educator interface pages: the course content
  preview (quiz rows only), the cohort Report tab's quiz confusions, and the attempt review's Paper
  panel.
- Removing question detail from the cohort report PDF, for everyone.
- Removing QUIZ answers from the Django admin.
- The audit action `question.viewed`, glossary and docs.

Out:

- PDFs generated before this change: left as they are, with no flag, migration, deletion or
  download gate.
- The learner-facing incorrect-answers review (`Form.quiz_show_incorrect`).
- Showing the answered version in the attempt review (spec 5) and question versioning (spec 3).
- The course applications API, exports of application answers, shell commands (`content_save`,
  `qa_*`).
- Dedupe or throttling of view entries, logging refused requests, a notice telling holders they are
  logged.
- A course-scoped role, a `Course` scope in `can()`, a course History tab.

## Decisions

- **One check, organisation-scoped.** A cohort grant never passes an organisation check, so a
  site's permissions module cannot hand the permission to a cohort role by accident.
- **Superusers pass and are logged** like everyone else, through the same code path.
- **One entry per HTMX request that renders question detail.** This is the `conversation.viewed`
  rule: a prefetch, a plain GET or a request that renders no question detail writes nothing. A
  `cohortChanged` re-fetch or `?refresh=1` of the Report tab is another view and writes another
  entry.
- **A non-HTMX request never renders question detail.** Without this, the lazy panels' `<noscript>`
  `?loaded=1` link would show the detail and write no entry. Such a request renders the panel with
  the note "Question detail loads only with JavaScript turned on." in place of the detail.
- **Disabled "Needs permission" button on quiz rows** (user's choice). This is a deliberate
  exception to the panel-framework rule that a row the viewer cannot act on leaves its buttons
  cell empty. The button's own short label says why; no sentence sits beside it, since text in a
  button cell wraps and looks ugly. A disabled button does nothing when clicked.
- **The screen cache stays permission-neutral.** `cached_cohort_report` keeps one entry per cohort,
  and the panel redacts the data for a non-holder at read time. No cache-key change.
- **The viewer's organisation owns the entry.** For a course shared from another organisation, the
  owning organisation's Audit log does not show the view; the viewer's organisation granted the role.
- **The admin hides QUIZ answers from everyone, superusers included.** The admin writes no log, so
  it cannot be a gated path.

## Requirements

### Permission and role

- `content_engine/models/courses.py` `Course.Meta.permissions = [("view_course_questions", "Can view a course's quiz questions, options and correct answers")]`.
  The new `content_engine` migration is an `AlterModelOptions` that restates
  `ordering = ["title", "pk"]`.
- `role_based_permissions/registry.py` `PERMISSIONS`: add `freedom_ls_content_engine.view_course_questions`
  and `freedom_ls_role_based_permissions.assign_question_bank_viewer`.
- `role_based_permissions/models.py` `ObjectRoleAssignment.Meta.permissions`: add
  `("assign_question_bank_viewer", "Can grant or remove the question_bank_viewer role")`, with a
  migration.
- `role_based_permissions/roles.py` `BASE_ROLES`: new role
  ```python
  "question_bank_viewer": Role(
      display_name="Question bank viewer",
      assignment_scope=SCOPE_OBJECT,
      lti_role=None,
      description="May view a course's quiz questions, options and correct answers, in course previews, cohort reports and attempt reviews. Each view is logged.",
      permissions=frozenset({"freedom_ls_content_engine.view_course_questions"}),
  )
  ```
  `site_admin` and `organisation_admin` gain `assign_question_bank_viewer`. No role gains
  `view_course_questions`.
- `learner_management/capabilities.py`: the constant `VIEW_COURSE_QUESTIONS` and
  `can_view_course_questions(user, organisation) -> bool` (`can(user, VIEW_COURSE_QUESTIONS, organisation)`).
  `learner_management/queries.py` re-exports the constant beside `VIEW_CONVERSATION`; it already
  imports `capabilities`, so the constant cannot live in `queries.py`.
- `learner_management/queries.py`: `question_bank_viewer` joins `STAFF_ROLES` and
  `ORGANISATION_ROLES`, so `role_target` returns `"organisation"` and the Staff section lists,
  filters, grants and deactivates it.
- `educator_interface/tests/invariants/test_permission_matrix.py`: `ROLES`, `GATED_ROLES`, a
  `MATRIX` row for `VIEW_COURSE_QUESTIONS` (allowed: `question_bank_viewer` only; superuser passes),
  `CAPABILITY_SCOPE_KINDS` kind `organisation`, a cell for the new assign capability, and
  `_build_world` assignments.

### Course content preview

File `educator_interface/panels/course/content_preview.py`.

- `OutlineRow` gains `preview_withheld: bool`. Every row builder (`outline_rows`, `reference_rows`,
  `_part_row`, `_outline_item_rows`, `_form_page_rows`) takes `may_view_questions: bool`. For a
  quiz and a viewer without the permission, the form row and every page row get an empty
  `preview_query` and `preview_withheld=True`. `preview_sequence` and `_stepping_urls` then skip
  those rows, unchanged. All four callers (`CourseContentPanel.build_rows`,
  `CourseReferencePanel.build_rows`, `PreviewContentAction.get_context_data`,
  `PreviewCourseDetailsAction.get_context_data`) compute the boolean once per request with
  `can_view_course_questions(request.user, request.organisation)`.
- `partials/course_outline_actions.html` (and the card partial, if it has its own trigger): a
  withheld row shows a disabled button labelled "Needs permission" in place of Preview, with no
  text beside it. Its accessible name is "Needs permission to preview <title>" (for a page row,
  "<form title>: <page title>"). The Actions column is as wide as that button, not wider. The
  outline card labels its type "Type: <kind>" and puts its button in the item footer, 12px under
  that line.
- `PreviewContentAction` keeps `capability = None` and gains `label = "Preview"`.
  `render_fragment` resolves the target. For a quiz and a viewer without the permission it returns
  `denied_response`, a 403 whose text names the organisation's admins
  (`OrganisationSectionConfig.get_denied_context`). This refusal does not depend on the row list.
  It is the guard for a hand-built request only: the disabled button sends no request, so no click
  in the UI reaches it.
- For a holder, `get_context_data` calls `record_question_view` with surface `preview` when the
  rendered page shows at least one question: a page row, or a single-page quiz's form row. The
  intro row of a multi-page quiz shows only `quiz_facts` and writes nothing.
- The course details modal (`PreviewCourseDetailsAction`) shows no question detail and stays
  ungated.

### Cohort Report tab

File `educator_interface/panels/cohort/report_panels.py`, template
`panels/cohort_report_body_region.html`.

- `CohortReportBodyPanel.get_loaded_context` sets `question_detail: bool`, true only for a holder
  (`can_view_course_questions(user, cohort.organisation)`) on an HTMX request. When false, the
  panel passes `dataclasses.replace` copies of `data`'s course sections with
  `confusions_by_quiz={}`, so no question detail reaches the template context. In place of the
  "Quiz confusions across the cohort" section it shows one plain sentence (a `<p>`, no callout):
  - non-holder: "Question detail is hidden: you do not have permission to view questions."
  - non-HTMX: the JavaScript note from Decisions.

  Which note applies comes from a shared helper
  `question_detail_withheld_note(request, organisation)` in
  `educator_interface/panels/common/question_detail.py`. It returns the non-holder note, the
  JavaScript note or an empty string, and the Paper panel uses it too.

  The section's "No quiz in this report has any incorrect answers to analyse." empty state appears
  only when `question_detail` is true. Everything else on the tab is unchanged.
- When `question_detail` is true and at least one confusion card renders, write one entry with
  surface `cohort_report` and `forms` set to the quizzes shown.

### Django admin

The question, option, form and content admin pages are already unregistered. In
`form_engine/admin.py`:

- `answers_context(request, form_progress)`: for a QUIZ form, returns no `answer_groups` and
  sets `quiz_answers_hidden=True`. `admin/form_engine/answers_change_form.html` then shows "Answers
  to quizzes are not shown in the admin." in place of the document. This covers `FormProgressAdmin`
  and `CourseApplicationAdmin`. Survey and application answers are unchanged.
- `QuestionAnswerAdmin` and `QuestionAnswerFileAdmin`: `get_queryset` excludes answers whose
  `form_progress.form.strategy` is `QUIZ`, so the changelist, the search on question text and a
  direct change URL all exclude them. The `question__form_page__form` list filter must still load.
- `form_engine/views.py` `question_answer_file_download_view` applies the same exclusion through a
  shared queryset helper, since it does not go through the admin's `get_queryset`.
- No admin link or filter is left pointing at a removed page.

## Open questions

- Q: Does `question_bank_viewer` open any educator section by itself? → A: No. It only adds the
  permission; a holder also needs a role that opens the course, cohort or learner pages. (assumed
  default: the idea calls it a dedicated role holding the permission, and roles add up. Overrule by
  editing "Permission and role".)
- Q: Should the attempt review's Paper panel load lazily? → A: Yes. (assumed default: it keeps the
  HTMX-only rule for every on-screen view. Overrule by editing "Attempt review".)

## Success criteria

- A user who does not hold `freedom_ls_content_engine.view_course_questions` on the organisation,
  and is not a superuser, can reach no quiz question text, option text or correct answer in the
  educator interface or the Django admin.
- No PDF generated after this change contains quiz question text, option text or correct answers.
- Each view of question detail by a holder or superuser writes exactly one `question.viewed` audit
  log entry with the target and details above. Refused requests, non-HTMX renders and the
  multi-page quiz intro write none.
- An organisation admin can grant and deactivate `question_bank_viewer` from the Staff section; a
  cohort admin cannot.
