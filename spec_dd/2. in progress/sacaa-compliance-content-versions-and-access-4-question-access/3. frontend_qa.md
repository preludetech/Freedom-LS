# Frontend QA: question access

Quiz question detail (question text, option text, correct answers, a learner's chosen options) is
shown only to people who hold the question bank viewer role, each view is logged, PDFs carry none
of it, and the Django admin shows no quiz answers. Judge each page on this branch's server only.

**Decided by the user after QA. A fix never reverts these; a finding that would is a bug in the
finding.**

- A withheld quiz row shows one disabled button labelled "Needs permission" and no text beside it.
  No sentence goes in a cell or card footer that holds a button.
- The disabled button does nothing when clicked: no dialog, no request. The "You can't use
  “Preview” here any more" dialog is only the server's answer to a hand-built request (Test 4).
- Every outline card value except the title has a label: "Type" beside "Form", never a bare "Form". Labels carry no colon.
- A card's button sits in its footer with clear space (12px) above it, never pressed against the
  line above, at 768 and at 375.
- "Question detail is hidden: you do not have permission to view questions." (and the JavaScript
  note) is a plain sentence: no callout box, no tinted background, no info icon.

## Setup

1. Start the server with the `Dev server start` command under `## QA Hooks` in
   `.claude/sdd/config.md`, on `$PORT`. Base URL: `http://127.0.0.1:$PORT`.
2. Run `uv run python manage.py migrate` and `uv run python manage.py sync_role_permissions`.
3. Seed the data. Each command is idempotent:
   - `uv run python manage.py qa_create_course_content_preview` ("QA Preview Course" with topics, a
     part holding "Module quiz", and "Feedback survey"; cohort "QA Preview Cohort")
   - `uv run python manage.py qa_create_attempt_review_scenario` ("QA Attempt Review Course" with
     Quiz A to D and a survey; learners with completed quiz sittings; cohorts C1 and C2; educator E
     holding `cohort_viewer` on C1 only)
   - `uv run python manage.py qa_create_report_cohort` (a cohort with quiz attempts that include
     incorrect answers, for the Report tab and the PDF)
   - `uv run python manage.py qa_create_staff_administration_scenario` (staff members and roles)
4. People. Ask the QA data helper for any that the seeds did not create, in the organisation that
   holds the seeded courses and cohorts:
   - **Superuser**: `demodev@email.com` / `demodev@email.com`.
   - **Non-holder**: an active staff member who is `organisation_admin` and does not hold
     `question_bank_viewer`, and is not a superuser.
   - **Holder**: an active staff member who is `organisation_admin` and holds
     `question_bank_viewer`, not a superuser. Test 1 creates this grant through the interface; use
     a second organisation admin for it.
   - **Cohort admin**: a staff member holding only `cohort_admin` on one cohort.
5. Data the tests need, to be made by the QA data helper if missing:
   - a multi-page quiz and a single-page quiz in one course outline, with one quiz inside a part
     and one quiz in the course's Reference list;
   - a completed survey sitting and a completed quiz sitting, each visible in the Django admin, and
     one survey answer with an uploaded file.

Check each educator page at the three QA viewports. A page that errors (500, a blank region, a
broken dialog) fails, whatever the step says. Write down a distinctive question text and option
text from "Module quiz" and from Quiz A before starting: several tests search pages for them.

## Test 1: An organisation admin grants and deactivates the role

Log in as the Non-holder. Go to the organisation's Staff section.

1. Open "Add staff member" (or "Change role" on an existing staff member).
2. Find "Question bank viewer" among the roles.
3. Grant it to the second organisation admin (the Holder).
4. Filter the staff list by the role.
5. Open the Audit log section.

Checklist:
- [ ] "Question bank viewer" is offered with the description "May view a course's quiz questions,
      options and correct answers, in course previews, cohort reports and attempt reviews. Each
      view is logged."
- [ ] It is offered as a role on the whole organisation, with no cohort picker.
- [ ] After granting, the staff list shows the role badge on the Holder.
- [ ] The role filter lists "Question bank viewer" and narrows the list to the Holder.
- [ ] The Audit log shows a "Role assigned" entry naming the role.

Then deactivate the role on a third staff member you grant it to for this step only.

- [ ] The role can be deactivated, the badge goes, and the Audit log shows the deactivation.

Side effects to check:
- [ ] The other roles in the dialog and the filter are unchanged and in the same order as before
      the new one.
- [ ] A staff member holding only "Question bank viewer" sees no Cohorts, Learners or Courses
      section opened by it.

## Test 3: The course outline for a non-holder

Log in as the Non-holder. Open Courses, then "QA Preview Course", Course content panel.

1. Expand every part and multi-page form.
2. Look at the Actions column of each row.
3. Click Preview on a topic, then use Next in the dialog repeatedly to the end.
4. Open the Reference panel if the course has reference parts.

Checklist:
- [ ] Every quiz row (the quiz's own row and each of its page rows, inside and outside parts) shows
      a disabled button labelled "Needs permission", not "Preview".
- [ ] The Actions cell of a withheld row holds that button and nothing else: no reason sentence,
      no wrapped text. At 1920 a withheld row is as tall as a topic row.
- [ ] The disabled button's accessible name starts "Needs permission to preview" and names the row.
- [ ] Clicking the disabled button does nothing: no dialog opens and the network log shows no
      `preview_content` request.
- [ ] Topic rows, activity rows and "Feedback survey" rows (and the survey's page rows) have an
      enabled Preview that opens the dialog.
- [ ] "Course details" has an enabled Preview.
- [ ] Stepping with Next and Previous never lands on a quiz row: it jumps from the item before the
      quiz to the item after it.
- [ ] The Reference panel treats quiz rows the same way.
- [ ] At 768 and 375 the rows show as cards. Each card's type shows the label "Type" beside its
      kind, with no colon, never a bare "Topic" or "Form" under the title.
- [ ] On each card the button sits in a footer with clear space (about 12px) above it, not pressed
      against the "Type" line.
- [ ] Nothing overflows horizontally at any viewport.
- [ ] No quiz question text appears anywhere on the page.

## Test 4: A non-holder requests a quiz preview directly

This tests the server's guard against a hand-built request. No click in the interface reaches it:
the disabled button sends nothing (Test 3).

Still as the Non-holder. Log in as the Superuser in another browser profile, copy the URL a quiz
row's Preview button requests (the `hx-get` of the trigger, ending
`__actions/preview_content?item=...` and, for a page row, `&page=...`).

1. As the Non-holder, paste the URL in the address bar.
2. As the Non-holder, from the course page run in the browser console:
   `htmx.ajax('GET', '<that URL>', '#app-modal-body')`.

Checklist:
- [ ] Step 1 (a plain request) shows a not-found page and no questions.
- [ ] Step 2, and only step 2, opens a dialog titled "You can't use “Preview” here any more" that says the role
      doesn't allow it and names an organisation admin to ask. No question text.
- [ ] After both steps the organisation Audit log has no new "Question detail viewed" entry.

Checklist:

- [ ] The intro shows the quiz facts (pages, questions, pass mark and so on) and no questions.
- [ ] Each quiz page shows its questions with the correct answers marked.
- [ ] The Audit log lists exactly four new entries: one per quiz page viewed in step 2 (two), and
      two for the single-page quiz (steps 3 and 4). None for the intro, the topic or the survey.
- [ ] Each entry is labelled "Question detail viewed", names the Holder as actor, the course as
      target, and its description reads "Course preview: <quiz title>".
- [ ] "Question detail viewed" appears in the "What" filter under "Other".
- [ ] Reloading the course page (not opening a preview) adds no entry.

## Test 13: The Django admin hides quiz answers

Log in at `/admin/` as the Superuser.

1. Go to `/admin/freedom_ls_form_engine/formprogress/`. Open a completed quiz sitting.
2. Open a completed survey sitting.
3. Open a course application (`Course applications`).
4. Go to `/admin/freedom_ls_form_engine/questionanswer/`. Use the form filter to pick a quiz, then
   a survey. Search for a quiz question's text, then a survey question's text.
5. From the Superuser's database view or the data helper, take the id of one quiz `QuestionAnswer`
   and visit `/admin/freedom_ls_form_engine/questionanswer/<id>/change/`.
6. Go to `/admin/freedom_ls_form_engine/questionanswerfile/`. Download the survey answer's file.

Checklist:
- [ ] The quiz sitting's page shows "Answers to quizzes are not shown in the admin." where the
      answers document would be, and no question or option text. Its other fields (user, form,
      times, scores) still show.
- [ ] The survey sitting's page shows every question and answer, as before.
- [ ] The course application shows its answers and its file links, as before.
- [ ] The Question answer list holds survey and application answers and no quiz answer. Filtering
      by a quiz gives an empty list without an error. Filtering by a survey works.
- [ ] Searching for the quiz question text finds nothing; searching for the survey question text
      finds its answers.
- [ ] The quiz answer's change URL does not open (the admin's not-found handling), with no 500.
- [ ] The Question answer file list loads, and the survey file downloads.
- [ ] No link on any of these pages leads to a 404 or an error page.
