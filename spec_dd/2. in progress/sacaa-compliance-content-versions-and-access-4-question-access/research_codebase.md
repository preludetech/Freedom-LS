# Research: codebase touchpoints for question access (spec 4)

Topic `codebase`. Question: what in the existing codebase does this work touch, reuse or conflict with? This note goes deeper than `research_question_access_surfaces.md` and corrects it where the tree has moved. Paths are relative to the repo root. Read against `idea.md` and `answers.md` (quiz forms only; PDF decision made at generation; downloads of detail-carrying PDFs audited and refused without the permission; pre-existing PDFs treated as carrying detail).

## 0. Corrections to the earlier research and the idea (read first)

1. **The admin question and form-definition pages are already gone.** `freedom_ls/base/tests/invariants/test_admin_registry.py` asserts `Form`, `FormPage`, `FormQuestion`, `FormContent`, `QuestionOption`, every `content_engine` model, and `Learner`, `Cohort`, `LearnerCourseRegistration`, `CohortCourseRegistration` have no admin. `freedom_ls/content_engine/admin.py` no longer exists; `freedom_ls/form_engine/admin.py` registers only `FormProgress`, `QuestionAnswer`, `QuestionAnswerFile` (plus the inline `FormDeclarationInline`). So these bullets of the idea's "The Django admin loses" list are already done and need no work, only keeping as is: both `FormQuestion` registrations, `QuestionOption` admin, the question inline and option inline, the `_condition_label` columns. The `TestFormQuestionSections` tests and the `FormQuestionWithSectionsAdmin` import named in the old research are gone. What is left for this spec in the admin is only the answer views (section 4).
2. **Paths moved.** The educator interface is now `freedom_ls/educator_interface/panels/<section>/...`. `cohort_report_download` is `freedom_ls/educator_interface/panels/cohort/report_download.py` (not `educator_interface/views.py`). `ViewConversationAction` (the `conversation.viewed` precedent) is `freedom_ls/educator_interface/panels/learner/messages.py`; its test helpers `_viewed_entries` etc. are in `freedom_ls/educator_interface/tests/helpers.py` ~line 848.
3. **A third live question surface exists that the idea scopes out: the educator quiz attempt review.** `freedom_ls/educator_interface/panels/learner/quiz_attempt.py` (`QuizAttemptPaperPanel`, `quiz_attempt_paper_context`, `QuizAttemptConfig`, template `educator_interface/panels/quiz_attempt_paper.html`) shows every page of a sitting with question text, every option, the learner's answers, and `"show_answer_key": True` (line 264). It is gated only by `QuizAttemptConfig.authorise_instance` -> `openable_sitting_ids` (learner visibility), is not in the menu (`in_menu = False`) and writes no audit entry. The idea says gating it belongs to spec 5, and spec 5's idea assumes it. But it is already built, so between spec 4 and spec 5 landing an ungated, unlogged answer-key path remains. This contradicts the idea's claim "so no unlogged path remains". `freedom_ls/educator_interface/tests/invariants/test_answer_key_flag.py` pins the exact set of files that may mention `show_answer_key` (the four form_engine input templates, `form_engine/templates/form_engine/answers/options.html`, `form_engine/tests/test_answer_templates.py`, `content_preview.py`, `quiz_attempt.py`); gating inside those files keeps that test green, adding a new file that sets the flag breaks it. The spec must either gate the attempt review here, or state the gap explicitly.

## 1. Gating `PreviewContentAction` to QUIZ forms only

### 1a. How the outline offers a preview today
File `freedom_ls/educator_interface/panels/course/content_preview.py`.
- `OutlineRow` (frozen dataclass): `kind` in `course | part | topic | form | page`, `preview_query` (`item=<pk>` or `item=<pk>&page=<pk>`), `item_pk`, `page_pk`, `form_title`, `children`, `note`. `has_preview` = `not self.note and (self.kind == "course" or bool(self.preview_query))`. The row knows nothing about the form's `strategy`.
- Rows are built by `outline_rows(course)` and `reference_rows(course)` -> `_outline_item_rows` / `_form_page_rows` / `_part_row`. `_outline_item_rows` sees the `Form` child (`isinstance(child, Form)`), so `child.strategy == FormStrategy.QUIZ` is available at exactly the place the row is made. `FormStrategy` is already imported in this module (used in `PreviewContentAction` for `quiz_facts`). `Form.strategy` values: `UNSCORED`, `CATEGORY_VALUE_SUM`, `QUIZ` (`form_engine/models.py`; `FormFactory` default is `CATEGORY_VALUE_SUM`).
- A multi-page form produces a parent `form` row (`preview_query=item=<pk>`, previews the start/intro) plus one `page` row per page; a one-page form is a single `form` row. A quiz therefore has several rows to gate (parent and every page child).
- The Preview trigger is `educator_interface/templates/educator_interface/partials/course_outline_actions.html`: `{% elif object.preview_query and row_action_urls.preview_content %}`. `row_action_urls` is built in `freedom_ls/panel_framework/panels.py` (~line 246-265) from the panel's actions filtered by `action.is_available(self.ctx)`; it is per action, not per row. So a per-action capability turns the Preview button off for every row (topics included), which is wrong for "quiz forms only".
- Callers of the row builders: `CourseContentPanel.build_rows` (-> `outline_rows`), `CourseReferencePanel.build_rows` (-> `reference_rows`), `PreviewContentAction.get_context_data` (rebuilds `outline_rows(course)` or `reference_rows(course)` for the stepping sequence), `PreviewCourseDetailsAction.get_context_data` (`preview_sequence(outline_rows(course))`, stepping from index 0). Cards: `partials/course_outline_card.html`, cells `course_outline_title.html`, `_type.html`, `_number.html`. Educator tests: `educator_interface/tests/panels/course/test_content_preview.py`; `tests/invariants/test_course_shares.py` (lines ~163-168 walk `preview_content` and `preview_course_details` on `content` and `reference`); `tests/invariants/test_panel_template_rules.py`.

### 1b. Stepping when a quiz row is not previewable
`preview_sequence(rows)` keeps only rows whose `has_preview` is true, depth first; `_stepping_urls` takes the sequence and index and links the row either side (`previous_url` / `next_url`; `""` at ends; the course row links `PreviewCourseDetailsAction`, others `PreviewContentAction` with `?{row.preview_query}`). In `PreviewContentAction.get_context_data` the current index is found by `(row.item_pk, row.page_pk)`. Consequences:
- If a viewer without the permission has the quiz rows built with an empty `preview_query` (so `has_preview` is false), stepping skips them for free: no code change in `preview_sequence` or `_stepping_urls`, and the Preview button disappears because `course_outline_actions.html` tests `object.preview_query`.
- That means the row builders need a `can view questions` input (one boolean evaluated once per request against `request.organisation`), threaded through `outline_rows`, `reference_rows`, `_outline_item_rows`, `_form_page_rows`, `_part_row` and the four callers above. All four callers have `request`/`ctx.request`; `preview_sequence` stays pure.
- A direct request for a quiz item the viewer may not preview must be refused independently of the row list (the sequence only decides the buttons). `_course_list_items` finds the target item; the check belongs right after the `collection_item` lookup and before `_form_preview_context`.
- Edge: `PreviewCourseDetailsAction` links "next" to the first previewable row; with the first content row a hidden quiz it links the next previewable one. Fine, but the course-details modal's `extra_stats`/`course_details_context` should be checked not to expose question counts (not found in `course_details_context` read, but the spec author should confirm; `_quiz_facts` in `content_preview.py` only shows counts and flags and is inside the gated branch).
- Parts and topics/activities/surveys are untouched. A `Form` with `strategy` UNSCORED or CATEGORY_VALUE_SUM (survey) stays previewable; the preview still marks `show_answer_key` True for them, which is harmless (no `correct` on survey options) but means the flag stays set on non-quiz forms.

### 1c. How `PanelAction` capability checks work (and the scope trap)
`freedom_ls/panel_framework/actions.py` `PanelAction`:
- `capability: str | None` (class attribute, default `None`); `get_capability(ctx)` returns it; `permission_object(ctx)` returns `ctx.scope_object()`; `has_permission(ctx)`: `capability is None` -> True; scope `None` -> False; else `ctx.config.has_capability(ctx.request, capability, scope)`. `is_offered(ctx)` and `is_available(ctx)` (= permitted and offered) decide whether a trigger renders; "an action that is permitted but not offered still resolves".
- `ctx.scope_object()` (`panel_framework/context.py`) is the bound instance, else the list scope. On the course page the instance is a `Course`.
- `OrganisationSectionConfig.has_capability` (`educator_interface/panels/common/request.py`) is `can(request.user, capability, scope)`; `SectionConfigBase.has_capability` denies by default. `can()` (`learner_management/capabilities.py`) raises `TypeError` for any scope not in `(Site, Organisation, Cohort, Learner)` (`_site_of`, `_organisation_of`). **So simply setting `capability = VIEW_COURSE_QUESTIONS` on `PreviewContentAction` would call `can(user, cap, <Course>)` and raise `TypeError`.** The action must override `permission_object` to return `cast(OrganisationScopedRequest, ctx.request).organisation` (the `request.organisation` the section config already uses as `get_scope`).
- A per-action capability is also wrong for the quiz-only rule, because `PreviewContentAction` serves topics, forms and pages from one URL (`__actions/preview_content?item=..&page=..`). The framework's refusal path: `_handle_action` (`panel_framework/views.py` ~1122): `if not action.has_permission(ctx)`: non-HTMX -> `PermissionDenied`; HTMX -> `denied_response(ctx, action)` (403, template `panel_framework/partials/action_denied.html`, text from `SectionConfigBase.get_denied_context`, org override `OrganisationSectionConfig.get_denied_context` names the organisation admins). `render_fragment(ctx)` is documented as the hook "an action that can refuse the dialog before it opens overrides"; `denied_response` can be returned from there for a quiz target. `has_permission` also takes `ctx` only (the request carries `GET["item"]`), but resolving the item there duplicates `get_context_data`.
- The repo's own capability precedent: `ViewConversationAction` (`panels/learner/messages.py`): `capability = VIEW_CONVERSATION`, `has_permission` override adds `MESSAGING_ENABLED`, `get_context_data` raises `Http404` when `HX-Request != "true"` and then calls `record_entry`. `PreviewContentAction.get_context_data` already raises `Http404` for non-HTMX, the same shape.
- `walk_interface` / `test_every_capability_reachable_from_the_interface_is_in_matrix` (`educator_interface/tests/invariants/test_permission_matrix.py` ~985-1003) collects `action.get_capability(item.ctx)` from every walked action and requires each to be in `MATRIX`; if the new capability is returned from `get_capability` it must be added to `MATRIX` and `CAPABILITY_SCOPE_KINDS` (kind `organisation`).

### 1d. The course page and audit entry for the preview
Course instance and section: `educator_interface/panels/course/config.py` `CourseConfig.authorise_instance` -> `courses_visible_to(user, organisation)`; `CourseContentPanel.get_actions()` returns `[]` when `_preview_available` is false, so a preview of a course only registered (not available to the organisation) already 404s. The audit entry for a quiz preview would be written in `PreviewContentAction.get_context_data` once the item is resolved and the quiz check passed, with `ctx.instance` (the `Course`) as target (a `Course` is `SiteAwareModelBase`-derived, so `record_entry` accepts it) and the request's organisation. Each page of a multi-page quiz is a separate request, so a stepping reviewer writes one entry per page (per the idea). The intro/parent row of a multi-page quiz (`page_pk is None`, `total_pages > 1`) renders `_form_preview_context` with no pages (`path.pages[:0]`), so shows `quiz_facts` only (counts, pass mark, shuffle flags) and no questions; the spec should decide whether that request is a "view" (the idea says write only where questions render). Template: `educator_interface/templates/educator_interface/modal/content_preview.html`; question rendering via `form_engine/inputs/*.html` with `show_answer_key`.

## 2. The cohort report

### 2a. On-screen: `CohortReportBodyPanel`
`freedom_ls/educator_interface/panels/cohort/report_panels.py`.
- `CohortReportBodyPanel(LazyBodyPanel)`: `get_loaded_context()` calls `cached_cohort_report(cohort, refresh=request.GET["refresh"]=="1")` and returns `data`, `confusions=_quiz_confusions(data)`, `avatars`, `refresh_url`. No `capability`, so `Panel.has_permission` (panels.py ~165) is True. `_quiz_confusions` builds `QuizConfusionCard(quiz, block: ConfusionBlock, heading)` for quizzes with `confusions_by_quiz[form_id].total`.
- Template `educator_interface/templates/educator_interface/panels/cohort_report_body_region.html`, section at lines 117-154 "Quiz confusions across the cohort": per card a table with columns Q, "Question and correct answer" (`question.question_text`, `question.correct_option_texts` as success chips), "Incorrect answers chosen" (`question.distractors` text and counts), "Got it wrong" (percentages/counts, which are not question detail), plus `cap_disclosure.html` (`shown`/`total`) and an empty-state "No quiz in this report has any incorrect answers to analyse." The rest of the body (summary tables with per-quiz result cells, attention list) shows no question text. So the gate has one site: the confusions section (a replacement note, and either suppress `confusions` or pass an empty list plus a `question_detail_hidden` flag so the empty-state does not read as "no incorrect answers").
- `LazyBodyPanel` (`panel_framework/lazy_panels.py`): `Panel.get_context_data` calls `get_loaded_context` only when `request.GET["loaded"] == "1"`. The first render is a skeleton whose wrapper does `hx-get="{{ loaded_url }}" hx-trigger="load"`; the template (`panel_framework/templates/panel_framework/panels/_lazy_region.html`) also has a `<noscript>` link to the same `?loaded=1` URL, so **a plain non-HTMX GET with `loaded=1` renders the full body**. For the idea's rule "written only on the HTMX request that renders the content" the audit write must test `HX-Request == "true"` and the no-JS link then either shows the detail unlogged (not acceptable) or must be refused/omit detail; the spec needs a rule for the no-JS path. The refresh link is `?loaded=1&refresh=1`.
- Re-fetch triggers: `refresh_events = (COHORT_CHANGED,)` (`educator_interface/events.py`, `"cohortChanged"`). `_panel_base.html` hangs `hx-get="{{ base_url }}" hx-trigger="cohortChanged from:body"` on the panel; the response is the skeleton which immediately fetches `loaded=1` again. So **every cohort change fired while the Report tab is open (and every `?refresh=1`) re-renders the body and would write another entry** under "no dedupe". `GenerateReportAction.handle_submit` uses `render_region(CohortReportDownloadsPanel(ctx))` for another panel; it does not re-render the body.
- Capability for this panel: `Panel.capability` (panels.py 146-180) is checked on the panel's `scope_object()` (the `Cohort` instance), `can(user, cap, cohort)` works (supported scope; organisation grants cover a cohort via `_organisation_of`). But the panel must still render for everyone (only the question detail is withheld), so the panel capability cannot be used to hide the panel; the check is a boolean inside `get_loaded_context` (`can(request.user, VIEW_COURSE_QUESTIONS, cohort.organisation)` or against `request.organisation`).
- Placement of the write: `get_loaded_context` runs per loaded fetch and is where `cached_cohort_report` is read, so it is the natural place for `record_entry` (guarded by HX header and by "the data actually carries detail": there may be no quiz with incorrect answers; whether an empty confusions section is a "view" is a spec decision).

### 2b. The cache
`freedom_ls/reports/screen_cache.py`.
- `_cache_key(site_id, cohort_id, kind)` = `reports:screen:{SCHEMA_VERSION}:{site_id}:{cohort_id}:{kind}`, `KINDS = ("progress", "report")`, `SCHEMA_VERSION = 3` ("bump whenever a cached dataclass changes shape"). `forget_cohort(site_id, cohort_id)` deletes both kinds (signals in `reports/signals.py`).
- `cached_cohort_report(cohort, refresh=False)` stores the result of `gather_cohort_report_data(str(cohort.pk), cohort.site_id, pdf_detail=False)` (timeout `config.REPORTS_SCREEN_CACHE_SECONDS`) and returns `_trim_report(data, active_member_ids)`. Module docstring: "The cached data is permission-neutral: it holds every learner of the cohort, so callers authorise the request before they read it." `pdf_detail=False` drops the org logo and `wrong_answers`, but **the cached `CourseSection.confusions_by_quiz` always carries question text, correct option texts and distractor texts**.
- Only caller of `cached_cohort_report`: `CohortReportBodyPanel.get_loaded_context` (plus tests `reports/tests/test_screen_cache.py`). So the cache key has one consumer.
- Options this makes available: (a) keep one cached entry (permission-neutral, as documented) and redact at read time, as `_trim_report` already does with `dataclasses.replace` on `courses`; the redaction replaces each `confusions_by_quiz` value with an empty `ConfusionBlock(questions=[], shown=0, total=0)` (or the panel simply passes no `confusions`), so no key change and no way for a holder's panel to be served to a non-holder because the object is never rendered unredacted for them; (b) add a third kind or a flag to the key (`"report"` vs `"report_detail"`) which doubles the gathers and `forget_cohort` must delete the new kind too. Option (a) matches the existing design and the idea's concern ("a holder's cached panel is never served to a non-holder") is met because the cache holds data, not rendered HTML (rendered output is not cached anywhere). If the data class gains a field, `SCHEMA_VERSION` must be bumped.

## 3. Django admin pieces that are left (idea: answer views for QUIZ)

All in `freedom_ls/form_engine/admin.py` unless stated.
- `answers_context(request, form_progress)` returns `{"answer_groups": answer_groups(form_progress), "can_download_answer_files": ...}` and is the **single feed** for the answers document in both `FormProgressAdmin.render_change_form` and `course_applications/admin.py` `CourseApplicationAdmin.render_change_form` (`if form_progress is not None: context.update(answers_context(request, form_progress))`).
