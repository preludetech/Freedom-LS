# Spec: the dev database stays up

Resources: `idea.md` and the `research_*.md` files beside it.

## Purpose

Every worktree shares one dev Postgres, started from `dev_db/docker-compose.yaml`, and it keeps
going down. The crash is Docker Desktop's host file sharing. It stalls on file events under the
bind-mounted data dir and powers off the VM (`research_live_diagnostics.md`). On top of that,
starting the server from another worktree recreates the container. There is no restart policy.
Everyone connects as the superuser. `-n auto` runs 16 xdist workers. Stale databases and leaked
Playwright MCP processes pile up, and the evidence is gone by the time anyone looks.

When this work is done the server's data lives in a named volume. The container is identical
whichever worktree starts it, it restarts itself, and it is sized on purpose. App and test traffic
runs as a non-superuser role. Test runs are bounded, and a developer has one command each to
diagnose a failure, drop stale databases and reap leaked MCP processes.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| per-branch database | narrowed | `claude_plugins/fls-dev/skills/git-worktree-setup/SKILL.md`: the `db_<branch>` database, together with its `test_db_<branch>` and `test_db_<branch>_gwN` test databases |
| worktree stamp | coined | a `COMMENT ON DATABASE` on a `db_<branch>` database recording which repository and worktree created it. There was no way to attribute a database before. |

## Scope

In:

- `dev_db/`: compose file, helper scripts, README.
- `claude_plugins/fls-dev/scripts/dev_db_init.sh` and `dev_db_delete.sh`.
- `config/settings_dev.py`, the root `conftest.py`, `pyproject.toml` pytest config.
- Agent guidance on how full-suite test runs are run, in the `ds`, `sdd` and `fls-dev` plugins.
- `claude_plugins/django-stack/.mcp.json` and a new MCP reaper script in the `ds` plugin.
- Dev-setup docs.

Out (see `idea.md` "Not doing"): a Postgres container per worktree, PgBouncer, per-run ephemeral
test databases, `--reuse-db` by default, OOM-killer tuning. Also out: a role per worktree, and
launching `@playwright/mcp` from a pinned `devDependency` instead of `npx`, which would add a
package to every `ds` project.

## Decisions

- **The compose project is renamed to `fls_dev_db`.** An old worktree running the old file (project
  `dev_db`) then cannot recreate the new container. Its `up` fails on the port conflict instead.
- **The compose file takes no relative paths and no variable interpolation.** Either one makes the
  resolved config differ between worktrees, and a different config recreates the container.
  `docker-entrypoint-initdb.d/` goes, and `create-test-db.sql` with it, since nothing uses `test_db`.
- **The app role is created by `dev_db_init.sh`, not by a cluster init script.** That script already
  runs for every worktree as a superuser, so the role also appears on a cluster created before this
  change. The compose file needs no init mount.
- **One role, `fls_dev`, for runserver and pytest**, with `CREATEDB`. Splitting app and test roles
  buys nothing on a dev server.
- **`pguser` stays the superuser and is for humans and admin scripts only**, so
  `superuser_reserved_connections` guarantees a way in.
- **Sizing is fixed in the compose file and sized for a 4 GiB engine.** A per-machine value would
  make the config differ between worktrees. The numbers come from the 16 GB column of
  `research_server_sizing.md` §6, with `max_connections` raised for six worktrees.
- **Non-durable settings include `fsync=off`.** Recovery from corruption is recreating the volume
  and rerunning setup in each worktree.
- **The idle-in-transaction timeout is set on the role, not server-wide**, so `pguser` admin
  sessions are never cut off.
- **`statement_timeout`, `lock_timeout`, `transaction_timeout` and `idle_session_timeout` stay
  unset.** Each would abort legitimate slow migrations or open shells (`research_session_reaping.md`
  §2).
- **Agent full-suite runs are tracked, not wall-clock killed.** They run as an explicit background
  command and the agent waits for its notification. Claude Code ends such a command with a
  foreground subagent's final response. `pytest-timeout` caps any single hung test. No outer
  `timeout` wrapper is used, because the suite can legitimately take more than 10 minutes.
- **FLS database tools are Python scripts in repo-only `dev_db/`**, run with `uv run python`, so
  their rules are unit-testable. The MCP reaper is a shell script in the `ds` plugin, because every
  `ds` project leaks the same way.
- **Stale-database detection trusts only worktree stamps from this repository.** Name prefixes
  cannot tell FLS apart from downstream projects: `db_fcweb_*` follows the same convention.
- **Existing worktrees recover on demand.** After the switch each one reruns
  `.claude/fls-dev/scripts/install_dev.sh`. There is no bulk helper.

## Requirements

### Server: `dev_db/docker-compose.yaml`

- Top-level `name: fls_dev_db`.
- `postgres` service, `image: postgres:17`:
  - `volumes: - pgdata:/var/lib/postgresql/data`, with a top-level `volumes: {pgdata: {}}`. The
    `${DB_DATA_PATH:-~/.lms_postges_dev_data}` bind mount and the `./docker-entrypoint-initdb.d`
    mount are removed.
  - `environment` unchanged: `POSTGRES_USER=pguser`, `POSTGRES_PASSWORD=password`,
    `POSTGRES_DB=db`.
  - `ports: "6543:5432"`, unchanged.
  - `restart: unless-stopped`, `stop_grace_period: 30s`.
  - `mem_limit: 3g`, `shm_size: 256m`. Use `mem_limit`, not `deploy.resources`, which plain
    `docker compose up` ignores.
  - `healthcheck`: `["CMD-SHELL", "pg_isready -U pguser -d postgres"]`, `interval: 5s`,
    `timeout: 5s`, `retries: 5`, `start_period: 15s`.
  - `command:` in list form (avoids YAML quoting of `log_line_prefix`), `postgres` followed by
    `-c` for each of:

    ```
    fsync=off
    synchronous_commit=off
    full_page_writes=off
    max_connections=120
    superuser_reserved_connections=3
    shared_buffers=768MB
    work_mem=16MB
    maintenance_work_mem=128MB
    logging_collector=on
    log_directory=log
    log_filename=postgresql-%a.log
    log_truncate_on_rotation=on
    log_rotation_age=1d
    log_rotation_size=0
    log_line_prefix=%m [%p] %q%u@%d app=%a client=%h
    log_connections=on
    log_disconnections=on
    log_lock_waits=on
    log_temp_files=0
    ```

    `log_directory=log` is relative to `PGDATA`, so logs live on the volume and survive container
    recreation. The log files form a seven-day ring.
- `mailpit` service keeps its config. It is renamed along with the project.

### Role and per-branch databases: `claude_plugins/fls-dev/scripts/`

`dev_db_init.sh` (still connecting as `pguser`, the admin path):

- Ensures role `fls_dev` exists, idempotently, in a `DO $$ … IF NOT EXISTS (SELECT FROM pg_roles
  WHERE rolname = 'fls_dev') … $$` block: `LOGIN PASSWORD 'password' CREATEDB`. It also runs
  `ALTER ROLE fls_dev SET idle_in_transaction_session_timeout = '15min'` every time.
- Creates `db_<branch>` and `test_db_<branch>` with `OWNER fls_dev`, and runs `ALTER DATABASE …
  OWNER TO fls_dev` when they already exist. The `GRANT … TO pguser` lines go.
- Writes the worktree stamp on `db_<branch>`:
  `COMMENT ON DATABASE db_<branch> IS '{"repo": "<abs git common dir>", "worktree": "<abs worktree
  path>"}'`, from `git rev-parse --path-format=absolute --git-common-dir` and
  `git rev-parse --show-toplevel`.
- The `db` fallback when there is no branch is kept, and is not stamped.

`dev_db_delete.sh` also terminates connections to, and drops, every `test_db_<branch>_gw%`
database. Today it leaves those behind.

The branch-name sanitisation in both scripts still mirrors `branch_to_db_name` in
`freedom_ls/base/git_utils.py`. That rule does not change.

### Django settings: `config/settings_dev.py`

In `DATABASES["default"]`:

- `"USER": "fls_dev"`. `"PASSWORD"` stays `"password"` with its `# pragma: allowlist secret`.
- `"TEST": {"NAME": f"test_{_db_name}", "TEMPLATE": "template0"}`. Django ignores the current
  lower-case `"name"` key. Its default happens to produce the same name.
- `"OPTIONS": {"application_name": _application_name}`. `_application_name` is
  `f"{kind}:{worker}:{_db_name}"`, truncated to 63 characters. `kind` is `pytest` when `TESTING`,
  otherwise the `manage.py` subcommand (`runserver`, `migrate`, `shell`…), or `django`. `worker` is
  `PYTEST_XDIST_WORKER` or `-`. The branch part goes last so truncation only cuts that.

### Test runs

- Root `conftest.py`: add `pytest_xdist_auto_num_workers(config: pytest.Config) -> int`, returning
  `min(4, os.cpu_count() or 1)`. It only affects `-n auto`/`-n logical`. An explicit `-n 8` still
  works.
- `pyproject.toml`: add `pytest-timeout` to the dev group and `timeout = 300` to
  `[tool.pytest.ini_options]`.
- Agent guidance for full-suite runs: run the command with the Bash tool's `run_in_background:
  true` and wait for the completion notification. Never poll with `ps`/`pgrep` loops. Never start
  a second full run in the same worktree while one is in flight. This goes in:
  - `claude_plugins/django-stack/skills/testing/SKILL.md`, next to the `-n auto` line at :45.
  - `claude_plugins/django-stack/commands/rebase_main.md` Step 9.
  - `claude_plugins/fls-dev/agents/qa-bugfixer.md` Step 5.
  - `claude_plugins/sdd/commands/implement_plan.md` (:37 and the `sdd:sdd-mechanic` brief at :56).
  - `claude_plugins/sdd/commands/address_pr_review.md` (:54).

  This guidance is a fix every `ds` and `sdd` project benefits from, so it is not config-gated.

### Playwright MCP: `claude_plugins/django-stack/`

- `.mcp.json`: replace `@playwright/mcp@latest` with an exact version current at implementation
  time, and add `"--idle-timeout", "600000"`. The other args are unchanged.
- New `scripts/reap_playwright_mcp.sh`, in the shape of `kill_runserver.sh`, mirrored into
  `templates/wrapper_scripts/` and `.claude/ds/scripts/` like the existing scripts:
  - Candidates are processes whose command line matches `@playwright/mcp` or `playwright-mcp`,
    whose parent is PID 1, and which are more than an hour old, plus all their descendants (the
    browsers).
  - With no argument it lists `pid, age, rss, command`. `--kill` sends SIGTERM, waits 5 s, then
    sends SIGKILL to survivors.
  - It works on Linux and macOS. Age comes from `ps -o etime`, because `etimes` is Linux-only.
- `skills/use-playwright/SKILL.md` gains a short note that the server's processes can outlive the
  session, and where the reaper is. `README.md`'s Scripts list gains the script.

### Developer tools: `dev_db/`

All tools address the server through `docker compose -f <dev_db>/docker-compose.yaml`, never by a
container name, and connect as `pguser`.

- **`stale_dbs.py`**. It lists the per-branch databases that belong to this repository and whose
  worktree is gone:
  - A `db_<branch>` database is stale when its worktree stamp's `repo` equals this checkout's git
    common dir, and either the stamp's `worktree` is not in `git worktree list --porcelain`, or
    that worktree's current branch maps to a different name through `branch_to_db_name`.
  - `test_db_<branch>` and `test_db_<branch>_gwN` are stale when their `db_<branch>` is.
  - Databases with no stamp, or another repository's stamp, are never candidates. It prints a
    count of unstamped `db_*`/`test_db_*` databases so a leftover is visible.
  - With no argument it lists names and sizes. `--drop` terminates their connections, drops them,
    and prints what it dropped.
  - The classification is a pure function, taking the stamps, the database names and the worktree
    list, separate from the I/O.
- **`diagnose.py`**. One command that runs ordered checks and prints one line per finding, each
  with a verdict and a next step. It exits non-zero when any check fails:
  1. Engine reachable (`docker info`). If not, and Docker Desktop logs exist, it searches them
     for `injecting event blocked for` / `Service fs failed` over the last 3 days. It reports the
     last match as a Docker Desktop file-service failure. Log dirs:
     `~/.docker/desktop/log/{host,vm}/` on Linux, `~/Library/Containers/com.docker.docker/Data/log/`
     on macOS.
  2. Engine: whether it is Docker Desktop, with the Linux-only recommendation to use Docker Engine.
     It warns when `docker info` `MemTotal` is under 4 GiB.
  3. Leftover containers from the old `dev_db` compose project, which block the new one's ports.
  4. The `postgres` container: running, health, `OOMKilled`, `ExitCode`, `RestartCount`,
     `StartedAt`, created time, and the `com.docker.compose.project.working_dir` label, which names
     the worktree that created it. Reports "recreated at T from W" when the container was created
     within the last 24 h.
  5. Postgres logs from the volume (`docker compose exec` when running, else
     `docker run --rm -v fls_dev_db_pgdata:/data postgres:17`). It searches the last 3 days for
     `too many clients`, `remaining connection slots`, `could not resize shared memory`,
     `terminated by signal`, `No space left on device`, `PANIC`, `being accessed by other users`
     and `idle-in-transaction timeout`, and prints the count and last occurrence of each.
  6. When Postgres answers: connections grouped by `application_name` and `state` against
     `max_connections`, sessions idle in transaction for more than 5 minutes, disk use of the data
     volume and `/dev/shm` inside the container, and the stale-database count from
     `stale_dbs.py`'s classifier.
  7. The count of orphaned Playwright MCP processes (the reaper's rule), and `pytest` processes
     whose parent is PID 1.
- **`bin_sh.sh`** runs `psql -U pguser -d postgres` inside the service. It currently execs into a
  container name that does not exist, with no command.
- **`cleanup_devdb.sh`** becomes a full reset: `docker compose down -v`, then `up -d`. It first
  prints that this destroys every worktree's database and asks for confirmation. It no longer
  touches `sudo` or `./gitignore`.

## Testing

Unit tests in `tests/` (the repo-level test directory, which already tests shell and dev tooling):

- `pytest_xdist_auto_num_workers` returns 4 on an 8-core or 16-core count and the core count when it
  is below 4.
- The settings build: `TEST["TEMPLATE"] == "template0"`, `TEST["NAME"]` is `test_<db>`, `USER` is
  `fls_dev`, and `application_name` has the form `pytest:<worker>:<db>` and is at most 63
  characters for a 50-character branch.
- The stale-database classifier, with cases:
  - A stamped database whose worktree is gone is stale.
  - A stamped database whose worktree now has another branch checked out is stale.
  - A stamped database whose worktree is live is kept.
  - A database stamped by another repository is kept.
  - An unstamped `db_fcweb_x` is kept.
  - `test_db_x` and `test_db_x_gw3` follow `db_x`.
  - `db`, `test_db`, `postgres` and templates are kept.
- The diagnose log matcher classifies a sample line for each signature.

Manual checks, recorded in the QA plan:

- `docker compose up -d` from two worktrees in turn leaves the container's ID and `StartedAt`
  unchanged.
- The old compose file's `up` fails on the port and leaves the new container running.
- `docker kill` of the container brings it back healthy.
- An idle-in-transaction `fls_dev` session is ended after 15 minutes while a `pguser` one is not.
- A full `uv run pytest -n auto` runs 4 workers and creates `test_db_<branch>_gw0..3` from
  `template0`.
- Logs survive `docker compose down` followed by `up`.
- `reap_playwright_mcp.sh` lists a manually orphaned MCP server and kills it and its browser.

## Documentation and downstream

- `dev_db/README.md`, rewritten:
  - Prerequisites: Docker Engine on Linux, Docker Desktop or OrbStack elsewhere. On Colima, raise
    the VM to at least 4 GiB. On Desktop, turn on "start at login", because the container restarts
    only while the engine is up.
  - `docker compose up -d`.
  - **Switching from the bind-mounted server**, in this order:
    1. `docker compose -p dev_db down`.
    2. `up -d` from an updated checkout.
    3. Rerun `.claude/fls-dev/scripts/install_dev.sh` in each worktree after it is rebased.

    Nothing carries over, other projects' databases included. `~/.lms_postges_dev_data` can then be
    deleted, and needs `sudo` because the files are owned by uid 999.
  - The non-durable settings and the corruption recovery path (`cleanup_devdb.sh`, then setup in
    each worktree).
  - `diagnose.py`, `stale_dbs.py`, `bin_sh.sh`.
  - `DB_DATA_PATH` no longer applies to dev, so the `ds` `db_clear.sh` skips.
- `claude_plugins/fls-dev/skills/git-worktree-setup/SKILL.md` "Per-branch databases": owner
  `fls_dev`, the worktree stamp, `stale_dbs.py`.
- `CLAUDE.md` Commands: add `uv run python dev_db/diagnose.py` and `uv run python dev_db/stale_dbs.py`.
- `claude_plugins/django-stack/README.md` Scripts list and the `ds` changelog/README note for the
  `.mcp.json` change.
- Upgrade notes for concrete projects that consume `fls-dev` through the submodule:
  - `dev_db_init.sh` now creates `fls_dev` and stamps databases.
  - Their settings keep working as `pguser`. Switching to `fls_dev` is what gives them the
    connection-slot and timeout protections.
  - Their old submodule `dev_db/` can no longer start once the new server holds the ports.

## Open questions

- The exact `@playwright/mcp` version to pin, and confirmation that `--idle-timeout` exists at
  that version. Default: the latest release at implementation time.
- The sizing numbers are a starting point. Once `diagnose.py` has real `pg_stat_activity` data,
  revisit `max_connections` and the worker cap of 4.
- Default taken: `stale_dbs.py --drop` does not prompt, since listing is the default. Overrule if
  it should confirm interactively.

## Success criteria

- `docker volume ls` shows `fls_dev_db_pgdata`, and `docker inspect` of the postgres container
  shows no bind mounts.
- Running `docker compose up -d` in two different worktrees does not change the container ID.
- `docker kill` of the postgres container is followed by a healthy container within a minute,
  with no command run.
- `SHOW max_connections` is 120, and `SELECT rolsuper FROM pg_roles WHERE rolname='fls_dev'` is
  false.
- Every connection from runserver and pytest shows `usename = fls_dev` and a non-empty
  `application_name` in `pg_stat_activity`.
- `uv run pytest -n auto` starts 4 workers on a machine with more than 4 cores.
- After `docker compose down` and `up -d`, the previous session's lines are still in
  `PGDATA/log/`.
- `stale_dbs.py` lists a stamped database whose worktree was removed, and never lists `db_fcweb_*`
  or another project's databases.
- `diagnose.py` names a Docker Desktop file-service failure when that signature is in the
  Desktop logs.
- `.mcp.json` pins an exact `@playwright/mcp` version, and `reap_playwright_mcp.sh` exists in all
  three `ds` script locations.
- The unit tests listed under Testing pass.
