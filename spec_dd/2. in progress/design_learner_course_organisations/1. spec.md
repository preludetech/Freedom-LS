# Spec: design learner course organisations

Source: `idea.md`. Research: the `research_*.md` files beside it. Design: `design.md` (a Claude
Design design, a visual reference only, read as that file says).

## 1. Purpose

A course that belongs to exactly one organisation names that organisation on the learner
dashboard today, as a text-first byline with the logo in a small rectangle. The all-courses rows,
the applications panel and the course detail page name no organisation at all. This work gives
every learner-facing surface one organisation treatment: a circular mark beside the name, placed
where the design puts it, with a square profile logo and a short bio an organisation can supply
through the admin.

## 2. Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| organisation mark | coined | The circle that stands for an organisation: its `profile_logo`, else its `logo`, else an initials monogram. The player outline's `course_organisation_chip.html` already calls its logo box a "mark"; this spec names the circular one. |
| named organisation | narrowed | `Course.single_organisation()` (§5.2): the one organisation a course belongs to, when it belongs to exactly one and that one is not the site's default organisation. |

## 3. Scope

In:

- `Organisation.profile_logo` and `Organisation.bio`, edited in the admin.
- The organisation mark and byline components, replacing the rectangular byline.
- Dashboard course cards: the padded header block and the byline under it.
- Long-format rows: the all-courses page, the dashboard's narrow-viewport rows, and the
  dashboard applications panel, in the G2 layout.
- The course detail page: the byline in the hero and the organisation card in the sidebar.

Out:

- Which organisation a card names. An in-progress card keeps naming the organisation the learner
  studies through (`CourseProgress.learner.organisation`); every other card names the course's
  named organisation. Only the rendering changes.
- The course player's `course_organisation_chip.html`, reports, `logo_on_dark`, and the markdown
  embed card's content (it inherits the shell changes and gains no byline).
- Any link to an organisation page, a course count, or a schema.org `provider` entry.
- An educator-interface editor for organisations. The admin is the only editor.
- Server-side cropping or resizing of the profile logo.

## 4. Decisions

- **The named organisation excludes the site's default organisation at the model.** The default
  organisation stands for the site, which the chrome already brands, so
  `Course.single_organisation()` returns `None` for it and no template re-checks `is_default` for a
  course-owned organisation. The byline component keeps its own `is_default` guard for the
  studied-through organisation an in-progress card passes.
- **One shell, one look.** `course-card-shell` and `course-row-shell` change once; every card and
  row built on them, the markdown embed card included, takes the new look. No prop switches it off.
- **The profile logo is drawn with `object-cover`; the fallback `logo` with `object-contain`.** A
  profile logo is uploaded for the circle and may be cropped to it; a `logo` is usually a wordmark
  and must not be. The validator accepts a non-square profile logo and the circle centre-crops it.
- **The bio is plain text.** Rendered escaped with line breaks kept, never as markdown.
- **The sidebar's sticky wrapper holds both the sign-up panel and the organisation card.** A card
  placed after a sticky sibling is slid over by it; moving `lg:sticky lg:top-6` to a wrapper
  around both keeps them together.
- **"Details" stays the visible label everywhere** and gets an `sr-only` suffix naming the course,
  so repeated identical links still have distinct accessible names.

## 5. Requirements

### 5.1 Organisation model and admin (`freedom_ls/organisations/`)

`models.py`:

- `profile_logo = models.ImageField(_("profile logo"), upload_to=organisation_profile_logo_upload_to,
  storage=get_organisation_logo_storage, blank=True, validators=[validate_organisation_logo_extension,
  validate_organisation_logo], help_text=…)`. The help text says: a square image, at least 128 by
  128 pixels, shown in a circle beside the organisation's name on course cards and the course
  page; without one the light-background logo is shown instead.
- `organisation_profile_logo_upload_to(instance, filename)` returns
  `_logo_upload_path(instance, filename, "-profile")`.
- `LOGO_FIELD_NAMES = ("logo", "logo_on_dark", "profile_logo")`, so `save()` sweeps the superseded
  profile logo object from the public bucket exactly as it does the other two.
- `bio = models.CharField(_("bio"), max_length=500, blank=True, help_text=…)`: a short description
  shown on the course page, with the limit stated.
- One new migration, `0002_*`, from `makemigrations`.

`forms.py` (`OrganisationAdminForm`): `Meta.fields = ["name", "logo", "logo_on_dark",
"profile_logo", "bio"]`; the `invalid_image` loop iterates `LOGO_FIELD_NAMES` rather than its
own tuple; `bio` uses a `Textarea` widget.

`admin.py` (`OrganisationAdmin.fields`): `["name", "slug", "logo", "logo_on_dark",
"profile_logo", "bio", SUMMARIES_FIELD]`.

### 5.2 The named organisation (`freedom_ls/content_engine/models/courses.py`)

`Course.single_organisation(self) -> Organisation | None`: the course's one organisation when
`self.organisations.all()` holds exactly one row and it is not `is_default`; otherwise `None`. It
reads the prefetched `organisations` cache and issues no query when that is present. Every caller
below prefetches `organisations`.

`freedom_ls/learner_interface/views.py::_stamp_single_organisation` becomes
`stamp_card_organisation(course, course.single_organisation())`; the discovery and recommendation
annotators keep their prefetch.

### 5.3 Components (`freedom_ls/learner_interface/templates/cotton/`)

`organisation-mark.html` (new). Params: `organisation`, `size` (`sm`, the default, for cards and
rows; `md` for the detail hero; `lg` for the organisation card), mergeable `class`. Renders one
`rounded-full overflow-hidden shrink-0` circle on an opaque `bg-surface` fill with a `ring-1
ring-border`:

- `organisation.profile_logo` set: `<img src alt="" class="size-full object-cover">`.
- else `organisation.logo` set: `<img src alt="" class="size-full object-contain p-1">`.
- else `organisation.initials`: the monogram, `aria-hidden="true"`, in `bg-surface-2
  text-on-surface font-semibold`, as `course_organisation_chip.html` draws it.
- else `<c-icon name="unknown">`, `aria-hidden="true"`.

The mark never carries the accessible name; the name beside it does.

`organisation-byline.html` (rewritten, same `organisation` param). Still renders nothing for a
falsy value or `is_default`. Otherwise one `flex items-center gap-2 min-w-0` line: `<c-organisation-mark>`
then the name in a `truncate` span with `title="{{ organisation.name }}"`. New params: `size`,
passed through to the mark, and mergeable `class` so the hero can set its text colour; the default
text stays `text-sm text-muted`. The player chip's comment that names this component as its
card-sized sibling stays true, so it stays.

### 5.4 Dashboard cards (`freedom_ls/learner_interface/templates/`)

`cotton/course-card-shell.html`: the article gains inner padding so the accent block sits inset
from the card edge on every side with its own rounded corners, as `design_screenshots/cards__b.png`
draws it. The block keeps its height and centred icon. The body keeps its `space-y-2` rhythm; its
own padding adjusts so the text aligns with the block's edge.

`learner_interface/partials/course_card.html`: `<c-organisation-byline :organisation="course.card_organisation" />`
moves from after the title link to the top of the default slot, so it is the first thing under
the header, before the status eyebrow and the title. Nothing else on the card moves. The template's
docstring lists the new order.

### 5.5 Long-format rows

`cotton/course-row-shell.html`: the eyebrow slot becomes one `flex items-start justify-between
gap-3` line; the row leaf fills its left and right halves. The article keeps its border and
rounded corners. `learner_interface/partials/course_row_list.html` drops `divide-y divide-gray-100`
for a `gap-3` between rows, so rows are separate bordered cards with no rule between them.

`learner_interface/partials/course_row.html` renders, as in
`design_screenshots/index__ig2.png`:

- Eyebrow left: `<c-organisation-byline :organisation="course.card_organisation" />`, then, when
  `course.difficulty` is set, `course.get_difficulty_display` in the eyebrow's `text-xs text-muted
  uppercase tracking-wide` style, separated from the name by a middle dot. With no organisation the
  level stands alone; with neither, the left half is empty.
- Eyebrow right: `<c-chip size="xs">` tags, in this order where present: the status chip for
  `registered`, `in_progress`, `complete` and `coming_soon` (`course_status_eyebrow.html` stays the
  one source of those labels and icons and gains an `as_chip` param that wraps them in
  `<c-chip variant="muted" size="xs">`, keeping its `data-testid`), the `access_badge` chip for an
  anonymous visitor, then the price as a `muted` chip holding `<c-course-price variant="compact">`. `course_listing_price.html`
  is no longer included by the row, and no status appears anywhere else on the row.
- Default slot: the title link, "Next up", and the deadline line, unchanged.
- Footer: the progress bar where it is today, then `course_details_link.html` right-aligned.

`learner_interface/partials/course_details_link.html`: keeps `<c-button variant="link"
size="small" icon_right="next">`, the label `Details`, and gains
`<span class="sr-only"> for {{ course.title }}</span>` after it.

`views.py::all_courses`: the visible queryset prefetches `organisations` (add it to
`utils.py::get_all_courses()`), and each entry's course is stamped with
`stamp_card_organisation(course, course.single_organisation())`. The row's docstring no longer
says the all-courses page leaves `card_organisation` unstamped.

### 5.6 Applications panel (`freedom_ls/course_applications/`)

`templates/course_applications/partials/dashboard_applications.html`: each `li` renders a
`<c-course-row-shell>` for `app.course` (accent, icon, title) instead of the icon tile, so the
panel's rows match the all-courses rows:

- Eyebrow left: `<c-organisation-byline :organisation="app.course.single_organisation" />` and the
  level, as §5.5.
- Eyebrow right: the existing `Pending review` (`info`) or `Incomplete` (`warning`) chip.
- Default slot: the stretched title link to `status_url` as today, then the "Finish your
  application…" line for an unsubmitted application.
- Footer: a right-aligned line holding `course_details_link.html` (with `course=app.course`) and
  the existing `View my application` / `Continue application` button with its `sr-only` suffix.
  The mobile chevron stays.

The `ul` keeps its pagination, swap id, live region and partialdefs; it drops its own rounded
border and `divide-y` for the `gap-3` of §5.5.

`queries.py::get_active_applications` and the anonymous `owned_applications` queryset in
`backends.py::get_dashboard_contributions_for_request` add `prefetch_related("course__organisations")`.
No Python in `course_applications` imports `learner_interface`; the cotton components and the
details-link partial are reached through the template loader only, as the panel already reaches
`c-chip`.

### 5.7 Course detail page (`freedom_ls/learner_interface/`)

`views.py::course_detail`: the lookup becomes
`Course.objects.select_related("dashboard_category").prefetch_related("organisations")`; the
context gains `organisation = course.single_organisation()`.

`templates/learner_interface/course_detail.html`:

- Hero: when `organisation` is set, the first child of the inner well is
  `<c-organisation-byline :organisation="organisation" size="md" class="text-white" />` followed by
  a rule (`border-b border-white/20`) and a margin before the category chip, as
  `design_screenshots/detail__d1.png` draws it without its link. The name is not a link.
- Sidebar: `lg:sticky lg:top-6` moves from the sign-up panel to a new wrapper `div` with
  `space-y-6` around the panel and, when `organisation` is set, a `.surface` organisation card
  after it (`data-testid="course-organisation-card"`): `<c-organisation-mark size="lg">` beside the
  name in `font-semibold`, then, when `organisation.bio` is non-empty, the bio in `text-sm
  text-muted` rendered with `linebreaksbr`. No eyebrow label, no course count, no link, as
  `design_screenshots/detail__d6.png` without those. The aside keeps `order-first`, so on a phone
  the card follows the sign-up panel above the About section.

The JSON-LD comment and payload are unchanged.

### 5.8 Styles

`tailwind.components.css` changes only if a class the shells need does not exist as a utility.
Run `npm run tailwind_build` after the template changes.

### 5.9 Demo and QA data

- `freedom_ls/dev_tools/demo_organisations.py`: `DEMO_ORGANISATIONS` carries a bio per

- `freedom_ls/qa_helpers/management/commands/qa_create_organisations.py`: two new cases, one with a

## 6. Testing

- `Organisation`: the profile logo upload path is `organisations/<pk>-profile<ext>`; replacing a
  profile logo deletes the superseded object (extend the existing sweep tests over
  `LOGO_FIELD_NAMES`); `bio` over 500 characters is rejected by the admin form; the admin form
  names PNG, JPEG or WebP for an unreadable profile logo.
- `Course.single_organisation()`: `None` for zero organisations, for several, and for the default
  organisation alone; the organisation for exactly one non-default; no query with the prefetch
  present (`django_assert_num_queries(0)`).
- `organisation-mark`: profile logo wins over logo and is `object-cover`; logo alone is
  `object-contain`; neither gives the initials, `aria-hidden`; a name with no letters gives the
  `unknown` icon; the `img` has `alt=""`.
- `organisation-byline`: name beside the mark with `title`; nothing for the default organisation
  or an empty value (replace the name-only test, which no longer applies).
- Dashboard: the byline precedes the status eyebrow and the title in the card; the in-progress
  card still names `CourseProgress.learner.organisation`; `IN_PROGRESS_MAX_QUERIES` in
  `test_dashboard.py` holds.
- All-courses: a row for a one-organisation course shows the byline and level; a row for a
  multi-organisation or default-organisation course shows neither byline nor level when
  `difficulty` is blank; the status, access badge and price render once each, as chips, and
  `course_listing_price.html` output is absent; `ALL_COURSES_MAX_QUERIES` in
  `test_course_listing.py` holds.
- Applications panel: a row shows the byline, the level, the status chip, the Details link to
  `course_detail` and the application button; the paging and live-region tests in
  `course_applications/tests/test_backends.py` still pass; the panel's query count does not grow
  with the number of applications on a page.
- Course detail: hero byline and sidebar card present for a one-organisation course, for an
  anonymous visitor too; absent for a multi-organisation course and for the default organisation;
  the bio paragraph absent when `bio` is empty; the hero holds no link to an organisation; the
  budget in `test_detail_page_query_count_does_not_grow_with_items` holds.
- Every `Details` link's accessible name ends with the course title.
- `test_organisation_course_flow.py` and `test_course_browse_flow.py` select the new markup
  wherever they select the byline or the row layout today.

## 8. Open questions

- Q: Should the course detail organisation card render when the organisation has no bio, leaving
  only the mark and name already shown in the hero? → A: Yes (assumed default: the idea asks for
  the card without a condition, and a bio-less card still tells a learner who offers the course.
  Overrule by editing §5.7.)
- Q: Should a non-square profile logo be rejected rather than centre-cropped? → A: Centre-cropped
  (assumed default: rejection would need a new validator and the crop is reversible by
  re-uploading. Overrule by editing §4 and §5.1.)

## 9. Success criteria

- `makemigrations --check` is clean after `organisations/0002_*`, and the full test suite passes.
- On the dashboard, every course card shows its accent block inset from the card edge and, for a
  one-organisation course, a circular mark and name under the block, above the status and title.
- On the all-courses page and in the applications panel, a one-organisation course row shows mark,
  name and level on its first line, its chips top-right, no divider between rows, and a text-only
  `Details` link bottom-right.
- The course detail page for a one-organisation course shows the mark and name above a rule at
  the top of the hero, and an organisation card with mark, name and bio under the sign-up panel,
  with no organisation link anywhere; the same page for a multi-organisation course shows neither.
- Uploading a profile logo in the admin replaces the circle's image everywhere; removing it
  returns the circle to the `logo`, and the replaced object is gone from storage.
- The dashboard, all-courses and course detail query budgets are unchanged.
- Pre-commit passes on the branch.
