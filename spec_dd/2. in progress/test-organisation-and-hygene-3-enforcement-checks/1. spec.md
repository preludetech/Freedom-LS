# Spec: enforcement checks for the two test-organisation rules

Spec 3 of the Test organisation and hygiene effort (`spec_dd/1. next/roadmap.md`). Source:
`idea.md`. Tool choice and false-positive analysis: `research_test_rule_enforcement.md`.

## Purpose

`ds:testing` defines two rules, **Mirroring** and **Dependency direction** (see "Test organisation
and hygiene" in `claude_plugins/django-stack/resources/testing.md`). Nothing checks either one. This
spec adds a check for each, run in pre-commit and CI. Each check starts from a baseline of today's
violations, so it passes on the day it lands and fails only on a new violation. Cleanup specs 4-15
delete their apps' baseline lines as they fix them.

## Terminology

| Term | Status | Meaning |
| --- | --- | --- |
| declared edge | coined | A runtime edge between two apps that no import or model relation shows, listed by hand in `test_organisation/declared_edges.toml` with its reason. |
| import baseline | coined | `test_organisation/import_baseline.txt`: today's Dependency direction violations, one `importer -> imported` per line. Shrink-only. |
| mirroring baseline | coined | `test_organisation/mirroring_baseline.txt`: today's Mirroring violations, one test file path per line. Shrink-only. |
| mirroring exemption | coined | A line in `test_organisation/mirroring_exemptions.txt`: a test file or subpackage allowed not to mirror a module, with its reason. Permanent, not debt. |

## Scope

In:

- `generate_app_map.py` learns the hidden runtime edges and generates import-linter contracts from
  the same walk that writes `docs/app_structure.md`.
- A new Mirroring check script.
- Both baselines, the exemptions file and the declared-edges file, seeded from the live tree.
- Pre-commit hooks, CI steps, dev dependency, docs.

Out:

- Fixing any existing violation. That is specs 4-15.
- Gating "every module has a test file".
- `apps.get_model("label.Model")` and other runtime string lookups. Spec 1 does not count them as
  dependencies, and the check does not see them.
- Wiring the checks into `implement_plan`'s review step, unless spec 2
  (`test-organisation-and-hygene-2-sdd-review-and-boy-scout`) is already in `spec_dd/3. done/` when
  this is implemented. In that case this spec does it.

## Decisions

- **Mirroring is strict.** `<app>/tests/<sub>/test_<name>.py` must have `<app>/<sub>/<name>.py` or
  the package `<app>/<sub>/<name>/`. Behaviour-named files (`test_dashboard_ordering.py`) and flat
  templatetag and management-command tests are violations. 229 of 378 app test files fail today, and
  all of them go in the mirroring baseline. New test files must conform. The cleanup specs work
  through the backlog.
- **Runtime deps are direct deps**, the "Runtime deps" column of `docs/app_structure.md`. An app's
  tests may not import an app it reaches only transitively.
- **Contracts set `allow_indirect_imports = true`.** Otherwise a test importing its own runtime code
  inherits every app that code imports, and nearly every contract fails.
- **The generated contracts file is separate from the import baseline.** The generator reads the
  baseline and merges it into the contracts it writes. It never writes the baseline. A cleanup spec
  edits only a hand-kept file, and the generated file keeps its "do not hand-edit" banner. The other
  option, rewriting parts of a TOML file in place, would leave generated and hand-kept lines mixed
  in one file.
- **Import baseline lines are per importer module**, e.g.
  `freedom_ls.accounts.tests.test_deferred_login -> freedom_ls.learner_interface.views`. An app-pair
  wildcard would let a new file in the same app add the same violation unnoticed.
- **Stale baseline lines fail the check.** import-linter's `unmatched_ignore_imports_alerting` stays
  at its default, `error`. The Mirroring script does the same for its own files. When a cleanup
  fixes a violation, it has to delete the line.
- **No command writes either baseline.** Seeding is a one-off during this spec. After that, lines
  are only deleted by hand. The Mirroring script's `--print-violations` prints violations in
  baseline format to stdout and writes nothing.
- **Hidden edges:** the generator detects model relations in AST. Settings-registered dotted paths
  go in the declared-edges file.
- **Cross-cutting subpackages are exempted by name** in `mirroring_exemptions.txt`, not by a
  reserved directory name and not by "any subdirectory that mirrors nothing".
- **The user-model app's `factories` module is allowed in every app's tests.** import-linter works
  on modules, not names, so the allowance covers `freedom_ls.accounts.factories` as a whole,
  `SiteFactory` included, until spec 4 moves `SiteFactory` out.
- **Config lives in `[tool.test_organisation]` in `pyproject.toml`.** Both scripts stay in the
  generic `django-stack` plugin and stay stdlib-only (`tomllib`). A project without the table gets
  today's `generate_app_map.py` behaviour and no checks.
- **The generator's `--check` covers `docs/app_structure.md` and the contracts file.** Both come
  from one walk. A stale doc was already a problem: it has no `comms` app today.

## Requirements

### Configuration: `pyproject.toml`

```toml
[tool.test_organisation]
user_model_app = "freedom_ls.accounts"
declared_edges = "test_organisation/declared_edges.toml"
import_contracts = "test_organisation/import_contracts.toml"
import_baseline = "test_organisation/import_baseline.txt"
mirroring_baseline = "test_organisation/mirroring_baseline.txt"
mirroring_exemptions = "test_organisation/mirroring_exemptions.txt"
```

- Add `import-linter>=2.15` to **both** dev lists, `[project.optional-dependencies].dev` and
  `[dependency-groups].dev`. They duplicate each other. It never goes in `[project].dependencies`.
- `test_organisation/` sits at the repo root. The `include = ["freedom_ls*"]` allow-list already
  keeps it out of the package build.
- `.gitignore` gains `.import_linter_cache/`.

### Hidden runtime edges: `claude_plugins/django-stack/scripts/generate_app_map.py`

`compute_edges` adds these to `edges.runtime`, from non-test modules only (`is_test_path` false):

1. A `ForeignKey`, `OneToOneField` or `ManyToManyField` call whose first argument is a string
   `"<label>.<Model>"`. The label resolves to an app via the `label = "..."` on each app's
   `AppConfig` in `apps.py`, parsed with `ast`, and falls back to the last segment of the module
   path. A label with no dot means the same app and is ignored.
2. `settings.AUTH_USER_MODEL` as that first argument, and any `get_user_model()` call. Both are edges
   to `user_model_app`. (`form_engine/models.py:236` assigns `User = get_user_model()` and relates
   to `User`.)
3. Every entry in `declared_edges.toml`:

   ```toml
   [[edge]]
   from = "base"
   to = "learner_management"
   reason = "TEMPLATES registers freedom_ls.learner_management.context_processors.can_access_educator_interface; base's header reads its context variable."
   ```

   `from` and `to` are app short names as the doc uses them. An unknown name, a missing `reason`, or
   an edge that detection or an import already provides is an error. That keeps the file to edges
   nothing else can see.

The edges render as ordinary solid runtime arrows. The doc's header and `LEGEND` say that solid
arrows include model relations by string label or user model, and declared edges.

Expected changes on first regeneration: `comms` appears, and `course_recommendations →
content_engine`, `form_engine → accounts` and `base → learner_management` become runtime edges.

### Contract generation: same script

When `[tool.test_organisation]` is present, `main()` also writes `import_contracts` (TOML, read by
`lint-imports --config`), with a generated-file banner matching `docs/app_structure.md`'s. It
reuses `find_apps`, `compute_edges` and their longest-path-first matching.

```toml
[tool.importlinter]
root_packages = ["freedom_ls.accounts", "freedom_ls.base", "..."]  # every app's module path

[[tool.importlinter.contracts]]
id = "accounts"
name = "accounts tests import only accounts' runtime deps"
type = "forbidden"
allow_indirect_imports = true
source_modules = ["freedom_ls.accounts.tests", "freedom_ls.accounts.factories"]
forbidden_modules = ["freedom_ls.comms", "..."]
ignore_imports = [
    # allowance: the user-model app's factories
    "freedom_ls.x.tests.test_y -> freedom_ls.accounts.factories",
    # baseline
    "freedom_ls.accounts.tests.test_deferred_login -> freedom_ls.learner_interface.views",
]
```

- `root_packages` lists every app rather than naming `freedom_ls`, which has no `__init__.py`.
- `source_modules`: the app's `tests` package, plus every other module in the app that
  `is_test_path` classifies as test code (`factories.py`, `conftest.py`, root-level `test_*.py` such
  as `contrib/conformance`'s). Contracts and doc use the same classification.
- `forbidden_modules`: every app's module path, minus the app's own path and its runtime deps.
- An app with no test modules, or with nothing to forbid, gets no contract.
- `ignore_imports` has two blocks:
  - The allowance block is generated. It has one line for each module in the app's `source_modules`
    that imports `<user_model_app>.factories` (or a submodule of it), and only when the app has no
    runtime dep on the user-model app. Lines are emitted only where the import exists, so the
    unmatched-ignore error never fires on them.
  - The baseline block holds every import baseline line whose importer falls in this app's
    `source_modules`.
- The generator fails, naming the line, when a baseline line:
  - matches no app's `source_modules`,
  - has an imported module that isn't in that app's `forbidden_modules` (the edge became allowed, so
    the line is stale), or
  - is malformed.
- `--check` writes nothing. It exits 1 and names the files when `docs/app_structure.md` or
  `import_contracts` would change, and prints `run /ds:app_map`.
- The stderr diff of added and removed edges stays as it is.

### Import baseline: `test_organisation/import_baseline.txt`

One `importer -> imported` per line, full dotted module paths. Under a `# <app>` header per app,
sorted, apps sorted. `#` comments and blank lines allowed. It is seeded once from the violations
`lint-imports` reports against the first generated contracts, taken from the live tree. The
audit's numbers are not transcribed. The file's header says: hand-edited, lines are only ever
deleted, and a stale line fails the check.

### Mirroring check: `claude_plugins/django-stack/scripts/check_test_mirroring.py`

Stdlib-only, typed. It reuses `find_apps` from `generate_app_map.py` and reads
`[tool.test_organisation]`.

- **Scope.** Inside each app, the files pytest collects: `test_*.py`, `*_tests.py`, `tests.py`.
  Root `tests/`, `freedom_ls/tests/`, `freedom_ls/conftest.py` and `claude_plugins/` are out of
  scope. Helper modules (`conftest.py`, `factories.py`, `_*.py`, `stub_*.py`, `root_urls.py`) are
  never test files, so they are exempt by construction.
- **Structural exemption.** Anything under `<app>/tests/playwright/`.
- **Pass.** `<app>/tests/<sub...>/test_<name>.py` passes when `<app>/<sub...>/<name>.py` exists or
  `<app>/<sub...>/<name>/__init__.py` exists.
- **Fail.** Any other collected file: a name with no module at the mirrored path, a `*_tests.py` or
  `tests.py`, or a test file outside the app's `tests/` package.
- **Baseline and exemptions.** A violation passes if its path is in the mirroring baseline, or is
  covered by a mirroring exemption. An exemption is a file path, or a directory path ending `/`
  that covers everything under it.
- **Stale entries fail.** A baseline line whose file is gone or now conforms fails. So does an
  exemption that covers no violating file, and a path in both files.
- **Message.** Each failure names the file, the module path it expected, and the three ways out:
  rename or move the file, add a reasoned exemption, or delete the stale line. It points at
  "Mirroring" in `ds:testing`'s testing resource.
- **Exit code.** 0 when clean, 1 otherwise.
- **`--print-violations`** prints every current violation not covered by an exemption, in baseline
  format, and exits 0.

`mirroring_exemptions.txt`: one path per line, each followed by `  # <reason>`. A line without a
reason is an error. It is seeded with the `contrib/conformance` root-level `test_*.py` files, the
named exception in `fls-dev:testing`. Cross-cutting files that aren't grouped yet
(`content_engine`'s `test_demo_content_*.py` and `test_katex_vendor_assets.py`,
`form_engine/tests/test_import_independence.py`) go in the baseline, not here. Their cleanup specs
group them into a subpackage and add the exemption.

`mirroring_baseline.txt`: repo-relative paths, the same header, grouping and sorting as the import
baseline, seeded from `--print-violations`. The count is about 229, from 28 apps.
`learner_interface/tests/playwright/form_ui_tests.py` is under `playwright/`, so it is exempt.

### Pre-commit: `.pre-commit-config.yaml`

Three `repo: local` hooks in the existing `mypy` block's shape (`language: system`,
`pass_filenames: false`, `require_serial: true`), with no `types`/`files` filter so they run on
every commit:

| id | entry |
| --- | --- |
| `app-map-fresh` | `uv run python claude_plugins/django-stack/scripts/generate_app_map.py --check` |
| `lint-imports` | `uv run lint-imports --config test_organisation/import_contracts.toml` |
| `test-mirroring` | `uv run python claude_plugins/django-stack/scripts/check_test_mirroring.py` |

`app-map-fresh` runs first, so `lint-imports` never runs against stale contracts.

### CI: `.github/workflows/tests.yml`

The `lint` job gains the same three commands as `run:` steps, in that order, after
`ruff format --check`.

### `/ds:app_map`: `claude_plugins/django-stack/commands/app_map.md`

Step 1 describes the contracts output, the hidden-edge detection and `--check`. Step 3's reminder
also covers the contracts: a new runtime edge shrinks an app's forbidden list and needs the same
approval.

## Testing

The script tests live in the root `tests/` directory, following `tests/test_rebase_lost_change_check.py`,
with `tmp_path` fixture trees. They need no markers.

`generate_app_map.py`:

- A string-label FK to another app's `AppConfig.label` adds a runtime edge. A same-app label with no
  dot adds none. A string-label FK in a test module adds none.
- `settings.AUTH_USER_MODEL` and `get_user_model()` add an edge to `user_model_app`.
- A declared edge appears as a runtime edge. An unknown app name, a missing reason, or a duplicate
  of a detected edge is an error.
- The contract's `source_modules` includes `factories.py`, `conftest.py` and a root-level
  `test_*.py`. `forbidden_modules` excludes the app and its runtime deps. `allow_indirect_imports`
  is true.
- An app with nothing to forbid, or no test modules, gets no contract.
- Allowance lines appear only for importers that import the user-model app's factories, and only
  in apps without a runtime dep on it.
- Baseline lines land in the right contract. An unowned, now-allowed or malformed line is an error
  naming the line.
- `--check` exits 0 on a fresh tree, exits 1 after a change that alters an edge, and writes nothing.
- Without `[tool.test_organisation]`, output is byte-identical to today's for the same tree.

`check_test_mirroring.py`:

- Conforming flat and nested files pass (`tests/templatetags/test_x.py` ↔ `templatetags/x.py`), and
  so does a package target.
- A flat templatetag test, a behaviour-named file, `*_tests.py`, `tests.py` and a colocated
  `test_*.py` each fail.
- `tests/playwright/` and helper modules are ignored.
- File and directory exemptions pass. An exemption without a reason is an error.
- A stale baseline line, a stale exemption, and a path in both files each fail.
- `--print-violations` output round-trips: written as a baseline, the check passes.

Against the real tree (integration, in the same files): generating from the repo leaves
`docs/app_structure.md` and the contracts file unchanged, `lint-imports` passes, and the Mirroring
check passes.

End to end, proved once by hand during implementation and recorded in the plan's QA notes:

- Adding a forbidden import to a clean test file fails `lint-imports`.
- Deleting a baseline line whose violation still exists fails it.
- Fixing a violation without deleting its line fails it.
- The same three for the Mirroring check.
- A new runtime import without regeneration fails `app-map-fresh`.

## Open questions

Defaults taken, which the user can overrule:

- `--check` also gates `docs/app_structure.md`, so any new cross-app import needs `/ds:app_map`
  before it can be committed.
- The `accounts.factories` allowance covers `SiteFactory` until spec 4 moves it.
- The Mirroring script lives in `django-stack` as a generic tool, not in `fls-dev`.
- The support files live in a root `test_organisation/` directory rather than loose at the repo
  root.

## Success criteria

- `uv run pre-commit run --all-files` passes on the finished branch, and so does the CI `lint` job.
- `test_organisation/import_contracts.toml` has one contract per app that has test modules and
  something to forbid. Each has `allow_indirect_imports = true`.
- `docs/app_structure.md` lists `comms`, and shows `course_recommendations → content_engine`,
  `form_engine → accounts` and `base → learner_management` as solid edges.
- Each end-to-end case in Testing fails the named hook, and reverting it passes.
- Deleting all of one app's lines from both baselines makes the checks fail, and the failures list
  exactly that app's violations.
- `import-linter` appears in both dev lists and not in `[project].dependencies`.
- `uv run pytest tests/` passes, with the new script tests included.
