# Spec: educator course content preview

Idea: `idea.md`. Research: the `research_*.md` files beside this spec.

## Purpose

Educators cannot see what a course contains. The course page in the educator interface shows only the title, category and registrations, and the learner pages write progress the moment anyone opens them. Educators need to read the course's details and its content from the educator interface, as a learner would see them, without creating any learner records.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| content preview | coined | A read-only rendering of one `Topic` or `Form` child, or of the course details, in the shared modal on the educator course page. No existing term: "preview" in the educator interface today names the learner/cohort quick view and the CSV import step, neither of which renders course content. |
| course outline | narrowed | The ordered `Course.collection_items()` tree (parts and their children). Same word the learner page uses (`<nav aria-label="Course outline">`); here without any learner status. |

## Scope

In:

- The existing course page (`CourseInstanceView`) gains a fuller details panel and a "Course content" panel holding the course outline.
- A Preview control on every `Topic` and `Form` row of the outline, opening a content preview in `#app-modal`.
- A "Preview course details page" control opening the learner-facing course details content in the same modal.
- A wide size for the shared modal, used by content previews only.

Out:

- Previous/next navigation inside the preview. One item per open.
- Interactive forms. Nothing in a preview can be submitted or saved.
- Previewing a `CoursePart`. A part has no content of its own; its row only expands and collapses.
- A quick view for courses, and any change to the Courses list.
- History push or a full-page fallback for preview URLs. A non-HTMX request to a preview URL is a 404, as `ViewConversationAction` does.
- Fixing the open downstream bug where container components re-sanitise their slot (`spec_dd/2. in progress/downstream_bugs_oct_29/accordion-strips-nested-component-attributes/`). A preview shows content exactly as learners currently see it, bug included.

## Decisions

- **Previews are built from content, never from learner views.** `view_course_item`, `view_topic` and `form_start` create `CourseProgress`, `TopicProgress` and `FormProgress` rows on GET. Previews render `rendered_content()` and the `form_engine` question templates directly.
- **Forms render read-only with the answer key shown.** Every page and question of the form is shown (`conditions.full_path(form)`, so conditional pages appear too), inputs disabled, no submit, and each `QuestionOption` with `correct=True` is marked with text plus the `check` icon, not colour alone. Educators review content; the key is what they check.
- **`educator_interface` gains a runtime edge to `form_engine`** (user-approved). Regenerate `docs/app_structure.md` with `/ds:app_map`.
- **The learner course details content becomes a shared partial in `content_engine`.** The learner page and the preview both render it; the partial holds only viewer-independent facts, so the sign-up panel, CTAs, interest control, enrolment summary and start URL stay in the learner template. `content_engine` owns `Course` and both interfaces already depend on it.
- **The details preview omits the "Course content" section.** The educator page already shows the outline beside the control, and the learner outline is built from learner progress.
- **Educators see the outline and previews when `Course.table_of_contents_in_development` is true**, with a note that learners do not see the outline yet.
- **Preview targets resolve through the authorised course.** The item is looked up in `course.collection_items_flat()` of a course that `CourseConfig.authorise_instance` already passed; an id from any other course is a 404, identical to a missing one.
- **No new capability.** Preview actions declare `capability = None`: anyone who can open the course page can preview its content.

## Requirements

### Educator course page (`freedom_ls/educator_interface/views.py`)

1. `CourseDetailsPanel.fields` shows, each row only when it has a value: title, subtitle, category (`dashboard_category`), visibility, level (`difficulty`), duration (`display_estimated_duration`), time limit (`display_time_limit`), learning outcomes, and lesson count. Labels match the learner details page ("Level", "Duration", "Time limit", "Lessons"). Where `InstanceDetailsPanel` cannot display a value directly (array, duration), add a property or method on `Course` in `content_engine`, not in the view.
2. A new `CourseContentPanel(Panel)` titled "Course content" joins `CoursePanelStack` after `details`, with template `educator_interface/panels/course_content.html` (extends `panel_framework/panels/panel.html`, like `CohortCourseCompletionPanel`). It renders the course outline from `Course.collection_items()` with prefetched children (no per-row queries):
   - Top-level rows numbered `1.`, `2.`; children of a part numbered `1.1`, `1.2`, the same order and numbering as the learner outline.
   - Each row: number, type icon (`topic`, `form`, `folder`) with a visible or `sr-only` type label, title (wraps, never truncated), and for `Topic`/`Form` rows a Preview trigger at the row end.
   - Parts are `<button aria-expanded>` rows toggled by Alpine, open by default, with no `localStorage` persistence. An empty part says "No items in this part."
   - A course with no collection items shows `<c-panel-empty-state>`: "No content in this course yet."
   - When `table_of_contents_in_development` is true, a `<c-callout level="info">` above the outline: "Learners can't see this outline yet. The course is marked as still in development."
   - The panel header carries the "Preview course details page" trigger.
3. Triggers are `<c-modal-trigger size="small">` with visible text "Preview" and `aria_label="Preview <title>"`; the details trigger's label is "Preview course details page". No learner URL appears anywhere on the page.

### Preview actions (`freedom_ls/educator_interface/views.py`)

4. `PreviewContentAction(PanelAction)`, `action_name = "preview_content"`, row-scoped on `CourseContentPanel`, `renders_in_footer = False`, `capability = None`, shaped like `ViewConversationAction`:
   - Reads `?item=<ContentCollectionItem pk>`, resolves it within the authorised course's `collection_items_flat()`, 404 when absent or a `CoursePart`.
   - 404 on a request without `HX-Request`; `handle_submit` raises 404. GET only.
   - Renders `educator_interface/modal/content_preview.html`.
5. `PreviewCourseDetailsAction(PanelAction)`, `action_name = "preview_course_details"`, same guards, renders `educator_interface/modal/course_details_preview.html`.
6. Neither action writes a row of any model. No `TopicProgress`, `CourseProgress`, `FormProgress`, answer, registration, audit or webhook event.

### Preview fragments (`freedom_ls/educator_interface/templates/educator_interface/modal/`)

7. Both fragments start with `<c-modal-header focus_title="true">` (the item or course title), then a non-dismissible info callout: "Preview. This is how learners see it. Nothing here is saved." The type ("Topic", "Form", "Course details") shows as a `<c-chip size="xs">` in the header. The root element declares the wide modal size (requirement 11).
8. `content_preview.html`, `Topic`: `<c-markdown-container>{{ topic.rendered_content }}</c-markdown-container>`. No mark-complete, player navigation or breadcrumbs.
9. `content_preview.html`, `Form`: the form's own `rendered_content`, then each page of `full_path(form)` in order with its title, rendered through `form_engine/partials/page_children.html` with `page_children` and `question_positions` from the `SittingPath`, `existing_answers={}`, `rejected_answers={}`, `read_only=True`. Every input is disabled; `file_upload` renders no live uploader and makes no request to `form_engine` upload URLs. Correct options carry the answer-key mark (Decisions). No `<form>` element wraps the preview, so the modal's discard prompt never fires and a backdrop click closes it.
10. `course_details_preview.html` includes the shared partial (requirement 12).

### Shared modal (`freedom_ls/panel_framework/`)

11. `#app-modal` gets a wide size, opted into by the swapped fragment (e.g. a `data-modal-size="wide"` attribute on its root) and cleared when the modal closes, so every other dialog keeps `min(92vw, 32rem)`. Wide is `min(92vw, 64rem)` by `min(90dvh, 100%)` from `sm` up; below `sm` it stays the standard bottom sheet with `max-height` raised to `95dvh`. The body scrolls; header stays pinned; wide tables and code blocks scroll inside the body, never widening the dialog. The size rule is scoped to the open dialog, so it never overrides `dialog:not([open]) { display: none }`. Document the size in `claude_plugins/fls-dev/skills/panel-framework/SKILL.md` and cover it with an invariant test in `panel_framework/tests/invariants/`.

### Shared course details partial (`freedom_ls/content_engine/`)

12. Extract from `learner_interface/templates/learner_interface/course_detail.html` into `content_engine/templates/content_engine/partials/course_details.html` the hero facts (category chip, title, subtitle, organisation byline), the stats strip (lessons, level, duration, time limit, price), "About this course" and "What you'll learn". Its context comes from one function in `content_engine` (e.g. `course_details_context(course)` returning `lesson_count_label`, `includes_assessments`, `organisation`), which `learner_interface.views.course_detail` calls in place of its inline computation. The learner page renders identically before and after; the enrolment stat and everything viewer-dependent stays in the learner template.

## Testing

- **No writes:** opening each preview (topic, quiz form, survey form with a conditional page, file-upload question, course details) leaves the row counts of `TopicProgress`, `CourseProgress`, `FormProgress`, form answers, registrations and audit entries unchanged, and fires no `record_course_started`.
- **Scoping:** a collection item from another course, another organisation's non-public course, another site, a `CoursePart` pk, a missing pk and a non-HTMX GET all return 404; a user who cannot enter the organisation gets 404 on both actions; POST is 404.
- **Outline:** order and numbering match `Course.collection_items()` for a course with top-level items and parts; empty course and empty part copy; the in-development callout; query count does not grow with the number of items.
- **Form rendering:** every question type in `question.html` renders disabled; correct options are marked for `multiple_choice`, `checkboxes` and `dropdown`; conditional pages appear; no submit button and no `<form>`.
- **Details panel:** each new field appears when set and its row is absent when empty.
- **Shared partial:** the learner `course_detail` page's existing tests pass unchanged; the details preview contains the About and What you'll learn content and no sign-up panel or CTA.
- **Modal size:** an invariant that the wide size applies only when the fragment opts in and resets on close.
- **Browser (Playwright):** open a topic preview by keyboard; focus lands on the title; Escape closes; focus returns to the same Preview button; content with an accordion or flashcard mounts its Alpine behaviour after the HTMX swap; at 375px the sheet has no horizontal scroll; open, close and reopen after a Back navigation shows content, not an empty dialog.
- `interface_walk.py` and `test_section_smoke.py` pick up the new panel and actions without errors.

## Documentation and downstream

- `docs/product/educator-interface.md`: the Courses section describes the details, the course outline and the content preview (read-only, answer key shown, nothing saved); keep "Courses have no quick view"; update the summary bullet and Limits list.
- `docs/app_structure.md`: regenerate for the `educator_interface → form_engine` edge.
- `claude_plugins/fls-dev/skills/panel-framework/SKILL.md`: the wide modal size and when to use it.
- Upgrade notes: downstream projects that override `learner_interface/course_detail.html` must render the new shared partial or keep their override in step with it.

## Success criteria

- An educator on a course page sees its details and full outline, and can open a preview of every topic, every form and the course details page.
- Opening any preview creates no database row (the no-writes test passes).
- A preview URL for content outside the authorised course returns 404.
- A form preview shows every page and question disabled, with correct options marked.
- The learner course details page renders unchanged.
- Every other dialog in the educator interface still opens at 32rem.
- `docs/app_structure.md` shows the `educator_interface → form_engine` edge and `lint-imports` passes.
