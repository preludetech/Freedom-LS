# Spec: educator course content preview

Idea: `idea.md`. Research: the `research_*.md` files beside this spec.

## Purpose

Educators cannot see what a course contains. The course page in the educator interface shows only the title, category and registrations, and the learner pages write progress the moment anyone opens them. Educators need to read the course's details and its content from the educator interface, as a learner would see them, without creating any learner records.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| content preview | coined | A read-only rendering of one `Topic` or `Form` child, or of the course details, in the shared modal on the educator course page. Distinct from the learner/cohort quick view. |
| course outline | narrowed | The ordered `Course.collection_items()` tree (parts and their children), as in the learner page's `<nav aria-label="Course outline">`, here without learner status. |

## Scope

In:

- The existing course page (`CourseInstanceView`) gains a fuller details panel and a "Course content" panel holding the course outline.
- A Preview control on every `Topic` and `Form` row of the outline, opening a content preview in `#app-modal`.
- A "Preview course details page" control opening the learner-facing course details content in the same modal.
- A wide size for the shared modal, used by content previews only.

Out:

- Previous/next navigation inside the preview. One child per open.
- Interactive forms. Nothing in a preview can be submitted or saved.
- Previewing a `CoursePart`. A part has no content of its own; its row only expands and collapses.
- A quick view for courses, and any change to the Courses list.
- History push or a full-page fallback for preview URLs.
- The open container-component re-sanitising bug (`spec_dd/2. in progress/downstream_bugs_oct_29/accordion-strips-nested-component-attributes/`) and the unrouted `Topic.preview_url` behind `content-link`. Previewed content behaves as it does for learners today.

## Decisions

- **Previews are built from content, never from learner views.** `view_course_item`, `view_topic` and `form_start` create `CourseProgress`, `TopicProgress` and `FormProgress` rows on GET.
- **Forms render read-only with the answer key shown.** Educators review content, and the key is what they check.
- **`educator_interface` gains a runtime edge to `form_engine`** (user-approved).
- **The learner course details content becomes shared partials in `content_engine`.** `content_engine` owns `Course`, both interfaces already depend on it, and nothing in the shared parts may depend on `learner_interface`.
- **The details preview omits the "Course content" section.** The outline is already on the educator page beside the control, and the learner outline is built from learner progress.
- **Educators see the outline and previews when `Course.table_of_contents_in_development` is true.**
- **Preview targets resolve through the authorised course.** An id from any other course is a 404, identical to a missing one.
- **No new capability.** Anyone who can open the course page can preview its content.

## Requirements

### Educator course page (`freedom_ls/educator_interface/views.py`)

1. `CourseDetailsPanel` shows title, subtitle, category (`dashboard_category`), visibility, level (`difficulty`), duration (`display_estimated_duration`), time limit (`display_time_limit`), learning outcomes and lesson count. It overrides `get_rows` to drop rows with no value and to use the learner details page's labels ("Level", "Duration", "Time limit", "Lessons"). A value that needs computing (array, lesson count) comes from a property or method on `Course` in `content_engine`, not from the view.
2. A new `CourseContentPanel(Panel)` titled "Course content" joins `CoursePanelStack` after `details`, with template `educator_interface/panels/course_content.html` (extends `panel_framework/panels/panel.html`, like `CohortCourseCompletionPanel`). It renders the course outline from `Course.collection_items()` with no per-row queries. One set of queries per `CoursePart` is allowed.
   - Top-level rows are numbered `1.`, `2.`; a part's children `1.1`, `1.2`, matching the learner outline.
   - Each row: number, type icon (`topic`, `form`, `folder`) with a visible or `sr-only` type label, title (wraps, never truncated), and for `Topic`/`Form` rows a Preview trigger at the row end.
   - Parts are `<button aria-expanded>` rows toggled by Alpine, open by default, with no `localStorage` persistence. An empty part says "No items in this part."
   - A course with no collection items shows `<c-panel-empty-state>`: "No content in this course yet."
   - When `table_of_contents_in_development` is true, a `<c-callout level="info">` above the outline reads: "Learners can't see this outline yet. The course is marked as still in development."
   - The panel header (`panel_header_action` block of `_panel_base.html`) carries the "Preview course details page" trigger, built from `row_action_urls["preview_course_details"]`.
3. Triggers are `<c-modal-trigger size="small">` with visible text "Preview" and `aria_label="Preview <title>"`; the details trigger's label is "Preview course details page". No learner URL appears anywhere on the page.
4. `educator_interface/_shell.html` loads `content_engine`'s Alpine bundle, so flashcards, equations and the picture lightbox work in previews.

### Preview actions (`freedom_ls/educator_interface/views.py`)

5. `PreviewContentAction(PanelAction)`, `action_name = "preview_content"`, on `CourseContentPanel`, `renders_in_footer = False`, `capability = None`, shaped like `ViewConversationAction`:
   - Reads `?item=<ContentCollectionItem pk>` through `uuid_or_404`, then finds it in the authorised course's `collection_items_flat()`. 404 when absent or when its child is a `CoursePart`.
   - 404 on a request without `HX-Request`; `handle_submit` raises 404.
   - Renders `educator_interface/modal/content_preview.html`.
6. `PreviewCourseDetailsAction(PanelAction)`, `action_name = "preview_course_details"`, on `CourseContentPanel`, `renders_in_footer = False`, `capability = None`, same HTMX and submit guards, renders `educator_interface/modal/course_details_preview.html`.
7. Neither action writes a row of any model and neither fires `record_course_started` or any audit or webhook event.

### Preview fragments (`freedom_ls/educator_interface/templates/educator_interface/modal/`)

8. Both fragments start with `<c-modal-header focus_title="true">` (the child's or course's title) with a `<c-chip size="xs">` naming the type ("Topic", "Form", "Course details"), then a non-dismissible info callout: "Preview. This is how learners see it. Nothing here is saved." The root element carries `data-modal-size="wide"`.
9. `content_preview.html` for a `Topic`: `<c-markdown-container>{{ topic.rendered_content }}</c-markdown-container>`. No mark-complete, player navigation or breadcrumbs.
10. `content_preview.html` for a `Form`: the form's own `rendered_content`, then each page of `conditions.full_path(form)` in order with its title, rendered through `form_engine/partials/page_children.html` with `page_children` and `question_positions` from the `SittingPath`, `existing_answers={}`, `rejected_answers={}`, `read_only=True` and `show_answer_key=True`.
    - A page with a `condition_option` is headed "Shown only if <question> is answered <option>".
    - No `<form>` element wraps the preview, so the modal's discard prompt never fires and a backdrop click closes it.
11. `course_details_preview.html` renders the modal-safe variant of the hero partial and the body partial (requirement 14).

### Form templates (`freedom_ls/form_engine/templates/form_engine/inputs/`)

12. `multiple_choice.html`, `checkboxes.html` and `dropdown.html` read a new `show_answer_key` context flag. When set, each option with `QuestionOption.correct` true carries the `check` icon and the text "Correct answer", not colour alone. No learner or course application view sets the flag.
13. Under `read_only`, `file_upload.html` renders no `x-data="questionFileUpload"`, no picker, no request to `form_engine` upload URLs and no "No file attached." line; it shows a neutral "File upload question" note instead.

### Shared course details partials (`freedom_ls/content_engine/`)

14. Extract from `learner_interface/templates/learner_interface/course_detail.html` two partials under `content_engine/templates/content_engine/partials/`:
    - `course_details_hero.html`: category chip, title, subtitle, organisation byline and the stats strip (lessons, level, duration, time limit, price), with the `stat-card` partialdef moved in. A slot or include point lets the learner page add its viewer-dependent Enrolment stat. A modal-safe variant drops the full-bleed `w-screen`/negative-margin classes.
    - `course_details_body.html`: "About this course" and "What you'll learn".
    - Their context comes from one function in `content_engine`, e.g. `course_details_context(course)` returning `lesson_count_label`, `includes_assessments` and `organisation`. `learner_interface.views.course_detail` calls it in place of its inline computation.
    - Move the `organisation-byline`, `organisation-mark` and `course-price` cotton components from `learner_interface/templates/cotton/` to `content_engine/templates/cotton/`.
    - The sign-up panel, CTAs, interest control, Enrolment stat and start URL stay in the learner template, and the learner page renders as before.

### Shared modal (`freedom_ls/panel_framework/templates/panel_framework/partials/modal_host.html`)

15. `#app-modal:has([data-modal-size="wide"])` is `min(92vw, 64rem)` wide and `min(90dvh, 100%)` tall from `sm` up. Below `sm` it stays the standard bottom sheet with `max-height` raised to `95dvh`. Every other dialog keeps `min(92vw, 32rem)`. The dialog scrolls with the header sticky; wide tables and code blocks scroll inside the content, never widening the dialog. The rule applies to the open dialog only and never overrides `dialog:not([open]) { display: none }`.

## Testing

- **No writes:** opening each preview (topic with embedded `picture`, `file-download` and `content-link` components, quiz form, survey form with a conditional page, file-upload question, course details) leaves the row counts of `TopicProgress`, `CourseProgress`, `FormProgress`, form answers, registrations and audit entries unchanged and fires no `record_course_started`. Each renders without error.
- **Scoping:** a collection item from another course, another organisation's non-public course or another site, a `CoursePart` row, a missing pk, a malformed pk and a non-HTMX GET each return 404; a user who cannot enter the organisation gets 404 on both actions; POST is 404.
- **Outline:** order and numbering match `Course.collection_items()` for a course with top-level children and parts; empty course and empty part copy; the in-development callout; with the number of parts fixed, the query count does not grow with the number of children.
- **Details panel:** each field appears with its label when set and its row is absent when empty.
- **Form rendering:** every question type in `question.html` renders disabled; correct options are marked for `multiple_choice`, `checkboxes` and `dropdown`; conditional pages appear with their condition heading; no submit button and no `<form>`; the file-upload question shows the neutral note.
- **Answer key never leaks:** learner form pages and course application pages render no answer-key mark for a quiz with correct options.
- **Shared partials:** the learner `course_detail` page's existing tests pass unchanged; the details preview contains About and What you'll learn and no sign-up panel, CTA or Enrolment stat.
- **Modal size:** an invariant in `panel_framework/tests/invariants/` that only a fragment declaring `data-modal-size="wide"` widens the dialog.
- **Browser (Playwright):** open a topic preview by keyboard; focus lands on the title; Escape closes; focus returns to the same Preview button; a flashcard in previewed content works after the HTMX swap; no console errors; at 375px the sheet has no horizontal scroll; open, close and reopen after a Back navigation shows content, not an empty dialog.
- `interface_walk.py` and `test_section_smoke.py` pick up the new panel and actions without errors.
