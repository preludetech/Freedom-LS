# Frontend QA: educator course content preview

Spec: `1. spec.md`. Plan: `2. plan.md`.

## §0 Setup

1. Pick a free port with `.claude/ds/scripts/find_available_port.sh` and start the server:

   ```
   uv run python manage.py runserver $PORT
   ```

   Base URL: `http://127.0.0.1:$PORT`. Confirm the `#debug-branch-badge` element reads `educator-interface-course-content-preview`.

2. Log in at `http://127.0.0.1:$PORT/accounts/login/` with the `## QA Login` credentials from `.claude/sdd/config.md` (admin email `demodev@email.com`, password the same). This user is a superuser and reaches every organisation.

3. Seed data (`sdd:qa-data-helper`; factories first, per `claude_plugins/fls-dev/resources/qa_data_helper.md`). All on the site the tester browses, all PUBLISHED and public unless stated, and the preview course registered to a cohort in the `demodev` organisation so it is listed under Courses:

   - **Course "QA Preview Course"**, subtitle "Checking the content preview", category set, difficulty set, `estimated_duration` 1h30m, `time_limit_days` 90, two learning outcomes, markdown content (the About text), and this outline in order:
     1. Topic "Welcome" whose markdown holds a `picture` component (an uploaded image), a `file-download` component, a `content-link` to topic 2, a `flashcard`, a `table` wide enough to need horizontal scroll (8+ columns), and a `code-block` with a 200-character line.
     2. Topic "Reading"
     3. Part "Module one" holding Topic "Inside the part" and Form "Module quiz" (a quiz: a multiple-choice question with one correct option, a checkboxes question with two correct options, a dropdown with one correct option, a short-text question).
     4. Part "Empty module" with no children.
     5. Form "Feedback survey" (a survey): page 1 "Your feedback" with a multiple-choice question "Did you enjoy it?" (options Yes / No), a number, a date, a long-text and a file-upload question; page 2 titled "Tell us more" with `condition_option` = the "No" option and a long-text question; page 3 titled "Anything else" with no condition and one long-text question. Three pages, so the outline shows a multi-page form.
   - **Course "QA Empty Course"**: published, no collection items, also registered to the demodev cohort.
   - **Course "QA Draft Outline"**: a copy of the preview course's shape with `table_of_contents_in_development=True` (visibility must allow it; use the visibility the content rules accept with that flag), registered to the demodev cohort.
   - **Course "QA Other Org Course"**: belonging only to a second organisation "QA Other Org" with a registration there and none in demodev, holding one topic. Note one of its collection item pks.
   - **A learner** `qa-learner@example.com` / `testpass123` in a demodev cohort registered for "QA Preview Course".
   - **An educator** `qa-other-educator@example.com` / `testpass123` who administers only "QA Other Org".

   Record every pk the tests below need: the preview course pk, the pk of the collection item for "Welcome", for "Module one", for "Inside the part", and for the other organisation's topic.

4. Course page URL for the preview course: `http://127.0.0.1:$PORT/educator/organisations/demodev/courses/<course pk>`.


   Expect `true`.
