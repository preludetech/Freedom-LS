# Frontend QA: educator course content preview

Spec: `1. spec.md`. Plan: `2. plan.md`.

## §0 Setup

1. Pick a free port with `.claude/ds/scripts/find_available_port.sh` and start the server:

   ```
   uv run python manage.py runserver $PORT
   ```

   Base URL: `http://127.0.0.1:$PORT`. Confirm the `#debug-branch-badge` element reads `educator-interface-course-content-preview`.

2. Log in at `http://127.0.0.1:$PORT/accounts/login/` with the `## QA Login` credentials from `.claude/sdd/config.md` (admin email `demodev@email.com`, password the same). This user is a superuser and reaches every organisation.

3. Seed data (`sdd:qa-data-helper`; factories first, per `claude_plugins/fls-dev/resources/qa_data_helper.md`). All on the site the tester browses, all PUBLISHED and public unless stated, and the preview course registered to a cohort in the `demodev` organisation so it is listed under Courses:

   - **Course "QA Preview Course"**, subtitle "Checking the content preview", category set, difficulty set, `estimated_duration` 1h30m, `time_limit_days` 90, two learning outcomes, markdown content (the About text), and this outline in order:
     1. Topic "Welcome" whose markdown holds a `picture` component (an uploaded image), a `file-download` component, a `content-link` to topic 2, a `flashcard`, a `table` wide enough to need horizontal scroll (8+ columns), and a `code-block` with a 200-character line.
     2. Topic "Reading"
     3. Part "Module one" holding Topic "Inside the part" and Form "Module quiz" (a quiz: a multiple-choice question with one correct option, a checkboxes question with two correct options, a dropdown with one correct option, a short-text question).
     4. Part "Empty module" with no children.
     5. Form "Feedback survey" (a survey): page 1 with a multiple-choice question "Did you enjoy it?" (options Yes / No), a number, a date, a long-text and a file-upload question; page 2 titled "Tell us more" with `condition_option` = the "No" option and a long-text question.
   - **Course "QA Empty Course"**: published, no collection items, also registered to the demodev cohort.
   - **Course "QA Draft Outline"**: a copy of the preview course's shape with `table_of_contents_in_development=True` (visibility must allow it; use the visibility the content rules accept with that flag), registered to the demodev cohort.
   - **Course "QA Other Org Course"**: belonging only to a second organisation "QA Other Org" with a registration there and none in demodev, holding one topic. Note one of its collection item pks.
   - **A learner** `qa-learner@example.com` / `testpass123` in a demodev cohort registered for "QA Preview Course".
   - **An educator** `qa-other-educator@example.com` / `testpass123` who administers only "QA Other Org".

   Record every pk the tests below need: the preview course pk, the pk of the collection item for "Welcome", for "Module one", for "Inside the part", and for the other organisation's topic.

4. Course page URL for the preview course: `http://127.0.0.1:$PORT/educator/organisations/demodev/courses/<course pk>`.

## §1 Details panel

1. Open the course page. In the Details panel, expect rows labelled Title, Subtitle, Category, Visibility, Level, Duration ("~1 hour 30 min"), Time limit ("90 days"), Learning outcomes (both outcomes), Lessons ("3": Welcome, Reading, Inside the part; the two forms are not lessons).
2. Open "QA Empty Course". Expect Lessons "0" and no Subtitle, Duration, Time limit or Learning outcomes row when those are unset.

## §2 Course outline

1. On the preview course page, find the "Course content" panel after Details. Expect rows numbered `1.` Welcome, `2.` Reading, `3.` Module one, `4.` Empty module, `5.` Feedback survey; inside Module one, `3.1` Inside the part, `3.2` Module quiz.
2. Each row shows a type icon (topic, form, folder). Titles wrap rather than truncating: confirm by narrowing the window to 768 and checking no title ends in an ellipsis.
3. Parts are open by default. Click "Module one": its children collapse and the row's `aria-expanded` flips to `false`; click again to reopen. Reload the page: both parts are open again (no persistence).
4. "Empty module" expanded shows "No items in this part."
5. Topic and Form rows end in a "Preview" button whose accessible name is "Preview <title>". Part rows have no Preview button.
6. Right-click "Preview" on Welcome and inspect: the `hx-get` URL is under `/educator/organisations/demodev/courses/...` with `?item=`. Search the page source for `/courses/` learner paths and `/learn` style URLs: none appear.
7. Open "QA Empty Course": the panel shows "No content in this course yet." and the header still offers "Preview course details page".
8. Open "QA Draft Outline": an info callout above the outline reads "Learners can't see this outline yet. The course is marked as still in development." and the outline and Preview buttons are present.

## §9 Scoping and adversarial branches

Run these as the superuser in the educator interface, with the dev tools network panel open so you can issue requests with and without the HTMX header.

1. Take the Welcome Preview button's `hx-get` URL and open it directly in the address bar (no `HX-Request` header): expect a 404 page, not the fragment.
2. From the course page, run in the console:

   ```
   fetch(location.pathname + "/__panels/content/__actions/preview_content?item=<other org topic collection item pk>", {headers: {"HX-Request": "true"}}).then(r => console.log(r.status))
   ```

   Expect 404. Repeat with `?item=<Module one collection item pk>` (a part): 404. With `?item=not-a-uuid`: 404. With `?item=00000000-0000-0000-0000-000000000000`: 404. With no `item` parameter: 404. If the panel URL segment differs, copy the exact path from a real Preview button's `hx-get` and only swap the query string.
3. POST to the same URL with the HTMX header (`method: "POST"`, include the CSRF token from the `hx-headers` on `<body>`): 404.
4. Log in as `qa-other-educator@example.com` in a private window and open `http://127.0.0.1:$PORT/educator/organisations/demodev/courses/<preview course pk>`: 404. Then fetch the preview action URL with the HTMX header from that session: 404.
5. As the superuser open `http://127.0.0.1:$PORT/educator/organisations/demodev/courses/<QA Other Org Course pk>`: 404 (no demodev registration), so none of its content is reachable through demodev.
