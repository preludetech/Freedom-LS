# Implementation plan: Registration rules

Source: `1. spec.md` in this directory. `research_codebase.md` beside it holds the code facts this
plan builds on; the other `research_*.md` files hold the reasoning behind the spec's decisions.

Code snippets below are shapes, not finished files: they omit imports and the implementer adds
them, with full type hints on every function and no `Any`. Comments and docstrings in the
snippets are written to be copied as they are. Nothing else in this document is: never copy a
sentence that names a slice into code.

Every open question in the spec takes its default: inactive learners never match, a rule with no
conditions matches the whole organisation, the preview list is uncapped, there is no periodic
reconcile, an unpublished course warns and keeps registering, and enabling a rule notifies every
learner it registers.

## Slice 1: a rule can be created, disabled, in the admin

**Behaviour.** With `"freedom_ls.registration_rules"` in `INSTALLED_APPS`, `migrate` creates the
`RegistrationRule` table. A superuser opens the rules add page, which asks only for `name`,
`organisation` and `course`, saves, and lands on the change page of a disabled rule whose
`organisation` and `course` are read-only. The rule-kind seam resolves `attribute` to
`AttributeRuleKind`, whose `matching_learners` already returns the organisation's active learners
(no conditions yet) and nothing when the rule is disabled. `manage.py check` reports `E001`
without `hr_attributes` and `E002` for a kind path that does not import. `danger_content_delete`
still completes with rules present. With the app absent from `INSTALLED_APPS`, its tests are not
collected and the rest of the suite passes.

This slice ends in a stored rule that registers nobody; the first learner-visible behaviour is
Slice 2.

> **Review concern:** the vertical-slices review found this slice carries guard rails (the two
> checks, the `danger_content_delete` branch, the rule-kind loader) before any learner sees a
> result. Options: 1. keep them here, because the app cannot be installed cleanly without the
> checks and `danger_content_delete` fails from the moment the PROTECT FK exists (recommended);
> 2. move the checks and the loader into a later guard-rails slice and fold the register path of
> Slice 2 into this one.
>
> **Assumed default:** option 1. Why: a slice that leaves `manage.py check` or a dev command
> broken is not a working system. To change: this section.

- New `freedom_ls/registration_rules/models.py` with `RegistrationRule` only (the other two
  models arrive with the slices that use them; each gets its own migration):

```python
"""Rules that keep a course's registrations in step with who works where.

A rule belongs to one organisation, names one course and says who matches.
Evaluation runs in the background and reconciles the course's registrations
with the current match, so a repeated or stale run changes nothing.
"""


class RegistrationRule(SiteAwareModel, TimestampedModel):
    class Outcome(models.TextChoices):
        REGISTER = "register", "Register"

    # Both PROTECT: a rule explains registrations that may outlive the people
    # who wrote it, and neither side is deleted while one exists.
    organisation = models.ForeignKey(
        "freedom_ls_organisations.Organisation",
        on_delete=models.PROTECT,
        related_name="registration_rules",
    )
    course = models.ForeignKey(
        "freedom_ls_content_engine.Course",
        on_delete=models.PROTECT,
        related_name="registration_rules",
    )
    name = models.CharField(max_length=200)
    # A key of REGISTRATION_RULE_KINDS. Validated by the loader, not by choices,
    # so a project can add a kind without a migration.
    kind = models.CharField(max_length=50, default="attribute")
    outcome = models.CharField(
        max_length=20, choices=Outcome.choices, default=Outcome.REGISTER
    )
    # Off at creation: conditions are added on the change page, and enabling
    # is what first registers anyone.
    is_enabled = models.BooleanField(default=False)
    # Written with QuerySet.update() when a run of the whole rule finishes, so
    # it never moves updated_at. Null or older than updated_at means a change
    # that no run has applied yet.
    last_evaluated_at = models.DateTimeField(null=True, blank=True)

    class Meta:
        ordering = ["name"]

    def __str__(self) -> str:
        return self.name
```

```python
@dataclass(frozen=True)
class AttributeConditions:
    """What an attribute rule asks of a learner. Empty sets and None constrain nothing."""

    job_title_ids: frozenset[UUID] = frozenset()
    department_ids: frozenset[UUID] = frozenset()
    location_ids: frozenset[UUID] = frozenset()
    organisation_start_on_or_after: date | None = None
    organisation_start_before: date | None = None
    job_title_start_on_or_after: date | None = None
    job_title_start_before: date | None = None
    department_start_on_or_after: date | None = None
    department_start_before: date | None = None
    location_start_on_or_after: date | None = None
    location_start_before: date | None = None


@dataclass(frozen=True)
class RuleState:
    """A rule as a value, so preview and evaluation run one query over the same input.

    Built from a saved rule or from the admin's validated, unsaved form data.
    """

    site_id: int
    organisation_id: UUID
    course_id: UUID
    is_enabled: bool
    conditions: AttributeConditions

    @classmethod
    def from_rule(cls, rule: RegistrationRule) -> RuleState:
        # Imported here: loader imports this module for its return type.
        from freedom_ls.registration_rules.loader import get_rule_kind

        return cls(
            site_id=rule.site_id,
            organisation_id=rule.organisation_id,
            course_id=rule.course_id,
            is_enabled=rule.is_enabled,
            conditions=get_rule_kind(rule.kind).conditions_from_rule(rule),
        )


class AttributeRuleKind:
    """Matches learners on the HR attributes they hold."""

    def conditions_from_rule(self, rule: RegistrationRule) -> AttributeConditions:
        # A rule with no conditions row constrains nothing, so it matches the
        # whole organisation.
        return AttributeConditions()

    def matching_learners(self, state: RuleState) -> QuerySet[Learner]:
        # _base_manager and explicit site: a task has no request for the
        # site-aware manager to read.
        if not state.is_enabled:
            return Learner._base_manager.none()
        return Learner._base_manager.filter(
            site_id=state.site_id,
            organisation_id=state.organisation_id,
            is_active=True,
        ).order_by("pk")
```

  `loader.py` imports `AttributeRuleKind` under `if TYPE_CHECKING:` with
  `from __future__ import annotations`, so the two modules do not import each other at runtime.

```python
@functools.cache
def get_rule_kind(key: str) -> AttributeRuleKind:
    """The kind class for `key`, instantiated once per process.

    Tests that override REGISTRATION_RULE_KINDS clear this cache; the autouse
    fixture in freedom_ls/conftest.py does it around every test.
    """
    paths = config.REGISTRATION_RULE_KINDS
    if key not in paths:
        raise ImproperlyConfigured(
            f"{key!r} is not a key of REGISTRATION_RULE_KINDS ({sorted(paths)})."
        )
    kind_class: type[AttributeRuleKind] = import_string(paths[key])
    return kind_class()
```

  The return annotation names `AttributeRuleKind` because no abstract base is wanted; a second
  kind would be a class with the same three methods.

```python
@admin.register(RegistrationRule)
class RegistrationRuleAdmin(SiteAwareModelAdmin):
    list_display = ["name", "organisation", "course", "is_enabled", "last_evaluated_at"]
    list_filter = ["organisation", "is_enabled", "course"]
    list_select_related = ["organisation", "course"]
    search_fields = ["name"]
    autocomplete_fields = ["organisation", "course"]
    readonly_fields = ["last_evaluated_at", "created_at", "updated_at"]

    def get_fields(self, request, obj=None):
        # The add page takes the three things a rule cannot change afterwards.
        # Conditions and the switch wait for the change page, where the
        # organisation is known and a preview can be shown.
        if obj is None:
            return ["name", "organisation", "course"]
        return [
            "name",
            "organisation",
            "course",
            "is_enabled",
            "last_evaluated_at",
            "created_at",
            "updated_at",
        ]

    def get_readonly_fields(self, request, obj=None):
        readonly = list(super().get_readonly_fields(request, obj))
        # Changing either would silently retract one group and register
        # another. Staff disable the rule and make a new one instead.
        return readonly if obj is None else [*readonly, "organisation", "course"]

    def response_add(self, request, obj, post_url_continue=None):
        # Always on to the change page, where conditions are added. Forcing
        # "_continue" keeps the stock "added" message and redirect.
        request.POST = request.POST.copy()
        request.POST["_continue"] = "1"
        return super().response_add(request, obj, post_url_continue)
```

## Slice 2: enabling a rule registers every matching learner

**Behaviour.** Saving a rule with `is_enabled=True` enqueues `evaluate_rule_task` after commit.
The task, with no request in its thread, reads the organisation's switch; when it is on, every
learner the rule matches and who has no `LearnerCourseRegistration` for the course gets one
(`self_registered=False`, `is_active=True`) and a `RuleRegistration` naming the rule, in batches
of `REGISTRATION_RULE_BATCH_SIZE`, and `last_evaluated_at` is stamped when the run finishes. The
existing progress-record receiver mints the `CourseProgress`, raises `course.registered` for the
learner and, now, also fires the `course.registered` webhook, because `_ensure_and_announce` calls
the new site-explicit `fire_webhook_event_for_site`. A registration that already existed, active
or not, is never touched and gains no `RuleRegistration`. The registration change page in the
admin shows a read-only "Registration rule" field naming the rule. Delete is refused while the
rule is enabled, on the change page and in the bulk action; deleting a disabled rule writes its
name to its `RuleRegistration` rows first, and the rows survive with `rule=None`.

The slice is committed in three ordered steps, each with its own tests passing: (a) the model,
evaluation, task and trigger; (b) the webhook split; (c) the admin field and rule deletion.

```python
    retract: tuple[UUID, ...] = ()

class EvaluationResult:
    registered: tuple[UUID, ...] = ()
    reactivated: tuple[UUID, ...] = ()
    retracted: tuple[UUID, ...] = ()

    def merged_with(self, other: EvaluationResult) -> EvaluationResult: ...


def rules_enabled_for(organisation_id: UUID) -> bool:
    """The organisation's switch. No settings row means off."""
    return OrganisationHRSettings._base_manager.filter(
        organisation_id=organisation_id, registration_rules_enabled=True
    ).exists()


def classify_rule_changes(
    rule: RegistrationRule, state: RuleState, learner_ids: Sequence[UUID] | None = None
) -> RuleChanges:
    """Compare the rule's match with the course's registrations. Reads only.

    `state` may differ from the saved rule: the admin preview passes the
    submitted form as a state while ownership still comes from the saved rows.
    """
    matching = get_rule_kind(rule.kind).matching_learners(state)
    registrations = LearnerCourseRegistration._base_manager.filter(
        site_id=state.site_id, course_id=state.course_id
    )
    if learner_ids is not None:
        matching = matching.filter(pk__in=learner_ids)
        registrations = registrations.filter(learner_id__in=learner_ids)
    matching_ids = set(matching.values_list("pk", flat=True))
    rows = list(
        registrations.values_list(
            "learner_id",
            "is_active",
            "rule_registration__rule_id",
            "rule_registration__is_retracted",
        )
    )
    registered_ids = {learner_id for learner_id, _, _, _ in rows}
    # Register the matching learners who have no registration row at all. Any
    # existing row, active or not, belongs to someone else and is never touched.
    register = sorted(matching_ids - registered_ids)
    return RuleChanges(register=tuple(register))


def apply_rule_changes(rule: RegistrationRule, changes: RuleChanges) -> EvaluationResult:
    """Write the changes, in learner-pk order, with explicit site ids throughout."""
    registered: list[UUID] = []
    for learner_id in changes.register:
        try:
            # A savepoint per row: a learner registered by someone else between
            # the read and this write hits the unique constraint, and only this
            # row rolls back. Theirs stands; a rule never takes over a row.
            with transaction.atomic():
                registration = LearnerCourseRegistration(
                    site_id=rule.site_id,
                    learner_id=learner_id,
                    course_id=rule.course_id,
                    is_active=True,
                    self_registered=False,
                )
                # save(), not bulk_create: the progress record and the
                # course.registered announcement hang off post_save.
                registration.save()
                RuleRegistration._base_manager.create(
                    site_id=rule.site_id,
                    registration=registration,
                    rule=rule,
                    rule_name=rule.name,
                )
        except IntegrityError:
            continue
        registered.append(learner_id)
    return EvaluationResult(registered=tuple(registered))


def evaluate_rule(rule_id: UUID, site_id: int) -> EvaluationResult:
    """Reconcile one rule against everyone it matches or owns."""
    rule = RegistrationRule._base_manager.filter(pk=rule_id, site_id=site_id).first()
    if rule is None or not rules_enabled_for(rule.organisation_id):
        return EvaluationResult()
    state = RuleState.from_rule(rule)
    in_scope = sorted(
        set(get_rule_kind(rule.kind).matching_learners(state).values_list("pk", flat=True))
        | set(
            Learner._base_manager.filter(
                site_id=site_id,
                learnercourseregistration__rule_registration__rule_id=rule_id,
            ).values_list("pk", flat=True)
        )
    )
    result = EvaluationResult()
    for batch in itertools.batched(in_scope, config.REGISTRATION_RULE_BATCH_SIZE):
        # One transaction per batch, re-reading the rule under a row lock, so a
        # rule disabled or a switch turned off mid-run takes effect at the next
        # batch rather than after the whole organisation.
        with transaction.atomic():
            rule = (
                RegistrationRule._base_manager.select_for_update()
                .filter(pk=rule_id, site_id=site_id)
                .first()
            )
            if rule is None or not rules_enabled_for(rule.organisation_id):
                return result
            changes = classify_rule_changes(
                rule, RuleState.from_rule(rule), learner_ids=list(batch)
            )
            result = result.merged_with(apply_rule_changes(rule, changes))
    # update(), not save(): a finished run is not an edit of the rule.
    RegistrationRule._base_manager.filter(pk=rule_id, site_id=site_id).update(
        last_evaluated_at=timezone.now()
    )
    return result
```

## Slice 3: conditions on HR attributes

**Behaviour.** The change page carries an "Attribute conditions" inline: three multi-select

## Slice 4: retract, reactivate, hand over, detach

**Behaviour.** A learner who stops matching a rule has the rule's registration deactivated with
`is_retracted=True` when they have not started the course; a started learner keeps the
registration. When another enabled rule on the same course still matches the learner, the
`RuleRegistration` is re-pointed at it and the registration stays active. A retracted learner who
matches again is reactivated on the same row, silently. A registration whose `is_active` anyone
other than the engine changes, in the admin or by self-registering, loses its `RuleRegistration`
and is thereafter left alone. Disabling a rule retracts every learner it owns, by the same path.

```python
def _hand_overs(
    rule: RegistrationRule, state: RuleState, learner_ids: Sequence[UUID]
) -> dict[UUID, HandOver]:
    """Which other enabled rule on the course takes each learner this rule lets go of.

    Rules are tried in name order so two runs hand the same learner to the
    same rule.
    """
    others = (
        RegistrationRule._base_manager.filter(
            site_id=state.site_id,
            organisation_id=state.organisation_id,
            course_id=state.course_id,
            is_enabled=True,
        )
        .exclude(pk=rule.pk)
        .order_by("name", "pk")
    )
    remaining = set(learner_ids)
    taken: dict[UUID, HandOver] = {}
    for other in others:
        if not remaining:
            break
        matched = get_rule_kind(other.kind).matching_learners(RuleState.from_rule(other))
        for learner_id in matched.filter(pk__in=remaining).values_list("pk", flat=True):
            taken[learner_id] = HandOver(learner_id, other.pk, other.name)
            remaining.discard(learner_id)
    return taken
```

## Slice 5: learner, attribute and switch triggers

**Behaviour.** Saving a `Learner`, saving or deleting a `LearnerHRAttributes` row, and saving
`OrganisationHRSettings` with the switch on each enqueue an evaluation after commit. A learner's
evaluation reconciles every enabled rule of their current organisation and every registration a
rule owns for them, so a learner who moved or was removed is retracted from the old
organisation's rules. Turning the switch on evaluates every rule of the organisation, enabled or
not, applying what attribute and rule changes made while it was off would have caused.

From this slice on, every `Learner` and `LearnerHRAttributes` save in the whole suite enqueues a
task. The suite runs tasks on `ImmediateBackend`, so each such save now also runs an evaluation
inline; it finds no rules and returns. At the end of the slice run
`uv run pytest freedom_ls/learner_management freedom_ls/hr_attributes freedom_ls/learner_interface freedom_ls/learner_progress`
to confirm nothing there assumed a quiet save.

```python
def evaluate_learner(learner_id: UUID, site_id: int) -> EvaluationResult:
    """Reconcile one learner against the rules that match or own them.

    Locks only the Learner row; evaluate_rule locks only the rule. Both write
    registrations in learner-pk order, so the two cannot deadlock.
    """
    result = EvaluationResult()
    with transaction.atomic():
        learner = (
            Learner._base_manager.select_for_update()
            .filter(pk=learner_id, site_id=site_id)
            .first()
        )
        if learner is None:
            return result
        rules = (
            RegistrationRule._base_manager.filter(site_id=site_id)
            .filter(
                Q(organisation_id=learner.organisation_id, is_enabled=True)
                | Q(rule_registrations__registration__learner_id=learner_id)
            )
            .distinct()
            .order_by("pk")
        )
        # One switch read per organisation: a learner who moved still holds
        # the old organisation's rows, and that organisation has its own switch.
        switches: dict[UUID, bool] = {}
        for rule in rules:
            if rule.organisation_id not in switches:
                switches[rule.organisation_id] = rules_enabled_for(rule.organisation_id)
            if not switches[rule.organisation_id]:
                continue
            changes = classify_rule_changes(rule, RuleState.from_rule(rule), learner_ids=[learner_id])
            result = result.merged_with(apply_rule_changes(rule, changes))
    return result


def evaluate_organisation(organisation_id: UUID, site_id: int) -> EvaluationResult:
    """Every rule of the organisation, disabled ones included, so their registrations catch up."""
    result = EvaluationResult()
    for rule_id in (
        RegistrationRule._base_manager.filter(organisation_id=organisation_id, site_id=site_id)
        .order_by("pk")
        .values_list("pk", flat=True)
    ):
        result = result.merged_with(evaluate_rule(rule_id, site_id))
    return result
```

## Slice 7: the admin says when a change has not been applied

**Behaviour.** The changelist gains a boolean "Change not yet applied" column: enabled, and
`last_evaluated_at` null or older than `updated_at`. The change form shows a warning when the
course is not published ("This course is not published. The rule still registers learners, who
will not see it until it is.") and, when the last change has not been applied, a warning naming
the cause it can see: "Registration rules are switched off for {organisation}; this rule's
changes apply once they are switched on." or "This rule's last change has not been applied yet.
The task is queued or has failed; check the task worker."

**Files.**

- `freedom_ls/registration_rules/admin.py`:
  - `get_queryset` adds
    `change_not_yet_applied=ExpressionWrapper(Q(is_enabled=True) & (Q(last_evaluated_at__isnull=True) | Q(last_evaluated_at__lt=F("updated_at"))), output_field=BooleanField())`;
    `@admin.display(boolean=True, description="Change not yet applied", ordering="change_not_yet_applied")`
    reads the annotation; `list_display` gains it.
  - `_change_form_warnings(obj)` appends two entries. `obj` comes from `self.get_object`, which
    goes through `get_queryset`, so `obj.change_not_yet_applied` is already there and the
    predicate is written once: when `obj.course.visibility != CourseVisibility.PUBLISHED`, the
    unpublished warning; when `obj.change_not_yet_applied`, the switch-off cause if
    `not rules_enabled_for(obj.organisation_id)`, else the task-worker cause.

**Tests** (`tests/test_admin.py`):

- The column is false for a disabled rule, true for an enabled rule with
  `last_evaluated_at=None`, true when `last_evaluated_at < updated_at` (`time_machine`), false
  after `evaluate_rule` runs.
- An unpublished course shows a warning naming the course's state, and `evaluate_rule` still
  registers.
- An enabled rule with the switch off shows a warning naming the organisation; with the switch on
  and no run, one naming the task worker; after a run, neither.
