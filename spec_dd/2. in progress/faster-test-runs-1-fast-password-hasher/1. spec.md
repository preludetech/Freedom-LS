# Spec: Tests hash passwords with a fast hasher

## Purpose

`UserFactory` hashes a password for every user it builds, and `config/settings_base.py` puts
`Argon2PasswordHasher` first in `PASSWORD_HASHERS`. Argon2 is slow and memory-hungry by design, so
the suite pays that cost thousands of times. Under pytest, FLS switches to Django's
`MD5PasswordHasher`. Deployed sites and the dev server keep Argon2, and concrete projects that
star-import `freedom_ls/conftest.py` get the switch without configuring anything. The case is in
`idea.md`.

## Scope

In:

- An autouse switch in `freedom_ls/conftest.py` that applies to every test, FLS's own and a
  concrete project's.
- A named way for one test to opt back into the hashers the settings configure.
- Tests that prove the switch is on, that the opt-in works, and that the settings modules still
  put Argon2 first.
- Before and after timings for the two samples in
  `spec_dd/1. next/faster-test-runs/research_test_timings.md`, "Password hashing".

Out:

- Any change to `PASSWORD_HASHERS` in `config/settings_base.py`, `settings_dev.py` or
  `settings_prod.py`.
- Test runs that do not load `freedom_ls/conftest.py`: the standalone `panel_framework` and `icons`
  runs, and tests that spawn a pytest or Django subprocess (`tests/test_run_tests.py`,
  `course_applications/tests/invariants/test_collection_safety.py`).
- Other test speed-ups; the sibling specs in the roadmap's "Faster test runs" effort own them.

## Decisions

- **Session scope, through `override_settings`.** A session-scoped autouse fixture runs before
  every other fixture, so no fixture of any scope hashes with Argon2. `override_settings(...).enable()`
  sends `setting_changed`, and Django's `reset_hashers` receiver in
  `django/contrib/auth/hashers.py` clears the `get_hashers` caches. A plain assignment to
  `settings.PASSWORD_HASHERS` would leave a stale cache.
- **A fixture, not a settings module or a `pytest_*` hook.** Concrete projects run under their own
  settings module, and a star-import carries fixtures reliably but not hooks.
- **MD5 first, the configured list after it.** New hashes use MD5. Any hash made by a configured
  hasher, such as an Argon2 hash in a fixture, still verifies.

## Requirements

### `freedom_ls/conftest.py`

- New session-scoped autouse fixture `_fast_password_hasher`.
  - It reads `settings.PASSWORD_HASHERS` (the configured list) and enables
    `override_settings(PASSWORD_HASHERS=["django.contrib.auth.hashers.MD5PasswordHasher", *rest])`,
    where `rest` is the configured list without the MD5 entry. A list that already holds MD5 does
    not get it twice.
  - It yields the configured list and disables the override at teardown.
  - Its docstring says what it does, why, and how a test opts back in, as
    `_disable_preview_overrides` does.
- New fixture `production_password_hashers(settings, _fast_password_hasher)`, not autouse. It sets
  `settings.PASSWORD_HASHERS` to the configured list for one test. pytest-django's `settings`
  fixture restores the fast list at teardown and sends `setting_changed` both ways. A class or
  module opts in with `@pytest.mark.usefixtures("production_password_hashers")`.
- The MD5 hasher is named by its dotted path. Nothing imports `hashlib.md5`.

## Testing

The new tests sit where the `test-mirroring` hook accepts them.

- Default: `get_hasher().algorithm == "md5"`, and a `UserFactory()` user's `password` starts with
  `md5$`.
- Configured hashers kept: a hash from `make_password(pw, hasher="argon2")` passes `check_password`
  under the default switch.
- Opt-in: with `production_password_hashers`, `get_hasher().algorithm == "argon2"`, and
  `set_password` followed by `check_password` round-trips. This also proves `argon2-cffi` loads.
- Opt-in ends with the test: a later test sees `md5` again.
- Settings untouched: `config.settings_base.PASSWORD_HASHERS[0]` and
  `config.settings_dev.PASSWORD_HASHERS[0]`, read from the modules rather than `django.conf.settings`,
  are `"django.contrib.auth.hashers.Argon2PasswordHasher"`.
- The existing suite passes unchanged. No existing test asserts a hasher or a hash format
  (`research_codebase.md`), and the Playwright login flows hash and check in one process, so the
  live server thread sees the same list.

  asserts an Argon2 hash or a hash prefix opts in with `production_password_hashers`. A project
  opts out of the switch altogether by defining its own `_fast_password_hasher` in its conftest.

## Open questions

- Q: How does a test opt back into the configured hashers? → A: the `production_password_hashers`
  fixture (assumed default: it follows the conftest's fixture style, needs no marker registration
  and no test needs it yet. Overrule by editing "Requirements" to use a registered marker instead.)

## Success criteria

- `uv run pytest` passes with no test changed apart from the new ones.
- Under pytest, `get_hasher().algorithm` is `md5` in every test that does not opt in.
- A test using `production_password_hashers` gets `argon2`.
- `config/settings_base.py`, `settings_dev.py` and `settings_prod.py` have no diff.
- Pre-commit (bandit, ruff) passes on the change with no `# nosec` or `noqa` added.
- `timings.md` records both samples before and after, and the after times are lower.
