Rules from the skills that shape several slices:

- A panel holds at most one `primary` outside a dialog; row buttons are small `secondary` inside
  `<c-data-table-actions>`; two buttons in one row each name their object in `aria_label`.
- A row the viewer cannot act on states its fields and leaves its actions cell empty, with no note.
- Every `ReasonMixin` subclass submits through the mixin's `handle_submit`
  (`tests/invariants/test_reason_mixin.py`), and `ReasonMixin` is listed first in the bases.
- Educator templates write `<c-button>`, framework templates `<c-panel-button>`.
- Do not add `x-cloak` to collapsed child rows: without JavaScript every row must show. The brief
  open-then-collapse paint on load is the accepted cost.
- 422 for an HTMX validation error.
- Assert behaviour through the rendered page (`hx-trigger`, `data-*`), not class attributes.

`panels/common/course_page.py` get `tests/panels/common/test_registration_actions.py` and
`tests/panels/common/test_course_page.py`; new `panels/course/actions.py` gets

## Why shared bases

CLAUDE.md says not to create abstract base classes unasked. The spec asks for one: the cohort,
learner and course pages offer the same Deactivate and Reactivate dialogs on the same
registrations, so each dialog lives once in `panels/common/registration_actions.py` and each page
supplies only which rows it may reach and how it refreshes.

```python
def scoped(ctx: PanelContext) -> OrganisationScopedRequest:
    return cast(OrganisationScopedRequest, ctx.request)


class CoursePageActionMixin(PanelAction):
    """An action on the course page. Its capability is asked about the
    organisation in view until a request names a row, then about the row's
    own cohort or learner, because can() has no rule for a course. List it
    after any reason mixin and before the action it guards."""

    def subject_of(self, row: Model) -> Cohort | Learner:
        """The cohort or learner a row of this action belongs to."""
        raise NotImplementedError

    def row_subject(self, ctx: PanelContext) -> Cohort | Learner | None:
        if self.row_param is None:
            return None
        params = ctx.request.POST if ctx.request.method == "POST" else ctx.request.GET
        if self.row_param not in params:
            return None
        return self.subject_of(self.get_row_object(ctx))

    def permission_object(self, ctx: PanelContext) -> Model | None:
        return scoped(ctx).organisation

    def has_permission(self, ctx: PanelContext) -> bool:
        capability = self.get_capability(ctx)
        if capability is None:
            return True
        request = scoped(ctx)
        subject = self.row_subject(ctx)
        if subject is None:
            return can_on_any(request.user, request.organisation, capability)
        return can(request.user, capability, subject)
```

    whose registration is inactive reactivates it."""

    label = "Register"
    action_name = "register_cohort"
    capability = ADD_COHORT_REGISTRATION
    form_class = CohortPickerForm
    submit_buttons = [
