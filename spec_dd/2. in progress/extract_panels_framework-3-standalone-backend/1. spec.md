# Spec: the panel framework's backend stands alone

Spec 3 of 6 in the Panel framework extraction effort (`spec_dd/1. next/roadmap.md`, "Panel framework
extraction"). Idea: `idea.md`. Answers: `answers.md`.

## Purpose

Another Django project needs the panel framework, and it cannot install a package whose model,
settings helper and formatting import FLS. This spec removes every Python import of `freedom_ls`
from outside `freedom_ls/panel_framework/`, without moving the code yet. The framework's unit tests
then run under a minimal settings module with no FLS conftest. Educators see no change, and tenant
isolation of bulk-action runs behaves as it does today, except that an unresolved site now sees no
runs instead of every site's.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| standalone run | coined | The framework's unit tests run by the separate pytest command in Requirement 9, under `freedom_ls/panel_framework/tests/standalone_settings.py`, with no FLS conftest |
| `needs_fls_host` | coined | pytest marker on a framework unit test that needs FLS's real templates, icon set or URLconf; deselected in the standalone run until spec 4 |

## Scope

In: the framework's six non-test imports from FLS, `BulkActionRun`'s site handling, a `TASKS`
check, the standalone run and its CI step, an import guard, and the FLS settings, test call sites
and dev dependencies these need.

Out (owner in brackets):

- Migration `0001_initial` rewrite, app label rename, check-id prefix change, ContentType handling
  [spec 5].
- Templates, JS, CSS, icons, the page shell, primitives, and the component, invariant (beyond
  `lxml`) and Playwright tiers [spec 4].
- The package repo, its `pyproject.toml`, installing it into FLS [spec 5].
- Any change to `SiteAwareModel` or `site_aware_models` for the rest of FLS.
- The stale-run sweep's placement (already in the framework from spec 1) and `RunStatus` reuse by
  `learner_management`.

## Requirements

Everything copied from FLS is a copy; FLS keeps its own. If the site handling turns out to need
`site_aware_models` internals, stop and say so: the effort does not add a shared core package.

### 1. Settings helper (`config.py`)

- A new framework module, `freedom_ls/panel_framework/app_settings.py`, holds a copy of `Setting`
  and `AppSettings` from `freedom_ls/base/app_settings.py`. `required_settings_errors` is not copied,
  because the framework declares no required setting.
- `config.py` imports from it and declares a second setting under its full name, read as
  `config.PANEL_FRAMEWORK_SITE_RESOLVER`:

  ```python
  "PANEL_FRAMEWORK_SITE_RESOLVER": Setting(
      default="django.contrib.sites.shortcuts.get_current_site"
  ),
  ```

  `BULK_BACKGROUND_THRESHOLD` keeps its name.
- Settings are read on access, never cached at import, so `override_settings` works.

### 2. Site resolution (`freedom_ls/panel_framework/sites.py`, new)

`resolve_site(request: HttpRequest) -> Site | None`:

- returns `request._panel_framework_site` when that attribute is set;
- otherwise imports `config.PANEL_FRAMEWORK_SITE_RESOLVER` with
  `django.utils.module_loading.import_string` at call time (not module import, so FLS's test
  patches of `get_current_site` stay effective), calls it with the request, and stores the result
  on `request._panel_framework_site`;
- returns `None`, and caches it, when the resolver raises `Site.DoesNotExist` (the default
  resolver's answer to an unknown host) or returns anything that is not a `Site` instance (a
  `RequestSite`, or FLS's `UnknownSite`);
- raises `ImproperlyConfigured` naming the setting and the bad value when the path cannot be
  imported or is not callable.

The attribute name is the framework's own, so it never aliases FLS's `request._cached_site`.

### 3. `BulkActionRun` (`models.py`)

- Subclasses `models.Model`, with no abstract base in place of `SiteAwareModel`. Declares, before
  its own fields and with definitions identical to `SiteAwareModel`'s:

  ```python
  id = models.UUIDField(primary_key=True, default=uuid.uuid4, editable=False)
  site = models.ForeignKey(Site, on_delete=models.PROTECT)
  ```

  `site` stays required. A save without one fails on the NOT NULL constraint; there is no
  save-time fallback.
- `objects` is a framework manager built from a `BulkActionRunQuerySet` with:
  - `for_site(site_id: int)`: `filter(site_id=site_id)`;
  - `for_request(request)`: `for_site(site.pk)` when `resolve_site(request)` is a `Site`, else
    `none()`. `SiteAwareManager` returned every site's rows in that case.
- The manager does not set `use_in_migrations`, and `Meta.base_manager_name` stays unset, so
  `_base_manager` stays Django's plain manager (relied on by `bulk_runs.py:72-80`,
  `housekeeping.py` and FLS's `qa_create_bulk_operations_scenario`).
- Nothing in the framework reads a thread-local.

### 4. Read and write paths

| Path | After this spec |
| --- | --- |
| `views.py:1147` `_handle_run_status` | `BulkActionRun.objects.for_request(request).filter(...)`; another site's run is a 404 |
| `bulk_actions.py:383` `RecordedBulkAction.execute` | resolves the site with `resolve_site(ctx.request)` and passes `site=` to `create`. A `None` site raises `PermissionDenied`, and no row is written |
| `bulk_actions.py:396,398`, `tasks.py` `_run_bulk_action_task(run_id, site_id)` | unchanged signature; still pass `run.site_id` |
| `bulk_runs.py:72-80` `_run_on_site` | unchanged (`_base_manager.filter(site_id=..., pk=...)`) |
| `housekeeping.py` | unchanged; still cross-site via `_base_manager`, closing runs on every site |

Every other FLS use of `BulkActionRun.objects` either needs no site filter and is single-site in
its tests, or moves to `for_site`/`for_request`.

### 5. CSV helpers (`tables.py`, `views.py`)

- A new framework module, `freedom_ls/panel_framework/csv_safety.py`, holds copies of
  `FORMULA_TRIGGERS`, the E.164 phone-number exemption, `escape_csv_formula` and `UTF8_BOM` from
  `freedom_ls/base/csv_safety.py`, and `EchoWriter` from `csv_import.py:135-141`. Nothing else from
  `csv_import.py` is copied.
- `tables.py` and `views.py` import from it.
- Its tests are a copy of `freedom_ls/base/tests/test_csv_safety.py`, including the test that pins
  the exact `FORMULA_TRIGGERS` tuple.

### 6. Date formats (`field_display.py`)

`field_display.py` stops importing `freedom_ls.base.date_display`. The framework defines its own
`DATE_DISPLAY_FORMAT = "j M Y"` and `DATETIME_DISPLAY_FORMAT = "j M Y, H:i"`, in `field_display.py`
or a small framework module. Rendered dates do not change.

### 7. `TASKS` check (`checks.py`, `apps.py`)

- A second check function, registered in `PanelFrameworkConfig.ready()` with plain `register` (not
  `deploy=True`).
- When `settings.DEBUG` is False and the default task backend is
  `"django.tasks.backends.immediate.ImmediateBackend"` or `"django.tasks.backends.dummy.DummyBackend"`,
  it returns one `Warning` with id `freedom_ls_panel_framework.W001`. The message names the backend.
  The hint says bulk actions over `BULK_BACKGROUND_THRESHOLD` rows run as background tasks and need
  a durable backend with a worker, and that the warning can be silenced by id.
- It reads `TASKS` with `.get`, so a `TASKS` with no `default` alias or no `BACKEND` gives no
  warning and no error. It compares dotted strings and imports no backend class.
- Under pytest (`DEBUG=False`) with FLS's `ImmediateBackend`, W001 appears in every
  `call_command("check")` in the FLS suite (`test_checks.py:326`,
  `educator_interface/tests/invariants/test_system_checks.py:16`). A warning does not fail `check`,
  so those tests still pass.

### 8. FLS wiring

- `config/settings_base.py` sets
  `PANEL_FRAMEWORK_SITE_RESOLVER = "freedom_ls.site_aware_models.models.get_cached_site"`, so FLS
  keeps `FORCE_SITE_NAME` and its own request cache.
- Every FLS test that creates a run with no site passes `site=` explicitly. The known call sites
  are `educator_interface/tests/test_views.py:5485`, `test_actions.py:7367,8338`,
  `test_notification_urls.py:18,35`, `invariants/test_config_authorisation.py:203`,
  `invariants/test_organisation_isolation.py:171`, and `deployment/tests/test_housekeeping.py:891`
  (`_make_bulk_record`). Outside the framework's own tests, `site=` additions and the scoping
  guard below are the only test edits.
- A scoping guard, `educator_interface/tests/invariants/test_bulk_run_scoping.py`, parses FLS's
  non-test, non-migration Python with `ast` and fails on any `BulkActionRun.objects` call other
  than `for_site`, `for_request` or `create`, because `objects` no longer filters by site.
- `pyproject.toml` declares `lxml` and `cssselect` (`test_panels.py:636` calls `.cssselect`) in both
  dev lists (`[project.optional-dependencies].dev` and `[dependency-groups].dev`), with `uv.lock`
  updated.
- The `needs_fls_host` marker is added to the FLS `markers` list (needed under `--strict-markers`).
  The FLS run does not deselect it.
- `.github/workflows/tests.yml` gets one step that runs the standalone command.

### 9. The standalone run

All files live in `freedom_ls/panel_framework/tests/`, so spec 5 moves them with the package.

- **pytest config.** `standalone_pytest.ini`. It is not named `pytest.ini`, `.pytest.ini`,
  `tox.ini`, `setup.cfg` or `pyproject.toml`: pytest would otherwise discover it for an FLS run
  targeted at framework files and switch FLS to the standalone settings. Its `addopts` carry
  `--ds=freedom_ls.panel_framework.tests.standalone_settings` (`--ds` beats a shell
  `DJANGO_SETTINGS_MODULE`) and `-m "not needs_fls_host"`, and no Playwright or FLS options. It sets
  `norecursedirs = components invariants playwright`, `python_files`, and its own marker list.
- **Command.** `uv run pytest -c freedom_ls/panel_framework/tests/standalone_pytest.ini
  freedom_ls/panel_framework/tests`. The path is part of the command, because `-c` makes `tests/`
  the rootdir and `testpaths` would not scope a run started from the repo root. With `tests/` as
  rootdir and confcutdir, neither the repo-root `conftest.py` nor `freedom_ls/conftest.py` loads.
- **Settings.** `standalone_settings.py`. SQLite in memory: the framework has no PostgreSQL-only
  construct, and its one text lookup (`icontains`, `tables.py:405`) folds only ASCII case on SQLite.
  FLS's own run stays on PostgreSQL. `INSTALLED_APPS`: `django.contrib` `auth`, `contenttypes`,
  `sessions`, `sites`, `messages`, `admin` (for `admin:login` in `root_urls.py`), `django_cotton`,
  the framework, and a test app. `ROOT_URLCONF` is the tests' `root_urls.py`. `AUTH_USER_MODEL` is
  the test app's user. `TEMPLATES` has the cotton loader, the request context processor, a stand-in
  `site_name` context processor, and the stand-in template directory first. `TASKS` uses
  `ImmediateBackend`. `SITE_ID` is unset, so the default resolver matches by host.
- **Test app.** A minimal email-login user model (`USERNAME_FIELD = "email"`, a manager whose
  `create_user(email=..., password=..., **extra)` serves `helpers.make_staff_user`).
- **Stand-in templates.** A directory only the standalone settings include. It holds minimal
  versions of every template outside `freedom_ls/panel_framework/templates/` that the unit tests
  reach, found by a render pass, not from memory. That includes at least the cotton components
  `c-icon`, `c-button`, `c-button-group`, `c-chip`, `c-pagination`, `c-dropdown-menu`,
  `c-dropdown-menu-separator`, `c-callout`, `c-back-link`, `c-page`, `c-date` and `c-datetime`, and
  the templates `_base.html`, `_base_interface.html`, `partials/form.html` and
  `partials/page_title.html`. Each keeps the props and slots the framework passes. They are test
  fixtures, not spec 4's components.
- **Fixtures.** The framework tests request `site` and `mock_site_context` by name (about 500
  uses), and those names stay. The framework's `tests/conftest.py` defines both. In the FLS run they
  delegate to FLS's fixtures of the same name, so the thread-local request, `SITE_CACHE` and the
  `get_current_site` and `SiteManager.get_current` patches stay in force and FLS's context
  processors keep working. In the standalone run they create a `Site` whose domain matches the
  `RequestFactory` and test-client host (`testserver`), clear `SITE_CACHE` per test, and make
  `resolve_site` return that site. Framework tests stop importing `drop_ambient_request`,
  `SiteFactory` and `site_context`; `Site.objects.create` replaces `SiteFactory`. No copy of
  `logged_in_client` or `database_task_backend` is made, because no framework test uses them. Changes to
  `tests/conftest.py` stay small, because spec 2 edits it too.
- **`needs_fls_host`.** Marks the unit tests that need FLS's real templates, icon set or URLconf:
  at least `test_tables.py:2208,2225` (heroicons SVG via `FREEDOM_LS_ICON_SET`) and the three
  `test_reference.py` tests that load `config.urls` (lines 166-239). A test that fails only because
  a stand-in renders different markup is marked, not given a weaker assertion.
- **Module naming.** `freedom_ls/` has no `__init__.py`, so tests import as
  `panel_framework.tests.*` (`tests/conftest.py:18-24`). The standalone run imports the framework
  and its tests under one name each.

### 10. Import guard (`tests/test_import_guard.py`, new)

- Parses every `.py` file under `freedom_ls/panel_framework/` with `ast` and fails on any `import`
  or `from` naming a `freedom_ls` module outside `freedom_ls.panel_framework`. The failure message
  names the file, line and import.
- Covers non-test code, `tests/` and `migrations/`. Exempt by name, in a pinned tuple in the test:
  `tests/components/`, `tests/invariants/`, `tests/playwright/`. Spec 4 removes them.
- Runs in both the FLS run and the standalone run.

### 11. Test modules for the new modules

`app_settings.py`, `csv_safety.py` and `sites.py` are private modules (no `__all__`, not in
`test_public_names.py::PUBLIC_MODULES`). Each gets a mirrored test module: `test_app_settings.py`
(a copy of `freedom_ls/base/tests/test_app_settings.py`), `test_csv_safety.py` (Requirement 5) and
`test_sites.py`.

## Testing

What has to be proved, beyond what each requirement states:

- **Tenant isolation, per path, with two `Site` rows.** `for_request` returns only the request
  site's runs. The run-status view 404s on another site's run. A bulk action creates its run under
  the request's site. `_run_on_site` will not load a run under the wrong `site_id`. The sweep still
  closes stale runs on every site.
- **Unresolved site.** An unknown host under the default resolver, and a resolver returning a
  non-`Site`, both give `for_request` no rows and make creation raise `PermissionDenied`.
- **Resolver.** The default resolves by host. The setting overrides it. The resolver is called
  once per request. An unimportable or non-callable path raises `ImproperlyConfigured` naming the
  setting.
- **Standalone isolation.** A collect-only run of the standalone command imports no FLS conftest
  and no `freedom_ls/tests` module.
- **Import guard.** It fails on a temporary file with a `freedom_ls.base` import.

`test_models.py::test_a_run_takes_its_site_from_the_ambient_site` and
`test_the_default_manager_hides_another_sites_runs` assert the behaviour being replaced; they are
rewritten for explicit scoping.

## Documentation and downstream

- `claude_plugins/fls-dev/skills/panel-framework/SKILL.md`: the resolver setting, `for_request` and
  `for_site`, `site=` on create, the `TASKS` warning, and the import guard. `fls-dev:multi-tenant`

- `claude_plugins/fls-dev/skills/testing/SKILL.md`: the standalone command and the `needs_fls_host`

- Upgrade notes: `requires_settings_change: true`. A downstream project inheriting
  `config/settings_base.py` gets the setting. One with its own settings must set
  `PANEL_FRAMEWORK_SITE_RESOLVER` to its resolver or accept `get_current_site`.

## Open questions

- Q: Should the standalone run be a `[tool.test_tiers]` tier? → A: No. It is a documented command
  plus a CI step, because that table cannot name an extra tier. (assumed default: the user chose
  "command + CI step" when told a tier needs a generic-plugin change. Overrule by editing
  Requirements 8 and 9.)
- Q: What does confirming a bulk action on a request with no resolvable site raise? → A:
  `PermissionDenied`. (assumed default: no row is written and the request cannot reach the view
  through FLS's middleware anyway. Overrule by editing Requirement 4.)

## Success criteria

- `grep -rn "freedom_ls\." freedom_ls/panel_framework --include=*.py` shows only
  `freedom_ls.panel_framework` imports, apart from the three exempt test directories.
- `uv run pytest -c freedom_ls/panel_framework/tests/standalone_pytest.ini freedom_ls/panel_framework/tests`
  passes.
- `uv run pytest` (FLS full suite) passes.
- `uv run manage.py makemigrations --check --dry-run` exits 0.
- `uv run manage.py check` with `DEBUG=False` and `ImmediateBackend` prints
  `freedom_ls_panel_framework.W001`; with FLS's production `TASKS` it does not.
- `BulkActionRun.__mro__` contains no `freedom_ls.site_aware_models` class.
