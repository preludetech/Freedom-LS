# Spec: downstream bugs, October 2026 bundle

## Purpose

A downstream project's QA run on 2026-10-28 found 14 defects in FLS (`idea.md` and the 14 `idea.md`
files in the subdirectories beside it). The project shadowed templates, subclassed the access
backend, swapped the signup form and deselected tests to work around them. Each fix below is what
has to be true in FLS for the matching workaround to be deleted, plus the fixes the project could
not work around at all.

## Scope

In: every defect in the 14 subdirectories, including all 17 sub-items of
`learner-ux-polish-from-mega-qa/idea.md`, with these resolutions from the question batch:

- ACCT-6: the emailed confirmation link carries the signup's `next`.
- LEARN-6: Mermaid fences get a `content_validate` warning; no client-side rendering.
- APP-5: an application whose course the learner is registered on leaves the dashboard panel.
- LEARN-8: "Leave and save" saves the current page's answers.
- LEARN-13: the time limit is labelled "Course time limit" on the dashboard and in the player
  outline, reversing deadlines-1's "Course".
- APP-7: the section pager writes `?page=N` into the URL with `hx-replace-url`, reversing the
  "paging never pushes a URL" decision.
- Notifications when `NOTIFICATIONS_ENABLED` is off: no code change. user-communication-1
  Decision 11 stands; the opt-out is documented.

Out:

- `settings-defaults-tests-assert-against-the-downstream-config-package` and the other filings in
  the downstream's `spec_dd/for_freedom_ls/` that have no directory here. The three
  `test_settings_defaults.py` deselects stay until that spec lands.
- Mermaid rendering, libphonenumber phone validation (`spec_dd/1. next/phone-number-form-field`),
  the profile page redesign (`spec_dd/1. next/user-profile-upgrades`), application approve/reject
  (`application-review-ui`).
- Content-side halves of the QA findings; those are the downstream's content to fix.
- Translations: changed strings are listed in the upgrade notes, not translated.

## Decisions

- **Container slots are converted and sanitised once, before cotton runs.** The second
  `render_markdown` pass is where `<c-equation>` output loses its attributes, and a
  `sanitize=False` path would let `[x](javascript:…)` in a slot become a live link. python-markdown's
  `md_in_html` extension gives one-pass nested rendering: every `c-*` block tag gets
  `markdown="1"` semantics except tags declared raw-bodied.
- **"Continue" targets `course_home`**, which already resolves the resume item. `course_home` must
  never redirect to an item `_blocked_item_redirect` would turn away, or Detail → Continue → detail
  loops with the new LEARN-12 message.
- **Header auth links fall back to the current page** (reversing the 2026-07-17 bare-URL
  criterion) with `url_with_next` untouched, because the signup page's in-form links rely on its
  pass-through.
- **Verbs are "Log in", "Log out", "Sign up"**, sentence case everywhere. `login.html` already
  says "Log in"; "Login" and "Sign Out" are the outliers.
- **The learner-facing noun for a `Form` follows its strategy**: "quiz" for `FormStrategy.QUIZ`,
  "form" otherwise. "test" and capitalised "Form" never appear.
- **The icon test asserts structure, not a literal.** `claude_plugins/fls-dev/resources/testing.md`
  line 58 prescribes a structural regex plus a flex case; the idea preferred reading the active
  set's dimensions, but the documented rule wins and the sibling test is already the flex case.
- **Zero-page forms are rejected only where a course places them.** Page-less application forms
  are a supported shape (`course_applications/views.py` `_resume_url`, `TestAPageLessForm`).
- **`correct: null` is normalised for display only.** Scoring treats it as neither required nor
  forbidden (`form_engine/tests/test_scoring.py`) and reports count it as a distractor; changing
  content would change scores.
- **Site-level values are `AppSettings`, not a model.** There is no `SiteConfig`; the meta
  description joins `SiteAwareModelsConfig`.
- **Profile name requirement follows the site's signup policy** via `apply_signup_name_policy`,
  so a site that does not require names keeps a blank-name learner editable.
- **The phone floor is 7 digits**, a named constant, deleted when libphonenumber validation lands.

## Requirements

### Markdown rendering: nested components inside container slots

`freedom_ls/markdown_rendering/markdown_utils.py::render_markdown`:

- Load `md_in_html`. Before conversion, every `c-*` tag in `config.MARKDOWN_ALLOWED_TAGS` is
  treated as a Markdown-bodied block (the `markdown="1"` semantics, including nested `<c-slot>`
  children such as flashcard `front`/`back`) unless its name is in a new
  `MarkdownRenderingConfig.MARKDOWN_RAW_BODY_TAGS` setting (`markdown_rendering/config.py`), whose
  default is `{"c-equation", "c-code-block"}`.
- `nh3.clean` runs once, on the converted author source, with the current allowlist. Cotton then
  expands components whose slots are already final HTML.

`pull-quote.html`, `flashcard.html` (both faces) and `table.html` emit their slot with
`{{ slot }}`; `table.html` keeps stripping its wrapper from the slot it now receives as a
rendered `<table>`. The comments in those files and in `grid.html` that describe the
re-sanitising limitation are replaced. The `{% markdown %}` tag in
`content_engine/templatetags/content_tags.py` stays for other callers.
