# Spec: downstream bugs, October 2026 bundle

## Purpose

A downstream project's QA run on 2026-10-28 found 14 defects in FLS (`idea.md` and the 14
subdirectory `idea.md` files beside it). This spec fixes all 14, so the project can delete the
workarounds it built for them.

## Scope

In: every defect in the 14 subdirectories, including all 17 sub-items of
`learner-ux-polish-from-mega-qa/idea.md`. Two of them reverse earlier decisions: LEARN-13 renames
the time limit "Course time limit" (deadlines-1 titled it "Course"), and APP-7 writes the section
pager's page into the URL (learner-dashboard-small-fixes and learner-facing-ux-refinements kept it
out). The notifications sub-item makes no code change: user-communication-1 Decision 11 stands,
and the opt-out is documented.

Out:

- `settings-defaults-tests-assert-against-the-downstream-config-package` and the other filings in
  the downstream's `spec_dd/for_freedom_ls/` that have no directory here. The three
  `test_settings_defaults.py` deselects stay until that spec lands.
- Mermaid rendering, libphonenumber phone validation (`spec_dd/1. next/phone-number-form-field`),
  the profile page redesign (`spec_dd/1. next/user-profile-upgrades`), application approve/reject
  (`application-review-ui`).
- Content-side halves of the QA findings; those are the downstream's content to fix.
- Translations: changed strings are listed in the upgrade notes, not translated.

## Decisions

- **No `sanitize=False` path.** The second `render_markdown` pass is where `<c-equation>` output
  loses its attributes, but it is also where a slot's `[x](javascript:…)` first becomes an `<a>`.
  Nested Markdown is therefore converted in the first pass, with python-markdown's `md_in_html`.
- **`course_home` never redirects to a blocked item.** With "Continue" pointing at it and the
  LEARN-12 message on the blocked-item redirect, a stale resume pointer would otherwise loop
  Detail → Continue → Detail.
- **`url_with_next` stays untouched.** The signup page's in-form links rely on its pass-through;
  the header gets its own tag.
- **The icon test asserts structure**, per `claude_plugins/fls-dev/resources/testing.md` line 58;
  the idea's preference for reading the active set's dimensions loses to the documented rule.
- **Page-less application forms stay supported** (`course_applications/views.py` `_resume_url`,
  `TestAPageLessForm`), so the zero-page rule applies only to forms a course places.
- **`correct: null` stays `None` in the data.** Scoring treats it as neither required nor
  forbidden (`form_engine/tests/test_scoring.py`) and reports count it as a distractor; only the
  review page's verdict changes.
- **Site-level values are `AppSettings`.** There is no `SiteConfig` model.
- **The profile form's name rule follows the site's signup policy**, so a site that does not
  require names keeps a blank-name learner editable.
- **"You're enrolled" is the learner-facing copy**, beside "Enrol for free"; identifiers keep the
  `enrolment_` prefix of their sibling `enrolment_summary`.

- Loads `md_in_html`. A python-markdown `Preprocessor`, registered with a priority between
  `fenced_code` (25) and `md_in_html`'s `html_block` (20) so fenced examples are untouched, gives

## Open questions

Defaults taken after the review wave; overrule by editing the named section.

- Q: Which tags get Markdown bodies? → A: every allowed `c-*` tag except `MARKDOWN_RAW_BODY_TAGS`
  (assumed default: a downstream lists its leaf tags rather than its containers. The alternative is
  a `MARKDOWN_BODY_TAGS` allow-list of containers. Markdown rendering.)
- Q: How is the `<title>` suffix composed? → A: a block tag around `head_title` (assumed default:
  Django cannot test a block's emptiness. The alternative keeps the full title per template with
  a shared suffix partial. Base templates › `<title>`.)
- Q: Where does the zero-page rule learn which forms a course places? → A: a Django-free helper
  extracted from `content_save` (assumed default: one definition of "placed". The alternative
  reimplements a directory rule in `validate.py` and accepts drift. Content validation.)
- Q: Does the sidebar fixture parametrise? → A: a factory fixture (assumed default: avoids
  doubling every test in the file. Portable tests.)
