## accordion-strips-nested-component-attributes

**Current locations.** `render_markdown` `fd/markdown_rendering/markdown_utils.py:15`; markdown convert `:33`; `nh3.clean` `:55-57` (idea `:53-55`); cotton compile+render `:59-71` (idea `:59-66`); `{% markdown %}` tag `fd/content_engine/templatetags/content_tags.py:139-147` (idea `:140-147`; the tag passes only `request`, no context). Cause analysis is correct. `{% markdown ... %}` is used by `content_engine/templates/cotton/`: `accordion.html:77`, `card.html:47`, `admonition.html:33`, `pull-quote.html:26`, `flashcard.html:191,215` (front/back), `table.html:21` (`{% markdown slot as rendered_table %}`). `grid.html:10-25` and `image-grid.html:9` already emit `{{ slot }}` for exactly this reason. The idea lists `card/admonition/grid/table/pull-quote` but misses `flashcard`, and `grid` is already safe.

**Why the idea's Option 1 is unsafe.** The first `markdown.convert` treats `c-*` tags in `MARKDOWN_ALLOWED_TAGS` as block-level and leaves their bodies as raw Markdown text (`docs/how tos/custom-content-widgets.md:65-67`). The second `render_markdown` is where the slot's Markdown first becomes HTML (links, images, lists). That is the pass that must be sanitised: `[x](javascript:...)` only becomes an `<a href>` there. A `sanitize=False` path would open that hole. A safe fix keeps sanitising Markdown-derived HTML but not component output. Options for the spec: (a) expand nested cotton first, with only the author text sanitised, then convert Markdown on slot text before components expand; or (b) sanitise the converted slot and keep nested component output as trusted placeholders. Reviewer memory: `.claude/agent-memory/ds-code-reviewer/project_markdown_widget_pipeline.md` ("cotton output is trusted, slot re-sanitised").

**Touch list.** `markdown_utils.py`; `content_tags.py::markdown`; the six templates above (comments in `accordion.html:5-40`, `table.html:13-16`, `grid.html:10-13`, `flashcard.html:89` describe the limitation); `docs/how tos/custom-content-widgets.md:60-67`.
**Docs that state the limitation and go stale if fixed**: `claude_plugins/fls-content/skills/widget-reference/resources/c-table.md:28-37`, `claude_plugins/fls-content/skills/markdown-conversion/resources/conversion-patterns.md:37`, `docs/product/content-editing-workflow.md:155`.
**Reuse.** `render_markdown`, `{% markdown x as var %}`, cotton `{{ slot }}`; the existing `c-equation` template (`cotton/equation.html`) for the regression (`x-data="equation"`, `role="math"`, `tabindex`).
**Conflicts.** `fd/markdown_rendering/tests/test_markdown_utils.py:545` `test_c_table_wrapper_is_stripped_inside_a_markdown_slot` (accordion and flashcard params) pins the current limitation and must be inverted.
