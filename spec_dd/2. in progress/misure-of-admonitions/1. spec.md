# Spec: theme-fit callouts for app pages

Idea: `idea.md`. Recorded answers: `answers.md`. Research: `research_*.md` in this directory.

## Purpose

App pages show status messages through `<c-callout>`, which carries the course-content look, and
through `<c-panel-notice>`, which only panels and dialogs use. Neither fits the learner and educator
design as a general component, and nothing keeps content-engine widgets out of app templates.

This work rebuilds `<c-callout>` in the base app with the app look, and adds its panel framework
counterpart, `<c-panel-callout>`, which FLS renders as `<c-callout>`. Together they replace
`<c-panel-notice>`, which is deleted, and a new test keeps content widgets out of app templates. The
content engine and `<c-admonition>` do not change.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| callout (`<c-callout>`) | narrowed | A static, toned status box in an app page, panel or dialog. Until now the word also covered the content look `<c-callout>` borrowed from the content engine; that look belongs to `<c-admonition>` only. The `.alert` theme classes (`tailwind.components.css`, `docs/how tos/theme-fls.md`) become this component's styling, renamed `.callout*`. |
| panel callout (`<c-panel-callout>`) | coined | The panel framework's callout, called by framework templates only. The framework ships a self-contained default; FLS overrides it with a thin wrapper around `<c-callout>`. The `panel-` prefix follows `extract_panels_framework-4-template-contract`: framework-owned cotton components are `panel-*`, so they never shadow or depend on a host's same-named component. Spec 4 already plans a `panel-callout` primitive; this is it. |
| content widget | narrowed | A content-engine cotton component that exists only for authored markdown: the banned list under "Guard test". `MARKDOWN_ALLOWED_TAGS` in `config/settings_base.py` is the wider list markdown may use. |
| toast | narrowed | The dismissible, fixed-position message from Django's messages framework (`base/templates/partials/messages.html`, `_toast.html`). Not a callout. |

"Admonition" is the word for the content-engine box. "Alert" stays the ARIA role (`role="alert"`)
and is not a component name.

## Scope

In:

- Rebuilding `<c-callout>` in `freedom_ls/base/templates/cotton/callout.html`.
- `<c-panel-callout>`: the framework default in `freedom_ls/panel_framework/templates/cotton/` and
  the FLS wrapper in `freedom_ls/base/templates/cotton/`.
- Migrating every `<c-callout>` use in `freedom_ls/` to the new attributes, every `<c-panel-notice>`
  use, and the hand-built error box in `base/templates/partials/form.html`.
- Deleting `<c-panel-notice>` and its tests.
- A guard test for app templates.
- Skills, brand guidelines, docs and upgrade notes.

Out:

- `freedom_ls/content_engine/` and `<c-admonition>`.
- Toasts.
- Field-level error text beside a field or control (such as `comms/partials/composer.html:88`).
- The dialog error summary (`panel_framework/partials/error_summary.html`). It is a validation summary that takes focus, a different job.
- Dismissing a callout.
- Copy changes to migrated messages, and merging the paused and access-ended pair in `course_detail.html`.
- First Class's `lp/step.html`. Downstream projects migrate through the upgrade notes.

## Decisions

- **One callout everywhere, with no aliases.** `c-panel-notice` is deleted and `c-callout` loses
  its content look, so every context has one right answer (`answers.md`). FLS templates, panel and
  dialog templates in FLS apps included, call `<c-callout>`. Templates under
  `freedom_ls/panel_framework/` call `<c-panel-callout>`, which renders as `<c-callout>` in FLS, so
  both look the same.
- **The panel framework never calls `<c-callout>`.** The framework is being extracted
  (`extract_panels_framework-4-template-contract`). Its templates may call only `panel-*` components
  and `c-icon`, and they rely on no FLS CSS class. So `<c-panel-callout>` follows that spec's
  primitive pattern now: a self-contained framework default, overridden by an FLS wrapper in
  `freedom_ls/base/templates/cotton/`. That wrapper wins because `freedom_ls.base` comes before
  `freedom_ls.panel_framework` in `INSTALLED_APPS`. `panel-callout` replaces `panel-notice`.
- **The attribute is `tone`**, the name `c-panel-notice` and `c-button` already use. `level` is
  gone, and the guard test rejects it on `<c-callout>`.
- **The look is `c-panel-notice`'s.** A tinted box with a thin full border, `rounded-md`, and no
  outer margin; the parent spaces its children. The left stripe and large title are the content
  look.
- **The styling lives in the `.callout` theme classes**, renamed from the unused `.alert` family, so
  a theme reshapes every callout in one place. Panel callouts reach these classes through the FLS
  wrapper. The framework default uses utility classes on theme tokens instead, because the framework
  cannot depend on FLS CSS.
- **Live roles follow `c-panel-notice`.** `error` gets `role="alert"`, `success` gets
  `role="status"`, and `info` and `warning` get none because they are read in place. The HTMX
  error re-renders and their tests already rely on this.
- **Every tone shows a decorative icon** (`aria-hidden`). The tone never relies on colour alone
  (WCAG 1.4.1).
- **The title is not a heading.** Its right level depends on where the callout sits, and most
  callouts are one sentence.

## Requirements

### The component

`freedom_ls/base/templates/cotton/callout.html`, rewritten:

```html
<c-callout tone="info|success|warning|error" title="…">One or two sentences.</c-callout>
```

- `<c-vars tone="info" title="" class="" />`. An unknown tone renders as `info`, never nothing.
- The outer box is `class="callout callout-{{ tone }}{% if class %} {{ class }}{% endif %}"`,
  followed by `{{ attrs }}`, so `id`, `data-testid`, `tabindex` and `hx-*` pass through.
- Layout lives in the template: a flex row with a gap, the `<c-icon>` first with `shrink-0` and a
  `callout-icon` class, then the title and the default slot. Icon names follow
  `partials/_toast.html`: `info`, `success`, `warning`, `error`.
- `title` renders as `<strong class="block font-semibold">` when given.
- The slot takes plain text, inline markup, a list or a `<c-button>`.
- No `text-sm`. The callout inherits the body size of its context, as the panel-framework rule for
  notices in dialog bodies requires.

`tailwind.components.css`, the `.alert` family becomes the `.callout` family:

- Rename `.alert`, `.alert-success`, `.alert-error` and `.alert-info` to `.callout*`. No template
  uses the `.alert` names today.
- Add `.callout-warning`.
- `.callout` padding is `p-3`.
- Each tone class sets `bg-<tone>/10 border-<tone>/20 text-on-surface`. Tone-coloured text fails
  contrast on these tints for warning and success.
- `.callout-<tone> .callout-icon` sets the icon colour to the tone, so a theme can repoint it.
- `freedom_ls/themes/first_class/static/themes/first_class/theme.css` overrides `.alert*` with
  `-light` tints. Rename each override to `.callout*`, keep it working, and add a first_class
  `.callout-warning` to match them.

### The panel callout

`<c-panel-callout>` has the same props, slot, attribute passthrough and role mapping as
`<c-callout>`:

```html
<c-panel-callout tone="info|success|warning|error" title="…">One sentence.</c-panel-callout>
```

- The framework default, `freedom_ls/panel_framework/templates/cotton/panel-callout.html`, renders
  the same structure as `<c-callout>` (icon, title, slot, roles, unknown tone as `info`). It uses
  token utility classes (`bg-<tone>/10 border-<tone>/20 text-on-surface rounded-md border p-3`) and
  `c-icon`. It uses no FLS class, component, tag or partial. Its icon names are `info`, `success`,
  `warning` and `error`, which `REQUIRED_ICON_NAMES` already plans to list.
- The FLS wrapper, `freedom_ls/base/templates/cotton/panel-callout.html`, renders
  `<c-callout tone="{{ tone }}" title="{{ title }}" {{ attrs }}>{{ slot }}</c-callout>` and passes
  `class` through too.

  - `course_applications/templates/course_applications/form_page.html`

    box stays an `error` callout like the rest.

### Deletions

- `freedom_ls/panel_framework/templates/cotton/panel-notice.html` and
  `freedom_ls/panel_framework/tests/components/test_panel_notice.py`.
- `freedom_ls/panel_framework/tests/standalone_templates/cotton/callout.html`, the standalone tier's
  stand-in for `c-callout`. Nothing in the framework calls `c-callout` after the reference page
  migrates.
- The panel framework reference page (`panel_framework/reference/_examples.html`):
  - Its `callout-info` and `c-panel-notice` examples become one `c-panel-callout` example per tone.
  - `COMPONENT_NAMES` and the `c-panel-notice` test in `panel_framework/tests/test_reference.py` follow.

### Guard test

New `freedom_ls/base/tests/invariants/test_app_templates_use_app_components.py`, in the shape of
`freedom_ls/icons/tests/invariants/test_no_font_awesome.py`: a scan with a carve-out, parametrised
per banned tag.

- It scans `freedom_ls/*/templates/**/*.html`, except `freedom_ls/content_engine/templates/`, where
  the widgets live and nest.
- It skips text inside `{% comment %}…{% endcomment %}` and `{# … #}`.
- A tag matches as `<c-NAME(?![\w-])`, so `<c-card` does not catch a future `<c-card-…>`.
- These tags are banned:
  - The content widgets: `c-admonition`, `c-accordion`, `c-flashcard`, `c-pull-quote`, `c-equation`,
    `c-youtube`, `c-pdf-embed`, `c-file-download`, `c-code-block`, `c-table`, `c-picture`,
    `c-image-grid`, `c-card`, `c-content-link` and `c-article-link`.
  - The deleted component: `c-panel-notice`.
- A `<c-callout` or `<c-panel-callout` tag carrying a `level=` attribute fails, naming `tone`.
- App templates may still use the other content-engine components: `c-course-price`,
  `c-organisation-byline`, `c-organisation-mark`, `c-article-byline`, `c-article-card` and `c-grid`.
- A failure names the file, the tag and the fix: "use `<c-callout>` for a status message in an app
  page; content widgets are for authored markdown only".
- The reference page escapes any banned tag it shows as sample code.

Related tests:

- `panel_framework/tests/invariants/test_templates.py` `FORBIDDEN_IN_DIALOGS` drops its
  `<c-callout>` entry, because `<c-callout>` is now the right box in an FLS dialog. Its hand-built
  `bg-error/10` box rule stays. Its message names `<c-panel-callout>` for framework templates and
  `<c-callout>` for FLS templates.
- The same module gains a rule that no template under `freedom_ls/panel_framework/templates/` calls
  `<c-callout(?![\w-])`. Spec 4's "no FLS component" invariant later covers this rule.
- `learner_interface/tests/views/test_course_player.py` `test_the_closed_notice_is_not_a_callout`
  keeps its name. It asserts that no node under the notice's parent has the `callout` class, so the
  "a page a person cannot use is never a boxed callout" rule stays guarded.

## Testing

- Component tests (`freedom_ls/base/tests/components/test_callout_component.py`, rewritten):
  - each tone renders `callout callout-<tone>` and its icon
  - an unknown tone renders as `info`
  - the role mapping for all four tones
  - the title renders as non-heading text
  - a passed `class` merges into the one class attribute
  - `id` and `data-testid` land on the box
- Panel callout tests (`freedom_ls/panel_framework/tests/components/test_panel_callout.py`):
  - The framework default, rendered from the framework's templates directory: each tone's tint
    classes and icon, the role mapping, an unknown tone as `info`, attribute passthrough, and no
    `callout` class.
  - Under FLS settings, `<c-panel-callout>` renders HTML equal (parsed and normalised) to
    `<c-callout>` for each tone, with a title, a `class` and a `data-testid`.
  - The framework's standalone tier passes with the default.
- The guard test fails on a fixture holding `<c-admonition>`, `<c-panel-notice>` or
  `<c-callout level="info">`, passes on `<c-course-price>` and `<c-callout tone="info">`, and
  ignores a banned tag inside either comment form.
- Feature tests that find a migrated callout by text, `data-testid` or `role` pass without changes to
  their assertions.
- Frontend QA covers each migrated page at the QA viewports:
  - the callout's width matches its container
  - the spacing around it holds
  - tint, text and icon are readable for every tone in both themes

## Open questions

- Q: Should the login page's "New here?" prompt become a plain line under the form instead of a callout? → A: It stays an `info` callout. (assumed default: the migration is like-for-like. Overrule by editing "Migrations".)
- Q: Should the developer-only "UNHANDLED FORM TYPE" box in `question.html` raise an exception instead? → A: It stays an `error` callout. (assumed default: failure behaviour is outside this spec. Overrule by editing "Migrations".)
- Q: Product docs call some of these boxes a "notice". Should they say "callout"? → A: No, product docs keep "notice" for what a person reads, and "callout" is the component name. (assumed default: reader-facing wording is not a code identifier. Overrule by editing "Documentation and downstream".)
- Q: Should the callout offer a compact size? → A: No, one size that inherits its context's text size. (assumed default: the panel and page uses differ only in text size. Overrule by editing "The component".)

## Success criteria

- `grep -rn '<c-panel-notice' freedom_ls --include='*.html'` finds nothing.
- `grep -rnE '<c-(panel-)?callout[^>]*\blevel=' freedom_ls --include='*.html'` finds nothing.
- `grep -rn '<c-callout[ >/]' freedom_ls/panel_framework/templates` finds nothing.
- `git diff main -- freedom_ls/content_engine` is empty.
- Adding `<c-admonition>` to any app template fails `uv run pytest`.
- `uv run pytest` passes.
- `tailwind.components.css` holds `.callout-warning` and no `.alert` rule.
- No skill, brand guideline or how-to offers `<c-panel-notice>` or `<c-callout level=…>`.
- The spec directory holds `upgrade_notes.md` with the removal and the mapping.
