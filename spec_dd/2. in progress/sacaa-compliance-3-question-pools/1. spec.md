# Spec: question pools, drawing N questions per attempt

Idea: `idea.md`. Up-front answers: `answers.md`. Research: the `research_*.md` files beside them.

## Purpose

Every sitting of a QUIZ form serves every question on every page, so a learner who fails can
rehearse the same paper, and an ATO cannot build SACAA-style syllabus-weighted papers. An author
sets `draw: N` in a page's FORM_PAGE section; each sitting is served N shuffle units drawn at
random from that page, and the draw is written into the served paper when the sitting starts.
Every sitting of the form is scored out of the same total.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| drawing page | coined | A `FormPage` whose `draw` is set. Its shuffle units are the pool the draw picks from. |
| shuffle unit | narrowed | `shuffle_units` in `freedom_ls/form_engine/served_paper.py`, from `sacaa-compliance-2-shuffle`. Here it is also the draw unit: a single question or a whole keep-together group. Author-facing text says "questions or groups". |

"Sitting" means `FormProgress` and "served paper" means `FormProgress.served_paper`, as in the
domain glossary and the shuffle spec.

## Scope

In: the `draw` key in the FORM_PAGE section (schema, model, migration, `content_save`); the draw
inside `build_served_paper`; a new validator pass; the learner start-screen question count; the
educator content preview; the `fls-content` authoring documentation, the bundled validator copy
and a pool demo course.

Out: everything `idea.md` lists as out of scope. Also out: an "always include" flag on a unit
(QTI's `required`), avoiding questions seen on an earlier sitting, a learner-facing "your paper is
drawn" notice, a validator warning on small pools (pool size is authoring guidance, and a draw of
all units stays valid), and exposing `draw` in the admin (spec 2 left the sibling fields out too).

## Decisions

- **Draw before shuffle, in its own RNG scope.** `_scope_rng(seed, f"draw:{page.id}")`, never
  `page:{page.id}` or `pages`, so toggling a shuffle knob or editing another page leaves the drawn
  set unchanged for the same seed. The stored list is the record; nothing redraws from the seed.
- **Drawn units keep authored order unless `shuffle_questions` is on.** Pick indices with
  `rng.sample(range(len(units)), n)` and sort them; the existing page shuffle then reorders.
  `rng.sample(units, n)` as the final order would shuffle a page whose shuffle is off.
- **The served paper keeps its shape** (`seed`, `pages[{id, children}]`, `options`). Undrawn
  children are absent, so every reader that already walks the served paper (scoring, results,
  incorrect answers, navigation, resume, paging counts, reports) is correct without change.
- **The validator forms units itself.** `validate.py` and its bundled copy are Django-free, so the
  pass groups consecutive children by truthy `group` with `itertools.groupby`, the rule
  `shuffle_units` uses, and never imports `served_paper`.

## Requirements

### Schema (`freedom_ls/form_engine/schema.py`)

`FormPage` gains `draw: int | None = Field(None, ge=1, description=...)`. A bare `draw:` (YAML
null), a `bool` and a `float` are schema errors, following the `_reject_bare_sections` and
`Condition._literal_as_str` guards. The non-QUIZ rule needs the form's strategy, so it lives in
the validator.

### Model and migration (`freedom_ls/form_engine/models.py`)

`FormPage.draw = PositiveSmallIntegerField(null=True, blank=True, validators=[MinValueValidator(1)],
help_text=...)`, help text in the style of `Form.shuffle_*`. Only null means "no draw"; code tests
`page.draw is not None`. One new `form_engine` migration with a single `AddField`; existing rows
are null and nothing is backfilled.

### `content_save` (`freedom_ls/content_engine/management/commands/content_save.py`)

`save_with_uuid` dumps with `exclude_none=True`, so `save_form_page` passes `draw=item.draw`
explicitly, as it does for `condition_option`. Removing `draw:` from a file and re-saving resets
it to null.

### Validator (`freedom_ls/content_engine/validate.py`)

A new pass, `validate_form_draw`, runs after `validate_form_shuffle` in `validate()`. It walks
`_form_pages`, reports through a `_draw_error` wrapper of `_form_error` with header
`"Invalid draw"`, and reports every error in one run. A page-level error targets
`_target_label(page, 0)`; a unit is named by its first child's `_target_label`.

The split-group and cross-page-group checks inside `validate_form_shuffle` move into one shared
predicate that both passes call. The draw pass skips a page that predicate flags, since its units
are not well formed and the shuffle pass already reports it.

| Rule | Problem / fix |
| --- | --- |
| `draw` on a page of a non-QUIZ form | `draw is only allowed on QUIZ forms (this form is <strategy>).` / `Remove draw, or change the form's strategy to QUIZ.` |
| `draw` greater than the page's unit count | `draw is <N>, but this page has <M> questions or groups to draw from.` / `Lower draw to <M> or less, or add questions to the page.` |
| A unit with no question: a `FormContent` outside any group, or a group of content only | `<unit label> has no question to travel with on a drawing page.` / `Put it in a group with the questions it introduces.` |
| Units with different question counts | `questions and groups on a drawing page must each hold the same number of questions; <first unit> holds <a> and <first unit that differs> holds <b>.` / `Split the page so each page's questions or groups are the same size.` |

Questions are counted per unit; a content block inside a group does not count. `when` on a
drawing page is already rejected by `validate_form_conditions`.

### The draw (`freedom_ls/form_engine/served_paper.py`)

`_served_children(page, form, seed)` forms `shuffle_units(page.children())`, then, when
`page.draw is not None`, keeps `min(page.draw, len(units))` of them as Decisions says, then
shuffles with the page RNG when `form.shuffle_questions` is on, then flattens. A page with no draw
creates no draw RNG. `build_served_paper`'s seed comment says the seed drives the one-time draw
and shuffle.

### Learner start screen and educator preview

- A new draw-aware count in `freedom_ls/form_engine/queries.py`, beside `count_form_questions`,
  loads the form's pages and children (prefetched with the served-tree lookups). For a drawing
  page it counts `min(draw, units) × the first unit's question count`; for any other page, its
  questions.
- `view_form` (`freedom_ls/learner_interface/views.py:1877`) uses it for `question_count`. The page
  count stays `form.pages.count()`: a draw never removes a page.
- `_form_preview_context` (`freedom_ls/educator_interface/panels/course/content_preview.py:317-357`)
  uses it for `question_count`, so the `form_facts.html` chip shows the per-sitting count. It also
  adds the page's `draw`, unit count and questions per unit. On a drawing page,
  `modal/content_preview.html` shows one line under the page heading: "Draws 5 of 12 questions
  per attempt", or "Draws 2 of 6 groups (4 questions) per attempt" when the units are groups. The
  preview keeps listing every question; it is educator-only.
- The QA seed commands that call `count_form_questions` keep it.

### Guards to verify

The upload guard (`_owned_file_question` in `freedom_ls/form_engine/views.py`) and the answer
save path in `form_fill_page` must not store an answer for a question absent from the served
paper. The implementer checks both against a drawn paper first; where one stores it, the fix is
in scope.

## Testing

- Schema: zero, negative, bare, boolean and float `draw` values fail; a positive integer parses.
  The model field rejects 0.
- Validator: each rule in the table fails with its message; pages of single questions, of
  equal-size groups, and with a draw equal to the unit count pass. A split group on a drawing
  page reports only the shuffle error. A drawing QUIZ page with `when` fails with the existing
  conditions message.
- `content_save` stores `draw` and resets it when the key is removed.
- The draw, with the seed patched through `new_seed`: each drawing page serves exactly `draw`
  units, a group whole with its content first, in authored order when `shuffle_questions` is off;
  every unit is drawn over a seed range; toggling a shuffle knob or editing another page leaves
  the drawn set unchanged; `draw` above the unit count serves every unit without raising.
- Learner flow on a drawn paper: counts and numbering cover drawn questions only, reload and
  resume show the same items, a failing learner's retake with a different seed draws a different
  set, `max_score` is equal across sittings, and the results page shows no outdated-score notice.
- No leak: the start screen, the results page and `get_incorrect_quiz_answers` never show an
  undrawn question or the pool size, and an answer or upload for an undrawn question is not
  stored.
- Educator preview: the line shows for questions and for groups, not on a page with no draw; the
  chip shows the per-sitting count.
- Reports: `build_sat_questions` pairs a question only with the sittings that drew it.
- The bundled validator copy's tests pass and it imports nothing from `freedom_ls`.
- Existing quiz, shuffle and served-paper tests pass unchanged.

## Open questions

- Q: What does `build_served_paper` do when `draw` exceeds the page's units, or a page has mixed
  unit sizes, after an edit outside `content_save` (admin delete)? → A: It serves
  `min(draw, units)` and draws as normal; `max_score` can then vary (assumed default: never blocks
  a learner, matches spec 1's missing-item behaviour, and the validator catches it on the next
  save. Overrule by editing The draw.)
- Q: Should the served paper record that a page was drawn, and from how many units? → A: No.
  `sacaa-compliance-4-attempt-review` reads `FormPage.draw` and the live units (assumed default:
  keeps the paper's shape, as spec 2 did for groups. Overrule by editing Decisions.)
- Q: Should learners be told their paper is drawn from a larger set? → A: No (assumed default:
  any count leaks the pool size, and spec 2 left out its "this quiz is shuffled" notice too.
  Overrule by editing Scope.)
- Q: Should the educator preview chip show the pool total too? → A: No, it shows the per-sitting
  count; the page line carries the pool size (assumed default: the chip then matches what a
  learner is scored on. Overrule by editing Learner start screen and educator preview.)

## Success criteria

- `uv run manage.py content_validate` passes on the demo content, and fails with the matching
  message on a copy with `draw` above a page's unit count, or with a mixed page.
- On the pool demo, two sittings with different seeds serve different questions, the same number
  per page, with the same `max_score`.
- A learner on the pool demo never sees an undrawn question or the pool size, on the start
  screen, the page flow or the results page.
