# Spec: question pools, drawing N questions per attempt

Idea: `idea.md`. Up-front answers: `answers.md`. Research: `research_codebase.md`,
`research_best_practices.md`, `research_reference_implementations.md`, `research_prior_art.md`,
`research_ux_patterns.md`, `research_known_complaints.md`, `research_question_bank_patterns.md`.

## Purpose

Every sitting of a QUIZ form serves every question on every page, so a learner who fails can
rehearse the same paper, and an ATO cannot build SACAA-style syllabus-weighted papers. An author
sets `draw: N` on a page header; each sitting is served N shuffle units drawn at random from that
page, and the draw is written into the served paper when the sitting starts. Every sitting of the
form is scored out of the same total.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| drawing page | coined | A `FormPage` whose `draw` is set. Its shuffle units are the pool the draw picks from. |
| shuffle unit | narrowed | `served_paper.shuffle_units`, from `sacaa-compliance-2-shuffle`. Here it is also the draw unit: a single question or a whole keep-together group. |

"Sitting" means `FormProgress` and "served paper" means `FormProgress.served_paper`, as in the
domain glossary and the shuffle spec.

## Scope

In: the `draw` key on the page header (schema, model, migration, `content_save`); the draw inside
`build_served_paper`; a new validator pass; the learner start-screen question count; the educator
content preview line; tests; the `fls-content` authoring documentation, the bundled validator copy
and a pool demo course.

Out: everything `idea.md` lists as out of scope (sections as pools, shared banks, weighted or
tagged draws, retake rules, the served-paper storage and shuffle knobs, the educator per-attempt
view and export, frozen question text). Also out: an "always include" flag on a unit (QTI's
`required`), avoiding questions seen on an earlier sitting, a learner-facing "your paper is drawn"
notice, a validator warning on small pools, and exposing `draw` in the admin (spec 2 left the
sibling fields out too).

## Decisions

- **Draw before shuffle, in its own RNG scope.** `_scope_rng(seed, f"draw:{page.id}")`, never
  `page:{page.id}` or `pages`, so toggling a shuffle knob or editing another page leaves the drawn
  set unchanged for the same seed. The stored list is the record; nothing redraws from the seed.
- **Drawn units keep authored order unless `shuffle_questions` is on.** Pick the indices with
  `rng.sample(range(len(units)), n)`, sort them, then let the existing page shuffle reorder.
  `rng.sample(units, n)` as the final order would shuffle a page whose shuffle is off.
- **The served paper keeps its shape** (`seed`, `pages[{id, children}]`, `options`). Undrawn
  children are absent. Every reader that already walks the served paper (scoring, results,
  incorrect answers, navigation, resume, paging counts, the upload guard, reports) needs no code
  change, only tests.
- **The validator forms units itself.** `validate.py` and its bundled copy are Django-free, so the
  pass groups consecutive children by truthy `group` with `itertools.groupby`, the same rule as
  `shuffle_units`. It does not import `served_paper`.
- **Pool size guidance is documentation, not a warning.** A draw of all units stays valid (it only
  reorders).

## Requirements

### Schema (`freedom_ls/form_engine/schema.py`)

`FormPage` gains `draw: int | None = Field(None, ge=1, description=...)`. A bare `draw:` (YAML
null), a `bool` and a `float` are schema errors, following the `_reject_bare_sections` and
`Condition._literal_as_str` guards. The non-QUIZ rule needs the form's strategy, so it lives in
the validator.

### Model and migration (`freedom_ls/form_engine/models.py`)

`FormPage.draw = PositiveSmallIntegerField(null=True, blank=True, help_text=...)`, help text in
the style of `Form.shuffle_*`. One new `form_engine` migration with a single `AddField`; existing
rows are null and nothing is backfilled.

### `content_save` (`freedom_ls/content_engine/management/commands/content_save.py`)

`save_with_uuid` dumps with `exclude_none=True`, so `save_form_page` passes `draw=item.draw`
explicitly, as it does for `condition_option`. Removing `draw:` from a file and re-saving resets
it to null.

### Validator (`freedom_ls/content_engine/validate.py`)

A new pass, `validate_form_draw`, runs after `validate_form_shuffle` in `validate()`. It walks
`_form_pages`, reports through a `_draw_error` wrapper of `_form_error` with header
`"Invalid draw"`, targets `_target_label(page, 0)`, and reports every error in one run. It skips a
page the shuffle pass already reports for a split or cross-page group, since its units are not
well formed.

| Rule | Problem / fix |
| --- | --- |
| `draw` on a page of a non-QUIZ form | `draw is only allowed on QUIZ forms (this form is <strategy>).` / `Remove draw, or change the form's strategy to QUIZ.` |
| `draw` greater than the page's unit count | `draw is <N>, but this page has <M> items to draw from.` / `Lower draw to <M> or less, or add items to the page.` |
| A unit with no question: a `FormContent` outside any group, or a group of content only | `<child label> has no question to travel with on a drawing page.` / `Put it in a group with the questions it introduces.` |
| Units with different question counts | `items on a drawing page must each hold the same number of questions; <label A> holds <a> and <label B> holds <b>.` / `Split the page so each page's items are the same size.` |

Questions are counted per unit; a content block inside a group does not count. `when` on a
drawing page is already rejected by `validate_form_conditions` (QUIZ forms take no `when`), so no
new rule is added for it.

### The draw (`freedom_ls/form_engine/served_paper.py`)

- `_served_children(page, form, seed)` forms `shuffle_units(page.children())`, then, when
  `page.draw` is set, keeps `min(page.draw, len(units))` of them as the Decisions above say, then
  shuffles with the page RNG when `form.shuffle_questions` is on, then flattens.
- `build_served_paper` needs no other change: options are only emitted for served questions. Its
  seed comment says the seed drives the one-time draw and shuffle.
- A page with no `draw` creates no draw RNG and serves as today.
- A retake is a new `FormProgress` with a new `new_seed()`, so it draws afresh with no new code.

### Learner start screen

`form_start` (`freedom_ls/learner_interface/views.py:1877`) shows
`count_form_questions(form)`, the pool total. A new draw-aware count, in
`freedom_ls/form_engine/queries.py` beside `count_form_questions`, sums per page
`draw × questions per unit` when `draw` is set and the page's question count otherwise. It
replaces the start-screen value and is reused by the educator preview. The page count stays
`form.pages.count()`: a draw never removes a page.

### Educator content preview

`_form_preview_context` (`freedom_ls/educator_interface/panels/course/content_preview.py:317-357`)
adds the page's `draw`, its unit count and its questions per unit. On a drawing page,
`modal/content_preview.html` shows one line under the page heading: "Draws 5 of 12 questions per
attempt", or "Draws 2 of 6 groups (4 questions) per attempt" when the units are groups. The
form-level chip in `form_facts.html` shows the draw-aware count. The preview keeps listing every
question; it is educator-only.

## Testing

- Schema: `draw: 0`, `draw: -1`, bare `draw:`, `draw: true` and `draw: 2.5` fail; `draw: 3` parses.
- Validator: one test per rule in the table, plus valid cases: a page of single questions, a page
  of equal-size groups, a draw equal to the unit count, a drawing page beside a page with no
  draw. A drawing QUIZ page with `when` fails with the existing conditions message. A page with a
  split group reports only the shuffle error.
- `content_save`: `draw` is stored, and removing it and re-saving resets it to null.
- `_served_children` / `build_served_paper`, with the seed patched through `new_seed`: each drawing
  page serves exactly `draw` units; a group is served whole with its content block first; with
  `shuffle_questions` off the drawn units are in authored order; over a seed range every unit is
  drawn at least once. For the same seed, toggling `shuffle_questions` or `shuffle_pages`, or
  editing another page, leaves the drawn set unchanged. A page with no draw is unchanged and
  touches no draw RNG. `draw` above the unit count (a row deleted outside `content_save`) serves
  every unit and does not raise.
- Learner flow on a drawn paper: page flow, "N of M answered" and numbering count drawn questions
  only; reload, back-navigation, an HTMX page post and resume show the same items; a failing
  learner's retake draws a different set when the seed differs. Score, `max_score`,
  `quiz_percentage()` and `passed()` read the drawn set, `max_score` is the same on two sittings
  with different seeds, and the results page shows no outdated-score notice.
- No leak: the start screen shows the draw-aware count; the results page and
  `get_incorrect_quiz_answers` never name an undrawn question; an answer or file upload for an
  undrawn question is not stored.
- Educator preview: the one line shows for questions and for groups, and not on a page with no
  draw; the chip shows the draw-aware count.
- Reports: `build_sat_questions` pairs a question only with the sittings that drew it.
- Existing quiz, shuffle and served-paper tests pass unchanged.

## Documentation and downstream

- `claude_plugins/fls-content/skills/content-types/resources/form-files.md`: a `draw` row in the
  FORM_PAGE table and a "Drawing questions from a page" section after "Shuffling a quiz". It states
  the four validator rules; that N counts items, so a page of two-question groups serves 2 × N
  questions; that a page holding a two-question stimulus and a lone question is split into two
  pages; that a pool should be of even difficulty and well over N items (at twice N, about half a
  retake repeats); that a retake may repeat questions; and that drawn forms carry no "see question
  3" references. It gives a two-subject example pointing at the demo course. The shuffle
  section's line on groups says groups are also the draw unit.

## Open questions

- Q: What does `build_served_paper` do when `draw` exceeds the page's units, or a page has mixed
  unit sizes, after an edit outside `content_save` (admin delete)? → A: It serves
  `min(draw, units)` and draws as normal; `max_score` can then vary (assumed default: never blocks
  a learner, matches spec 1's missing-item behaviour, and the validator catches it on the next
  save. Overrule by editing The draw.)
- Q: Should the served paper record that a page was drawn, and from how many units? → A: No.
  `sacaa-compliance-4-attempt-review` reads `FormPage.draw` and the live units (assumed default:
  keeps the paper's shape, as spec 2 did for groups. Overrule by editing Decisions.)
- Q: Should learners be told their paper is drawn from a larger set? → A: No (assumed default:
  any count leaks the pool size, and spec 2 left out its "this quiz is shuffled" notice too.
  Overrule by editing Scope.)
- Q: Should the educator preview chip show the pool total too? → A: No, it shows the per-attempt
  count; the page line carries the pool size (assumed default: the chip then matches what a
  learner is scored on. Overrule by editing Educator content preview.)

## Success criteria

- `uv run manage.py content_validate` passes on the demo content; on a copy with `draw` above a
  page's unit count, or a mixed page, it fails with the matching message.
- On the pool demo, two sittings with different seeds serve different questions, the same number
  per page, with the same `max_score`.
- A reload or resume of a drawn sitting shows the same questions.
- The start screen, the results page and the incorrect-answers list never show an undrawn
  question or the pool size.
- The educator preview of a drawing page shows the "Draws N of M" line.
- Existing quiz tests pass unchanged.
