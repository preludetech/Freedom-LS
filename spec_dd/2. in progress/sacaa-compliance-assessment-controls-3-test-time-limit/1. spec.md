# Spec: Quiz time limit

## Purpose

A QUIZ form can set a time limit in its front matter. The learner sees the limit before starting and a countdown while sitting. The server ends the sitting when the limit lapses: it marks the answers saved so far and records that time ran out, so an auditor can tell a lapsed clock from a learner pressing submit. The regulation line and brief are in `idea.md`.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| quiz time limit | coined | `Form.time_limit_minutes`: how long one sitting of a QUIZ form may run. Distinct from the course **time limit** (`Course.time_limit_days`, deadlines), which is calendar-based and per record. |
| sitting expiry | coined | `FormProgress.start_time` plus the form's current quiz time limit. Not a deadline: the deadlines app is not involved. |
| completion reason | coined | `FormProgress.completion_reason`: why a sitting was completed. |
| time-up post | coined | The `form_submit_and_exit` request the countdown sends with `time_up` set. |
| page post | coined | A time-up post or a `form_fill_page` POST: a request that carries the answers on the open page. |
| grace window | coined | `EXPIRY_GRACE` (10 seconds) after the sitting expiry, in which a page post is still saved. |

## Scope

In:

- A `time_limit_minutes` front matter field on QUIZ forms, default none.
- A completion reason on every sitting, with `learner_submitted` and `time_expired`, built so `sacaa-compliance-assessment-controls-5-test-disturbance` can add values.
- The limit on the start page, a countdown and two warnings in the runner, an automatic submit at expiry.
- Server enforcement on every request that touches an open sitting, and a housekeeping sweep.
- The completion reason and the recorded limit on the attempt review and in the cohort report attempts table; "Time ran out" on the learner's results page.

Out: everything in `idea.md` "Out of scope", and a control to hide the countdown.

## Decisions

- **The clock is wall-clock from `start_time`** and ignores leaving, logout and course pauses, so `kept_if_untouched_since` never spares an expired sitting.
- **Enforcement reads the form's current limit on every request.** A `content_save` that changes the limit moves the expiry of open sittings; one that removes it makes them untimed. Nothing is stored on the sitting for enforcement.
- **The sitting records the limit in force when it completed**, so the review stays true after an author edits the form.
- **A `time_expired` sitting's `completed_time` is the earlier of its sitting expiry and now.** A lapsed sitting found later by a request or the sweep gets the expiry instant, so cron lag never reads as overtime and a page post that lands in the grace window still reads as on time; a time-up post that lands just before expiry gets its real time, never a future one. `sacaa-compliance-assessment-controls-2-attempt-limits` measures waits from this value.
- **The client submits at 0:00.** The countdown posts the open page when it reaches zero, so the learner gets the whole limit.
- **Page posts have a 10-second grace window** (`EXPIRY_GRACE`) after the sitting expiry for network latency. A page post is a time-up post or a `form_fill_page` POST (Next, or submit on the last page). One that arrives within the window saves the posted page, then the sitting completes as `time_expired` and the learner lands on results. Any other request after expiry, and any page post after the window, saves nothing.
- **The server never trusts the client's claim that time is up.** It honours a time-up post only from 5 seconds before the sitting expiry (`TIME_UP_LEAD`, which covers the floored `remaining_seconds`) to the end of the grace window.
- **A manual submit that races the expiry completes as `time_expired`.** `complete()` re-checks expiry under its lock.
- **First completion wins.** A second `complete()` changes neither reason nor time.
- **Every route sends a learner whose sitting just expired to results**, including the start URL, so nobody starts a new sitting without seeing "Time ran out".
- **No extend control.** The limit is essential under WCAG 2.2.1: the regulation requires assessment when the test time lapses.

## Requirements

### Form field and content pipeline

- `freedom_ls/form_engine/models.py` `Form`: `time_limit_minutes = PositiveIntegerField(null=True, blank=True)` beside `quiz_pass_percentage`.
- `freedom_ls/form_engine/schema.py` pydantic `Form`: `time_limit_minutes: int | None = Field(default=None, gt=0)`, added to the QUIZ-only `knobs` in `validate_quiz_fields`. The `knobs` check tests truthiness, so `gt=0` is what rejects `0`.
- `freedom_ls/content_engine/management/commands/content_save.py` `save_form`: removing the key from `form.md` clears the stored value on the next load, as `save_course` does for `time_limit_days` (excluded from the dump, passed explicitly).
- Bundled schema `claude_plugins/fls-content/validate/schema.py`: the same field and `knobs` entry. Authoring docs `claude_plugins/fls-content/skills/content-types/resources/form-files.md`: a front matter row and the QUIZ-only note.
- `freedom_ls/educator_interface/panels/course/content_preview.py` `_quiz_facts`: a "Time limit" row, "None set" or the formatted limit.
- `demo_content/`: one timed QUIZ form, placed so it does not slow the QA of other demo quizzes.

### Sitting: reason, recorded limit, expiry

All in `freedom_ls/form_engine/models.py`, one migration with the `Form` field.

- `CompletionReason(models.TextChoices)` beside `FormStrategy`, exported in `__all__`: `LEARNER_SUBMITTED = "learner_submitted", "Learner submitted"` and `TIME_EXPIRED = "time_expired", "Time ran out"`.
- `FormProgress.completion_reason = CharField(choices=CompletionReason.choices, default=CompletionReason.LEARNER_SUBMITTED)`. Existing rows need no backfill.
- `FormProgress.time_limit_minutes = PositiveIntegerField(null=True, blank=True)`, written by `complete()` from the form, null when the form has no limit.
- `FormProgress.expires_at() -> datetime | None`: `start_time + timedelta(minutes=form.time_limit_minutes)`, or `None` with no limit. `FormProgress.is_expired(now) -> bool`: open, timed and `now > expires_at()` (strict, as `deadlines/consequences.py`). Every view, the time-up post, `remaining_seconds` and the sweep use these, so they cannot disagree on the boundary. `TIME_UP_LEAD = timedelta(seconds=5)` and `EXPIRY_GRACE = timedelta(seconds=10)` sit beside them. `FormProgress.in_grace(now) -> bool`: open, timed and `expires_at() < now <= expires_at() + EXPIRY_GRACE`. `FormProgress.accepts_time_up(now) -> bool`: open, timed and `expires_at() - TIME_UP_LEAD <= now <= expires_at() + EXPIRY_GRACE`.
- `complete(reason=CompletionReason.LEARNER_SUBMITTED)`: inside its atomic block it re-reads the row with `FormProgress._base_manager.select_for_update(of=("self",)).select_related("form")`, refreshes the instance from it (callers hold stale copies, and `save()` writes every field), and returns if `completed_time` is set. With the row's current form it then: turns `LEARNER_SUBMITTED` into `TIME_EXPIRED` when `is_expired(now)`; for `TIME_EXPIRED` sets `completed_time = min(expires_at(), now)`; stores the reason and `time_limit_minutes`. Existing callers keep the default reason.
- `FormProgress.complete_if_expired(now) -> bool`: completes an expired open sitting with `TIME_EXPIRED`, saving nothing posted, and returns whether it did.

### Request-time enforcement

`freedom_ls/learner_interface/views.py` gains one helper, `_complete_expired_sitting`, that looks up the learner's course progress record read-only through `course_progress_for` (`learner_progress/queries.py`), finds the open sitting at the placement, and calls `complete_if_expired`. It is the first step of `view_course_item` (form items), `form_start`, `form_declaration`, `form_fill_page`, `course_form_complete` and `form_submit_and_exit`: ahead of `_course_access_redirect`, `_form_start_gate`, `_blocked_item_redirect`, the pause and closed guards, `ensure_served_paper` and `record_page_reached`. So a paused, closed or access-ended learner's expired sitting completes too. When it completes a sitting, the route redirects to `course_form_complete`, whose access gate then finds a completed attempt; `course_form_complete` itself carries on and renders the result. A `form_fill_page` POST checks the grace window first ("Page posts at expiry"); one past the window is not saved.

`freedom_ls/learner_progress/attempts.py` keeps a backstop: `start_attempt` (first inside the `CourseProgress` lock, ahead of the `START_REUSE_WINDOW` reuse, `finalise_stale_incomplete` and the attempt count `sacaa-compliance-assessment-controls-2-attempt-limits` adds) and `close_left_signed_sitting` call `complete_if_expired`. `finalise_stale_incomplete` stays `submit_on_exit`-only for unexpired sittings.

### Page posts at expiry

One helper in `freedom_ls/learner_interface/views.py`, `_save_page_and_complete`, serves both page posts. In one `transaction.atomic()` it locks the sitting row as `complete()` does, re-checks `completed_time` and the window under the lock, saves the posted page with `submit_page(..., require_answers=False)`, ignoring the answers it rejects (it already stores only valid ones), then calls `complete(TIME_EXPIRED)`, which stamps `completed_time = min(expires_at(), now)`, and returns whether it completed the sitting. So no concurrent request can complete the sitting between the save and the completion, and no page is saved to a sitting that is already marked. A rejected answer never re-renders the page or leaves the sitting open. When it completes the sitting, the view redirects to `course_form_complete`.

Each view calls it as its first step, ahead of `_complete_expired_sitting`, which would otherwise complete a sitting in its grace window before the page is saved. When it does not complete the sitting, the view carries on as below.

`form_fill_page` POST:

- `in_grace(now)`: `_save_page_and_complete`, on any page.
- Otherwise: unchanged, after `_complete_expired_sitting`, so a POST past the window saves nothing.

`form_submit_and_exit` accepts a `time_up` field posted by the countdown. The `time_up` check also runs ahead of the existing `not form.submit_on_exit and not closed` refusal, so a timed quiz that saves on exit still auto-submits.

- Untimed sitting (no limit, or the limit was removed): `time_up` is ignored; behaviour is unchanged.
- `accepts_time_up(now)`: `_save_page_and_complete`.
- More than 5 seconds left: save nothing, complete nothing, redirect to the runner's current page.
- Past the grace window, or the sitting was already completed (by another request inside the window): fall through to `_complete_expired_sitting`; nothing is saved.

### Housekeeping sweep

`freedom_ls/deployment/housekeeping.py` `run_housekeeping_sweeps`: a new block in the existing shape, with a `notes` line giving the count.

- Read candidate pks without a lock through `FormProgress._base_manager` (no request site): open sittings whose form has a limit and whose expiry, annotated as `ExpressionWrapper(F("start_time") + F("form__time_limit_minutes") * Value(timedelta(minutes=1)), output_field=DateTimeField())`, plus `EXPIRY_GRACE` is before now, so the sweep never completes a sitting whose page post may still be in flight. No lower time bound.
- Per pk, in its own `transaction.atomic()`: re-select with `select_for_update(skip_locked=True, of=("self",))` and the same filter, skip if gone or locked, else `complete(reason=TIME_EXPIRED)`. A row raising `DatabaseError` or `ValueError` (scoring) counts in `sweep_failures` and the sweep continues.
- The only `form_attempt_completed` receiver, `learner_progress.signals.recalculate_course_progress_on_form_attempt`, needs no request site.

### Learner interface

- Start page, `freedom_ls/form_engine/templates/form_engine/partials/form_facts.html` (via `view_form`): the limit as a fact ("45 minutes", "1 hour 30 minutes"), and before the start button: "This quiz has a time limit of 45 minutes. The clock starts when you press Start and does not stop if you leave. When time runs out, your quiz is submitted with the answers you have saved."
- Runner, `freedom_ls/learner_interface/templates/learner_interface/course_form_page.html` and `_render_form_fill_page`:
  - The context carries `remaining_seconds` from `expires_at()` and the same `now` as the helper, floored, never negative.
  - A countdown in the top bar beside the answered count: a registered CSP-safe `Alpine.data` component in `learner_interface/static/learner_interface/js/alpine-components.js`. Elapsed time is the larger of the `performance.now()` and `Date.now()` deltas since load, so neither a changed device clock nor a suspended tab hides lost time. It recomputes on `visibilitychange` and `pageshow`; a `pageshow` with `persisted` reloads the page so the server decides. Format `m:ss` under an hour, `h:mm:ss` from an hour. The server-rendered initial text serves no-JS learners.
  - The countdown element has `role="timer"`, `aria-atomic="true"` and the accessible name "Time left". It is not a live region, and it never animates or flashes.
  - When the countdown reaches 0:00, once per page, the component sets the module's shared `runnerNavigating` flag (which also stops Next and Previous and the `beforeunload` guard), points `#runner-page-form`'s `action` at `form_submit_and_exit` (from a `data-` attribute), adds a hidden `time_up` input and calls `form.submit()`. A programmatic submit fires no submit event, so `examRunnerForm._onSubmit`'s required-answer check does not run.
  - Warnings, only when the limit is over 5 minutes, at 5 minutes and 1 minute left. Each is a visible inline callout under the top bar plus text in a dedicated live region present at page load, separate from the "Page N of M" region: polite at 5 minutes, assertive at 1 minute. A warning never takes focus. It is announced once, when crossed; a page loaded already past a threshold shows the callout silently. Copy: "5 minutes left. When time runs out, your quiz is submitted with your saved answers." and "1 minute left. This page is saved and submitted when time runs out."
  - Exit dialog on a timed quiz that saves on exit: "Your progress is saved — you can resume later." becomes "Your answers are saved. The time limit keeps running while you are away."
- Results page, `freedom_ls/learner_interface/templates/learner_interface/course_form_complete.html`: for a `TIME_EXPIRED` sitting, a line in the verdict banner: "Time ran out. Your quiz was submitted with the answers you had saved."

## Testing

Unit tests are pytest functions; boundaries use `time_machine.travel`. `start_time` is `auto_now_add`, so tests set it with `FormProgress.objects.filter(pk=...).update(start_time=...)`.

- Schema: `time_limit_minutes` accepted on QUIZ; rejected on other strategies; `0` and negatives rejected; the bundled schema agrees.
- `content_save`: setting the key stores it; removing it clears it.
- `is_expired`: false before and exactly at the sitting expiry, true after; false for untimed and completed sittings.
- `in_grace`: false at and before the sitting expiry, true after it to exactly 10 seconds after, false later; false for untimed and completed sittings.
- `accepts_time_up`: false more than 5 seconds before the sitting expiry, true from 5 seconds before to exactly 10 seconds after, false after; false for untimed and completed sittings.
- `complete()`: default reason; a lapsed `TIME_EXPIRED` stamps the expiry, an early one stamps now; the limit is recorded; a `LEARNER_SUBMITTED` call after expiry becomes `TIME_EXPIRED`; a second call changes nothing; two threads on their own connections (`@pytest.mark.django_db(transaction=True)`) complete once.
- An expired sitting with no answers scores 0 of the served paper's `max_score`; with some answers it marks those only.
- Each route in "Request-time enforcement" completes an expired open sitting and redirects to results, including for a paused course, a closed item, ended access and a quiz that saves on exit. `form_start` does not create a new sitting in that request. A `form_fill_page` POST within 10 seconds after expiry saves the page, completes as `time_expired` and redirects to results, on a middle page and on the last page, including with a required question unanswered and with an invalid answer; one later saves nothing.
- Time-up post: inside the window (5 seconds before to 10 seconds after expiry) saves the page and completes, including with a required question unanswered and with an invalid answer; one landing 8 seconds after expiry records `completed_time` at the expiry; more than 5 seconds left changes nothing; more than 10 seconds after expiry saves nothing and completes; on an untimed sitting behaves as a plain exit.
- A limit shortened by `content_save` expires an open sitting on its next request; a removed limit leaves it open.
- Sweep: completes expired sittings across sites; leaves a sitting inside its grace window; leaves unexpired and untimed ones; skips a row locked by a request; reports a failing row and carries on.
- Playwright (`learner_interface/tests/playwright/test_form_flow.py`), rewinding `start_time` in the database and waiting for the real countdown: the start page shows the limit; the countdown counts; the 1-minute callout shows and its live region holds the text; the auto-submit saves the open page and lands on results with "Time ran out".
- Educator: the attempt review shows the reason and recorded limit; the cohort report attempts table shows the reason on screen and in the PDF.

## Documentation and downstream

- Upgrade notes: a new `form_engine` migration. Operators must schedule `fls_run_housekeeping`: without it, a sitting whose learner never returns stays open, unscored and unseen by reports and attempt limits.
- Product docs: the quiz time limit and the completion reason.
- Collisions: `sacaa-compliance-assessment-controls-2-attempt-limits` (in progress) edits `start_attempt`, `_form_start_gate`, the `Form` schema and `knobs`, `save_form`, `_quiz_facts`, the demo quiz and the next `form_engine` migration number. `sacaa-compliance-assessment-controls-5-test-disturbance` (blocked by this spec) edits the same functions, the `examRunner` component and `form_submit_and_exit`, and adds values to `CompletionReason`.

## Open questions

- Q: How long a grace window do page posts get? → A: 10 seconds after the sitting expiry, and 5 seconds before it (assumed default: the user asked for "a few seconds"; 10 covers a slow mobile round trip. Overrule by editing `EXPIRY_GRACE` and `TIME_UP_LEAD` in "Sitting: reason, recorded limit, expiry".)
- Q: What reason do sittings completed because an item closed or access ended get? → A: `learner_submitted`, as today (assumed default: those paths predate this spec, and `sacaa-compliance-assessment-controls-5-test-disturbance` adds reasons. Overrule by editing "Sitting: reason, recorded limit, expiry".)
- Q: Should the learner's previous-attempts list and the educator learner Courses tab attempts table show the reason? → A: No (assumed default: the idea names the attempt review and the cohort report only. Overrule by editing "Educator surfaces".)

## Success criteria

- In a visible tab, a learner who sits until the clock runs out lands on results with "Time ran out", and the answers on the page open at the time are marked.
- A learner who closes the tab and returns after the sitting expiry lands on results, and the sitting's `completed_time` equals `start_time` plus the limit.
- `fls_run_housekeeping` completes an abandoned expired sitting with reason `time_expired`.
- A QUIZ without `time_limit_minutes` behaves as before: the existing form and runner tests pass unchanged.
