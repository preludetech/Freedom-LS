# Spec: Quiz time limit

## Purpose

A QUIZ form can set a time limit in its front matter. The learner sees the limit before starting and a countdown while sitting. The server ends the sitting when the limit lapses: it marks the answers saved so far and records that time ran out, so an auditor can tell a lapsed clock from a learner pressing submit. This answers the client-supplied regulation line "the programme shall assess the student when the exam/skills test time has lapsed regardless of the number of questions answered" (see `idea.md`).

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| quiz time limit | coined | `Form.time_limit_minutes`: how long one sitting of a QUIZ form may run. Distinct from the course **time limit** (`Course.time_limit_days`, deadlines), which is calendar-based and per record. |
| sitting expiry | coined | `FormProgress.start_time` plus the form's current quiz time limit. Not a deadline: the deadlines app is not involved. |
| completion reason | coined | `FormProgress.completion_reason`: why a sitting was completed. |

## Scope

In:

- A `time_limit_minutes` front matter field on QUIZ forms, default none.
- A completion reason on every sitting, with `learner_submitted` and `time_expired`, built so `sacaa-compliance-assessment-controls-5-test-disturbance` can add values.
- The limit on the start page, a countdown and two warnings in the runner, an automatic submit before expiry.
- Server enforcement on every request that touches an open sitting, and a housekeeping sweep.
- The completion reason, and the limit that applied, on the attempt review and in the cohort report attempts table. "Time ran out" on the learner's results page.

Out: everything in `idea.md` "Out of scope" (per-learner extra time, marking changes, disturbance, inactivity, topic or per-question timers, pausing the clock), a grace period, a hide-the-countdown control, and an extend control.

## Decisions

- **The clock is wall-clock from `start_time`** and ignores leaving, logout and course pauses. `kept_if_untouched_since` never spares an expired sitting.
- **Enforcement reads the form's current limit on every request.** A `content_save` that changes the limit moves the expiry of open sittings; one that removes it makes them untimed. No limit or expiry is stored on the sitting for enforcement.
- **The sitting records the limit in force when it completed** (`FormProgress.time_limit_minutes`), so the review stays true after an author changes the form.
- **An expired sitting's `completed_time` is its sitting expiry**, not when a request or the sweep noticed it, so cron lag never looks like overtime. `sacaa-compliance-assessment-controls-2-attempt-limits` measures waits from this value.
- **No grace period.** A page posted after the sitting expiry is not saved.
- **The client submits about 5 seconds early.** The countdown posts the current page when 5 seconds remain, so the post reaches the server before the sitting expiry and the page is saved. The learner loses those seconds; that is the price of no grace period.
- **The server never trusts the client's claim that time is up.** A time-up post is honoured as `time_expired` only when the server finds 15 seconds or fewer left (or the sitting already expired). Earlier, it is refused and the learner returns to the runner.
- **First completion wins.** `complete()` stays idempotent: a second call changes neither the reason nor the time.
- **No extend control.** The limit is an essential limit under WCAG 2.2.1: the regulation requires assessment when the test time lapses.

## Requirements

### Form field and content pipeline

- `freedom_ls/form_engine/models.py` `Form`: `time_limit_minutes = PositiveIntegerField(null=True, blank=True)` beside `quiz_pass_percentage`.
- `freedom_ls/form_engine/schema.py` pydantic `Form`: `time_limit_minutes: int | None = Field(default=None, gt=0)`. Add it to the QUIZ-only `knobs` in `validate_quiz_fields`. The `knobs` check tests truthiness, so `gt=0` is what rejects `0`.
- `freedom_ls/content_engine/management/commands/content_save.py` `save_form`: removing the key from `form.md` clears the stored value on the next load. Follow `save_course`'s handling of `time_limit_days` (exclude it from the dump and pass it explicitly).
- Bundled schema `claude_plugins/fls-content/validate/schema.py`: the same field and `knobs` entry. Authoring docs `claude_plugins/fls-content/skills/content-types/resources/form-files.md`: a front matter row and the QUIZ-only note.
- `freedom_ls/educator_interface/panels/course/content_preview.py` `_quiz_facts`: a "Time limit" row, "None set" or the formatted limit.
- `demo_content/`: one timed QUIZ form, placed so it does not slow the QA of other demo quizzes.

### Sitting: reason, recorded limit, expiry

All in `freedom_ls/form_engine/models.py`, one migration with the `Form` field.

- `CompletionReason(models.TextChoices)` beside `FormStrategy`, exported in `__all__`: `LEARNER_SUBMITTED = "learner_submitted", "Learner submitted"` and `TIME_EXPIRED = "time_expired", "Time ran out"`.
- `FormProgress.completion_reason = CharField(choices=CompletionReason.choices, default=CompletionReason.LEARNER_SUBMITTED)`. Existing rows need no backfill.
- `FormProgress.time_limit_minutes = PositiveIntegerField(null=True, blank=True)`: written by `complete()` from `form.time_limit_minutes`, left null when the form has no limit.
- `FormProgress.expires_at() -> datetime | None`: `start_time + timedelta(minutes=form.time_limit_minutes)`, or `None` when there is no limit. `FormProgress.is_expired(now) -> bool`: open, timed and `now > expires_at()` (strict, as `deadlines/consequences.py` does). Every view, the time-up post and the sweep use these two, so they cannot disagree on the boundary. The sweep's SQL annotation computes the same expression.
- `complete(reason=CompletionReason.LEARNER_SUBMITTED)`: stamps the reason; for `TIME_EXPIRED` sets `completed_time` to `expires_at()`; records `time_limit_minutes`. It locks the sitting row (`select_for_update`) and re-reads `completed_time` under the lock, so the runner, the time-up post and the sweep cannot complete one sitting twice. Existing callers keep the default reason.
- `FormProgress.complete_if_expired(now) -> bool`: under the same lock, completes an expired open sitting with `TIME_EXPIRED` and saves nothing posted. It returns whether the sitting is now completed by expiry.

### Request-time enforcement

`complete_if_expired` runs on the learner's open sitting for the placement before any access, pause, closed, blocked or declaration redirect, and before `ensure_served_paper` or `record_page_reached`. A paused, closed or access-ended learner's expired sitting is still completed. After completing, the request goes to `course_form_complete` (or the route's existing destination for learners whose access has ended).

- `freedom_ls/learner_progress/attempts.py`:
  - `start_attempt`: first thing inside the `CourseProgress` lock, ahead of the `START_REUSE_WINDOW` reuse, `finalise_stale_incomplete` and any attempt count `sacaa-compliance-assessment-controls-2-attempt-limits` adds. An expired attempt is then a completed attempt that counts.
  - `close_left_signed_sitting`: the same, for the declaration route.
  - `finalise_stale_incomplete` stays `submit_on_exit`-only for unexpired sittings.
- `freedom_ls/learner_interface/views.py`:
  - `view_course_item`: before the `paused`/`closed` guard around `finalise_stale_incomplete`. The start page then shows the result, not "Continue".
  - `form_start`: through `start_attempt`.
  - `form_fill_page`: before the POST branch. A page posted after the sitting expiry is not saved; the sitting completes and the learner lands on results.
  - `course_form_complete`: before `_course_access_redirect(route=FORM_RESULTS)`, which checks for a completed attempt, so a learner whose only sitting just expired reaches results.
  - `form_submit_and_exit`: see the time-up post below.

### The time-up post

`form_submit_and_exit` accepts a `time_up` field posted by the countdown.

- Sitting already expired: save nothing, complete with `TIME_EXPIRED`.
- `time_up` with 15 seconds or fewer left: save the posted page with `require_answers=False`, discarding answers that fail validation and keeping the rest, then complete with `TIME_EXPIRED`. Rejected answers never re-render the page or leave the sitting open.
- `time_up` with more than 15 seconds left: save nothing, complete nothing, redirect to the runner's current page.
- `time_up` passes the existing `submit_on_exit`/closed refusal: a timed quiz with save on exit still auto-submits.
- Without `time_up`, behaviour is unchanged.

### Housekeeping sweep

`freedom_ls/deployment/housekeeping.py` `run_housekeeping_sweeps`: a new block in the existing shape (its own `try/except DatabaseError`, a `notes` line with the count). It selects open sittings whose form has a limit and whose sitting expiry is past via `FormProgress._base_manager` (there is no request site), with `select_for_update(skip_locked=True)`, and calls `complete(reason=TIME_EXPIRED)` on each in its own transaction. A row that fails is counted in `sweep_failures` without stopping the rest. The query has no lower time bound. `form_attempt_completed` receivers must work without a request site; the plan confirms each one.

### Learner interface

- Start page, `freedom_ls/form_engine/templates/form_engine/partials/form_facts.html` (via `view_form`): the limit as a fact ("45 minutes", "1 hour 30 minutes"), and before the start button: "This test has a time limit of 45 minutes. The clock starts when you press Start and does not stop if you leave. When time runs out, your test is submitted with the answers you have saved."
- Runner, `freedom_ls/learner_interface/templates/learner_interface/course_form_page.html` and `_render_form_fill_page`:
  - The context carries `remaining_seconds`, computed by the server at render, floored, never negative.
  - A countdown in the top bar beside the answered count, a registered CSP-safe `Alpine.data` component in `learner_interface/static/learner_interface/js/alpine-components.js`. It anchors `remaining_seconds` to `performance.now()`, never `Date.now()`, and recomputes on `visibilitychange` and `pageshow`. Format `m:ss` under an hour, `h:mm:ss` from an hour. The server-rendered initial text is the value at load, for no-JS learners.
  - The countdown element has `role="timer"`, `aria-atomic="true"` and an accessible name "Time left". It is not a live region, so ticks are never announced. No animation or flashing.
  - At 5 seconds left the component disables further navigation, turns off the `beforeunload` guard, and posts `#runner-page-form` to `form_submit_and_exit` with `time_up`. The post bypasses `examRunnerForm._onSubmit`'s required-answer check. It fires once per page.
  - Warnings, only when the limit is over 5 minutes: at 5 minutes and at 1 minute left. Each one is a visible inline callout under the top bar and text in a dedicated live region present at page load, separate from the "Page N of M" region: polite at 5 minutes, assertive at 1 minute. A warning never takes focus. It is announced once when crossed; a page loaded already past a threshold shows the callout without announcing it. Copy: "5 minutes left. When time runs out, your test is submitted with your saved answers." and "1 minute left. This page is saved and submitted when time runs out."
  - Exit dialog on a timed quiz that saves on exit: "Your progress is saved — you can resume later." becomes "Your answers are saved. The time limit keeps running while you are away."
- Results page, `freedom_ls/learner_interface/templates/learner_interface/course_form_complete.html`: for a `TIME_EXPIRED` sitting, a line in the verdict banner: "Time ran out. Your test was submitted with the answers you had saved."

### Educator surfaces

- Attempt review, `freedom_ls/educator_interface/panels/learner/quiz_attempt.py` `QuizAttemptSummaryPanel.get_rows`: a "Completion reason" row (the choice label) and, when `time_limit_minutes` is set, a "Time limit" row from the sitting's recorded value.
- Cohort report attempts table: `QuizAttempt` in `freedom_ls/reports/report_data.py` gains `completion_reason` with a default, filled in `reports/gather.py` `_quiz_result_for` from the already-loaded sitting. `reports/templates/reports/partials/learner_detail.html` shows it as a column, with a `col-attempt-*` width rule in `reports/static/reports/print.css`, for screen and PDF.

## Testing

- Schema: `time_limit_minutes` accepted on QUIZ; rejected on other strategies; `0` and negatives rejected; the bundled schema agrees.
- `content_save`: setting the key stores it; removing it clears it on the next load.
- `FormProgress.is_expired`: false before, false exactly at, and true after the sitting expiry; false for untimed forms and completed sittings.
- `complete()`: the default reason is `learner_submitted`; `TIME_EXPIRED` stamps `completed_time` at the sitting expiry and records the limit; a second call changes nothing; concurrent completion from two connections completes once (`TransactionTestCase`, real row lock).
- An expired sitting with no answers completes and scores 0 of the served paper's `max_score`; with some answers it marks those only.
- Each route completes an expired open sitting and lands on results: `view_course_item`, `form_start`, `form_declaration`, `form_fill_page` GET and POST (POST not saved), `course_form_complete` with no earlier completed attempt, `form_submit_and_exit`. Also for a paused course, a closed item, ended access and a quiz with save on exit.
- Time-up post: within 15 seconds saves the page and completes as `time_expired`, including a page with a required question unanswered and one with an invalid answer; more than 15 seconds left saves and completes nothing; after expiry saves nothing.
- A limit shortened by `content_save` expires an open sitting on its next request; a removed limit leaves it open.
- `start_attempt` on an expired open sitting completes it before creating the next one, ignoring the reuse window and `kept_if_untouched_since`.
- Sweep: completes expired sittings across sites, leaves unexpired and untimed ones, skips rows locked by a request, reports a failed row without stopping the rest.
- Playwright (`learner_interface/tests/playwright/test_form_flow.py`): the start page shows the limit; the countdown shows and counts; the 1-minute warning shows and its live region holds the text; with `start_time` rewound, the auto-submit saves the open page and lands on results with "Time ran out".
- Educator: the attempt review shows the reason and recorded limit; the cohort report attempts table shows the reason on screen and in the PDF.

## Open questions

- Q: How close to the sitting expiry must a time-up post arrive to be honoured? → A: 15 seconds or fewer left (assumed default: three times the 5-second lead, enough for a slow round trip, too short to end a test early on a wrong client clock. Overrule by editing "The time-up post".)
- Q: What reason do sittings completed because an item closed or access ended get? → A: `learner_submitted`, as today (assumed default: those paths predate this spec, and `sacaa-compliance-assessment-controls-5-test-disturbance` adds reasons. Overrule by editing "Sitting: reason, recorded limit, expiry".)
- Q: Should the learner's previous-attempts list and the educator learner Courses tab attempts table show the reason? → A: No (assumed default: the idea names the attempt review and the cohort report only; the `QuizAttempt` field makes the Courses tab a template change later. Overrule by editing "Educator surfaces".)

## Success criteria

- A QUIZ with `time_limit_minutes: 10` shows "10 minutes" on its start page; a QUIZ without the key shows no limit and behaves as before.
- A learner who sits until the clock runs out lands on results with "Time ran out", and the page open at the time is marked.
- A learner who closes the tab and returns after the sitting expiry lands on results; the sitting's `completed_time` equals `start_time` plus the limit.
- An abandoned expired sitting is completed by `fls_run_housekeeping` with reason `time_expired`.
- A page POSTed after the sitting expiry leaves no new `QuestionAnswer` rows.
- The attempt review and the cohort report attempts table show "Time ran out" for that sitting and "Learner submitted" for others.
- A screen reader hears the 5-minute and 1-minute warnings once each, and no countdown ticks.
