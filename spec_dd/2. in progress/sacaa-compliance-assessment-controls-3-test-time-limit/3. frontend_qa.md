# Frontend QA: Quiz time limit

Checks the quiz time limit in a browser: the start page, the countdown, the warnings, the automatic submit, what happens when a learner returns late, and the educator surfaces that show the completion reason.

## §0 Setup

- Start the dev server with the `Dev server start` command under `## QA Hooks` in `.claude/sdd/config.md`, on `$PORT`.
- Base URL: `http://127.0.0.1:$PORT`.
- Seed the worktree's own dev database if it is empty (the home page 500s with "FORCE_SITE_NAME='DemoDev' does not match any Site" when it is):
  - `uv run manage.py create_demo_data --yes`
  - `uv run python manage.py content_save ./demo_content DemoDev`
- Log in at `/accounts/login/` with the `## QA Login` values: `demodev@email.com` / `demodev@email.com`.
- The timed quiz is in the demo course whose directory is `demo_content/functionality_demo_quiz_time_limit/` (10-minute limit, two pages, saves on exit). Find the course on `/courses/` by its title and register `demodev@email.com` on it if it is not already (a data helper task if the page offers no way).
- An untimed quiz for comparison: the course "Functionality Demo - shuffled quiz".
- A second account is needed as a learner in a cohort for the cohort report (Test 13); any seeded cohort learner registered on the timed course works. Ask the data helper for one if none exists, with a completed `time_expired` sitting and a completed `learner_submitted` sitting.

### Moving the clock

Tests rewind the open sitting's `start_time` instead of waiting ten minutes. `<SECONDS_LEFT>` is how long the sitting should have left; a negative number means it expired that long ago.

```
uv run python manage.py shell -c "
from datetime import timedelta
from django.utils import timezone
from freedom_ls.form_engine.models import FormProgress
s = FormProgress._base_manager.filter(completed_time__isnull=True, form__time_limit_minutes__isnull=False, user__email='demodev@email.com').latest('start_time')
FormProgress._base_manager.filter(pk=s.pk).update(start_time=timezone.now() - timedelta(minutes=s.form.time_limit_minutes) + timedelta(seconds=<SECONDS_LEFT>))
print(s.pk)
"
```

After rewinding, reload the runner page so the countdown picks up the new time, unless the test says not to.

To start each test from a clean state, finish or expire any open sitting first (rewind it to `-60` and open the quiz's start URL once).

## Test 1: The start page shows the limit

1. Open the timed course and go to its quiz item (the start page).
2. Expect a fact chip reading "10 minutes" beside the question and page counts.
3. Expect, above the start button, a notice: "This quiz has a time limit of 10 minutes. The clock starts when you press Start and does not stop if you leave. When time runs out, your quiz is submitted with the answers you have saved."
4. Open the start page of the untimed quiz. Expect no time chip and no notice.

## Test 2: The educator content preview lists the limit

1. Go to `/educator/`, open Courses, open the timed course, and open the quiz's content preview from the course outline.
2. Expect a "Time limit" row reading "10 minutes" in the quiz facts.
3. Open the preview of the untimed quiz. Expect "Time limit" to read "None set".

## Test 3: The countdown runs in the runner

1. On the timed quiz's start page press Start.
2. Expect a countdown in the top bar beside the answered count, starting just under `10:00`, in `m:ss` form.
3. Watch for five seconds. Expect it to count down one second at a time, with no flashing, colour pulsing or movement of the bar around it.
4. In the page snapshot expect the countdown to have `role="timer"` and the accessible name "Time left".
5. Press Next, then Previous. Expect the countdown to carry on from the right time on each page, not restart at `10:00`.
6. At 375px wide, expect the exit button, title, countdown and answered count to fit in the bar with no overlap and no horizontal scroll.
7. Check the browser console: no errors.
8. Open the untimed quiz's runner. Expect no countdown.

## Test 4: Warnings at 5 minutes and 1 minute

1. With a sitting open on the timed quiz, rewind to `310` seconds left and reload the runner. Expect no warning yet.
2. Wait until the countdown passes `5:00`. Expect a warning callout under the top bar: "5 minutes left. When time runs out, your quiz is submitted with your saved answers." Focus stays where it was.
3. Rewind to `70` seconds left and reload. Expect the 5-minute callout to be showing already.
4. Wait until the countdown passes `1:00`. Expect the callout to read: "1 minute left. This page is saved and submitted when time runs out." In the page snapshot expect an assertive live region holding the same text.
5. Reload with under a minute left. Expect the 1-minute callout to show at once.
6. At 375px wide, expect the callout to fit without pushing the questions off screen or causing horizontal scroll.

## Test 5: Time runs out while the learner is on the page

1. Start a fresh sitting on the timed quiz. On page 1 choose an answer for one question and leave a required question blank. Do not press Next.
2. Rewind to `8` seconds left and reload the runner. Choose the same answer again (the reload cleared it).
3. Wait for the countdown to reach `0:00`.
4. Expect the page to submit by itself, with no "Leave site?" prompt and no validation message about the blank required question.
5. Expect to land on the results page with the line "Time ran out. Your quiz was submitted with the answers you had saved."
6. Expect the score to reflect the answer chosen in step 2 (review the incorrect answers list or the attempt review in Test 12).

## Test 6: The learner leaves and returns after the time is up

1. Start a fresh sitting on the timed quiz and answer page 1, then press Next.
2. Use the exit button and leave. Expect the exit dialog to say: "Your answers are saved. The time limit keeps running while you are away."
3. Rewind to `-300` (expired five minutes ago). Do not reload anything yet.
4. Open the quiz's start page URL. Expect to be sent to the results page showing "Time ran out", not the start page.
5. Go back to the quiz's start page. Expect the previous attempt listed, and Start to begin a new sitting with a full `10:00`.
6. Repeat steps 1 to 3, then open the runner page URL (`.../fill_form/1` as shown in the address bar while sitting) instead of the start page. Expect the results page with "Time ran out".

## Test 7: A Next press just after the time is up is saved

Timing-sensitive: step 3 must follow step 2 within ten seconds.

1. Start a fresh sitting on the timed quiz. On page 1 answer every question. Do not press Next.
2. Rewind to `-2` (expired two seconds ago). Do not reload the page.
3. Immediately press Next.
4. Expect the results page with "Time ran out", and the page 1 answers counted in the score.

If step 3 was slower than ten seconds, the result is Test 8's; repeat the test.

## Test 8: A Next press long after the time is up saves nothing

1. Start a fresh sitting on the timed quiz. On page 1 answer every question correctly. Do not press Next.
2. Rewind to `-120`. Do not reload the page.
3. Press Next.
4. Expect the results page with "Time ran out" and a score of 0: the page was not saved.

## Test 9: The server ignores an early claim that time is up

1. Start a fresh sitting on the timed quiz, with most of the ten minutes left.
2. In the page, run this script (it imitates the countdown's post):

   ```js
   const f = document.getElementById("runner-page-form");
   const i = document.createElement("input"); i.type = "hidden"; i.name = "time_up"; i.value = "1"; f.appendChild(i);
   f.action = document.querySelector("[data-time-up-url]").dataset.timeUpUrl; f.submit();
   ```

3. Expect to land back on the runner page with the countdown still running. The sitting is not completed and no result is shown.

## Test 10: The exit dialog on timed and untimed quizzes

1. In the timed quiz's runner open the exit dialog. Expect: "Your answers are saved. The time limit keeps running while you are away."
2. In the untimed save-on-exit quiz's runner open the exit dialog. Expect the unchanged copy: "Your progress is saved — you can resume later."

## Test 11: Housekeeping completes an abandoned sitting

1. Start a fresh sitting on the timed quiz, answer page 1, press Next, then close the tab.
2. Rewind to `-600`.
3. Run `uv run python manage.py fls_run_housekeeping`. Expect its output to note one completed time-expired sitting.
4. Open the quiz's start page. Expect the attempt listed among previous attempts, and no open sitting to resume.
5. Run the command again. Expect no sitting completed the second time.

## Test 12: The attempt review shows the completion reason

1. Go to `/educator/`, open Learners, open the learner `demodev@email.com`, and open the attempt review for a sitting that ran out of time (from Test 5, 6 or 11).
2. In the Summary expect "Completion reason: Time ran out" and "Time limit: 10 minutes".
3. Expect "Completed" to be exactly ten minutes after "Started" for the sitting from Test 6 or 11.
4. Open the attempt review of a sitting the learner submitted on the untimed quiz. Expect "Completion reason: Learner submitted" and no "Time limit" row.

## Test 13: The cohort report shows the completion reason

1. Go to `/educator/`, open Cohorts, open the cohort holding the learner from §0, and open its report.
2. In that learner's "Quiz attempts" table expect a "Completion reason" column, with "Time ran out" on the expired sitting and "Learner submitted" on the other.
3. Download the PDF. Expect the same column and values, every column readable, and no text clipped or wrapped awkwardly in the attempts table.

## Test 14: Changing the limit mid-sitting

1. Start a fresh sitting on the timed quiz.
2. In `demo_content/functionality_demo_quiz_time_limit/`, change the quiz's `time_limit_minutes` to `30` and run `uv run python manage.py content_save ./demo_content DemoDev`.
3. Reload the runner. Expect the countdown to show just under `30:00` less the time already spent.
4. Remove the `time_limit_minutes` line and run `content_save` again. Reload the runner. Expect no countdown, and the start page to show no time chip or notice.
5. Restore the file with `git checkout -- demo_content/functionality_demo_quiz_time_limit/` and run `content_save` again. Expect the countdown back at the 10-minute limit.

## Test 15: An untimed quiz behaves as before

1. Take the untimed quiz from start to finish: start, answer, Next, submit.
2. Expect no countdown, no warnings, the usual submit confirmation, and a results page without "Time ran out".
3. Check the browser console on the start page, runner and results page: no errors.
