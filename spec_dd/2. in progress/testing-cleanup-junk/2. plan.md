# Implementation plan: test suite cleanup

Source: `idea.md` in this directory (the spec stage was skipped, so the idea is the spec). The six
`research_*.md` files beside it hold the inventories, rubric, flow candidates and measurements this
plan builds on; a slice names the research table it works from, and the implementer reads that
table rather than re-deriving it.

Code snippets below are shapes, not finished files: they omit imports and the implementer adds
them, with full type hints on every function and fixture parameter (`DjangoDbBlocker`,
`pytest.TempPathFactory`, `ViewportSize`, and so on) and no `Any`. Comments and docstrings in the
snippets are written to be copied as they are. Nothing else in this document is: never copy a
sentence that names a slice into code, a test name, an exemption reason or a skill.

The branch lands as one pull request. The CI unit job keeps its current coverage gate until
Slice 26 sets the measured one, so an intermediate commit may fail that job; every slice is still
committed only with the local default suite and the three `test_organisation` hooks green.

## Rules every slice follows

- **Baselines move with the files.** Deleting, renaming or moving a test file deletes its lines
  from `mirroring_baseline.txt` and `import_baseline.txt` in the same change. Neither file ever
  gains a line. Both files stay, with their header comments, even when every entry is gone.
- **Every new test directory is a package.** `views/`, `models/`, `components/`, `invariants/`,
  `demo_content/`, `templatetags/`, `management/` and `management/commands/` each get an empty
  `__init__.py` in the change that creates them. pytest runs in `prepend` import mode here, and
  without the package files same-named modules in different directories collide.
- **An exemption line lands with the first file it covers**, in the exact `<path>  # <reason>`
  form the slice gives, and the covered files' baseline lines leave in the same change.
- **A merged or moved source file is deleted in the same change** (`git rm`), its unused imports
  and fixtures go with it, and `uv run pytest --collect-only -q | sort | uniq -d` prints nothing.
- **Direction before mirroring.** A test file with `import_baseline.txt` lines is first judged by
  what it exercises. A test that asserts another app's behaviour (a webhook payload, a
  notification row, a learner row) moves into that app's mirrored test module and its import
  baseline lines are deleted. A test that only reaches for another app's objects as setup reaches
  them through its own app's factories where they exist (`comms.factories` already wraps
  `content_engine.factories`), or through `UserFactory`, which every app may use. A merge that would
  hand an existing import baseline line to a differently named module is not done; the file keeps
  its name and its lines. Webhook tests follow one rule: a test that asserts the payload or the
  delivery goes to `webhooks/tests/test_events.py` or `test_delivery.py`; a test that asserts that
  an app emits the event stays with the emitting app, in the module that mirrors the emitter.
- **"By import" means:** the target is the test module that mirrors the production module the test
  imports its subject from; a file that imports subjects from two modules is split between the two.
- **Regenerate, never hand-edit.** Every slice that deletes, renames or moves a test module ends
  with `uv run python claude_plugins/django-stack/scripts/generate_app_map.py`, then the three hooks
  (`uv run pre-commit run app-map-fresh lint-imports test-mirroring --all-files`).
- **Rubric sweep on every file touched.** When a slice reads a file to merge or move it, it applies
  R1 to R13 and K1 to K4 from `research_junk_and_brittle_tests.md` to every test in it: a CSS or
  Tailwind class assert goes unless the class is an `aria-*`, `role`, `href`, `hx-*` or `data-*`
  contract; a long copy literal becomes an assert on a stable hook unless the copy is the feature;
  a test whose only assert is `status_code == 200` goes. A test that meets K1 to K4 stays whatever
  else it does. Slices 6 and 7 cover the files no merge touches.
- **One shared test replaces a per-instance family.** Never leave both the family and the
  replacement.
- **Every flow module** sets `pytestmark = [pytest.mark.playwright,
  pytest.mark.django_db(transaction=True)]` at file level.
- **Nothing in the `freedom_ls/tests/` package is renamed.** New shared helpers are added beside the
  existing modules.
- **Test names, docstrings, comments and exemption reasons** state facts about the code and never
  mention this plan, its slices, the spec, or what the code used to do.
- **After Slice 2**, a slice that touches a `conftest.py`, `freedom_ls/tests/` or the
  `test_organisation` scripts also runs `uv run pytest -m dev_tooling`, because the tests of those
  live there.

   ```python

   def site_context(site: Site) -> Iterator[Site]:
       """Make `site` the ambient site for code running in this thread.

       SiteAwareModel reads the thread-local request, templates and allauth call
       get_current_site, and the role registry calls Site.objects.get_current;
       all four have to agree or a factory-built row lands on a different site
       from the one a view then reads.

       ...  # the current mock_site_context body with unittest.mock.patch, restoring on exit
   ```

   `mock_site_context` in `freedom_ls/conftest.py` becomes `with site_context(site): yield site`.
2. New `freedom_ls/tests/demo_content_fixtures.py` (module docstring: only the `fls_internal`
   tests of this repo can use it, because `demo_content/` is not distributed):

   ```python
   @pytest.fixture(scope="module")
   def demo_site(django_db_setup: None, django_db_blocker: DjangoDbBlocker) -> Site:
       """The site the demo tree is imported into, created outside any test transaction."""
       with django_db_blocker.unblock():
           site, _ = Site.objects.get_or_create(domain="demo.test", defaults={"name": "demo"})
       return site


   @pytest.fixture(scope="module")
   def demo_media_root(tmp_path_factory: pytest.TempPathFactory) -> Path:
       """A media root that outlives the per-test one, so imported images stay readable."""
       return tmp_path_factory.mktemp("demo_media")


   @pytest.fixture(scope="module")
   def loaded_demo_content(
       demo_site: Site, demo_media_root: Path, django_db_blocker: DjangoDbBlocker
   ) -> Iterator[Site]:
       """The shipped demo tree, imported once per module.

       The import optimises every image and writes hundreds of rows; importing it
       per test would be the slowest setup in the suite. The rows live outside the
       per-test transaction and every table is flushed when the module ends, which
       is the reset every transaction=True test already performs.
       """
       with django_db_blocker.unblock(), override_settings(MEDIA_ROOT=demo_media_root), site_context(demo_site):
           save_content_to_db(settings.BASE_DIR / "demo_content", demo_site.name)
       try:
           yield demo_site
       finally:
           with django_db_blocker.unblock():
               call_command("flush", interactive=False, verbosity=0)


   @pytest.fixture
   def site(demo_site: Site) -> Site:
       """The module's demo site, so mock_site_context and the view tests agree on it."""
       return demo_site


   @pytest.fixture(autouse=True)
   def _isolate_media_root(settings: SettingsWrapper, demo_media_root: Path) -> None:
       """Point every test in the package at the module's media root, where the
       imported images are."""
       settings.MEDIA_ROOT = demo_media_root
   ```
