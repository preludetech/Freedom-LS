# Frontend QA: Meta and TikTok pixels

Two new platform apps send the same five analytics events GA4 already gets to the Meta pixel and
the TikTok pixel. Both pixels load only for a visitor whose country, read from the header named by
`VISITOR_COUNTRY_HEADER`, is known and outside the EEA, the UK and Switzerland, and never on an
educator page. GA4 is unchanged: it loads for every country and on educator pages.

| Analytics event | Condition | Meta | TikTok |
| --- | --- | --- | --- |
| `course_registered` | | `fbq('track', 'CompleteRegistration', …)` | `ttq.track('CompleteRegistration', …)` |
| `course_access_requested` | `request_kind == "application"` | `fbq('track', 'SubmitApplication', …)` | `ttq.track('SubmitApplication', …)` |
| `sign_up` | | `fbq('trackCustom', 'SignUp', …)` | `ttq.track('SignUp', …)` |
| `course_completed` | | `fbq('trackCustom', 'CourseCompleted', …)` | `ttq.track('CourseCompleted', …)` |
| `generate_lead` | | `fbq('track', 'Lead', …)` | `ttq.track('SubmitForm', …)` |

An interest registration (`request_kind: "interest"`) and `course_started` send nothing to Meta or
TikTok. `generate_lead` has no FLS page and is covered by unit tests only. The parameters are the
same as GA4's: `course_slug`, `course_id`, `access_type`, plus `request_kind`,
`registration_method` or `registration_source` per event, and `method: "email"` for `sign_up`.

## How to observe

Three layers, from what FLS controls to what the platform received:

1. **Page source.** The head partials and the event scripts are server-rendered. A `ZA` visitor's
   page source contains `connect.facebook.net/en_US/fbevents.js` and
   `fbq('set', 'autoConfig', false, '<META ID>')` before `fbq('init', '<META ID>')`, then
   `fbq('track', 'PageView')`; and `analytics.tiktok.com/i18n/pixel/events.js` with
   `ttq.load('<TIKTOK ID>')` then `ttq.page()`. An event script looks like
   `<script>fbq('trackCustom', 'SignUp', {"method": "email"}); document.currentScript.remove();</script>`.
   Read the source with `view-source:` or `browser_evaluate` on `document.documentElement.outerHTML`
   right after load. Event scripts remove themselves, so query the *source*, not the live DOM, for
   them.
2. **Network.** `browser_network_requests` after each action. Meta sends every event as a request to
   `https://www.facebook.com/tr/?id=<META ID>&ev=<Name>…`; the `ev` query value is the event name
   (`PageView`, `SignUp`, `CompleteRegistration`, …). TikTok's loader is
   `https://analytics.tiktok.com/i18n/pixel/events.js?sdkid=<TIKTOK ID>…` and its events are POSTs to
   `https://analytics.tiktok.com/api/v2/pixel`. The request list is the record for the CSP host
   groups too: note every host either pixel contacts.
3. **Test Events.** With real test pixel IDs, Meta Events Manager → Test Events and TikTok Events
   Manager → Test Events show each event by name within a minute.

**Pixel IDs.** Use real test pixels if you have them: that is the only way to see the Test Events
rows and TikTok's event POSTs (with an unknown ID TikTok's loader returns nothing and `ttq.track`
sends nothing). Without them use `META_PIXEL_ID=100000000000001 TIKTOK_PIXEL_ID=QATEST0000000000`;
Meta's `/tr/` requests still fire with a fake ID, so layers 1 and 2 still prove everything
except TikTok's network and both platforms' Test Events. Say in the report which you used.

**The country header.** The dev server has no proxy, so the browser sends the header itself. Set it
for the whole browser context with `browser_run_code_unsafe`:

```js
await page.context().setExtraHTTPHeaders({ 'X-Visitor-Country': 'ZA' });
```

Change the value the same way, and clear it with `setExtraHTTPHeaders({})`. Every request after
the call carries the new value, so navigate again after changing it. "The header set to X" below
means this call with X.

Beyond the golden path this run hunts for:

- **A pixel loading for the wrong visitor:** an EEA visitor, an unknown country, an educator page,
  a token-bearing allauth page, or a deployment with no header configured.
- **A page view that fires twice, or not at all**, across a full load, a boosted `Next`, a
  breadcrumb link and Back.
- **A conversion that fires twice, on the wrong platform, or with the wrong name**, and an interest
  registration leaking to Meta or TikTok.
- **GA4 changing by accident.** Its queue moved to `base`, its events partial now renders from a
  shared list, and its `send_to` is now a filter. Every GA4 behaviour from the previous QA run is
  re-checked in §5.
- **A queued event lost or duplicated** when only some platforms are configured, or when a page
  includes the events partial twice.

## §0 Setup

### 0.1 Server

1. `PORT=$(.claude/ds/scripts/find_available_port.sh)`. Use that number literally from here on.
2. Start the server backgrounded, as its own call, with every platform configured:

   ```
   VISITOR_COUNTRY_HEADER=X-Visitor-Country META_PIXEL_ID=<meta id> TIKTOK_PIXEL_ID=<tiktok id> GOOGLE_ANALYTICS_MEASUREMENT_ID=G-QATEST0000 GOOGLE_ADS_CONVERSION_ID=AW-QATEST000 GOOGLE_ADS_CONVERSION_LABELS=sign_up=QAsignup,course_registered=QAregistered uv run python manage.py runserver $PORT
   ```

   This is "the full configuration" below.
3. Open `http://127.0.0.1:$PORT/` and confirm `#debug-branch-badge` names the `tracking-pixels`
   branch. If it names another branch, another server holds the port; go back to step 1.
4. Set the header to `ZA`.

### 0.2 Seed data

1. Demo content loaded: `uv run python manage.py content_save demo_content DemoDev`.
2. `uv run python manage.py qa_create_ga_setup_seed`. It is idempotent; run it again before any
   re-run. **Write down every slug, UUID and learner pk it prints.** It provides:
   - **Learner A** (`qa-learner-a@email.com`): registered, with fresh progress, for
     `standard-markdown-demo-finance` and `qa-second-course`.
   - **Learner B** (`qa-learner-b@email.com`): no `CourseApplication`, not registered for
     `qa-free-course-self-registration`.
   - `qa-application-gated-course-no-form`, application-gated with no form.
   - `qa-coming-soon-course`, a coming-soon course nobody has expressed interest in.

   Every learner's password equals their email.
3. **Superuser:** `demodev@email.com` from `.claude/fls-dev/config.md`.
4. Anything else missing is created through the `fls-dev:qa-data-helper` agent, never by hand.

### 0.3 System checks

Run from the shell, not the browser:

1. `META_PIXEL_ID=1 uv run python manage.py check` with `VISITOR_COUNTRY_HEADER` unset. Expect
   `freedom_ls_meta_pixel.W001`.
2. `TIKTOK_PIXEL_ID=1 uv run python manage.py check` with `VISITOR_COUNTRY_HEADER` unset. Expect
   `freedom_ls_tiktok_pixel.W001`.
3. `VISITOR_COUNTRY_HEADER=HTTP_X_VISITOR_COUNTRY uv run python manage.py check`. Expect
   `freedom_ls_base.E003` with a hint naming `X-Visitor-Country`.
4. `VISITOR_COUNTRY_HEADER=X-Visitor-Country META_PIXEL_ID=1 TIKTOK_PIXEL_ID=1 uv run python manage.py check`.
   Expect none of the three.

## §1 The pixels load only for an allowed visitor

1. Signed out, header `ZA`, open `/`. In the page source expect both base codes (layer 1), with the
   `autoConfig` call before `init`, no `<noscript>` and no `disablePushState`. In the network list
   expect `fbevents.js`, exactly one `/tr/?…ev=PageView`, `events.js?sdkid=<TIKTOK ID>`, and (real
   ID) one TikTok pixel POST. GA4's `gtag/js?id=G-QATEST0000` loads too.
2. Set the header to `za` (lower case) and reload. Expect the same.
3. Set the header to `DE` and reload. Expect no `facebook` or `tiktok` string anywhere in the
   source and no request to either host. Expect GA4 still loading, with its consent default call
   listing `"DE"`.
4. Repeat step 3 for `GB`, `CH` and `NO`: nothing from either pixel.
5. Set the header to `XX`, then to an empty string, then clear it entirely. Reload after each.
   Expect nothing from either pixel each time. GA4 loads each time.
6. Set the header to `ZAF`. Expect nothing from either pixel: three letters is not a country code.
7. Set the header to `ZA` again. Log in as the superuser and open `/educator/`. Click through two
   sidebar links. Expect no pixel base code and no request to either host on any of these pages,
   and GA4 present on all of them.
8. Still the superuser, open `/` (a learner page). Expect both pixels back.
9. Log out.

### 1.1 Token-bearing pages

1. Sign up a fresh account. Take its confirmation link from Mailpit and open it. On
   `/accounts/confirm-email/<key>/` expect no request to `facebook`, `tiktok` or
   `googletagmanager`, and none of the three in the source.
2. Confirm the email. On the next ordinary page expect all three back.
3. Request a password reset for Learner B, open its link from Mailpit. Expect the same silence on
   the set-password page. Set the password back to the email address.

### 1.2 Unconfigured deployment

1. Stop the server. Start it with the full configuration minus `VISITOR_COUNTRY_HEADER`.
2. Header `ZA`, open `/`. Expect nothing from either pixel, GA4 present. The header means nothing
   until the setting names it.
3. Stop the server. Start it with the full configuration minus `META_PIXEL_ID` and
   `TIKTOK_PIXEL_ID`.
4. Open `/`. Expect nothing from either pixel and GA4 present.
5. Restart with the full configuration before §2.

## §2 Page views

Log in as Learner A. Clear the network list before each step (a fresh `browser_network_requests`
call after noting the previous count is enough).

1. Open `standard-markdown-demo-finance` and its first course item with a full page load (type the
   URL). Expect exactly one `/tr/?…ev=PageView` and one TikTok pixel POST (real ID) for this load.
2. Click "Next". The URL changes with no full reload (`hx-boost`). Expect exactly one new
   `ev=PageView` and one new TikTok POST, sent by each pixel's own history listener, and no
   second `fbevents.js` or `events.js` load. Expect no `fbq('track', 'PageView')` script inside
   `#interface-main` in the swapped content: FLS adds none.
3. Click the course-name breadcrumb (`hx-push-url`). Expect exactly one new `PageView` per
   platform.
4. Press Back. Expect at most one new `PageView` per platform, and no event script in the DOM.
5. Read the full request list for this section and note every distinct host contacted by either
   pixel. Expect only `connect.facebook.net`, `www.facebook.com`, `analytics.tiktok.com` and
   possibly `analytics-ipv6.tiktokw.us`. Any other host is a finding for the CSP groups.
6. In the console, expect no CSP report-only warning naming a facebook or tiktok host.

## §3 Conversion moments

For each step, check the page source for the exact script string, the network list for the Meta
`ev=` value, and (real IDs) Test Events for the row. Every FLS event script must be gone from the
live DOM after load: `document.querySelectorAll('script')` contains none whose text includes `fbq('track` or `ttq.track`.

### 3.1 `sign_up`

1. Signed out, header `ZA`, sign up with a fresh email address. On the verify-your-email page expect
   in the source exactly one `fbq('trackCustom', 'SignUp', {"method": "email"})` and exactly one
   `ttq.track('SignUp', {"method": "email"})`, beside the GA4 `sign_up` and its `conversion`.
   Network: one `ev=SignUp`.
2. Reload. Expect none of them.
3. **Repeat sign-up.** Submit the sign-up form again with the same email. Expect no `SignUp` on the
   resulting page.
4. **Invalid input.** Submit with mismatched passwords. Expect the errors and no `SignUp`.
5. **EEA sign-up.** Set the header to `DE` and sign up another fresh account. Expect the GA4
   `sign_up` script and no `fbq` or `ttq` anywhere. Then set the header back to `ZA` and open `/`.
   Expect no `SignUp` there either: the shared pop already spent the event on the `DE` page, so it
   is not replayed to Meta later.

### 3.2 `course_access_requested`

1. Log in as Learner B. Open `functionality-demo-application-gated-course`, "Apply now", complete
   the form and submit. On the dashboard expect exactly one
   `fbq('track', 'SubmitApplication', {…"request_kind": "application"})` and one
   `ttq.track('SubmitApplication', …)` with the course's slug and UUID. Network: `ev=SubmitApplication`.
2. Reload. Expect none.
3. Open `qa-application-gated-course-no-form`, "Apply now", confirm. Expect one `SubmitApplication`
   per platform on the status page. Visit the apply URL again: no second one.
4. **Interest is not an application.** Open `qa-coming-soon-course`, note the request count, click
   "I'm interested". The button swaps in place. Expect the GA4 `course_access_requested` with
   `request_kind: "interest"` in the swapped fragment (check the response body via the network
   list or `browser_evaluate` on the wrapper before the script removes itself), and **no** `fbq` or
   `ttq` in the fragment and no `/tr/` request. Click "Remove interest": nothing.

### 3.3 `course_registered`

1. Still Learner B, open `qa-free-course-self-registration`, "Enrol for free". On the first course
   page expect exactly one `fbq('track', 'CompleteRegistration', {…"registration_method": "self_registration"})`
   and one `ttq.track('CompleteRegistration', …)`, and **no** `CourseStarted` or any other call for
   the `course_started` GA4 event that renders beside them. Network: `ev=CompleteRegistration` and
   no `ev=` for `course_started`.
2. Reload. Expect none.
3. **Reactivation.** Ask the data helper to set `is_active=False` on Learner B's registration for
   this course, then "Enrol for free" again. Expect no `CompleteRegistration`.

### 3.4 `course_completed`

1. Log in as Learner A. Open `standard-markdown-demo-finance`'s first item. Expect the GA4
   `course_started` and nothing for Meta or TikTok.
2. Work through with "Next" (boosted) to "Finish Course". On the completion page expect exactly one
   `fbq('trackCustom', 'CourseCompleted', {…"registration_source": "individual"})` and one
   `ttq.track('CourseCompleted', …)` inside `#interface-main`'s swapped content, and none in the
   live DOM afterwards. Network: `ev=CourseCompleted`.
3. Back, then Forward, then reload. Expect no second `CourseCompleted`.
4. **Full-page route.** Reset Learner A's `completed_time` to null through the data helper and type
   the finish URL. Expect exactly one `CourseCompleted` per platform in the source, not one per
   include point.

### 3.5 Test Events (real IDs only)

Expect one row each in Meta Test Events and TikTok Test Events for `SignUp`, `SubmitApplication`
(twice, from 3.2), `CompleteRegistration` and `CourseCompleted`, with the parameters from the
tables, plus the page views. Note whether TikTok flags `course_slug`, `course_id`, `access_type`
or the others as unrecognised parameters; the spec's open question depends on it.

## §6 Nothing else broke

1. As the superuser, open the Django admin. Expect it to load with no pixel and no GA4.
2. Open a URL that does not exist. Expect the 404 page with no console errors.
3. On any page, check the console for JavaScript errors from the pixel blocks. Requests to
   facebook or tiktok hosts failing with 4xx are expected with fake IDs.
4. Follow the Privacy link in the footer. Expect version 1.3 and, under "Analytics and
   advertising", the names Google Analytics, Google Ads, Meta (Facebook and Instagram) and TikTok;
   the account-number sentence scoped to Google Analytics; a sentence that Meta and TikTok also
   use the data for their own purposes and process it outside South Africa; and that the Meta and
   TikTok pixels are not used for visitors in the EEA, the UK or Switzerland. Section 5 names the
   same four. The text is served from git `HEAD`, so an uncommitted edit will not show.
5. View the source of `/`. Expect `posthog.init(` only if `POSTHOG_API_KEY` was set for this run,
   and otherwise absent, as before.
