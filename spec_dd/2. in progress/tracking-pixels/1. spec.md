# Spec: Meta and TikTok pixels

## Purpose

FLS reports five conversion moments to Google Ads. Campaigns now also run on Meta (Facebook and
Instagram) and TikTok, and both platforms need the same moments from their own browser pixels. The
audience is South African adults. The approach is set in `idea.md`.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| analytics event | coined | A one-shot funnel moment a view records in the session, today `GoogleAnalyticsEvent` in `freedom_ls/google_tag/events.py`. Every platform app now reads it. Same event names. No platform-neutral term exists. |
| platform app | coined | An installable app that sends analytics events to one advertising or analytics platform: `google_tag`, `meta_pixel`, `tiktok_pixel`. No existing term covers the set. |
| visitor country | coined | The ISO 3166-1 alpha-2 code the fronting proxy puts in the header named by `VISITOR_COUNTRY_HEADER`, or unknown. Nothing in FLS resolves a country today. |

## Scope

In:

- A platform-neutral recorder, event enum and session queue in `base`, replacing the Google-named
  ones. This is a breaking rename.
- Two new platform apps, `freedom_ls.meta_pixel` and `freedom_ls.tiktok_pixel`, each on when
  installed and given a pixel ID.
- Five analytics events mapped to each platform's events, fixed in code.
- The country gate: the pixels load only for visitors whose country is known and outside the EEA,
  the UK and Switzerland.
- CSP host groups, the default privacy policy, a deployer guide, upgrade notes.
- `infrastructure_changes.md` beside this spec: the Cloudflare and edge changes production needs
  before it knows the visitor country. Implemented later, in the infrastructure repo.

Out: everything under "Out of scope" in `idea.md`. Also out: sending the Meta or TikTok pixel
anything that identifies the visitor (`external_id`, `ttq.identify`, advanced matching).

## Decisions

- **The loader is left out for a gated visitor, not revoked.** The gate is decided server-side, so
  nothing is fetched from Meta or TikTok, and nobody has to turn on TikTok's "Cookie Consent Mode",
  which `ttq.holdConsent()` (proposed in `idea.md`) needs before it does anything.
- **Unknown country means dormant.** A missing header, an empty value, `XX`, `T1` or anything that
  is not two letters counts as unknown. Losing a few South African conversions costs less than
  tracking an EEA visitor against Meta's Business Tools Terms.
- **Country comes from a proxy header named in a setting, with no GeoIP fallback.** Production's
  Caddy edge already sets `X-Real-IP` this way. GeoIP needs a MaxMind licence and an update job, and
  time zone cannot gate a script before it loads.
- **The shared code lives in `base`.** `base` has no runtime dependencies and every platform app
  already depends on it (`docs/app_structure.md`), so the move adds no edges and downstream projects
  need no new `INSTALLED_APPS` entry. `base/webhook_event_types.py` already holds
  shared event vocabulary there.
- **One pop per render, shared by every platform.** If each platform popped the session queue for
  itself, the first to render would empty it for the others.
- **`SignUp` and `CourseCompleted` are final.** Operators build custom conversions on them, and a
  rename breaks those.
- **No `eventID`/`event_id`.** It only matters for deduplication against the server-side APIs, and
  `server-side-conversion-tracking` changes the recorder anyway.
- **Event parameters pass through unchanged.** None identify a person, and Meta takes them as
  custom parameters.
- **No `value`/`currency`.** Meta makes both optional for `CompleteRegistration` and `Lead`, and
  TikTok recommends neither for lead-generation events.
- **A sibling deployer guide.** Each app is switched on separately and the Google guide's sections
  are Google setup. The Google guide links to the new one.

## Requirements

### Shared analytics events (`freedom_ls/base/`)

New module `freedom_ls/base/analytics_events.py` takes over the platform-neutral half of
`freedom_ls/google_tag/events.py`:

| Today | Becomes (`freedom_ls.base.analytics_events`) |
| --- | --- |
| `GoogleAnalyticsEvent` | `AnalyticsEvent`, same members and values |
| `GoogleAnalyticsEventPayload` | `AnalyticsEventPayload` |
| `GOOGLE_ANALYTICS_EVENTS_SESSION_KEY = "google_analytics_events"` | `ANALYTICS_EVENTS_SESSION_KEY = "analytics_events"` |
| `record_google_analytics_event` | `record_analytics_event` |
| `record_sign_up` | `record_sign_up` |
| `pop_google_analytics_events` | `pop_analytics_events` |
| `CONSENT_MODE_DENIED_REGIONS` (`google_tag/context_processors.py`) | `EU_CONSENT_POLICY_COUNTRIES` |

- Delete `google_tag/events.py`. No compatibility aliases.
- Validation keeps GA4's name, prefix, reserved-parameter and length rules, the strictest of the
  three platforms.
- `record_analytics_event` no-ops unless at least one of `freedom_ls.google_tag`,
  `freedom_ls.meta_pixel` or `freedom_ls.tiktok_pixel` is installed, since otherwise nothing pops
  the queue.
- `EU_CONSENT_POLICY_COUNTRIES` keeps the 32 codes and their grouping comments. `google_tag` imports
  it for the Consent Mode `region` list. Fix the stale path in the comment at
  `freedom_ls/google_tag/templates/partials/google_analytics.html:24`.
- `visitor_country(request) -> str | None` reads the header named by `VISITOR_COUNTRY_HEADER` and
  returns the upper-cased code, or `None` if unknown.
- `ad_pixels_allowed(request) -> bool` is `True` only when `visitor_country` is known and not in
  `EU_CONSENT_POLICY_COUNTRIES`, and the request did not resolve inside the `educator_interface`
  URL namespace. No other staff-only page extends `_base.html`.
- `VISITOR_COUNTRY_HEADER: str | None`, default `None`, declared in `freedom_ls/base/config.py`. It
  holds an HTTP header name (`X-Visitor-Country`), read through `request.headers`. A new error
  `freedom_ls_base.E003` in `freedom_ls/base/checks.py`, like `accounts` E003 for
  `TRUSTED_PROXY_IP_HEADER`, fires when the value looks like a `request.META` key (`HTTP_…`). The
  two errors share `request_meta_key_error(...)` in `freedom_ls/base/checks.py`, and the two W001
  warnings below share `pixel_without_visitor_country_warning(...)` there.
- `PixelCall` (a `NamedTuple`, like `Setting`: `method`, `name`, `condition`) and
  `pixel_call(mapping, event) -> PixelCall | None` live in `analytics_events.py`. Each platform
  app's mapping is a `dict[str, PixelCall]` keyed by analytics event name, and `pixel_call` is the
  one lookup that applies a row's condition, so neither app repeats it.
- New context processor `freedom_ls.base.context_processors.analytics_events` returns
  `analytics_events`, a callable bound to the request, so only a template that goes on to emit pops
  the session, as `google_analytics_events` does today.
- New partial `freedom_ls/base/templates/partials/analytics_events.html`. When `analytics_enabled`,
  it resolves `analytics_events` once and includes each platform's events partial with that list,
  each include guarded by that platform's context variable (`google_analytics_measurement_id`,
  `meta_pixel_id`, `tiktok_pixel_id`). It pops even when no platform is on, so events never wait for
  an ID set later. This replaces the eager discard in `google_tag_config`.
- The three include points of `partials/google_analytics_events.html` include
  `partials/analytics_events.html` instead: `freedom_ls/base/templates/_base_interface.html:208`,
  `freedom_ls/base/templates/_base.html:162`,
  `freedom_ls/course_interest/templates/course_interest/partials/express_interest_cta.html:26`. The
  first one reached in a response emits and the others find the session empty. The new partial's
  comment carries the reasoning now in `google_analytics_events.html`.

### `google_tag`

- `google_tag_config` drops `google_analytics_events` and the eager pop. It still exposes
  `google_analytics_measurement_id`, `google_ads_conversion_id` and the region list.
- `partials/google_analytics_events.html` renders from the list the neutral partial passes it,
  emitting the same `gtag('event', …)` and conversion calls as today. Ads `send_to` is still worked
  out at render time from `GOOGLE_ADS_CONVERSION_LABELS`, through a `google_ads_send_to` template
  filter in `google_tag/templatetags/google_tag_tags.py` that wraps `conversion_send_to`.
- The `<head>` include in `_base.html:90-92` is guarded by `google_analytics_measurement_id`, so a
  project without `google_tag` and its context processor renders without `TemplateDoesNotExist`.
- GA4 otherwise behaves as today, including on educator pages and for every country.

### `meta_pixel` (new app, `freedom_ls/meta_pixel/`)

- `apps.py`: `name = "freedom_ls.meta_pixel"`, `label = "freedom_ls_meta_pixel"`, `ready()`
  imports `checks`. Added to `INSTALLED_APPS` in `config/settings_base.py`.
- `config.py`: `META_PIXEL_ID: str | None`, default `None`. `config/settings_base.py` reads it from
  the `META_PIXEL_ID` environment variable, next to the Google ones (line 600).
- `context_processors.meta_pixel_config` returns `meta_pixel_id`: the configured ID when
  `ad_pixels_allowed(request)`, else `None`. Added to `TEMPLATES` in `config/settings_base.py`.
- `checks.py`: warning `freedom_ls_meta_pixel.W001` when `META_PIXEL_ID` is set and
  `VISITOR_COUNTRY_HEADER` is not, because the pixel would never load.
- The mapping, as data in `freedom_ls/meta_pixel/events.py`:

  | Analytics event | Condition | Call |
  | --- | --- | --- |
  | `course_registered` | | `fbq('track', 'CompleteRegistration', params)` |
  | `course_access_requested` | `request_kind == "application"` | `fbq('track', 'SubmitApplication', params)` |
  | `generate_lead` | | `fbq('track', 'Lead', params)` |
  | `sign_up` | | `fbq('trackCustom', 'SignUp', params)` |
  | `course_completed` | | `fbq('trackCustom', 'CourseCompleted', params)` |

  Every other event, including an interest registration, `course_started` and any name a
  downstream project records, sends nothing.
- `templates/partials/meta_pixel.html`, included in `_base.html`'s `<head>` after the Google block
  and guarded by `meta_pixel_id`. When `analytics_enabled`, it renders Meta's base code loading
  `https://connect.facebook.net/en_US/fbevents.js`, then, in this order:

  ```js
  fbq('set', 'autoConfig', false, '<id>');
  fbq('init', '<id>');
  fbq('track', 'PageView');
  ```

  `autoConfig` off stops Meta's automatic events and page-metadata scraping. No `<noscript>` image
  fallback and no `fbq.disablePushState`.
- `templates/partials/meta_pixel_events.html`: one self-removing `<script>` per mapped event, in the
  shape of `google_analytics_events.html`. Values go through `escapejs` and `inline_script_json`.
  The mapping is applied by a `meta_pixel_call` template filter in
  `meta_pixel/templatetags/meta_pixel_tags.py` (`tiktok_pixel_call` in `tiktok_pixel_tags.py` for
  TikTok), which calls `pixel_call` with the app's mapping.

### `tiktok_pixel` (new app, `freedom_ls/tiktok_pixel/`)

Same shape as `meta_pixel`: `name = "freedom_ls.tiktok_pixel"`, `label = "freedom_ls_tiktok_pixel"`,
`TIKTOK_PIXEL_ID` (env var `TIKTOK_PIXEL_ID`), `tiktok_pixel_config` returning `tiktok_pixel_id`,
warning `freedom_ls_tiktok_pixel.W001`, partials `tiktok_pixel.html` and `tiktok_pixel_events.html`.

- The mapping, in `freedom_ls/tiktok_pixel/events.py`:

  | Analytics event | Condition | Call |
  | --- | --- | --- |
  | `course_registered` | | `ttq.track('CompleteRegistration', params)` |
  | `course_access_requested` | `request_kind == "application"` | `ttq.track('SubmitApplication', params)` |
  | `generate_lead` | | `ttq.track('SubmitForm', params)` |
  | `sign_up` | | `ttq.track('SignUp', params)` |
  | `course_completed` | | `ttq.track('CourseCompleted', params)` |

- The head partial renders TikTok's base code loading `https://analytics.tiktok.com/i18n/pixel/events.js`,
  then `ttq.load('<id>'); ttq.page();`. No `holdConsent`, no `identify`.

### Page views

Each pixel sends one `PageView` per full page load from its base code, and its own
`pushState`/`replaceState` listener counts boosted and `hx-push-url` navigation. FLS adds no
page-view call. The head partials are never part of an HTMX swap (`hx-select="#interface-main"`).

### CSP (`config/settings_base.py:482-546`)

Two host groups in `SECURE_CSP_REPORT_ONLY`, each with a comment giving the reason, in the style of
the Google block:

| Directive | Meta | TikTok |
| --- | --- | --- |
| `script-src` | `https://connect.facebook.net` | `https://analytics.tiktok.com` |
| `connect-src` | `https://www.facebook.com`, `https://connect.facebook.net` | `https://analytics.tiktok.com`, `https://analytics-ipv6.tiktokw.us` |
| `img-src` | `https://www.facebook.com` | none |

The implementer confirms these against a live Pixel Helper trace with a real pixel ID and adds any
other host the trace shows.

### Privacy policy (`legal_docs/_default/privacy.md`)

"Analytics and advertising" names Google Analytics, Google Ads, Meta (Facebook and Instagram) and
TikTok. It says Meta and TikTok also use the data for their own purposes and that it is processed
outside South Africa, and that the Meta and TikTok pixels are not used for visitors in the EEA, the
UK or Switzerland. The "account number" sentence is scoped to Google Analytics, the only one that
receives it. Section 5 names the same providers. `version` goes to `"1.3"` and `effective_date`
to the release date.

## Testing

Unit and request tests, laid out as the `fls-dev:testing` skill sets out:

- `record_analytics_event` stores under `analytics_events`, dedupes, validates as before, no-ops
  with all three platform apps absent, and still records when only `meta_pixel` is installed.
- `visitor_country`: `ZA` and `za` give `ZA`. `XX`, `T1`, an empty value, `ZAF`, a missing header and
  an unset setting give `None`.
- `ad_pixels_allowed`: true for `ZA`. False for `DE`, `GB`, `CH`, `NO`, for unknown, and for an
  `educator_interface` URL with `ZA`.
- `EU_CONSENT_POLICY_COUNTRIES` has 32 unique valid ISO codes, `GB` not `UK`, `GR` not `EL`, no `ZA`.
- The `VISITOR_COUNTRY_HEADER` check and both W001 warnings fire and stay quiet correctly.
- One shared queue: a response rendering all three platforms emits each recorded event once per
  platform. With `hx-boost`, the event lands inside `#interface-main` (extend
  `test_boosted_request_keeps_the_event_inside_interface_main`). The `express_interest_cta.html`
  swap emits the interest event for GA4 and nothing for Meta or TikTok.
- A recorded event is gone after a render with no pixel IDs set.
- Each mapping row renders its exact call string. Interest registration, `course_started` and an
  unmapped downstream name render no Meta or TikTok call.
- Head partials render for a `ZA` visitor with the ID set. They are absent for `DE`, for an unknown
  country, on an educator page, on the two token-bearing allauth pages, and with the ID unset.
  Meta's `autoConfig` call renders before `init`.
- With each platform app and its context processor removed in turn, `/` and a course player page
  render without error and the other platforms still emit.
- `test_csp_report_only_header_names_meta_hosts` and `…_tiktok_hosts` in
  `freedom_ls/base/tests/test_csp.py`, in the shape of the Google ones.

QA plan items, run with Playwright MCP against the dev server using real test pixel IDs,
`VISITOR_COUNTRY_HEADER` set and the header injected:

- A full load, a player Next (`hx-boost`), a breadcrumb link (`hx-push-url`) and Back. Each forward
  navigation sends exactly one `PageView` to each platform, and Back at most one. The trace also
  records the hosts for the CSP groups.
- Each conversion moment shows once in Meta Test Events and TikTok Test Events with the mapped name.
- With the header set to `DE`, and with it absent, no request goes to either platform.

## Documentation and downstream

- **New `docs/how tos/meta-and-tiktok-pixels.md`**, shaped like the Google guide:
  - What FLS sends: the two mapping tables and the parameters. Page views come from the pixels.
    No personal data is sent.
  - Conditions for setting a pixel ID: an adult-only learner population, a privacy policy that
    names the platform, and `VISITOR_COUNTRY_HEADER` set behind a proxy that overwrites the header
    on every request. Without the header, nothing loads.
  - Environments: production sets `META_PIXEL_ID` and `TIKTOK_PIXEL_ID`, staging leaves both unset.
  - Meta Events Manager: automatic advanced matching off, custom conversions on `SignUp` and
    `CourseCompleted`, and which events are primary or secondary goals.
  - TikTok Events Manager: automatic advanced matching off, `SignUp` and `CourseCompleted`
    registered as custom events, and the goals.
  - Checking it works: each platform's Pixel Helper and Test Events.
  - For developers: turning each app off (leave it out of `INSTALLED_APPS` and drop its context
    processor), pages that don't extend `_base.html`, and a downstream event with no mapping
    sending nothing to either pixel.
- **`docs/how tos/google-analytics-and-ads.md`**: the lead-form sample uses `record_analytics_event`
  and `AnalyticsEvent` from `freedom_ls.base.analytics_events`, and `course_event_params` from
  `freedom_ls.course_access.analytics_events`. "Pages that don't extend `_base.html`" names
  `partials/analytics_events.html`. The guide links to the new one.
- **`docs/product/`**: update through `/fls-dev:update_product_docs` wherever GA4 is described as
  the only platform.
- **Upgrade notes** (`/fls-dev:update_upgrade_notes`). Breaking changes: the renamed module, enum,
  functions and session key, and `course_access.google_analytics` becoming
  `course_access.analytics_events`. Events queued under the old session key at deploy time are never
  sent. Settings changes: the two new apps in `INSTALLED_APPS` and three new context processors (all
  optional), `META_PIXEL_ID`, `TIKTOK_PIXEL_ID` and `VISITOR_COUNTRY_HEADER`. Template review: any
  override of `_base.html`, `_base_interface.html` or the old events partial.
