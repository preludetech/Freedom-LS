# Plan: educator interface looks good

Implementation plan for `idea.md` (the spec; the spec stage was skipped). A restyle only: no new
models, views, URLs, settings or migrations. Every slice edits templates in place at their existing
paths, uses only the theme tokens in `freedom_ls/themes/default/static/themes/default/theme.css`,
the existing cotton components and the semantic icon names in `freedom_ls/icons/semantic_names.py`,
and leaves behaviour, `hx-*` wiring and Alpine component logic as they are.

One deliberate exception to the brand rule that headings, links and table cells take no classes:
`data-table.html`, `panel-card.html` and `table_sheet.html` put utilities on their own `th`, `h2`
and links, because the base layer is site-wide (markdown tables, learner pages) and a component
owns its look in its own template. Nothing is added to `tailwind.components.css`.

## What exists and is reused

- **Shell.** `freedom_ls/base/templates/_base_interface.html` owns the sidebar dialog (the
  `sidePanel` Alpine controller in `freedom_ls/base/static/base/js/alpine-components.js`), which
  is the docked sidebar from `lg` up and the navigation bottom sheet below it, and the content
  header with the navigation toggle. The learner interface's course player extends the same shell
  (`freedom_ls/learner_interface/templates/learner_interface/_course_base.html`) and overrides
  `sidebar_heading_aria`, `panel_toggle_label`, `sidebar_class` and `header_extra`. The
  controller's dialog `close` handler returns focus to the toggle (`if (this.triggerEl)
  this.triggerEl.focus()` in the `init()` of `sidePanel`), and `close()` and `toggle()` are its
  public methods.
- **Educator shell.** `freedom_ls/educator_interface/templates/educator_interface/interface.html`
  slots the organisation switcher (`partials/organisation_switcher.html`), the shared nav
  (`panel_framework/partials/sidebar_nav.html`) and the user block into `sidebar_content`.
- **Tables.** `freedom_ls/panel_framework/templates/cotton/data-table.html`,
  `cotton/data-table-card.html`, `panel_framework/partials/table_toolbar.html`,
  `panel_framework/partials/table_sheet.html`, `partials/table_selection_bar.html`, the cell
  templates under `cotton/data-table-cells/` and `freedom_ls/base/templates/cotton/pagination.html`.
  `DataTable` in `freedom_ls/panel_framework/tables.py` already supplies `primary_column`,
  `secondary_columns`, `sortable_columns`, `toolbar` (the declared filters) and `card_template`.
  `LearnerDataTable` and `CohortDataTable` in `freedom_ls/educator_interface/views.py` declare no
  filters, so the learners table's filter and sort sheet shows sort only. Columns stay exactly as
  declared today.
- **Panel chrome.** `cotton/panel-card.html` (loads `panel_tags`, whose `flag` filter reads
  boolean attributes), `cotton/panel-page-header.html` (already stacks title and actions below
  `md`), `cotton/panel-definition-list.html`, `cotton/panel-definition-row.html`,

## Skills to use

- Every step that edits a template: `fls-dev:template` then `ds:template`. Templates stay at their
  current paths so theme shadowing by path keeps resolving. Django `{% comment %}` only.
- Every step that touches Tailwind classes: `fls-dev:frontend-styling` then `ds:frontend-styling`,
  with `brand-guidelines` (`visual.md`) as the component and token decision table. Read `theme.css`
  before choosing a colour, radius or font. After each slice run `npm run tailwind_build` (the
  output is gitignored).
- Every step that adds, changes, resizes or removes an icon: `fls-dev:icon-usage`. An explicit
  `class` on `<c-icon>` replaces the default `size-5`, so always pass a size.
- Steps that touch the sidebar, the navigation bottom sheet, the filter and sort sheet or the
  dialog: `ds:alpine-js` and `fls-dev:alpine-js`. The CSP build is on: no inline expressions, and
  the existing `sidePanel`, `modal`, `dropdownMenu` and `sidebarMenuItem` components are reused,
  not changed.
- Steps that touch markup carrying `hx-*` attributes: `ds:htmx`. `hx-target`, `hx-swap`,
  `hx-preserve` and the 422 contract stay as they are.
- Every test step: `fls-dev:testing` and `ds:testing` for pytest; `fls-dev:playwright-tests` and
  `ds:playwright-tests` for browser tests (every browser test carries `@pytest.mark.playwright`).
  Tests assert on structure and accessibility, never on CSS classes or padding.
- Naming: `domain-glossary`. Comments: `code-comments`. Prose: `unslop`.
- MCP: the Playwright MCP (`mcp__plugin_ds_playwright__*`) for the design check that
  `implement_plan` runs after each slice with a **Design states** line. A leftover server or
  browser is reaped with `.claude/ds/scripts/kill_runserver.sh <PORT>` and
  `.claude/ds/scripts/reap_playwright_mcp.sh`.
