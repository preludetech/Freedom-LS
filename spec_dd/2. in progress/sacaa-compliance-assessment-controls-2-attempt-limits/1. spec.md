# Spec: quiz attempt limits and waits

Idea: `idea.md`. Answers: `answers.md`. Research: `research_*.md` in this directory.

## Purpose

SACAA limits a learner to a fixed number of re-writes of a quiz. After that, the learner has to redo
the course. Today "Try Again" works without limit while the placement is open. A course author can
now cap how many sittings a learner gets at a QUIZ placement. They can also set minimum waits after
failed sittings. The server enforces both when a sitting starts. The start page and the results page
show the numbers and a live countdown.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| **attempt-limited quiz** | coined | A `Form` with `strategy` QUIZ whose `max_attempts` is above 0 or whose `retry_wait_minutes` is non-empty. It never refers to a time limit. |
| **sitting** | narrowed | One form progress record (`FormProgress`) and its course form attempt (`CourseFormAttempt`), as in the domain glossary. Here only sittings under one course progress record at one placement count. |
| `AttemptDecision` | coined | What `learner_progress/attempts.py` `attempt_decision` returns: sittings used, sittings left, when the next sitting opens, and the refusal. Follows the house `*Decision` suffix, as in `MessagingDecision`. |
| `AttemptRefusal` | coined | Why a new sitting is refused: `PASSED`, `NO_ATTEMPTS_LEFT` or `WAITING`. |

"Failed" means `form_engine.queries.quiz_verdict(form, form_progress) is False`. "Passed" means it
is `True`.

## Scope

In:

- Front matter keys `max_attempts` and `retry_wait_minutes` on QUIZ forms. Each key gets a model
  field, a migration and validator rules.
- One rule function, `attempt_decision`. `start_attempt` enforces it under its lock, and the start
  gate, the start page and the results page read it.
- Refusing a new sitting at an attempt-limited quiz once the latest completed sitting passed.
- The numbers, the `NO_ATTEMPTS_LEFT` state and a live countdown on the start page and the results
  page.
- The educator preview rows, the authoring doc, the bundled validator and the demo quiz.
- A new idea for the educator view of a learner's attempts (below).

Out:

- Any educator view of a learner's attempts used, attempts left or next opening time. This goes in
  the new idea `spec_dd/1. next/sacaa-compliance-assessment-controls-8-educator-attempt-status/idea.md`
  (`answers.md`).
- Granting an extra attempt, resetting counts and automatic course restart.
  `sacaa-compliance-assessment-controls-7-course-restart` owns the reset.
- Per-cohort overrides, and any change to how a course deadline closes a placement.
- How expired or disturbed sittings complete (specs 3 and 5). This spec only counts them.
- Non-QUIZ forms, and `course_applications`, which mints sittings for application forms without
  the gate.
- Making the start page's "Try Again" and the results page's "Retry quiz" use the same label.

## Decisions

- **Only an attempt-limited quiz refuses after a pass** (`answers.md`). A QUIZ form with neither
  key set behaves exactly as today, so the two pool-quiz re-sit tests at
  `learner_interface/tests/views/test_form_runner.py:5007` and `:5022` keep passing.
- **`max_attempts: 0` means no limit**, and 0 is the schema default. Because the default is not
  `None`, removing a key resets the stored value on the next `content_save`.
- **A sitting with no verdict** (`quiz_verdict` is `None`, for example when it has no scores)
  counts toward the cap. It is neither a failure nor a pass.
- **A wait runs only when the latest completed sitting failed** (`answers.md`). The wait is
  `retry_wait_minutes[min(N, len) - 1]` minutes, where N counts the failed sittings at this
  placement under this course progress record. It runs from that latest sitting's
  `completed_time`, and the next sitting opens when `now >= opens_at`.
- **Check order inside the lock:** an open sitting left after stale handling is reused and never
  refused. Then `PASSED`, then `NO_ATTEMPTS_LEFT`, then `WAITING`. When the last allowed sitting
  failed, the learner sees "No attempts left", not a wait.
- **A refused start redirects to the placement's start page** (`view_course_item`). The idea asked
  for a new gate outcome. A redirect is enough because the start page renders the reason from the
  same `attempt_decision` call, so a reload keeps it and no session message is needed.
- **WCAG 2.2.1 does not apply.** The wait is a gap between tasks, not a limit on one.

## Requirements

### Authoring: `form_engine/schema.py`, `form_engine/models.py`, bundled validator

1. Pydantic `Form` gains two fields beside `requires_declaration`, each with a `Field(description=...)`:
   - `max_attempts: StrictInt = Field(default=0, ge=0, le=32767)`: "QUIZ only. How many sittings a
     learner gets at this placement. 0 (the default) means no limit."
   - `retry_wait_minutes: list[StrictInt] = []`: "QUIZ only. Minimum minutes before the next sitting
     after a failed sitting: entry N follows the Nth failure, and the last entry repeats. Default:
     no waits." `StrictInt` rejects booleans and floats.
2. `validate_quiz_fields` adds `max_attempts` and `retry_wait_minutes` to the `knobs` dict, so a
   non-QUIZ form that sets either gets the existing "... should only be set when strategy is QUIZ"
   error. It also rejects these, in the same message style:
   - a `retry_wait_minutes` entry below 1;
   - an explicit empty list (`"retry_wait_minutes" in self.model_fields_set` and the list is empty).

   A wait list with `max_attempts` 0 is valid.
3. Model `Form` gains `max_attempts = PositiveSmallIntegerField(default=0)` and
   `retry_wait_minutes = JSONField(default=list, blank=True)`, each with `help_text`, in the next
   `form_engine` migration.
4. `Form.is_attempt_limited() -> bool` returns whether the form is an attempt-limited quiz.
5. `claude_plugins/fls-content/validate/schema.py` gets the same fields and rules, and
   `claude_plugins/fls-content/validate/tests/test_validator.py` gets the matching tests. The
   non-QUIZ parametrised knob test covers both keys, each with a value of its own type
   (`max_attempts: 3`, `retry_wait_minutes: [5]`).

### The rule: `learner_progress/attempts.py`

6. A `StrEnum` `AttemptRefusal` with `PASSED`, `NO_ATTEMPTS_LEFT` and `WAITING`, and a frozen
   dataclass `AttemptDecision`:

   | Field | Meaning |
   | --- | --- |
   | `used` | completed sittings at the placement under the course progress record |
   | `max_attempts` | `form.max_attempts`, `0` for no limit |
   | `left` | `max_attempts - used`, floored at 0, or `None` when there is no limit |
   | `opens_at` | when a running wait ends, else `None` |
   | `remaining_seconds` | seconds from `now` to `opens_at`, rounded up, `0` with no wait |
   | `refusal` | an `AttemptRefusal` or `None` |
7. `attempt_decision(course_progress, collection_item, form, now) -> AttemptDecision` is the only
   place the rule lives. It reads `completed_attempts(course_progress, collection_item)` (one query
   with `select_related("form")`) and applies the Decisions. For a form that is not an
   attempt-limited quiz it returns `used` and no refusal. `now` is a parameter so tests freeze no
   clock.
8. `start_attempt` takes `now` from `timezone.now()` and applies the Decisions' check order after
   `finalise_stale_incomplete` and before `get_or_create_incomplete`, inside the existing `atomic()`
   block and `CourseProgress` lock. On a refusal it skips `get_or_create_incomplete` and the
   declaration save and lets the `atomic()` block commit, so a stale sitting it completed stays
   completed. It then raises `AttemptRefused(decision)`, a new exception in the same module, after
   the block. No new sitting and no `FormDeclaration` is written.

### The gate and views: `learner_interface/views.py`

9. `_form_start_gate` reads `attempt_decision` after its existing checks. It skips the read when an
   open sitting exists. On a refusal it returns its existing `redirect` outcome, pointing at
   `view_course_item` for the placement. `FormStartGate` gets no new field. The gate stays advisory.
   It is shared by `form_start` and `form_declaration`, so a refused learner is never asked to sign.
   The finish page's `outstanding_items` re-sit link to `form_start` lands here too.
10. `form_start` and the `form_declaration` POST catch `AttemptRefused` from `start_attempt` and give
    the same redirect. That covers two concurrent starts and a stale sitting that `start_attempt`
    completes, both of which the gate cannot see.
11. `view_form` and `course_form_complete` add `attempt_decision` to their context. They compute it
    with one `now`, for the placement and course progress record they already resolve. `view_form`
    passes it to `form_start_page_buttons`.

### Buttons: `learner_interface/utils.py`

12. `form_start_page_buttons` takes `decision: AttemptDecision | None`, and every caller and test
    is updated to pass it. When the latest completed sitting failed:
    - with refusal `NO_ATTEMPTS_LEFT`, it returns no "Try Again" and no other button;
    - with refusal `WAITING`, it returns "Try Again" with a `wait` flag (the return type becomes
      `list[dict[str, str | bool]]`);
    - otherwise it returns "Try Again" as today.

### Templates: start page, results page, shared partial

13. A new partial, `learner_interface/partials/attempt_decision.html`, is included by
    `course_form.html` above the footer and by `course_form_complete.html` under the result banner.
    It renders nothing for a form that is not an attempt-limited quiz. Otherwise it shows:
    - with refusal `PASSED`, on the start page only: "You passed this quiz, so it can't be retaken."
      This shows on every visit, so a learner redirected from a typed URL sees it (`answers.md`).
    - with a cap and no pass: "Attempts: 2 of 3 used, 1 left." A quiz with no cap shows no count
      line (`answers.md`).
    - with `NO_ATTEMPTS_LEFT`: a `<c-callout tone="warning" title="No attempts left">` reading
      "You have used all 3 attempts." and nothing more (`answers.md`).
    - with `WAITING`: "You can try again at {% local_time opens_at %} (in 2 h 15 min)." The
      remaining time is server-rendered by a new filter, `wait_duration`, beside `local_time` in
      `base/templatetags/time_tags.py`, which formats `attempt_decision.remaining_seconds`. It uses
      the same format as the countdown. The reason element
      has an `id` that the Try Again button names with `aria-describedby`.
14. The waiting Try Again button is a `<c-button type="submit" disabled="disabled">` with no `href`,
    so it renders a real `<button type="submit" disabled>`. On both pages it gets
    `id="attempt-retry-button"`, the value the partial's `data-button-id` carries. It sits inside a `<form method="get">`
    whose `action` is the `form_start` URL. On the start page it keeps
    `data-testid="try-again-button"`. On the results page it takes the place of "Retry quiz", keeps
    that label and gets `data-testid="retry-quiz-button"`. With `NO_ATTEMPTS_LEFT` the results footer
    falls through to its existing non-retry branch ("Continue" or the return link). The footer's
    existing `access_ended`, `paused` and `item_closed` branches win over every state here. While
    paused, no countdown and no button are shown.
15. `course_form_complete.html`'s failed banner keeps "Review the material and try again" for an
    open retry. With `NO_ATTEMPTS_LEFT` it drops that sentence and adds no next step. With `WAITING`
    it reads "Review the material before your next attempt." (`answers.md`).

### Countdown: `learner_interface/static/learner_interface/js/alpine-components.js`

16. A new CSP-safe `Alpine.data("attemptCountdown", ...)` component sits on the partial's wait line.
    Its root carries `data-remaining-seconds` and `data-button-id`, the `id` of the Try Again button
    it enables. It sets its deadline once as `Date.now() + remaining * 1000`, from the server's
    remaining seconds rounded up, never from the server's clock time. Skew between browser and
    server therefore cancels out, and the button never enables early. It ticks once a second and
    recomputes on `visibilitychange`. It cleans up its interval and listener in `destroy()`, as
    `dateEyebrow` does. The display matches `wait_duration`: "2 h 15 min" at an hour or more,
    "14 min 5 s" under an hour, "45 s" under a minute. The ticking text is `aria-hidden="true"`. At
    zero it removes `disabled` from the button and changes the reason to "You can try again now.".
    A visually hidden `role="status"` line announces that once. Focus does not move. Without
    JavaScript the server-rendered text stays, and a reload after the wait renders the enabled
    button. The server re-checks every click.
17. `claude_plugins/fls-dev/skills/alpine-js/SKILL.md` lists `attemptCountdown` in its inventory
    table.

### Educator preview: `educator_interface/panels/course/content_preview.py`

18. `_quiz_facts` adds "Attempts allowed" ("3", or "No limit") and "Waits after a failed attempt"
    ("60, 120, 150 minutes", or "None").

### Demo content

19. `demo_content/functionality_demo_end_with_quiz/3. quiz/form.md` sets `max_attempts: 3` and
    `retry_wait_minutes: [1, 2]`. The waits are short so a QA pass can watch the countdown reach
    zero. The quiz intro does not explain the mechanics. Tests that sit this demo quiz more than
    once are updated.

## Testing

Beyond a test per requirement:

- `attempt_decision` with a frozen `now`: a wait with exactly 0 s left is open; the last entry
  repeats for the 4th failure of a 3-entry list; a no-verdict sitting counts toward the cap and ends
  any wait; a cap and a wait both due report `NO_ATTEMPTS_LEFT`; a pass at an attempt-limited quiz
  reports `PASSED`, and the same at a quiz with neither key reports none.
- Counts are per placement and per course progress record: a second placement of the form, and a
  new course progress record for the same learner, each start from 0.
- A refused `start_attempt` writes no `FormProgress`, `CourseFormAttempt` or `FormDeclaration`. An
  open sitting is reused even when the cap is used up. A stale submit-on-exit sitting that
  `start_attempt` completes is counted in the same call and stays completed when the call refuses.
- Races, in two threads against PostgreSQL (`django_db(transaction=True)`):
  - two concurrent starts for the last allowed sitting create exactly one sitting;
  - with the last allowed sitting open, answered and stale on a submit-on-exit form, two concurrent
    starts are both refused and the stale sitting ends completed.
- Typing the `form_start` URL and posting `form_declaration` while refused each redirect to the
  start page and write nothing. A refused declaration quiz never renders the declaration page.
- Start and results pages render each state's copy. The waiting button is a `<button disabled>`
  with `aria-describedby` pointing at the reason. A paused learner sees neither the countdown nor
  the button. `wait_duration` and `attemptCountdown` give the same strings for the same seconds.
- Removing both keys from front matter resets the model fields on the next `content_save`.
- Validator: a non-QUIZ form with either key, a zero or negative wait, a boolean or float entry, an
  explicit empty list and a `max_attempts` above 32767 are each rejected in both copies of the
  schema.
- Playwright: on a seeded waiting state with a few seconds left, the button turns enabled with no
  reload, and clicking it starts a sitting.

## Open questions

- Q: Does a non-QUIZ form that writes `max_attempts: 0` get rejected? → A: No. The truthiness-based
  `knobs` check lets it through, and 0 changes nothing. (assumed default: harmless, it equals the
  default. Overrule by editing requirement 2.)
- Q: How does the countdown reach the button in the footer? → A: Through `data-button-id` on the
  countdown root. (assumed default: works under the CSP build with no shared Alpine scope.
  Overrule by editing requirement 16.)
- Q: Is the "(in 2 h 15 min)" text server-rendered? → A: Yes, by a `wait_duration` filter matching
  the countdown. (assumed default: keeps the no-JavaScript page complete. Overrule by editing
  requirement 13.)
- Q: Which names does the spec use? → A: "attempt-limited quiz", `AttemptDecision`, "No attempts
  left" rather than "locked", and "placement" rather than "item". (assumed default: avoids words the
  glossary already gives to time limits, outline locks and collection items. Overrule by editing
  Terminology.)

## Success criteria

- A QUIZ form with `max_attempts: 2` lets a learner complete two sittings at a placement. A third
  start, by button or by typed URL, redirects to the start page showing "You have used all 2
  attempts.".
- With `retry_wait_minutes: [60]`, the first failure shows "You can try again at <time> (in 1 h 0
  min)", and a typed `form_start` URL before then writes nothing.
- On a page left open, the Try Again button becomes active at zero with no reload.
- A passed learner at an attempt-limited quiz cannot start a sitting and sees "You passed this
  quiz, so it can't be retaken.". A passed learner at a QUIZ with neither key can start one, as
  today.
- A form without the new keys saves with `max_attempts` 0 and `retry_wait_minutes` `[]`, and its
  pages look as they do today.
