# Spec: quiz attempt limits and waits

Idea: `idea.md`. Answers: `answers.md`. Research: `research_*.md` in this directory.

## Purpose

SACAA limits a learner to a fixed number of re-writes of a quiz. After that, the learner has to redo
the course. Today "Try Again" works without limit while the item is open. A content author can now
cap how many sittings a learner gets at a QUIZ placement. They can also set minimum waits after
failed sittings. The server enforces both when a sitting starts. The start page and the results page
show the numbers and a live countdown.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| **limited quiz** | coined | A `Form` with `strategy` QUIZ whose `max_attempts` is above 0 or whose `retry_wait_minutes` is non-empty. |
| **sitting** | narrowed | One form progress record (`FormProgress`) and its course form attempt (`CourseFormAttempt`), as in the domain glossary. Here only sittings under one `CourseProgress` record at one placement count. |
| `AttemptAllowance` | coined | What `learner_progress/attempts.py` `attempt_allowance` returns: sittings used, sittings left, when the next sitting opens, and the refusal. No existing term covers it. |
| `AttemptRefusal` | coined | Why a new sitting is refused: `PASSED`, `NO_ATTEMPTS_LEFT` or `WAITING`. |

"Failed" means `form_engine.queries.quiz_verdict(form, form_progress) is False`. "Passed" means it
is `True`.

## Scope

In:

- Front matter keys `max_attempts` and `retry_wait_minutes` on QUIZ forms. Each key gets a model
  field, a migration and validator rules.
- One rule function, `attempt_allowance`. `start_attempt` enforces it under its lock, and the start
  gate, the start page and the results page read it.
- Refusing a new sitting at a limited quiz once the latest completed sitting passed.
- The numbers, the locked state and a live countdown on the start page and the results page.
- The educator preview rows, the authoring doc, the bundled validator and the demo quiz.
- A new idea for the educator view of a learner's attempts (below).

Out:

- Any educator view of a learner's attempts used, attempts left or next opening time. This goes in
  the new idea `spec_dd/1. next/sacaa-compliance-assessment-controls-8-educator-attempt-status/idea.md`,
  which this spec adds (`answers.md`).
- Granting an extra attempt, resetting counts and automatic course restart.
  `sacaa-compliance-assessment-controls-7-course-restart` owns the reset.
- Per-cohort overrides, and any change to how a course deadline closes an item.
- How expired or disturbed sittings complete (specs 3 and 5). This spec only counts them.
- Non-QUIZ forms, and `course_applications`, which mints sittings for application forms without
  the gate.
- Making the start page's "Try Again" and the results page's "Retry quiz" use the same label.

## Decisions

- **Only a limited quiz refuses after a pass** (`answers.md`). A QUIZ form with neither key set
  behaves exactly as today, so the two pool-quiz re-sit tests at
  `learner_interface/tests/views/test_form_runner.py:5007` and `:5022` keep passing.
- **`max_attempts: 0` means no limit**, and 0 is the schema default. Moodle uses the same
  convention. A non-`None` default is written on every `content_save`, so removing the key resets
  the stored value (`content_save.py` `save_with_uuid` dumps with `exclude_none=True`).
- **A sitting with no verdict** (`quiz_verdict` is `None`, for example when it has no scores)
  counts toward the cap. It is neither a failure (no wait) nor a pass.
- **The wait for failure N** is `retry_wait_minutes[min(N, len) - 1]` minutes, where N counts the
  failed sittings at this placement under this record. It runs from the `completed_time` of the
  latest failed sitting. The next sitting opens when `now >= opens_at`.
- **Check order inside the lock:** an open sitting left after stale handling is reused and never
  refused. Then `PASSED`, then `NO_ATTEMPTS_LEFT`, then `WAITING`. When the last allowed sitting
  failed, the learner sees "locked", not a wait.
- **A refused start writes nothing and redirects to the item's start page** (`view_course_item`).
  That page renders the reason from the same `attempt_allowance` call, so a reload keeps the reason
  and no session message is needed. A redirect also fits the gate's existing `redirect` outcome and
  the deadlines precedent for closed items.
- **The countdown counts from the server's remaining seconds**, not from the browser clock. It sets
  its target as `Date.now() + remaining_seconds * 1000` once at load, so clock skew between browser
  and server cancels out, and a sleeping tab recomputes correctly when it wakes. Remaining seconds
  are rounded up, so the button never enables early. The click is re-checked on the server anyway.
- **WCAG 2.2.1 does not apply to the wait.** The wait is not a time limit on the learner's task but
  a regulatory gap between tasks, and leaving the page loses nothing.

## Requirements

### Authoring: `form_engine/schema.py`, `form_engine/models.py`, bundled validator

1. Pydantic `Form` gains two fields beside `requires_declaration`, each with a `Field(description=...)`:
   - `max_attempts: int = Field(default=0, ge=0)`: "QUIZ only. How many sittings a learner gets at
     this placement. 0 (the default) means no limit."
   - `retry_wait_minutes: list[StrictInt] = []`: "QUIZ only. Minimum minutes before the next sitting
     after each failed sitting: entry N follows the Nth failure, and the last entry repeats.
     Default: no waits." `StrictInt` rejects booleans and floats.
2. `validate_quiz_fields` adds `max_attempts` and `retry_wait_minutes` to the `knobs` dict, so a
   non-QUIZ form that sets either gets the existing "... should only be set when strategy is QUIZ"
   error. It also rejects these, in the same message style:
   - a `retry_wait_minutes` entry below 1;
   - an explicit empty list (`"retry_wait_minutes" in self.model_fields_set` and the list is empty).

   A wait list with `max_attempts` 0 is valid.
3. Model `Form` gains `max_attempts = PositiveSmallIntegerField(default=0)` and
   `retry_wait_minutes = JSONField(default=list, blank=True)`, each with `help_text`. The migration
   is the next `form_engine` number. Specs 3 and 5 also add `Form` migrations, so whichever lands
   second renumbers its own.
4. `Form.is_limited_quiz() -> bool` returns whether the form is a limited quiz.
5. `claude_plugins/fls-content/validate/schema.py` gets the same fields and rules, and
   `claude_plugins/fls-content/validate/tests/test_validator.py` gets the matching tests. The
   non-QUIZ parametrised knob test covers both keys.

### The rule: `learner_progress/attempts.py`

6. A `StrEnum` `AttemptRefusal` with `PASSED`, `NO_ATTEMPTS_LEFT` and `WAITING`, and a frozen
   dataclass `AttemptAllowance`:

   | Field | Meaning |
   | --- | --- |
   | `used` | completed sittings at the placement under the record |
   | `max_attempts` | `form.max_attempts`, `0` for no limit |
   | `left` | `max_attempts - used`, floored at 0, or `None` when there is no limit |
   | `opens_at` | when a running wait ends, else `None` |
   | `refusal` | an `AttemptRefusal` or `None` |

   It also has a `remaining_seconds(now) -> int` method that rounds up and is 0 when there is no wait.
7. `attempt_allowance(course_progress, collection_item, form, now) -> AttemptAllowance` is the only
   place the rule lives. It reads `completed_attempts(course_progress, collection_item)` (one query
   with `select_related("form")`) and applies the Decisions. For a form that is not a limited quiz
   it returns `used` and no refusal. `now` is a parameter so tests freeze no clock.
8. `start_attempt` takes `now` from `timezone.now()` and checks the rule after
   `finalise_stale_incomplete` and before `get_or_create_incomplete`, inside the existing `atomic()`
   block and `CourseProgress` lock. It runs the check only when no open sitting is left after stale
   handling. When the check refuses, it raises `AttemptRefused(allowance)`, a new exception in the
   same module. The raise rolls back the transaction, so no sitting and no `FormDeclaration` is
   written. Callers that pass `declaration` get the same check before the declaration is saved.

### The gate and views: `learner_interface/views.py`

9. `_form_start_gate` reads `attempt_allowance` after its existing checks. It skips the read when an
   open sitting exists. On a refusal it returns its existing `redirect` outcome, pointing at
   `view_course_item` for the placement. `FormStartGate` gets no new field. The gate stays advisory.
   It is shared by `form_start` and `form_declaration`, so a refused learner is never asked to sign.
10. `form_start` and the `form_declaration` POST catch `AttemptRefused` from `start_attempt` and give
    the same redirect. That covers two concurrent starts and a stale sitting that `start_attempt`
    completes, both of which the gate cannot see.
11. `view_form` and `course_form_complete` add `attempt_allowance` (as `allowance`) to their
    context. They compute it with one `now`, for the placement and record they already resolve.
    `view_form` passes it to `form_start_page_buttons`.

### Buttons: `learner_interface/utils.py`

12. `form_start_page_buttons` takes `allowance: AttemptAllowance | None`, and every caller and test
    is updated to pass it. When the latest completed sitting failed:
    - with refusal `NO_ATTEMPTS_LEFT`, it returns no "Try Again" and no other button;
    - with refusal `WAITING`, it returns "Try Again" with a `wait` flag and no `href` change;
    - otherwise it returns "Try Again" as today.
13. `outstanding_items` on the finish page still links to `form_start` for a re-sit. A capped or
    waiting learner who follows it lands on the start page with the reason (requirement 9). No
    change there.

### Templates: start page, results page, shared partial

14. A new partial, `learner_interface/partials/attempt_allowance.html`, is included by
    `course_form.html` above the footer and by `course_form_complete.html` under the result banner.
    It renders nothing for a form that is not a limited quiz, or when the latest completed sitting
    passed. Otherwise it shows:
    - with a cap: "Attempts: 2 of 3 used, 1 left."
    - with `NO_ATTEMPTS_LEFT`: a `<c-callout tone="warning" title="No attempts left">` reading
      "You have used all 3 attempts." and nothing more (`answers.md`).
    - with `WAITING`: "You can try again at {% local_time opens_at %} (in <countdown>)." The reason
      element has an `id` that the Try Again button names with `aria-describedby`.
15. The waiting Try Again button is a `<c-button>` with no `href`, so it renders a real
    `<button disabled>`. It sits inside a `<form method="get">` whose `action` is the `form_start`
    URL. At zero the countdown removes `disabled` and changes the reason to "You can try again now.".
    On the start page it keeps `data-testid="try-again-button"`. On the results page it takes the
    place of "Retry quiz", keeps that label and gets `data-testid="retry-quiz-button"`. With
    `NO_ATTEMPTS_LEFT` the results footer falls through to its existing non-retry branch
    ("Continue" or the return link). The footer's existing `access_ended`, `paused` and
    `item_closed` branches win over every state here. While paused, no countdown and no button are
    shown.
16. `course_form_complete.html`'s failed-banner copy "Review the material and try again" gets one
    more branch per refusal, following the `item_closed` pattern. It offers no invitation to try
    again when the footer offers no button.

### Countdown: `learner_interface/static/learner_interface/js/alpine-components.js`

17. A new CSP-safe `Alpine.data("attemptCountdown", ...)` component reads `data-remaining-seconds`
    from its root. It sets its deadline as `Date.now() + remaining * 1000` once, ticks once a
    second, and recomputes on `visibilitychange`. It cleans up its interval and listener in
    `destroy()`, as `dateEyebrow` does. The display shows "2 h 15 min" at an hour or more,
    "14 min 5 s" under an hour, and "45 s" under a minute. The ticking text is `aria-hidden="true"`.
    A visually hidden `role="status"` line announces only once, at zero: "You can try again now.".
    Focus does not move. Without JavaScript the server-rendered time stays, and a reload after the
    wait renders the enabled button.
18. `claude_plugins/fls-dev/skills/alpine-js/SKILL.md` lists `attemptCountdown` in its inventory
    table.

### Educator preview: `educator_interface/panels/course/content_preview.py`

19. `_quiz_facts` adds "Attempts allowed" ("3", or "No limit") and "Waits after a failed attempt"
    ("60, 120, 150 minutes", or "None").

### Demo content

20. `demo_content/functionality_demo_end_with_quiz/3. quiz/form.md` sets `max_attempts: 3` and
    `retry_wait_minutes: [1, 2]`. The waits are short so a QA pass can watch the countdown reach
    zero. The quiz intro does not explain the mechanics. Tests that sit this demo quiz more than
    once are updated.

## Testing

Beyond a test per requirement:

- `attempt_allowance` with a frozen `now`: a wait of exactly 0 s left is open; the last entry
  repeats for the 4th failure of a 3-entry list; a no-verdict sitting counts toward the cap but
  starts no wait; a cap and a wait both due report `NO_ATTEMPTS_LEFT`; a pass at a limited quiz
  reports `PASSED`, and the same at an unlimited quiz reports none.
- Counts are per placement and per `CourseProgress`: a second placement of the form, and a new
  record for the same learner, each start from 0.
- `start_attempt` refused writes no `FormProgress`, `CourseFormAttempt` or `FormDeclaration`. An
  open sitting is reused even when the cap is used up. A stale submit-on-exit sitting that
  `start_attempt` completes is counted in the same call.
- Two concurrent `start_attempt` calls for the last allowed sitting, in two threads against
  PostgreSQL (`django_db(transaction=True)`): exactly one sitting is created.
- Typing the `form_start` URL and posting `form_declaration` while refused each redirect to the
  start page and write nothing. A refused declaration quiz never renders the declaration page.
- Start and results pages render each state's copy. The waiting button is a `<button disabled>`
  with `aria-describedby` pointing at the reason. A paused learner sees neither the countdown nor
  the button.
- Removing both keys from front matter resets the model fields on the next `content_save`.
- Validator: a non-QUIZ form with either key, a zero or negative wait, a boolean or float entry,
  and an explicit empty list are each rejected in both copies of the schema.
- Playwright: on a seeded waiting state with a few seconds left, the button turns enabled with no
  reload, and clicking it starts a sitting.

## Documentation and downstream

- `claude_plugins/fls-content/skills/content-types/resources/form-files.md`: the two keys in the
  front matter table, the QUIZ-only paragraph and the QUIZ example.
- Specs 3 and 5 must set a sitting's `completed_time` to the moment it expired or was disturbed,

  or extend `attemptCountdown` rather than add a second component.
- Product docs and upgrade notes are written by the `/sdd:document` hooks.

## Success criteria

- A QUIZ form with `max_attempts: 2` lets a learner complete two sittings at a placement. A third
  start, by button or by typed URL, redirects to the start page showing "You have used all 2
  attempts.".
- With `retry_wait_minutes: [60]`, the first failure shows "You can try again at <time> (in 1 h 0
  min)", and a typed `form_start` URL before then writes nothing.
- On a page left open, the Try Again button becomes active at zero with no reload.
- A passed learner at a limited quiz cannot start a sitting. A passed learner at a QUIZ with neither
  key can, as today.
- A form without the new keys saves with `max_attempts` 0 and `retry_wait_minutes` `[]`, and its
  pages look as they do today.
- `uv run pytest` passes, including the race test.
