## Task 1 — The two contract tests (TDD: write these first, confirm RED)

**File:** `freedom_ls/base/tests/test_theme_tokens.py`

Append to the existing `# --- tailwind.components.css contract ---` section, and add a new section
for the `first_class` assertion.

**The trap to avoid.** A naive `assert ".btn-sm" in css` passes *today*, because the string `.btn-sm`
is a substring of the existing `.btn.btn-sm`. That test would never go red and would prove nothing.
The declaration test must match the selector at the start of a line.

```python
# add to the existing imports
import re


def test_components_css_declares_btn_sm_as_single_class() -> None:
    """`.btn-sm` is a single class so a theme can reach small-button padding."""
    css = COMPONENTS_CSS.read_text()
    assert ".btn.btn-sm" not in css
    assert re.search(r"^\s*\.btn-sm\s*\{", css, re.MULTILINE) is not None


def test_first_class_theme_declares_btn_sm() -> None:
    """`.btn-sm` sits at equal specificity to `.btn`, so a theme reopening
    `.btn` padding must reopen `.btn-sm` too or its small buttons take the
    full-size padding."""
    css = FIRST_CLASS_THEME_CSS.read_text()
    assert re.search(r"^\s*\.btn-sm\s*\{", css, re.MULTILINE) is not None
```

Run `uv run pytest freedom_ls/base/tests/test_theme_tokens.py` and confirm **both new tests fail**
before touching any CSS. `test_components_css_declares_btn_sm_as_single_class` fails on the
`.btn.btn-sm` assertion; `test_first_class_theme_declares_btn_sm` fails on the regex.

Do not add tests for padding values, gap values, icon size classes or rendered markup. The spec puts
those in visual QA, and `freedom_ls/learner_interface/tests/test_course_cards.py:1-6` records the
project convention against CSS-class assertions.

## Task 2 — The button contract in `tailwind.components.css`

### 2a. `.btn` gains `gap-2`

Lines 163-168. Add `gap-2` after `justify-center`; change nothing else.

```css
.btn {
    @apply inline-flex items-center justify-center gap-2 px-6 py-2 font-medium rounded-md
           focus:outline-none focus:ring-2 focus:ring-offset-2
           disabled:opacity-50 disabled:cursor-not-allowed
           no-underline cursor-pointer transition-colors
}
```

`gap-2` is 8px, which is exactly the `mr-2`/`ml-2` it replaces, so default-size buttons see no
spacing change.

### 2b. `.btn.btn-sm` becomes `.btn-sm`

Lines 210-213. The comment at line 210 is **replaced, not deleted** — its "must come after `.btn`"
note still holds and the new text has to carry it. The rule keeps its position after `.btn`, which is
what makes it win at equal specificity.

```css
/* Small button size. Single class on purpose: the compound `.btn.btn-sm`
 * outranked every theme's `.btn`, so no theme could reach these numbers.
 * The cost of the single class is that a theme reopening `.btn` padding
 * must reopen `.btn-sm` too. See docs/how tos/theme-fls.md, Tier 2. */
.btn-sm {
    @apply px-3 py-2 gap-1.5 text-sm
}
```

Padding rises from `px-2 py-1.5` to `px-3 py-2`. `gap-1.5` (6px) is proportionate to the smaller box
and its 16px icon.

### 2c. `.htmx-hide-on-request` gets a base rule

A loading button wraps its icons and label in `<span class="htmx-hide-on-request">`
(`cotton/button.html:47`, the class's only consumer). That span is a flex *item* of `.btn`, not a
flex container, so the button's `gap` never reaches the icons inside it.

Add the base rule inside the existing HTMX block, immediately after the
`/* HTMX request state utilities for loading indicators */` comment at line 519 and before the
existing `.htmx-request .htmx-hide-on-request` rule:

```css
.htmx-hide-on-request {
    display: inline-flex;
    align-items: center;
    gap: inherit;
}
```

`gap` is not an inherited property, so the explicit `inherit` keyword is what pulls the button's own
gap down — a small loading button keeps 6px, a default one 8px. The existing
`.htmx-request .htmx-hide-on-request { display: none }` is `(0,2,0)` against this rule's `(0,1,0)`,
so it still wins during a request regardless of source order.

Do not shorten this to `display: contents`. It would work — the icons and label would become direct
flex items of `.btn` and pick up its `gap` with one declaration instead of three — but
`display: contents` has a history of assistive-technology quirks and appears nowhere else in this
codebase. Take the explicit nested flex container.

## Task 3 — `first_class` declares `.btn-sm`

**File:** `freedom_ls/themes/first_class/static/themes/first_class/theme.css`

The theme reopens `.btn` at lines 95-99 with `px-6 py-3`. Once `.btn-sm` is a single class the two
sit at equal specificity, and `tailwind.input.css` imports the active theme (line 33) after the
components layer (line 19), so the theme's `.btn` wins on source order. Without a theme `.btn-sm`,
small buttons come out at `px-6 py-3`.

Add inside the same `@layer components` block, next to `.btn-secondary`:

```css
.btn-sm {
    @apply px-3 py-2;
}
```

Padding only. `text-sm` already arrives from both the base `.btn-sm` and the theme's own `.btn`;
`gap-1.5` comes from the base rule, which the theme does not contest.

The spec's open question — whether `first_class`'s small button should be scaled to its own
`px-6 py-3` rather than matching the base — ships as `px-3 py-2`. Do not deviate.

## Task 4 — Icon spacing and size in `cotton/button.html`

**File:** `freedom_ls/base/templates/cotton/button.html`

The `.btn` path must render `size-4` icons on a small button and `size-5` otherwise, and must carry
no icon margins. **One** conditional decides both, so the size class and the icon class cannot drift
apart.

### 4a. Wrap the non-dropdown branch in a `{% with %}`

Open it immediately after `{% else %}` (line 35) and close it immediately before `{% endif %}`
(line 53), so it wraps the whole branch, lines 36-52:

```django
{% with size_class=size|yesno:"btn-sm," icon_class=size|yesno:"size-4,size-5" %}
```

`yesno` makes `size` truthiness-based where line 43 tested equality against `'small'`. `size`
recognises only `"small"` today, so the two agree for every supported value.

### 4b. Line 43 — the class string

```django
class="btn btn-{{ variant }} {{ size_class }} {{ class }}"
```

### 4c. Lines 47, 48, 50 — the icons

Drop every `mr-2` / `ml-2` on this path and take the computed class:

- Line 47 (inside `.htmx-hide-on-request`): both icons become `class="{{ icon_class }}"`.
- Line 48 (the spinner): `class="{{ icon_class }} animate-spin"`. Its literal space before
  `{{ loading_text }}` **stays** — that span is `.htmx-show-on-request`, which is already
  `inline-flex` with its own `gap` (`tailwind.components.css:528-532`).
- Line 50 (the non-loading path): both icons become `class="{{ icon_class }}"`.

### 4d. Line 32 — the dropdown variant keeps its margins, with a comment

The dropdown container is `block w-full text-left` (class string at line 20, applied at line 29), not
a flex box, so a container `gap` would silently do nothing and converting a menu item to flex would
change its layout for no gain. The template ends up carrying two spacing idioms, so line 32 needs a
comment saying why:

```django
{% comment %}These icons keep margins: the menu-item container above is a block,
not a flex box, so the `gap` that spaces icons on the .btn path has nothing to
act on here.{% endcomment %}
```

Leave the `size-5` literals on line 32 as they are — `size` is not a dropdown prop.

### 4e. Update the usage comment

The comment block at lines 55-96 must say the `size` prop takes `"small"` or nothing. Amend the
existing `<!-- Small size -->` example (lines 76-77) rather than adding a new block, e.g.

```
  <!-- Small size. The only value `size` takes; anything else, including
       omitting it, renders a default-size button. Small buttons get
       size-4 icons, everything else size-5. -->
  <c-button size="small">Small button</c-button>
```

### Note on the rendered output

With `size` empty, line 43 renders a double space in the `class` attribute. That is inert in HTML and
no test asserts on it; do not add a `{% spaceless %}` or a filter chain to tidy it.

`freedom_ls/base/tests/test_button_component.py` covers the `loading` prop's rendered markup and must

## Task 6 — The side-panel focus indicator

**File:** `tailwind.base_interface.css`

Add at the **top level** of the existing `@layer components` block, outside both `@media` blocks —
desktop column and mobile overlay both take focus when they open, so both want the rule. Place it
after the `.side-panel-grid` rule (ends line 22) and before the `max-width: 1023.98px` media block
(opens line 26).

```css
/* The docked desktop panel is opened with dialog.show(), which runs the
 * dialog focusing steps; with no autofocus in the subtree the <dialog>
 * itself takes focus, so this paints on every page load. It is a real
 * :focus-visible indicator, not a spurious ring. Replace it, never remove
 * it. `outline` rather than a Tailwind ring-*, because ring-* compiles to
 * box-shadow, which forced-colors mode suppresses outright. */
.side-panel-dialog:focus-visible {
    outline: 2px solid var(--color-focus-ring);
    outline-offset: -2px;
}
```

Setting `outline` replaces the UA outline outright, so there is no separate `outline: none` step, and
`outline` is recoloured rather than dropped under `forced-colors`, so no
`@media (forced-colors: active)` block is needed. Do not add one.

`outline-offset: -2px` draws the line flush inside the dialog's edge. On desktop the dialog is a
sticky, full-height, full-width box (the `min-width: 1024px` block, lines 120-125) and
`.side-panel-body` fills it with `bg-sidepanel`, so the outline paints over the side-panel surface.

**Do not** add `tabindex` to the `<dialog>` at `_base_interface.html:53-56`, or `autofocus` anywhere in
its subtree. The focusing steps target the dialog regardless; a `tabindex` would make the whole
column a tab stop, and an `autofocus` would only relocate the ring while throwing screen-reader focus
into the panel on every page load. `_base_interface.html` and `alpine-components.js` are unchanged.

Whether a permanently docked, non-dismissible desktop column should run the dialog focusing steps at
all is explicitly out of scope. Leave `data-desktop-lock="true"` (`_base_interface.html:22`) alone.
