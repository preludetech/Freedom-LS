# Spec: three visual defects in shared FLS chrome

## Purpose

Visual QA of the `first_class` theme found three defects, all of them in shared FLS CSS or a shared
cotton component, so every consumer hits them whatever theme is active. `idea.md` and the three
per-defect directories beside it carry the mechanism for each; `buttons.png` and
`dashboard cards.png` are the evidence.

- Small buttons crowd their icon. The course player's Next arrow reads as jammed against the button's
  right edge.
- Course-card Details links sit at different heights across a grid, so the row of links reads as
  ragged.
- The docked side panel paints a focus outline around its whole column on every page load.

The first is a symptom of a deeper fault. `.btn.btn-sm` is written as a compound selector, which puts
small-button padding permanently out of reach of the theming contract. The padding and the selector
are fixed together, because fixing only the padding leaves the next theme in the same trap.

## Scope

**In.** The `.btn`/`.btn-sm` size contract and its icon spacing; the `first_class` theme's companion
`.btn-sm` rule; the `.course-card-body` flex-column change and the Details wrapper that pins to it;
an author-drawn focus indicator for `.side-panel-dialog`; the Tier 2 section of
`docs/how tos/theme-fls.md`.

**Out.**

- A hard 44px hit-target floor for every small button. `px-3 py-2` stops short of WCAG 2.2 SC 2.5.5
  Target Size (Enhanced, Level AAA) on purpose; going further is a much larger visual change and
  should be decided on its own.
- Whether a permanently docked, non-dismissible desktop column should run the dialog focusing steps
  at all. `data-desktop-lock="true"` is hardcoded in the shared shell, so changing it reaches the
  learner, educator and `panel_framework` interfaces at once and needs its own QA pass. The restyle
  below stands whichever way that goes. The mobile path is a separate matter, and `showModal()`
  earns its keep there.
- `.btn-secondary`'s `border-2` in `first_class` (`theme.css:101-103`). It contributes 2px of the
  asymmetry between Previous and Next, but is not worth separate action.
- Driving `.btn` padding through CSS custom properties, Bootstrap-style. It removes the trap
  structurally, but rewrites every `.btn` consumer and introduces a second sizing idiom alongside
  `.chip-xs` (`tailwind.components.css:259-261`), a plain single class. Revisit it if a `.btn-lg` or
  a second sized component hits the same trap.

## Decisions

**The side panel's focus indicator is held to WCAG 2.2 SC 2.4.7 Focus Visible and the 3:1 contrast
bar reaching it through SC 1.4.11 Non-text Contrast, both Level AA. SC 2.4.13 Focus Appearance
(Level AAA) is not a target here.** SC 2.4.13 measures area against the unfocused component's own
perimeter, and the component is the whole column, so under it nothing smaller than a full-column ring
could conform. The indicator that ships still traces the column, but by choice.

**The indicator is drawn with `outline`, not Tailwind's `ring-*` utilities.** This departs from the
house pattern, where `.flashcard-trigger:focus-visible` (`tailwind.components.css:428-430`) and the
four `--color-focus-ring` consumers all use `ring-2`. Tailwind's `ring-*` compiles to `box-shadow`,
which `forced-colors` mode suppresses entirely. `outline` is recoloured rather than dropped, so no
`@media (forced-colors: active)` block is needed, and setting it replaces the UA outline outright,
so no separate `outline: none` step.

**Icon spacing moves to a `gap`; the icon margins go.** `gap` is the idiom everywhere else in the
codebase. `cotton/button-group.html`, `.task-list-item` and the HTMX loading-state rule all space
children with it, and `cotton/button.html`'s `mr-2`/`ml-2` are the only child margins doing it the
other way. It also fixes two cases the margins get wrong. An icon with no label still reserves its
margin, and a button carrying both a leading and a trailing icon only gets one of them spaced. The
margin removal and the `gap` must land together, since removing the margins alone leaves icon and
label touching.

**Padding stays symmetric.** Material 3 shrinks the icon-adjacent edge to correct exactly this
optical crowding, and it is rejected. The padding rule would have to know which side carries the
icon, so it needs either a second template-level class or a `:has()` selector, a second spacing idiom
on top of the `gap` change. The crowding is attacked at its source instead, by raising the padding
and shrinking the icon in the same change. If QA still reads the trailing arrow as crowded, asymmetric
padding is a scoped follow-up, not a reason to hold this.

**The card footer is pinned with flex column plus `margin-top: auto`.** CSS `subgrid` across sibling
cards assumes a matching row count per card and the variants differ; adding a dedicated actions slot
to the shell changes the component's prop contract for the same visual result. No `mt-auto` exists
anywhere in the repo today, so this introduces the pattern rather than following one.

**The selector contract gets a committed test; the three visual outcomes do not.** The reopen-both
rule is a silent breaking change for any theme that reopens `.btn`, and
`freedom_ls/base/tests/test_theme_tokens.py` is the established place to assert on source CSS files
for the component contract. Pixel outcomes stay visual QA. See Testing.

## Requirements

### 1. The button contract in `tailwind.components.css`

`.btn` (163-168) gains `gap-2`. Everything else in the rule stays.

```css
.btn {
    @apply inline-flex items-center justify-center gap-2 px-6 py-2 font-medium rounded-md
           focus:outline-none focus:ring-2 focus:ring-offset-2
           disabled:opacity-50 disabled:cursor-not-allowed
           no-underline cursor-pointer transition-colors
}
```

`.btn.btn-sm` (211-213) becomes a single class. It keeps its position after `.btn`, which is what
makes it win at equal specificity. The existing comment at line 210 is replaced, not deleted. Its
"must come after `.btn`" note still holds, and the new text carries it.

```css
/* Small button size. Single class on purpose: the compound `.btn.btn-sm`
 * outranked every theme's `.btn`, so no theme could reach these numbers.
 * The cost of the single class is that a theme reopening `.btn` padding
 * must reopen `.btn-sm` too. See docs/how tos/theme-fls.md, Tier 2. */
.btn-sm {
    @apply px-3 py-2 gap-1.5 text-sm
}
```

`gap-2` (8px) matches the `mr-2`/`ml-2` it replaces, so default-size buttons see no spacing change.
`gap-1.5` (6px) is proportionate to `.btn-sm`'s smaller box and 16px icon.

A loading button wraps its icons and label in `<span class="htmx-hide-on-request">`. That span is a
flex item of `.btn`, not a flex container of its own, so the button's `gap` never reaches the icons
inside it. Give the span a gap. Add a base rule beside the existing HTMX block (519-532):

```css
.htmx-hide-on-request {
    display: inline-flex;
    align-items: center;
    gap: inherit;
}
```

`gap: inherit` takes the button's own gap, so a small loading button keeps 6px. The existing
`.htmx-request .htmx-hide-on-request { display: none }` is more specific and still wins during a
request. `cotton/button.html:47` is the class's only consumer.

### 2. Icon spacing and size in `freedom_ls/base/templates/cotton/button.html`

The `.btn` path must render `size-4` icons on a small button and `size-5` otherwise, and must carry
no icon margins. One conditional decides both, so the size class and the icon class cannot drift
apart.

Replace the `{% if size == 'small' %}` at line 43 with a `{% with %}` wrapping the whole non-dropdown
branch:

```django
{% with size_class=size|yesno:"btn-sm," icon_class=size|yesno:"size-4,size-5" %}
```

- Line 43 becomes `class="btn btn-{{ variant }} {{ size_class }} {{ class }}"`.
- Lines 47 and 50 drop `mr-2`/`ml-2` and take `class="{{ icon_class }}"`.
- Line 48's spinner becomes `class="{{ icon_class }} animate-spin"`. Its literal space before
  `{{ loading_text }}` can stay: that span is `.htmx-show-on-request`, already `inline-flex` with its
  own `gap` (`tailwind.components.css:528-532`).

`yesno` makes `size` truthiness-based where line 43 tested equality. `size` recognises only `"small"`
today, so the two agree for every supported value; the `<c-vars>` block and the usage comment at
lines 55-96 must say the prop takes `"small"` or nothing.

The dropdown variant keeps `mr-2`/`ml-2` at line 32. Its container is `block w-full text-left` (the
class string is at line 20, applied at line 29), not a flex box, so a container `gap` would silently
do nothing there, and converting a menu item to flex would change its layout for no gain. The
template ends up carrying two spacing idioms; line 32 needs a comment saying why.

### 3. The `first_class` theme

`freedom_ls/themes/first_class/static/themes/first_class/theme.css` reopens `.btn` at 95-99 with
`px-6 py-3` but has no `.btn-sm`. Once `.btn-sm` is a single class, the theme's `.btn` beats it on
source order, because `tailwind.input.css` imports the active theme (line 33) after the components
layer (line 19). The theme must declare `.btn-sm` or small buttons come out at `px-6 py-3`.

Add to the same `@layer components` block, next to `.btn-secondary`:

```css
.btn-sm {
    @apply px-3 py-2;
}
```

Padding only. `text-sm` comes from both the base `.btn-sm` and the theme's own `.btn`; `gap-1.5`
comes from the base rule, which the theme does not contest.

`freedom_ls/themes/default/static/themes/default/theme.css` is tokens-only and never reopens `.btn`,
so it needs no change. Those are the only two themes in the repo.

### 4. Course-card Details alignment

`.course-card-body` (`tailwind.components.css:306`) becomes a flex column:

```css
.course-card-body {
    padding: var(--fls-card-padding);
    @apply flex flex-col;
}
```

The mixed form matches `.course-card` two rules above it: `@apply` for anything a Tailwind utility
covers, a raw declaration for the `--fls-*` custom property.

`course_card.html:62` pins the Details row:

```django
<div class="flex justify-end mt-auto">
```

`mt-auto` only consumes free space for a **direct** flex item of `.course-card-body`. If a later edit
nests this wrapper one level deeper, the pin silently stops working and the defect returns with no
CSS error. The template needs a comment saying so.

`space-y-2` on the body (`course-card-shell.html:25`) does not defeat the pin, though the two do
collide. Tailwind v4 compiles `space-y-*` to `margin-block-start` as well as `margin-block-end` on
`:not(:last-child)`, and the Details wrapper is a non-last child on any card with a progress footer,
so `margin-block-start: 0` lands on the same axis as `margin-top`. The `:where()` wrapper settles it.
Those declarations carry zero specificity, so `.mt-auto` at `(0,1,0)` wins. Raising `space-y-*`'s
specificity later would break the pin.

`.course-card-body` is shared with `cotton/course-row-shell.html:46`, so the flex-column change also
reaches the all-courses row. Every direct child there is already a block or flex box with no float,
percentage height or inline-layout dependency, so it should be a visual no-op. It is the one thing
to confirm before shipping. `course_row.html` is immune to the defect itself, rendering Details
inline in the eyebrow slot (line 55) rather than in the body's block flow, and takes no `mt-auto`.

Those two shells and their two content templates are the entire change surface; nothing else in the
repo references `.course-card-body`.

Where a card carries a progress footer, `mt-auto` pushes Details and the footer to the bottom as a
group, so Details aligns across cards that agree on whether they have a footer. The dashboard renders
each status in its own grid today, so every grid is homogeneous. A future mixed-status grid would not
align, and that is acceptable.

### 5. The side-panel focus indicator

Add to `tailwind.base_interface.css`, at the top level of its existing `@layer components` block,
outside both `@media` blocks. Desktop column and mobile overlay both take focus when they open, so
both want the rule.

```css
/* The docked desktop panel is opened with dialog.show(), which runs the
 * dialog focusing steps; with no autofocus in the subtree the <dialog>
 * itself takes focus, so this paints on every page load. It is a real
 * :focus-visible indicator, not a spurious ring. Replace it, never remove
 * it. `outline` rather than a Tailwind ring-*, because ring-* compiles to
 * box-shadow, which forced-colors mode suppresses outright. */
.side-panel-dialog:focus-visible {
    outline: 2px solid var(--color-focus-ring);
    outline-offset: -2px;
}
```

`--color-focus-ring` is declared once, at
`freedom_ls/themes/default/static/themes/default/theme.css:134`, as an `@theme inline` alias of
`--color-primary`. It is still emitted as a custom property on `:root`, so hand-authored CSS can read
it. `first_class` does not redeclare it, so it resolves to that theme's primary.

`outline-offset: -2px` draws the line flush inside the dialog's edge. On desktop the dialog is a
sticky, full-height, full-width box (`tailwind.base_interface.css`, the `min-width: 1024px` block)
and `.side-panel-body` fills it with `bg-sidepanel`, so the outline paints over the side-panel
surface. The 3:1 check is `--color-focus-ring` against `--color-sidepanel`, per theme.

Do not add `tabindex` to the `<dialog>`, or `autofocus` anywhere in its subtree. The focusing steps
target the dialog regardless; a `tabindex` would make the whole column a tab stop, and an `autofocus`
would only relocate the ring while throwing screen-reader focus into the panel on every page load.

`_base_interface.html` and `alpine-components.js` are unchanged.

### 6. Build

`npm run tailwind_build` compiles `tailwind.input.css` to `static/vendor/tailwind.output.css`, which
is gitignored along with the generated `tailwind.active_theme.css`. None of these changes is visible
until it runs. QA against `first_class` needs `FLS_THEME=first_class` resolved at build time, since
`write_active_theme_css` reads it from Django settings.

## Testing

Two source-CSS contract tests go in `freedom_ls/base/tests/test_theme_tokens.py`, which already
asserts on source CSS files for the Tier-1/Tier-2 contract and already declares the
`FIRST_CLASS_THEME_CSS` path constant these need:

- `tailwind.components.css` declares `.btn-sm` and no longer contains `.btn.btn-sm`.
- `first_class`'s `theme.css` declares `.btn-sm`.

Nothing else gets a committed test. The three visual outcomes are presentational, and the project
verifies those in the browser. `freedom_ls/learner_interface/tests/test_course_cards.py:1-6` states
"Per project conventions: no CSS class assertions", and the prior spec at
`spec_dd/3. done/2026-06-09_12:22_visual-bug-hunt/1. spec.md` shipped its two presentational bugs the
same way. There is no screenshot diffing here, and the suite's one `to_have_css`
(`learner_interface/tests/playwright/test_course_toc.py:293`) waits out a transition before a
geometry assertion rather than asserting a style.

The existing suite must still pass, `freedom_ls/base/tests/test_button_component.py` included; it
covers the `loading` prop's rendered markup, which the icon-class change touches.

Visual QA has to prove:

1. **Small buttons.** In the course player nav (`course_topic.html`, six `size="small"` controls at
   lines 18, 30, 34, 40, 45, 52) the Next arrow no longer crowds the right edge, and the row reads as
   comfortable. Compare against `buttons.png`.
2. **Every other small button.** `px-3 py-2` reaches all of them, and on the borderless variants the
   extra padding shows as offset rather than as a larger box. Check `course_details_link.html:18`
   (`variant="link"`, right-aligned in the card footer), `course_list.html:76` ("Browse all
   courses"), `express_interest_cta.html:27` (`variant="ghost"`) and `picture.html:53`.
3. **Icon-only and dual-icon buttons.** A button with an icon and no label is symmetric; a button
   with both a leading and a trailing icon spaces both.
4. **Loading state.** At both sizes the spinner sits correctly against its text, and a `loading`
   button that also carries `icon_left` spaces its icon from the label in the resting state.
5. **Dropdown menu items.** Unchanged. They keep the icon margins.
6. **Card grids.** Details links sit on a common baseline across a grid whose cards have titles of
   differing length. Compare against `dashboard cards.png`. Verify the chain rather than the
   screenshot alone: the grid stretches its rows, `<article>` is a flex column, the body keeps
   `flex-1`, the body is itself a flex column, and the Details wrapper is a direct child carrying
   `mt-auto`. A homogeneous grid can look right with a broken chain.
7. **The all-courses row.** `course_row.html` is visually unchanged by the shared
   `.course-card-body` edit. Confirm no direct child of the body relied on block layout. No shrunk
   `w-fit`/`inline-block` child, no blockified inline child, no float, no dependence on margin
   collapse.
8. **The side panel.** On first load of the course player and the educator interface, the ring is a
   flat 2px on-brand line inside the column's edge, not the browser's halo. It still appears at all,
   because a missing indicator fails SC 2.4.7. Below `lg`, the opened mobile overlay gets the same
   line; check it reads acceptably against the bottom sheet's rounded top corners.
9. **Focus-ring contrast.** For every shipped theme, `--color-focus-ring` against
   `--color-sidepanel` is at least 3:1.
10. **Forced colours.** With Windows High Contrast Mode (or `forced-colors: active` emulation) the
    side-panel ring is still visible.
11. **Browsers.** Spot-check the dialog-focusing-steps case, loading the page rather than tabbing to
    a control, in current Chrome, Firefox and Safari.

## Documentation and downstream

`docs/how tos/theme-fls.md` is the only doc that covers these components. Two edits, both in **Tier 2
— Re-opening component classes** (lines 256-277):

- State the rule: reopening `.btn`'s padding means owning `.btn-sm` too, because the two sit at equal
  specificity and the theme is imported last. It belongs after the cascade-order paragraph at line
  274.
- Extend the worked example (lines 263-271) to show `.btn-sm` alongside `.btn`. That snippet is
  `first_class`'s real block reproduced verbatim, so it teaches the omission unless it changes with
  the theme.

The sentence at line 276 listing what `first_class` overrides gains `.btn-sm`. Example B under
`## Worked examples` describes that block in prose rather than reproducing it, so it needs no change.

Downstream projects that ship their own theme and reopen `.btn` padding must add a `.btn-sm` rule.
This is a breaking change for them: without it their small buttons take the theme's full-size
padding. It has to appear in the upgrade notes.

## Open questions

Whether `first_class`'s `.btn-sm` should be scaled to its own `.btn` rather than matching the base
rule. Its `.btn` is `px-6 py-3` against the base's `px-6 py-2`, so a proportionate small button might
want more than `px-3 py-2`. The spec ships both at `px-3 py-2`, which is the number the idea reached
on `first_class` evidence. Settle it from the QA screenshots.

## Success criteria

1. `tailwind.components.css` contains no compound modifier selector; `.btn-sm` is a single class at
   `px-3 py-2 gap-1.5 text-sm`, declared after `.btn`.
2. `.btn` declares `gap-2` and `cotton/button.html` has no `mr-2`/`ml-2` on any icon inside `.btn`.
   The dropdown variant still has them, with a comment explaining the split.
3. A `size="small"` button renders `size-4` icons and every other button renders `size-5`, from one
   conditional in the template.
4. With `FLS_THEME=first_class`, a small button measures 12px horizontal and 8px vertical padding,
   not the theme's `px-6 py-3`.
5. A loading button carrying `icon_left` spaces icon from label at both sizes.
6. In a dashboard grid of cards with one- and two-line titles, every Details link shares a baseline.
7. The all-courses row renders identically to before the change.
8. On first load of the course player, the side panel shows a flat 2px `--color-focus-ring` line
   inside its edge, and still shows an indicator under forced colours.
9. `docs/how tos/theme-fls.md`'s Tier 2 section states the reopen-both rule and its example shows
   `.btn-sm`.
10. The test suite passes, including the two new contract tests in `test_theme_tokens.py`.
