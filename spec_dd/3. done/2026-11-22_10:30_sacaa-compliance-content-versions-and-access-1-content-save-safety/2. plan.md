## Conventions for every slice

- New refusals raise `django.core.management.CommandError`. Existing `ValueError` failures stay.
- Every refusal is built by one helper in `content_save.py`, introduced in Slice 1, so the shape
  lives in one place: the `❌` headline with its count, the groups, the fix last.

  ```python
  def _refusal(
      headline: str,
      groups: Sequence[tuple[str, Sequence[str]]],   # (heading, lines)
      fix: str,
      *,
      limit: int | None = None,   # lines shown per group before "... and N more"
  ) -> str: ...
  ```

- Refusal tests call `call_command("content_save", *paths, site.name, "--traceback")` and assert on
  a fragment of the `CommandError` message.
- Tests that need a git repo build it with dulwich through `freedom_ls/tests/git_repos.py`. No test
  runs a `git` binary.
- Type hints on every new function. No `Any`, no `# type: ignore`, no new logging.

       """(file, description) for every uuid the save would have to generate."""

       for item in all_parsed:

### Slice 4

One `content_save` call loads several source paths as one save.

**Builds on:** slices 1, 2, 3
**Touches:** `freedom_ls/content_engine/management/commands/content_save.py`, `freedom_ls/content_engine/tests/management/commands/test_content_save.py`

1. Command arguments: `@click.argument("paths", nargs=-1, required=True)` then
   `@click.argument("site_name")`. The docstring shows
   `python manage.py content_save ../bloom_content ../bloom_extra Bloom`.
2. The command runs four steps, each over every path before the next starts:
   1. **Path checks.** Each path exists. No path equals, or is inside, another (compare resolved
      paths). `CommandError`.
   2. **Git check.** Slice 1's check for every path. Dirty files from all paths go in one refusal,
      one group per source path, headed by the path as the author typed it.
   3. **Validation.** `validate(path)` for every path. Catch each `ValueError`, and when any path
      failed raise one `ValueError` holding every report, each headed `Source path: <path>`.
   4. **Save.** `save_content_to_db(paths, site_name, generate_uuids=...)`.
3. `save_content_to_db(paths: Path | str | Sequence[Path | str], site_name, *, generate_uuids=True)`.
   Split the current body in two so every check runs before the first write:

   ```python
   @dataclass
   class _ParsedSource:
       path: Path
       all_files: list[Path]
       content_files: set[Path]
       all_parsed: list[BaseBaseContentModel]

   @transaction.atomic
   def save_content_to_db(paths, site_name, *, generate_uuids=True):
       site = Site.objects.get(name=site_name)
       # A lone str is itself a Sequence, so it is told apart by type.
       path_list = [paths] if isinstance(paths, (str, Path)) else list(paths)
       sources = [_parse_source(Path(p)) for p in path_list]
       # Placement checks per source; errors from every source are raised together.
       if not generate_uuids:
           _refuse_missing_uuids(sources)
       _refuse_relative_path_collisions(sources)
       image_statuses = [status for source in sources for status in _write_source(source, site)]
       # The success line and the image summary, once.
   ```

   `_write_source` is the current body from "Save non-content files" to
   `collection_items_synced.send`, unchanged in order, with its own `ImageCache(source.path)` and
   its own `write_manifests()`. Every path-based reference still resolves inside its own source
   path, and `validate_question_sections` keeps `loaded_root=source.path`.

   > **Assumed default:** `moved_children`, `carry_placement_due_dates` and
   > `collection_items_synced.send` run once per source path, not once for the whole call. Why: a
   > move is found inside one course, a course lives in one source path, and the spec makes each
   > source path self-contained, so this is what two separate calls do today. To change: Slice 4
   > step 3, combining every source's `created`, `written` and `moved` into one send after the
   > last source.
4. `_refuse_relative_path_collisions`: the relative path of every file in `all_files`, per source.
   Two sources sharing one raise `CommandError` (through `_refusal`) naming the relative path and
   both source paths. Template tags look files up by `file_path` alone and `File` is silently
   overwritten, so no database constraint would catch this.
5. With more than one source, `_refuse_missing_uuids` heads each group
   `<source path>: <relative file>`. Only the headings it passes to `_refusal` change.

Tests:

- one path plus site works; three paths plus site works; content from two paths lands in one save;
- the same path twice, and a path inside another, are refused before the git check (the tree is
  also dirty, and the message is the path refusal);
- a validation failure in the second path writes nothing from the first;
- a database failure while writing the second path rolls back the rows of the first;
- the same relative path in two paths fails naming both, for a content file and for an uploaded

- each path gets its own image cache manifests under its own tree;
- missing uuids across two paths come back in one message, grouped by path;
- dirty files in two paths come back in one refusal, grouped by path.

**Builds on:** slices 1, 2, 3
**Touches:** `freedom_ls/content_engine/validate.py`, `freedom_ls/content_engine/tests/test_validate.py`, `freedom_ls/content_engine/ignore_list.py`, `freedom_ls/content_engine/tests/test_ignore_list.py`, `freedom_ls/content_engine/management/commands/content_validate.py`, `freedom_ls/content_engine/tests/management/commands/test_content_validate.py`

1. `validate.py`, stdlib and `yaml` only, so the offline copy can carry the same code:

   ```python
   IGNORED_PROBLEM = "content_save skips this file: it is in the .fls-content.yaml ignore list"
   IGNORED_FIX = "Remove this entry, or remove the line from ignore: in .fls-content.yaml."

   def read_ignore_list(root: Path) -> frozenset[Path]:
       """The paths a content repo's .fls-content.yaml lists under ignore:, as absolute paths."""
       # No file, or no ignore: key -> frozenset().
       # Parse with yaml.safe_load: the file comes from a checkout, so it must never be
       # able to construct Python objects.
       # ignore: must be a list of strings. Strip a leading "./" and a trailing "/".
       # ValueError naming the entry and the file when an entry is absolute, has a ".."
       # component, contains "*", "?" or "[", or is empty once stripped.
       # Return content_key(root / entry) for each entry.

   def is_ignored(file_path: Path, ignore: frozenset[Path]) -> bool:
       if not ignore:
           return False
       # By path component, so "docs" never matches "docs-old".
       key = content_key(file_path)
       return key in ignore or any(parent in ignore for parent in key.parents)
   ```

2. Thread `ignore: frozenset[Path] = frozenset()` as a keyword argument through
   `get_all_files`, `is_loader_skipped`, `auto_discovered_children`, `collection_children`,
   `_ParsedByPath` (for `children_of`), `validate_children_lists`, `validate_due_date_placements`,
   `validate_question_sections`, `_section_problem` and `validate(path, ignore=...)`. An empty
   default keeps every existing caller unchanged.
   - `is_loader_skipped` returns True for an ignored file, which removes it from `get_all_files`,
     so it is never parsed and never uploaded as a `File`.
   - `auto_discovered_children` has two `iterdir` loops with the same filter. Move the filter into
     one small generator both loops use, which leaves out skipped and ignored entries.
   - `collection_children` uses `ignore` only for auto-discovery. It keeps every explicit
