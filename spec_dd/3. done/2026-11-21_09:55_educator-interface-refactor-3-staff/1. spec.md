# Spec: move the staff area into `panels/staff/`

## Purpose

`freedom_ls/educator_interface/views.py` and `actions.py` are each over 3,000 lines. The organisation staff section's code (config, data table, actions, role filter, quick view) is about 1,370 lines of `actions.py` alone, with about 3,550 lines of tests in `tests/test_actions.py`. This spec moves the staff area into `freedom_ls/educator_interface/panels/staff/` and its tests into `tests/panels/staff/`. It is spec 3 of the "Educator interface code layout" effort in `spec_dd/1. next/roadmap.md`. The approach is settled in `idea.md`.

## Scope

In:
- Moving the staff names listed under Requirements out of `views.py`, `actions.py`, `filters.py` and `quick_views.py`.
- Moving the staff test slices out of `tests/test_actions.py`, `tests/test_views.py` and `tests/test_filters.py`, plus one test from `tests/test_quick_views.py`.
- Repointing every import, `monkeypatch.setattr` string and module-attribute access of a moved name, in production code and tests.
- `upgrade_notes.md` for downstream projects.

Out:
- Any behaviour, UI, URL, URL name, template, template path or app-label change.
- The flat domain modules `forms.py`, `staff.py`, `learner_import.py` and `messaging.py`. The staff forms and `RoleEntry`, `staff_role_entries`, `current_role_entries` stay where they are.
- `panels/common/` and every other area (cohort, learner, course, dashboard, audit log), and the final deletion of the emptied flat modules (`educator-interface-refactor-7-cleanup`).
- Removing the lazy `interface_config` import cycle.
- Splitting `panels/staff/actions.py` further, or adding `panels.py`, `data_table_panels.py`, `instance_view.py` or `bulk_actions.py` (the staff section has none of that content).

## Decisions

- **Names are the contract, not line numbers.** Every line number below is the tree this branch started from, and is a locator only. The implementer re-finds each name before cutting it.
- **Pure move, byte for byte.** Moved bodies, test names, docstrings and assertions are unchanged. Only import lines, patch strings and module references change. `TODO` and `@claude` comments move with their code.
- **No re-export shim.** The flat modules lose the moved names, so a stale reference fails with `AttributeError` or `ImportError` instead of resolving to the old copy.
- **One `actions.py`.** The staff actions share `StaffRowMixin`, `_organisation` and `_refused` across every natural seam, and the tests are not organised along those seams.
- **Cohort imports staff, never the reverse.** The three cohort-scoped actions and `roles_grantable_on` live in `panels/staff/actions.py`, and the cohort Settings panel in `views.py` imports them from there. `panels/staff/` imports nothing at module level from `views.py`, the flat `actions.py` or cohort and learner code.
- **No migration.** No staff class carries `@register_bulk_action`, so no `BulkActionRun.action_path` row names one.
- **Shared test helpers go to `tests/helpers.py`.** A helper or fixture used by both moved and staying tests is not duplicated. Plain helpers go to `freedom_ls/educator_interface/tests/helpers.py` and fixtures go to `freedom_ls/educator_interface/tests/conftest.py`, under their current names. A test module never imports from another test module.
- **Test files split by what the assertions read.** A page-level test whose assertions read table rows, cells or per-row triggers goes in `test_data_tables.py`. One that asserts section access, intro context or navigation goes in `test_config.py`. A test that spans the shell or several areas stays in its flat file.

## Requirements

### Package layout

New, each `__init__.py` empty:

```
freedom_ls/educator_interface/panels/staff/
    __init__.py  actions.py  config.py  data_tables.py  filters.py  quick_view.py
freedom_ls/educator_interface/tests/panels/staff/
    __init__.py  test_actions.py  test_config.py  test_data_tables.py  test_filters.py  test_quick_view.py
```

Each new module follows the `panels/common/` conventions:
- `from __future__ import annotations`
- a one-line purpose docstring
- absolute imports only
- an `__all__` listing every name the module defines, underscore names included, in the order ruff RUF022 sorts it (as in `panels/common/`)

From `filters.py` (100-156): `may_see_staff_roles`, `StaffRoleFilter`. This module imports nothing from the other staff modules.

## Testing

- The full suite passes. Patch strings are proved by running the suite, not by grep.
- `uv run pytest --collect-only -q --no-cov` gives the same count, and the same set of test names with paths stripped, before and after. Tests a rebase brings in from main are allowed for.
- Every new module imports cleanly as the first import in a fresh interpreter. So does each flat module it was cut from.
- Grep checks:
  - No reference to a moved name through its old module path remains in the repo: Python, templates, `.md` and `.toml`, excluding `spec_dd/`.
  - `panels/staff/` has no module-level import of `views.py`, flat `actions.py` or cohort/learner code.
  - `panels/common/` imports nothing from `panels/staff/`.
- `uv run manage.py check` and `uv run manage.py makemigrations --check --dry-run` are clean.
- `pre-commit run --all-files` passes, including `test-mirroring` and `lint-imports`. `test_organisation/mirroring_baseline.txt` names no staff file. If the hook reports a line as stale, that line goes in the same change.
- The Playwright files `test_members_flow.py`, `test_cohort_settings_staff_flow.py`, `test_lost_access_flow.py` and `test_section_smoke.py` pass after the move, and the run output shows them executed, not skipped. Staff deactivate and reactivate have no Playwright coverage, so the moved Django tests are their only cover.
