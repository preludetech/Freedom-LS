# Research: codebase impact of design_learner_course_organisations

All paths are relative to the repo root. Source of the prior work: `spec_dd/3. done/2026-10-27_20:02_organisation-courses/1. spec.md` (merged; its §3 explicitly put the all-courses list, markdown embed card, completed cards and course detail page OUT of scope for the byline, which is the gap this idea fills).

## 1. Canonical word

- **"organisation"** everywhere (code, glossary `.claude/skills/domain-glossary/SKILL.md` "Tenancy" section line ~130-135: `Organisation` = "a client inside a site", a grouping not an isolation boundary). "Provider" is NOT a project term (only incidental hits in `docs/product/roadmap.md`, `deployment.md`, `security-and-data-handling.md`). The design's "G2 · Provider + level" label must be rendered as organisation name + level (`Course.difficulty` / `get_difficulty_display`). Spec should say "organisation", not "provider".
- Glossary coined terms from the done spec: "organisation course" (a `Course` with >=1 row in `Course.organisations`), `CourseAudience`, "in the audience". "Offered by a single organisation" has no existing term; it equals "organisation course with exactly one organisation".

## 2. Organisation model (`freedom_ls/organisations/models.py`)

- `Organisation(SiteAwareModel, TimestampedModel)` (line 58). Fields: `name` (150), `slug` (unicode, set once, not re-derived), `logo` ImageField ("logo (for light backgrounds)"), `logo_on_dark` ImageField, `is_default` bool (the Site's fallback org, set only by a Site post_save receiver in `signals.py`). Constraints: unique (site, slug), (site, name), one default per site.
- **No bio/description field, no "profile" image field.** Both are new: (a) a "profile" image logo (idea: use it, else fall back to `logo`), (b) a short bio. Only migration is `freedom_ls/organisations/migrations/0001_initial.py` (migration reset happened earlier); add `0002_*` (never edit 0001). CLAUDE.md: run `makemigrations`.
- `Organisation.initials` property: monogram from name (None if no alphabetic chars) - used by `course_organisation_chip.html` as a no-logo fallback (circle with initials, or `<c-icon name="unknown">`). Reusable for the circular fallback.
- `Organisation.save()` sweeps superseded logo objects via `LOGO_FIELD_NAMES = ("logo", "logo_on_dark")` and `_stored_logo_names()`. Comment says: "a field added here without the sweep following would abandon its superseded objects" in a public anonymously-readable bucket. **A new profile image field MUST be added to `LOGO_FIELD_NAMES`** and get its own upload_to with a distinct variant suffix (existing pattern: `_logo_upload_path(instance, filename, variant)` -> `organisations/{pk}{variant}{ext}`; variants `""` and `-on-dark`; add e.g. `-profile`). Naming `LOGO_FIELD_NAMES` is also used for tests.
- `get_organisation_logo_storage()` -> `storage_for_alias(config.ORGANISATION_LOGO_STORAGE_ALIAS, ...)`, default alias `"public"` (`freedom_ls/organisations/config.py`, `config/settings_base.py:288`). New field: `storage=get_organisation_logo_storage` (module-level callable, per skill).
- Validators `freedom_ls/organisations/validators.py`: `validate_organisation_logo_extension` (png/jpg/jpeg/webp), `validate_organisation_logo` (2 MiB, <=4000px, min 64x32, Pillow decode; `check_logo_safety`). Reuse both for the profile image. NB min 64x32 allows non-square images; a circular crop needs `object-cover` or a squareness/min-size rule (design decision).
- `freedom_ls/organisations/utils.py`: `get_default_organisation(site)`, `ensure_organisation(site, name, slug_base)`.
- Admin: `freedom_ls/organisations/admin.py` `OrganisationAdmin(GuardedSiteAwareModelAdmin)`: `fields = ["name","slug","logo","logo_on_dark",SUMMARIES_FIELD]`; no delete; slug in `save_model`. Form `freedom_ls/organisations/forms.py` `OrganisationAdminForm` has `Meta.fields = ["name","logo","logo_on_dark"]` and loops over `("logo","logo_on_dark")` to set the `invalid_image` message. **New fields must be added to admin `fields`, form `Meta.fields` and that loop tuple.** There is no educator-interface UI for editing organisations (admin only) - grep found none.
- Factory: `freedom_ls/organisations/factories.py` `OrganisationFactory(SiteAwareFactory)` (name sequence + unique slug; no logo). Tests: `freedom_ls/organisations/tests/{test_models,test_admin,test_validators,...}.py`; image helpers in `freedom_ls/tests/images.py`, test storages in `freedom_ls/tests/storages.py`.
- Existing consumers of `logo`: `freedom_ls/reports/{render,indexes}.py` + `reports/templates/reports/{report,partials/title_page}.html` (report cover; reads stored logo bytes - a new field must not change this), `learner_interface` templates below, qa_helpers commands (`qa_create_organisations.py`, `qa_create_organisation_scenarios.py`, `qa_create_report_brand_organisations.py`, `qa_create_dronex_demo.py`). `logo_on_dark` is only used by reports.

## 3. Course <-> organisation link

- `freedom_ls/content_engine/models/courses.py`: `Course.organisations` M2M (`related_name="courses"`, blank) and `Course.audience` (`CourseAudience`). Set from course frontmatter by organisation slug in `management/commands/content_save.py`. Admin read-only. Docs: `docs/product/content-editing-workflow.md` ~line 91.
- "Single organisation" determination already exists: `freedom_ls/learner_interface/views.py::_stamp_single_organisation(course)` (line ~297): `course.organisations.all()`, exactly one -> stamp, zero/several -> None (uses prefetched `organisations`). `stamp_card_organisation(course, organisation)` in `freedom_ls/learner_interface/utils.py:156` does `setattr(course, "card_organisation", org)`.
- Stamp sources: discovery cards `_annotate_discovery_courses` (views.py ~434), recommendations `_annotate_recommendations` (~368; `_discovery_courses` prefetches `organisations`), in-progress cards use `CourseProgress.learner.organisation` in `get_current_courses` (utils.py ~873, that is the organisation studied THROUGH, not necessarily the course's organisation; default org suppressed by the component). **Subtlety for the idea**: an in-progress card's byline can name the learner's organisation, not the course's single organisation; decide whether the new design wants "course's single organisation" semantics everywhere.
- Gate/queries: `freedom_ls/learner_management/queries.py`, `freedom_ls/course_access/{backends,visibility}.py` (`raise_404_if_unavailable`). `get_course_by_path` in `learner_interface/templatetags/course_card_tags.py` (embed card).
- No-N+1 test exists (`django_assert_max_num_queries` for dashboard); new surfaces (all-courses rows, course detail) must prefetch `organisations`, and the dashboard must not gain per-card queries from profile image lookups (images are fields on `Organisation`, so no extra query).

## 5. File-storage conventions

`claude_plugins/fls-dev/skills/file-storage/SKILL.md`: logos belong in the `public` alias (public bucket, anonymous read, key prefix `organisations/`, **overwrite at a stable key**, `max-age=86400`). Rules for a new ImageField: `storage=<module-level callable>` (reuse `get_organisation_logo_storage`), `upload_to` keyed on pk + variant suffix + extension (never the uploaded filename), and since extensions can change, add the field to `LOGO_FIELD_NAMES` so `save()` deletes the superseded object. Do not edit `_OVERWRITE_PURPOSES` (`freedom_ls/deployment/storage.py`). The skill's alias table says `public` consumer is "`Organisation.logo`" - update to mention the new field(s) (docs in plugin `fls-dev`, FLS-specific so allowed there). Existing ImageField usages in `freedom_ls`: only `Organisation.logo` and `logo_on_dark` (grep). Tests for storage: `freedom_ls/deployment/tests/test_storage.py`, `freedom_ls/tests/storages.py`.

## 8. Conflicts, risks and open questions

1. **Prior art already exists** for the dashboard byline (done spec); this work restyles it (circle, profile image, header inset) rather than introducing it. The idea says "dont change anything else" on the dashboard: keep `card_organisation` stamping logic as-is, change only `organisation-byline.html` and `course-card-shell.html` (hero padding). Hero padding in the shell also affects the embed card compact variant (`cotton/course-card.html`) which shares `course-card-shell`; scope the change via a prop/class if the embed card must not change, and the "completed" and discovery cards all use `course_card.html` so all dashboard cards change together.
2. **Component reuse vs new variants:** `organisation-byline` (card), `course_organisation_chip.html` (player outline) and the new course-detail header + org card are three-to-four renderings of "logo + name". Single source for "which image to show" (profile image else `logo`, else initials circle) should be a model property/method on `Organisation` (e.g. alongside `initials`), not repeated in templates. The existing component renders `logo` on a `bg-surface` box for contrast; a circle needs `rounded-full overflow-hidden object-cover` and a background so transparent logos stay legible (the chip comment on opaque fill still applies). `logo_on_dark` is for dark backgrounds; the course-detail hero is dark/accent coloured, so the header there might want `logo_on_dark`, but the idea specifies profile else default `logo` only.
3. **Default organisation suppression:** both existing components render nothing for `is_default`. The idea says "if a course is offered by a single organisation" - consistent, but confirm the org card on the detail page should also hide for the default organisation (a course with only the site's default org would show a card naming the site itself).
4. **Multi-site:** `Organisation` is `SiteAwareModel`; `Organisation.objects` filters by the thread-local site, `_base_manager` does not. Template access through `course.organisations.all()` is already scoped. Do not use `_base_manager` in views. Logo URL comes from the shared public bucket; the profile image key `organisations/{pk}-profile{ext}` is unique per org.
5. **Public bucket / stable key / sweep** (see §2, §5): forgetting `LOGO_FIELD_NAMES` leaves old profile images publicly readable.
6. **Admin only:** orgs edit logo via Django admin; the bio and profile image should be added there; no educator UI exists. Bio is "short": use `TextField` or `CharField(max_length=...)` with `blank=True`; render escaped (no markdown unless required).
7. **All-courses and detail views need prefetch:** `all_courses` uses `get_all_courses()` via `filter_visible`; add `.prefetch_related("organisations")` and `_stamp_single_organisation` (currently private to `views.py`; the all-courses row and detail page will reuse it - possibly move to `utils.py` next to `stamp_card_organisation`).
8. **"Level tag":** `Course.difficulty` (choices; `get_difficulty_display`) exists; the all-courses row currently shows no level, and the markdown body renders it as plain text. Tag = `<c-chip>` (used in cards: `variant`, `size="xs"`).
9. **Details button:** `partials/course_details_link.html` already is a text-only link button, with a chevron (`icon_right="next"`) and `size="small"`; the idea says "always say 'details'" (currently "Details"). Keep the stretched-link layering (`relative z-10`).
10. **Applications:** `dashboard_applications.html` is a different layout (no accent icon, no `Course` card context); cross-app template coupling and the "keep generic" boundary in `course_applications` (no learner_interface import) need a decision. Done spec's open question: approved applications register through the default organisation (byline suppressed for in-progress cards).
11. **Demo content:** `demo_content/functionality_demo_organisation_course_{northwind,harbour}/course.md` (audience public vs organisation_learners, with `organisations:`); demo setup creates the orgs before `content_save`. New fields (bio, profile image) should be populated for the demo orgs where the demo setup creates them (check `freedom_ls/qa_helpers/management/commands/qa_create_organisations.py` / demo setup) so the new UI is visible.
12. **Design source:** idea's `design_prompt.md` points at an inaccessible Claude Design project; dashboard class names and exact spacing must come from the spec author, not from this codebase.
