# Frontend QA: design learner course organisations

## 0. Setup

```bash
npm run tailwind_build
uv run python manage.py create_demo_data --yes
uv run python manage.py content_save ./demo_content DemoDev
uv run python manage.py qa_create_organisations
uv run python manage.py qa_create_dashboard_applications_panel
PORT=$(.claude/ds/scripts/find_available_port.sh)
uv run python manage.py runserver $PORT
```

- Base URL: `http://127.0.0.1:$PORT`. Dashboard `/`, all courses `/courses/`, course detail
  `/courses/<slug>/`, Django admin `/admin/`, organisations in the admin
  `/admin/freedom_ls_organisations/organisation/`, courses in the admin
  `/admin/freedom_ls_content_engine/course/`.
- Logins (password equals the email): site admin `demodev@email.com`; learners
  `demodev_s1@email.com` to `demodev_s50@email.com`. Use a fresh private window per login.
  django-axes locks an email after five failed logins; run `uv run python manage.py axes_reset`
  if you trip it.
- Organisations after setup, all on DemoDev: **Harbour College** and **Northwind Logistics** (demo,
  each with a bio, no logo, so the mark shows initials), **RPAS Training** (a `logo`, no profile
  logo), **Skyline Aviation** (a profile logo and a bio), **Coastal Flight School** (a wide `logo`,
  no profile logo, no bio), **Northside** (nothing), plus the site's default organisation
  **DemoDev**.
- Demo courses: the two **Workplace Safety Essentials** courses belong to Harbour College
  (audience `organisation_learners`) and Northwind Logistics (audience `public`). Find their slugs
  in the admin course list (column "Organisations"): `<harbour-slug>` and `<northwind-slug>`.
  Every other demo course has no organisation.
- Attach an organisation to a course in the admin: open the course, pick it in **Organisations**,
  set **Difficulty** where a step asks for one, save. Set up these before Scenario 2:
  - a public demo course of your choice, call it `<skyline-course>`: organisation Skyline Aviation,
    difficulty Beginner;
  - another, `<coastal-course>`: organisation Coastal Flight School, no difficulty;
  - another, `<multi-course>`: organisations Skyline Aviation and Coastal Flight School, difficulty
    Advanced;
  - another, `<default-course>`: organisation DemoDev only, difficulty Intermediate;
  - one of the seven `qa-…` gated courses the applications panel seeder created (admin course
    list, filter by title starting "QA"): organisation Skyline Aviation, difficulty Beginner. Pick
    one that is on the panel's first page for `demodev@email.com` (the three newest).
- Register a learner through an organisation where a step needs it:
  `uv run python manage.py qa_register_org_course --learner-email <email> --organisation "<name>"
  --course-slug <slug>`.
- The three QA viewports are 375, 768 and 1920 wide. "At every viewport" below means all three.

## Scenario 1: the admin edits a profile logo and a bio

1. Log in as `demodev@email.com`. Open the organisation list in the admin and open **Skyline
   Aviation**.
2. **Expect:** the form shows, in order, Name, Slug (read-only), Logo (for light backgrounds), Logo
   (for dark backgrounds), Profile logo, Bio. The profile logo's help text says it is shown in a
   circle, that a square image of at least 128 by 128 pixels works best, that other shapes are
   cropped, and that the light-background logo is shown without one. The bio is a multi-line text
   box whose help text states the 500-character limit.
3. Paste 501 characters into Bio and save. **Expect:** the form is rejected with an error on Bio;
   nothing else changes.
4. Replace the bio with two short sentences and save. **Expect:** saved.
5. Upload a plain text file renamed `.png` as the profile logo and save. **Expect:** an error on
   Profile logo naming PNG, JPEG or WebP.
6. Upload a wide (non-square) PNG as the profile logo and save. **Expect:** accepted. Note the
   stored file name shown next to the field (`organisations/<pk>-profile.png`).
7. Upload a square JPEG as the profile logo and save. **Expect:** accepted; the file name now ends
   `-profile.jpg`. Check the media directory (or bucket) for the organisation's pk: **expect** one
   `-profile` object, the `.jpg`; the `.png` is gone.
8. Tick the profile logo's **Clear** box and save. **Expect:** no profile logo; the `-profile.jpg`
   object is gone from storage, and the organisation's `logo` and `logo_on_dark`, if any, are
   untouched. Re-upload the square JPEG so later scenarios have a profile logo.

## Scenario 2: the dashboard cards (design state cards__b)

Design screenshot: `design_screenshots/cards__b.png`, width 1180.

1. From the shell, run `uv run python manage.py qa_register_org_course --learner-email
   demodev_s3@email.com --organisation "Skyline Aviation" --course-slug <skyline-course>`. Log in as
   `demodev_s3@email.com` in a private window and open `/`. Start the course from its card so it is
   in progress, then return to `/`.
2. **Expect** at 1920: the card for `<skyline-course>` in the In progress section shows, under
   the accent tile, a round mark holding the Skyline profile logo cropped to the circle, then
   "Skyline Aviation", then the "In progress" status line, then the title.
3. **Expect** on the discovery cards: `<coastal-course>` shows the Coastal wide logo fitted inside
   the circle (not cropped, with a small inset); `<harbour-slug>`'s public sibling
   `<northwind-slug>` shows the initials "NL" in a grey circle; `<multi-course>` and
   `<default-course>` show no byline; a course with no organisation shows no byline.
4. **Expect** on every card: the accent tile is inset from the card's edge on all sides with
   corners rounded less than the card's; the title, byline and body text start at the tile's left
   edge; the progress bar and the Details link are where they were.
5. Hover a long organisation name card (attach the ~150-character organisation from
   `qa_create_organisations` to a spare course first if you want one): **expect** the name
   truncates with an ellipsis on one line and the full name appears as a tooltip.
6. Log out. Open `/` anonymously. **Expect:** the discovery cards show the same bylines; access
   badges ("Free", "By application") still render in the status position under the byline.
7. Repeat steps 2 to 4 at 375 and 768. Under 1024 the dashboard shows rows instead of cards:
   **expect** the rows of Scenario 3, with no horizontal scrolling.

Design checklist (from the plan):
- [ ] The accent tile is inset from the card edge on all four sides.
- [ ] The tile's corners are rounded less than the card's.
- [ ] The byline is the first line under the tile, before the status and the title.
- [ ] The byline's mark is a circle; the name sits beside it on one line and truncates.
- [ ] A card for a course with no named organisation shows no byline and otherwise matches.
- [ ] The in-progress card names the organisation the learner studies through.

## Scenario 3: the all-courses rows (design state index__ig2)

Design screenshot: `design_screenshots/index__ig2.png`, width 1180.

1. Anonymous, open `/courses/` at 1920.
2. **Expect** for `<skyline-course>`: top-left, the round mark and "Skyline Aviation", a middle
   dot, then "BEGINNER" in small uppercase muted text; top-right, a "Free" chip (or "By
   application" for a gated course) and, if the course has a price, a grey chip with the price;
   the title under the eyebrow; the "Details" link bottom-right as text with a chevron and no
   border. No price line anywhere else on the row, no status text anywhere else.
3. **Expect** for `<coastal-course>`: the wide logo fitted in the circle, the name, no dot, no
   difficulty. For `<multi-course>` and `<default-course>`: no byline; "ADVANCED" and
   "INTERMEDIATE" respectively stand alone at the left with no leading dot. For a course with
   neither: the left half empty, the chips still top-right.
4. **Expect** the rows are separate bordered cards with a gap between them, no dividing line.
   Hover a row: it lifts like the dashboard cards.
5. Log in as `demodev_s3@email.com` and open `/courses/`. **Expect:** the `<skyline-course>` row
   shows an "In progress" chip (grey, with the play icon) top-right and no "Free" chip; its
   progress bar sits in the footer above the Details link. A course you have not registered for
   shows no status chip and no access badge (signed in), only a price chip if priced.
6. Tab through the page. **Expect:** every "Details" link is reachable; a screen reader name check
   (inspect the link's accessible name in devtools) reads "Details for <course title>" and the
   visible label is still just "Details".
7. Repeat steps 2 to 4 at 375 and 768. **Expect:** the chips wrap under each other at the right
   when there is no room, the byline truncates rather than pushing the chips off, and the page has
   no horizontal scroll.
8. Open `/` at 375 signed in. **Expect:** each section's row list shows the same rows as
   `/courses/`, byline and difficulty included, and the "Browse all courses" link is still
   centred under the rows.

Design checklist (from the plan):
- [ ] Rows are separate bordered cards with a gap and no divider between them.
- [ ] The byline and the difficulty share one line at the top-left, separated by a middle dot.
- [ ] A row with no organisation shows the difficulty alone at the left; one with neither shows an
      empty left half.
- [ ] The tag chips sit top-right on the same line as the byline.
- [ ] The status appears once on the row, as a chip with its icon.
- [ ] The price appears once, as a muted chip, and never as a separate line.
- [ ] The Details link is text with a chevron, bottom-right, with no border.
- [ ] On the applications panel the one tag is the application status chip, and the Details link
      and the application button share the footer line.

## Scenario 4: the applications panel

1. Log in as `demodev@email.com` and open `/` at 1920. **Expect:** the "Your applications" panel
   shows three rows in the same row layout as `/courses/`: accent panel left, eyebrow top-left,
   one chip top-right ("Incomplete" in warning colours or "Pending review" in info colours), no
   "Free" or price chip, the title, "Finish your application to have it reviewed." on a draft row,
   and a footer line holding "Details" then "Continue application" or "View my application",
   right-aligned.
2. **Expect** the row for the gated course you attached to Skyline Aviation shows the mark,
   "Skyline Aviation" and "BEGINNER" in its eyebrow; the other rows show an empty left half.
3. Click "Details" on that row. **Expect:** the course detail page, not the application status
   page. Go back and click the title: **expect** the application status page. Click the
   application button: **expect** the same status page.
4. Use the panel's pager. **Expect:** the next page swaps in with the same row layout, the
   position text updates, and focus lands on the panel heading as before.
5. At 375: **expect** the application button is hidden and a chevron shows at the right of the
   footer line; "Details" still shows; the whole row is tappable to the status page; no horizontal
   scroll.
6. Open `/` as `qa-no-apps@example.com`. **Expect:** no panel at all.
7. Anonymous session: open an application-gated course's detail page and start an application
   without signing in, then open `/`. **Expect:** the panel shows that draft in the same row
   layout, with its byline when the course has a named organisation.

## Scenario 5: the course detail page (design states detail__d1 and detail__d6)

Design screenshots: `design_screenshots/detail__d1.png` and `design_screenshots/detail__d6.png`,
width 1180.

1. Anonymous, open `/courses/<skyline-course>/` at 1920.
2. **Expect** in the hero: before the category chip, a round white-filled mark with the Skyline
   profile logo and the name "Skyline Aviation" in white, then a thin translucent rule, then the
   category chip, title, subtitle and stats strip as before. Nothing in the byline is a link.
3. **Expect** in the sidebar: under the sign-up panel, a bordered card with the mark at 48px, the
   name in bold, and the bio as small muted text under them. No course count, no link.
4. Scroll the page. **Expect:** the sign-up panel and the organisation card scroll together as one
   sticky block and never overlap.
5. Open `/courses/<coastal-course>/`. **Expect:** the hero byline with the wide logo fitted in the
   circle; the sidebar card with the mark and the name and no bio paragraph.
6. Open `/courses/<multi-course>/` and `/courses/<default-course>/`. **Expect:** no hero byline, no
   rule, no organisation card; the sign-up panel is still sticky.
7. In the admin, set the Skyline bio to 500 characters across several lines. Reload
   `/courses/<skyline-course>/` at 1920 with the window height reduced to about 600px.
   **Expect:** the bio keeps its line breaks, nothing renders as HTML, and the sidebar block
   scrolls within itself so the end of the bio can be reached; the sign-up button's focus ring is
   not clipped when tabbed to.
8. Log in as `demodev_s3@email.com` and reopen `/courses/<skyline-course>/`. **Expect:** the same
   byline and card for a registered learner.
9. At 375: **expect** the sidebar card follows the sign-up panel, above "About this course"; the
   hero byline sits above the chip; no horizontal scroll. At 768: the same.
10. View page source. **Expect:** the JSON-LD block carries no `provider` entry.

Design checklist detail__d1 (from the plan):
- [ ] The byline is the first thing in the hero, above the category chip.
- [ ] The mark is a circle with a white fill on the accent background; the name is white.
- [ ] A rule separates the byline from the rest of the hero.
- [ ] Nothing in the byline or the rule is a link.
- [ ] A multi-organisation or default-organisation course shows no byline and no rule.

Design checklist detail__d6 (from the plan):
- [ ] The card sits directly under the sign-up panel, in the same column, same width.
- [ ] The mark and the name share one line; the bio follows underneath.
- [ ] The card renders without the bio paragraph when the bio is empty.
- [ ] Scrolling the page keeps the panel and the card together.
- [ ] On a phone the card follows the sign-up panel above "About this course".
