# Spec: design learner course organisations

Source: `idea.md`. Research: the `research_*.md` files beside it. Design: `design.md` (a Claude
Design design, a visual reference only, read as that file says).

## 1. Purpose

Every learner-facing surface names a course's organisation the same way: a circular mark beside
the name, placed where `idea.md` puts it on the dashboard card, the long-format row and the course
detail page. An organisation supplies the square logo the circle draws and a short bio for the
course page through the admin.

## 2. Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| organisation mark | coined | The circle that stands for an organisation: its `profile_logo`, else its `logo`, else an initials monogram. Existing docs and the `logo` help text use "mark" loosely for the logo itself; this term means only the circle. |
| named organisation | coined | The one organisation a course belongs to, when it belongs to exactly one and that one is not the site's default organisation. Returned by `Course.single_organisation()` (§5.2); the nearest existing names are `card_organisation` and `_stamp_single_organisation`. |

## 3. Scope

In:

- `Organisation.profile_logo` and `Organisation.bio`, edited in the admin.
- The organisation mark and byline components, replacing the rectangular byline.
- Dashboard course cards: the padded header block and the byline under it.
- Long-format rows: the all-courses page, the dashboard's narrow-viewport rows, and the
  dashboard applications panel, in the G2 layout.
- The course detail page: the byline in the hero and the organisation card in the sidebar.

Out:

- Which organisation a card names. An in-progress card keeps naming the organisation the learner
  studies through (`CourseProgress.learner.organisation`); every other card names the course's
  named organisation. Only the rendering changes.
- Any link to an organisation page, a course count, or a schema.org `provider` entry. The hero,
  the organisation card and the rows carry none.
- The course player's `course_organisation_chip.html`, reports, `logo_on_dark`, and the markdown
  embed card's content (`cotton/course-card.html` inherits the shell changes and gains no byline).
- An educator-interface editor for organisations. The admin is the only editor.
- Server-side cropping or resizing of the profile logo.

## 4. Decisions

- **The named organisation excludes the site's default organisation at the model.** The default
  organisation stands for the site, which the chrome already brands. `Course.single_organisation()`
  returns `None` for it, so no template re-checks `is_default` for a course-owned organisation. The
  byline component keeps its own `is_default` guard for the studied-through organisation an
  in-progress card passes.
- **The profile logo is fitted inside the circle (`object-contain`, inset 8%); the fallback
  `logo` with `object-contain p-1`.** A wide profile logo then clears the curve instead of being
  clipped at its ends, and a wordmark `logo` is never cropped. The validator accepts a non-square
  profile logo; the circle scales it down to fit.

## 5. Requirements

### 5.1 Organisation model and admin (`freedom_ls/organisations/`)

`models.py`:

- `profile_logo = models.ImageField(_("profile logo"), upload_to=organisation_profile_logo_upload_to,
  storage=get_organisation_logo_storage, blank=True, validators=[validate_organisation_logo_extension,
  validate_organisation_logo], help_text=…)`. The help text says: shown in a circle beside the
  organisation's name on course cards and the course page; a square image of at least 128 by 128
  pixels works best, and other shapes are scaled down to fit inside it; without one the
  light-background logo is shown instead. The existing validator is reused unchanged.
- `organisation_profile_logo_upload_to(instance, filename)` returns
  `_logo_upload_path(instance, filename, "-profile")`.
- `LOGO_FIELD_NAMES = ("logo", "logo_on_dark", "profile_logo")`, so `save()` sweeps the superseded
  profile logo object from the public bucket exactly as it does the other two.
- `bio = models.CharField(_("bio"), max_length=500, blank=True, help_text=…)`: a short plain-text
  description shown on the course page, with the limit stated.
- One new migration, `0002_*`, from `makemigrations`.

`forms.py` (`OrganisationAdminForm`): `Meta.fields = ["name", "logo", "logo_on_dark",
"profile_logo", "bio"]`; the `invalid_image` loop iterates `LOGO_FIELD_NAMES` rather than its
own tuple; `bio` uses a `Textarea` widget.

`admin.py` (`OrganisationAdmin.fields`): `["name", "slug", "logo", "logo_on_dark",
"profile_logo", "bio", SUMMARIES_FIELD]`.

### 5.2 The named organisation (`freedom_ls/content_engine/models/courses.py`)

`Course.single_organisation(self) -> Organisation | None`: the course's one organisation when
`self.organisations.all()` holds exactly one row and it is not `is_default`; otherwise `None`. It
reads the prefetched `organisations` cache when present and issues one query otherwise.

`freedom_ls/learner_interface/views.py::_stamp_single_organisation` keeps its name and callers;
its body becomes `stamp_card_organisation(course, course.single_organisation())`, and `all_courses`
(§5.5) calls it too.

### 5.3 Components (`freedom_ls/learner_interface/templates/cotton/`)

Both components carry their styling as utilities in their own template, per
`claude_plugins/fls-dev/resources/templates_and_cotton.md`; `tailwind.components.css` is not
edited.

`organisation-mark.html` (new). Params: `organisation`, `size` (`sm`, the default, for cards and
rows; `md` for the detail hero; `lg` for the organisation card), mergeable `class`. Renders one
`rounded-full overflow-hidden shrink-0` circle on an opaque `bg-surface` fill with a `ring-1
ring-border`:

- `organisation.profile_logo` set: `<img src alt="" class="size-full object-contain p-[8%]">`.
- else `organisation.logo` set: `<img src alt="" class="size-full object-contain p-1">`.
- else `organisation.initials`: the monogram, `aria-hidden="true"`, in `bg-surface-2
  text-on-surface font-semibold`, as `course_organisation_chip.html` draws it.
- else `<c-icon name="unknown">`, `aria-hidden="true"`, as the chip does.

The mark never carries the accessible name; the name beside it does.

`organisation-byline.html` (rewritten, same `organisation` param). Still renders nothing for a
falsy value or `is_default`. Otherwise one `flex items-center gap-2 min-w-0` line: `<c-organisation-mark>`
then the name in a `truncate` span with `title="{{ organisation.name }}"`. New params: `size`,
passed through to the mark, and mergeable `class`. The line is `text-sm`, and `text-muted` only
when no `class` is passed, so the hero's `text-white` is the one colour on the element.

### 5.4 Dashboard cards (`freedom_ls/learner_interface/templates/`)

`cotton/course-card-shell.html`: `p-0` on the article is replaced by a small inner padding, so
the accent block sits inset from the card edge on every side with a radius smaller than the
card's `rounded-2xl`, as `design_screenshots/cards__b.png` draws it. The block keeps its height
and centred icon; the body's padding changes so its text aligns with the block's edge. The
markdown embed card (`cotton/course-card.html`, `compact` variant) renders inside this shell and
takes the inset without any change of its own; no prop switches it off.

`learner_interface/partials/course_card.html`: the byline leaves the card body. The card passes
`:organisation="course.card_organisation"` to the shell, which draws it as
`<c-organisation-byline overlap="true">`: a large raised mark overlapping the bottom of the accent
block, the name beside it, carrying no z-index so the stretched title link stays on top of it. The
`eyebrow` slot holds only the status or the access badge; the shell draws no eyebrow wrapper when
the slot rendered nothing but whitespace. The byline is then the first thing under the header,
before the status and the title. Nothing else on the card moves. The template's docstring lists
the new order.

### 5.5 Long-format rows

`cotton/course-row-shell.html`: the shell renders `{{ eyebrow }}` inside a `flex items-start
justify-between gap-3` wrapper, and each caller (the row, the applications panel) passes exactly
two child `div`s, left and right. The article keeps its border and
rounded corners. `learner_interface/partials/course_row_list.html` separates rows by a gap rather
than a rule, so rows are separate bordered cards with no divider.

`learner_interface/partials/course_row.html` renders, as in
`design_screenshots/index__ig2.png`:

- Eyebrow left: `<c-organisation-byline :organisation="course.card_organisation" />`, then, when
  `course.difficulty` is set, `course.get_difficulty_display` in the eyebrow's `text-xs text-muted
  uppercase tracking-wide` style, separated from the name by a middle dot. With no organisation the
  difficulty stands alone; with neither, the left half is empty. The left half is its own
  partial, `learner_interface/partials/course_row_eyebrow_left.html` (context: `organisation`,
  `course`), which the applications panel (§5.6) includes too.
- Eyebrow right: `<c-chip size="xs">` tags, in this order where present: the status chip for
  `registered`, `in_progress`, `complete` and `coming_soon`; the `access_badge` chip for an
  anonymous visitor; then the price as a `muted` chip holding `<c-course-price variant="compact">`,
  rendered by `course_listing_price.html` through a new `as_chip` param so the price rule stays in
  one place. The row shows no price outside that chip, and no status appears anywhere else on
  the row.
- Default slot: the title link, "Next up", and the deadline line, unchanged.
- Footer: the progress bar where it is today, then `course_details_link.html` right-aligned.

`learner_interface/partials/course_status_eyebrow.html` stays the one source of the status
labels and icons and gains an `as_chip` param. With it, the root element is
`<c-chip variant="muted" size="xs">` carrying the same `data-testid`, label and icon, with no `<p>`
and none of the `<p>`'s text classes; without it the partial renders as today. The label and icon
branches live in `course_status_label.html`, which both roots include, so neither repeats them.

`learner_interface/partials/course_details_link.html`: keeps `<c-button variant="link"
size="small" icon_right="next">` and the label `Details`, and gains
`<span class="sr-only"> for {{ course.title }}</span>` after it, so repeated identical links have
distinct accessible names.

`views.py::all_courses` calls `_stamp_single_organisation` on each entry's course.
`utils.py::get_all_courses()` gains `.prefetch_related("organisations")`, and the now-redundant
`.prefetch_related("organisations")` in `views.py::_discovery_courses` goes. The row's docstring no
longer says the all-courses page leaves `card_organisation` unstamped.

### 5.6 Applications panel (`freedom_ls/course_applications/`)

`templates/course_applications/partials/dashboard_applications.html`: each `li` renders a
`<c-course-row-shell>` for `app.course` (accent, icon, title) instead of the icon tile, so the
panel's rows match the all-courses rows:

- Eyebrow left: `<c-organisation-byline :organisation="app.course.single_organisation" />` and the
  difficulty, as §5.5.
- Eyebrow right: the existing `Pending review` (`info`) or `Incomplete` (`warning`) chip. No price
  or access chip: an application row's one tag is its application status.
- Default slot: the stretched title link to `status_url` as today, then the "Finish your
  application…" line for an unsubmitted application.
- Footer: a right-aligned line holding `course_details_link.html` (with `course=app.course`) and
  the existing `View my application` / `Continue application` button with its `sr-only` suffix.
  Both keep `relative z-10` so they sit above the title link's overlay. The mobile chevron stays.
  The rows take the `.course-card` hover lift like every other row.

The `ul` keeps its pagination, swap id, live region and partialdefs; it drops its own rounded
border and `divide-y` for the gap of §5.5.

`queries.py::get_active_applications` and the anonymous `owned_applications` queryset in
`backends.py::get_dashboard_contributions_for_request` add `prefetch_related("course__organisations")`.

The panel now includes a `learner_interface` partial and reverses `learner_interface:course_detail`.
No Python in `course_applications` imports `learner_interface`, so `docs/app_structure.md` gains
no edge, but the panel only renders with `learner_interface` installed. The template's top
comment says so.

### 5.7 Course detail page (`freedom_ls/learner_interface/`)

`views.py::course_detail`: the lookup becomes
`Course.objects.select_related("dashboard_category").prefetch_related("organisations")`; the
context gains `organisation = course.single_organisation()`.

`templates/learner_interface/course_detail.html`:

- Hero: when `organisation` is set, the first child of the inner well is
  `<c-organisation-byline :organisation="organisation" size="md" class="text-white" />` followed by
  a rule (`border-b border-white/20`, the hero's existing white-on-accent treatment) and a margin
  before the category chip, as `design_screenshots/detail__d1.png` draws it.
- Sidebar: `lg:sticky lg:top-6` moves from the sign-up panel to a new wrapper `div` with
  `space-y-6` around the panel and, when `organisation` is set, a `.surface` organisation card
  after it (`data-testid="course-organisation-card"`). A card placed after a sticky sibling is slid
  over by it, which is why the wrapper holds both. The wrapper is capped at the viewport height
  (`lg:max-h-[calc(100vh-3rem)] lg:overflow-y-auto`) so a long bio on a short screen scrolls inside
  it rather than being clipped, with `lg:p-1 lg:-m-1` so the scroll box does not clip the panel's
  focus rings. The card holds `<c-organisation-mark size="lg">` beside the name in
  `font-semibold`, then, when `organisation.bio` is non-empty, the bio in `text-sm text-muted`
  rendered escaped with `linebreaksbr`, as `design_screenshots/detail__d6.png` draws it. The aside
  keeps `order-first`, so on a phone the card follows the sign-up panel above the About section.

The JSON-LD comment and payload are unchanged.

## 6. Testing

- `Organisation`: the profile logo upload path is `organisations/<pk>-profile<ext>`; replacing a
  profile logo deletes the superseded object (extend the existing sweep tests over
  `LOGO_FIELD_NAMES`); `bio` over 500 characters is rejected by the admin form; the admin form
  names PNG, JPEG or WebP for an unreadable profile logo.
- `Course.single_organisation()`: `None` for zero organisations, for several, and for the default
  organisation alone; the organisation for exactly one non-default; no query with the prefetch
  present (`django_assert_num_queries(0)`); the same answer without the prefetch.
- `organisation-mark`: profile logo wins over logo and is fitted inside the circle
  (`object-contain`); logo alone is `object-contain`; neither gives the initials, `aria-hidden`; a name with no letters gives the
  `unknown` icon; the `img` has `alt=""`.
- `organisation-byline`: name beside the mark with `title`; nothing for the default organisation
  or an empty value (replace the name-only test, which no longer applies); `text-muted` absent
  when a `class` is passed.
- Card shell: the accent block is inset (the article no longer has `p-0`); the markdown embed card
  renders inside it with no byline.
- Dashboard: the byline precedes the status eyebrow and the title in the card; the in-progress
  card still names `CourseProgress.learner.organisation`; the narrow-viewport rows
  (`data-testid="section-row-list"`) show the byline and difficulty; `IN_PROGRESS_MAX_QUERIES` in
  `test_dashboard.py` holds.
- All-courses: a row for a one-organisation course shows the byline and difficulty; a row for a
  multi-organisation or default-organisation course shows neither byline nor difficulty when
  `difficulty` is blank; the status, access badge and price render once each, as chips, with the
  status icon kept, and no price outside the chip; `ALL_COURSES_MAX_QUERIES` in
  `test_course_listing.py` holds.
- Applications panel: a signed-in row and an anonymous-session row each show the byline, the
  difficulty, the status chip, the Details link to `course_detail` and the application button; the
  paging and live-region tests in `course_applications/tests/test_backends.py` still pass; the
  panel's query count does not grow with the number of applications on a page.
- Course detail: hero byline and sidebar card present for a one-organisation course, for an
  anonymous visitor too; absent for a multi-organisation course and for the default organisation;
  the bio paragraph absent when `bio` is empty; the hero holds no link to an organisation; the
  budget in `test_detail_page_query_count_does_not_grow_with_items` holds.
- Every `Details` link's accessible name ends with the course title.
- `test_organisation_course_flow.py` and `test_course_browse_flow.py` select the new markup
  wherever they select the byline or the row layout today.

The three query budgets are maxima. If the two new prefetches push a budget over its constant,
the constant rises by exactly the prefetch cost in the same commit, and the commit message says so.

## 8. Open questions

- Q: Should the course detail organisation card render when the organisation has no bio, leaving
  only the mark and name already shown in the hero? → A: Yes (assumed default: the idea asks for
  the card without a condition, and a bio-less card still tells a learner who offers the course.
  Overrule by editing §5.7.)
- Q: Should a non-square profile logo be rejected rather than fitted inside the circle? → A:
  Fitted, not cropped (assumed default: rejection would need a new validator, and a wide logo
  fitted inside the circle stays whole. Overrule by editing §4 and §5.1.)

## 9. Success criteria

- `makemigrations --check` is clean after `organisations/0002_*`, and the full test suite passes.
- The QA plan's browser checks of §5.4 to §5.7 pass at the three QA viewports, for a
  one-organisation course and a multi-organisation course.
- Uploading a profile logo in the admin replaces the circle's image everywhere; removing it
  returns the circle to the `logo`, and the replaced object is gone from storage.
- Pre-commit passes on the branch.
