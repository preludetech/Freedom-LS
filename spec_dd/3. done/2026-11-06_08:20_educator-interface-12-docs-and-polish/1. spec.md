# Spec: Educator interface docs and polish

Spec 12 of 12 in the educator interface rebuild (`spec_dd/1. next/roadmap.md`, "Educator interface
rebuild"). Idea: `idea.md`. Research: the `research_*.md` files beside this one.

## Purpose

Specs 1 to 11 each documented and tested their own change, but nobody has read or walked the result
end to end. This spec closes the effort, so that one product doc and one set of upgrade notes
describe an interface that behaves and reads the same on every screen.

- `tailwind.components.css`, `freedom_ls/qa_helpers/management/commands/` and `.claude/agent-memory/`,
  for the deletions.

  `screen_reader_checklist.md`.

Out:

## Decisions

- **Spec 12 lands before any `extract_panels_framework-*` spec starts.** The polish pass edits
  framework templates and `alpine-components.js`, which the extraction moves.
- **Touch targets follow spec 9's rule:** 44px below the `md` breakpoint only.
- **Button weight.** In a confirmation dialog, a reversible action (deactivate, reactivate,
  register, move, resend) confirms with `primary`; an action that deletes a row (delete, remove
  from cohort) confirms with `error`. Trigger buttons in row menus and the selection bar use
  `secondary` for reversible actions and `error` for deleting ones.
- **A learner with no name** is shown by `User.display_name` (which falls back to the email)
  everywhere a learner name appears: link text, quick-view title, breadcrumb, row checkbox label,
  history and report rows.
- **Clearing the learner status filter**, by any route, returns to the default Active + Pending
  view.
- **A 404 from a panel request** (the object left the educator's scope after the page loaded)
  shows the action-unavailable dialog. The status stays 404 and the body is identical for "never
  existed" and "out of scope", so it cannot be used to enumerate.
- **Consolidated upgrade notes live in `effort_upgrade_notes.md`**, not this spec's own
  `upgrade_notes.md`. `update_fls` reads `upgrade_notes.md` one spec at a time, so a downstream
  that already advanced through specs 1 to 11 would apply their steps twice. This spec's own
  `upgrade_notes.md`, written by the `fls-dev:update_upgrade_notes` hook, covers only spec 12's
  changes.
- **The screen-reader pass is two parts.** QA inspects the accessibility tree through Playwright
  and records the result in the QA report. A person runs `screen_reader_checklist.md` (learner
  quick view, one confirmation dialog, the learners table) with VoiceOver and Safari or NVDA and
  Firefox, and records the pair used and the result in that file. If nobody has run it when the
  spec closes, `deliberately_left.md` says so.

## Requirements

### 1. Consistency pass

The reference is `fls-dev:domain-glossary`, section "Changes" and the `is_active` row of "Words that
are already taken".

1. **Bulk "Unregister" actions are renamed.** In `freedom_ls/educator_interface/actions.py`:

   | Today | Becomes |
   |---|---|
   | `UnregisterFromCourseBulkAction`, `action_name = "unregister_from_course"` | `DeactivateRegistrationBulkAction`, `action_name = "deactivate_registration"` |
   | `UnregisterCohortFromCourseBulkAction`, `action_name = "unregister"` | `DeactivateCohortRegistrationBulkAction`, `action_name = "deactivate_cohort_registration"` |

   Both get `label = "Deactivate a course registration"`. Their `sentence()` reads "Deactivate the
   {course} registration for N learners." (or "N cohorts."). Bulk URLs sit on the table's
   `base_url` and the registry is keyed by `(table_key, action_name)`, so the slugs do not collide
   with the single-row actions of the same name.
2. **One label per action.** `RegisterCohortForCourseAction.label` becomes "Register for a course".
3. **Identifiers follow the glossary.** Test names, helpers, variables and docstrings across
   `freedom_ls/educator_interface/` and `freedom_ls/panel_framework/` that say `unregister`,
   `suspend`, `revoke`, or `removed` for an `is_active` flip are renamed (a grep-driven sweep;
   `tests/test_actions.py` alone has 78 hits). Quoted retired words in
   `freedom_ls/audit_log/tests/invariants/test_vocabulary.py` stay.
4. **Member badge.** `data-table-cells/member.html` says "Account inactive", not "Account turned
   off", for `User.is_active` False. The glossary's `is_active` row gains `User` (an account that
   cannot sign in).
5. **Confirmation dialogs share one shape.** This covers the `*_confirmation.html` templates under
   `educator_interface/templates/educator_interface/modal/` and the bulk confirmation partials;
   forms and result dialogs (`add_member.html`, `change_cohorts.html`, `add_learners_results.html`,
   `member_change_refused.html`) are not confirmations.
   - The title is a question naming the object and, for bulk, the count ("Deactivate Thandi
     Nkosi?", "Remove 12 learners from Cohort A?").
   - The body says what stops, what is kept, and how to undo it.
   - The footer is `<c-button-group variant="right" …>` with Cancel and a confirm button labelled
     with the verb, weighted per the button-weight decision.
   - Cancel has `autofocus`, except in `move_confirmation.html`'s form branch, where the
     destination select keeps it.
   - `loading_text` is the verb's "-ing" form followed by "…".

   Bulk dialogs get this from the panel framework: the bulk action base in
   `freedom_ls/panel_framework/bulk_actions.py` gains `confirm_variant` and `loading_text`, which
   `partials/bulk_confirmation_form.html` reads. `variant` keeps driving the trigger in
   `table_selection_bar.html`. Affected today:
   - single-row dialogs: every `deactivate_*`, `reactivate_*` and
     `resend_setup_email_confirmation.html` confirm moves to `primary`, and
     `remove_from_cohort_confirmation.html` moves to `error`;
   - bulk actions: `DeactivateLearnersBulkAction`, `DeactivateCohortsBulkAction` and the two renamed
     deactivate-registration actions move to a `secondary` trigger with a `primary` confirm, and
     `RemoveFromCohortBulkAction` moves to `error` for both.
6. **Empty states.** Every empty list and card renders through `<c-panel-empty-state>`, including
   `partials/members_empty.html` and `partials/audit_log_empty.html`. Each list has two messages:
   - first use: what will appear, and the action to add one, shown only to someone who can take it;
   - no results: filters matched nothing, with a clear-filters link.

   Every message is a sentence ending in a full stop.
7. **Badges.** The state of a record renders through `<c-panel-status-badge>`, directly or through
   `<c-active-status-badge>`, `learner_status_badge`, `progress_status_badge` or `flag_badge`. One
   state has one label and one tone everywhere: Active and Registered are `success`, Inactive is
   `muted`, Pending is `info`. `<c-chip>` stays for tags and categories.

### 3. Polish pass

Every educator screen and dialog, and the organisation switcher:

- **Layout:** at 390×844 and 1440×900 in both themes, plus 768×1024 for the learners and cohorts
  tables. No page-level horizontal scroll at 390. Wide tables scroll inside a labelled, focusable
  region. Dashboard, learners and cohorts match the mockups in
  `spec_dd/1. next/educator-interface-full-polish/Educator LMS Interface Design/` for layout and
  density; screens without a mockup match those three for density and component shape.
- **Keyboard:** every action works by keyboard alone. Focus is visible and never hidden by a sticky
  header, the selection bar or the quick view (WCAG 2.4.11). A dialog moves focus in on open, traps
  Tab, closes on Escape, and returns focus to the trigger (or to the table heading when a refresh
  replaced the trigger). The quick view is non-modal on desktop and modal below `md`.
- **Accessibility tree:** the quick view and every dialog take their accessible name from their
  heading. Tables have a caption or `aria-labelledby`, `th scope`, and `aria-sort` on the sorted
  column. Row checkboxes are labelled with the row's name. Toasts and HTMX result messages sit in a
  polite live region. Badge text is read, not conveyed by colour alone.
- **Contrast:** text 4.5:1 and non-text (borders, focus rings, badge edges) 3:1, in both themes.

Each finding is fixed or recorded in `deliberately_left.md`: one row per item with screen, issue,
WCAG criterion where one applies, why it is left, and the follow-up idea's path in
`spec_dd/1. next/` when there is one. Its first row points at the dark-mode idea.

## Testing

- **Smoke test per section** in `freedom_ls/educator_interface/tests/playwright/test_section_smoke.py`,
  parametrised over dashboard, learners, cohorts, courses, members, audit log and the cohort Report
  tab. Each loads the section as an `organisation_admin`, asserts the heading and one data row by
  role locator, and asserts no console errors through a new console-error helper in
  `tests/playwright/helpers.py`.
- **Keyboard flow:** one test opens a learner's quick view with Enter, asserts focus moves into it,
  closes it with Escape, and asserts focus returns to the row trigger. A second opens a deactivate
  dialog by keyboard, asserts Cancel has focus, closes it with Escape, and asserts focus returns to
  the trigger.
- **Decisions, proved by unit tests:**
  - a nameless learner shows their email as link text, quick-view title and checkbox label;
  - each route that clears the status filter (chip, "Clear all", Reset if it exists) yields
    Active + Pending;
  - a single-row and a bulk action on an out-of-scope object answer 404 with the
    action-unavailable dialog, its body identical to the one for a non-existent id;
  - the renamed bulk actions answer at their new slugs, and the old slugs answer 404 for both
    HTMX and plain requests.
- **Each known defect** that changes behaviour or copy has a test that fails before the fix.
- **The educator interface and panel framework suites pass**, Playwright included.
