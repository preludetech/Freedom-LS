# Frontend QA: Recommend outcome for registration rules

A registration rule can now recommend a course instead of registering learners on it. Staff pick
the outcome on the add page; once enabled and confirmed, the rule puts the course in each matching
learner's "Recommended courses" dashboard section and takes it away when they stop matching or the
rule is disabled. Registering by any path clears a recommendation. This run walks the add page,
the preview and confirm flow for a recommend rule, the learner's dashboard, every clearing path,
re-recommending after a registration is withdrawn, two rules sharing one recommendation, the
recommendation admin's new column, filter and warnings, deletion, and the ways it could go wrong:
a staff-made recommendation a rule must not take over, a duplicate add, a staff delete that comes
back, a double confirm, and a viewer who may not preview.

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever
this document writes `<PORT>`. Shell variables do not survive between tool calls.

Development settings run tasks on `ImmediateBackend`, so every evaluation a save triggers has
finished by the time the admin's redirect lands. Nothing here waits for a worker.

## §0 Setup

### 0.1 Server

1. `.claude/ds/scripts/find_available_port.sh`: note the number and use it literally from here on.
2. Start `uv run python manage.py runserver <PORT>` backgrounded, as its own call.
3. Open `http://127.0.0.1:<PORT>/` and confirm `#debug-branch-badge` names the
   `corporate-job-course-recommendations-3-recommend-outcome` branch. If it names another branch,
   another server holds the port; go back to step 1.

### 0.2 Seed data

## §1 The outcome is chosen once

### 1.1 The add page

1. Open the rules changelist, click "Add registration rule". Expect four inputs: Name, Organisation,
   Course, and an **Outcome** rendered as two radio buttons, "Register" and "Recommend", with
   "Register" selected and the help text "Register: matching learners are registered. Recommend:
   the course appears in their Recommended courses and they choose whether to register."
2. Enter Name `Finance audit pick`, Organisation `QA Rec Org One`, Course `QA Audit Essentials`,
   Outcome **Recommend**. Save.
3. Expect to land on the rule's change page with a success message.

### 1.2 The change page and the changelist

1. On the change page expect Outcome shown read-only as "Recommend", beside the read-only
   Organisation and Course. No radio buttons.
2. Back on the changelist expect an "Outcome" column reading "Recommend" for this rule, and an
   "Outcome" filter in the sidebar with "Register" and "Recommend".
3. Check the recommendation changelist: still only the staff-recommended learner's row. Creating a
   rule recommended nobody.

---

## §2 Enabling: preview, then recommendations

### 2.1 The preview

1. On `Finance audit pick`'s change page select Departments `Finance`, tick "Is enabled", Save.
2. Expect the confirmation page titled "Confirm changes to Finance audit pick", whose first sentence
   says the save changes who is **recommended** on the course.
3. Expect "Will be recommended (3)" listing the finance learner, the second finance learner and the
   two-org learner by name and email. Expect the registered learner **absent** (already
   registered), the staff-recommended learner **absent** (already recommended), and the ops
   learner absent.
4. Expect "Recommendation will be removed (0)" and "Stops matching but stays recommended (0)" each
   saying "Nobody". Expect **no** heading containing "registered" or "retracted" and no "Started
   the course" anywhere on the page.
5. Before confirming, check the recommendation changelist in a second tab: still one row.

### 2.2 Confirm

1. Click "Confirm and save". Expect the changelist with the usual "changed successfully" message,
   Is enabled true, Last evaluated at set, Change not yet applied false.
2. Recommendation changelist: four rows for `QA Audit Essentials`: the staff-recommended learner
   and the three from the preview. Expect a "Made by" column reading `Finance audit pick` for the
   three and `Staff` for the staff-recommended learner's row.
3. Registration changelist: still only the registered learner's row for `QA Audit Essentials`. A
   recommend rule registered nobody.
4. Open the finance learner's recommendation. Expect a read-only "Registration rules" field showing
   `Finance audit pick` as a link; click it and expect the rule. Open the staff-recommended
   learner's recommendation: "Registration rules" is blank.

### 2.3 The learner's dashboard

1. On the finance learner's dashboard expect `QA Audit Essentials` inside "Recommended courses" and
   not among their current courses.
2. On the registered learner's dashboard expect `QA Audit Essentials` among their current courses
   and no "Recommended courses" entry for it.
3. On the ops learner's dashboard expect no `QA Audit Essentials` card at all in the recommended
   section.

## §3 Registering clears the recommendation

### 3.1 Self-registration

1. On the finance learner's dashboard open `QA Audit Essentials` from the recommended card and
   register (the course's start button).
2. Back on the dashboard expect the course among their current courses and gone from "Recommended
   courses".
3. Recommendation changelist: the finance learner's row is gone. Three rows remain.

### 3.2 A staff registration

1. Registration changelist, "Add", learner the second finance learner, course
   `QA Audit Essentials`, active. Save.
2. Recommendation changelist: the second finance learner's row is gone.

### 3.3 A cohort registration, then a membership

1. Cohort admin (`http://127.0.0.1:<PORT>/admin/freedom_ls_learner_management/cohort/`): open
   `QA Rec Cohort`, add the two-org learner's QA Rec Org One `Learner` as a member, save.
2. Recommendation changelist: the two-org learner's row is still there (the cohort holds no course).
3. On the cohort add a course registration for `QA Audit Essentials`, active, save.
4. Recommendation changelist: the two-org learner's row is gone.
5. On the cohort add the staff-recommended learner as a member, save. Their **staff-made**
   recommendation is gone too: registering clears whoever made it.
6. Recommendation changelist: no rows for `QA Audit Essentials`.

### 3.4 A rule change shows the right lists afterwards

1. Open `Finance audit pick`, change nothing, Save. Preview: all three lists say "Nobody" (every
   Finance learner is registered). Confirm.

## §4 Withdrawing a registration recommends again

### 4.1 Individual registration deactivated

1. Registration changelist: open the second finance learner's row, untick "Is active", save.
2. Recommendation changelist: a new row for the second finance learner, "Made by"
   `Finance audit pick`. Their dashboard shows the course under "Recommended courses".

### 4.2 Cohort membership removed

1. On `QA Rec Cohort` delete the two-org learner's membership, save.
2. Recommendation changelist: a row for the two-org learner, made by `Finance audit pick`.

### 4.3 Cohort registration deactivated

1. On `QA Rec Cohort` untick the course registration's "Is active", save.
2. Recommendation changelist: a row for the staff-recommended learner, made by `Finance audit
   pick`. The rule recommends them now; the earlier staff row is not resurrected.

### 4.4 Learner deactivated

1. Learner admin (`http://127.0.0.1:<PORT>/admin/freedom_ls_learner_management/learner/`): open
   the second finance learner's `Learner`, untick "Is active", save.
2. Recommendation changelist: the second finance learner's row is gone (an inactive `Learner`
   matches no rule).
3. Tick "Is active" again, save. Their row is back (they still match and are not registered).

### 4.5 Still registered another way

1. Registration changelist: open the finance learner's self-made row, untick "Is active", save.
   Then, before checking, re-tick it and save.
2. Recommendation changelist: no row for the finance learner. Their dashboard shows the course
   among current courses only.

## §5 Two rules, one recommendation

1. Create `Org Two finance pick` for `QA Rec Org Two`, course `QA Audit Essentials`, Outcome
   Recommend. On its change page select QA Rec Org Two's `Finance`, enable, Save. Preview: "Will
   be recommended (0)" (the two-org learner is already recommended) and the other lists "Nobody".
   Confirm.
2. Open the two-org learner's recommendation: "Registration rules" lists both
   `Finance audit pick` and `Org Two finance pick` as links. "Made by" on the changelist names
   both. Their dashboard shows the course once under "Recommended courses".
3. Open `Finance audit pick`, change Departments to `Operations`, Save. Preview: "Will be
   recommended (1)" names the ops learner; "Recommendation will be removed (2)" names the second
   finance learner and the staff-recommended learner; "Stops matching but stays recommended (1)"
   names the two-org learner with the reason "Also recommended by Org Two finance pick". Confirm.
4. Recommendation changelist: rows for the ops learner (`Finance audit pick`) and the two-org
   learner (`Org Two finance pick` only). The two removed rows are gone. The two-org learner's
   dashboard still shows the course.
5. Disable `Org Two finance pick` (untick "Is enabled", Save). Preview: "Recommendation will be
   removed (1)" names the two-org learner. Confirm. Their row is gone and their dashboard no longer
   recommends the course.
6. Set `Finance audit pick` back to Departments `Finance`, Save, confirm the preview: the ops
   learner is removed; the second finance learner, the staff-recommended learner and the two-org
   learner are recommended again.

## §6 Staff-made recommendations are never taken over

1. Recommendation changelist, "Add": the ops learner, `QA Second Course`. Save. Expect success and
   "Made by" `Staff`.
2. Add the same pair again. Expect the form back with an error saying a recommendation for this
   user and course already exists, and still one row.
3. Create `Second course pick` for `QA Rec Org One`, `QA Second Course`, Recommend, Departments
   `Operations`, enable. Preview: "Will be recommended (0)" (the ops learner already holds a
   staff-made row). Confirm. Open the ops learner's `QA Second Course` recommendation:
   "Registration rules" is blank; "Made by" `Staff`.
4. Disable `Second course pick`, confirm. The ops learner's `QA Second Course` row is still there.

## §7 Staff deletes of a rule-made row

1. Recommendation changelist: open the second finance learner's `QA Audit Essentials` row (made by
   `Finance audit pick`), click Delete. On the confirmation page expect a warning that a
   recommendation a registration rule made comes back on the rule's next evaluation while the
   learner still matches, and to disable or change the rule instead. Confirm the delete. Expect
   the changelist with no further warning.
2. Open `Finance audit pick`, change nothing, Save, confirm the preview ("Will be recommended (1)"
   names the second finance learner). Their row is back.
3. Tick the ops learner's `QA Second Course` row (staff-made) and the second finance learner's row,
   action "Delete selected", Go. Expect the confirmation page **with** the warning (one selected
   row is rule-made). Cancel.
4. Tick only the ops learner's `QA Second Course` row, "Delete selected", Go. Expect the
   confirmation **without** the warning. Confirm. Re-run `Finance audit pick`'s save and confirm:
   the staff-made row stays gone.

## §8 The recommendation admin's filter

1. Recommendation changelist, filter "Made by" = "Registration rule": only rule-made rows (every
   `QA Audit Essentials` row). Filter "Staff": only staff-made rows (none now; add one for the ops
   learner on `QA Second Course` again and it appears).
2. Clear the filter: every row.

## §9 Warnings and the switch

### 9.1 Unpublished course

1. Create `Draft pick` for `QA Rec Org One`, `QA Draft Course`, Recommend, Departments `Finance`,
   enable, confirm the preview.
2. Reopen its change page: expect the warning "This course is not published. The rule still
   recommends it, but learners will not see the recommendation until it is."
3. The finance learner's dashboard shows no `QA Draft Course` card. Recommendation changelist shows
   their row for it. Disable `Draft pick` and confirm.

### 9.2 Switch off keeps rows

1. Organisations admin: open `QA Rec Org One`, untick "Registration rules enabled" in the HR
   settings panel, save.
2. Learner admin: change the second finance learner's department to `Operations`, save. Their
   `QA Audit Essentials` recommendation is still there.
3. Tick "Registration rules enabled" again, save. The second finance learner's row is gone; the
   rule caught up.
4. Set their department back to `Finance`, save: the row is back.

---

## §10 Deleting a rule

1. On `Finance audit pick` (enabled) expect no "Delete" link, and
   `/admin/freedom_ls_registration_rules/registrationrule/<id>/delete/` gives 403.
2. Switch QA Rec Org One's rules off (§9.2 step 1), then disable `Finance audit pick` and confirm
   the preview (it shows the switch-off notice and lists everyone under "Recommendation will be
   removed"). Open its delete page: expect 403, and on the changelist's bulk delete the
   confirmation names it as "Rule still removing its recommendations: Finance audit pick".
3. Recommendation changelist while the switch is still off: the rule's rows are all still there
   (nothing is removed while the switch is off), and the two-org learner's row still names both
   rules if `Org Two finance pick` is enabled; if it is not, re-enable it and confirm first so the
   two-org learner's recommendation is shared.
4. Switch QA Rec Org One's rules back on. The removal run happens: `Finance audit pick`'s own
   rows are gone, and the two-org learner's row remains, made by `Org Two finance pick` only (the
   rule dropped its own `RuleRecommendation` and left the shared recommendation).
5. Open `Finance audit pick`'s delete page: allowed. The confirmation lists no "Recommended
   course" (its run removed everything it held). Confirm the delete. The two-org learner's row is
   untouched. Open it: "Registration rules" names `Org Two finance pick` only.

## §11 Adversarial

### 11.1 Double confirm

1. Open `Org Two finance pick`, change nothing, Save, "Confirm and save". Browser back to the
   preview, "Confirm and save" again. Expect a normal save and no duplicate recommendation rows.

### 11.2 A viewer may not preview

1. Create a staff user with only "Can view registration rule" permission, log in as them, open a
   rule's change page. Expect the read-only view with Outcome shown; a forced POST (devtools) gets
   403; no preview page.

### 11.3 Rule names are for rule viewers only

1. Create a staff user with "Can view recommended course" and "Can change recommended course"
   permissions but **no** registration-rule permission. Log in as them, open the recommendation
   changelist: the "Made by" column reads "Registration rule" for rule-made rows, with no rule
   name; a rule-made row's change page shows "Registration rules" as "Registration rule" with no
   link. Staff-made rows still read "Staff". The "Made by" filter still narrows.

### 11.4 Register rules are unchanged

1. Create `Finance register` for `QA Rec Org One`, `QA Second Course`, Outcome **Register**,
   Departments `Finance`, enable. Preview: "Will be registered (n)" with the register headings
   and no recommend headings. Confirm. Registration changelist: active rows showing the rule.
   Disable and confirm; leave it.
