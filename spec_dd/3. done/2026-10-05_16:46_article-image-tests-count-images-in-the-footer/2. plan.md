# Plan: end the article-image view tests' `<main` slice at `</main>`

Spec: `idea.md` in this directory.

## What exists today

- `freedom_ls/blog/tests/test_views.py` holds every affected test. Four tests narrow the rendered
  article page with `main = body[body.index("<main") :]` (lines 361, 463, 481, 495). The slice runs
  to the end of the document, so it includes the footer that `_base.html` renders after `</main>`.
- The same file already keeps its page helpers together: `_get_article_page` (line 120), `_title`
  and `_meta` sit under the first block of tests. `_main_region` goes beside them.
- `freedom_ls/base/templates/_base.html` renders `<main class="grow">…</main>` and then
  `{% include "partials/footer_bar.html" %}` as a sibling of `<main>`. The stock
  `freedom_ls/base/templates/partials/footer_bar.html` has no `<img>`, which is why FLS's own suite
  never saw the bug.
- `config/settings_base.py` lists the template loaders as cotton, then filesystem, then
  app-directories, wrapped in the cached loader. A directory prepended to `TEMPLATES[0]["DIRS"]`
  therefore overrides any app template of the same name, exactly as a downstream project's
  `templates/partials/footer_bar.html` does. Django's `setting_changed` receiver for `TEMPLATES`
  rebuilds the engines, so the cached loader picks the override up within the test that sets it.
- The repo's idiom for overriding a template in a test is the `settings` fixture with a deep-copied
  `TEMPLATES` and a directory prepended to `DIRS`: `leaf_override` in
  `freedom_ls/panel_framework/tests/test_templates.py` and `_use_panel_test_templates` in
  `freedom_ls/panel_framework/tests/conftest.py`. The fixture below uses the same idiom with
  pytest's `tmp_path`, so no template file is checked in and nothing needs cleaning up.
- `article_with_image` in `freedom_ls/conftest.py` gives a published article with a one-pixel PNG
  and `image_alt="A grey square"`. The regression test reuses it.
- Grep results for other open-ended slices in `freedom_ls/`: `<main` appears in no other Python
  file. Two other `index(...) :]` slices exist (`google_tag/tests/test_context_processors.py:415`
  and `panel_framework/tests/test_component_attention_list.py:27`). Both deliberately mean "from
  this marker to the end" and do not count or unpack elements, so they stay as they are. Nothing
  beyond `test_views.py` changes.

## Slice 1: the article-image tests look only inside `<main>`

**Behaviour delivered.** The four article-page tests stop depending on what a project renders
after `</main>`. They now run against a footer that carries its own `<img>`, which is the
condition a downstream project with a footer logo puts them under, and a regression test proves
that override really renders and that `_main_region` leaves it out.

All edits are in `freedom_ls/blog/tests/test_views.py`. The slice lands as one commit, after step 4.

### 1. Red: put the four tests under a footer with an image

Add `import copy`, `from pathlib import Path` and `import pytest_django.fixtures` at the top of the
module. Then add the fixture directly above the first of the four tests
(`test_article_page_orders_back_link_title_subtitle_byline_then_body`), since this module is its
only user:

```python
@pytest.fixture
def footer_with_image(
    settings: pytest_django.fixtures.SettingsWrapper, tmp_path: Path
) -> None:
    """Override the footer partial with one that renders an image.

    A downstream project puts its footer logo here, so the article-page tests
    must hold up with an <img> after </main>.
    """
    partial = tmp_path / "partials" / "footer_bar.html"
    partial.parent.mkdir()
    partial.write_text('<footer><img src="/static/logo.png" alt=""></footer>')
    templates = copy.deepcopy(settings.TEMPLATES)
    templates[0]["DIRS"] = [str(tmp_path), *templates[0]["DIRS"]]
    settings.TEMPLATES = templates
```

The deep copy keeps the fixture from mutating the live settings dict in place, which is what lets
the `settings` fixture's teardown restore the original.

Mark all four tests that slice on `<main` with the fixture:

- `test_article_without_an_image_has_no_img_before_the_body`

Then add the regression test after `test_decorative_header_image_renders_empty_alt`:

```python
@pytest.mark.django_db
@pytest.mark.usefixtures("footer_with_image")
def test_article_page_main_region_excludes_an_image_in_the_footer(
    client: Client, article_with_image: Article
) -> None:
    # Act
    body = _get_article_page(client, article_with_image)

    # Assert
    assert "/static/logo.png" in body
    assert "/static/logo.png" not in _main_region(body)
```

The first assertion proves the overriding footer really rendered its image, so neither this test
nor the four above can pass by the override silently failing to load. The second is the property
the four tests rely on.

### 2. Green: add the helper beside `_get_article_page`

```python
def _main_region(body: str) -> str:
    """The rendered <main> element, excluding everything the base template renders outside it.

    Slicing from <main> to the end of the document would include the footer,
    which a project may override with markup of its own, such as a logo image.
    """
    start = body.index("<main")
    end = body.index("</main>", start) + len("</main>")
    return body[start:end]
```

### 3. Use the helper at all four call sites

Replace each `main = body[body.index("<main") :]` with `main = _main_region(body)` in the four
tests listed in step 1. No assertion in any of the four changes.
