## Decisions

- **No new storage, field type or rendition.** The image is a `File` row the loader already
  creates. `Article.image` stores the authored relative path and `Article.image_file` resolves it
  the same way `get_file_by_path` does, pinned to the article's own site.
- **An unresolvable image is reported by the validator and ignored by the pages.** `image_file`
  is `None` when the path matches no `File`, so the page, the cards and the meta tags behave as if
  the article had no image. Nothing renders a broken-image placeholder.
- **One card component, two ways in.** `c-article-card` gains an `article` attribute beside
  `path`. Markdown authors keep using `path` (the allowlist is unchanged), and the blog index
  passes `:article="article"`. The card's markup lives once, in an inline template partial.
- **The index is a `c-grid` of compact article cards.** Cards already carry `h-full`, so grid
  cells stretch every card in a row to the same height, with or without a thumbnail. "The same
  size" means equal height per row; titles and descriptions are not clamped.
- **The index resolves every image in one query.** `image_file` is a `cached_property`, and
  `ArticleQuerySet.with_image_files()` primes it for a whole page of articles from a single
  `File` query, so the index does not grow a query per article. A card rendered from markdown
  resolves its own article's image, one query per card, as `c-picture` does.
- **The validator checks the image against `all_file_paths`**, the files the loader would save,
  not the bare filesystem, so an image under a `_` or `.` directory is reported rather than
  silently missing after `content_save`. A single-file run has no file list to check against and
  skips the pass.
- **`og:image` comes from the view**, as `request.build_absolute_uri(image_file.file.url)`, and
  `og:image:alt` is emitted only when `image_alt` is non-empty.
- **Aspect ratios are arbitrary utilities** (`aspect-[16/10]`, `aspect-[2/1]`): the theme has no
  aspect token and Tailwind's `aspect-video` is 16:9, not the design's shapes.

## Slice 1: An article's image reaches its page's `og:image` and Twitter card

**Behaviour.** An article file with `image` and `image_alt` loads, and its page emits an absolute
`og:image`, `og:image:alt` and `twitter:card = summary_large_image`. An article with no image is
unchanged. This slice carries the alt-text rule because `image` can no longer be rejected without
a rule for its alt text.

### Schema: `freedom_ls/content_base/schema.py` and `freedom_ls/content_engine/schema.py`

In `BaseContentModel`, fix the inherited field's description, which is the only change there:

```python
image: str | None = Field(None, description="Path to the image, relative to this file")
```

In `Article`:

```python
class Article(BaseContentModel, MarkdownContentModel, content_type=ContentType.ARTICLE):
    ...
    image_alt: str | None = Field(
        None, description="Alt text for the image; empty when it is decorative"
    )

    @field_validator("category", mode="before")
    @classmethod
    def _course_only_field(cls, value: str | None, info: ValidationInfo) -> str | None:
        ...

    @model_validator(mode="after")
    def _image_needs_alt(self) -> "Article":
        # An image without alt text is invisible to a screen reader. An explicit
        # empty string is the author saying the image is decorative.
        if self.image and self.image_alt is None:
            raise ValueError(
                f"Article {self.file_path} has an image but no image_alt. "
                "Describe the image, or write image_alt: \"\" if it is decorative."
            )
        return self
```

`_course_only_field` keeps its body; only `image` leaves its decorator. `image_alt` without
`image` is accepted and ignored. `image: ""` counts as no image everywhere.

### Model and migration: `freedom_ls/content_engine/models/articles.py`

```python
image = models.CharField(
    max_length=500, blank=True, help_text=_("Image path, relative to the article file")
)
image_alt = models.CharField(max_length=500, blank=True)

@cached_property
def image_file(self) -> File | None:
    """The File behind `image`, or None when there is no image or it does not resolve.

    Same resolution as `get_file_by_path`, pinned to this article's own site
    because cards render inside body markdown where no request names a site.
    """
    if not self.image:
        return None
    return File.objects.filter(
        site_id=self.site_id, file_path=self.calculate_path_from_root(self.image)
    ).first()
```

`File` is imported from `freedom_ls.content_engine.models.files`; `cached_property` from
`functools`. Then `uv run manage.py makemigrations content_engine --name article_image` (let
Django number it) and `uv run manage.py migrate`.

### Loader: `content_save.py` `save_article`

Add `image=item.image or ""` and `image_alt=item.image_alt or ""` to the `save_with_uuid` call,
beside `author`, for the reason the docstring already gives: the dump drops `None`, so an
explicit value is what clears a removed key. Extend that docstring's list of fields.

### View and template: `freedom_ls/blog/views.py`, `blog/article_detail.html`

## Slice 4: The blog index is a grid of article cards

**Behaviour.** The index lists published articles as compact article cards in a grid, newest
first, each with its thumbnail when it has one. Every card in a row is the same height. The
index runs a fixed number of queries however many articles it lists.

**Design states:** `Blog/1280`, `Blog/375`

### Queryset: `freedom_ls/content_engine/models/articles.py`

```python
class ArticleQuerySet(models.QuerySet["Article"]):
    ...
    def with_image_files(self) -> list[Article]:
        """Evaluate the queryset and resolve every article's image in one File query.

        Keyed by site as well as path, so a page that lists one site's
        articles never picks up another site's file at the same path.
        """
        articles = list(self)
        wanted = {
            (article.site_id, article.calculate_path_from_root(article.image)): article
            for article in articles
            if article.image
        }
        found = {
            (file.site_id, file.file_path): file
            for file in File.objects.filter(
                site_id__in={site_id for site_id, _ in wanted},
                file_path__in={path for _, path in wanted},
            )
        }
        for article in articles:
            key = (article.site_id, article.calculate_path_from_root(article.image))
            article.image_file = found.get(key) if article.image else None
        return articles
```

Assigning to a `cached_property` stores the value on the instance, which is how Django's own
prefetching primes a cached relation, so the cards read `article.image_file` without a query.

## Slice 5: The validator reports an image path that does not resolve

**Behaviour.** `content_validate` fails, naming the file and the path, when an article's `image`
does not point at a file the loader would save. A resolving image passes. A single-file run skips
the check.

### `freedom_ls/content_engine/validate.py`

Rename `_widget_reference_error` to `_reference_error`, give it a `header` parameter with the
default `"Broken widget reference"`, and take `field` as the ready-made string instead of the
widget name:

```python
def _reference_error(
    file_path: Path,
    content_type: ContentType,
    field: str,
    path: str,
    problem: str,
    fix: str,
    header: str = "Broken widget reference",
) -> str:
    """Build the error block for a path that does not resolve.

    Same header/field/problem/given-value/fix layout as
    `_category_reference_error`, without its declared-list section.
    """
    ...
```

The three call sites in `validate_widget_references` compute `field = f"c-{widget} path"` once
per match and pass it. Then:

```python
def validate_article_images(all_parsed: list, all_file_paths: list[Path]) -> list[str]:
    """Check every article's `image` against the files the loader would save.

    The path is relative to the article file. Files under `_` and `.` directories
    are never loaded, so an image there is reported rather than found on disk.
    """
    errors: list[str] = []
    saved = {os.path.normpath(path) for path in all_file_paths}
    for item in all_parsed:
        if item.content_type != ContentType.ARTICLE or not item.image:
            continue
        if os.path.normpath(item.file_path.parent / item.image) not in saved:
            errors.append(
                _reference_error(
                    item.file_path,
                    item.content_type,
                    field="image",
                    path=item.image,
                    problem="no file at this path",
                    fix="Fix the path. It is relative to this article's file.",
                    header="Broken image reference",
                )
            )
    return errors
```

`validate()` calls it after `validate_widget_references`, only when `path.is_dir()`, passing
`all_file_paths`.

## Design

### `Blog/1280`

- Screenshot: `spec_dd/2. in progress/article-images/design_screenshots/Blog__1280.png`
- Viewport width: 1280
- Reach it: `/articles/` (the blog index) with at least four published articles, most with an
  image, at least one without. The demo set after Slice 6 is enough once padded with two more
  published articles that have images.
- Elements, in order:
  1. Page heading "Blog" (FLS: the `BLOG_NAME` H1 the index already has).
  2. A grid of article cards, three per row, equal gutters, every card in a row the same height.
     Each card, top to bottom:
     - Thumbnail, 16:10, rounded corners, full card width.
     - Title, bold, wrapping to two lines.
     - Description, two lines, muted.
     - Byline: author, separator, date, small and muted.
- Controls shown: none (the whole card is one link).
- Omitted from the design: tag filters, the tag label on each card, reading time, the featured
  article above the grid, the site header and the intro sentence.
- Design checklist:
  - [ ] The index H1 is the blog name.
  - [ ] Published articles render as cards in a three-column grid at 1280.
