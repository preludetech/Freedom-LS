# Plan: educator interface refactor 4, course

The course area of `freedom_ls/educator_interface/views.py` moves into the package
`freedom_ls/educator_interface/panels/course/`, and its tests move to `tests/panels/course/`. Nothing a
user sees changes: no template, URL, URL name, app label or migration moves.

Paths below are under `freedom_ls/educator_interface/` unless they start with `freedom_ls/`,
`test_organisation/` or another top-level directory. Line numbers are from the branch tip after the
rebase onto main at the time of writing. They drift as slices land, so find each block by name.

## Ground rules for every slice

- **Byte-for-byte moves.** A moved name keeps its body, comments, `TODO` and `@claude` comments,
  decorators and spelling. Only import lines change. Casts keep their current form
  (`cast(OrganisationScopedRequest, ...)` in the course block is unquoted, and stays unquoted).
- **Module shape**, copied from `panels/common/*.py`: a one-line docstring saying what the module holds
  (never where it came from), `from __future__ import annotations`, the imports, then
  `__all__ = [...]` listing every name the module defines, underscore names included, in the order
  ruff's `RUF022` gives (run `uv run ruff check --select RUF022 --fix <file>` to settle it), then the
  code in the order it had in `views.py`.
- **Absolute imports only**, never `from .x import`. A `panels/course/` module imports only its own
  sibling modules, `panels/common/*`, `freedom_ls.panel_framework.*`, `freedom_ls.educator_interface.exceptions`,
  domain apps and the standard library. It never imports `views`, `actions`, `filters`,
  `quick_views`, `reporting` or another area package.
- **`views.py` keeps importing a moved name only while code still in `views.py` uses it.** While
  slices are in flight, `views.py` imports from `panels.course.*` the names its remaining course
  code uses (the panel stack, `CourseConfig`). These are uses, not a re-export shim, and they fall
  away as the users move. After the last slice, `views.py` imports exactly `CourseConfig` (for
  `interface_config`) and the two column helpers.
- **Unused imports are decided by ruff.** After each cut from `views.py`, run
  `uv run ruff check freedom_ls/educator_interface/views.py --select F401 --fix` and keep what is
  left. Do not hand-prune from a list. Leave every other line of `views.py` untouched.
- **Test moves are cut and paste.** A moved test keeps its name, decorators, body and assertions.
  No test is added or deleted, so `uv run pytest --collect-only -q --no-cov | tail -1` reports the same total
  before slice 1 and after every slice. Record the total before slice 1.
- **Shared test helpers go to `tests/helpers.py` under their existing names.** The moved tests take
  `_interface_url` from `tests/helpers.py`, which already defines the same function (line 154).
  `_get_document` (slice 5) and `_content_action_url` (slice 6) move there, and every user imports
  them from there. A cross-reference of `tests/test_views.py` found no other helper that crosses
  the boundary between a moving range and a staying one; re-run the grep for each underscore helper
  you move to confirm.
- **Every slice's test run.** Before each commit in slices 1 to 6, run
  `uv run pytest freedom_ls/educator_interface/ --no-cov` and the collect-only total check above, so
  a break shows up in the commit that caused it. A slice's "Tests that prove it" adds only what that
  run does not already cover. Every partial `pytest` run, `--collect-only` included, takes
  `--no-cov`.
- **Commit per slice**, plain `git commit`, with the pre-commit hooks passing (`test-mirroring` and
  `lint-imports` included). Slice 4 is a rename-only commit and must not be squashed with another.

## Module dependency order

```
common/tables.py   <- data_tables.py <- data_table_panels.py <- instance_view.py <- config.py
                                         panels.py           <-/
                      content_preview.py                     <-/
```

`config.py` imports `CourseDataTable` and `CourseInstanceView`. `instance_view.py` imports the four
panels. `CourseOutlineTable` sits in `content_preview.py` above `CourseContentPanel`, which names it
at class-body time; putting it in `data_tables.py` would make `data_tables` import `OutlineRow` from
`content_preview` while `content_preview` imports the table back. No cycle exists in this layout.
