# Plan: more prominent signup button

## Problem

A would-be learner who clicks "Apply now", "Enrol for free" or "I'm interested" while logged out lands on allauth's stock login page. Nothing on that page tells them they need an account, and the enumeration-safe login error never will. See `idea.md`.

## Decision

Three changes, each a thin vertical slice:

1. Acquisition calls to action send anonymous visitors to signup with `next` set, and fall back to login when the site is closed for signups.
2. The login and signup pages each carry a button-weight switch to the other page, with a heading that says which page this is.
3. A failed login shows the generic error plus a "New here? Create an account" callout that carries the typed email to signup.

## Existing functionality to reuse

- `redirect_to_auth(request, *, next_url, auth_url)` in `freedom_ls/accounts/utils.py`. Wraps `django.contrib.auth.views.redirect_to_login`, so it carries `next` the same one-hop way `@login_required` does, and answers an htmx request with `204 + HX-Redirect`. It already takes an `auth_url` and already falls back to `settings.LOGIN_URL` when that is `None`. Every redirect in this plan goes through it. No custom `next` threading is added.
- `AccountAdapter.is_open_for_signup(request)` in `freedom_ls/accounts/allauth_account_adapter.py`, reached through `allauth.account.adapter.get_adapter(request)`. This is the one sanctioned answer to "are signups open on this site". The `signup_policy` context processor (`freedom_ls/accounts/context_processors.py`) exposes the same answer to templates as `allow_signups`.
- `get_entrance_context_data` (allauth) gives the login and signup templates `signup_url` and `login_url`, both already carrying a validated `next`.
- `url_with_next` in `freedom_ls/accounts/templatetags/accounts_tags.py` builds a `next`-carrying URL from any URL name, via allauth's `passthrough_next_redirect_url`. allauth's `get_request_param` reads `next` from POST before GET, so the tag works on the failed-login re-render, where `next` sits in the form's hidden field.
- allauth's `SignupView.get_initial` prefills the email field from `?email=`, validating it first, so a junk value is dropped rather than rendered.
- The existing signup override at `freedom_ls/base/templates/account/signup.html`, and the project's allauth element overrides in `freedom_ls/base/templates/allauth/`. The login override goes beside the signup one. `base` is earlier in `INSTALLED_APPS` than `accounts`, so that directory is the one allauth's template names resolve to. No skill dictates a different location.
- Cotton components `c-button` (`variant="primary|secondary"`) and `c-callout` (`level`, `title`) in `freedom_ls/base/templates/cotton/`. `freedom_ls/form_engine/templates/form_engine/partials/answer_errors.html` is the existing pattern for a `role="alert"` region wrapping a callout.
- Test fixtures: `mock_site_context`, `site`, `course_with_topic(access_type=...)` and `logged_in_client` in `freedom_ls/conftest.py`; `SiteSignupPolicyFactory(allow_signups=...)` in `freedom_ls/accounts/factories.py`; the `_next_param` helper in `freedom_ls/accounts/tests/test_deferred_login.py`; the `request_context` render pattern in `freedom_ls/accounts/tests/test_accounts_tags.py`; the underscore-prefixed helper-module convention (`_completion_view_fixtures.py`, `_git_helpers.py`) in `freedom_ls/accounts/tests/`.

No new cross-app dependency: `course_applications`, `course_interest` and `learner_interface` already depend on `accounts` (`docs/app_structure.md`). No model change, no migration, no new setting.

Implementation:

`freedom_ls/accounts/utils.py`, next to `redirect_to_auth` (add the `reverse` and `get_adapter` imports):

```python
def acquisition_auth_url(request: HttpRequest) -> str | None:
    """The auth page an acquisition call to action sends an anonymous visitor to.

    Signup while the site is open for signups. Otherwise None, which
    redirect_to_auth resolves to LOGIN_URL, the same page login_required uses.
    """
    if get_adapter(request).is_open_for_signup(request):
        return reverse("account_signup")
    return None
```

Returning `None` for the closed case reuses the fallback `redirect_to_auth` already has, rather than resolving `LOGIN_URL` a second time here.

`freedom_ls/accounts/decorators.py` (new module):

```python
def acquisition_login_required(
    view_func: Callable[..., HttpResponse],
) -> Callable[..., HttpResponse]:
    """login_required for acquisition calls to action.

    Same contract as login_required, but an anonymous visitor lands on
    acquisition_auth_url with next set, and an htmx request gets the
    HX-Redirect that redirect_to_auth produces.
    """
    @wraps(view_func)
    def _wrapped(request: HttpRequest, *args, **kwargs) -> HttpResponse:
        if request.user.is_authenticated:
            return view_func(request, *args, **kwargs)
        return redirect_to_auth(
            request,
            next_url=request.get_full_path(),
            auth_url=acquisition_auth_url(request),
        )
    return _wrapped
```

`Callable[..., HttpResponse]` is how the codebase types callables it needs no generic precision over; the URL resolver calls views dynamically, so `ParamSpec` would buy nothing. `request.get_full_path()` is the same `next` value `login_required` sends, and is the request's own path, so it satisfies `redirect_to_auth`'s "built server-side" rule.

`freedom_ls/course_applications/views.py`: replace `@login_required` on `apply` with `@acquisition_login_required` (import from `freedom_ls.accounts.decorators`). The other views in that module keep `@login_required`, so that import stays. The inline comment on `user = cast(User, request.user)` names `login_required`; update it.

Implementation:

`freedom_ls/accounts/templatetags/accounts_tags.py`, extend `url_with_next`:

```python
@register.simple_tag(takes_context=True)
def url_with_next(context, url_name: str, **query: str) -> str:
    url = reverse(url_name)
    request = context.get("request")
    if request is not None:
        url = str(passthrough_next_redirect_url(request, url, REDIRECT_FIELD_NAME))
    extra = {key: value for key, value in query.items() if value}
    if extra:
        url = f"{url}{'&' if '?' in url else '?'}{urlencode(extra)}"
    return url
```

allauth's own `add_query_params` would do the append, but it lives in `allauth.core.internal`, so the tag uses `urllib.parse.urlencode` rather than take on an internal import. Update the tag's docstring usage line to show the keyword form.

`freedom_ls/base/templates/account/login.html`: add `accounts_tags` to the `{% load %}`, and replace the slice 4 non-field error loop with:

```django
{% if form.errors %}
    <div role="alert">
        {% for error in form.non_field_errors %}
            <p class="text-error text-sm">{{ error }}</p>
        {% endfor %}
        {% if allow_signups %}
            {% url_with_next "account_signup" email=form.data.login as signup_with_email_url %}
            <c-callout level="info" title="New here?">
                <p>{% trans "If you don't have an account yet, create one and you'll be sent straight back to where you were." %}</p>
                <c-button href="{{ signup_with_email_url }}" variant="primary">{% trans "Create an account" %}</c-button>
            </c-callout>
        {% endif %}
    </div>
{% endif %}
```

`form.data.login` is the raw submitted value: on GET `form.data` is empty, so it resolves to nothing, and the block is not rendered anyway. Django autoescapes the href; `urlencode` keeps the value safe inside the query string; allauth's `get_initial` validates it before prefilling. The region sits outside the `<form>`, so the browser re-render announces it (same reasoning as `answer_errors.html`).
