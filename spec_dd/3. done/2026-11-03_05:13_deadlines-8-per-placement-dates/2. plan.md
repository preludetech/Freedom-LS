## Slice 1: a `children:` entry sets or suppresses the due date of its own placement

**Behaviour.** A `course.md` or `part.yaml` entry for a topic or form carries the due keys or
`no_due_date: true`; the loader writes that value on the entry's own placement row and the
resolver reads it, so the same topic placed elsewhere keeps the file's value. `overrides:` is
refused.

> **Assumed default:** this slice carries `no_due_date` and the `overrides` removal as well as the
> due keys, so it is not the very thinnest path. Why: `no_due_date` is the suppress half of the
> same behaviour, the migration is cheap, and a slice that still wrote `overrides` would be
> undone a commit later. To change: split `no_due_date` and the `overrides` removal into a slice
> 1b after the due-keys-only path is green.

> **Assumed default:** after this slice the loader accepts due keys on an activity, article or
> part entry until slice 2 refuses them. Why: slice 2 follows directly and the refusal needs the
> shared function it introduces. To change: move the direct-entry rule of slice 2 into this
> slice.

  and the two messages in `_one_kind_of_due_date` use `self._due_date_subject()`.

- After `DueDateFields`:

  ```python
  class PlacementDueDate(DueDateFields):
      """A children: entry's own deadline: the due keys set one for this placement alone,
      no_due_date says there is none here, and neither leaves the child file's value in
      place."""

      model_config = ConfigDict(extra="forbid")

      path: Path = Field(..., description="Path to the child content file")
      no_due_date: bool = Field(False, description="No deadline for this placement")

      def _due_date_subject(self) -> Path | None:
          return self.path

      def sets_a_due_key(self) -> bool:
          return any(getattr(self, name) is not None for name in DUE_DATE_FIELD_NAMES)

      def holds_due_value(self) -> bool:
          """Whether the entry replaces the child file's value: any due key, or no_due_date."""
          return self.no_due_date or self.sets_a_due_key()

      @model_validator(mode="after")
      def _no_due_date_stands_alone(self) -> Self:
          # no_due_date says there is no deadline here; a due key beside it says the opposite.
          if self.no_due_date and self.sets_a_due_key():
              raise ValueError(f"{self.path}: no_due_date takes no due keys")
          return self
  ```

  Pydantic runs a base class's `after` validators before the subclass's, so
  `_one_kind_of_due_date` still fires first and names the path.

## Slice 2: the cross-reference rules a direct entry obeys, shared by loader and validator

**Behaviour.** Due keys or `no_due_date` on an entry whose child is an activity, article or part
fail the load and the validator, naming the declaring file, the entry and the bad path. Several
such errors are reported in one failure.

### Shared helpers move to `validate.py`

`content_key`, `resolve_author_path` and `is_skipped_path` move from `content_save.py` to
`freedom_ls/content_engine/validate.py` (they are pure `pathlib`), and `content_save.py` imports
them from there, keeping every call site unchanged. `is_skipped_path` sits beside
`get_all_files`, and `get_all_files`'s own `startswith("_")`/`startswith(".")` test calls it, so
the rule exists once; the "mirrors" sentence in its docstring goes.

### The shared function

`validate.py`, beside `validate_widget_references`. `Course` and `CoursePart` are imported from
`freedom_ls.content_engine.schema` for the annotations (pure pydantic; the bundle's one `schema`
module holds them, so the re-sync's import patch covers the import).

```python
_DUE_DATE_CHILD_TYPES = frozenset({ContentType.TOPIC, ContentType.FORM})
_placement_error = functools.partial(_reference_error, header="Invalid due date placement")


def _direct_entry_errors(
    item: Course | CoursePart, index: int, entry: Child, target: BaseBaseContentModel
) -> list[str]:
    """A due date belongs to a topic or form placement."""
    if entry.holds_due_value() and target.content_type not in _DUE_DATE_CHILD_TYPES:
        return [
            _placement_error(
                item.file_path, item.content_type, f"children[{index}]", str(entry.path),
                problem=f"a due date on a {target.content_type} placement",
                fix="Only a TOPIC or FORM placement takes due keys or no_due_date.",
            )
        ]
    return []


def validate_due_date_placements(all_parsed: Sequence[BaseBaseContentModel]) -> list[str]:
    """Check every children: entry that sets a due date against the file it names.

    An entry whose path names nothing is left to the unknown-child check.
    """
    errors: list[str] = []
    # Keyed by content_key, not normpath: an entry's path is resolved the way the loader
    # resolves it, so the two agree on every file.
    by_path = {content_key(item.file_path): item for item in all_parsed}
    for item in all_parsed:
        if not isinstance(item, (Course, CoursePart)):
            continue
        for index, entry in enumerate(item.children or []):
            target = by_path.get(resolve_author_path(item.file_path, entry.path))
            if target is None:
                continue
            errors.extend(_direct_entry_errors(item, index, entry, target))
    return errors
```

### Callers

- `validate()`: the cross-file pass adds
  `for message in validate_due_date_placements(all_parsed): failed_files.append((path, message))`
  after the widget pass.
- `save_content_to_db`: immediately before "Process collection children":

  ```python
  # Every placement error at once, inside the transaction, so one load reports all of
  # them and writes nothing.
  placement_errors = validate_due_date_placements(all_parsed)
  if placement_errors:
      raise ValueError("\n".join(placement_errors))
  ```

## Slice 3: a part placement's `children:` sets due dates for the part's children

**Behaviour.** A `course.md` entry for a part carries a nested `children:` list naming the part's
topics and forms. The loader writes one `CoursePartChildDueDate` row per named child, the
resolver credits that value to that course only, and the same part placed in another course keeps
the `part.yaml` or file value. The nested rules fail the load and the validator.

> **Assumed default:** this stays one slice (schema, model, migration, the nested rules with the
> auto-discovery extraction they need, the loader second pass, the resolver and its budgets).
> Why: the loader's placement lookups can only be safe once every nested rule runs, and the
> rules need the part's auto-discovered children, so the pieces cannot be committed green apart.
> To change: split a 3a without the stale-row deletion and a 3b that adds it.

> **Assumed default:** after this slice the resolver credits the placement value while the
> deadlines admin's "Content default" still shows the file value until slice 4. Why: slice 4
> follows directly and owns the admin read. To change: move `content_default_for`'s change here.

### Schema

`freedom_ls/content_engine/schema.py`, above `Child`:

```python
class PartChildDueDate(PlacementDueDate):
    """One child of a placed part, with the deadline this placement gives it. The path is
    relative to the directory holding the part's part.yaml."""

    @model_validator(mode="after")
    def _carries_one_value(self) -> Self:
        if not self.holds_due_value():
            raise ValueError(
                f"{self.path}: set a due key or no_due_date; an entry without either does nothing"
            )
        return self
```

`Child` gains `children: list[PartChildDueDate] | None = Field(None, description="Due dates for
the children of a placed part")`.

### The nested cross-reference rules

`validate.py`:

- The auto-discovery scan moves out of `save_content_to_db` into

  ```python
  def auto_discovered_children(collection_file: Path) -> list[Path]:
      """The children a collection without a children: list gets: every content file and
      content directory beside it, in name order, skipping what the directory walk skips,
      course_categories.yaml and articles. Resolved keys, as the loader stores them."""
  ```

  with the body of today's `if not children_list:` block, returning `content_key(...)` of each
  main file. `content_save.py` calls it:
  `children_list = [...explicit...] or [(path, None) for path in auto_discovered_children(schema_item.file_path)]`.
  The comment above the explicit branch ("Both branches produce ...") moves with it.

- ```python
  def _children_of_part(part: CoursePart) -> list[Path]:
      """The part's children as resolved keys, listed or auto-discovered."""
      if part.children:
          return [resolve_author_path(part.file_path, child.path) for child in part.children]
      return auto_discovered_children(part.file_path)


  def _shown_relative_to(path: Path, directory: Path) -> str:
      """A resolved key as an author would write it under the part's directory."""
      base = content_key(directory)
      return str(path.relative_to(base)) if path.is_relative_to(base) else str(path)


  def _nested_list_errors(
      item: Course | CoursePart,
      index: int,
      entry: Child,
      target: BaseBaseContentModel,
      by_path: Mapping[Path, BaseBaseContentModel],
  ) -> list[str]:
      """A nested children: list belongs on a course's placement of a part and names the
      part's topics and forms, each once."""
      field = f"children[{index}].children"
      error = functools.partial(_placement_error, item.file_path, item.content_type)
      if isinstance(item, CoursePart):
          return [error(field, str(entry.path),
                        problem="a nested children: list in a part.yaml entry",
                        fix="Set the part's child dates in part.yaml's own children: list.")]
      if not isinstance(target, CoursePart):
          return [error(field, str(entry.path),
                        problem=f"a nested children: list on a {target.content_type} placement",
                        fix="Only a placed part takes a nested children: list.")]
      part_children = _children_of_part(target)
      known = set(part_children)
      listed = ", ".join(_shown_relative_to(p, target.file_path.parent) for p in part_children)
      errors: list[str] = []
      seen: set[Path] = set()
      for nested_index, nested in enumerate(entry.children or []):
          nested_field = f"{field}[{nested_index}]"
          resolved = resolve_author_path(target.file_path, nested.path)
          child = by_path.get(resolved)
          if resolved not in known:
              errors.append(error(nested_field, str(nested.path),
                                  problem="the part has no child at this path",
                                  fix=f"The part's children are: {listed}. Paths are relative to the part's directory."))
          elif child is not None and child.content_type not in _DUE_DATE_CHILD_TYPES:
              errors.append(error(nested_field, str(nested.path),
                                  problem=f"this child is a {child.content_type}",
                                  fix="Name the part's topics and forms."))
          elif resolved in seen:
              errors.append(error(nested_field, str(nested.path),
                                  problem="this child is named twice", fix="Name each child once."))
          seen.add(resolved)
      return errors
  ```

  A listed child that is not in `by_path` (not on disk, or failed to parse) is left to the
  unknown-child check, hence the `child is not None` guard. The "names a part" rule the spec
  states is the same type rule as the direct entry's, so a nested activity or article is
  refused too.

- `validate_due_date_placements`'s loop adds, after the direct rule:
  `if entry.children is not None: errors.extend(_nested_list_errors(item, index, entry, target, by_path))`.

### Loader second pass

`save_content_to_db`:

- The course and part save loops add their schema to `schema_by_path`, as the topic, activity
  and form loops do, so a part's file path is reachable by key.
- In the child loop keep each written row by `row_by_placement[(collection.id, child_path)] = row`
  and, when `child_content` is a `CoursePart`, append the row to `part_placements`.
- After the loop and before `collection_items_synced.send`:

  ```python
  # A course is written before the parts it places, so the part's own rows exist only
  # now. Every part placement written by this load is reconciled, including one whose
  # entry no longer has a nested list: its rows go. The load runs with no request, so
  # the site goes on every write and delete by hand.
  kept: list[UUID] = []
  for collection, schema_item in collections_data:
      if schema_item.content_type != SchemaContentType.COURSE:
          continue
      for entry in schema_item.children or []:
          if not entry.children:
              continue
          part_path = resolve_author_path(schema_item.file_path, entry.path)
          part_placement = row_by_placement[(collection.id, part_path)]
          part_schema = schema_by_path[part_path]
          for nested in entry.children:
              child_row = row_by_placement[
                  (part_placement.child_id, resolve_author_path(part_schema.file_path, nested.path))
              ]
              value, _ = CoursePartChildDueDate.objects.update_or_create(
                  site=site,
                  part_collection_item=part_placement,
                  collection_item=child_row,
                  defaults=due_date_columns(nested),
              )
              kept.append(value.pk)
  CoursePartChildDueDate.objects.filter(
      site=site, part_collection_item__in=part_placements
  ).exclude(pk__in=kept).delete()
  ```

The cross-reference rules ran before the loop, so every `row_by_placement` lookup here hits; a
miss is a bug and raises rather than skipping.

## Slice 4: the deadlines admin shows the placement value as the content default

**Behaviour.** On the cohort registration and course progress change pages, "Content default"

changed" reports a changed placement value like a changed file value. Rendering costs the same

### Queries

`freedom_ls/deadlines/queries.py`:

```python
PlacementValues = Mapping[UUID, DeadlineValue | None]


def placement_values_for(course: Course) -> PlacementValues:
    """Every value the course's part placements give the parts' children, keyed by the
    child's row id. One query for a page of rows."""
    course_type = ContentType.objects.get_for_model(Course)
    return {
        value.collection_item_id: content_layer_value(value)
        for value in CoursePartChildDueDate.objects.filter(
            part_collection_item__collection_type=course_type,
            part_collection_item__collection_id=course.pk,
        )
    }


def _sits_in_a_part(item: ContentCollectionItem) -> bool:
    return item.collection_type_id == ContentType.objects.get_for_model(CoursePart).pk


def content_default_for(
    row: CohortDeadlineOverride | LearnerDeadlineOverride,
    placement_values: PlacementValues | None = None,
) -> DeadlineValue | None:
    """What the content says for the row's item in the row's course, or the course time limit
    for a time-limit row. A part's row carries the part's value; the course's placement of the
    part replaces it when it sets one. `placement_values` stands in for that read when a
    caller has many rows under one course and fetched them at once."""
    item = row.collection_item
    course = row.course
    if item is None:
        return time_limit_value(course.time_limit_days) if course is not None else None
    if course is not None and _sits_in_a_part(item):
        values = placement_values if placement_values is not None else placement_values_for(course)
        return values[item.pk] if item.pk in values else content_layer_value(item)
    return content_layer_value(item)
```

`layers_beneath(row, cohort_rows=None, placement_values=None)` and
`canonical_beneath(row, cohort_rows=None, placement_values=None)` pass the mapping through.

> **Assumed default:** the mapping stays an optional parameter, None meaning "read per row".
> Why: `cohort_rows` on the same functions already sets that precedent and the single-row
> callers (`_stamped`, `test_queries.py`) stay simple. To change: make it required and have
> `_stamped` call `placement_values_for(instance.course)` itself.
