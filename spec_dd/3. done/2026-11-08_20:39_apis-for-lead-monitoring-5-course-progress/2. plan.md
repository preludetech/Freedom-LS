Source: `1. spec.md` in this directory. Research that backs the plan: `research_codebase.md`
(every writer of `CourseProgress`, the `update_fields` trap, the API template).

and pre-commit passing, and can be committed alone. Slice 1 is the smallest change that leaves
the system working and testable on its own (the column, its backfill and its index); slice 3 is
the thinnest endpoint; slices 2 and 4 widen them. The last slice is a final verification step and
is labelled as such.

### 1.1 The field, the index and the `save` override

`freedom_ls/learner_progress/models.py`, `CourseProgress`, after `progress_percentage`:

```python
    # The changed-since signal for readers that sync this table: auto_now and
    # the save() override below move it on every write to the row.
    # last_accessed_time is the learner's last visit and is not it.
    updated_at = models.DateTimeField(auto_now=True)
```

`Meta.indexes`, after the existing `(learner, course)` index:

```python
        indexes = [
            models.Index(fields=["learner", "course"]),
            models.Index(
                fields=["site", "updated_at", "id"], name="lp_progress_site_upd_idx"
            ),
        ]
```

The override, between `clean` and `__str__`, with the keyword-only signature and typing of
`LoadedIsActiveMixin.save`:

```python
    def save(
        self,
        *,
        force_insert: bool | tuple[ModelBase, ...] = False,
        force_update: bool = False,
        using: str | None = None,
        update_fields: Iterable[str] | None = None,
    ) -> None:
        # Every production writer passes update_fields, which makes Django skip
        # auto_now. An empty update_fields writes nothing and stays empty.
        fields = None if update_fields is None else frozenset(update_fields)
        if fields:
            fields = fields | {"updated_at"}
        super().save(
            force_insert=force_insert,
            force_update=force_update,
            using=using,
            update_fields=fields,
        )
```

`ModelBase` comes from `django.db.models.base`, `Iterable` from `collections.abc`.

### 1.2 The migration

Write `0003_courseprogress_updated_at.py` by hand (`makemigrations` would ask for a one-off
default and emit a single `AddField`, which cannot backfill). Dependency:
`("freedom_ls_learner_progress", "0002_course_progress_cohort_constraint_deferrable")`.

```python
from django.db import migrations, models
from django.db.models.functions import Greatest


def backfill_updated_at(apps: StateApps, schema_editor: BaseDatabaseSchemaEditor) -> None:
    # The latest thing known to have happened to the row. GREATEST skips nulls
    # on PostgreSQL and created_at is never null, so every row gets a value.
    CourseProgress = apps.get_model("freedom_ls_learner_progress", "CourseProgress")
    CourseProgress._base_manager.update(
        updated_at=Greatest(
            "created_at", "started_at", "last_accessed_time", "completed_time"
        )
    )


class Migration(migrations.Migration):
    dependencies = [
        ("freedom_ls_learner_progress", "0002_course_progress_cohort_constraint_deferrable"),
    ]

    operations = [
        migrations.AddField(
            model_name="courseprogress",
            name="updated_at",
            field=models.DateTimeField(null=True),
        ),
        migrations.RunPython(backfill_updated_at, migrations.RunPython.noop),
        migrations.AlterField(
            model_name="courseprogress",
            name="updated_at",
            field=models.DateTimeField(auto_now=True),
        ),
        migrations.AddIndex(
            model_name="courseprogress",
            index=models.Index(
                fields=["site", "updated_at", "id"], name="lp_progress_site_upd_idx"
            ),
        ),
    ]
```

`StateApps` is `django.db.migrations.state.StateApps`; `BaseDatabaseSchemaEditor` is
`django.db.backends.base.schema.BaseDatabaseSchemaEditor`. Then:

```
uv run manage.py makemigrations --check --dry-run   # must print "No changes detected"
uv run manage.py migrate
```

If `migrate` on the dev database, or the test run, fails with "cannot ALTER TABLE because it has
pending trigger events", split the file in two: `0003_courseprogress_updated_at.py` holds the
`AddField` and the `RunPython`; `0004_courseprogress_updated_at_index.py` holds the `AlterField`
and the `AddIndex`. The migration test below then imports `0003`.

### 2.2 Recalculation writes only a changed percentage

`recalculate_progress_percentage` in the same file:

```python
def recalculate_progress_percentage(record: CourseProgress) -> None:
    """Rewrite one record's stored percentage from its own completion rows.

    The escape hatch for code that writes completions without a transition to
    fire — see `recalculate_course_progress_on_save`.

    `update_fields`, because `last_accessed_time` is written by the player: a
    background recalculation must not look like a visit.
    """
    new_percentage = calculate_course_progress_percentage(
        record.course, completed_collection_item_ids(record)
    )
    # Compared against the database, not the instance: a caller holding a stale
    # instance must still write, and a recalculation that changes nothing must
    # not move updated_at and re-emit the row to changed-since readers.
    record.refresh_from_db(fields=["progress_percentage"])
    if record.progress_percentage == new_percentage:
        return
    record.progress_percentage = new_percentage
    record.save(update_fields=["progress_percentage"])
```

The docstring's first two paragraphs are the existing ones and stay. No other writer changes:
the `save()` override from slice 1 covers the `recalculate_progress_percentages` command, the
cohort-move re-point (`save(update_fields=["cohort_registration"])`), the player visit and the
course completion in `freedom_ls/learner_interface/views.py`; the inserts in
`freedom_ls/learner_progress/utils.py` are stamped by `auto_now`.

> **Assumed default:** the `refresh_from_db` costs one extra `SELECT` per recalculation, which
> the `recalculate_progress_percentages` command now pays per record, and it is kept. Why: the
> spec names this mechanism, the completion query it sits beside is heavier, and the one-query
> alternative (`filter(pk=...).exclude(progress_percentage=new).update(progress_percentage=new, updated_at=timezone.now())`)
> bypasses the `save()` override every other writer relies on. To change: edit 2.2.

### 3.1 The module

`freedom_ls/learner_progress/api.py`, after `freedom_ls/accounts/api.py`, imports in the order
the `ruff` isort hook enforces (standard library, third party in one block with `django` and
`drf_spectacular` and `rest_framework` sorted together, then first party):

```python
from uuid import UUID

from drf_spectacular.types import OpenApiTypes
from drf_spectacular.utils import extend_schema_field

from django.db.models import QuerySet
from rest_framework import serializers

from freedom_ls.api.filters import UpdatedSinceFilterSet
from freedom_ls.api.routers import router
from freedom_ls.api.scopes import ApiScope
from freedom_ls.api.viewsets import ReadOnlyApiViewSet

from .models import CourseProgress


class CourseProgressApiSerializer(serializers.ModelSerializer):
    course_id = serializers.UUIDField(read_only=True)
    course_title = serializers.CharField(source="course.title", read_only=True)
    registration_id = serializers.SerializerMethodField()
    registration_kind = serializers.SerializerMethodField()

    class Meta:
        model = CourseProgress
        fields = (
            "id",
            "course_id",
            "course_title",
            "registration_id",
            "registration_kind",
            "progress_percentage",
            "started_at",
            "last_accessed_time",
            "completed_time",
            "updated_at",
        )
        read_only_fields = fields

    # Exactly one of the two registration foreign keys is set; the database
    # check constraint course_progress_has_exactly_one_grant keeps it so.
    @extend_schema_field(OpenApiTypes.UUID)
    def get_registration_id(self, record: CourseProgress) -> UUID | None:
        if record.learner_registration_id is not None:
            return record.learner_registration_id
        return record.cohort_registration_id

    @extend_schema_field({"type": "string", "enum": ["learner", "cohort"]})
    def get_registration_kind(self, record: CourseProgress) -> str:
        if record.learner_registration_id is not None:
            return "learner"
        return "cohort"


class CourseProgressFilterSet(UpdatedSinceFilterSet):
    class Meta:
        model = CourseProgress
        fields: list[str] = []


class CourseProgressApiViewSet(ReadOnlyApiViewSet):
    filterset_class = CourseProgressFilterSet
    required_scope = ApiScope.REGISTRATIONS_AND_PROGRESS
    serializer_class = CourseProgressApiSerializer

    def get_queryset(self) -> QuerySet[CourseProgress]:
        # The base manager crosses sites; the base viewset's filter_queryset
        # narrows every lookup to the key's site. last_accessed_item is not
        # joined: nothing here reads it.
        return CourseProgress._base_manager.select_related(
            "course",
            "learner__user",
            "learner__organisation",
            "learner_registration",
            "cohort_registration",
        )


router.register("course-progress", CourseProgressApiViewSet, basename="course_progress")
```

The URL names are `api:course_progress_list` and `api:course_progress_detail`. `id` is the
model's UUID primary key and serialises as a string; `progress_percentage` as an integer; the
four timestamps as ISO 8601 with `Z`, the three nullable ones as `null`. `course_id` is
declared so the schema types it as a UUID rather than an integer-looking foreign key. The
`learner__user` and `learner__organisation` joins are declared now so slice 4 changes nothing in
`get_queryset`.

> **Assumed default:** `get_registration_id` is annotated `UUID | None` although the schema and
> the response never carry `null`. Why: both foreign keys are nullable to mypy, the check
> constraint is what rules out the `None` case, and the annotation is what lets the method stay
> two lines; the schema annotation and the slice's schema test pin the non-null contract. To
