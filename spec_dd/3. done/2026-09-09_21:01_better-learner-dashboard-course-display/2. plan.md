# Implementation plan: better learner dashboard course display

Spec: `1. spec.md` in this directory. Section references below (§1 to §8) point at the spec's
Requirements. This plan is implementation only. Product docs, upgrade notes and the offline
validator re-sync under `claude_plugins/fls-content/validate/` are handled by later steps of the
workflow and are not in this plan.

Work in TDD order inside each step: write the failing test named in the step, watch it fail, make
it pass, refactor. Do not write every test up front.

2. In `content_engine/schema.py` add `CourseCategoryEntry` and `CourseCategories` as §2 gives them,
   plus:
   - `RESERVED_SECTION_SLUGS = frozenset({"in-progress", "recommended", "available", "coming-soon", "history"})`
     as a module constant. It lives here rather than in `learner_interface` because the offline
     validator copies this module and runs with no Django; `learner_interface` imports it from
     here in step 6.
   - `SLUG_PATTERN = re.compile(r"[A-Za-z0-9_-]+")`, the character set Django's `validate_slug`
     accepts, so the schema needs no Django import. Always apply it with `SLUG_PATTERN.fullmatch(slug)`;
     `match` and `search` do not anchor the end and would let `bad slug!` through.
   - A `derive_content_type` method on `CourseCategories` returning
     `ContentType.COURSE_CATEGORIES`. `parse_yaml_file` calls this on the first document of a file
     for every later document that omits `content_type`; without it a second `---` document in
     `course_categories.yaml` raises `AttributeError` instead of reaching the "two declarations"
     check in step 4.
   - A `model_validator(mode="after")` on `CourseCategories` that accumulates and raises the
     per-declaration errors from §4's table in one `ValueError`: duplicate `slug`, duplicate
     `uuid` (name both slugs), a `slug` not matching `SLUG_PATTERN`, and a `slug` in
     `RESERVED_SECTION_SLUGS` (list the reserved set). The message names `self.file_path`, and
     `validate_yaml_section` already prefixes the file and content type.
3. On the `Course` schema class:
   - add `categories: list[str] = Field(default_factory=list)` and
     `dashboard_category: str | None = None`;
   - add a `@field_validator("category", mode="before")` that always raises
     `ValueError("'category' is no longer a course field. Use 'categories' (a list of category slugs), and 'dashboard_category' when there is more than one.")`.
     A before-validator on an inherited field only runs when the key is present in the input, so
     a file without the key is untouched and one with it fails with `Field: category` in the report;
   - add a method `resolve_dashboard_category(self) -> str | None`: returns
     `self.dashboard_category` when set, the single entry when `categories` has exactly one, else
     `None`. This is the single-category shorthand, and the loader in step 3 is its one caller.
     The validator in step 4 reports the "omitted with two or more" case, which this method's
     `None` cannot distinguish from "no categories", so step 4 reads `dashboard_category` and
     `categories` directly rather than calling it.

### 6b. The section model, in `dashboard_sections.py`

A new module so `views.py` does not grow another three hundred lines. It holds:

```python
SECTION_PAGE_SIZE = 3

@dataclass(frozen=True)
class DashboardSection:
    slug: str                     # page parameter is page_<slug>
    heading: str
    description: str              # "" for the built-in sections
    wrapper_id: str               # current-courses, recommended-courses, available-courses,
                                  # coming-soon-courses, learning-history, category-<slug>
    page_obj: Page                # items are Course objects, except Recommended courses where they
                                  # are RecommendedCourse rows: read `courses` for cards, `page_obj`
                                  # only for pagination state
    courses: list[Course]         # this page's courses, annotated, always Course objects
    browse_all_url: str           # "" when the section has no link

    @property
    def page_param_name(self) -> str: return _page_param_name(self.slug)
    @property
    def heading_id(self) -> str: return f"section-heading-{self.slug}"
    @property
    def swap_id(self) -> str: return f"section-page-{self.slug}"
    @property
    def position_text(self) -> str: "1 to 3 of 12" from page_obj.start_index(), end_index(), paginator.count; "" when count is 0
    @property
    def nav_label(self) -> str: f"{self.heading} pages"


def _page_param_name(slug: str) -> str:
    return f"page_{slug}"


def page_for(request: HttpRequest, slug: str, object_list: QuerySet[Course] | list) -> Page:
    return Paginator(object_list, SECTION_PAGE_SIZE).get_page(
        request.GET.get(_page_param_name(slug))
    )


def section_page_href(request, param_name, page_number) -> str:   # exactly as §6
```

`RESERVED_SECTION_SLUGS` is imported from `content_engine.schema`. The `swap_id`, `heading_id` and
`category-<slug>` prefixes are fixed strings that cannot collide with each other or with the four

A template tag `{% section_page_href param_name page_number as href %}` in a new

### 6d. The HTMX branch

htmx sends the target element's id in the `HX-Target` header. On
`request.headers.get("HX-Request") == "true"`, read that header, strip the `section-page-` prefix
to get the section slug, and build only that section:

- a reserved slug dispatches to the matching helper above (In progress and Learning history
  require an authenticated user; return 404 otherwise);
- any other slug is `get_object_or_404(CourseCategory, slug=slug, show_on_dashboard=True)` then
  `_category_section`;
- a missing or unrecognised header, or a helper returning `None`, is a 404.

The shared inputs a section needs (registrations, recommendations, the discovery queryset) are
still computed, because the catch-all and category sections exclude registered and recommended
courses; what is skipped is every other section's page query and annotation. Render
`learner_interface/partials/course_list.html#section-page-response` (step 8) with
`{"section": section}` and return 200. The whole-page path renders `dashboard.html` as today.

First tests (`freedom_ls/learner_interface/tests/test_dashboard_view.py`, extended, plus a new

### 8d. Focus, in `alpine-components.js`

Register `courseSectionPagination` on the section wrapper (which survives the swap):

```
Alpine.data("courseSectionPagination", () => ({
  pressed: null,
  _onBeforeRequest: null,
  _onAfterSwap: null,
  init() {
    this._onBeforeRequest = (e) => { this.pressed = e.detail.elt.dataset.direction ?? null }
    this._onAfterSwap = () => {
      if (!this.pressed) return
      const control = this.$el.querySelector(`[data-direction="${this.pressed}"]`)
      const target = control && control.getAttribute("aria-disabled") !== "true"
        ? control
        : this.$el.querySelector("h2")
      target?.focus({ preventScroll: true })
      this.pressed = null
    }
    this.$el.addEventListener("htmx:beforeRequest", this._onBeforeRequest)
    this.$el.addEventListener("htmx:afterSwap", this._onAfterSwap)
  },
  destroy() {
    this.$el.removeEventListener("htmx:beforeRequest", this._onBeforeRequest)
    this.$el.removeEventListener("htmx:afterSwap", this._onAfterSwap)
  },
}))
```

Named handlers with a `destroy()` follow `dateEyebrow` and `examRunner` in the same file. htmx
events bubble, so listening on the wrapper catches the inner swap. No scrolling after the swap;
nothing pads a short page.

First tests (`freedom_ls/learner_interface/tests/test_dashboard_accessibility.py`): the spec's
**Accessibility** list on rendered HTML: both controls present with `aria-disabled` at the
boundaries, one `<nav>` per section with distinct `aria-label`s, the `<h2>` outside the element
with `id="section-page-<slug>"`, exactly one `role="status"` element on the page, and the HTMX

`test_course_cards.py` must keep passing unchanged, which pins the wrapper ids and card markup.
