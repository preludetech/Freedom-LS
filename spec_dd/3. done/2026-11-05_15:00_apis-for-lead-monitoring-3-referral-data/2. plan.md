# Plan: Lead monitoring API, referral data

Source: `1. spec.md` in this directory. Research that backs the plan: `research_codebase.md`
(touch points, the `updated_at` hardwiring in child 1's pagination and filter, the four models'
fields and indexes).

and pre-commit passing, and can be committed alone. Slice 1 is the thinnest behaviour that runs
end to end (a key reads one site's referral codes), and it owns the pagination generalisation
because nothing in this spec can page without it. Slices 2 to 4 add one resource each, widening
the shared machinery only where that resource needs it. Slice 5 is a final verification step and
is labelled as such.

> **Assumed default:** the plan is implementation only. `docs/api.md`, the product-doc edits and
> the upgrade notes are not slices. Why: the planning command excludes documentation and the todo
> carries those items for the documentation step. To change: add a final slice after slice 5.

No migration: the spec's Decisions table rules one out, and no slice changes a model.

### 1.2 The paginator reads `cursor_field`

`freedom_ls/api/pagination.py`. The `ordering` class attribute and every literal `updated_at` go.
The `TypeVar` bound becomes `Model`; the `TimestampedModel` import goes with it. The cursor
field name comes from the viewset class, never from the request: the only request-supplied
input is the cursor value, and it keeps every existing bound (length, two strings, pk parsed by
the model's own field, one 400 body).

```python
from collections.abc import Callable
from datetime import date, datetime

from django.core.exceptions import ImproperlyConfigured

M = TypeVar("M", bound=Model)

DEFAULT_CURSOR_FIELD = "updated_at"


def _parse_aware_datetime(raw: str) -> datetime:
    parsed = datetime.fromisoformat(raw)
    # A naive instant has no single position on an aware column.
    if timezone.is_naive(parsed):
        raise ValueError(BAD_CURSOR)
    return parsed


# Keyed by get_internal_type, not matched with isinstance: DateTimeField
# subclasses DateField, so an isinstance chain would have to be ordered by hand.
_CURSOR_PARSERS: dict[str, Callable[[str], date]] = {
    "DateTimeField": _parse_aware_datetime,
}


class ApiKeysetPagination(BasePagination):
    cursor_query_param = "cursor"
    page_size_query_param = "page_size"

    def paginate_queryset(
        self, queryset: QuerySet[M], request: Request, view: APIView | None = None
    ) -> list[M]:
        self.request = request
        # Bound to a str name first: rest_framework is untyped, so the
        # attribute arrives as Any.
        cursor_field: str = getattr(view, "cursor_field", DEFAULT_CURSOR_FIELD)
        self.cursor_field = cursor_field
        # Resolved before the cursor is read, so a viewset paging on a field
        # of the wrong type fails on its first page, not on its second.
        parse = _cursor_parser(queryset.model, cursor_field)
        self.page_size = self._page_size(request)
        position = self._decode_cursor(request, queryset.model, parse)
        queryset = queryset.order_by(cursor_field, "id")
        if position is not None:
            value, last_pk = position
            queryset = queryset.filter(
                Q(**{f"{cursor_field}__gt": value})
                | Q(**{cursor_field: value, "pk__gt": last_pk})
            )
        # One row past the page says whether a next page exists without a count.
        rows = list(queryset[: self.page_size + 1])
        self.has_next = len(rows) > self.page_size
        self.rows: list[M] = rows[: self.page_size]
        return self.rows

    def _next_link(self) -> str | None:
        if not self.has_next:
            return None
        last = self.rows[-1]
        cursor = self._encode_cursor(getattr(last, self.cursor_field), last.pk)
        # replace_query_param keeps every other parameter of the request.
        return str(
            replace_query_param(
                self.request.build_absolute_uri(), self.cursor_query_param, cursor
            )
        )

    def _encode_cursor(self, value: date, pk: int | UUID) -> str:
        # datetime is a date, so one signature covers both cursor field types.
        payload = json.dumps([value.isoformat(), str(pk)])
        return urlsafe_b64encode(payload.encode()).decode()

    def _decode_cursor(
        self, request: Request, model: type[Model], parse: Callable[[str], date]
    ) -> tuple[date, int | UUID] | None:
        raw = request.query_params.get(self.cursor_query_param)
        if raw is None:
            return None
        if len(raw) > CURSOR_MAX_LENGTH:
            raise ValidationError({self.cursor_query_param: [BAD_CURSOR]})
        try:
            decoded = json.loads(urlsafe_b64decode(raw.encode()))
            # Exactly two strings: anything else is not a cursor this class wrote.
            if not (
                isinstance(decoded, list)
                and len(decoded) == 2
                and all(isinstance(part, str) for part in decoded)
            ):
                raise ValueError(BAD_CURSOR)
            value = parse(decoded[0])
            pk = model._meta.pk.to_python(decoded[1])
        except (
            ValueError,
            TypeError,
            binascii.Error,
            UnicodeDecodeError,
            DjangoValidationError,
        ) as exc:
            raise ValidationError({self.cursor_query_param: [BAD_CURSOR]}) from exc
        return value, pk


def _cursor_parser(model: type[Model], cursor_field: str) -> Callable[[str], date]:
    """The parser for the cursor field's type."""
    field = model._meta.get_field(cursor_field)
    parse = _CURSOR_PARSERS.get(field.get_internal_type())
    if parse is None:
        raise ImproperlyConfigured(
            f"{model.__name__}.{cursor_field} is not a field this pagination can page on."
        )
    return parse
```

`get_field` on a name the model lacks raises `FieldDoesNotExist`; that is a viewset configuration
error, not a request error, and it surfaces as one. Slice 4 adds the `"DateField"` entry to
`_CURSOR_PARSERS`. `get_schema_operation_parameters` and `get_paginated_response_schema` are
untouched: the cursor stays opaque in the schema.

> **Assumed default:** the cursor's trust boundary stays as it is: the field name is a class
> attribute, the value keeps the 512-character cap, the two-string check, the model's own pk
> parser and the one 400 body, and `_CURSOR_PARSERS` refuses any field that is not a date or
> datetime. Why: no request input reaches a lookup name, and the decoder's bounds are unchanged.
> To change: 1.2, and slice 4's over-length cursor test.

Users responses and cursors are byte-for-byte what they were: the default field is still
`updated_at`, the payload is still `[isoformat, pk]`.

### 1.3 `paginate_all` takes a cursor field

`freedom_ls/api/tests/helpers.py`:

```python
from django.db.models import Model
from rest_framework.views import APIView

from freedom_ls.api.pagination import DEFAULT_CURSOR_FIELD, ApiKeysetPagination


class CursorFieldView(APIView):
    """The one attribute the paginator reads from a view."""

    def __init__(self, cursor_field: str) -> None:
        super().__init__()
        self.cursor_field = cursor_field


def paginate_all[M: Model](
    queryset: QuerySet[M], path: str = "/pages/", cursor_field: str = DEFAULT_CURSOR_FIELD
) -> list[list[M]]:
    """Every page of `queryset` through `ApiKeysetPagination`, following `next`."""
    factory = APIRequestFactory()
    view = CursorFieldView(cursor_field)
    pages: list[list[M]] = []
    next_url: str | None = path
    while next_url is not None:
        request = Request(factory.get(next_url))
        paginator = ApiKeysetPagination()
        pages.append(paginator.paginate_queryset(queryset, request, view))
        next_url = paginator.get_paginated_response([]).data["next"]
    return pages
```

The `TimestampedModel` import leaves this module too.

### 1.5 The referral codes endpoint

`freedom_ls/referral_tracking/api.py` (new). `rest_framework` and `freedom_ls.api` are imported
only here, so a project that installs `referral_tracking` without `freedom_ls.api` never imports

```python
"""Read-only API resources for referral tracking.

Every viewset starts from the model's base manager: the default manager reads
the thread-local request site, and the base viewset's filter_queryset binds
every lookup to the key's site instead, so no lookup depends on thread state.
"""

from django.db.models import QuerySet
from rest_framework import serializers

from freedom_ls.api.routers import router
from freedom_ls.api.scopes import ApiScope
from freedom_ls.api.viewsets import ReadOnlyApiViewSet

from .models import ReferralCode


class ReferralCodeApiSerializer(serializers.ModelSerializer):
    class Meta:
        model = ReferralCode
        fields = (
            "id",
            "code",
            "label",
            "notes",
            "destination",
            "inactive_destination",
            "is_active",
            "hit_count",
            "last_hit_at",
            "created_at",
        )
        read_only_fields = fields


class ReferralCodeApiViewSet(ReadOnlyApiViewSet):
    cursor_field = "created_at"
    required_scope = ApiScope.REFERRAL_DATA
    serializer_class = ReferralCodeApiSerializer

    def get_queryset(self) -> QuerySet[ReferralCode]:
        # Base manager: the base viewset binds the site (see the module docstring).
        return ReferralCode._base_manager.all()


router.register("referral-codes", ReferralCodeApiViewSet, basename="referral_code")
```

No `filterset_class`: the spec puts no filter on referral codes, and `DjangoFilterBackend` does
nothing for a view without one. Detail lookup is DRF's default `pk`, a UUID. `ReferralCode`'s
`Meta.ordering` is descending, and the paginator's `order_by` replaces it. Values go out as
stored: `hit_count` is the counter, `last_hit_at` is `null` for a code never hit, blank `notes`
is `""`.

> **Assumed default:** `label` and `notes`, operator-written free text, are returned as the spec
> lists them. Why: the spec's field list is the contract, and the `referral_data` scope gates
> the resource. To change: drop `notes` from the `fields` tuple in 1.5 and from the spec.

```python
from freedom_ls.api.filters import AwareIsoDateTimeFilter, UpdatedSinceFilterSet

from .models import ReferralCode, ReferralCodeHit
```

### 4.1 A `DateField` cursor

`freedom_ls/api/pagination.py`, one entry in `_CURSOR_PARSERS`:

```python
_CURSOR_PARSERS: dict[str, Callable[[str], date]] = {
    "DateTimeField": _parse_aware_datetime,
    # date.fromisoformat rejects a value with a time part, so a datetime
    # cursor on a date column fails here rather than being truncated to a day.
    "DateField": date.fromisoformat,
}
```

Nothing else changes: `_encode_cursor` already takes a `date`, the position filter already keys
on `self.cursor_field`, and `date.fromisoformat("2030-01-01T00:00:00")` raises `ValueError`,
which is already in the except tuple and becomes the one 400 body.

### 4.2 `IsoDateFilter`

`freedom_ls/api/filters.py`:

```python
class IsoDateField(forms.DateField):
    # One format, so a datetime or a localised date is rejected rather than parsed.
    input_formats = ["%Y-%m-%d"]
    default_error_messages = {"invalid": "Give a date as YYYY-MM-DD."}


class IsoDateFilter(django_filters.DateFilter):
    field_class = IsoDateField
```

Django's `DateField.to_python` strips the string and tries each entry of `input_formats` with
`strptime`, so `2030-01-01T00:00:00` and `not-a-date` are both the `invalid` error, which
django-filter and DRF turn into a 400 keyed by the parameter name. The error message is the
message the spec asks for: a date is expected.

### 4.3 The first-touch counts endpoint

```python

        lookup_expr="gte",
```
