# Plan: Educator audit log: avatars, export, compact expandable rows

Implementation plan for `1. spec.md`. Every path is relative to the repo root. Line numbers are
from the worktree at the time of writing and are a guide, not a contract.

The spec's "Documentation and downstream" section (upgrade notes, product docs) is not built by
this plan; the documentation step that follows implementation produces it. The `audit_log`
README row for the new action is documentation too and is left to that step. The domain glossary
edit *is* built here, because `freedom_ls/audit_log/tests/invariants/test_vocabulary.py` mirrors
the glossary and fails the new action code until both change together.

Seven slices. Each leaves the suite green and is committed alone. Slice 1 is the thinnest thing
that runs end to end: a generic row detail on a stub table. Slices 2 and 3 put it on the three
audit screens and add the avatars. Slice 4 adds the export hooks the screens need, Slice 5 the
new audit action, Slice 6 the learner History export complete with its recorded entry, and
Slice 7 widens the export to the cohort History and the organisation Audit log.

> **Assumed default:** Slices 1, 4 and 5 are framework-only steps with no educator-visible
> change, proven against stub tables and the registry. Why: each is generic behaviour every later
> slice needs, its tests run without the audit screens, and merging them into Slice 2 or 6 would
> make those slices carry two apps' worth of change. To change: fold Slice 1 into Slice 2, Slice 4
> into Slice 6 and Slice 5 into Slice 6, keeping the tests.

## Slice 1: a generic row detail on `DataTable`

**Behaviour.** A `DataTable` that sets `row_detail_template` renders, at `md` and up, a trailing
toggle column whose button opens a hidden detail row under its row, and below `md` a
`<details>` disclosure at the end of each card. A table without the attribute renders exactly as
today. Nothing in the educator interface changes yet.

**`freedom_ls/panel_framework/tables.py`.**

```python
class DataTable:
    ...
    #: A template rendered under a row, hidden until the row's toggle opens
    #: it (a <details> disclosure below md). None means rows have no detail
    #: and the table renders no toggle column.
    row_detail_template: str | None = None

    @staticmethod
    def has_row_detail(row: Model) -> bool:
        """Whether this row has anything to show under it. Only consulted
        when `row_detail_template` is set; every row has one by default."""
        return True
```

In `get_context`, the row dicts gain `has_row_detail`, and the context gains the template:

```python
detailed = cls.row_detail_template is not None
rows = [
    {
        "object": row,
        "label": _lazy_label(row),
        "has_row_detail": detailed and cls.has_row_detail(row),
    }
    for row in page_obj
]
return {
    ...,
    "row_detail_template": cls.row_detail_template,
}
```

**`freedom_ls/panel_framework/panels.py`.** The bulk column is a panel decision
(`DataTablePanel.get_context_data` sets `bulk_actions`), so the one number both the detail row's
`colspan` and the empty-state `colspan` span is computed there, once:

```python
# Every column a full-width cell must span: the data columns, the toggle
# column when rows have a detail, and the selection column when bulk
# actions render.
context["table_colspan"] = (
    len(context["columns"])
    + (1 if context["row_detail_template"] else 0)
    + (1 if context["bulk_actions"] else 0)
)
```

`_data_table_region_base.html` passes `:row_detail_template="row_detail_template"` and
`:table_colspan="table_colspan"` to `<c-data-table>`.

**`cotton/data-table.html`.** New `row_detail_template=""` and `table_colspan=""` vars. The
`<table>` carries `x-data="rowDetail"` when the template is set. Header: after the column
headers, `{% if row_detail_template %}<th><span class="sr-only">More</span></th>{% endif %}`.
The empty-state `colspan` becomes `{{ table_colspan }}`. Body, per row (`forloop.counter` keeps
ids unique inside the region):

```django
{% if row_detail_template %}
    <td class="w-0 text-right">
        {% if row.has_row_detail %}
            <button type="button"
                    class="group inline-flex size-11 items-center justify-center rounded-full text-muted hover:text-on-surface"
                    aria-expanded="false"
                    aria-controls="{{ region_id }}-detail-{{ forloop.counter }}"
                    aria-label="More about {{ row.label }}"
                    x-on:click="toggle">
                <span aria-hidden="true" class="motion-safe:transition-[rotate] group-aria-expanded:rotate-180">
                    <c-icon name="dropdown" class="size-4" />
                </span>
            </button>
        {% endif %}
    </td>
{% endif %}
</tr>
{% if row.has_row_detail %}
    <tr hidden data-row-detail id="{{ region_id }}-detail-{{ forloop.counter }}">
        <td colspan="{{ table_colspan }}" class="bg-surface-2">
            {% include row_detail_template with object=row.object %}
```

**`cotton/data-table-card.html`.** New `row_detail_template=""` var, passed from
`data-table.html`. After the `{% if card_template %}…{% endif %}` block, inside the

```django
    <details class="mt-2">
```

**`tailwind.components.css`.** The two `tbody tr` rules become `tbody tr:not([data-row-detail])`
and `tbody tr:not([data-row-detail]):last-child`, so a detail row adds no border and no hover of
its own, and the row above it keeps the border it has today. When a hidden detail row follows
the last data row of a page, that data row is no longer `:last-child` and keeps its `border-b`;
that rule reads as the table's bottom edge and is left as is. A CSS comment above the rules
says that a `[data-row-detail]` row is the expandable panel under a data row and borrows that
row's borders.

**`freedom_ls/panel_framework/static/panel_framework/js/alpine-components.js`.**

```js
// Row detail toggle (cotton/data-table.html). x-data sits on the <table>;
// each toggle button names its detail row through aria-controls, so rows
// open independently and the server renders every row closed. The detail is
// a <tr> switched through `hidden`, which cannot animate, so there is no
// x-transition: only the chevron moves, through CSS keyed on aria-expanded.
// Focus stays on the button.
Alpine.data("rowDetail", () => ({
    toggle(event) {
        const button = event.currentTarget;
        const detail = document.getElementById(button.getAttribute("aria-controls"));
        if (!detail) return;
        const opening = detail.hidden;
        detail.hidden = !opening;
        button.setAttribute("aria-expanded", String(opening));
    },
}));
```

An HTMX swap of the region replaces the `<table>`, so a fresh instance starts with every row
closed; no listener, so no `destroy()`.

> **Assumed default:** the toggle flips `hidden` and `aria-expanded` on the DOM directly instead
> of binding a reactive property with `x-show` and `x-transition`. Why: the detail row is a
> sibling of the toggle's row, not a descendant, and one `x-data` on the table owns every row, so
> a per-row bound property would need a nested scope per row pair; a `<tr>` cannot animate
> through `display` anyway. To change: Slice 1, the `rowDetail` component.

Add `rowDetail` to the inventory table in `claude_plugins/fls-dev/skills/alpine-js/SKILL.md`.

**Stubs for the tests.** `freedom_ls/panel_framework/tests/templates/panel_framework/test_row_detail.html`,

```python
#: Target models that are a person: the user pk is the target itself, or the row's user.
_PERSON_TARGETS: tuple[type[Model], ...] = (User, Learner, OrganisationMember)


def _attach_target_users(entries: Sequence[AuditLogEntry]) -> None:
    """Set `target_is_person` and `target_user_pk` on every entry.

    A person target gets the live user's pk (None once the row is gone, so
    the template shows the neutral circle beside the stored label); any
    other target is not a person and renders as plain text. Keyed on the
    stored content type id against the registry's ids, so no entry's
    `target_content_type` relation is read, and one lookup per model type
    regardless of the page size. No `is_active` filter: an inactive user
    keeps their avatar.
    """
    person_models_by_type_id = {
        ContentType.objects.get_for_model(model).pk: model for model in _PERSON_TARGETS
    }
    by_model: dict[type[Model], list[AuditLogEntry]] = {}
    for entry in entries:
        model = person_models_by_type_id.get(entry.target_content_type_id)
        entry.target_is_person = model is not None
        entry.target_user_pk = None
        if model is not None:
            by_model.setdefault(model, []).append(entry)
    for model, typed in by_model.items():
        user_field = "pk" if model is User else "user_id"
        rows = model.objects.filter(pk__in={entry.target_object_id for entry in typed})
        found = {str(pk): user_pk for pk, user_pk in rows.values_list("pk", user_field)}
        for entry in typed:
            entry.target_user_pk = found.get(entry.target_object_id)
```

## Slice 4: export hooks in `panel_framework`

```python
class DataTablePanel(Panel):
    ...
    def get_export_queryset(self, request: HttpRequest) -> QuerySet:
        """The rows the CSV export narrows with the same search, filters
        and sort as the screen. Defaults to the screen's own rows; a panel
        overrides it to add a `select_related` the screen does not need."""
        return self.get_queryset(request)

    def before_export(self, request: HttpRequest, rows: QuerySet) -> QuerySet:
        """Runs once after narrowing and before the streaming response is
        built, while the request's site is still the ambient scope, so a
        panel can record the export. Returns the rows to stream."""
        return rows

    def narrow(self, request: HttpRequest, queryset: QuerySet | None = None) -> tuple[TableQuery, QuerySet]:
        """... `queryset` replaces the panel's own rows as the starting point
        (the export passes `get_export_queryset`), so a render and an export
        still parse and apply the request identically."""
        query = self.data_table.parse_query(request, self.table_key)
        rows = self.data_table.filter_queryset(
            request, self.get_queryset(request) if queryset is None else queryset, query
        )
        return query, rows
```
