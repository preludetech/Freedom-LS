# Implementation plan: Cohort progress PDF report

Implements `1. spec.md`. Read the spec first — this plan does not restate its rationale, only what to
build, in what order, and against which existing code.

## How to work through this plan

- **TDD throughout.** Each task states the tests to write *first*. Do not write the whole test suite
  up front — write the tests for the task you are on, watch them fail, then implement.
- Tasks are ordered so that each one leaves the suite green. Phases 1–3 are independently mergeable.
- After any model change: `uv run manage.py makemigrations` then `uv run manage.py migrate`. Never
  edit an existing migration.
- Run `uv run pytest` before moving between phases.
- **Invoke the skills listed under each phase before writing that phase's code** — the full skill map,
  with the hard rules each one imposes, is in "Skills to use" at the end of this document. Read it
  before starting Phase 1.

## Rules that bind every task in this plan

These come from the project skills and apply everywhere; they are not repeated per task.

- **No spec section numbers in code.** Never write `# per spec §12.4` or `{% comment %}§9{% endcomment %}`
  in any file. If a comment is only a citation, delete it; if it carries real reasoning that happened
  to originate in the spec, keep the reasoning and drop the citation. (`code-comments` skill; this
  plan cites `§` freely, the code must not.)
- **Never delete a `TODO` or `@claude` comment** unless that TODO is actually done. (CLAUDE.md and the
  `code-comments` skill, converging.)
- **Test data comes from factory_boy factories, never `.objects.create()`.** Every site-aware factory
  subclasses `SiteAwareFactory` from `freedom_ls.site_aware_models.factories`, never
  `factory.django.DjangoModelFactory` directly.
- **Every test touching a site-aware model takes the `mock_site_context` fixture** and never sets
  `site` by hand.
- **No `if` / `for` / `try` in test bodies.** Tests must pass in any order (`pytest-randomly` and
  `pytest-xdist` are both on).
- **Don't assert hardcoded config values**, including the subtle variant: feeding live configuration
  through the code under test and asserting the derived result against a hardcoded expectation. This
  bites the theme-token extraction test specifically (Task 4.3).
- **`config.py` is read-only** — it resolves settings and nothing else. No mutation of Django
  settings, no side effects.
- A missing/misconfigured setting is reported by a **system check**, never by raising at import or in
  `ready()`.

# Phase 1 — Fix multi-select quiz scoring (spec §14)

## Task 1.1 — Failing tests for the checkbox scoring bug

Add to `freedom_ls/student_progress/tests/test_form_progress_score_quiz.py` (213 lines today, three
`multiple_choice` tests — extend it rather than starting a new file; keep the existing tests passing
untouched).

Write these first and watch them fail:

- Checkbox question, 2 correct of 4, student ticks all 4 → score 0. *(This is the headline bug.)*
- Checkbox, ticks exactly the 2 correct → score 1.
- Checkbox, ticks 1 of the 2 correct → score 0.
- Checkbox, ticks the 2 correct plus 1 incorrect → score 0.
- Checkbox, ticks nothing (`QuestionAnswer` exists, no selected options) → score 0.
- Checkbox with an option whose `correct is None`: selecting all correct options plus the `None`
  option → score 1 (a `None` option is neither required nor forbidden); selecting only the `None`
  option → score 0.
- Question with **no** option marked `correct=True` at all (including `short_text`/`long_text`, which
  have no options) → score 0. *This is the regression guard against the naive set-equality rule
  scoring an unanswerable question correct.*
- The three existing `multiple_choice` cases still behave identically.
- For every case above, assert `get_incorrect_quiz_answers()` agrees with `score_quiz()`: the question
  appears in the incorrect list **iff** it did not contribute to the score.

## Task 1.2 — One shared correctness predicate

In `freedom_ls/student_progress/models.py`, add a module-level predicate above `FormProgress` and make
`score_quiz()` and `get_incorrect_quiz_answers()` both call it. This is the only place the rule lives.

```python
def is_quiz_answer_correct(
    selected_option_ids: set[UUID], options: Iterable[QuestionOption]
) -> bool:
    """Exact-match scoring: every correct option selected, no incorrect one.

    `QuestionOption.correct` is nullable. `True` is required, `False` is forbidden,
    `None` is neither — an option nobody marked up is not evidence either way.
    A question with no correct option cannot be answered correctly; that keeps
    free-text questions (which have no options at all) scoring zero, as they do today.
    """
    required = {o.id for o in options if o.correct is True}
    forbidden = {o.id for o in options if o.correct is False}
    if not required:
        return False
    return required <= selected_option_ids and not (selected_option_ids & forbidden)
```

Then:

- `score_quiz()` (`models.py:419-455`) — replace the
  `for option in selected_options: if option.correct: score += 1; break` block with a call to the
  predicate. `max_score` semantics are untouched: every `FormQuestion` still counts 1.
- `get_incorrect_quiz_answers()` (`models.py:~505`) — replace
  `is_correct = any(option.correct for option in selected_options)` with the same call.

Both call sites already have the question's options in hand via `question.options` /
`answer.selected_options`; pass `question.options.all()` as `options` and the selected ids as a set.

**Behaviour change to be explicit about:** a `multiple_choice` question authored with more than one
`correct=True` option becomes unanswerable under exact match, because the UI only ever submits one
option. Spec §14 asserts single-select MC is unaffected, which holds for the normal one-correct case.
Task 1.4 audits for the abnormal case.

overridable — it is an anonymity floor, and a setting would be a one-line way to weaken it without
understanding what the number protects. Promoting a constant to a setting later is
backwards-compatible; withdrawing a setting is not.

## Task 2.5 — Deletion hygiene (spec §12.4)

Django does not delete files on row delete, and a cascade from `Cohort` never calls the instance's
`delete()`. Both paths — admin single delete, admin bulk-delete action, and cohort cascade — go
through Django's collector, which **does** send `post_delete` for every collected instance as long as
a receiver is connected. So one receiver covers all three; do not also override `Model.delete()` (that
would double up on one path and still miss the others).

In `models.py`:

```python
@receiver(post_delete, sender=GeneratedReport)
def delete_report_file(
    sender: type[GeneratedReport], instance: GeneratedReport, **kwargs: object
) -> None:
    """Storage does not follow the row. An orphaned PDF is PII left behind."""
    if instance.file:
        instance.file.delete(save=False)
```

Connect it in `apps.py:ready()` if you prefer explicit wiring, or leave the decorator in `models.py`
(both are used in the repo; `models.py` keeps it next to the field it protects).

Spec §12.4 prefers file-then-row ordering so a crash leaves an orphaned file rather than a row
pointing at nothing. `post_delete` inverts that, but the failure mode is the same shape: a crash in
the receiver leaves an orphaned file with the row already gone. The download view must defend against
a missing file anyway (Task 5.3), so this is the correct trade.

Add a TODO next to the receiver recording the deferred retention/expiry decision (spec §12.4). Do not
remove it later without implementing retention.

**Tests (first):**
- Delete a `GeneratedReport` through the ORM → the file is gone from storage.
- Delete via `QuerySet.delete()` (what the admin bulk action does) → file gone.
- **Delete the `Cohort`** → its reports' rows *and* files are both gone. This is the test spec §12.4
  explicitly asks for.

## Task 2.7 — Isolate report storage in tests (do this before any test writes a file)

Without this, every test that saves a report file writes a real PDF into the developer's live `media/`
directory, permanently, on every run — and `pytest-randomly`/`pytest-xdist` multiply it. `STORAGES` is
defined **only** in `config/settings_prod.py:136-141`, and has no `"reports"` key even there; under
`settings_base` / `settings_dev` (which the test suite uses) there is no `STORAGES` at all, so
`get_reports_storage()` falls through to Django's default `FileSystemStorage` rooted at
`MEDIA_ROOT = BASE_DIR / "media"` (`config/settings_base.py:254-255`). This is the first `FileField` in
FLS any test actually writes to, so there is no existing fixture to inherit.

Add an autouse fixture in `freedom_ls/reports/tests/conftest.py`:

```python
@pytest.fixture(autouse=True)
def isolated_reports_storage(tmp_path, settings) -> None:
    """Report files go to tmp_path, never the developer's real media/ directory."""
    settings.STORAGES = {
        **settings.STORAGES,
        "reports": {
            "BACKEND": "django.core.files.storage.FileSystemStorage",
            "OPTIONS": {"location": str(tmp_path)},
        },
    }
```

`REPORTS_STORAGE_ALIAS` already defaults to `"reports"`, so this alone redirects the storage.

**Do not fix this by adding a permanent `"reports"` alias to `config/settings_dev.py`.** That would
quiet the tests while leaving real dev-server usage still falling back to a publicly served
`MEDIA_ROOT` — which is precisely what the W001 check in Task 2.4 exists to warn about.

# Phase 3 — At-risk rule registry (spec §8)

## Task 3.1 — Rule protocol and rules

`freedom_ls/reports/at_risk.py`.

A rule is a small object with `id: str`, `label: str`, `severity: str`, and
`evaluate(student) -> str | None`. Define the shape as a `typing.Protocol` (not an ABC — CLAUDE.md: no
abstract base classes unless asked), and implement the three v1 rules as plain classes taking their
thresholds as constructor parameters.

```python
class AtRiskRule(Protocol):
    id: str
    label: str
    severity: str

    def evaluate(self, student: "StudentDetail") -> str | None: ...


class NoRecordedActivityRule:
    id = "no_activity"
    label = "No recorded activity"

    def evaluate(self, student: StudentDetail) -> str | None:
        if student.has_any_progress:
            return None
        return "Has not started any course item."


class FailedLatestQuizAttemptRule:
    id = "failed_latest_quiz"
    label = "Failed most recent quiz attempt"
    # A quiz with quiz_pass_percentage unset yields passed=None: no pass mark,
    # no verdict, no flag.

class InactiveForDaysRule:
    def __init__(self, days: int = 7) -> None: ...
    id = "inactive"
    label = "No activity recently"
    # Measured from the most recent completion timestamp; a student with no
    # timestamps at all is covered by NoRecordedActivityRule, not this one.

AT_RISK_RULES: list[AtRiskRule] = [
    NoRecordedActivityRule(),
    FailedLatestQuizAttemptRule(),
    InactiveForDaysRule(days=7),
]
```

**Rules must not query.** `evaluate()` receives the already-gathered `StudentDetail` and returns a
reason string. Everything a v1 rule needs — `has_any_progress`, `last_activity_at`, `quiz_results` —
is a plain value on the dataclass (Task 4.1). The `InactiveForDaysRule` compares against a `now`
carried on the report data, not `timezone.now()` called inside the rule, so the whole report is
evaluated against one consistent instant and the rule stays trivially testable.

**Tests (first):** each rule at its threshold boundaries — exactly 7 days vs 8; a null
`quiz_pass_percentage` producing no flag; a student who trips two rules producing two reasons. Use
`time-machine` for the day-threshold cases.

## Task 3.2 — Loader

Withdrawn. This task built a `functools.cache`d loader resolving
`REPORTS_AT_RISK_RULES_MODULE` into the rule list, so a downstream project could supply its own
rules module without forking. It shipped and was then removed: the indirection cost a
`.cache_clear()` discipline in every test that overrode the setting, a two-name export contract,

impersonating a downstream project — all to save one `import_module` call. `AT_RISK_RULES` in
`freedom_ls/reports/at_risk.py` is the registry, read directly by the gather layer.

## Task 4.2 — `gather_cohort_report_data(cohort_id: str, site_id: int) -> CohortReportData`

**Every query filters explicitly on `site_id=site_id`.** There is no request in a background task, so
`SiteAwareManager` returns everything unfiltered with no warning
(`site_aware_models/models.py:43-50`). Follow `webhooks/events.py:66-70`.

Structure, in order — collect id lists once, then a fixed number of batched queries. **No query inside
any per-student or per-question loop.**

```
1.  cohort            = Cohort.objects.get(pk=cohort_id, site_id=site_id)
2.  registrations     = CohortCourseRegistration.objects.filter(
                            cohort=cohort, site_id=site_id
                        ).select_related("collection").order_by("-is_active", "collection__title")
                        # inactive registrations included and marked, not filtered out
3.  memberships       = CohortMembership.objects.filter(
                            cohort=cohort, site_id=site_id
                        ).select_related("user")
    -> student_ids, and if len(student_ids) > config.REPORTS_MAX_STUDENTS: raise ReportTooLarge
4.  per course: items = course.viewable_items()   # one children() prefetch per course
    -> topic_ids, form_ids; quiz_form_ids = forms with strategy == QUIZ
       (viewable_items() already excludes CoursePart; Activities are excluded here
        per spec §13 and are therefore out of the completion denominator too)
5.  topic_progress    = TopicProgress.objects.filter(
                            site_id=site_id, user_id__in=student_ids, topic_id__in=topic_ids,
                        ).values_list("user_id", "topic_id", "complete_time")
6.  form_progress     = FormProgress.objects.filter(
                            site_id=site_id, user_id__in=student_ids, form_id__in=form_ids,
                        ).order_by(F("completed_time").desc(nulls_last=True), "-start_time")
    -> latest-per-(user, form) = first row seen; completed_count incremented when
       completed_time is not None.  Exactly the proven shape at
       educator_interface/views.py:366-382, batched cohort-wide instead of 20 at a time.
7.  first_attempts    = FormProgress.objects.filter(
                            site_id=site_id, user_id__in=student_ids,
                            form_id__in=quiz_form_ids, completed_time__isnull=False,
                        ).annotate(
                            rank=Window(RowNumber(),
                                        partition_by=[F("user_id"), F("form_id")],
                                        order_by=F("start_time").asc())
                        ).filter(rank=1)
    -> first_attempt_ids   (filtering on a window annotation is supported from
       Django 4.2; FLS is on 6.x, so no manual subquery wrapping)
8.  questions         = FormQuestion.objects.filter(
                            site_id=site_id, form_page__form_id__in=quiz_form_ids,
                        ).select_related("form_page").prefetch_related("options"
                        ).order_by("form_page__order", "order")
    -> question_number computed in Python by enumerating within each form.
       DO NOT call FormQuestion.question_number() — it re-queries pages and
       questions per call (content_engine/models.py:523-538). Do not call
       FormPage.children() either; it merges two querysets in Python and is
       not prefetch-friendly (spec §13).
9.  answers           = QuestionAnswer.objects.filter(
                            site_id=site_id, form_progress_id__in=<all attempt ids>,
                        ).prefetch_related("selected_options")
    -> feed evaluate_quiz_answers() (Task 1.3) once for the whole cohort
10. distractors       = QuestionOption.objects.exclude(correct=True).filter(
                            site_id=site_id,
                            question_id__in=question_ids,
                            questionanswer__form_progress_id__in=first_attempt_ids,
                        ).values("question_id", "id", "text"
                        ).annotate(times_selected=Count("questionanswer")
                        ).order_by("question_id", "-times_selected")
    -> .exclude(correct=True), NEVER filter(correct=False): `correct` is nullable,
       and a correct=None option must be counted as a distractor (spec §6).
```

Then, in Python only:

- **`CourseSection.student_rows` is built from the full `student_ids` list, per course** — one row for
  every cohort member, not only for members who happen to have a progress row on that course. A
  student with no activity on Course X still gets a row on Course X's table at 0% with `—` cells.
  Building rows by iterating the progress maps instead of the membership list is the easy mistake that
  silently drops exactly the students the report most needs to show.
- **Completion percentage — recomputed, never read from `CourseProgress.progress_percentage`.**
  Denominator = count of `viewable_items()` filtered to `Topic` and `Form`. Numerator = completed
  `TopicProgress` (`complete_time` set) + completed `FormProgress` over those items. A student with no
  `CourseProgress` row is 0%, not omitted.

  `student_management/utils.py:calculate_course_progress_percentage(course, completed_topic_ids,
  completed_form_ids)` implements the same rule and is deliberately **not** called here: it returns
  only the percentage, while the report needs the completed/total counts too (they appear in the
  summary table next to the percentage), and it re-walks `course.children()` per student when gather
  already holds the flat item list from step 4. Pin the two implementations together with a test
  instead — assert gather's percentage equals `calculate_course_progress_percentage()` for the same
  student and course. That catches drift (a new content type counted by one and not the other) without
  a redundant tree walk. Note `viewable_items()` excludes only `CoursePart`, so the filter to `Topic`
  and `Form` is what excludes Activities; the utility gets the same result via its `content_type`
  `elif` chain.
- **Last item completed** = `max()` over `TopicProgress.complete_time` and
  `FormProgress.completed_time`. Never `CourseProgress.last_accessed_item` — that is last *viewed*.
- **Quiz score** = the latest attempt's stored `scores`, shown as-is. Wrap the derivation in the guard
  already proven at `educator_interface/views.py:485-494`:

  ```python
  percentage = passed = None
  if fp.completed_time and fp.scores:
      try:
          percentage = fp.quiz_percentage()
          passed = fp.passed() if form.quiz_pass_percentage is not None else None
      except (KeyError, ValueError):
          percentage = passed = None
  ```
  `quiz_percentage()` raises on falsy `scores`, `passed()` raises on a null `quiz_pass_percentage`,
  and `quiz_pass_percentage` is genuinely nullable (`content_engine/models.py:430-434`).
- **Per-student wrong answers counted per attempt** — three misses across three attempts is
  `times_wrong=3`. Do not collapse.
- **Cohort confusions** over **first attempts only**, ranked worst-first by error rate, capped at
  `CONFUSIONS_PER_QUIZ_MAX` with the shown/total counts carried on the dataclass for disclosure.
  `show_percentage` is `respondent_count >= MIN_RESPONDENTS_FOR_PERCENTAGE`.
- Free-text (`short_text` / `long_text`) questions are excluded from wrong-answer aggregation and the
  confusion tally entirely (spec §13).
- **At-risk flags are evaluated exactly once**, here, into `StudentDetail.flags`. The attention list
  is built by filtering and sorting *that same list* — it never re-evaluates. This is what makes
  success criterion 4 structurally true rather than a coincidence, and it means the render layer never
  imports the rule registry.
- Attention list: students with ≥1 flag, ordered worst-first by completion percentage, sliced to
  `ATTENTION_LIST_MAX`, with `shown` and `total` both carried.

**Tests (first):**

- Data shape end to end for a small cohort.
- Completion recomputation: a `CourseProgress.progress_percentage` deliberately set to a wrong value
  is ignored.
- Latest-vs-first attempt selection with three attempts at different times.
- Null `quiz_pass_percentage` → `passed is None`, no exception.
- Student with no `CourseProgress` row → present, 0%, `has_any_progress=False`.
- A student with zero progress on one course but activity on another → still has a `StudentRow` in
  *both* courses' `student_rows`, at 0% in the first.
- Inactive `CohortCourseRegistration` → its `CourseSection` present with `is_active=False`.
- A `correct=None` option selected by a student appears in the distractor tally (the
  `.exclude(correct=True)` guard).
- **Two-site isolation**: identical cohorts on site A and site B; gathering for A returns no student,
  progress row or option from B. Build the data with `mock_site_context`, but assert on gather's own
  explicit filtering — this is success criterion 10.
- **Query count**: `django_assert_num_queries` with a fixed bound; then re-run with 3× the students
  and 3× the questions and assert the same bound. This is success criterion 9 and the only real guard
  against the N+1 the design exists to avoid.

**Theme token extraction.** The compiled bundle's custom properties are the only WeasyPrint-readable
source of the role tokens (the theme source declares them inside a Tailwind v4 `@theme { }` at-rule
WeasyPrint cannot parse). Verified shape of `static/vendor/tailwind.output.css`:

```css
@layer theme {
  :root, :host {
    --color-success: #38A169;
    ...
  }
```

So the extractor must cope with the `@layer theme {` wrapper and with the selector being
`:root, :host`, not bare `:root`:

```python
def extract_theme_tokens() -> str:
    """Return the compiled bundle's leading custom-property block as a `:root { ... }` rule.

    A narrow read of one declaration block — not "feed WeasyPrint compiled Tailwind",
    which would drag in preflight and utilities that WeasyPrint mis-parses.
    """
    path = finders.find("vendor/tailwind.output.css")
    if path is None:
        raise ReportRenderError(
            "Compiled Tailwind bundle not found. Run `npm run tailwind_build`."
        )
    css = Path(path).read_text()
    start = css.index("{", css.index(":root"))
    depth, end = 0, None
    for i, char in enumerate(css[start:], start):
        if char == "{":
            depth += 1
        elif char == "}":
            depth -= 1
            if depth == 0:
                end = i
                break
    if end is None:
        raise ReportRenderError("Unbalanced braces in the compiled Tailwind bundle.")
    declarations = [
        line.strip()
        for line in css[start + 1 : end].splitlines()
        if line.strip().startswith("--")
    ]
    return ":root {\n" + "\n".join(declarations) + "\n}"
```

**The brace scan is not optional.** The target block is nested — the bundle opens
`@layer theme {` on one line and `:root, :host {` on the next, so a `split("}")[0]` or a regex up to
the first `}` terminates on the wrong brace and silently returns a truncated or empty token set. Walk
the braces and match depth. Filtering to lines starting with `--` also drops any nested at-rule that
might appear inside the block in a future Tailwind version.

Resolve **every** asset (`print.css`, the bundled font, the bundle above) through
`django.contrib.staticfiles.finders.find()`. **Never `settings.STATIC_ROOT`** — it is set only in
`config/settings_prod.py:86`, and the test suite runs on `config.settings_dev`, so a `STATIC_ROOT`-keyed
render would pass in production and fail in CI. Finders search `STATICFILES_DIRS` and app static dirs
in dev and fall through to collected storage in production: one path, all three environments.

**Restrictive URL fetcher.** The report renders author-supplied question and option text; WeasyPrint's
default fetcher will follow `http(s)://` and `file://` URLs it finds there, which is an SSRF and
local-file-read surface. Spec §9 names `weasyprint.urls.URLFetcher(allowed_protocols=[],
allow_redirects=False)`. **Check that class and signature against the version actually installed
before using it** — `url_fetcher=` has always accepted a plain callable, so if the class is absent or
shaped differently, implement the callable form instead:

```python
def restrictive_url_fetcher(url: str) -> dict[str, object]:
    """Any URL in the document body is a network or filesystem read we did not ask for."""
    raise ReportRenderError(f"External resource fetch refused: {url}")
```

Either way the requirement is the same: anything the document references raises, turning a silent
network call into a loud render failure that marks the report `failed`. Add `data:` to the allowed set
only if inline base64 assets are actually used. The test suite runs with `--disable-socket`, which
independently proves no fetch happens.

Call WeasyPrint as `weasyprint.HTML(string=html, base_url=<resolved static dir>,
url_fetcher=...).write_pdf()`.

Raise a module-level `ReportRenderError` for every render-time failure so `tasks.py` has one thing to
catch.

**Tests (first):**
- Extraction contract, asserted against a **controlled input CSS string** that mimics the bundle's
  real shape (`@layer theme { :root, :host { --color-success: #38A169; ... } }` plus a following
  `@layer utilities` block): the returned rule contains the custom properties and none of the
  utilities. Do **not** read the repo's real bundle and assert today's hex values — that is asserting
  a hardcoded config value through the code under test.
- One separate integration-flavoured test that the *real* bundle yields every role token the report
  uses (`success`, `warning`, `error`, `info`, their `-light` tints and `on-*-light` foregrounds,
  `surface`, `muted`) — asserting **presence of the names**, not their values. All of these are

  a token defined via `color-mix()` is not safe without first confirming WeasyPrint supports it.
- A missing/unresolvable bundle raises `ReportRenderError` rather than degrading to an uncoloured PDF.
- `build_report_html()` content assertions (Task 4.5) — no WeasyPrint call.

## Task 4.4 — Print stylesheet and font

`freedom_ls/reports/static/reports/print.css` — small and hand-authored. **Do not feed WeasyPrint the
compiled Tailwind bundle**, and do not use Tailwind utility classes in the report templates.

One stylesheet, but organised to match Task 4.5's file split: the page/`@page` rules and the shared
leaf rules (`.completion-bar`, `.flag-list`, `.quiz-cell`, `.cap-disclosure`) first, then one
comment-delimited block per section partial, in the same order as the includes in `report.html`. Each
section partial has a single root element carrying its own class (`.title-page`, `.at-a-glance`,
`.contents`, `.methodology`, `.summary-tables`, `.student-details`, `.confusions`) and every rule in a
section's block is scoped under that class, so a section's styling can be read, changed or dropped
without tracing what else it touches.

Colours come only from the role tokens inlined by Task 4.3 — `var(--color-success)` etc. No hex
values, no brand colour names. The available token vocabulary is fixed: `primary`, `secondary`,
`accent`, `success`, `warning`, `error`, `info` (each with an `on-*` partner), the
`success-light`/`warning-light`/`error-light`/`info-light` tints with their `on-*-light` foregrounds,
and `surface`, `surface-2`, `on-surface`, `border`, `muted`, `focus-ring`. There is no `*-bold` series
in any FLS theme — do not invent one. **Do not use the marketing palette from the `brand-guidelines`
skill** (`ocean`, `midnight`, `chalk`, `sand`, `forest`, …): those are copy/marketing colour names,
not implemented design tokens, and using them here would reintroduce exactly the hardcoded colours
spec §10 forbids.

```css
@page { size: A4 portrait; margin: 20mm 15mm; }
@page landscape-table { size: A4 landscape; margin: 15mm; }
.landscape-section { page: landscape-table; }

thead { display: table-header-group; }
tr { break-inside: avoid; }
.student-section { break-before: page; }
.student-section:first-of-type { break-before: avoid; }
```

`page` is inherited, so putting `.landscape-section` on the wrapping element covers every page its
content flows onto. The summary tables must **not** sit inside a container with `overflow: hidden` or
a fixed height, or they will not break across pages.

Running headers, page numbers, contents and bookmarks:

```css
@page {
    @top-center  { content: element(student-name); }
    @bottom-right { content: "Page " counter(page) " of " counter(pages); }
}

.student-section > .student-name { position: running(student-name); }

.toc a::after { content: target-counter(attr(href), page); }

h2.course-heading  { bookmark-level: 1; bookmark-label: content(); }
h3.student-heading { bookmark-level: 2; bookmark-label: content(); }
```

WeasyPrint keeps displaying the most recently declared running element until a new one is declared,
which is exactly "the current student's name stays in the header until the next student's section
starts" — no per-page logic in Python.

**Anchor id convention** (the contents page and the attention list's page references both resolve
through `target-counter(attr(href), page)`, so the ids must be predictable):

- course section: `id="course-{{ section.course_id }}"`
- student section: `id="student-{{ student.user_id }}"`
- confusion block: `id="confusions-{{ quiz.form_id }}"`

The attention list links to `#student-{{ student.user_id }}`; the contents page links to all three.
- Progress bars: nested divs (fixed-width outer, percentage-width inner) with role-token backgrounds.
  **No flexbox** — WeasyPrint's flexbox support is not deeply tested. Inline SVG is the fallback if
  rounded caps are needed.
- Alternate row banding on the wide summary tables.

**Font:** bundle DejaVu Sans under `freedom_ls/reports/static/reports/fonts/` and declare it with
`@font-face`. Permissive licence and it covers the §10 status glyphs. Do not rely on system fonts —
WeasyPrint substitutes silently for a missing family and renders a `.notdef` box for a missing code
point, both invisible until someone reads a printed report. Ship the licence file alongside it.

**Status glyphs (spec §10)** — plain Unicode, never emoji (a headless container may have no
colour-emoji font, and colour glyphs desaturate unpredictably, defeating the greyscale requirement):
complete/on-track `✓` U+2713, failing/not-started `✗` U+2717, warning/borderline `▲` U+25B2, in
progress `●` U+25CF, started-no-verdict `○` U+25CB, not applicable `—`. Every status cell carries the
number *and* the glyph — colour is never the only signal.

Full table cells use `*-light` tints with their paired `on-*-light` foregrounds; solid role fills with
`on-*` foregrounds are reserved for small badges.

`freedom_ls/reports/templates/reports/report.html` plus **one file per section**, and one file per

  Task 4.2. The same-string test in this task then guards the include, not two hand-kept copies.
- **`cap_disclosure.html` is the only place a "shown of total" sentence is written.** The attention
  list and every confusion block route through it, so the disclosure cannot be present in one place
  and forgotten in another.
- **Each anchor id is emitted by exactly one partial** — course ids in `course_summary_table.html`,

- **No partial computes.** Every number, ordering, cap and boolean is already on the dataclasses from

  have is a gap in `gather()`, not a reason to derive it here.

Content rules the templates must honour:

- **Methodology block** states, in plain language: what "complete" means and that it is recomputed

- Caps are always disclosed: "showing worst 10 of 23 questions with at least one incorrect answer".

- Always show the correct option alongside the wrong ones, so each table stands alone.

## Task 4.6 — PDF integration tests

A deliberately small set, marked `@pytest.mark.weasyprint` (Task 6.1), asserting only what a PDF can
prove — use `pypdf`:

- The output is a well-formed PDF.
- The summary section's page is landscape (`mediabox.width > mediabox.height`) and other pages are
  portrait.
- The bundled font is actually embedded — so a missing font fails loudly in CI instead of silently
  substituting.
- **The embedded font actually covers the six status code points** (`✓` U+2713, `✗` U+2717, `▲`
  U+25B2, `●` U+25CF, `○` U+25CB, `—` U+2014) — inspect the font's cmap. "A font is embedded" and
  "this font can draw these glyphs" are different claims, and a subset font can satisfy the first
  while rendering `.notdef` boxes for the second. This is the automated half of the greyscale
  requirement; the printed check is the other half.
- **The PDF has a non-empty outline** (`pypdf`'s `.outline`) whose entries match the document's
  sections — proving `bookmark-level` / `bookmark-label` produced a real outline rather than silently
  doing nothing.
- **Table-of-contents page references resolved** — extracted text around the contents entries carries
  numeric page references that are present and non-decreasing, proving
  `target-counter(attr(href), page)` resolved rather than emitting blanks.
- The cohort name appears in extracted text. Treat `extract_text()` as a smoke test only; it has known
  spacing artefacts.

Header-row repetition across page breaks is not reliably provable through `pypdf`; it stays a
code-review and visual check.

**Never assert exact PDF bytes** — fonts, timestamps and library versions make output
non-reproducible. No visual snapshot diffing in the core suite.

## Task 5.1 — `tasks.py`

Mirror `webhooks/events.py:42-89`: a thin `@task()` wrapper delegating to a plain function taking
primitive, JSON-safe ids.

```python
@task()
def _generate_cohort_report_task(report_id: str, site_id: int) -> None:
    generate_cohort_report(report_id, site_id)


def generate_cohort_report(report_id: str, site_id: int) -> None:
    report = GeneratedReport.objects.filter(pk=report_id, site_id=site_id).first()
    if report is None:
        return
    report.status = RUNNING; report.started_at = timezone.now(); report.save(...)
    try:
        data = gather_cohort_report_data(str(report.cohort_id), site_id)
        pdf = render_report_pdf(data)
        report.file.save("cohort-report.pdf", ContentFile(pdf), save=False)
        report.status = READY
        report.error_message = ""
    except (ReportRenderError, ReportTooLarge, Cohort.DoesNotExist) as exc:
        report.status = FAILED
        report.error_message = str(exc)
    finally:
        if report.status == GeneratedReport.STATUS_RUNNING:
            report.status = GeneratedReport.STATUS_FAILED
            report.error_message = (
                report.error_message or "Unexpected error during report generation."
            )
        report.finished_at = timezone.now()
        report.save(update_fields=["status", "error_message", "finished_at"])
```

**The status check inside `finally` is load-bearing — do not drop it.** The `except` tuple is
deliberately narrow (CLAUDE.md forbids blanket `except Exception`), so anything outside it — a
`TypeError` from a bug in the gather layer, an `OSError` or storage-backend error from `file.save()`,
a database `OperationalError` — propagates straight through. `finally` still runs, but without the
status check it would stamp `finished_at` and leave `status` at `running` forever, and the partial
unique index would then block that cohort from ever generating another report. The gather layer is the
largest and most query-heavy piece of new code in the feature, so this is not a hypothetical path.
Setting `failed` here also preserves the specific `error_message` when the `except` clause already set
one, and supplies a generic message when it did not. The exception still re-raises after `finally`, so
the worker's own error reporting is unaffected.

**Tests (first)** — all of these run under the isolated storage fixture from Task 2.7. The file write
happens inside `generate_cohort_report()` whether or not `render_report_pdf()` is mocked, so mocking
the renderer does **not** avoid the real-`media/` problem on its own.

Happy path leaves `ready` with a non-empty file; a mocked render raising leaves
`failed` with a readable `error_message`, `finished_at` set, and the cohort immediately re-generatable
(success criterion 13); a cohort over `config.REPORTS_MAX_STUDENTS` — asserted with the setting
overridden to a small value, not by building 500 students — leaves the row `failed` with a message
naming the limit; an unexpected exception type still leaves the row `failed`, never `running`; the
task filters on `site_id` and does nothing for a report on another site.

`admin_view()` only guarantees staff status — the object-level check is separate and mandatory. The

Creation:

```python
try:
    with transaction.atomic():
        report = GeneratedReport.objects.create(
            cohort=cohort, site_id=cohort.site_id, requested_by=request.user
        )
        transaction.on_commit(
            lambda: default_task_backend.enqueue(
                _generate_cohort_report_task,
                args=[str(report.pk), cohort.site_id],
                kwargs={},
            )
        )
except IntegrityError:
    messages.info(request, "A report for this cohort is already being generated.")
```

- **`site_id=cohort.site_id` is a deliberate exception** to the multi-tenant rule that `site_id`
  auto-populates from the request and is never set by hand. Setting it explicitly guarantees
  `report.site_id == cohort.site_id` — the exact value the enqueued task then filters every one of its
  queries on — independent of ambient thread-local state. Say so in a comment at the call site.
- Keep a friendly `.exists()` pre-check for the common case, but the `IntegrityError` catch is the
  actual guard — a check-then-act pre-check loses a genuine race, the partial unique index does not.
- **`transaction.on_commit` is required.** There is no correct precedent in the repo:
  `fire_webhook_event` enqueues immediately after `create()`, which is a live bug there. Without
  `on_commit`, `ImmediateBackend` (dev/test) or a fast worker can start before the row is visible.
  Note for tests: `pytest.mark.django_db` wraps each test in a transaction that never commits, so use
  `django_capture_on_commit_callbacks(execute=True)` in tests that need the task to actually run.
- Redirect back to the changelist with a success message either way.

Also a GET view rendering the form (cohort dropdown + submit), template
`freedom_ls/reports/templates/admin/reports/generate_form.html`, following
`webhooks/templates/admin/webhooks/send_test_form.html`.

**Tests (first):** a user without `view_cohort` on the target cohort gets 403/404 and no row is
created; a user with it gets a `pending` row; **two simultaneous requests produce exactly one report**

## Task 5.3 — `views.py` — download view

```python
def download_report_view(request: HttpRequest, object_id: str) -> HttpResponse:
    report = get_object_or_404(
        GeneratedReport.objects.select_related("cohort"), pk=object_id
    )
    if not request.user.has_perm(
        "freedom_ls_student_management.view_cohort", report.cohort
    ):
        raise PermissionDenied
    if report.status != GeneratedReport.STATUS_READY or not report.file:
        raise Http404
    filename = f"{slugify(report.cohort.name)}-progress-report.pdf"
    response = FileResponse(report.file.open("rb"), as_attachment=True, filename=filename)
    response["Cache-Control"] = "private, no-store, must-revalidate"
    return response
```

- The same object-level permission `educator_interface` already uses, resolved by django-guardian. No
  report-specific permission is invented. Call shape per `panel_framework/actions.py:208-214`.
- `FileResponse` streams in chunks and handles RFC 5987 filename encoding — do not hand-roll the
  header. `no-store` keeps a PII-bearing document out of shared and browser disk caches.
- `X-Accel-Redirect` / `X-Sendfile` are explicitly **not** v1 — nginx/Apache-specific, and FLS installs
  into projects behind neither.
- **`{{ report.file.url }}` must never appear in any template.** Note
  `content_engine/templates/cotton/file-download.html:17` does exactly this — it is the anti-pattern,
  not the precedent.

**Tests (first):** a user without `view_cohort` on that cohort gets 403; an anonymous user is
redirected to admin login; a `pending` report 404s; the success response is an attachment carrying the
`no-store` header; a row whose file is missing from storage 404s rather than 500s.

## Deliberate deviations from skills and conventions, recorded so a reviewer does not read them as mistakes

1. **`ds:frontend-styling` says "use Tailwind utility classes exclusively — no custom CSS unless
   absolutely necessary."** This feature is that exception: WeasyPrint cannot consume the compiled
   Tailwind bundle (it produces ignored and invalid CSS), so `print.css` is hand-authored. The
   skill's underlying discipline still binds — never invent a token, use only the real role tokens.
2. **`ds:template` / `fls-dev:template` assume a page template extending the site base with cotton
   components.** The print templates extend nothing and use no cotton, because they are never served
   to a browser. What carries over is the path convention — app-local `templates/reports/` for the
   document, `templates/reports/partials/` for the sections (Task 4.5). The skill's `{% partialdef %}`
   option is deliberately not used: sections are separate files so each can be styled, tested and
   overridden by a downstream project on its own.
3. **CLAUDE.md says "every app must define `app_name` in its `urls.py`."** `freedom_ls/reports` has no
   `urls.py` at all, so no `app_name`. That rule binds apps owning public routes; this one owns none,
   and an empty `urls.py` would create exactly the public URL surface the access-control design exists
   to deny (spec §4). `webhooks` is the existing precedent — it has no `urls.py` either.
4. **`fls-dev:multi-tenant` says `site_id` auto-populates from the request and is never set by hand.**
   Task 5.2 sets it explicitly on the `GeneratedReport` it creates, for the reason given there.
