# Plan: users are deactivated, not deleted, and superusers force delete with a reason

Spec: `1. spec.md` in this directory. Research: `research_codebase.md`, `research_user_deletion.md`.
TDD throughout: each slice starts with a failing test for its behaviour, then the code.

## Where things live, and why

`accounts` and `learner_management` sit below `learner_progress` (`docs/app_structure.md`), and
`course_applications` sits above it through `course_access`. Force delete needs `User`, `Learner`,
`CourseProgress`, `CourseFormAttempt` and `FormProgress` in one place, so it lives in
`learner_progress`:

| Piece | File |
| --- | --- |
| Collection, blocking check, delete order, audit entries | `freedom_ls/learner_progress/force_delete.py` (new) |
| Reason form, admin mixin, confirmation view | `freedom_ls/learner_progress/force_delete_admin.py` (new) |
| Confirmation page | `freedom_ls/learner_progress/templates/admin/learner_progress/force_delete_confirm.html` (new) |
| `UserAdmin` subclass with force delete, read-only `LearnerAdmin` | `freedom_ls/learner_progress/admin.py` |
| `USER_ERASURE_CASCADE_MODELS`, `USER_ERASURE_UNLINKED_RECORDS`, `UserAdmin` without delete | `freedom_ls/accounts/admin.py` |

One new runtime edge: `learner_progress → audit_log` (`record_entry`, `REASON_LENGTH`,
`acting_user`). It makes no cycle: `audit_log` reaches only `accounts`, `base`, `organisations` and
`site_aware_models`. `acting_user` moves from `freedom_ls/api_admin/audit.py` to
`freedom_ls/audit_log/writer.py` so `learner_progress` does not depend on `api_admin`
(`api_admin → audit_log` already exists). `learner_progress` never imports `course_applications`;
it reads `USER_ERASURE_UNLINKED_RECORDS` instead.

Tests follow the import contracts in `test_organisation/import_contracts.toml`: an app's tests import
only apps it depends on at runtime. So `learner_progress` tests build only `accounts`,
`learner_management`, `form_engine`, `learner_progress` and `audit_log` rows; the deadline rows, the
applicant rows and the educator audit log view are tested from `deadlines`, `course_applications`
and `educator_interface`, which depend on `learner_progress`.

**Site scoping.** The view loads targets only through the admin's `get_queryset(request)`, which the
site-aware manager filters to the host's site. Everything inside the transaction then reads through
`_base_manager`, bounded by those site-scoped primary keys or by rows reached from them: the default
manager filters on the request's site, which a cascade or a lock query must not depend on.

5. **Collection and blocking** (`freedom_ls/learner_progress/force_delete.py`). One function both
   the page and the delete call, so they agree:

   ```python
   @dataclass(frozen=True)
   class ForceDeletePlan:
       objects: dict[type[Model], set[Model]]   # every row that goes, each once
       blocking_models: tuple[str, ...]         # verbose names of models that stop the delete

       def counts(self) -> dict[str, int]: ...  # verbose_name_plural -> count, sorted by name;
                                                # auto-created M2M join models left out (listing() too)
       @property
       def can_run(self) -> bool: return not self.blocking_models

   def build_plan(*, targets: Sequence[Model], progress_roots: Sequence[Model],
                  request: HttpRequest, admin_site: AdminSite) -> ForceDeletePlan:
       """Two collections, because collection stops at a PROTECT edge: one
       from the course progress records, one from the targets."""
       using = router.db_for_write(type(targets[0]))   # targets is never empty: the view 404s first
       progress = _collect(progress_roots, using)
       target = _collect(targets, using)
       objects = union of progress.model_objs and target.model_objs, per model
       held = every object in progress.model_objs
       leftover = [obj for obj in target.protected if obj not in held] + list(progress.protected)
       blocking = tuple(sorted(verbose names of:
           - each leftover object's model, and
           - each model in `objects` that is not the target model and not in
             USER_ERASURE_CASCADE_MODELS, whose registered admin refuses
             has_delete_permission(request, obj) for any of its objects)))
       return ForceDeletePlan(objects, blocking)

   def _collect(roots: Sequence[Model], using: str) -> NestedObjects:
       collector = NestedObjects(using=using)
       collector.collect(roots)
       return collector
   ```

   `progress_roots` for a user is `CourseProgress._base_manager.filter(learner__user__in=users)`;
   slice 3 adds the tests for that branch. Test the blocking rule here with
   `monkeypatch.setattr` on `USER_ERASURE_CASCADE_MODELS` to a set without `LegalConsent`, for a user
   holding a `LegalConsent`. (Swapping a module-level setting-like value is configuration, not a mock
   of project behaviour.)

6. **Delete** (same module):

   ```python
   class ForceDeleteBlocked(Exception):
       def __init__(self, blocking_models: tuple[str, ...]) -> None:
           super().__init__(", ".join(blocking_models))
           self.blocking_models = blocking_models

   def force_delete_users(users: Sequence[User], *, actor: User, reason: str,
                          request: HttpRequest, admin_site: AdminSite) -> int:
       with transaction.atomic():
           locked = list(User._base_manager.filter(pk__in=[u.pk for u in users]).select_for_update())
           progress = CourseProgress._base_manager.filter(learner__user__in=locked)
           plan = build_plan(targets=locked, progress_roots=list(progress), request=request, admin_site=admin_site)
           if not plan.can_run:
               raise ForceDeleteBlocked(plan.blocking_models)
           for user in locked:
               record_entry(action="user.deleted", actor=actor, target=user,
                            target_label=user.display_name, organisation=None,
                            reason=reason, details={"counts": <this user's counts>})
           # CourseProgress.learner is PROTECT, so the progress records go first.
           progress.delete()
           User._base_manager.filter(pk__in=[u.pk for u in locked]).delete()
       return len(locked)
   ```

   Per-user counts: `build_plan` for that one user (an admin selection is small). The aggregate plan
   decides `can_run`. The admin `LogEntry` is not written.

7. **Admin mixin and view** (`freedom_ls/learner_progress/force_delete_admin.py`), users only in this
   slice:

   ```python
   class ForceDeleteForm(forms.Form):
       # CharField strips by default, so whitespace only fails `required`.
       reason = forms.CharField(max_length=REASON_LENGTH, widget=UnfoldAdminTextareaWidget)

   class ForceDeleteAdminMixin:
       def has_force_delete_permission(self, request: HttpRequest, obj: object | None = None) -> bool:
           # Unfold passes an object_id string for detail actions; the stock
           # action list passes nothing. Neither matters: only superusers.
           return request.user.is_superuser

       def get_urls(self) -> list[URLPattern]:
           # Before the stock patterns, or <path:object_id>/ swallows it.
           custom = [path("force-delete/", self.admin_site.admin_view(self.force_delete_view),
                          name="freedom_ls_accounts_user_force_delete")]
           return custom + list(super().get_urls())

       @unfold_action(description="Force delete", url_path="force-delete-one",
                      permissions=["force_delete"], variant=ActionVariant.DANGER)
       def force_delete_one(self, request: HttpRequest, object_id: str) -> HttpResponseRedirect: ...

       def force_delete_view(self, request: HttpRequest) -> HttpResponse:
           # admin_view supplies login and CSRF; the permission is checked
           # here because this URL can be typed by hand.
           if not self.has_force_delete_permission(request):
               raise PermissionDenied
           objs = list(self.get_queryset(request).filter(pk__in=ids_from(request, self.model)))
           if not objs:
               raise Http404
           plan = build_plan(...)
           form = ForceDeleteForm(request.POST or None)
           if request.method == "POST" and plan.can_run and form.is_valid():
               actor = acting_user(request)   # read before the delete: it may be the actor's own account
               try:
                   count = force_delete_users(objs, actor=actor, reason=form.cleaned_data["reason"], ...)
               except ForceDeleteBlocked as blocked:
                   -> re-render with blocked.blocking_models, status 422
               self.message_user(request, ngettext("Force deleted %(count)d user.", ...))
               return redirect(changelist url)
           return TemplateResponse(request, "admin/learner_progress/force_delete_confirm.html",
                                   {..., **admin_page_context(request, self, title)},
                                   status=422 if request.method == "POST" else 200)
   ```

   `ForceDeleteBlocked` covers a race between GET and POST: the page re-renders with the blocking
   models and nothing is deleted.

### Slice 6: `User.last_active` is written by signed-in requests

3. `freedom_ls/accounts/middleware.py`:

   ```python
   class LastActiveMiddleware:
       """Records when a signed-in person last used the site.

       Only session sign-ins reach here as a user: API keys authenticate inside
       the API view, after middleware, and set no request.user. At most one
       write per interval per user; update() runs no save(), so updated_at (the
       API's sync cursor) and post_save receivers stay still.
       """

       def __init__(self, get_response: Callable[[HttpRequest], HttpResponse]) -> None:
           self.get_response = get_response

       def __call__(self, request: HttpRequest) -> HttpResponse:
           user = getattr(request, "user", None)
           if user is not None and user.is_authenticated:
               now = timezone.now()
               cutoff = now - timedelta(seconds=config.LAST_ACTIVE_WRITE_SECONDS)
               if user.last_active is None or user.last_active < cutoff:
                   # The base manager: the request's site may not be set yet.
                   User._base_manager.filter(pk=user.pk).filter(
                       Q(last_active__isnull=True) | Q(last_active__lt=cutoff)
                   ).update(last_active=now)
                   user.last_active = now
           return self.get_response(request)
   ```

### Slice 7: existing users get a backfilled last active

**Behaviour:** after migrating, each user's `last_active` is the later of `last_login` and their
latest `CourseProgress.last_accessed_time`, or null when both are null.

**Builds on:** slice 6

**Touches:** `freedom_ls/learner_progress/migrations/`,
`freedom_ls/learner_progress/tests/test_migrations.py`

The backfill lives in `learner_progress`, which depends on `accounts`, not the reverse. Migration
`freedom_ls/learner_progress/migrations/0004_backfill_user_last_active.py`, depending on the latest
`learner_progress` migration (`0003_courseprogress_updated_at` today) and
`("freedom_ls_accounts", "0006_user_last_active")` (check both labels and names at implementation
time):

```python
def backfill_last_active(apps: Apps, schema_editor: BaseDatabaseSchemaEditor) -> None:
    User = apps.get_model("freedom_ls_accounts", "User")
    CourseProgress = apps.get_model("freedom_ls_learner_progress", "CourseProgress")
    latest_course_activity = (
        CourseProgress._base_manager.filter(learner__user=OuterRef("pk"))
        .order_by().values("learner__user")
        .annotate(latest=Max("last_accessed_time")).values("latest")
    )
    # PostgreSQL's GREATEST skips nulls, so one null side gives the other.
    User._base_manager.update(last_active=Greatest("last_login", Subquery(latest_course_activity)))

operations = [migrations.RunPython(backfill_last_active, migrations.RunPython.noop)]
```

**Tests** (in the existing `learner_progress/tests/test_migrations.py`, calling
`backfill_last_active` the way that file calls its migration): login later than course activity;
course activity later than login; only one present; neither (stays null); course progress in two
organisations takes the latest.
