# Plan: Articles

Implementation plan for `1. spec.md`. Every slice runs end to end, leaves the suite green, and is
committed on its own with `uv run git commit`. Tests are written first (TDD); the tests named under
each slice are the behaviours to pin, not an exhaustive list.

Not in this plan, because later SDD steps own them: the `fls-content` skill files, `docs/product/`,
`claude_plugins/fls-dev/resources/markdown_content.md`, `docs/how tos/landing-pages.md` and
`upgrade_notes.md`. The bundled offline validator under `claude_plugins/fls-content/validate/` is
code with tests and a success criterion, so it is in (slice 15).

## Conventions that bind every slice

- **Skills.** Load `fls-dev:testing` and `ds:testing` before writing any test, `fls-dev:template`
  and `ds:template` before any template, `fls-dev:frontend-styling` and `ds:frontend-styling` before
  styling a card, `fls-dev:multi-tenant` for anything that touches `site`, `ds:app-settings` and
  `fls-dev:app-settings` for `config.py` and `checks.py`, `ds:admin-interface` (unfold resource) and
  `fls-dev:admin-interface` for the admin, `fls-dev:markdown-content` for every cotton widget,
  `code-comments` before writing any comment, `domain-glossary` before naming anything, and
  `brand-guidelines` plus `unslop` for every string a person reads.
- **Tests mirror modules and respect dependency direction** (`ds:testing`): an app's tests import
  only apps it depends on at runtime (`docs/app_structure.md`). `blog` depends on `content_engine`;
  `content_engine` depends on neither `blog` nor `learner_interface`; `markdown_rendering` depends
  on `base` only. Every test touching a site-aware model takes `mock_site_context`. Factories only,
  never `.objects.create()`. `reverse()`, never hard-coded URLs. No CSS-class assertions; assert on
  what a reader sees or on structural facts. Absence assertions are paired with a positive assertion
  in the same scenario. Loader tests write content under `tmp_path`, never into the repo.
- **Optional app guard.** `freedom_ls/blog/tests/conftest.py` sets `collect_ignore_glob = ["test_*.py"]`
  when `app_not_installed("freedom_ls.blog")` (precedent `course_applications/tests/conftest.py`).
  A test outside `blog` that reverses a `blog:` URL is guarded with
  `pytest.mark.skipif(app_not_installed("freedom_ls.blog"), reason=...)`, or its module skips at
  import with `allow_module_level=True` when every test in it needs the blog. The helper is
  `freedom_ls.tests.app_guards.app_not_installed`.
- **Comments say why, never what**, and never cite the spec, the plan or a research file. Template
  comments use `{% comment %}…{% endcomment %}`, never `{# … #}`.
- **Model changes** end with `uv run manage.py makemigrations` then `uv run manage.py migrate`;
  never edit an existing migration.
- **Full suite** runs as `uv run pytest -n auto` with `run_in_background: true`; one run at a time.
- **Type hints** on every function, no `Any`, no `# type: ignore`, `X | None` syntax. New modules
  that annotate with their own classes start with `from __future__ import annotations`.
- **Tailwind.** `npm run tailwind_build` after any new utility class. Its output under
  `static/vendor/` is gitignored and never committed.
- **Vocabulary.** "article" in identifiers, never "post" or "page". Always "article card" / "course
  card". `index` and `article_detail` are the URL names. The spec says "blog app is not installed"
  for the degraded widget case; the plan uses the same words.

## Slice 1: A published article has a public page

**Behaviour.** An `Article` row exists, and `GET /articles/<slug>/` renders its title, subtitle and
body to a logged-out visitor. A hidden slug and an unknown slug both return the standard 404. An
article on another site returns 404.

**Why first.** It is the thinnest path through model, migration, app, URL, view and template, and
every later slice widens it. The model carries `author`, `show_date` and `show_author` from the
start, although slice 2 is their first reader, because adding them later would mean a second
migration and the project never edits an existing one.

### Changes

1. `freedom_ls/content_base/schema.py`: add `ARTICLE = "ARTICLE"` to `ContentType`.
2. `freedom_ls/content_engine/schema.py`: the minimum `Article` schema so `test_schema_registry.py`
   stays green (`SCHEMAS` parity):
   ```python
   class ArticleVisibility(StrEnum):
       PUBLISHED = "published"
       HIDDEN = "hidden"

   class Article(BaseContentModel, MarkdownContentModel, content_type=ContentType.ARTICLE):
       slug: str | None = None
       published_on: date
       author: str | None = None
       visibility: ArticleVisibility = ArticleVisibility.PUBLISHED
       show_date: bool | None = None
       show_author: bool | None = None
   ```
   Validators come in slice 7.
3. New `freedom_ls/content_engine/models/articles.py`, starting with
   `from __future__ import annotations` and `from typing import cast`, importing
   `from freedom_ls.content_base.schema import ContentType as SchemaContentTypes` as `topics.py`
   does:
   ```python
   class ArticleVisibility(models.TextChoices):
       PUBLISHED = "published", _("Published")
       HIDDEN = "hidden", _("Hidden")

   class ArticleQuerySet(models.QuerySet["Article"]):
       def published(self) -> ArticleQuerySet:
           return self.filter(visibility=ArticleVisibility.PUBLISHED)

   class ArticleManager(SiteAwareManager):
       # Hand-written pass-through, the way comms.NotificationManager does it,
       # because SiteAwareManager.from_queryset() is not a base mypy can resolve.
       _queryset_class = ArticleQuerySet
       def published(self) -> ArticleQuerySet:
           return cast("ArticleQuerySet", self.get_queryset()).published()

   class Article(TitledContent, MarkdownContent):
       CONTENT_TYPE = SchemaContentTypes.ARTICLE
       published_on = models.DateField()
       author = models.CharField(max_length=200, blank=True)
       visibility = models.CharField(max_length=20, choices=ArticleVisibility.choices, default=ArticleVisibility.PUBLISHED, db_index=True)
       show_date = models.BooleanField(null=True)
       show_author = models.BooleanField(null=True)
       objects = ArticleManager()

       class Meta:
           ordering = ["-published_on", "slug"]
           constraints = [models.UniqueConstraint(fields=["site", "slug"], name="unique_article_slug_per_site")]

       def get_absolute_url(self) -> str:
           return reverse("blog:article_detail", kwargs={"slug": self.slug})
   ```
   `shows_date` / `shows_author` come in slice 2.
4. `freedom_ls/content_engine/models/__init__.py`: import and re-export `Article`,
   `ArticleVisibility`; add both to `__all__`.
5. `uv run manage.py makemigrations freedom_ls_content_engine -n article` → `0006_article.py`,
   then `uv run manage.py migrate`.
6. `freedom_ls/content_engine/factories.py`: `ArticleFactory(SiteAwareFactory)` shaped like
   `TopicFactory`, plus `published_on = factory.LazyFunction(date.today)` and
   `visibility = ArticleVisibility.PUBLISHED`.
7. New app `freedom_ls/blog/`, laid out like `freedom_ls/meta_pixel/`:
   - `__init__.py`, `apps.py` (`BlogAppConfig`: `name = "freedom_ls.blog"`,
     `label = "freedom_ls_blog"`, `verbose_name = "Blog"`; `ready()` gains the `checks` import in
     slice 6).
   - `config.py`:
     ```python
     class BlogConfig(AppSettings):
         BLOG_URL_PREFIX: str
         declared_settings = {"BLOG_URL_PREFIX": Setting(default="articles")}
     config = BlogConfig()
     ```
   - `urls.py`: `app_name = "blog"`; `path("<slug:slug>/", views.article_detail, name="article_detail")`.
     The index route lands in slice 4.
   - `views.py`:
     ```python

         article = get_object_or_404(Article.objects.published(), slug=slug)
         return render(request, "blog/article_detail.html", {"article": article})
     ```
   - `templates/blog/article_detail.html`: extends `_base.html`; inside `<c-page width="narrow">`

   - `tests/__init__.py`, `tests/conftest.py` (the optional-app guard above).
8. `config/settings_base.py`: add `"freedom_ls.blog"` to `INSTALLED_APPS`.
9. `config/urls.py`: import `apps` from `django.apps` and `config as blog_config` from
   `freedom_ls.blog.config`. Build
   `_blog_urlpatterns = [path(f"{blog_config.BLOG_URL_PREFIX}/", include("freedom_ls.blog.urls"))] if apps.is_installed("freedom_ls.blog") else []`
   and splice `*_blog_urlpatterns` into `urlpatterns` before the `learner_interface` include at

## Slice 2: The byline honours per-article overrides and site-wide defaults

**Behaviour.** The article page shows a byline with the date (as `<time datetime="YYYY-MM-DD">`)
and the author, each only when allowed by `show_date` / `show_author`, falling back to
`ARTICLE_SHOW_DATE` / `ARTICLE_SHOW_AUTHOR`. An empty author never shows.

### Changes

1. `freedom_ls/content_engine/config.py`: add `ARTICLE_SHOW_DATE: bool` and
   `ARTICLE_SHOW_AUTHOR: bool` to `ContentEngineConfig`, both `Setting(default=True)`.
2. `models/articles.py`:
   ```python
   @property
   def shows_date(self) -> bool:
       return config.ARTICLE_SHOW_DATE if self.show_date is None else self.show_date

   @property
   def shows_author(self) -> bool:
       if not self.author:
           return False
       return config.ARTICLE_SHOW_AUTHOR if self.show_author is None else self.show_author
   ```
   Import `config` from `freedom_ls.content_engine.config`.
3. New `freedom_ls/content_engine/templates/cotton/article-byline.html`, the one place byline
   markup lives (the article page, the index in slice 4 and the article card in slice 11 all use
   it; `content_engine` owns it because `blog` templates may include `content_engine` components
   but not the reverse):
   ```django
   <c-vars article />
   {% if article.shows_date or article.shows_author %}
   <p class="text-sm text-muted">
       {% if article.shows_date %}<time datetime="{{ article.published_on|date:'Y-m-d' }}">{{ article.published_on|date }}</time>{% endif %}
       {% if article.shows_date and article.shows_author %}<span aria-hidden="true"> · </span>{% endif %}
       {% if article.shows_author %}<span>{{ article.author }}</span>{% endif %}
   </p>
   {% endif %}
   ```
   Not added to `MARKDOWN_ALLOWED_TAGS`: it is for templates, not authors.
4. `article_detail.html`: `<c-article-byline :article="article" />` under the title block.

### Tests

- `content_engine/tests/test_article_model.py`: `shows_date` / `shows_author` for override true,
  override false, override `None` with each setting value (`override_settings`), and empty author.
- `content_engine/tests/test_config.py`: the two settings default to `True` and read a project
  override.
- `blog/tests/test_views.py`: the byline shows `<time datetime=...>` and the author when allowed;

## Slice 6: The URL prefix is a checked setting

**Behaviour.** `BLOG_URL_PREFIX` is validated by a system check, and a changed prefix moves the
index, the article pages, the sitemap URLs and the robots line together. An empty setting means
"use the default", because `AppSettings` returns the declared default for `None` and `""`.

### Changes

1. `freedom_ls/blog/checks.py`, following `meta_pixel/checks.py`:
   ```python
   _PREFIX_PATTERN = re.compile(r"[a-z0-9-]+(/[a-z0-9-]+)*")

   @register()
   def check_blog_url_prefix(app_configs: Sequence[AppConfig] | None, **kwargs: object) -> list[Error]:
       from freedom_ls.blog.config import config
       prefix = config.BLOG_URL_PREFIX
       if _PREFIX_PATTERN.fullmatch(prefix):
           return []
       return [Error(f"BLOG_URL_PREFIX {prefix!r} is not a valid URL prefix.",
                     hint="Use lowercase letters, digits and hyphens, with single slashes between segments and none at either end, e.g. 'articles' or 'news/blog'.",
                     id="freedom_ls_blog.E001")]
   ```
   Module docstring lists E001 the way `meta_pixel/checks.py` lists W001.
2. `apps.py` `ready()`: `from freedom_ls.blog import checks  # noqa: F401`.
3. `blog/tests/conftest.py`: a `blog_url_prefix` fixture that returns a callable: it enters
   `override_settings(BLOG_URL_PREFIX=prefix)`, reloads `config.urls` and calls
   `clear_url_caches()`; on teardown it exits the override, reloads `config.urls` again and clears
   the caches, so the URLconf never leaks into another test (`pytest-randomly` is on).

### Tests

- `blog/tests/test_checks.py`: the check is registered; E001 for `"/articles"`, `"articles/"`,
  `"Art icles"`, `"News"`; no error for `"articles"` and `"news/blog"` (parametrize the two shapes
  separately).
- `blog/tests/test_seo_discoverability.py`: with `blog_url_prefix("news")`, `reverse("blog:index")`
  starts with `/news/`, and the sitemap article URLs and the robots allow line follow it.

## Slice 7: An article loads from the content repo

**Behaviour.** `content_save` validates an `ARTICLE` markdown file anywhere in the repo, derives a
slug when none is written, writes the uuid back, and a second load changes nothing.

### Changes

1. `freedom_ls/content_engine/schema.py`, beside `SLUG_PATTERN`: a stdlib `slugify(value: str) -> str`
   transcribing Django's (`unicodedata.normalize("NFKC")`, drop characters outside
   `[\w\s-]`, strip, lower, collapse `[-\s]+` to `-`). The module must import with no Django
   installed, which is why Django's own is not imported.
2. `Article` schema validators:
   - One `@model_validator(mode="after")`, shaped like the `CourseCategories` validators: when
     `slug` is `None`, set it to `slugify(file_path.stem)`, or `slugify(file_path.parent.name)` when
     the file is named `content.md`; then require `SLUG_PATTERN.fullmatch(slug)` on the result, so a
     derived slug that collapses to `""` is refused too. Errors name `self.file_path`.
   - `@field_validator("category", mode="before")` and `("image", mode="before")`: raise a clear
     `ValueError` ("'category' is not an article field …"), following `Course._category_is_retired`.
     A before-validator only runs when the key is present, so files that omit them are untouched.
   - `visibility`: `ArticleVisibility` has no `coming_soon`, so pydantic rejects it already; the
     test pins that the message names the two allowed values.
3. `content_save.py`:
   - `save_article(item, site, base_path)`:
     ```python
     return save_with_uuid(Article, item, site, base_path, derive_slug=False,
                           author=item.author or "", show_date=item.show_date, show_author=item.show_author)
     ```
     The three are passed as extra fields, which `save_with_uuid` applies after the dump, because
     the dump uses `exclude_none` and would otherwise leave a stale stored value when a key is
     removed from the file. (Slice 8 adds the collision refusal in front of this call.)
   - `save_content_to_db`: a new pass after the `ACTIVITY` pass:
     `for item in grouped.get(SchemaContentType.ARTICLE, []): save_article(item, site, path)`.
     Articles are not added to `content_by_path`, so an explicit `children:` entry naming one still
     fails as "not loaded".
4. `uv run manage.py makemigrations --check --dry-run` reports no changes.

### Tests

- `content_engine/tests/test_article_schema.py`: slug default from the stem and from the parent
  directory for `content.md`; a written bad slug and a derived empty slug are both rejected naming
  the file; `published_on` is required; `coming_soon`, `category` and `image` are rejected with the
  article message; `slugify` matches Django's `slugify` on a handful of inputs (parametrize)
  including `"1. My Article"` → `"1-my-article"`.
- `content_engine/tests/test_content_save_articles.py`, modelled on
  `test_content_save_course_categories.py` but writing under `tmp_path`: first load writes the uuid
  back and stores the fields; a second load is byte-identical and leaves one row.

  naming the owner; removing `author`, `show_date` and `show_author` clears them; an `ARTICLE` file

## Slice 10: `c-article-link` links to a published article

**Behaviour.** In any markdown body, `<c-article-link path="../other.md">text</c-article-link>`
renders a link to the target article when it is published and the blog app is installed; otherwise
the slot renders as plain text (or nothing when empty). The target's title is used only when the
slot is empty and the target is published.

### Changes

1. `freedom_ls/content_engine/templatetags/content_tags.py`, beside `get_content_by_path`:
   ```python
   @register.filter
   def get_published_article_by_path(file_path: str | None, content_instance: BaseContent) -> Article | None:
       file_path = (file_path or "").strip()
       if not file_path:
           return None
       final_path = content_instance.calculate_path_from_root(file_path)
       # Filter on the content's own site, not the thread-local one: body markdown
       # is also rendered where no request has pinned a site.
       return (ArticleQuerySet(model=Article)
               .filter(site_id=content_instance.site_id, file_path=final_path)
               .published().first())
   ```
   `ArticleQuerySet(model=Article)` rather than `Article._base_manager` so the `published()` rule is
   written once.

## Slice 12: `c-course-card` shows a course from any markdown

**Behaviour.** `<c-course-card path="../course/course.md" variant="row|compact">` renders a course
card: title, subtitle or description, compact price, difficulty, estimated duration and the access
badge, with one stretched title link to `learner_interface:course_detail`. Hidden or missing
courses render nothing; coming-soon courses render.

### Changes

1. New `freedom_ls/learner_interface/templatetags/course_card_tags.py`:
   ```python
   @register.filter
   def get_course_by_path(file_path: str | None, content_instance: BaseContent) -> Course | None:
       file_path = (file_path or "").strip()
       if not file_path:
           return None
       final_path = content_instance.calculate_path_from_root(file_path)
       # Same reasoning as get_published_article_by_path: filter on the content's own site.
       return (Course._base_manager.filter(site_id=content_instance.site_id, file_path=final_path)
               .exclude(visibility=CourseVisibility.HIDDEN).first())

   @register.filter
   def course_access_badge(course: Course) -> AccessBadge | None:
       return get_course_access_backend().get_access_badge(course=course)
   ```
2. `freedom_ls/learner_interface/templates/cotton/course-card.html`:
   - `<c-vars path variant="row" />`; `{% load course_card_tags %}`; render nothing without a course.
   - `variant == "compact"` → `<c-course-card-shell>`; anything else → `<c-course-row-shell class="h-full">`,
     both with `accent_slot_key`, `icon`, `icon_fallback`, `title` from the course. The `class`
     prop is the shells' mergeable hook; `h-full` lets a row card fill a grid cell.
   - Eyebrow slot: `{% with badge=course|course_access_badge %}{% if badge %}<c-chip variant="{{ badge.variant }}" size="xs">{{ badge.label }}</c-chip>{% endif %}{% endwith %}`
     (the `course_row.html` shape). Never reads `access_config`.
   - Title: `{% url 'learner_interface:course_detail' course_slug=course.slug as url %}` then
     `{% include "learner_interface/partials/card_title_link.html" with url=url title=course.title %}`.
   - Body: `{{ course.subtitle|default:course.description }}`; a details line with
     `course.get_difficulty_display` and `course.display_estimated_duration` when present; the price
     as `{% with price=course.current_price %}{% if price %}<p class="text-sm font-semibold"><c-course-price :price="price" variant="compact" /></p>{% endif %}{% endwith %}`,
     the `course_listing_price.html` shape. No tax note, never "$0". No status, progress or details
     link (`course_card.html` and `course_row.html` are not reused because they carry those).
3. `MARKDOWN_ALLOWED_TAGS`: `"c-course-card": {"path", "variant"}`.
4. `claude_plugins/fls-dev/commands/update_claude_plugin_fls_content.md` Step 1 regex: add the

## Slice 14: The validator checks widget references

**Behaviour.** `validate()` reports a broken `path` in any of the three widgets, a target of the
wrong type, and duplicate article slugs, each as a block in the category-error shape, and passes a
valid tree.

### Changes

`freedom_ls/content_engine/validate.py`:

1. `_WIDGET_TAG_PATTERN = re.compile(r'<c-(article-link|article-card|course-card)\b[^>]*?\bpath="([^"]*)"')`.
2. `_widget_reference_error(file_path, content_type, widget, path, problem, fix) -> str`: a sibling
   of `_category_reference_error` producing the same header/field/problem/given-value/fix block,
   with `Field: <widget> path`. (Generalising the category helper would drag its declared-list
   rendering along, so a short sibling is simpler.)
3. `validate_widget_references(all_parsed: list) -> list[str]`:
   ```
   by_path = {normpath(item.file_path): item for item in all_parsed}
   for item with a `content` body:
       for widget, path in _WIDGET_TAG_PATTERN.findall(item.content):
           target = by_path.get(normpath(item.file_path.parent / path))
           if target is None: error "no content file at this path"
           elif widget in article widgets and target.content_type != ARTICLE: error "not an ARTICLE"
           elif widget == course-card and target.content_type != COURSE: error "not a COURSE"
   slugs = group ARTICLE items by slug; two or more files → error naming both files
   ```
   Use `os.path.normpath`, not `content_key` (which lives in the Django-dependent loader), so the
   bundled copy needs no patch.
4. `validate()` step 4: call it beside `validate_category_references`.

### Tests

- `content_engine/tests/test_validate_widget_references.py`, modelled on
  `test_validate_course_categories.py`: one test per widget with a broken path (naming the file and
  the path); an article widget pointing at a `TOPIC`; a course card pointing at an `ARTICLE`;
