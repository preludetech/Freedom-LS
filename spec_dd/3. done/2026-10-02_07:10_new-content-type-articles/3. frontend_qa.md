# Frontend QA: Articles

Browser checks for the public blog, the article page and the four content widgets. Run them after
the implementation plan is complete.

## 0. Setup

1. Pick a port and start the dev server:
   ```bash
   PORT=$(.claude/ds/scripts/find_available_port.sh)
   uv run python manage.py runserver $PORT
   ```
   The base URL is `http://127.0.0.1:$PORT`.
2. Load the demo content into the dev site (the site is named `DemoDev`):
   ```bash
   uv run manage.py content_save ./demo_content DemoDev
   ```
   Then run `git status --short demo_content/` and confirm it prints nothing. A rewritten file
   means a uuid was written back, which is a bug: the committed demo articles already carry theirs.
3. Admin login (from `.claude/fls-dev/config.md`): email `demodev@email.com`, password
   `demodev@email.com`. Only test 6 needs it. Every other test runs logged out: open a private
   window or log out first.
4. Demo article slugs (from the file stems under `demo_content/functionality_demo_articles/`):

   | Slug | What it is |
   | --- | --- |
   | `getting-started-with-articles` | Published, author and date shown, holds every widget |
   | `undated-notes` | Published, `show_date: false`, author shown |
   | `unsigned-update` | Published, no author |
   | `hidden-draft` | Hidden |

Viewports used below: phone 375 × 812, tablet 768 × 1024, desktop 1280 × 800.

5. **Design reference.** The blog index and the article page are checked against the registered
   design (`design.md`). Compare against these screenshots in `design_screenshots/`:

   | Page | Desktop | Phone |
   | --- | --- | --- |
   | Blog index (section 2A) | `2a__desktop-index.png` | `2a__mobile-index.png` |
   | Article page | `journal__desktop-article.png` | `journal__mobile-article.png` |

   Compare layout, spacing, hierarchy and dividers only. Colours, fonts and the site header and
   footer come from the active theme, not the design, so a different colour or face is not a bug.
   The design shows things this feature does not build, and they must be absent: the "Journal"
   eyebrow and intro paragraph on the index, category labels, the author avatar and role, reading
   time, "Next in the journal", and the category-tab index (`journal__*-index.png`).

## 1. The blog index

1. Go to `/articles/` logged out.
2. Expect a 200 page with the H1 "Articles" and three entries: Getting started with articles,
   Undated notes and Unsigned update (titles as written in the demo files), newest `published_on`
   first. The hidden draft is absent. The tab title is "Articles — DemoDev".
3. Each entry shows a linked title, a description and a byline. Bylines read author · date: "Getting
   started with articles" shows both, "Undated notes" shows the author only, "Unsigned update" shows
   the date only.
4. **Layout against `2a__desktop-index.png`** (desktop and tablet): the H1 sits alone at the top with
   a full-width rule under it, and no eyebrow or intro paragraph. Each entry is a row with a hairline
   under it and generous vertical padding. The title sits in the left column, a little wider than
   the right; the description and the byline stack in the right column, top-aligned with the title.
   The header rule and the row rules are the same width.
5. **Layout against `2a__mobile-index.png`** (phone): each row stacks title, description, byline in
   one column, with the hairlines between rows.
6. Hover a row: the whole row takes a light surface tint. Click an empty part of a row (beside the
   title, or on the description): expect the article page for that slug. Click a title: same.
7. Reload, press Tab until a row's title link has focus. A focus ring shows around the whole row,
   fully visible.
8. Side effect: open `/courses/` and the dashboard (log in as the admin for the dashboard). Both
   render as before, with no article content on either.

## 2. The article page, byline and SEO

1. Go to `/articles/getting-started-with-articles/` logged out. Expect 200, an "← Articles" link
   above the title, the title as the H1, the subtitle under it when the article has one, then the
   byline with the author and the date, then the body with its first heading rendered as an H2 (not
   another H1).
2. **Layout against `journal__desktop-article.png`** (desktop and tablet): one centred reading
   column, about the design's width. The back link is small, in the primary colour, with a left
   arrow icon; it goes to `/articles/`. The byline is its own row between two hairlines, author in
   semibold on the left and the date muted on the right. The body starts below the lower hairline.
   Admonitions and blockquotes in the body use the site's existing styles. Absent: a category
   label, an avatar or initials, an author role, a reading time, and "Next in the journal" at the
   foot.
3. **Layout against `journal__mobile-article.png`** (phone): the same order in one column. The
   byline row keeps the author left and the date right when both fit, and wraps the date under the
   author when they don't; either is fine, overflow is not.
4. View the page source. In `<head>` expect:
   - `<title>` equal to the article title;
   - `<meta name="description">` equal to the article's `description` frontmatter;
   - `og:type` `article`, `og:title` the title, `og:description` the same as the description;
   - `<link rel="canonical">` and `og:url` both equal to this page's URL on this host;
   - `article:published_time` with the date as `YYYY-MM-DD`, and `<meta name="author">`;
   - no `og:image`, and `twitter:card` `summary`.
5. Go to `/articles/undated-notes/`. The byline shows the author only. The source has no
   `article:published_time` but still has `<meta name="author">`.
6. Go to `/articles/unsigned-update/`. The byline shows the date only. The source has
   `article:published_time` and no `<meta name="author">`.
7. Go to `/articles/hidden-draft/` and `/articles/does-not-exist/`. Both return the site's standard
   404 page and the two pages look identical. Neither reveals the hidden article's title.
8. Go to `/articles/getting-started-with-articles/?utm_source=x`. The canonical link omits the
   query string.
9. Side effect: no learner UI appears on any article page: no progress bar, no "Start course",
   no registration prompt, and the header shows the logged-out state.

## 3. Sitemap and robots

1. Go to `/sitemap.xml`. Expect `/articles/` and the three published article URLs, each on this
   host. The hidden draft is absent. Course URLs are still present.
2. Go to `/robots.txt`. Expect `Allow: /courses/`, `Allow: /articles/` and the `Sitemap:` line.

## 4. Widgets inside the demo article

All on `/articles/getting-started-with-articles/`, logged out.

1. **Inline links.** In the paragraph of inline links expect: a link with the author's text that
   goes to another published article; a link whose text is that article's title (the empty-slot
   form); and the link to the hidden draft rendered as plain text, with no link, no red "not
   found" span and never the words "Hidden draft".
2. **Article cards.** Expect a row card (horizontal, with an accent strip) and a compact card
   (vertical) for published articles, each showing the title, description and byline. The card
   pointing at the hidden draft renders nothing at all: no empty box, no gap larger than the normal
   paragraph spacing. Card bylines read author · date, the same as the index.
3. **Course cards.** Expect two row cards and two compact cards: "Functionality Demo - Price:
   fixed" shows the badge "Free" and the price `USD 250.00` with no "excl. tax" note; "Functionality
   Demo - Application gated course" shows the badge "By application" and the discounted price with
   the original struck through. Neither shows a status eyebrow, a progress bar or a "Details" link.
   Click a card's title: expect the course detail page.
4. **Grid.** The mixed grid shows article cards, course cards and a picture tiled together. At
   desktop they sit in columns; at phone width they stack in one column. Cards in the same row are
   the same height. Clicking the picture opens the lightbox as on other pages.
5. **Whole-card click.** Click an empty area of a card (not the title). Expect navigation to the
   card's target. Right-click the card: the browser offers the link context menu, confirming a
   single link.
6. **Keyboard.** Reload, press Tab until a card's title link has focus. The focus ring is fully
   visible around the card, not clipped by the card's edge.
7. **Side effect, existing widgets.** Open the Content Widgets demo course
   (`/courses/content-widgets-demo-reference/`, a coming-soon course; log in as the admin if the
   content needs it) and its Media topic. The existing `c-image-grid` of pictures renders as
   before: pictures tiled, lightbox working, no change in spacing.

## 5. Responsive layout

For each of `/articles/`, `/articles/getting-started-with-articles/` and the course detail page of
a course whose topic contains cards, at phone, tablet and desktop widths:

1. No horizontal scrollbar, and swiping sideways on phone moves nothing.
2. Card titles and descriptions wrap rather than overflow.
3. At phone width the row variants either hold their horizontal layout without overflow or
   collapse to the compact layout; either is acceptable, overflow is not.
4. On `/articles/`, the rows are two columns at tablet and desktop and one stacked column at phone
   width. Resize slowly from 1280 down to 375: the switch is clean, with no overlapping text.
5. On the article page at phone width, the byline row fits or wraps without overflow.

## 6. Admin

Log in as the admin and open the Articles changelist under Content engine.

1. The list shows title, slug, `published_on` and visibility, with a visibility filter and a tag
   filter in the sidebar.
2. Open "Hidden draft". `slug` and `visibility` are read-only. A delete button is present, unlike
   on a Topic's change page, and the form carries the note that an article whose file is still in
   the repo comes back on the next `content_save`.
3. Delete "Unsigned update". Confirm it is gone from `/articles/` and its URL returns 404.
4. Run `uv run manage.py content_save ./demo_content DemoDev`. "Unsigned update" is back at the
   same URL with the same uuid, and `git status --short demo_content/` is clean.
5. Change `visibility` is not possible through the admin, so instead edit
   `demo_content/functionality_demo_articles/unsigned-update.md` to `visibility: hidden`, reload
   with `content_save`, and confirm the URL now returns 404 and the index no longer lists it.
   Revert the file afterwards and reload again.

## 7. Failure and adversarial branches

1. **Slug collision.** Copy `unsigned-update.md` to `unsigned-update-copy.md`, remove its `uuid`
   line and set `slug: unsigned-update`. Run `content_save`. Expect it to refuse with a message
   naming the owning uuid and the file. Nothing in the database changed. Delete the copy.
2. **Bad slug.** Set `slug: "bad slug!"` on the copy from step 1 and run `content_save`. Expect a
   validation error naming the file and the field. Delete the copy.
3. **Broken widget path.** In `getting-started-with-articles.md`, change one `c-course-card` path
   to `../nope/course.md` and run `content_save`. Expect validation to fail, naming the file, the
   widget and the path, before anything is saved. Also run the bundled validator from the repo root:
   ```bash
   uv run --no-project --with pydantic --with pyyaml --with python-frontmatter --with babel python claude_plugins/fls-content/validate/validate.py demo_content
   ```
   Expect the same failure. Revert the file and confirm both pass again.
4. **Removed author.** Delete the `author` line from `getting-started-with-articles.md`, run
   `content_save`, reload the article. The byline shows the date only. Restore the line, reload,
   and the author is back.
5. **Prefix setting.** With the server stopped, add `BLOG_URL_PREFIX = "/articles"` to the end
   of `config/settings_dev.py` and run `uv run manage.py check`. Expect `freedom_ls_blog.E001`.
   Change it to `BLOG_URL_PREFIX = "news/blog"`, start the server, and confirm `/news/blog/` serves
   the index, `/articles/` 404s, and `/robots.txt` now says `Allow: /news/blog/`. Remove the line
   afterwards. An empty value is not an error: it falls back to `articles`.
6. **Blog name setting.** With the server stopped, add `BLOG_NAME = "Posts"` to the end of
   `config/settings_dev.py` and start the server. `/articles/` shows the H1 "Posts" and the tab
   title "Posts — DemoDev"; the back link on an article page reads "← Posts". The URL is still
   `/articles/`. Remove the line afterwards and confirm "Articles" is back.
7. **Direct URL probes.** `/articles/../admin/`, `/articles/Hidden-Draft/` and
   `/articles/hidden-draft` without the trailing slash: the first two return 404 (the slug route is
   case-sensitive), the last redirects to the slashed URL and then 404s. None returns a 500.
