# Spec: panel framework components

Spec 4 of 12 in the educator interface rebuild (`spec_dd/1. next/roadmap.md`, "Educator interface
rebuild"). Source: `idea.md` in this directory. Depends on `educator-interface-1-panel-framework-core`,
which has landed.

## Purpose

Specs 6 to 10 build educator screens to the mockups in
`spec_dd/1. next/educator-interface-full-polish/Educator LMS Interface Design/`. This spec builds the
cotton components those screens are made of, once, in `panel_framework`, on FLS role tokens and
`c-icon`. It also restyles the framework's own view and panel templates through them, so every
panel matches the mockups without a feature spec touching styling. The components are a public
API, so their names and attributes are a contract for downstream projects.

## Scope

**In:** the components under Requirements; rendering the framework's view headings, panel frame,
instance details and tab nav through them; the default theme's `.chip-*` status tints; five new
semantic icon names; a reference page.

**Out**

- Charts (spec 10 uses the `dataviz` skill if it needs one).
- Every other change to `base` components, `c-callout` and `c-chip`'s markup included.
- A dark theme.
- The mockups' assessment states ("Retake due", "Submitted") and "Invited" (the roadmap calls it
  "pending").
- Mapping domain statuses to tones. Specs 6, 7, 9 and 10 own their words
  (`research_status_vocabulary.md` suggests tones).
- The stepper, file chip and column-mapping rows (spec 8). The floating action button.
- Filter query-string state, filter declarations and focus after removing a filter (spec 2).
- When to show a skeleton and the delay before it appears (spec 3).
- Moving or merging `c-course-progress-bar`, and moving any component to the learner interface.
- Marketing and learner-facing pages.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| tone | coined | The attribute choosing a status colour: `success`, `warning`, `error`, `info` or `muted`. The values are `c-chip`'s variant names. The codebase has no word for the choice itself. |
| slot (avatar) | narrowed | A palette slot, as in `Course.accent_slot`. Here it means one of six avatar colours. "Named slot" keeps its cotton meaning. |

## Decisions

1. **The `panel-` file prefix.** Cotton's namespace is flat. `panel-` matches how `course-` and
   `content-` are used and collides with nothing.
2. **Mobile header actions wrap to a second row.** Header actions are capped at three, so wrapping
   needs at most one extra row. An overflow menu would give the same buttons two keyboard models at
   two widths.
3. **One closed tone vocabulary across the kit.** It includes `error` and `warning`, the values
   `AtRiskRule.severity` emits. An unknown tone renders as `muted`.
4. **Toned text uses the `on-*-light` tokens.** Coloured text such as `text-success` on a surface or
   tint is below 4.5:1. Delta lines and severity icons use `text-on-success-light`,
   `text-on-warning-light`, `text-on-error-light`, `text-on-info-light`, or `text-muted` for `muted`.
5. **The default theme's chip tints are fixed in place.** In `tailwind.components.css`,
   `.chip-success`, `.chip-error` and `.chip-info` are `bg-X/15 text-X`, which measure about 2.8:1,
   3.2:1 and 2.4:1. `.chip*` is one of the classes a theme reopens, and those live in that file,
   so the fix goes there. It is the only change to that file.
6. **Instance details become one `<dl>`.** Label and value pairs are not tabular data, so
   `_instance_details_base.html` drops its `<table>`.
7. **A stat tile's delta has two attributes.** `direction` is the fact and picks the decorative icon.
   `tone` is the caller's judgement of whether that is good. The tile never derives one from the
   other.
8. **Avatar colours get their own six slots**, not the course accent slots, which `theme.css`
   reserves for course branding. The slot comes from `crc32` of the id. Unlike `hash()` it is stable
   across processes, and it works for integer and UUID ids alike.
9. **Forced colours are handled in three places only:** the progress bar, the filter toggle and the
   badge outline. The avatar colour and skeleton blocks carry no information.
10. **No shadows.** The mockups shadow every card, but FLS has no shadow scale and the brand
    guidelines rule out decorative shadows, so cards and tiles use a border. The mockups' 10-12px
    radii become `rounded-lg`. Their three grey text tiers all become `text-muted`.

## Requirements

### Conventions for every component

- File: `freedom_ls/panel_framework/templates/cotton/panel-<name>.html`, used as `<c-panel-<name>>`.
- Line 1 is a `<c-vars>` declaring every attribute with its default. The root element carries
  `{{ attrs }}`, so callers can add `id`, `data-*` and `hx-*`.
- A `{% comment %}` header, modelled on `cotton/flashcard.html` and `cotton/chip.html`, gives the
  purpose, each attribute with its allowed values, default and fallback, the named slots, any
  accessibility decision that is not obvious, and usage examples. A component that would suit the
  learner interface (the progress bar, empty state, skeleton) says so there, as a candidate to move
  later.
- Tailwind utilities go on the markup, using role tokens only. A `<style>@layer components {…}</style>`
  block inside the component is allowed only for CSS no utility expresses (progress pseudo-elements,
  avatar slot properties).
- Icons come through `c-icon` only. A decorative icon is `aria-hidden`: `c-icon` always names its
  `<svg>` (`role="img"` and an `aria-label`), so a decorative icon is wrapped in
  `<span aria-hidden="true">`, the way `cotton/button.html` does it.
- No component has its own `aria-live` region. Anything announced after a swap goes through
  `#scope-announcer` (`templates/panel_framework/partials/announcer_host.html`).
- No `|safe` on any caller-supplied value.
- An attribute that takes a fixed set of values falls back to its default on an unknown value. It
  does not raise.
- A named slot that is missing, empty or whitespace-only counts as not given, and the markup that
  would hold it is not rendered.
- A component whose root is another cotton component (the status badge on `c-chip`) forwards its
  caller's attributes with `:attrs="attrs"`.
- The template-side logic Django templates cannot express lives in filters in
  `freedom_ls/panel_framework/templatetags/panel_tags.py`, each a pure function: `tone` (an unknown
  tone becomes `muted`), `heading_level` (takes the component's default, returns `1`-`6`),
  `clamp_percentage` (0-100 integer), `initials` (from a name), `avatar_slot` (below) and `times`
  (an integer to a `range`, for the skeleton's `lines`).

### Page header: `panel-page-header`

| Attribute | Default | Meaning |
|---|---|---|
| `title` | required | Heading text |
| `subtitle` | `""` | One line under the title, `text-muted` |
| `heading_level` | `"1"` | `1`-`6` |
| `title_id` | `""` | `id` on the heading element |

Named slots: `badge` (a status badge beside the title), `meta` (a line of secondary data, such as
an email or a mono id), `stats` (an inline stat row), and `actions` (at most three buttons).

- The heading element contains the title text and nothing else. The `panelChanged` listener in
  `panel_framework/static/panel_framework/js/alpine-components.js` replaces the `textContent` of
  `#instance-title`, so a badge inside the heading would be wiped out.
- Actions render in `<c-button-group variant="right" class="flex-wrap">`, beside the title block from
  `md` and on a row under it below `md`. The group is not rendered when the slot is empty.
- The `stats` slot sits to the right of the title block from `md` (05) and below it on mobile (M08).
- The header sits under the breadcrumbs, which stay a separate region.

Call sites:

- `templates/panel_framework/views/_instance_view_base.html`: replaces the bare
  `<h1 id="instance-title">` and its action group with
  `<c-panel-page-header :title="main.instance" title_id="instance-title">`, with the actions in the
  `actions` slot.
- `templates/panel_framework/views/_list_view_base.html`: adds a header with `title=main.heading`
  (the section's `menu_label`). The actions move into its `actions` slot in both branches, including
  when `main.refresh_events` is set. `partials/list_refresh.html` then renders only the `listRefresh`
  host, keeping its `x-data` and `data-refresh-*` attributes, outside the swapped table region.
- `templates/panel_framework/views/_base_view_base.html`: adds a header with `title=main.heading`.
  `BaseViewConfig` pages (spec 10's dashboard) have no `h1` today.

### Stat tile: `panel-stat-tile` and `panel-stat-row`

`panel-stat-tile`:

| Attribute | Default | Meaning |
|---|---|---|
| `label` | required | What is counted |
| `value` | required | The figure |
| `sub` | `""` | Plain sub-line |
| `delta` | `""` | Delta text, e.g. "Up 4 points" |
| `direction` | `""` | `up`, `down`, `flat`; icon `trend_up`, `trend_down`, none |
| `tone` | `"muted"` | Colour of the delta line |
| `variant` | `"boxed"` | `boxed` (bordered `bg-surface` card: 01, M01, quick view) or `inline` (no card: 05, M08) |

- It is a `<dl>` with the label as `<dt>` first and the value as `<dd>`. CSS puts the value on top
  visually. The sub-line and delta are further `<dd>`s. The delta is text, and its icon is
  decorative.
- The default slot renders under the value, for the progress bar inside 01's "Average progress" tile.
- The value uses `tabular-nums`.

`panel-stat-row` has one attribute, `variant` (`boxed` or `inline`). `boxed` is a grid, two columns
below `md` and four from `lg`. `inline` is a wrapping flex row with the wider gap used on 05.

### Status badge: `panel-status-badge`

Attributes: `tone` (default `muted`) and `label`. It renders
`<c-chip variant="{{ tone }}" size="xs" …>{{ label }}</c-chip>`, adding a `forced-colors:border`
outline through `c-chip`'s `class`. `primary` and `secondary` are not tones and fall back to `muted`.
The label is shown as given; callers pass sentence case. The badge owns no domain words.

`tailwind.components.css`: `.chip-success`, `.chip-warning`, `.chip-error` and `.chip-info` become
`bg-<role>-light text-on-<role>-light`, the pairs `first_class` already uses. `.chip-primary`,
`.chip-secondary` and `.chip-muted` are unchanged.

### Avatar chip: `panel-avatar-chip`

| Attribute | Default | Meaning |
|---|---|---|
| `name` | required | Display name, and the accessible name |
| `user_id` | required | Picks the colour slot |
| `initials` | `""` | Overrides the initials derived from `name` |
| `secondary` | `""` | Email or role, second line, `text-muted` |
| `size` | `"md"` | `md` (32-36px rows) or `lg` (52px profile header, 03) |
| `name_hidden` | `""` | Truthy: the name and second line are not rendered, for a caller that shows the name itself (the attention row's subject link) |

- The initials circle is `aria-hidden`. The name is visible text.
- Initials default to the first letters of the first and last words of `name`, uppercased. One word
  gives one letter, and an empty name gives none.
- The slot comes from a new filter, `avatar_slot`, in
  `freedom_ls/panel_framework/templatetags/panel_tags.py`, typed `int | str | uuid.UUID -> int`,
  computing `zlib.crc32(str(value).encode()) % 6 + 1`.
- The six slots are custom properties declared in the component's own `@layer components` block
  (`.panel-avatar-1` … `.panel-avatar-6`). Each is a `color-mix` of a role token into
  `--color-surface`, never a raw hex. `success`, `warning` and `error` are excluded so that no avatar
  reads as a status. Initials are `text-on-surface`, and every slot must reach 4.5:1 against it in
  both shipped themes. A theme recolours the palette by redefining the properties or shadowing the
  component.

### Attention list: `panel-attention-list` and `panel-attention-row`

`panel-attention-list` is a `<ul>` with dividers, holding `panel-attention-row` elements, each an
`<li>`.

| Attribute | Default | Meaning |
|---|---|---|
| `subject` | required | Who or what the row is about (a learner name, a cohort-level issue) |
| `href` | required | Where the row leads |
| `reason` | `""` | Why it needs attention, e.g. "4 days idle" |
| `user_id` | `""` | Given: the leading element is `panel-avatar-chip` |
| `icon` | `""` | Given, with no `user_id`: a severity icon leads instead (05) |
| `icon_tone` | `"muted"` | Tone of the severity icon |
| `badge_label`, `badge_tone` | `""`, `"muted"` | Optional `panel-status-badge` |
| `action_label` | `""` | The single action's visible verb, e.g. "Message" |
| `action_href` | `""` | The action's target |

- The action's accessible name includes the subject: visible "Message" plus visually hidden
  " Thandi Mokoena".
- From `md` a row shows the leading element, the subject linked to `href`, the reason, the badge and
  the action (01, 05).
- Below `md` the whole row is the tap target for `href`, with a trailing decorative `next` icon, and
  the action is hidden (M01, M08). The DOM holds one link per destination, never a second link to
  `href`.

### Progress bar: `panel-progress-bar`

Attributes: `percentage` (default `0`, clamped 0-100), `label` (default `"Progress"`: the `<progress>`
`aria-label`, and visible text when `show_label` is set) and `show_label` (default empty).

- Native `<progress value max="100">` as in `c-course-progress-bar`, with no ARIA progressbar role.
  The percentage sits beside the bar as visible text, never inside it.
- The track is `bg-surface-2` and the fill `bg-primary`, through `::-webkit-progress-bar`,
  `::-webkit-progress-value` and `::-moz-progress-bar` in the component's `@layer components` block.
- Under `forced-colors: active` the bar has a `CanvasText` border, the track is `Field` and the fill
  `Highlight`.

### Card: `panel-card`

| Attribute | Default | Meaning |
|---|---|---|
| `title` | `""` | Heading, omitted when empty |
| `description` | `""` | One line under the heading |
| `heading_level` | `"2"` | `1`-`6` |
| `landmark` | `""` | Truthy: the root is `<section aria-labelledby>` on the heading; otherwise a `<div>` |

Named slots: `header_action` (a single link beside the heading, such as "View all") and `actions`
(footer, at most three, in `c-button-group variant="right"`, above a top border). The default slot
is the body. The card is `bg-surface`, bordered and `rounded-lg`, with a header border when it has a
heading.

`templates/panel_framework/panels/_panel_base.html` renders its `panel_header`, `panel_body` and
`panel_actions` blocks through the card:

- `data-panel`, the conditional region `id`, and the `hx-get` / `hx-trigger="panelChanged from:body"` /
  `hx-target` / `hx-swap` attributes stay on the panel's outermost element, the `<section>`, which
  drops `.surface`. The card is that section's only child, with `:title="title"`.
- All three block names keep working for the leaf and `_base` override routes spec 1 established.
  A `{% block %}` inside a cotton slot is overridable (cotton nodes expose their `nodelist`, so
  Django's block discovery reaches them). `panel_body` and `panel_header` sit in the card's default
  slot, `panel_header` first with empty default content, since the card now renders the heading from
  `title`. `panel_actions` sits inside the `actions` slot.
- A bare panel and a hand-placed card render the same chrome from the one component file.
- With `landmark`, the heading's `id` is `<id>-title` when the caller passes an `id`, otherwise
  `<title|slugify>-title`.

### Definition list: `panel-definition-list` and `panel-definition-row`

`panel-definition-list` has one attribute, `columns` (default `"3"`, allowed `2`, `3`, `4`). It is a
`<dl>`, stacked below `md` and a `columns`-wide grid from `md` (03, 05).

`panel-definition-row` has one attribute, `label`. It renders a `<div>` holding a `<dt>` (small
uppercase `text-muted` label) and a `<dd>` containing the default slot.

`templates/panel_framework/panels/_instance_details_base.html` renders its rows through these,
labels `|capfirst` as now, values through `_details_value.html` unchanged.

### Toolbar: `panel-toolbar` and its parts

- **`panel-toolbar`**: a plain `<div>`, not `role="toolbar"`. Named slots are `search`, `filters`,
  `actions` and `applied`. It takes one attribute, `clear_all_href`: when set, a "Clear all" link
  renders after the applied chips. The caller sets it only when a filter is applied. From `md` the
  search, filters and actions share a row, with the actions right-aligned. Below `md` the search
  takes the full width.
- **`panel-search-field`**: `name`, `value`, `label` (required, a real `<label>`), `label_hidden`
  (visually hides the label when set), `placeholder` and `id` (default `search-<name>`, the `for`
  target). The `search` icon is decorative. `{{ attrs }}` lands on the `<input>` so spec 2 can add
  `hx-*`.
- **`panel-filter-toggle`**: `<button type="button" aria-pressed="true|false">`, taking `label` and
  `pressed`. The pressed state differs by more than colour: it adds a decorative `check` icon. Under
  forced colours the pressed state uses `Highlight`/`HighlightText` and the unpressed a
  `ButtonBorder` border.
- **`panel-applied-filter`**: the chip text (`label`, e.g. "Status: Inactive") plus its own
  `<button>` whose accessible name is "Remove filter: <label>", with a decorative `close` icon.
  `{{ attrs }}` lands on the remove button.

### Empty state: `panel-empty-state`

Attributes: `icon` (a semantic name, decorative) and `message` (one sentence, a `<p>`, never a
heading). The one action goes in the default slot. The caller writes the wording for first use,
no results and error. The layout is centred and uses the kit's spacing, since the mockups draw none.

### Tab bar

Styling only, in `templates/panel_framework/panels/_tab_set_base.html`'s existing
`<nav aria-label><ul><a aria-current>`. The active tab has a primary underline, `font-semibold` and
`text-on-surface`; the others are `text-muted` (03, 05). Below `md` the list scrolls horizontally,
with no wrapping inside a tab (M08). No tab roles are added. `data-tab-set` and the link `hx-*`
attributes are unchanged.

### Skeleton: `panel-skeleton`

Attributes: `shape` (default `text`; also `tile` and `row`, matching a stat tile and an attention
row) and `lines` (default `3`, for `text`). The wrapper is `aria-hidden="true"` and uses
`animate-pulse motion-reduce:animate-none`. `aria-busy` belongs on the region being loaded and is the
caller's.

### Callout

The mockups' callout (03, 08, M06, M11) is `c-callout`. There is nothing to build.

### Icons

In `freedom_ls/icons/semantic_names.py`, add `add`, `search`, `filter`, `trend_up` and `trend_down`
under their comment groups, and map each in all four dicts in `freedom_ls/icons/mappings.py`:

| Name | heroicons | lucide | tabler | phosphor |
|---|---|---|---|---|
| `add` | `plus` | `plus` | `plus` | `plus` |
| `search` | `magnifying-glass` | `search` | `search` | `magnifying-glass` |
| `filter` | `funnel` | `funnel` | `filter` | `funnel` |
| `trend_up` | `arrow-trending-up` | `trending-up` | `trending-up` | `trend-up` |
| `trend_down` | `arrow-trending-down` | `trending-down` | `trending-down` | `trend-down` |

### Reference page

- `freedom_ls/panel_framework/reference.py`: `component_reference(request, template_name=...)`,
  decorated with `staff_member_required` (as `freedom_ls/deployment/views.py` does). It renders
  `panel_framework/reference/component_reference.html` from static example data defined in the
  module, with no model access and no `DEBUG` check.
- The page extends the site's normal base template (`_base.html`), so the active theme applies. The
  examples themselves are one partial, `panel_framework/reference/_examples.html`, which the page
  includes, so a test can render the examples without the page chrome. Every component appears in
  every state listed in this spec, each example with a one-line "Use when" note and a stable `id` of
  the form `<component>-<state>` (for example `stat-tile-boxed-delta-down`) for spec 12's visual
  check.
- The base template's header and footer reverse `accounts:` and `educator_interface:` URLs the test
  URLconf does not carry, so the test route renders the same view with
  `template_name="panel_framework/test_component_reference.html"`: a test-only wrapper in
  `freedom_ls/panel_framework/tests/templates/`, modelled on `test_interface.html`, that extends
  `_base.html`, blanks `header` and `footer`, and includes the examples partial.
- `freedom_ls/panel_framework/urls.py` (new): `app_name = "panel_framework"`,
  `path("components/", component_reference, name="component_reference")`.
- `config/urls.py`: inside the existing `if settings.DEBUG:` block,
  `path("panel-framework/", include("freedom_ls.panel_framework.urls"))`.
- `freedom_ls/panel_framework/tests/urls.py`: the same view at `components/`, unconditionally, placed
  before the catch-all `interface` pattern.
- `staff_member_required` sends anonymous and non-staff users to `admin:login`. Every
  panel_framework test runs under `tests/root_urls.py`, which therefore gains the admin URLs so the
  redirect resolves.

## Testing

Component tests render through `render_to_string` or `CottonCompiler`, as
`freedom_ls/panel_framework/tests/test_templates.py` and
`freedom_ls/icons/tests/test_icon_cotton_component.py` do. They assert on the markup contract
(elements, ARIA, text and escaping), never on classes or pixels. Tests mirror the source layout under
`freedom_ls/panel_framework/tests/`.

- **Page header**: renders `h1` by default and `h3` when `heading_level="3"`. An unknown level falls
  back to `h1`. The badge and meta render outside the heading element. `title_id` lands on the
  heading. No action group renders when the slot is empty. A title containing `<script>` is escaped.
- **View templates**: the instance view still emits exactly one `id="instance-title"`, whose content
  is only the instance text. List and base views now render one `h1` with the section's
  `menu_label`. The list view still renders the `listRefresh` host with its `data-refresh-*`
  attributes, and its actions render in the header.
- **Stat tile**: `<dt>` precedes `<dd>` in source. `direction="up"` renders the `trend_up` icon
  `aria-hidden` next to the delta text. `tone` does not change the icon, and `direction` does not
  change the tone. No delta markup renders when `delta` is empty. An unknown `variant` renders
  `boxed`.
- **Status badge**: each of the five tones renders the matching chip variant. `primary` and an
  unknown tone render `muted`. The label is escaped.
- **Chip tokens**: a source-CSS test in the style of `freedom_ls/base/tests/test_theme_tokens.py`
  asserts that `.chip-success`, `.chip-warning`, `.chip-error` and `.chip-info` in
  `tailwind.components.css` use their `-light` / `on-*-light` pair.
- **Avatar**: `avatar_slot` is in 1-6, the same across calls for the same int, str and UUID, and
  different ids spread across more than one slot. The initials element is `aria-hidden` and the
  name is visible text. Derived initials cover "Thandi Mokoena" → "TM", a one-word name, and an empty
  name.
- **Attention list**: the root is a `<ul>` of `<li>`. The action's accessible text contains the
  subject. `user_id` renders an avatar, and `icon` without `user_id` renders the icon. Each row has
  exactly one link to `href`.
- **Progress bar**: a native `<progress>` with `aria-label`, no `role="progressbar"`. The percentage
  appears as text outside the element. `-5` and `150` clamp to `0` and `100`.
- **Card**: a `<div>` root by default, and `<section aria-labelledby>` pointing at the heading's id
  when `landmark` is set. No footer renders without actions.
- **Panel frame**: `_panel_base.html` still carries `data-panel`, the region id and the
  `panelChanged` trigger on its outermost element. Both the leaf-template and `_base`-template
  override routes still replace `panel_header`, `panel_body` and `panel_actions`, using the existing
  `template_overrides/` fixtures.
- **Instance details**: renders one `<dl>` with a `<dt>`/`<dd>` pair per field and no `<table>`.
  Boolean values still render through `_details_value.html`'s icons.
- **Toolbar**: no `role="toolbar"`. The search input has an associated `<label>`. The filter toggle
  is a `<button type="button">` with `aria-pressed` matching `pressed`. The applied filter's remove
  button is named "Remove filter: <label>". "Clear all" renders only with `clear_all_href`.
- **Empty state**: the icon is `aria-hidden`, and the message is a `<p>`, not a heading.
- **Tab bar**: no `role="tab"`, `tablist` or `aria-selected`. `aria-current="page"` stays on the
  active link.
- **Skeleton**: the wrapper is `aria-hidden="true"`. `lines` controls the line count, and an unknown
  `shape` renders `text`.
- **Icons**: every new name resolves in all four sets, and the `icons` system check reports no
  missing mapping.
- **Reference page**: rendering the component examples with the example context issues zero queries
  (`django_assert_num_queries(0)`); the base template's own chrome is outside that count. Anonymous
  and non-staff users are redirected to the admin login, and staff get 200. Every component has at
  least one element with an `id` of the `<component>-<state>` form.
  `panel_framework:component_reference` does not resolve under `config.urls` with `DEBUG=False`.
- **Playwright** (`@pytest.mark.playwright`, against the test URLconf): the reference page loads for
  staff. At a 375px viewport, tapping an attention row navigates to its `href`, and the page header's
  actions sit below the title without horizontal scroll.

    - Panels render through `panel-card` and no longer carry `.surface`, so a theme's `.surface`
      rules stop reaching them.
    - List and base views gain an `h1`, and list-view actions move into it.
    - The default theme's status chips change colour to the `-light` pairs.
    - A theme that shadows any of these templates must re-check them.
  - The five new semantic icon names, so a project with a custom icon set can map them.
  - The optional `panel_framework.urls` include for the reference page, and that it belongs under
    `DEBUG`.
- `claude_plugins/fls-dev/skills/icon-usage/`: add the five names to the registry list.
- `.claude/skills/brand-guidelines/`: the component-patterns table names `panel-status-badge` for
  statuses on educator screens, and states that `.chip-*` status tints use the `-light` pairs.
- `claude_plugins/fls-dev/resources/frontend_styling.md`: note the avatar slot properties as a

- The panel framework product doc and skill are spec 12's.

## Open questions

Defaults taken; overrule any of them before planning.

- **Avatar slot colours.** Six `color-mix` tints of `primary`, `secondary`, `accent` and `info` at
  two strengths, chosen in the plan and checked for 4.5:1.
- **Mobile row chevron.** The existing `next` icon (an arrow in every set) rather than a new chevron
  name. `collapse` maps to a chevron but means something else.
- **Base views.** They get the page header. The idea names only list views.
- **Header actions beyond three.** Nothing enforces the cap. A spec that needs a fourth action should
  reopen Decision 2 and use `c-dropdown-menu`, not add a component.
