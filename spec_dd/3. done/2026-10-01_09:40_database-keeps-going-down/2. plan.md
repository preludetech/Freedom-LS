# Plan: the dev database stays up

Spec: `1. spec.md` in this directory. Background: `idea.md` and the `research_*.md` files.

## Ground rules for the implementer

- TDD for every behaviour below: write the failing test, make it pass, refactor. The plan names the
  tests; it does not write them out.
- **Do not stop, restart or switch the running dev Postgres server during implementation.** The
  port, `pguser` credentials and database names do not change, so the suite keeps running against
  whichever server is already up. Other worktrees depend on that server. Switching to the new
  compose project happens outside the plan.
- Shell scripts must pass `shellcheck` (pre-commit runs it). Python must pass ruff, mypy and bandit.
  Subprocess calls use argument lists, never `shell=True`, with the `# noqa: S603` marker the
  existing tests use.
- Comments follow the `code-comments` skill. The spec cites research files and section numbers
  (e.g. "`research_session_reaping.md` §2"). Do not copy those citations into code comments. Keep the
  reason, drop the reference.
- Tests follow `ds:testing` and `fls-dev:testing`: AAA layout, one behaviour per test, no loops or
  conditionals in test bodies, `parametrize` only where every case has the same shape. None of the
  new tests touch a database, so no `django_db`, no factories.
- New tests live in the repo-level `tests/` directory, next to the existing shell and dev-tooling
  tests (`tests/test_rebuild_after_rebase.py`, `tests/test_rebase_lost_change_check.py`). Downstream
  projects do not collect `tests/`, so these tests stay unmarked, like the files already there.
- Full-suite runs in this plan follow Slice 8's rule: one Bash command with `run_in_background: true`,
  then wait for the notification.
- Plugin skills, commands and agents are in scope because they change how agents behave.
  `dev_db/README.md`, `CLAUDE.md`, `claude_plugins/django-stack/README.md` and the upgrade notes
  from the spec's "Documentation and downstream" section are not part of this plan.

```sh
# Role first: the databases below are owned by it.
psql_cmd -v ON_ERROR_STOP=1 -f - <<'SQL'
DO $$
BEGIN
    IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'fls_dev') THEN
        CREATE ROLE fls_dev LOGIN PASSWORD 'password' CREATEDB;
    END IF;
END
$$;
SQL
psql_cmd -c "ALTER ROLE fls_dev SET idle_in_transaction_session_timeout = '15min';"

ensure_db() {   # $1 = database name
    if psql_cmd -tc "SELECT 1 FROM pg_database WHERE datname = '$1'" | grep -q 1; then
        psql_cmd -c "ALTER DATABASE $1 OWNER TO fls_dev;"

        psql_cmd -c "CREATE DATABASE $1 OWNER fls_dev;"

}
ensure_db "$DB_NAME"
ensure_db "$TEST_DB_NAME"
```

- Nothing goes inside the heredoc except SQL: `#` is not a SQL comment. If detect-secrets flags the

Tests, in `tests/test_dev_db_scripts.py`. The stub `psql` also appends its stdin to the log when

### 9.2 `claude_plugins/django-stack/scripts/reap_playwright_mcp.sh`

POSIX `sh` and POSIX `awk`, for Linux and macOS. Shape:

```sh
#! /bin/sh
# Usage: reap_playwright_mcp.sh [--kill]
# Lists Playwright MCP servers orphaned by an ended Claude Code session, and their browsers.
# --kill sends SIGTERM, waits 5 s, then SIGKILL to survivors.
set -eu

snapshot=$(mktemp); trap 'rm -f "$snapshot"' EXIT
ps -A -o pid=,ppid=,uid=,etime=,rss=,args= > "$snapshot"

candidates=$(awk -v me="$(id -u)" '
    # etime is [[dd-]hh:]mm:ss -> seconds
    function age(e,   d, n, p) { … }
    { ppid[$1]=$2; uid[$1]=$3; etime[$1]=$4; rss[$1]=$5; cmd[$1]=substr($0, index($0, $6)) }
    END {
        # subreaper: the current user'"'"'s own "systemd --user"
        # orphan: parent is 1 or the subreaper
        # roots: orphans with uid == me whose cmd matches /@playwright\/mcp|playwright-mcp/
        #        and whose age > 3600
        # then add every descendant of a root (repeat the parent pass until nothing new is added)
        # print: pid, age, rss, command
    }' "$snapshot")
```

- Use only POSIX awk. macOS `awk` and Debian `mawk` lack gawk extensions such as `systime()`,
  `gensub()` and `strftime()`. `age()` parses `etime` with `split()`.
- The command line has spaces, so rebuild it from `$6` to the end of the line (`substr($0,
  index($0, $6))`), not from `$6` alone.
- No argument: print a `pid age rss command` header and the candidate lines, or "No orphaned
  Playwright MCP processes".
- `--kill`: `kill -TERM` every candidate pid, `sleep 5`, then `kill -KILL` any pid that
  `kill -0` still finds. Print what was ended.
- Only the current user's processes are candidates, so `--kill` never targets someone else's.
- Age comes from `etime`, not `etimes` (Linux-only).

### 10.1 `dev_db/` as a package, and the one way to reach the server

`stale_dbs` and `diagnose` (Slices 11 and 12) both use this.

- `dev_db/__init__.py`, empty (like `config/__init__.py`).
- `dev_db/server.py`:

```python
COMPOSE_FILE = Path(__file__).resolve().parent / "docker-compose.yaml"


class ServerUnavailable(Exception):
    pass


def compose(*args: str) -> subprocess.CompletedProcess[str]:
    return subprocess.run(  # noqa: S603
        ["docker", "compose", "-f", str(COMPOSE_FILE), *args],
        capture_output=True, text=True, check=False,
    )


def psql(sql: str) -> list[list[str]]:
    """Run sql as pguser inside the postgres service; return rows of tab-separated fields.

    It connects over the container's local socket, which the postgres image trusts, so no
    password is passed.
    """
    result = compose("exec", "-T", "postgres", "psql", "-U", "pguser", "-d", "postgres",
                     "-AtX", "-F", "\t", "-v", "ON_ERROR_STOP=1", "-c", sql)
    # non-zero return code -> raise ServerUnavailable(result.stderr)
    return [line.split("\t") for line in result.stdout.splitlines()]
```

## Slice 11: `diagnose` checks the engine and the container

Behaviour: `uv run python -m dev_db.diagnose` runs checks 1–4 from the spec in order. It prints one
line per finding, with a verdict and a next step, and exits non-zero when any check fails.

### 11.2 The log matcher (shared with Slice 12)

### 11.3 Checks 1–4

1. `check_engine_reachable`: `docker info` exits 0 → OK. Otherwise FAIL. Then look in the Desktop
   log dirs (`~/.docker/desktop/log/host/`, `~/.docker/desktop/log/vm/` on Linux,
   `~/Library/Containers/com.docker.docker/Data/log/` on macOS) for files modified in the last 3
   days. Run `summarise` with `DESKTOP_SIGNATURES` and, on a match, report "Docker Desktop
   file-service failure" with the last occurrence and the next step: restart Docker Desktop.
2. `check_engine_kind`: `docker info --format '{{json .}}'`. `OperatingSystem` contains
   "Docker Desktop" and `sys.platform == "linux"` → WARN recommending Docker Engine. `MemTotal` under
   4 GiB → WARN.
3. `check_old_project`: `docker ps -a --filter label=com.docker.compose.project=dev_db --format
   '{{.Names}}'`. Any output → FAIL, next step `docker compose -p dev_db down`.
4. `check_container`: `server.compose("ps", "-a", "-q", "postgres")` for the ID, then
   `docker inspect <id>`. None → FAIL, next step `docker compose -f dev_db/docker-compose.yaml up -d`.
   Otherwise report running, health, `OOMKilled`, `ExitCode`, `RestartCount`, `StartedAt`, and
   `Created`. A creation time within 24 h adds "recreated at T from W", with W taken from the
   `com.docker.compose.project.working_dir` label. Not running, unhealthy, or `OOMKilled` → FAIL.

Tests, new file `tests/test_diagnose.py`:
- `match_signature` classifies a sample Desktop line for each Desktop signature (parametrized).
- `match_signature` returns `None` for an unrelated line.
- `summarise` counts matches and keeps the last occurrence.
- `main` returns 1 when any finding is FAIL and 0 when none is, with the check functions patched to
  return fixed findings (the I/O boundary).

Commit: `dev_db: diagnose checks the engine and the postgres container`.
