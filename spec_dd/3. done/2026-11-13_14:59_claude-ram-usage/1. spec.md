# Spec: memory-aware test runs and SDD fan-out

## Purpose

Parallel SDD batches and parallel pytest runs exhaust RAM on the developer machine. When that
happens an xdist worker or the whole run is killed, and the agent restarts the full tier from
scratch. Sometimes the kernel kills something worse: a Claude session, the browser or the VM.
After this work, a test run sizes its xdist worker count to the memory that is free when it
starts. It waits a bounded time when memory is short. It recovers from a worker crash by
re-running only the tests that never finished. SDD fan-out starts no more units than memory
allows, and always at least one.

Inputs: `idea.md`, `answers.md` and the `research_*.md` files in this directory.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| test runner | coined | The generic script `run_tests.py` that wraps one pytest command: memory gate, xdist worker sizing, crash recovery, verdict. No existing term; `select_tests.py` only chooses the command. |
| pytest attempt | coined | One pytest process the test runner starts. The first runs the command; a later one re-runs unfinished tests. Distinct from the fan-out unit and batch "attempts" in `fanout_recipe.md` and `implement_plan.md`. |
| unfinished test | coined | A test the pytest attempt collected that has no final outcome: the test running on an xdist worker when it crashed, and every test queued behind it. |
| memory capacity | coined | How many units of a given size fit in free memory now, as printed by `run_tests.py --capacity`. |

## Scope

In:

- A test runner in the `django-stack` plugin that every tier run goes through.
- Memory-aware xdist worker count, bounded wait, crash detection, retry of unfinished tests only,
  a single verdict.
- Memory capacity checks before SDD batch waves and before the fan-out recipe's parallel workers.
- FLS values for the thresholds.

Out:

- Splitting the suite into checkpointed sections. The crash retry is the resume (`answers.md`).
- A lock or queue shared across worktrees. Each run checks memory for itself (`answers.md`).
- Dev servers and Playwright MCP browsers started by QA.
- macOS and Windows memory readings. On a platform without `/proc/meminfo` the runner skips the
  gate and sizing and says so.
- The single-test TDD run (`uv run pytest <file>::<test> -x --no-cov`) stays a bare pytest call.
- CI. `.github/workflows/tests.yml` keeps calling pytest directly.

## Decisions

- **Gate on free memory, size xdist workers by it.** This is the root-cause fix. The crash retry
  is the safety net.
- **`MemAvailable` sizes, PSI gates, swap in use is ignored.** This machine has 20 GB swapped at
  idle, so a swap-used threshold would wait forever. PSI catches thrashing that `MemAvailable`
  misses.
- **An explicit `-n <k>`.** It bypasses the root `conftest.py` hook `pytest_xdist_auto_num_workers`
  (cap 4), which stays for CI and bare `-n auto` runs.
- **`--max-worker-restart=0`.** xdist's own restart brings a replacement worker up under the same
  pressure. Failing fast hands recovery to the runner.
- **Completion is recorded by a pytest plugin, not read from `--lf`.** `--lf` reruns genuine
  failures and misses tests queued behind a crash.
- **Any worker crash is retried, whatever its cause.** A segfault is retried the same way as an
  OOM kill. Retries are bounded, and no check tries to prove memory was to blame. One exception:
  a test whose worker dies while running it in every pytest attempt, of two or more, is counted
  as failed, so a test that always segfaults ends the run `FAIL` and not `INCOMPLETE`.
- **Test processes volunteer as OOM victims.** The kernel then kills a restartable test process
  before a Claude session, the browser or the VM. The runner itself keeps its own score, because
  it holds the retry logic.
- **Fan-out capacity is a hook in the SDD config.** The `sdd` plugin cannot call `django-stack`
  scripts, so a project points `.claude/sdd/config.md` at a command that prints memory capacity.
- **Plugin defaults are unmeasured starting points.** They cannot be measured before the runner
  exists. A project measures its own `per_worker_mb`, and FLS does.

## Requirements

### Test runner: `claude_plugins/django-stack/scripts/run_tests.py`

Stdlib only, like `select_tests.py`. Wrapper `claude_plugins/django-stack/templates/wrapper_scripts/run_tests.sh`
(installed by `ds:init` as `.claude/ds/scripts/run_tests.sh`, same shape as `select_tests.sh`).
Usage: `run_tests.sh <pytest command…>` or `run_tests.sh --capacity <unit-mb>`.

**Configuration.** Precedence: env var, then `[tool.test_tiers.memory]` in `pyproject.toml`, then
the plugin default. These are the runner's own keys, not xdist options. They are validated the way
`load_tier_config` in `select_tests.py` validates `[tool.test_tiers]`: a wrong type or unknown key
exits 2 and names the key.

| Key | Env var | Default | Meaning |
| --- | --- | --- | --- |
| `per_worker_mb` | `DS_TEST_PER_WORKER_MB` | 1024 | Memory one xdist worker needs |
| `reserve_mb` | `DS_TEST_RESERVE_MB` | 2048 | Memory left free for everything else |
| `max_workers` | `DS_TEST_MAX_WORKERS` | `os.cpu_count()` | Ceiling on `-n` |
| `psi_some_avg10_limit` | `DS_TEST_PSI_LIMIT` | 10.0 | Wait while `some avg10` in `/proc/pressure/memory` is above this |
| `wait_timeout_s` | `DS_TEST_WAIT_TIMEOUT_S` | 600 | Longest wait before running with 1 xdist worker |
| `max_retries` | `DS_TEST_MAX_RETRIES` | 2 | Crash retries after the first pytest attempt |
| `oom_score_adj` | `DS_TEST_OOM_SCORE_ADJ` | 500 | Set on the pytest child; 0 skips |

`DS_TEST_MEMORY_GUARD=off` runs the command unchanged: no gate, sizing, retry or extra lines.

Test-only seams, kept out of the user-facing table: `DS_TEST_MEMINFO_PATH` and `DS_TEST_PSI_PATH`
replace the `/proc` paths, and `DS_TEST_TIME_SCALE` multiplies every sleep, poll and timeout.

**Gate and sizing**, before every pytest attempt:

1. Before the first pytest attempt only, sleep a random 0 to 5 s, so worktrees started together
   don't all read the same free figure.
2. `fit = floor((MemAvailable − reserve_mb) / per_worker_mb)`. When `fit ≥ 1` and PSI is under its
   limit, run with `k = min(fit, max_workers)`, or on a retry `min(fit, max_workers, ⌈previous k / 2⌉)`.
   A missing PSI file never blocks.
3. Otherwise wait. Poll every 5 s. Print one line when the wait starts, then one every 60 s, then
   one when it ends. When `wait_timeout_s` passes, run with `k = 1` and say so.

**Building the command.** The runner appends its options to the end of the argv it is given:
`-n <k> --max-worker-restart=0 -p ds_run_record --ds-record=<file>`. An argv with no `-n` gets no
xdist options; the gate still applies. A later `-n` overrides the command's `-n auto`. A number
the command gives (`-n 2`) is a ceiling on `k`, and `-n 0` is treated as no `-n`.

**Accepted commands.** The runner runs only a pytest command: an argv that starts with `pytest`,
`python -m pytest`, `python3 -m pytest`, `uv run pytest` or `uv run --directory <dir> pytest`. Any
other argv exits 2 and names the accepted forms, before the gate and whatever
`DS_TEST_MEMORY_GUARD` says. A project allows the wrapper prompt-free, so it must not become a way
to run an arbitrary command.

**Each pytest attempt:**

- Starts pytest in its own session (`start_new_session=True`), with the scripts directory added to
  `PYTHONPATH`. The child sets its own `oom_score_adj` before exec, and the runner's score stays as
  it was.
- The runner marks itself a child subreaper (`prctl(PR_SET_CHILD_SUBREAPER)` through `ctypes`,
  Linux only). Processes that detach, such as the Chromium Playwright launches, then re-parent to
  the runner when their parent dies. When the pytest attempt ends, the runner kills every
  descendant it still has, found through `/proc`, before it reads memory again. SIGINT or SIGTERM
  to the runner does the same, then exits.

**Record plugin: `claude_plugins/django-stack/scripts/ds_run_record.py`.** It records on the
controller only: a process with `config.workerinput` writes nothing. It appends JSON lines to the
record file and flushes each one:

- The collected node ids, deduplicated. With xdist they come from
  `pytest_xdist_node_collection_finished`, marked `@pytest.hookimpl(optionalhook=True)` so the
  plugin loads without xdist. Without xdist they come from `pytest_collection_finish`.
- One line per test when its outcome is final, from `pytest_runtest_logreport`. An outcome is final
  at the teardown report, or at the first setup or call report that is not a pass (a skip at setup
  is final). A report whose longrepr carries xdist's `worker '<id>' crashed while running` text is
  marked `crashed` and is never final.
- One `finished` line from `pytest_sessionfinish`, so the runner can tell a session that ended on
  its own from one whose controller was killed.

With `--ds-only-nodeids=<file>` the plugin deselects every collected item not in the file, in
`pytest_collection_modifyitems`, so a retry keeps the command's markers, paths and options.

**Classification** after each pytest attempt:

- **Crash**: the record has a crashed line, or it has no `finished` line and the exit code shows
  a death by signal (negative, or above 128 as `uv run` reports it): the controller was killed.
  A crashed line is written for xdist's crashed report and for any worker that goes down with an
  error, which covers a worker killed while collecting or idle. The unfinished tests are retried.
  Genuine failures already recorded are kept and never retried.
- **Exit before a session**: no `finished` line and an ordinary exit code. pytest stopped on its
  own (a usage error, a conftest that fails to import, `--help`). It is not retried and its exit
  code passes through.
- **No crash**: the pytest attempt's results are final. A session that finished on its own with
  tests still unfinished stopped on purpose (`-x`, `--maxfail`) and is not retried.
- When the controller died before collection was recorded, the next pytest attempt runs the whole
  command again.

**Retry.** Up to `max_retries` times: back off 30 s, then 60 s, then run the gate again, then run
the unfinished tests through `--ds-only-nodeids`. A retry appends `--no-cov` when `pytest_cov` is
importable, because a subset run must not fail a coverage threshold.

**Output.** Every runner line starts with `ram:` or `run:`, has no colour, and gives counts rather
than node-id lists. The full detail goes in the record file, and its path is printed once. The
runner deletes the record file after `RESULT PASS` and keeps it otherwise. The lines are:

- At launch: one `ram:` line with `MemAvailable`, PSI, the chosen `k` and where each non-default
  setting came from.
- On a crash: `run: pytest attempt <n>/<max_retries + 1> crashed (<unfinished> tests unfinished); backing off <s> s, retrying with -n <k>`.
- At the end, last in the output:

  ```
  run: pytest attempts <n>, xdist workers <k1> -> <kn>
  run: tests <collected> collected, <finished> finished, <failed> failed, <unfinished> unfinished
  run: summary (merged): <n> passed, <n> failed, <n> skipped in <s>s
  run: RESULT PASS|FAIL|INCOMPLETE
  ```

Exit codes: PASS 0. FAIL 1. INCOMPLETE 75, when retries ran out with tests still unfinished. That
is neither a pass nor a code defect. Any other pytest exit code (2 to 5) with no crash passes
through.

**`--capacity <unit-mb>`** prints one integer, `max(1, floor((MemAvailable − reserve_mb) / unit-mb))`,
and exits 0. Without `/proc/meminfo` it prints a large number (fail open).

### `select_tests.py` and the tier docs

- `claude_plugins/django-stack/scripts/select_tests.py`: when `.claude/ds/scripts/run_tests.sh`
  exists under the project root, `FULL_COMMAND` and `TARGETED_PREFIX` start with it, e.g.
  `command: .claude/ds/scripts/run_tests.sh uv run pytest -n auto --no-cov …`. Otherwise they stay
  as today, so a project that has not re-run `/ds:init` keeps working. Memory is read only at run
  time, so the printed line stays deterministic for a given tree.
- `claude_plugins/django-stack/resources/test_tiers.md`:
  - The full tier and the `--lf` re-run in "When a targeted run or full run fails" go through the
    runner.
  - The tier doc names its verdict line: `run: RESULT …`, preceded by `run: summary (merged)`.
    Reporting quotes both, not pytest's own last line. `INCOMPLETE` is reported as blocked on
    memory, not as a failure to fix.
  - The settings table and precedence live here, once.
  - A crash retry happens inside the one background run, so the "no `ps`/`pgrep` loops, no
    `timeout` wrapper" guardrail is unchanged.
- `claude_plugins/sdd/commands/protected/run_test_tier.md`: the report quotes the verdict line the
  project's tier doc names, when it names one. `sdd` never spells out the `run:` format. The
  blank-hook fallback still runs bare `uv run pytest`.

### SDD fan-out

- `claude_plugins/sdd/commands/init.md`: the `.claude/sdd/config.md` template, under
  `## Worktree Scripts`, gains three keys, all shipped blank and documented next to
  `Parallel batches`:
  - `Memory capacity:` a command that takes a unit size in MB and prints memory capacity
  - `Batch memory (MB):` the size of one batch: its subagent, Setup script and targeted test run
  - `Worker memory (MB):` the size of one fan-out worker

  A blank `Memory capacity` or a blank size means no check.
- `claude_plugins/sdd/commands/implement_plan.md` **Batch waves**: the batch wave becomes the
  first `min(len(ready), cap, capacity)` of `ready`. `capacity` is the `Memory capacity` command's
  output for `Batch memory (MB)`, read just before each batch wave forms. A batch wave of one is
  unaffected. A batch that dies from memory still counts against the existing two-retry budget.
- `claude_plugins/sdd/skills/claude-code-authoring/resources/fanout_recipe.md` point 4: when
  `Worker memory (MB)` and `Memory capacity` are set, spawn at most `capacity` workers at first.
  Then, as each one returns, re-read capacity and top up from the remaining units. When either is
  blank, spawn every unit at once as today. The commands that restate the recipe follow the same
  rule: `spec_from_idea.md`, `spec_review.md`, `plan_from_spec.md`, `roadmap.md`.

### FLS values

- `.claude/ds/scripts/run_tests.sh`: the wrapper `ds:init` generates, committed like its siblings,
  with its three allow entries in `.claude/settings.json` (bare, `./` and `bash` forms).
- `pyproject.toml` `[tool.test_tiers.memory]`: `max_workers = 4`, matching the root `conftest.py`
  cap. `per_worker_mb` is set from a measurement: the peak RSS of one xdist worker plus its
  Chromium during a full-tier run, rounded up to the next 256 MB.
- The measurements are taken by sampling `/proc` during a run, with a throwaway sampler that is
  not committed. No measuring tool is added.
- `.claude/sdd/config.md`: `Memory capacity: .claude/ds/scripts/run_tests.sh --capacity`, plus
  measured `Batch memory (MB)` and `Worker memory (MB)`.
- `claude_plugins/fls-dev/skills/testing/SKILL.md`: the measured FLS values and how to re-measure
  them.

## Testing

- `tests/test_run_tests.py`, using the stub-tool pattern in `tests/stub_tools.py` and the test-only
  seams (fake meminfo, fake PSI file, `DS_TEST_TIME_SCALE`):
  - the xdist worker count follows free memory, capped by `max_workers` and floored at 1
  - the wait prints its heartbeat lines, and after the timeout the run uses 1 xdist worker
  - PSI above the limit waits; a missing PSI file does not
  - an env var beats pyproject, which beats the default; a bad or unknown key exits 2 and names it
  - `DS_TEST_MEMORY_GUARD=off` runs the command byte-for-byte
  - an argv that is not a pytest command exits 2 and runs nothing, with the guard on or off
  - `--capacity` arithmetic, and fail-open without meminfo
- Crash recovery runs real pytest against a throwaway test package in `tmp_path`, with its own
  config file so the repo's `addopts` don't apply. One test SIGKILLs its own xdist worker on the
  first pytest attempt only. Then:
  - the retry runs only the unfinished tests, with half the xdist workers
  - retries exhausted gives INCOMPLETE, exit 75; a test that kills its worker in every pytest
    attempt gives FAIL, exit 1
  - the merged summary counts every test exactly once
- `ds_run_record.py`: `--ds-only-nodeids` deselects the rest with and without xdist, and the plugin
  loads when xdist is absent.
- Process cleanup: a detached grandchild the test leaves running is gone when the pytest attempt
  ends. The pytest child has `oom_score_adj` 500, and the runner keeps its original value.
- `tests/test_select_tests.py`: the expected `command:` strings gain the runner prefix when the
  wrapper exists, and stay unchanged when it doesn't.

## Open questions

- Q: Is a Claude Code subagent its own OS process, and so worth sizing? → A: Assumed yes; FLS sets
  `Worker memory (MB)` from a measurement. (assumed default: when the measurement shows workers
  cost little, the key stays blank and nothing changes. Overrule by editing "SDD fan-out".)

## Success criteria

- With `MemAvailable` too low for one xdist worker, a full tier waits, prints a heartbeat each
  minute, and after `wait_timeout_s` runs with `-n 1`.
- With room for two xdist workers, the `ram:` line shows `-n 2` even though `max_workers` is 4.
- A run whose xdist worker is SIGKILLed once ends `RESULT PASS`, counts every test once, and does
  not re-run the tests that finished.
- A run with a genuine failure and a crash ends `RESULT FAIL`, and the failing test ran once.
- During a tier run, `/proc/<pytest pid>/oom_score_adj` reads 500 and the runner's own value is
  unchanged.
- `grep -rni "freedom\|fls" claude_plugins/django-stack/scripts/run_tests.py claude_plugins/django-stack/scripts/ds_run_record.py claude_plugins/sdd/commands/init.md`
  finds no new match.
