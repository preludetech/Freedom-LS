# Spec: retire content that is removed from the source

## Purpose

A `content_save` run adds and updates content but never takes any away, so a Topic, Form or
FormQuestion deleted from the content repo stays in the database and is still served. SACAA
requires that a withdrawn question is blocked from learners yet kept for audit, and deleting is
not possible because learner rows hold content with PROTECT. This spec makes one `content_save`
run cover a site's whole source. Content missing from the run is **retired**: no learner is served
it, every learner record that points at it is kept, educators see it marked, and it is un-retired
if it comes back. Background and settled decisions: `idea.md`, `answers.md`.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| retired | narrowed | Glossary (`claude_plugins/fls-dev/skills/domain-glossary/SKILL.md`) uses it for `JobTitle`, `Department`, `Location` entries with `is_active=False`. Here it also means a content row whose `retired_at` is set: not served to learners, never deleted. Never "inactive", "deactivated", "removed" or "archived". |
| retirable models | coined | The twelve models that carry `retired_at`: `Course`, `CoursePart`, `Topic`, `Activity`, `Article`, `Form`, `FormPage`, `FormContent`, `FormQuestion`, `QuestionOption`, `CourseCategory`, `File`. |
| un-retire | coined | A later `content_save` run that finds a retired row's uuid (or a `File`'s path) clears its `retired_at`. |
| live | coined | Not retired: a row of a retirable model whose `retired_at` is null. Used in identifiers (`live_children`). |

## Scope

In: a `retired_at` state on the retirable models, set and cleared by `content_save`; every
learner-facing read leaving retired rows out; progress, registrations, the educator interface, the
cohort report and the Django admin following suit; the glossary, product docs and upgrade notes.

Out: question versions (`sacaa-compliance-content-versions-and-access-3-question-versions`); git
checks, several paths and missing-uuid refusal (spec 1, done); the question-viewing role and admin
question page removal (`sacaa-compliance-content-versions-and-access-4-question-access`); deleting
content or changing `danger_content_delete`; `content_snapshots`; changing `Course.visibility` or
`Article.visibility`; building drawing pages (`sacaa-compliance-3-question-pools`); any per-row
audit entry for a retire; a lock between overlapping `content_save` runs.

## Decisions

- **The filter is explicit, never in a manager.** `objects`, `_base_manager` and the reverse
  related managers stay unfiltered, because un-retiring upserts, `danger_content_delete`, the admin,
  reports, audit reads, `QuestionAnswer.selected_options` and pinned papers all need retired rows.
  Learner-facing reads opt in to the filter by name.
- **One timestamp per run.** Every row a run retires gets the same `retired_at` (`run_time`), so
  "what did this save retire" is one query.
- **Each row retires by its own absence.** Retirement never cascades to children and is never
  stamped on them. A child whose own uuid is still in the source stays live, and learner reads skip
  it because its parent is skipped.
- **Retired overrides visibility, the visibility override and registration.** A retired `Course` is
  closed to every learner, registered or not, on every environment. This is unlike
  `CourseVisibility.HIDDEN`, which lets registered learners in.
- **Learners get a plain 404.** A link to retired content gets the same response as a missing page.
  There is no new learner copy.
- **Pinning is for quiz papers only.** A quiz sitting finishes on its `served_paper`. A sitting with
  no served paper (surveys, `CATEGORY_VALUE_SUM`) reads the live tree, so a question retired
  mid-sitting drops out of the pages still to come.
- **`retired_at` is the general state; `dropped_from_source_at` is the narrower one.**
  `FormQuestion.dropped_from_source_at` is set by `mark_dropped_questions` only for a question that
  leaves a form file the run still loads, and the same run retires that question. A question under
  a removed form, page, topic or course is retired without it. A question is out of revision when
  either is set. A question that returns to its file is seen by the run, which clears both.
- **Revision history is kept on retire.** The retire sweep sends no `form_questions_dropped`, so
  `RevisionSchedule` and `RevisionReview` rows stay and an un-retired question comes back with the
  learner's schedule. The handler for a dropped question is unchanged.

## Requirements

### Models and migrations

- Add `retired_at = models.DateTimeField(null=True, blank=True, db_index=True)` to the existing
  abstract `BaseContent` (`freedom_ls/content_base/models.py`, covering ten of the models), and
  declare the same field on `QuestionOption` (`freedom_ls/form_engine/models.py`) and `File`
  (`freedom_ls/content_engine/models/files.py`). No new abstract class. One `AddField` migration
  each in `content_engine` and `form_engine`, with no backfill.
- Add an `is_retired` property, and a queryset method `not_retired()` for the retirable models that
  learner reads query directly (`Course`, `CourseCategory`, `Article`, `Form`, `File`). Follow
  `ArticleQuerySet.published()` / `ArticleManager` in `content_engine/models/articles.py`, keeping
  `SiteAwareManager` behaviour. `ArticleQuerySet` gains `not_retired()` next to `published()`. The
  method is written once, on a shared `RetirableQuerySet` in `content_base/models.py`, reached
  through a `RetirableManager` that is `objects` on `BaseContent`, `QuestionOption` and `File`, so
  every retirable model has it. The manager itself filters nothing.
- `ContentCollectionItem` gets no field. A collection item left behind by a child's move to another
  collection keeps its present behaviour (`content_engine/moved_children.py`).

### `content_save` (`freedom_ls/content_engine/management/commands/content_save.py`)

- **Mark.** `_write_source` collects the pk of every row it saves, per retirable model, and the
  relative path of every `File` it sees. `_write_sources` merges these sets across all paths.
- **Un-retire.** `save_with_uuid` always writes `retired_at=None` in its `defaults`, so the content
  update and the un-retire are one write. `save_file_to_db` clears `retired_at` on an existing
  `File`.
- **Sweep.** After the `for source in sources` loop and before the `ContentSave` row is written,
  inside the same `@transaction.atomic`: for each retirable model,
  `_base_manager.filter(site=site, retired_at__isnull=True)`, excluding the seen pks (seen paths for
  `File`), `.update(retired_at=run_time, updated_at=run_time)`. It covers every row of the site, whether or not it came
  from a file. A run that fails or rolls back retires nothing.
- **Opt-in.** `save_content_to_db` gains `retire_missing: bool = False` and
  `allow_course_retire: bool = False`. The `content_save` command always passes
  `retire_missing=True`. Without it the function runs no sweep and no course guard, so existing
  callers (tests, `demo_content_fixtures.py`, downstream projects) are unchanged.
- **Course guard.** Before the first write, compare the `Course` uuids parsed from all paths with
  the site's live courses. When any live course is missing, refuse the run and name each course
  (title and uuid) and the `--allow-course-retire` flag, which the command gains and passes as
  `allow_course_retire`. A second check after the sweep is the backstop: it fails and rolls back if
  the sweep retired a course anyway.
- **Drawing pages.** When a drawing page's pool, with retired questions (and the whole group of any
  retired grouped question) taken out, has fewer items than its draw count, the save fails and names
  the page. `sacaa-compliance-3-question-pools` builds this check on the live-children function
  below.
- **Output.** After the transaction commits, the same way `removal_lines` and the `Images:` summary
  are printed, print one count line per run with per-model counts, zeros included:
  `Retired: 3 (Topic 1, FormQuestion 2). Un-retired: 1 (Topic 1).` A rolled-back run prints neither.
  Un-retired counts come from rows whose `retired_at` was set before the upsert.
- **Progress.** Add a signal, `course_retirement_changed`, in `content_engine/signals.py` that is
  sent once per course whose tree had a row retired or un-retired. Find those courses through the `ContentCollectionItem`
  placements of each retired or un-retired child, going on from a `CoursePart` to its course. Its
  receiver in `learner_progress/signals.py` calls `recalculate_progress_percentage` for each
  `CourseProgress` of the course, guarding the empty case as
  `recalculate_course_progress_on_placement_removal` does.
- **Slug collisions.** When `_refuse_article_slug_collisions` or `_refuse_category_slug_collisions`
  refuses a slug held by a retired row, the message says the owner is retired.

### Learner reads: courses and categories

- `VisibilityEnforcingBackend.filter_visible` (`course_access/backends.py`) excludes retired
  courses before the `override_visibility_to_visible()` early return and outside the registration
  exemption. `_visibility_decision` returns the closed decision for a retired course before its
  override branches and every visibility check.
- `raise_404_if_unavailable` (`course_access/visibility.py`) and `_course_access_decision`
  (`learner_interface/views.py`) raise 404 for a retired course. That covers every player view that
  looks up a course by slug (`view_course_item`, `form_start`, `form_fill_page`,
  `course_form_complete`, `course_reference`, `course_reference_topic`, `course_finish`,
  `form_submit_and_exit`) and the `course_applications` and `course_interest` views.
- `get_all_courses` and `get_course_registrations` (`learner_interface/utils.py`) leave out retired
  courses. That covers the catalogue, discovery, the dashboard and the completed-courses history.
- Retired `CourseCategory` rows leave the dashboard category list (`learner_interface/views.py`
  `CourseCategory.objects.filter(show_on_dashboard=True)`) and the catalogue's category filters. A
  course stays listed when its `dashboard_category` or a `categories` entry is retired.
- The public blog (`blog/views.py`) chains `not_retired()` after `published()` on the index and on
  `article_detail`. The sitemap leaves out retired articles and courses.

### Learner reads: course outline

- `Course.collection_items()` and `CoursePart.collection_items()`
  (`content_engine/models/courses.py`) stay unfiltered for the educator outline.
- `collection_items_flat()` skips a collection item whose child is retired, and the whole subtree of
  a retired `CoursePart`, in Python on `item.child.retired_at` after the generic
  `prefetch_related("child")`. `viewable_collection_items()` and `children_flat()`, which build on
  it, are therefore filtered, and so are `viewable_items()`, `lesson_count()` and
  `includes_assessments()`. The skip is one helper, `live_collection_items(collection)`, which
  the other outline readers below use too.
- `collection_items_flat`, `viewable_collection_items` and `viewable_items` each take
  `include_retired: bool = False` and keep retired collection items when
  asked. If either is memoized, the keyword is part of its memo key. The cohort report and the
  deadline admin use it.
- The learner outline sidebar, status and breadcrumb readers skip retired children too:
  `get_course_index`, `get_content_status`, `create_child_dict_with_flattened_index`
  (`learner_interface/utils.py`) and `get_item_part` and the breadcrumb lookup
  (`learner_interface/views.py`). Their indexes match the filtered player indexes.
- `course_reference_topics` and the reference views skip retired parts and topics.
- Player navigation (`player-nav.html`, `player-footer.html`), the progress bar and
  `get_resume_index` read the filtered list. Collection item indexes shift when an earlier one
  retires, and `get_resume_index` already falls back to the first item.
- Markdown links to a retired `Topic` or `Form` (`content_engine/templatetags/content_tags.py`)
  render as unresolved. `get_file_by_path` and the `audio_file` view (`content_engine/views.py`)
  treat a retired `File` as missing.
- `deadlines/resolver.py` ignores retired collection items, and the deadline pickers do not offer
  them. Deadline rows stored on them are kept.

### Learner reads: forms and questions

- Add `live_pages(form)`, `live_children(page)` and `live_options(question)` in `form_engine`: a
  form's non-retired pages, a page's non-retired children and a question's non-retired options.
  `build_served_paper` (`_served_children`, `_served_options` in
  `form_engine/served_paper.py`), `compute_path` (`form_engine/conditions.py`) and the unpinned
  branch of `FormProgress._quiz_questions` use them, before `shuffle_units` and any shuffle. A group
  is served without its retired member, and a group with no live member disappears. Retired
  `FormPage` rows are left out too. A gate whose `condition_option` belongs to a retired question
  never opens.
- `served_path`, `frozen_path` and `full_path` stay unfiltered, so a pinned or finished sitting keeps
  its retired questions and options and its `max_score`.
- Scoring and answer review read the options the sitting was offered plus the non-retired options
  added since: the served paper's options when it has one, the non-retired options when it does
  not. A correct option added after the sitting was marked counts, and the review then says "This
  quiz has changed since the attempt was marked". That covers
  `FormProgress.compute_quiz_scores`, `get_incorrect_quiz_answers` (its correct options), every
  `is_quiz_answer_correct` caller and `form_engine/scoring.py` `evaluate_quiz_answers`.
- A retired `Form` is not served, because the outline skips its placement. `course_applications`
  refuses a retired `Course.application_form` the way it refuses a missing one. An in-progress
  `FormProgress` on a retired form stays as recorded.
- `form_engine/views.py` answer-file upload keeps looking questions up without the filter, so a
  pinned paper can still be answered.
- Learner-facing counts and numbering (`count_form_questions` callers,
  `FormQuestion.question_number`) leave out retired questions when the sitting has no served paper.
- Revision (`freedom_ls/revision/queries.py` `_revisable_questions`, which every bank read goes
  through: the bank, the card, the dashboard and outline counts, the ready count) leaves out a
  retired question, a question whose `FormPage` or `Form` is retired, and a question whose only
  correct option is retired. A session skips a question retired after it started. The card shows,
  accepts and marks against `live_options(question)` only.

### Registrations

- `require_course_open_to` (`learner_management/queries.py`) raises a new
  `CourseRetiredError(CourseNotOpenError)` for a retired course. That covers `self_register`,
  `register_cohort_for_course` and reactivating an existing registration.
  `registration_rules/evaluation.py` `apply_rule_changes` skips a retired `rule.course`.
- `registerable_courses`, `registerable_courses_for` and `registerable_courses_for_learner` leave out
  retired courses, which takes them out of the educator add-registration forms and the bulk actions.
- No registration's `is_active` changes when content retires.

### Progress and completion

- `completable_items` (`learner_progress/utils.py`), `calculate_course_progress_percentage` and
  `outstanding_items` (`learner_interface/utils.py`) read the filtered outline, so retired children
  are out of totals and completion checks. A learner who has finished every live child completes at
  `course_finish`.
- A `CourseProgress` with `completed_time` set keeps it. `TopicProgress`, `FormProgress`,
  `QuestionAnswer`, `CourseFormAttempt` and `CourseProgress` rows on retired content are not
  changed.

### Educator interface and reports

- Add `retired_badge(retired_at: datetime | None) -> StatusBadge | None` beside `inactive_badge` in
  `educator_interface/panels/common/badges.py`: `StatusBadge("muted", "Retired")`, or `None` when
  live. Render it with `<c-panel-status-badge>`; add no new component.
- It appears:
  - in `CourseDataTable` (`panels/course/data_tables.py`) as a badge column, and in the course page
    header `badge` slot. The course detail shows "Retired on <date>" in its definition list.
  - on outline, form page, question and option rows of the course content preview
    (`panels/course/content_preview.py`), via a `retired: bool` on `OutlineRow`, in `reference_rows`,
    and in `_form_preview_context`.
  - on course-title cells in learner and cohort registration lists (`panels/learner/`,
    `panels/cohort/`).
  - in course filter choices (`panels/common/filters.py`), through a `mark_retired: bool = False`
    keyword on `Course.label_for` that only that module sets.
- Retired content stays listed and openable in the educator interface. `courses_visible_to` keeps
  retired courses.
- Cohort report (`reports/indexes.py` `build_course_catalogue`, `load_quiz_questions`;
  `reports/gather.py`): `build_course_catalogue` reads `viewable_items` with retired children
  included. A retired Topic or Form stays a column, carrying the Retired badge and the recorded
  progress and answers, and is left out of completion denominators. The PDF matches the screen.
- Every educator view that shows a `QuestionAnswer` marks a retired question and a chosen retired
  option, and shows the answer in full. Today those are the cohort report's quiz columns and wrong
  answers (`reports/gather.py` `_build_quiz_columns`, `build_wrong_answers_by_learner_quiz`) and the
  admin answers page (`answer_groups`, `admin/form_engine/_answers.html`). No educator-interface
  panel shows answers yet.
- `freedom_ls/educator_interface/tests/invariants/` rules hold for the new column and badges.

### Django admin

- No retired filter or column. `remove-unnecessary-admin-panel-functionality` deletes the content and form admins, so no
  changelist of a retirable model is left. The admin answers page marks retired answers, as the
  Educator section says.

## Testing

- Sweep: a row missing from the run is retired with the run's timestamp; a row seen in any one of
  several paths is not; a `File` retires and un-retires by path; a second identical run changes
  nothing; a run that fails after the sweep leaves every `retired_at` as it was;
  `save_content_to_db` without `retire_missing=True` retires nothing.
- Un-retire: a returning uuid clears `retired_at` in the same write as its content update, and its
  learner data shows again.
- Course guard: a run missing a course is refused before any file is written or uuid added, names
  the course, and passes with `--allow-course-retire`.
- Output: count lines appear after commit, zeros included, and nothing is printed for a rolled-back
  run.
- Progress: after a retire, the stored `progress_percentage` of each affected course is
  recalculated.
- Leak tests, one per learner surface, each with a retired row present: catalogue, course list,
  completed history, course detail and player 404, outline sidebar and breadcrumb, navigation,
  progress bar, reference pages, blog and sitemap, markdown links and file embeds, `audio_file`,
  categories, registration service functions and pickers, application form, and the visibility
  override.
- Served paper: a new paper omits retired questions, options, content and pages; a group loses only
  its retired member; a group with no live member is gone; nothing retired is ever shuffled in.
- Pinning: a quiz sitting started before a question retires still serves, accepts and scores it,
  and keeps its `max_score`. A sitting started after does not get it. A survey sitting drops it
  from the pages still to come.
- Scoring: a retired correct option left off a paper neither makes an answer wrong nor shows as
  the correct answer in the review. The review shows "This quiz has changed since the attempt was
  marked" when a live correct option was added since.
- Revision: a retired question, a question on a retired page or form, and a question whose only
  correct option is retired is not banked, ready or counted; a session skips a question retired
  after it started; the card leaves out a retired option and refuses one that is posted; an answer
  is marked against live options; a question made live again is banked with its schedule kept; one
  run that drops a question from a kept form and removes another form retires both and marks and
  announces only the first as dropped.
- Completion: retired children leave the percentage and the outstanding list; a learner with every
  live child done completes; a course with every child retired keeps its records.
- Records kept: `FormProgress`, `QuestionAnswer` with its selected options, `TopicProgress`,
  `CourseProgress` (completed ones stay completed), `CourseFormAttempt` and both registration types
  are unchanged after a retire, and `is_active` is unchanged. `RevisionSchedule` and
  `RevisionReview` rows are unchanged too.
- Educator: the Retired badge shows on each surface listed above, and retired content stays
  listed; the cohort report shows a retired column outside the denominator and marks answers to
  retired questions; the admin answers page marks a retired question and a chosen retired option.

- Glossary (`claude_plugins/fls-dev/skills/domain-glossary/SKILL.md`): add the content sense of
  **retired** to "Words with an existing meaning", and mention it in the `is_active` row's retired
  exception.
- `docs/product/content-editing-workflow.md`: removing content from the source retires it, the
  `--allow-course-retire` flag, and un-retire.
- `docs/product/learner-experience.md` Revision: revision banks follow retire and un-retire.
- The `fls-content` plugin's `content_save` guidance and
  `claude_plugins/fls-dev/resources/markdown_content.md`: the same points.
- Upgrade notes (`/fls-dev:update_upgrade_notes`): migrations required; the first `content_save`
  command against an existing site retires every row it does not find, hand-made and QA rows
  included, and refuses if that would retire a course; direct `save_content_to_db` callers stay
  additive unless they pass `retire_missing=True`.

## Success criteria

- A content row deleted from the source is never shown to any learner after the next
  `content_save`, and every learner row pointing at it still exists.
- The same row returned to the source with its uuid is served again after the next run.
- A quiz attempt in progress when a question retires finishes with that question and an unchanged
  `max_score`.
- `uv run pytest` passes.
