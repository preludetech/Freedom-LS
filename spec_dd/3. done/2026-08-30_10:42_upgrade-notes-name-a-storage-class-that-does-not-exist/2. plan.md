## Task B: the root `.env.example`

Port the storage block from `spec_dd/3. done/2026-08-27_12:32_prod_bucket_setup/env_example`
(lines 82-168, the six `AWS_S3_<PURPOSE>_BUCKET_NAME` variables at :105-119) into `.env.example`,
replacing the single-bucket block at lines 82-98. Keep the root file's house style for the
surrounding sections.

The three defects to close:

1. No per-purpose bucket variables. A project copying this file gets every alias falling through the
   shared name into one bucket, which is the E003 condition plus E001 for whichever alias matches
   `default`.
2. Line 83 calls `AWS_STORAGE_BUCKET_NAME` "also the on/off gate: unset uses local `FileSystemStorage`
   instead". `build_storages()` has no such conditional, and the guidance is the opposite: leave it
   unset in production so a misspelled per-bucket variable fails loudly
   (`freedom_ls/deployment/checks.py:262-265`).
3. Lines 93-96 present `AWS_S3_CUSTOM_DOMAIN` with `AWS_QUERYSTRING_AUTH=False` as a plain opt-in,
   with no warning that the shared form reaches every media alias. That is the hazard E004 catches.

**Access note.** `.claude/settings.json` denies `Read(.env.*)`, which matches `.env.example` and fires
before the `PreToolUse` hook written to exempt it. This task is blocked until that rule is narrowed.
