# Frontend QA — split into several plans

**This file has been split. Do not run it.** It is kept only as a signpost, because tooling and earlier
documents look for `3. frontend_qa.md` at this path. The original single-feature plan is in git history at
commit `cabce8c0`.

## Why it was split

This branch stacks two features that have never been QA'd together.

`extract_forms_into_seperate_app` is finished and merged into `main`; its QA ran on its own branch and
passed clean. `better_course_progress_tracking` then landed on top and reached into the seam that split
created — `FormProgress.form` became `PROTECT`, `form_attempt_completed` gained an `attempt` kwarg, and a
new join model `CourseFormAttempt` binds a `form_engine` attempt to a `learner_progress` record.

The first QA run of this branch also **ran out of budget** and left twelve sections unexecuted, including
two success criteria, and three bugs were fixed after it finished.

So the work split three ways: what has never been tested, what was never reached, and what may have been
broken underneath.

## The runs

Each plan lives in its own directory, so each writes its own `qa_report.md` and `screenshots/` and **no run
can delete another's artifacts**. They are independent and can be run in any order, by different
people, from fresh contexts.

| Plan | Covers | Priority |
|---|---|---|
| `3a. seam_qa/frontend_qa_seam.md` | S1–S10 — where the two features meet: which record a form completion credits, the `CourseFormAttempt` join row, placement-keyed attempts, `PROTECT` on answered content, `danger_content_delete`, cohort-report attempt filtering, the deadline grain mismatch | **Highest — none of it has ever been run** |
| `3b. progress_gaps_qa/frontend_qa_progress_gaps.md` | G1–G11 — the progress-tracking sections run 1 never reached, including success criterion 6 (shared content) and criterion 9 (per-organisation deadlines), plus regression checks on run 1's three fixes | High |
| `3c. form_engine_regression_qa/frontend_qa_form_engine_regression.md` | R1–R9 — the form_engine plan re-walked against this branch: the signal substitution, content types, the render-time templatetag, the admin, adversarial branches. **Owns the mobile and tablet passes for every run on this branch** | Medium |
| `3d. report_smoke_qa/frontend_qa_report_smoke.md` | RS1–RS7 — a smoke test of the cohort report, added after the branding feature shipped. One short report for an organisation with a name and logo: does it still generate on this branch, and are its numbers real? | Medium — run it before the branding plan in `3. done/`, which is moot if this fails |

Run them with, for example:

```
/fls-dev:do_qa "spec_dd/2. in progress/better_course_progress_tracking/3a. seam_qa/frontend_qa_seam.md"
```

## Things that hold across all of them

- **Viewports.** `3a`, `3b` and `3d` are **desktop only** — `3d`'s artifact is a PDF at a fixed page
  size and has no responsive behaviour at all. `3c` §R9 owns the 375×812 and 768×1024 passes for the
  whole feature set, so `CLASS = FULL` firing four times does not quadruple the responsive work.
- **The todo.** These directories have no `todo.md`. Tick and append against the parent
  `spec_dd/2. in progress/better_course_progress_tracking/todo.md`, section `## 9. QA`.
- **`danger_content_delete`** belongs to `3a` §S8 only. Run it there yourself, always as
  `danger_content_delete --yes` — bare, it blocks forever on a confirmation prompt. Do not run it from
  `3b`: it wipes the content every plan depends on, so it goes last and is followed immediately by a
  re-seed from `3a` §0.1.
- **The report body checks** in `3b` §G8 are flagged human-run: reports render PDF-only, so nothing there
  can be clicked in a browser.
- **The database was rebuilt on 2026-08-25, and must stay that way.** It had been *migrated* across the
  `form_engine` rebase rather than rebuilt, so the split was never applied — `form_engine`'s migrations
  unapplied, its tables absent, and stale `freedom_ls_content_engine.form` content types left behind. Any
  course containing a form died with `AttributeError: 'NoneType' object has no attribute '_base_manager'`.
  It is correct now. Each plan's §0.0 carries the check and the drop-and-rebuild recipe, because another
  rebase puts you straight back there.
- **The two crashing seed commands are fixed.** `qa_create_report_cohort` and `qa_complete_form` used to
  raise `IntegrityError: null value in column "site_id" of relation
  "freedom_ls_form_engine_formprogress"` because `CourseFormAttemptFactory` did not pass its explicit
  `site=` down to the `FormProgressFactory` sub-factory. Fixed in `2c2b5e35`, and the whole seed was
  re-run clean on 2026-08-27. Nothing is `BLOCKED` on this any more; each plan's §0.1b keeps the history.
- **Seed commands.** Every command in these plans was checked against its real signature in this
  worktree. Both source plans had commands that exit 2 as written; the corrections are carried in each
  plan's §0. If a command still fails with a click usage error, fix the plan — that is not a product
  regression.

Original section numbers from both source plans are carried in brackets, so an existing reference to "§8",
"§12.5", "A2" or "F3" still resolves.
