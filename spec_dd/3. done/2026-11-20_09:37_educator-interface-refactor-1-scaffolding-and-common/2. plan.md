# Plan: educator interface refactor 1, scaffolding and common

Pure move. No behaviour, UI, URL, template, model or migration changes. Paths are under
`freedom_ls/educator_interface/` unless they start with `freedom_ls/`, `test_organisation/` or
`.sdd-work/`.
Line numbers are from the tree at plan time; re-find each name by grep before cutting it.

## Ground rules for every slice

- **TDD for a move.** No test is written and no assertion changes. The existing tests are the
  safety net: each slice moves code, repoints imports, then runs the targeted tier. "Red" for a
  slice is a failing import or a failing test after the cut. Fix the import, never the assertion.
- **Byte-for-byte.** Each moved name keeps its body, decorators, docstring and spelling (leading
  underscores included). Only import lines change, plus the one `OrganisationScopedRequest`
  docstring edit in slice 1.
- **Each new `panels/common/*.py` module** starts with `from __future__ import annotations` and a
  one-line module docstring stating what the module holds (never where it came from), uses only
  absolute imports (`from freedom_ls....`), and declares a sorted `__all__` listing every name the
  table in the spec gives it, underscore names included. It never imports `views`, `actions`,
  `filters`, `quick_views`, `reporting` or anything under `panels/` outside `panels/common/`. It
  may import the flat `forms.py`.
- **Imports left unused** in a shrunk module go (ruff `F401` catches them). Imports the moved code
  needs come with it.
- **String casts** such as `cast("OrganisationScopedRequest", ...)` stay quoted.
- **Patch strings:** after each slice, `grep -rn "patch\|monkeypatch" freedom_ls/` for the moved
  names. None names one today; if one appears, it names the module that looks the name up.
- **Test helpers shared by a moving and a staying test** move to `tests/helpers.py` under their
  current spelling (underscores kept, matching the production rule) and both files import them from
  there. A helper only the moving tests use moves into the new test file.
- **Commits.** Each slice is at least one commit with plain `git commit`. A test-file move is its
  own commit. The whole-file move in slice 1 is a `git mv` with no content change in that commit.
  The `test-mirroring` pre-commit hook needs each test file's module to exist when the test file is
  committed, so the production module always lands in an earlier commit or the same one.
- **Tests per slice:** targeted tier (`.claude/ds/scripts/select_tests.sh --working-tree` before
  committing, then run the printed `command:` exactly, in the background). See
  `claude_plugins/django-stack/resources/test_tiers.md`.

## Skills to use

- `fls-dev:testing` (`claude_plugins/fls-dev/skills/testing/SKILL.md`) and `ds:testing`: test
  mirroring, empty `__init__.py` in every new test directory, `conftest.py` holds fixtures only,
  helpers go in `tests/helpers.py`, keep existing markers, tests pass in any order.
- Test tiers (`claude_plugins/django-stack/resources/test_tiers.md`): name a tier before every
  pytest run; partial runs and `--collect-only` take `--no-cov`.
- `fls-dev:panel-framework`: the framework names (`LazyBodyPanel`, `render_region`, the bulk
  registry, `PermittedBulkAction`, `ReasonMixin`) stay in `panel_framework`; import them only
  through each framework module's `__all__`. Invariant tests under `tests/invariants/`
  (`test_reason_mixin.py`, `test_bulk_run_scoping.py`) must stay green.
- `ds:code-comments` and `sdd:planning-references-in-code`: new module docstrings state purpose;
  no comment or docstring narrates the move or cites a spec, plan or slice. The `# TODO` block in
  `views.py` stays.
- No UI, template or browser skill applies, and no MCP is needed.
