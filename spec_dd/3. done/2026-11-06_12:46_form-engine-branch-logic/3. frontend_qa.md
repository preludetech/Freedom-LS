# Frontend QA: conditional pages and questions

A form author can now gate a `FormPage`, a `FormQuestion` or a `FormContent` block on an answer
given on an earlier page (`when:` in the page YAML, naming a question by its new `slug`). A sitting
only sees, saves to and is held up by the pages and questions on its path. The demo application form
gained the employer case: page 1 asks "Is your employer paying for this course?", and a "Your
employer" page with a required employer name and invoice email only applies when the answer is Yes.
At submission the sitting records what it was asked (`asked`), drops answers to questions it was not
asked, and a `CATEGORY_VALUE_SUM` form scores against the sitting's own questions. The admin answers
view and the application export say "Not asked" for an off-path question.

Beyond the golden path, this run hunts for:

- **A gate that leaks.** An applicant who said No must never reach the employer page by Next,
  Previous, the page-jump nav or a typed URL, and its required questions must never block them.
- **A gate that eats answers.** Yes, fill the page, No, Yes again: the employer answers must still be
  there. Only submission throws them away.
- **Numbers that lie.** "Page N of M", the page-jump labels, the dots, the visible question numbers,
  the answered tally and the submit dialog totals must all count on the path.
- **A page opened behind the learner.** Flipping the gate to Yes from a later page must route the
  learner through the employer page before submission, in both the course player and the review
  page.
- **Frozen records.** After submission, editing the condition in the YAML and re-importing must
  change neither the review page nor the admin view of that sitting.
- **Unchanged behaviour.** A form with no `when` anywhere behaves exactly as before.

## §1 Import validation (command line)

Each case copies the demo form to a scratch directory, breaks it, and imports it. Use the
scratchpad directory for the copies; never edit `demo_content/` itself.

1. **Dangling slug.** In the copy's `2. your-employer.yaml` change `question: employer_pays` to
   `question: employer_pay`. Run `uv run python manage.py content_save <copy> DemoDev`.
   Expect: a failure whose message names `2. your-employer.yaml`, the page "Your employer", `when`,
   the unknown slug and the declared slugs (`employer_pays`).
2. **Source on the same page.** Move the "Is your employer paying" question section from
   `1. about-you.yaml` into `2. your-employer.yaml` (above the gated questions). Expect: a failure
   saying the source has to be on an earlier page.
3. **Unknown value.** Change `equals: "yes"` to `equals: "yse"`. Expect: a failure naming the valid
   values `yes, no`.
4. **Unquoted boolean.** Change `equals: "yes"` to `equals: yes`. Expect: a failure that tells the
   author to quote the value.
5. **Two faults at once.** Combine 1 and 3 on two different sections. Expect: both reported in one
   run.
6. **Unchanged form.** Re-run `content_save ./demo_content DemoDev` on the real tree. Expect: success,
   and the demo form's `FormQuestion` rows unchanged (compare a count before and after in the admin
   at `/admin/freedom_ls_form_engine/formquestion/`).

## §2 Application shell: the No path

Sign in as `qa.applicant.a@email.com`.

1. Open the course listing, find "Functionality Demo - Application gated course", open it and
   press Apply. Expect: page 1 "About you" of the application form.
2. The page-jump nav shows four links, 1 to 4 ("About you", "Your employer", "Supporting
   documents", "Availability" on hover); only 1 is current. Note: before any answer the employer
   page is off the path, so expect **three** links, 1 to 3, and page 1 current.
3. Fill in page 1's required questions. Answer **No** to "Is your employer paying for this
   course?". Press Next. Expect: the "Supporting documents" page; the nav reads 1, 2, 3 with 2
   current; the browser URL ends in `/page/3/`.
4. Type the URL with `/page/2/` (the authored employer page). Expect: a redirect to `/page/3/`,
   never the employer page.
5. Press Previous. Expect: page 1 (URL `/page/1/`), not the employer page.
6. Press Next again, upload any small PNG on "Supporting documents", press Next, answer
   "Availability", press Next. Expect: "Check your answers" with three cards: About you,
   Supporting documents, Availability. No "Your employer" card; no "Not answered" row for an
   employer question.
7. Press "Submit application". Expect: the dashboard with the "has been submitted" message. The
   required employer questions did not block it.
8. As the admin, open `/admin/freedom_ls_form_engine/formprogress/`, open applicant A's sitting.
   Expect: the "Answers" section lists the "Your employer" group with each question reading **Not
   asked** (muted), while a skipped optional question on page 1 (phone number, if left blank) reads
   **Not answered**. The "Progress" fieldset shows `asked` as read-only JSON with `pages`,
   `questions` and `content` keys.
9. Still as the admin, export the course applications (`/admin/freedom_ls_course_applications/
   courseapplication/`, select applicant A's row, action "Export", CSV). Expect: the employer
   columns read `Not asked`; the blank phone column is empty.

## §3 Application shell: Yes, No, Yes again

Sign in as `qa.applicant.b@email.com` and apply to the same course.

1. Page 1: answer **Yes** to the employer question, fill the rest, press Next. Expect: "Your
   employer" (URL `/page/2/`), nav 1, 2, 3, 4 with 2 current, the content block shown, and three
   questions numbered consecutively after page 1's.
2. Press Next with the employer name blank. Expect: a 422 re-render with "Question N needs an
   answer" where N is the question's position on the path (count page 1's questions and add one).
3. Fill in employer name "Acme" and invoice email `billing@acme.test`, press Next. Expect:
   "Supporting documents".
4. Press Previous twice. Expect: "Your employer" then "About you". On "About you" change the
   answer to **No** and press Next. Expect: "Supporting documents" directly; the nav shrinks to
   1, 2, 3.
5. Finish the documents and availability pages. Expect: "Check your answers" with no "Your
   employer" card.
6. Press "Edit" on the About you card, change the employer answer back to **Yes**, press "Save and
   return to your answers". Expect: the browser lands on "Your employer" with the query string
   `?return=check`, the Back control reads "Back to your answers", the submit control reads "Save
   and return to your answers", and **"Acme" and `billing@acme.test` are already filled in**.
7. Press "Save and return to your answers". Expect: "Check your answers" with a "Your employer" card
   showing Acme and the email.
8. Press "Edit" on the About you card again, change nothing, press "Save and return to your
   answers". Expect: straight back to "Check your answers" (no detour, since nothing is
   unanswered).
9. Submit. Expect: the dashboard success message.
10. As the admin, open applicant B's `FormProgress`. Expect: the employer answers shown, and no
    "Not asked" in that group.
11. **Frozen path.** Edit `demo_content/functionality_demo_application_form/2. your-employer.yaml`
    so the page's `when` reads `equals: "no"`, run `content_save ./demo_content DemoDev`, then open
    applicant A's and B's sittings in the admin and B's "Check your answers" page
    (`/applications/<pk>/check/` from the dashboard link). Expect: unchanged from §2.8 and §3.10:
    A still "Not asked", B still shows Acme. Revert the YAML edit with `git checkout -- demo_content`
    and re-import.

## §4 Course player

Sign in as `qa.branch@email.com` and open the course URL the data helper reported.

1. Open the "Branching survey" item. Expect: the start screen says the form has **4 questions** and
   **3 pages** (whole-form counts; the start screen is not path-aware).
2. Start the form. Expect: `page-indicator` reads **Page 1 of 2**, the progress bar is half full,
   two dots, the tally reads "0 of 3 answered", questions numbered 1 and 2.
3. Answer No and Medium, press Next. Expect: "Wrap up" with **Page 2 of 2**, URL ending `/fill_form/3`,
   question numbered **3**, tally "2 of 3 answered".
4. Type the URL ending `/fill_form/2`. Expect: a redirect to `/fill_form/3`.
5. Click the first dot to return to page 1, change the answer to Yes, press Next. Expect: "Extra"
   with **Page 2 of 3**, three dots, the content block shown, question numbered 3, tally
   "2 of 4 answered".
6. Leave the extra question blank and click the third dot (page 3 was reached earlier, so it is
   accessible). Expect: "Wrap up" as Page 3 of 3, question numbered 4.
7. Answer Well and press Next, then Submit in the dialog. Expect: **no** completion. The learner is
   redirected to the "Extra" page with a "Question 3 needs an answer" message (the page the answers
   reopened behind them).
8. Answer "Some", press Next. Expect: "Wrap up" with the earlier answer still selected. Press Next
   and Submit. Expect: the completion page; its category scores show `Core` **2 + 3 of 6** and
   `Extra` **2 of 3**.
9. Resume check: as the admin, run `uv run python manage.py qa_reset_learner_progress --help` and
   use it (or ask the data helper) to give `qa.branch@email.com` a fresh attempt. In the browser,
   answer No and Medium on page 1, press Next, then leave by the Exit control ("Leave and save").
   Re-open the item and press Continue. Expect: it resumes on "Wrap up" as Page 2 of 2, never on
   the gated page.
10. Submit that attempt with Fine. As the admin open both completed sittings. Expect: the second has
    `scores` with `Core` max 6 and **no `Extra` key at all**; the first has `Extra` with max 3. In the
    second sitting's answers view the "Extra" question reads "Not asked".
