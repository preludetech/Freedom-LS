# Frontend QA: audit log

Every educator-interface action that changes a learner, a cohort, a registration, a role or a
member now writes an append-only `AuditLogEntry`. Educators see those entries on a learner's
History tab, a cohort's History tab, and an organisation-level Audit log section with Who, What
and When filters. Eight removal and deactivation dialogs take an optional reason that shows in the
history. This run walks the writers through the screens that trigger them, checks the three
readers, the reason field and its validation, the filters, and the ways it could go wrong: a
no-op that must not write, a refused action that must not write, a cohort admin who must see
nothing, an admin of another organisation who must see only their own, a deleted cohort whose
name must survive, and labels containing markup that must render as text.

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever
this document writes `<PORT>`. Shell variables do not survive between tool calls.

Everything under `/educator/` below is relative to `http://127.0.0.1:<PORT>`. Entries carry no
link to a page of their own, so expected rows are described by their cells: When, Who, What,
Details (and Target in the organisation log and the cohort History).

## §1 A reason reaches the learner's History tab

1. Open `/educator/organisations/northside/learners`, click **Ada Lovelace**. Note the tab strip: Overview,
   Courses, **History**.
2. Click **History**. Expect the empty state "No history for this learner yet. Actions such as
   moving or deactivating them are recorded here." (If earlier runs left rows, expect those rows
   instead and carry on.)
3. Click **Deactivate** in the page header. In the dialog, expect an input labelled
   **Reason (optional)** with the help text "Only staff can see this. It is shown in the history."
   Type `Left the programme` and click **Deactivate**.
4. The page re-renders with the Inactive badge. Open the **History** tab. Expect one new row:
   When shows today's date and a time; Who is **Orla Admin**; What is **Learner deactivated**;
   Details shows `Left the programme`.
5. Click **Reactivate**, leave the reason empty (the reactivate dialog has no reason field),
   confirm. Expect a second row, newest first: **Learner reactivated** by Orla Admin, with empty
   Details.
6. Open the learner page again at `/educator/organisations/northside/learners/<ada-pk>/__tabs/history` directly.
   Expect the same two rows.

## §2 The reason is validated

1. On Ada's page click **Deactivate**. Paste a 501-character reason (any text; 501 is one over
   the limit). Click **Deactivate**.
2. Expect the dialog to stay open, re-rendered with an error on the Reason field (Django's
   "Ensure this value has at most 500 characters" wording), and the response status 422 in the
   network log. Ada's badge still reads Active.
3. Trim the reason to 500 characters and confirm. Expect the deactivation to succeed and the
   History row to show the full 500 characters.
4. Reactivate Ada so later tests start from an active learner.
5. Check the same field exists on each of the other seven dialogs as you reach them below:
   Remove from cohort, Deactivate registration (learner page), Deactivate registration (cohort
   Courses tab), Deactivate cohort, Delete cohort, Deactivate role, Deactivate member. The input
   carries `maxlength="500"`, so a real paste is cut at 500 in the browser; to reach the 422 in
   step 2, set the 501-character value through the page's JavaScript.
