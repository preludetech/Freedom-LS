# Plan: Audit log

Implementation plan for `1. spec.md`. Every path is relative to the repo root. Line numbers are
from the worktree at the time of writing and are a guide, not a contract.

The spec's "Documentation and downstream" section (product docs, the app README, upgrade notes,
the app-structure doc) is not implemented by this plan. It is produced by the documentation step
that follows implementation. The one exception is regenerating `docs/app_structure.md` and the
import contracts with `/ds:app_map`, which the `app-map-fresh` pre-commit hook requires before the
new app's first commit can land.

Spec 8 (bulk operations) has no code on this branch. This plan builds the bulk-run writer contract
(`record_run_summary`, shared `run_id`, the organisation log's summary row) and proves the reader
half with entries written by test code; wiring a bulk action or an import commit to the writer is
spec 8's work.

### Cross-app edges

New runtime edges, all named by the spec: `audit_log --> accounts, base, organisations,
site_aware_models`; `role_based_permissions --> audit_log`; `learner_management --> audit_log`;
`educator_interface --> audit_log`. `audit_log` never imports `role_based_permissions`,
`learner_management` or `educator_interface`, in code or in tests: the describe renderers for
`role.*` are registered from `educator_interface`, and `AuditLogEntryFactory` targets an
`Organisation`. `role_based_permissions` does not gain an edge to `organisations`: the organisation
of a role target is resolved by `organisation_of` in `audit_log`, which already depends on
`organisations`.

> **Assumed default:** the seven runtime edges above are accepted as the spec draws them and
> recorded in `docs/app_structure.md` by `/ds:app_map` in slice 1. Why: the spec's Decision 1
> chose a new app precisely so these are the only edges needed, and `learner_management` cannot be
> the model's home. To change: this section and the spec's Decisions.

### Multi-tenancy decisions

> **Assumed default:** `record_entry` sets `site` from its argument or from `site_of(target)`,
> never from the request. Why: the writer runs in management commands and background tasks where
> no request exists, and a site-role entry must carry the role's site, not the actor's. A test
> asserts the entry's site equals the target's. To change: slice 1, Writer.

> **Assumed default:** `unscoped` and `_base_manager` are write and background paths only; every
> reader (tables, panels, filters, admin) goes through `objects`, which keeps the ambient site
> filter. Why: `base_manager_name = "unscoped"` exists so Django's own internals carry the
> append-only guard, not to widen reads. To change: slice 1, Model.

> **Assumed default:** `prune_audit_log` deletes across every site. Why: retention is an
> operator task with no request to scope it, and the setting is platform-wide. To change: slice
> 13.

### `writer.py`

```python
def subject_key(obj: Model) -> str:
    return f"{obj._meta.app_label}.{obj._meta.model_name}:{obj.pk}"

def organisation_of(target: Model) -> Organisation | None:
    """The organisation an audited target belongs to: the target itself when
    it is one, none for a Site, else the target's `organisation` when it has
    one. The learner-management models that carry one cannot be named here
    without a dependency cycle, so they are recognised by that attribute."""
    if isinstance(target, Organisation): return target
    if isinstance(target, Site): return None
    organisation = getattr(target, "organisation", None)
    return organisation if isinstance(organisation, Organisation) else None

def record_entry(*, action, actor, target, target_label, organisation, subjects=(), reason="",
                 details=None, run_id=None, site=None) -> AuditLogEntry:
    validate_action(action)
    return AuditLogEntry.unscoped.create(
        # Explicit, never from the request: this also runs in commands and
        # background tasks, and a site role's entry belongs to the role's site.
        site=site or site_of(target),
        organisation=organisation,
        actor=actor,
        actor_label=actor.display_name if actor else "",
        action=action,
        target_content_type=ContentType.objects.get_for_model(target),
        target_object_id=str(target.pk),
        target_label=target_label,
        subjects=[subject_key(target), *(subject_key(s) for s in subjects)],
        reason=reason.strip(),
        details=dict(details or {}),
        run_id=run_id,
    )
```

No transaction, no `on_commit`, no `try`: the caller's `transaction.atomic()` decides whether the
row survives. `target` is typed `Model`, since a `Site` is a valid subject for site roles.

```python
class ReasonMixin(PanelAction):
    """A confirm dialog that takes an optional reason. List it first in the
    bases, as RequiresActiveCohortMixin is, so the reason is validated before

    reason: str = ""
```

## Slice 10: the bulk-run contract

**Behaviour.** A bulk run writes one entry per changed object and one summary entry sharing a

### Writer (`audit_log/writer.py`)

```python
RUN_ROWS_KEPT = 50
RUN_LABEL_LENGTH = 255

def record_run_summary(*, action, run_id, organisation, actor, reason="", counts, rows=(), bulk_action=None) -> AuditLogEntry:
    """The one summary entry of a bulk run. `counts` holds changed, skipped
    and failed; `rows` are the skipped or failed rows as (label, outcome), cut
    to RUN_ROWS_KEPT with `truncated` saying so and each label cut to
    RUN_LABEL_LENGTH. Nothing else reaches `details`, so a caller cannot store
    raw import cells in the log."""
    if action not in SUMMARY_ACTIONS: raise ValueError(...)
    kept = [{"label": label[:RUN_LABEL_LENGTH], "outcome": outcome} for label, outcome in list(rows)[:RUN_ROWS_KEPT]]
    details = {"counts": {"changed": ..., "skipped": ..., "failed": ...}, "rows": kept, "truncated": len(rows) > RUN_ROWS_KEPT}
    if bulk_action is not None: details["bulk_action"] = bulk_action
    return record_entry(action=action, actor=actor, target=organisation, target_label=organisation.name,
                        organisation=organisation, reason=reason, details=details, run_id=run_id)
```

{failed} failed".

  ```python
                 .annotate(position=Window(RowNumber(), partition_by=F("run_id"),
                                           order_by=[F("created_at").desc(), F("id").desc()]))
                 .filter(position__lte=RUN_ROWS_KEPT))
  totals = dict(AuditLogEntry.objects.filter(organisation=organisation, run_id__in=run_ids)
                .exclude(action__in=SUMMARY_ACTIONS).values_list("run_id").annotate(total=Count("pk")))
  ```

## Slice 13: the prune command

**Behaviour.** An operator deletes entries older than a number of days, or previews how many would
go. With no age given anywhere, or a non-positive one, the command refuses.

- `audit_log/config.py`: `AUDIT_LOG_RETENTION_DAYS: int | None` with
  `Setting(default=None)`.
- `models.py`, `AuditLogEntryQuerySet`:

  ```python
  def prune_before(self, cutoff: datetime, *, batch_size: int = 1000) -> int:
      """The only delete path. Deletes rows created before `cutoff` in
      batches so a long-retained table never locks in one statement."""
      total = 0
      while True:
          batch = list(self.filter(created_at__lt=cutoff).values_list("pk", flat=True)[:batch_size])
          if not batch:
              return total
          total += self._delete_batch(batch)

  def _delete_batch(self, pks: list[UUID]) -> int:
      # The base delete, since this class's own refuses.
      deleted, _ = models.QuerySet.delete(self.filter(pk__in=pks))
      return deleted
  ```

- `audit_log/management/commands/prune_audit_log.py` (`djclick`), with empty `__init__.py` files
  in `audit_log/management/` and `audit_log/management/commands/`:

  ```python
  @click.command()
  @click.option("--older-than", "older_than", type=click.IntRange(min=1), default=None,
                help="Delete entries older than this many days.")
  @click.option("--dry-run", is_flag=True)
  def command(older_than: int | None, dry_run: bool) -> None:
      days = older_than if older_than is not None else config.AUDIT_LOG_RETENTION_DAYS
      if days is None or days < 1:
          raise click.ClickException("Give --older-than DAYS (at least 1) or set AUDIT_LOG_RETENTION_DAYS.")
      cutoff = timezone.now() - timedelta(days=days)
      if dry_run:
          click.echo(f"Would delete {AuditLogEntry.unscoped.filter(created_at__lt=cutoff).count()} entries.")
          return
      click.echo(f"Deleted {AuditLogEntry.unscoped.all().prune_before(cutoff)} entries.")
  ```

  Not called from `fls_run_housekeeping`.

Tests: `audit_log/tests/test_models.py` (`prune_before` deletes only rows before the cutoff,
returns the count, and with `batch_size=2` over five rows still deletes them all);
`audit_log/tests/test_config.py` (default `None`);
`audit_log/tests/management/__init__.py`, `audit_log/tests/management/commands/__init__.py` (empty)
and `audit_log/tests/management/commands/test_prune_audit_log.py`: a dry run deletes nothing and
prints the count; `--older-than 30` deletes only entries older than 30 days (`time_machine` to
create them); the setting supplies the default; neither given, `--older-than 0` and a setting of
`0` each raise `ClickException` and delete nothing.
