# Spec: the permission matrix test builds its world once

Idea: `idea.md`. Answers: `answers.md`. Research: `research_*.md` beside this file.

## Purpose

`freedom_ls/educator_interface/tests/invariants/test_permission_matrix.py` collects 802 tests. 790
of them call `_build_world`, which creates two sites, three organisations, four cohorts, four
learners, ten password-hashed users and six role grants, so the same world is built 790 times.
`test_can_matches_the_matrix` (696 cases) and
`test_deactivating_the_staff_member_row_withdraws_the_grant` (67 cases) take most of that time
(the idea's 763 is these 696 plus the 67). After this work each world-building test builds one
world and walks many cells against it. The same cells are checked, and a failure names the cell
that disagreed.

## Terminology

| Term | Status | Meaning |
| --- | --- | --- |
| world | narrowed | the `World` that `_build_world` returns in `test_permission_matrix.py` |
| cell | coined | one `(capability, role, kind, relation)` the file checks, as `_cases()` yields it |
| walk | coined | one test that builds a world and checks many cells against it, reporting every mismatch at the end |

## Scope

In:

- Every test in `test_permission_matrix.py` that calls `_build_world`.
- `measurements.md` beside this spec, holding the before-and-after figures and the cell-set
  comparison.

Out:

- `MATRIX`, `CAPABILITY_SCOPE_KINDS`, `RELATIONS_FOR_KIND`, `ROLES`, `GATED_ROLES`, `_build_world`
  and every permission rule. The walks read them unchanged.
- Tests in the file that do not build a world: `test_every_capability_a_role_holds_has_a_matrix_entry`,
  `test_every_matrix_entry_names_every_role`,
  `test_a_roles_permissions_equal_the_capabilities_its_matrix_column_allows`, the three
  `walk_interface` tests and `test_assign_cohort_viewer_is_in_the_matrix`.
- Other slow tests, including users of `scenario_world.build_world`
  (`faster-test-runs-6-prune-slow-tests`), and the test password hasher
  (`faster-test-runs-1-fast-password-hasher`).

## Decisions

- **One world per test, inside pytest-django's per-test transaction**, as `answers.md` chose. No
  module- or session-scoped database fixture.
- **Matrix walks are per capability** so a single capability can still be re-run alone, by node id
  (`::test_can_matches_the_matrix[add_cohort]`). `-k` matches substrings, so `-k add_cohort` also
  selects `add_cohortmembership`.
- **Deactivation walks are per gated role**, because every gated cell of a role depends on that
  role's single `StaffMember` row. One deactivate and reactivate per role checks all its cells.
- **Mismatches go in a list built by hand.** No `pytest-check`, no subtests.
- **Two tests that change shared data keep a world of their own.**
  `test_cohort_admin_holds_add_cohortmembership_on_another_cohort_only_with_a_grant_there` grants
  cohort_admin on C2, which would flip `(cohort, other_cohort)` cells.
  `test_the_cohort_import_gate_refuses_an_inactive_cohort` deactivates C1, which
  `check_import_gate` reads. Both stay one-case tests, as does the read-only
  `test_cohort_admin_holds_delete_cohortmembership_on_its_own_cohort`.

## Requirements

All code changes are in `freedom_ls/educator_interface/tests/invariants/test_permission_matrix.py`.

### The matrix walk

`test_can_matches_the_matrix` is parametrized over the keys of `CAPABILITY_SCOPE_KINDS`. Each test
id is the capability's codename, the part after the dot (`view_cohort`). Each test builds one world
with `_build_world(mock_site_context)` and walks every cell `_cases()` yields for its capability,
comparing `can(user, capability, scope) is expected`, where `expected` is
`(kind, relation) in MATRIX[capability][role]`. Identity on `bool` stays, so a truthy non-bool
return still fails.

### The deactivation walk

`test_deactivating_the_staff_member_row_withdraws_the_grant` is parametrized over `GATED_ROLES`.
Each test builds one world, takes that role's cells from `_gated_true_cases()`, and runs three
steps. Every step runs even when an earlier one found mismatches, and the test reports them all.

1. Check `can()` is `True` for every cell. Snapshot the role's `ObjectRoleAssignment` rows, and
   take one `frozenset(get_perms(user, scope))` per distinct `(kind, relation)`.
2. Deactivate the role's `StaffMember` row. Check every cell is `False` and both snapshots are
   unchanged.
3. Reactivate the row, in a `finally`. Check every cell is `True` and both snapshots are unchanged.

A mismatch line from this walk names its step.

### The role walks

These four tests lose their `role` parametrization. Each builds one world and loops over `ROLES`,
with the expected value computed from `MATRIX` as now:

- `test_cohorts_visible_to_agrees_with_can_on_every_cohort`
- `test_learners_visible_to_agrees_with_can_on_every_learner`
- `test_the_organisation_import_gate_needs_bulk_manage_learners_and_add_learner`
- `test_the_cohort_import_gate_needs_add_learner_and_add_cohortmembership`

### The failure report

One helper builds the report for every walk in the file and fails the test with
`pytest.fail(report, pytrace=False)`:

```
3 of 24 cells disagree for freedom_ls_learner_management.view_cohort
capability=freedom_ls_learner_management.view_cohort role=cohort_admin kind=cohort relation=other_cohort expected=False actual=True
...
```

- The first line gives the disagreeing count, the walked count and what the walk covers (a
  capability, a role, or the test's subject).
- Each following line is one cell as `key=value` pairs: its coordinates, the expected value and the
  actual value.
- Lines are sorted, so the same failure always prints the same report.
- An exception raised while checking a cell fails the test. The walk catches `Exception`, adds the
  cell's coordinates with `add_note` and re-raises it. This catch is deliberately broad: it only
  annotates, never swallows, and it is the only broad catch in the file. A comment says so.

## Testing

- **A walk fails when it should.** Flip one `MATRIX` entry locally, and separately make one gated
  cell's expectation wrong. The matching walk fails with a report naming that cell. Neither change
  is committed.
- **Coverage is unchanged.** Before the change, list the cell of every collected
  `test_can_matches_the_matrix` and `test_deactivating_…` case from the `--collect-only` ids. After
  the change, the cells are those `_cases()` and `_gated_true_cases()` yield, since the walks
  iterate them. The two lists are equal (696 and 67 cells). Record both counts and the comparison
  in `measurements.md`.
- **Each walk is independent.** The file passes in `pytest-randomly`'s random order and with
  `-p no:randomly`.
- **The file is measured before and after**, on this branch, from the worktree root:

  ```
  uv run pytest freedom_ls/educator_interface/tests/invariants/test_permission_matrix.py -n 0 -p no:randomly --durations=0 --durations-min=0 -q
  uv run pytest freedom_ls/educator_interface/tests/invariants/test_permission_matrix.py --collect-only -q
  ```

  `measurements.md` records, for each run, the test count, the summed setup and call time
  (test-body time, which leaves out test-database creation), the wall time and the password hasher
  in effect. It compares the before figure with `spec_dd/1. next/faster-test-runs/research_test_timings.md`
  ("Largest parametrized tests"). Both runs use the same hasher. If
  `faster-test-runs-1-fast-password-hasher` has landed on main by then, that is its hasher.
