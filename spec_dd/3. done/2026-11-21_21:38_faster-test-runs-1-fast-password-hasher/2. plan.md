# Plan: Tests hash passwords with a fast hasher

Spec: `1. spec.md` in this directory.

Two slices, both in `freedom_ls/conftest.py` and one new test module. No model, migration, view,
template or settings change.

## Facts the implementation relies on

- `config/settings_base.py:247-252` is the only `PASSWORD_HASHERS` definition. `settings_dev.py`
  and `settings_prod.py` star-import it. None of the three changes.
- pytest runs under `config.settings_dev` (`pyproject.toml`, `[tool.pytest.ini_options]`).
- `django.test.override_settings` sends `setting_changed` on enter and on exit. Django's
  `reset_hashers` receiver in `django/contrib/auth/hashers.py` then clears the `get_hashers`
  caches. pytest-django's `settings` fixture goes through the same signal, so
  `production_password_hashers` needs no cache handling of its own.
- The root `conftest.py` star-imports `freedom_ls.conftest`, and pytest also loads
  `freedom_ls/conftest.py` itself (under the bare name `conftest`, since `freedom_ls/` has no
  `__init__.py`). So `fast_password_hasher` has two registrations: one serves `freedom_ls/` and
  one serves `tests/`. One session can run both. The second copy then reads `PASSWORD_HASHERS`
  while the first copy's override is still on, and that is why the fixture strips MD5 from what
  it reads. Overrides nest, so teardown unwinds them in order.
- Module-level names in `freedom_ls/conftest.py` travel with every star-import (see its comment
  above the Playwright import). So new imports go inside the fixture bodies, as
  `_clear_messaging_policy_cache` does.
- `User` is site-aware (`freedom_ls/accounts/models.py:110`), so any test that builds a
  `UserFactory()` takes `mock_site_context`, and `django_db` through `pytest.mark.django_db`.
- No existing test asserts a hasher name or a hash prefix (`research_codebase.md`). No existing
  test changes.

## Test module location

The new tests go in `tests/test_password_hashers.py`, a new module. It is a cross-cutting test of
a conftest fixture: no production module mirrors it.

- The `test-mirroring` hook (`claude_plugins/django-stack/scripts/check_test_mirroring.py`) checks
  only test files inside an app, which is a directory holding an `apps.py`. `tests/` has no
  `apps.py`, so the hook accepts the module without a baseline or exemption line.
- `tests/` is in `testpaths` and gets `freedom_ls/conftest.py`'s fixtures through the root
  `conftest.py` star-import. So these tests run on the star-imported copy of the fixture, which
  is the copy a concrete project gets.
- Do not use `freedom_ls/tests/test_conftest.py`. `freedom_ls/` has no `__init__.py`, so pytest
  would import `freedom_ls/tests/` as the top-level package `tests`, and that collides with the
  repo's own `tests/` package. Do not use `tests/test_settings_dev.py` or `tests/test_conftest.py`
  either: both are module-marked `dev_tooling` and the default run deselects them.
- The module gets no `pytestmark`. Every test that touches the database is marked
  `@pytest.mark.django_db`.

## Slices

### Slice 1: every test hashes with MD5 by default

**Behaviour:** under pytest, new password hashes use MD5. A hash made by a configured hasher, such
as Argon2, still verifies. The settings modules still put Argon2 first.

**Builds on:** none

**Touches:** freedom_ls/conftest.py, tests/test_password_hashers.py

Tests first (RED), in `tests/test_password_hashers.py`:

- `test_get_hasher_by_default_is_md5`: `get_hasher().algorithm == "md5"`.
- `test_user_factory_password_by_default_is_md5_hash(mock_site_context)`: `UserFactory().password`
  starts with `"md5$"`. Needs the database.
- `test_argon2_hash_by_default_still_verifies`:
  `check_password("a-password", make_password("a-password", hasher="argon2"))` is `True`. This
  proves the configured hashers stay in the list after MD5.
- `test_settings_module_lists_argon2_first`, parametrised over the dotted names
  `"config.settings_base"` and `"config.settings_dev"`: the body calls
  `importlib.import_module(name)` and asserts `module.PASSWORD_HASHERS[0] ==
  "django.contrib.auth.hashers.Argon2PasswordHasher"`. It reads the module attribute, never
  `django.conf.settings`, because `override_settings` changes only the live settings object.

Implementation (GREEN), in `freedom_ls/conftest.py`:

- Add a module constant for the dotted path, near `_ONE_PIXEL_PNG`. A star-import skips the
  underscore name, and only the fixtures use it.

  ```python
  _MD5_PASSWORD_HASHER = "django.contrib.auth.hashers.MD5PasswordHasher"  # pragma: allowlist secret
  ```

  The `detect-secrets` pre-commit hook flags the line as a secret because of the word "password".
  The marker tells it the line holds a dotted import path, not a credential.

- Add the fixture beside the other autouse fixtures, after `_disable_preview_overrides`:

  ```python
  @pytest.fixture(scope="session", autouse=True)
  def fast_password_hasher() -> Iterator[tuple[str, ...]]:
      """Hash passwords with MD5 for the whole test session.

      Argon2 is slow on purpose, and most tests create users. MD5 goes first, so
      new hashes use it. The configured hashers stay after it, so their hashes
      still verify. Session-scoped so it is on before any fixture creates a user.
      It uses `override_settings`, whose `setting_changed` signal clears Django's
      cached hasher list. A plain assignment would leave that cache stale.

      Public, because `from freedom_ls.conftest import *` skips underscore names.
      A concrete project turns it off by defining its own `fast_password_hasher`
      after that import.

      Yields the configured hashers.
      """
      from django.conf import settings
      from django.test import override_settings

      # Two registrations (this file, and the root conftest's star-import) can
      # both run in one session, and the second reads the first's MD5 list.
      configured = tuple(
          hasher for hasher in settings.PASSWORD_HASHERS if hasher != _MD5_PASSWORD_HASHER
      )
      with override_settings(PASSWORD_HASHERS=[_MD5_PASSWORD_HASHER, *configured]):
          yield configured
  ```

- Run the new module, then the tier the wrapper selects. Every existing test passes unchanged.

### Slice 2: one test opts back into the configured hashers

**Behaviour:** a test that takes `production_password_hashers` hashes with the configured
hashers (Argon2 first). The next test is back on MD5.

**Builds on:** slice 1

**Touches:** freedom_ls/conftest.py, tests/test_password_hashers.py

Tests first (RED), in `tests/test_password_hashers.py`:

- `test_get_hasher_with_production_password_hashers_is_argon2(production_password_hashers)`:
  `get_hasher().algorithm == "argon2"`.
- `test_set_password_with_production_password_hashers_is_argon2_hash(mock_site_context,
  production_password_hashers)`: arrange `user = UserFactory()`, act
  `user.set_password("a-password")`, assert `user.password` starts with `"argon2"`. Needs the
  database.
- `test_check_password_with_production_password_hashers_accepts_set_password(mock_site_context,
  production_password_hashers)`: arrange `user = UserFactory()` and
  `user.set_password("a-password")`, act and assert `user.check_password("a-password")` is
  `True`. Needs the database.
- `test_get_hasher_after_production_password_hashers_test_is_md5`: asserts
  `get_hasher().algorithm == "md5"`. It is a leak guard. It holds in any order, so it passes at
  RED too. When pytest-randomly runs it after an opt-in test, it fails if the opt-in leaked. Its
  docstring says this, without citing any planning document.

Implementation (GREEN), in `freedom_ls/conftest.py`, beside `fast_password_hasher`:

```python
@pytest.fixture
def production_password_hashers(
    settings: "SettingsWrapper", fast_password_hasher: tuple[str, ...]
) -> None:
    """Hash with the configured password hashers for one test.

    For a test that checks real hashing, such as an Argon2 hash or a hash prefix.
    pytest-django's `settings` fixture restores the MD5 list when the test ends.
    A class or module opts in with
    `@pytest.mark.usefixtures("production_password_hashers")`.
    """
    settings.PASSWORD_HASHERS = list(fast_password_hasher)
```

- `SettingsWrapper` comes from `pytest_django.fixtures`. Import it under the existing
  `if TYPE_CHECKING:` block. The module has no `from __future__ import annotations`, so the
  annotation is a string, as `reverse_url`'s `"LiveServer"` is.
- Add one sentence to the `fast_password_hasher` docstring: "A test that needs the configured
  hashers takes `production_password_hashers`."
- Run the new module, then the tier the wrapper selects.
