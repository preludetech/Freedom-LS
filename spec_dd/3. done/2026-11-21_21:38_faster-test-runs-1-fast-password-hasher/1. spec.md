# Spec: Tests hash passwords with a fast hasher

## Purpose

Under pytest, FLS hashes passwords with Django's `MD5PasswordHasher` instead of Argon2. Deployed
sites and the dev server keep Argon2, and concrete projects that star-import
`freedom_ls/conftest.py` get the switch without configuring anything. The case is in `idea.md`.

## Scope

In:

- An autouse switch in `freedom_ls/conftest.py` that applies to every test, FLS's own and a
  concrete project's.
- A named way for one test to opt back into the hashers the settings configure.
- Tests that prove the switch is on, that the opt-in works, and that the settings modules still
  put Argon2 first.

Out:

- Any change to `PASSWORD_HASHERS` in `config/settings_base.py`, `settings_dev.py` or
  `settings_prod.py`.
- Test runs that do not load `freedom_ls/conftest.py`: the standalone `panel_framework` and `icons`
  runs, and tests that spawn a pytest or Django subprocess (`tests/test_run_tests.py`,
  `course_applications/tests/invariants/test_collection_safety.py`).
- Other test speed-ups; the sibling specs in the roadmap's "Faster test runs" effort own them.

## Decisions

- **Session scope, through `override_settings`.** A session-scoped autouse fixture runs before
  every other fixture, so no fixture of any scope hashes with Argon2. `override_settings(...).enable()`
  sends `setting_changed`, and Django's `reset_hashers` receiver in
  `django/contrib/auth/hashers.py` clears the `get_hashers` caches. A plain assignment to
  `settings.PASSWORD_HASHERS` would leave a stale cache.
- **A public fixture, not a settings module or a `pytest_*` hook.** Concrete projects run under
  their own settings module. `from freedom_ls.conftest import *` carries fixtures but skips
  underscore-prefixed names, because the module has no `__all__`. So the fixture's name has no
  leading underscore.
- **MD5 first, the configured list after it.** New hashes use MD5. Any hash made by a configured
  hasher, such as an Argon2 hash in a fixture, still verifies.

## Requirements

### `freedom_ls/conftest.py`

- New session-scoped autouse fixture `fast_password_hasher`.
  - It reads `django.conf.settings.PASSWORD_HASHERS` (the configured list). A session fixture
    cannot take pytest-django's function-scoped `settings` fixture.
  - It enables
    `override_settings(PASSWORD_HASHERS=["django.contrib.auth.hashers.MD5PasswordHasher", *rest])`,
    where `rest` is the configured list without the MD5 entry, so a list that already holds MD5
    does not get it twice.
  - It yields `rest` and disables the override at teardown. FLS registers the fixture twice, once
    from `freedom_ls/conftest.py` and once through the root `conftest.py` star-import, so a second
    copy can read the list while the first copy's override is on. Removing MD5 gives both copies
    the same list in any order. A project whose own settings list MD5 loses it on opt-in.
  - Its docstring says what it does, why, and how a test opts back in, as
    `_disable_preview_overrides` does.
- New fixture `production_password_hashers(settings, fast_password_hasher)`, not autouse. It sets
  `settings.PASSWORD_HASHERS` to the list `fast_password_hasher` yields, for one test. pytest-django's `settings`
  fixture restores the fast list at teardown. A class or module opts in with
  `@pytest.mark.usefixtures("production_password_hashers")`.
- The MD5 hasher is named by its dotted path.

## Testing

The new tests run in the default tier, so they carry no `dev_tooling` marker and sit in a module the
`test-mirroring` hook accepts (not `tests/test_settings_dev.py`).

- Default: `get_hasher().algorithm == "md5"`, and a `UserFactory()` user's `password` starts with
  `md5$`.
- Configured hashers kept: a hash from `make_password(pw, hasher="argon2")` passes `check_password`
  under the default switch.
- Opt-in: with `production_password_hashers`, `get_hasher().algorithm == "argon2"`, and
  `set_password` followed by `check_password` round-trips.
- Opt-in ends with the test: a later test sees `md5` again.
- Settings untouched: `config.settings_base.PASSWORD_HASHERS[0]` and
  `config.settings_dev.PASSWORD_HASHERS[0]`, read from the modules rather than `django.conf.settings`,
  are `"django.contrib.auth.hashers.Argon2PasswordHasher"`.
- Playwright login flows need no change: the live server thread shares the process's settings.

## Open questions

- Q: How does a test opt back into the configured hashers? → A: the `production_password_hashers`
  fixture (assumed default: it follows the conftest's fixture style and needs no marker
  registration.)
- Q: What does `fast_password_hasher` yield when FLS registers it twice? → A: the configured list
  with MD5 removed (decided by the user at plan time).

## Success criteria

- `uv run pytest` passes, the new tests included, with no existing test changed.
- `config/settings_base.py`, `settings_dev.py` and `settings_prod.py` have no diff.
- `timings.md` records both samples before and after, and the after times are lower.
