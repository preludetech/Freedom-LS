# Frontend QA: the header Messages button shows only to users with a use for it

This change makes the header Messages button (the speech-bubble icon beside the notification
bell) render only for a signed-in user who either already has a conversation on this site or whom
the messaging policy offers someone to message. Out of the box the policy lets a learner message
an active `cohort_admin` of a cohort they belong to, and lets an educator message the learners
they can see. Nothing else changes: the messages page at `/messages/` still answers for everyone,
the bell is untouched, and the button's panel and badge behave as before for users who keep it.

Beyond the golden path, this run hunts for:

- **A button that lingers.** A learner whose only route is closed by an organisation's messaging
  configuration must lose the button, while a learner with a conversation keeps it whatever the
  configuration says.
- **A button that vanishes wrongly.** An educator with learners to reach, and a learner with any
  one open route, must keep it.
- **Header side-effects.** With the button gone, the bell and the user menu must still sit
  correctly in the header at every viewport, and the bell must still open and close.
- **The page behind the button.** A user without the button who types `/messages/` must get the
  messages page, not an error.

---

## §0 Setup

### 0.1 Server

1. `PORT=$(.claude/ds/scripts/find_available_port.sh)`. Use that number literally from here on.
2. `uv run python manage.py runserver $PORT`, backgrounded.
3. Base URL: `http://127.0.0.1:$PORT`. Check that `#debug-branch-badge`, bottom left, names
   `hide-messages-icon-in-toolbar-for-some-users`.
4. The dev settings turn messaging on (`MESSAGING_ENABLED = True` in `config/settings_dev.py`).
   §5 needs it off and uses a scratch settings module; everything else runs on the dev settings.

### 0.2 Data

The dev database needs the demo data (`uv run manage.py create_demo_data --yes`, then
`uv run manage.py content_save ./demo_content DemoDev`) plus the direct messaging scenario on the
**DemoDev** site:

```
uv run python manage.py qa_create_direct_messaging_scenario --site-name DemoDev
```

Running it again resets it: it puts every conversation back, clears the personas' extra
conversations, and resets the site, Northside and Southside messaging configuration to the
defaults. Each persona's password is its own email address.

The personas this plan uses:

| Email | Who | Conversations after the seed |
|---|---|---|
| `l3@qa.test` (Lara Learner) | learner in Northside **Cohort A**; `edu@qa.test` is `cohort_admin` of Cohort A | none |
| `l1@qa.test` (Lena Learner) | learner in Cohort A | with `edu` (35 messages) and with `viewer` |
| `s1@qa.test` (Sam South) | learner in Southside **Cohort S**; no cohort admin, only `south.admin@qa.test` as `organisation_admin`, a role the shipped settings do not offer to learners | with `south.admin` (1 message) |

### 0.3 Before §2: remove Sam's only conversation

§2 needs a learner with no conversation and no recipient. After the seed, run:

```
uv run python manage.py shell -c "from freedom_ls.comms.models import Conversation; print(Conversation._base_manager.filter(participants__user__email='s1@qa.test').delete())"
```

The printed tuple should show one conversation deleted. Re-running the seed puts it back.

### 0.4 Login

Sign in at `http://127.0.0.1:$PORT/accounts/login/` with the persona's email as both email and
password. Sign out between personas through the user menu in the header (the avatar at the far
right), or use a fresh browser context per persona.

The button under test: in the header, `#messages-button` (a round icon button whose accessible
name starts "Messages"), immediately left of the notification bell. "Present" below means that
element is in the page; "absent" means it is not in the DOM at all, not merely hidden.

## §1 A learner with an open route keeps the button

1. Sign in as `l3@qa.test`.
2. Land on the dashboard (`/`).
   - **Expect:** the Messages button is present beside the bell, with its sr-only label
     "Messages" (no unread count, since Lara has no conversation).
3. Click the Messages button.
   - **Expect:** the panel opens, shows the empty state and a way to start a new message (Lara
     may message Eve, her cohort admin).
4. Press Escape.
   - **Expect:** the panel closes and focus returns to the button.
5. Open a course page from the dashboard.
   - **Expect:** the button is still present on that page's header.

## §2 A learner with no route and no conversation has no button

Run §0.3 first.

1. Sign in as `s1@qa.test`.
2. Land on the dashboard.
   - **Expect:** no Messages button in the header. The bell and the user menu sit side by side
     with no empty gap where the button was.
3. Click the bell.
   - **Expect:** the notifications panel opens as usual.
4. Press Escape.
   - **Expect:** the panel closes and focus returns to the bell.
5. Repeat step 2 at 375 x 812 and at 768 x 1024.
   - **Expect:** no Messages button; the header still fits with no horizontal scroll and the
     bell and avatar aligned.
6. Visit `/messages/` directly.
   - **Expect:** the messages page renders (HTTP 200, the "Messages" heading, an empty
     conversation list, and no "New message" control since Sam has nobody to message). No 404 and
     no error page.
7. Visit `/messages/new/` directly.
   - **Expect:** whatever it answered before this change for a user with no recipients (it is
     not part of this change); note the status and content in the report if it is an error page.

## §3 An existing conversation brings the button back

Carries on from §2 with Sam still signed in.

1. In a second browser context, sign in as `south.admin@qa.test`.
   - **Expect:** Sid has the Messages button (an organisation admin can message the learners
     they see).
2. Open the Messages button, choose "New message", pick Sam South, send "Hello Sam".
   - **Expect:** the thread opens with the sent message.
3. Back in Sam's context, reload the dashboard.
   - **Expect:** the Messages button is present, and its badge label reads "Messages, 1 unread"
     once the badge loads.
4. Click the button.
   - **Expect:** the panel lists the conversation with Sid and the excerpt "Hello Sam".
5. Open the conversation and read it, then reload the dashboard.
   - **Expect:** the button stays present; the label drops back to "Messages".

## §4 Closing the organisation's educator route hides the button, except for a conversation

1. Sign in as `demodev@email.com` and open `/admin/freedom_ls_messaging_policy/organisationmessagingconfig/add/`.
2. Choose organisation **Northside**, set "Learner to educator" to **Closed**, leave the other
   flags at their defaults, save.
3. In another context, sign in as `l3@qa.test` and load the dashboard.
   - **Expect:** no Messages button (Lara's only route, her cohort admin, is now closed).
4. Visit `/messages/` as Lara.
   - **Expect:** the page renders with an empty list and no "New message" control.
5. Sign in as `l1@qa.test` and load the dashboard.
   - **Expect:** the Messages button is present with an unread count (Lena's conversations keep
     it even though the route is closed). Open the panel: the conversations list as before.
6. Sign in as `edu@qa.test` and load the dashboard.
   - **Expect:** the Messages button is present with an unread count (Eve's existing
     conversations keep it).
7. Back in the admin, delete the Northside row created in step 2 (or re-run the seed command from
   §0.2, which resets the configuration).
8. Reload as `l3@qa.test`.
   - **Expect:** the Messages button is back.

## §5 Messaging off: no button for anyone

1. Create a scratch settings module `config/settings_qa_messaging_off.py` (do not commit it):

   ```python
   from config.settings_dev import *  # noqa: F403

   MESSAGING_ENABLED = False
   ```

2. Stop the dev server and restart it:
   `DJANGO_SETTINGS_MODULE=config.settings_qa_messaging_off uv run python manage.py runserver $PORT`.
3. Sign in as `l1@qa.test` (who has conversations) and load the dashboard.
   - **Expect:** no Messages button; the bell is still there and still opens.
4. Visit `/messages/`.
   - **Expect:** 404.
5. Delete the scratch settings module and restart the server on the dev settings.

## §6 Reset

Re-run `uv run python manage.py qa_create_direct_messaging_scenario --site-name DemoDev` so the
next pass starts from the seeded state (it restores Sam's conversation, removes the Sid-to-Sam
conversation §3 made, and resets the Northside configuration).
