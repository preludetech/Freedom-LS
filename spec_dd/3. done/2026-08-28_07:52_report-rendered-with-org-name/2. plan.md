# Implementation plan: Reports rendered with the organisation's brand

Spec: `1. spec.md` in this directory. Read it before starting — this plan does not restate its
reasoning, only what to build and in what order.

## Ground rules

- **TDD.** Every task below states the tests to write *first*. Write the failing test, watch it
  fail, then write the code. Do not write the whole suite up front.
- **No model changes, no migrations.** If `uv run manage.py makemigrations --check --dry-run`
  reports anything, something went wrong.
- **Marker discipline.** `pyproject.toml:79` sets `addopts = "... -m 'not ci_only and not
  weasyprint' ..."`, so WeasyPrint-marked tests **do not run** on a plain `uv run pytest`. Run them
  explicitly: `uv run pytest -m weasyprint freedom_ls/reports/`.
- **Layer contract.** `indexes.py` is the only module that does I/O. `gather.py` issues no queries
  and holds only pure decisions. `render.py` and `report_data.py` never touch the ORM. This is
  documented in the module docstrings and **not mechanically enforced** — keep it by hand.
- **Commit with `uv run git commit`** (pre-commit hooks).

## Task 2 — The pure text decisions in `gather.py`

Two module-level helpers, placed beside `_abbreviate_quiz_title` (`gather.py:140-157`), following
its shape exactly: small, pure, no I/O, docstring explaining the *why*.

There are **three** text decisions but only **two** functions, because two of the decisions are the
same operation at different budgets. The cover wordmark and the footer identity line both need the
name cut to a length their slot can hold; only the number differs. One `_truncate_to_budget`
helper serves both — writing two near-identical truncators would be the repetition CLAUDE.md tells
us to extract.

### 2a. Tests first — `freedom_ls/reports/tests/test_gather_helpers.py`

Two new classes modelled on `TestAbbreviateQuizTitle` (`test_gather_helpers.py:129-152`). No
markers, no database. Cover, per function:

`_wordmark_size_class(name)`
- a short name → `"full"`
- a name exactly at the `full` threshold → `"full"`
- one character past it → `"condensed"`
- a name past the `condensed` threshold → still `"condensed"` — the class has two values, and a
  name too long for the condensed budget is handled by truncating the text, not by inventing a
  third size
- an empty string → `"full"` (defensive; an organisation always has a name)

`_truncate_to_budget(text, max_chars)`
- text under the budget → returned unchanged
- text exactly at the budget → unchanged, **no ellipsis**
- text one character over → truncated with a single `…` (U+2026), and the **total** length
  including the ellipsis is within budget — assert `len(result) <= max_chars`
- assert `"..."` (three periods) is *not* what gets appended
- a cut landing on a space does not leave a dangling `"Foo …"`
- an empty string → `""`
- a budget of 1 → does not produce something longer than 1 character (guards the `max_chars - 1`
  arithmetic against an off-by-one at the small end)

Then, at both real budgets, one case each proving the wiring: a 150-character name truncated at
`WORDMARK_CONDENSED_MAX_CHARS` and at `FOOTER_ORGANISATION_MAX_CHARS` gives two *different*
lengths, both within their own budget.

Pin the threshold constants by importing them, not by re-typing the numbers in every test.

### 2b. Implementation

```python
# Character budgets for the cover wordmark and the footer identity line. They
# are paired with specific print.css rules -- the 70mm cap on the wordmark
# slot, the footer row's fixed height -- so they are constants rather than
# settings: a project that changed one without the other would get a budget
# describing a slot that no longer exists.
WORDMARK_FULL_MAX_CHARS = 42
WORDMARK_CONDENSED_MAX_CHARS = 87
FOOTER_ORGANISATION_MAX_CHARS = 40


def _wordmark_size_class(name: str) -> str:
    """Which of print.css's two wordmark sizes this name is set at.

    WeasyPrint implements neither `text-overflow` nor `block-ellipsis`, so the
    stylesheet cannot rescue a long name at render time -- the size is a
    decision, made here, and asserted in a unit test.
    """
    return "full" if len(name) <= WORDMARK_FULL_MAX_CHARS else "condensed"


def _truncate_to_budget(text: str, max_chars: int) -> str:
    """`text` cut to `max_chars`, ending in a single ellipsis when it had to be.

    The cover wordmark slot and the footer identity line both hold a fixed
    amount of the organisation's name and neither can grow, so both need this;
    only the budget differs. One ellipsis character rather than three periods,
    because three periods cost three of the characters the budget was counting.
    """
    if len(text) <= max_chars:
        return text
    return text[: max_chars - 1].rstrip() + "…"
```

Note the `- 1` and the `rstrip()`: the ellipsis counts toward the budget, and a cut landing on a
space would otherwise leave `"Foo …"`. Both are cases the tests above assert.

`_truncate_to_budget` is called at two budgets in Task 4b — `WORDMARK_CONDENSED_MAX_CHARS` for the
cover, `FOOTER_ORGANISATION_MAX_CHARS` for the footer. Applying the wordmark budget unconditionally
is correct: a name short enough for the `full` size class is comfortably under the condensed budget
too, so the call is a no-op for it.

The three constants are **starting values**. Task 8 tunes them against a real render and updates
both the constants and the tests that pin them.

### 3d. Implementation

In `freedom_ls/reports/indexes.py`, beside `resolve_site_name()` (`indexes.py:577-586`):

```python
def load_organisation_logo_data_uri(organisation: Organisation) -> str | None:
    """The organisation's logo as a base64 `data:` URI, or None to fall back to the wordmark.

    Read through the storage API rather than `FieldFile.path`: `Storage.path()`
    raises NotImplementedError by default and S3Storage does not override it,
    so a path-based read works on local disk and breaks in production. Reading
    the bytes here also keeps the render layer's URL fetcher from ever having
    to reach a network.

    Every failure lands on None. An uploaded media object can drift at runtime
    independently of any deploy, so unlike the site logo -- deploy-time
    configuration, which raises when it is broken -- a vanished, corrupt,
    oversized or bomb-shaped logo degrades to the wordmark and the report still
    generates. Field validators only run under full_clean(), so an unvalidated
    file can reach storage: the checks below are the read path re-applying what
    the upload validator would have.
    """
    if not organisation.logo:
        return None

    try:
        with organisation.logo.storage.open(organisation.logo.name, "rb") as handle:
            raw = handle.read()
    except OSError:
        return None

    if len(raw) > MAX_BYTES:
        return None

    try:
        # verify() decodes the whole stream, not just the header, and destroys
        # the object it is called on -- hence the re-open for the format. A
        # header can parse cleanly over a truncated or corrupt body, and that
        # file would otherwise be embedded as an image WeasyPrint then silently
        # fails to draw, leaving an empty brand slot on the cover instead of the
        # wordmark that is supposed to stand in for a missing logo.
        Image.open(io.BytesIO(raw)).verify()
        image_format = Image.open(io.BytesIO(raw)).format
    except (OSError, Image.UnidentifiedImageError, Image.DecompressionBombError):
        return None

    mime_type = LOGO_MIME_TYPES.get(image_format or "")
    if mime_type is None:
        return None

    return f"data:{mime_type};base64,{base64.b64encode(raw).decode('ascii')}"
```

Every line here is load-bearing — spec §5.2 lists why for each. In particular: `logo.storage` not
`default_storage`; `storage.open()` not `field.open()` (which caches a handle on the live
instance); a context manager; MIME from a fresh decode not the filename; `DecompressionBombError`
in the tuple (it subclasses `Exception`, not `OSError`); no bare `except Exception`.

**`except OSError` around the storage read is correct and must not be widened.** It looks too
narrow for S3, and it is not: `S3Storage._open()` translates a 404 into a plain `FileNotFoundError`
(`.venv/.../storages/backends/s3.py:529-537`, verified against the installed version) and re-raises
any *other* `ClientError` unchanged. So a vanished object falls back to the wordmark on both local
disk and S3, while an S3 outage or credentials failure propagates — deliberately, and consistently
with the ORM failures the loaders around it already let through. Do not add `ClientError` here;
that would swallow an infrastructure outage as "no logo" and render a wrong report instead of
failing.

New imports at the top of `indexes.py`: `base64`, `io`, `from PIL import Image`,
`from freedom_ls.organisations.models import Organisation`,
`from freedom_ls.organisations.validators import LOGO_MIME_TYPES, MAX_BYTES`.

**Do not hide the `Organisation` import behind `TYPE_CHECKING`** — `MAX_BYTES` is a runtime import
regardless, and the point is to declare the dependency honestly (spec §5.4).

```python
# The mediatypes this app itself emits, derived from the one list that decides
# which image formats an organisation may upload -- so dropping a format there
# closes it here too, rather than leaving a fetcher that still accepts it.
_ALLOWED_DATA_URI_MEDIATYPES = frozenset(LOGO_MIME_TYPES.values())


    def fetch(url: str) -> URLFetcherResponse:
        from weasyprint.urls import FatalURLFetchingError, default_url_fetcher

        parsed = urlsplit(url)
        if parsed.scheme == "file":
            path = Path(url2pathname(parsed.path)).resolve()
            if path in allowed_paths:
                return default_url_fetcher(url)
        elif parsed.scheme == "data":
            _validate_report_data_uri(parsed.path)
            return default_url_fetcher(url)
        raise FatalURLFetchingError(f"External resource fetch refused: {url}")
```

with a module-level helper that raises `FatalURLFetchingError` on anything it does not recognise:

```python
def _validate_report_data_uri(payload: str) -> None:
    """Refuse any `data:` URI that is not one this app itself emits.

    Narrow to the three image mediatypes the organisation-logo loader produces,
    base64 only, under the same 2 MiB cap the upload validator enforces. FLS's
    own path can never reach the cap -- the loader refuses to build a URI from
    more than MAX_BYTES of source bytes -- so this exists for a future caller
    that reuses this fetcher for an image source nobody has validated.
    """
```

Body, in order:

1. Split the payload on the first `,`; no comma → refuse.
2. Split the metadata on `;`. The **first** element is the mediatype; require it to be in
   `_ALLOWED_DATA_URI_MEDIATYPES`. Any remaining elements must be exactly `["base64"]` — this both
   requires base64 and refuses stray parameters.
3. `base64.b64decode(data, validate=True)` inside a `try`, catching `binascii.Error` and raising
   `FatalURLFetchingError` from it. `validate=True` matters: without it, non-alphabet characters
   are silently discarded.
4. `len(decoded) > MAX_BYTES` → raise `FatalURLFetchingError`.

Import `LOGO_MIME_TYPES` and `MAX_BYTES` from `freedom_ls.organisations.validators` at module level
in `render.py`, and `base64` / `binascii` from the stdlib. Note this import is safe for the layer
contract: `validators.py` imports only Pillow and Django form/validation machinery, never a model,
so it does not drag the ORM into the render layer. Note `FatalURLFetchingError` is imported lazily inside
`fetch` today; the helper needs it too — import it lazily inside the helper for the same reason
(`render.py:1-12`: no WeasyPrint at module import time).

Loudness here is deliberate and correct, and does **not** contradict Task 3's silent fallback: a
bad logo degrades to the wordmark *before* it ever becomes a URI, so the only way to reach this
raise is a caller that skipped that.
