# Spec: reporting and dashboards (educator interface spec 10)

Idea: `idea.md`. Effort context: the "Educator interface rebuild" section of
`spec_dd/1. next/roadmap.md`. Measurements behind the data decisions:
`research_gather_measurement.md`. Other research: the `research_*.md` files beside this spec.

## Purpose

An educator's only view of learner progress is the cohort report PDF, which they request from the
Django admin. The educator interface's dashboard is a placeholder. The cohort Overview's "Needs
attention" card always reads "Nothing needs attention yet". The learner page shows a progress bar per
course and nothing more. This spec puts the report's gathered data on screen at three levels
(organisation, cohort, learner). It moves PDF generation and download into the interface and adds a
CSV export of the learners tables.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| progress gather | coined | `gather_cohort_progress`: the cohort report gather cut down to the cohort, registrations, roster, course catalogue and progress index. It yields recomputed completion and at-risk flags per learner, with no quiz confusion and no wrong answers. No existing term, because the gather has only ever run whole. |
| recomputed completion | coined | `LearnerDetail.completion_percentage`: completed course items over viewable items, recomputed from topic and form progress records. Distinct from the **progress percentage** (`CourseProgress.progress_percentage`). |
| progress status | coined | Not started, in progress or complete, derived from recomputed completion. The same three buckets exist as `CourseProgressStatusFilter` (`learner_progress/admin.py`) and the player's item status (`course_minimal_toc.html`). Neither is reused: one filters stored records and the other describes a single item. Not `LearnerStatus` (active, pending, removed). |
| learner drill-down | coined | The per-course detail on the learner page's Courses tab (`LearnerCoursesPanel`). |
| learners CSV export | coined | The data table framework's CSV export, enabled on the learners table so the organisation Learners list and a cohort's Learners tab both export: Name, Email, Status, Cohorts, Courses, Last active. It replaced the "cohort members CSV" (learners plus educators, on the Report tab) after QA found that one misplaced. |

## Scope

In:

- The organisation dashboard, replacing `DashboardPanel`'s placeholder: four stat tiles, a
  needs-attention list across visible cohorts, and a cohort progress list.
- A Report tab on the cohort detail page that renders the gathered report data.
- The cohort Overview's "Needs attention" card, filled from the progress gather.
- The learner drill-down.
- Generating and downloading the cohort report PDF from the cohort page.
- The learners CSV export.
- One shared definition of progress status and at-risk flags in `reports`.
- Removed learners leave the report roster, in the PDF too.

Out:

- Redesigning the PDF or its pipeline, beyond the roster filter above. Deadlines. Retakes.
  Messaging. Anything learner-facing.
- Report types beyond the cohort report and the learners CSV export.
- Charts of any kind. Progress bars that carry a number are not charts.
- A quick view version of the learner drill-down. The learner quick view stays as spec 7 left it.
- Mockup elements the idea leaves out (see `idea.md`).
- Report retention, scheduled or emailed reports, shareable links (`docs/product/reports.md` Limits
  stay true).

## Decisions

1. **Which data each level reads.** The gather's answer loaders dominate its time, while its query
   count stays constant (`research_gather_measurement.md`). The Learners and Cohorts tiles are ORM
   aggregates. The Average progress and Learners needing attention tiles, the attention lists, the
   cohort rows and the drill-down read the progress gather. Only the Report tab runs the full
   gather.
2. **A short per-cohort cache, not event invalidation.** Invalidating on progress events would
   couple the cache to every progress write path.
3. **Figures use recomputed completion, never the progress percentage**, so the dashboard, the
   Report tab and the PDF show one number. The learner quick view keeps showing the progress
   percentage; see Open questions.
4. **Removed learners leave the roster.** `load_roster` keeps only memberships whose
   `Learner.is_active` is true, the predicate `cohort_counts` uses, so the report's learner count
   matches the cohort header and the Learners tab. The PDF changes with it.
5. **The learners CSV comes from the table export hook, not a view of its own.** The spec first
   called for a one-off members CSV (learners plus educators) on the Report tab. QA found it
   misplaced there, so it was replaced by `get_export_columns` on `LearnerDataTable`, which serves
   the organisation list and the cohort tab, honours the table's search and filters, and leaves
   educators to the Settings tab.
6. **The drill-down uses a per-learner loader with the gather's shape.** The cohort gather needs a
   cohort and cannot cover individually registered courses, so the idea's fallback applies. It runs
   live and uncached: one learner across two courses measured 24 ms and 11 queries.
7. **Generate and download are gated on `download_cohort_report`**, which is what the existing
   `reports/views.py` generate and download views check. The idea's `can_view_cohort` guards only
   the admin changelist.
8. **Presentation stays in `educator_interface`, data in `reports`.** This adds the edges
   `educator_interface → reports`, which is acyclic: `reports` imports neither
   `educator_interface` nor `panel_framework`.

## Requirements

### `reports`: gathers (`freedom_ls/reports/gather.py`, `indexes.py`, `report_data.py`)

- `load_roster(cohort, site_id)` applies the Decision 4 filter before the `REPORTS_MAX_LEARNERS`
  check, so removed learners do not count toward the limit.
- `gather_cohort_report_data` splits into a shared core (`load_cohort`, `load_registrations`,
  `load_roster`, `build_course_catalogue`, `load_progress_index`, then per-learner assembly) and
  the answer stages (`load_first_attempt_ids`, `load_quiz_questions`,
  `load_selected_options_by_pair`, `load_distractor_rows`, the tallies) plus branding
  (`load_organisation_logo_data_uri`, `resolve_site_name`). Neither gather copies the other's code.
- New `gather_cohort_progress(cohort_id: str, site_id: int) -> CohortProgressData` runs only the
  core. `CohortProgressData` holds `cohort_id`, `cohort_name`, `generated_at`, `learners:
  list[LearnerSummary]`, `attention_list`, `cohort_size`, `mean_completion: int | None` (`None` for
  an empty cohort), `median_completion`, `not_started_count` and `complete_count`.
  `LearnerSummary` holds `learner_id`, `full_name`, `sort_key`, `completion_percentage`,
  `last_completed_title`, `last_completed_at` and `flags`, which is what the dashboard and Overview
  read. For the same cohort and instant, these fields equal the full gather's `LearnerDetail`
  fields.
- A public `learner_sort_key(user: User) -> tuple[str, str]` replaces the private
  `_learner_sort_key`, so another surface can order learners the way the report does.

### `reports`: screen cache (`freedom_ls/reports/screen_cache.py`, new; `config.py`)

- `cached_cohort_progress(cohort, *, refresh=False)` and `cached_cohort_report(cohort, *,
  refresh=False)` key on site id, cohort id, gather kind and a module-level schema version constant.
  They store the dataclass and expire after `REPORTS_SCREEN_CACHE_SECONDS`, a new `ReportsConfig`
  setting with default 300. `refresh=True` re-gathers and overwrites. `ReportTooLargeError` is not
  cached; it propagates.
- On every read, the cache drops learner rows whose learner is no longer an active member of the
  cohort (one query for the live active-member ids). It then recomputes the attention list and
  every count and completion figure from the remaining rows, including the full report's at-a-glance
  figures and summary rows. Quiz confusion figures are not recomputed and keep the cached figures
  until expiry.
- The cache holds permission-neutral cohort data. Callers authorise before reading.
- The plan measures the pickled size of both dataclasses at 300 learners against the production
  `DATABASE_CACHES` `MAX_ENTRIES`. Measured: about 385 KiB for the progress gather, of which
  `LearnerSummary` keeps a fraction, and 1.3 MiB for the full gather.

### `reports`: learner drill-down data (`gather.py`, `indexes.py`)

- New `gather_learner_course_details(learner: Learner, registrations: list[LearnerCourseRegistration | CohortCourseRegistration], site_id: int) -> list[LearnerCourseDetail]`
  returns one entry per registration, in the order given. Each `LearnerCourseDetail` holds the
  course title, the registration (cohort name or individual), `completion_percentage`,
  `completed_item_count`, `total_item_count`, `completed_items`, `quiz_results: list[QuizResult]`
  (every attempt with score, percentage and pass state), `last_completed_title`,
  `last_completed_at`, `flags: list[AtRiskFlag]` evaluated over that course alone, and
  `progress_status`.
- The progress indexes it builds are keyed by course progress record, not only by learner and
  item. A learner holding a course through a cohort and individually, or through two cohorts, gets
  separate entries that never merge. `_registration_ids` accepts individual registrations as well
  as cohort ones. The query count is fixed by the courses' structure, never by attempts or
  registrations.
- It reuses the gather's catalogue, folding, scoring (`_quiz_result_for`, `_score_attempt`) and
  `AT_RISK_RULES`. It reads course progress records through `reports/indexes.py`, the read path
  the domain glossary already allows.

### `reports`: one status definition (`freedom_ls/reports/statuses.py`, new)

- `ProgressStatus(TextChoices)`: `NOT_STARTED` "Not started", `IN_PROGRESS` "In progress",
  `COMPLETE` "Complete". `progress_status(completion_percentage: int) -> ProgressStatus` maps 0 to
  not started, 100 to complete and everything else to in progress. `_completion_statistics` uses it
  for `not_started_count` and `complete_count`.
- At-risk flags stay as `AT_RISK_RULES` defines them. No other module re-implements a rule or its
  7-day threshold. A learner with no course items to complete (a cohort registered for no course,
  or for an empty one) is not flagged for no recorded activity: with nothing to start, nothing has
  been left unstarted.
- `reports` returns no tones or markup. `educator_interface` maps not started to `muted`, in
  progress to `info` and complete to `success`, and a flag's `severity` (`error`, `warning`) to the
  tone of the same name.
- Wherever a learner shows, the progress status badge shows. Each at-risk flag adds a badge
  labelled with the rule's `label`, and its `reason` is visible on the row, not only in a tooltip.

### `reports`: generation and download outside the admin (`freedom_ls/reports/services.py`, new; `views.py`)

- `request_cohort_report(cohort: Cohort, user: User) -> GeneratedReport | None`, extracted from
  `generate_report_view`, holds the in-flight pre-check, the `transaction.atomic()` create, the
  `on_commit` enqueue and the `IntegrityError` race path. It returns `None` when a report is already
  in flight.
- `report_file_response(report: GeneratedReport) -> FileResponse`, extracted from
  `download_report_view`, keeps the slugified `{organisation}-{cohort}-progress-report.pdf`
  filename and the `Cache-Control: private, no-store, must-revalidate` header. It raises `Http404`
  unless `status == ready` with a readable file.
- The admin views call both, and their existing tests pass unchanged.
- `latest_cohort_reports(cohort) -> CohortReportState` returns the in-flight report, the newest
  ready report, and the newest failed report newer than that ready one. It is one `union()` of
  three sliced querysets with `select_related("requested_by")`.

### `educator_interface`: lazy panel bodies (`freedom_ls/educator_interface/reporting.py`, new)

New panels, queries and the lazy-body helper go in `reporting.py`, which `views.py` imports.
A gather-fed panel renders a `c-panel-skeleton` unless the request carries `loaded=1`. The
skeleton fetches the same panel URL with `loaded=1` using `hx-get`, `hx-trigger="load"` and
`hx-swap="outerHTML"`, per the `ds:htmx` skill. A `<noscript>` link points at the loaded URL. The
dashboard's gather-fed region, the Report tab body and the Overview "Needs attention" card all use
it.

### `educator_interface`: organisation dashboard (`DashboardPanel`, `templates/educator_interface/panels/dashboard.html`)

- **Visible cohorts**: `cohorts_visible_to(request.user, organisation)` filtered to
  `is_active=True`. One queryset feeds every figure below.
- **Stat tiles** (`c-panel-stat-row` with four `c-panel-stat-tile`):
  - Learners: a single aggregate counting distinct learners with `Learner.is_active` who are members
    of a visible cohort. Sub-line "Across N cohorts". Renders inline.
  - Cohorts: the visible cohort count, linking to the cohorts section. Renders inline.
  - Average progress: each learner in the progress gathers counts once, at the mean of their
    recomputed completion across their visible cohorts. Shown with a `c-panel-progress-bar`, and a
    dash rather than 0% when there are no learners. Lazy.
  - Learners needing attention: the uncapped count of distinct learners with at least one at-risk
    flag in any visible cohort's progress gather, read from `learners`, not from the capped
    `attention_list`. Lazy.
  The two lazy tiles show a skeleton value until the lazy region loads. One fetch fills both
  tiles, the list and the cohort rows.
- **Needs attention list**: one row per flagged learner. Each row names the learner, links to their
  learner page, has a quick view trigger for `LearnerQuickView`, and lists each visible cohort the
  learner is flagged in with the cohort's active course titles and that cohort's flag badges and
  reasons. Rows carry no leading icon: it was the same for every row and said nothing. From `lg`
  up the cohort detail sits in a column to the right of the name, so a row stays short. Rows are ordered by the
  learner's lowest recomputed completion across their flagged cohorts, then by `sort_key`. The
  list shows at most `ATTENTION_LIST_MAX` rows and says "N flagged, M shown" in
  `cap_disclosure.html`'s wording when it cuts. When nobody is flagged it says "Nobody needs
  attention right now".
- **`panel-attention-row` extension** (`panel_framework/templates/cotton/`): a default slot for
  per-cohort detail and a trigger slot. The trigger is a `<button>` with `relative z-10` whose
  accessible name includes the learner's name, so it sits above the stretched row link at phone
  width. `component_reference.html`, `_examples.html` and `panel_framework/tests/components` are
  updated.
- **Cohort progress list**: one row per visible cohort within the limit, with the cohort name linked
  to the cohort page, `mean_completion` as a number and a bar, the learner count and the flagged
  count. Ordered by lowest mean first, then by name.
- **Freshness and limits**: "Figures as of <oldest generated_at among the gathers used>". A cohort
  whose gather raises `ReportTooLargeError` is left out of the gather-fed figures (it still counts
  in Learners and Cohorts). A notice names it: "<cohort> has N learners, over the report limit of M,
  and is not included".
- **Empty states**: with no visible cohorts, an organisation admin sees "You have no cohorts yet"
  and anyone else sees "No cohorts are assigned to you". No division by zero.
- The placeholder copy "On-screen reporting for … arrives in a later release" is removed.

### `educator_interface`: cohort page (`CohortTabSet`, `CohortOverviewStack`)

- **Report tab**: a `report` child of `CohortTabSet`, after `learners` and before `settings`. It
  is a `PanelStack` of a downloads panel and a lazy body panel. The body renders
  `cached_cohort_report(cohort)` as panels in the PDF's order, under the PDF's section headings:
  - At a glance: cohort size, median completion, and the not started and complete counts.
  - Attention list: flags and reasons, with the cap disclosure.
  - Per course: a summary table of learner rows with completion and quiz cells, split as
    `summary_tables` split them.
  - Quiz confusion per quiz, with the PDF's below-10-respondents rule (counts, not percentages).

  A "Figures as of <generated_at>" line sits at the top, with a "Refresh" control that re-requests
  the body with `refresh=1`. Over the limit, the body shows the `ReportTooLargeError` message
  instead. Per-learner detail with wrong answers is not rendered on screen. Learner names link to
  the learner page.
- **Downloads panel**:
  - The panel is shown only to a role holding
    `freedom_ls_learner_management.download_cohort_report` on the cohort (the panel's
    `capability`); without it the Report tab shows the report body alone. While the generate
    form's POST is in flight the button is disabled and reads "Generating…" with a spinner.
  - Contents:
    - Idle: a "Generate PDF report" button that POSTs to `request_cohort_report`.
    - In flight: "A report is being generated", requested by <name> at <time>. The region polls
      every 3 s and is `role="status"` / `aria-live="polite"`. Once the report is ready or failed,
      the response drops the polling trigger. Once it has been in flight for 10 minutes, the
      response also drops the trigger, says "This is taking longer than expected" and offers a
      manual refresh link.
    - Ready: "Download PDF (generated <time> by <name>)" and "Generate a new report".
    - Failed: the report's `error_message` and a retry button.
    - A POST that loses the in-flight race returns the in-flight state, not an error.
- **Overview "Needs attention" card** (`CohortNeedsAttentionPanel`): a lazy body rendered from
  `cached_cohort_progress(cohort).attention_list`, with flag badges, reasons, learner links and the
  cap disclosure. Over the limit, it shows the `ReportTooLargeError` message. The
  `{% comment %}TODO …{% endcomment %}` in `cohort_needs_attention.html` is removed, because this
  completes it.

### `educator_interface`: file routes (`freedom_ls/educator_interface/urls.py`)

Two `re_path` routes go before the catch-all. Each resolves the organisation with the same shared
code the `interface()` view uses, sets `request.organisation`, and authorises the cohort through
`CohortConfig.get_instance_view`. An organisation or cohort out of scope is a 404.

- **PDF download**: `get_object_or_404` on the `GeneratedReport` scoped to that cohort, the
  `download_cohort_report` check, then `report_file_response`.
- **Learners CSV export**: `LearnerDataTable.get_export_columns()` returns Name, Email, Status,
  Cohorts, Courses and Last active, every value read from the caches `get_queryset` prefetches or
  annotates. The framework's export response supplies the BOM, `escape_csv_formula`, streaming,
  the table's current search, filters and sort, and the filename
  `learners[-{cohort-slug}]-{YYYY-MM-DD}.csv` (`CohortLearnersPanel.get_export_scope_slug`
  names the cohort). The toolbar's "Export CSV" link appears on both learners tables.

### `educator_interface`: learner drill-down (`LearnerCoursesPanel`, `templates/educator_interface/panels/learner_courses.html`)

- `LearnerRegistrationProgress` (`learner_progress/queries.py`) gains the registration object, and
  the panel passes the registrations `visible_registrations_with_progress` returns to
  `gather_learner_course_details`. Registrations through a cohort the viewer cannot see stay
  hidden.
- One card per registration, with:
  - the course title, "via <cohort>" or "Individual", the progress status badge and any flag
    badges with reasons;
  - a progress bar with "N of M items";
  - the last completed item and when;
  - the completed items, collapsed by default;
  - an attempts table per quiz: attempt number, completed date, score, percentage, pass mark, and
    a "Passed" or "Failed" badge carrying the word, with the latest attempt marked.
- "Not registered on any courses yet" when there are none.

### Permissions

- Every new panel goes through the existing organisation authorisation and the cohort or learner
  `authorise_instance`. Out of scope is a 404.
- Cohort admins and cohort viewers see dashboard figures computed only over their assigned cohorts.

### Mobile

At phone width the tiles go two-up, and the attention and cohort rows become two-line rows with
the whole row tappable. Summary tables scroll horizontally inside their card with the learner
column sticky. The download buttons go full width.

## Testing

- `gather_cohort_progress` runs only the core loaders (fewer queries than the full gather), and its
  `LearnerSummary` fields equal the full gather's for the same cohort.
- `gather_learner_course_details`: the query count is constant across 1 and 3 attempts per quiz
  and across one and two registrations. A learner holding one course through a cohort and
  individually gets two unmerged entries. Flags and percentages for a cohort-registered course
  equal the cohort gather's for that learner.
- `screen_cache`: a second read within the TTL re-gathers nothing. A learner removed after caching
  disappears from rows and counts on the next read. `ReportTooLargeError` is not cached.
- Dashboard, per role (`organisation_admin`, `cohort_admin`, `cohort_viewer`), with an
  out-of-scope cohort and a second site seeded: every figure covers only visible cohorts. The
  attention tile equals the uncapped distinct flagged count, including above
  `ATTENTION_LIST_MAX`. A learner in two cohorts counts once in Average progress.
- Downloads: a second POST returns the in-flight state. The in-flight fragment keeps its polling
  trigger, and the ready, failed and over-10-minutes fragments drop it, tested with seeded
  `GeneratedReport` rows at the client level.
- File routes: 404 for an out-of-scope organisation, an out-of-scope cohort, another cohort's
  report, a pending or failed report, and a viewer without `download_cohort_report` (PDF only).
- Learners CSV export: a name of `=HYPERLINK("x","y")` is neutralised. A cohort tab's export
  lists that cohort's learners only and names the cohort in the filename. A learner never active
  has an empty Last active cell.
- `educator_interface/tests/invariants/test_permission_matrix.py` exercises
  `download_cohort_report`. `test_dashboard.py`'s placeholder assertion is replaced.
- Playwright: generate a report on the cohort page and a download link appears (needs the compiled
  Tailwind bundle). The dashboard renders at phone width.

## Open questions

- The learner quick view and the learner list's Courses cell show the progress percentage, while
  the drill-down and dashboard show recomputed completion. They can disagree for one course. Is
  moving the quick view onto recomputed completion a spec 12 item?
- `ATTENTION_LIST_MAX` (12) caps the dashboard list, and nothing lists every flagged learner across
  cohorts. Is a "view all" page wanted later?
- Both gathers jump more than threefold between 100 and 300 learners (the full gather reached 14 s
  at 300). The cause is unconfirmed. Should the plan take an `EXPLAIN` of the 300-learner loaders
  before building on these numbers?
- Q: Should the first tile say "Active learners", as the idea does? → A: It says "Learners".
  (Assumed default: `LearnerStatus.ACTIVE` excludes pending learners, but the tile counts every
  learner not removed, pending included. "Active" would read as the narrower status. Overrule by
  editing the Stat tiles requirement.)
- Q: Is "cohort members CSV" clear, given `CohortMembership` covers learners only? → A: Keep it,
  defined in Terminology. (Superseded after QA: the members CSV was replaced by the learners CSV
  export, see decision 5.)

## Success criteria

- An educator with `download_cohort_report` generates and downloads the cohort PDF from the cohort
  page without the Django admin.
- A cohort viewer's dashboard shows the four tiles, the needs-attention list and the cohort
  progress list, computed over their cohorts only.
- The Report tab's at-a-glance figures equal the PDF's for the same cohort and gather.
- `grep progress_percentage` over `reporting.py` and the new templates finds nothing.
