Implements `1. spec.md`. Work test first in every slice: write the failing test the slice names,
watch it fail, make it pass, then run the full suite (`uv run pytest -n auto`, backgrounded, once)

type hints (`**kwargs: object` on receivers, `QuerySet[Model]` where the row type is known), no

## Slice 1: the Members section lists who holds a role

**Behaviour:** an organisation admin or site-level admin sees an "Administration" group in the
sidebar with a "Members" section. Its list has one row per member (name with the email under it,
or the email alone), built from active `organisation_admin`, `cohort_admin` and `cohort_viewer`
assignments on the organisation or any of its cohorts. A cohort admin or cohort viewer sees no
such menu entry and gets 404 on `members`. Any path under `members/<anything>` is 404.

**Design states:** none (no design registered).

1. `freedom_ls/panel_framework/views.py`, `SectionConfigBase`:

   ```python
   #: The capability a request needs to see this section at all, asked on
   #: get_scope's object. None means the section shows whenever the
   #: interface itself is reachable. A section the request cannot see is
   #: left out of the menu and every path under it is a 404, so its
   #: existence is never confirmed to someone outside its audience.
   view_capability: str | None = None

   @classmethod
   def is_visible(cls, request: HttpRequest) -> bool:
       if cls.view_capability is None:
           return True
       scope = cls.get_scope(request)
       if scope is None:
           return False
       return cls.has_capability(request, cls.view_capability, scope)
   ```

   `_build_menu_items` skips a section whose `is_visible(request)` is false (the group is
   dropped when it ends up empty, which the existing `if items:` already does). `_resolve_path`
   raises `Http404("Section not shown")` right after `sections[parts[0]]` when the section is not
   visible, before `_bind_root`, so action, panel and quick-view paths under a hidden section all
   404. `_build_breadcrumbs` needs nothing: a 404 never reaches it.
2. `ListViewConfig.get_instance_view`: when `cls.instance_view is None`, raise
   `Http404(f"{cls.__name__} has no instance pages")` instead of `ValueError`; keep the
   `ValueError` for a missing `model`. The docstring on `ListViewConfig` says a list may have no
   instance pages, in which case no row links anywhere.
3. `freedom_ls/educator_interface/tests/interface_walk.py`: in the `ListViewConfig` branch,
   after walking the list's own actions, `if section.instance_view is None: continue`, so no
   instance is seeded and no detail walk runs. `_seed_instance` is unchanged.
4. `freedom_ls/learner_management/queries.py` (not `role_assignment.py`, which imports
   `queries.py` at module level, so the constant lives where both can read it;
   `role_assignment.py` imports it, and the educator interface reads it from either):

   ```python

   #: downstream site may add roles to its config, but none of them has an
   #: assign_ capability, so none can be offered or shown here.
   ```

5. `freedom_ls/learner_management/queries.py`, reusing `_active_role_assignments` from
   `capabilities.py` (the one place the assignment join is written):

   ```python
   def member_assignments(organisation: Organisation) -> QuerySet[ObjectRoleAssignment]:
       """Active member-role assignments on the organisation itself or on any
       of its cohorts, active cohorts and inactive alike. Built from the
       assignment rows rather than OrganisationMember rows, because a member
       row only exists once a grant created it and nothing backfilled them."""
       roles = frozenset(MEMBER_ROLES)
       cohort_keys = (
           Cohort.objects.filter(organisation=organisation)
           .annotate(key=Cast("pk", output_field=CharField()))
           .values("key")
       )
       return _active_role_assignments(Organisation, roles).filter(
           object_id=str(organisation.pk)
       ) | _active_role_assignments(Cohort, roles).filter(object_id__in=cohort_keys)


   def members_of(organisation: Organisation) -> QuerySet[User]:
       """Everyone holding a member role in the organisation, suspended members
       and turned-off accounts included: they still hold the role. A site
       admin or superuser is here only through such a role, never through
       their site-level access."""
       return User.objects.filter(
           pk__in=member_assignments(organisation).values("user_id")
       ).order_by("first_name", "last_name", "email", "pk")
   ```

   `User` is imported inside the function the way `active_organisation_admins` does it.

## Slice 2: roles, markers and who added whom

**Behaviour:** each row shows the roles held, each with its scope ("Whole organisation", or the
first two cohort names then "+N more", an inactive cohort marked "(inactive)"), and who added it
and when ("Not recorded" for a null grantor). Markers beside the name: "You", "Suspended",
"Account turned off", "Also a learner". Reactivating an assignment or changing its grantor moves
`assigned_at` to now. A full page of ten members stays under a fixed query bound.

**Design states:** none.

1. `freedom_ls/role_based_permissions/utils.py`: the "reactivate or change grantor" block that
   `assign_object_role`, `assign_site_role` and `assign_system_role` each repeat becomes one
   helper:

   ```python
   def _refresh_assignment(
       assignment: ObjectRoleAssignment | SiteRoleAssignment | SystemRoleAssignment,
       assigned_by: User | None,
       *,
       stamp: bool,
   ) -> list[str]:
       """Reactivate the row and record the grantor; with `stamp`, the grant
       time moves too, so "added on" is the time of the grant that set
       "added by"."""
   ```

   returning the fields to update (empty when nothing changed). `assign_object_role` and
   `assign_site_role` call it with `stamp=True`, `assign_system_role` with `stamp=False`.
2. `freedom_ls/panel_framework/views.py`, `ListViewConfig`:

   ```python
   @classmethod
   def get_cell_context(cls, request: HttpRequest) -> dict[str, object]:
       """Extra context every cell template of this list renders with,
       computed once per request rather than once per row. Empty by default."""
       return {}
   ```

   `PanelContext.config` is typed `type[SectionConfigBase]`, so `_bind_root`'s list branch sets
   `table.cell_context = section.get_cell_context(request)` on the bound `ListViewPanel`, the
   way it already sets `bulk_actions`; `ListViewPanel.cell_context: dict[str, object] = {}` and
   its `get_context_data` merges it after `super().get_context_data()`, so a cell reaches it the
   way `membership_actions.html` reaches `manageable_cohort_ids` today. `interface_walk._bind`
   leaves it at the default.
3. New `freedom_ls/educator_interface/members.py`, imported by both `views.py` and
   `actions.py` (which may import `views.py` only under `TYPE_CHECKING`):

   ```python
   @dataclass(frozen=True)
   class RoleEntry:
       """One role a member holds in the organisation: its scope, and the
       newest grant that set who added it."""

       role: str
       display_name: str
       cohorts: tuple[Cohort, ...]  # empty for organisation_admin
       assigned_by: User | None
       assigned_at: datetime

       @property
       def scope(self) -> str:
           if self.role == "organisation_admin":
               return "Whole organisation"
           names = [
               c.name if c.is_active else f"{c.name} (inactive)" for c in self.cohorts
           ]
           if len(names) <= 2:
               return ", ".join(names)
           return f"{', '.join(names[:2])} +{len(names) - 2} more"


   def member_role_entries(user: User, site: Site) -> list[RoleEntry]:
       """Reads only the held_assignments prefetch and each assignment's
       prefetched target, so a page costs the same as one row. Entries follow
       MEMBER_ROLES order; cohorts sort by name; the display names come from
       the site's role config."""
   ```

   A cohort role whose targets did not resolve raises `ValueError`, never reads as
   organisation-wide: a missing target means the cohort-deletion cleanup failed.

   `MemberDataTable.get_queryset` prefetches, on each `User`:
   - `Prefetch("object_role_assignments", queryset=member_assignments(organisation).select_related("assigned_by").prefetch_related("target"), to_attr="held_assignments")`
     (a `GenericForeignKey` prefetches in one query per content type, so only the page's own
     cohorts load);
   - `Prefetch("organisationmember_set", queryset=OrganisationMember.objects.filter(organisation=organisation), to_attr="member_rows")`
     (the site-aware manager: the request's organisation is on the request's site, and every
     later `OrganisationMember` read in the educator interface uses the same manager);
   - `Prefetch("learner_set", queryset=Learner.objects.filter(organisation=organisation, is_active=True), to_attr="learner_rows")`.

   `MemberDataTable.get_rows` (the `CourseDataTable.get_rows` pattern, iterating the untyped
   `page_obj.object_list` so the per-row attributes type-check without a cast) sets
   `row.role_entries = member_role_entries(row, organisation.site)` and
   `row.is_suspended = not any(m.is_active for m in row.member_rows)` on every row of the page.
   The organisation comes from `request`, so `get_rows` keeps the framework signature.
4. `MemberConfig.get_cell_context` returns `{"viewer": request.user}`.
5. `MemberDataTable.get_columns` gains

   ```python
   class GrantableRole:

       role: str

       """The roles and cohorts a grantor may hand out in this organisation,
       in MEMBER_ROLES order. The cohorts come from one queryset per role,
       built from the same grant builders can() reads, so the cost does not
       grow with the number of cohorts. This is the source of every choice
       offered and every submitted choice checked; assign_role and
       remove_role remain the authoritative check on each target."""
       result: list[GrantableRole] = []
       if can(grantor, ASSIGN.format(role="organisation_admin"), organisation):
           result.append(GrantableRole("organisation_admin", None))
       for role in ("cohort_admin", "cohort_viewer"):
           cohorts = tuple(

               .filter(is_active=True)
               .order_by("name")
           )
           if cohorts:

       return result

       """Whether `after` lets the person do anything `before` did not. Each
       pair is a role and the key of its target (the organisation's pk or a
   ```

   ```python
       def get_context_data(self, ctx):
           user, entry = ...

               "member": user, "entry": entry, "role": config[entry.role],
               "keeps": join_prose(["their account", other roles held here as "<display name> on <scope>", "their learner access in this organisation" when an active Learner exists]),
   ```

   ```python
       whose target resolves to None. _base_manager, because a delete from the
       admin or a management command may run with no request site in scope,
       where the site-aware manager would match nothing and leave the rows
       behind."""
       target_type = ContentType.objects.get_for_model(target)
       ObjectRoleAssignment._base_manager.filter(
           content_type=target_type, object_id=str(target.pk)
       ).delete()
       UserObjectPermission.objects.filter(
           content_type=target_type, object_pk=str(target.pk)
       ).delete()
   ```
