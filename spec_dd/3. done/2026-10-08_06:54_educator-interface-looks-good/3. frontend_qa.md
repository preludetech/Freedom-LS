# Frontend QA: educator interface looks good

Browser checks for the restyled educator interface and the shared panel framework templates under
it. The restyle changes no behaviour, so every test pairs a look check against the design
screenshot with a behaviour check that what was there before still works. Tests marked **desktop**
run at 1442 wide; tests marked **phone** run at 392 wide; where it matters, 768 (the `md`
breakpoint) is named too. The design screenshots are a visual reference only: compare layout,
order, hierarchy and density, never colour, font or icon glyphs, which come from the FLS theme.

## 0. Setup

1. Pick a port and start the server:

   ```
   PORT=$(.claude/ds/scripts/find_available_port.sh)
   uv run python manage.py runserver $PORT
   ```

   The base URL is `http://127.0.0.1:$PORT`.

2. Seed data. The `DemoDev` site and the `demodev` organisation exist in the dev database. Ask the
   `fls-dev:qa-data-helper` agent for:

   - a second organisation (`QA Second Org`) that `demodev@email.com` can reach, so the
     organisation switcher is a dropdown;
   - a cohort `QA Looks Cohort` in `demodev` with 30 learners (so the learners table pages at 25)
     and one course registration, for example
     `uv run python manage.py qa_create_large_cohort DemoDev --cohort-name "QA Looks Cohort" --num-learners 30`;
   - one learner in that cohort with a long email address (40+ characters) and a long first name,
     for the overflow checks.

3. Log in at `http://127.0.0.1:$PORT/accounts/login/` as `demodev@email.com` /
   `demodev@email.com`.

4. Open `http://127.0.0.1:$PORT/educator/`. You are redirected to
   `/educator/organisations/demodev/dashboard`. Below, `/educator/ORG/` stands for
   `/educator/organisations/demodev/`.

5. Run the server with `FLS_THEME=first_class` for the look checks: the design was drawn against
   that theme. Repeat the surface checks in test 8 with the default theme too.
