# Spec: referer host normalisation

Idea: `idea.md`. Up-front answers: `answers.md`. Research: `research_*.md` in this directory.

## Purpose

`SignupAttribution.referer` holds the raw, capped `Referer` header. Anything that asks which site
sent a visitor has to reduce it to a host first, and small differences (`www.google.com`,
`google.com.`, `google.com:443`) split one source into several. Two pure helpers in
`referral_tracking` do that reduction once, for the marketing channel classifier
(`referral-tracking-marketing-channels`) and external-referer capture
(`referral-tracking-external-referer-first-touch`). First-Class-LMS then deletes its own copy
(`apps/lead_forms/referers.py`).

## Scope

In:

- `normalised_host(host: str) -> str` and `referer_host(referer: str) -> str` in a new module
  `freedom_ls/referral_tracking/referers.py`.
- Their tests.

Out:

- Any change to capture, `SignupAttribution`, the API or the CSV export. The stored referer stays
  raw; the helpers are read-side only.
- Folding subdomains other than `www.` (`m.`, `l.`, `lm.`). Grouping `m.facebook.com` with
  `facebook.com` is the classifier's job, by suffix match (`answers.md`).
- Mapping a host or package name to a platform or channel.
- Any user interface.

## Decisions

- **The names and the module match the reference** (`referers.py`, `normalised_host`,
  `referer_host`), so First-Class-LMS repoints its imports and both downstream specs use the names
  they already expect.
- **An `android-app://` referer returns the bare package name**, not a prefixed form, because the
  classifier being ported from First-Class-LMS matches on bare package names.
- **IPv6 literals keep their address**, unlike the reference, which turns `http://[::1]:8080/`
  into `""`.

## Requirements

### `freedom_ls/referral_tracking/referers.py` (new)

The module imports only the standard library. It reads no settings and touches no database. Both
helpers return `""`, never `None`, when there is no comparable host.

`normalised_host(host: str) -> str` takes a bare host as a caller has it: a `request.get_host()`
value, a `Site.domain`, or a `.hostname` from `urlsplit`. In order, it:

1. Strips surrounding whitespace and lowercases.
2. Drops the port. A bracketed IPv6 literal (`[::1]:8080`) keeps what is inside the brackets; with
   no closing bracket the value is kept as it is. A value with exactly one `:` drops everything
   from it on. A value with two or more `:` and no brackets is a bare IPv6 literal and is kept
   whole.
3. Strips surrounding whitespace again, so `google.com :443` loses the space before its port.
4. Strips trailing dots.
5. Converts a non-ASCII host to punycode with the standard library `idna` codec, so a `Site.domain`
   saved as `münchen.de` matches the `xn--mnchen-3ya.de` a browser sends. A host the codec rejects
   (an empty label, a label over 63 characters) is kept as it is. The codec is IDNA 2003, which maps
   `ß` to `ss` where browsers keep it.
6. Strips one leading `www.` if anything is left after it.

`referer_host(referer: str) -> str`:

- Splits `referer.strip()` with `urllib.parse.urlsplit` and reads `.hostname`, both inside one
  `try` that catches `ValueError` and returns `""`. It never reads `.port`, which raises on a bad
  port. `.hostname` already drops the port, the userinfo and the IPv6 brackets.
- `http` or `https` scheme with a hostname: returns `normalised_host(hostname)`.
- `android-app` scheme with a hostname: returns the hostname lowercased. Any path after the package
  is ignored.
- Anything else returns `""`: another scheme (`ftp:`, `mailto:`, `about:`), no scheme (`google.com`),
  no hostname (`http:///x`), an empty string, or a referer `urlsplit` rejects.

A referer at the 255-character cap whose authority runs to the end of the value (no path, query or
fragment after it) was cut inside its host, userinfo or port, and returns `""` rather than a partial
host such as `goo` from `https://www.goo`. A referer cut later, in its path or query, still yields its
host. The module holds the cap as `REFERER_LENGTH_CAP`, because it cannot import `models.CAPS`; a test
keeps the two equal.

## Documentation and downstream

- Upgrade notes say the two helpers are new public API in `freedom_ls.referral_tracking.referers`,
  and that a project holding its own copy can delete it and import these. For First-Class-LMS that
  means deleting `apps/lead_forms/referers.py` and its test, and repointing the imports in
  `apps/lead_forms/middleware.py`, `apps/admin_dashboard/channels.py` and
  `apps/admin_dashboard/lead_csv.py`.
- Product docs stay as they are, because nothing a user or operator sees changes.

## Open questions

- Q: Should `normalised_host` convert an internationalised host to punycode, so `münchen.de` and
  `xn--mnchen-3ya.de` compare equal? → A: Yes. Browsers send the punycode form in `Referer`, but a
  `Site.domain` can be saved in Unicode, and the two have to compare equal.

## Success criteria

- `freedom_ls/referral_tracking/referers.py` imports nothing outside the standard library.
- Neither helper raises on any `str` input. The test file asserts the exact result for control
  characters and unmatched brackets.
- `git diff main -- freedom_ls/referral_tracking/models.py freedom_ls/referral_tracking/capture.py`
  is empty.
