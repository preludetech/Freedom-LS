# Frontend QA: organisation courses

## 0. Setup

```bash
npm run tailwind_build
uv run python manage.py create_demo_data --yes
uv run python manage.py content_save ./demo_content DemoDev
PORT=$(.claude/ds/scripts/find_available_port.sh)
uv run python manage.py runserver $PORT
```

- Base URL: `http://127.0.0.1:$PORT`. Dashboard `/`, all courses `/courses/`, course detail
  `/courses/<slug>/`, Django admin `/admin/`, educator interface `/educator/`.
- Logins (password equals the email): site admin `demodev@email.com`; learners
  `demodev_s1@email.com` to `demodev_s50@email.com`, all in the DemoDev default organisation and
  its first cohort.
- The demo load creates two organisations on DemoDev, **Harbour College** (slug `harbour-college`)
  and **Northwind Logistics** (slug `northwind-logistics`), and two courses titled **Workplace
  Safety Essentials**: the Harbour one with audience `organisation_learners`, the Northwind one
  with audience `public`. Find their slugs in the admin course list
  (`/admin/freedom_ls_content_engine/course/`, column "Organisations"); call them `<harbour-slug>`
  and `<northwind-slug>` below. Every other demo course has no organisation.
- Give a learner an organisation with the admin: `/admin/freedom_ls_learner_management/learner/add/`,
  pick the user and the organisation, save. Where a step needs a registration through an
  organisation, use `uv run python manage.py qa_register_org_course --learner-email <email>
  --organisation "<name>" --course-slug <slug>`.
- Use a fresh private window per login. django-axes locks an email after five failed logins; run
  `uv run python manage.py axes_reset` if you trip it.

## Scenario 1: a learner outside both organisations

1. Log in as `demodev_s1@email.com`. Open `/`.
2. **Expect:** no card titled "Workplace Safety Essentials" from Harbour College. One card titled
   "Workplace Safety Essentials" with the byline **Northwind Logistics** under its title (the public
   one). Every other demo course renders as before, with no byline.
3. Open `/courses/`. **Expect:** the same: Northwind present, Harbour absent.
4. Open `/courses/<harbour-slug>/`. **Expect:** the site's 404 page. Also try
   `/courses/<harbour-slug>/1/` and `/courses/<harbour-slug>/access/` (the URL the detail page's
   start button posts to; a GET is fine for the 404 check). **Expect:** 404 for each.
5. Open `/courses/<northwind-slug>/`. **Expect:** the detail page renders. Click its start button.
6. **Expect:** you land in the course player. Return to `/`. **Expect:** the Northwind course is in
   the In progress section; its card shows **no** byline, because the registration went through the
   DemoDev default organisation (the learner has no row in Northwind Logistics).
7. In the admin, open `/admin/freedom_ls_learner_management/learnercourseregistration/` and find
   that registration. **Expect:** its learner reads `demodev_s1@email.com - DemoDev` (the default
   organisation).

## Scenario 2: a learner in Harbour College

1. As `demodev@email.com`, add a Learner row for `demodev_s2@email.com` in Harbour College (Setup
   notes).
2. Log in as `demodev_s2@email.com` in a private window. Open `/`.
3. **Expect:** two cards titled "Workplace Safety Essentials", one with the byline **Harbour
   College**, one with **Northwind Logistics**. The byline sits under the title, in muted text, not
   in the status line above the title. If the organisation has no logo, the byline is the name only.
4. Open `/courses/<harbour-slug>/`. **Expect:** the detail page renders. Click start.
5. **Expect:** the player opens, and the player sidebar's organisation chip shows Harbour College.
   Return to `/`. **Expect:** the Harbour course is In progress, with the byline **Harbour
   College** on its card.
6. In the admin registration list, **expect:** the new registration's learner reads
   `demodev_s2@email.com - Harbour College`, not the default organisation.
7. Now register the same learner for the Northwind (public) course from its detail page.
   **Expect:** success; the registration's learner is `demodev_s2@email.com - DemoDev`, and the card
   for it in In progress has no byline.

## Scenario 3: a learner who leaves the organisation loses access to its course

1. As the admin, open the Harbour College Learner row for `demodev_s2@email.com` and untick
   **is active**. Save.
2. As `demodev_s2@email.com`, open `/`. **Expect:** no Harbour card anywhere (a registration made
   through a deactivated Learner row grants no access). Open `/courses/<harbour-slug>/detail/`,
   `/courses/<harbour-slug>/1/` and `/courses/<harbour-slug>/access/` directly. **Expect:** 404
   for each. The admin registration list still shows exactly one registration for this learner
   and course, still through Harbour College (nothing is re-registered through the default
   organisation).
3. As the admin, tick **is active** on the Learner row again. As the learner, open `/`.
   **Expect:** the Harbour course is back in In progress, its byline Harbour College. Now
   deactivate the registration itself (the LearnerCourseRegistration row, untick is active). As
   the learner, open `/`. **Expect:** no Harbour card anywhere. Open
   `/courses/<harbour-slug>/detail/`. **Expect:** 404.
4. Restore both rows (tick is active on the Learner and the registration) before Scenario 4.

## Scenario 4: the admin refuses a registration into the wrong organisation

1. As `demodev@email.com`, open `/admin/freedom_ls_learner_management/learnercourseregistration/add/`.
2. Pick `demodev_s1@email.com - DemoDev` as learner and the Harbour "Workplace Safety Essentials"
   course. Save.
3. **Expect:** the form is not saved; a validation error on the course field says the course is not
   open to the learner's organisation.
4. Change the course to the Northwind (public) one and save. **Expect:** saved.
5. Open `/admin/freedom_ls_learner_management/cohortcourseregistration/add/`, pick a DemoDev cohort
   (`Cohort 2025.03.04`) and the Harbour course, save. **Expect:** the same refusal. Pick the
   Northwind course instead. **Expect:** saved. Delete or deactivate that cohort registration
   afterwards so later scenarios are not affected.
6. Open `/admin/freedom_ls_registration_rules/registrationrule/add/`. Organisation DemoDev,
   course the Harbour one, any name. Save. **Expect:** a refusal on the course field. Organisation
   Harbour College with the same course. **Expect:** saved.

## Scenario 5: the Course admin

1. Open `/admin/freedom_ls_content_engine/course/`.
2. **Expect:** an "Organisations" column; the two Workplace Safety Essentials rows read "Harbour
   College" and "Northwind Logistics" respectively; every other course's cell is empty. A filter by
   organisation in the right-hand sidebar; choosing Harbour College leaves one row.
3. Open the Harbour course's change page. **Expect:** Organisations and Audience shown read-only in
   the first fieldset, audience `Organisation learners`. The Northwind course shows `Public`.

## Scenario 6: the educator interface sees only courses open to the viewed organisation

1. As `demodev@email.com` (a superuser), open `/educator/organisations/demodev/courses`.
2. **Expect:** every demo course without an organisation, plus the Northwind (public) course.
   The Harbour course is absent even for a superuser.
3. Open `/educator/organisations/harbour-college/courses`. **Expect:** the Harbour course is
   listed, the Northwind one too, and the shared courses.
4. In DemoDev, open a cohort page (`/educator/organisations/demodev/cohorts`, pick
   `Cohort 2025.03.04`) and the register-for-course action. **Expect:** the course picker offers
   the Northwind course and the shared courses, never the Harbour course.
5. Still in DemoDev, open a learner's page (any `demodev_sN`) and its register action.
   **Expect:** the same picker contents.
6. Take the Harbour course's pk from the admin and open
   `/educator/organisations/demodev/courses/<pk>`. **Expect:** the denied page, not the course.

## Scenario 7: the markdown embed card

1. The demo course "Content Widgets" (`functionality_demo_content_widgets`) embeds other courses
   with `<c-course-card>`. If neither Workplace Safety Essentials course is embedded there, add a
   temporary `<c-course-card path="../functionality_demo_organisation_course_harbour/course.md">`
   and the Northwind equivalent to one of its topics locally, re-run `content_save`, and revert
   the file after the check.
2. As `demodev_s1@email.com`, open that topic. **Expect:** the Northwind card renders; nothing
   renders for the Harbour one (no card, no error).

## Scenario 8: the loader refuses an unknown organisation slug

1. In a local copy of the Harbour `course.md`, change `organisations:` to `[no-such-org]`. Run
   `uv run python manage.py content_save ./demo_content DemoDev`.
2. **Expect:** the command fails; the error names `no-such-org`, the course file path and the
   valid slugs on DemoDev (`harbour-college`, `northwind-logistics`, the default organisation's
   slug). Nothing is half-saved: the admin still shows the course with Harbour College.
3. Revert the file and re-run `content_save`. **Expect:** success.

## Scenario 9: layout and side effects

1. As `demodev_s2@email.com` (in Harbour College, both courses in progress), open `/` at
   375px, 768px and 1280px widths.
2. **Expect:** at each width the byline stays on one line and truncates a long name with an
   ellipsis rather than wrapping or widening the card; the page has no horizontal scrollbar; the
   logo box (if a logo is set on the organisation via the admin's Organisation change page) is a
   small fixed-height box level with the name text.
3. Set a logo on Harbour College in `/admin/freedom_ls_organisations/organisation/` (any PNG),
   reload `/`. **Expect:** the byline now shows the logo in an opaque box before the name; the
   image has no alt text announced (screen reader reads the name once).
4. Open `/` as an anonymous visitor (log out). **Expect:** the Northwind card shows with its
   byline and access badge; the Harbour card is absent; `/courses/<harbour-slug>/` is a 404.
5. Open the DemoDev dashboard as `demodev@email.com` with the visibility preview override on
   (set `OVERRIDE_COURSE_VISIBILITY_TO_VISIBLE=True` in the environment and restart the server).
   **Expect:** the Harbour course appears for a user outside Harbour College, as hidden courses
   do under the override. Turn the override off again.
