# Research: codebase (what say-it-then-reveal touches, reuses, conflicts with)

Paths are under `freedom_ls/` unless stated. Builds on `research_content_media.md` s3 and `research_audio_widgets.md`; only new or corrected facts here.

## 1. `c-audio` as built (`content_engine/templates/cotton/audio.html`)

- `<c-vars src="" label="" respelling="" symbol="" />`, `{% load content_tags %}`.
- `{% with file_obj=src|get_file_by_path:content_instance %}`: missing or `file_type != "AUDIO"` gives `<c-content-error message="Audio not found: {{ src }}" />`; empty `label` gives `"Audio needs a label: {{ src }}"`.
- Root: `<div class="my-6" x-data="audioFile" [x-id="['audio-respelling']" if respelling]>`. Inner card `flex ... has-aria-pressed:border-primary has-aria-pressed:bg-primary/5`.
- Symbol tile: `<span aria-hidden="true" ... bg-primary text-on-primary>{{ symbol }}</span>`. Label `<span class="block font-bold">`. Respelling `<span x-bind:id="$id('audio-respelling')">` built from filter `respelling_parts` (`content_tags.py`, returns `(text, stressed)` pairs).
- Play control: `<c-button variant="ghost" aria_label="Play pronunciation of {{ label }}" x-bind:aria-describedby=... x-bind:aria-pressed="playing" x-on:click="toggle" data-src="{% url 'content_engine:audio_file' file_obj.pk %}">` with three `x-show` icon spans: `idle` -> `audio_play`, `loading` -> `loading` (spin), `playing` -> `audio_playing`.
- Status line: `<p role="status" x-text="failed ? 'Audio could not be played. Try again.' : ''">`, always in DOM.
- The whole widget is one Alpine scope; the button is the only handler. There is no hook for "play from outside".

## 2. Alpine JS (`content_engine/static/content_engine/js/alpine-components.js`)

CSP build: no inline expressions; everything via `Alpine.data()`. Header comment (lines 8-13) lists components and must gain the new one.

`flashcard` (`:58-63`): `{flipped:false, flip(), frontStyle(), backStyle()}`. Nothing audio-aware.

`audioFile` (`:102-187`), module-level singletons: `sharedAudio` (one `new Audio()`, lazily made by `audioElement()`), `owner` (the active widget proxy), `nextAudioFileId` (identity, because Alpine hands a fresh scope proxy per method call so `this` is not stable).
- State: `idle/loading/playing/failed` set by `_setState(state)` and `_fail()`.
- `toggle()`: if `owner._id === this._id && !this.idle` then pause, `currentTime=0`, idle (stop). Otherwise the previous owner is reset to idle (`failed=false`), `owner = this`, state `loading`, `src = this.$el.dataset.src`. If `audio.getAttribute("src") === src && !audio.error` it rewinds (`currentTime = 0`) rather than refetching, else sets `audio.src`. Then `audio.play().catch(...)` synchronously inside the click (iOS). AbortError is ignored.
- Events on the shared element: `playing` (only if `owner?.loading`), `ended`/`pause` (owner to idle), `error` (owner `_fail()` if not idle).
- `destroy()` pauses and clears `owner` if this widget owns it.
- One-at-a-time playback is therefore achieved by the single shared element plus `owner` hand-off. Any new widget that plays must go through `owner`/`sharedAudio`, which are closure-private inside the `alpine:init` callback.
- Reading `this.$el.dataset.src`: `$el` is the element carrying the handler (the button), so the playing element must carry `data-src`.

Options for the reveal (not a decision): (a) reveal widget wraps a real `c-audio` and, on Reveal, triggers a click on that nested button via a `$refs`/`querySelector(...).click()` (a programmatic click inside the user's click is still user-activated; reuses `toggle` untouched, but toggle STOPS if already playing and the Hide-then-Reveal replay relies on stop/idle state being right); (b) extract the player into a shared factory/helper (e.g. a `playAudio(widget, src)` function used by both `audioFile` and a new `audioReveal` `Alpine.data`) so the reveal can call play directly and idempotently (play, never toggle). (a) needs no JS refactor but cannot "play" idempotently; (b) touches the `owner`/`_setState` closure. A nested Alpine scope inside another `x-data` is fine (research_content_media s3).
- Nested-scope reach: an outer `x-data` can read the inner `audioFile` data via `Alpine.$data(el)`; the CSP build supports it but the inner `toggle` has no "play-only" variant.
- Hide while playing: `audioFile.destroy()` runs only on element removal; an `x-show`/`inert` hide does not stop playback, so Hide (or re-reveal) must stop it explicitly if the clip should stop.

## 3. Markdown pipeline, the `{% markdown %}` tag and the real flashcard problem

- `markdown_rendering/markdown_utils.py` `render_markdown(markdown_text, request, context=None)` (`:15`): `context = context or {}`; markdown -> `nh3.clean` with `tags = nh3.ALLOWED_TAGS + MARKDOWN_ALLOWED_TAGS keys`, `attributes = nh3.ALLOWED_ATTRIBUTES` plus per-tag sets (plus `input`, `li`, `ul`) -> `CottonCompiler().process` -> `engines["django"].from_string(compiled).render(context, request)`.
- `content_engine/templatetags/content_tags.py`: `@register.simple_tag(takes_context=True) def markdown(context, value)` (`:160-168`) does `request = context.get("request")` and `return render_markdown(value, request)`. No context passed, so the inner render has an empty context (plus request context processors). The edit lands here: pass `{"content_instance": context.get("content_instance")}` or the flattened context.
- Top-level entry that supplies context: `content_base/models.py:96` `rendered_content()` -> `render_markdown(self.content, None, context={"content_instance": self})`. Other callers: `accounts/legal_docs.py:284` (request only), `form_engine/models.py:234` (`render_markdown(self.question, None)`, no context).
- Every `{% markdown <slot> %}` caller (templates in `content_engine/templates/cotton/`): `accordion.html:77` (`slot`), `admonition.html:33` (`slot`), `card.html:47` (`slot`), `flashcard.html:191` (`front`) and `:215` (`back`), `pull-quote.html:26` (`slot`), `table.html:21` (`{% markdown slot as rendered_table %}`). `grid.html` deliberately emits `{{ slot }}` (comment lines 10-13). No other app templates use the tag (grep of `*.html`).
- `get_file_by_path(file_path, content_instance)` (`:133-157`): returns `None` for empty path, else `content_instance.calculate_path_from_root(file_path)` then `File.objects.get(file_path=...)` (first on MultipleObjectsReturned). With `content_instance` undefined, Django passes `""` and `"".calculate_path_from_root` raises `AttributeError`, so a nested file-resolving component whose `<c-...>` is still raw text in the second pass would crash the render, not show a red box. Same dependency in `get_content_by_path`, `get_published_article_by_path`, `course_card_tags.get_course_by_path`; templates `picture.html`, `pdf-embed.html`, `file-download.html`, `card.html`, `content-link.html`, `article-card.html`, `article-link.html`, `audio.html`, `learner_interface/templates/cotton/course-card.html`.

CONFLICT / UNVERIFIED, important: the existing test `markdown_rendering/tests/test_markdown_utils.py` `test_c_table_wrapper_is_stripped_inside_a_markdown_slot` (`:534-578`, parametrised over accordion and flashcard) documents that Cotton has ALREADY rendered a nested component into the slot (using the outer context, where `content_instance` exists) before `{% markdown slot %}` runs; the second pass then runs nh3 over finished component HTML and strips non-allowlisted attributes. `fls-content` widget docs say the same: `c-audio` "must not go" inside accordion/flashcard/admonition/card/pull-quote/table, "the widget is lost" (`c-audio.md:40`, `widget-reference/SKILL.md:90`, `docs/product/content-editing-workflow.md:160` for table). Implication: a nested `c-audio` in a flashcard face would survive context resolution (outer render) but have `x-data`, `x-on:click`, `x-bind:*`, `data-src`, `x-show`, `role`, `class` stripped, and `button`/`svg` are not in nh3 defaults. So passing context through `markdown` alone may NOT make nested `c-audio` work; the second sanitise pass is the likely real blocker. `research_content_media.md` s3 flagged the context issue as "not confirmed by running"; a failing test should be written first to find which failure occurs. Candidate fixes (for the spec to choose): the `markdown` tag skips nh3/cotton compile for slot HTML that is already rendered and trusted; or slot content is sanitised once at the outer level and `{% markdown %}` only runs the markdown converter; or pass context AND allowlist. Whichever is picked, the idea's wording ("`{% markdown %}` passes no context") understates it. Existing tests that must keep passing: the table-strip test above documents current stripping as expected behaviour and would need revisiting if the fix changes it.
- Existing context-passing tests to mirror: `test_markdown_utils.py:413,434,467,598,760,934,950` use `context={"content_instance": FakeInstance()}`; `mock_request` fixture.

## 4. Flashcard (`content_engine/templates/cotton/flashcard.html`)

- Root `x-data="flashcard"`; `<div class="relative perspective-[1400px] min-h-11">` holds, in order: the full-surface flip `<button type="button" aria-label="Flip card" x-on:click="flip()" x-bind:aria-pressed="flipped">` (absolute, inset-0, no z-index), then the face stack `<div class="grid ... transform-3d pointer-events-none">` containing two faces.
- Faces: `.flashcard-face` (front, `x-bind:inert="flipped"`, `x-bind:aria-hidden="flipped"`, `x-bind:style="frontStyle()"`) and `.flashcard-face .flashcard-back` (back, `inert="!flipped"`). Each face body: kicker label "Question"/"Answer", `{% markdown front %}` / `{% markdown back %}`, a decorative "Tap to flip" hint with `c-icon name="retry"`.
- Embedded `<style>` in `@layer components`: `.flashcard-face :is(table, pre) { max-width:100%; overflow-x:auto; pointer-events:auto }` (`:90-94`) is the existing mechanism that lets a descendant take pointer events back. The audio button fix is an analogous `pointer-events: auto` rule on the nested audio widget (e.g. extend the `:is(...)` selector with a hook such as `[x-data="audioFile"]` or the button, or a class/attribute on `audio.html`). Because the button is a sibling of (not inside) the flip trigger, no stopPropagation is needed. A click on the card text beside the audio card must still flip.
- `.flashcard-back :is(p, li, ...)` repaint rules do not cover `span`; audio card colours (`bg-surface`, `text-on-surface` defaults, `text-muted`, `border-border`) will sit on the tinted back panel; check contrast and `--flashcard-*` variables.
- `inert`/`aria-hidden` on the hidden face is exactly the pattern the idea wants for the hidden answer in the reveal widget (`x-bind:inert`, `x-bind:aria-hidden`); `inert` on the hidden audio button also makes it unreachable.
- Flashcard `size` allowlist: `c-flashcard: {size}`; slots via `c-slot name`.

## 9. Other conflicts / notes

- Docs currently tell authors never to nest `c-audio` in `c-flashcard` etc. (`SKILL.md:90`, `c-audio.md:40`); the flashcard-with-audio work must reverse this and update both (and keep the warning for the other slot widgets if they stay broken). The same note must cover `c-audio-reveal` if it wraps a nested `c-audio` in any slot widget.
- `c-button` (`<c-button variant="ghost" aria_label=...>`) is the base button used by `audio.html`; the reveal toggle button can reuse it (attribute `aria_label`).
- Single-file/one-scope approach: placing `x-data="audioReveal"` around a `<c-audio>` that has its own `x-data="audioFile"` is a nested scope; the inner `x-id` for respelling works per scope.
- `audio.html` outputs `my-6` margins; inside the reveal the nested card would double margins unless suppressed (grid uses `[&>*]:my-0!` for that).
- Content-error pattern: `<c-content-error message="...">` for author mistakes (missing file, empty label); the reveal should reuse the same messages by delegating to the nested `c-audio` or share checks.
- Tag attributes are lower-case, no `-` conflicts: `c-audio-reveal` is a distinct cotton name from `c-audio` (Cotton resolves by exact file name, `audio-reveal.html`), but nh3 tag allowlist and `md.block_level_elements` are exact-match, so both must be listed.
- Domain note: `symbol` already exists on `c-audio` as the optional tile; in `c-audio-reveal` it becomes the pre-reveal prompt, and the tile must not be repeated post-reveal unless the nested card shows it (design choice for the spec).
