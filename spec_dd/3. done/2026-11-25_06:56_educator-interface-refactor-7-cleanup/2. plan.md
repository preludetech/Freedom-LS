## How to move a test

For each test, in each slice:

1. Cut the test function (or class) with its decorators, docstring and blank-line spacing.
2. Cut every private helper, constant, type alias and fixture used only by tests going to the same
   destination, and paste them above the first test that uses them.
3. A helper used by tests going to more than one destination moves to `tests/helpers.py` (the
   slice names each one) and every destination imports it from there.
4. Add the imports the destination now needs, merged into its existing import blocks. Remove
   imports the source no longer uses (ruff `F401` flags them).
5. When the destination has a file-level `pytestmark`, check it is harmless for the moved test
   (every one here only adds a site-context fixture, which the moved tests already take or tolerate).

A test's home is the test file mirroring the module that defines the behaviour it checks. A
parametrised test whose cases span areas moves whole to the `tests/panels/common/` file mirroring
the shared module it exercises.
