### Slice 2: the framework file widget

A file field on a form action renders through `PanelClearableFileInput`: the current file's basename, a `Remove` checkbox when the field is optional, and the native file input. Requirements 3 and 8.

**Builds on:** slices 1
**Touches:** `freedom_ls/panel_framework/widgets.py`, `freedom_ls/panel_framework/templates/panel_framework/widgets/clearable_file_input.html`, `freedom_ls/panel_framework/actions.py`, `freedom_ls/panel_framework/tests/test_widgets.py`, `freedom_ls/panel_framework/tests/test_actions.py`, `freedom_ls/panel_framework/tests/invariants/test_public_names.py`

Steps:

1. `PF/widgets.py`:

   ```python
   __all__ = ["PanelClearableFileInput"]


   class PanelClearableFileInput(forms.ClearableFileInput):
       """A file input that names the current file without linking to it."""

       template_name = "panel_framework/widgets/clearable_file_input.html"
       use_fieldset = False
       clear_checkbox_label = "Remove"
       initial_text = "Current file:"

       def is_initial(self, value: object) -> bool:
           # Not `.url`: on private storage reading it signs a URL, and a
           # storage with no URL support raises.
           return bool(getattr(value, "name", ""))

       def get_context(self, name: str, value: object, attrs: dict[str, object] | None) -> dict[str, object]:
           context = super().get_context(name, value, attrs)
           # The basename alone: the full name is the storage key.
           context["widget"]["current_file_name"] = (
               os.path.basename(value.name) if self.is_initial(value) else ""
           )
           # Django leaves the Remove tick in the attrs the file input
           # prints; it belongs on the checkbox alone.
           context["widget"]["checked"] = context["widget"]["attrs"].pop("checked", False)
           return context
   ```

   Match the parameter types to Django's own stubs if mypy asks for something narrower; no `Any`.

2. The template replaces Django's `django/forms/widgets/clearable_file_input.html`. Read the installed Django's version first and keep its handling of `widget.checkbox_name`, `widget.checkbox_id`, the `disabled` attribute, and the `attrs.html` include for the file input. Structure:

   ```django

       <p>
           {{ widget.initial_text }}
           <span class="break-all" title="{{ widget.current_file_name }}">{{ widget.current_file_name }}</span>
       </p>
       {% if not widget.required %}
           <label for="{{ widget.checkbox_id }}">
               <input type="checkbox" name="{{ widget.checkbox_name }}" id="{{ widget.checkbox_id }}"{% if widget.checked %} checked{% endif %}{% if widget.attrs.disabled %} disabled{% endif %}>
               {{ widget.clear_checkbox_label }}<span class="sr-only"> {{ widget.current_file_name }}</span>
           </label>
       {% endif %}
   {% endif %}
   <input type="{{ widget.type }}" name="{{ widget.name }}"{% include "django/forms/widgets/attrs.html" %}>
   ```

   Never print `widget.value`. Autoescape stays on. No `text-sm`, no raw colour, no `hx-*` attribute on any element.

3. `FormPanelAction._use_framework_file_widgets`, beside `_mark_refresh_fields`, called from `get_form` (on the form it returns) and `get_unbound_form`:

   ```python
   def _use_framework_file_widgets(self, form: forms.BaseForm) -> None:
       """Give each default file widget the framework's own, which shows the
       current file's name without its storage key or a link."""
       for field in form.fields.values():
           # Exactly Django's default: a form that declares a widget of its
           # own, a subclass included, keeps it.
           if type(field.widget) is not forms.ClearableFileInput:
               continue
           widget = PanelClearableFileInput(attrs=field.widget.attrs.copy())
           widget.is_required = field.required
           field.widget = widget
   ```

### Slice 3: the choose-again message

A 422 where a file was chosen tells the user, on the file field, to choose it again. Requirement 6.

**Builds on:** slices 1, 2
**Touches:** `freedom_ls/panel_framework/actions.py`, `freedom_ls/panel_framework/tests/test_actions.py`

Steps:

```python
CHOOSE_AGAIN_MESSAGE = "Choose the file again. It is not kept when the form has errors."


class FormPanelAction(ModalPanelAction):
    def handle_submit(self, ctx: PanelContext) -> HttpResponse:
        form = self.get_form(ctx)
        if form.is_valid():
            return self.form_valid(ctx, form)
        # Here rather than in form_invalid, which subclasses override.
        self._add_choose_again_errors(ctx, form)
        return self.form_invalid(ctx, form)

    def _add_choose_again_errors(self, ctx: PanelContext, form: forms.BaseForm) -> None:
        """A browser cannot be handed a file back, so a re-rendered file input
        is empty. Say so on each file field the user had filled in."""
        for name, field in form.fields.items():
            uploaded = form.add_prefix(name) in ctx.request.FILES
            # A field with an error of its own already says what is wrong.
            if isinstance(field, forms.FileField) and uploaded and name not in form.errors:
                form.add_error(name, CHOOSE_AGAIN_MESSAGE)
```

`CHOOSE_AGAIN_MESSAGE` goes in `__all__` (the reference page imports it in slice 8).

Tests (`tests/test_actions.py`, asserting the constant):

- 422 with a file chosen and another field invalid: the file input renders with no value, the choose-again message is on the file field, the error summary's count includes it, and on an `EditAction` whose instance has a file the current file is still shown.
- A prefixed form gets the message.
- 422 where the file field has its own error (a form validator rejects the upload): only that error shows.
- 422 with no file chosen: no choose-again message.
- A subclass that overrides `form_invalid` still gets the message.

   ```js
   // The loading text of a form's submit buttons says what the request is
   // doing. It is set on every request, back to the button's own text when no
   // file is going up, so a failed upload never leaves "Uploading…" behind.
   const UPLOADING_LABEL = "Uploading…";
   document.addEventListener("htmx:beforeRequest", (event) => {
       const form = event.detail.elt;
       if (!(form instanceof HTMLFormElement)) return;
       const uploading = Array.from(form.querySelectorAll("input[type=file]")).some(
           (input) => input.files.length > 0,
       );
       form.querySelectorAll("button[type=submit] [data-loading-label]").forEach((span) => {
           // The span holds the spinner and then the text; only the text changes.
           span.lastChild.textContent = " " + (uploading ? UPLOADING_LABEL : span.dataset.loadingLabel);
       });
   });
   ```

Steps:

1. `modal/form.html`: as the first child of `<c-modal-body>`, above the status message and error summary:

   ```django

   ```

2. `alpine-components.js`, document-level, outside `alpine:init`:

   ```js
   const REQUEST_ERROR_TOO_LARGE = "The file may be too large to upload. Choose a smaller file.";
   const REQUEST_ERROR_GENERIC = "Your changes could not be saved. Try again.";

   // A panel form whose request failed with nothing to swap in says so inside
   // the form: the response body is a server error page, never form markup.
   // Only a request the form itself issued counts, so a field's own refresh
   // request and the quick view keep their handling.
   function showRequestError(event) {
       const config = event.detail.requestConfig;
       const form = config && config.elt;
       if (!(form instanceof HTMLFormElement)) return;
       const holder = form.querySelector("[data-request-error]");
       if (!holder) return;
       const status = event.detail.xhr ? event.detail.xhr.status : 0;
       // The page reloads for these.
       if (status === 403 || status === 404) return;
       // The host has already shown this response its own way.
       if (config.panelErrorShown) return;
       const message = document.createElement("p");
       message.setAttribute("role", "alert");
       message.textContent = status === 413 ? REQUEST_ERROR_TOO_LARGE : REQUEST_ERROR_GENERIC;
       holder.replaceChildren(message);
       holder.hidden = false;
       if (form.closest("dialog")) holder.focus();
   }
   document.addEventListener("htmx:responseError", showRequestError);
   document.addEventListener("htmx:sendError", showRequestError);
   ```
