# Implementation plan — tracking where learners come from

## Goal

Add the `freedom_ls/referral_tracking` app from `1. spec.md`: two read-only `SiteAwareModel`s
(`SignupAttribution`, `FirstTouchCount`), the capture middleware that mints a signed first-party
attribution cookie and tallies first touches, the write of one `SignupAttribution` row per signup
from `SiteAwareSignupForm.custom_signup()`, two read-only admins with a CSV export action, and one
setting group.

Everything design-level is settled in the spec (§4) and is not reopened here. Where this plan names
a function or constant the spec did not, the spec's own vocabulary is the source of the name:
"first touch", "attribution key", "cap", "mint", "sanitise", "attribution cookie".

## The one-cap rule, in code

The spec's rule that every captured field has exactly one cap (§4) is kept by declaring the caps
once, in `models.py`, and reading them from both the model field declarations and the sanitiser:

```python
# freedom_ls/referral_tracking/models.py
CAPS: dict[str, int] = {
    "advert_code": 64, "utm_source": 64, "utm_medium": 64, "utm_campaign": 255,
    "utm_content": 128, "utm_term": 128,
    "gclid": 128, "gbraid": 128, "wbraid": 128, "fbclid": 256,
    "landing_path": 255, "referer": 255, "raw_query": 512,
    "ga_cookie": 64, "fbp_cookie": 64, "fbc_cookie": 320, "user_agent": 512,

ATTRIBUTION_KEY_FIELDS = (
    "advert_code", "utm_source", "utm_medium", "utm_campaign", "utm_content", "utm_term",

```

Every `CharField` on both models is declared as `max_length=CAPS["<name>"]`. The six attribution-key
columns are declared explicitly on each model (no abstract base; the codebase convention is not to
add one unasked).

### Task 3 — Capture: sanitisation and the attribution cookie

`freedom_ls/referral_tracking/capture.py`.

```python
TRACKED_PARAMS = (
    "advert_code",
    "utm_source", "utm_medium", "utm_campaign", "utm_content", "utm_term",
    "gclid", "gbraid", "wbraid", "fbclid",
)
LOWERCASED_PARAMS = ("utm_source", "utm_medium")
COOKIE_SALT = "freedom_ls.referral_tracking"

# Short cookie keys, one per frozen field plus the landing time.
COOKIE_KEYS: dict[str, str] = {
    "advert_code": "a", "utm_source": "s", "utm_medium": "m", "utm_campaign": "c",
    "utm_content": "n", "utm_term": "t", "gclid": "g", "gbraid": "gb", "wbraid": "wb",
    "fbclid": "f", "landing_path": "p", "referer": "r", "raw_query": "q",
    "first_seen": "ts",
}
```

Functions, all with full type hints:

```python
_CONTROL_CHARS = {c: None for c in (*range(0x00, 0x20), 0x7F)}

def sanitise(value: str, cap: int, *, lower: bool = False) -> str:
    # No unquote(): request.GET is already decoded, and decoding again would
    # corrupt a legitimate %2B or smuggle characters past this filter.
    value = value.translate(_CONTROL_CHARS)
    value = unicodedata.normalize("NFC", value).strip()
    if lower:
        value = value.lower()
    return value[:cap]

def has_tracked_params(request: HttpRequest) -> bool:
    return any(name in request.GET for name in TRACKED_PARAMS)

def first_touch_from_request(request: HttpRequest) -> dict[str, str]:
    """Every frozen field for this landing, sanitised, plus first_seen as ISO 8601."""
    first_touch = {
        name: sanitise(request.GET.get(name, ""), CAPS[name], lower=name in LOWERCASED_PARAMS)
        for name in TRACKED_PARAMS
    }
    first_touch["landing_path"] = sanitise(request.path, CAPS["landing_path"])
    first_touch["referer"] = sanitise(request.headers.get("Referer", ""), CAPS["referer"])
    first_touch["raw_query"] = sanitise(request.META.get("QUERY_STRING", ""), CAPS["raw_query"])
    first_touch["first_seen"] = timezone.now().isoformat()
    return first_touch

def set_attribution_cookie(response: HttpResponseBase, first_touch: dict[str, str]) -> None:
    payload = {COOKIE_KEYS[name]: value for name, value in first_touch.items() if value}
    encoded = base64.urlsafe_b64encode(
        json.dumps(payload, separators=(",", ":")).encode("utf-8")
    ).decode("ascii")
    response.set_signed_cookie(
        config.REFERRAL_TRACKING_COOKIE_NAME, encoded,
        salt=COOKIE_SALT, max_age=_cookie_max_age(),
        httponly=True, samesite="Lax", secure=settings.SESSION_COOKIE_SECURE,
    )

def read_attribution_cookie(request: HttpRequest) -> dict[str, str] | None:
    """The first touch the cookie carries, or None for absent, expired, forged or unparseable."""
    encoded = request.get_signed_cookie(
        config.REFERRAL_TRACKING_COOKIE_NAME, default=None,
        salt=COOKIE_SALT, max_age=_cookie_max_age(),
    )
    if encoded is None:
        return None
    try:
        payload = json.loads(base64.urlsafe_b64decode(encoded))
    except ValueError:   # binascii.Error, UnicodeDecodeError and JSONDecodeError all subclass it
        return None
    if not _is_first_touch_payload(payload):
        return None
    return {name: payload.get(short, "") for name, short in COOKIE_KEYS.items()}

def _is_first_touch_payload(payload: object) -> bool:
    """A JSON object whose keys are all short keys, whose values are all str, and whose
    landing time parses."""
    if not isinstance(payload, dict):
        return False
    known = set(COOKIE_KEYS.values())
    if any(key not in known or not isinstance(value, str) for key, value in payload.items()):
        return False
    try:
        datetime.fromisoformat(payload.get("ts", ""))
    except ValueError:
        return False
    return True
```

`request.get_signed_cookie(..., default=None)` is Django's own way of folding `BadSignature` (and so
`SignatureExpired`) into "no cookie"; passing `max_age` there is what enforces the 90 days
server-side. `_cookie_max_age()` is `config.REFERRAL_TRACKING_COOKIE_MAX_AGE_DAYS * 86400`.

The shape check is what lets Task 6 call `datetime.fromisoformat` on `first_seen` with no guard of
its own: a validly signed cookie from an older payload shape, still inside its window, reads as
"no cookie" here rather than raising inside a signup POST.

`sanitise` is the single sanitiser for every captured value, including the three ad cookies and the
user agent read at signup (Task 6): truncation is its last step, and its earlier steps are no-ops
on a well-formed cookie value, so one function serves both.

Tests (`tests/test_capture.py`), each a single behaviour: null byte stripped without raising;
control characters removed; `Facebook` → `facebook` for `utm_source` while `Spring Sale` keeps its
case for `utm_campaign`; over-length value truncated to its cap; duplicated parameter takes the
last value (`rf.get("/?utm_source=a&utm_source=b")`); a value carrying `%2B` is stored with the
literal `+` Django already decoded and nothing else; `first_seen` round-trips through the cookie;
a forged cookie value (a tampered string on the request's cookie jar) reads as `None`; a
signed-but-garbage payload reads as `None`; a cookie older than the setting's window reads as
`None` (use `time_machine` to sign it in the past).

### Task 4 — The tally

`freedom_ls/referral_tracking/counters.py`, exactly as spec §5.3:

```python
KEY_SEPARATOR = "\x1f"
OVERFLOW_SENTINEL = "\x00overflow"

def attribution_key_hash(*values: str) -> str: ...   # sha256 hexdigest of the joined values

def increment_first_touch(
    *, site: Site, day: date, key_hash: str, is_overflow: bool = False, **key_fields: str
) -> None:
    ...   # the spec's body, with its final try/except moved into create_or_increment_first_touch

def create_or_increment_first_touch(
    *, site: Site, day: date, key_hash: str, is_overflow: bool, **key_fields: str
) -> None:
    """Create the row, or increment it if another request created it first."""
    try:
        with transaction.atomic():
            FirstTouchCount.objects.create(
                site=site, day=day, key_hash=key_hash, is_overflow=is_overflow,
                count=1, **key_fields,
            )
    except IntegrityError:
        FirstTouchCount.objects.filter(
            site=site, day=day, key_hash=key_hash
        ).update(count=F("count") + 1)
```

The only change from the spec's body is that the `try`/`transaction.atomic()`/`except` tail is its
own function, so the concurrent-insert recovery can be tested on a real collision (below) instead
of by patching the ORM. The behaviour is identical.

`increment_first_touch` takes `site` because its `filter()` calls need it: `SiteAwareManager`
scopes a queryset only while a request is on the thread, and the tests call this function with
none. The same `site` is then passed to `create()` so the row lands on the site the `update()` just
looked at, rather than on whatever the thread-local happens to hold.

The caller (Task 5) builds `key_fields` in `ATTRIBUTION_KEY_FIELDS` order and hashes
`attribution_key_hash(*(key_fields[name] for name in ATTRIBUTION_KEY_FIELDS))`, so the same key
always produces the same digest.

Tests (`tests/test_counters.py`), under `mock_site_context`: a mint creates the row with `count=1`;
a second call for the same key increments it to 2 and creates no second row; a distinct key creates
a distinct row; keys differing only in `utm_content` are distinct rows; with the cap set to 2 via the
`settings` fixture, the third novel key increments the overflow row (`is_overflow=True`, blank key
columns) and creates no key row; an existing key past the cap still increments its own row; the
overflow row is not counted against the cap.

The concurrent-insert test is deterministic and mocks nothing. Build the row with
`FirstTouchCountFactory(count=1)`, then call `create_or_increment_first_touch` for the same
`(site, day, key_hash)`: that is exactly the state a losing request sees when its `update()` missed
and the other request's `INSERT` has since committed. The `create()` raises a real `IntegrityError`
from `unique_first_touch_count`, the savepoint rolls back, and the fallback `update()` runs. Assert
it does not raise and the count is 2. This is also what proves the nested `transaction.atomic()` is
doing its job: remove it and the test fails with `TransactionManagementError`.

### Task 5 — Middleware

`freedom_ls/referral_tracking/middleware.py`, shaped like `CurrentSiteMiddleware`:

```python
class AttributionCaptureMiddleware:
    def __init__(self, get_response: Callable[[HttpRequest], HttpResponseBase]) -> None:
        self.get_response = get_response

    def __call__(self, request: HttpRequest) -> HttpResponseBase:
        if (
            request.method != "GET"
            or not has_tracked_params(request)
            or read_attribution_cookie(request) is not None
        ):
            return self.get_response(request)   # ordinary traffic: no query, no cookie
        site = get_cached_site(request)
        if not isinstance(site, Site):
            return self.get_response(request)   # rejected Host: no site to tally against
        first_touch = first_touch_from_request(request)
        response = self.get_response(request)
        set_attribution_cookie(response, first_touch)
        patch_vary_headers(response, ["Cookie"])
        patch_cache_control(response, private=True, no_store=True)
        key_fields = {name: first_touch[name] for name in ATTRIBUTION_KEY_FIELDS}
        increment_first_touch(
            site=site,
            day=timezone.localdate(),
            key_hash=attribution_key_hash(*(key_fields[name] for name in ATTRIBUTION_KEY_FIELDS)),
            **key_fields,
        )
        return response
```

The first touch is captured before the view runs (so the view cannot mutate what is recorded) and
written after it (so a view that raises leaves neither cookie nor tally behind).

overridden.

Tests (`tests/test_admin.py`), following `freedom_ls/accounts/tests/test_admin.py` including its
`staff_client` fixture built on `mock_site_context`; rows come from the two factories. Both changelists
return 200 for a staff user granted only the two `view_*` permissions; the add URL returns 403 on
both; a POST to the change URL does not persist; a POST to the delete URL keeps the row; a staff
user with no permission on the models gets 403 on both changelists.

### Task 8 — CSV export

The export runs on `django-import-export` (a new base dependency, with `"import_export"` added to
`INSTALLED_APPS` after `"unfold.contrib.import_export"` so Unfold's templates win lookup).

`freedom_ls/site_aware_models/admin_exports.py` (shared, new): `FORMULA_TRIGGERS` and
`escape_csv_formula`; `FormulaSafeCSV`, a `CSV` format whose `export_data` escapes every string cell
(headers untouched) and prefixes the body with the UTF-8 BOM; `IsoDateTimeWidget` / `IsoDateWidget`
rendering `isoformat()`; and `SiteAwareModelResource`, a `ModelResource` base that maps date fields
to those widgets and excludes `site`.

`freedom_ls/site_aware_models/admin.py`: `SiteAwareExportModelAdmin(ExportActionMixin,
SiteAwareModelAdmin)` with Unfold's `ExportForm`, both skip-form flags on, the detail-page export
button off, `get_export_formats` returning `[FormulaSafeCSV]`, and `has_export_permission` gated on
`has_view_permission` (the package default is "any staff user").

`freedom_ls/referral_tracking/resources.py`: `SignupAttributionResource` (with `user` declared as a
`ForeignKeyWidget` on `email`, via `get_user_model()` to avoid the `accounts` import cycle) and
`FirstTouchCountResource`. Both admins set `resource_classes`.

Tests (`freedom_ls/site_aware_models/tests/test_admin_exports.py`, no DB): every trigger character
is prefixed; ordinary values untouched; the format escapes cells but not headers, starts with the
BOM, leaves `None` and integers alone; the widgets render `isoformat()` and `""` for `None`.

Tests (`tests/test_exports.py`, driven through the admin with the `staff_client` fixture): the body
starts with `codecs.BOM_UTF8`; a `utm_campaign` of `=1+1` exports as `'=1+1`; a value with an
embedded comma is quoted; the header names `gclid`, `client_ip` and `user_agent` and omits `site`;
`signed_up_at` is ISO 8601; `user` is the email; the action on a filtered changelist
(`action=export_admin_action`, `select_across=1`) returns only matching rows; the Export button's
URL returns the filtered set; that URL returns 403 to a staff user without the view permission; the
changelist offers the action; the `FirstTouchCount` export escapes and writes `day` as ISO 8601;
the resources map their date fields to the ISO widgets.

## Naming

- `ReferralTrackingSettings` is the `AppSettings` subclass; `ReferralTrackingConfig` is the
  `AppConfig`. Two classes, two names.
- The cookie-side helpers say "attribution cookie" (`set_attribution_cookie`,
  `read_attribution_cookie`), the spec's own phrase. The landing-side capture says "first touch"
  (`first_touch_from_request`). The tally says "first touch" too (`increment_first_touch`,
  `attribution_key_hash`), as the spec already does.
- `CAPS` and `ATTRIBUTION_KEY_FIELDS` name the spec's "cap" and "attribution key" and live in
  `models.py` because the model is where a cap becomes a column.
- The query parameter, the cookie field and the column are all `advert_code`. `ref` is never read.
