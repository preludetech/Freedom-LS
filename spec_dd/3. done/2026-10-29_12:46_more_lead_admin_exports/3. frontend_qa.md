# Frontend QA: admin CSV exports for users and course applications

The "Users" and "Course applications" admin changelists gain an "Export" button and an "Export
selected" action, both downloading a CSV at once. The users file holds nine fixed columns. The
applications file holds eight fixed columns and then one answer column per question of every
application form involved, drafts and anonymous applications included. Both are gated on the
model's view permission. This run downloads the files as a superuser and as permission-limited
staff, reads them, and tries the ways a file could carry something it must not.

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever
this document writes `<PORT>`. Shell variables do not survive between tool calls.

A "download" below means: open the given URL in the browser tab while signed in, let the browser
save the file, then read the saved file as text. Every file starts with a UTF-8 byte-order mark;
read it with `utf-8-sig`. When reading is awkward in the browser, fetch the same URL with the
signed-in session's cookies and read the response body instead. Either way, what is checked is
the file's text.

## §0 Setup

### 0.1 Server

1. `.claude/ds/scripts/find_available_port.sh` — note the number and use it literally from here on.
2. Start `uv run python manage.py runserver <PORT>` backgrounded, as its own call.
3. Open `http://127.0.0.1:<PORT>/` and confirm `#debug-branch-badge` names the
   `more_lead_admin_exports` branch. If it names another branch, another server holds the port;
   go back to step 1.

### 0.2 Seed data

Every item below must exist before §1. Data that cannot be created through the UI is created
through the `fls-dev:qa-data-helper` agent, never by hand.

1. **Demo content loaded.** `uv run python manage.py content_save demo_content DemoDev`. This
   loads the gated course "Functionality Demo - Application gated course" and its three-page
   "Application form" ("About you": full name, date of birth, email, phone, portfolio link, years
   of software, how you heard, which interest you, why this course; "Supporting documents": ID
   scan upload, anything else; "Availability": preferred time, time zone). Idempotent.
2. **Superuser:** `demodev@email.com` from `.claude/fls-dev/config.md`.
3. **Reviewer, applicant, bystander:** `uv run python manage.py qa_create_application_review_accounts`.
   It seeds `qa_reviewer@email.com` (staff, holding `view_courseapplication`,
   `view_formprogress`, `view_questionanswer` and `view_questionanswerfile`, and no `accounts`
   permission), and resets `qa_applicant@email.com` and `qa_bystander@email.com` to plain
   learners. Password equals the email. Run it once at the start, not between sections.
4. **A staff user with no permission at all.** Through `fls-dev:qa-data-helper`: a user
   `qa_nobody@email.com`, `is_staff=True`, no permissions, no groups, password equal to the email,
   with a verified allauth `EmailAddress`. Call this the *bystander staff*.
5. **A submitted application with every answer type.** Sign in as `qa_applicant@email.com`, open
   the gated course from the catalogue, press "Apply", and fill the form:
   - "About you": full name `=Ada QA` (the leading `=` is deliberate), date of birth
     `1990-02-03`, email, phone, a portfolio URL, years of software `4`, pick one "How did you
     hear" option, tick two "Which of these interest you" boxes, and a "Why do you want to take
     this course?" answer of at least two paragraphs separated by a blank line.
   - "Supporting documents": upload `id-scan.png` (any PNG under 1 MB with real pixel content,
     saved in the scratch directory). Leave "Is there anything else we should know?" empty.
   - "Availability": pick a time and a time zone.
   - On "Check your answers", press "Submit application".
   Call this the *submitted application*. Sign out.
6. **A draft application.** Sign in as `qa_bystander@email.com`, press "Apply" on the same
   course, answer only the full name on "About you" (`Bea Draft`), press Continue once, then
   leave without submitting. Call this the *draft application*. Sign out.
7. **An anonymous application.** Signed out, open the gated course and press "Apply". Give the
   email `anon.applicant@example.com`, first name `Cass`, last name `Anon`, accept the terms,
   fill the full name and the date of birth, continue to the end and submit. Do not follow the

8. **A no-form application.** `uv run python manage.py qa_create_application_docs_scenario`
   creates a gated course that names no form and a learner (`demodev_applicant@email.com`) who

9. **A user who never verified.** Through `fls-dev:qa-data-helper`: a plain user
   `unverified@example.com` with an allauth `EmailAddress` whose `verified` is `False`. And a
   user `Mixed.Case@example.com` whose `EmailAddress.email` is `mixed.case@example.com`,
   verified. Call these the *unverified user* and the *mixed-case user*.

## §1 The Users export (superuser)

Sign in as `demodev@email.com` and open `http://127.0.0.1:<PORT>/admin/freedom_ls_accounts/user/`.

### 1.1 The controls are there

1. Expect an "Export" button on the changelist toolbar, and "Export selected users" in the
   actions dropdown.
2. Expect the page otherwise unchanged: the same columns (Email, First name, Last name, Staff,
   Active), the same filters on the right, and "Add user" still present.
3. Open any user's change page. Expect no export button there, and the same fieldsets as before
   (Email and password; Personal info; Permissions; Important dates; the Legal consents inline).

### 1.2 The whole list

1. Download `http://127.0.0.1:<PORT>/admin/freedom_ls_accounts/user/export/`.
2. Expect the header row to be exactly, in order:
   `id,email,first_name,last_name,is_active,is_staff,email_verified,created_at,last_login`.
3. Expect one row per user listed on the changelist, and no more.
4. Expect `is_active` and `is_staff` to read `TRUE` or `FALSE` in every row, never `1`/`0`.
5. Expect `created_at` and `last_login` to be ISO 8601 with an offset (for instance
   `2026-10-27T09:12:33.123456+00:00`), and `last_login` empty for a user who never signed in
   (the bystander staff, before §3).
6. Expect `email_verified` to be `TRUE` for `demodev@email.com` and the mixed-case user, and
   `FALSE` for the unverified user.
7. Search the file text for `password`, `pbkdf2`, `argon2`, `is_superuser`, `groups`: expect no
   hit.
8. Search for `site`: expect no `site` column.

### 1.3 Filters and selection narrow the file

1. On the changelist, filter "Staff status" to "Yes" and press "Export". Expect the file to
   hold only the staff users (`demodev@email.com`, `qa_reviewer@email.com`, the bystander staff).
2. Clear the filter. Tick `qa_applicant@email.com` and `qa_bystander@email.com` only, choose
   "Export selected users", press Go. Expect a file with exactly those two rows.
3. Search for `qa_applicant` on the changelist and press "Export". Expect one row.

## §2 The Course applications export (superuser)

Open `http://127.0.0.1:<PORT>/admin/freedom_ls_course_applications/courseapplication/`.

### 2.1 The controls are there and the admin is still read-only

1. Expect an "Export" button and an "Export selected course applications" action.
2. Expect no "Add course application" button, and no "Delete selected" action.
3. Open the submitted application's change page. Expect it to open in view mode as before, with
   the answers document (page headings "About you", "Supporting documents", "Availability", each
   question with its answer, "Not answered" for the one left blank) and no export button. This
   page shares its question ordering with the export, so a regression here matters.
4. Expect the changelist's "Submitted time" column to show a time for the submitted and anonymous
   applications, nothing for the draft, and the created time for the no-form application.

### 2.2 The whole list

1. Download `http://127.0.0.1:<PORT>/admin/freedom_ls_course_applications/courseapplication/export/`.
2. Expect the header to start with exactly, in order:
   `id,applicant_email,applicant_name,is_email_verified,course,is_submitted,submitted_time,created_at`.
3. Expect the header to continue with the thirteen question texts of the demo form, in form
   order: the nine "About you" questions, then the two "Supporting documents" questions, then
   the two "Availability" questions. No other columns.
4. Expect four data rows: the submitted, draft, anonymous and no-form applications.
5. **Submitted row:** `qa_applicant@email.com`, the user's name, `is_email_verified` `TRUE`,
   `course` is the course title (not a number), `is_submitted` `TRUE`, `submitted_time` ISO 8601.
   Its answer cells: the full name reads `'=Ada QA` (escaped with a leading apostrophe); the
   date of birth is `1990-02-03` exactly; the years of software is `4`; "How did you hear" is the
   option text; "Which of these interest you" is the two ticked options' texts joined by `; ` in
   the order the form lists them; "Why do you want to take this course?" holds the whole answer
   with its line break inside a quoted cell; the ID scan cell is `id-scan.png`; "Is there anything
   else" is empty; the time is `HH:MM` as stored; the time zone is the option text.
6. **Draft row:** `qa_bystander@email.com`, `is_submitted` `FALSE`, `submitted_time` empty,
   full name `Bea Draft`, every other answer cell empty.
7. **Anonymous row:** `anon.applicant@example.com`, name `Cass Anon`, `is_email_verified`
   `FALSE`, `is_submitted` `TRUE`, its two answers filled, the rest empty.
8. **No-form row:** `demodev_applicant@email.com`, `is_submitted` `TRUE`, `submitted_time` equal
   to `created_at`, every answer cell empty.
9. Search the file text for `user_uploads`, `form_answers`, `http`, `.jpg`, `.jpeg`: expect no
   hit other than the portfolio URL answer. The file name `id-scan.png` appears once and no
   storage key appears.
10. Search for `site`: expect no `site` column.

### 2.3 Filters and selection narrow the file

1. Filter "submitted" to "Draft", press Submit, then "Export". Expect only the draft row.
2. Filter "submitted" to "Submitted". Expect the submitted, anonymous and no-form rows.
3. Clear filters. Filter "course" to the no-form course, press Submit, then "Export". Expect
   only the no-form row, and expect the header to carry no answer columns at all, because no
   exported application sat a form.
4. Clear filters. Filter "email verified" to "Unverified". Expect only the anonymous row.
5. Tick the submitted and the draft application only, choose "Export selected course
   applications", press Go. Expect exactly those two rows.

### 2.4 A second form in the same file

1. Through `fls-dev:qa-data-helper`: a second application-gated course "QA Second Course" with a
   one-page form titled "Second form" holding two short-text questions, `What is your full name?`
   (the same text as the demo form's first question) and `Favourite colour`, and a submitted
   application to it by `qa_applicant@email.com` answering both (`Ada Again`, `Teal`).
2. Download the whole list again.
3. Expect the demo form's columns first (its title "Application form" sorts before "Second
   form"), then the second form's two columns.
4. Expect the two "full name" headers to be disambiguated as `What is your full name?
   (Application form)` and `What is your full name? (Second form)`; expect `Favourite colour` to
   keep its bare header.
5. Expect the new row to be empty under every demo-form column and filled under both second-form
   columns, and the earlier rows to be empty under the second form's columns.

## §3 Permissions

### 3.1 The reviewer: applications yes, users no

1. Sign out. Sign in as `qa_reviewer@email.com` and open `http://127.0.0.1:<PORT>/admin/`.
2. Expect "Course applications" listed and "Users" absent.
3. Open the applications changelist. Expect the "Export" button and the action. Download
   `http://127.0.0.1:<PORT>/admin/freedom_ls_course_applications/courseapplication/export/`.
   Expect the same file shape as §2.2, answer columns included.
4. Open `http://127.0.0.1:<PORT>/admin/freedom_ls_accounts/user/export/` directly. Expect a 403.
5. Post the action by hand is not needed: the changelist itself is 403 for this user at
   `http://127.0.0.1:<PORT>/admin/freedom_ls_accounts/user/`. Confirm that.

### 3.2 The bystander staff: nothing

1. Sign out. Sign in as the bystander staff.
2. Open `http://127.0.0.1:<PORT>/admin/freedom_ls_accounts/user/export/`. Expect 403.
3. Open `http://127.0.0.1:<PORT>/admin/freedom_ls_course_applications/courseapplication/export/`.
   Expect 403.
4. Open `http://127.0.0.1:<PORT>/admin/freedom_ls_accounts/user/export/?is_staff__exact=1`.
   Expect 403: a filter does not open a door.

### 3.3 Signed out

1. Sign out. Open `http://127.0.0.1:<PORT>/admin/freedom_ls_accounts/user/export/`. Expect a
   redirect to the admin login, not a file.

## §5 Report

Record every expectation that did not hold with the section number, what was seen, and the
first lines of the downloaded file where a file was involved. A difference in column order, a
`1`/`0` boolean, a storage key, a password hash, a row from a filtered-out set or a missing
403 is a failure.
