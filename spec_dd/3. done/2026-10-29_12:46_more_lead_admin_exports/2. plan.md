## Slice 1: the shared export base escapes headers and writes `TRUE`/`FALSE`

**Behaviour.** `FormulaSafeCSV.export_data` escapes a header cell that starts with a formula
trigger exactly as it escapes a body cell. A `SpreadsheetBooleanWidget` renders `True` as `TRUE`,
`False` as `FALSE` and anything else as an empty cell. `SiteAwareModelResource.WIDGETS_MAP`
maps `BooleanField` to it, so the referral exports' boolean columns (`is_active`,
`is_machine_fetch`, `is_overflow`) change from `1`/`0` to `TRUE`/`FALSE`. Their headers are field
names, so header escaping leaves them as they were. A referral test asserts `is_active` reads
`TRUE`/`FALSE`.

**Files.**

- `freedom_ls/site_aware_models/admin_exports.py`:

```python
class FormulaSafeCSV(CSV):
    """CSV a spreadsheet can open directly.

    Every string cell is escaped, headers included: a header can be text a
    form author typed, not only a model field name.
    """

    def export_data(self, dataset: Dataset, **kwargs: object) -> str:
        if dataset.headers is not None:
            dataset.headers = [_escape_cell(header) for header in dataset.headers]
        for index in range(len(dataset)):
            dataset[index] = [_escape_cell(cell) for cell in dataset[index]]
        body: str = super().export_data(dataset, **kwargs)
        return f"{UTF8_BOM}{body}"


class SpreadsheetBooleanWidget(BooleanWidget):
    """Render True as TRUE and False as FALSE, which a spreadsheet reads as booleans.

    The base widget writes 1 and 0, which a sheet reads as numbers. None, or
    anything that is not a bool, is an empty cell. Only text formats are
    offered, so the ``force_native_type`` path is not needed here.
    """

    def render(self, value: object, obj: object = None, **kwargs: object) -> str:
        if not isinstance(value, bool):
            return ""
        return "TRUE" if value else "FALSE"
```

  Also update the module docstring's list of what the module adds, so it names the boolean
  widget alongside the ISO date widgets.

- `freedom_ls/site_aware_models/tests/test_admin_exports.py` (exists; extend). Tests to drive
  the slice:
  - parametrised over `FORMULA_TRIGGERS`: a `Dataset` whose header starts with the trigger comes
    out of `FormulaSafeCSV().export_data` with that header prefixed by `'`;
  - a header with no trigger is unchanged;
  - a body cell starting with a trigger is still escaped when the header is not;
  - parametrised: `SpreadsheetBooleanWidget().render(True)` is `"TRUE"`, `render(False)` is
    `"FALSE"`, `render(None)` is `""`.

## Slice 2: the Users changelist exports nine columns

**Behaviour.** The "Users" changelist carries the Export button and the "Export selected" action.
The file holds `id`, `email`, `first_name`, `last_name`, `is_active`, `is_staff`,
`email_verified`, `created_at`, `last_login`, in that order, booleans as `TRUE`/`FALSE`, dates as
ISO 8601 and an empty cell for a user who never logged in. `email_verified` is `TRUE` only when
an allauth `EmailAddress` with `verified=True` matches the user's `email` case-insensitively.
The password hash, superuser flag, groups and permissions never reach the file. A staff user
without `view_user` gets 403 on the export URL. Users on another site are absent.

**Files.**

- New `freedom_ls/accounts/resources.py`:

```python
USER_EXPORT_FIELDS = (
    "id",
    "email",
    "first_name",
    "last_name",
    "is_active",
    "is_staff",
    "email_verified",
    "created_at",
    "last_login",
)


class UserResource(SiteAwareModelResource):
    """One row per user, with nothing that could open an account.

    The model also carries the password hash, the superuser flag, groups and
    permissions, and a resource with no ``fields`` would write all of them, so
    the columns are an explicit whitelist.
    """

    WIDGETS_MAP = {
        **SiteAwareModelResource.WIDGETS_MAP,
        "BooleanField": SpreadsheetBooleanWidget,
    }
    # Annotated in filter_export, so the changelist query is unchanged and no
    # row costs a query.
    email_verified = Field(attribute="email_verified", widget=SpreadsheetBooleanWidget())

    class Meta:
        model = get_user_model()
        fields = USER_EXPORT_FIELDS
        export_order = USER_EXPORT_FIELDS

    def filter_export(
        self, queryset: QuerySet[User], **kwargs: object
    ) -> QuerySet[User]:
        # Matched on the address, not only the user: allauth lets a user hold
        # several addresses, and only the one the account signs in with counts.
        verified = EmailAddress.objects.filter(
            user=OuterRef("pk"), verified=True, email__iexact=OuterRef("email")
        )
        return queryset.annotate(email_verified=Exists(verified))
```

  `Meta.model` is resolved with `get_user_model()` as the spec asks; the type hints import
  `User` from `.models`, which is the module's own app. A declared `Field` with no
  `column_name` is headed by its attribute name, so none is passed. `created_at` and `last_login` are
  `DateTimeField`s, so the inherited `WIDGETS_MAP` already renders them with
  `IsoDateTimeWidget`, which writes `""` for `None`.

- `freedom_ls/accounts/admin.py`: `UserAdmin` extends `SiteAwareExportModelAdmin` instead of
  `SiteAwareModelAdmin` and gains `resource_classes = [UserResource]`. Forms, fieldsets,
  `get_form`, `get_deleted_objects` and the inline are untouched. Import `SiteAwareExportModelAdmin`
  alongside `SiteAwareModelAdmin`, which the other admins in the module still use.

- New `freedom_ls/accounts/tests/test_resources.py`, with its own `staff_client` (a
  `UserFactory(staff=True)` holding the `view_user` permission from
  `Permission.objects.get(content_type__app_label="freedom_ls_accounts", codename="view_user")`)
  and `unprivileged_staff_client` fixtures, plus `_export_selected` and `_rows` helpers copied
  from the referral tests. Tests to drive the slice:
  - the header is exactly `USER_EXPORT_FIELDS` in order;
  - neither `"password"` nor the user's `password` hash appears anywhere in the body;
  - `email_verified` is `TRUE` for a user with a verified `EmailAddress`;
  - `TRUE` when the `EmailAddress.email` differs from `user.email` only in case;
  - parametrised over the two setups: `FALSE` for an unverified `EmailAddress`, and `FALSE`
    for a verified one holding a different address;
  - parametrised over `is_active` and `is_staff`: the column reads `TRUE` for a user with the
    flag set and `FALSE` otherwise;
  - `created_at` is `isoformat()`;
  - `last_login` is empty for a user who never logged in;
  - `UserResource.fields` contains none of `password`, `is_superuser`, `groups`,

## Slice 4: `form_questions` is the one place that orders a form's questions

**Behaviour.** `form_questions(form)` returns every question currently on the form, pages in
their order and questions in `page_questions` order within each page. `answer_groups` reads its
page walk from it and returns exactly the groups it returned before. This is the groundwork the
answer columns build on; nothing user-visible changes.

**Files.**

- `freedom_ls/form_engine/queries.py`:

```python
def form_questions(form: Form) -> list[FormQuestion]:
    """Every question currently on the form, in the order a sitting meets them.

    Pages in their own order, then each page's questions as `page_questions`
    lays them out. Expects the form's pages, with their questions and text
    items, to be prefetched; a form read bare costs a query per page.
    """
    return [
        question for page in form.pages.all() for question in page_questions(page)
    ]
```

## Slice 5: answer columns for one form

**Behaviour.** An applications export whose applications all sat the same form carries, after
the fixed columns, one answer column per question currently on that form, in `form_questions`
order, headed by the question text. A cell holds the answer as text: option questions as the
selected options' `text` in option `order` joined with `"; "`; a file upload as its
`original_filename`; date and time answers as their stored ISO text; every other type as
`text_answer` in full, newlines kept. A skipped question and an application with no sitting give
empty cells. An answer starting with `=` and a question text starting with `=` both come out
escaped. The number of queries an export runs does not grow with the number of applications.

**Files.**

- `freedom_ls/form_engine/enums.py`, beside `FREE_TEXT_QUESTION_TYPES`:

```python
# Option questions store their answer as selected QuestionOption rows, not text.
OPTION_QUESTION_TYPES = frozenset(
    {QuestionType.MULTIPLE_CHOICE, QuestionType.DROPDOWN, QuestionType.CHECKBOXES}
)
```

- New `freedom_ls/form_engine/exports.py`:

```python
"""Laying sittings out as spreadsheet columns.

The resource that exports applications lives in an app this one must not
import, so it hands sittings in and gets columns and cell text back.
"""


@dataclass(frozen=True)
class AnswerColumn:
    """One column of an export: the answers to one question under one header."""

    question: FormQuestion
    header: str


def answer_columns(form_progresses: Collection[FormProgress]) -> list[AnswerColumn]:
    """The answer columns for these sittings, one per question of each form sat.

    Forms are ordered by title, then id, so an export mixing courses keeps each
    form's questions together. Expects each sitting's form and answers, with
    their questions, to be prefetched.
    """
    forms = {form_progress.form_id: form_progress.form for form_progress in form_progresses}
    ordered_forms = sorted(forms.values(), key=lambda form: (form.title, form.id))
    # Pages load once per form here, not once per sitting.
    prefetch_related_objects(ordered_forms, "pages__text_items", "pages__questions")
    return [
        AnswerColumn(question, question.question)
        for form in ordered_forms
        for question in form_questions(form)
    ]


def answer_cell(answer: QuestionAnswer | None) -> str:
    """One answer as spreadsheet text; an empty cell for a question never answered."""
    if answer is None:
        return ""
    question_type = answer.question.type
    if question_type in OPTION_QUESTION_TYPES:
        options = sorted(answer.selected_options.all(), key=lambda option: option.order)
        return "; ".join(option.text for option in options)
    if question_type == QuestionType.FILE_UPLOAD:
        # The name the applicant gave the file, never its storage key or a URL.
        # hasattr, because a missing reverse one-to-one raises rather than returning None.
        if not hasattr(answer, "answer_file"):
            return ""
        return answer.answer_file.original_filename
    # Dates and times stay as their stored ISO text: a sheet parses that where
    # it would not parse the locale-formatted display text.
    return answer.text_answer
```

```python
        self._answers: dict[UUID, dict[UUID, QuestionAnswer]] = {}

    def filter_export(
        self, queryset: QuerySet[CourseApplication], **kwargs: object
    ) -> QuerySet[CourseApplication]:
        return queryset.select_related(
            "user", "anonymous_applicant", "course", "form_progress"
        ).prefetch_related(
            "form_progress__form",
            "form_progress__answers__question",
            "form_progress__answers__selected_options",
            "form_progress__answers__answer_file",
        )

    def before_export(
        self, queryset: QuerySet[CourseApplication] | None, **kwargs: object
    ) -> None:
        # The rows are loaded once, here: the answer columns are built from
        # them and the cells read the same objects, so nothing is fetched twice.
        if queryset is None:
            queryset = self.get_queryset()
        self._applications = list(self.filter_export(queryset))
        sittings = [
            application.form_progress
            for application in self._applications
            if application.form_progress is not None
        ]
        self._answers = {
            sitting.pk: {answer.question_id: answer for answer in sitting.answers.all()}
            for sitting in sittings
        }
        for column in answer_columns(sittings):
            self.fields[f"question_{column.question.id}"] = Field(
                column_name=column.header,
                dehydrate_method=partial(self._answer_cell, question_id=column.question.id),
            )

    def iter_queryset(
        self, queryset: QuerySet[CourseApplication]
    ) -> Iterator[CourseApplication]:
        # The rows are already in memory from before_export, which built the
        # answer columns from them; the package's chunked walk would read the
        # same rows a second time.
        return iter(self._applications)

    def _answer_cell(self, application: CourseApplication, question_id: UUID) -> str:
        if application.form_progress is None:
            return ""
        return answer_cell(self._answers[application.form_progress.pk].get(question_id))
```

  This `filter_export` replaces the Slice 3 one. `Resource.export()` still calls
  `filter_export` on the queryset after `before_export`, but that second queryset is never
  evaluated because `iter_queryset` yields the rows already loaded; the joins live in one
  place and the hook order the package defines is kept. The field keys are
  `question_<FormQuestion.id>`, so a reworded question keeps one column and two forms asking
  the same text get two. The answer fields are appended after `APPLICATION_EXPORT_FIELDS`
  because `get_export_order` lists `Meta.export_order` first and the rest in insertion order.
  Headers go through `FormulaSafeCSV`'s header escaping from Slice 1.

  The answer columns are gated on `view_courseapplication` alone, as the spec decides: the
  change page already shows a viewer every answer through `answers_context`, so the export is
  no wider a read path than the page. The admin test below pins that.

> **Assumed default:** `before_export` adds `Field`s to the instance's `fields` and
> `iter_queryset` ignores its argument, so the resource carries per-export state. Why: the
> package copies `fields` per instance and the admin builds a fresh resource for every export,
> so nothing leaks between exports; passing the columns through `get_export_resource_kwargs`
> would add an admin-side plumbing path for the same result. To change: Slice 5, the
> `CourseApplicationResource` snippet.

## Slice 6: several forms, off-page questions, duplicate headers

**Behaviour.** An export mixing courses carries the union of every form's answer columns, forms
ordered by title then id, with empty cells where a question belongs to another course's form.
After a form's page questions come its off-page questions that some exported sitting answered,
so no answer is dropped. When two answer columns would share a header, each gets ` (<form title>)`
appended; any still equal get ` (<n>)` appended, `n` being the column's 1-based position among the
answer columns.

**Files.**

- `freedom_ls/form_engine/exports.py`: the Slice 5 body of `answer_columns` is replaced by
  this one, not extended:

```python
def answer_columns(form_progresses: Collection[FormProgress]) -> list[AnswerColumn]:
    """The answer columns for these sittings, one per question of each form sat.

    Forms are ordered by title, then id, so an export mixing courses keeps each
    form's questions together. Each form contributes the questions currently
    on its pages, then any question off every page that one of these sittings
    answered. Expects each sitting's form and answers, with their questions,
    to be prefetched.
    """
    forms = {form_progress.form_id: form_progress.form for form_progress in form_progresses}
    sittings_by_form: dict[UUID, list[FormProgress]] = {}
    for form_progress in form_progresses:
        sittings_by_form.setdefault(form_progress.form_id, []).append(form_progress)
    ordered_forms = sorted(forms.values(), key=lambda form: (form.title, form.id))
    # Pages load once per form here, not once per sitting.
    prefetch_related_objects(ordered_forms, "pages__text_items", "pages__questions")
    questions: list[tuple[Form, FormQuestion]] = []
    for form in ordered_forms:
        on_page = form_questions(form)
        on_page_ids = {question.id for question in on_page}
        questions.extend((form, question) for question in on_page)
        # A question can leave every page but never be deleted while answered
        # (the answer's FK protects it), so its answers still get a column.
        off_page = {
            answer.question_id: answer.question
            for form_progress in sittings_by_form[form.id]
            for answer in form_progress.answers.all()
            if answer.question_id not in on_page_ids
        }
        questions.extend(
            (form, question)
            for question in sorted(off_page.values(), key=lambda q: (q.order, q.id))
        )
    headers = _qualified(
        [question.question for _, question in questions],
        [form.title for form, _ in questions],
    )
    headers = _qualified(headers, [str(n) for n in range(1, len(headers) + 1)])
    return [
        AnswerColumn(question, header)
        for (_, question), header in zip(questions, headers, strict=True)
    ]


def _qualified(headers: list[str], suffixes: list[str]) -> list[str]:
    """`headers`, with the suffix appended to each one that another header repeats.

    Called twice: first with the form titles, which tell apart two forms
    asking the same thing, then with the column positions, the last resort
    for one form asking it twice.
    """
    repeated = {header for header, count in Counter(headers).items() if count > 1}
    return [
        f"{header} ({suffix})" if header in repeated else header
        for header, suffix in zip(headers, suffixes, strict=True)
    ]
```

  The form a column belongs to is the sitting's form, never `question.form_page.form`: an
  off-page question's page may belong to another form entirely.

> **Assumed default:** the off-page rule (an answered question whose id is on no current page)
> is written here and in `answer_groups`, as one comprehension each. Why: `answer_groups`
> needs `(question, answer)` rows for one sitting and this needs distinct questions across
> many, so a shared helper would return neither shape without a second pass. To change:
> Slice 4, by extracting a helper into `queries.py` that both call.
