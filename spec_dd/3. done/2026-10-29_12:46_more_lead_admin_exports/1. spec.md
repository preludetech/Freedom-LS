# Spec: admin CSV exports for users and course applications

Idea: `idea.md`. Research: the `research_*.md` files beside this spec.

## Purpose

Site staff need to take users and course applications out of the admin into a spreadsheet. An
application export carries the applicant's full application form, one column per question.
Applications from anonymous applicants are included. The admin already has a tested CSV export
base. Only the `referral_tracking` admins use it so far.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| answer column | coined | One column of an application export, holding the answers to one `FormQuestion`. No existing term: nothing in the code lays answers out as columns yet. |

## Scope

In:

- A CSV export on the `User` changelist (`freedom_ls/accounts/admin.py: UserAdmin`).
- A CSV export on the `CourseApplication` changelist (`freedom_ls/course_applications/admin.py:
  CourseApplicationAdmin`). It covers user-held and anonymous applications, drafts and submitted
  ones, with an answer column for every question of each form in the export.
- Formula-escaping of header cells in `FormulaSafeCSV`.

Out:

- An export on `AnonymousApplicantAdmin`. Every anonymous applicant already appears in the
  application export through `CourseApplication.anonymous_applicant`, and a claimed one would be
  counted twice.
- Registration-form answers (`SiteSignupPolicy.additional_registration_forms`), `LegalConsent`
  records, HR attributes and signup attribution in the Users export.
- File contents. A file-upload answer exports its filename only.
- XLSX or any format besides CSV, a column picker, a long (row-per-answer) format, background or
  emailed exports, and an export audit trail.
- A new "lead admin" role or export permission.

## Decisions

- **Reuse `SiteAwareExportModelAdmin`.** It already gives the filtered "Export" button, the "Export
  selected" action, the formula-safe CSV and the view-permission gate.
- **Export is gated on the model's view permission, not a new permission.** A viewer can already
  read every answer on the change page, and file contents stay behind `can_download_answer_files`.
  A site's "lead admins" are whoever the operator grants `accounts.view_user` and
  `course_applications.view_courseapplication` to.
- **One row per application, with the union of answer columns across every form in the export.** A
  cell is blank when the question belongs to another course's form, or when the applicant did not
  answer it.
- **Answer columns are keyed by `FormQuestion.id`, not by question text.** A question reworded since
  an applicant answered it keeps one column, and two forms that ask the same text get two.
- **Drafts are exported, told apart by an `is_submitted` column.** The existing submitted/draft
  filter narrows the export when wanted.
- **Boolean cells in every admin export read `TRUE` or `FALSE`.** Excel reads these as booleans.
  The referral exports change from `1`/`0` too, so every export agrees.

## Requirements

### Shared export base (`freedom_ls/site_aware_models/admin_exports.py`)

- `FormulaSafeCSV.export_data` escapes the header row with `escape_csv_formula`, as it does every
  string cell. Question text becomes header text, so headers are no longer only model field names.
  Update the class docstring to match.
- A boolean widget, `SpreadsheetBooleanWidget`, that renders `True` as `TRUE` and `False` as
  `FALSE`. `SiteAwareModelResource.WIDGETS_MAP` maps `BooleanField` to it, so every resource on
  the base uses it, the referral ones included. A computed boolean column (`email_verified`,
  `is_email_verified`, `is_submitted`) is not a model field and sets the widget itself.

### Users export (`freedom_ls/accounts/`)

- New `freedom_ls/accounts/resources.py: UserResource(SiteAwareModelResource)`. Resolve the model
  with `get_user_model()`, per the CSV-export rules in
  `claude_plugins/fls-dev/resources/admin_interface.md`.
- Columns are an explicit `fields` whitelist, in this order: `id`, `email`, `first_name`,
  `last_name`, `is_active`, `is_staff`, `email_verified`, `created_at`, `last_login`. `created_at`
  is the date joined; `User` has no `date_joined`. `password`, `groups`, `user_permissions` and
  `is_superuser` never reach the file.
- `email_verified` is true when the user has an allauth `EmailAddress` with `verified=True` whose
  `email` matches the user's `email` case-insensitively. It is an `Exists` annotation added in
  `UserResource.filter_export`, so the changelist query is unchanged and no row costs a query.
- `UserAdmin` extends `SiteAwareExportModelAdmin` instead of `SiteAwareModelAdmin`, with
  `resource_classes = [UserResource]`. Its forms, fieldsets and inline are unchanged.

### Application export (`freedom_ls/form_engine/`, `freedom_ls/course_applications/`)

- **Shared question ordering.** Extract from `answer_groups` a function `form_questions` in
  `freedom_ls/form_engine/queries.py` that takes a `Form` with its pages and questions prefetched
  and returns its current questions in page order, then `page_questions` order within each page.
  `answer_groups` and the export both call it.
- **Answer columns.** New module `freedom_ls/form_engine/exports.py`; `form_engine` must not import
  `course_applications`. It exposes `answer_columns`, which takes a collection of `FormProgress` and
  returns the ordered answer columns (`AnswerColumn`: a `FormQuestion` plus header text), and
  `answer_cell`, which renders one `QuestionAnswer`, or `None`, as cell text.
  - Forms are ordered by `title`, then `id`. Each form contributes every question currently on its
    pages, in the shared order. Then come its off-page questions that some exported sitting
    answered, so no answer is dropped.
  - Header text is the question's `question` field. When two answer columns in one export would
    share a header, append ` (<form title>)` to each. If any are still equal, append ` (<n>)` by
    column position.
- **Cell text** by question type:
  - `MULTIPLE_CHOICE`, `DROPDOWN`, `CHECKBOXES` (together `OPTION_QUESTION_TYPES` in
    `freedom_ls/form_engine/enums.py`, beside `FREE_TEXT_QUESTION_TYPES`): the selected options'
    `text`, in option `order`, joined with `"; "`.
  - `FILE_UPLOAD`: the answer file's `original_filename`. Never the storage path or a URL.
  - `DATE` and `TIME`: the stored ISO `text_answer` unchanged, not `format_answer`'s
    locale-formatted text.
  - Every other type: `text_answer` in full, newlines kept.
  - No answer row: an empty cell.
- **Resource.** New `freedom_ls/course_applications/resources.py:
  CourseApplicationResource(SiteAwareModelResource)`. Fixed columns first, in this order:
  - `id`
  - `applicant_email`
  - `applicant_name`
  - `is_email_verified`
  - `course` (the course `title`)
  - `is_submitted`
  - `submitted_time`, declared with `IsoDateTimeWidget`
  - `created_at`

  The answer columns follow. The resource builds them per export, on the instance, in
  `before_export` from the queryset it is handed, and reuses those loaded objects for the rows
  rather than reading the queryset twice. An application with no sitting has blank answer cells.
- `submitted_time` has one source, a `CourseApplication.submitted_time` property, that both
  `CourseApplicationAdmin` and the resource read, so the export and the changelist cannot disagree.
- `CourseApplicationAdmin` extends `SiteAwareExportModelAdmin`, with
  `resource_classes = [CourseApplicationResource]`. It stays read-only.
- **Queries.** `CourseApplicationResource.filter_export` adds the prefetches:
  `form_progress__form`, `form_progress__answers__question`,
  `form_progress__answers__selected_options` and `form_progress__answers__answer_file`.
  `get_queryset` stays as it is, so the changelist does not load answers. Each form's pages and
  questions load once per form, not once per application. Within one export chunk
  (`get_chunk_size()`), the query count does not grow with the number of applications.

### Site isolation

Both exports start from the admin's own queryset, which `SiteAwareManager` scopes to the request's
site. Forms, questions, options and answers reached from those rows are on the same site because
they hang off same-site foreign keys. No code filters on `site_id` by hand.

## Testing

Follow `claude_plugins/fls-dev/skills/testing/SKILL.md`. The templates are
`freedom_ls/referral_tracking/tests/test_resources.py` and `tests/test_admin.py`.

- `FormulaSafeCSV`: a header cell starting with `=`, `+`, `-`, `@`, tab or carriage return comes
  out escaped.
- Boolean widget: `True` renders `TRUE`, `False` renders `FALSE`.
- `UserResource`: exports exactly the nine columns in order. `password` appears in no form, neither
  header nor hash. `email_verified` is `TRUE` only for a verified `EmailAddress` matching the
  user's `email`, including when the two differ only in case.
- Users admin: the changelist renders with the Export button and the "Export selected" action. The
  export button downloads the filtered changelist.
- Answer columns:
  - two forms are ordered by title, with blanks for the other form's questions;
  - a skipped question gives a blank cell;
  - a question moved off every page but answered still has its column, after the page questions;
  - a reworded question keeps one column under its current text;
  - duplicate headers get the form-title suffix, then the positional suffix.
- `answer_groups` returns the same groups as before the ordering was extracted.
- Cell rendering: multiple choice, dropdown and checkboxes (option text joined `"; "`, in option
  order); file upload (filename only); date and time (stored ISO text); long text with newlines;
  an answer starting with `=` comes out escaped.
- `CourseApplicationResource`:
  - a user-held application and an unclaimed anonymous one: the anonymous row takes its email and
    name from `AnonymousApplicant`, with `is_email_verified` `FALSE`;
  - a draft row has `is_submitted` `FALSE`;
  - an application with no sitting has blank answer cells;
  - the query count is the same for 2 and for 10 applications.
- Applications admin: the export honours the course filter and the submitted filter.
- Permissions: a staff user holding no permission at all on `User` or on `CourseApplication` gets
  403 on that model's export URL.
- Multi-site: users and applications, anonymous included, on a second site never appear in an
  export taken on the first.

## Documentation and downstream

- `docs/product/admin-interface.md`: the users and applications lists export to CSV, what each
  export contains (answer columns, drafts, anonymous rows, file names only), and that the
  view permission is what grants the export.
- `docs/product/security-and-data-handling.md`: the applicant and user exports are a new way
  personal data leaves the system. Note who can run them and that files are never included.
- Upgrade notes: `FormulaSafeCSV` now escapes headers, which affects a downstream subclass or a
  custom resource with a header starting with a trigger character. No settings or migrations.

## Success criteria

- Neither export file contains password data, a file's contents, or a row from another site.
- Staff without the model's view permission cannot export either list.
- An applications export opened in Excel shows one row per filtered application, anonymous and
  draft ones included, with every question of every form involved as a column.
