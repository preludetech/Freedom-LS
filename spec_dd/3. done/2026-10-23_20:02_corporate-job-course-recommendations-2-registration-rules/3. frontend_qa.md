# Frontend QA: Registration rules

The Django admin gains a "Registration rules" section. A rule belongs to an organisation, names a
course, carries attribute conditions on a change-page inline, and once enabled registers every
matching learner in the background. Every save that can change who is registered shows a preview
list first. This run walks the two-step create, the preview and confirm flow, retraction and
reactivation, the learner-side triggers, the organisation switch, the warnings, deletion, and the
ways it could go wrong: a staff-made registration a rule must not take over, a started learner a
rule must not retract, a learner from another organisation, a staff deactivation that must detach
the rule, a double submit of the confirmation, and inverted date bounds.

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever
this document writes `<PORT>`. Shell variables do not survive between tool calls.

Development settings run tasks on `ImmediateBackend`, so every evaluation a save triggers has
finished by the time the admin's redirect lands. Nothing here waits for a worker.

## §0 Setup

### 0.1 Server

1. `.claude/ds/scripts/find_available_port.sh`: note the number and use it literally from here on.
2. Start `uv run python manage.py runserver <PORT>` backgrounded, as its own call.
3. Open `http://127.0.0.1:<PORT>/` and confirm `#debug-branch-badge` names the
   `corporate-job-course-recommendations-2-registration-rules` branch. If it names another branch,
   another server holds the port; go back to step 1.

## §1 Creating a rule takes two steps

### 1.1 The add page

1. On the admin index, expect a "Registration rules" section with one entry, "Registration rules".
   Expect no entry for rule registrations or attribute conditions.
2. Open the rules changelist, click "Add registration rule". Expect exactly three inputs: Name,
   Organisation (autocomplete), Course (autocomplete). Expect no "Is enabled" checkbox and no
   conditions panel.
3. Enter Name `Finance in Cape Town`, Organisation `QA Org One`, Course `QA Budgeting Basics`.
   Save.
4. Expect to land on the rule's **change page** (URL ends `/change/`), with a success message.

### 1.2 The change page

1. On the change page expect: Name editable; Organisation and Course shown read-only (no
   dropdown); an "Is enabled" checkbox, unticked; "Last evaluated at" empty; an "Attribute
   conditions" panel with three multi-selects (Job titles, Departments, Locations) and eight
   date fields.
2. Open the Departments select: expect `Finance` and `Operations` only. `Audit` (deactivated) is
   absent. QA Org Two's `Finance` is absent.
3. Open Locations: `Cape Town`, `Durban`. Job titles: `Analyst`.
4. Back on the changelist, expect columns Name, Organisation, Course, Is enabled, Last evaluated
   at, Uses inactive entries, Change not yet applied; the row shows Is enabled false and both
   boolean columns false.
5. Check the registration changelist: still only the staff-registered learner's row for
   `QA Budgeting Basics`. Creating a rule registered nobody.

### 1.3 Invalid conditions are refused, before any preview

1. On the change page set "Organisation start on or after" to `2024-01-01` and "Organisation
   start before" to `2023-01-01`. Tick "Is enabled". Save.
2. Expect the change page back with a field error on "Organisation start before" ("Must be later
   than the 'on or after' date."), no preview page, and the rule still disabled (reload to check).
3. Clear both dates.

## §2 Enabling: preview, then registrations

### 2.1 The preview

1. On `Finance in Cape Town`'s change page select Departments `Finance` and Locations
   `Cape Town`, tick "Is enabled", click Save.
2. Expect a confirmation page inside the admin shell (sidebar and breadcrumbs present), titled
   "Confirm changes to Finance in Cape Town", not the changelist.
3. Expect "Will be registered (2)" listing the finance learner and the new hire by name and email.
   Expect the staff-registered learner **absent** (their registration already exists), the ops,
   Durban, audit and blank learners absent, and the other-org learner absent.
4. Expect "Will be retracted (0)" and "Stops matching but stays registered (0)" each saying
   "Nobody".
5. Expect no switch-off notice (QA Org One's switch is on).
6. Before confirming, open the rules changelist in a second tab: the rule is still disabled, and
   the registration changelist still has one row. Nothing was saved.

### 2.2 Cancel keeps the edits

1. On the preview click "Back to the form".
2. Expect the change page with `Finance` and `Cape Town` still selected and "Is enabled" still
   ticked, and no success message. Reload the page: the selections are gone and the rule is
   disabled. Cancel saved nothing.

### 2.3 Confirm

1. Repeat 2.1 steps 1 to 2, then click "Confirm and save".
2. Expect the changelist with the usual "changed successfully" message. The row shows Is enabled
   true, Last evaluated at set to now, Change not yet applied false.
3. Registration changelist: three rows for `QA Budgeting Basics`: the staff-registered learner,
   the finance learner and the new hire; all active.
4. Open the finance learner's registration. Expect a read-only "Registration rule" field showing
   `Finance in Cape Town` as a link to the rule; "Self registered" false. Click the link: it opens
   the rule.
5. Open the staff-registered learner's registration: "Registration rule" is blank.
6. Open the registration add page: "Registration rule" is blank (or absent); the form still saves
   nothing extra.

### 2.4 The learner's side

1. In a private window log in as `qa_rule_finance@email.com` at `http://127.0.0.1:<PORT>/`.
   Expect `QA Budgeting Basics` among the learner's registered courses on the dashboard, and a
   "registered for" notification in the notifications area.
2. Open the course and view its first topic, so the course counts as started. Log out.
3. Log in as `qa_rule_ops@email.com`: `QA Budgeting Basics` is not among their courses.

## §3 Editing an enabled rule

### 3.1 Widening

1. As the superuser, on `Finance in Cape Town` add `Durban` to Locations (keep `Cape Town`).
   Save.
2. Preview: "Will be registered (1)" names the Durban learner. The other two lists say "Nobody".
   Confirm.
3. Registration changelist: the Durban learner now has an active registration showing the rule.

### 3.2 Narrowing retracts the unstarted and keeps the started

1. On the rule remove `Cape Town` from Locations (leave `Durban`). Save.
2. Preview: "Will be retracted (1)" names the new hire. "Stops matching but stays registered (1)"
   names the finance learner with the reason "Started the course". "Will be registered (0)".
   The staff-registered learner is in no list.
3. Confirm. Registration changelist: the new hire's row is now **inactive** and still shows the
   rule; the finance learner's row is still active; the staff-registered learner's row is
   untouched; no row was deleted.
4. Open the new hire's registration: "Registration rule" still names the rule.

### 3.3 Matching again reactivates the same row, silently

1. Add `Cape Town` back to Locations. Save. Preview: "Will be registered (1)" names the new hire
   (reactivation counts as registering). Confirm.
2. Registration changelist: the new hire's row is active again, with the same "Registered at"
   as before. No second row exists for them.
3. In a private window log in as `qa_rule_newhire@email.com`: expect no **new** notification
   for the course (one from §2 only).

## §4 Hand-over between rules

1. Create a second rule `Everyone in Cape Town` for QA Org One and `QA Budgeting Basics` with
   Locations `Cape Town` only; enable it. Preview: "Will be registered (2)" names the ops learner
   and the audit learner (both in Cape Town; the finance learner, new hire and staff-registered
   learner are already registered). Confirm.
2. Open `Finance in Cape Town`, untick "Is enabled", Save. Preview: "Will be retracted (1)" names
   the Durban learner (not in Cape Town); "Stops matching but stays registered (2)": the finance
   learner ("Started the course") and the new hire ("Still matched by Everyone in Cape Town").
3. Confirm. Registration changelist: Durban learner inactive; the new hire's registration now
   shows `Everyone in Cape Town` in "Registration rule"; the finance learner's still shows
   `Finance in Cape Town`.
4. Open `Everyone in Cape Town`, disable it. Preview: "Will be retracted (3)": the new hire, the
   ops learner, the audit learner. "Stops matching but stays registered (0)" (the finance
   learner is owned by the other rule). Confirm, then check the three rows are inactive.
5. Re-enable `Finance in Cape Town` (Locations `Cape Town` and `Durban`). Preview: "Will be
   registered (2)": the new hire and the Durban learner (both retracted, both match). Confirm and
   check both are active again and point at `Finance in Cape Town`.

## §5 Learner-side triggers

### 5.1 An attribute change registers a learner

1. Open the ops learner in the Learner admin
   (`http://127.0.0.1:<PORT>/admin/freedom_ls_learner_management/learner/`), change their HR
   attributes department to `Finance`, save.
2. Registration changelist: the ops learner's registration for `QA Budgeting Basics` is active
   and shows `Finance in Cape Town`. No preview was shown; learner edits apply directly.

### 5.2 An attribute change retracts a learner

1. Change the ops learner's department back to `Operations`, save.
2. Their registration is inactive, still showing the rule.

### 5.3 A new learner

1. Create a new user `qa_rule_joiner@email.com` and a Learner of QA Org One, then on the Learner
   change page set HR attributes Finance, Cape Town, save.
2. Their registration for `QA Budgeting Basics` exists, active, showing the rule.

### 5.4 Removing a learner

1. On the joiner's Learner page untick "Is active", save.
2. Their registration is inactive. Tick "Is active" again, save: active again, same row.

### 5.5 The blank learner never matches

1. The blank learner (no HR attributes row) has no registration for the course, before or after
   any of the above.

## §6 Staff changes detach the rule

1. Open the new hire's registration (active, rule-made). Untick "Is active", save.
2. Reopen it: "Registration rule" is now blank.
3. Open `Finance in Cape Town`, change its Name only, Save. Preview: the new hire is in no list.
   Confirm. The new hire's registration stays inactive: the rule left it alone.
4. Tick "Is active" on that registration again and save: still blank "Registration rule", and a
   later rule change still lists them nowhere.

## §7 The organisation switch

### 7.1 Switch off

1. Open `QA Org One` in the Organisations admin, untick "Registration rules enabled" in the HR
   settings panel, save.
2. Open `Finance in Cape Town`. Expect a warning on the change page: registration rules are
   switched off for QA Org One and the rule's changes apply once they are switched on.
3. Change the Durban learner's department to `Operations` (Learner admin). Their registration
   stays active: nothing is evaluated while the switch is off.
4. On the rule, add `Analyst` to Job titles, Save. Preview: a notice that nothing will change
   until the switch is on, **and** the lists still render ("Will be retracted" now names
   everyone except the started finance learner, since nobody holds `Analyst`). Confirm.
5. Rules changelist: "Change not yet applied" is true for the rule; "Last evaluated at" has not
   moved. Registration changelist: nothing changed.
6. Remove `Analyst` from Job titles again, Save, confirm the preview.

### 7.2 Switch on catches up

1. Tick "Registration rules enabled" on `QA Org One`, save.
2. Registration changelist: the Durban learner (now Operations) is inactive; everyone who matches
   is active. Rules changelist: "Change not yet applied" false, "Last evaluated at" updated.

### 7.3 An organisation with no settings row

1. Create a rule `Org Two Finance` for `QA Org Two` and `QA Budgeting Basics` with Departments
   `Finance` (QA Org Two's), enable it. Preview: the switch-off notice, "Will be registered (1)"
   naming the other-org learner. Confirm.
2. The other-org learner has no registration. The rule shows "Change not yet applied".
3. Disable `Org Two Finance` (preview, confirm) and leave it.

## §8 Warnings

### 8.1 Inactive entries

1. On `Finance in Cape Town` select `Audit` in Departments. It is not offered: the picker shows
   only active entries plus selected ones.
2. Reactivate `Audit` in the Departments admin, select it on the rule, save (preview, confirm).
   Then deactivate `Audit` again.
3. Open the rule: Departments shows `Audit (inactive)` still selected, and a warning names it.
   Rules changelist: "Uses inactive entries" true. The audit learner, who holds `Audit`, is
   registered (the preview on step 2 listed them).
4. Deselect `Audit`, save, confirm. The warning and the column clear; the audit learner is
   retracted (they no longer match).

### 8.2 Unpublished course

1. Create `Hidden course rule` for QA Org One and `QA Hidden Course`, Departments `Finance`,
   enable, confirm the preview.
2. The change page shows a warning that the course is not published and the rule still
   registers. The finance learner's registration for `QA Hidden Course` exists and is active.
3. Disable and confirm, then leave it.

## §9 Deletion

1. On `Finance in Cape Town` (enabled) expect no "Delete" link on the change page. Open
   `/admin/freedom_ls_registration_rules/registrationrule/<id>/delete/` directly: expect 403.
2. On the changelist tick `Finance in Cape Town` and `Org Two Finance`, action "Delete selected",
   Go. Expect the confirmation page refusing the selection and naming `Finance in Cape Town` as
   protected (enabled). Nothing is deleted.
3. Disable `Everyone in Cape Town` is already disabled from §4; delete it from its change page.
   Expect success. Open the registration of a learner it owned at some point (if any still point
   at it) or skip; otherwise: disable `Hidden course rule` and delete it, then open the finance
   learner's `QA Hidden Course` registration. Expect "Registration rule" showing
   `Hidden course rule (deleted)`, and the row still inactive from §8.2 step 3 (deleting the rule
   neither reactivated nor deleted the row).

## §10 Adversarial

### 10.1 Double confirm

1. Open `Finance in Cape Town`, change nothing, click Save (the rule is enabled, so the preview
   shows). Click "Confirm and save". On the resulting changelist press the browser's back button
   to the preview page and click "Confirm and save" again.
2. Expect a normal save, no error page, and no duplicate registration rows (registration
   changelist count unchanged).

### 10.2 Cross-organisation entry

1. Open the browser devtools on `Finance in Cape Town`'s change page, add an `<option>` to the
   Departments select whose value is QA Org Two's `Finance` id (from its admin URL), select it,
   Save.
2. Expect a validation error on Departments ("Choose entries from this rule's organisation."),
   no preview, nothing saved.

### 10.3 View-only staff

1. Create a staff user with only "Can view registration rule" permission, log in as them, open a
   rule's change page and submit it. Expect the read-only view; a forced POST (devtools) gets
   403. No preview page for a viewer.

## §11 Layout

On the preview page (§2.1) and the rule change page, at viewport widths 375, 768 and 1920 px:
no horizontal scrollbar, the three lists readable, both buttons visible and reachable, the
sidebar collapsed or present as unfold normally renders it.
