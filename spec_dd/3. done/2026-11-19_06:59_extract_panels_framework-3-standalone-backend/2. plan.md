Spec: `1. spec.md` in this directory. R1 to R11 below are the spec's requirement numbers.

All paths are relative to the repo root. "The framework" is `freedom_ls/panel_framework/`.

## What exists and is reused

  the settings-helper copy and its tests (R1, R11).

  `freedom_ls/base/tests/test_csv_safety.py`: the source of the CSV copy and its tests (R5).

- `BulkActionRun._base_manager` reads in `bulk_runs.py`, `housekeeping.py`, `run_records.py` and
  `qa_helpers/management/commands/qa_create_bulk_operations_scenario.py` filter on `site_id`
  themselves or are cross-site on purpose. Not edited.
- `freedom_ls/panel_framework/tests/helpers.py` (`make_staff_user`, `make_stub*`),
  `stub_models.py`, `stub_panels.py`, `root_urls.py`, `urls.py`, `view_helpers.py` and the
  `_panel_test_tables` fixture already keep the unit tests free of FLS models. The standalone run
  reuses them.
- `test_organisation/mirroring_exemptions.txt` accepts a single file path with a reason. That is
  how a test that mirrors no module passes the `test-mirroring` hook.
- `freedom_ls/educator_interface/tests/invariants/` already holds FLS's project-wide isolation
  checks and is exempt from mirroring.

## Decisions the spec leaves to the plan

- **Date formats (R6)** live in `field_display.py` as two module constants. No new module.
- **Fixture coexistence (R9).** `site` and `mock_site_context` for the standalone run live in
  `tests/standalone_fixtures.py`. `tests/conftest.py` imports them only when the settings module is
  the standalone one. In the FLS run the conftest defines neither, so FLS's root fixtures of the
  same names apply unchanged: that is the delegation the spec asks for, and it keeps the conftest
  edit to one block.
- **Migrations in the standalone run.** The ini passes pytest-django's `--nomigrations`, so tables
  come from the models and the test app needs no migration. FLS's own run still applies the
  framework's real migration on PostgreSQL.
- **`Site` rows in framework tests** come from `helpers.make_site`, which wraps
  `Site.objects.create`, so no test body creates a row directly.

> **Assumed default:** the default resolver stays `django.contrib.sites.shortcuts.get_current_site`,
> which answers with `SITE_ID` when a host sets one. Why: the spec fixes the default, and FLS sets
> its own resolver. To change: slice 3, the `PANEL_FRAMEWORK_SITE_RESOLVER` declaration. The
> setting's comment says a host with several sites must not rely on `SITE_ID`.

### Slice 3: the site of a request comes from a configurable resolver

`resolve_site(request)` returns the request's `Site`, or `None`, through
`PANEL_FRAMEWORK_SITE_RESOLVER`. FLS points the setting at its own resolver. Nothing calls
`resolve_site` yet; slice 5 is its first caller, and this slice's own tests prove it.

**Builds on:** slices 1
**Touches:** freedom_ls/panel_framework/sites.py, freedom_ls/panel_framework/config.py, freedom_ls/panel_framework/tests/test_sites.py, freedom_ls/panel_framework/tests/helpers.py, config/settings_base.py

- `config.py`: add the annotation `PANEL_FRAMEWORK_SITE_RESOLVER: str` and the declaration

  ```python
  # Dotted path of a callable that takes the request and returns its Site.
  # The default follows django.contrib.sites, where SITE_ID wins over the
  # request's host: a project serving several sites from one process must
  # set its own resolver, or every request shares one site's runs.
  "PANEL_FRAMEWORK_SITE_RESOLVER": Setting(
      default="django.contrib.sites.shortcuts.get_current_site"
  ),
  ```

- Create `sites.py`:

  ```python
  """The site a request belongs to, as the host project resolves it."""

  SETTING_NAME = "PANEL_FRAMEWORK_SITE_RESOLVER"
  # The framework's own attribute, so it never aliases a cache the host keeps on the request.
  _REQUEST_ATTR = "_panel_framework_site"
  _UNSET = object()


  def resolve_site(request: HttpRequest) -> Site | None:
      """The request's Site row, or None when the host resolves it to no row.

      Resolved once per request. The resolver is imported on the first call
      for each request rather than at module import, so a changed setting or
      a patched resolver takes effect.
      """
      cached = getattr(request, _REQUEST_ATTR, _UNSET)
      if cached is not _UNSET:
          return cast(Site | None, cached)
      try:
          resolved = _resolver()(request)
      except Site.DoesNotExist:
          # django.contrib.sites answers an unknown host this way.
          resolved = None
      site = resolved if isinstance(resolved, Site) else None
      setattr(request, _REQUEST_ATTR, site)
      return site


  def _resolver() -> Callable[[HttpRequest], object]:
      path = config.PANEL_FRAMEWORK_SITE_RESOLVER
      if not isinstance(path, str):
          raise ImproperlyConfigured(f"{SETTING_NAME} = {path!r} is not a dotted path.")
      try:
          resolver = import_string(path)
      except ImportError as error:
          raise ImproperlyConfigured(f"{SETTING_NAME} = {path!r} cannot be imported.") from error
      if not callable(resolver):
          raise ImproperlyConfigured(f"{SETTING_NAME} = {path!r} is not callable.")
      return resolver
  ```

  Any other exception the resolver raises propagates unchanged.
- `tests/helpers.py`: add `make_site(name: str, domain: str) -> Site`, wrapping
  `Site.objects.create`. It is the one place framework tests create a `Site` row.
- `config/settings_base.py`: add
  `PANEL_FRAMEWORK_SITE_RESOLVER = "freedom_ls.site_aware_models.models.get_cached_site"`, with a
  comment that it keeps `FORCE_SITE_NAME` and FLS's request cache in force for bulk-action runs.
- Tests (`tests/test_sites.py`), each under `override_settings(PANEL_FRAMEWORK_SITE_RESOLVER=...)`
  where it needs a stand-in. Stand-in resolver functions are defined in the test module and
  referenced as `f"{__name__}.<function>"`, so the path is right in both runs. A fixture in the
  module calls `Site.objects.clear_cache()` before and after each test, because
  `get_current_site` caches by host for the life of the process.
  - the default resolver returns the `Site` whose domain is the request's host, with two `Site`
    rows present;
  - the default resolver on a host that matches no `Site` returns `None`;
  - the setting overrides the default;
  - the resolver is called once for two `resolve_site` calls on one request and once more for a
    second request, parametrised over a resolver that returns a `Site`, one that returns a
    `RequestSite`, and one that raises `Site.DoesNotExist`;
  - a resolver returning `RequestSite(request)` gives `None`;
  - a resolver raising any other exception propagates it;
  - an unimportable path, a non-callable path and a non-string value each raise
    `ImproperlyConfigured` whose message names `PANEL_FRAMEWORK_SITE_RESOLVER` and the bad value
    (one parametrised test).
