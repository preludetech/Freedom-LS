# Frontend QA — better form start page

The change is a restyle of the **form start page** — the screen a learner sees before beginning a
`Form` in the course player. It touches `course_form.html`, deletes the meta-grid partial and
restyles the previous-attempts partial. Nothing server-side changes, so the risk is entirely visual
and structural: a state that no longer renders, a control that has moved or gone, a hardcoded colour
that only looks right on one theme, or a layout that breaks when real content is longer than the
design's lorem.

## §0 Setup

### Start the server

```bash
PORT=$(.claude/ds/scripts/find_available_port.sh)
uv run python manage.py runserver $PORT
```

Base URL is `http://127.0.0.1:$PORT`. Substitute it everywhere below.

### Build the CSS first

The change adds Tailwind classes that are not currently in the tree. **If you skip this, every test
below will fail for the wrong reason.**

```bash
npm run tailwind_build
```

### Seed data

```bash
uv run python manage.py qa_create_form_question_types
uv run python manage.py qa_create_quiz_progression_block
uv run python manage.py qa_create_free_text_survey
```

These give you:

| Fixture | Learner | Course slug | Form |
| --- | --- | --- | --- |
| `qa_create_form_question_types` | `demodev@email.com` | `qa-question-types-course` | every question type, one page |
| `qa_create_quiz_progression_block` | `demodev_quizqa@email.com` | `qa-progression-block-course` | QUIZ, `quiz_pass_percentage=80`, a topic before and after it |
| `qa_create_free_text_survey` | `demodev_quizqa@email.com` | `qa-free-text-survey-course` | free-text survey |

Login convention in this project is **password == email address**. Admin is
`demodev@email.com` / `demodev@email.com`.

To put a learner back to a clean "never attempted" state between tests:

```bash
uv run python manage.py qa_reset_learner_progress \
    --learner demodev_quizqa@email.com --course-slug qa-progression-block-course
```

## §1 The first-time start page — the golden path

The core of the change.

1. Log in as `demodev_quizqa@email.com`.
2. Go to `http://127.0.0.1:$PORT/courses/qa-progression-block-course/`.
3. Complete or open the first topic so the quiz is reachable, then open the quiz.

**Expect:**

- One **centred column**, not a full-width page. Everything — badge, eyebrow, title, intro, pills,
  button — is horizontally centred and sits in a narrow column (roughly 560–580px), not stretched
  across the viewport.
- A **rounded square badge** at the top, filled with the theme's secondary colour, holding a single
  outline icon. It is a solid fill — not a gradient, and it casts no coloured glow.
- Beneath it, the form's subtitle as an **eyebrow**: small, monospace, UPPERCASE, widely tracked,
  muted grey.
- The **form title** as a large bold display heading.
- The form's authored intro text.
- A row of **pill chips**: "N questions" and "N pages", each with a small secondary-coloured icon.
  Check the numbers are actually right — count the questions and pages in the form.
- A single **primary button** reading "Start Form", centred.

**Expect gone** (these are the old design, and their absence is the point):

- The old two-cell bordered meta grid with big numbers stacked over "QUESTIONS" / "PAGES" labels.
- Any left-aligned page title at the top-left of the content column.

**Watch for:**

- Pluralisation. A form with exactly **one** question must say "1 question", not "1 questions".
  If no seeded form has a single question, make one in the admin
  (`http://127.0.0.1:$PORT/admin/`) and check it.
- The badge icon and the "questions" pill icon should not be the same glyph sitting twice on one
  card. If they are, that is a finding.

## §2 The returning learner — previous attempts still work

This is the state the simple design had no answer for, so it is the most likely regression.

1. Still as `demodev_quizqa@email.com`, complete the quiz (any answers) and submit it.
2. Navigate back to the quiz start page.

**Expect:**

- The **Previous attempts** section is still there, below the card.
- It is **left-aligned**, not centre-aligned — it is a list of rows, and centring the dates and
  scores would look broken.
- Each row shows a date and, for the QUIZ, a percentage plus the raw `score / max_score`.
- Row backgrounds match the page's surface colour and do not read as a hard white block against an
  off-white page. This is the specific thing being fixed — the old rows were hardcoded `bg-white`.
- The button now reads **"Try Again"** (you will have failed at 80% unless you answered correctly)
  or **"Next"** / **"Finish Course"** if you passed. It is still centred.

**Then take a second and third attempt** and confirm the list grows and stays readable. Take **six**
attempts and confirm only the five most recent are listed — the view slices to 5.

## §3 Every start-page state

The button logic has five branches. Walk each and confirm the layout still holds — the card should
never look half-empty or lose its centring.

| State | How to get there | Expect |
| --- | --- | --- |
| No attempts | fresh learner, or run `qa_reset_learner_progress` | "Start Form", no previous-attempts section at all (not an empty heading) |
| Mid-attempt | start the quiz, answer page 1, navigate away via the course outline without submitting | **"Continue Form"**. Confirm it resumes on the right page |
| Failed quiz | submit deliberately wrong answers on `qa-progression-block-course` | **"Try Again"**, and the following topic is still locked in the outline |
| Passed quiz | submit correct answers | **"Next"** |
| Last item | find or build a course whose form is the final item | **"Finish Course"** |

For each: the CTA is a single centred button, and clicking it goes where it says.

## §4 Real content, not lorem

The design was drawn with a short title and one short paragraph. Real content is not.

1. In the admin, edit a form (e.g. `qa-all-question-types-form`) and give it:
   - a long title (10+ words),
   - a long `subtitle`,
   - intro markdown containing **a heading, a bullet list, a numbered list, a code block and a
     blockquote**.
2. Reload the start page.

**Expect:**

- The long title wraps sensibly inside the narrow column and does not overflow.
- The eyebrow wraps rather than pushing the page sideways.
- **The bullet list, numbered list, code block and blockquote are LEFT-aligned.** Centred list items
  are the specific failure mode here. A centred paragraph is fine and expected; centred bullets are
  a bug.
- Nothing causes horizontal scrolling on the page.

3. Now clear the form's `subtitle` entirely and reload.

**Expect:** no eyebrow, and no empty gap where it used to be — the title should move up cleanly.

4. Clear the form's markdown content entirely and reload.

**Expect:** badge, eyebrow, title, pills and button, with no stray empty container between the title
and the pills.

## §5 Both themes

The idea's whole point is that this survives a theme change. Run this — it is not optional.

The active theme comes from the `FLS_THEME` environment variable (`config/settings_base.py:33`),
defaults to `default`, and the CSS is regenerated at build time.

1. Stop the server. Build and run under **first_class**:

   ```bash
   FLS_THEME=first_class npm run tailwind_build
   FLS_THEME=first_class uv run python manage.py runserver $PORT
   ```

   Reload the start page. Expect the indigo/teal brand: a teal badge, indigo button, DM Sans / Outfit
   type, and the chunkier first_class radii on the pills and button.

2. Stop, then build and run under **default**:

   ```bash
   npm run tailwind_build
   uv run python manage.py runserver $PORT
   ```

   Reload. Expect the blue/slate default brand — badge in slate, button in ocean blue, system font.

**Expect in both:** every element is legible, nothing disappears into its background, and no colour
looks obviously imported from the other theme. Specifically check the **badge icon against the badge
fill** and the **pill icon against the pill background** — those are the two places a
foreground/background pair could have been mismatched.

**A finding here** is any hardcoded colour: a white row that stays white when the theme's surface
isn't, a teal that stays teal under the default theme, a font that doesn't change.

## §6 Responsive

Check at three widths — 375px (mobile), 768px (tablet), 1440px (desktop).

- **375px**: the card fills the width with sensible side padding. The two pills wrap onto separate
  lines rather than squashing or overflowing. The button is reachable and not clipped. No horizontal
  scrollbar.
- **768px**: the course outline is behind the toggle; the card is still centred in the content area.
- **1440px**: the card stays a narrow centred column — it must **not** stretch to fill the wide
  content well. If it does, the max-width was lost.

Also open the course outline panel at desktop width and confirm the card re-centres in the remaining
space rather than staying centred to the full viewport and appearing off-centre.

## §7 Navigation still behaves (HTMX)

The CTA sits inside `c-player-nav`, which boosts navigation so only the content column swaps.

1. From the start page, click the primary button.
2. **Expect:** the page changes without a full white flash, the URL updates, and the course outline
   in the sidebar updates its highlight.
3. Press the **browser back button**.
4. **Expect:** you land back on the start page, fully rendered — badge, pills and all. A blank or
   half-rendered card here means the boost target or select was broken.
5. Reload that page directly (F5). Expect the same page.

## §8 Failure and permission branches

- **Not registered for the course.** Log in as a different learner who is not registered
  (`demodev_s1@email.com` is deliberately unregistered for one course — see
  `qa_create_course_player_learner`) and hit the quiz URL directly. Expect the existing redirect /
  preview behaviour, **not** a broken start page and not a server error.
- **Logged out.** Open the quiz URL in a private window. Expect the login redirect, not a stack
  trace.
- **A locked item.** On `qa-progression-block-course` with a failed quiz, click the following topic
  in the outline. Expect it to stay locked — the restyle must not have changed unlocking.
- **A form with zero questions or zero pages.** Create one in the admin and open its start page.
  Expect "0 questions" / "0 pages" rendered without crashing and without a mangled layout.

## §9 Accessibility spot-check

- Tab through the page. The primary button takes focus and shows a visible focus ring.
- The previous-attempts section still has its heading, and that heading is associated with the
  section (it was `aria-labelledby`).
- The badge icon should not announce itself as meaningful content when it is purely decorative next
  to the title that already says the same thing.
- Zoom the browser to 200%. The card should reflow, not clip.
