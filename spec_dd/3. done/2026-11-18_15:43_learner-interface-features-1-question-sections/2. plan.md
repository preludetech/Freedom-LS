### Slice 1: A question's own `sections:` list is stored as its topics and parts

Behaviour: a `FORM_QUESTION` section with `sections: [../01. key-ideas/content.md, ../part.yaml]`

4. **Loader.** In `content_save.py`:
   - `save_form_question` passes `exclude_fields={"options", "when", "sections"}`.
   - New function, called in the page loop right after `save_form_question` returns the question,
     as `save_question_sections(question, *effective_sections(item), content_by_path)`:

     ```python
     def save_question_sections(
         question: FormQuestion,
         declarer: SectionsDeclarer,
         section_paths: list[Path],
         content_by_path: Mapping[Path, models.Model],
     ) -> None:
         """Set the question's sections to exactly this list.

         Both set() calls run every time, empty lists included, so a path removed
         from the file drops that section. Targets come from this run's saved rows,
         never a slug or database lookup, so they are always this site's rows.
         """
         topics: list[Topic] = []
         course_parts: list[CoursePart] = []
         for path in section_paths:
             key = resolve_author_path(declarer.file_path, path)
             target = content_by_path.get(key)
             if isinstance(target, Topic):
                 topics.append(target)
             elif isinstance(target, CoursePart):
                 course_parts.append(target)
             else:
                 raise ValueError(
                     f"{declarer.file_path}: question {question.question!r} names "
                     f"section {path} ({key}), which is not a TOPIC or COURSE_PART "
                     "loaded in this run"
                 )
         question.topics.set(topics)
         question.course_parts.set(course_parts)
     ```

       question: FormQuestion, form: Form
   ) -> tuple[SectionsDeclarer, list[Path]]:

### Slice 3: A bad section path fails validation and the load, before anything is written

Behaviour: a path to no file, to a file that is not a part or topic, a path listed twice in one
list, or (for `content_save`) a target outside the loaded directory is reported, every one at
once, in the `_reference_error` block layout. `content_save` writes nothing.

**Builds on:** slices 1, 2

**Touches:** freedom_ls/content_engine/validate.py, freedom_ls/content_engine/tests/test_validate.py, freedom_ls/content_engine/management/commands/content_save.py, freedom_ls/content_engine/tests/management/commands/test_content_save.py

1. Give `_reference_error` an optional `resolved: Path | None = None` that adds a
   `Resolved to: <path>` line under `Given value`, so a section error shows the path as written
   and as resolved. Existing callers are unchanged.

2. New builder, used by the validator and by `save_question_sections`:

   ```python
   def section_error(
       declarer: Form | FormQuestion, index: int, path: Path, resolved: Path,
       problem: str, fix: str,
   ) -> str:
       """The error block for one bad entry in a sections: list."""
       field = f"sections[{index}]"
       if isinstance(declarer, FormQuestion):
           field = f"{_target_label(declarer, 0)} → {field}"
       return _reference_error(
           declarer.file_path, declarer.content_type, field, str(path),
           problem, fix, header="Invalid section reference", resolved=resolved,
       )
   ```

3. New cross-file check, modelled on `validate_form_conditions`:

   ```python
   _SECTION_TYPES = frozenset({ContentType.COURSE_PART, ContentType.TOPIC})

   def validate_question_sections(
       all_parsed: Sequence[BaseBaseContentModel], *, read_outside: bool = True
   ) -> list[str]:
       """Check every sections: list, on a form and on each question that sets its own.

       With read_outside, a target beyond the validated path is read from disk,
       as a single-directory validate run needs. content_save passes False:
       it links only rows it loads in the same run.
       """
       parsed = {content_key(i.file_path): i for i in all_parsed}
       lookup = _ParsedByPath(all_parsed).get if read_outside else parsed.get
       for each declarer (a Form with the key, a FormQuestion with the key):
           keys = [resolve_author_path(declarer.file_path, p) for p in declarer.sections]
           repeated = _repeated_indices(keys)
           for i, (given, key) in enumerate(zip(declarer.sections, keys)):
               target = lookup(key)
               not key.is_file()                      -> "no file at this path"
               target is None and not read_outside    -> "this file is not loaded with the form: it sits outside the directory content_save was given"
               target is None                         -> skip (the file's own validation reports it)
               target.content_type not in _SECTION_TYPES -> f"this file is a {target.content_type}"
               i in repeated                          -> "this section is named twice"
   ```

   Fix lines: "Name a part's part.yaml or a topic's markdown file; paths are relative to this
   file's directory." / "Name each section once." / "Load a directory that holds both the form and
   the section."

4. Call it from `validate()` beside `validate_form_conditions`, and add
   `*validate_question_sections(all_parsed, read_outside=False)` to the pre-write
   `placement_errors` list in `save_content_to_db`.
5. `save_question_sections` swaps its plain message for `section_error(declarer, index, path,
   key, problem, fix)`, so a caller that skipped validation still gets the same block. Its
   signature is unchanged.

Tests in `test_validate.py` (both directions for each rule): a missing file; a course, form,

`save_content_to_db` fails the load.

### Slice 4: The admin shows a question's sections read-only

Behaviour: the `FormQuestion` change page has a "Sections" fieldset listing its topics and parts,
read-only.

**Builds on:** slice 1

**Touches:** freedom_ls/content_engine/admin.py, freedom_ls/content_engine/tests/test_admin.py

`topics` and `course_parts` are `content_engine` relations, so `form_engine/admin.py` stays
unchanged and `content_engine/admin.py` re-registers `FormQuestion` with a subclass. Importing
`form_engine.admin` from `content_engine.admin` registers the base first, whatever the app order;
the reverse accessors cannot be named in `readonly_fields` directly, hence display methods:

```python
from freedom_ls.form_engine.admin import FormQuestionAdmin
from freedom_ls.form_engine.models import FormQuestion

class FormQuestionWithSectionsAdmin(FormQuestionAdmin):
    """FormQuestionAdmin plus the sections the question tests.

    Registered here because the sections are content_engine relations, and
    form_engine does not depend on content_engine.
    """
    readonly_fields = (*FormQuestionAdmin.readonly_fields, "section_topics", "section_course_parts")
    fieldsets = (
        *FormQuestionAdmin.fieldsets[:-1],
        ("Sections", {
            "fields": ("section_topics", "section_course_parts"),
            "description": "Set by the sections: key in the form files and rewritten on every load.",
        }),
        FormQuestionAdmin.fieldsets[-1],
    )

    @admin.display(description="Topics")
    def section_topics(self, obj: FormQuestion) -> str:
        return ", ".join(topic.title for topic in obj.topics.all())

    @admin.display(description="Course parts")
    def section_course_parts(self, obj: FormQuestion) -> str:
        return ", ".join(part.title for part in obj.course_parts.all())

admin.site.unregister(FormQuestion)
admin.site.register(FormQuestion, FormQuestionWithSectionsAdmin)
```

`FormQuestionInline` is unchanged. Tests in `content_engine/tests/test_admin.py` (content_engine
tests may import form_engine), with a question that names a topic and a part: the change page,
through `staff_client`, shows both titles; a POST of the change form leaves the question's
`topics` and `course_parts` unchanged (they are read-only). The admin delete refusal for a named
`Topic` already holds: `TopicAdmin` and `CoursePartAdmin` grant no delete permission
(`test_content_admins_never_permit_deletion`), and slice 1 tests the database-level PROTECT.
