# Frontend QA: panel framework tables

Browser checks for the rebuilt table layer. The educator tables adopt only the table key, the
prefixed query parameters, the new page size, the announcement and focus behaviour, and the mobile
cards and sheet. They declare no filters, no bulk actions and no export, so those three features
are exercised only by the automated tests in `panel_framework/tests/`; this document does not
cover them in the browser.

## 0. Setup

1. Pick a port and start the server:

   ```
   PORT=$(.claude/ds/scripts/find_available_port.sh)
   uv run python manage.py runserver $PORT
   ```

   The base URL is `http://127.0.0.1:$PORT`.

2. Seed data. The `DemoDev` site and the `demodev` organisation exist in the dev database. Create a
   cohort large enough to page at 25 rows and give it two course registrations:

   ```
   uv run python manage.py qa_create_large_cohort DemoDev --cohort-name "QA Tables Cohort" --num-learners 30
   ```

   If the cohort ends up with fewer than two course registrations, or the organisation has fewer
   than 26 cohorts, ask the `fls-dev:qa-data-helper` agent to top them up (a second cohort course
   registration on "QA Tables Cohort"; `qa_create_org_cohort_pagination --num-cohorts 30` for the
   cohorts list).

3. Log in at `http://127.0.0.1:$PORT/accounts/login/` as `demodev@email.com` /
   `demodev@email.com`.

4. Open `http://127.0.0.1:$PORT/educator/`. You are redirected to
   `/educator/demodev/dashboard`. In what follows `ORG` stands for `demodev`.

## 1. Two tables on one page page independently

1. Go to Cohorts, open "QA Tables Cohort". The details tab shows "Course Registrations" and
   "Learners" tables.
2. The learners table shows 25 rows and pagination. Click page 2.
3. Expect: only the learners table changes (rows 26–30), the course registrations table is
   untouched, and the address bar reads
   `/educator/ORG/cohorts/<pk>/__tabs/details?learners-page=2`. It never contains `__panels`.
4. Reload the page. Expect the learners table on page 2 and course registrations on page 1.
5. Edit the address bar to `?learners-page=2&course_registrations-page=1` and load it. Expect the
   same rendering. Then try `?course_registrations-page=2`: with only two registrations the table
   stays on its single page and nothing errors.
6. Try `?learners-page=999` and `?learners-page=abc`. Expect the last page and the first page
   respectively, no error page.

## 2. Sort, page reset and browser history

1. On the same cohort details tab, click the "First Name" header of the learners table.
2. Expect: rows sort ascending, the header shows an ascending icon, the address bar gains
   `learners-sort=user__first_name`, and the page indicator is on page 1.
3. Click page 2, then click "Last Name". Expect the address bar to show
   `learners-sort=user__last_name` with no `learners-page`, and the table on page 1.
4. Click "Last Name" again. Expect `learners-sort=-user__last_name` and descending order.
5. Press the browser Back button twice. Each time, expect the address bar and the table to agree
   (sort icon, first row, page number).
6. Press Forward. Same expectation.
7. Copy the URL, open it in a new tab. Expect identical state.

## 3. Search replaces the URL and encodes text

1. Go to Learners (`/educator/ORG/learners`).
2. Type a learner's first name slowly. Expect the table to narrow after a short pause without a
   full reload, and the address bar to update to `?learners-q=<text>` without adding history
   entries (Back returns to the page you came from, not to each keystroke).
3. Type `a & b + c #`. Expect no error, an empty table with "No results" visible only to screen
   readers (check the `#scope-announcer` element in devtools reads "No results"), and the address
   bar showing the encoded text.
4. Clear the search with the input's own clear control. Expect the full table back.
5. Sort by "First Name", then search. Expect the sort to survive the search (the header icon
   stays and `learners-sort` stays in the URL).
6. Press Enter in the search box. Expect the same result as typing, with no full page reload.

## 4. Announcement and focus

1. With devtools open on the Elements tab, find `#scope-announcer`.
2. Click a sort header. Expect the announcer text to read like "Showing 1–25 of 30, sorted by
   First Name".
3. After the click, press Tab once. Expect focus to move to the first focusable control inside
   the table region (the search box or first header link), which shows focus landed on the table
   rather than staying at the top of the page.

## 5. JavaScript off

1. In devtools, disable JavaScript (Command palette → "Disable JavaScript"). Reload the cohort
   details tab.
2. Click page 2 on the learners table. Expect a full page load to
   `?learners-page=2` with the right rows.
3. Click a sort header. Expect a full page load with the sort applied and the page reset.
4. Type in the search box and press Enter. Expect a full page load to the page URL with
   `learners-q=<text>` and any existing `learners-sort` preserved.
5. Re-enable JavaScript.

## 6. Mobile cards and the sheet

1. Set the responsive viewport to 390 × 844. Open Learners.
2. Expect cards instead of a table: each card leads with the learner's first name as a link, the
   remaining columns as a meta line, and no horizontal scrollbar on the page.
3. Expect the toolbar to show the search box on its own row and a "Sort" button on the right. No
   "Filter" button appears, because this table declares no filters.
4. Tap "Sort". A bottom sheet titled "Filter & sort" slides up with radio options for the sortable
   columns and a "Show results" button.
5. Choose "Last Name (descending)" and tap "Show results". Expect the sheet to close, the cards to
   re-order, and the address bar to show `learners-sort=-user__last_name`.
6. Reopen the sheet and tap "Reset". Expect the sort cleared from the URL and the default order.
7. Reopen the sheet and press the device Back button (or the browser Back). Expect the sheet to
   close without leaving the page.
8. Tap the page-2 control at the bottom of the cards. Expect "Page 2 of 2" and the cards for rows
   26–30.
9. Open Cohorts at the same viewport. Expect cards with the cohort name as the title and learner
   count and registered courses in the meta line.
10. Widen the viewport past 768px. Expect the table to reappear and the cards to disappear
    without a reload.

### Mobile with JavaScript off

1. Still at 390 × 844, disable JavaScript and reload Learners.
2. Expect the "Filter & sort" form to render inline below the toolbar. Choose a sort and submit.
   Expect a full page load with the sort applied to the cards.
3. Re-enable JavaScript.

## 7. Things the change could break elsewhere

1. **Old bookmarks.** Load `/educator/ORG/learners?page=2&sort=user__first_name`. Expect the
   table on page 1 in default order with no error: the old names are simply ignored.
2. **Tabs still push their own URL.** On a cohort, click between tabs (if more than one exists)
   and confirm the URL changes to `__tabs/<name>` and Back works as before.
3. **Learner dashboard pagination** uses the same `c-pagination` component through its older
   inputs. Log out, log in as a learner with many courses (or ask the data helper for one), open
   the learner dashboard and page a section. Expect it to work as before.
4. **Admin CSV export** shares the moved formula-escaping code. Go to
   `http://127.0.0.1:$PORT/admin/`, open a model with an export button (Referral tracking →
   Signup attributions), choose Export → CSV. Expect a download that opens in a spreadsheet with
   readable UTF-8 text, and any cell starting with `=`, `+`, `-` or `@` shown as text with a
   leading apostrophe.
5. **Course detail tables.** Open Courses, then a course. Its "Cohort Registrations" and "Direct
   Registrations" tables must page and sort independently (`cohort_registrations-page`,
   `learner_registrations-page`) and render as cards at 390px.
6. **Organisation switcher.** With a second organisation available, switch organisations while a
   table is sorted. Expect the switch to work and the new organisation's list to render with no
   stale `learners-*` parameter carried over from a table that is not on the page.
7. **Create Cohort refresh.** On the Cohorts list, create a cohort through "Create Cohort" with
   "Save and add another". Expect the list to refresh in place and stay on the table's current
   sort.
