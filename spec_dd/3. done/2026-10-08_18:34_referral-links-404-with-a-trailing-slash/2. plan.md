Source: `idea.md` in this directory (the spec stage was skipped, so the idea is the spec).

Code snippets below are shapes, not finished files: they omit imports and the implementer adds
them, with full type hints on every function and no `Any`. Comments and docstrings in the

  ending at the code. `CODE_PATTERN` comes from `freedom_ls/referral_tracking/codes.py`.
- `freedom_ls/referral_tracking/views.py`: `follow_referral_code` records the hit and builds the

  `RemoveSlashMiddleware`. Its class shape (`__init__(self, get_response)` plus `__call__`) is
  the one to copy.
- `django.middleware.common.CommonMiddleware`: `should_redirect_with_slash` is the rule being
  mirrored, and `django.urls.is_valid_path` is the helper it uses. The new middleware uses the
  same one.
- `config/settings_base.py`: `MIDDLEWARE`, where `CommonMiddleware` sits fifth. The dev settings
  spread this list, so one entry here reaches tests and the dev server alike.
- `freedom_ls/base/tests/error_pages_urls.py`: the precedent for a standalone test URLconf
  beside the tests, selected with `override_settings(ROOT_URLCONF=...)`. The middleware tests
  follow it so `base` tests never import another app's routes.
- Anonymous GETs pass through the whole middleware stack without a query, and the test URLconf
  below supplies its own bare `handler404`, so the middleware tests need neither `django_db`
  nor `mock_site_context`. The referral tests keep both, as they do today.

## Slice 1: the referral routes answer the slashed form directly

**Behaviour.** `/go/farm/`, `/GO/FARM/`, `/d/farm/` and `/D/FARM/` behave exactly like their
slashless spellings: same view, same door, one hit recorded, same redirect target, query string
preserved, and a single hop. `reverse()` still gives the slashless URL.

**Change `freedom_ls/referral_tracking/urls.py`.** Append `/?` before the end anchor on both
patterns:

```python
re_path(
    rf"^[gG][oO]/(?P<code>{CODE_PATTERN.pattern})/?$",
    follow_referral_code,
    {"door": Door.GO},
    name="follow_go",
),
re_path(
    rf"^[dD]/(?P<code>{CODE_PATTERN.pattern})/?$",
    follow_referral_code,
    {"door": Door.D},
    name="follow_d",
),
```

Extend the module docstring with one sentence on why the slash is optional and answered in the
route instead of redirected:

```
The trailing slash is optional and served in place, not redirected: links get
typed, pasted and autocompleted with one, and a 301 to the slashless form
would add a hop to a response that is already `noindex` and `no-store`.
```

**Tests, in `freedom_ls/referral_tracking/tests/test_views.py`.** The first three groups go
red before the route change and green after it. The guards in the last group are green
throughout and exist so a later edit cannot undo the behaviour.

Red first:

- `_spellings(code)` returns eight entries, annotated `tuple[str, ...]`: the four existing
  spellings, then each with a trailing slash. The three tests that loop over it become
  parametrised over `_spellings("mrbeast")`, one case per spelling, and the loops go:
  - `test_every_spelling_redirects_to_the_same_target` (renamed from
    `test_all_four_url_spellings_redirect_to_the_same_target`): the response's `url` splits to
    path `/courses/` and query `ref=mrbeast`.
  - `test_each_spelling_records_a_hit`: exactly one `ReferralCodeHit` for the code.
  - `test_each_spelling_records_its_own_door`: parametrised over `(url, door)` pairs; the one hit
    carries that door.
- `test_the_response_has_no_trailing_slash_redirect_hop` becomes parametrised over four URLs:
  `reverse("referral_tracking:follow_go", kwargs={"code": "mrbeast"})` and the same for
  `follow_d`, each with and without `+ "/"`. Each asserts `len(response.redirect_chain) == 1`
  under `follow=True`.
- `test_the_slashed_form_keeps_the_query_string`: parametrised over the two reversed URLs with
  `"/?x=9"` appended; the redirect's query, per `urlsplit`, is the literal `x=9&ref=mrbeast`.

Guards:

- `test_reverse_gives_the_slashless_url`: parametrised over `("follow_go", "/go/mrbeast")` and
  `("follow_d", "/d/mrbeast")`; `reverse(f"referral_tracking:{name}", kwargs={"code":
  "mrbeast"})` equals the literal.
- `test_referral_path_ending_in_double_slash_returns_404`: the reversed `follow_go` URL plus
  `"//"` answers 404.
- `test_referral_path_with_extra_segment_returns_404`: the reversed URL plus `"/extra"` answers
  404.

## Slice 2: every other route survives a stray trailing slash

**Behaviour.** A request, of any method, to `/robots.txt/`, `/sitemap.xml/` or any other
slashless route with a slash added answers a 301 to the slashless form, query string kept. Any
method is redirected because `CommonMiddleware` does the same in the other direction. A 404
raised by a view whose route did match stays a 404. `/`, a path ending in `//`, and a path whose
slashless form does not resolve either are untouched.

**Add `RemoveSlashMiddleware` to `freedom_ls/base/middleware.py`.** Extend the module
docstring with a paragraph naming it, then:

```python
class RemoveSlashMiddleware:
    """Answer a 404 for a slashed path with a 301 to its slashless form.

    `CommonMiddleware` only ever appends a slash, so a route with none
    (`/robots.txt`, `/sitemap.xml`, the learner form routes) 404s as soon as
    a browser, a chat app or a hand-typed link adds one. This is the same
    rule in the other direction. It fires only on a 404 whose path does not
    resolve but whose slashless form does, so it never turns a view's own
    404 into a redirect. It strips exactly one slash: a path ending in `//`
    is not a slip anyone makes, and redirecting it would hide a bad link.
    """

    def __init__(
        self,
        get_response: Callable[[HttpRequest], HttpResponse | StreamingHttpResponse],
    ) -> None:
        self.get_response = get_response

    def __call__(self, request: HttpRequest) -> HttpResponse | StreamingHttpResponse:
        response = self.get_response(request)
        if response.status_code != 404 or not self.should_redirect_without_slash(request):
            return response
        # `get_full_path` has already escaped the path and the query, so only
        # the slash goes.
        path, separator, query = request.get_full_path().partition("?")
        return HttpResponsePermanentRedirect(f"{path[:-1]}{separator}{query}")

    @staticmethod
    def should_redirect_without_slash(request: HttpRequest) -> bool:
        path = request.path_info
        if not path.endswith("/") or path.endswith("//"):
            return False
        urlconf = getattr(request, "urlconf", None)
        return not is_valid_path(path, urlconf) and bool(is_valid_path(path[:-1], urlconf))
```

Imports: `HttpResponsePermanentRedirect` from `django.http`, `is_valid_path` from
`django.urls`. The root path `/` needs no guard of its own: it resolves, so the first
`is_valid_path` call already answers it. A path cannot come out of this starting with `//`,
because the resolver never matches a path whose first segment is empty, so no leading-slash
escape is needed.

**Register it in `config/settings_base.py`.** Insert
`"freedom_ls.base.middleware.RemoveSlashMiddleware"` directly after
`"django.middleware.common.CommonMiddleware"`, with a comment:

```python
# Directly after CommonMiddleware: the reverse of its APPEND_SLASH, so
# /robots.txt/ redirects to /robots.txt instead of 404ing.
```

**Test URLconf, `freedom_ls/base/tests/remove_slash_urls.py`.** A standalone module in the
shape of `error_pages_urls.py`, holding only what the tests need:

```python
"""Root URL configuration for the RemoveSlashMiddleware tests.

Standalone, like `error_pages_urls.py`, so these tests reach no other app's
routes and the module imports in a downstream install with no `config`.

`handler404` answers with a bare response: the tests read the status and the
`Location` header, and rendering the site's 404 page would drag the site
context and the database into tests about URL routing.
"""


def _ok(request: HttpRequest) -> HttpResponse:
    return HttpResponse("ok")


def _not_found(request: HttpRequest) -> HttpResponse:
    raise Http404


def _bare_404(request: HttpRequest, exception: Exception) -> HttpResponse:
    return HttpResponseNotFound("not found")


handler404 = _bare_404

urlpatterns = [
    path("", _ok, name="root"),
    path("plain", _ok, name="plain"),
    path("slashed/", _ok, name="slashed"),
    path("missing/", _not_found, name="missing"),
]
```

**Tests, `freedom_ls/base/tests/test_middleware.py`.** Written in the two groups below, each
group red then green. Every test uses
`override_settings(ROOT_URLCONF="freedom_ls.base.tests.remove_slash_urls")`, drives
`Client()` through the real `MIDDLEWARE` stack, builds URLs from `reverse()` plus or minus a
slash, and asserts the status code and the `Location` header as literals. Only `/nowhere/` and
`reverse("plain") + "//"` are typed as strings, because nothing can reverse them. No test takes
`django_db` or `mock_site_context`.

Core, with the class and the settings entry landing together:

- `test_slashed_path_whose_slashless_form_resolves_redirects_to_it`: GET `reverse("plain") +
  "/"` answers 301 with `Location` `/plain`.
- `test_view_404_on_a_matched_route_stays_404`: GET `reverse("missing")` answers 404.
- `test_path_that_resolves_neither_way_stays_404`: GET `/nowhere/` answers 404.

Edges:

- `test_redirect_keeps_the_query_string`: GET `reverse("plain") + "/?a=1&b=2"` answers 301 to
  `/plain?a=1&b=2`.
- `test_slashed_path_ending_in_double_slash_stays_404`: GET `reverse("plain") + "//"` answers
  404.
- `test_root_path_requested_returns_200`: GET `reverse("root")` answers 200.
- `test_slashless_request_to_a_slashed_route_still_appends_a_slash`: GET
  `reverse("slashed")[:-1]` answers 301 to `/slashed/`.
- `test_post_to_a_slashed_path_redirects_like_a_get`: POST to `reverse("plain") + "/"` answers
  301 to `/plain`.

One test proves the real `config.urls` stack and goes in
`freedom_ls/referral_tracking/tests/test_views.py`, beside the other 404 tests, so `base` keeps
to its own routes:

- `test_unknown_code_with_a_trailing_slash_stays_404`: GET the reversed `follow_go` URL for
  `doesnotexist` plus `"/"` answers 404, not 301, because the route matched and the view raised.
