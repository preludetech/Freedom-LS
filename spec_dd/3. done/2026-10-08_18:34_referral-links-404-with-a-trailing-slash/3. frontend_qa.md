# Frontend QA: referral links with a trailing slash

Referral links now work with or without a trailing slash, and every other URL on the site
forgives one stray trailing slash by redirecting to the form that resolves. This run follows a
referral code through all of its spellings, confirms the hit is counted once per visit, and then
checks the general redirect plus the cases it must leave alone.

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever
this document writes `<PORT>`. Shell variables do not survive between tool calls.

---

## §0 Setup

### 0.1 Server

1. `.claude/ds/scripts/find_available_port.sh`. Note the number and use it literally from here on.
2. Start `uv run python manage.py runserver <PORT>` backgrounded, as its own call.
3. Open `http://127.0.0.1:<PORT>/` and confirm `#debug-branch-badge` names the
   `referral-links-404-with-a-trailing-slash` branch. If it names another branch, another server
   holds the port; go back to step 1.

### 0.2 Seed data

Missing data is created through the `fls-dev:qa-data-helper` agent, never by hand, except the
referral code, which this run creates through the admin because the admin form is part of what
is being checked.

1. **Demo content loaded.** `uv run python manage.py content_save demo_content DemoDev`, so
   `/courses/` lists at least one course.
2. **Superuser:** `demodev@email.com` from `.claude/fls-dev/config.md`.
3. **A referral code.** Sign in as the superuser, open
   `http://127.0.0.1:<PORT>/admin/freedom_ls_referral_tracking/referralcode/add/`, enter code
   `farm`, label `Farm poster`, destination `/courses/`, and save. On the change form note the
   two URLs it shows: they must read `/go/farm` and `/d/FARM` with no trailing slash. Note the
   hit count (0). Sign out.

---

## §1 The referral code in every spelling

Use a fresh private window (no session) for each visit so the attribution cookie from one visit
does not change the next. Watch the Network panel with "Preserve log" on.

### 1.1 The slashless spellings still work

1. Visit `http://127.0.0.1:<PORT>/go/farm`. Expect to land on `/courses/?ref=farm` after exactly
   one 302. No 301 appears in the log.
2. Repeat for `/GO/FARM`, `/d/farm` and `/D/FARM`. Same landing, one hop each.

### 1.2 The slashed spellings behave the same

1. Visit `http://127.0.0.1:<PORT>/go/farm/`. Expect the same landing, `/courses/?ref=farm`, after
   exactly one 302. There must be no 301 to `/go/farm` first.
2. Repeat for `/GO/FARM/`, `/d/farm/` and `/D/FARM/`. Same landing, one hop each.
3. Visit `/go/farm/?utm_source=poster`. Expect to land on `/courses/` with both `utm_source=poster`
   and `ref=farm` in the query string.

### 1.3 The hits were counted

1. Sign in as the superuser and open the referral code's change form. The hit count is 9 (four
   slashless visits, four slashed visits, one with a query string). The changelist's "last
   followed" column shows a time from the last minute.
2. The admin change form still shows the two copyable URLs without a trailing slash.

### 1.4 Spellings that must still fail

1. Visit `/go/farm//`. Expect the site's 404 page. No redirect to `/go/farm/` or `/go/farm`.
2. Visit `/go/farm/extra`. Expect the 404 page.
3. Visit `/go/nope/`. Expect the 404 page: an unknown code with a slash is not rescued.
4. Reopen the referral code's change form: the hit count is still 9.

## §2 Every other URL

### 2.1 A stray slash on a slashless route redirects

1. Visit `http://127.0.0.1:<PORT>/robots.txt/`. Expect a 301 to `/robots.txt` and the robots text
   rendered.
2. Visit `/sitemap.xml/`. Expect a 301 to `/sitemap.xml` and the XML rendered.
3. Visit `/robots.txt/?v=2`. Expect the 301's target to be `/robots.txt?v=2`.

### 2.2 The missing-slash direction is unchanged

1. Visit `/courses`. Expect a 301 to `/courses/` and the course list, as before.
2. Visit `/educator`. Expect a 301 to `/educator/` and then whatever that page did before
   (a sign-in redirect when signed out).

### 2.3 Real 404s stay 404s

1. Visit `/courses/no-such-course/`. Expect the 404 page, not a redirect to
   `/courses/no-such-course`.
2. Visit `/nowhere/`. Expect the 404 page.
3. Visit `/robots.txt//`. Expect the 404 page.

### 2.4 Normal browsing is unaffected

1. Sign in as `demodev@email.com`, open `/courses/`, open a course, step through two items with
   the next button, and open one that contains a form or quiz and start it. Every page loads with
   no unexpected redirect in the Network log.
2. Sign out and sign back in through `/accounts/login/`. The flow works as before.
3. Open `/admin/` and the referral code changelist. Both load normally.
