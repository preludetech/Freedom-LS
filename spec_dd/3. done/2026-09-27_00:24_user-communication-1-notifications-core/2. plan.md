## Slice 1: a course registration stores a notification

**Behaviour.** Creating an active `LearnerCourseRegistration` by any path (self-registration,
admin, factory) writes one `Notification` for the learner's user, on the registration's site, with
the course as target and the title in `data`. `raise_notification` validates in the caller and
writes after commit. A failure in the write never changes the registration response. No UI yet.

**Files.**

- `freedom_ls/base/notification_categories.py`

  ```python
  @dataclass(frozen=True)
  class NotificationCategory:
      key: str
      label: StrPromise
      icon: str
      message: StrPromise
      url_builder: str | None

  FLS_NOTIFICATION_CATEGORIES = [
      NotificationCategory(key="course.registered", label=_("Course registration"), icon="course",
          message=_("You're registered for %(course_title)s"),
          url_builder="freedom_ls.learner_interface.notification_urls.course_home_url"),

  ```

  in the dev group and the import never runs at runtime. The module imports nothing from any app.
- `freedom_ls/learner_interface/notification_urls.py`: `course_home_url(course: Course) -> str`
  returning `reverse("learner_interface:course_home", kwargs={"course_slug": course.slug})`.
- `freedom_ls/comms/__init__.py`, `apps.py` (`name`, `label="freedom_ls_comms"`,
  `verbose_name="Notifications"`, `default_auto_field="django.db.models.BigAutoField"`,
  `ready()` importing `checks`), `config.py` (`CommsConfig(AppSettings)` with the three declared
  settings and a module-level `config = CommsConfig()`), `checks.py` (E001 duplicate category
  keys; E002 is added in slice 7), `models.py`, `notify.py`, `factories.py`,
  `migrations/0001_initial.py` (from `makemigrations`), `tests/__init__.py`.
- `freedom_ls/comms/models.py` holds the category lookup as well as the model, so `notify.py`
  and the model both import it from one place with no cycle:

  ```python
  def get_notification_category(key: str) -> NotificationCategory:
      for category in config.NOTIFICATION_CATEGORIES:
          if category.key == key: return category
      raise ValueError(f"Unknown notification category: {key!r}")

  def message_placeholders(message: StrPromise) -> set[str]:
      return set(re.findall(r"%\((\w+)\)s", str(message)))

  class NotificationQuerySet(models.QuerySet):
      def for_user(self, user): return self.filter(user=user)
      def unread(self): return self.filter(read_at__isnull=True)
      def unseen(self): return self.unread().filter(seen_at__isnull=True)

  class NotificationManager(SiteAwareManager.from_queryset(NotificationQuerySet)):
      def get_queryset(self):
          keys = [c.key for c in config.NOTIFICATION_CATEGORIES]
          return super().get_queryset().filter(category__in=keys)

  class Notification(SiteAwareModel):
      user, category, content_type, object_id, target, data, created_at, seen_at, read_at  # per spec
      objects = NotificationManager()
      class Meta:
          ordering = ("-created_at", "-id")
          indexes = [
              models.Index(fields=["user", "site", "-created_at"]),
              models.Index(fields=["user", "site"], name="comms_notification_unseen_idx",
                           condition=Q(read_at__isnull=True, seen_at__isnull=True)),
          ]
  ```

  Only the partial index needs a name (Django requires one with `condition`); the list index
  stays unnamed like the rest of the tree. The unregistered-category filter sits in
  `get_queryset`, so every surface and the badge drop those rows without remembering to.
  `_base_manager` stays unfiltered for the task in slice 7. `message`, `label`, `icon` and `url`
  arrive in slice 3 with the first surface that renders them.
- `freedom_ls/comms/notify.py`

  ```python
  def raise_notification(*, user, category, target, site_id: int, data) -> None:
      notification_category = get_notification_category(category)
      missing = message_placeholders(notification_category.message) - data.keys()
      if missing: raise ValueError(f"Notification data is missing {sorted(missing)} for {category!r}")

      def write() -> None:
          Notification.objects.create(user=user, category=category, target=target,
                                      site_id=site_id, data=data)
      transaction.on_commit(write, robust=True)
  ```

  Delivery enqueueing is added to `write` in slice 7.

## Slice 3: the notification centre lists and opens notifications

**Behaviour.** A signed-in user visits `/notifications/` and sees their notifications for this
site under day headings, 20 per page, newest first. Visiting marks unseen rows seen. Each row shows
the category icon, the message (linked when the target resolves), the label and a relative time.
Following a link goes through `notification_open`, which marks the row read. Anonymous HTMX
requests get 204 + `HX-Redirect`. Only the All view exists yet.

**Files.**

- `freedom_ls/comms/models.py`: add the rendering helpers

  ```python
  @property
  def message(self) -> str: return str(get_notification_category(self.category).message) % self.data
  @property
  def label(self) -> str: return str(get_notification_category(self.category).label)
  @property
  def icon(self) -> str: return get_notification_category(self.category).icon
  @property
  def url(self) -> str | None:
      builder = get_notification_category(self.category).url_builder
      if builder is None or self.target is None: return None
      return import_string(builder)(self.target)
  ```

- `freedom_ls/comms/relative_time.py`: `relative_time(value: datetime, now: datetime) -> str`
  ("Just now" under a minute, "N min ago" under an hour, "N hours ago" same local day,
  "Yesterday, 16:20", "21 Sep", "21 Sep 2025" outside the current year) and
  `day_heading(day: date, today: date) -> str` ("Today", "Yesterday", "Monday 21 September",
  "Monday 21 September 2025"). Both work in the active timezone via `timezone.localtime`.
- `freedom_ls/comms/templatetags/__init__.py`, `comms_tags.py`: filter `relative_time` (calls
  `relative_time(value, timezone.now())`). The `badge_count` filter and the inclusion tag
  `notification_bell` land in slice 4.
- `freedom_ls/comms/views.py`

  ```python
  def login_required_htmx(view):
      @wraps(view)
      def wrapper(request, *args, **kwargs):
          if not request.user.is_authenticated:
              return redirect_to_auth(request, next_url=reverse("comms:notification_list"))
          return view(request, *args, **kwargs)
      return wrapper

  def _notifications_for(request) -> NotificationQuerySet:
      return Notification.objects.for_user(request.user).prefetch_related("target")

  def _mark_seen(request) -> None:
      _notifications_for(request).unseen().update(seen_at=timezone.now())

  def _stamp_read(queryset: NotificationQuerySet) -> None:
      now = timezone.now()
      queryset.update(read_at=now, seen_at=Coalesce("seen_at", Value(now)))

  def _day_groups(page) -> list[tuple[str, list[Notification]]]:
      today = timezone.localdate()
      return [(day_heading(day, today), list(rows)) for day, rows in
              groupby(page.object_list, key=lambda n: timezone.localtime(n.created_at).date())]

  def _list_context(request) -> dict:
      page = Paginator(_notifications_for(request), 20).get_page(request.GET.get("page"))
      return {"page_obj": page, "day_groups": _day_groups(page),
              "base_url": reverse("comms:notification_list"), "page_title": "Notifications"}

  @login_required_htmx
  def notification_list(request):
      _mark_seen(request)
      is_htmx = request.headers.get("HX-Request") == "true"
      template = "comms/notification_list.html#list" if is_htmx else "comms/notification_list.html"
      return render(request, template, _list_context(request))

  @login_required_htmx
  def notification_open(request, pk):
      notification = get_object_or_404(_notifications_for(request), pk=pk)
      _stamp_read(_notifications_for(request).filter(pk=pk, read_at__isnull=True))
      return redirect(notification.url or reverse("comms:notification_list"))
  ```

  `prefetch_related("target")` on a GFK batches one query per content type, so the count stays
  flat as rows grow; it lives in `_notifications_for` so every list, panel and fragment inherits
  it. `_stamp_read` is the one place read implies seen. The list container id
  `notification-list` is a template constant, spelled in the template and in `c-pagination`'s
  `table_id`, not a context variable.
- `freedom_ls/comms/urls.py` (`app_name = "comms"`): `notification_list` at `""`,
  `notification_open` at `<uuid:pk>/open/`. `config/urls.py`:
  `path("notifications/", include("freedom_ls.comms.urls"))`.
- `freedom_ls/comms/templates/comms/notification_list.html`: extends `_base.html`, `head_title`
  "Notifications", `<c-page width="narrow">`, `<h1>Notifications</h1>`, then a
  `{% partialdef list %}` block wrapping `<div id="notification-list">` with the day groups
  (`<section aria-labelledby>` + `<h2>` per day, `<ul>` of rows) and
  `<c-pagination :page_obj="page_obj" :base_url="base_url" table_id="notification-list" />`.
  The toolbar, states and filter arrive in slice 5.
- `freedom_ls/comms/templates/comms/partials/notification_row.html`: one `<li>` used by the
  centre now and the panel later. Icon `<c-icon :name="notification.icon">`; the message as
  `<a href="{% url 'comms:notification_open' notification.pk %}">` when `notification.url`, else
  a `<span>`; visually hidden "Unread." before unread text; the "Unread" marker as a
  token-coloured dot (`<span class="size-2 rounded-full bg-primary" aria-hidden="true">`)
  followed by the word "Unread"; `font-semibold` for unread; meta line
  `{{ notification.label }} · <time datetime="{{ created_at|date:'c' }}" title="{{ created_at }}">{{ created_at|relative_time }}</time>`.
  Colours: `text-on-surface`, `text-muted`, `bg-surface`, `border-border`, `hover:bg-surface-2`,
  focus ring via `focus-visible:ring-2 focus-visible:ring-[var(--color-focus-ring)]`.

badge refreshes from `notification_badge` every `NOTIFICATION_BADGE_POLL_SECONDS` while visible
and at once on becoming visible, without replacing the button. Visiting the centre zeroes it in
the same response. The bell does not open anything yet.

  `notification_badge` (GET, guarded) rendering `comms/partials/notification_badge.html` with

- `freedom_ls/comms/static/comms/js/alpine-components.js`

  ```js
  Alpine.data("notificationBell", () => ({
      open: false,
      loading: false,
      failed: false,
      _timer: null,
      _onVisibility: null,
      init() {
          const seconds = Number(this.$el.dataset.pollSeconds);
          this._onVisibility = () => document.visibilityState === "visible"
              ? this.startPolling(seconds, true) : this.stopPolling();
          document.addEventListener("visibilitychange", this._onVisibility);

      startPolling(seconds, refreshNow) { this.stopPolling(); if (refreshNow) this.refreshBadge();
          this._timer = setInterval(() => this.refreshBadge(), seconds * 1000); },
      stopPolling() { clearInterval(this._timer); },
      refreshBadge() { this.$refs.badge.dispatchEvent(new CustomEvent("refresh")); },
      destroy() { this.stopPolling(); document.removeEventListener("visibilitychange", this._onVisibility); },
  }));
  ```

## Slice 7: delivery backends run as tasks

**Behaviour.** Each path in `NOTIFICATION_DELIVERY_BACKENDS` gets its own task per stored
notification. The empty default enqueues nothing. A bad path fails the system check. Nothing
visible changes for FLS itself; this is the seam spec 2 fills.

**Files.**

- `freedom_ls/comms/delivery.py`: `class NotificationDeliveryBackend` with
  `def deliver(self, notification: Notification) -> None: raise NotImplementedError`, a plain
  base class like `CourseAccessBackend`.
- `freedom_ls/comms/tasks.py`

  ```python
  @task()
  def deliver_notification(backend_path: str, notification_id: str, site_id: int) -> None:
      notification = (Notification._base_manager.select_related("user")
                      .filter(site_id=site_id).get(pk=notification_id))
      import_string(backend_path)().deliver(notification)
  ```

- `freedom_ls/comms/notify.py` `write`: after `create`, for each path in
  `config.NOTIFICATION_DELIVERY_BACKENDS`,
  `default_task_backend.enqueue(deliver_notification, args=[path, str(notification.pk), site_id], kwargs={})`.
- `freedom_ls/comms/checks.py`: E002 for a backend path `import_string` cannot load (catch
  `ImportError`), reported as an `Error`, never raised.
