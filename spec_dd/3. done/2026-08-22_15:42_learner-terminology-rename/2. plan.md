# Implementation Plan: `student` → `learner` terminology rename

Spec: `1. spec.md` in this directory. Read it first — this plan does not restate the *why*, only the *how*.

---

## 0. Ground rules for this plan

**This is a pure rename.** No new features, no behaviour changes, no refactors of opportunity. If a batch
tempts you to fix something you noticed, stop and write it down instead — it becomes its own spec (spec §15).

**TDD applies differently here.** There is nothing new to test-drive. The existing suite *is* the harness:
it must be green at every checkpoint listed below, and every gate in §9 must pass. There are exactly **two**
places where a test's meaning changes rather than just its spelling, and those are called out in Batch 4 —
edit the test first, watch it fail for the right reason, then make the source change.

**Never use a case-insensitive replace.** Spec §3.5 settles the technique: three separate case-sensitive
substring passes (`Student`→`Learner`, `student`→`learner`, `STUDENT`→`LEARNER`), scoped to an explicit file
list, never `\b` word-boundary regex and never `sed -i 's/student/learner/gi'`.

**Commit via `uv run git commit`** (per `CLAUDE.md`) so the pre-commit hooks run.

**Ruff import sorting shifts.** `known-first-party = ["freedom_ls"]` means a renamed import can change sort
position. Run `uv run ruff check --fix .` then `uv run ruff format .` at the end of every batch that touches
Python imports, before committing.

## 3. The sweep technique

Every batch below that says "sweep" means exactly this, and nothing looser.

```bash
# 1. Build an explicit file list for THIS batch. Never sweep the whole repo blind.
#    -z emits NUL-separated paths; -I skips binary files.
# 2. Three case-sensitive passes. Order does not matter (every identifier is a
#    prefix composition), but the three passes must stay separate.
git grep -lIz 'student\|Student\|STUDENT' -- <paths for this batch> \
  | xargs -0 -r sed -i \
      -e 's/Student/Learner/g' \
      -e 's/student/learner/g' \
      -e 's/STUDENT/LEARNER/g'

# 3. Residual check for THIS batch's paths.
git grep -nI -i 'student' -- <paths for this batch>
```

> **`-z` / `-0` is load-bearing, not defensive style.** Plain `xargs` splits on *all* whitespace, so a path
> containing a space is passed as two nonexistent filenames and **silently never edited** while `sed` errors on
> both fragments. This repo has such a path in scope: `docs/how tos/theme-fls.md`, which Batch 8c must edit.
> `-r` suppresses a confusing `sed: no input files` when a batch's match set is empty.

**Excluded by construction** — never in any `FILES` list (spec §3.6, plus §2 items N and P above):

- everything under `spec_dd/` (all four stages: `0. drafts/`, `1. next/`, `2. in progress/`, `3. done/`)
- `.claude/skills/brand-guidelines/SKILL.md:177`
- `cmi.core.student_id` wherever it appears as a historical quote
- webhook payload **keys** (`user_id`, `user_email`) — already correct
- `freedom_ls/role_based_permissions/registry.py:66-85` and `:82-85` — hand-edit per item N
- `roles.py:13`'s TODO — deleted only once the condition is verified met (Batch 4)

**Before you start, and again at the end**, check for accidental substring collisions:

```bash
git grep -nI -iE 'understud|studentesse' -- . ':!spec_dd'   # expect: nothing, both times
```

## 10. Load-bearing assumption

**No downstream consumer has a persistent, migrated database.** `bloom_ls` and `first_class_ls` — the two
repos auto-notified by `.github/workflows/notify-downstream.yml` — are dev/CI only, user-confirmed. FLS's own
dev database is rebuilt from scratch. **Everything in Batch 4 depends on this.** If it stops holding before
this ships, §3.1's fresh-initial strategy flips to in-place migration rewrite plus a manual cutover script,
§3.3's no-shims decision needs revisiting, and this plan must be rewritten.
