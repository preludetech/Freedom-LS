# Frontend QA: `student` → `learner` terminology rename

## What this is testing, and why a browser is needed at all

The change is a pure rename with **no intended behaviour change**, so every test below is a
regression test: the page must look and behave *exactly* as it did before. What makes browser QA
non-optional is that four whole classes of breakage in this change are invisible to `pytest`,
`manage.py check` and `mypy`:

1. **Django admin string lookups.** `list_select_related`, `list_filter`, `search_fields` and
   `autocomplete_fields` are resolved at *query* time, not import time. A missed rename returns
   wrong or empty results rather than raising. Workflow 3 exists entirely for this.
2. **Template and static paths.** A stale `{% static 'student_interface/js/...' %}` yields a 404 and
   a dead Alpine component — the page still renders, just without its interactivity.
3. **HTMX panel URLs.** Educator panel keys become URL segments (`…/__panels/learners`). A
   half-renamed key gives an empty panel, not an exception.
4. **Render-time dict keys.** `learner_selected` is built at render time and consumed by the
   template. If the model and the template disagree, the incorrect-answer list renders **empty**
   and nothing complains.

Treat "the word 'student' is visible anywhere in the UI" as a bug in its own right, on every page
you visit, whether or not the step asks you to look for it.

## Setup

### 1. Rebuild the database

The app labels changed, so the old tables are gone and `django_content_type` rows are stale. Do a
clean rebuild — do **not** QA against a database carried over from before the rename.

```bash
.claude/fls-dev/scripts/dev_db_delete.sh
.claude/fls-dev/scripts/dev_db_init.sh
uv run python manage.py migrate
uv run python manage.py create_demo_data
uv run python manage.py content_save ./demo_content DemoDev
```

### 2. Kill any server left running from before the rename

`ContentType.objects.get_for_model()` caches per process. A `runserver` that was alive across the
label change will serve stale content types and produce confusing, wrong results.

```bash
.claude/ds/scripts/kill_runserver.sh
```

### 3. Start a server on a free port

```bash
PORT=$(.claude/ds/scripts/find_available_port.sh)
uv run python manage.py runserver $PORT
```

Base URL is `http://127.0.0.1:$PORT` — substitute the literal port number into every URL below.

> **Port note.** `config/settings_dev.py:107` sets `FORCE_SITE_NAME = "DemoDev"`, so
> `get_cached_site()` returns the DemoDev site for **every** request regardless of host or port. Any
> port serves DemoDev data; you do not need port 8000 and you do not need a hosts-file entry.
> Separately, the header reads **"FirstClass"** because that is `HEADER_TITLE` branding in
> `settings_dev.py` — it is not a different site. Do not chase it.

This workflow proves the move was complete. **Learner-facing URL *paths* are unchanged by this
work** — only the internal namespace moved — so any 404 here is a real bug, not an expected
relocation.

## Reporting

Any of the following is a **fail**, not a nitpick:

- The word "student" visible in rendered UI, page source, a URL, or a console message.
- An admin changelist column that is blank, or an admin search that returns nothing for a record you
  can see unfiltered.
- A panel or list that renders its frame but no rows.
- A 404 on a static asset, or an Alpine component that no longer responds to interaction.
- Any visual or behavioural difference from before the rename — this change was supposed to have
  none.
