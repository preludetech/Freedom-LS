# Shared test infrastructure

Spec 4 of 15 in the Test organisation and hygiene effort (`spec_dd/1. next/roadmap.md`). Source:
`idea.md`.

## Purpose

Every app's test suite loads `freedom_ls/conftest.py`, so its fixes land in one PR before specs
5–13 run in parallel against it. This spec brings it and the shared `SiteFactory` up to spec 1's
two rules and conftest layering standard.

## Scope

In:

- `SiteFactory` moved from `freedom_ls/accounts/factories.py` to `freedom_ls/tests/factories.py`,
  with every importer updated.
- The Playwright re-export in `freedom_ls/conftest.py` made explicit.
- `course_with_scored_quiz` and `sit_quiz` moved out of `freedom_ls/conftest.py` into
  `learner_progress`.
- Collection guards for `course_interest` and `course_recommendations`.
- The dead `freedom_ls/student_interface/`, `student_management/` and `student_progress/`
  directories.
- The regenerated `test_organisation/import_contracts.toml` and `docs/app_structure.md`.

Out:

- Per-app conftest, fixture and factory cleanup, including plain helper functions in apps' own
  `tests/conftest.py`. Each app's own spec among 5–15 owns that.
- `reverse_url` living in the root conftest and being imported from it by hand.
- Cross-app consumers of `course_interest`/`course_recommendations` in other apps' tests (for
  example `educator_interface/tests/test_course_visibility_and_interest.py`).
- Setting the testing standards (spec 1) and the baseline files' format (spec 3).
- Any baseline line other than those this spec's fixes retire.

## Decisions

- **Clean move, no re-export.** `accounts/factories.py` keeps no `SiteFactory` alias. A shim would
  keep the `accounts` edge alive. Downstream projects get the new path from the upgrade notes.
- **Playwright fixtures stay global, imported by name.** Playwright tests live in eleven apps'
  `tests/playwright/` directories. Downstream projects get the fixtures by star-importing
  `freedom_ls.conftest`. A named import keeps both working and stops the wildcard leaking every
  public name in `playwright_fixtures.py` (`pytest`, `User`, `UserFactory`, `expect`, …). Scoping
  the import to eleven per-directory conftests would break downstream Playwright tests.
- **Quiz fixtures go to `learner_progress`.** It is the lowest app that depends on everything they
  build (`content_engine`, `form_engine`, `learner_progress`). `learner_interface` depends on
  `learner_progress` at runtime, so its conftest may import them. A module in `freedom_ls/tests/`
  would hide their app dependencies from the checks.
- **`SiteFactory` lives in `freedom_ls/tests/`.** `Site` is `django.contrib.sites`, not an FLS
  model, and `freedom_ls/tests/` is not an app, so importing the factory adds no app edge. `blog`
  does not depend on `site_aware_models` (`docs/app_structure.md`, `blog` row), so placing it there
  would have made `blog` create its `Site` rows by hand.
- **No hand-edited baseline line changes.** The `SiteFactory` edge is not in
  `test_organisation/import_baseline.txt`. It is covered by the generated `accounts.factories`
  allowance in `import_contracts.toml`. No baseline names a `student_*` path, `freedom_ls/tests/` or
  the root conftest.

## Requirements

### `SiteFactory`

- Move the class (`name`/`domain` declarations, docstring) from `freedom_ls/accounts/factories.py`
  to `freedom_ls/tests/factories.py`. Key `django_get_or_create` on `domain`, the column `Site`
  makes unique, instead of `name`.
- Drop the `Site` import from `accounts/factories.py`. `SiteFactory` is its only user.
- Every reference to `SiteFactory` through `freedom_ls.accounts.factories` moves to
  `freedom_ls.tests.factories`: multi-line imports, function-local imports
  (`webhooks/tests/test_events.py`) and dotted-string references included.
- `freedom_ls/blog/tests/test_views.py` imports `SiteFactory` from the new path like every other
  importer.

### `freedom_ls/conftest.py`

- Replace `from freedom_ls.tests.playwright_fixtures import *  # noqa: F403` and its comment with a
  named import of the four fixtures `playwright_fixtures.py` defines, with a comment saying why the
  conftest imports them:

  ```python
  from freedom_ls.tests.playwright_fixtures import (  # noqa: F401
      logged_in_page,
      logged_in_user,
      playwright,
      reset_local_storage,
  )
  ```

- Delete the `course_with_scored_quiz` and `sit_quiz` fixtures.

### Quiz fixtures in `learner_progress`

- New plain module `freedom_ls/learner_progress/tests/quiz_fixtures.py` holds `course_with_scored_quiz`
  and `sit_quiz`. Their signatures, return values and docstrings stay as they are, so no consuming
  test changes. Their factory and model imports move to module level.
- New `freedom_ls/learner_progress/tests/conftest.py` imports both by name.
- `freedom_ls/learner_interface/tests/conftest.py` imports both by name.

### Collection guards

- New `freedom_ls/course_interest/tests/conftest.py` and
  `freedom_ls/course_recommendations/tests/conftest.py`:

  ```python
  """Collection guard for the course_interest tests."""

  from freedom_ls.tests.app_guards import ignore_tests_unless_installed

  collect_ignore_glob = ignore_tests_unless_installed("freedom_ls.course_interest")
  ```

  Neither file imports from its optional app.
- `ignore_tests_unless_installed` in `freedom_ls/tests/app_guards.py` returns the globs for every
  test module under the conftest's directory, subdirectories included. The existing guards (`blog`,
  `hr_attributes`, `registration_rules`, `course_applications`) use it, and the separate guard in
  `blog/tests/demo_content/conftest.py` goes.

### Dead directories

- `freedom_ls/student_interface/`, `freedom_ls/student_management/` and
  `freedom_ls/student_progress/` must not exist.

### Generated dependency files

- Regenerate `test_organisation/import_contracts.toml` and `docs/app_structure.md` with
  `generate_app_map.py` (`/ds:app_map`). The `… -> freedom_ls.accounts.factories` allowance lines
  for files that imported only `SiteFactory` disappear, and so does `accounts` from the "Test-only
  deps" column of apps whose only `accounts` import was `SiteFactory`.

## Testing

No behaviour changes, so the proof is that the existing suite and checks still pass:

- The `full` tier passes, `playwright`-marked tests included.
- `generate_app_map.py --check`, `lint-imports --config test_organisation/import_contracts.toml` and
  `check_test_mirroring.py` pass, with `import_baseline.txt` and `mirroring_baseline.txt` unchanged.
- `pytest --collect-only -q` on `freedom_ls/course_interest/tests` and
  `freedom_ls/course_recommendations/tests` collects every test with the app installed. A manual
  check proves the uninstalled case: a throwaway settings module that filters the app out of
  `INSTALLED_APPS` (as `course_applications/tests/invariants/test_collection_safety.py` does), with
  `--co` run on that app's own `tests/` directory only (`learner_interface/views.py` imports both
  apps at module level), collects nothing and exits 5, with no collection error.
- `pytest --fixtures`
  from `freedom_ls/learner_interface/tests/views/` lists `course_with_scored_quiz` and `sit_quiz`
  defined in `freedom_ls/learner_progress/tests/quiz_fixtures.py`.

## Documentation and downstream

- `claude_plugins/fls-dev/skills/testing/SKILL.md`:
  - "Fixture placement" says the root conftest imports the Playwright fixtures by name, and that
    `course_with_scored_quiz`/`sit_quiz` live in `learner_progress/tests/quiz_fixtures.py`. It
    states the pattern: fixtures shared across apps live in a plain module in the lowest app that
    depends on everything they build, and each consumer's `tests/conftest.py` imports them by name.
  - The `freedom_ls/tests/` paragraph names `SiteFactory`'s home,
    `freedom_ls.tests.factories`.
  - Generic plugins (`ds`, `sdd`) are untouched.
- Upgrade notes for downstream projects (breaking changes):
  - `freedom_ls.accounts.factories.SiteFactory` → `freedom_ls.tests.factories.SiteFactory`. It now
    gets or creates by `domain`, not `name`.
  - `course_with_scored_quiz` and `sit_quiz` are no longer exported by `freedom_ls.conftest`.
    Import them from `freedom_ls.learner_progress.tests.quiz_fixtures`.
  - Names only `playwright_fixtures.py` imported (for example `EmailAddress`, `Page`, `Playwright`,
    `PlaywrightError`, `expect`, `connections`, `User`, `close_db_connections_before_playwright_stops`)
    no longer reach a project that star-imports `freedom_ls.conftest`.
  - `course_interest` and `course_recommendations` tests now skip collection when the app is not
    installed.
- The ideas for specs 13 and 14
  (`spec_dd/1. next/test-organisation-and-hygene-13-learner-interface-part-1/idea.md`, `…-14-…`)
  and the roadmap's "Unknowns resolved inside a spec" row for spec 4 record the Playwright and quiz
  fixture placement. The roadmap's "Ordering and parallelism" note says spec 4 runs before 5–13
  because it edits `freedom_ls/conftest.py` and moves `SiteFactory`, not because it deletes
  baseline lines.

## Success criteria

- `grep -rn "accounts.factories import.*SiteFactory\|accounts.factories.SiteFactory" freedom_ls`
  returns nothing, and no multi-line `accounts.factories` import names `SiteFactory`.
- `freedom_ls/conftest.py` contains no `import *`, `course_with_scored_quiz` or `sit_quiz`.
- `freedom_ls/blog/tests/test_views.py` imports nothing from `site_aware_models` or `accounts`.
- `freedom_ls/course_interest/tests/conftest.py` and `freedom_ls/course_recommendations/tests/conftest.py`
  exist and import nothing from their optional app.
- `ls -d freedom_ls/student_*` finds nothing.
- `git diff main -- test_organisation/import_baseline.txt test_organisation/mirroring_baseline.txt`
  is empty.
