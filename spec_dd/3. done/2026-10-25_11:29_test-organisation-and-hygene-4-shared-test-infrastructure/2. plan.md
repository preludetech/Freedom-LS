# Implementation plan: shared test infrastructure

Source: `1. spec.md` in this directory. `research_codebase.md` beside it holds the codebase facts
the spec rests on.

Code snippets below are shapes, not finished files: they omit imports the implementer adds, with
full type hints on every function and no `Any`. Comments and docstrings inside the snippets are
written to be copied as they are. A line of the form `...  # <note>` is an instruction to the
implementer and is never copied. Nothing else in this document is copied into code.

No behaviour changes. Every slice is a behaviour-preserving move, so there are no new tests to
write first: the proof of each slice is that the existing suite and the Testing section's checks
(`generate_app_map.py --check`, `lint-imports`, `check_test_mirroring.py`) still pass. Each slice is committed on its own with `uv run git commit`, so the pre-commit hooks
(`ruff`, `mypy`, `app-map-fresh`, `lint-imports`, `test-mirroring`) gate every commit. Before
running pytest, name the tier the way `claude_plugins/django-stack/resources/test_tiers.md` says:
`.claude/ds/scripts/select_tests.sh --working-tree` prints the tier and the command, and every
partial run (`--co`, `--fixtures`, a single file) carries `--no-cov`. `**/conftest.py` and
`**/factories.py` are escalation globs in `select_tests.py`, so slices 1 to 4 each print
`tier: full`. Run `targeted` and `full` tiers in the background and wait for them; no polling, no
`timeout` wrapper.

## Slice 1: Collection guards for `course_interest` and `course_recommendations`

**Behaviour.** Both optional apps' tests skip collection when the app is not installed, and
collect in full when it is.

Create `freedom_ls/course_interest/tests/conftest.py`:

```python
"""Collection guard for the course_interest tests."""

from freedom_ls.tests.app_guards import app_not_installed

collect_ignore_glob: list[str] = []
if app_not_installed("freedom_ls.course_interest"):
    collect_ignore_glob = ["test_*.py"]
```

Create `freedom_ls/course_recommendations/tests/conftest.py` the same way, with
`course_recommendations` in the docstring and `"freedom_ls.course_recommendations"` in the call.
Neither file imports anything from its app. Both `tests/` directories are flat (confirmed: four and
two `test_*.py` files, no subdirectory), so the glob covers every test.

**Proof.**

- Before and after, `uv run pytest --collect-only -q --no-cov freedom_ls/course_interest/tests
  freedom_ls/course_recommendations/tests` reports the same number of tests.
- The uninstalled case, run once per app with a throwaway settings module in `.sdd-work/`:

  ```bash
  mkdir -p .sdd-work
  printf 'from config.settings_dev import *\nINSTALLED_APPS = [a for a in INSTALLED_APPS if a != "freedom_ls.course_interest"]\n' > .sdd-work/settings_without_course_interest.py
  PYTHONDONTWRITEBYTECODE=1 DJANGO_SETTINGS_MODULE=settings_without_course_interest \
    PYTHONPATH=.sdd-work:. uv run pytest --co -q -p no:cov -p no:playwright -p no:cacheprovider -o addopts= \
    freedom_ls/course_interest/tests; echo "exit=$?"
  ```

  Expected: no tests collected, no collection error, `exit=5`. Only the app's own `tests/`
  directory is passed, because `learner_interface/views.py` imports both apps at module level.
  `PYTHONDONTWRITEBYTECODE=1` keeps Python from leaving a `__pycache__` beside the module.
  Repeat for `course_recommendations`, then delete both throwaway modules by name:
  `rm .sdd-work/settings_without_course_interest.py .sdd-work/settings_without_course_recommendations.py`.
- `select_tests.sh --working-tree` prints `tier: full` (two new `conftest.py` files); run the
  printed command.
- `uv run pre-commit run --all-files` passes with `mirroring_baseline.txt` unchanged (a `conftest.py`
  is not a collected test file, so the mirroring check ignores it).

Commit: `test-organisation-and-hygene-4-shared-test-infrastructure: guard the course_interest and
course_recommendations tests against an uninstalled app`.
