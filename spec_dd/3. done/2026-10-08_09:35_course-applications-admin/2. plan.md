# Implementation plan: course applications in the admin

Source: `idea.md` in this directory (the spec stage was skipped, so the idea is the spec). The
three `research_*.md` files beside it hold the code facts this plan builds on.

Code snippets below are shapes, not finished files: they omit imports (`datetime`, `Q`,
`dataclass`, `UUID`, `prefetch_related_objects`, `SafeString`, `NotRegistered`, `reverse`,
`format_html`, `AutocompleteSelectFilter`, `InclusiveRangeDateTimeFilter`, and so on) and the
implementer adds them, with full type hints on every function and no `Any`. Comments and
docstrings in the snippets are written to be copied as they are. Nothing else in this document
is: never copy a sentence that names a slice into code.

## Slice 1: a read-only `CourseApplication` changelist

**Behaviour.** The admin index lists "Course applications". Its changelist shows one row per
application with the applicant's email and name, the course, whether it is submitted, its
submitted time, and when it was created. Drafts are listed alongside submitted applications.
Nobody can add, change or delete an application there; the change page opens in view mode and
shows the three read-only values until Slice 5 widens it. Erasing a user from the User admin
still removes their applications.

**Files.**

- New `freedom_ls/course_applications/admin.py`:

```python
# The admin below denies delete so nobody can thin out applications one by one.
# Erasing the applicant is the one path that must take them along, and the User
# admin only vouches for the models named here.
USER_ERASURE_CASCADE_MODELS.add(CourseApplication)


@admin.register(CourseApplication)
class CourseApplicationAdmin(SiteAwareModelAdmin):
    """Find an application and read it. Nothing here writes.

    Applications are created only by the apply flow, which also creates the
    sitting; re-pointing the user, course or sitting from here would break the
    rule that the sitting is the applicant's own sitting of that course's form,
    and deleting one would leave its sitting and files with no owner.
    """

    list_display = [
        "applicant_email",
        "applicant_name",
        "course",
        "is_submitted",
        "submitted_time",
        "created_at",
    ]
    # Every column reads one of these relations; without them the changelist
    # queries once per row.
    list_select_related = ["user", "course", "form_progress"]
    ordering = ["-created_at"]
    fields = ["is_submitted", "submitted_time", "created_at"]
    readonly_fields = fields

    def has_add_permission(self, request: HttpRequest) -> bool:
        return False

    def has_change_permission(
        self, request: HttpRequest, obj: CourseApplication | None = None
    ) -> bool:
        return False

    def has_delete_permission(
        self, request: HttpRequest, obj: CourseApplication | None = None
    ) -> bool:
        return False

    @admin.display(description="Applicant", ordering="user__email")
    def applicant_email(self, obj: CourseApplication) -> str:
        return obj.user.email

    @admin.display(description="Applicant name", ordering="user__last_name")
    def applicant_name(self, obj: CourseApplication) -> str:
        return f"{obj.user.first_name} {obj.user.last_name}".strip()

    @admin.display(boolean=True, description="Submitted")
    def is_submitted(self, obj: CourseApplication) -> bool:
        return obj.is_submitted

    @admin.display(description="Submitted time")
    def submitted_time(self, obj: CourseApplication) -> datetime | None:
        # An application with no sitting was submitted the moment it was created.
        if obj.form_progress is None:
            return obj.created_at
        return obj.form_progress.completed_time
```

  `submitted_time` carries no `ordering`: sorting by the sitting's `completed_time` would put
  the no-form rows, which display their `created_at`, at the null end. With
  `has_change_permission` returning False, Django serves the change page in view mode, so the
  three fields render read-only and there is no save bar; `has_view_permission` still answers
  True for anyone holding `view_courseapplication`.

- `freedom_ls/course_applications/tests/test_admin.py` (new). Tests to drive the slice:
  - the changelist renders for a superuser with one draft and one submitted application and
    both appear;
  - the submitted column is false for a draft and true for a submitted sitting and for an
    application with no sitting;
  - the submitted time is the sitting's `completed_time`, and `created_at` for a no-form
    application;
  - the add view answers 403; the delete view answers 403 on GET and on POST and the row
    remains; the change page answers 200 on GET with no save controls and 403 on POST;
  - deleting the applicant through the User admin removes the application and its sitting;
  - a staff user with `view_courseapplication` can open the changelist; one without it cannot.

## Slice 2: view permissions replace the superuser gate

**Behaviour.** A staff user holding `view_formprogress`, `view_questionanswer` or
`view_questionanswerfile` can open the matching admin pages, and one holding
`view_questionanswerfile` can download a file through the admin route. A staff user without the
permission still gets 403 and sees no entry on the admin index. Add and delete still need the
matching add and delete permissions. Superusers keep everything.

```python
def can_download_answer_files(user: PermissionsMixin | AnonymousUser) -> bool:
    """Whether this user may download the files applicants attached.

    One permission opens both the QuestionAnswerFile admin and the download
```

## Slice 3: the answers document on the `FormProgress` change page

**Behaviour.** The `FormProgress` change page shows the sitting's answers as a read-only document
that walks the form in order: one group per page, headed by the page title, each group listing
one row per question with the question's text beside its answer. Choice answers show the option
text; dates and times go through `format_answer`; long answers appear in full; a file answer
shows its filename; a question with no answer row reads "Not answered". An answer whose question
is no longer on any of the form's pages appears in a final group headed "Questions no longer on
the form". The editable answer inline is gone. The sitting's `user` and `form` are read-only on
the change page, and `furthest_page_reached` is shown.

**Files.**

- `freedom_ls/form_engine/queries.py`: add the data structure and the walk.

```python
FINAL_GROUP_TITLE = "Questions no longer on the form"


@dataclass(frozen=True)
class AnswerRow:
    question: FormQuestion
    # None when the applicant left the question unanswered: a blank answer stores no row.
    answer: QuestionAnswer | None


@dataclass(frozen=True)
class AnswerGroup:
    title: str
    rows: list[AnswerRow]


def answer_groups(form_progress: FormProgress) -> list[AnswerGroup]:
    """The sitting's answers, laid out the way the form lays out its questions.

    Walks the form's current pages, so a question the applicant skipped still
    has a row and a question edited since shows its current wording. The join
    is to the live form definition, not a snapshot. Answers whose question is
    on no page follow in a final group.
    """
    prefetch_related_objects(
        [form_progress],
        "answers__selected_options",
        "answers__answer_file",
        "answers__question",
    )
    # One dict for the whole sitting rather than existing_answers_dict per page:
    # the final group needs the answers no page accounts for.
    answers = {answer.question_id: answer for answer in form_progress.answers.all()}
    groups: list[AnswerGroup] = []
    page_question_ids: set[UUID] = set()
    pages = form_progress.form.pages.prefetch_related("text_items", "questions")
    for page in pages:
        questions = page_questions(page)
        page_question_ids.update(question.id for question in questions)
        groups.append(
            AnswerGroup(
                title=page.title,
                rows=[AnswerRow(question, answers.get(question.id)) for question in questions],
            )
        )
    # A question can leave every page but never be deleted while answered (the
    # answer's FK protects it), so an answer with no page is still an answer.
    off_page_rows = [
        AnswerRow(answer.question, answer)
        for answer in form_progress.answers.all()
        if answer.question_id not in page_question_ids
    ]
    if off_page_rows:
        groups.append(AnswerGroup(title=FINAL_GROUP_TITLE, rows=off_page_rows))
    return groups
```

  `FormPage.title` is required, so there is no fallback heading.

- `freedom_ls/form_engine/admin.py`:
  - delete `QuestionAnswerInline` and the `inlines` line on `FormProgressAdmin`;
  - add `"furthest_page_reached"` to `readonly_fields` and to the "Progress" fieldset;
  - `get_readonly_fields(self, request: HttpRequest, obj: FormProgress | None = None) -> list[str]`
    returns the declared list plus `user` and `form` when `obj` is not None, with this comment:
    "The sitting is the record of what one person was asked; its owner and form never change
    after the fact. The add page still needs both.";
  - `change_form_template = "admin/form_engine/answers_change_form.html"`;
  - a module-level helper and a `render_change_form` override. `render_change_form` runs after
    Django's permission check with the object already loaded, on the GET and on an invalid-POST
    re-render, so nothing is computed for a reader about to get 403 and nothing is loaded twice:

```python

class FormProgressAdmin(SiteAwareModelAdmin):

            context.update(answers_context(obj))
```

  The rendering sits in a template rather than in a `readonly_fields` method because a read-only
  field method receives only the object, and the file link (Slice 4) and the summary links

## Slice 5: the `CourseApplication` change page

**Behaviour.** The `CourseApplication` change page opens with a summary linking to the applicant,
the course and the form progress record, then shows the applicant's answers through the same
document as the `FormProgress` page. A summary link is plain text when the reader could not open
the page behind it. An application with no sitting says so in the summary and shows no answers
section.

**Files.**

- `freedom_ls/site_aware_models/admin.py`: add

```python
def admin_change_link(request: HttpRequest, obj: Model, label: str | None = None) -> SafeString:
    """A link to obj's admin change page, or its text when this reader could not open it.

    Asks the registered ModelAdmin rather than a permission string, so an admin
    with its own view rule answers for itself. A link that ends in a 403 is
    worse than none.
    """
    text = label if label is not None else str(obj)
    try:
        can_view = admin.site.get_model_admin(type(obj)).has_view_permission(request, obj)
    except NotRegistered:
        can_view = False
    if not can_view:
        return format_html("{}", text)
    opts = obj._meta
    url = reverse(f"admin:{opts.app_label}_{opts.model_name}_change", args=[obj.pk])
    return format_html(
        '<a href="{}" class="text-primary-600 dark:text-primary-500">{}</a>', url, text
    )
```

- New `freedom_ls/form_engine/templates/admin/form_engine/_summary.html`: one row per
  `(label, value)` pair in `summary_rows`, label bold, value as given (a `SafeString` from
  `admin_change_link`, or a plain string the template escapes). Use the row classes listed under
  "What exists".

- `answers_change_form.html`: add `{% if summary_rows %}{% include "admin/form_engine/_summary.html" %}{% endif %}`
  before the answers include.

- `freedom_ls/course_applications/admin.py` `CourseApplicationAdmin`:

```python
            if form_progress is not None:
                context.update(answers_context(request, form_progress))
        return super().render_change_form(request, context, add, change, form_url, obj)
```

## Slice 7: filters and search on the changelist

**Behaviour.** The `CourseApplication` changelist can be narrowed to submitted or draft
applications, to one course, and to a created-date range; it can be searched by applicant email,
first name, last name and course title.

**Files.**

- `freedom_ls/course_applications/admin.py`:

```python
class CourseApplicationSubmittedFilter(admin.SimpleListFilter):
    """Submitted or draft, by the same rule as CourseApplication.is_submitted.

    An application with no sitting was submitted the moment it was created, so
    "submitted" is an OR over two shapes and the shared completion filter, which
    tests one timestamp, cannot express it.
    """

    title = "submitted"
    parameter_name = "submitted"

    def lookups(
        self, request: HttpRequest, model_admin: admin.ModelAdmin
    ) -> list[tuple[str, str]]:
        return [("submitted", "Submitted"), ("draft", "Draft")]

    def queryset(
        self, request: HttpRequest, queryset: QuerySet[CourseApplication]
    ) -> QuerySet[CourseApplication]:
        if self.value() == "submitted":
            return queryset.filter(
                Q(form_progress__isnull=True)
                | Q(form_progress__completed_time__isnull=False)
            )
        if self.value() == "draft":
            return queryset.filter(
                form_progress__isnull=False, form_progress__completed_time__isnull=True
            )
        return queryset
```

  On `CourseApplicationAdmin`:

```python
    list_filter = [
        CourseApplicationSubmittedFilter,
        ("course", AutocompleteSelectFilter),
        ("created_at", InclusiveRangeDateTimeFilter),
    ]
    # Filters apply on Submit, so a created-date range goes through as a pair of
    # dates rather than refreshing the list after each box.
    list_filter_submit = True
    search_fields = ["user__email", "user__first_name", "user__last_name", "course__title"]
```

- `freedom_ls/course_applications/tests/test_admin.py`:

    "submitted" and "draft" results agree with each row's `is_submitted`;

  - a search by last name finds the application, and so does a search by course title;
  - a created-date range with only the date boxes filled narrows the list.
