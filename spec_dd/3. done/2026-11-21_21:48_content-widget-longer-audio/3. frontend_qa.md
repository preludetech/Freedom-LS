# Frontend QA: longer audio clip widget (`c-audio-clip`)

## Setup

1. Migrate and load the demo content, so the new clip file and every audio file's duration exist:
   `uv run python manage.py migrate`, then
   `uv run python manage.py content_save ./demo_content DemoDev`.
   The run finishes without an error; no "Could not read the audio duration" line names a demo file.
2. Start the server: `uv run python manage.py runserver $PORT`. Base URL `http://127.0.0.1:$PORT`.
3. Log in at `/accounts/login/` with the QA login from `.claude/sdd/config.md` (`## QA Login`).
4. Open the "Content Widgets - Demo Reference" course and go to the "Media" topic. If the course is
   not open to the learner view, use the educator interface's course content preview for the same
   topic. Scroll to the `## Audio clip` section, which comes after `## Audio`.

Run every test at the three QA viewports: 1920×1080, 768×1024 and 375×812. Keep the console open:
no JavaScript errors at any point. The mockups beside `idea.md` are the visual reference:
`image.png` (idle), `image-1.png` (loading), `image-2.png` (playing), `image-3.png` (error).

## Test 1: idle (compare `image.png`)

1. The section shows two clips. The first has a title, a kind label and a transcript toggle; the
   second has only a title.
2. For each clip check:
   - [ ] a card with the same border, surface and corner radius as the `c-audio` cards above it
   - [ ] a round play button at the left, in the vertical centre of the card, at least 44×44 px, filled in the primary colour, with a play triangle at its optical centre (not low, not left)
   - [ ] the title in bold on one line; a title too long for the width ends in an ellipsis, and hovering it shows the full title
   - [ ] the first clip's kind ("Listening exercise") sits at the right of the title row in small muted mono text and does not shrink; the second clip has no kind text and no gap where it would be
   - [ ] under the title, a seek bar with a visible thumb at the left, then `0:00 / m:ss` with `0:00` in normal text and `/ m:ss` muted, digits not shifting width
   - [ ] the total time matches the recording's length
   - [ ] the first clip shows "Show transcript" with a chevron under the seek row; the second shows no toggle
   - [ ] at 375 px nothing scrolls sideways and the time text is not cut off
3. Open the network panel and reload. No request goes to `/content/audio/` or to any `.mp3` before
   a Play press, and the totals still show.

## Test 2: loading and playing (compare `image-1.png`, `image-2.png`)

1. Throttle the network to "Slow 3G" and press Play on the first clip.
   - [ ] the button shows a spinning loading icon while it loads
   - [ ] then a pause icon (two bars) once sound starts, centred in the button; the button stays the same size
   - [ ] after a mouse click the button shows no focus ring
2. Remove throttling. While it plays:
   - [ ] the thumb moves and the played part of the bar fills in the primary colour
   - [ ] the elapsed time counts up each second
   - [ ] the title stays on one line
   - [ ] the total may correct itself by a second once the audio loads, never by more, and the thumb reaches the end exactly when the sound ends
3. Press the button again: it pauses, shows the play triangle, and the time stays where it stopped.
   Press again: it resumes from there.
4. Let a clip play to its end (seek near the end first). It returns to `0:00` and the button
   changes from pause back to the play triangle. The next press plays from the start.
5. Clear the browser cache and reload, so the dev server sends the file without Range support.
   Press Play, then drag the thumb near the end while it plays. The bar never freezes while sound
   plays: either it jumps there and the clip ends as in step 4, or it goes back to the sound's real
   position. When the sound ends, the button shows Play again.
6. With the OS or devtools "prefers-reduced-motion: reduce" set, the loading icon does not spin.

## Test 3: seeking

1. Before ever pressing Play on the second clip, drag its thumb to about the middle. The time text
   follows the drag. Press Play: it starts from that point, not from `0:00`.
2. While playing, drag the thumb. The time follows the drag without jumping back while you hold
   it; on release playback continues from the new point.
3. Pause, then click near the end of the bar. It jumps there and stays paused.
4. Click at the very right edge of the bar: the elapsed time reads the total (the last second).
5. Keyboard: Tab to the seek bar; a visible focus ring shows.
   - Right arrow moves forward 5 seconds, Left arrow back 5 seconds.
   - End jumps to the end, Home to `0:00`.
6. At 375×812 with touch emulation, drag the thumb with touch. It moves, and a tap at the right
   edge reaches the last second. The touch target is comfortable (about 44 px high) though the
   track itself is thin.
7. Seeking works once the file is in the browser cache: seeking within the loaded file works
   without restarting. The dev server's `/media/` handler ignores `Range`, so on a clip's first,
   uncached load a seek may not take and the bar follows the sound instead (Test 2.5). Safari is
   not tested.

## Test 4: one sound at a time

1. Play clip 1, pause it at some point (note the time). Play clip 2. Then play a `c-audio` word
   (e.g. Bravo) above. Each new start stops the one before; only one sound plays at a time.
2. Press Play on clip 1. It resumes at the noted time, not from `0:00`.
3. While clip 1 plays, press Bravo. Clip 1 shows Play and keeps its time; Bravo plays.
4. While Bravo plays, press clip 2. Bravo stops and returns to its speaker icon (and rewinds:
   pressing it again plays the word from the start).
5. The `c-audio` words above still play, stop on a second press, and show their own error line when
   blocked, exactly as before.

## Test 5: error state and retry (compare `image-3.png`)

1. In devtools, block the request pattern `*/content/audio/*`. Reload. Seek clip 1 to about 0:20,
   then press Play.
   - [ ] the card takes the error border and a light error tint
   - [ ] the play button turns red (error fill, white icon) and shows the retry icon (circling arrows), centred, at the same size, and stays in the vertical centre of the card; opening the transcript does not move it
   - [ ] the seek row is replaced by "This audio couldn't load."; there is no separate "Try again" button
   - [ ] the title wraps instead of being cut with an ellipsis
   - [ ] the transcript toggle still opens and closes the transcript
   - [ ] a screen reader (or the accessibility tree) announces "This audio couldn't load."
2. Press the red retry button while still blocked. The error shows again and is announced again.
3. Unblock the pattern and press the red retry button. The clip plays from about 0:20, not from
   the start (on a host that honours Range; see Test 2.5 for the dev server), the button turns
   back to the primary colour with the pause icon, and the error state clears.
4. In the error state the play button's accessible name is "Try again: <title>".

## Test 6: transcript

1. Press "Show transcript" on clip 1.
   - [ ] the panel opens smoothly under the seek row; the label changes to "Hide transcript" and the chevron turns from pointing down to pointing up
   - [ ] "Hide transcript" looks exactly like "Show transcript": no border or focus ring after a mouse click
   - [ ] the transcript shows as separate paragraphs
   - [ ] with reduced motion set, it opens with no animation
2. Press "Hide transcript". The panel closes; while closed its text is not in the accessibility tree.
3. The toggle is reachable by Tab, works with Enter and Space, and shows a focus ring when reached
   by keyboard.

## Test 7: accessibility attributes

Inspect clip 1:

1. The card is a group named by the title.
2. The play button's accessible name is "Play <title>" in every state but the error state, where
   it is "Try again: <title>". `aria-pressed` is `true` only while playing.
3. The seek bar's name is "Seek <title>". Its `aria-valuetext` reads spoken time, e.g. "1 minute
   12 seconds of 3 minutes 18 seconds", and during playback it changes at most once a second.
4. The visible time text is hidden from assistive technology.
5. The two demo clips share one file, but no two elements on the page share an `id`.

## Test 8: authoring errors and null duration

Edit `demo_content/functionality_demo_content_widgets/2. media/content.md` temporarily. Revert it
afterwards with `git checkout -- "demo_content/functionality_demo_content_widgets/2. media/content.md"`
and re-run the `content_save` command.

1. Add `<c-audio-clip src="audio/missing.mp3" title="Missing"></c-audio-clip>` with blank lines
   around it. A red box reads "Audio not found: audio/missing.mp3".
2. Add `<c-audio-clip src="images/<any demo image>" title="Picture"></c-audio-clip>`. A red box
   reads "Audio not found: images/...".
3. Add a clip with the real clip file and no `title`. A red box reads "Audio needs a title: ...".
4. Add `onclick="alert(1)"` and a `<script>` line inside a clip's transcript. Neither survives in
   the page source and nothing runs.
5. Null duration: in the Django shell, set the clip `File`'s `duration_seconds` to `None`
   (`File.objects.filter(file_path__endswith="<clip name>.mp3").update(duration_seconds=None)`).
   Reload. The total shows `--:--` and the seek bar is disabled. Press Play: once sound starts the
   total shows the real length and the seek bar works. Re-run `content_save`: the duration is back.

## Test 9: no regressions on the Media topic

1. The rest of the Media topic (pictures, image grids, YouTube, the four `c-audio` words) looks and
   works as before at all three viewports.
2. Navigate away from the topic while a clip plays (use the course navigation). Nothing keeps
   playing on the next page.
