## Existing full-run record and timing output
- Full-run record exists: `claude_plugins/sdd/scripts/full_run_record.py`, one file per branch `.sdd-work/full_run_record_<branch>.txt` holding a commit SHA only (no durations). Spec 12 (`faster-test-runs-12-reliable-full-run-record`, in `1. next`) will change who writes it (maybe the runner); spec 11 extends it with failed tests. The ranking is a separate artefact and should not reuse this file.
- No existing `--durations`, junitxml or duration report in config, CI or scripts (grep found none outside spec_dd). Only prior timings are the samples in `spec_dd/1. next/faster-test-runs/research_test_timings.md` (19,507 tests; 220 Playwright; 8,277 parametrized; 66s collection; 55-65s DB setup per worker; accounts 657 tests/294s; 1,400-case shuffle test ~0.04s/case; matrix ~3.5s/case). A full run is about 25 minutes at 4 workers.
- Means to record per-test durations: `--durations=0` (prints to terminal only, per worker under xdist, needs `-n`-aware aggregation), `--junitxml=...` (merges xdist workers, carries per-test `time`), or a small conftest/plugin hook writing JSON. `pytest-timeout` does not report durations. Test-body (call) time vs setup/teardown must be separated: the sample notes about 1s teardown for `django_db(transaction=True)` tests.
- `--dist loadfile` is set, so per-module fixture cost lands on one worker; module-scoped demo-content import cost shows in the first test of a module's setup, which a ranking must attribute sensibly.
