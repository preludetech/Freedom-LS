# Plan: educator interface refactor 2, dashboard and audit log

Pure move. No behaviour, UI, URL, template, model or migration changes. Paths are under
`freedom_ls/educator_interface/` unless they start with `freedom_ls/`, `test_organisation/` or
`.sdd-work/`. Line numbers are from the tree at plan time; re-find each name by grep before cutting
it, and move tests by name, never by range.

## Ground rules for every slice

- **TDD for a move.** No test is written and no assertion changes, except the one
  `_NEW_REPORTING_FILES` entry in slice 2. The existing tests are the safety net: each slice moves
  code, repoints imports, then runs the targeted tier. "Red" for a slice is a failing import or a
  failing test after the cut. Fix the import, never the assertion.
- **Byte-for-byte.** Each moved name keeps its body, decorators, docstring, comments and spelling
  (leading underscores included). Only import lines change, plus the missing type hints slice 1
  adds to the shared test helpers. Moved tests keep their decorators
  (`@pytest.mark.django_db`, `@pytest.mark.usefixtures("mock_site_context")`, parametrize marks)
  and their order within each source block. Never drop a `# TODO` or `@claude` comment.
- **Each new production module** starts with a one-line module docstring stating what the module
  holds (never where it came from), then `from __future__ import annotations`, uses only absolute
  imports (`from freedom_ls....`), and declares a sorted `__all__` listing every name the spec's
  table gives it, underscore names included. Follow `panels/common/request.py` as the model.
- **Import rule for an area.** A module under `panels/dashboard/` or `panels/audit_log/` imports
  only `panels/common/`, `freedom_ls.panel_framework`, `freedom_ls.educator_interface.avatars` and
  other apps. Never `views`, `reporting`, `filters`, `actions`, `quick_views` or the sibling area.
  Inside `panels/audit_log/`, imports run one way: `filters` ← `data_tables` ← `data_table_panels`
  and `config`. Private names cross that line as plain imports (`from ...data_tables import
  _record_export`).
- **String casts** such as `cast("OrganisationScopedRequest", ...)` stay quoted.
- **Imports left unused** in a shrunk module go in the same commit (ruff `F401` catches them).
  Imports the moved code needs come with it.
- **Patch strings** name the module that looks the name up. `reporting.py` keeps importing
  `learner_avatars` for the cohort panels, so a stale `reporting.learner_avatars` patch string
  still resolves and silently patches nothing. That is why slice 2 checks the dashboard patch by
  mutation.
- **Commits.** Plain `git commit`. Each slice is at least one commit. The `test-mirroring`
  pre-commit hook needs each test file's module to exist when the test file is committed, so the
  production module always lands in an earlier commit or the same one. Every commit leaves the
  targeted tier green.
- **Tests per slice:** targeted tier. Before each commit run
  `.claude/ds/scripts/select_tests.sh --working-tree` and run the printed `command:` exactly, in
  the background. See `claude_plugins/django-stack/resources/test_tiers.md`. `--collect-only` and
  partial runs take `--no-cov`.
