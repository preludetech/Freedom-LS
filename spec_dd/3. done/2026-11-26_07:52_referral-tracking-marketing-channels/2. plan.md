# Plan: marketing channels for referral tracking

Spec: `1. spec.md` in this directory.

## Overview

One new pure module, `freedom_ls/referral_tracking/channels.py`, and its tests,
`freedom_ls/referral_tracking/tests/test_channels.py`. No model, migration, setting, URL, view,
template or admin change.

The module is a port of First-Class-LMS `apps/admin_dashboard/channels.py` (on disk at
`/home/sheena/workspace/first_class/First-Class-LMS.git/main/apps/admin_dashboard/channels.py`).
Copy its tables and rule bodies, then apply the spec's Decisions. The differences from the
reference, all of which the tests pin:

| Reference | This module |
| --- | --- |
| imports `LeadSubmission` and `SignupAttribution`; `from_record` takes their union | imports only `referers.referer_host`; `from_record` takes `FirstTouchFields` (a `Protocol`) |
| `ChannelBasis` values `"fbclid only"` etc., labels equal to values | snake_case values, human labels, new member `REFERRAL_CODE` |
| `classify` ignores `referral_code` | `referral_code` gives Referral after the referer rule and before `fbclid` |
| `GOOGLE_SEARCH_HOST = ^google\.([a-z]{2,3}\|co\.[a-z]{2})$` | adds `\|com\.[a-z]{2}` |
| `EMAIL_HOSTS` has three entries | adds `outlook.office.com`, `outlook.office365.com`, `mail.proton.me`, `icloud.com` |
| `has_signal` checks the raw UTM pair | `has_signal` strips and lowercases the pair the same way `classify` does |

Existing code to reuse, not reimplement:

- `freedom_ls.referral_tracking.referers.referer_host` gives the comparable host of a raw referer, or
  `""`. For an `android-app://` referer it returns the bare lowercased package name, which is why the
  referer rule re-checks the raw string for the `android-app://` prefix before any host table.
- `SignupAttribution` (`freedom_ls/referral_tracking/models.py`) has exactly the fourteen
  `FirstTouchFields` names as `CharField(blank=True)` plus `first_seen`. A quick mypy check
  confirmed that a `Protocol` with plain `str` annotations accepts a `SignupAttribution` instance
  under django-stubs, so no adapter or cast is needed.
- `freedom_ls/referral_tracking/tests/test_referers.py` is the style precedent: module-level
  `parametrize` tables, no database, no fixtures.

## Slices

All four slices edit the same two files, so they form one chain and run in order. The rules land in
the order `classify` applies them, so each slice appends to `classify` and never inserts between

### Slice 1: the public types, and `classify` for no touch and an empty touch

Behaviour: a caller can build a `FirstTouch` from a `SignupAttribution`, and `classify` returns
Unknown for `None` and Direct for a touch with every field empty.

**Builds on:** none
**Touches:** freedom_ls/referral_tracking/channels.py, freedom_ls/referral_tracking/tests/test_channels.py

Create `channels.py` with:

```python
"""The marketing channel a first touch came through, worked out from its stored fields.

Pure: no request and no database query. Callers classify at read time, so a rule
change reclassifies history.
"""

from dataclasses import dataclass, fields
from datetime import datetime
from typing import Protocol

from django.db import models


class Channel(models.TextChoices):
    # Declaration order is the display order: `.choices` feeds filter dropdowns.
    DIRECT = "direct", "Direct"
    ORGANIC_SEARCH = "organic_search", "Organic search"
    PAID_SEARCH = "paid_search", "Paid search"
    ORGANIC_SOCIAL = "organic_social", "Organic social"
    PAID_SOCIAL = "paid_social", "Paid social"
    EMAIL = "email", "Email"
    REFERRAL = "referral", "Referral"
    OTHER = "other", "Other"
    UNKNOWN = "unknown", "Unknown"


class ChannelBasis(models.TextChoices):
    UTM = "utm", "UTM tags"
    GCLID = "gclid", "Google click ID"
    REFERER = "referer", "Referring site"
    REFERRAL_CODE = "referral_code", "Referral code"
    FBCLID_ONLY = "fbclid_only", "Meta click ID only"
    NONE = "none", "No signal"


class FirstTouchFields(Protocol):
    """Any record with the first-touch field names, such as `SignupAttribution`
    or a project's own lead model."""

    advert_code: str
    referral_code: str
    utm_source: str
    utm_medium: str
    utm_campaign: str
    utm_content: str
    utm_term: str
    gclid: str
    gbraid: str
    wbraid: str
    fbclid: str
    landing_path: str
    referer: str
    raw_query: str


@dataclass(frozen=True)
class FirstTouch:
    advert_code: str
    referral_code: str
    utm_source: str
    utm_medium: str
    utm_campaign: str
    utm_content: str
    utm_term: str
    gclid: str
    gbraid: str
    wbraid: str
    fbclid: str
    landing_path: str
    referer: str
    raw_query: str
    first_seen: datetime

    @classmethod
    def from_record(cls, record: FirstTouchFields, first_seen: datetime) -> "FirstTouch":
        names = [f.name for f in fields(cls) if f.name != "first_seen"]
        return cls(**{name: getattr(record, name) for name in names}, first_seen=first_seen)


@dataclass(frozen=True)
class ChannelResult:
    channel: Channel
    source_platform: str
    basis: ChannelBasis


def classify(first_touch: FirstTouch | None) -> ChannelResult:
    """The first matching rule wins."""
    if first_touch is None:
        return ChannelResult(Channel.UNKNOWN, "", ChannelBasis.NONE)
    return ChannelResult(Channel.DIRECT, "", ChannelBasis.NONE)
```

Tests (TDD, write each failing first):

- `Channel` `(value, label)` pairs in declaration order equal a literal list of nine pairs. Same for
  `ChannelBasis` and its six pairs. The labels are pinned too, because they are the text a filter
  dropdown shows.
- `[f.name for f in fields(FirstTouch)]` equals a literal list of the fourteen names plus
  `first_seen`.
- `list(FirstTouchFields.__annotations__) + ["first_seen"]` equals the `FirstTouch` field names.
- `FirstTouch.from_record` on an unsaved `SignupAttribution` with a distinct value in every one of
  the fourteen fields, and a fixed aware `first_seen`, equals a `FirstTouch` built from literals.
  Because `from_record` takes a `FirstTouchFields`, mypy also checks that the model satisfies the
  protocol.
- `classify(None)` gives `ChannelResult(Channel.UNKNOWN, "", ChannelBasis.NONE)`.
- An all-empty touch gives `ChannelResult(Channel.DIRECT, "", ChannelBasis.NONE)`.

A test helper builds a `FirstTouch` with every field `""` and a fixed `first_seen`, overridden by
keyword: `_touch(**overrides: str) -> FirstTouch`. Every later slice's tables use it.

### Slice 2: the direct pair and the UTM rules

Behaviour: a touch with a non-direct UTM pair is classified by its source and medium, with basis
`UTM`, and nothing later runs. The `direct`/`none` marker is not a UTM signal and gives Direct.

**Builds on:** slice 1
**Touches:** freedom_ls/referral_tracking/channels.py, freedom_ls/referral_tracking/tests/test_channels.py

Add `import re` and the constants copied from the reference: `DIRECT_SOURCES`, `DIRECT_MEDIA`,
`PAID_MEDIUM`, `VIDEO_MEDIUM`, `DISPLAY_MEDIA`, `SOCIAL_MEDIA`, `EMAIL_VALUES`, `REFERRAL_MEDIA`,
`SEARCH_SOURCES`, `SOCIAL_SOURCES`, `VIDEO_SOURCES`. Keep the regexes as the reference writes them
(`PAID_MEDIUM` is GA4's pattern). Hoist the reference's per-call
`social_sources = {**SOCIAL_SOURCES, **VIDEO_SOURCES}` to a module constant
`_SOCIAL_AND_VIDEO_SOURCES`, built once.

Copy `_utm_result(source, medium)` from the reference, including its local `result` closure, so a
diff against the copy it replaces stays small. Its eight branches are the eight UTM rules in order.

```python
def is_direct_pair(utm_source: str, utm_medium: str) -> bool:
    """True when the source is a direct marker and the medium is an empty marker."""
    return (
        utm_source.strip().lower() in DIRECT_SOURCES
        and utm_medium.strip().lower() in DIRECT_MEDIA
    )


def _utm_signal(first_touch: FirstTouch) -> tuple[str, str] | None:
    """The stripped, lowercased UTM pair, or None when it says nothing.

    Normalised here because rows written outside capture may differ in case or
    whitespace, and `classify` and `has_signal` must agree on what counts."""
    source = first_touch.utm_source.strip().lower()
    medium = first_touch.utm_medium.strip().lower()
    if not (source or medium) or is_direct_pair(source, medium):
        return None
    return source, medium
```

In `classify`, after the `None` check:

```python
utm_pair = _utm_signal(first_touch)
if utm_pair is not None:
    return _utm_result(*utm_pair)
```

Tests, parametrized tables of `(utm_source, utm_medium, expected ChannelResult)`, each expected
value a literal:

- `is_direct_pair` truth table: each of `direct`, `(direct)` against each of `none`, `(none)`,
  `(not set)` is true; mixed case and surrounding spaces are true; `direct`/`email`, `google`/`none`,
  `""`/`none` and `direct`/`""` are false.
- The direct marker: `(direct)`/`(none)` with nothing else gives Direct, `NONE`.
  `FirstTouch.from_record(SignupAttribution(utm_source="direct", utm_medium="none"), ...)` gives
  Direct with basis `none`.
- Paid search: `google`/`cpc` → Paid search, Google; `bing`/`ppc` → Bing; `google`/`paid_search`.
- Paid social: `facebook`/`paid` → Facebook; `fb`/`cpc` → Facebook; `ig`/`cpc` → Instagram;
  `tt`/`paid_social` → TikTok; `x`/`cpc` → X; `an`/`cpc` and `msg`/`cpc` → Meta;
  `youtube`/`cpv` → YouTube; `linkedin`/`retargeting` → LinkedIn.
- Other from display or unlisted paid: `newsletter`/`display`; `someadnet`/`cpm`;
  `someadnet`/`cpc`.
- Organic search: `google`/`organic`; `google`/`""` (a source with no medium); `""`/`organic` (a
  medium with no source, platform `""`).
- Organic social: `facebook`/`social`; `linkedin`/`""`; `""`/`social-media` (platform `""`);
  `""`/`video` and `newsletter`/`promo-video` (a medium containing `video`); `vimeo`/`""`.
- Email: `newsletter`/`email` and `e-mail`/`""` → Email, `"Email"`.
- Referral: `partner`/`referral`, `partner`/`affiliate`.
- Other: `partner`/`banana`, an unrecognised pair.
- Case and whitespace: `" Google "`/`"CPC"` → Paid search, Google.
- Exact match: `facebook.com`/`social` gives Organic social with platform `""`, because a
  host-shaped source is not looked up in the host tables; `xbox`/`cpc` gives Other, not X.
- Paid against organic per platform: `facebook`/`cpc` → Paid social and `facebook`/`social` →
  Organic social; `google`/`cpc` → Paid search and `google`/`organic` → Organic search.

### Slice 3: Google click identifiers and the referer rules

Behaviour: with no UTM decision, a Google click identifier gives Paid search, then a referer with a
host is classified by host with basis `REFERER`, then Direct.

**Builds on:** slice 2
**Touches:** freedom_ls/referral_tracking/channels.py, freedom_ls/referral_tracking/tests/test_channels.py

Add `from freedom_ls.referral_tracking.referers import referer_host`. Copy from the reference:
`SEARCH_HOSTS`, `SOCIAL_HOSTS`, `VIDEO_HOSTS`, `EMAIL_HOSTS`, `APP_PACKAGES`,
`_ANDROID_APP_PREFIX`, `_matches`, `_lookup` and `_referer_result`, with its local `result`
closure. Then:

- `GOOGLE_SEARCH_HOST = re.compile(r"^google\.([a-z]{2,3}|co\.[a-z]{2}|com\.[a-z]{2})$")`, the
  pattern exactly as the requirement states it.
- `EMAIL_HOSTS` gains `"outlook.office.com": "Outlook"`, `"outlook.office365.com": "Outlook"`,
  `"mail.proton.me": "Proton Mail"` and `"icloud.com": "iCloud Mail"`. `referer_host` drops the
  `www.`, so `https://www.icloud.com/mail/` gives the host `icloud.com`.

`_referer_result` keeps the reference's order: the raw-string `android-app://` check first (the
helper returns a bare package, so a package could otherwise match a web host table), then
`EMAIL_HOSTS`, then the Google pattern, then search, social and video hosts, then Referral with no
platform. A referer with no host returns `None`.

```python
def _has_google_click_id(first_touch: FirstTouch) -> bool:
    return bool(first_touch.gclid or first_touch.gbraid or first_touch.wbraid)
```

`classify`, after the UTM branch:

```python
if _has_google_click_id(first_touch):
    return ChannelResult(Channel.PAID_SEARCH, "Google", ChannelBasis.GCLID)
from_referer = _referer_result(first_touch.referer)
if from_referer is not None:
    return from_referer
return ChannelResult(Channel.DIRECT, "", ChannelBasis.NONE)
```

Tests:

- Each of `gclid`, `gbraid`, `wbraid` alone → Paid search, Google, `GCLID`.
- UTM beats a click identifier: `newsletter`/`email` plus `gclid` → Email by `UTM`.
- A click identifier beats a referer: `gclid` plus a Facebook referer → Paid search.
- The direct pair falls through: `direct`/`none` plus `gclid` → Paid search; plus a referer → the
  referer's result.
- A parametrized `(referer, expected ChannelResult)` table:
  - Subdomains: `https://l.facebook.com/l.php?u=x`, `https://lm.facebook.com/`,
    `https://m.facebook.com/` → Organic social, Facebook; `https://l.instagram.com/` → Instagram;
    `https://search.yahoo.com/` → Organic search, Yahoo.
  - Google: `https://www.google.co.za/`, `https://www.google.com.au/`, `https://www.google.de/` →
    Organic search, Google. `https://accounts.google.com/` and `https://docs.google.com/` →
    Referral, `""`.
  - Lookalikes: `https://box.com/` → Referral (not X); `https://ghost.co/` → Referral (not `t.co`).
  - Email: `https://outlook.office.com/`, `https://outlook.office365.com/` → Email, Outlook;
    `https://mail.proton.me/` → Email, Proton Mail; `https://www.icloud.com/mail/` → Email,
    iCloud Mail; `https://mail.yahoo.com/` → Email, Yahoo Mail
    (not Yahoo search).
  - Android: `android-app://com.google.android.gm/` → Email, Gmail;
    `android-app://com.linkedin.android/` → Organic social, LinkedIn;
    `android-app://com.example.app/` → Referral, `""`.
  - No host: `"not a url"` and `"http://"` → Direct, `NONE`.
- Host-table integrity, parametrized over `SEARCH_HOSTS`, `SOCIAL_HOSTS`, `VIDEO_HOSTS` and
  `EMAIL_HOSTS`: the list of `(entry, other)` pairs where `entry != other` and
  `entry.endswith("." + other)` is `[]`. This is an invariant on the tables, not a behaviour: an
  entry nested under another in the same table would never be reached, so its platform would be
  silently ignored. The pairs come from a module-level helper using a comprehension, so the test
  body has no loop.

### Slice 4: the referral code, `fbclid` and `has_signal`

Behaviour: with no UTM, click-identifier or referer decision, a referral code gives Referral, then
`fbclid` gives Organic social via Meta, then Direct. A caller can ask whether a touch carried
anything at all, including an `advert_code`.

**Builds on:** slice 3
**Touches:** freedom_ls/referral_tracking/channels.py, freedom_ls/referral_tracking/tests/test_channels.py

`classify`, replacing the final Direct return:

```python
if first_touch.referral_code:
    # A referral code is explicit first-party intent; fbclid alone is a guess.
    return ChannelResult(Channel.REFERRAL, "", ChannelBasis.REFERRAL_CODE)
if first_touch.fbclid:
    return ChannelResult(Channel.ORGANIC_SOCIAL, "Meta", ChannelBasis.FBCLID_ONLY)
return ChannelResult(Channel.DIRECT, "", ChannelBasis.NONE)
```

`advert_code` is never read by `classify`: it names an advert, not a channel.

```python
def has_signal(first_touch: FirstTouch) -> bool:
    """Whether the touch carried anything, not whether it can be classified,
    so an advert code counts."""
    return bool(
        _utm_signal(first_touch) is not None
        or first_touch.advert_code
        or first_touch.referral_code
        or _has_google_click_id(first_touch)
        or first_touch.fbclid
        or referer_host(first_touch.referer)
    )
```

Tests:

- `referral_code` alone → Referral, `""`, `REFERRAL_CODE`.
- `fbclid` alone → Organic social, Meta, `FBCLID_ONLY`.
- Precedence: a Facebook referer plus `referral_code` → Organic social by `REFERER`; `referral_code`
  plus `fbclid` → Referral; `gclid` plus `referral_code` → Paid search.
- The direct pair falls through: `direct`/`none` plus `referral_code` → Referral; plus `fbclid` →
  Organic social, Meta.
- `advert_code` alone → Direct, `""`, `NONE`.
- `has_signal`, a parametrized `(overrides, expected bool)` table:
  - all empty, the direct pair, a whitespace-only `utm_source` (`"   "`) and an unparseable referer
    alone → false;
  - `advert_code` alone, `utm_medium="email"`, `referral_code`, `gclid`, `gbraid`, `wbraid`,
    `fbclid` and a referer with a host → true.
