# Frontend QA: Learners associated with organisations

Browser verification for `1. spec.md` / `2. plan.md`. Everything below is done in a real browser
against the dev server.

Two things this cut changes are invisible in the golden path and are where the bugs will be, so they
get their own sections: **cross-organisation isolation** (§2 — two `Prefetch`es were deleted and the
scoping is now structural) and **content access after removal** (§6 — a gate rewritten in three
places, one of which is a `Q` expression whose per-row twin must agree with it).

---

## 0. Setup

### 0.1 Database and server

The database is recreated from scratch — this cut has no backfill.

ids — keep that output open, several checks below need a slug or a pk from it.

## 6. Removal suspends access; records survive

This is the behaviour change. **Rita Removed** is `is_active=False` in RPAS Training but still holds
an **active** registration for the solo course.

1. In `/admin/` → **Learner course registrations**, confirm Rita's registration row exists and its
   Active box is **ticked**. In `/admin/` → **Learners**, confirm her Learner row's Active box is
   **unticked**. Records preserved, entitlement withdrawn — both facts visible at once.
2. Log in as **Rita**. Her dashboard lists the solo course in **neither** current nor completed
   courses.
3. Go to `/courses/functionality-demo-show-end-with-topic/` — the detail page loads (it is a public,
   visible course) but offers her the **self-registration CTA**, not a "continue" link.
4. Try the player directly: `/courses/functionality-demo-show-end-with-topic/home/`. **Expect a
   redirect to the course detail page**, not the player.
5. **The list and the per-row check must agree.** As **admin**, register Rita's learner for the
   hidden course (`qa-hidden-visibility`) via `/admin/`, then as Rita:
   - the hidden course does **not** appear in any course listing, and
   - `/courses/qa-hidden-visibility/` returns **404**.

   A course that 404s but still shows in a list — or vice versa — means `filter_visible` and the
   per-row gate have diverged. Undo this registration afterwards.
6. **Educator view.** As **Olive Educator**, `/educator/organisations/rpas-training/learners` does
   **not** list Rita. As **Lena Legacy**, if Rita were in Year 9 Maths she would also not appear —
   the flag applies to both branches.
7. **Reactivate.** In `/admin/`, tick Rita's Learner Active box and save. As Rita: the solo course is
   back on her dashboard, the player opens, and her progress is exactly where it was — nothing was
   rebuilt because nothing was destroyed. As Olive: Rita is back in the Learners list.
8. Set her back to `is_active=False` before moving on.

## 9. Side effects and failure branches

1. **Deadlines still resolve.** As **Cara Learner**, open the cohort course
   (`/courses/functionality-demo-course-parts/`) and confirm any deadline badges render the same
   dates as before this cut. Cara holds `Learner` rows in two organisations — if the deadline lookup
   was narrowed from "this person" to "this learner", her deadlines would vanish or change.
2. **Cohort deadline overrides.** In `/admin/` → **Cohort course registrations** → open the Year 9
   Maths registration → the User Deadline Overrides inline. Add an override for Cara's learner and
   save; confirm it renders on her course page. Then try adding one for a learner who is **not** in
   that cohort — **expect a validation error**, not a save.
3. **Reports still build.** As **Olive Educator**, generate a cohort report for Year 9 Maths. It
   lists every member with names and progress, in surname order. A report missing names means
   `load_roster`'s user hop was missed.
4. **Course learner counts are per-person, not per-learner-row.** In the **Courses** section, note
   the **Active Learners** count for the solo course. Cara and Sol are both registered through
   Northside; Rita's registration is through an inactive RPAS learner. Add a *second* registration
   for Cara for that same course through a different organisation via `/admin/`, reload the Courses
   list, and confirm **the count did not go up** — she is one person. Remove that extra registration
   afterwards.
5. **Webhook payload is unchanged.** Trigger a fresh self-registration (§7) and check the dev console
   / webhook log for `course.registered`. The payload still carries `user_id` and `user_email` with
   the registering person's values — not learner ids.
6. **Anonymous browsing still works.** Log out entirely. Course listing pages and public course
   detail pages still load, and the hidden course still 404s. The gate rewrite touched the same
   queries anonymous visitors flow through.
7. **The old section name is gone everywhere.** With the browser devtools network tab open, click
   through the whole educator interface — Cohorts, Learners, Courses, and every panel and tab —
   watching for any request to a `…/users/…` path. There should be none, and no 404s at all.
8. **Organisation deletion is still protected.** In `/admin/`, try to delete **RPAS Training**.
   **Expect a refusal** — learners now protect it too, on top of cohorts.
