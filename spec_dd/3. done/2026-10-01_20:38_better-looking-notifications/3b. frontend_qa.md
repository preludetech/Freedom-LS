# Frontend QA: better-looking notifications, phase 2

Phase 2 restyles the bell, the badge, the bell panel and the notification centre to match the
registered design in FLS's own theme. Nothing behavioural changed: the same views, URLs, polling and
Alpine component serve the same rows. So this run checks two things on every surface: that it now
looks like the design state it maps to, and that every behaviour the earlier notifications QA proved
still works under the new markup. The risky changes are structural: the row's link now stretches over
the whole row, the Mark read/unread button sits above it on its own layer, the icon moved into a tile,
and the filter links lost their underline. Each of those can break a click, a focus target or a
screen-reader name without any test noticing.

Beyond the ten design states this run hunts for:

- **A click that goes to the wrong place.** Clicking a row's icon, meta line or empty space must open
  the notification's target. Clicking Mark read or Mark unread must never navigate. A row whose
  course was deleted has no link and must not react to a click.
- **A control hidden under the stretched link.** Mark read, Mark unread, the panel's Mark all as read
  and See all, the pagination links and the filter pills must all take a click and keyboard focus.
- **An unread marker that lies.** Tint, bold, dot and "Unread" must appear together and vanish
  together, in the panel and on the centre, after Mark read, Mark unread and Mark all as read.
- **A badge that stops updating or loses its ring.** The badge refreshes on open, on mark-all and on
  the poll, keeps its ring, and still caps at 99+.
- **Accessibility regressions.** The bell's accessible name, the panel heading focus after Mark all as
  read, the icon-only Mark read names at 375px and the "Unread." screen-reader prefix all survive.

Substitute the literal port number chosen by `.claude/ds/scripts/find_available_port.sh` wherever this
document writes `<PORT>`. Shell variables do not survive between tool calls.

The Django debug toolbar sits over parts of the header on narrow viewports. Remove it with
`document.getElementById('djDebug')?.remove()` before clicking anything it covers.

Credentials for the admin account are in `.claude/fls-dev/config.md`. Seeded QA users follow the
DemoDev convention: the password is the email address.

Design screenshots live beside this file under `design_screenshots/`. A test that names one is a
design test: compare this run's screenshot with it against the checklist, judging layout, order,
hierarchy, density, states and copy, never colour, font, icon glyphs or pixels. An element the design
draws that the checklist does not list (the Preferences gear and button, "Show older notifications",
the message item, the "about" segment, the "New" wording) is correctly absent.

## §0 Setup

### 0.1 Build and serve

1. Run `npm run tailwind_build`. The built stylesheet is not committed, and the new classes (tiles,
   tints, the badge ring) only exist after a build.
2. Run `.claude/ds/scripts/find_available_port.sh`. Note the number and use it literally.
3. Start the server backgrounded, as its own call: `uv run python manage.py runserver <PORT>`.
4. Base URL is `http://127.0.0.1:<PORT>`.

### 0.2 Seed data

1. Run `uv run python manage.py qa_create_notification_scenarios` (destructive and idempotent). It
   creates:

   | Persona | What |
   | --- | --- |
   | `notify.learner@demodev.example.com` | Learner A. 25 visible notifications, 5 unread (3 unseen), spread over six weeks across several day headings and two pages. One row's course has been deleted (3 days ago, page 1). |
   | `notify.other@demodev.example.com` | Learner B, 2 unseen. |
   | `notify.educator@demodev.example.com` | An educator, 1 unseen. |
   | `notify.many@demodev.example.com` | Learner C, 120 unseen. |

2. With the `fls-dev:qa-data-helper` agent, create `notify.empty@demodev.example.com`: a login-ready
   learner on the DemoDev site (verified primary email, password equal to the email) with no
   notifications. Delete any existing user of that email first.

Re-run step 1 whenever a section needs Learner A's unread rows back.

### 0.3 Viewports

Desktop is 1280 wide, mobile is 375 wide, tablet is 768 wide. Resize with the browser tool before each
test that names a width.

## §2 The bell panel

Re-run `qa_create_notification_scenarios` first. Log in as Learner A, visit `/` at 1280.

### 2.1 Panel open at desktop (design)

Design screenshot: `design_screenshots/uc-1-bell__pop.png`. Width 1280.

1. Click the bell. The badge goes to 0 (hidden). A popover opens under the bell's right edge.
2. Take a full-page screenshot.
3. Check: heading "Notifications" with "5 unread" beside it in muted text; eight rows, newest first;
   each row has a small rounded icon tile at the left with the course icon on a neutral grey tile; the
   message is in plain body text with no underline, bold on the five unread rows; the meta line reads
   "Course registration · <time>"; unread rows are tinted and carry a dot and "Unread" at the right;
   the footer has a ghost "Mark all as read" with an icon and a ghost "See all" with an arrow.
4. Hover over the icon tile of a row, then over the empty space right of the message. The cursor is a
   pointer in both places.

Design checklist:

- [ ] The panel is a popover under the bell's right edge, bordered, rounded, with a shadow, on top of
      the page.
- [ ] The heading reads "Notifications" with "N unread" beside it in a muted, smaller weight.
- [ ] At most eight rows, newest first.
- [ ] Each row leads with an icon tile: a rounded square with the category icon, neutral grey for
      course registration.
- [ ] The message is in the body text colour with no underline, and bold on unread rows.
- [ ] Long messages clamp to two lines.
- [ ] The meta line below the message is smaller and muted: label, a middle dot, relative time.
- [ ] Unread rows have a light primary tint across the full row and a dot plus "Unread" label at the
      right; read rows have neither.
- [ ] The whole row is the click target (pointer cursor anywhere on the row).
- [ ] The footer has "Mark all as read" with an icon at the left and "See all" with a trailing arrow
      at the right, both as ghost buttons.

### 2.2 Whole-row click from the panel

### 2.3 Mark all as read from the panel

3. Keyboard: press Escape, reload, Tab to the bell, Enter, Tab to "Mark all as read", Enter. Focus
