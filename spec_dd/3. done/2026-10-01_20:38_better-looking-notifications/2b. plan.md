# Plan: better-looking notifications, phase 2 (the notifications UI)

This plan builds phase 2 of `1. spec.md`: restyle every surface `user-communication-1-notifications-core`
built so it reads like the registered design, in FLS's own theme. Behaviour does not change: no view,
URL, Alpine component or polling edit. Phase 1 (the SDD process) is already implemented through
`2. plan.md` and is not repeated here. Batch markers for this plan are `[batch 2b.N]`.

Inputs to keep open while implementing: `1. spec.md` ("Phase 2 UI" and "Testing"), `design.md` ("How
to treat it"), the Design section below, and `research_design_vs_built_gap.md` for the screen-by-screen
gap. The design is a visual reference, never a source of scope: build only what the Design section
transcribes.

## Skills and tools

- **`ds:template`, then `fls-dev:template`**: every template edit (slices 1-4). Partials stay at
  `freedom_ls/comms/templates/comms/partials/`, since themes shadow by path. Django-style
  `{% comment %}` only.
- **`ds:frontend-styling`, then `fls-dev:frontend-styling`**: every class change. Only tokens from
  `freedom_ls/themes/default/static/themes/default/theme.css`; no hex, no raw palette utilities, no
  new tokens. `tailwind.input.css` scans templates as plain text, so every colour class is written out
  as a complete literal string, never assembled from a variable. Run `npm run tailwind_build` after
  each slice that adds a class (the output file is untracked, so nothing to commit).
- **`brand-guidelines`** (`visual.md`): status text on a pale tint uses the `-light` pair; `bg-surface-2`
  is the tinted-panel neutral; surfaces stay flat, so the icon tile gets no shadow or border.
- **`fls-dev:icon-usage`** and its `resources/configuring-icons.md`: slices 3 and 4. `<c-icon>` by
  semantic name only; `class` replaces the default `size-5`. The skill lists semantic names by pointing
  at `SEMANTIC_ICON_NAMES`, so adding `check_all` there is what makes the skill list it; the skill file
  itself needs no edit.
- **`ds:htmx`**: slice 1 moves the row's Mark read/unread button; its `hx-*` attributes and targets
  stay exactly as they are.
- **`ds:testing`, then `fls-dev:testing`**: tests mirror the module (`base/notification_categories.py`
  → `base/tests/test_notification_categories.py`), `mock_site_context` on every site-aware test,
  factories for data, `@pytest.mark.parametrize` instead of loops. Parse rendered HTML with
  `lxml.html` the way `freedom_ls/educator_interface/tests/test_sidebar.py` does. `ds:testing` says not
  to assert on CSS classes; the spec asks for two class assertions, the unread tint and the tile
  classes, and those are the only two this plan writes, each on the one element that must carry the
  class. Everything else styling-wise is checked by the design check, not by pytest.
- **`ds:playwright-tests`, then `fls-dev:playwright-tests`**: slice 1's browser tests. Both target files
  already carry a module-level `pytestmark` with `playwright`. Locate a row with
  `page.get_by_role("listitem").filter(has_text=...)`; clicking it outside the message text needs a
  `position=` argument on `click()`, which is not a CSS locator, so no locator-priority exception is
  needed.
- **`domain-glossary`**: use the spec's words: icon tile, whole-row target, unread tint, day headings,
  badge ring, filter, all-read banner, design state, design checklist, token mapping.
- **`code-comments`**: no spec or plan citations in templates or Python.
- **`ds:alpine-js` / `fls-dev:alpine-js`**: read only; nothing in `notification_bell.html`'s `x-*`
  attributes changes.
- **MCP**: none during implementation. The design check that `implement_plan` runs after slices 3 and 4
  drives `mcp__plugin_ds_playwright__*` through the `Design check` hook; the slices themselves do not.

## Slice 1: the row reads as an inbox item

**Behaviour.** In the panel and on the centre, a notification row's message is in the row's text
colour with no underline, the whole row is the click target with a pointer cursor, unread rows are
tinted, and panel messages clamp to two lines. Mark read/unread still works and still sits outside the
link. A notification with no URL still has no click target.

No design state is complete after this slice: the row is finished by slice 2 and its states are
checked under slices 3 and 4.

**Files.** `freedom_ls/comms/templates/comms/partials/notification_row.html` only.

Pseudocode for the row:

```django
<li class="relative flex items-start gap-3 px-4 py-4 sm:items-center
           {% if not notification.read_at %}bg-primary/5 hover:bg-primary/10{% else %}hover:bg-surface-2{% endif %}">
    {% comment %}the icon stays as it is until slice 2{% endcomment %}
    <div class="min-w-0 flex-1">
        <p class="text-on-surface {% if not notification.read_at %}font-semibold{% endif %}
                  {% if not show_actions %}line-clamp-2{% endif %}">
            {% if not notification.read_at %}<span class="sr-only">Unread. </span>{% endif %}
            {% if notification.url %}
                <a href="{% url 'comms:notification_open' notification.pk %}"
                   class="text-on-surface no-underline after:absolute after:inset-0 after:content-['']
                          rounded-sm focus-visible:outline-none focus-visible:ring-2
                          focus-visible:ring-[var(--color-focus-ring)]">{{ notification.message }}</a>
            {% else %}
                <span>{{ notification.message }}</span>
            {% endif %}
        </p>
        ...meta line unchanged...
    </div>
    <div class="relative z-10 flex shrink-0 items-center gap-3">
        {% if not notification.read_at %}
            <span class="pointer-events-none inline-flex items-center gap-1 text-xs font-semibold text-primary"
                  aria-hidden="true">
                <span class="size-2 rounded-full bg-primary"></span>
                Unread
            </span>
        {% endif %}
        ...the two c-button branches unchanged...
    </div>
</li>
```

Notes:

- `relative` on the `<li>` is what the stretched `after:absolute after:inset-0 after:content-['']`
  anchors to, the same stretched-link idiom `freedom_ls/panel_framework/templates/cotton/panel-attention-row.html`
  already uses. Nothing between the `<li>` and the `<a>` may be positioned.
- The actions `<div>` is `relative z-10` so the Mark read/unread button sits above the stretched
  area. The button stays a sibling of the link, never inside it. The "Unread" label in that div is
  `pointer-events-none`, so a click on it falls through to the link: in the panel the div holds only
  the label, and without this the row's right edge would be dead.
- The `<li>` drops its own `bg-surface`: both parents (the centre card and the panel) already paint it.
  An unread row keeps its tint on hover (`hover:bg-primary/10`); a read row hovers to `surface-2`.
- The `<a>` needs its own `text-on-surface` because the base layer colours every `<a>` `text-primary`.
- The pointer cursor comes from the `<a>`'s pseudo-element; no `cursor-pointer` is needed.
- The visible label is `aria-hidden="true"` as a whole, so the inner dot no longer needs its own.
- `line-clamp-2` applies only when `show_actions` is false, which is the panel; the centre screenshots
  do not clamp.

**Tests** (TDD, written first):

- `freedom_ls/comms/tests/test_rendering.py`, a new `TestRowMarkup` class that GETs
  `comms:notification_list` with `logged_in_client` and parses the row with `lxml.html`:
  - an unread row's `li` carries `bg-primary/5` and its visible label span has `aria-hidden="true"`;
  - the Mark read button is not a descendant of the row's `<a>` (`row.cssselect("a button")` is empty
    and `row.cssselect("button")` is not);
  - a notification whose target is gone renders a `<span>`, no `<a>`.
- `freedom_ls/comms/tests/playwright/test_notification_centre.py`:
  - `test_clicking_a_row_outside_the_message_text_opens_its_target`: a row for a course, located with
    `page.get_by_role("listitem").filter(has_text=...)`, clicked at `position={"x": 12, "y": 12}`
    (the row's left padding, outside the message text); expect the page URL to be
    `live_server.url + notification.url`;
  - extend `test_marking_a_row_read_then_unread_toggles_its_unread_marker` with
    `expect(page).to_have_url(_centre_url(live_server))` after the Mark read click, which is the
    "marks it read without navigating" check.
- The existing Playwright tests in both files still pass.

## Slice 2: category colour and the icon tile

**Behaviour.** Each row's icon sits in a small rounded tile. The tile's colour comes from the
notification category: a category with no colour gets a neutral tile. `course.registered` keeps no
colour.

No design state is complete after this slice; the row's states are checked under slices 3 and 4.

**Files.**

- `freedom_ls/base/notification_categories.py`:

  ```python
  from enum import StrEnum

  class NotificationColour(StrEnum):
      PRIMARY = "primary"
      SUCCESS = "success"
      WARNING = "warning"
      INFO = "info"
      ERROR = "error"

  @dataclass(frozen=True)
  class NotificationCategory:
      key: str
      label: StrPromise
      icon: str
      message: StrPromise
      url_builder: str | None
      colour: NotificationColour | None = None
  ```

  `FLS_NOTIFICATION_CATEGORIES` is unchanged, so `course.registered` stays `None`.

- `freedom_ls/comms/models.py`: beside `icon`,

  ```python
  @property
  def colour(self) -> NotificationColour | None:
      return get_notification_category(self.category).colour
  ```

- `freedom_ls/comms/templates/comms/partials/notification_row.html`: replace the bare icon with the
  tile. Every class string is a complete literal so Tailwind sees it:

  ```django
  <span class="grid size-9 shrink-0 place-items-center rounded-md
      {% if notification.colour == "primary" %}bg-primary/10 text-primary
      {% elif notification.colour == "success" %}bg-success-light text-on-success-light
      {% elif notification.colour == "warning" %}bg-warning-light text-on-warning-light
      {% elif notification.colour == "info" %}bg-info-light text-on-info-light
      {% elif notification.colour == "error" %}bg-error-light text-on-error-light
      {% else %}bg-surface-2 text-muted{% endif %}">
      <c-icon :name="notification.icon" class="size-5" />
  </span>
  ```

  `NotificationColour` is a `StrEnum`, so the template's string comparison holds. Each glyph colour
  clears 3:1 against its tile in both shipped themes: the `on-*-light` inks on their `-light` tints,
  `muted` on `surface-2` (`#718096` on `#EDF2F7` in `first_class` is the tightest, about 3.7:1), and
  `primary` on a 10% primary wash.

**Tests** (TDD, written first):

- `freedom_ls/base/tests/test_notification_categories.py` (new): a `NotificationCategory` built
  without `colour` has `colour is None`.
- `freedom_ls/comms/tests/test_rendering.py`:
  - `test_colour_comes_from_the_category`, next to `test_label_and_icon_come_from_the_category`: with

- The `comms` system check tests (`test_checks.py`) still build `NotificationCategory` without

## Design

Read `design.md` first. Ten design states, all under `design_screenshots/`. Every state is reached
logged in; the personas and their data come from `qa_create_notification_scenarios`
(`uv run python manage.py qa_create_notification_scenarios`). Learner A is
`notify.learner@demodev.example.com` (26 notifications, 25 visible on the centre, 5 unread, one whose
course was deleted); the password is the email. No seeded persona has zero notifications, so the two
empty states need one made for the purpose with `fls-dev:qa-data-helper`: a login-ready learner on the
DemoDev site named `notify.empty@demodev.example.com`, password equal to the email, no notifications.
Only the panel clamps messages; the centre never does.

The design's copy differs from FLS's in three places, and FLS's copy stays: the unread label reads
"Unread" (design: "New"), the bell's accessible name says "new" (design: "unread"), and the centre row
has no third "about" segment in its meta line. FLS also shows Mark unread on read rows of the centre,
which the design does not draw; it stays. Elements the design draws that the spec does not ask for
(the Preferences gear and button, "Show older notifications", the message notification item, the
`role="dialog"`) are not transcribed.
