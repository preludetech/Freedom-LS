# Spec: learner CSV upload design fix

## Purpose

Bring the learner CSV import's three pages (upload, preview, result) into line with the registered
design (`idea.md`), keeping every behaviour the import already has.

Resources:

- `idea.md`: the idea.
- `design.md`: the Claude Design design for the import (screens 05 to 08).
- `research_*.md`: the research beside this spec.

## Scope

In:

- Restyle `learner_import_upload.html`, `learner_import_preview.html`, `learner_import_result.html`,
  `partials/learner_import_result_body.html` and `partials/import_stepper.html` under
  `freedom_ls/educator_interface/templates/educator_interface/`.
- A drag-and-drop zone and a file format table on the upload page.
- On the preview page: summary tiles that are the label filters, and a separate block for error rows.
- Two copy fixes QA logged against the shipped import: no "0 new accounts will get a setup email."
  line, and no "0 rows were not added." clause.
- The view-context additions and the `HX-Refresh` header on the finished status poll these need
  (listed under Requirements). No model, URL or migration changes.

Out:

- Everything the design draws that the product does not do: the sample file, the cohort codes list,
  by-cohort counts, the update-or-skip choice for existing learners, the invitation checkbox, a
  Cancel button, the extra columns (`cohort_code`, `location`, `licence_held`), and the design's
  limits (1,000 rows, 5 MB).
- The design's sidebar, top bar and breadcrumb: the educator shell and `standalone_page.html` already draw them.
- `partials/run_status.html`, which other background runs share, and `learner_import_denied.html`.
- The design's theme, colours, fonts and icons. The pages use the project theme, existing cotton
  components and semantic icon names. No theme token, icon name or font is added.

## Decisions

1. **Step labels stay "1. Upload", "2. Preview", "3. Result"**, with "Step N of 3". Only the
   stepper's look changes.
2. **Drag-and-drop fills the native input.** The `<input type="file">` stays in the form and works
   by click and keyboard (WCAG 2.2 SC 2.5.7 needs a non-drag path). Nothing uploads until "Upload
   and preview" is pressed.
3. **The preview's rows table leaves error rows out unless the Error filter is on.** Error rows have
   their own block above it, so listing them twice adds nothing.
4. **The importing state is styled around `run_status.html`, not in it.** Its queued and running
   copy ("Waiting to start.", "N of M rows processed.") is unchanged.
5. **Limits shown on the upload page come from the code**: `LEARNER_IMPORT_MAX_ROWS` and
   `MAX_UPLOAD_BYTES` from `freedom_ls.base.csv_import`.
6. **The `local_time` tag moves to `base`.** The result page's completion time uses the
   `localTime` Alpine component, which already lives in `base`, but its template tag lives in
   `deadlines`, an app `educator_interface` does not depend on. The tag moves to a new `base`
   library, `time_tags`, and `deadline_tags` keeps registering the same function so existing
   `{% load deadline_tags %}` templates, here and downstream, are unchanged.

## Requirements

### Stepper: `partials/import_stepper.html`

- Keep the `nav[aria-label="Import steps"]`, the ordered list and `aria-current="step"` on the
  current step.
- Each step renders as a numbered marker and its label in one row. A completed step's marker shows
  the `check` icon in place of the number. The current step is emphasised with weight as well as
  colour.
- Below `sm` the labels may hide visually (screen readers still read them) as long as "Step N of 3"
  plus the current label stays visible. The list has no bullet markers at any width.

### Upload page: `learner_import_upload.html`

Layout: from `lg`, two columns: the upload card on the left and a "File format" card on the right.
Below `lg` they stack, upload first.

**Upload card** (`c-panel-card`, title "Upload a CSV file"):

- A one-line lede: up to `max_rows` learners and `max_file_size` per file, and nothing is created
  until the preview is confirmed.
- File-level errors: keep the existing hand-written alert div, with its `role="alert"`,
  `tabindex="-1"`, `autofocus`, heading "The file could not be uploaded." and error list. Style it
  with the classes `c-callout level="error"` uses and add the `error` icon. (`c-callout` has no
  attribute pass-through, so it cannot be the alerting element.) It sits above the drop zone, which
  stays usable for the re-upload.
- The drop zone is a dashed-border `<label for="{{ form.file.id_for_label }}">` holding:
  - a visually hidden span with `{{ form.file.label }}` ("CSV file") as its first child, so the
    label's accessible name and `get_by_label("File")` keep working;
  - the native input, visually hidden (`sr-only`, not `display:none`);
  - the prompt "Drop your CSV here, or browse", with "browse" styled as a link.
- A muted limits line (`.csv`, `max_rows`, `max_file_size`) sits directly under the drop zone,
  outside the label, with a fixed id. `LearnerImportForm.file`'s widget attrs in `forms.py` set
  `accept=".csv,text/csv"`, `aria-describedby` pointing at that id, and the `sr-only` class.
- Drop zone states, each shown with text or border style as well as colour:
  - idle: the prompt above.
  - drag-over: the border turns solid and the prompt reads "Drop to choose this file".
  - file chosen: the file's name and size replace the prompt, with a "Choose a different file" hint.
  - focus: a visible focus ring on the zone while the hidden input has focus (`focus-within`).
- The submit button "Upload and preview" stays, full width below `sm`.
- A cohort import keeps its sentence that every learner goes into the named cohort and the
  `cohort` column is ignored.

**Drop-zone behaviour**: a new Alpine component, `Alpine.data("fileDropZone", …)` in
`freedom_ls/base/static/base/js/alpine-components.js`, following the `fls-dev:alpine-js` skill
(CSP build: method references and `x-text`/`x-show`/`x-bind:class` methods, no inline
expressions). It handles `dragenter`, `dragover`, `dragleave` and `drop` on the label, and assigns
the dropped file to the input through a `DataTransfer`. A depth counter (or a `relatedTarget`
check) keeps the drag-over state from flickering as the pointer crosses the label's children. It
listens to the input's `change` event so a picked file shows its name the same way. It does not
filter by type; the server's existing validation decides. With JavaScript off the zone is still a
working label for the native input.

**File format card** (`c-panel-card`, title "File format", description "One learner per row. The
first row must contain these column headers."):

- "Download template": a `c-button` with `href="{{ template_url }}"`, `download` and
  `icon_left="download"`, in the card's `header_action` slot. Cohort imports keep their `?cohort=` link.
- A table with columns Column, Required, Format: one row per name in `HEADERS`, in `HEADERS`
  order. The column name renders in `<code>`. Required reads "Required" for `email` and "Optional"
  for the others. Format is a short description plus an example in muted monospace, taken from
  `TEMPLATE_EXAMPLE_ROWS` where it has a value. The descriptions are new copy:
  - `email`: "Used to sign in, and to match learners who already have an account."
  - `first_name`: "Given name. Existing accounts keep their names."
  - `last_name`: "Family name."
  - `cohort`: "The cohort's name, matched exactly." On a cohort import this row reads "Ignored:
    everyone goes into {{ cohort.name }}."
- Below `sm` each table row stacks as a card (the row-card layout below).

`learner_import.py` gains a `HEADER_DESCRIPTIONS` mapping keyed by header name. The
`learner_import` view passes a `format_rows` list (name, required, description, example) built from
`HEADERS`, `HEADER_DESCRIPTIONS` and `TEMPLATE_EXAMPLE_ROWS`, plus `max_rows` (the row limit with a
thousands separator) and `max_file_size` (`filesizeformat` of `MAX_UPLOAD_BYTES`). The comma-joined `headers` context value goes.

### Preview page: `learner_import_preview.html`

Top to bottom:

1. **File header card.** The file chip (`c-chip`, text unchanged: "{{ file_name }} · N rows") and
   "Upload a different file" as a secondary `c-button` linking to `upload_url`, with the `retry` icon.
2. **Summary tiles.** `c-panel-stat-row` (stock grid: two columns, four from `lg`) with one
   `c-panel-stat-tile` per entry in `label_counts`, value the count and label the label name. Each
   tile is wrapped in its filter link: `<a data-label-filter href="?label=…"
   aria-label="{{ name }}: {{ count }}">`, with `aria-current="true"` on the active one. When the
   Error count is above 0, its link carries error-coloured border and text classes and a
   `c-icon name="error"`. When a filter is active, a "Clear filter" link returns to `preview_url`.
3. **Error block**, only when `error_count` is above 0. A bordered card in error colours with the
   `warning` icon, heading "{{ error_count }} row(s) with errors will not be added.", the line "Fix
   them in your file and upload it again, or add the other rows now.", and two actions: the existing
   "Download the N error row(s)" button (`data-error-download`, text unchanged) and "Upload a
   corrected file" linking to `upload_url`. Below them, a table of the error rows with columns Line,
   Email, Reason. When `error_count` is above `error_rows|length`, a line reads "Showing the first
   {{ error_rows|length }} of {{ error_count }}. Download the error rows to see them all." The view
   adds `error_rows` to the preview context, built as the result page builds it:
   `error_rows(learner_import)[:IMPORT_RESULT_ERROR_ROWS]`, each with its `error_reason`.
4. **Rows card** (title "Rows", `flush`). The existing desktop table and `ul[data-row-cards]`
   mobile cards, column order unchanged (Line, Email, First name, Last name, Cohort, Label,
   Reason). The Label cell is a `c-panel-status-badge`. `learner_import.py` gains
   `PREVIEW_LABEL_TONES`, keyed by `ImportLabel` value: `NEW_ACCOUNT` `success`; `JOINED`,
   `REACTIVATED` and `ADDED_TO_COHORT` `info`; `ALREADY_MEMBER` `muted`; `ERROR` `error`. The view
   sets a `tone` on each row of `page_obj` from it. With no filter the view excludes
   `preview_label=error` rows from `shown`; with a filter it shows that label's rows. The existing
   pagination `nav` stays, restyled, keeping `rel="prev"`/`rel="next"` and the `label` parameter
   (`c-pagination` is HTMX-only and has no `rel` links). When the unfiltered table would be empty
   (every row is an error), the card is omitted.
5. **Confirm card**, last. The existing notes as a short muted list:
   - "{{ new_account_count }} new account(s) will get a setup email.", only when the count is above 0.
   - "Existing accounts keep their names."
   - "Counts can change if someone else adds these learners before you confirm."
   - The background note when `add_count and in_background`.

   Then the POST form with the primary "Add N learners" button, right-aligned from `sm`, full
   width below. When `add_count` is 0, the card instead says "Nothing can be added: every row has
   an error or is already a member." and "Upload a different file" is its primary action. The
   page has no other `type="submit"` button.

**Row-card layout**: every table on these pages (format, error rows, rows, result error rows) is a
table from `md` (`sm` for the format table) and the `data-row-cards` style card list below it.

### Result page: `learner_import_result.html` and `partials/learner_import_result_body.html`

- The result card is centred and narrower than the canvas from `md`, with no card title; the
  stepper stays above it.
- **Queued and running**: the card's heading is "Importing learners", above `run_status.html`. The
  heading sits outside `#run-status`, so the poll cannot replace it. When
  `partial_learner_import_status` answers with a finished run (`RunStatus.DONE` or
  `RunStatus.FAILED`), it adds an `HX-Refresh: true` header and the full page re-renders. A
  finished run's page has no "Importing learners" heading, and its result heading is focused on
  load (`tabindex="-1"`, `autofocus`) so screen readers announce the outcome.
- **Done**: the `success` icon, the headline "Added N learner(s)." followed by " M row(s) were not
  added." only when M is above 0, then a muted line with the file name and `finished_at` in the
  viewer's local time (`{% load time_tags %}` and `{% local_time learner_import.finished_at %}`,
  skipped when `finished_at` is null). The per-label counts and "N setup email(s) were sent."
  become a list of rows, each a label and a right-aligned count, with the `error` icon on the error
  row; the setup email row shows only when the count is above 0.
- **Failed**: the `error` icon and the existing "Stopped after X of Y rows" and `error_message`.
- The error rows table (`table[data-error-rows]`, columns unchanged) and the download button stay,
  styled as the preview's error block.
- "Uploading the whole file again is safe: rows already added show as 'already a member'." stays,
  as muted text.
- Actions: "Import another file" as a secondary `c-button` and the back link ("Back to learners" or
  "Back to the cohort's learners", same href) as the primary `c-button` with `icon_right="next"`.
  Side by side from `sm`, stacked full width below.

### Shared error block and hooks

The preview's error block and the result's error rows table render through one new partial,
`freedom_ls/educator_interface/templates/educator_interface/partials/import_error_block.html`,
holding the download button, the `table[data-error-rows]`, its row cards and the "Showing the
first …" line, with the heading, intro line and "Upload a corrected file" link only on the
preview. The result view passes `in_progress` (true while queued or running) so the page and the
status fragment read one fact.

Hooks the tests read, beside the existing `data-label-filter`, `data-error-download`,
`data-error-rows` and `data-row-cards`: `data-step-label` on each stepper label,
`data-format-table` on the upload page's table, `data-drop-zone` on the drop-zone label,
`data-error-block` on the shared block, `data-error-reupload` on its "Upload a corrected file"
link, `data-import-rows` on the preview's rows table, and `data-tone` (the
`PREVIEW_LABEL_TONES` value) on each Label cell.

### All pages

- No horizontal page scroll at any QA viewport (375, 768, 1920).
- Touch targets for buttons, tiles and the drop zone are at least 44px tall below `md`.
- Status is never colour alone: every error or success treatment has an icon or text with it.
- Styling uses Tailwind utilities on the markup and existing theme tokens (`fls-dev:frontend-styling`).

## Testing

Update the existing assertions in `freedom_ls/educator_interface/tests/test_views.py` and
`tests/playwright/test_learner_import_flow.py` that this restyle changes on purpose: the first-`code`
header string, "0 rows were not added." (including the done-fragment text in
`test_the_status_partial_drops_the_trigger_and_holds_the_result_once_done`), the `tbody tr` count
that included error rows, "Show all rows", and the `list-style-type` check on the old label-count
list. Every other import assertion passes unchanged.

New view tests:

- The upload page's format table has one row per name in `HEADERS`, in order, with `email` marked
  Required and the others Optional, and shows the row and size limits from the config.
- On a cohort import the `cohort` row says it is ignored and names the cohort.
- The file input has `accept=".csv,text/csv"` and an `aria-describedby` that resolves to the limits line.
- A bad file still gives 422 and a focused `role="alert"`, and the drop zone label is still present.
- Preview with no filter: the rows table has no error rows; with `?label=error` it has only error rows.
- Preview with errors: the error block lists the error rows with line, email and reason, and has the
  download link and an "Upload a corrected file" link to `upload_url`. With more error rows than
  `IMPORT_RESULT_ERROR_ROWS`, it shows that many and the "Showing the first … of …" line.
- Preview with no errors: no error block.
- Preview with no new accounts: no "new accounts will get a setup email" line.
- Preview where every row is an error: no Rows card, "Nothing can be added", and "Upload a
  different file" as the primary action.
- Preview pagination under a filter: `a[rel="next"]` keeps the `label` parameter.
- "Clear filter" appears only when `?label=` is set, and links to `preview_url`.
- Every summary tile link keeps `data-label-filter`, its href and its "{{ name }}: {{ count }}"
  `aria-label`; the active one has `aria-current="true"`.
- Each label renders as a status badge with the tone from `PREVIEW_LABEL_TONES`.
- Result with no rows lost: "Added N learners." with no "were not added" clause and no setup-email
  row when none were sent.
- Result while running: heading "Importing learners", `#run-status` unchanged (poll attributes,
  "Waiting to start.", the progress element).
- The status fragment sends `HX-Refresh: true` for a done or failed run and no such header while
  queued or running.

Playwright (`tests/playwright/test_learner_import_flow.py`):

- Dropping a CSV onto the drop zone (dispatching `dragenter`, `dragover` and `drop` with a
  `DataTransfer`) fills the input, shows the file name, and "Upload and preview" reaches step 2.
- The drag-over state shows "Drop to choose this file".
- Choosing a file through the input by keyboard (focus the input, set files) shows its name the same way.
- The stepper has `list-style-type: none`, and no page in the flow scrolls sideways at any of
  `QA_VIEWPORTS`.

## Open questions

- Q: Should the importing state add the design's "You can leave this page; the import continues in
  the background" line? → A: No. (assumed default: the design is never a source of scope, and the
  preview already carries the background note. Overrule by editing Result page, Queued and running.)
- Q: On a cohort import, keep both the card sentence and the format-table row saying the `cohort`
  column is ignored? → A: Keep both. (assumed default: the sentence is existing behaviour with a
  test; the row is where the column is described. Overrule by editing Upload page.)
- Q: Show the row limit with a thousands separator ("2,000 learners")? → A: Yes, formatted in the
  view as `f"{LEARNER_IMPORT_MAX_ROWS:,}"`, since `django.contrib.humanize` is not installed.
  (assumed default: it reads better and changes no behaviour. Overrule by editing the upload view
  context paragraph.)
