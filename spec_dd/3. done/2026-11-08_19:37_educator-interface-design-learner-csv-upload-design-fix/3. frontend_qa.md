# Frontend QA: learner CSV upload design fix

Checks the restyled import flow (upload, preview, result) in a browser. The plan is
`2. plan.md`; its Design section holds the transcriptions the checklists below are copied from.

The branch was rebased onto main after `educator-interface-12-docs-and-polish` landed. That spec
touched the import pages and the parts they share, so Test 11 covers what it changed, and the
steps it affects in Tests 4, 7 and 9 are updated in place. What main changed that reaches this
flow:

- The control-link invariant: every control link is a `<c-button variant="link">` or
  `<c-back-link>`, never a hand-styled `<a>`. Main converted the import templates' links; the
  rebase kept this feature's buttons and made "Clear filter" a link button.
- One date-time format in the educator interface, `6 Nov 2026, 09:12` (24-hour, viewer's zone),
  from the brand voice rules. The result page's completion time comes from `local_time`.
- Global form styles: `input[type="file"]` now gets the text-field border, full width and a
  styled file button, and below `md` every button and text field in `.panel-canvas` or
  `.panel-surface` gets `min-h-11`. The import's file input is `sr-only` inside the drop zone.
- `html` scroll padding now clears the sticky header at the top and the selection bar at the
  bottom; the upload alert and the result headline take focus on load.
- `alpine-components.js` was changed on both sides: main fixed `dropdownMenu` (stays open when
  the browser scrolls its trigger into view); this feature added `fileDropZone` and moved
  `localTime` into base.
- The Add learners textarea became the one-person Add learner dialog, and the "Import learners"
  trigger is now a small secondary button beside it.
- The import-denied page's back link and the run status back link became `<c-back-link>`.
- `panel-stat-row`, `panel-stat-tile` and `panel-status-badge` changed (phone grid, 44px tile
  links inside `dd`, a `data-tone` attribute on the badge); the preview tiles and badges use them.

## Setup

1. Build the stylesheet so the new utilities exist: `npm run tailwind_build`.
2. Start the server on a free port: `uv run python manage.py runserver $PORT`. Base URL:
   `http://127.0.0.1:$PORT`.
3. Log in at `http://127.0.0.1:$PORT/accounts/login/` with the QA login from
   `.claude/sdd/config.md` (`## QA Login`). That user is a site admin and an organisation admin
   of the dev organisation.
4. Open the educator interface and note the organisation slug in the URL
   (`/educator/organisations/<slug>/...`). Every URL below uses that `<slug>`.
5. The upload page is `http://127.0.0.1:$PORT/educator/organisations/<slug>/learners/import/`.
   The learners list links to it with a small secondary "Import learners" button beside
   "Add learner".

Files to prepare in a scratch directory:

- `good.csv`: header `email,first_name,last_name,cohort`, then three rows: two new emails
  (`qa-one@example.com,One,Person,` and `qa-two@example.com,Two,Person,`) and one row for a
  learner who is already a member of the organisation (take an email from the learners list).
- `mixed.csv`: `good.csv` plus two error rows: `not-an-email,,,` and a row whose email repeats
  `qa-one@example.com`.
- `all-errors.csv`: the header and two rows: `nonsense,,,` and `,Blank,Email,`.
- `bad-header.csv`: `name\nAda\n`.
- `big.csv`: the header and 60 rows, 55 of them `badN,,,` style errors (N = 1 to 55) and 5 new
  emails, so the Error filter paginates.
- `notes.txt`: any text file.

Viewports: 375, 768 and 1920 wide. "No sideways scroll" means
`document.documentElement.scrollWidth <= window.innerWidth` after layout settles.

## Test 1: upload page layout and format table

Design state: `educator-learner-import/05-upload`, screenshot
`design_screenshots/educator-learner-import__1280.png` (frame "05 Upload").

1. Go to the upload page at 1920.
2. Expect the stepper above the cards: "Step 1 of 3" and three steps in a row, step 1's marker
   filled and its label bold, steps 2 and 3 muted. No bullet markers.
3. Expect two columns: "Upload a CSV file" on the left and "File format" on the right.
4. In the upload card, expect a muted lede naming the limits: "Add up to 2,000 learners at
   once, 1.0 MB per file. Nothing is created until you review the preview and confirm."
5. Expect the dashed drop zone reading "Drop your CSV here, or browse" with "browse" styled as a
   link, and a muted monospace line under it: ".csv · up to 2,000 rows · 1.0 MB".
6. Expect the "Upload and preview" button under the zone.
7. In the "File format" card: the description "One learner per row. The first row must contain
   these column headers.", a "Download template" button with a download icon in the header, and
   a table with columns Column, Required, Format holding four rows in this order: `email`
   (Required), `first_name` (Optional), `last_name` (Optional), `cohort` (Optional). Each Format
   cell has a sentence and an example in muted monospace under it (`grace@example.com`,
   `Grace`, `Hopper`, `Cohort name`).
8. Click "Download template". Expect a download named `learner-import-template.csv`.
9. Resize to 768: the cards stack, upload first. The format table is still a table.
10. Resize to 375: the format table becomes a list of cards, one per column, each showing the
    name, Required/Optional, the sentence and the example. The "Upload and preview" button is
    full width and at least 44px tall. The stepper shows "Step 1 of 3: Upload" with the step
    labels visually hidden.
11. At every viewport: no sideways scroll.

Design checklist:
- [ ] Three steps in one row, marker then label; current step filled and bold; no bullets.
- [ ] Two columns from `lg`, upload left and format right; stacked below.
- [ ] Lede states the row and size limits.
- [ ] Dashed drop zone with the prompt and "browse" styled as a link.
- [ ] Limits line under the zone, muted.
- [ ] Format table: one row per header in `HEADERS` order; `email` Required, others Optional.
- [ ] Each row: name in `<code>`, description, example in muted monospace.
- [ ] "Download template" with the download icon in the card header.

## Test 2: drop zone states

1. On the upload page at 1920, press Tab until the hidden file input has focus. Expect a visible
   focus ring around the whole drop zone.
2. Click anywhere in the drop zone. Expect the native file picker to open (choose `good.csv`
   through it, or close it and set the file on the input directly).
3. With `good.csv` chosen: the prompt is replaced by `good.csv`, its size (e.g. "0.1 KB"), and
   the hint "Choose a different file".
4. Choose `mixed.csv` through the zone again. Expect the name to change to `mixed.csv`.
5. Drag-over state. In the page's console (or an evaluate call), build a `DataTransfer` holding
   a `File`, then dispatch `dragenter` and `dragover` on the `label[for="id_file"]` element with
   that `dataTransfer`. Expect the border to turn solid and the prompt to read "Drop to choose
   this file". Dispatch `dragleave` once: the state must stay (the counter handles nested
   enters); dispatch it again until the zone returns to the previous state. Dispatch `drop` with
   the transfer: the dropped file's name shows and the drag-over styling is gone.
6. Move the pointer over the prompt text and the limits line while dragging (a real drag from the
   OS file manager, if available): the zone must not flicker between states.
7. Nothing is uploaded until "Upload and preview" is pressed: the URL does not change during any
   of the above.
8. Reload the page with JavaScript disabled (DevTools: Disable JavaScript). The zone is still a
   label: clicking it opens the picker, and submitting a chosen file reaches the preview.
   Re-enable JavaScript afterwards.
9. At 375: the zone is at least 44px tall and the states above look the same.

   member." with a primary "Upload a different file" button. There is no submit button.

`BULK_BACKGROUND_THRESHOLD` (default 250). Ask the data helper for a CSV of 300 fresh emails, or

## Test 10: accessibility pass

1. On each of the three pages, Tab through every control: the drop zone input, buttons, tile
   links, pagination, error-block buttons. Every focused element shows a visible focus ring, and
   the tab order follows the visual order.
2. With a screen reader or the accessibility tree: the stepper is `nav "Import steps"` with the

   "CSV file" and its description is the limits line; the result headline is announced on load.
3. Status is never colour alone: the Error tile and error rows have an icon or wording, the
   success result has an icon, the drag-over state changes the prompt text.

## Test 11: what the rebase onto main reaches

Each step checks a change main made to something this flow uses (see the list at the top).
Run every step at 375, 768 and 1920 unless it names a viewport, and keep the browser console
open: no errors at any step.

1. **File input under the global styles.** On the upload page, the browser's own "Choose file"
   button and "No file chosen" text never show, before or after choosing a file. The drop zone is
   the only visible control. At 375 there is no extra blank space above or below the zone (the
   `sr-only` input must not take up 44px of layout from the `min-h-11` rule) and no sideways
   scroll. Repeat with JavaScript disabled: same result, and the label still opens the picker.
2. **Touch targets below md.** At 375, measure every button and link button on the three pages
   ("Upload and preview", "Download template", "Upload a different file", "Clear filter",
   "Download the N error rows", "Upload a corrected file", Previous/Next, "Add N learners",
   "Import another file", "Back to learners") and every tile link: each is at least 44px tall.
   At 768 and 1920 the buttons are back to their normal heights, none taller than its
   neighbours in the same row.
3. **Control links.** On the three pages, every link that is a control renders through
   `<c-button>` or `<c-back-link>`: in the accessibility tree and the DOM, no bare `<a>` with
   hand-written link styling. The tile links and the "browse"/"Choose a different file" text
   inside the drop zone are the known exceptions (the tiles are cards, the drop zone text is
   inside the label).
4. **Focus on load under the sticky header.** At 375 and 768, upload `bad-header.csv`: the
   focused alert is fully visible below the sticky header, not under it. Confirm an import:
   the focused result headline is fully visible below the header too.
5. **Preview tiles and badges after the component changes.** At 375 the tiles sit in a
   two-column grid with matching heights; each whole tile is the link and is at least 44px tall,
   with no inner link of its own. The Rows table's status badges keep their tones (success,
   muted, info, error) at every viewport, in both the table and the phone cards.
6. **Dropdowns on the import pages.** `alpine-components.js` changed on both sides. On each of
   the three pages at 375, open the sidebar and the organisation switcher (or the user menu),
   scroll the page a little so the trigger moves, and check the menu closes only when the page
   scrolls away from where it was at open; a menu whose trigger the browser scrolled into view
   for the click stays open. Escape closes it and returns focus to its trigger. Then check the
   drop zone (Test 2 step 5) and the result's completion time (Test 7 step 2) still work: both
   components load from the same file.
7. **Entry points.** On the learners list, "Add learner" opens the one-person dialog (email,
   first name, last name, cohort); it has no pasted list and no pointer to the file import. The
   "Import learners" button beside it is small and secondary and opens the upload page. On a
   cohort's Learners tab, the same button opens the cohort upload page (Test 9).
8. **Denied page.** Log in as a cohort admin of the dev organisation (ask the data helper for one
   if none exists) and open `/educator/organisations/<slug>/learners/import/`. Expect status 403
   and a card "You can't import learners here" with "Your role doesn't allow it.", who to ask,
   and a "Back to learners" back link (arrow icon, `<c-back-link>`) that opens the learners list.
   The page has the same header band and canvas as the other import pages, no stepper and no
   sideways scroll.
9. **Failed result back link.** On the failed import from Test 8 step 4, the page shows exactly
   one way back to the learners: the "Back to learners" primary button in the actions row. No
   second "Back to learners" back link from the shared run status partial.
