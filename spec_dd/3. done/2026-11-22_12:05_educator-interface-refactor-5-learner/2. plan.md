# Plan: educator interface refactor 5, learner

Pure move plus one data migration. No behaviour, UI, URL, URL name, template, app label or model
change. Paths are under `freedom_ls/educator_interface/` unless they start with `freedom_ls/`,
`test_organisation/`, `claude_plugins/` or `.sdd-work/`. Line numbers are from the tree at plan
time (they match `research_codebase.md`); re-find each name by grep before cutting it, and move
tests by name, never by range.

## Ground rules for every slice

- **TDD for a move.** No test is written and no assertion changes, except: the
  `_NEW_REPORTING_FILES` entry (slice 9), the `test_0001` migration target (slice 6), the new
  `test_0002` (slice 6) and the reason-mixin walk (slice 5, same count asserted). The existing tests
  are the safety net: each slice moves code, repoints imports, then runs the targeted tier. "Red"
  for a slice is a failing import or a failing test after the cut. Fix the import, never the
  assertion.
- **Byte-for-byte.** Each moved name keeps its body, decorators, docstring, comments, `# TODO` and
  `@claude` comments, and spelling (leading underscores included). Only import lines change.
  Quoted casts such as `cast("OrganisationScopedRequest", ...)` stay quoted. Moved tests keep their
  decorators and marks, and their order within each source block.
- **Each new production module** starts with a one-line module docstring stating what the module
  holds (never where it came from), then `from __future__ import annotations`, uses only absolute
  imports (`from freedom_ls....`), and declares a sorted (`RUF022`) `__all__` listing every name
  the module owns, underscore names included. Model: `panels/common/request.py`,
  `panels/audit_log/config.py`. Every new `__init__.py` is empty.
- **Import direction.** `panels/common` ← `panels/cohort/data_tables.py` ← `panels/learner/*`. A
  learner module imports `panels/common/`, `panels/audit_log/data_table_panels.py` (for
  `HistoryPanel`), `panels/cohort/data_tables.py`, `freedom_ls.panel_framework`, the flat domain
  modules (`forms`, `learner_import`, `messaging`, `tasks`, `avatars`, `events`, `paths`) and other
  apps. It never imports `views`, `actions`, `reporting`, `filters` or `quick_views`, except that
  `import_views.py` imports the shell `views.py`. Inside the learner area imports run one way:
  `filters` ← `data_tables` ← `data_table_panels`; `actions` ← `bulk_actions` ← `config`;
  `quick_view` ← `panels`; `panels`, `data_table_panels`, `messages` ← `instance_view` ← `config` ←
  `import_views`. `panels/cohort/data_tables.py` imports only `panels/common/`. Flat modules
  (`views.py`, `actions.py`, `reporting.py`, `quick_views.py`) may import from `panels/learner/`.
- **No pull from a flat module.** Before cutting a block, grep its body for every name it uses.
  If a body uses a name still defined in `views.py`, `actions.py`, `reporting.py`, `filters.py` or
  `quick_views.py` (other than the shell names `import_views.py` may take), stop and report it:
  importing back is forbidden.
- **No re-export shim.** A flat module loses each moved name and never re-imports it for others.
  Imports left unused in a shrunk module go in the same commit (ruff `F401` flags them).
- **Patch strings** name the module that now looks the name up. A stale string on a flat module
  that still imports the name resolves and patches nothing, so slice 11 checks one by mutation.
- **Commits.** Plain `git commit`. Each slice is at least one commit. The `test-mirroring` hook
  needs each test file's module to exist when the test file is committed, so a production module
  lands in the same or an earlier commit than its test file. A whole-file test move is a `git mv`
  with no content change in its own commit; its import repoints land in the commit before. Every
  commit leaves the targeted tier green.
- **Tests per slice:** targeted tier. Before each commit run
  `.claude/ds/scripts/select_tests.sh --working-tree` and run the printed `command:` exactly, in the
  background. See `claude_plugins/django-stack/resources/test_tiers.md`. `--collect-only` and
  partial runs take `--no-cov`.
- **Test placement.** A test whose request is made against a learner page, panel or action moves
  with learner. A test that drives a cohort page (the cohort Learners tab's triggers and picker,
  cohort-tab add-learner variants), spans areas, or is table-agnostic (bulk run status polling,
  `EDUCATOR_TABLES` and its parametrised tests, `test_a_history_panel_says_what_will_be_recorded`)
  stays where it is and has only its imports repointed. A moved test keeps the `_site_context`
  opt-in it had: a module `pytestmark` when every test in the new file needs it, otherwise the
  per-test use or local autouse fixture it came with. A helper that a moving and a staying test
  both use, or that two new test files use, goes to `tests/helpers.py` with full type hints (no
  `Any`). A helper only one new file uses moves into that file.

   ```python
   _OLD = "freedom_ls.educator_interface.actions."
   _NEW = "freedom_ls.educator_interface.panels.learner.bulk_actions."

   # (old action_path, new action_path) for every registered learner bulk action;
   # their unregistered bases are never stored.
   MOVES = [
       (f"{_OLD}{name}", f"{_NEW}{name}")
       for name in [
           "AddToCohortBulkAction",
           "RemoveFromCohortBulkAction",
           "DeactivateLearnersBulkAction",
           "ReactivateLearnersBulkAction",
           "RegisterForCourseBulkAction",
           "DeactivateRegistrationBulkAction",
           "ResendSetupEmailBulkAction",
       ]
   ]


   def _repoint(apps: Apps, pairs: list[tuple[str, str]]) -> None:
       """A stored run names its action class by dotted path and is loaded with
       import_string, so each run must name the module that defines its class.
       Every site's runs are repointed: the historical model's manager has no
       site filter, and a run left on the old path on any site would fail to load.
       Matches whole paths only, so other classes under the same prefix stay."""
       BulkActionRun = apps.get_model("freedom_ls_panel_framework", "BulkActionRun")
       for old_path, new_path in pairs:
           BulkActionRun.objects.filter(action_path=old_path).update(action_path=new_path)


   def forwards(apps: Apps, schema_editor: BaseDatabaseSchemaEditor | None) -> None:
       _repoint(apps, MOVES)


   def backwards(apps: Apps, schema_editor: BaseDatabaseSchemaEditor | None) -> None:
       _repoint(apps, [(new, old) for old, new in MOVES])


   class Migration(migrations.Migration):
       dependencies = [("freedom_ls_educator_interface", "0001_rename_unregister_bulk_runs")]
       operations = [migrations.RunPython(forwards, backwards)]
   ```
