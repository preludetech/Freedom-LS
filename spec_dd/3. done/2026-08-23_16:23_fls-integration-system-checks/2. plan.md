## Ground truth (confirmed against the current tree, 2026-08-23)

- **`freedom_ls_course_access.E001` already reports an unset
  `COURSE_ACCESS_BACKEND`.** `freedom_ls/course_access/checks.py:42-46`
  short-circuits on `config.missing_required()` and returns
  `required_settings_errors(config, "freedom_ls_course_access")`.
  `freedom_ls/course_access/tests/test_checks.py::TestCourseAccessSystemCheck::test_unset_backend_reports_required_setting_error`
  passes today. No new check is needed for this.
- **`freedom_ls_course_access.E001` is also used for the `access_config`
  validation error** at `freedom_ls/course_access/checks.py:69` — the overload
  this plan splits.
- **`required_settings_errors(config, app_label)`**
  (`freedom_ls/base/app_settings.py:62`) hardcodes `<app_label>.E001`. It is
  shared with `freedom_ls/reports/checks.py:34` and
  `freedom_ls/content_engine/checks.py:20`, so **do not change the helper** —
  move the *other* course_access error off E001 instead.
- **`freedom_ls/learner_interface/apps.py`** is a bare `AppConfig`
  (`LearnerInterfaceConfig`, `label = "freedom_ls_learner_interface"`) with no
  `ready()`.
- **Sitemap wiring** lives in the project root: `config/urls.py:41-54` names
  `sitemap` and `robots_txt`, with `StaticViewSitemap`/`CourseSitemap` from
  `config/sitemaps.py` and `robots_txt` from `config/views.py`. None of it ships
  in the package.
- **FLS-shipped backends:** `freedom_ls/course_access/backends.py`
  (`CourseAccessBackend`, `FreeOnlyCourseAccessBackend`,
  `VisibilityEnforcingBackend`) and
  `freedom_ls/course_applications/backends.py`
  (`ApplicationCourseAccessBackend`). Only the last lives in an app a downstream
  might legitimately not install — it is the E003 case.
  `VisibilityEnforcingBackend` is **never** a legal `COURSE_ACCESS_BACKEND`
  value: `freedom_ls/course_access/loader.py:36-37` always wraps whatever is
  configured. Do not build an E003 case around it.
- **Check-test style:** `freedom_ls/course_access/tests/test_checks.py` — call
  the check directly with `app_configs=None`, drive via `@override_settings`,
  assert on `.id`. The file is 149 lines with two classes and ten tests:
  `TestCourseAccessSystemCheck` (line 15, five tests) and
  `TestPreviewOverridesDisabledInProductionCheck` (line 72, five W001 tests that
  already assert `.id`). `@pytest.mark.django_db` is applied at class level to
  the first class **only** (line 14) — the new E003 class needs no DB.
- **Neither `access_config` test asserts an ID today.**
  `test_bad_access_config_produces_error` (line 46) asserts only
  `len(errors) >= 1`; `test_error_includes_course_slug` (line 59) asserts only
  `any("bad-course" in str(e) for e in errors)`. That is exactly why the
  E001 → E002 change would otherwise pass green.
- **`freedom_ls/conftest.py:56-75`** autouse-clears the loader cache around every
  test. E003 never calls `get_course_access_backend()`, so its tests need none of
  the `cache_clear()` ceremony `loader.py` documents.
- **`app_configs` contract:** the existing course_access checks declare
  `app_configs` and then ignore it (`checks.py:28,78`). The two new checks honour
  it, so the module will hold both behaviours. Retrofitting the existing two is
  out of scope.
- **`ROOT_URLCONF` has no default** in `django/conf/global_settings.py`, so
  `settings.ROOT_URLCONF` raises `AttributeError` — not `ImproperlyConfigured` —
  on a project that never set one. Django's own `check_url_config`
  (`django/core/checks/urls.py`) reads it as `getattr(settings, "ROOT_URLCONF",
  None)`. W001 must do the same or it can break `manage.py check` outright.
- **The W001 premise is confirmed, not assumed.** `sitemap.xml` ships only at
  `django/contrib/sitemaps/templates/sitemap.xml`, and this project reaches it
  through `django.template.loaders.app_directories.Loader`
  (`config/settings_base.py:180`; `APP_DIRS` is commented out at line 172). That
  loader enumerates installed app configs only, so dropping the app makes
  `/sitemap.xml` raise `TemplateDoesNotExist`. No implementation-time
  confirmation step is needed.
- **`freedom_ls/tests/app_guards.py::app_not_installed`** already wraps
  `apps.is_installed()` for exactly the "is this optional app present" question,
  and `freedom_ls/course_access/tests/test_access_override.py:21` uses it. Reuse
  it in the new test modules rather than re-deriving the call.
- **`django.contrib.sitemaps` and `freedom_ls.learner_interface` both define no
  models**, so removing either via `@override_settings(INSTALLED_APPS=...)` is
  registry-safe. `freedom_ls.course_applications` does own `CourseApplication`,
  but nothing outside that app declares a model FK to it — only factories, QA
  commands and tests import it — so that override is safe too.

## T1 — Tests first (RED)

### T1.1 `freedom_ls/course_access/tests/test_checks.py`

Update the existing `access_config` assertions to expect `E002`:

- `test_bad_access_config_produces_error` and `test_error_includes_course_slug`
  assert no ID at all today (see Ground truth), so the re-ID would pass green
  without them. Add an explicit
  `assert errors[0].id == "freedom_ls_course_access.E002"` to both.
- Leave `test_unset_backend_reports_required_setting_error` asserting `E001`
  — it is the regression guard for success criterion #4.

Add a `TestCourseAccessBackendAppInstalledCheck` class:

- Fires (primary): point `COURSE_ACCESS_BACKEND` at a `freedom_ls.` path that
  lives in no installed app — e.g.
  `@override_settings(COURSE_ACCESS_BACKEND="freedom_ls.not_an_app.backends.Backend")`
  → one Error with id `freedom_ls_course_access.E003`.
  `get_containing_app_config` only prefix-matches installed app *names*, so this
  exercises the real branch with no app-registry churn and no import.
- Fires (the realistic scenario, success criterion #1):
  `@override_settings(COURSE_ACCESS_BACKEND="freedom_ls.course_applications.backends.ApplicationCourseAccessBackend")`
  plus an `INSTALLED_APPS` without `freedom_ls.course_applications` → the same
  Error. **Required** — it is the only test that exercises criterion #1 as
  written. `course_applications` owns `CourseApplication`, migrations and a
  `config/urls.py:65` include, so the override forces a full registry
  repopulation, but no model outside that app FKs to it (see Ground truth), so
  the repopulation is clean. The synthetic-path test above stays as the cheap
  always-stable companion.
- Silent for the reference config (the shipped backend with its app installed).
- Silent for a non-FLS path — `@override_settings(COURSE_ACCESS_BACKEND="config.access.MyBackend")`
  → `[]`, even though no app contains it. This is the false-positive guard.
- Silent when the setting is unset (`COURSE_ACCESS_BACKEND=""`) → `[]`, because
  E001 owns that condition.
- `app_configs` early-return: passing an unrelated app config → `[]`.

### T1.2 `freedom_ls/learner_interface/tests/test_checks.py` (new)

- Fires: `INSTALLED_APPS` without `django.contrib.sitemaps`, with the default
  URLconf (which wires `sitemap`) → one Warning, id
  `freedom_ls_learner_interface.W001`.
- Silent under the reference settings (sitemaps installed).
- Silent when no `sitemap` URL is wired — `@override_settings(ROOT_URLCONF=...)`
  pointing at a module with no `sitemap` name, and no `django.contrib.sitemaps`.
- Silent when there is no `ROOT_URLCONF` —
  `@override_settings(ROOT_URLCONF=None)` with `django.contrib.sitemaps` absent
  → `[]`. This guards the `getattr` in T4.1: without it the check raises
  `AttributeError` and takes `manage.py check` down with it.
- Silent when `freedom_ls.learner_interface` is not installed — the
  `apps.is_installed()` gate. Assert the precondition with
  `freedom_ls.tests.app_guards.app_not_installed` rather than a fresh
  `apps.is_installed()` call.
- `app_configs` early-return honoured.

Note for whoever writes these: `@override_settings(INSTALLED_APPS=...)` triggers
an app-registry reload, so build the list by filtering
`settings.INSTALLED_APPS` rather than hand-writing a short one.

## T3 — Add `freedom_ls_course_access.E003`

New `@register()` function in `freedom_ls/course_access/checks.py`, alongside the
existing two. Local imports inside the body, matching the module's style.

```python
@register()
def check_course_access_backend_app_installed(
    app_configs: Sequence[AppConfig] | None, **kwargs: object
) -> list[CheckMessage]:
    from django.apps import apps

    from freedom_ls.course_access.config import config

    if app_configs is not None and not any(
        c.label == "freedom_ls_course_access" for c in app_configs
    ):
        return []
    if config.missing_required():
        # An unset backend is E001's business.
        return []
    dotted = config.COURSE_ACCESS_BACKEND
    if not dotted.startswith("freedom_ls."):
        # A downstream's own backend lives outside any FLS app; whether it
        # loads is the conformance suite's question, not this check's.
        return []
    if apps.get_containing_app_config(dotted.rsplit(".", 1)[0]) is None:
        return [
            Error(
                f"COURSE_ACCESS_BACKEND {dotted!r} is not provided by any installed app.",
                hint="Add the backend's app to INSTALLED_APPS, or point COURSE_ACCESS_BACKEND at a backend you have installed.",
                id="freedom_ls_course_access.E003",
            )
        ]
    return []
```

No install-gate on `course_access` itself is needed: the module is only imported
from `CourseAccessConfig.ready()`, so an uninstalled app registers nothing.
`get_containing_app_config` does not import the target and returns `None` rather
than raising, so the check cannot raise.

## T4 — Add `freedom_ls_learner_interface.W001`

### T4.1 New `freedom_ls/learner_interface/checks.py`

```python
@register()
def check_sitemaps_app_installed(
    app_configs: Sequence[AppConfig] | None, **kwargs: object
) -> list[CheckMessage]:
    from django.apps import apps
    from django.conf import settings
    from django.core.exceptions import ImproperlyConfigured
    from django.urls import NoReverseMatch, reverse

    if not apps.is_installed("freedom_ls.learner_interface"):
        return []
    if app_configs is not None and not any(
        c.label == "freedom_ls_learner_interface" for c in app_configs
    ):
        return []
    if apps.is_installed("django.contrib.sitemaps"):
        return []
    if not getattr(settings, "ROOT_URLCONF", None):
        return []
    try:
        reverse("sitemap")
    except (NoReverseMatch, ImproperlyConfigured):
        return []
    return [
        Warning(
            "A 'sitemap' URL is wired but 'django.contrib.sitemaps' is not in INSTALLED_APPS.",
            hint="Add 'django.contrib.sitemaps' to INSTALLED_APPS, or remove the sitemap URL.",
            id="freedom_ls_learner_interface.W001",
        )
    ]
```

Both gates use `apps.is_installed()`, never `name in settings.INSTALLED_APPS`:
that setting legitimately holds AppConfig dotted paths (this project's own
`config/settings_base.py:74` lists `django_cotton.apps.SimpleAppConfig`), so a
string test would misread a downstream that names either app by its config class.
`apps.is_installed()` compares `app_config.name`
(`django/apps/registry.py:242-249`); precedent at
`freedom_ls/contrib/conformance/_registry.py:28-29`.

The sitemaps gate comes before `reverse()` so a correctly-configured project
never loads the URLconf during checks.

`ROOT_URLCONF` must be read through `getattr(..., None)`, never as
`settings.ROOT_URLCONF`: it has no `global_settings` default, so a project that
never set one raises `AttributeError`, which the `except` clause does not catch
and which would break `check`/`runserver`/`migrate` with a raw traceback.
`ImproperlyConfigured` is still caught, but for the case it actually covers — a
`ROOT_URLCONF` that imports yet exposes no `urlpatterns`. The residual the spec
accepts (a URLconf that raises on import for some other reason) is unchanged.

## Downstream-visible change

The `E001` → `E002` re-ID must be called out at SDD step 11
(`/fls-dev:update_upgrade_notes`) with `requires_settings_change: true` and
`changed_settings` naming `SILENCED_SYSTEM_CHECKS`: a project silencing
`freedom_ls_course_access.E001` for access-config reasons must **remove** that
entry and add `.E002`. Adding `.E002` alone silently keeps the
missing-required-setting error suppressed.
