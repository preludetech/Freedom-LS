New module `freedom_ls/base/images.py`. `content_engine --> base` and `organisations --> base` both
already exist in `docs/app_structure.md`, so this adds no inter-app edge.

Move, do not copy, the reasoning currently sitting as comments at
`freedom_ls/organisations/validators.py:72-101`:

```python
DECODE_FAILURES = (OSError, Image.UnidentifiedImageError, SyntaxError, ValueError)
BOMB_FAILURES = (Image.DecompressionBombWarning, Image.DecompressionBombError)


@contextlib.contextmanager
def bomb_warnings_as_errors() -> Iterator[None]:
    """..."""
    with warnings.catch_warnings():
        warnings.simplefilter("error", Image.DecompressionBombWarning)
        yield
```

The docstring must say that a caller which does *not* wrap its decode in this is choosing to decode
the warning band, and why the two callers in this repo choose differently: `check_logo_safety` is
refusing an untrusted upload, so it escalates; `optimise_image` is processing an author's own file,
where escalating would classify a legitimate 90-179 megapixel photo as unprocessable and store it at
full size. `Image.MAX_IMAGE_PIXELS` stays at Pillow's default in both, and
`ImageFile.LOAD_TRUNCATED_IMAGES` is never set anywhere — it is global, and `check_logo_safety`
depends on truncated files failing to decode.

Then rewrite `check_logo_safety` to import all three from `freedom_ls.base.images` and drop its local
`warnings` import and inline tuples. Its two `except` clauses become `except BOMB_FAILURES` and
`except DECODE_FAILURES`; its `with warnings.catch_warnings(): warnings.simplefilter(...)` becomes
`with bomb_warnings_as_errors():`.

**Prove:** `uv run pytest freedom_ls/organisations/tests/test_validators.py` passes with the test file
untouched. That is the whole acceptance test for this step — the behaviour is unchanged by

## Step 3 — The optimiser, `freedom_ls/content_engine/images.py`

The core of the feature. No Django or ORM imports; stdlib plus `PIL` plus `freedom_ls.base.images`
only. Build it test-first, one behaviour at a time, in roughly the order below — each new test
should fail for the right reason before the code exists.

### 3a. The contract

```python
class ImageEncodeStatus(StrEnum):
    OPTIMISED = "optimised"
    KEPT_SOURCE = "kept source"
    PASSTHROUGH = "passthrough"
    UNDECODABLE = "could not decode"


@dataclasses.dataclass(frozen=True)
class ImageEncodeDecision:
    status: ImageEncodeStatus
    source_format: str | None
    source_size: tuple[int, int] | None
    data: bytes | None
    suffix: str | None
    mime_type: str | None
    lossless: bool | None
    stored_size: tuple[int, int] | None
    error: str | None
```

`data is None` means "store `raw` unchanged" — SVG, animation, undecodable bytes, an already-small
WebP and the never-grow guardrail all collapse to it, so the caller has exactly one branch and can
never pair one branch's bytes with the other's name. `data`, `suffix`, `mime_type`, `lossless` and
`stored_size` are set together or not at all and are `None` unless `status` is `OPTIMISED`. `error`
is the mirror: `f"{type(err).__name__}: {err}"` when `status` is `UNDECODABLE`, `None` otherwise.
`source_format` and `source_size` are filled in whenever Pillow decoded far enough to know them and
are both `None` when it did not — a PNG whose `IHDR` is too short fails inside `Image.open` itself,
before there is a format to name, which is why `source_format` is `str | None`.
Give the class a docstring; the field group rule belongs in it.

### 3b. The constants

Each gets a comment. `LOSSLESS_EFFORT`'s comment must say that under `lossless=True` the `quality=`
argument is encode *effort*, not fidelity, and that it is therefore not commensurable with
`LOSSY_QUALITY` even though both are passed through the same parameter.

```python
MAX_DIMENSION_PX = 1600
LOSSY_QUALITY = 80
LOSSLESS_EFFORT = 100
ENCODE_METHOD = 6
SECOND_ENCODE_BYTES = 250 * 1024
LOSSY_WINS_DIVISOR = 3
SVG_SUFFIXES = {".svg"}
```

`SVG_SUFFIXES`' comment records that `.svgz` is deliberately absent because
`get_file_type_from_extension` (`content_save.py:442`) does not list it, so a `.svgz` is never
`FileType.IMAGE` and cannot reach here.

### 3c. `_encode`

```python
def _encode(img: Image.Image, icc: bytes | None, *, lossless: bool) -> bytes:
    buf = io.BytesIO()
    img.save(
        buf,
        format="WEBP",
        lossless=lossless,
        quality=LOSSLESS_EFFORT if lossless else LOSSY_QUALITY,
        method=ENCODE_METHOD,
        icc_profile=icc,
    )
    return buf.getvalue()
```

Nothing else is passed. `exact` and `alpha_quality` keep their defaults; `save_all` is never set,
because animated inputs never reach here. `icc=None` is safe — Pillow collapses it to no profile.

Comment the metadata asymmetry above this function: Pillow's WebP `_save` reads `exif`, `xmp` and
`icc_profile` from `encoderinfo` only, never from `img.info`, and `Image.save()` does not merge the
two, so *not* passing EXIF is what drops it (along with the GPS coordinates phones attach), and the
ICC profile is the one thing that has to be passed back deliberately. This is WebP-specific — the
JPEG and PNG save paths do read from `info`. Say so, or someone will later "fix" this toward
libwebp's `-mixed` behaviour, which dual-encodes and takes the smaller bitstream. That suits
animation frames, where both candidates are equally acceptable. Here they are not.

### 3d. `optimise_image`

`def optimise_image(raw: bytes, suffix: str) -> ImageEncodeDecision`. The order is load-bearing and
getting it wrong fails silently, so keep it exactly as written:

```
1.  suffix.lower() in SVG_SUFFIXES        -> PASSTHROUGH, source_format="SVG", source_size=None
    (before any decode; Pillow has no SVG codec, and get_file_type_from_extension lowercases too,
     so DIAGRAM.SVG is an IMAGE and must not fall through to a decode it cannot survive)

    source_format: str | None = None       # both stay None when Image.open itself
    source_size: tuple[int, int] | None = None   # raises: there is no format to name yet
    try:                                   # catches BOMB_FAILURES and DECODE_FAILURES;
        with Image.open(io.BytesIO(raw)) as opened:   # no bomb_warnings_as_errors here
2.          #  ^ BytesIO, not the file handle: it keeps backing the lazy image
3.          source_format = opened.format
            source_size = opened.size      # read before draft() and thumbnail(), which
                                           # both mutate size in place
4.          if source_format != "MPO" and getattr(opened, "n_frames", 1) > 1:
                return PASSTHROUGH         # getattr, not is_animated: JpegImageFile and
                                           # BmpImageFile define neither. MPO is excluded
                                           # because phone .jpg files open as MPO with
                                           # n_frames == 2 and would pass real 5 MB photos
                                           # through untouched.
5.          if source_format == "WEBP" and max(source_size) <= MAX_DIMENSION_PX:
                return PASSTHROUGH         # re-encoding buys nothing and spends a generation
6.          opened.draft(None, (MAX_DIMENSION_PX * 2, MAX_DIMENSION_PX * 2))
                                           # no-op for non-JPEG; libjpeg DCT scaling otherwise.
                                           # must run before exif_transpose(): draft() works
                                           # only on an unloaded image, and exif_transpose()
                                           # calls load()
7.          img = ImageOps.exif_transpose(opened)      # returns a new image, never None;
                                                       # calls load(), where a corrupt body raises
8.          icc = opened.info.get("icc_profile")
            tags = opened.getexif()        # getexif(), never img.info["exif"], so a PNG
            camera_exif = bool(tags.get(ExifTags.Base.Make) or tags.get(ExifTags.Base.Model))
    except BOMB_FAILURES + DECODE_FAILURES as err:
        return UNDECODABLE with error=f"{type(err).__name__}: {err}"

9.  source_mode = img.mode
    if source_mode not in ("RGB", "RGBA"):
        img = img.convert("RGBA" if img.has_transparency_data else "RGB")
        if source_mode not in {"RGB", "RGBX", "RGBA", "RGBa", "P", "PA"}:
            icc = None                     # Image._new copies info through convert(), so a CMYK
                                           # or greyscale profile would otherwise ride along
                                           # describing a colour space the pixels have left
10. img.thumbnail((MAX_DIMENSION_PX, MAX_DIMENSION_PX), Image.Resampling.LANCZOS)
                                           # statement, not assignment: mutates and returns None.
                                           # Square box == longest-edge cap with no orientation
                                           # branch. thumbnail returns early when it already fits,
                                           # which is where "never upscale" comes from;
                                           # ImageOps.contain has no such guard. Both default to
                                           # BICUBIC, so pass LANCZOS explicitly.
11. encoded, lossless = <the encode rule>
12. if len(encoded) >= len(raw):
        return KEPT_SOURCE                 # strict: a tie keeps the source rather than churning
                                           # the extension and MIME type for nothing
    return OPTIMISED(data=encoded, suffix=".webp", mime_type="image/webp",
                     lossless=lossless, stored_size=img.size)
```

Steps 2-8 all still read `opened`, so they sit inside one guarded block and inside the `with`.
Step 9 onward operates on the fully-loaded `img` and cannot raise a decode error.

The two corrupt-PNG fixtures fail at structurally different points and are not interchangeable.
`shorten_png_ihdr` raises `ValueError` inside `Image.open` itself, before `source_format` exists —
which is why both names are initialised above the `try`, and why the dataclass types
`source_format` as `str | None`. `break_png_chunk_crc` parses its header cleanly and raises
`SyntaxError` later, inside `exif_transpose`'s `load()`, by which point both are already set. Get
the initialisation wrong and the first fixture raises `UnboundLocalError` straight out of
`optimise_image`, breaking the one invariant this function has.

The encode rule, verbatim from the spec:

```python
if source_format in ("JPEG", "MPO"):
    encoded, lossless = _encode(img, icc, lossless=False), False
else:
    candidate = _encode(img, icc, lossless=True)
    if not camera_exif and len(candidate) <= SECOND_ENCODE_BYTES:
        encoded, lossless = candidate, True
    else:
        lossy = _encode(img, icc, lossless=False)
        if len(lossy) * LOSSY_WINS_DIVISOR <= len(candidate):
            encoded, lossless = lossy, False
        else:
            encoded, lossless = candidate, True
```

Comment why a JPEG source gets one lossy encode and no comparison: the pixels are already lossily
compressed, so a lossless encode preserves the existing artefacts bit-exactly at several times the
bytes. And why the size floor gates the comparison: lossy WebP always chroma-subsamples, which is
what smears coloured text and thin lines, so raising `LOSSY_QUALITY` never fixes a screenshot;
gating behind a 250 KB lossless result keeps screenshots out of the comparison entirely and leaves
the 3x ratio to arbitrate only large images, which are overwhelmingly photographs. Integer
arithmetic on both sides of the comparison — no floats.

Nothing raises out of `optimise_image`. One bad file must neither abort a run over a whole content
repository nor vanish from it. WebP's 16383 px format limit surfaces as `ValueError`, already inside
`DECODE_FAILURES`, and is unreachable while `thumbnail` is called unconditionally.

### 3e. What to prove, in `freedom_ls/content_engine/tests/test_optimise_image.py`

No database, no `django_db` marker, no fixtures beyond the builders from step 2.

- **Format and cap.** A large JPEG comes back `OPTIMISED`, `mime_type == "image/webp"`, both
  `stored_size` edges ≤ 1600, and fewer bytes than the source. A 900x600 source keeps exactly
  `(900, 600)` — never upscaled.
- **The rule.** A JPEG takes the single-lossy path (`lossless is False`). A small screenshot PNG
  comes back `lossless is True`. A large photographic PNG, and a PNG carrying camera EXIF, both reach
  the comparison. Parametrize the two sides of `LOSSY_WINS_DIVISOR` and assert *which candidate won*
  (`decision.lossless`), never a byte count.
- **Orientation.** The orientation-6 fixture comes out with width and height the way a viewer shows
  them, not the way the raw buffer stored them.
- **Colour and metadata.** An ICC-tagged RGB source keeps `info["icc_profile"]` in the output. A CMYK
  source does not. `Image.open(io.BytesIO(decision.data)).getexif()` is empty, including for the
  GPS-tagged fixture.
- **Transparency.** A `P`-mode PNG with `tRNS` and an `RGBA` PNG both come out with
  `has_transparency_data` true, and the resized output contains no palette-index colour bleed (assert
  the output's colour set stays within the source's, rather than eyeballing).
- **Pass-through and failure.** SVG, animated GIF and an already-small WebP each come back
  `PASSTHROUGH` with `data is None`; each corrupt-PNG fixture comes back `UNDECODABLE` with
  `data is None` and an `error` naming the exception type. Assert the two corrupt fixtures
  separately: `shorten_png_ihdr` comes back with `source_format is None`, `break_png_chunk_crc` with
  `source_format == "PNG"`. Collapsing them into one parametrized case hides the failure-before-open
  path entirely. Assert the *status*, not merely that
  nothing was encoded — otherwise the four cases stay indistinguishable and step 5's output cannot be
  trusted. Every non-`UNDECODABLE` decision has `error is None`. An MPO-format `.jpg` is `OPTIMISED`,
  not mistaken for animation.
- **Never grow.** The tiny already-optimised PNG comes back `KEPT_SOURCE` with `data is None`.
- **Determinism.** `optimise_image(raw, ".jpg").data == optimise_image(raw, ".jpg").data`. Run-to-run
  stability only — **no** committed golden file or digest. Pillow re-cuts wheels with new bundled
  libwebp versions independently of this repo, and libwebp's output is not promised stable across its
  own versions, so a golden hash turns a routine `uv lock --upgrade-package pillow` into a red test
  with no defect behind it.

## Step 4 — The ingest call site, `save_file_to_db`

`freedom_ls/content_engine/management/commands/content_save.py:459-497`. Restructure so the bytes are

```python

        if decision.data is not None:
            mime_type = decision.mime_type

    file_obj, created = File.objects.get_or_create(... defaults with mime_type or "" ...)
    if not created:
        ...  # same three assignments, now with the post-encode mime_type

    if file_obj.file:
        file_obj.file.delete(save=False)

    if decision is not None and decision.data is not None:
        file_obj.file.save(
            file_path.with_suffix(decision.suffix).name,
            ContentFile(decision.data),
            save=True,
        )
    else:
        with open(file_path, "rb") as f:
            file_obj.file.save(file_path.name, DjangoFile(f), save=True)

    click.echo(...)
    return decision
```

Points that are easy to get wrong:

- **`mime_type` must be assigned before the write at `:494`.** That `FieldFile.save(..., save=True)`
  is the only DB write in the function, and it is what persists the metadata mutations at `:483-485`.
  Both the `defaults=` dict at `:471-479` and the update branch at `:482-485` need the post-encode
  value.
- **`file_obj.file.delete(save=False)` stays, and stays first.** `course_media` is excluded from
  `_OVERWRITE_PURPOSES` (`freedom_ls/deployment/storage.py:43`), so a write at an existing key is
  *renamed* rather than replaced. Deleting first is what keeps `content_engine/photo<uuid>.webp`
  stable across runs and what stops the superseded `.jpg` object being orphaned in the bucket when
  the extension changes.
- **`File.file_path` and `File.original_filename` are never touched.** `file_path` is the unique key
  (`files.py:53-58`) and the key `<c-picture src="...">` resolves against, which is what keeps
  existing content working with no content edit. `original_filename` stays the author's `photo.jpg`.
- **Only an image is read into memory.** `read_bytes()` sits inside the `IMAGE` branch. A course's
  `video.mp4` or PDF handbook keeps today's streamed `DjangoFile(f)` path — buffering every
  non-image file whole, so that two image-only branches have `raw` available, is a cost paid by
  files that get no benefit from it. That is also why `data is None` re-opens the file rather than
  keeping `raw` alive: "store it unchanged" and "store what is on disk" are the same thing.
- `django.core.files.File as DjangoFile` (imported at `:19`) **stays** — it is still the non-image
  path. Add `django.core.files.base.ContentFile` alongside it.
- The delete is hoisted out of the `with open(...)` block so the delete-first invariant is stated
  once, and only the `FieldFile.save()` call differs between the two branches.
- `optimise_image` is called with `file_path.suffix` — the raw suffix. `optimise_image` does the
  lowercasing.

Then in `save_content_to_db` (`:511-518`), collect what `save_file_to_db` returns:

## Step 5 — Author-facing output

`content_save.py:497` is `logger.info`, and `LOGGING` is configured only in
`config/settings_prod.py:95`. `config/settings_dev.py` and `config/settings_base.py` have none, and
`pyproject.toml:75` and `manage.py:10` both default to `settings_dev` — so an author running the
command locally sees no per-file line at all today. That is the bug this step fixes.

- **Move the per-file line at `:497` and the closing line at `:707` to `click.echo`.** `djclick` is
  already imported at `content_save.py:13` and this is a CLI command with a human at the keyboard.
