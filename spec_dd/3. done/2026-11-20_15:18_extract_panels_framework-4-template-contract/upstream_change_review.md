# Upstream-change review: extract_panels_framework-4-template-contract

direction: changed

## What main gained

Spec 3 (`extract_panels_framework-3-standalone-backend`, now in `spec_dd/3. done/2026-11-19_06:59_extract_panels_framework-3-standalone-backend/`) landed. The framework owns its settings helper: `freedom_ls/panel_framework/app_settings.py` holds `Setting` and `AppSettings` (copies of the `freedom_ls.base` ones), and `config.py:25-44` declares settings as `PanelFrameworkConfig(AppSettings)` with a class annotation plus an entry in `declared_settings = {"NAME": Setting(default=...)}`. It already declares `BULK_BACKGROUND_THRESHOLD`, `PANEL_TABLE_PAGE_SIZE` and `PANEL_FRAMEWORK_SITE_RESOLVER`. `config/settings_base.py:638` sets the resolver for FLS.

The framework's system checks now use more ids. `checks.py` has `freedom_ls_panel_framework.W001` (`check_task_backend`, a non-durable task backend, line 77) and `W002` (`check_site_resolver`, line 114), besides E001-E008. Both are registered in `apps.py`.

The framework unit tier runs with no FLS. `tests/standalone_pytest.ini` points at `tests/standalone_settings.py`, which uses in-memory SQLite, `tests/standalone_app/` as the user model, and `tests/standalone_templates/` as `DIRS[0]`. The stand-in templates are `_base.html`, `_base_interface.html`, `partials/form.html`, `partials/page_title.html` and `cotton/{icon,button,button-group,chip,callout,back-link,pagination,dropdown-menu,dropdown-menu-separator,date,datetime,page}.html`. Each is a bare-bones fixture that uses the host's unprefixed names. The spec says they are "test fixtures, not spec 4's components". The marker `needs_fls_host` deselects tests that need FLS's real templates, icons or URLconf (`test_reference.py` lines 279, 352, 366, 376 and 389; `test_tables.py` lines 2264, 2271 and 2278). The spec defines it as "deselected in the standalone run until spec 4".

`tests/test_import_guard.py` fails on any `freedom_ls` import outside the framework. It exempts `tests/components`, `tests/invariants` and `tests/playwright`. Spec 3 says "Spec 4 removes them".

`field_display.py:74-75` now owns `DATE_DISPLAY_FORMAT = "j M Y"` and `DATETIME_DISPLAY_FORMAT = "j M Y, H:i"`. FLS's `base/date_display.py` is the original. `educator_interface/tests/invariants/test_framework_copies_match_base.py` pins these constants, plus `escape_csv_formula`, `EchoWriter`, `Setting`, `AppSettings`, `FORMULA_TRIGGERS`, `UTF8_BOM` and `_E164_PHONE_NUMBER`, to their originals. Its `SAME_SOURCE` and `SAME_VALUE` lists are the convention for "a private copy must match": `panel-framework/SKILL.md` says "Change a helper in both places at once". `testing/SKILL.md` documents the standalone command and the marker.

`docs/app_structure.md` is unchanged in substance. `panel_framework` still depends on `accounts` and has only the dotted edge to `base` (lines 294 and 344). No app boundary moved.

## Why it matters for this spec

1. **Check id collision (`1. spec.md`, "System checks", lines 207-221, and Testing, line 327).** The spec gives `W001` to "icon component rendering empty". `W001` is already `check_task_backend`, and `W002` is taken too. Two checks sharing an id would break `SILENCED_SYSTEM_CHECKS` and the existing `test_checks.py`. `E009` and `E010` are still free (the framework's highest error is E008), so they stand. The spec's own line "Ids continue the existing sequence" requires the icon warning to take the next free warning id, `W003`.
2. **Settings helper (`1. spec.md` "Out" line 45 and "Setting" lines 223-233).** The spec defers "whatever settings helper `config.py` uses when it lands". It has landed, and `idea.md` line 22-23 says "read through the framework's `AppSettings`". The spec should now say how the setting is declared: an annotation plus a `Setting(default=...)` entry in `PanelFrameworkConfig.declared_settings`, read as `config.PANEL_REFERENCE_BASE_TEMPLATE`. "Whichever lands second rebases" is settled. This is a wording fix, not a changed decision.
3. **Spec 3's stand-in templates and standalone settings are not mentioned (`1. spec.md` "Minimal shell", "Test tiers", lines 264-305).** Spec 4 assumes `tests/templates/panel_framework/test_interface.html` and `test_component_reference.html` extend the FLS `_base_interface.html` and `_base.html`. In the standalone run those resolve to spec 3's stand-ins in `standalone_templates/`. After spec 4:
   - Framework templates call `c-panel-*` and `panel_framework/partials/page_title.html`, so the stand-in `cotton/{button,button-group,chip,callout,back-link,pagination,dropdown-menu,dropdown-menu-separator,date,datetime,page}.html`, `partials/page_title.html`, `_base.html` and `_base_interface.html` are dead code.
   - Stand-in `cotton/icon.html` and `partials/form.html` remain needed, unless spec 4 changes how the framework reaches a form partial.
   - The spec must say what happens to them. The coherent answer is to delete the dead stand-ins, leave `icon.html`, and make the minimal shell what the standalone run renders.
   - `_use_panel_test_templates` (spec line 293-296) must be reconciled with `standalone_settings.py:45`. The conftest prepends `[tests/templates, framework/templates, *existing]`, and in the standalone run `existing` is the stand-in directory, so the order must be stated. A stale stand-in `partials/page_title.html` or `_base.html` must not shadow the framework's files.
4. **`partials/form.html` is an unmentioned FLS partial.** `modal/form.html:24`, `partials/reason_field.html:6` and `reference/_examples.html:506,516` include it. Spec 3 had to ship a stand-in for it. The spec's Purpose says templates "include an FLS partial", but only `page_title.html` is handled. The "no template includes a path outside `panel_framework/`" invariant (spec line 309-311) will fail on `partials/form.html`, and the host contract has no row for it. The spec must either move or copy it into the framework (with an FLS thin include as for `page_title`) or list it in the host contract. Its first grep success criterion does not cover it either.
5. **`needs_fls_host` and "until spec 4" (spec 3's "Terminology" line 20).** The spec does not say whether the marker is retired. Once the minimal shell and framework primitives exist, the `test_reference.py` tests marked at lines 279-389 may need only `PANEL_REFERENCE_BASE_TEMPLATE`. The spec must state which marked tests lose the marker, and that standalone settings run the autouse `PANEL_REFERENCE_BASE_TEMPLATE` fixture. It also needs a new standalone-run requirement: the new tier tests (primitive contract, icon checks, the `write_panel_framework_css` command) run in `standalone_pytest.ini` where they can, because `c-icon` is the stand-in and the E010/W003 icon check renders it. `testing/SKILL.md` documents the marker, so the skill update (spec "Documentation and downstream") must keep that text true.
6. **Import guard exemptions and playwright helpers (spec lines 297-299).** Spec 3 pinned `tests/components`, `tests/invariants` and `tests/playwright` as exempt "until spec 4 removes them". Spec 4 copies `freedom_ls.tests.playwright_helpers` into the framework but never states that the exemption tuple is removed. It should say so, as a requirement with `test_import_guard.py` as the proof, and say that the component, invariant and Playwright tests import nothing from `freedom_ls`. Today `tests/invariants/test_templates.py:31` still reads `FREEDOM_LS_PACKAGE_DIR`.
7. **Copies pinned by `test_framework_copies_match_base.py`.** The spec's copies (the `pagination_suffix` copy in `data_table_tags`, the playwright helper copies, the primitive templates) have no drift guard of the kind spec 3 established. The Testing section covers primitive output equality under FLS settings only, not the `pagination_suffix` source or the helpers. The spec should add the `pagination_suffix` copy and the playwright helpers to the `SAME_SOURCE` list in that test, or explain why a different guard is enough. The `panel-framework` skill text ("Change a helper in both places at once") should then be extended.
8. **Date formats (`panel-date`/`panel-datetime`, spec line 140).** "A documented format" is now concrete. The framework owns `j M Y` and `j M Y, H:i` (`field_display.py:74-75`). The framework's `as_of.html` uses `{{ as_of|date:"T" }}` beside `c-datetime`. FLS's `c-date`/`c-datetime` convert an aware datetime to the current zone (`base/date_display.py:16-39`), and the framework templates must do the same (the Django `date` filter converts to the current time zone for an aware value, which matches). The spec should (a) pin the two format strings, (b) require a test that the format strings in the templates equal `field_display.DATE_DISPLAY_FORMAT` and `DATETIME_DISPLAY_FORMAT`, because `test_framework_copies_match_base.py` pins only the constants and not the template literals, and (c) say `short` is accepted but not rendered by the framework default (or implement it as `j M`). `panel-date` is called from `data-table-cells/date.html`, `_details_value.html` and `as_of.html`.
