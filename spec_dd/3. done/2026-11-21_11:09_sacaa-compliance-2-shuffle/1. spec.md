# Spec: shuffle quiz pages, questions and answer options

Idea: `idea.md`. Up-front answers: `answers.md`. Research: `research_codebase.md`,
`research_best_practices.md`, `research_reference_implementations.md`, `research_prior_art.md`,
`research_ux_patterns.md`, `research_known_complaints.md`, `research_randomization_ux_integrity.md`.

## Purpose

A QUIZ form serves every learner the same order, so learners can pass "question 3 is B" to each
other. Authors get three independent opt-in knobs that shuffle pages, page children and answer
options once per sitting. Two controls keep a shuffled quiz correct: an option lock and a
keep-together group. The shuffled order goes into the served paper that
`sacaa-compliance-1-served-paper-record` built.

## Terminology

| Term | Status | Meaning / source |
| --- | --- | --- |
| keep-together group | coined | The `FormContent` and `FormQuestion` children of one page that share a `group` value. They form one contiguous run and move as one block. Unrelated to `Cohort` or Django's auth `Group`. |
| shuffle unit | coined | A list of page children that moves as one in a page's shuffle: a keep-together group, or a single ungrouped child. `sacaa-compliance-3-question-pools` draws the same units. |
| locked option | coined | A `QuestionOption` with `locked: true`. It keeps its authored index while the other options shuffle. A position lock, not an access lock. |

"Sitting" means `FormProgress`, as in the domain glossary, and "served paper" means
`FormProgress.served_paper`.

## Scope

In: the form-level knobs `shuffle_pages`, `shuffle_questions` and `shuffle_options`, the option
`locked` flag and the `group` key on content blocks and questions (schema, models, migration,
validator, `content_save`); shuffling inside `build_served_paper`; the results-page "Question N"
label; the `fls-content` authoring documentation and a shuffled demo quiz.

Out: everything `idea.md` lists as out of scope. At this spec's edges that means the served-paper
storage, path, navigation, resume and scoring (spec 1), question pools (spec 3), the educator
per-attempt view and export (spec 4), and the admin, which does not expose the sibling fields
(`submit_on_exit`, `correct`) either. A positional-wording lint, a learner-facing "this quiz is
shuffled" notice and an educator-preview hint are also out.

## Decisions

- **The seed drives the shuffle, and the stored lists stay the record.** The existing 63-bit
  `secrets` seed in the served paper seeds a private `random.Random` for each scope:
  `f"{seed}:pages"`, `f"{seed}:page:{page.id}"` and `f"{seed}:options:{question.id}"`, so editing
  one page does not reorder another. `random.shuffle` output is not stable across Python versions,
  so nothing rebuilds an order from the seed. The module-level `random` functions and
  `random.seed()` are never used.
- **A group is a string, not a model** (`answers.md`). A `group` value appears in one contiguous
  run per form, so nesting cannot be written. The split-group rule in the validator is the
  nesting error.
- **Groups are allowed when `shuffle_questions` is off** (`answers.md`). There they are a no-op,
  and question pools will draw them as units.
- **The knobs are form-level only, with no page lock** (`answers.md`). `FormPage` forbids extra
  keys, so a knob in a page header already fails the schema.
- **The served paper keeps spec 1's shape** (`seed`, `pages[{id, children}]`, `options`).

## Requirements

### Schema (`freedom_ls/form_engine/schema.py`)

- `Form`: add `shuffle_pages`, `shuffle_questions` and `shuffle_options`, each `bool = False`. A
  plain `bool` dumps `False`, so removing a key from the file resets the stored value.
  `validate_quiz_fields` raises when any of them is `True` on a non-QUIZ strategy, in that
  method's existing wording: `shuffle_options should only be set when strategy is QUIZ (in <path>)`.
- `QuestionOption`: add `locked: bool = False` beside `correct`.
- `FormContent` and `FormQuestion`: add `group: str | None`. A value that is empty after
  stripping, or that has leading or trailing whitespace, is a schema error. Its maximum length
  matches the model field.

### Models and migration (`freedom_ls/form_engine/models.py`)

- `Form`: three `BooleanField(default=False)` fields, with help text in the style of
  `submit_on_exit`.
- `FormContent` and `FormQuestion`: `group = CharField(max_length=100, blank=True, default="")`.
- `QuestionOption`: `locked = BooleanField(default=False)`.
- One new `form_engine` migration of plain `AddField` operations. Existing rows take the opt-out
  defaults.

### `content_save` (`freedom_ls/content_engine/management/commands/content_save.py`)

`save_with_uuid` dumps with `exclude_none=True`, so a `None` group would never be written and a
removed `group:` would leave the stored value. `save_form_content` and `save_form_question` pass
`group=item.group or ""` explicitly, as `save_form_question` already does for `slug`.

### Validator (`freedom_ls/content_engine/validate.py`)

A new pass, `validate_form_shuffle`, is appended to the cross-file passes in `validate()`. The
form, page-file and block-number walk inside `validate_form_conditions` (forms keyed by
`file_path.parent`, `sections_by_file`, sorted page files, block numbering for `_target_label`)
moves into one helper that both passes call. The error block of `_condition_error` gets a
header parameter rather than a copy. The pass reports every error in one run:

| Rule | Problem / fix |
| --- | --- |
| `group` on a content block or question of a non-QUIZ form | `group is only allowed on QUIZ forms (this form is <strategy>).` / `Remove group, or change the form's strategy to QUIZ.` |
| `locked: true` on an option when the form's `shuffle_options` is off (always the case on a non-QUIZ form) | `option "<text>" is locked, but shuffle_options is off for this form, so it never moves.` / `Set shuffle_options: true in the form front matter, or remove locked.` |
| A group value on two pages | `group "<name>" is used on page "<A>" and page "<B>". A group stays on one page.` / `Rename one of the groups, or move its members onto one page.` |
| A group value in two runs on one page | `group "<name>" is split: <child label> sits between its members.` / `Move the members together, or give <child label> the same group.` |

For the split rule, the pass walks each page's children itself, tracking each group's run, so it
can name the first child that breaks it. Labels come from `_target_label`. A one-member group is
valid. So is a group with no content block, or one that starts with a question.

### Shuffle functions (`freedom_ls/form_engine/served_paper.py`)

- `shuffle_units(children: Sequence[T]) -> list[list[T]]`, where `T` is bound to a `Protocol`
  with a read-only `group` property returning `str | None`. A maximal run of consecutive children
  with the same truthy `group` becomes one unit in authored order. Every other child is a
  one-element unit. It takes schema items (`None`) and model rows (`""`) alike. Question pools will
  import it.
- `shuffle_with_locks(items, is_locked, rng)`: locked items keep their absolute index, and the
  rest are shuffled into the free positions. Shuffling everything and swapping the locked ones
  back would bias the order. If every item is locked, or only one is free, the order is unchanged.
- Neither function touches the database or global random state. The RNG is passed in.

### Building the served paper (`build_served_paper`)

`ensure_served_paper` still builds the paper once, when the sitting starts:

- The pages come from `form.pages.all()`, and are shuffled with the pages-scope RNG when
  `form.shuffle_pages` is on.
- Each page's children are `shuffle_units(page.children())`. When `form.shuffle_questions` is on,
  the units are shuffled with that page's RNG. Either way they are then flattened.
- Each question's options are `shuffle_with_locks(options, lambda o: o.locked, rng)` with that
  question's RNG when `form.shuffle_options` is on, and authored order otherwise.
- When all three knobs are off, no RNG is created and the paper equals today's.
- The "provenance only" comment changes to say that the seed drives the one-time shuffle and that
  nothing rebuilds from it.

### Results page

`FormProgress.get_incorrect_quiz_answers` adds a `number` key to each dict it returns. It comes
from `path.question_positions()` when the sitting has a served paper, and from
`question.question_number()` otherwise. The list is in served order. The label at
`learner_interface/templates/learner_interface/course_form_complete.html:105` reads
`item.number`. Free-text questions are not listed, so the numbers can skip. They are the numbers
the learner saw.

Cohort reports, `reports/indexes.py` and the `data-testid` values in `question.html` keep the
authored `question_number`, because a report spans sittings with different orders.

## Testing

- `shuffle_with_locks`: for every seed in a fixed range, the output is a permutation and every
  locked item is at its authored index. Cover: no locks, all locked, one free, a lock at the first
  index, a lock at the last index, two adjacent locks, a lock in the middle. A stub RNG proves the
  free items fill the free positions in shuffled order. A fixed-range distribution check over three
  free options puts each of the six orders inside a wide band.
- `shuffle_units`: runs become units, singletons stay singletons, members keep authored order, on
  both schema items and model rows. Over a seed range, shuffled units leave every group contiguous
  and in order.
- `build_served_paper`: each knob alone and all three together. With all knobs off, an RNG that
  raises when used proves no RNG is touched and the paper is unchanged. Turning one knob off, or
  adding a question to page 1, leaves the other scopes' orders unchanged for the same seed. A
  group on a page with `shuffle_questions` off stays in authored order.
- Validator: one test per rule in the table, including `locked: true` on a non-QUIZ form, plus
  valid cases: a one-member group, a group with `shuffle_questions` off, a lock with
  `shuffle_options` on. A knob on a non-QUIZ form, and a knob in a page header, fail the schema.
  Removing a knob, `locked` or `group` from a file and re-saving resets it.
- Learner flow on a real shuffled paper, with the seed fixed by patching the seed source, never
  `random`: page sequence, child order, numbers and option order in all three input types match the
  paper, with no CSS `order` style. They stay the same across reload, back-navigation, an HTMX page
  post and resume. Page-jump links and `record_page_reached` follow served position. A re-sit gets
  a new paper. The results label shows the served number, and the authored number for a sitting
  with no paper. Score and `max_score` equal those of the same answers on an unshuffled sitting.
- The demo quiz, loaded through `content_save`, gives different orders on two sittings whose seeds
  are patched to different values.

## Documentation and downstream

- `claude_plugins/fls-content/skills/content-types/resources/form-files.md` documents the three
  knobs, `group` and `locked`, and gains a "Shuffling a quiz" section modelled on the `when`
  section. That section states the validator rules and the "reword it, else lock it, else turn
  `shuffle_options` off" order for "All of the above" and "None of these". It also says:
  - a lock fixes a position, not a meaning ("Both A and B" still breaks);
  - shuffled forms have no "see question 3", "the diagram above" or option-letter references;
  - a stimulus is grouped with its questions;
  - instructions go in the form body when `shuffle_pages` is on;
  - authored page numbers show in URLs;
  - shuffling is not proctoring.
- Demo content: a new course, `demo_content/functionality_demo_shuffled_quiz/`, with one QUIZ
  form of at least three pages. All three knobs are on. One "All of the above" option is locked.
  One page holds a group made of a content block with a picture and its two questions, next to
  ungrouped questions. The existing demo quizzes are not changed.

## Open questions

- Q: Should the served paper record group membership for the audit view? → A: No. Groups are read
  from the model rows (assumed default: this keeps spec 1's paper shape and no consumer needs it
  yet; `sacaa-compliance-4-attempt-review` can add it. Overrule by editing Decisions.)
- Q: Should the results page list the correct and selected options in served order? → A: No, they
  stay in authored order (assumed default: they are lists of answers, not an option group, and the
  learner is not choosing from them. Overrule by editing Results page.)
- Q: Should the demo be a new course or a quiz added to an existing demo course? → A: A new course
  (assumed default: existing demo quizzes and their QA keep the authored order. Overrule by editing
  Documentation and downstream.)

## Success criteria

- Existing quiz tests pass unchanged.
- A learner on the demo quiz sees one order through reloads, back-navigation and resume, and a
  re-sit sees another.
- `uv run manage.py content_validate` on the demo content passes. On a copy with a group split
  across two runs, it fails with the split-group message.
