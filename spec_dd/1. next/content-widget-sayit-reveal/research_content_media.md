# Research: content components and media today (for audio widgets)

All paths relative to the repo root. Read-only research.

## 1. How a markdown content component is built end to end

Pipeline (`claude_plugins/fls-dev/resources/markdown_content.md:19-23`, `freedom_ls/markdown_rendering/markdown_utils.py:15-73`): markdown -> nh3 sanitise -> cotton compile (`CottonCompiler.process`) -> Django template render with the content context.

- Template: `freedom_ls/content_engine/templates/cotton/<name>.html`. Starts with `<c-vars ... />` for attribute defaults (e.g. `picture.html:1`, `file-download.html:1`), `{% load content_tags %}`, and a `{% comment %}` block documenting attributes.
- Allowlist: `MARKDOWN_ALLOWED_TAGS` in `config/settings_base.py:390-410`, a dict of tag -> set of allowed attributes. `markdown_utils.py:30-31` adds each key to the markdown block-level elements; `:37-44` adds the keys to nh3 allowed tags and the sets to nh3 attributes. Any tag or attribute not listed is silently stripped by nh3 (no error). The setting is read through `freedom_ls/markdown_rendering/config.py:7-11` (default `{}`); a downstream project overrides the dict. Attribute names are lowercase-compared by nh3, so `video_id` style underscores are fine, but nh3 only allows what is listed. Boolean attrs (`open`) come out as `open=""` (`claude_plugins/fls-content/.../widget-reference/SKILL.md:90`).
- Nothing in the sanitiser allows `<audio>`, `<source>` or `<button>` in author markdown (only nh3 defaults plus `input`, `markdown_utils.py:50-53`). An audio element must therefore be emitted by the cotton template, after sanitising, not written by authors. Raw tags inside the template are fine: the template is trusted, only the markdown body is sanitised.
- Alpine: components must be registered with `Alpine.data()` in `freedom_ls/content_engine/static/content_engine/js/alpine-components.js` (header lines 1-12: the build is `@alpinejs/csp`, so no inline JS expressions in `x-*` attributes, only method/property names; the file must load before Alpine). Existing: `equation` (`:26`), `flashcard` (`:57-62`, `flipped`, `flip()`, `frontStyle()`, `backStyle()`), `contentLightbox` (`:69-99`). Update the header list when adding one.
- Where the bundle loads: `learner_interface/_course_base.html:18`, `_exam_runner_base.html:29`, `blog/article_detail.html:24`, `educator_interface/_shell.html:17`. Any page that renders a component with Alpine state must load it; a new page type rendering markdown must add the script.
- Demo: `demo_content/functionality_demo_content_widgets/` has topics per group: `2. media/content.md` (c-image-grid at lines 46-64), `4. interactive-widgets/content.md` (c-flashcard at 100-160). Media demos reference files by relative path (`demo_content/functionality_demo_end_with_topic/1. topic/content.md:76,78` use `src="sample.pdf"`; `sample.pdf` sits next to the md).
- Authoring plugin `claude_plugins/fls-content`: one reference file per widget at `skills/widget-reference/resources/c-<name>.md` (see `c-flashcard.md`: title, "Allowed attributes", attribute table, slots, examples). The `SKILL.md` has the "All widgets at a glance" table (`:13-33`), a duplicated "Authorised attribute sets" block (`:39-59`, "Each documented set equals the MARKDOWN_ALLOWED_TAGS allowlist exactly") and a resource index (`:95-114`). A new built-in widget needs: a resource file, an entry in all three places in SKILL.md. `claude_plugins/fls-dev/resources/markdown_content.md:63-80` also carries a copy of the allowlist and component list to update. Downstream-only widgets are declared in `.claude/fls-content/widgets/c-*.md` (`custom-widgets.md:8-50`), so a downstream project can ship a project-specific widget without touching the generic plugin. The generic-plugin rule in `CLAUDE.md` (no FLS names in `claude_plugins/fls-content`'s generic parts? it is content tooling, check) applies to ds/sdd/productivity; fls-content documents FLS widgets and is where built-in widget docs live.
- Validation: `claude_plugins/fls-content/validate/validate.py:668-720` (`validate_widget_references`) only checks `path` attributes on article-link/article-card/course-card. No check that `src` of picture/pdf/file exists (grep found none); a missing file renders an error box at runtime.
- Tests that pin the allowlist: `freedom_ls/markdown_rendering/tests/test_markdown_utils.py:328` (pins `c-flashcard`), `tests/test_config.py`.

## 2. How content media files are referenced, loaded, stored

Reference: authors write `src="relative/path.ext"`. Template filter `get_file_by_path` (`freedom_ls/content_engine/templatetags/content_tags.py:112-136`) resolves it with `content_instance.calculate_path_from_root(path)` and looks up `File` by `file_path` (not site-filtered explicitly here; `File` is `SiteAwareModel`, so the manager filters by site). Returns None when missing; components show a red "not found" box (`file-download.html:25-30`, `pdf-embed.html:41-47`, `picture.html:166-172`). Rendered URL is `{{ file_obj.file.url }}` (`picture.html:37`, `file-download.html:17`, `pdf-embed.html:21`). The component needs `content_instance` in context.

Components:
- `picture.html`: `<img src=file.url loading=lazy>` in `c-media-card` plus a native `<dialog>` lightbox (`contentLightbox`).
- `image-grid.html` / `grid.html`: layout wrappers around c-picture children.
- `file-download.html`: `c-button href=file.url target=_blank`.
- `pdf-embed.html`: iframe on `file.url`.

Model: `freedom_ls/content_engine/models/files.py:30-61`, `File(SiteAwareModel, TimestampedModel)` with `file` (FileField, `upload_to=file_upload_handler` -> `content_engine/{stem}{pk}{ext}`, `storage=get_content_media_storage`), `file_type` (TextChoices IMAGE/DOCUMENT/VIDEO/AUDIO/OTHER — AUDIO already exists, `:37`; migration 0001:119), `file_path` (unique per site, `:46-58`), `original_filename`, `mime_type`.

Storage: alias `course_media` (setting `CONTENT_MEDIA_STORAGE_ALIAS`; `deployment/storage.py:12,66`). Per `claude_plugins/fls-dev/skills/file-storage/SKILL.md:21-27,36-41`, it is the "Course media" bucket: private, signed URLs, holds "Course images, PDFs, video", rebuildable from the content repo. Audio fits this bucket and alias with no new alias. `course_media` refuses overwrite (skill `:71-78`), keys are `content_engine/{stem}{pk}{ext}` so unique. In S3 mode `querystring_auth` defaults True with expiry 3600 s (`storage.py:197-203`), so URLs expire in an hour. Local dev uses FileSystemStorage.

Access is not protected per learner: any signed/served URL works for anyone holding it; there is no Django view gating course media by enrolment. It is a bucket-level private + short-lived signed URL model, same as images/PDFs.

Loader: `freedom_ls/content_engine/management/commands/content_save.py`. Every non-`.md/.yaml/.yml` file in the content tree is saved as a `File` (`:966-985`), no allowlist rejects any extension. `get_file_type_from_extension` (`:785-802`) already classifies audio `{.mp3,.wav,.ogg,.m4a,.flac,.aac}` as `File.FileType.AUDIO`. `save_file_to_db` (`:859-931`) guesses `mime_type` via `mimetypes.guess_type`, stores it; only `IMAGE` goes through the optimisation pipeline (`:869-875`, `images.py`, `IMAGE_EXTENSIONS` in `content_engine/validate.py:34`). Audio takes the plain copy path (`:926-928`). So audio files already load, are typed AUDIO and are stored today; what is missing is any component that uses them. Possible gaps to check in the spec: `mimetypes.guess_type` for `.m4a`/`.ogg`/`.opus` may return None or `audio/mp4a-latm` depending on platform (stored as "" then); `.opus`/`.weba` are not in the audio set (fall to OTHER); no size limit or virus scan exists for content files (no scan code found under `freedom_ls/content_engine`; the file-scanning spec was dropped from the roadmap per recent commit message). Upload scan/validation applies to user uploads (`accounts/validators.py` is Pillow-based for profile pictures), not to content-repo files. Content repo size is the real limit: audio for ~26 letters x several clips is small.

What would change for audio: (1) probably nothing in the loader for mp3/ogg/m4a/wav; (2) add `.opus` (and `.weba`) to `audio_extensions` only if wanted; (3) optionally set a fallback `mime_type` map so `<source type=...>` is always right (the component can also derive type from extension); (4) `content_validate` could check audio `src` exists (none today for any media); (5) CSP: `SECURE_CSP_REPORT_ONLY` (`config/settings_base.py:561-604`) has `default-src 'self'` and no `media-src`, and only the profile-picture bucket host is added to `img-src` (`:589`). When course_media is on a bucket host, `<audio>` falls back to `default-src` and would be reported (report-only today, so not blocking) — a spec should add `media-src` with `media_csp_sources(CONTENT_MEDIA_PURPOSE)` (`storage.py:140-168`), or note it is blocked when CSP is enforced. The same gap already applies to images and PDFs from the bucket.

## 3. The existing flashcard component

`templates/cotton/flashcard.html` + Alpine `flashcard` (`alpine-components.js:57-62`). Named slots `front`/`back` rendered with `{% markdown front %}` / `{% markdown back %}` (`:191,:215`) — i.e. each slot is run through `render_markdown` again (`content_tags.py:139-147`, `render_markdown(value, request)` with no context), so cotton components inside slots go through the sanitiser and compile again. Consequences:
- `markdown` tag passes no `context`, so `content_instance` is NOT in the nested render context. Nested `c-picture`, `c-file-download` or any component using `get_file_by_path:content_instance` inside a slot would get `content_instance` undefined and `calculate_path_from_root` would fail or the file would show as not found. This is the key blocker for audio in flashcard faces; verify with a test. (Not confirmed by running; read from `content_tags.py:139-147` and `markdown_utils.py:15-17`.) A fix: pass the context through the `markdown` tag, or have the audio component accept a pre-resolved URL.
- Also the nested `c-slot`/`c-*` tags must be in `MARKDOWN_ALLOWED_TAGS` (global, so fine).
- Layering (`flashcard.html:36-43,:155-160`): the flip button is below the faces; the face stack has `pointer-events-none` so clicks on prose fall through to flip. Descendants only take pointer events back through the `.flashcard-face :is(table, pre) { pointer-events: auto }` rule (`:90-94`). So a nested audio play button inside a face is not clickable as is: the click falls through to the flip trigger and flips the card. Fix: add `pointer-events: auto` for the audio control (e.g. extend the `:is(...)` selector or give the component a class/attribute the rule matches); put the audio component's own `@click` handlers on that element; stop propagation is not needed because the trigger is a sibling, not an ancestor. Keyboard: faces use `inert` on the hidden one (`:175,:206`), so the hidden face's audio button is unfocusable, which is right; a button in the visible face is reachable by Tab.
- 3-D transform: each face is a stacking context with `backface-hidden`; a native `<audio controls>` element inside a rotated face renders but browser UI controls inside 3-D transformed contexts can misbehave on older Safari; a custom button + hidden `<audio>` (or `new Audio()` in Alpine) avoids it. The hidden `<audio>` should not live in the flashcard Alpine scope as a second component sharing state.
- Alpine state: `flashcard` scope has `flipped`; a nested Alpine component (own `x-data`) inside a face nests fine.
- Pre-existing a11y: both faces carry `aria-hidden` toggled by `flipped`; the sr-only "Flip card" button covers everything. Audio autoplay on flip would need a hook the flashcard does not have (`flip()` only toggles).
- This existing component is a static in-page widget (no persistence, no rating). It is unrelated to the SRS flashcards in learner-interface-features-4 (see section 5).

## 6. Implications for specs

(a) Audio play component (`c-audio` or similar)
1. Authors cannot write `<audio>`; nh3 strips it. The cotton template must emit the audio markup; add the tag and its attributes (e.g. `src`, `label`, `caption`) to `MARKDOWN_ALLOWED_TAGS`, `claude_plugins/fls-dev/resources/markdown_content.md`, and the fls-content widget-reference (SKILL.md table, attribute block, resource file) plus a demo in `demo_content/functionality_demo_content_widgets/2. media/`.
2. Resolve `src` with `get_file_by_path:content_instance`; missing file shows the red not-found box like siblings. Use `file_obj.file.url`; the File is already `file_type=AUDIO` and `mime_type` is stored (may be empty; derive `<source type>` from extension or fall back).
3. The loader already accepts and types mp3/wav/ogg/m4a/flac/aac as AUDIO and stores them on `course_media` unoptimised; no model or migration needed. `.opus`/`.weba` are the only likely additions. No scan/size check exists for content-repo files.
4. URLs from S3 mode are signed and expire after 3600 s: a page left open past that fails to play. Decide whether to preload (`preload="auto"`) or accept.
5. CSP has no `media-src`; add one with `media_csp_sources` before CSP is enforced.
6. Alpine must be a CSP-build component registered via `Alpine.data()` in `content_engine/static/content_engine/js/alpine-components.js`, with method/property names only in `x-*` attributes; no inline expressions. Control must be a real button (44px target, aria-label, play/pause state, `prefers-reduced-motion` irrelevant). Support one-at-a-time playback across many instances (a page listing every letter) via a shared module-level "currently playing" reference.
7. Listing page of 26+ players: lazy `preload="none"`/`metadata`, so a page does not fetch 26 files at once.
8. Must render in the educator preview modal and every page that loads the content bundle; no preview-specific work expected beyond narrow-width layout.

(b) "Say it, then reveal" component
1. Reveal is a disclosure/flip-like interaction; reuse the `c-accordion` or `flashcard` patterns rather than a new mechanism. Hidden content must be `inert`/`aria-hidden` as the flashcard does, so it is not announced or focusable early.
2. If it records the learner's voice or uses speech recognition, that is new browser permission, a new CSP/permissions-policy question and a privacy question (audio is personal data; the `user_uploads` alias, prefixed per user, would be the only storage fit, `file-storage/SKILL.md:42,118-119`). If it is only "think/say aloud, then click reveal", nothing is stored and nothing server-side changes. The idea decides which.
3. If it also plays the sound at reveal, it reuses (a) and its nested-render constraints.
4. Authoring via named `c-slot` content needs blank lines inside slots (`c-flashcard.md:25`); if the answer slot holds an audio component it hits the same `{% markdown %}` no-context issue as flashcard slots.
5. No completion/progress is recorded by existing content widgets (all stateless); persisting "I said it" would be a new learner-progress concept, out of scope unless asked.

(c) Audio on spaced-repetition flashcards
1. Cards are not yet designed: spec 4 leaves media in cards open (`idea.md:53-56`) and depends on spec 3's scheduler. An audio spec cannot fix a storage or authoring shape until spec 4 picks card model versus question type; it should state it builds on that choice.
2. If front/back are markdown rendered through `{% markdown %}`, nested components lose `content_instance` (`content_tags.py:139-147`, `markdown_utils.py:15-17`), so audio `src` lookup fails until context is passed or the URL is pre-resolved at load time (also fixes the in-page `c-flashcard`).
3. Inside a flipping face the stack is `pointer-events-none`; an audio button needs `pointer-events: auto` or a click flips the card (`flashcard.html:90-94,155-160`). Hidden faces are `inert`, so only the visible face's audio is operable.
4. Revision and flashcard sessions are separate pages from the course player; they must load the `content_engine` bundle and any new audio JS. Per-session pages can run many cards: audio must preload only the current card, and signed URLs must be minted at render so they are fresh.
5. Rating comes after flip and is stored in the revision record, not `QuestionAnswer` (spec 4 `:31-33`); audio plays are not ratings and should not be logged unless a spec asks.
6. Editing or removing a card affects learner history (spec 4 `:55-56`); replacing an audio file means `course_media` writes a new key (no overwrite), and `save_file_to_db` handles supersession (`content_save.py:904-922`).
7. Name the thing: "flashcard" is used for both the static `c-flashcard` and the scheduled cards of spec 4; keep them distinct in the spec.
