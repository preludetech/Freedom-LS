# FORM, FORM_PAGE, FORM_QUESTION, and FORM_CONTENT Files

A form lives in a **numbered subdirectory** (e.g. `03. quiz/`) containing:
- Exactly one `form.md` — the FORM
- One or more numbered `.yaml` files — each contains FORM_PAGE + questions/content

---

## FORM (`form.md`)

### Frontmatter fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `content_type` | `FORM` | Yes | Must be exactly `FORM` |
| `title` | `str` | Yes | Display title |
| `strategy` | `QUIZ`, `CATEGORY_VALUE_SUM`, or `UNSCORED` | Yes | Form scoring strategy |
| `quiz_show_incorrect` | `bool` | Conditional | Required when `strategy: QUIZ`; **must be absent** for `CATEGORY_VALUE_SUM` and `UNSCORED` |
| `quiz_pass_percentage` | `int` (0–100) | Conditional | Required when `strategy: QUIZ`; **must be absent** for `CATEGORY_VALUE_SUM` and `UNSCORED` |
| `submit_on_exit` | `bool` | No (default `false`) | If `true`, partial attempt is finalised on navigation away |
| `shuffle_pages` | `bool` | No (default `false`) | QUIZ only. Each sitting serves the pages in a random order. See "Shuffling a quiz" below |
| `shuffle_questions` | `bool` | No (default `false`) | QUIZ only. Each sitting serves each page's questions in a random order. `group` keeps questions together |
| `shuffle_options` | `bool` | No (default `false`) | QUIZ only. Each sitting serves each question's options in a random order. `locked` pins an option |
| `sections` | `list[path]` | No | Paths to the topic markdown files or `part.yaml` files the questions test, relative to `form.md`'s directory. Questions inherit this list unless they set their own `sections:` |
| `subtitle` | `str` | No | Optional subtitle |
| `description` | `str` | No | Optional description |
| `content` | `str` | No | Optional markdown intro body |
| `due_date` | date | No | Fixed due date as a YAML date, e.g. `2026-03-14` (no time). Not allowed together with `due_days_after_registration`. |
| `due_days_after_registration` | `int` (>= 0) | No | Due this many days after the learner registers for the course. Not allowed together with `due_date`. |
| `due_time` | `str` | No | Quoted 24-hour `"HH:MM"`. Needs `due_date` or `due_days_after_registration`. Without it the form is due at the end of that day. |
| `uuid` | `str` | No | Written by `content_save` — **omit on new files** |

A shuffle knob set to `true` on a `CATEGORY_VALUE_SUM` or `UNSCORED` form fails validation with `<knob> should only be set when strategy is QUIZ`. The knobs go in `form.md` only, never in a page header.

Due-date fields follow the same rules as on a topic (see `topic-files.md`, "Due dates"). Write them in
`form.md`; a `children:` entry can replace them for one placement (see `course-files.md`, "Due dates per
placement").

### QUIZ example

```yaml
---
content_type: FORM
strategy: QUIZ
title: Module Knowledge Check
quiz_show_incorrect: true
quiz_pass_percentage: 80
---
```

### Survey (CATEGORY_VALUE_SUM) example

```yaml
---
content_type: FORM
strategy: CATEGORY_VALUE_SUM
title: Course Feedback Survey
---
```

### Unscored (UNSCORED) example

`UNSCORED` records answers without a score or pass/fail outcome. It is the strategy an
application form uses (see the course access configuration section of `course-files.md`). An
application form never asks for the applicant's email, name or agreement to the site's terms:
FLS collects those itself, and that section lists them.

```yaml
---
content_type: FORM
strategy: UNSCORED
title: Application form
subtitle: Tell us about yourself
---

There are no right answers here. Answer as honestly as you can.
```

## FORM_PAGE (first section of a page YAML file)

Page YAML files are named with a numeric prefix: `1. page.yaml`, `2. more-questions.yaml`.
Each one is a page of questions. The results/score page a learner sees after submitting is
generated by FLS, never authored. There is no RESULTS content type; only the ten
documented content types exist.

The **first** `---`-delimited YAML section is the FORM_PAGE.

### Frontmatter fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `content_type` | `FORM_PAGE` | Yes | Must be exactly `FORM_PAGE` |
| `title` | `str` | Yes | Page heading |
| `subtitle` | `str` | No | Optional subtitle |
| `description` | `str` | No | Optional instruction text |
| `when` | mapping | No | Show this page only when an earlier answer matches. See "Conditional pages, questions and content (`when`)" below |
| `uuid` | `str` | No | Written by `content_save` — **omit on new files** |

### Example FORM_PAGE section

```yaml
---
content_type: FORM_PAGE
title: Feedback
description: Tell us what you thought of this course.
```

Note: there is no closing `---` at the end of this first section when followed by question sections — the next `---` opens the next section.

## FORM_QUESTION (subsequent sections with a `question` key)

**FORM_QUESTION and FORM_CONTENT inherit a smaller base model** — they have **no** `title`, `subtitle`, `description`, `category` (as a display field), or `image` fields.

The parser selects `FORM_QUESTION` when a subsequent section contains a `question` key.

### Fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `question` | `str` | Yes | The question text |
| `type` | `multiple_choice`, `checkboxes`, `short_text`, `long_text`, `number`, `file_upload`, `date`, `time`, `email`, `url`, `phone`, or `dropdown` | Yes | Question type |
| `required` | `bool` | No (default `true`) | Whether the question must be answered |
| `category` | `str` | No | Used by `CATEGORY_VALUE_SUM` scoring strategy |
| `options` | `list` | Conditional | Required for `multiple_choice`, `checkboxes`, and `dropdown` |
| `min` | `str` | No | Inclusive lower bound for `date`, `time` or `number` — `YYYY-MM-DD`, `HH:MM`, or a plain number |
| `max` | `str` | No | Inclusive upper bound — same formats as `min` |
| `decimal_places` | `int` | No (default `0`) | Decimal places a `number` answer may use. Only valid on `number` |
| `slug` | `str` | No | The name a later `when` uses to refer to this question. Lowercase letters, digits and underscores only (`^[a-z0-9_]+$`), at most 100 characters, unique within the form. Only needed on a question that a `when` points at |
| `when` | mapping | No | Show this question only when an earlier answer matches. See "Conditional pages, questions and content (`when`)" below |
| `sections` | `list[path]` | No | Paths to the topic markdown files or `part.yaml` files this question tests, relative to the page yaml's directory. Overrides the form's `sections:` for this question; `sections: []` means none. See the `sections` section below |
| `group` | `str` | No | QUIZ forms only. Keep-together group: children of one page that share this name stay together, in authored order, when the page's questions shuffle. See "Shuffling a quiz" below |
| `uuid` | `str` | No | Written by `content_save` — **omit on new files** |
| `meta` | `dict` | No | Optional metadata |
| `tags` | `list[str]` | No | Optional tags |

Each option in `options`:

| Field | Type | Required | Notes |
|---|---|---|---|
| `text` | `str` | Yes | Display text |
| `value` | `int` or `str` | Yes | Stored value |
| `correct` | `bool` | No | For QUIZ strategy — marks the correct answer |
| `locked` | `bool` | No (default `false`) | Used in shuffled quizzes: keep this option at its authored position while the others shuffle. Only valid when the form sets `shuffle_options: true` |
| `uuid` | `str` | No | Written by `content_save` |

### Multiple-choice question example

```yaml
---
question: "What is a variable?"
type: multiple_choice
options:
  - text: "A named container for a value"
    value: a
    correct: true
  - text: "A fixed constant"
    value: b
  - text: "A function parameter"
    value: c
```

### Short-text question example

```yaml
---
question: "What did you find most useful about this course?"
type: short_text
required: false
category: general
```

### Number question example

`min` and `max` are inclusive. `decimal_places` defaults to `0` — whole numbers only.

```yaml
---
question: "How many years have you been writing software?"
type: number
required: true
min: 0
max: 70
```

### Date question example

Write `min`/`max` as `YYYY-MM-DD`, quoted.

```yaml
---
question: "What is your date of birth?"
type: date
required: true
min: '1900-01-01'
max: '2010-01-01'
```

### Time question example

Write `min`/`max` as `HH:MM`. Quote any bound whose hour starts with a zero-free
digit pair YAML could read as a number: `'17:00'` needs quotes, `09:00` does not.
Quoting both is the safe habit.

```yaml
---
question: "What time of day do you prefer for live sessions?"
type: time
required: true
min: '09:00'
max: '17:00'
```

### Email and URL question examples

Both validate the answer's format when the learner submits it.

```yaml
---
question: "What is your email address?"
type: email
required: true
```

```yaml
---
question: "Share a link to your portfolio, GitHub profile or LinkedIn, if you have one"
type: url
required: false
```

### Phone question example

Renders a country picker, preselected from the learner's browser language, beside a number box. The learner types the
number that follows the country's calling code, and it is checked against the chosen country when they submit. A
number typed with a leading `+` and its country code is read as international whatever the picker says. The answer
is stored in international (E.164) form, e.g. `+27821234567`, and shown that way. Extensions are not accepted.
There are no phone-specific YAML keys.

```yaml
---
question: "What is your phone number?"
type: phone
required: false
```

### Dropdown question example

Takes `options` in the same shape as `multiple_choice`, but renders as a select; use it
when there are too many options for radio buttons.

```yaml
---
question: "Which time zone are you usually in?"
type: dropdown
required: true
options:
  - text: "Pacific (UTC-8)"
    value: pacific
  - text: "Eastern (UTC-5)"
    value: eastern
```

### File-upload question example

```yaml
---
question: "Upload a scan of your ID or a recent certificate"
type: file_upload
required: true
```

## FORM_CONTENT (subsequent sections with a `content` key)

The parser selects `FORM_CONTENT` when a subsequent section has a `content` key instead of a `question` key. It embeds explanatory markdown between questions.

### Fields

| Field | Type | Required |
|---|---|---|
| `content` | `str` | Yes |
| `when` | mapping | No |
| `group` | `str` | No |
| `uuid` | `str` | No |

### Example

```yaml
---
content: |
  ## Reading comprehension

  Read the following passage before answering the questions below.

  > "The goal of education is not to fill a bucket but to light a fire."
```

## Conditional pages, questions and content (`when`)

`when` shows a page, a question, or a content block only when an earlier answer matches. It works
in `UNSCORED` and `CATEGORY_VALUE_SUM` forms and is not allowed in a `QUIZ` form. A page's `when`
goes in its FORM_PAGE section; a question's or content block's `when` goes in its own section.

```yaml
when:
  question: employer_pays   # the slug of the source question
  equals: 'yes'             # or `includes:` for a checkboxes source (exactly one of the two)
```

Rules (`validate.py` checks all of them across the form's files):

- `question` is the `slug` of a question in the same form. Give that question a `slug:`. A `when`
  naming a slug no question has is an error, and the error lists the slugs the form does declare.
- The source question must be on an **earlier page**, not the same page or a later one. Pages run
  in sorted file-name order, so pad page numbers consistently, as for other numbered files.
- The source must be a `multiple_choice`, `dropdown` or `checkboxes` question.
- Use exactly one of `equals` or `includes`. `equals` is for a `multiple_choice` or `dropdown`
  source; `includes` is for a `checkboxes` source (the value must be among those ticked). Using the
  wrong one for the source type is an error.
- The value must be one of the source question's option `value`s (not its `text`). The error lists
  the valid values.
- Quote the value. Unquoted `yes`, `no`, `on`, `off`, `true` and `false` are read by YAML as
  booleans and are rejected: write `equals: 'yes'`. A number such as `3` is accepted and compared
  as the text `"3"`.
- `slug` must be unique within the form. A duplicate is an error.

Example, from the `functionality_demo_application_form` demo. Page 1 declares the source question:

```yaml
question: Is your employer paying for this course?
type: multiple_choice
required: true
slug: employer_pays
options:
  - text: 'Yes'
    value: 'yes'
  - text: 'No'
    value: 'no'
```

Page 2 (`2. your-employer.yaml`) is shown only when the answer was `yes`:

```yaml
---
content_type: FORM_PAGE
title: Your employer
subtitle: So we can invoice the right people
when:
  question: employer_pays
  equals: 'yes'
---
content: |-
  We invoice employers directly. Tell us who they are and where the invoice
  should go.
---
question: What is your employer's name?
type: short_text
required: true
```

## Shuffling a quiz

Three independent `form.md` knobs shuffle a `QUIZ` form once per sitting. All default to `false`:

- `shuffle_pages: true` serves the pages in a random order.
- `shuffle_questions: true` serves each page's questions and content blocks in a random order. It never moves a question to another page.
- `shuffle_options: true` serves each question's options in a random order.

Two controls keep a shuffled quiz correct.

**`locked` on an option** keeps that option at its authored position while the others shuffle. Use it for "All of the above" and "None of these", which only make sense last:

```yaml
options:
  - text: "Red"
    value: red
  - text: "Blue"
    value: blue
    correct: true
  - text: "All of the above"
    value: all
    locked: true
```

**`group` on a content block or question** keeps a stimulus with its questions. Children of one page that share a `group` name form one block, in authored order, and the block moves as one when the page's questions shuffle:

```yaml
---
content: |-
  Look at the picture, then answer the next two questions.

  <c-picture src="../images/shuffled-quiz-picture.svg" alt="..."></c-picture>
group: sky-picture
---
group: sky-picture
question: What is the yellow shape in the picture?
type: multiple_choice
```

The validator checks:

- `group` is only allowed on `QUIZ` forms.
- `locked: true` needs `shuffle_options: true` on the form. Otherwise the option never moves, and the error says so.
- A `group` name must not be empty or have leading or trailing spaces.
- A `group` stays on one page. The same name on two pages is an error.
- A group's members must be next to each other. Another child between them is an error naming that child.
- A one-member group is valid. So is a group with no content block. Groups are a no-op when `shuffle_questions` is off, but they are still allowed.

Writing a shuffled form:

- **Reword "All of the above" and "None of these", else lock it, else turn `shuffle_options` off.** A lock fixes a position, not a meaning. "Both A and B" and "Both of the first two" still break when options move.
- **No positional references.** Don't write "see question 3", "the diagram above" or "option (b)". Order changes per learner.
- **Group a stimulus with its questions.** Don't rely on a passage sitting above the questions it supports.
- **When `shuffle_pages` is on, put instructions in the form body** (the markdown after the `form.md` front matter), not on the first page. Any page can come first.
- Authored page numbers still show in page URLs, even when the served order differs.
- Shuffling is not proctoring. It makes copying harder and nothing more.

Example: `demo_content/functionality_demo_shuffled_quiz/` has a `QUIZ` with all three knobs on, a locked option, and a `sky-picture` group made of a picture block and its two questions, next to ungrouped questions.

## Sections a question tests (`sections`)

`sections` names the topics or course parts a question tests. `content_save` stores the link, and
the admin shows it on the question. Nothing shows the sections to learners yet. It works on every
form `strategy`, so a bank form need not be a `QUIZ`.

```yaml
sections:
  - ../01. key-ideas/content.md   # a topic's markdown file
  - ../part.yaml                  # or a part's part.yaml
```

Each entry is a path to a topic markdown file or a `part.yaml`, relative to the directory of the
file that holds the `sections:` key. See [course-files.md](course-files.md) for path syntax.

- Put `sections:` on the form (`form.md`) to set a default for every question.
- Put it on a question to replace the form's list for that question. A question without the key
  inherits the form's list. `sections: []` means the question tests no section, even when the form
  names some.
- A `sections:` key with no value (for example, every entry commented out) fails validation. Write
  `sections: []` for none, or, on a question, remove the key to inherit the form's list.
- Order carries no meaning, and each section may be named only once per list.
- Every `content_save` rewrites each question's sections to exactly its effective list. Removing a
  path or the key removes the link on the next load.
- A target must sit inside the directory passed to `content_save`, because only files loaded in
  that run are linked. A target outside it, a path with no file, a file that is not a topic or
  `part.yaml` (an image, or a file that does not parse), or a file under a name starting with `_`
  or `.` fails the load with an "Invalid section reference" error. The offline validator reports
  the same errors, except a target outside the validated directory, which it reads from disk. The error names the
  declaring file, the field (`sections[<i>]`) and the problem. Every bad entry is reported at once,
  before anything is written. A moved or renamed target is not followed: fix the path.
- A form that sits in no course (a bank form) needs no placement, but where it sits matters. Put
  it in a **sibling directory of the courses**. Do not put it in a course directory that has no
  `children:` list: `content_save` auto-discovers it and places it in that course. Do not put it
  under a `_` prefix: files and directories starting with `_` are not loaded.

Example, from `functionality_demo_course_parts`. The form defaults to the whole part, and the
question overrides it with one topic:

```yaml
# 03. knowledge-check/form.md
---
content_type: FORM
strategy: QUIZ
title: Knowledge Check
sections:
  - ../part.yaml
---
```

```yaml
# 03. knowledge-check/1. page.yaml (a question section)
question: What is a course part?
type: multiple_choice
sections:
  - ../01. key-ideas/content.md
```

## Full page YAML file example

```yaml
---
content_type: FORM_PAGE
title: Module 1 Quiz
description: Answer all questions to complete the module.
---
question: "What does a variable store?"
type: multiple_choice
options:
  - text: "A value that can change"
    value: a
    correct: true
  - text: "A fixed program instruction"
    value: b
---
content: |
  Great job! Now let's test your understanding of data types.
---
question: "Which type holds whole numbers in Python?"
type: multiple_choice
options:
  - text: "int"
    value: int
    correct: true
  - text: "float"
    value: float
  - text: "str"
    value: str
```
